# 拡張ROMバンク（4th ROM）切り替え

仕様書 第1版 / 2026-09-19

`docs/spec/` の書き方は [l1-ipl.md](l1-ipl.md) に倣う。**「観測」と
「観測から導いた実装上の制約」を節ごとに分け、実装は観測にだけ従う。**
この文書は測定結果だけから書かれており、公式 ROM のコードは一切参照
していない。測定に使ったROMはすべて自作の試験ROM（`tools/harness/
make_ext_rom_test.py`）であり、公式ROM・`private/`は一切参照していない
（`CLAUDE.md`禁止事項1-7のいずれにも該当しない）。

ポート`0x32`・`0x71`のビット定義そのもの（EROMSL・4th ROMコントロール）
は [l1-ipl.md](l1-ipl.md) 第4・5a・5c節に既にあるので、ここでは重複して
書かず、必要な箇所だけ参照する。この文書が新しく書くのは、**その
ビット定義を使って実際にバンクを切り替えたときに何が起きるか**（読み
分け・ファイル欠落・割り込み安全性・中継呼び出し）という、L1のIPL区間
より後、L4以降の実行時に関わる話である。

## 1. 観測 — ハードウェア/エミュレータの事実

**ポート`0x71`のbit0（`EXT_ROM_NOT`）が総スイッチ、有効時にどのバンクを
見せるかをポート`0x32`の下位2ビット（`MISC_CTRL_EBANK`）で選ぶ。** 対象は
`0x6000`–`0x7FFF`の**読み出し**だけで、書き込みは常にメインRAM（ROM/RAM
モードの通常ROM窓と同じ扱い）。

根拠: `docs/notes/ext1-rom-bank-results.md` Q1（B1〜B3・B9、2走とも決定論的）。

- **`0x71`のbit0を落とし`0x32`の下位2bitでバンク0〜3を選ぶと、窓
  （`0x6000`–`0x7FFF`）の内容がそのバンクのものに切り替わる**
  （`q1_bank_reads_match_n`。4バンクとも、あらかじめ置いた識別パターン
  〈先頭バイト・末尾バイト〉が取り違えなく読めた）。
- **`0x71`を戻すと窓はメインROM側に戻る**（`q1_restore_reads_main`）。
- **バンク切り替え・復元の前後で、対象外のビット（`0x32`のPMODE等）は
  保持される**（`q1_other_bits_preserved`。中継ルーチンが「読んでから
  対象ビットだけ書き換えて書き戻す」設計だった場合の実測であり、これは
  ハードウェアの回路仕様そのものの観測ではなく、その設計を実装したとき
  に無関係ビットが実際に壊れなかったことの確認）。
- **バンクROMファイルが1本欠けていると、そのバンクを選んだときの窓は
  全バイト`0xFF`になる。他のバンク・メインROM側には波及しない**
  （`q2_missing_bank_reads_ff`・`q2_other_banks_unaffected`。エミュレータの
  `load_rom()`がファイル未発見時に`0xFF`埋めし、失敗を致命扱いにしない
  という実装どおりの結果が実測で裏づけられた）。
- **`0x79D7`（自作main ROMが機種判定〈ROM_VERSION〉用に空けている予約
  番地、[l1-ipl.md](l1-ipl.md)第2節P4該当部）も、窓の中にあるため他の
  番地と同様にバンク切り替えの影響を受け、切り替えを戻せば元の値に
  戻る**（`q1_rom_version_addr_restores`。
  バンクを選択している間、この番地からはバンク側のバイトが読める
  ——切り替え中の値そのものはバンク側の内容に依存するため、`0x79D7`を
  判定に使うコードは**窓がメインROM側を指している間に**読む必要がある）。
- **バンク有効中に発生した割り込みは、ハンドラが窓の外（メインROM/RAM側
  の固定番地）に置かれ、窓の中の番地を直接呼ばない設計であれば、正しく
  受理・復帰できる**（`q3_interrupt_during_window_ok`。200往復すべて
  完走・結果一致、実際にバンク有効中に割り込みを受理した回数が
  独立した2種の証拠〈受理時のバンク有効フラグ・`--int-log`の`ret_pc`が
  窓の範囲内だった件数〉の両方で複数件確認された上での判定）。
- **逆に、割り込みハンドラが窓の中の番地を呼ぶ設計は壊れる**（詳細は
  第2節）。

## 2. 観測から導いた実装上の制約（設計上の必須要件）

本節は**観測そのものではなく、上記の観測から導いた実装上の制約**である
（自作main ROMがバンクを使うときに必ず守る必要がある要件、という位置
づけで節を分ける）。

根拠: `docs/notes/ext1-rom-bank-results.md`「設計上の結論（中継ルーチンの
必須要件）」節（B1〜B7の観測に基づく）。

1. **中継ルーチン（バンク切り替え・呼び出し・復元を行うルーチン）は
   必ず窓の外（`0x0000`–`0x5FFF`またはRAM）に置く。** 窓の中に置くと、
   そのルーチン自身が別のバンクへ切り替えた瞬間に消える。
2. **割り込みハンドラは窓の外に置き、窓の中の番地を呼ばない。**
   `q3_interrupt_during_window_ok`（安全な設計、ハンドラは窓の外の固定
   番地でフラグを見るだけ）と`q3_handler_inside_window_breaks`（禁止
   設計、ハンドラが窓の中へ`CALL`する）の差はこの1点のみで、結果は
   「200往復すべて成功」対「76往復で完全停止（ハングと同型の暴走）」に
   分かれた。**割り込みハンドラが窓の中のコードを呼ぶ設計は、単発の
   不具合ではなくハンドラ自身が自己再入するループに陥りうる**
   （`q3_handler_inside_window_breaks`、機構は`docs/notes/ext1-rom-bank-
   results.md`Q3節に詳しい——窓の中が想定外のバイト列になっていた場合、
   `CALL`先がハンドラ自身の先頭へ舞い戻る形で無限に近い再入が起き、
   スタックを暴走的に消費した）。
3. **バンク側（窓の中）のコードから、窓の中の他の番地・常駐部の外側の
   ルーチンを直接`CALL`する設計は使わない。** 中継ルーチンはバンク側の
   ルーチンを1回`CALL`して戻ってくる形だけを前提とし、バンク側から
   さらに別のバンクへ跨る呼び出しは検証していない（測定していない）。
4. **中継ルーチンは、バンク切り替えの前に`0x71`・`0x32`の現在値を読んで
   保存し、対象ビット（`0x71`のbit0・`0x32`の下位2bit）だけを書き換えて
   バンクを選び、呼び出しから戻った後に保存しておいた値をそのまま書き
   戻す。** 無関係なビット（PMODE等）を破壊してはならない。この定型は
   [l1-ipl.md](l1-ipl.md)第4節が観測した「読んでから書き戻す」定型と
   同じ形であり、本測定はその定型を実装した場合に無関係ビットが実際に
   保持されることを裏づけた（第1節`q1_other_bits_preserved`）。
5. **バンクファイルが1本欠けても、他バンク・メインROM側の読み出しには
   影響しない。** 欠落バンクを選んだ場合の窓は全バイト`0xFF`になる
   （第1節）ため、欠落を検出してフォールバックする設計にするなら、その
   判定はバンク側の想定内容と衝突しない値を基準に組む必要がある。

## 3. 未確定（材料に無いため、この版では埋めない）

以下は次の測定・段階で扱う。**推測で埋めない。**

1. **中継呼び出しの費用（オーバーヘッド）は未測定。** Q4で得られた
   `clock`差分（`--io-log`のイベント通し番号の差分）は、測定後の
   レビューで「経過時間でも命令数でもない」と訂正されており
   （`docs/notes/ext1-rom-bank-results.md`「訂正」節）、**費用の大小に
   ついては何も言えない。** 分かっているのは「中継ルーチンが経由・
   往復として確定的に成立し、毎回同じ構造で完了する」という定性的な
   事実のみ。費用を測るには、改めて事前登録（フレーム数を時間の代理
   指標として使うことの妥当性、多数回ループの作り方）が要る。
2. **公式ROMが拡張ROMバンクを実際に使う場面（存在するか、どのタイミング
   か）は未測定。** 公式ROMのI/O観測（ディスクあり・キー入力ありなど
   条件を広げた測定）が必要で、本測定の対象外（`ext-rom-bank-survey.md`
   第6b節Q5・Q6、`ext1-rom-bank-preregistration.md`「位置づけ」節が
   明記したスコープ外）。
3. **バンク側（窓の中）のコードから、別のバンク・窓の外の常駐部ルーチンを
   跨いで呼び出す場合の挙動**は測定していない（第2節項3の裏返し、
   禁止のみ確認し代替設計は検証していない）。
4. **公式の拡張ROM（4本、`N88_0.ROM`〜`N88_3.ROM`）の中身・各バンクに
   どの機能が収められているか**は、測定しておらず本文書の対象外
   （測る手段が無い——公式拡張ROMの内部構造を読むこと自体が禁止事項2の
   対象になりうるため、着手していない）。
5. **実機（PC-8801本体）で同じ挙動になるかは未検証。** 第1〜2節の観測は
   すべてQUASI88（エミュレータ）上の自作試験ROMによるものであり、実機の
   挙動そのものを主張しない（第0節「位置づけ」参照）。
6. **割り込み安全性の判定は統計的な多数回往復（200回）によるもので、
   厳密な同時性（バンク切り替えの窓のちょうど中央で割り込みが発生した
   ケース）を精密に狙って確認したものではない。** `ext1-rom-bank-
   preregistration.md`「迷った点・設計判断」節1に明記済みの設計上の
   妥協であり、本測定はこの妥協の範囲で`ACTIVE_HIT_COUNT`・`ret_pc`の
   2種の独立証拠により「バンク有効中に実際に複数回踏んだ」ことを確認
   した上での判定である。
