## 1. 観測 — 行番号つきの行を打ったときの画面の反応

**行番号つきの行を打っても、その行は打鍵のエコーだけが画面に残り、`Ok`も
それ以外の出力も現れない。** これは直接モードの文（[l4-basic.md](l4-basic.md)
第1節、打った行の直後に出力→`Ok`が続く）とは異なる。

根拠: `l4-s5a-program-line-input-list-format-results.md`「腕ごとの構造」節・
「other_lineが出た腕」節。12腕（A1〜A12）は、いずれも`new`（行番号を伴わない
直接モードのコマンド）→行番号つきの行（1〜2行）→`list`（行番号を伴わない
直接モードのコマンド）という構成で打鍵されたが、記録器が「打った行より下・
`Ok`行より上」の範囲で捉えた`other_line`（数字で始まらない、またはASCII範囲外
を含む行）は、**12腕全てで例外なく2行だけ**だった。

- 1行目: `new`の直後に現れる`Ok`行（相対行1）
- 2行目: `list`の入力そのもののエコー行

行番号つきの行を1行だけ打った腕（A1〜A5・A9〜A12）でも、2行打った腕
（A6〜A8）でも、`other_line`の数は変わらず2行のままだった。**行番号つきの
行を打った直後に`Ok`や他の出力が挟まることは一度も無かった。** `new`・`list`
という行番号を伴わないコマンドだけが、直接モードと同じように`Ok`（`new`の
場合）や出力（`list`の場合、第2節）を伴う。

## 2. 観測 — `LIST` の出力書式

対象は`l4-s5a`の12腕（A1〜A12）。以下の打鍵文字列・`LIST`出力は、いずれも
自分で打ったプログラムを処理系がそのまま表示したものであり、禁止事項7の対象外
（事前登録「記録する内容」節が明示的に許可）。

| 腕 | 打鍵文字列（`new`〜`list`の要点） | `LIST`の出力 |
|---|---|---|
| A1 | `10 print 1` | `10 PRINT 1` |
| A2 | `10print1`（空白無し） | `10 PRINT1` |
| A3 | `10 print  1`（`print`の後に空白2つ） | `10 PRINT  1` |
| A4 | `10 ?1`（`?`の後に空白無し） | `10 PRINT 1` |
| A5 | `10 print 1:print 2` | `10 PRINT 1:PRINT 2` |
| A9 | `65529 print 1`（大きい行番号） | `65529 PRINT 1` |
| A10 | `10 print "abc"`（文字列） | `10 PRINT "abc"` |
| A11 | `10 print 1.5`（小数） | `10 PRINT 1.5` |
| A12 | `10 print 1234567890123#`（長い倍精度定数） | `10 PRINT 1234567890123#` |

根拠: `l4-s5a-program-line-input-list-format-results.md`「腕ごとの記録」節・
判定Q2。

### 2.1 行番号の書式

**行番号の前後に余分な空白は付かない。** 打った行番号の直後は、元の打鍵と
同じ間隔（空白1個、または打鍵どおりの間隔）になる。A1〜A12いずれも、行番号
の前に余分な空白は挿入されず、行頭（相対桁0相当）からそのまま数字が始まる。

### 2.2 命令語の大文字化

**小文字で打った命令語は、`LIST`の出力では大文字化される。** 打鍵は小文字
`print`で与えたが（打鍵注入の仕様、[l4-basic.md](l4-basic.md)踏襲）、A1〜A12
全腕で`LIST`出力は`PRINT`と大文字で表示された。

### 2.3 命令語の後の空白・`?`展開との食い違い

**命令語の後の空白は、元の打鍵にあればそのまま保持され、無ければ挿入
されない。** ただし`?`を`PRINT`に展開する場合だけ、打鍵に空白が無くても
`PRINT`の後に空白が挿入される。

| 腕 | 打鍵 | `LIST`出力 | 命令語後の空白 |
|---|---|---|---|
| A1 | `10 print 1`（`print`の後に空白あり） | `10 PRINT 1` | 保持（あり） |
| A2 | `10print1`（`print`の後に空白無し） | `10 PRINT1` | 保持（無し） |
| A4 | `10 ?1`（`?`の後に空白無し） | `10 PRINT 1` | **`?`→`PRINT`展開時だけ挿入される** |

**A2とA4は、どちらも「命令語の直後に空白無しで打った」という同じ形の入力
だが、`LIST`の出力での空白挿入の有無が異なる。** `print`とそのまま打った
場合（A2）は空白が挿入されないままだが、`?`と打って`PRINT`に展開される
場合（A4）は空白が挿入される。この食い違いの原因（内部表現の違い等）は
ROM内部構造の話になるため立ち入らず、**表面に現れた形だけを実装の対象と
する**（根拠: 結果ノート「観測」節）。

### 2.4 `:` の前後の空白

**`:`の前後に余分な空白は入らない。** A5（`print 1:print 2`）の`LIST`出力
は`PRINT 1:PRINT 2`で、`:`の前後は打鍵どおり空白無しのままだった。

### 2.5 打ったときの余分な空白の保持

**打鍵で入れた余分な空白（連続する複数の空白）は、そのままの個数で保持
される。** A3（`print`の後に空白を2つ打った`print  1`）の`LIST`出力は
`PRINT  1`で、空白2個がそのまま2個で残った（1個に詰められたり、0個に
削られたりしなかった）。

### 2.6 数値の定数・文字列

**数値の定数（小数・`#`付き倍精度定数）も文字列リテラルも、書式の変換を
受けず打鍵どおりに`LIST`出力へ再現される。**

- A10（文字列`"abc"`）: 引用符の追加・削除なく`"abc"`のまま。
- A11（小数`1.5`）: 小数点の位置の変更なく`1.5`のまま。
- A12（`#`付きの長い倍精度定数`1234567890123#`）: `#`の省略・桁の変更なく
  `1234567890123#`のまま。

### 2.7 大きい行番号

**大きい行番号（`65529`）も、先頭に余分な0や空白を挟む書式にはならず、
そのまま出力される。** A9の`LIST`出力は`65529 PRINT 1`だった。

## 3. 観測 — 同じ行番号の打ち直し・行番号だけの行・行番号順の並び

### 3.1 同じ行番号を打ち直すと行が置き換わる（`replaced`）

根拠: `l4-s5a-program-line-input-list-format-results.md` Q3（A7）。行番号
`10`で`print 1`→`print 2`の順に2回打った（`10 print 1`・`10 print 2`）結果、
`LIST`出力は`10 PRINT 2`の1行だけで、**先に打った`print 1`の内容は残らず、
後から打った内容で置き換わった。**

### 3.2 行番号だけを打つとその行が削除される（`deleted`）

根拠: 同結果ノートQ3（A8）。`10 print 1`・`20 print 2`を打った後、行番号
`10`だけを打った（内容を続けない）結果、`LIST`出力は`20 PRINT 2`の1行だけで、
**行番号`10`の行はプログラムから消えた。**

### 3.3 `LIST`は打った順ではなく行番号順に並ぶ（`sorted`）

根拠: 同結果ノートQ4（A6）。`20 print 2`→`10 print 1`の順（行番号の大きい
方を先）に打ったが、`LIST`出力は`10 PRINT 1`→`20 PRINT 2`の順（行番号の
小さい方が先）になった。**`LIST`の並びは行番号順であり、打った順ではない。**

## 4. 観測 — `RUN` とプログラムの実行

対象は`l4-s5b`の12腕（B1〜B12）。以下の打鍵文字列・出力は、いずれも自分で
打ったプログラムを`RUN`が`PRINT`で出力した数値であり、禁止事項7の対象外
（事前登録「記録する内容」節・「本文を出さない取り扱い」節が明示的に許可）。
`STOP`・実行中の誤りの出力（4.5節）だけは件数と範囲のみで、値・文言は書かない。

| 腕 | 打鍵文字列（`new`〜`run`の要点） | `RUN`の出力 |
|---|---|---|
| B1 | `10 print 1` / `20 print 2` | `1` → `2`（2行） |
| B2 | `10 for i=1 to 3` / `20 print i` / `30 next` | `1` → `2` → `3`（3行） |
| B3 | `10 for i=1 to 10 step 3` / `20 print i;` / `30 next` | `1`・`4`・`7`・`10`（`;`で1行に4値） |
| B4 | `10 for i=3 to 1` / `20 print i` / `30 next` / `40 print 9` | `9`のみ（本体の出力無し） |
| B5 | `10 gosub 100` / `20 print 2` / `30 end` / `100 print 1` / `110 return` | `1` → `2`（2行） |
| B6 | `10 goto 30` / `20 print 1` / `30 print 2` | `2`のみ（`20`行は飛ばされる） |
| B7 | `10 a=5` / `20 print a*2` | `10` |
| B8 | `10 i=1.5` / `20 print i+1` | `2.5` |
| B12 | （プログラム無し、`new`の直後に`run`） | 出力行無し |

根拠: `l4-s5b-run-control-flow-results.md`「腕ごとの記録」節・判定Q1〜Q6。

### 4.1 行番号順の実行・`GOTO`・`END`・空のプログラム

**`RUN`は行番号の順にプログラムを実行する。** 根拠: 同結果ノート判定Q1
（**`in_order`**、B1・B6）。B1（`10 print 1`/`20 print 2`）は`1`→`2`の順で
出力され、行番号順の実行そのものを確認した。

**`GOTO`は指定した行番号へ飛び、その間の行は実行されない。** B6
（`10 goto 30`/`20 print 1`/`30 print 2`）は`20`行（`print 1`）を飛ばして
`30`行（`print 2`）だけが実行され、出力は`2`のみだった。

**空のプログラムを`RUN`すると、出力無しでそのまま`Ok`になる。** 根拠:
同結果ノート判定Q6（記述のみ、B12）。`new`の直後に何も行を打たず`run`した
結果、出力行は0行のまま`Ok`行が現れた。誤りは発生しなかった。

**`RUN`直後の入力エコー行のさらに後、実行結果の出力に続いて`Ok`が現れる。**
これは直接モードの並び（[l4-basic.md](l4-basic.md)第1節、打った行→出力→
`Ok`）と同じ形で、`run`のエコー行を起点に、実行結果の出力→`Ok`という順に
なる（`l4-s5b-run-control-flow-results.md`「腕ごとの記録」節の`run`エコー
行・`Ok`行の相対位置）。

**`RUN`に行番号を指定すると、その行から実行が始まる（それより前の行は
実行されない）。** 根拠: `l4-s5c-variables-flow-results.md`（`672539e`）
判定Q7、**`starts_at_line`**（C9）。`10 print 1`/`20 print 2`を打った後
`run 20`（行番号`20`を指定）を実行した結果、出力は`2`の1行だけで、`10`
行の`print 1`に相当する出力（`1`）は現れなかった。

### 4.2 `FOR`〜`NEXT`

**`FOR`〜`NEXT`の本体は、開始値から終了値まで（既定の刻み幅は`+1`）
`STEP`の刻みで実行され、開始値が終了値を最初から超えている場合は本体を
1回も実行しない。** 根拠: 同結果ノート判定Q2。

- B2（`for i=1 to 3`、刻み幅の指定無し=既定`+1`）: **`body_runs_3`**。
  `i=1,2,3`の3回、本体（`print i`）が実行され`1`・`2`・`3`が出力された。
- B3（`for i=1 to 10 step 3`）: **`body_runs_4`**。`i=1,4,7,10`の4回で
  終了した（次は`i=13`で10を超えるため）。
- B4（`for i=3 to 1`、`step`指定無し=既定`+1`、開始値3が終了値1を最初から
  超えている）: **`body_skipped`**。本体（`20 print i`）の出力は一切現れず、
  ループの外にある`40 print 9`の`9`だけが出力された。**`FOR`の本体が
  1回も実行されなかった。**

**ループを抜けた後の制御変数は、終了値を1回超えた値のまま残る（終了値
そのものではない）。ループの前に持っていた値は、`FOR`の初期化で
上書きされ影響しない。** 根拠: `l4-s5c-variables-flow-results.md`
（`672539e`）判定Q1、**`after_loop_4`**（C1・C11）。

- C1（`10 for i=1 to 3`/`20 next`/`30 print i`）: ループを抜けた後
  `print i`の出力は`4`。`NEXT`で3回目の加算の後、条件`i>3`を満たした
  時点の値がそのまま残る（終了値`3`ではなく、それを1回超えた`4`）。
- C11（`10 i=10`/`20 for i=1 to 3`/`30 next`/`40 print i`、ループ前に
  `i=10`を代入済み）: 出力はC1と同じ`4`。**`FOR`が`i`を`1`へ初期化する
  ため、ループ開始前の既存値`10`の影響は残らなかった。**

### 4.2a `FOR` の入れ子・`NEXT` への変数名

**`FOR`は入れ子にでき、`NEXT`に変数名を付けて対応するループを指定
できる。** 根拠: 同結果ノート判定Q2、**`nested_ok`**（C2）。
`10 for i=1 to 2`/`20 for j=1 to 2`/`30 print i*10+j;`/`40 next j`/
`50 next i`を`RUN`した結果、内側`j`・外側`i`のループが期待どおりの
回数実行され、出力は`i*10+j`の並び（`11`・`12`・`21`・`22`、
`i=1,j=1→11`・`i=1,j=2→12`・`i=2,j=1→21`・`i=2,j=2→22`の順）として
1行に現れた。`NEXT j`・`NEXT i`と変数名を付けた`NEXT`も、対応する
ループへ問題なく紐づいた。

### 4.3 `GOSUB`〜`RETURN`

**`GOSUB`は指定した行へ分岐し、`RETURN`で`GOSUB`の次の行へ戻る。**
根拠: 同結果ノート判定Q3（**`gosub_returns`**、B5）。
`10 gosub 100`→（`100 print 1`で`1`）→`110 return`→（`GOSUB`の次の行
`20 print 2`で`2`）→`30 end`の順どおり、出力は`1`→`2`の順で現れた。

**`GOSUB`は入れ子にできる。** 根拠: `l4-s5c-variables-flow-results.md`
（`672539e`）判定Q8、**`nested_gosub_ok`**（C10）。`10 gosub 30`→
`30 gosub 50`→（`50 print 5`で`5`）→`60 return`→（`30`行の`GOSUB`の次
へ戻り）`40 return`→（`10`行の`GOSUB`の次へ戻り）`20 end`という、
`GOSUB`が2重に入れ子になった構成で、両方の`RETURN`が正しく元の呼び出し
元へ戻り、`50 print 5`による出力`5`が現れた。

### 4.4 変数 — 代入と参照

**変数への代入・参照・演算は、代入した値を反映した計算結果を出力する。**
根拠: `l4-s5b-run-control-flow-results.md`判定Q4（記述のみ）。

- B7（`10 a=5`/`20 print a*2`）: 出力は`10`（`5*2`の計算結果）。
- B8（`10 i=1.5`/`20 print i+1`）: 出力は`2.5`（`1.5+1`の計算結果）。

**観測から言えること**: 無印（接尾辞無し）の変数に整数（B7の`a`）・小数
（B8の`i`）のどちらを代入しても、代入した値がそのまま計算に使われる。

**観測から言えないこと**: 無印の変数の内部の型（単精度浮動小数点として
扱われているか、整数型が別に存在し値によって自動的に切り替わるか等）は、
`PRINT`の出力（第5.3節、[l4-basic.md](l4-basic.md)）から間接的に推測でき
そうに見えるが、本測定では変数の型を直接確かめる腕（例えば整数の範囲を
超える値を代入して昇格の有無を見る腕）が無く、確認していない（第6節
「未確定」）。

### 4.4a 変数名の有効文字数

**変数名は、少なくとも3文字目までが区別される。** 根拠:
`l4-s5c-variables-flow-results.md`判定Q3、**`more_significant`**（C3）。
`10 abc=1`/`20 abd=2`/`30 print abc`を`RUN`した結果、出力は`1`のままで、
`abd`への代入の影響を受けなかった。**`abc`と`abd`は3文字目（`c`/`d`）
まで区別される別の変数だった。** 何文字目まで区別されるかの上限は
本測定では突き止めておらず、未確定のまま（第6節）。

### 4.4b 整数変数（`%`）への代入の丸め

**整数変数（`%`接尾辞）へ小数を代入すると、ちょうど半分になる値は
絶対値の大きい側へ丸められる。** 根拠: 同結果ノート判定Q4、
**`rounds_half_away`**（C4・C5・C12）。

- C4（`10 a%=5/2`/`20 print a%`、`5/2=2.5`）: 出力は`3`（絶対値の大きい
  側`3`へ丸められた。最近接偶数丸めなら`2`になるはずだが、そうならな
  かった）。
- C5（`10 a%=-5/2`/`20 print a%`、`-5/2=-2.5`）: 出力は`-3`（C4と対称に、
  絶対値の大きい側`-3`へ丸められた）。
- C12（`10 a=1`/`20 a%=a+0.5`、`1+0.5=1.5`）: 出力は`2`（絶対値の大きい
  側。最近接偶数丸めでも同じく`2`になるためこの1腕単独では区別できない
  が、C4・C5が明確に`rounds_half_away`を示しているため矛盾しない）。

この丸めの方向は、`PRINT`の浮動小数点の丸め半端（[l4-basic.md](l4-basic.md)
第5.3節、「半分は絶対値の大きい側」）と同じ形である。

### 4.4c 倍精度変数（`#`）への代入と精度

**単精度の演算結果を倍精度変数へ代入すると、単精度の丸め誤差に由来する
桁の乱れが倍精度の桁数のまま表示される。倍精度の演算結果を代入すると、
乱れは現れない。** 根拠: 同結果ノート判定Q5（記述のみ、C6・C7）。

- C6（`10 a#=1/3`/`20 print a#`、`1/3`は単精度どうしの演算）: 出力は
  `.3333333432674408`（小数点以下16桁）。単精度で計算した近似値が
  そのまま倍精度の桁数で表示され、7桁目以降（`3333334...`）に単精度の
  丸め誤差に由来するとみられる乱れた桁が現れた。
- C7（`10 a#=1#/3`/`20 print a#`、`1#/3`は倍精度どうしの演算）: 出力は
  `.3333333333333333`（小数点以下16桁、全て`3`）。C6のような桁の乱れは
  現れなかった。

**単精度→倍精度の変換そのものは正確に行われている。** C6の食い違いは
「単精度で計算した後に倍精度へ変換した」ことによる単精度側の丸め誤差の
表出であり、変換自体（単精度の値を倍精度の桁数で表示すること）が不正確
なのではない。これは[l4-basic.md](l4-basic.md)第5.1節が観測した、単精度
定数から倍精度への型の扱いの記述と整合する。

### 4.4d 文字列変数

**文字列変数への代入・参照・`PRINT`は、代入した文字列をそのまま出力
する。** 根拠: 同結果ノート判定Q6、**`string_ok`**（C8）。`10 a$="12"`/
`20 print a$`を`RUN`した結果、出力は`12`だった。**文字列の中身が数字
以外のときの出力は、本測定の記録の規則（数字で始まり表示可能ASCIIだけ
の行のみ文字コードを記録する規則）では観測しておらず、未確定のまま**
（第6節。今回は数値分類器でそのまま扱える`"12"`という中身をあえて選んで
測定したため）。

### 4.5 `STOP` と実行中の誤り

**`STOP`は、そこでプログラムの実行を止め、それ以降の行は実行されない。
出力は1行（件数のみ記録、文言は書かない）。** 根拠: 同結果ノート判定Q5
（記述のみ、B9）。`10 print 1`/`20 stop`/`30 print 2`を`RUN`した結果、
`1`（`10`行の出力）の後に`other`分類の行が1行（非空白セル件数10、桁範囲
0-11）現れて`Ok`に至り、`30`行（`print 2`）に相当する出力（`2`）は
現れなかった。**`STOP`以降の行が実行されなかったことと整合する。**

**実行中に構文の誤りが起きた場合も、出力は1行（件数のみ記録）。**
根拠: 同結果ノート判定Q5（記述のみ、B10）。`10 print 1+`（構文として
不完全な式）を`RUN`した結果、`run`の入力エコー行の直後に`other`分類の
行が1行（非空白セル件数19、桁範囲0-21）現れ、`Ok`に至った。

**`STOP`・実行中の誤りの出力行の文言は、測定では確かめていない。**
禁止事項7によりエラーメッセージ等の本文は測定で扱っておらず、上記の
2腕とも件数・桁範囲・「数字0-9のコードを持つセルが含まれるか」という
真偽値だけを記録している（具体的な数字・行番号の値・文言は一切記録
していない）。`STOP`・実行中の誤りのメッセージの文言そのものは、直接
モードの構文の誤り（[l4-basic.md](l4-basic.md)第6節・第7.1節）と同様、
**マニュアルのエラーメッセージ一覧**（[l4-basic.md](l4-basic.md)第7.1節、
「XX in 行番号」のような行番号付きの形を含む資料の記載）を参照する形に
とどめ、実機・エミュレータの画面表示と一致するかどうかは本版では確認
していない（未確定、第6節）。

### 4.6 止まらないプログラム（参考、判定に含めない）

`l4-s5b`のB11（`10 print 1`/`20 goto 10`、無限ループ）は、`Ok`行が現れる
ことがないため判定Q1〜Q6のいずれにも含めない（事前登録が明示的に定めた
扱い）。打った行より下の出力領域の非空白セル件数は33件で2走とも一致し、
**画面が`PRINT`の出力で埋まっている状態**（無限ループが実際に出力を
生成し続けていること）を確認した。実行を途中で止める手段（`STOP`キー等）
は本測定の器具では注入できず、確認していない（第6節「未確定」）。

## 5. 参考 — トークン番号との関係（実装への注意）

**`LIST`の目標は打鍵の文字どおりの再現であり、公式のトークンの並び・
番号とは無関係である。** 語の一覧・トークン番号の割り当て規則
（`docs/notes/l4-token-design.md`・`src/l4_basic/tokens.tsv`、辞書順に
`0x80`から採番）は自作BASICが内部でプログラムをどう格納するかを決める
自前の規則であり、公式ROMの内部表現を読み取ったものではない（禁止事項2）。
本書の第2節が定める`LIST`の出力書式（行番号・大文字化・空白の保持・`?`展開）
は、内部のトークン化方式によらず**打鍵した文字列を再構成した結果の見え方**
として実装すればよい（ゴールA、`docs/notes/l4-design.md`）。トークン番号の
表そのものはこの仕様書の対象外であり、書き写さない。
