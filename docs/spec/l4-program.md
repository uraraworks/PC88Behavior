# L4 プログラムモード — 行の入力と LIST

仕様書 第14.16版 / 2026-10-10

測定対象: エミュレータ QUASI88 libretro 版、コア既定 N88 V2、ディスク無し、公式ROM一式。

`docs/spec/` の書き方は [l3-main.md](l3-main.md)・[l4-basic.md](l4-basic.md) に倣う。
**「観測」と「推定」を節ごとに分け、実装は観測にだけ従う。** 「観測」と「資料の
記載」も節を分ける（測定 > 資料の原則。資料の記載は判定の根拠にしない）。
**画面本文（公式ディスクの一覧・第三者由来の文字列など）はこの文書のどこにも
書かない**（`CLAUDE.md` 禁止事項7）。書いてよいのは、自分で指定した打鍵文字列
とその直接の結果（自分で打ったプログラムを処理系が表示したもの、`LIST`の出力
を含む）、非空白セルの件数・位置範囲、行・列番号までである
（`l4-s5a-program-line-input-list-format-preregistration.md`「記録する内容」節
の区分を踏襲）。エラー等の行（`other_line`）は文言を書かず、件数と範囲だけを
記録する。

画面出力・行入力・スクロール・キー入力・テキストVRAMの構造は
[l3-main.md](l3-main.md)（第3版）に、直接モードの`PRINT`の書式・行の扱いは
[l4-basic.md](l4-basic.md)（第3.7版）にすでにあるので、ここでは重複して書かず
参照のみ行う。本書は**プログラムモード**（行番号つきの行の入力と`LIST`）を
対象とする、段階5の最初の仕様書である。

## 1. 観測 — 行番号つきの行を打ったときの画面の反応

**行番号つきの行を打っても、その行は打鍵のエコーだけが画面に残り、`Ok`も
それ以外の出力も現れない。** これは直接モードの文（[l4-basic.md](l4-basic.md)
第1節、打った行の直後に出力→`Ok`が続く）とは異なる。

根拠: `l4-s5a-program-line-input-list-format-results.md`「腕ごとの構造」節・
「other_lineが出た腕」節。12腕（A1〜A12）は、いずれも`new`（行番号を伴わない
直接モードのコマンド）→行番号つきの行（1〜2行）→`list`（行番号を伴わない
直接モードのコマンド）という構成で打鍵されたが、記録器が「打った行より下・
`Ok`行より上」の範囲で捉えた`other_line`（数字で始まらない、またはASCII範囲外
を含む行）は、**12腕全てで例外なく2行だけ**だった。

- 1行目: `new`の直後に現れる`Ok`行（相対行1）
- 2行目: `list`の入力そのもののエコー行

行番号つきの行を1行だけ打った腕（A1〜A5・A9〜A12）でも、2行打った腕
（A6〜A8）でも、`other_line`の数は変わらず2行のままだった。**行番号つきの
行を打った直後に`Ok`や他の出力が挟まることは一度も無かった。** `new`・`list`
という行番号を伴わないコマンドだけが、直接モードと同じように`Ok`（`new`の
場合）や出力（`list`の場合、第2節）を伴う。

## 2. 観測 — `LIST` の出力書式

行番号の途中の空白・65529上限での読み取りと本文の切り分けは [l4-basic.md 第14.7節](l4-basic.md#147-行番号の読み取りl4-s5j) を参照。

対象は`l4-s5a`の12腕（A1〜A12）。以下の打鍵文字列・`LIST`出力は、いずれも
自分で打ったプログラムを処理系がそのまま表示したものであり、禁止事項7の対象外
（事前登録「記録する内容」節が明示的に許可）。

| 腕 | 打鍵文字列（`new`〜`list`の要点） | `LIST`の出力 |
|---|---|---|
| A1 | `10 print 1` | `10 PRINT 1` |
| A2 | `10print1`（空白無し） | `10 PRINT1` |
| A3 | `10 print  1`（`print`の後に空白2つ） | `10 PRINT  1` |
| A4 | `10 ?1`（`?`の後に空白無し） | `10 PRINT 1` |
| A5 | `10 print 1:print 2` | `10 PRINT 1:PRINT 2` |
| A9 | `65529 print 1`（大きい行番号） | `65529 PRINT 1` |
| A10 | `10 print "abc"`（文字列） | `10 PRINT "abc"` |
| A11 | `10 print 1.5`（小数） | `10 PRINT 1.5` |
| A12 | `10 print 1234567890123#`（長い倍精度定数） | `10 PRINT 1234567890123#` |

根拠: `l4-s5a-program-line-input-list-format-results.md`「腕ごとの記録」節・
判定Q2。

### 2.1 行番号の書式

**行番号の前後に余分な空白は付かない。** 打った行番号の直後は、元の打鍵と
同じ間隔（空白1個、または打鍵どおりの間隔）になる。A1〜A12いずれも、行番号
の前に余分な空白は挿入されず、行頭（相対桁0相当）からそのまま数字が始まる。

### 2.2 命令語の大文字化

**（2026-10-01 追記: `print` 以外の語・変数名・`REM`・`DATA`・`GO TO`・`?` の規則は
[l4-basic.md](l4-basic.md) 第14節。ここの根拠の12腕は `print` と `?` だけだった。）**

**小文字で打った命令語は、`LIST`の出力では大文字化される。** 打鍵は小文字
`print`で与えたが（打鍵注入の仕様、[l4-basic.md](l4-basic.md)踏襲）、A1〜A12
全腕で`LIST`出力は`PRINT`と大文字で表示された。

### 2.3 命令語の後の空白・`?`展開との食い違い

**命令語の後の空白は、元の打鍵にあればそのまま保持され、無ければ挿入
されない。** ただし`?`を`PRINT`に展開する場合だけ、打鍵に空白が無くても
`PRINT`の後に空白が挿入される。

| 腕 | 打鍵 | `LIST`出力 | 命令語後の空白 |
|---|---|---|---|
| A1 | `10 print 1`（`print`の後に空白あり） | `10 PRINT 1` | 保持（あり） |
| A2 | `10print1`（`print`の後に空白無し） | `10 PRINT1` | 保持（無し） |
| A4 | `10 ?1`（`?`の後に空白無し） | `10 PRINT 1` | **`?`→`PRINT`展開時だけ挿入される** |

**A2とA4は、どちらも「命令語の直後に空白無しで打った」という同じ形の入力
だが、`LIST`の出力での空白挿入の有無が異なる。** `print`とそのまま打った
場合（A2）は空白が挿入されないままだが、`?`と打って`PRINT`に展開される
場合（A4）は空白が挿入される。この食い違いの原因（内部表現の違い等）は
ROM内部構造の話になるため立ち入らず、**表面に現れた形だけを実装の対象と
する**（根拠: 結果ノート「観測」節）。

### 2.4 `:` の前後の空白

**`:`の前後に余分な空白は入らない。** A5（`print 1:print 2`）の`LIST`出力
は`PRINT 1:PRINT 2`で、`:`の前後は打鍵どおり空白無しのままだった。

### 2.5 打ったときの余分な空白の保持

**打鍵で入れた余分な空白（連続する複数の空白）は、そのままの個数で保持
される。** A3（`print`の後に空白を2つ打った`print  1`）の`LIST`出力は
`PRINT  1`で、空白2個がそのまま2個で残った（1個に詰められたり、0個に
削られたりしなかった）。

### 2.6 数値の定数・文字列

**数値の定数（小数・`#`付き倍精度定数）も文字列リテラルも、書式の変換を
受けず打鍵どおりに`LIST`出力へ再現される。**

- A10（文字列`"abc"`）: 引用符の追加・削除なく`"abc"`のまま。
- A11（小数`1.5`）: 小数点の位置の変更なく`1.5`のまま。
- A12（`#`付きの長い倍精度定数`1234567890123#`）: `#`の省略・桁の変更なく
  `1234567890123#`のまま。

### 2.7 大きい行番号

**大きい行番号（`65529`）も、先頭に余分な0や空白を挟む書式にはならず、
そのまま出力される。** A9の`LIST`出力は`65529 PRINT 1`だった。

## 3. 観測 — 同じ行番号の打ち直し・行番号だけの行・行番号順の並び

### 3.1 同じ行番号を打ち直すと行が置き換わる（`replaced`）

根拠: `l4-s5a-program-line-input-list-format-results.md` Q3（A7）。行番号
`10`で`print 1`→`print 2`の順に2回打った（`10 print 1`・`10 print 2`）結果、
`LIST`出力は`10 PRINT 2`の1行だけで、**先に打った`print 1`の内容は残らず、
後から打った内容で置き換わった。**

### 3.2 行番号だけを打つとその行が削除される（`deleted`）

根拠: 同結果ノートQ3（A8）。`10 print 1`・`20 print 2`を打った後、行番号
`10`だけを打った（内容を続けない）結果、`LIST`出力は`20 PRINT 2`の1行だけで、
**行番号`10`の行はプログラムから消えた。**

### 3.3 `LIST`は打った順ではなく行番号順に並ぶ（`sorted`）

根拠: 同結果ノートQ4（A6）。`20 print 2`→`10 print 1`の順（行番号の大きい
方を先）に打ったが、`LIST`出力は`10 PRINT 1`→`20 PRINT 2`の順（行番号の
小さい方が先）になった。**`LIST`の並びは行番号順であり、打った順ではない。**

## 4. 観測 — `RUN` とプログラムの実行

対象は`l4-s5b`の12腕（B1〜B12）。以下の打鍵文字列・出力は、いずれも自分で
打ったプログラムを`RUN`が`PRINT`で出力した数値であり、禁止事項7の対象外
（事前登録「記録する内容」節・「本文を出さない取り扱い」節が明示的に許可）。
`STOP`・実行中の誤りの出力（4.5節）だけは件数と範囲のみで、値・文言は書かない。

| 腕 | 打鍵文字列（`new`〜`run`の要点） | `RUN`の出力 |
|---|---|---|
| B1 | `10 print 1` / `20 print 2` | `1` → `2`（2行） |
| B2 | `10 for i=1 to 3` / `20 print i` / `30 next` | `1` → `2` → `3`（3行） |
| B3 | `10 for i=1 to 10 step 3` / `20 print i;` / `30 next` | `1`・`4`・`7`・`10`（`;`で1行に4値） |
| B4 | `10 for i=3 to 1` / `20 print i` / `30 next` / `40 print 9` | `9`のみ（本体の出力無し） |
| B5 | `10 gosub 100` / `20 print 2` / `30 end` / `100 print 1` / `110 return` | `1` → `2`（2行） |
| B6 | `10 goto 30` / `20 print 1` / `30 print 2` | `2`のみ（`20`行は飛ばされる） |
| B7 | `10 a=5` / `20 print a*2` | `10` |
| B8 | `10 i=1.5` / `20 print i+1` | `2.5` |
| B12 | （プログラム無し、`new`の直後に`run`） | 出力行無し |

根拠: `l4-s5b-run-control-flow-results.md`「腕ごとの記録」節・判定Q1〜Q6。

### 4.1 行番号順の実行・`GOTO`・`END`・空のプログラム

**`RUN`は行番号の順にプログラムを実行する。** 根拠: 同結果ノート判定Q1
（**`in_order`**、B1・B6）。B1（`10 print 1`/`20 print 2`）は`1`→`2`の順で
出力され、行番号順の実行そのものを確認した。

**`GOTO`は指定した行番号へ飛び、その間の行は実行されない。** B6
（`10 goto 30`/`20 print 1`/`30 print 2`）は`20`行（`print 1`）を飛ばして
`30`行（`print 2`）だけが実行され、出力は`2`のみだった。

**空のプログラムを`RUN`すると、出力無しでそのまま`Ok`になる。** 根拠:
同結果ノート判定Q6（記述のみ、B12）。`new`の直後に何も行を打たず`run`した
結果、出力行は0行のまま`Ok`行が現れた。誤りは発生しなかった。

**`RUN`直後の入力エコー行のさらに後、実行結果の出力に続いて`Ok`が現れる。**
これは直接モードの並び（[l4-basic.md](l4-basic.md)第1節、打った行→出力→
`Ok`）と同じ形で、`run`のエコー行を起点に、実行結果の出力→`Ok`という順に
なる（`l4-s5b-run-control-flow-results.md`「腕ごとの記録」節の`run`エコー
行・`Ok`行の相対位置）。

**`RUN`に行番号を指定すると、その行から実行が始まる（それより前の行は
実行されない）。** 根拠: `l4-s5c-variables-flow-results.md`（`672539e`）
判定Q7、**`starts_at_line`**（C9）。`10 print 1`/`20 print 2`を打った後
`run 20`（行番号`20`を指定）を実行した結果、出力は`2`の1行だけで、`10`
行の`print 1`に相当する出力（`1`）は現れなかった。

### 4.2 `FOR`〜`NEXT`

**`FOR`〜`NEXT`の本体は、開始値から終了値まで（既定の刻み幅は`+1`）
`STEP`の刻みで実行され、開始値が終了値を最初から超えている場合は本体を
1回も実行しない。** 根拠: 同結果ノート判定Q2。

- B2（`for i=1 to 3`、刻み幅の指定無し=既定`+1`）: **`body_runs_3`**。
  `i=1,2,3`の3回、本体（`print i`）が実行され`1`・`2`・`3`が出力された。
- B3（`for i=1 to 10 step 3`）: **`body_runs_4`**。`i=1,4,7,10`の4回で
  終了した（次は`i=13`で10を超えるため）。
- B4（`for i=3 to 1`、`step`指定無し=既定`+1`、開始値3が終了値1を最初から
  超えている）: **`body_skipped`**。本体（`20 print i`）の出力は一切現れず、
  ループの外にある`40 print 9`の`9`だけが出力された。**`FOR`の本体が
  1回も実行されなかった。**

**ループを抜けた後の制御変数は、終了値を1回超えた値のまま残る（終了値
そのものではない）。ループの前に持っていた値は、`FOR`の初期化で
上書きされ影響しない。** 根拠: `l4-s5c-variables-flow-results.md`
（`672539e`）判定Q1、**`after_loop_4`**（C1・C11）。

- C1（`10 for i=1 to 3`/`20 next`/`30 print i`）: ループを抜けた後
  `print i`の出力は`4`。`NEXT`で3回目の加算の後、条件`i>3`を満たした
  時点の値がそのまま残る（終了値`3`ではなく、それを1回超えた`4`）。
- C11（`10 i=10`/`20 for i=1 to 3`/`30 next`/`40 print i`、ループ前に
  `i=10`を代入済み）: 出力はC1と同じ`4`。**`FOR`が`i`を`1`へ初期化する
  ため、ループ開始前の既存値`10`の影響は残らなかった。**

### 4.2a `FOR` の入れ子・`NEXT` への変数名

**`FOR`は入れ子にでき、`NEXT`に変数名を付けて対応するループを指定
できる。** 根拠: 同結果ノート判定Q2、**`nested_ok`**（C2）。
`10 for i=1 to 2`/`20 for j=1 to 2`/`30 print i*10+j;`/`40 next j`/
`50 next i`を`RUN`した結果、内側`j`・外側`i`のループが期待どおりの
回数実行され、出力は`i*10+j`の並び（`11`・`12`・`21`・`22`、
`i=1,j=1→11`・`i=1,j=2→12`・`i=2,j=1→21`・`i=2,j=2→22`の順）として
1行に現れた。`NEXT j`・`NEXT i`と変数名を付けた`NEXT`も、対応する
ループへ問題なく紐づいた。

### 4.3 `GOSUB`〜`RETURN`

**`GOSUB`は指定した行へ分岐し、`RETURN`で`GOSUB`の次の行へ戻る。**
根拠: 同結果ノート判定Q3（**`gosub_returns`**、B5）。
`10 gosub 100`→（`100 print 1`で`1`）→`110 return`→（`GOSUB`の次の行
`20 print 2`で`2`）→`30 end`の順どおり、出力は`1`→`2`の順で現れた。

**`GOSUB`は入れ子にできる。** 根拠: `l4-s5c-variables-flow-results.md`
（`672539e`）判定Q8、**`nested_gosub_ok`**（C10）。`10 gosub 30`→
`30 gosub 50`→（`50 print 5`で`5`）→`60 return`→（`30`行の`GOSUB`の次
へ戻り）`40 return`→（`10`行の`GOSUB`の次へ戻り）`20 end`という、
`GOSUB`が2重に入れ子になった構成で、両方の`RETURN`が正しく元の呼び出し
元へ戻り、`50 print 5`による出力`5`が現れた。

### 4.4 変数 — 代入と参照

**変数への代入・参照・演算は、代入した値を反映した計算結果を出力する。**
根拠: `l4-s5b-run-control-flow-results.md`判定Q4（記述のみ）。

- B7（`10 a=5`/`20 print a*2`）: 出力は`10`（`5*2`の計算結果）。
- B8（`10 i=1.5`/`20 print i+1`）: 出力は`2.5`（`1.5+1`の計算結果）。

**観測から言えること**: 無印（接尾辞無し）の変数に整数（B7の`a`）・小数
（B8の`i`）のどちらを代入しても、代入した値がそのまま計算に使われる。

**観測から言えないこと**: 無印の変数の内部の型（単精度浮動小数点として
扱われているか、整数型が別に存在し値によって自動的に切り替わるか等）は、
`PRINT`の出力（第5.3節、[l4-basic.md](l4-basic.md)）から間接的に推測でき
そうに見えるが、本測定では変数の型を直接確かめる腕（例えば整数の範囲を
超える値を代入して昇格の有無を見る腕）が無く、確認していない（第8節
「未確定」）。

### 4.4a 変数名の有効文字数

**変数名は、少なくとも3文字目までが区別される。** 根拠:
`l4-s5c-variables-flow-results.md`判定Q3、**`more_significant`**（C3）。
`10 abc=1`/`20 abd=2`/`30 print abc`を`RUN`した結果、出力は`1`のままで、
`abd`への代入の影響を受けなかった。**`abc`と`abd`は3文字目（`c`/`d`）
まで区別される別の変数だった。** 何文字目まで区別されるかの上限は
本測定では突き止めておらず、未確定のまま（第8節）。

### 4.4b 整数変数（`%`）への代入の丸め

**整数変数（`%`接尾辞）へ小数を代入すると、ちょうど半分になる値は
絶対値の大きい側へ丸められる。** 根拠: 同結果ノート判定Q4、
**`rounds_half_away`**（C4・C5・C12）。

- C4（`10 a%=5/2`/`20 print a%`、`5/2=2.5`）: 出力は`3`（絶対値の大きい
  側`3`へ丸められた。最近接偶数丸めなら`2`になるはずだが、そうならな
  かった）。
- C5（`10 a%=-5/2`/`20 print a%`、`-5/2=-2.5`）: 出力は`-3`（C4と対称に、
  絶対値の大きい側`-3`へ丸められた）。
- C12（`10 a=1`/`20 a%=a+0.5`、`1+0.5=1.5`）: 出力は`2`（絶対値の大きい
  側。最近接偶数丸めでも同じく`2`になるためこの1腕単独では区別できない
  が、C4・C5が明確に`rounds_half_away`を示しているため矛盾しない）。

この丸めの方向は、`PRINT`の浮動小数点の丸め半端（[l4-basic.md](l4-basic.md)
第5.3節、「半分は絶対値の大きい側」）と同じ形である。

### 4.4c 倍精度変数（`#`）への代入と精度

**単精度の演算結果を倍精度変数へ代入すると、単精度の丸め誤差に由来する
桁の乱れが倍精度の桁数のまま表示される。倍精度の演算結果を代入すると、
乱れは現れない。** 根拠: 同結果ノート判定Q5（記述のみ、C6・C7）。

- C6（`10 a#=1/3`/`20 print a#`、`1/3`は単精度どうしの演算）: 出力は
  `.3333333432674408`（小数点以下16桁）。単精度で計算した近似値が
  そのまま倍精度の桁数で表示され、7桁目以降（`3333334...`）に単精度の
  丸め誤差に由来するとみられる乱れた桁が現れた。
- C7（`10 a#=1#/3`/`20 print a#`、`1#/3`は倍精度どうしの演算）: 出力は
  `.3333333333333333`（小数点以下16桁、全て`3`）。C6のような桁の乱れは
  現れなかった。

**単精度→倍精度の変換そのものは正確に行われている。** C6の食い違いは
「単精度で計算した後に倍精度へ変換した」ことによる単精度側の丸め誤差の
表出であり、変換自体（単精度の値を倍精度の桁数で表示すること）が不正確
なのではない。これは[l4-basic.md](l4-basic.md)第5.1節が観測した、単精度
定数から倍精度への型の扱いの記述と整合する。

### 4.4d 文字列変数

**文字列変数への代入・参照・`PRINT`は、代入した文字列をそのまま出力
する。** 根拠: 同結果ノート判定Q6、**`string_ok`**（C8）。`10 a$="12"`/
`20 print a$`を`RUN`した結果、出力は`12`だった。**文字列の中身が数字
以外のときの出力は、本測定の記録の規則（数字で始まり表示可能ASCIIだけ
の行のみ文字コードを記録する規則）では観測しておらず、未確定のまま**
（第8節。今回は数値分類器でそのまま扱える`"12"`という中身をあえて選んで
測定したため）。

### 4.5 `STOP` と実行中の誤り

**`STOP`は、そこでプログラムの実行を止め、それ以降の行は実行されない。
出力は1行（件数のみ記録、文言は書かない）。** 根拠: 同結果ノート判定Q5
（記述のみ、B9）。`10 print 1`/`20 stop`/`30 print 2`を`RUN`した結果、
`1`（`10`行の出力）の後に`other`分類の行が1行（非空白セル件数10、桁範囲
0-11）現れて`Ok`に至り、`30`行（`print 2`）に相当する出力（`2`）は
現れなかった。**`STOP`以降の行が実行されなかったことと整合する。**

**実行中に構文の誤りが起きた場合も、出力は1行（件数のみ記録）。**
根拠: 同結果ノート判定Q5（記述のみ、B10）。`10 print 1+`（構文として
不完全な式）を`RUN`した結果、`run`の入力エコー行の直後に`other`分類の
行が1行（非空白セル件数19、桁範囲0-21）現れ、`Ok`に至った。

**`STOP`・実行中の誤りの出力行の文言は、測定では確かめていない。**
禁止事項7によりエラーメッセージ等の本文は測定で扱っておらず、上記の
2腕とも件数・桁範囲・「数字0-9のコードを持つセルが含まれるか」という
真偽値だけを記録している（具体的な数字・行番号の値・文言は一切記録
していない）。`STOP`・実行中の誤りのメッセージの文言そのものは、直接
モードの構文の誤り（[l4-basic.md](l4-basic.md)第6節・第7.1節）と同様、
**マニュアルのエラーメッセージ一覧**（[l4-basic.md](l4-basic.md)第7.1節、
「XX in 行番号」のような行番号付きの形を含む資料の記載）を参照する形に
とどめ、実機・エミュレータの画面表示と一致するかどうかは本版では確認
していない（未確定、第8節）。

### 4.6 止まらないプログラム（参考、判定に含めない）

`l4-s5b`のB11（`10 print 1`/`20 goto 10`、無限ループ）は、`Ok`行が現れる
ことがないため判定Q1〜Q6のいずれにも含めない（事前登録が明示的に定めた
扱い）。打った行より下の出力領域の非空白セル件数は33件で2走とも一致し、
**画面が`PRINT`の出力で埋まっている状態**（無限ループが実際に出力を

### 4.10 変数・配列・DIM・ERASE・メモリ消費（l4-s9y。観測）

根拠: [結果](../notes/l4-s9y-results.md)、[事前登録](../notes/l4-s9y-dim-preregistration.md)
（822463f）、[追補1](../notes/l4-s9y-addendum1-adoption.md)、結果コミット **1569b1e**。
追補1で固定した143腕を公式で2走し、全数値関門を通過した。
本節は採用された観測を規則と固定点に起こす。旧 l4-s5d の DIM・宣言なし参照の
観測とも整合し、既定上限10を推定から観測へ更新する。

#### 4.10.1 宣言・要素・型と単純変数（観測）

`DIM a%(u1,u2,…)` の各引数は要素数ではなく最大添字。下限は0で、
要素数は **`E=∏(uj+1)`**。複数配列は `DIM a%(2),b%(3)` のように列挙する。
新しい配列は整数・単精度・倍精度の値が0、文字列は空（`LEN=0`）。
型の選択は4.21節（接尾辞優先、無ければ型宣言表）に従う。

同じ名前でも型が違う配列は別で、単純変数と配列も別である。
`a%=9` と `DIM a%(2),a!(2),a#(2),a$(2),b%(2)` は共存し、
添字1に順に3・4・5・長さ2の文字列・8を代入すると各値を独立に取得する。
`ERASE a%` 後も単純変数 `a%=9`、`b%(1)=8`、`a!(1)=4` が残る。

#### 4.10.2 メモリ配置について規定する範囲 — FRE(0) の差（観測）

**内部の格納形式・物理番地・管理情報や要素の番地の並びは観測していないので規定しない。
本節のメモリ仕様は FRE(0) の減少・回復量であり、物理的な並びは実装の自由である。**
GET の数値対応（4.10.8）は利用者に見える結果として別に満たす。

配列名 `a` の成功確保で、1要素の消費 N と1次元固定分は次のとおり。
測定区間で新しい単純変数が生じないよう、診断変数を先に生成している。
`b=FRE(0)`、DIM直後 `c=FRE(0)` としたときの **`b-c=9+N×E`** を再現する。

| 型 | N（バイト/要素） | 1次元固定分 | 上限0 | 上限999 | 上限2999 |
|---|---:|---:|---:|---:|---:|
| 整数 `%` | 2 | 9 | 11 | 2009 | 6009 |
| 単精度 `!` | 4 | 9 | 13 | 4009 | 12009 |
| 倍精度 `#` | 8 | 9 | 17 | 8009 | DIMはERR 7、続くERASEはERR 5 |
| 文字列 `$`（空要素） | 3 | 9 | 12 | 3009 | 9009 |

各型の上限0・1・9・10・99・999の成功値は同じ式に従う。
文字列の3バイトは空要素の消費であり、内容の領域や代入による追加消費は未測定。

同じ1000整数要素の `DIM a%(999)`、`DIM a%(9,99)`、`DIM a%(9,9,9)` は
それぞれ **2009・2011・2013** バイト消費する。測った1〜3次元では
固定分 **`H(d)=7+2×d`**、全消費 **`H(d)+N×E`** に整合する。
名前長の違い・高次元の固定分には一般化しない。
成功した型別腕では ERASE の `FRE(0)-c` が確保時の減少量と等しく、
上記3形の腕では ERASE 後 `FRE(0)-b=0`。失敗DIM後の診断値0は消費量0の根拠ではない。

**確保できる要素数はメモリ容量によって変わり、固定要素数の上限だけでは決まらない。**

CLEAR自体の境界・FREは [l4-basic.md 第20節](l4-basic.md#20-観測--clear-の上限番地と-frel4-s9d)

#### 4.10.5 宣言なしの自動確保（観測）

未宣言配列は初回の要素参照（読取り・代入）の次元数で、**各上限10・各下限0**として
自動確保される。以後同名同型のDIMはERR 10、次元数不一致や上限超過はERR 9。
1〜3次元で各添字10への代入・読取りが成功して値7、最後の添字11への代入はERR 9。
ERASE後の `a%(10)` 読取りも新たに自動確保して0、続く `a%(11)` はERR 9。

4次元整数の既定配列は11⁴=14641要素を必要とし、通常上限では
最初の代入 `a%(10,10,10,10)=7`、同要素の読取り、最後の添字11への代入が
それぞれERR 7（総誤り3件）。その後 `DIM a%(1)` は成功する。
失敗確保は既存配列として残らず、この結果を「自動配列は3次元まで」という制限にしない。

#### 4.10.6 添字・DIM上限の丸めと評価順（観測）

添字とDIM上限はCINTと同じ最近接整数化を使い、半分は絶対値の大きい側へ丸める。
負の値は丸めた後に判定する。`DIM a%(3)` に値10・11・12・13を入れた参照では次の結果。

| 引数 | 整数化 | 配列参照 |
|---|---:|---|
| −1・−.51・−.5 | −1 | ERR 5 |
| −.49・0・.49 | 0 | 10 |
| .5・1.49 | 1 | 11 |
| 1.5 | 2 | 12 |
| 2.5・3.49 | 3 | 13 |
| 3.5 | 4 | ERR 9 |
| 32767 | 32767 | ERR 9 |
| 32768 | CINTもERR 6 | ERR 6 |
| `"x"` | CINTもERR 13 | ERR 13 |

DIM上限 `.49`・`−.49` は0、`.5` は1、`1.5` は2、`2.5` は3となり、
それぞれ丸めた上限までの添字0〜3への代入だけが通る。
`DIM a%(-.5)` はERR 5、その後の添字0〜3への代入は自動確保により全て成功する。
多次元の `(1.5,2.5)` は `(2,3)`、`(1.49,2.49)` は `(1,2)` の値17を取得し、
`(-.5,1)` はERR 5。

添字の式は左から評価し、**全添字の式評価が配列上限の検査より先**となる。

#### 4.10.7 ERASE・再DIM・CLEAR/RUN/行編集（観測）

`ERASE a%,b%` は添字なしで配列名を列挙し、指定した配列を消す。
成功確保のFRE消費は回復し（4.10.2）、同名単純変数・他型・他名の配列は保持する。
二重DIMはERR 10、ERASEしてからの再DIMは成功し、新要素は0・空文字列となる。
`DIM a%(2,3)`、`a%(1,2)=7`、`ERASE a%`、`DIM a%(4,1)` の後の
`a%(1,1)` は0。複数配列のERASE・再DIMも成功。未宣言配列のERASEはERR 5。
型宣言後のERASEが引く型は4.21.5に従う。

初期値7の配列は **CLEAR・RUN・成功した行の挿入/削除/置換・同内容の打ち直し**で
初期化され、最初の診断参照 `a%(1)` は0を返す。操作なし・存在しない行の削除は
保持し同参照は7。行編集・NEW等の状態全般は4.17に従う。

**この診断参照自身が、初期化後には既定配列を自動確保する。**
その後の `DIM a%(2)` は、初期化・保持を合わせた8腕すべてでERR 10（各腕総誤り1件）。
初期化直後、参照する前の再DIMが成功するかは本段では独立に測っていない。
再DIM成功という事前予測が外れた6腕（clear/run/insert/delete/replace/same）を
ERR 0に読み替えない。

### 4.11 `CONT`

### 4.12 演算子 `^`・`\`・`MOD`

|---|---|---|

「器具の確認」節）。

になるか）は、本測定の腕（正の整数どうしの演算のみ）からは分からない

（第8節）。

**主要な文字列関数（`MID$`・`LEN`・`LEFT$`・`RIGHT$`・`VAL`・`STR$`・

| E4 | `print len("12345")` | `5` | `LEN` |

| E6 | `print right$("12345",2)` | `45` | `RIGHT$` |

### 4.15 整数化 — `INT`・`FIX`・`CINT`

**`INT`は床関数（負の無限大方向への切り捨て）、`FIX`はゼロ方向への
切り捨て、`CINT`の半端は絶対値の大きい側へ丸められる。** 根拠: 同結果
ノート判定Q3（E11〜E14）。

| 腕 | 打鍵文字列 | 出力 | 備考 |
|---|---|---|---|
| E11 | `print int(-1.5)` | `-2` | 床関数（`-1.5`以下の最大の整数） |
| E12 | `print fix(-1.5)` | `-1` | ゼロ方向への切り捨て。`INT`（`-2`）と異なる |
| E13 | `print cint(2.5)` | `3` | **`rounds_half_away`**（絶対値の大きい側） |
| E14 | `print cint(-2.5)` | `-3` | **`rounds_half_away`**（E13と対称） |

**`CINT`の半端の丸め方向は、整数変数（`%`）への代入の丸め
（[l4-program.md](l4-program.md)第4.4b節）や`PRINT`の浮動小数点の丸め
半端（[l4-basic.md](l4-basic.md)第5.3節）と同じ「絶対値の大きい側」で
一貫している。**

### 4.16 `ABS`・`SGN`・`SQR`・`SIN`・`COS`

**`ABS`・`SGN`・`SQR`・`SIN`・`COS`は、割り切れる入力に対しては算術的に
期待される値を返す。** 根拠: 同結果ノート判定Q4（記述のみ、E15・E16）。

| 腕 | 打鍵文字列 | 出力 |
|---|---|---|
| E15 | `print abs(-3);sgn(-3);sgn(0)` | `3`,`-1`,`0` |
| E16 | `print sqr(16);sin(0);cos(0)` | `4`,`0`,`1` |

**割り切れない値（無理数になる`SQR`・端数の残る`SIN`/`COS`/`TAN`/`ATN`/
`EXP`/`LOG`）の値は、`l4-s6a`（第9版で追加）で観測した。** 根拠:
[l4-s6a-transcendental-functions-results.md](../notes/l4-s6a-transcendental-functions-results.md)。
測定対象はSQR・SIN・COS・TAN・ATN・EXP・LOGの7関数、42腕（無理数入力・
大きい引数・小さい引数・倍精度引数・エラー入力を含む）。GW-BASIC
（MIT公開ソース）を命令単位で読んで再現した予測器
（`tools/l4_mbf_oracle_v3.py`）との照合で、38腕中27腕（71%）が一致、
4腕がエラー系一致（`SQR(-1)`・`LOG(0)`・`LOG(-1)`・`EXP(100)`の
オーバーフローはいずれも`Illegal Function Call`/オーバーフローの表示
になった。文言は書かない）。

**単精度の通常の入力（無理数を含む）では、GW-BASIC本来の有効桁数7桁
ではなく6桁で表示される。** これは`l4-basic.md`の浮動小数点PRINT書式
（`l4-s4a`由来）で既に分かっていた既知の食い違いと同じ現象で、`l4-s6a`
でも一貫していた（S1〜S4・S6・N1〜N3・C1〜C3・T1・T3・A1〜A4・A6・
E1〜E4・E7・L1〜L3・L7の27腕がこれで一致）。

**倍精度引数（`#`サフィックス）を渡すと、単精度に丸められずに倍精度
（16桁）の結果が返る。** 根拠: `l4-s6a`のS5(`SQR(2#)`)・N5(`SIN(1#)`)・
A5(`ATN(1#)`)・E5(`EXP(1#)`)・L4(`LOG(2#)`)の5腕。値は数学的に正しい
倍精度近似（例: `ATN(1#)`はπ/4の倍精度近似、`EXP(1#)`はeの倍精度近似）
であり、倍精度のまま計算して倍精度で返しているとみられる。

**大きい引数・極端な引数では、末尾の桁がGW-BASIC本来の位取り縮約の
再現(v3予測器)とずれることがある。** 根拠: `l4-s6a`のN4(`SIN(100)`)・
C4(`COS(100)`)・T4(`TAN(100)`)・T2(`TAN(.5)`)の4腕は末尾1桁が数ULP
ずれ、N7(`SIN(1000000)`)・N6(`SIN(6.283185)`、真値がほぼ0)の2腕は
それより大きくずれた。この食い違いは、後述の`SIN`/`COS`/`TAN`の内部
計算手順（範囲縮約を単精度で行い、丸めをround-half-away化する）で
ほぼ解消したことを`l4-s6b`〜`l4-s6g`の一連の測定で確認した（下記参照）。

### 4.16a `SIN`・`COS`・`TAN`の単精度内部計算手順（`l4-s6b`〜`l4-s6g`で確定）

**`SIN`/`COS`/`TAN`は、範囲縮約（引数を2πで割った余りを求める処理）も
多項式評価（Hornerの多項式近似）も、GW-BASICのソース上の「倍精度で
範囲縮約する」現行手順ではなく、それより旧い「範囲縮約を単精度で行う」
手順に一致し、かつ内部の単精度演算（乗算・加算・減算すべて）が
第5.3a節（`l4-basic.md`）の四則演算の丸め規則（正しい丸め・
tieはround-half-away）に従う。** 根拠:

- `l4-s6b`（`docs/notes/l4-s6b-transcendental-precision-results.md`）
  でGW-BASICソースどおりの倍精度範囲縮約（候補M0）は21腕中2腕(10%)
  しか一致せず、
- `l4-s6c`（`docs/notes/l4-s6c-single-precision-range-reduction-
  results.md`）で範囲縮約を単精度に変えた候補M5が42腕中22腕(52%)まで
  改善し、
- `l4-s6d`〜`l4-s6f`（範囲縮約の乗算・多項式評価の乗算を段階的に
  正しい丸め〔round-half-even〕にする候補M6〜M8）で最終的に
  `l4-s6f`時点は21腕中12腕(57%、実質13腕)まで改善したが、`cos(44)`・
  `tan(44)`の2腕で退行が残り、
- **`l4-s6g`（`docs/notes/l4-s6g-away-rounding-transcendentals-
  preregistration.md`＋結果ノート）で、M8の構造はそのまま内部演算の
  丸めだけをround-half-away化した候補M9が、既存106腕の事後照合で
  102腕(96%)一致（M8の不一致8腕がM9で一致に転じ、M8の一致94腕からの
  退行は0腕）、新規に測定した`SIN`/`COS`/`TAN`15腕（小・中・大の引数、
  `print cdbl(...)`で単精度ビットを16桁全展開して照合）は**15腕
  全て**M9が完全一致し、M8/M0は15腕全て不一致だった。**

残る不一致4腕（`l4-s6b`のA16`sin(6.28)`・A17`sin(6.2831853)`・
A18`sin(6.3)`・A20`sin(10000000)`）は、いずれもSIN固有の別要因
（範囲縮約以外の未特定の原因、丸め方式とは無関係とみられる）が残る
（第8節「未確定」に記載）。

### 4.16b `ATN`・`EXP`・`LOG`の内部計算手順（`l4-s6h`で確定）・`SQR`（未確定のまま）

**`ATN`・`EXP`・`LOG`の内部演算（乗算・加算・減算・除算すべて）も、
`SIN`/`COS`/`TAN`と同じround-half-away丸めに従う。** `l4-s6g`の5腕
ずつ（`docs/notes/l4-s6g-away-rounding-transcendentals-results.md`）
では決定力不足だったが、`l4-s6h`（`docs/notes/l4-s6h-atn-exp-log-
more-arms-preregistration.md`＋結果ノート）で各12腕（+対照2腕）に
広げて再測定し、`print cdbl(...)`による16桁全展開の照合で次の結果を
得た。

| 関数 | 割れた腕数 | M0(even)的中 | M9(away)的中 |
|---|---|---|---|
| ATN | 12 | 2 | 10 |
| EXP | 12 | 0 | **12** |
| LOG | 12 | 0 | 12 |
| 計 | 36 | 2(6%) | **34(94%)** |

- **LOGは12腕全てM9が的中（100%）。**
- **EXPは12腕全てM9が的中（100%）。** 残り1腕（`exp(-7)`）は実測の
  16桁を`l4-s6b`以来の手順（round-half-evenで単精度へ再エンコード→
  ビット比較）でM9予測とULP差0（符号・指数バイト・仮数とも完全一致）
  と確定した。`l4-s6d`/`l4-s6e`のD03（`cos(50)`）・D08（`tan(100)`）
  と同型の「値は一致・16桁表示の最終桁のみ差」であり、単精度の丸め
  方式の食い違いではない。
- **ATNは12腕中10腕M9が的中。** 残り2腕（`atn(1)`・`atn(-1)`）は
  逆にM0が的中し、M9とは1ULP差だった。GW-BASICソース（MATH1.ASM
  1110-1111行、`CMP AH,LOW 201`／`JB`）を再読し、`$ATAN`の`|x|>1`
  判定が現行実装どおり「指数バイトのみ・`>=`」であることを確認した
  うえで、分岐条件だけを`>`に変えた候補でも再計算したが、`x=1`では
  `1/x=1`のため両分岐が数学的に同値になり、結果は現行の`>=`と同じ
  （実測とは不一致）だった。**分岐条件の取り違えではないことを
  確認したが、この1ULP差自体は未解決のまま残す**（境界ちょうどの
  値は`x=±1`しかなく、追加の腕による切り分けはできない）。

**以上により、`ATN`・`EXP`・`LOG`の内部演算のround-half-away丸めは
第4.16a節のSIN/COS/TANと合わせて確定とする。** `ATN`の`|x|=1`の
1ULP差は、丸め方式・分岐条件のいずれにも起因しない未解決事項として
残す（第8節参照）。

`SQR`はM0/M9で予測が割れる腕が(7桁以内の整数・小数を計算的に約76000
通り探索しても)見つからず、確定させられないまま残る（`SQR`自体の
近似精度の限界も別途残る。第8節参照）。

対象は `l4-s9g`（14操作×10検査の本体140腕＋対照10腕、各2走、別の起動）。結果ノート

（`d8579d3`）・追補1（`d3770e2`）。準備は自作プログラムを RUN して STOP で止め、
その停止状態から1操作だけ行い、診断を実行した。誤りは ERR 番号だけを記録し、
画面の文言は書かない。括弧内の名は [l4-basic.md](l4-basic.md) 第7.1節の資料の記載。
**判定: 予測あり137腕と対照10腕が全て一致、不一致0（E_GW 採用）。** 元の判定は
対照が誤りの行の完全一致 exact を要求したため全 gate_failed だったが、公式は誤りの
全腕で exact=false だった。再判定は exact を比較から外した範囲の一致である。

**編集が成功すれば、位置・種類によらず同じ状態が初期化される。** 挿入・削除・置換
（停止した行そのもの、前、後、本文が長くなる置換、同一番号・同一本文の打ち直しを
含む）と引数なしの `CLEAR` は、診断の結果がすべて同じだった。STOP より前か後か、
行が増えるか減るかの差は、10検査のどれにも現れなかった。

**初期化の対象（実装者向けの表）。** ○＝その操作で初期化（無効化）される、
×＝保持される。

| 項目 | 挿入・削除・置換・CLEAR | NEW | 代入・LIST | 存在しない行番号だけの入力 |
|---|---|---|---|---|
| プログラム本文 | 編集内容どおり（CLEAR は保持） | ○（空になる） | × | × |
| 数値変数・配列・文字列変数 | ○（0・0・0、文字列は長さ0） | ○ | ×（代入した変数だけが変わる） | × |
| CONT の再開位置 | ○（CONT は ERR 17、Can't continue） | ○（ERR 17） | × | × |
| GOSUB の戻り先 | ○（RETURN は ERR 3、RETURN without GOSUB。CONT は ERR 17） | ○（CONT は ERR 17） | × | × |
| FOR の続き | ○（NEXT は ERR 1、NEXT without FOR。CONT は ERR 17） | ○（CONT は ERR 17） | × | × |
| READ の位置 | 先頭へ戻る（次の READ は最初の値） | 先頭へ戻る（本文が無いので GOTO 診断は不可） | × | × |
| ON ERROR の設定 | ○（ERR 5 を捕捉せず誤りで止まる） | ○ | × | ×（設定中は ERR 8 が誤り処理へ飛ぶ） |
| RESUME の保存 | ○（RESUME NEXT は ERR 20、RESUME without error。CONT は ERR 17） | ○（CONT は ERR 17） | × | 記述のみ（下記） |

NEW の診断で GOTO 110 は行が無いため ERR 8（Undefined line number）になり、
DATA・ON ERROR・RETURN・NEXT・RESUME の個別の無効化は NEW では GOTO では観測できない
（CONT の診断は他と同じ ERR 17）。**「消える」と「先頭へ戻る」は区別する。**
READ の位置は消えず先頭へ戻る。

根拠（腕ID）: 保持側は `none-*`・`list-*`・`assign-*`・`missing-vars/cont/gosub/for/data/return-goto/next-goto`。
初期化側は `insert-*`・`delete-*`・`replace-*`・`clear-*` の各検査、NEW は `new-*`。

**直接モードの代入と LIST は、何も初期化しない。** `a=29` のあとの値は
`s9h 1 29 23 3`（変更した変数だけが変わる）。LIST の前後で CONT・GOSUB・FOR・READ・
ON ERROR・RESUME が全て続行できた。

**存在しない行番号だけの入力は ERR 8（Undefined line number）を出すが、状態を保持する。**
操作の段階の誤りは番号8の包含 true、完全一致 false。

**予測を立てなかった3腕（記述のみ、規則にしない）。**
- `missing-onerror`: ON ERROR 設定中の存在しない行番号の入力は、直接の誤りの行を出さず
  誤り処理へ飛んだ（ERR 8 を示す印、RESUME 後の終了印）。その後の GOTO 110 は
  設定が残っていて ERR 5 を捕捉した。
- `missing-resume`・`missing-resume-goto`: 誤り処理の中の状態で入力した場合は ERR 8 が
  捕捉されずに出て、その後の診断（CONT／GOTO 110）は誤りなしで行100の印だけが出た
  （RESUME 完了の印は出ない）。2腕は同じ観測。理由は未確定。

**exact の差。** 公式は誤りが出た全96腕で番号の包含 true・完全一致 false だった。
自作は直接モードの誤りの行で完全一致 true になるため、**直接モードの誤りの行の形は
公式と自作で違う**。差の中身は推定せず記録しない（第8節36項）。

**決めなかったこと。** LOAD・MERGE による本文・状態の変化、CHAIN、スクリーンエディタでの
行編集中の挙動、内部ポインタの消去方法、CLEAR の引数、乱数・イベント・ファイル・
描画状態の初期化、ON ERROR／RESUME 設定中の存在しない行入力の仕組み。

### 4.18 `ON` 式 `GOTO`/`GOSUB`・`LET`・`WHILE`〜`WEND`（l4-s9j）

対象は `l4-s9j`（本体88腕＋対照12腕、各2走、別の起動）。結果ノート
`l4-s9j-results.md`、事前登録 `l4-s9j-on-let-while-preregistration.md`（4986049）・
追補1（f654cca）。プログラム中の誤りは `ON ERROR GOTO` で捕捉し、誤り番号と、誤りの前に
代入した p を記録した。直接モードの誤りは番号の包含だけを使う。誤りの番号は
[l4-basic.md](l4-basic.md) 第7.1節の表のとおり。**判定: 予測あり84腕が全て一致、不一致0**
（元の判定は捕捉した ERR 2 の腕で終端印が出ず関門失敗だったが、追補1で器具の未測定の仮定と
判明し、その腕の終端印だけを比較から外して再判定した）。

#### 4.18.1 `ON 式 GOTO 行番号,…` / `ON 式 GOSUB 行番号,…`（観測）

- **選択値が k（1〜行番号の個数 n）なら k 番目の行へ分岐する。** GOTO は分岐先のみを実行
  する。GOSUB は分岐先を呼び、`RETURN` で **`ON` 文の次の文**へ戻る（次の行とは限らない。
  同じ行のコロンの後ろの文があればそれ）。例: `30 on 1 gosub 100:print 8` は 100 の中身、
  8、次の行の順に実行される。`on 1 goto 100:print 8` では 8 は実行されない。
- **選択値が 0、または n を超える（255 以下）ときは分岐せず、次の文へ進む。**
  誤りにならない。GOSUB は呼ばれない。行が1個（n=1）でも同じ（`on 0 goto 100:print 8` は
  8 を実行、`on 2 goto 100` は次の文）。
- **選択値の範囲:** 負の値（-1）と 256 は ERR 5。文字列は ERR 13。誤りになった文では
  分岐も次の文の実行も起きない（p は誤りの前の値、GOTO・GOSUB とも）。
- **選択式は式でよい**（`on a+1 goto …`）。
- **選択値の整数化（予測を立てずに測った、観測のみ）:** 1.4→1、1.5→2、2.5→3、0.5→1。
  -0.5 は ERR 5。1000000000 は ERR 6（GOTO・GOSUB とも、誤りの前の p は保たれ、GOSUB は
  呼ばれず次の文も実行されない）。**この値の組は、CINT（第4.15節）と同じ四捨五入
  （0.5 は絶対値の大きい方へ）で整数にし、0〜255 の範囲検査をして外れれば ERR 5、整数に
  できない大きさなら ERR 6、という規則と整合する。** 中間値（-0.5 が -1 になること）や
  ERR 5 と ERR 6 の境目の値は観測していない（推定）。
- **選択されなかった行番号は、存在しなくても誤りにならない**（`on 1 goto 100,777`。
  GOSUB は 1,8,9 の順で完走）。**選択された行番号が存在しなければ ERR 8**（p は誤りの前の値）。
  同じ行番号を並べてもよい（`on 2 goto 100,100,100`）。
- 根拠（腕ID）: `on-{goto,gosub}-{one,two,three,zero,beyond,negative,byte-over,string,
  large,f14,f15,f25,fm05,f05,expr,unselected-missing,selected-missing,duplicate,single,
  single-zero-colon,single-over,colon-return}`。

#### 4.18.2 `LET`（観測）

- **`LET 変数=式` は `LET` を省略した代入と同じ結果になる**（数値変数、文字列変数、配列
  要素、プログラム・直接モードとも）。整数型への `2.6` の代入は LET の有無・プログラム／
  直接によらず 3（第4.4b節と同じ丸め）。
- **`LET` だけ、`LET =1`、`LET a`（`=` がない）は ERR 2。** `LET a="x"`（数値変数に文字列、
  `a` は数値）は ERR 13。プログラム中では捕捉でき、p は誤りの前の値。
- 根拠: `let-{program,direct}-{number,string,array,integer}-{let,plain}`、
  `let-{program,direct}-bad-{empty,equals,missing-equals,type}`。

#### 4.18.3 `WHILE 条件`〜`WEND`（観測）

- **条件が 0 以外なら本体を実行し、`WEND` で `WHILE` の条件の評価へ戻る。0 のときだけ偽**
  （-1、1、2、0.5、-0.5 は真）。条件が真のあいだ繰り返し、偽になれば `WEND` の次の文へ進む。
  初回が偽なら本体を一度も実行しない。**条件が文字列なら ERR 13。**
- **`WHILE` に入ると、先に対応する `WEND` を探す。** 探索は入れ子の `WHILE`/`WEND` の
  個数を数え、`REM`（`'` も同様と推定、未測定）の中と文字列定数の中にある
  `wend`・`while` は数えない（偽のとき本体の `rem wend:while 1`、`a$="wend:while"`、
  入れ子の `while 1`〜`wend` を飛び越して外側の `WEND` の次へ進んだ）。
  **対応する `WEND` がプログラム末まで無ければ、条件を評価する前に ERR 29**
  （条件が真でも偽でも同じ。本体の文は実行されない。p は `WHILE` と同じ行の前の文で
  代入した値）。
- **対応する `WHILE` が無い `WEND` は ERR 30。**
- `WHILE` どうしの入れ子、`FOR` の中の `WHILE`、`WHILE` の中の `FOR` はいずれも内側が先に
  完了して外側へ進む（例: 外 i、内 j で i*10+j を出して 1,2,11,12）。
- **1行に収めたループ**（`20 i=0:while i<3:i=i+1:print i:wend` に続く行）は 3 回回って
  `WEND` の次の文（次の行）へ進む。
- **`WHILE` の途中から `GOTO` で外へ出て、同じ `WHILE` へ再び入ることができる**
  （再入場後も条件の評価から通常どおり動く）。
- 根拠: `while-{normal,false,false-nested,false-rem,false-string,nested,for-outer,
  while-outer,reenter,orphan-wend,missing-true,missing-false,string,one-line,
  condition-*}`。

#### 4.18.4 測っていない範囲・注意（推定を含む）

- **捕捉した構文の誤り（ERR 2）の処理が `END` したあとの直接モード:** `let`・`let =1`・
  `let a` をプログラム中で捕捉して `END` した 3腕×2走で、**次に打った直接モードの行が
  実行されなかった**（ERR 13・5・29・30 を捕捉した同型の腕では実行された）。原因は未確定で、
  直接モードの入力が受け付けられたかどうかも含め中身を記録していない。これは自作の
  実装でも未確認。実装者は ERR 2 の後の挙動を、この測定の範囲では**決められない**。
- 測っていない: `WHILE` の入れ子の深さの上限、`WHILE` の途中での `CLEAR`/`NEW`/行編集、
  `ON` の割り込み系（`ON TIME`/`KEY`/`STOP`/`COM`）、行番号リストの個数の上限、
  選択値の ERR 5/6 の境目、`WEND` を `FOR`・`GOSUB` の途中から実行したときの扱い、
  `NEXT`/`RETURN` との混在した誤り、`WHILE` の `LIST` 表示。
- GW-BASIC のソースの手順（探索・状態の取り除き）は候補の根拠に使ったが、PC-8801 の
  観測の根拠にはしていない。

### 4.19 `DEF FN`・`SWAP`・`ERASE`（l4-s9k）

対象は `l4-s9k`（本体48腕＋対照11腕、各2走、別の起動）。結果ノート `l4-s9k-results.md`、
事前登録 `l4-s9k-deffn-swap-erase-preregistration.md`（3b1af61）、器具 `tools/l4_deffn_measure.py`
（8bab986）、期待値 `tests/conformance/expected_l4_deffn.tsv`。プログラム中の誤りは
`ON ERROR GOTO` で捕捉し、誤り番号と、誤りの前に代入した p を記録した（終端印は正常終了・
捕捉の両経路に置き、ERR 2 の後の直接打鍵には依存していない）。直接モードの誤りは番号の
包含だけを使う。誤り番号は [l4-basic.md](l4-basic.md) 第7.1節の表のとおり。**判定: 予測あり
55腕が全て一致、不一致0**（予測なし4腕は観測のみ）。以下、腕IDは根拠。

#### 4.19.1 `DEF FN`（観測）

- **登録は実行時。** `DEF FNx(仮引数,…)=式` は実行された時点で関数を登録する。DEF 行より前の
  行で呼ぶと ERR 18（fn-before-def）。一度も DEF していない関数も ERR 18（fn-undefined）。
- **再定義で更新される。** 同じ関数名の DEF を再び実行すると以後の呼出しは新しい式になる
  （fn-redefine: `x+1` で呼んで 4、`x+2` に再定義して 5）。
- **呼出し:** `FN名(実引数,…)`。引数なしの関数は `def fna=3` と書き、括弧なしの `fna` で
  呼ぶ（fn-none: 3）。引数は複数可（fn-two: `def fna(x,y)=x*10+y`、`fna(2,3)` で 23）。
  文字列関数（`fna$(a$)=a$+"z"`）も可（fn-string: 結果の長さ3・先頭の文字コード97）。
- **仮引数は呼出し中だけの束縛。** 同名の大域変数は呼出しの前後で変わらない
  （fn-scope: x=9 のとき `fna(2)` の間は x=2 として計算し、呼出し後の x は 9）。
  **本体は仮引数以外の大域変数を参照できる**（同: 本体の g は大域の 4 を使い `fna(2)`=6）。
- **入れ子:** 本体から別の関数を呼べる（fn-nested: 8）。
- **関数名は通常の変数名と同じく2文字目以降も区別される**（fn-names: fnab≠fnac、
  fn-long-names: fnabc≠fnabd。各々別の式を登録して 4,5）。
- **`FN` と名前の間の空白は可**（fn-space: `fn a(1)` は fna を呼ぶ）。
- **誤り（プログラム中）:** 実引数の個数が定義と違うと ERR 2（fn-too-few・fn-too-many、
  p=1）。仮引数が数値で実引数が文字列、または逆は ERR 13（fn-type-number・fn-type-string）。
  未定義は ERR 18。**直接モードの `DEF FN` は ERR 12**（fn-direct。番号の包含）。
- **`DEF FN` の誤りの各腕は ON ERROR で捕捉でき、続行して終端印まで進める**（再帰の ERR 7
  も同じ）。

#### 4.19.2 `DEF FN` の型変換（予測なし4腕の観測。値の根拠として使う）

- 関数名の型が整数（`fna%`）のとき、結果は整数に変換される。**丸めは CINT と同じ四捨五入**
  （0.5 は絶対値の大きい方）。fn-integer-round: `def fna%(x)=x/3` に 5, 7.5, -7.5 → 2, 3, -3。
- 整数に収まらない結果は **ERR 6**（fn-integer-type: 98304/3=32768）。
- 仮引数が整数（`x%`）のとき、実引数は同じ四捨五入で整数化される。fn-argument-integer:
  `def fna(x%)=x%` に 2.5, -2.5 → 3, -3。
- **無条件の再帰**（`def fna(x)=fna(x)`、呼出し）は **ERR 7** で止まり、無限に走らない
  （fn-recursion。捕捉して終端印まで進む）。深さの正確な値は測っていない。
- これらは予測なし（観測のみ）。観測外の値の丸め方は CINT の規則からの推定である。

#### 4.19.3 `SWAP`（観測）

- **同じ型どうしの値を交換する。** 無印・`%`・`!`・`#` の各数値型で 3 と 7 を交換して
  7,3（swap-number/integer/single/double）。文字列も交換できる（swap-string: `"ab"` と
  `"xyz"` で、交換後 a$ は長さ3・先頭 120、b$ は長さ2・先頭 97）。
- **配列要素も可**（swap-array: `a(1)` と `a(2)`、swap-array-scalar: `a(1)` と単純変数 b、
  どちらも 7,3）。**同じ変数どうしは何も変わらない**（swap-same: 7）。
- **型が違うと ERR 13**（数値と文字列、整数と単精度。swap-type-string・swap-type-integer、p=1）。
- **第1だけ未設定:** 第1を新設して交換する（swap-undefined-first-number: 7,0、
  swap-undefined-first-string: 長さ2,0。新設の値は数値0・空の文字列）。
- **第2が未設定なら ERR 5**（第1が設定済みでも、両方未設定でも。数値・文字列とも、
  swap-undefined-second-*・both-*、p=1）。
- **引数が1個なら ERR 2**（swap-one）。

#### 4.19.4 `ERASE`（観測）

第14.16版の4.10.2・4.10.7に、多次元の再DIMとFRE回復の追加観測を記す。

- **指定した配列だけを消す。** 消した後は同じ名前で `DIM` し直せる（erase-redim:
  `dim a(2)`、`a(1)=7`、`erase a`、`dim a(4)` の後 `a(1)`=0、`a(4)=9`。erase-string も同様に
  再 DIM 後の要素は空文字列）。他の配列と同名の単純変数は残る（erase-preserve:
  `erase a` の後で b(1)=8・単純変数 a=9）。
- **複数を指定できる**（erase-multiple: `erase a,b` の後に両方を DIM し直せ、各要素は 0）。
- **消した後で DIM せずに要素を参照すると、既定の上限 10 で自動的に配列ができる**
  （erase-auto-ten: 参照した `a(1)` は 0、`a(10)=9` は成功）。**添字 11 は ERR 9**
  （erase-auto-eleven、p=1）。
- **ERASE せずに既存の配列を DIM し直すと ERR 10**（erase-redim-without、p=1）。
- **存在しない配列名、および単純変数だけがある名前は ERR 5**（erase-missing・erase-scalar、
  p=1）。**引数なしの `ERASE` は ERR 2**（erase-empty）。

#### 4.19.5 推定と測っていない範囲

- 推定（根拠は GW-BASIC のソースの手順の読書で、観測の根拠ではない）: 型の変換の順序、
  配列領域の再配置を伴う SWAP の内部の挙動。実装は観測のみに従う。
- 測っていない（型宣言文との相互作用は第14.7版で 4.21 に測定済み）: `DEF USR`・`DEF SEG`、再帰の深さの
  正確な値と上限の決まり方（メモリ依存か）、行編集（行の挿入・削除・置換）・`CLEAR`・
  `NEW` と DEF の登録の関係、`FN` の引数個数の上限、文字列の仮引数の呼出し中の長さの上限、
  `SWAP` の2つ目が配列要素で配列が新設される場合の誤り、多次元配列の `SWAP`（`ERASE` は4.10.7で測定済み）、
  `ERASE` した配列が `FOR` の変数などだった場合、関数の本体に副作用のある式
  （`RND`・`INKEY$`）を置いた場合。

### 4.20 `TAB(`・`SPC(`・`POS`・`XOR`・`EQV`・`IMP`・`CSNG`（l4-s9l）

対象は `l4-s9l`（本体90腕＋対照11腕、各2走、別の起動）。結果ノート `l4-s9l-results.md`、
事前登録 `l4-s9l-tabspc-logic-csng-preregistration.md`（f935ea8）、追補 `l4-s9l-addendum1-csng-digits.md`
（ebcdb97。`csng-digits` を `csng-digits-6` へ差し替え）、器具 `tools/l4_tabspc_measure.py`（2ce58e5・c3a0280）、

**判定: 101腕×2走が関門通過、2走の観測は全腕で一致。** 予測あり85腕のうち65腕が予測（G_GW）と一致、
20腕が食い違い（4.20.5 節。原因は POS の起点と TAB の桁の数え方の2点のみ）。**実装の根拠は予測でなく公式の観測**
（期待値ファイルの食い違い腕は公式の観測を採る）。幅は起動既定の80桁。

#### 4.20.1 `XOR`・`EQV`・`IMP`（観測。論理35腕は全て予測と一致）

- 両辺を**符号付き16ビット整数へ丸めて**ビット演算する。丸めは半端を絶対値の大きい側へ
  （2.6→3、−2.5→−3、0.5→1。xor-round-26・neg25・05）。範囲外（40000・−32769）は **ERR 6**
  （xor-range-*、eqv-range、imp-range）。文字列（左右どちらでも）は **ERR 13**（xor-string-*、eqv-string）。
  境界 32767・−32768 は通る（xor-edge-*）。
- `XOR` は排他的論理和（5 xor 3=6、−1 xor 5=−6、−32768 xor −1=32767）。`EQV` は XOR の否定
  （5 eqv 3=−7、0 eqv 0=−1、−1 eqv 0=0、255 eqv 15=−241）。`IMP` は「左 AND NOT 右」の否定
  （0 imp 0=−1、1 imp 0=−2、−1 imp 0=0、5 imp 3=−5）。
- **優先順位（高い順）: NOT、AND、OR、XOR、EQV、IMP。** 比較・算術・単項マイナスはこれらより高い
  （xor-prec-*、eqv-prec-*、imp-prec-*。`5 xor 5` を IF の条件に置くと偽: xor-if）。
- 結果は整数。IF の条件にも使える。
- 測っていない: 文字列結果の型、`XOR` と実数・倍精度の中間丸め（範囲内の倍精度の値は 16 ビット整数へ丸めると
  する推定）。

#### 4.20.2 `TAB(`・`SPC(`・`POS`（観測）

幅80、**桁は0始まり**。以下で「桁」は PRINT の次に出る文字の桁。

- **`POS(0)` は現在桁を0始まりで返す。** `print "ab";` の後は 2（pos-basic）。引数は無視される
  （引数の値による違いは測っていない）。
- **`TAB(n)` は桁 n mod 80 へ進む。** TAB(1) は桁1、TAB(10) は桁10、TAB(80) は桁0、TAB(81) は桁1、
  TAB(256) は桁16、TAB(32767) は桁47（tab-k0-*）。
  - 現在桁より**後ろ**なら空白で埋めて進む（桁5→TAB(6)、TAB(10)）。
  - 現在桁と**同じ**なら何もしない（桁5に TAB(5)→桁5・行増分0: tab-k5-n5）。
  - 現在桁より**前**なら**改行してから**その桁へ進む（桁5に TAB(1)→桁1・行+1: tab-k5-n1、tab-back）。
  - n mod 80 が 0 になる場合（TAB(0)、TAB(80)）、桁0で行頭にいるなら何もしない（tab-k0-n0・n80）。
    桁79 からの TAB(80) は桁0・行+1（tab-k79-n80、n mod 80=0 は現在桁より前なので改行して桁0）。
  - 実数は四捨五入（5.5→6: tab-frac-55）。**負数（−1）は誤りにならず桁0**（tab-k0-nneg1）。
  - 範囲: n は符号付き16ビット整数として受け、**32768 は ERR 6**、65536 も ERR 6（tab-k0-n32768・tab-range-65536）。
    文字列は **ERR 13**、PRINT の外の式中（`a=tab(3)`）は **ERR 2**（tab-string・tab-in-expression）。
- **連鎖** `"a";tab(5);"b";tab(10);` は桁10（tab-chain）。**区切り無し** `tab(5)"b"` も通る
  （tab-no-separator）。**末尾に区切りが無くても改行しない**（TAB で終わる PRINT は桁10・行増分0: tab-end-nosemi）。
- **TAB の後のコンマ**は次の14桁境界（桁14）へ進み、続く1文字で桁15（tab-comma）。コンマの欄の規則は
  [l4-basic.md](l4-basic.md) 第4.1節（現在桁56以上で改行）と同じ。
- **`SPC(n)` は n mod 80 個の空白**を出す（SPC(80)→0個、81→1個、256→16個、79→79個）。実数は四捨五入
  （2.5→3個: spc-frac-25）。**負数は0個**（spc-k0-nneg1）。**32768 は ERR 6**、65536 も ERR 6、
  文字列は ERR 13、式中は ERR 2。連鎖（spc-chain）は各 SPC が現在桁から足される。
- **行端は1文字ずつ折り返す**: 桁70から SPC(20) は桁10・行+1、桁79から SPC(2) は桁1・行+1。
  桁70から SPC(10) は桁0・行+1（spc-k70-n10。80セルちょうどの規則）。
- **80セルちょうどを出した直後の桁は次行の桁0**（[l4-basic.md](l4-basic.md) 第4.1節と一致）。
  80個の文字の後は TAB(5)→桁5・行+1、TAB(80)→桁0・行+1、TAB(1)→桁1・行+1（tab-k80-*。予測なし）。
  これは「桁80は存在せず、桁0・行+1」と数えると TAB の前後の判定が全て説明できる。

#### 4.20.3 `CSNG`（観測。予測あり11腕が全て一致）

- 倍精度→単精度は**半端を絶対値の大きい側へ丸める**（16777217#→…+2、16777221#→…+2: csng-tie-up・csng-tie-up-2）。
- `csng(1/3#)>1/3#`、`csng(2/3#)>2/3#`、`csng(−2/3#)<−2/3#` は真、`csng(.7#)<.7#` は真、
  `csng(.5#)=.5#`（厳密に表せる値）は真、`csng(1/3)=1/3` は真（単精度に変換しても変わらない）。
- 整数は変換するだけ（123456→123456: csng-integer）。文字列は **ERR 13**（csng-string）。
- **単精度の表示は6桁**: `csng(123456.789#)` は 123457（csng-digits-6。7桁整数の印には
  ならず指数表記になるため、1回目の `csng-digits` は観測の関門に失敗し差し替えた）。
- `csng(1d-50)` は誤りにならず**値は0**（csng-underflow、予測なし）。

#### 4.20.4 自作判断・未測定

- **自作判断**: `POS` の引数の扱い、TAB/SPC の n が整数に丸まる境目（x.5 の符号による差は 5.5→6 と
  2.5→3 だけ測った。負の半端は未測定）、桁が既に80セル相当の位置にいる状態の内部表現（4.20.2 末尾の
  「桁0・行+1」の数え方は観測を説明する実装方針であって公式の内部の実装を主張しない）。
- **自作判断（`CSRLIN`）**: `CSRLIN` は測定器具が行の増分を観る手段として使った。自作は行を0始まりで返す。
  公式の起点は測っていない（増分のみ観測）＝自作判断。
- **自作判断（実装 22952cb の2点）**: `POS` の引数は評価するだけで値は使わない。`HEX$(TAB(` のように直前が `(` の
  `TAB(` は `PRINT` の項目として扱わない（式の中の `TAB(` は ERR 2 の側に倒す）。どちらも公式の挙動は測っていない。
- **未測定**（WIDTH 40 の TAB・SPC・POS は 4.22.4 で測定済み）: `WIDTH 40` など幅が80でない場合の TAB・SPC・POS、TAB の n が 0〜79 の範囲外で式の中身が
  大きな負の値（−1 以外）の場合、画面下端でのスクロールを伴う TAB・SPC、`LPRINT`・ファイル出力での
  TAB・SPC・POS、`POS` の引数の値、`PRINT USING` との併用、`INPUT` プロンプトの後の桁、`CSNG` の
  1d-50 以外の極端な値（オーバーフロー等）、倍精度の `XOR` の中間値、`XOR`・`EQV`・`IMP` の文字列結果型。

#### 4.20.5 予測と観測が食い違った20腕（記録）

POS の起点（予測は1始まり）と TAB の桁（予測は n−1）に起因する。予測は書き換えていない。値は「桁,行の増分」。
tab-k0-n0/n80/nneg1（予測 1,0/80,0/1,0 → 観測 0,0）、tab-k0-n32768（1,0 → ERR 6）、tab-k5-n5（5,1 → 5,0）、
tab-k79-n80（80,0 → 0,1）、tab-comma（16,0 → 15,0）、spc-k0-n0/n79/n80/n81/n256/nneg1（1/80/1/2/17/1 →
0/79/0/1/16/0）、spc-k0-n32768（1,0 → ERR 6）、spc-k5-n3/k70-n20/k79-n2/frac-25/chain（9,0/11,1/2,1/4,0/6,0 →
8,0/10,1/1,1/3,0/5,0）、pos-basic（3,0 → 2,0）。TAB の負数が桁0へ寄るという予測は当たり、ERR 5 の見方は外れ。

### 4.21 型宣言文 `DEFINT`・`DEFSNG`・`DEFDBL`・`DEFSTR`（l4-s9m）

対象は `l4-s9m`（本体100腕＋対照11腕、各2走、別の起動）。結果ノート `l4-s9m-results.md`、
事前登録 `l4-s9m-deftype-preregistration.md`（052bcd8）、追補 `l4-s9m-addendum1-short-forms.md`
（a0bac41。画面からあふれた3腕を1行にまとめた `-s` 腕へ差し替え）、器具 `tools/l4_deftype_measure.py`
（3cc2f69・差し替えは1666970）、結果コミット c030b8f、期待値 `tests/conformance/expected_l4_deftype.tsv`
（予測あり107腕＝本体96＋対照11）・`expected_l4_deftype_unpredicted.tsv`（予測なし4腕。照合には使わない）。
観測は自作プログラムが出した印と整数、誤り番号の包含真偽だけで、画面本文は扱っていない。誤り番号は
[l4-basic.md](l4-basic.md) 第7.1節の表のとおり。**判定: 111腕×2走が関門通過、2走の観測は全腕で一致。**
予測あり96腕のうち95腕が予測（G_GW）と一致、1腕が食い違い（4.21.9 節）。**実装の根拠は予測でなく公式の観測。**
直接モードの腕は誤りの行だけが誤りになる設計で、誤りのあとの行は実行される。以下、腕IDは根拠。

#### 4.21.1 型を引く規則（観測）

- 型の既定は**英字26文字×型の表**（大文字小文字を区別しない）にあり、起動時・RUN・NEW・CLEAR のあとは
  全文字が**単精度**（sng-default）。`DEFINT`・`DEFSNG`・`DEFDBL`・`DEFSTR` は、指定した文字の欄を
  それぞれ整数・単精度・倍精度・文字列へ書く。**同じ文字を後から宣言し直すと後が勝つ**（sng-after-int、
  later-wins-str）。
- 変数・配列・`DEF FN` の名前は、接尾辞（`%` `!` `#` `$`）が**あればそれが常に優先**し（suffix-single・
  double・string・int-under-single）、無ければ名前の**1文字目だけ**で表を引く。
  名前が長くても同じ（`defstr a` のあとの `abc` は文字列: str-long-name。`defint a` のあとの `ba` は
  単精度、`abc` は整数: first-letter-only）。
- **型ごとに別の変数**: 同じ綴りでも型が違えば別（suffix-coexist: `defint a:a=7:a!=2.6` の両方が残り
  7 と 26）。`defstr a` のあとの `a` は `a$` と同じ変数（str-dollar-same: 長さ2、str-prior-dollar:
  宣言の前の `a$="xyz"` が宣言後の `a` で長さ3）。`a%` は `defint a` でも `defstr a` でも整数のまま
  （str-int-suffix）。
- **宣言の前に作った変数は、型が変わると見えなくなる**（exist-before: `a=2.6`（単精度）のあと
  `defint a` で `a` は0、`a!` は26）。宣言を元へ戻せば元の変数が戻る（exist-return: `defsng a` で
  `a*10` が26）。整数の `a=2.6` を作ってから `defsng a` で見ると0、`defint a` へ戻すと3
  （exist-int-return-s）。変数の新設時の初期値（数値0・文字列長0）は l4-s9g の規則（4.17）のとおり。
- **プログラムは実行のたびに型を引く**（prog-runtime-type: 同じ文 `a=2.6:print a*10` が宣言の前は26、
  `defint a` の直後に別変数で0、宣言のあと30。prog-loop: `for k=1 to 2:a=2.6:…:defint a:next` は
  26, 30＝途中の宣言は次の周回から効く）。`if 1 then defint a` は宣言が働き、`if 0 then …` は働かない
  （prog-if-true・false）。実装は構文解析時や行の保存時に型を固定せず、実行時に表を引くこと。

#### 4.21.2 宣言文の構文と誤り（観測）

書式は「英字 [`-` 英字] {`,` 英字 [`-` 英字]}」。範囲 `a-c`、列挙 `a,c,e`、組合せ `a-b,x-z`、1文字、
`a-z`、空白入り `a - c , e` がいずれも通る（range-a-c・before・after、list-a-c-e、two-ranges、
range-whole、range-spaces。範囲は両端を含み、範囲外の文字は変わらない）。誤りは全て **ERR 2**。

**誤りの文のうち、どこまで反映されるか**は形で分かれる。

| 形 | 反映 | 腕 |
|---|---|---|
| `defint c-a`（逆順）、`defint a-`（範囲が開いたまま）、`defint 1`（英字でない）、`defint`（空） | **何も変えない**（後の `a=2.6` は単精度の26） | err-reverse・dash-open・digit・empty |
| `defint a,`（カンマで終わる）、`defint a,1`、`defint a,d-c`（2つ目が逆順）、`defint ab`、`defint a b` | **誤りの前までは反映済み**（後の `a=2.6` が3＝a は整数） | err-comma-end・comma-digit・second-reverse・two-letters |

実装の読み方（観測を説明する手順。内部の主張ではない）: 文を先頭から読み、1つの範囲（1文字または `x-y`）を
**検査に通ってから**書き込む。範囲の検査に失敗（逆順・開いた `-`・英字でない）すれば、その範囲は書かず
それまでの範囲だけが残る。範囲を書いたあと、続くのが `,` なら次の範囲へ、文末（`:` を含む）なら終わり、
それ以外（`ab` の `b`、`a b` の `b`）は**書き込み済みのまま** ERR 2。`defint a,d-c` の `a` は書き込み済みで、
`defint a,1` も同じ。最初の範囲の検査で失敗する形は何も変わらない。
**プログラム中の `defint c-a`・`defint` も ON ERROR で捕捉でき ERR 2**（prog-reverse・prog-empty。
誤りのあと終端印まで進める）。

#### 4.21.3 整数（`DEFINT`）（観測）

- **代入は CINT と同じ丸め**（4.4b）: 2.6→3、2.5→3、−2.5→−3、2.4→2、1/3→0、32767.4→32767
  （int-round・half-pos・half-neg・low・third・edge）。
- **範囲外（40000・32767.5）は ERR 6 で、変数は変わらない**（int-over・over-half: 直後の値は0のまま）。
  整数配列の要素も同じ（array-over: 40000 は ERR 6、値は0）。
- **整数どうしの演算が整数に収まらなければ単精度へ昇格する**（誤りにしない）: `a=300` で `a*300` は
  90000（int-mul-promote）、`a=20000` で `a+a` は40000（int-add-promote）。**`/` は単精度の結果**
  （`a=3` で `a/2*10` は15: int-divide）。

#### 4.21.4 単精度・倍精度・文字列（観測）

- **単精度・倍精度は代入のときにその型へ変換される。** 倍精度へ入れた `1/3#` は `1/3#` と等しく（−1）、
  単精度へ入れると等しくない（0）（dbl-third・sng-third）。**倍精度へ単精度の `1/3` を入れても `1/3#` とは
  等しくならない**（dbl-from-single: 0。式を単精度で計算してから広げる）。
- **9桁の定数** 123456789 は、単精度変数では 123456792 に丸まる（`a-123456780` が12: sng-big）、
  倍精度変数では 9（dbl-big）。
- **`DEFSTR` した文字は文字列変数**: 代入・長さ・連結が `a$` と同じに働く（str-len: 長さ2、str-concat:
  `defstr a-b` で `b=a+"yz"` の長さ3、range の組合せ）。他の文字（宣言しない `b`）は影響を受けない。
  **数値の代入は ERR 13 で変数は変わらない**（str-numeric: 長さ0）。文字列配列への数値も ERR 13
  （array-str-numeric）。`DEFSTR` した文字の配列の文字列要素は通る（array-str: 長さ2）。

#### 4.21.5 配列（観測）

- **配列も型ごとに別**: `dim a(3)`（単精度）のあとの `a(1)=2.6` に続けて `defint a:a(1)=5` とすると、
  `a(1)` は別の整数配列で、**ERR 10 にならない**。`defsng a` へ戻すと元の単精度配列が見える
  （array-before-def-s: 5, 26）。宣言後の `defint a:dim a(3)`（array-int）は `a(1)=2.6` が3。
- **同じ型・同じ名前の配列を二重に確保すると ERR 10**: `dim a%(3)` のあと `defint a:dim a(3)` は ERR 10
  （array-redim-int: 先に確保した整数配列を使い続ける。`a(1)=4` のあとの値は4）。
- **`ERASE` は宣言後の型の配列だけを引く**: `dim a(3):defint a` のあと `erase a` は、単精度の `a` の
  配列があっても **ERR 5**（整数の `a` の配列が無い）。`defsng a` へ戻せば消せて、`dim a(5)` も通る
  （array-erase-s: `a(5)` の値は1、直接の誤り ERR 5 は1回）。4.19.4 と同じ規則（単純変数だけの名前は ERR 5）の
  型を宣言で引く版である。

#### 4.21.6 宣言が戻る条件・戻らない条件（観測。l4-s9g の規則と一致）

宣言（表）は 4.17 の初期化の対象に**含まれる**。

- **単精度（既定）へ戻る**: プログラム行の挿入・削除・置換（reset-insert・delete・replace）、`CLEAR`
  （reset-clear）、`NEW`（reset-new）、`RUN`（直接の `run`: reset-run、プログラム中の `clear`・`run 40`:
  prog-clear・prog-run-line。`reset-run-program` は `10 a=2.6:V a*10` のプログラムを宣言のあとに `RUN` して26）。
  したがって**直接モードで入力した宣言は、その後に行を打つか `RUN` すると消える**。`STOP` のあとに行を
  編集しても戻る（stop-edit: 26）。
- **戻らない（宣言が効いたまま）**: 代入（keep-assign）・`LIST`（keep-list）・存在しない行番号だけの入力
  （ERR 8: keep-missing-line）・何もしない（keep-none）・`STOP`→`CONT`（stop-cont）・プログラム中の宣言が
  `END` したあとの直接モード（program-persists: `10 defint a` を `RUN` したあとの `a=2.6:a*10` が30）。
- 上の「戻る」は表だけの話で、変数・配列の中身が初期化されることは 4.17 の表のとおり（宣言で別型の変数が
  見えなくなることとは別）。

#### 4.21.7 関連する文（観測）

- **`DEF FN`（4.19）**: 関数名の型は **`FN` の次の名前の1文字目**の宣言で決まる（`fna` なら **a**。`FN` の `f`
  ではない）。`defint a` なら `fna(7.5)` は整数（`def fna(x)=x/3` で `*2` が6: fn-def-a）、`defint f`
  または宣言なしは5（fn-def-f・none）。**仮引数も表で型が決まる**（`defint x` で `def fna(x)=x` の
  `fna(2.6)*10` は30＝実引数が3へ丸まる: fn-param-int。丸めは 4.19.2 の `x%` と同じ）。`defstr a` なら
  `fna` は文字列を返す（fn-str: 長さ2）。接尾辞つきの関数名は接尾辞が優先（4.19.2）。
- **`READ`（6.1）**: 整数変数へ DATA の `2.6` を読むと3（read-int）。文字列変数へ DATA の数字 `12` を読むと
  長さ2（read-num-into-str）。**整数変数へ数字でない DATA（`hi`）を読むと ERR 2**（read-text-into-int:
  プログラム中、ON ERROR で捕捉）。倍精度変数へ DATA の `2.6` を読むと `a=2.6#` が真（read-dbl、予測なし。
  DATA の数値は倍精度の精度で読まれ、単精度へ丸めてから広げない）。
- **`SWAP`（4.19.3）**: 型は宣言後のもので比べる。`defint a,b` の整数どうしは交換できる（swap-int-int: 7）。
  `defint a` のあと `a`（整数）と `b`（単精度）は **ERR 13** で変数は変わらない（swap-int-single: 3）。
  `defint a` のあと `swap a,b%` は整数どうしで交換できる（swap-int-suffix: 7）。`defstr a,b` の文字列どうし
  は交換できる（swap-str: 交換後の長さ3）。`defstr a` の `a` と数値 `b` は ERR 13（swap-str-num: 長さ1）。
- **`FOR`（4.2）**: 制御変数が**文字列（`defstr i`）なら ERR 13**（for-str）。**倍精度（`defdbl i`）も ERR 13**
  （for-dbl-step。予測と違った点: 4.21.9）。整数（`defint i`）は通る（for-int: 1〜3 の和は6）。
  整数の制御変数（予測なし3腕、観測のみ）: **上限は CINT と同じ丸め**（`for i=1 to 2.6` は3回: for-int-limit）、
  **刻みも丸める**（`step .5` は1へ丸まり `for i=1 to 2 step .5` は2回: for-int-step）、
  **32767 を越えると ERR 6**（`for i=32766 to 32767` は32767を終えて32768へ進むとき整数の桁あふれで ERR 6、
  p=1＝FOR の準備は済んでいた: for-int-edge）。単精度の制御変数は従来どおり（4.2）。
- **`ERASE`**: 4.21.5 のとおり、宣言後の型の配列を引く。

#### 4.21.8 実装への読み替え（まとめ）

- 状態: 26文字の型表（既定は全て単精度）。`RUN`・`CLEAR`・`NEW`・プログラム行の挿入／削除／置換で全て単精度へ
  戻し（4.17 の初期化と同じ契機）、代入・`LIST`・存在しない行番号の入力・`CONT` では戻さない。
- 参照・代入・`DIM`・`ERASE`・`SWAP`・`READ`・`FOR`・`DEF FN` の名前と仮引数は、**実行のたびに**
  「接尾辞があればその型、無ければ1文字目の表」で型を決め、型ごとに別の変数・配列の名前空間を持つ。
- 整数代入は CINT の丸めで範囲外は ERR 6（変数不変）、文字列へ数値は ERR 13（変数不変）、整数の演算が
  収まらなければ単精度へ昇格、`/` は単精度。`FOR` は文字列・倍精度の制御変数で ERR 13、整数の上限・刻みを丸め、

- 宣言文の構文は 4.21.2 の表のとおり: 範囲単位で「検査→書き込み」し、失敗した範囲より前は残す。

#### 4.22.1 括弧なしの比較式（観測。予測あり42腕とも一致）

比較は PRINT の項目・代入の右辺・IF の条件に**括弧なしで**書ける。結果は**整数 −1（真）／0（偽）**。
数値と文字列の6演算子（`=` `<>` `<` `>` `<=` `>=`）とも通る（cmp-num-*・cmp-str-*）。
文字列どうしの比較の規則は [l4-basic.md](l4-basic.md) 第21節のとおり。

- **優先順位（高い順）: 単項マイナス・算術（`+` `-` `*` `/` 等）、連結 `+`、比較、`NOT`、`AND`、`OR`、`XOR`、`EQV`、`IMP`**
  （4.20.1 の論理演算の表のうち「比較・算術・単項マイナスより低い」の部分を、比較を算術と NOT の間に置いてつなぐ）。
  根拠: `2+3=5` は −1（cmp-add）、`1+1<2` は 0（cmp-add-before-lt）、`2*3<7` は −1（cmp-mul）、`"a"+"b"="ab"` は −1（cmp-concat）、
  `not 1=2` は −1（NOT は比較の後: cmp-not）、`-1=1` は 0（単項マイナスが先: cmp-negconst）、
  `1<2 and 2<3` は −1（cmp-and）、`1>2 or 2<3` は −1（cmp-or）、`1=1 and 2=3 or 4=4` は −1（cmp-mixed-and-or）。
- **同じ段の比較は左から**（連鎖）。`1<2<3` は `(1<2)<3` で −1（cmp-chain-lt）、`1=1=1` は `(−1)=1` で 0（cmp-chain-eq）、
  `1=1=-1` は −1（cmp-chain-eq-m1）。**文字列の連鎖** `"a"<"b"<"c"` は2段目が（数値 −1）対（文字列）になり **ERR 13**
  （cmp-chain-str-err。代入 `a=...` の形で打つと誤りの後も a は0のまま）。
- **比較記号の並びの規則**: 記号を並べ替えても同じ意味（`=<` は `<=`、`=>` は `>=`、`><` は `<>`: cmp-rel-*）。
  **同じ記号の重複は ERR 2**（`1==1`: cmp-dup-eq、PRINT の項目 `1<<2`: cmp-dup-lt-print）。
  3種そろえた `1<=>2` は誤りにならず −1（常に真: cmp-rel-triple）。
- **型**: 数値の左右の型が違えば高い方へ揃えて比べる（単精度 `1/3` と倍精度 `1/3#` は等しくない: cmp-sd-third、`1.5=1.5` は −1: cmp-float）。
  **文字列と数値の混在は常に ERR 13**（`"a"=1`・`1="a"`。代入でも PRINT の項目でも: cmp-mixed-err1/2・cmp-print-mixed/2）。
  変数どうし（`a=b`: cmp-vars）も同じ。
- **代入**: `a=1=1` は −1、`a=1=2` は 0、`a="b"="b"` は −1、整数変数 `a%=2>1` は −1（cmp-asg-*）。
  **文字列変数へ入れる `a$=1=1` は ERR 13**（cmp-asg-strvar-err。a$ は空のまま）。
- **誤りの扱いは直接モードの通常どおり**: 誤りの行だけが誤りになり、次の行は実行される
  （cmp-print-mixed で誤りの後の `print "s9nv";1;7` が実行される）。
- 4.20.1 の XOR・EQV・IMP、[l4-basic.md](l4-basic.md) 第21.3節（文字列比較と AND/OR/連結の優先順位。第21.3節末の
  「連鎖は未測定」は本節で測定済み）と矛盾しない。

#### 4.22.2 WIDTH の受理と誤り（観測）

`WIDTH 桁[,行]` を画面（既定の80桁・25行から変える）に使う。以下、誤りはプログラム中で `on error goto` が捕捉した番号（`p=1`）。

- **受理（誤りにならない）**: 桁 40・80、桁と行 `40,20`・`80,20`・`80,25`・`40,25`、**式** `width 20*2`、
  **小数** `width 40.4`・`width 79.6`（小数は誤りにならない。`79.6` が通ることから、切り捨てではなく四捨五入で桁を決めていると読める。
  その後の画面の状態は測っていない＝予測なし腕）。
- **ERR 5（範囲）**: 桁 0・39・41・81・256、行 19・24・26（`width 80,19`・`80,24`・`80,26`）。
  桁は 40 か 80 の2値だけ、行は 20 か 25 の2値だけを受ける。
- **構文の誤りと引数の欠け**（予測が外れた腕。実装の根拠はこの観測）:
  - **余分な引数** `width 80,25,3` は **ERR 2**。
  - **桁の省略** `width ,20`（行だけ）は **ERR 2**（構文の誤り）。直接モードの `width ,25` も ERR 2。
  - **行の欠けた末尾コンマ** `width 40,` は **ERR 22**（Missing operand）。
  - **引数なし** `width` は **ERR 22**。
  - **文字列の装置名** `width "a"` は **ERR 2**（Bad file name の ERR 56 ではない）。
  すなわち「被演算子が要るのに欠けた」形は 22、「文法に合わない」形は 2。行の省略（`width 40` だけ）は受理され、行数は現在のまま。
- **`width lprint n`** は画面に触れない装置幅の指定で、`width lprint 40` は受理。**`width lprint 0` も誤りにならない**
  （予測は ERR 5 だったが外れ）。lprint の幅の上限・範囲外は測っていない。
- **誤りになる width は何も変えない**（桁・行も画面も。4.22.3 の画面消去も起きない）。

#### 4.22.3 WIDTH の画面消去とカーソル（観測）

- **`width` が受理されると画面を消し、カーソルを先頭（ホーム）へ戻す。** 現在と同じ指定（`width 80,25`）でも消える
  （w-q-same。GW の「変化なしなら何もしない」は外れ、マニュアルの記述が当たり）。`cls`→`locate 5,10` のあとに
  `width 80,25` または `width 40` を実行すると、`pos(0)` は0、`csrlin` の変化は 0（w-home-80・w-home-40・w-d-home）。
  消去と同時に ERR 2/5 のような誤りになる width は消さない（w-q-err: `width 39`、w-q-rows: `width ,25`）。
- **`width lprint 40` は画面を消さない**（w-q-lprint）。
- 消えたかどうかは、直前に出した印がその後の採取に残るかで判定した（本文は読んでいない）。消去後に残る行（`Ok`・ファンクションキー行）は 5.1 のとおり。
- `width 40,20` や `width 80,20` を実行したあとに `width 80,25` へ戻す往復は誤りにならず、元の80桁の規則に戻る（w-d-roundtrip-*、
  w80-after-40: `width 40` のあと `width 80` で85字は桁5・行+1）。
- 行数（20/25）を変えたとき、ファンクションキー表示行の位置は 5.6・[l3-main.md](l3-main.md) 第13節の既存の測定が根拠で、
  本節では表示行の中身を測っていない。40桁時のテキストVRAMの並びは `l4-s9o` で測定済み（5.6.1。1行120バイトは変わらず、40桁の文字は2バイトおき）。
  本節の観測は `pos`・`csrlin` から読んだ論理的な桁・行で、消える範囲は 5.6.4。

#### 4.22.4 40桁時の折り返し・項目・コンマ・TAB・SPC・POS（観測。予測は全て的中）

桁は0始まり。80桁の規則（[l4-basic.md](l4-basic.md) 第4.1節、4.20.2）の「80」を**現在の桁数 W**（40）に置き換えると全て説明できる。値は「桁,行の増分」。

- **折り返し**: `string$(n,"a");` の後は、n=39 で 39,0、n=40 で **0,1**（ちょうど W セルの直後は次行の桁0）、n=41 で 1,1、n=45 で 5,1、n=85 で 5,2
  （w40-wrap-*）。80桁（w80-wrap-80/85）は 80 で 0,1、85 で 5,1。
- **項目の前改行**: 現在桁が0でなく、現在桁＋項目の長さが W を超えれば項目の前で改行（項目は割らない）。
  30字＋15字で 15,1、30字＋10字（ちょうど40）で 0,1、37字＋数値 `12345`（前後の空白で7セル）で 7,1
  （w40-item-wrap・w40-item-exact・w40-num-wrap）。
- **コンマ**: 「次の14の倍数の桁へ進む。現在桁が閾値 T 以上なら改行して次行の桁0」で、**T は (⌊W÷14⌋−1)×14**（80桁で 56、**40桁で 14**）。
  `"a",` は 14,0、`"a","b",`（桁15）は 0,1、13字のあとのコンマは 14,0、14字のあとのコンマは 0,1（w40-comma-1/2/13/14）。
  T の式は80桁と40桁の2点だけで確かめた一般化（他の W は存在しない）。
- **`TAB(n)`**: n mod W の桁へ進む。TAB(10) は 10,0、TAB(39) は 39,0、**TAB(45) は 5,0**（w40-tab-10/39/45）。
  現在桁より前なら改行してから進む（桁6 から TAB(5) は 5,1: w40-tab-back）。その他の規則（同じ桁なら何もしない等）は 4.20.2 と同じ。
- **`SPC(n)`**: n mod W 個の空白。SPC(39) は桁39、**SPC(45) は5個で桁5**（w40-spc-39/45）。
- **`POS(0)`**: 現在桁（0始まり）。`locate 5,2`（`width 40` のあと）で 5、`csrlin` の増分は 2（w40-locate-pos）。
- 40桁時の 4.20.4「未測定: WIDTH 40 など幅が80でない場合の TAB・SPC・POS」は本節で測定済み（画面下端スクロールを伴う場合は未測定のまま）。

#### 4.22.5 LOCATE の範囲外・スクロールの下限（予測なし腕の観測。規則の候補）

- **`locate` は桁・行の上限を超える指定でも誤りにならない**: 80桁・25行の行 23・24・25、80桁・20行の行 19・20、40桁の桁 39・40
  （カーソルをどこへ置くか〔丸める・折り返す・そのまま〕は測っていない）。5.2 の `LOCATE` の対応（x が桁、y が行）と矛盾しない。
- **スクロールの下限**（`console` の窓の下端との関係は5.4.6 (2): f≠0 で行数−2、f=0 で行数−1）: 30回 `print` した後の `csrlin` の、`width` 直後（ホーム）との差は、**80x25 と 40x25 で 23、80x20 と 40x20 で 18**
  （＝行数−2。桁数は影響しない）。最下行をファンクションキー表示行が使い、カーソルはその1行上で止まってスクロールする、と読める
  （5.5 の実行中のスクロールと整合）。`csrlin` の起点（0か1か）は測っていないので、本節の値は差だけ。
- **小数の幅**: 4.22.2 のとおり。**引数なしの `width` は ERR 22**（そのとき直前の画面は消えず、印が残る: w-q-noarg）。

#### 4.22.6 BEEP と OUT 0x40 の bit 5（観測）

ポート0x40のうち**変化したのは bit 5 だけ**で、他のビットは測定の窓の中（打鍵を始めてから終わりまで）で一度も立ち上がりも立ち下がりもしなかった。
窓の手前の書き込みを比較相手にして数えた（追補1。起動時の書き込みがあり、`prior` 欄＝有）。値列は扱っていない。

| 打つもの | bit 5 | 書き込み回数（窓内） |
|---|---|---|
| `beep`（引数なし） | **立ち上がり→立ち下がり**（1回鳴って止まる） | 2 |
| `beep 1` のみ | **立ち上がりのみ**（鳴り続ける） | 1 |
| `beep 1` のあと `beep 0` | 立ち上がり→立ち下がり | 2 |
| `beep 0` のみ | **変化なし**（無音の対照 `rem` も変化なし） | 1（書くが値は同じ） |
| `beep 2` のあと `beep 0` | 立ち上がり→立ち下がり（2は誤りにならず鳴る） | 2 |
| `beep:beep` | 立ち上がり→立ち下がり（1行に2つ） | 4 |
| `if 1 then beep` | 立ち上がり→立ち下がり | 2 |
| `a=1:beep a:beep a-1` | 立ち上がり→立ち下がり（変数・式の引数） | 2 |
| `print chr$(7);` | **立ち上がり→立ち下がり（`beep` と同じ動き）** | 2 |
| プログラム中の `beep`（`10 beep`/`run`） | 立ち上がり→立ち下がり | 2 |

- **規則**: 引数なしの `BEEP` は bit 5 を立て、続いて下げる。`BEEP n` は **n が0以外なら bit 5 を立てたまま**、**0なら bit 5 を下げる**（立っていなければ変化なし）。
  引数は式でよい。`CHR$(7)` の出力（PRINT 経由）は引数なしの `BEEP` と同じ動き。
- **範囲**: **`beep -1`・`beep 256` は ERR 5**（`beep 2` は受理。0〜255 の1バイトに収まらない値を誤りとする、と読める。3〜255 と小数は測っていない）。
  **`beep "a"` は ERR 13**、**`beep 0,1` は ERR 2**（余分な引数）。いずれもプログラム中でも同じ（beep-prog-str は ERR 13 を捕捉）。
- **誤りの BEEP の bit 5**: 上の誤りになる BEEP（`beep "a"`・`beep 0,1`・`beep -1`・`beep 256`）は bit 5 が立ち上がって下がる。
  これは **BEEP 文が検査の前に鳴らしているのではなく、誤りの表示が鳴らしている**（4.22.7。ON ERROR で捕捉すれば鳴らない）。
  `beep 0,1` は書き込みが1回多い（窓内3回）ので、`beep 0` に当たる部分が先に実行されてから余分な引数で ERR 2 になる形と読める（`beep -1`・`beep 256` も
  後続の `beep 0` の1回を足して3回で、誤りになる引数そのものはポートを書かない）。
- **音の長さ**: 引数なしの `BEEP` の立ち上がりと立ち下がりの**間隔（時間）は測っていない**。窓内の変化の有無だけ（自作判断。実装は鳴る長さを決める）。
- **ポート0x40の他のビットを保つかどうか**: 窓の中で他のビットが変化しなかったことだけが観測。書き込みのたびに他のビットを保っているのか、
  同じ値を書き直しているのかは、値列を扱っていないので**区別していない（未測定）**。実装は l1-ipl.md のポート表（b0〜b4 は制御用）に従い、
  他のビットを変えない形にするのが安全（自作判断）。

#### 4.22.7 誤り表示の音（追補2。観測）

**表示された誤りは、`OUT 0x40` の bit 5 を1回立ち上げて下げる**（立ち上がり1回・立ち下がり1回、書き込み2回。他のビットは動かない）。
BEEP を含まない誤りでも鳴る（機序は「誤りの表示」で、BEEP 文ではない）。G_GW（GW のソースにブザーの呼び出しは無い）は外れ。

- **鳴る（表示された誤り）**: 直接モードの構文の誤り `print 1+`（**ERR 22**）・未定義行 `goto 999`（ERR 8）・型の誤り `a$=1`（ERR 13）・
  `error 5`（ERR 5）、プログラムの実行中の未定義行（`10 goto 999`/`run`: ERR 8）・型の誤り（`10 a$=1`/`run`: ERR 13）、`beep "a"`（ERR 13）・`beep 0,1`（ERR 2）・
  `beep -1`・`beep 256`（ERR 5）。
- **鳴らない**:
  - **`on error goto` で捕捉された誤り**。`10 on error goto 30:a$=1`、`10 on error goto 30:error 5`、捕捉された `beep "a"`（ERR 13）・`beep -1`（ERR 5）はいずれも変化なし
    （誤りは表示されず、捕捉先が実行される）。
  - **誤りのない文**（`print 1` の直接行・プログラム）。
  - **直接モードの `print 1/0`（ERR 11）**: 誤りの表示は出るが bit 5 は動かない。0除算は誤りの処理を経ずに値を返して表示だけする型と読める
    （ブザーは誤りの処理に付く）。**プログラム中の `1/0`・他の誤りの番号（ERR 6・9 等）は未測定。**
- **測っていないこと**: ブザーが誤りのメッセージの前か後か、ERR 22 より外の番号ごとの網羅（測ったのは 2・5・8・11・13・22）、`resume` を含むトラップの再入、
  `error n` の他の番号、ブザーの間隔、プログラム中の誤りの行番号つき表示の前後。
- 既存の誤り表示の節への関係: [l4-basic.md](l4-basic.md) 第6節（構文の誤りの出力行が +1 行に現れる観測）と第7.1.1節（`print 1+` は
  資料6では ERR 22）に**音の観測を追記する参照を足した**。第6節の画面の観測（非空白15セル）と矛盾しない（音はポートの観測で、画面の観測とは別の軸）。
  `print 1+` が ERR 22 であることは資料の記載と一致した（本測定は直接 `print 1+` を ERR 22 と観測。事前予測の ERR 2 は外れ）。

#### 5.4.2 属性域に書く組（観測）

- `color n` のあとに印字した区間ごとに、5.6.2 の組（終端位置, 値）が行の属性域に書かれる。
- **n=0**: 組は書かれない（全20組が (0x80, 0x00)）。5.6.2 の区間規則どおりの (終端, 0) は**書かれない**（l3-main 第12節の「既定と同一」が正しい）。ただし**別の色から 0 へ戻した区間は組が書かれる**（5.6.2 の混在規則: `color 2`→`color 0`→`color 4` で値0の区間も組あり）。
- **n=1〜7**: 印字した区間に **(終端位置, n)** の1組。値バイトは n そのもの（8通りとも区別できた）。
  `l4-s5f` F5（`color 2:print 7`）の先頭2バイト 0x03 0x02 は (3, 2)、F6（`color 7`）の 0x03 0x07 は (3, 7) で、本規則と一致する。
- **この「値バイトは n そのもの」は白黒モード（起動既定）での観測**。`console ,,,1` のカラーモードでは値が変わる（5.4.5）。ビットの意味も5.4.5（`l4-s9r`）。

#### 5.4.3 既存の F5・F6 との関係

F5・F6 が見たのは「印字した区間の先頭の組」で、位置は区間の終端（3）、値は n（2・7）であり、**今回の規則と矛盾しない**。
位置バイト **0x80** が現れるのは次の場合だけ: (a) 未使用の組（(0x80, 0x00)）、(b) 20区間以上のときの20組目（5.6.2、値は最後の区間の値）。
通常の色つき区間の位置が 0x80 になることはない。F5・F6 の期待値として位置 0x80 を置いているテストがあれば、それは (a)(b) のどちらでもない限り誤りである
（本リポジトリ内では該当するテストを特定できなかった。`l4-s5f` の結果ノートの値は 0x03 だった）。

#### 5.4.4 第2〜第4引数とポート（`l4-s9q`、観測）

書式 `COLOR [第1][,第2][,第3][,第4]`。誤り番号は `on error`・`err` で採った。画面本文は扱っていない。

| 位置 | 受理 | 誤り |
|---|---|---|
| 第2引数 | 0〜7 | −1・8・9・255・256 は誤り5 |
| 第3引数 | **0 だけ** | 1〜7・−1・8・9・255・256 は全て誤り5 |
| 第4引数 | 0〜7 | −1・8・9・255・256 は誤り5 |
| 文字列（第2・3・4とも） | — | 誤り13 |
| 小数 2.5（第2・第4） | 受理（四捨五入） | — |

- 4引数の格子 `color 3,b,bo,fg`（b・bo・fg ∈ {0,1,2}）は、**bo=0 の9通りは全て誤りなし、bo=1・2 の18通りは全て誤り5**（b・fg の組に依らない）。
- 部分形: `color 3,1`・`color 3,,,2`・`color ,1,,2` は誤りなし、`color 3,1,1`・`color 3,,1`・`color ,1,1`・`color ,,1,2` は誤り5。**省略した引数は検査されない**（誤りにならない）。
- 5引数は誤り2、引数なし・末尾のカンマは誤り22（5.4.1と同じ）。
- 検査の順序は 5.4.1（値の検査が構文の検査より先）のとおり。誤りになった `color` はポートも属性も変えない。

**ポート 0x54 への書き込み（実装向け）。** 誤りにならずに実行された `color` は、**ポート 0x54 へ必ず2回**書く。誤りになった `color` や `color` を含まない基準の腕では書かない。**0x52 は動かない**（陽性対照 `out &h52,&h40` は 0x52 に 0x40 を示した）。

- 値は第2引数 b（0〜7、省略時 0）の3ビットで決まる:
  - 1回目 = `0x80 | (b の bit0 が1なら 0x07) | (b の bit1 が1なら 0x38)`（b=0〜3 で 128・135・184・191）。
  - 2回目 = `0xC0 | (b の bit2 が1なら 0x07)`（b=0〜3 は 192、b=4〜7 は 199）。
- **第2引数を省略した `color 2`・`color 7`・`color ,,0`・`color ,,,b` も同じ2回書き込みで、値は b=0（128・192）**。つまり `color` は実行のたびに背景（色0）を第2引数（省略時0）へ書き直す。
- **第3・第4引数はポートに現れない**（第4引数の値を変えても 0x54 の値は b で決まる）。
- ポートの意味（アナログパレットの書き込みの形に見えるが、資料との照合は未）は決めない。実装は上の値を書けばよい。
- 0x32 は全腕で 0xA9/0xAA（`color` の腕では 0xA8 も）を多数回切り替える雑音で、`color` と無関係に見える。0x30・0x31・0x34・0x35・0x53・0x55〜0x5B は `color` の腕で追加の書き込みが無い。

**訂正（`l4-s9r`）。** 「0x54 の**最後の値**が b=0〜7 で互いに異なる」と読んではならない: b の3ビットは**2回の書き込みに分かれて**入るので、最後（2回目）の値は 192 と 199 の2通りだけ。上の式は `l4-s9r` の公式49腕×2走でも変わらず（b=0〜7 の8通りとも1回目 128/135/184/191・2回目 192/199 の組、自作ROMも完全一致）。`color ,,,f`（f=0〜7）は 0x54 に影響せず 128・192。

**予測と外れ。** `color ,,bo` が 0〜7 で受理される（実際は 0 だけ）、背景色が 0x52 に出る（実際は 0x54）、`color 2`・`color 7` はポートを動かさない（実際は 0x54 に2回）。いずれも外れた。
**自作ROMとの差**（`35301b9` 時点）: COLOR の誤り番号（参照込み96文）は公式と全一致。ポート0x54は自作は書かない（公式と19腕で差）、`out &h52,&h40` は自作では誤り2。

#### 5.4.5 `COLOR` の値の意味 — 白黒モードとカラーモード（`l4-s9r`、観測）

根拠: [l4-s9r 結果](../notes/l4-s9r-results.md) 2.（公式、セル 8×20 の画素頻度と属性域の生値）。**属性ビットのハードウェア資料は読んでいない。以下は観測だけを根拠とする。**
画面のモードは2つ。**起動直後は白黒モード**。カラーモードへは `console ,,,1`（5.4.6）。5.4.2 の「値バイト=n」と s9p の観測は**白黒モード**のもの。

**白黒モード（起動既定）。** 色は付かず、前景は常に白・背景は黒。`color n`（0〜7）の n は**ファンクションコード**で、属性域には n がそのまま入る（組の書き方は5.4.2）:

| ビット | 値 | 観測した見え方 |
|---|---|---|
| bit0 | 1 | シークレット（字形が消え、セルは背景色の単色）。n=1・3 は黒160画素 |
| bit1 | 2 | ブリンク（採取位置では通常表示。位相・周期は未測定） |
| bit2 | 4 | リバース（字形と背景が入れ替わる）。n=4・6 は白120＋黒40、n=5・7 は全面白 |

n=0 は組なし（通常）。ビットは加算で組み合わさる（n=3=シークレット＋ブリンク、5=リバース＋シークレット〔全面前景色〕、7=全部）。

**カラーモード。** 属性値は **`0x08 | (n<<5)`**（n の3ビットを bit5〜7 に移し、bit3=カラー指定を立てる）。n の bit0=青(B)→bit5、bit1=赤(R)→bit6、bit2=緑(G)→bit7（つまり n は B=1・R=2・G=4 の GRB コード）。**n=7（白）だけは既定の値 0xE8 と同じなので組が書かれない**:

| n | 属性値 | 色（前景） | 画素 |
|---|---|---|---|
| 0 | 0x08 | 黒（背景と同じで字形が見えない） | 000000 |
| 1 | 0x28 | 青 | 0000ff |
| 2 | 0x48 | 赤 | ff0000 |
| 3 | 0x68 | 紫 | ff00ff |
| 4 | 0x88 | 緑 | 00ff00 |
| 5 | 0xA8 | 水色 | 00ffff |
| 6 | 0xC8 | 黄 | ffff00 |
| 7 | 組なし（既定 0xE8） | 白 | ffffff |

- カラーモードでの印の前の区間の組は (終端桁10, 0xE8)（既定の白）。
- 第2〜4引数（`color ,b`・`color ,,,f`）は**画素に出ない**（背景・前景とも、印のセル・空白セル・画面全体のヒストグラムが基準と同一）。出るのはポート 0x54 の書き込みだけ（5.4.4）。このエミュのスナップショットではグラフィック面が出ていない可能性があり、実機で見える条件は未測定。
- ポート 0x30 は白黒モードでは `console` 以外で書かれず、カラーモードでは 0x21（bit1=0）が書かれる（5.4.6）。0x52・0x53 は動かない。
- 自作ROM（現状）: 白黒モードの `color n` の見え方の分類は公式と同じ（字形の画素数だけフォント差）。カラーモードは未実装。

#### 5.4.6 `CONSOLE` 文（`l4-s9r` で `,,,1`、`l4-s9s` で全引数。観測）

形は `console 開始行, 行数, ファンクションキー表示, カラー`（4引数、全て省略可だが何か1つは要る）。`l4-s9s`
（[結果](../notes/l4-s9s-results.md)、結果 dcb899d・訂正 43750ba、追補1 3a19936・追補2 8e4e99e、公式191腕×2走・全て関門通過）。
観測は誤り番号・目印の位置・属性域・制御ポートの値で、画面本文は扱っていない。20行・25行で受理範囲は同じ。

**(1) 引数ごとの受理範囲と誤り番号**

| 形 | 結果 |
|---|---|
| `console`・`console ,`・`,,`・`,,,` | **ERR 22**（全省略は誤り） |
| 末尾にコンマが付く形（`3,`・`3,,`・`3,5,`・`,5,`・`,,1,`・`5,10,,`） | **ERR 22** |
| `console ,,,,`・`console ,,,1,`・`console 0,20,1,0,0`（引数・コンマが多すぎる） | **ERR 2** |
| **第1引数だけ**（`console 0`〜`24`・`1.5`。`0 20` は空白が無視され 020） | **ERR 2**（範囲が正しくてもコンマが無いので誤り） |
| 第1引数（開始行）25以上・負 | **ERR 5**。受理は **0〜24**（行数に依らない） |
| 第2引数（行数）0・26以上・負 | **ERR 5**。受理は **1〜25**（20行でも25まで） |
| 開始行＋行数が画面の行数を超える組（`5,16`・`10,11`・`20,1`・`0,20`・`1,20` ほか） | **受理**（和の検査は無い。実行時に切り詰める、(2)） |
| 第3引数（ファンクションキー）・第4引数（カラー） | **0〜255 を受理**、**負は ERR 5**。小数は四捨五入（0.5 は 1） |
| 文字列の引数（どの位置でも） | **ERR 13** |
| 省略の中間（`3,,1`・`0,20,,1`・`5,,1,0`） | 受理。省略した引数は**前の値が残る** |

- **誤りのときの部分適用**: 第4引数が負（ERR 5）でも、その前の第3引数は効く（`console ,,0,-1` でファンクションキー行が消えた）。
  ただし窓の引数（第1・第2）が誤りなら窓は変わらない（`console 3,0`・`3,40`）。`console 0,5,1,-1` も窓 0,5 は適用されない。
  **（実装向け）** 引数を左から順に検査し、誤りの引数より前の第3引数は適用、窓の引数は第1・第2が両方通ったときだけ適用、と読める（第1・第2が通り第3以降が誤りの組は `0,5,1,-1` で窓不適用だった。第3引数が誤りで第1・第2が通る組の適用の有無は未測定）。
- 0.5 など小数の第3・第4引数は 1 と同じ扱い。

**(2) スクロール範囲（窓）とファンクションキー表示**

- 窓 = 開始行 s から行数 n ぶん（行 s〜s+n−1）。**`print` のスクロールと `cls` は窓の行だけに作用し、窓の外の行は保持される**。
- 窓の下端 = min(s+n−1, **fkey下限**)。fkey下限は f≠0（既定）のとき**行数−2**（20行→18、25行→23）、f=0（`console ,,0`）のとき**行数−1**（19／24）。
  `console 0,20`・`0,19`・`0,25` は窓なしと同じ。`console 19,1`（20行）は開始行も切り詰められ `18,1` と同じ結果（行18の1行窓）。25行の `23,1` は行23の1行窓。
- 窓の下端から `print` を n 回打つと窓内が n 行上へ寄り、下端の n 行が空行、カーソルは下端に残る。
- 省略は前の値: `console 5,10` のあと `console ,,1` は窓 5..14 のまま、`console ,4` は開始行5のまま行数4（行5..8）。
- `locate` は絶対座標で、窓の外へも書ける。**`console s,n` はカーソルを動かさない**。
- 窓の外にカーソルがあるときの `print`: 窓より**下**（窓 5..14 に対し行18、窓 0..9 に対し行15）から打つと**窓がスクロールする**（カーソルが窓の下端以降なら窓を動かす）。窓より**上**（行3）から打つとスクロールせずカーソルが下へ動くだけ。
- **`cls`**: 窓の行だけを消し、ファンクションキー行は残る。窓なしなら行0〜(行数−2)（f=0 なら行数−1まで）。**`cls` 後のカーソルは (窓の上端, 桁0)**（窓なしは (0,0)、f=0 でも (0,0)、`19,1` は行18。`cls` のあと `print "zzz";` の位置で28腕全て一致）。
- **`width` が受理されると窓は全画面に戻る**（`console 5,10` のあとの `width 80,25`／`40`／`80,20`。5.6.8）。

**(3) ファンクションキー表示（第3引数 f）**

- f=0: ファンクションキー行（20行→行19、25行→行24）が空行になり、使える行は行数と一致。窓なしのスクロール下端は 19／24。
- f≠0（1・2・3・255・1.5・0.5）: ファンクションキー行は非空（非空バイト数は全て 21）。**f=2 でも f=1 と個数は同じ**に見える（10個表示との違いは出なかった。中身は扱わない）。下端は 18／23（4.22.5 と一致）。
- `console ,,0` のあと `console ,,1` で非空に戻る。`console ,,0` と `width 80,25` の順序はどちらが先でも結果は同じ（25行の最下行まで目印が置ける）。
- ファンクションキー行の属性域は、白黒でもカラーでも同じ組（位置 5,17,19,31,… の 0 と 4 の繰り返し。40桁は位置が半分）。

**(4) カラー／白黒の切替（第4引数 m）**

- m≠0（1・2・255・1.5・0.5〔1に丸め〕）で**カラー**、m=0 で**白黒**。同時指定（`0,20,0,1`・`,,1,1`・`5,10,1,1`・`,,0,255`。最後はファンクションキー行も消える）も同じ。
- **手順は `width` と同じ10項目（5.6.5）で、違いは先頭の `OUT 0x30` の値と CRTC の P5 だけ**（`0x31` は5.6.5どおり）:
  カラー＝ 0x30 に 80桁 **0x21**／40桁 **0x20**（bit1=0）、P5 = **0x53**（bit6 が立つ）。白黒へ戻すとき＝ 0x30 に 80桁 0x23／40桁 0x22、P5 = **0x13**。
  P1〜P4（20行 CE 93 73 38／25行 CE 98 6F 58）、DMAC の転送長・アドレス（F3C8）、`OUT 0x51` の 0x00・0x43・0x20、`OUT 0x68` の 0xA0・0xE4 の順序も `width` と同じ。
- **自作の `65ba524` が自作判断で入れた「カラー時 CRTC P5 に bit6」は、今回公式で 0x53 として観測され、裏付けられた**（20行・25行とも）。
- **画面の消去はモードが実際に変わるときだけ**: 白黒→カラー、カラー→白黒とも画面を消す（目印が全て消え、属性域は白黒への切替後が全20行 (0x80,0x00)、カラーへの切替後が (0x80,0xE8)。ファンクションキー行は消去のあとに残る／描き直される）。
  すでにそのモード（白黒のまま `console ,,,0`、カラーのまま `console ,,,1`）なら**ポートも書かず画面も消えない**。
- カラー中の `width` も10項目の手順を書き、**P5 は 0x53 のまま、0x30 は 80桁 0x21／40桁 0x20**（順序の入れ替えも同じ）。
- 色指定 `color r and 7` は 0x54 を 0x80,0xC0 の順で行ごとに書く（5.4.4と整合）。カラーの行の属性は `0x08｜(n<<5)`（5.4.5）。
- 起動既定は白黒。`console ,,,1` を実行しないかぎり白黒のまま。

**(5) 自作ROMの現状と未測定**

- 自作ROM（`65ba524`）は **`console ,,,1` だけ受理**し、手順は公式と一致する（カラー後の `width 40`／`80,25` も一致）。他の `console`（窓・ファンクションキー・誤り番号の区別・`console ,,,0` の白黒復帰）は未実装（`console ,,,0` はポートも画面も何もしない）。
  （第14.13版の「自作は `console ,,,1` を実行できない」は誤りだった。訂正。）
- 実装の要点: 4引数の受理と誤り番号、窓の保持・切り詰め・`cls`／`print` の作用範囲、省略時の前の値、f の効果、カラー↔白黒の切替（モードが変わるときだけ画面を消す）、`width` は窓を戻しカラー中も P5=0x53。
- **未測定**: 第3引数 2 の10個表示の有無（個数は同じだった）。点滅・40桁の窓・窓つきの `edit`。25行の `0,23` の `scroll` のカーソル（1件）。
  カラー中の窓とスクロールの相互作用（切替は画面を消すので窓の保持は測れていない）。第3引数が誤りで第1・第2が通る組の適用の有無。`console s,n,f,m` の全組み合わせ（上の表の形以外）。

### 5.6 `WIDTH`

対象は `l4-s9o`（公式11腕＋追補1の5腕、各2走、全て関門通過）。結果ノート [l4-s9o-results.md](../notes/l4-s9o-results.md)
（結果コミット 119dd62、追補1の結果 a71471f）、事前登録 `l4-s9o-width-vram-preregistration.md`・`l4-s9o-addendum1-attr-and-order.md`。
観測は自作プログラムが出した印の位置・印の行の属性域のバイト・制御ポートの値で、画面本文は扱っていない。
`WIDTH` の受理範囲・誤り・画面消去・カーソル・40桁の折り返しは 4.22.2〜4.22.4 を参照。本節はテキストVRAMとモード切替の書き込み。

**訂正（旧記述）。** 旧版（第6版〜第14.8版）は「`WIDTH 40` では120バイト/行のストライドが崩れる」と書いたが、**誤りだった**
（`l4-s5f` の測定が文字を1バイトおきで読み、隣の桁が混ざって見えた、と推定。旧測定の生データは読み直していない）。
行ストライドは桁数・行数によらず**120バイト**。崩れたのは「文字は1バイトおき」という前提で、40桁の文字は2バイトおきに置かれる。

#### 5.6.1 テキストVRAMの構造

- テキストVRAMは **F3C8 から1行120バイト、25行ぶん3000バイト**。桁数（40/80）・行数（20/25）で行ストライド・総量は変わらない。
- 行 r の先頭は F3C8 + 120×r。1行は **文字域（行内 0〜79）と属性域（行内 80〜119）**。
- **文字の番地**（行 r、桁 c、行内オフセットでなく先頭からのバイト位置）:
  - 80桁: 120×r + c（1バイトおき）。
  - 40桁: 120×r + 2×c（2バイトおき）。**文字と文字の間（奇数番目のバイト）の値は 0x20**。文字域 80バイト＝40文字×2バイトで、文字域の範囲は80桁と同じ。
  - 例（40桁）: 行6桁0→720、行9桁10→1100、行11桁37→1394。80桁は桁10→1090、桁77→1397。
- 空行の内容: 文字域は全て 0x20、属性域は20組とも (0x80, 0x00)（5.6.2）。

#### 5.6.2 属性域

- 属性域は行内 80〜119 の **20組×2バイト**（位置バイト、値バイト）。位置・組の数は80桁と40桁で同じ。
- **組の意味: 先頭から順に行を区間に区切る。各組は（その区間の終端位置, その区間の属性値）**。
  - 値バイトは `color` の引数そのもの（`color 2`→2、3→3、4→4）。区間 [0,終端) に色が付く。
  - 位置バイトの計算: **80桁は区間の終端桁そのもの、40桁は 2×終端桁−1**（終端桁 3→5、10→19、13→25、20→39、23→45）。
  - 例（80桁）: 桁10から3文字を `color 3` で描き `color 7` へ戻す → (10, 0)、(13, 3) の2組（[0,10) が既定の値0、[10,13) が値3）。
    桁0から描くと空の区間 [0,0) の組は書かれず、(3, 2) だけ。40桁は同じ操作で (19, 0)、(25, 3) と (5, 2)。
  - `color 7` に戻した側（印の後ろ）の組は書かれない。
- **未使用の組は (0x80, 0x00)**（20組すべてが未使用の行も同じ）。値バイトは、色なしの組・未使用の組とも全て 0x00（生値で 0x20 ではない）。
- 属性域の既定は **表示行数の外の行（20行のときの行20〜24を含む3000バイト全体）にも書かれる**。
- **行内に色が混ざるときの区間終端規則**（`l4-s9p` m1〜m5、80桁・40桁とも的中）: 印字するたびにその時点の色の区間の終端を組へ書き、色が変わるごとに次の組へ進む。
  - `color 2:"zzz";:color 4:"zzz"`: 80桁 (3,2)(6,4)、40桁 (5,2)(11,4)。
  - 3色のあと行の途中（桁3〜4）を `color 5` で上書き: 80桁 (3,2)(5,5)(6,4)(9,6)、40桁 (5,2)(9,5)(11,4)(17,6)。**上書きで区間が組み直される**（行全体への値の書き込みではない）。
  - `color 2`→`color 0`→`color 4`: (3,2)(6,0)(9,4)。**値0の区間にも組が書かれる**（先頭の n=0 だけ組なし。5.4.2）。
  - 組は先頭から詰まって書かれ、使わない組は (0x80, 0x00)。
  - 色つきの行をスクロールすると**組は行と一緒に動く**（位置は行内の桁なので変わらない）。
- **20区間以上のとき**（m2 24区間・追補1 m6 24・m7 20・m8 21、80桁・40桁とも同じ形）: 先頭19組は (pos(i), v_i)（pos は80桁 i、40桁 2i−1）。
  **20組目は常に (0x80, 最後の区間の値)**。ちょうど20区間でも同じ（m7 → (0x80, v20)）。21番目以降の区間の終端は記録されない。
- 属性域の反転・点滅・下線・グラフィックの属性は測っていない。
- 組の「終端」の意味は `color` だけで確かめた。反転・点滅・下線・グラフィックの属性は測っていない（5.6.7）。

#### 5.6.3 ファンクションキー行

- 文字域に内容のある行は **20行のとき行19、25行のとき行24**（40桁・80桁とも）。表示行数の外の行（行20〜24、25行なら行20〜23）の文字域は空白（属性域は5.6.2の既定）。
- **40桁時のファンクションキー行の内容（文字の並び・表示範囲）は測っていない**（本文を扱わないため。5.6.7）。

#### 5.6.4 `width` が消す範囲

- `width` が受理されると **3000バイト全体（25行ぶん）を消す**: 文字域は 0x20、属性域は20組とも (0x80, 0x00)。**表示行数で打ち切らない**
  （20行へ変える `width 40,20`・`width 80,20` でも行21の印が消えた。`width 40`・`width 80,25` も同様）。現在と同じ指定（25行のまま `width 80,25`）でも消える（4.22.3）。
- 消えるのは `width` が受理されたときだけ（誤りになる `width` は何も変えない。4.22.2）。消去のあとにファンクションキー行を再描画する（5.6.3）。
- 消去後に打った文字は、桁数に応じた並び（5.6.1）で書かれる。

#### 5.6.5 切替時のポート・CRTC・DMAC の書き込み

`width` が受理されるたび、**現在と同じ桁・行の指定でも**次の順序で OUT を行う（80桁・40桁・20行・25行の4通りで同じ順序）。値は公式の観測。
行数省略（`width 40`）は現在の行数を保つ（起動状態の20行からは20行、25行からは25行。0x31・DMAC の値からの読み）。

| 順 | 書き込み | 値 |
|---|---|---|
| 1 | `OUT 0x31` | 20行 0x19 ／ 25行 0x39（bit5＝25行） |
| 2 | `OUT 0x30` | 80桁 0x23 ／ 40桁 0x22（差は bit0 のみ。1＝80桁） |
| 3 | `OUT 0x51` | 0x00（CRTC RESET コマンド） |
| 4 | `OUT 0x68` | 0xA0（DMAC） |
| 5 | `OUT 0x64` | 0xC8、続けて 0xF3（DMA アドレス F3C8） |
| 6 | `OUT 0x65` | 20行 0x5F・0x89（2400バイト）／ 25行 0xB7・0x8B（3000バイト）（転送長。下位・上位の順） |
| 7 | `OUT 0x50` ×5 | 20行 0xCE・0x93・0x73・0x38・0x13 ／ 25行 0xCE・0x98・0x6F・0x58・0x13（CRTC RESET の5パラメータ） |
| 8 | `OUT 0x51` | 0x43 |
| 9 | `OUT 0x68` | 0xE4 |
| 10 | `OUT 0x51` | 0x20 |

- **カラーモード中は 0x30 が bit1=0（80桁 0x21／40桁 0x20）、P5（7項目目の5番目）が 0x53 になる**（`l4-s9s`、5.4.6 (4)）。上の表の値は白黒モード。
- **40桁と80桁の違いはポート 0x30 の bit0 だけ**。CRTC のパラメータ（桁の設定を含め 0xCE は共通）・DMAC の転送長・行ストライドは桁数で変わらない。行数は 0x31 の bit5・DMAC 転送長・CRTC の2パラメータ目〜4つ目に現れ、0x30 には現れない。
- 0x30 は `width` ごとに1回だけ書く（受理されない `width` は書かない）。0x31 は10の後も ROM が同じ値を定期的に書き直す（窓の中で約6900回）。
- 0x32 の定期的な書き込み（0xAA・0xA9・0xA8）は `width` と無関係（`width` なしでも同じ列がある）。意味は調べていない。
- **CRTC のカーソル位置**（上の10項目とは別）。**`locate c,r` の後（`l4-s9p`、5腕×2走、公式）: 最後のカーソルコマンドは 0x80 ＋2パラメータ**。
  - **80桁: （c, r）**（c=0,1,10,39,79、r=0,3,7,12,15 の5点とも一致）。
  - **40桁: （2×c, r）**（c=0,1,10,20,39 → 0,2,20,40,78。r は行そのもの）。2倍になるのは文字が2バイトおきに置かれる並び（5.6.1）と同じ単位。c=0 は区別の票にならない（残り4点で区別）。
  - 最後の指定のあと同じ値が約3400回繰り返される（ROM がカーソルを書き直し続ける）。実装は locate／文字出力のたびに、この値で位置を更新する。
  - **0x80 と 0x81 の使い分け（`l4-s9r` で解決。公式49腕×2走）。** 以前の食い違い（s9o は 0x81、s9p は 0x80）は**場面の違い**だった。**0x81＝カーソルが出る状態、0x80＝カーソルを出さない状態**。どちらも窓の終わりの60フレームで毎フレーム（約160回）書かれ、パラメータは（桁, 行）（40桁は 2×桁）:

    | 状態 | コマンド | パラメータ（桁, 行） |
    |---|---|---|
    | 起動直後の入力待ち（直接モードのプロンプト） | **0x81** | (0, 6)（Ok の次の行頭） |
    | 直接モードで打鍵中（例: `print 12` を改行なしで） | **0x81** | 打った文字数の直後 (8, 6) |
    | 直接モードの命令の実行が終わった直後（`width 40`・`width 80`・`locate 10,5`・`cls`・構文エラー・プログラム終了） | **0x81** | 桁は全て 0（Ok の次の行頭。`locate` の引数は反映されない） |
    | `input` 待ち | **0x81** | `? ` の直後 (2, 2) |
    | `input` 待ちで打鍵中 | **0x81** | 打った文字の直後 (4, 2) |
    | プログラム実行中（`goto` の自己ループ・`for` の二重ループ・`a$=inkey$:goto` のループ。`input` 待ちを除く） | **0x80** | 現在の出力位置（動かなければ実行開始時の行頭 (0, 2)。`locate` に追随） |

    - **切り替わる瞬間**（観測の範囲）: `run` の開始で 0x81→0x80、`end`・プログラム終了・エラー停止で 0x80→0x81（直後のプロンプトの行頭）、`input` に入ると 0x81、入力確定で 0x80 へ戻る。切り替えの厳密なフレーム位置は測っていない（窓の終わりの状態だけを観測）。
    - 実行中の `locate` 後の 0x80＋位置は s9p の観測（`locate c,r` の後、実行中の自己ループ＝0x80）と整合する。
    - 画素: 0x81 の腕ではカーソルのセル（8×20）が点滅する■（全面白の位相と黒だけの位相がある）。0x80 では見えない。点滅周期は未測定。
    - **実装向け**: 直接モードのプロンプト・行入力・`input` 待ちのあいだは 0x81＋位置、それ以外のプログラム実行中は 0x80＋位置を毎フレーム書き直す。
    - 0x80/0x81 の番号の意味づけは観測（出る/出ない）で足り、ビット定義の資料は読んでいない。
  - 自作ROMは現状、カーソル位置コマンドにパラメータを付けない（最後が 0x81 でパラメータなし）。公式との差は追補1の結果ノートに記録。`l4-s9r` 時点: 直接モードの状態は公式と同じ 0x81・同じ桁だが、**実行中（goto・for・input・inkey）は窓の終わりにカーソルコマンドを書かない**（公式は毎フレーム 0x80、input は 0x81）。
- 手順 10 項目のあとにカーソルを先頭（行0桁0）へ戻す（4.22.3）。**`csrlin` の起点**（`width` 後の最初の行番号が何か）は測っていない（4.22.8）。

#### 5.6.6 実装の要約（WIDTH 40／行数20 など）

1. 桁・行の検査（4.22.2）を通ったら、5.6.5 の10項目を（桁数・行数に応じた値で）実行する。
2. F3C8〜の3000バイトを、文字域 0x20・属性域 20組とも (0x80, 0x00) で埋める（40桁でも文字域は80バイトぶん全て 0x20）。
3. カーソルを先頭へ戻し、ファンクションキー行（20行は行19、25行は行24）を描く。
4. 文字の書き込み・読み出しは、現在の桁数で 5.6.1 の番地を使う。`color` の属性は 5.6.2 の組へ、80桁は終端桁・40桁は 2×終端桁−1 を位置として書く。

#### 5.6.7 未測定

- 40桁時のファンクションキー行の中身（表示される範囲・形）。
- `color` 以外の属性（下線・グラフィック文字）の組の値の意味、`color` 第2〜4引数の意味（受理範囲は5.4.4で測定済み。0x54の値の意味は未照合。反転・ブリンク・シークレットと色は5.4.5で観測済み）。
- （解決済み）`width` の窓での 0x81 の用途は、直接モードのプロンプトでカーソルを出すためのコマンド（5.6.5、`l4-s9r`）。
- **自作ROM側での描画の確認**（0x30 の bit0 を変えたとき画面上の桁がどうなるか。事前登録で範囲外とした補助測定）。
- 0x32 の定期書き込みの意味、0x31 を定期的に書き直さないと何が起きるか。
- `width` 後の `csrlin` の起点（4.22.8）。

#### 5.6.8 `WIDTH` とスクロール範囲・カラーの関係（`l4-s9s`、観測）

- **`width` が受理されると、`console` で指定した窓（開始行・行数）は全画面に戻る**（`console 5,10` のあと `width 80,25`／`40`／`80,20` で、窓の旧下端〔行14〕から打ってもスクロールせず、画面の下端から打つと全画面でスクロールする）。`width` が画面を消す（5.6.4）ので窓も初期化される。ファンクションキー表示 f の `width` による扱いは、f=0 のあと `width 80,25` でも最下行まで使える順序の観測のみ（`console ,,0` の前後どちらでも同じ）。
- **スクロール下限との関係**: 4.22.5 の「80x25／40x25 で 23、80x20／40x20 で 18」は、ファンクションキー表示あり（f≠0、既定）の窓なしの下端＝行数−2 と同じ値（5.4.6 (2)）。f=0 なら下端は行数−1（19／24）になり、4.22.5 の値はその場合は当てはまらない。
- **カラー中の `width`** は5.6.5の10項目を書き、P5 は 0x53 のまま、0x30 は 80桁 0x21／40桁 0x20（5.4.6 (4)）。白黒へ戻すとき（`console ,,,0`）は P5=0x13、0x30 は 0x23／0x22（5.6.5 と同じ値）。

## 6. 観測 — `READ`/`DATA`・`REM`・1行に複数の文

対象は`l4-s5g`（12腕＋陽性対照、`4d7945f`）。結果ノート
`l4-s5g-read-data-rem-multi-results.md`（`4d7945f`）・事前登録
`l4-s5g-read-data-rem-multi-statement-preregistration.md`（`3cd23ed`）。
以下の打鍵文字列・`RUN`出力は、いずれも自分で打ったプログラムを
`RUN`が`PRINT`した数値であり、禁止事項7の対象外（結果ノート「禁止事項7の
遵守について」節が明示的に許可する範囲）。`DATA`切れの出力（6.3節）だけは
件数と桁範囲のみで、値・文言は書かない。

| 腕 | 打鍵文字列 | `RUN`の出力 |
|---|---|---|
| G1 | `10 read a,b`/`20 print a+b`/`30 data 3,4` | `7`（`a+b`=`3+4`） |
| G2 | `10 for i=1 to 3`/`20 read a`/`30 print a;`/`40 next`/`50 data 5,6,7` | `5`・`6`・`7`（`;`で1行に3値） |
| G3 | `10 read a`/`20 restore`/`30 read b`/`40 print a;b`/`50 data 8,9` | `8`・`8`（1行に2値） |
| G4 | `10 read a$`/`20 print a$`/`30 data 12` | `12`（文字列変数への`READ`） |
| G5 | `10 if 1 then a=5`/`20 print a` | `5` |
| G6 | `10 dim a(3)`/`20 a(0)=7`/`30 print a(0)` | `7` |
| G7 | `10 a=1:b=2:print a+b` | `3`（`1+2`） |
| G8 | `10 read a`/`20 print a`（`DATA`文なし） | 出力1行（`other`、件数14・桁0-17） |
| G9 | `10 print 1:rem 9`/`20 print 2` | `1` → `2`（2行） |
| G10 | `10 ' 9`/`20 print 3` | `3` |
| G11 | `10 a=2:if a=2 then print 1:print 2`（真） | `1` → `2`（2行） |
| G12 | `10 if 0 then print 1:print 2`/`20 print 3`（偽） | `3`のみ |

根拠: `l4-s5g-read-data-rem-multi-results.md`「腕ごとの記録」節・判定
Q1〜Q8。

### 6.1 `READ`/`DATA`

**`READ`は`DATA`の値を、書かれた変数の並びの順に、また文の実行順に
（ループの中で複数回`READ`が実行される場合も含め）順に読み出す。**
根拠: 同結果ノート判定Q1、**`read_ok`**（G1〜G4の全腕）。

- G1（`read a,b`/`data 3,4`、複数の変数への同時`READ`）: 出力は`7`
  （`a=3`・`b=2`ではなく`a=3`・`b=4`として読まれ、`a+b`=`3+4`が正しく
  計算された）。**`,`区切りで複数の変数へ同時に`READ`できる。**
- G2（`FOR`ループの中で`read a`を3回、`data 5,6,7`）: 出力は`5`・`6`・
  `7`の3値。**ループの中で`READ`を複数回実行すると、`DATA`の値を
  順に読み進める**（1回目は`5`、2回目は`6`、3回目は`7`）。
- G3（`read a`→`restore`→`read b`、`data 8,9`）: 出力は`8`・`8`。詳細は
  6.2節（`RESTORE`）。
- G4（`read a$`、`data 12`）: 出力は`12`（文字列出力のため符号位置の
  空白は無い）。**`DATA`に書いた数字は、文字列変数へ`READ`すると
  文字列として読み込まれる。**

### 6.2 `RESTORE`

**`RESTORE`は、その後の`READ`が`DATA`の先頭から読み直されるように、
読み取り位置を先頭へ戻す。** 根拠: 同結果ノート判定Q2、
**`restore_ok`**（G3）。`10 read a`/`20 restore`/`30 read b`/
`40 print a;b`/`50 data 8,9`を`RUN`した結果、出力は`8`,`8`
（2回目の`read b`は`DATA`の2番目の値`9`ではなく、`RESTORE`により
先頭へ戻った`DATA`の1番目の値`8`を再び読んだ）。

### 6.3 `DATA`切れ（誤り）

**読み出す`DATA`が無い状態で`READ`を実行すると、誤りとして扱われ
出力は1行（件数のみ記録、文言は書かない）。** 根拠: 同結果ノート
判定Q6（記述のみ、G8）。`10 read a`/`20 print a`（`DATA`文が無い）を
`RUN`した結果、`run`の入力エコー行の直後に`other`分類の行が1行
（非空白セル件数14、桁範囲0-17）現れて`Ok`に至り、`20 print a`に
相当する数値出力は現れなかった。数字0-9のコードを持つセルが少なく
とも1つ含まれることは真偽値として確認したが、具体的な数字・文言は
記録していない（禁止事項7）。**`STOP`・実行中の誤り（第4.5節）と
同じ扱いの誤りである。**

### 6.4 `THEN` の後の代入

**`IF`の`THEN`の後には、行番号だけでなく代入文を直接書け、条件が真の
とき実行される。** 根拠: 同結果ノート判定Q3、**`then_assign_ok`**
（G5）。`10 if 1 then a=5`/`20 print a`を`RUN`した結果、`print a`の
出力は`5`だった。第4.7節（`IF`〜`THEN`〜`ELSE`）の`THEN`の後の形
（`PRINT`文・行番号）に加え、代入文も直接書けることを確認した。

### 6.5 配列の添字 `0`

**配列の添字`0`は有効で、代入・参照ができる。** 根拠: 同結果ノート
判定Q4、**`index0_ok`**（G6）。`10 dim a(3)`/`20 a(0)=7`/
`30 print a(0)`を`RUN`した結果、出力は`7`だった。第4.10節の配列の
基本動作（`DIM`宣言・宣言なしの範囲外）に加え、添字の下限側
（`0`）も期待どおりに機能することを確認した。

### 6.6 `:` で1行に複数の文

**`:`で区切った複数の文は、1行の中で順に全て実行される。** 根拠:
同結果ノート判定Q5、**`multi_ok`**（G7）。`10 a=1:b=2:print a+b`を
`RUN`した結果、出力は`3`（`1+2`）で、代入・代入・`PRINT`の3つの文
（`a=1`・`b=2`・`print a+b`）が全て実行された。

### 6.7 `REM` と `'`

**`REM`・`'`の後に書いた内容は注釈として実行されず、プログラムは
次の行へ進む。同じ行の他の文には影響しない。** 根拠: 同結果ノート
判定Q7、両腕とも**`rem_ok`**（G9・G10）。

- G9（`10 print 1:rem 9`/`20 print 2`）: 出力は`1`→`2`の2行。`:`で
  `rem 9`につないでも、それ以前の文（`print 1`）は実行され、`rem 9`
  自体は何も出力を起こさず、次の行（`20 print 2`）もそのまま実行
  された。
- G10（`10 ' 9`/`20 print 3`）: 出力は`3`の1行。`'`によるコメント
  だけの行（`10 ' 9`）は実行に影響せず、次の行（`20 print 3`）が
  そのまま実行された。

### 6.8 `IF` と同じ行の残り

**`IF`の条件が真なら、`THEN`の後の`:`以降も含めて同じ行の残りが
全て実行される。条件が偽なら、`THEN`の後だけでなく、同じ行の`:`
以降も含めてすべて飛ばされる。** 根拠: 同結果ノート判定Q8
（G11・G12）。

- G11（`10 a=2:if a=2 then print 1:print 2`、条件`a=2`は真）:
  **`rest_runs_when_true`**。出力は`1`→`2`の2行。`THEN`の後の
  `print 1`だけでなく、`:`でつないだ`print 2`も実行された。
- G12（`10 if 0 then print 1:print 2`/`20 print 3`、条件`0`は偽）:
  **`rest_skipped_when_false`**。出力は`3`の1行だけだった。`10`行の
  `print 1`・`print 2`のどちらも出力に現れず、**`THEN`の後の文
  だけでなく、同じ行の`:`以降（`print 2`）も含めてすべて飛ばされた**
  （`print 2`だけが実行される`rest_runs_when_false`ではなかった）。

## 7. 参考 — トークン番号との関係（実装への注意）

**`LIST`の目標は打鍵の文字どおりの再現であり、公式のトークンの並び・
番号とは無関係である。** 語の一覧・トークン番号の割り当て規則
（`docs/notes/l4-token-design.md`・`src/l4_basic/tokens.tsv`、辞書順に
`0x80`から採番）は自作BASICが内部でプログラムをどう格納するかを決める
自前の規則であり、公式ROMの内部表現を読み取ったものではない（禁止事項2）。
本書の第2節が定める`LIST`の出力書式（行番号・大文字化・空白の保持・`?`展開）
は、内部のトークン化方式によらず**打鍵した文字列を再構成した結果の見え方**
として実装すればよい（ゴールA、`docs/notes/l4-design.md`）。トークン番号の
