## 1. 観測 — 行番号つきの行を打ったときの画面の反応

**行番号つきの行を打っても、その行は打鍵のエコーだけが画面に残り、`Ok`も
それ以外の出力も現れない。** これは直接モードの文（[l4-basic.md](l4-basic.md)
第1節、打った行の直後に出力→`Ok`が続く）とは異なる。

根拠: `l4-s5a-program-line-input-list-format-results.md`「腕ごとの構造」節・
「other_lineが出た腕」節。12腕（A1〜A12）は、いずれも`new`（行番号を伴わない
直接モードのコマンド）→行番号つきの行（1〜2行）→`list`（行番号を伴わない
直接モードのコマンド）という構成で打鍵されたが、記録器が「打った行より下・
`Ok`行より上」の範囲で捉えた`other_line`（数字で始まらない、またはASCII範囲外
を含む行）は、**12腕全てで例外なく2行だけ**だった。

- 1行目: `new`の直後に現れる`Ok`行（相対行1）
- 2行目: `list`の入力そのもののエコー行

行番号つきの行を1行だけ打った腕（A1〜A5・A9〜A12）でも、2行打った腕
（A6〜A8）でも、`other_line`の数は変わらず2行のままだった。**行番号つきの
行を打った直後に`Ok`や他の出力が挟まることは一度も無かった。** `new`・`list`
という行番号を伴わないコマンドだけが、直接モードと同じように`Ok`（`new`の
場合）や出力（`list`の場合、第2節）を伴う。

## 2. 観測 — `LIST` の出力書式

対象は`l4-s5a`の12腕（A1〜A12）。以下の打鍵文字列・`LIST`出力は、いずれも
自分で打ったプログラムを処理系がそのまま表示したものであり、禁止事項7の対象外
（事前登録「記録する内容」節が明示的に許可）。

| 腕 | 打鍵文字列（`new`〜`list`の要点） | `LIST`の出力 |
|---|---|---|
| A1 | `10 print 1` | `10 PRINT 1` |
| A2 | `10print1`（空白無し） | `10 PRINT1` |
| A3 | `10 print  1`（`print`の後に空白2つ） | `10 PRINT  1` |
| A4 | `10 ?1`（`?`の後に空白無し） | `10 PRINT 1` |
| A5 | `10 print 1:print 2` | `10 PRINT 1:PRINT 2` |
| A9 | `65529 print 1`（大きい行番号） | `65529 PRINT 1` |
| A10 | `10 print "abc"`（文字列） | `10 PRINT "abc"` |
| A11 | `10 print 1.5`（小数） | `10 PRINT 1.5` |
| A12 | `10 print 1234567890123#`（長い倍精度定数） | `10 PRINT 1234567890123#` |

根拠: `l4-s5a-program-line-input-list-format-results.md`「腕ごとの記録」節・
判定Q2。

### 2.1 行番号の書式

**行番号の前後に余分な空白は付かない。** 打った行番号の直後は、元の打鍵と
同じ間隔（空白1個、または打鍵どおりの間隔）になる。A1〜A12いずれも、行番号
の前に余分な空白は挿入されず、行頭（相対桁0相当）からそのまま数字が始まる。

### 2.2 命令語の大文字化

**小文字で打った命令語は、`LIST`の出力では大文字化される。** 打鍵は小文字
`print`で与えたが（打鍵注入の仕様、[l4-basic.md](l4-basic.md)踏襲）、A1〜A12
全腕で`LIST`出力は`PRINT`と大文字で表示された。

### 2.3 命令語の後の空白・`?`展開との食い違い

**命令語の後の空白は、元の打鍵にあればそのまま保持され、無ければ挿入
されない。** ただし`?`を`PRINT`に展開する場合だけ、打鍵に空白が無くても
`PRINT`の後に空白が挿入される。

| 腕 | 打鍵 | `LIST`出力 | 命令語後の空白 |
|---|---|---|---|
| A1 | `10 print 1`（`print`の後に空白あり） | `10 PRINT 1` | 保持（あり） |
| A2 | `10print1`（`print`の後に空白無し） | `10 PRINT1` | 保持（無し） |
| A4 | `10 ?1`（`?`の後に空白無し） | `10 PRINT 1` | **`?`→`PRINT`展開時だけ挿入される** |

**A2とA4は、どちらも「命令語の直後に空白無しで打った」という同じ形の入力
だが、`LIST`の出力での空白挿入の有無が異なる。** `print`とそのまま打った
場合（A2）は空白が挿入されないままだが、`?`と打って`PRINT`に展開される
場合（A4）は空白が挿入される。この食い違いの原因（内部表現の違い等）は
ROM内部構造の話になるため立ち入らず、**表面に現れた形だけを実装の対象と
する**（根拠: 結果ノート「観測」節）。

### 2.4 `:` の前後の空白

**`:`の前後に余分な空白は入らない。** A5（`print 1:print 2`）の`LIST`出力
は`PRINT 1:PRINT 2`で、`:`の前後は打鍵どおり空白無しのままだった。

### 2.5 打ったときの余分な空白の保持

**打鍵で入れた余分な空白（連続する複数の空白）は、そのままの個数で保持
される。** A3（`print`の後に空白を2つ打った`print  1`）の`LIST`出力は
`PRINT  1`で、空白2個がそのまま2個で残った（1個に詰められたり、0個に
削られたりしなかった）。

### 2.6 数値の定数・文字列

**数値の定数（小数・`#`付き倍精度定数）も文字列リテラルも、書式の変換を
受けず打鍵どおりに`LIST`出力へ再現される。**

- A10（文字列`"abc"`）: 引用符の追加・削除なく`"abc"`のまま。
- A11（小数`1.5`）: 小数点の位置の変更なく`1.5`のまま。
- A12（`#`付きの長い倍精度定数`1234567890123#`）: `#`の省略・桁の変更なく
  `1234567890123#`のまま。

### 2.7 大きい行番号

**大きい行番号（`65529`）も、先頭に余分な0や空白を挟む書式にはならず、
そのまま出力される。** A9の`LIST`出力は`65529 PRINT 1`だった。

## 3. 観測 — 同じ行番号の打ち直し・行番号だけの行・行番号順の並び

### 3.1 同じ行番号を打ち直すと行が置き換わる（`replaced`）

根拠: `l4-s5a-program-line-input-list-format-results.md` Q3（A7）。行番号
`10`で`print 1`→`print 2`の順に2回打った（`10 print 1`・`10 print 2`）結果、
`LIST`出力は`10 PRINT 2`の1行だけで、**先に打った`print 1`の内容は残らず、
後から打った内容で置き換わった。**

### 3.2 行番号だけを打つとその行が削除される（`deleted`）

根拠: 同結果ノートQ3（A8）。`10 print 1`・`20 print 2`を打った後、行番号
`10`だけを打った（内容を続けない）結果、`LIST`出力は`20 PRINT 2`の1行だけで、
**行番号`10`の行はプログラムから消えた。**

### 3.3 `LIST`は打った順ではなく行番号順に並ぶ（`sorted`）

根拠: 同結果ノートQ4（A6）。`20 print 2`→`10 print 1`の順（行番号の大きい
方を先）に打ったが、`LIST`出力は`10 PRINT 1`→`20 PRINT 2`の順（行番号の
小さい方が先）になった。**`LIST`の並びは行番号順であり、打った順ではない。**

## 4. 観測 — `RUN` とプログラムの実行

対象は`l4-s5b`の12腕（B1〜B12）。以下の打鍵文字列・出力は、いずれも自分で
打ったプログラムを`RUN`が`PRINT`で出力した数値であり、禁止事項7の対象外
（事前登録「記録する内容」節・「本文を出さない取り扱い」節が明示的に許可）。
`STOP`・実行中の誤りの出力（4.5節）だけは件数と範囲のみで、値・文言は書かない。

| 腕 | 打鍵文字列（`new`〜`run`の要点） | `RUN`の出力 |
|---|---|---|
| B1 | `10 print 1` / `20 print 2` | `1` → `2`（2行） |
| B2 | `10 for i=1 to 3` / `20 print i` / `30 next` | `1` → `2` → `3`（3行） |
| B3 | `10 for i=1 to 10 step 3` / `20 print i;` / `30 next` | `1`・`4`・`7`・`10`（`;`で1行に4値） |
| B4 | `10 for i=3 to 1` / `20 print i` / `30 next` / `40 print 9` | `9`のみ（本体の出力無し） |
| B5 | `10 gosub 100` / `20 print 2` / `30 end` / `100 print 1` / `110 return` | `1` → `2`（2行） |
| B6 | `10 goto 30` / `20 print 1` / `30 print 2` | `2`のみ（`20`行は飛ばされる） |
| B7 | `10 a=5` / `20 print a*2` | `10` |
| B8 | `10 i=1.5` / `20 print i+1` | `2.5` |
| B12 | （プログラム無し、`new`の直後に`run`） | 出力行無し |

根拠: `l4-s5b-run-control-flow-results.md`「腕ごとの記録」節・判定Q1〜Q6。

### 4.1 行番号順の実行・`GOTO`・`END`・空のプログラム

**`RUN`は行番号の順にプログラムを実行する。** 根拠: 同結果ノート判定Q1
（**`in_order`**、B1・B6）。B1（`10 print 1`/`20 print 2`）は`1`→`2`の順で
出力され、行番号順の実行そのものを確認した。

**`GOTO`は指定した行番号へ飛び、その間の行は実行されない。** B6
（`10 goto 30`/`20 print 1`/`30 print 2`）は`20`行（`print 1`）を飛ばして
`30`行（`print 2`）だけが実行され、出力は`2`のみだった。

**空のプログラムを`RUN`すると、出力無しでそのまま`Ok`になる。** 根拠:
同結果ノート判定Q6（記述のみ、B12）。`new`の直後に何も行を打たず`run`した
結果、出力行は0行のまま`Ok`行が現れた。誤りは発生しなかった。

**`RUN`直後の入力エコー行のさらに後、実行結果の出力に続いて`Ok`が現れる。**
これは直接モードの並び（[l4-basic.md](l4-basic.md)第1節、打った行→出力→
`Ok`）と同じ形で、`run`のエコー行を起点に、実行結果の出力→`Ok`という順に
なる（`l4-s5b-run-control-flow-results.md`「腕ごとの記録」節の`run`エコー
行・`Ok`行の相対位置）。

**`RUN`に行番号を指定すると、その行から実行が始まる（それより前の行は
実行されない）。** 根拠: `l4-s5c-variables-flow-results.md`（`672539e`）
判定Q7、**`starts_at_line`**（C9）。`10 print 1`/`20 print 2`を打った後
`run 20`（行番号`20`を指定）を実行した結果、出力は`2`の1行だけで、`10`
行の`print 1`に相当する出力（`1`）は現れなかった。

### 4.2 `FOR`〜`NEXT`

**`FOR`〜`NEXT`の本体は、開始値から終了値まで（既定の刻み幅は`+1`）
`STEP`の刻みで実行され、開始値が終了値を最初から超えている場合は本体を
1回も実行しない。** 根拠: 同結果ノート判定Q2。

- B2（`for i=1 to 3`、刻み幅の指定無し=既定`+1`）: **`body_runs_3`**。
  `i=1,2,3`の3回、本体（`print i`）が実行され`1`・`2`・`3`が出力された。
- B3（`for i=1 to 10 step 3`）: **`body_runs_4`**。`i=1,4,7,10`の4回で
  終了した（次は`i=13`で10を超えるため）。
- B4（`for i=3 to 1`、`step`指定無し=既定`+1`、開始値3が終了値1を最初から
  超えている）: **`body_skipped`**。本体（`20 print i`）の出力は一切現れず、
  ループの外にある`40 print 9`の`9`だけが出力された。**`FOR`の本体が
  1回も実行されなかった。**

**ループを抜けた後の制御変数は、終了値を1回超えた値のまま残る（終了値
そのものではない）。ループの前に持っていた値は、`FOR`の初期化で
上書きされ影響しない。** 根拠: `l4-s5c-variables-flow-results.md`
（`672539e`）判定Q1、**`after_loop_4`**（C1・C11）。

- C1（`10 for i=1 to 3`/`20 next`/`30 print i`）: ループを抜けた後
  `print i`の出力は`4`。`NEXT`で3回目の加算の後、条件`i>3`を満たした
  時点の値がそのまま残る（終了値`3`ではなく、それを1回超えた`4`）。
- C11（`10 i=10`/`20 for i=1 to 3`/`30 next`/`40 print i`、ループ前に
  `i=10`を代入済み）: 出力はC1と同じ`4`。**`FOR`が`i`を`1`へ初期化する
  ため、ループ開始前の既存値`10`の影響は残らなかった。**

### 4.2a `FOR` の入れ子・`NEXT` への変数名

**`FOR`は入れ子にでき、`NEXT`に変数名を付けて対応するループを指定
できる。** 根拠: 同結果ノート判定Q2、**`nested_ok`**（C2）。
`10 for i=1 to 2`/`20 for j=1 to 2`/`30 print i*10+j;`/`40 next j`/
`50 next i`を`RUN`した結果、内側`j`・外側`i`のループが期待どおりの
回数実行され、出力は`i*10+j`の並び（`11`・`12`・`21`・`22`、
`i=1,j=1→11`・`i=1,j=2→12`・`i=2,j=1→21`・`i=2,j=2→22`の順）として
1行に現れた。`NEXT j`・`NEXT i`と変数名を付けた`NEXT`も、対応する
ループへ問題なく紐づいた。

### 4.3 `GOSUB`〜`RETURN`

**`GOSUB`は指定した行へ分岐し、`RETURN`で`GOSUB`の次の行へ戻る。**
根拠: 同結果ノート判定Q3（**`gosub_returns`**、B5）。
`10 gosub 100`→（`100 print 1`で`1`）→`110 return`→（`GOSUB`の次の行
`20 print 2`で`2`）→`30 end`の順どおり、出力は`1`→`2`の順で現れた。

**`GOSUB`は入れ子にできる。** 根拠: `l4-s5c-variables-flow-results.md`
（`672539e`）判定Q8、**`nested_gosub_ok`**（C10）。`10 gosub 30`→
`30 gosub 50`→（`50 print 5`で`5`）→`60 return`→（`30`行の`GOSUB`の次
へ戻り）`40 return`→（`10`行の`GOSUB`の次へ戻り）`20 end`という、
`GOSUB`が2重に入れ子になった構成で、両方の`RETURN`が正しく元の呼び出し
元へ戻り、`50 print 5`による出力`5`が現れた。

### 4.4 変数 — 代入と参照

**変数への代入・参照・演算は、代入した値を反映した計算結果を出力する。**
根拠: `l4-s5b-run-control-flow-results.md`判定Q4（記述のみ）。

- B7（`10 a=5`/`20 print a*2`）: 出力は`10`（`5*2`の計算結果）。
- B8（`10 i=1.5`/`20 print i+1`）: 出力は`2.5`（`1.5+1`の計算結果）。

**観測から言えること**: 無印（接尾辞無し）の変数に整数（B7の`a`）・小数
（B8の`i`）のどちらを代入しても、代入した値がそのまま計算に使われる。

**観測から言えないこと**: 無印の変数の内部の型（単精度浮動小数点として
扱われているか、整数型が別に存在し値によって自動的に切り替わるか等）は、
`PRINT`の出力（第5.3節、[l4-basic.md](l4-basic.md)）から間接的に推測でき
そうに見えるが、本測定では変数の型を直接確かめる腕（例えば整数の範囲を
超える値を代入して昇格の有無を見る腕）が無く、確認していない（第8節
「未確定」）。

### 4.4a 変数名の有効文字数

**変数名は、少なくとも3文字目までが区別される。** 根拠:
`l4-s5c-variables-flow-results.md`判定Q3、**`more_significant`**（C3）。
`10 abc=1`/`20 abd=2`/`30 print abc`を`RUN`した結果、出力は`1`のままで、
`abd`への代入の影響を受けなかった。**`abc`と`abd`は3文字目（`c`/`d`）
まで区別される別の変数だった。** 何文字目まで区別されるかの上限は
本測定では突き止めておらず、未確定のまま（第8節）。

### 4.4b 整数変数（`%`）への代入の丸め

**整数変数（`%`接尾辞）へ小数を代入すると、ちょうど半分になる値は
絶対値の大きい側へ丸められる。** 根拠: 同結果ノート判定Q4、
**`rounds_half_away`**（C4・C5・C12）。

- C4（`10 a%=5/2`/`20 print a%`、`5/2=2.5`）: 出力は`3`（絶対値の大きい
  側`3`へ丸められた。最近接偶数丸めなら`2`になるはずだが、そうならな
  かった）。
- C5（`10 a%=-5/2`/`20 print a%`、`-5/2=-2.5`）: 出力は`-3`（C4と対称に、
  絶対値の大きい側`-3`へ丸められた）。
- C12（`10 a=1`/`20 a%=a+0.5`、`1+0.5=1.5`）: 出力は`2`（絶対値の大きい
  側。最近接偶数丸めでも同じく`2`になるためこの1腕単独では区別できない
  が、C4・C5が明確に`rounds_half_away`を示しているため矛盾しない）。

この丸めの方向は、`PRINT`の浮動小数点の丸め半端（[l4-basic.md](l4-basic.md)
第5.3節、「半分は絶対値の大きい側」）と同じ形である。

### 4.4c 倍精度変数（`#`）への代入と精度

**単精度の演算結果を倍精度変数へ代入すると、単精度の丸め誤差に由来する
桁の乱れが倍精度の桁数のまま表示される。倍精度の演算結果を代入すると、
乱れは現れない。** 根拠: 同結果ノート判定Q5（記述のみ、C6・C7）。

- C6（`10 a#=1/3`/`20 print a#`、`1/3`は単精度どうしの演算）: 出力は
  `.3333333432674408`（小数点以下16桁）。単精度で計算した近似値が
  そのまま倍精度の桁数で表示され、7桁目以降（`3333334...`）に単精度の
  丸め誤差に由来するとみられる乱れた桁が現れた。
- C7（`10 a#=1#/3`/`20 print a#`、`1#/3`は倍精度どうしの演算）: 出力は
  `.3333333333333333`（小数点以下16桁、全て`3`）。C6のような桁の乱れは
  現れなかった。

**単精度→倍精度の変換そのものは正確に行われている。** C6の食い違いは
「単精度で計算した後に倍精度へ変換した」ことによる単精度側の丸め誤差の
表出であり、変換自体（単精度の値を倍精度の桁数で表示すること）が不正確
なのではない。これは[l4-basic.md](l4-basic.md)第5.1節が観測した、単精度
定数から倍精度への型の扱いの記述と整合する。

### 4.4d 文字列変数

**文字列変数への代入・参照・`PRINT`は、代入した文字列をそのまま出力
する。** 根拠: 同結果ノート判定Q6、**`string_ok`**（C8）。`10 a$="12"`/
`20 print a$`を`RUN`した結果、出力は`12`だった。**文字列の中身が数字
以外のときの出力は、本測定の記録の規則（数字で始まり表示可能ASCIIだけ
の行のみ文字コードを記録する規則）では観測しておらず、未確定のまま**
（第8節。今回は数値分類器でそのまま扱える`"12"`という中身をあえて選んで
測定したため）。

### 4.5 `STOP` と実行中の誤り

**`STOP`は、そこでプログラムの実行を止め、それ以降の行は実行されない。
出力は1行（件数のみ記録、文言は書かない）。** 根拠: 同結果ノート判定Q5
（記述のみ、B9）。`10 print 1`/`20 stop`/`30 print 2`を`RUN`した結果、
`1`（`10`行の出力）の後に`other`分類の行が1行（非空白セル件数10、桁範囲
0-11）現れて`Ok`に至り、`30`行（`print 2`）に相当する出力（`2`）は
現れなかった。**`STOP`以降の行が実行されなかったことと整合する。**

**実行中に構文の誤りが起きた場合も、出力は1行（件数のみ記録）。**
根拠: 同結果ノート判定Q5（記述のみ、B10）。`10 print 1+`（構文として

**`ABS`・`SGN`・`SQR`・`SIN`・`COS`は、割り切れる入力に対しては算術的に
期待される値を返す。** 根拠: 同結果ノート判定Q4（記述のみ、E15・E16）。

| 腕 | 打鍵文字列 | 出力 |
|---|---|---|
| E15 | `print abs(-3);sgn(-3);sgn(0)` | `3`,`-1`,`0` |
| E16 | `print sqr(16);sin(0);cos(0)` | `4`,`0`,`1` |

**割り切れない値（無理数になる`SQR`・端数の残る`SIN`/`COS`/`TAN`/`ATN`/
`EXP`/`LOG`）の値は、`l4-s6a`（第9版で追加）で観測した。** 根拠:
[l4-s6a-transcendental-functions-results.md](../notes/l4-s6a-transcendental-functions-results.md)。
測定対象はSQR・SIN・COS・TAN・ATN・EXP・LOGの7関数、42腕（無理数入力・
大きい引数・小さい引数・倍精度引数・エラー入力を含む）。GW-BASIC
（MIT公開ソース）を命令単位で読んで再現した予測器
（`tools/l4_mbf_oracle_v3.py`）との照合で、38腕中27腕（71%）が一致、
4腕がエラー系一致（`SQR(-1)`・`LOG(0)`・`LOG(-1)`・`EXP(100)`の
オーバーフローはいずれも`Illegal Function Call`/オーバーフローの表示
になった。文言は書かない）。

**単精度の通常の入力（無理数を含む）では、GW-BASIC本来の有効桁数7桁
ではなく6桁で表示される。** これは`l4-basic.md`の浮動小数点PRINT書式
（`l4-s4a`由来）で既に分かっていた既知の食い違いと同じ現象で、`l4-s6a`
でも一貫していた（S1〜S4・S6・N1〜N3・C1〜C3・T1・T3・A1〜A4・A6・
E1〜E4・E7・L1〜L3・L7の27腕がこれで一致）。

**倍精度引数（`#`サフィックス）を渡すと、単精度に丸められずに倍精度
（16桁）の結果が返る。** 根拠: `l4-s6a`のS5(`SQR(2#)`)・N5(`SIN(1#)`)・
A5(`ATN(1#)`)・E5(`EXP(1#)`)・L4(`LOG(2#)`)の5腕。値は数学的に正しい
倍精度近似（例: `ATN(1#)`はπ/4の倍精度近似、`EXP(1#)`はeの倍精度近似）
であり、倍精度のまま計算して倍精度で返しているとみられる。

**大きい引数・極端な引数では、末尾の桁がGW-BASIC本来の位取り縮約の
再現(v3予測器)とずれることがある。** 根拠: `l4-s6a`のN4(`SIN(100)`)・
C4(`COS(100)`)・T4(`TAN(100)`)・T2(`TAN(.5)`)の4腕は末尾1桁が数ULP
ずれ、N7(`SIN(1000000)`)・N6(`SIN(6.283185)`、真値がほぼ0)の2腕は
それより大きくずれた。この食い違いは、後述の`SIN`/`COS`/`TAN`の内部
計算手順（範囲縮約を単精度で行い、丸めをround-half-away化する）で
ほぼ解消したことを`l4-s6b`〜`l4-s6g`の一連の測定で確認した（下記参照）。

### 4.16a `SIN`・`COS`・`TAN`の単精度内部計算手順（`l4-s6b`〜`l4-s6g`で確定）

**`SIN`/`COS`/`TAN`は、範囲縮約（引数を2πで割った余りを求める処理）も
多項式評価（Hornerの多項式近似）も、GW-BASICのソース上の「倍精度で
範囲縮約する」現行手順ではなく、それより旧い「範囲縮約を単精度で行う」
手順に一致し、かつ内部の単精度演算（乗算・加算・減算すべて）が
第5.3a節（`l4-basic.md`）の四則演算の丸め規則（正しい丸め・
tieはround-half-away）に従う。** 根拠:

- `l4-s6b`（`docs/notes/l4-s6b-transcendental-precision-results.md`）
  でGW-BASICソースどおりの倍精度範囲縮約（候補M0）は21腕中2腕(10%)
  しか一致せず、
- `l4-s6c`（`docs/notes/l4-s6c-single-precision-range-reduction-
  results.md`）で範囲縮約を単精度に変えた候補M5が42腕中22腕(52%)まで
  改善し、
- `l4-s6d`〜`l4-s6f`（範囲縮約の乗算・多項式評価の乗算を段階的に
  正しい丸め〔round-half-even〕にする候補M6〜M8）で最終的に
  `l4-s6f`時点は21腕中12腕(57%、実質13腕)まで改善したが、`cos(44)`・
  `tan(44)`の2腕で退行が残り、
- **`l4-s6g`（`docs/notes/l4-s6g-away-rounding-transcendentals-
  preregistration.md`＋結果ノート）で、M8の構造はそのまま内部演算の
  丸めだけをround-half-away化した候補M9が、既存106腕の事後照合で
  102腕(96%)一致（M8の不一致8腕がM9で一致に転じ、M8の一致94腕からの
  退行は0腕）、新規に測定した`SIN`/`COS`/`TAN`15腕（小・中・大の引数、
  `print cdbl(...)`で単精度ビットを16桁全展開して照合）は**15腕
  全て**M9が完全一致し、M8/M0は15腕全て不一致だった。**

残る不一致4腕（`l4-s6b`のA16`sin(6.28)`・A17`sin(6.2831853)`・
A18`sin(6.3)`・A20`sin(10000000)`）は、いずれもSIN固有の別要因
（範囲縮約以外の未特定の原因、丸め方式とは無関係とみられる）が残る
（第8節「未確定」に記載）。

### 4.16b `ATN`・`EXP`・`LOG`の内部計算手順（`l4-s6h`で確定）・`SQR`（未確定のまま）

**`ATN`・`EXP`・`LOG`の内部演算（乗算・加算・減算・除算すべて）も、
`SIN`/`COS`/`TAN`と同じround-half-away丸めに従う。** `l4-s6g`の5腕
ずつ（`docs/notes/l4-s6g-away-rounding-transcendentals-results.md`）
では決定力不足だったが、`l4-s6h`（`docs/notes/l4-s6h-atn-exp-log-
more-arms-preregistration.md`＋結果ノート）で各12腕（+対照2腕）に
広げて再測定し、`print cdbl(...)`による16桁全展開の照合で次の結果を
得た。

| 関数 | 割れた腕数 | M0(even)的中 | M9(away)的中 |
|---|---|---|---|
| ATN | 12 | 2 | 10 |
| EXP | 12 | 0 | 11(+1腕は下記) |
| LOG | 12 | 0 | 12 |
| 計 | 36 | 2(6%) | **33(92%)** |

- **LOGは12腕全てM9が的中（100%）。**
- **EXPは12腕中11腕M9が的中。** 残り1腕（`exp(-7)`）は実測が
  M9予測と16桁目の1桁だけ食い違ったが（`neither_match`）、単精度の
  1ULP差なら7〜8桁目から食い違うはずの大きさであり、倍精度変換・
  16桁表示化の境界（丸め）による食い違いで、単精度の値自体はM9と
  同一とみられる。
- **ATNは12腕中10腕M9が的中。** 残り2腕（`atn(1)`・`atn(-1)`）は
  逆にM0が的中したが、この2腕はいずれも`$ATAN`の`|x|>1`判定
  （単精度`1.0`の指数バイト境界）ちょうどであり、分岐境界に起因する
  丸め方式とは別要因（`SIN`固有の残差4腕と同型の局所的な外れ）と
  みて、境界外の10腕（M9的中）を基準に確定する。

**以上により、`ATN`・`EXP`・`LOG`の内部演算のround-half-away丸めは
第4.16a節のSIN/COS/TANと合わせて確定とする。** `ATN`の`|x|=1`分岐
境界・`EXP`の`exp(-7)`最終桁食い違いは、丸め方式とは別の未解決事項
として残す（第8節参照）。

`SQR`はM0/M9で予測が割れる腕が(7桁以内の整数・小数を計算的に約76000
通り探索しても)見つからず、確定させられないまま残る（`SQR`自体の
近似精度の限界も別途残る。第8節参照）。

位置（row0, col0）そのものが主題のため、出力セル・属性の値・CRTC/DMA
への制御ポート書き込みの列は、結果ノートにある範囲で数値をそのまま
書く（属性値・制御ポートのOUT列はハードウェア設定値であり画面本文では
ないため、`tools/l4_vram_probe.py`の既存の許容範囲どおり書いてよい。
禁止事項5が対象とするデータポート`$FB`/`$FC`/`$FD`とは別の区分）。
`Ok`・入力エコー・誤りの行は件数と位置の範囲だけで、文字は書かない。

### 5.1 `CLS`（`CHR$(12)`を含む）

**`CLS`は画面を消す。消した後に残るのは、`Ok`相当の行と、ファンクション
キー表示の行だけである。プログラム中の`CLS`も同じ。** 根拠: 同結果
ノート判定Q1・Q7、**`clears`**（F1・F10・F11）。

| 腕 | 打鍵文字列 | 消去後に残った行 |
|---|---|---|
| F1 | `print 1`/`cls` | 絶対行0（件数3、`Ok`相当）・絶対行19（件数21、ファンクションキー表示相当） |
| F10 | `new`/`10 cls`/`20 print 7`/`run`（プログラム中の`CLS`） | 絶対行0（件数1、`7`）・絶対行1（件数3、`Ok`相当）・絶対行19（件数21） |
| F11 | `print chr$(12);7`（`CHR$(12)`による消去） | 絶対行0（件数1、`7`）・絶対行1（件数3、`Ok`相当）・絶対行19（件数21） |

いずれも消去前より非空白セル総数が大きく減り、絶対行19（ファンクション
キー表示の行、[l3-main.md](l3-main.md)第13節参照）だけは消去の対象外
だった。**`CHR$(12)`は`CLS`と同じ画面消去を起こす。**

### 5.2 `LOCATE`

**`LOCATE`の第1引数が桁（x）、第2引数が行（y）として働く。原点
`LOCATE 0,0`は絶対行0・絶対桁1（数値の符号位置の空白を含む）に対応する。
既存の行の内容の上に上書きが起きる。** 根拠: 同結果ノート判定Q2、
**`locate_x_then_y`**（F2・F3・F12）。

| 腕 | 打鍵文字列 | 出力位置 |
|---|---|---|
| F2 | `locate 10,5:print 7` | 絶対行5・絶対桁11（`y=5`が行、`x=10`が桁+符号1桁） |
| F3 | `locate 0,0:print 7` | 絶対行0・絶対桁1（原点でも同じ対応） |
| F12 | `print 1`/`print 2`/`locate 0,1:print 9` | `locate`実行前の絶対行1（`y=1`と一致）に3セルの変化。変化前のセルは空白ではなかった（既存の内容への上書き） |

### 5.3 行の端での折り返し（観測、推定は分けて記す）

**観測**: `LOCATE`で行の右端に近い桁を指定すると、その行には変化が
現れず、次の行に変化がまとまって現れた。根拠: 同結果ノート判定Q3
（記述のみ、F4）。`locate 78,5:print 12`を実行すると、`x,y`対応から
予想される絶対行5には変化が一切現れず、絶対行6（1行下）にまとまって
変化が現れた（`other`分類、件数16・桁範囲1-19。値は書かない）。

**推定**: 行の右端付近では、その行の末尾で止まったり打ち切られたり
せず、次の行の先頭へ折り返して続きが書かれることが示唆される。ただし
絶対行6の内容自体は`other`のためデコードしておらず、折り返した具体的な
文字位置までは確認できていない（未確定、第8節）。

### 5.4 `COLOR`と属性域

**`COLOR`の引数の値は、属性域の(位置,値)組の値バイトにそのまま入る。**
根拠: 同結果ノート判定Q4（記述のみ、F5・F6）。`7`が出力されたセルの
属性域（[l3-main.md](l3-main.md)第3節、`--attr-only-rows`）の先頭2バイト
は、F5（`color 2`）で`0302`、F6（`color 7`）で`0307`だった。2バイト目
（`02`・`07`）が`COLOR`の引数の値と一致し、1バイト目（`03`）は両腕で
共通だった。

**[l3-main.md](l3-main.md)の属性域の構造（第3節、40バイトは80桁への
逐次対応ではなく2バイト1組×20組の(位置バイト,値バイト)の並び）と
整合する。** 本測定で見えた「先頭2バイト」は、その最初の(位置,値)組
そのものであり、1バイト目が位置バイト・2バイト目が値バイト（`COLOR`の
引数）という対応で説明でき、既存の属性域の構造の記述と食い違わない。
値バイトの各ビットが色のどの成分に対応するか（色番号との対応式）は、
本測定では特定していない（未確定、第8節）。

### 5.5 実行中のスクロール

**プログラム実行中の出力が画面の行数を超えると、古い行が上へ押し出され
て消え、新しい行が下に追加される形でスクロールする。** 根拠: 同結果
ノート判定Q6（記述のみ、F9）。`for i=1 to 25`で25回`print i`した結果、
実行完了時点で画面に残っていたのは、絶対行6〜16の11行に後半の値
（`i`の大きいほう11個）が1行1値で連続して現れた部分だけだった（`i`の
小さいほうの値は画面の行数を超えた時点で上へスクロールして失われた）。

### 5.6 `WIDTH`

**`WIDTH 80,25`は、これまでの測定（[l3-main.md](l3-main.md)、
120バイト/行のストライド・表示行数に応じたファンクションキー表示行の
位置）と整合する。** 根拠: 同結果ノート判定Q5（記述のみ、F8）。
`width 80,25`/`print 7`を実行すると、絶対行0〜3に整った形（`Ok`相当・
入力エコー・出力・`Ok`相当）で出力が収まり、加えて絶対行24（件数21）が
変化した。この絶対行24は、[l3-main.md](l3-main.md)の既存測定が示す
`WIDTH80,25`のファンクションキー表示行の位置（row0=24）とおおむね
一致する。CRTC・DMAへの制御ポート（`0x50`・`0x51`・`0x64`・`0x65`・
`0x68`）へのOUTは、起動時と同じポートへの書き込みが`width`文の実行
付近でもう一度発生し、ポート`0x65`の値が起動時（`5F`・`89`）と異なる
値（`B7`・`8B`）になった。OUT総数は4038件（内訳: `0x50`=2679・
`0x51`=1341・`0x64`=6・`0x65`=6・`0x68`=6）。

**`WIDTH 40`は、上記のストライドの前提（120バイト/行）が崩れたため、
出力位置を一意に特定できなかった。** 根拠: 同結果ノート「WIDTH40の
前提について」節。`width 40`/`print 7`を120バイト/行のストライドで
読むと、単一の`print 7`文には不釣り合いに大きい変化（絶対行0〜4に
件数3・19・22・27・14、絶対行19に件数27）が複数行にわたって現れ、
`WIDTH80,25`（F8、絶対行0〜3に収まる整った形）とは全く異なる形になった。
**この食い違いは、120バイト/行という前提が`WIDTH 40`には当てはまらない
ことを示唆する**（実際のストライドがより小さく、120バイト単位で読むと
隣接する複数行のデータが混ざって見えるため、と考えられる）。CRTC・
DMAへの制御ポートへのOUT総数は3966件（内訳: `0x50`=2631・`0x51`=1317・
`0x64`=6・`0x65`=6・`0x68`=6）で、3回目のポート`0x65`への値は起動時と
完全に同じ（`5F`・`89`）だった。**`WIDTH 40`のときのテキストVRAMの
並び（1行あたりのストライド・アドレス空間）そのものは、本測定では
特定できておらず未確定のまま**（第8節）。

## 6. 観測 — `READ`/`DATA`・`REM`・1行に複数の文

対象は`l4-s5g`（12腕＋陽性対照、`4d7945f`）。結果ノート
`l4-s5g-read-data-rem-multi-results.md`（`4d7945f`）・事前登録
`l4-s5g-read-data-rem-multi-statement-preregistration.md`（`3cd23ed`）。
以下の打鍵文字列・`RUN`出力は、いずれも自分で打ったプログラムを
`RUN`が`PRINT`した数値であり、禁止事項7の対象外（結果ノート「禁止事項7の
遵守について」節が明示的に許可する範囲）。`DATA`切れの出力（6.3節）だけは
件数と桁範囲のみで、値・文言は書かない。

| 腕 | 打鍵文字列 | `RUN`の出力 |
|---|---|---|
| G1 | `10 read a,b`/`20 print a+b`/`30 data 3,4` | `7`（`a+b`=`3+4`） |
| G2 | `10 for i=1 to 3`/`20 read a`/`30 print a;`/`40 next`/`50 data 5,6,7` | `5`・`6`・`7`（`;`で1行に3値） |
| G3 | `10 read a`/`20 restore`/`30 read b`/`40 print a;b`/`50 data 8,9` | `8`・`8`（1行に2値） |
| G4 | `10 read a$`/`20 print a$`/`30 data 12` | `12`（文字列変数への`READ`） |
| G5 | `10 if 1 then a=5`/`20 print a` | `5` |
| G6 | `10 dim a(3)`/`20 a(0)=7`/`30 print a(0)` | `7` |
| G7 | `10 a=1:b=2:print a+b` | `3`（`1+2`） |
| G8 | `10 read a`/`20 print a`（`DATA`文なし） | 出力1行（`other`、件数14・桁0-17） |
| G9 | `10 print 1:rem 9`/`20 print 2` | `1` → `2`（2行） |
| G10 | `10 ' 9`/`20 print 3` | `3` |
| G11 | `10 a=2:if a=2 then print 1:print 2`（真） | `1` → `2`（2行） |
| G12 | `10 if 0 then print 1:print 2`/`20 print 3`（偽） | `3`のみ |

根拠: `l4-s5g-read-data-rem-multi-results.md`「腕ごとの記録」節・判定
Q1〜Q8。

### 6.1 `READ`/`DATA`

**`READ`は`DATA`の値を、書かれた変数の並びの順に、また文の実行順に
（ループの中で複数回`READ`が実行される場合も含め）順に読み出す。**
根拠: 同結果ノート判定Q1、**`read_ok`**（G1〜G4の全腕）。

- G1（`read a,b`/`data 3,4`、複数の変数への同時`READ`）: 出力は`7`
  （`a=3`・`b=2`ではなく`a=3`・`b=4`として読まれ、`a+b`=`3+4`が正しく
  計算された）。**`,`区切りで複数の変数へ同時に`READ`できる。**
- G2（`FOR`ループの中で`read a`を3回、`data 5,6,7`）: 出力は`5`・`6`・
  `7`の3値。**ループの中で`READ`を複数回実行すると、`DATA`の値を
  順に読み進める**（1回目は`5`、2回目は`6`、3回目は`7`）。
- G3（`read a`→`restore`→`read b`、`data 8,9`）: 出力は`8`・`8`。詳細は
  6.2節（`RESTORE`）。
- G4（`read a$`、`data 12`）: 出力は`12`（文字列出力のため符号位置の
  空白は無い）。**`DATA`に書いた数字は、文字列変数へ`READ`すると
  文字列として読み込まれる。**

### 6.2 `RESTORE`

**`RESTORE`は、その後の`READ`が`DATA`の先頭から読み直されるように、
読み取り位置を先頭へ戻す。** 根拠: 同結果ノート判定Q2、
**`restore_ok`**（G3）。`10 read a`/`20 restore`/`30 read b`/
`40 print a;b`/`50 data 8,9`を`RUN`した結果、出力は`8`,`8`
（2回目の`read b`は`DATA`の2番目の値`9`ではなく、`RESTORE`により
先頭へ戻った`DATA`の1番目の値`8`を再び読んだ）。

### 6.3 `DATA`切れ（誤り）

**読み出す`DATA`が無い状態で`READ`を実行すると、誤りとして扱われ
出力は1行（件数のみ記録、文言は書かない）。** 根拠: 同結果ノート
判定Q6（記述のみ、G8）。`10 read a`/`20 print a`（`DATA`文が無い）を
`RUN`した結果、`run`の入力エコー行の直後に`other`分類の行が1行
（非空白セル件数14、桁範囲0-17）現れて`Ok`に至り、`20 print a`に
相当する数値出力は現れなかった。数字0-9のコードを持つセルが少なく
とも1つ含まれることは真偽値として確認したが、具体的な数字・文言は
記録していない（禁止事項7）。**`STOP`・実行中の誤り（第4.5節）と
同じ扱いの誤りである。**

### 6.4 `THEN` の後の代入

**`IF`の`THEN`の後には、行番号だけでなく代入文を直接書け、条件が真の
とき実行される。** 根拠: 同結果ノート判定Q3、**`then_assign_ok`**
（G5）。`10 if 1 then a=5`/`20 print a`を`RUN`した結果、`print a`の
出力は`5`だった。第4.7節（`IF`〜`THEN`〜`ELSE`）の`THEN`の後の形
（`PRINT`文・行番号）に加え、代入文も直接書けることを確認した。

### 6.5 配列の添字 `0`

**配列の添字`0`は有効で、代入・参照ができる。** 根拠: 同結果ノート
判定Q4、**`index0_ok`**（G6）。`10 dim a(3)`/`20 a(0)=7`/
`30 print a(0)`を`RUN`した結果、出力は`7`だった。第4.10節の配列の
基本動作（`DIM`宣言・宣言なしの範囲外）に加え、添字の下限側
（`0`）も期待どおりに機能することを確認した。

### 6.6 `:` で1行に複数の文

**`:`で区切った複数の文は、1行の中で順に全て実行される。** 根拠:
同結果ノート判定Q5、**`multi_ok`**（G7）。`10 a=1:b=2:print a+b`を
`RUN`した結果、出力は`3`（`1+2`）で、代入・代入・`PRINT`の3つの文
（`a=1`・`b=2`・`print a+b`）が全て実行された。

### 6.7 `REM` と `'`

**`REM`・`'`の後に書いた内容は注釈として実行されず、プログラムは
次の行へ進む。同じ行の他の文には影響しない。** 根拠: 同結果ノート
判定Q7、両腕とも**`rem_ok`**（G9・G10）。

- G9（`10 print 1:rem 9`/`20 print 2`）: 出力は`1`→`2`の2行。`:`で
  `rem 9`につないでも、それ以前の文（`print 1`）は実行され、`rem 9`
  自体は何も出力を起こさず、次の行（`20 print 2`）もそのまま実行
  された。
- G10（`10 ' 9`/`20 print 3`）: 出力は`3`の1行。`'`によるコメント
  だけの行（`10 ' 9`）は実行に影響せず、次の行（`20 print 3`）が
  そのまま実行された。

### 6.8 `IF` と同じ行の残り

**`IF`の条件が真なら、`THEN`の後の`:`以降も含めて同じ行の残りが
全て実行される。条件が偽なら、`THEN`の後だけでなく、同じ行の`:`
以降も含めてすべて飛ばされる。** 根拠: 同結果ノート判定Q8
（G11・G12）。

- G11（`10 a=2:if a=2 then print 1:print 2`、条件`a=2`は真）:
  **`rest_runs_when_true`**。出力は`1`→`2`の2行。`THEN`の後の
  `print 1`だけでなく、`:`でつないだ`print 2`も実行された。
- G12（`10 if 0 then print 1:print 2`/`20 print 3`、条件`0`は偽）:
  **`rest_skipped_when_false`**。出力は`3`の1行だけだった。`10`行の
  `print 1`・`print 2`のどちらも出力に現れず、**`THEN`の後の文
  だけでなく、同じ行の`:`以降（`print 2`）も含めてすべて飛ばされた**
  （`print 2`だけが実行される`rest_runs_when_false`ではなかった）。

## 7. 参考 — トークン番号との関係（実装への注意）

**`LIST`の目標は打鍵の文字どおりの再現であり、公式のトークンの並び・
番号とは無関係である。** 語の一覧・トークン番号の割り当て規則
（`docs/notes/l4-token-design.md`・`src/l4_basic/tokens.tsv`、辞書順に
`0x80`から採番）は自作BASICが内部でプログラムをどう格納するかを決める
自前の規則であり、公式ROMの内部表現を読み取ったものではない（禁止事項2）。
本書の第2節が定める`LIST`の出力書式（行番号・大文字化・空白の保持・`?`展開）
は、内部のトークン化方式によらず**打鍵した文字列を再構成した結果の見え方**
として実装すればよい（ゴールA、`docs/notes/l4-design.md`）。トークン番号の
表そのものはこの仕様書の対象外であり、書き写さない。

## 8. 未確定（材料に無いため、この版では埋めない）

以下は次の測定・段階で扱う。**推測で埋めない。**

1. **命令語以外の英字（変数名等）の大文字・小文字の扱い。** `l4-s5a`の
   12腕はいずれも命令語（`print`・`?`）のみを含み、変数名を打った腕が
   無いため、変数名が`LIST`出力でどう表示されるか（大文字化されるか、
   打鍵どおりか）は観測していない。
2. **行番号の上限。** A9で`65529`（65530未満の大きな値）は正しく扱えた
   ことを確認したが、行番号として許される最大値・範囲外を打ったときの
   挙動は観測していない。
3. **空行（行番号だけでなく、内容が空の行）の扱いの一般形。** A8で
   「行番号だけを打つと削除される」ことは確認したが、これは既存の行が
   ある場合の削除であり、存在しない行番号だけを打った場合の反応（何も
   起きないか、`Ok`が出るか等）は観測していない。
4. **行番号の前の空白。** `l4-s5a`の腕はいずれも行頭（打った行の先頭）
   から行番号を打っており、行番号の前に空白を入れて打った場合に`LIST`
   出力がどうなるかは観測していない。
5. **`LIST`の範囲指定（例: `LIST 10-20`のような形式）。** `l4-s5a`は
   引数無しの`list`だけを測定しており、範囲・単一行を指定する`LIST`の
   構文・出力は観測していない。
6. **画面に収まらない長さのプログラム・行の扱い。** `l4-s5a`の12腕は
   いずれも`LIST`出力が画面の行数（25行）に十分収まる短いプログラムで、
   スクロール等が必要になる場合の挙動は[l3-main.md](l3-main.md)の一般則
   （スクロール）を参照する想定だが、プログラムモード特有の挙動
   （例えば`LIST`の途中でのキー入力によるページ送り等）があるかは
   本測定では確認していない。
7. **`other_line`（`Ok`行・入力エコー行以外に現れうる行、例えば構文の
   誤りがあった場合の行）の文言・書式。** 禁止事項7によりエラー
   メッセージ等の本文は測定で扱っておらず、`l4-s5a`の12腕でも
   `other_line`はいずれも想定どおりの2行（`new`直後の`Ok`行、`list`の
   入力エコー行）に限られ、構文の誤り等を伴う`other_line`は今回
   観測していない（[l4-basic.md](l4-basic.md)第6節の直接モードの構文の
   誤りとは別に、プログラムモードでの確認が必要）。
8. **`RETURN without GOSUB`等、流れの制御に関する誤りの形（第2版で
    追加）。** `l4-s5b`のQ5（4.5節）は`STOP`・構文の誤りだけを対象と
    しており、`GOSUB`を経ずに`RETURN`した場合、`NEXT`に対応する`FOR`
    が無い場合等の誤りの出力の形（件数・行数）は観測していない。
9. **止まらないプログラムの止め方（`STOP`キー等）（第2版で追加）。**
    4.6節のB11（無限ループ）は、出力が生成され続けていることは確認
    したが、実行を途中で止める手段は本測定の器具（打鍵注入）では
    再現できず確認していない（`l4-s5b-run-control-flow-preregistration.md`
    「B11の扱い」節、器具に専用オプションが無いことを確認済み）。
10. **変数名の有効文字数の上限（第4.4a節、第3版で更新）。** `l4-s5c`
    （C3）で「少なくとも3文字目までは区別される」ことは確認したが、
    何文字目まで区別されるか（上限）・大文字小文字混在の変数名が
    区別されるかは観測していない。
11. **配列の次元・添字の下限と上限（第4.10節、第4版で範囲を訂正）。**
    `l4-s5d`（D9〜D11）で1次元の配列の基本動作（`DIM`宣言あり・なし・
    範囲外）は確認できたが、多次元の配列（`DIM a(3,3)`のような形）、
    添字の下限（`0`から使えるか）、宣言なしの配列の添字上限が
    `10`ちょうどのときにどうなるか（推定`10`、第4.10節参照）は観測
    していない。
12. **文字列の中身が数字以外のときの出力（第4.4d節、第3版で追加）。**
    `l4-s5c`のC8は数字だけの文字列（`"12"`）をあえて選んで測定してお
    り、既存の記録の規則（数字で始まり表示可能ASCIIだけの行のみ文字
    コードを記録する規則）では、英字等を含む文字列変数の出力を観測
    できない。中身が数字以外の文字列変数の出力の形は未確定。
13. **`STOP`・実行中の誤りのメッセージが実機・エミュレータの画面表示と
    一致するか（第4.5節、第2版で追加）。** [l4-basic.md](l4-basic.md)
    第7.1節のマニュアルのエラーメッセージ一覧（行番号付きの形を含む）
    を参照する方針としたが、一致の確認そのものは本版では行っていない
    （[l4-basic.md](l4-basic.md)第10節と同じ扱い）。
14. **`ELSE`の無い`IF`の後の`:`（第4版で追加）。** `l4-s5d`の腕は
    いずれも`IF`〜`THEN`の後に別の文を`:`で連結する形（例:
    `IF x THEN y:z`のように`THEN`側の複数文）を含んでおらず、`ELSE`が
    無い`IF`文の後ろに`:`で文を続けた場合の扱いは観測していない。
15. **比較の演算子の優先順位（第4版で追加）。** `l4-s5d`のD15
    （`1<2 and 3<4`）は複合条件が正しく評価されることまでは確認したが、
    比較演算子（`<`・`>`・`=`等）と算術演算子・論理演算子（`AND`・`OR`
    等）の優先順位そのもの（例えば`a+1<b*2`のような式でどちらが先に
    評価されるか）を突き詰める腕は無く、観測していない。
16. **文字列の比較（第4版で追加）。** `l4-s5d`の比較演算（4.8節）は
    数値どうしの比較のみを対象としており、文字列どうしの比較
    （`"abc"="abc"`のような形）の可否・結果の値は観測していない。
17. **負の数に対する`\`・`MOD`、`^`の結果の型（第4.12節、第4版で追加）。**
    `l4-s5d`のD14は正の整数どうしの演算のみを対象としており、負の数を
    含む整数除算・剰余の挙動（商・剰余の符号）、べき乗`^`の結果の型
    （整数のままか、単精度・倍精度浮動小数点になるか）は観測していない。
18. **`INPUT`のプロンプトの形（第4.13節、第5版で追加）。** `l4-s5e`
    （E1・E2）はプロンプト行の非空白セル件数（1件）だけを確認しており、
    プロンプトの記号・書式そのものは記録していない（禁止事項7）。
19. **`?Redo from start`等、`INPUT`の再入力（第5版で追加）。** `l4-s5e`
    の腕はいずれも1回で有効な値を入力しており、型に合わない値（数値
    変数に文字列を入力する等）や個数が足りない入力を打った場合に
    再入力を促す動作があるかは観測していない。
20. **`CHR$`（`CHR$(12)`以外）・`INKEY$`・`STRING$`・`SPACE$`等、未測定
    の文字列関数（第5版で追加、第6版で範囲を訂正）。** `l4-s5e`は
    `MID$`・`LEN`・`LEFT$`・`RIGHT$`・`VAL`・`STR$`・`ASC`・`+`結合
    （第4.14節）を、`l4-s5f`は`CHR$(12)`が`CLS`と同じ画面消去を起こす
    こと（第5.1節）を確認したが、これら以外の文字列関数・`CHR$`の他の
    引数の値（文字コードとしての出力等）は観測していない。
21. **超越関数の倍精度専用経路・SIN固有の残差・ATNの分岐境界・EXPの
    最終桁食い違い・SQRの反復手順（第4.16節、第5版で追加、第9版で
    範囲を訂正、第10版・第11版で更新）。**
    `SIN`/`COS`/`TAN`の内部計算手順（範囲縮約の単精度化・演算の
    round-half-away丸め）は第4.16a節（`l4-s6g`）で、`ATN`/`EXP`/`LOG`
    の内部演算（round-half-away丸め）は第4.16b節（`l4-s6h`）で確定
    したが、以下は未確定のまま残る。(a) 倍精度引数(`#`)がなぜ倍精度で
    返るのか（GW-BASIC(IBM PC版)のMATH1.ASM/MATH2.ASMを読んだ限りでは
    $SIN等は単精度(`$FAC`)前提の命令列に見えるため、N88-BASIC固有の
    倍精度専用経路が別に存在する可能性が高いが未確認）、(b) `l4-s6b`の
    A16・A17・A18・A20（`sin(6.28)`等、真値がほぼ0に近い引数）に残る
    大きな不一致の原因（第4.16a節「残る不一致4腕」）、(c) `ATN`の
    `|x|=1`分岐境界（`atn(1)`・`atn(-1)`だけM0が的中した原因、
    第4.16b節・`l4-s6h`）、(d) `EXP`の`exp(-7)`だけ16桁目1桁が食い違う
    原因（第4.16b節・`l4-s6h`、単精度値自体はM9と同一とみられる）、
    (e) `SQR`自体の近似精度の限界（`l4-s6g`のZ31・Z35で内部丸め方式に
    依らず既知実装からULP単位でずれ、`l4-s6h`でも約76000通りの計算
    探索でM0/M9の予測が割れる入力が見つからなかった。GW-BASICの
    ニュートン法反復手順そのものは未特定のまま）。
    拡張ROMバンクでこれらを実装する前に、倍精度専用経路の有無・
    ATN境界/EXP最終桁の原因・SQRの反復手順を狙った追加測定が要る。
22. **`WIDTH 40`のテキストVRAMの並び（第5.6節、第6版で追加）。**
    `l4-s5f`のF7は、`WIDTH 80,25`と同じ120バイト/行のストライドという
    前提では出力位置を一意に特定できず、この前提が`WIDTH 40`には
    当てはまらないことを示唆する結果になった。実際のストライド・
    アドレス空間は未確定のまま、再測定が要る。
23. **`COLOR`の引数の範囲と色の意味（第5.4節、第6版で追加）。**
    `l4-s5f`のF5・F6は`color 2`・`color 7`の2値だけを対象としており、
    引数として使える値の範囲（0〜7以外を含むか）、属性域の値バイトの
    各ビットが色のどの成分（前景色・背景色・反転等）に対応するかは
    観測していない。
24. **`LOCATE`の範囲外の指定（第6版で追加）。** `l4-s5f`のF2・F3・F12
    は画面内に収まる座標だけを対象としており、桁・行に画面の範囲を
    超える値を指定した場合の挙動は観測していない（F4は範囲内の右端
    付近であり範囲外そのものではない）。
25. **行の端での折り返しの厳密な規則（第5.3節、第6版で追加）。**
    `l4-s5f`のF4は「次の行にまとまって変化が現れる」ことまでは観測
    したが、折り返した具体的な文字位置・桁数の規則は`other`分類の
    ため確認できていない（推定にとどまる）。
26. **`CONSOLE`・スクロールの対象範囲の詳細（第6版で追加）。** `l4-s5f`
    は`CONSOLE`文そのものを打った腕を含んでおらず、[l3-main.md](l3-main.md)
    第15節の範囲（表示行数−1等）とプログラムモードでの`RUN`中の
    スクロール（第5.5節）が同じ範囲になるかどうかの直接の突き合わせは
    行っていない。
27. **`PRINT USING`（書式指定付きのPRINT）（第5版で追加）。** 本版までの
    測定は素の`PRINT`（[l4-basic.md](l4-basic.md)第2〜5節）だけを対象と
    しており、`PRINT USING`の書式指定子・出力の形は観測していない。
28. **`RESTORE`への行番号指定（第7版で追加）。** `l4-s5g`のG3は引数の
    無い`RESTORE`（`DATA`の先頭へ戻る）だけを測定しており、
    `RESTORE 100`のように行番号を指定して特定の`DATA`行から読み直す
    形は観測していない。
29. **`DATA`の文字列の引用符・区切りの扱い（第7版で追加）。** `l4-s5g`
    のG1〜G4はいずれも引用符無しの数字（`data 3,4`等）だけを対象と
    しており、`DATA`に引用符付きの文字列（`data "a,b"`のようにカンマを
    含む値）を書いた場合の区切りの扱い・引用符の要否は観測していない。
30. **`ELSE`と`:`の組み合わせ（第4版から継続、第7版で範囲を明確化）。**
    `l4-s5g`のG11・G12は`ELSE`の無い`IF`〜`THEN`〜`:`の形（6.8節）を
    確認したが、`IF`〜`THEN`〜`:`〜`ELSE`〜`:`のように`ELSE`側にも
    `:`で複数の文を続けた場合の実行範囲は観測していない（第14項と
    合わせて未確定）。
31. **`REM`の後の`:`（第7版で追加）。** `l4-s5g`のG9（`10 print 1:rem 9`）
    は`REM`が行の末尾に来る形だけを測定しており、`REM`の後にさらに
    `:`が続く形（例: `10 rem 9:print 1`）で、`:`以降も注釈として
    無視されるか、`:`が区切りとして働き次の文が実行されるかは
    観測していない。
32. **`RND`（乱数関数）（第7版で追加）。** これまでの測定は`RND`を
    対象に含めておらず、引数の意味（負・0・正での再現性の違い等）・
    値の範囲は観測していない。
