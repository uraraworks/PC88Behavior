# L4 BASIC — 直接モードの PRINT

仕様書 第3.24版 / 2026-10-04

測定対象: エミュレータ QUASI88 libretro 版、コア既定 N88 V2、ディスク無し、公式ROM一式。

`docs/spec/` の書き方は [l3-main.md](l3-main.md) に倣う。**「観測」と「推定」を節ごとに
分け、実装は観測にだけ従う。** さらに本書では「観測」と「資料の記載」も節を分ける
（測定 > 資料の原則。資料の記載は判定の根拠にしない）。**画面本文
（公式ディスクの一覧・第三者由来の文字列など）はこの文書のどこにも書かない**
（`CLAUDE.md` 禁止事項7）。書いてよいのは、自分で指定した打鍵文字列とその直接の
結果（数値・記号・エコー）、非空白セルの件数・位置範囲、番地・行列番号までである
（`l4-s3a-print-format-preregistration.md`「本文を出さない取り扱い」の区分を踏襲）。

画面出力・行入力・スクロール・キー入力・テキストVRAMの構造は
[l3-main.md](l3-main.md)（第3版）にすでにあるので、ここでは重複して書かず参照のみ行う。

## 1. 観測 — 直接モードの行の扱い

**打った行を確定すると、その直後の行に実行結果が出力され、さらにその次の行に
`Ok` が出る。** 打った行を相対行0とすると、出力の行は相対行+1、`Ok` の行は
相対行+2で、全腕（構文の誤りを含む）で一貫していた。

根拠: `l4-s3a-print-format-results.md` Q4（記述のみ、判定名なし）。P1-7腕を含む
測定した全腕でこの並びが観測された。末尾に `;`・`,` を付けて2文に分けて打った
腕（P3-trail-semi・P3-trail-comma）でも、1文目→出力→`Ok`→2文目→出力→`Ok`という
同一パターンが繰り返された（第4節参照）。

直接モードの各行の先頭の絶対位置・番地は [l3-main.md](l3-main.md) 第2節の式
（`addr = 0xF3C8 + row0*120 + col0`）にそのまま従う。全腕で打った行の先頭セルは
絶対位置 (row0=6, col0=0)、番地 `F698` で一致した（`l4-s3a-print-format-results.md`
「原点」節）。浮動小数点の測定（第5節、`l4-s4a`・`l4-s4b`・`l4-s4c`）でも、全腕で
打った行の先頭セルは同じ絶対位置 (row0=6, col0=0) で一致している。

## 2. 観測 — PRINT: 整数の書式

**整数の前には符号のための1桁が確保される。正の数・0では空白、負の数では
`-`。** 根拠: `l4-s3a-print-format-results.md` Q1（判定`sign_space_before`）。
P1-0・P1-1・P1-7・P1-10・P1-32767の5腕で、出力行の相対列0が変化せず(元の空白
0x20のまま)数字が相対列1から始まった。P1-m1・P1-m32768の2腕では相対列0に
`-`(0x2D)が書き込まれ、数字は相対列1から始まった。

**整数の後ろには空白が1つ付く。符号の正負・桁数によらず一定（`trailing_space_1`）。**
根拠: `l4-s3a-print-format-results.md` Q1・Q3、および
`l4-s3b-print-trailing-results.md` Q1。`print 1;2` の腕（P3-semi-num、第4節）で、
`1`と`2`の間に2列ぶんの空白が生じ、これが「`1`の後置の空白1」＋「`2`の前置の
空白1」で説明できることから、正の数の後置空白がまず間接的に確認された
（l4-s3a）。続く `l4-s3b` では `PRINT n;"q"`（n = 5, -5, 0, 32767, -32768）の
5腕すべてで、数字末尾と`q`の間の未変化セルが1列で一致し、**正の数・0・負の数・
桁数によらず後置空白1であることが直接確認された**（P1Q-m5・P1Q-m32768で
負の数の後置空白を直接確認）。

## 3. 観測 — PRINT: 文字列の書式

**文字列の前後には空白が付かない。** 根拠: 同結果ノートQ2（判定名なし、記述の
み）。1文字列だけを出力する腕で、出力行の相対列0（先頭そのもの）から文字列が
始まった。後ろに何か付くかは単独腕からは直接確認できないが、文字列どうしを
`;` で連結する腕（第4節のP3-semi-str）で2つの文字列が間隔0で隣接したことから、
数値のような前置・後置の空白が無いと分かる。

## 4. 観測 — PRINT: 区切り記号（`;` と `,`）とゾーン幅

| 区切りの形 | 直前出力との間隔 | 判定 |
|---|---|---|
| 数値`;`数値 | 2列（空白2セル） | `no_suppress` |
| 数値`,`数値 | 14列 | `no_suppress`（ゾーン区切り、`zone_14`） |
| 文字列`;`文字列 | 0列（隣接） | `suppresses_between` |
| 文字列`,`文字列 | 14列 | `no_suppress`（ゾーン区切り、`zone_14`） |
| 数値`,`数値`,`数値 | 14列・14列 | `zone_14` |
| 末尾`;`（別々の2文に分けて打つ） | — | `newline_not_suppressed` |
| 末尾`,`（別々の2文に分けて打つ） | — | `newline_not_suppressed` |

根拠: `l4-s3a-print-format-results.md` Q3。

- **数値どうしの`;`は数値自身の書式（前後の空白）をそのまま残すだけで、`;`
  自体が追加の区切りを足すわけではない。** 2列の間隔は「前の数値の後置空白1」
  ＋「後ろの数値の前置空白1」で説明できる（第2節と符合）。
- **文字列どうしの`;`は直前の出力に直後で続く（間隔0）。** 数値の`;`とは
  異なる。
- **`,`はいずれも14列間隔のゾーン区切りになる（`zone_14`）。** 数値・文字列
  どちらも同じ幅で、3個並べても14列ずつだった。資料の記載「14文字ごと」
  （第7節）と一致する。
- **末尾の`;`・`,`は、別々の直接モード文2つに分けて打った構成では、2文目の
  出力を1文目と同じ行には続けなかった（`newline_not_suppressed`）。** これは
  直接モードが1文実行するごとに新しい行で`Ok`を出してから次の入力を待つ
  ためで、末尾の`;`・`,`が本来持つ「改行を起こさない」効果そのものは、この
  構成では`Ok`の改行に隠れて直接には確認できなかった（`l4-s3a-print-format-results.md`
  「言えないこと」）。

**行末の`;`・`,`の改行抑止効果（`l4-s3b`で確認）**: 単一の直接モード行の中で
`:`を使って2文を連結する形（`PRINT "a";:PRINT "b"`・`PRINT "a",:PRINT "b"`）
で追試したところ、`Ok`の改行に隠れずに直接確認できた。根拠:
`l4-s3b-print-trailing-results.md` Q2・Q3。

- **行末の`;`は改行を抑止し、次の出力が同じ行に間隔0で続く（`semicolon_suppresses`）。**
  `PRINT "a";:PRINT "b"` で `a`・`b` が同じ行の隣接列（間隔0）に出た。
- **行末の`,`は改行を抑止し、次の出力が同じ行の次のゾーン境界（列14）から
  始まる（`comma_to_zone_14`）。** `PRINT "a",:PRINT "b"` で `b` が同じ行の
  列14に出た。ゾーン幅14は第4節（数値・文字列間の`,`）と一致する。
- 対照（区切りなし、`PRINT "a":PRINT "b"`）では `b` が次の行の先頭列に出た
  （関門G5）。

## 5. 観測 — PRINT: 浮動小数点の書式

対象は`l4-s4a`（浮動小数点PRINTの出力の形、32腕）・`l4-s4b`（仮説H6＝単精度は
有効6桁で指数表記に切り替わる、23腕）・`l4-s4c`（小さい数〔`|v|<1`〕の固定⇔
指数表記の切替、候補の消去、20腕）の3測定。以下の値・記号は、いずれも自分で
指定した式（`PRINT`の引数）の直接の出力であり、禁止事項7の対象外（各事前登録
「本文を出さない取り扱い」節が明示的に許可、非数値出力〔範囲外・0除算〕の2腕
〔第5.6節〕だけは値を書かない）。

### 5.1 数値定数の型 — 桁数による単精度/倍精度の決まり方

**整数のように書いた定数は、小数点を除いた数字の個数が7桁以内なら単精度、
8桁以上なら倍精度になる。** 根拠: `l4-s4a-float-print-results.md`。

| 腕 | 打鍵文字列（桁数） | 実測の出力 |
|---|---|---|
| E1 | `print 999999`（6桁） | `999999`（固定、丸めなし） |
| E2 | `print 9999999`（7桁） | `1E+07`（単精度6桁に丸められ指数化。第5.4節） |
| E3 | `print 10000000`（8桁） | `10000000`（固定、8桁全部がそのまま出た） |
| D4 | `print 1234567.8`（8桁） | `1234567.8`（固定、8桁全部がそのまま出た） |
| D5 | `print 12345678`（8桁） | `12345678`（固定、8桁全部がそのまま出た） |

E2（7桁）は単精度の丸め（第5.4節、有効6桁）を受けて指数表記になったのに対し、
E3・D4・D5（8桁）はいずれも丸めを受けず全桁がそのまま出た。8桁以上の定数は
単精度では表現しきれない桁数であり、実測では倍精度として扱われていることが
この差から分かる。

**観測していないこと（この規則の適用範囲）**:

- 小数点の左右にある先頭の0（例: `.000015`の`0000`、`0.25`の先頭`0`）を
  この桁数に含めるかどうかは観測していない。E3・D4・D5（8桁以上として
  倍精度になった腕）はいずれも先頭が0でない数字から始まる定数であり、
  先頭0を含む書き方で8桁以上になる定数（例: `.00001234`）が同じ規則に
  従うかは未確認（第10節）。
- `E`指数付きで、仮数部の数字が8桁以上になる定数（例: `1.2345678e-2`）の
  型も観測していない。今回の腕はいずれも仮数部が7桁以内（`e`/`E`使用は
  E4・S4等）か、指数記号を使わない素の整数・小数（E1〜E3・D4・D5）かの
  どちらかで、両方が重なる腕が無い（第10節）。

**`!`（単精度）・`#`（倍精度）の接尾辞、`E`（単精度指数）・`D`（倍精度指数）が
それぞれ型を明示的に決める。** 根拠: 同結果ノート。

| 腕 | 打鍵文字列 | 型の指定 | 実測の出力 |
|---|---|---|---|
| W1 | `print 1#/3` | `#`接尾辞（分母） | `.3333333333333333`（倍精度16桁） |
| W4 | `print 1/3#` | `#`接尾辞（分子） | `.3333333333333333`（W1と同一の並び） |
| W2 | `print 1d10` | `D`指数 | `10000000000`（固定、倍精度） |
| A9（`l4-s4b`） | `print 12345.678!` | `!`接尾辞 | `12345.7`（単精度6桁に丸め） |
| A10（`l4-s4b`） | `print 1234567!` | `!`接尾辞 | `1.23457E+06`（単精度6桁の指数、A1と同一） |
| E4 | `print 1e10` | `E`指数 | `1E+10`（単精度） |

**`e`指数の後ろに`#`を付けた定数（例: `1.5e+10#`のような書き方）は、
数値を出力しなかった。** 根拠: `l4-s4l-double-fin-rep10-rounding-results.md`
（`62e35b4`）、L9〜L12（4腕、いずれも`e`指数の直後に`#`を続けて書いた
定数を含む式）の出力行が、数字・符号・小数点・`E`/`D`・空白の集合に
収まらず`non_numeric_output`に分類された。事前登録「本文を出さない
取り扱い」節の規則どおり、値・文言は記録せず件数と位置の範囲だけを
記録している（例: `print -962467.4715e+15#+962467471500000002048`）。
この形がどう解釈されたか（構文の誤りか、別の解釈になっているか）は
未確定（第10節）。

W1・W4は接尾辞の位置（分子・分母のどちら）によらず同じ倍精度書式になった
（`l4-s4a-float-print-results.md`「観測」節）。英字（`e`・`d`）は小文字で打鍵して
通った（両測定の「器具の確認」節、32腕・23腕・20腕すべてでエコー行に打鍵文字列
がそのまま出現）。

#### 5.1.1 単精度の定数の読み取り（FIN）

**観測**: 10進の文字列（桁の並び・小数点・指数）から単精度浮動小数点の

> ような`0.1`の反復掛け算ではない）、1手ごとに倍精度へ丸める。丸めは
> 半分なら絶対値の大きい側（第5.3節）。符号は最後に適用する。

`DREP10A`は、**`l4-s4k`の36件（事後の当てはめ）と、`l4-s4l`で数値を
出した24腕・対照12腕の全てを再現する。** ユーザー判断（2026-09-15）に
より、実装はこの`DREP10A`に従って先へ進む。

**単精度は「10で割る」を単精度に丸めた`0.1`の反復掛け算（`REP01`）で
行うのに対し、倍精度は「10で割る」を本当の割り算（`DREP10A`）で行う。**
両者の手順が違う理由は分かっていない（第10節）。

### 5.2 整数の演算・定数の範囲外は単精度へ昇格

**整数の範囲（-32768〜32767）を超える定数・演算結果は、エラーにはならず、
単精度浮動小数点の書式で出力される。** 根拠: `l4-s4a-float-print-results.md`
promote群（P1〜P5）、全腕`predicted_match`。

| 腕 | 打鍵文字列 | 範囲外の理由 | 実測の出力 |
|---|---|---|---|
| P1 | `print 40000` | 定数が32767超 | `40000` |
| P2 | `print 30000+30000` | 加算結果が32767超 | `60000` |
| P3 | `print -32768-1` | 減算結果が-32768未満 | `-32769` |
| P4 | `print 200*200` | 乗算結果が32767超 | `40000` |
| P5 | `print 7/2` | 整数どうしの割り算 | `3.5` |

**`/`（除算）は、整数どうしの演算でも常に実数（浮動小数点）の結果になる。**
P5（`7/2`）は範囲内の整数どうしの除算だが、結果は`3.5`という浮動小数点の
書式で出た（整数の`3`や`4`に丸められることはなかった）。

P1〜P4の出力（`40000`・`60000`・`-32769`・`40000`）は、いずれも第2節の整数の
書式（符号のための1桁、後置空白1）と同じ前置き・後置きの形をとった
（`l4-s4a-float-print-results.md`「観測」節、符号位置が相対桁0で正の数は空白
のまま・負の数は`-`）。範囲外に見える数でも、単精度浮動小数点としての桁数
（6桁以内）に収まっていれば固定表記のまま出て、指数表記への切り替え（第5.4節）
は起きない。

### 5.3 固定表記の書式（丸め・桁数・0の省略）

**単精度は有効数字6桁、倍精度は有効数字16桁に丸め、末尾の0は落とす。**
根拠: `l4-s4b-h6-results.md`（single_digits群11腕全て`predicted_match`、
`h6_digits_only`の桁数部分）・`l4-s4a-float-print-results.md`（W1・W3・W4等の
倍精度16桁の観測）。

- 単精度の丸め例: D1（`print 1/3`）→`.333333`（6桁）、A1（`print 1234567`、
  `l4-s4b`）→丸めた上で指数化（第5.4節）。
- 倍精度の丸め例: W1/W4（`print 1#/3`・`print 1/3#`）→`.3333333333333333`
  （16桁）。

**整数部が0のときは`0`を書かず、`.`から始める。** F2（`print .5`）→`.5`、
S1（`print .1`）→`.1`、K3等（`l4-s4c`、`|v|<1`の各腕）も同様に`.`から始まる。

**符号のための1桁・数字後ろの空白1は、整数（第2節）と同じ規則がそのまま
浮動小数点にも適用される。** 正の数・0では相対桁0が空白のまま、負の数では
相対桁0に`-`が書かれ、数字は相対桁1から始まる。根拠:
`l4-s4a-float-print-results.md`「観測（判定を動かさない記述）」節（F1〜F5・
D1〜D3・P1〜P5等、負の数はF3・P3等で確認）。

**単精度・倍精度とも、丸めるとちょうど半分になる値は絶対値の大きい側へ
丸める（偶数丸めではない）。** 根拠: 単精度は
`l4-s4g-single-rounding-tie-results.md`（`e637eca`）、single_round群20腕
（R1〜R20、6桁へ丸めるとちょうど半分になるよう選んだ定数）全てで候補`GW`
（GW-BASICの`$FOUT`手順どおり、半分は常に絶対値の大きい方向へ切り上げ）
だけが`candidate_consistent`（対照`EXACT`〔偶数丸め〕は20腕全てで
`candidate_rejected`）。倍精度は
`l4-s4h-double-rounding-tie-results.md`（`b498a33`、事前登録`ea02e1f`＋
追補`3a0b004`）、9腕（H1〜H9、16桁へ丸めるとちょうど半分になるよう選んだ
定数）全てで候補`GW`だけが`candidate_consistent`（対照`EXACT`は16桁目が
偶数の半端になる5腕〔H1・H3・H4・H6・H7〕で`candidate_rejected`）。単精度
・倍精度いずれも`GW`が`unique_survivor`になり、丸め半端の方向が一致した。

| 精度 | 打鍵文字列 | 実測の出力 | 備考 |
|---|---|---|---|
| 単精度 | `print 1841145` | `1.84115E+06` | 7桁の整数、6桁目が丸めでちょうど半分 |
| 単精度 | `print 5188305` | `5.18831E+06` | 同上（6桁目が`0`から`1`側へ切り上げ） |
| 単精度 | `print -34281.25` | `-34281.3` | 負の数、小数点以下がちょうど半分 |
| 単精度 | `print -266650.5` | `-266650` | 負の数、末尾桁がちょうど半分 |
| 単精度 | `print 990860.5` | `990860` | 正の数、末尾桁がちょうど半分（偶数へは丸めていない） |
| 倍精度 | `print 1234567890123456.5#` | `1234567890123457` | 17桁の値、16桁目が丸めでちょうど半分 |
| 倍精度 | `print 2000000000000000.5#` | `2000000000000001` | 同上（16桁目が`0`から`1`側へ切り上げ） |
| 倍精度 | `print 9007199254740992.5#` | `9007199254740993` | 同上（16桁目が偶数の半端） |
| 倍精度 | `print -1234567890123456.5#` | `-1234567890123457` | 負の数、`1234567890123456.5#`の符号違い |
| 倍精度 | `print 1234567890123456#+.5` | `1234567890123457` | 計算（加算）で半端を作った腕、直接指定と同じ結果 |

いずれも「絶対値の大きい側へ丸める」で一貫しており、`-34281.25`は
`-34281.2`（偶数丸め・値の小さい側）ではなく`-34281.3`（絶対値の大きい
側）に、`2000000000000000.5#`は`2000000000000000`（偶数丸め）ではなく
`2000000000000001`（絶対値の大きい側）になった。既存の観測例（第5.1節・
第5.4節のD1〜D3・E2・A1等の6桁丸め）はいずれも丸めの最終桁がちょうど
半分になる値ではなく、この規則と矛盾しない（D1`.333333`・E2`1E+07`等は
ちょうど半分の桁を含まない）。

**16桁目（単精度は6桁目）が奇数になる半端は、偶数丸め・絶対値の大きい
側への丸めのどちらでも同じ結果になり、候補を区別する材料にはならない。**
根拠: `l4-s4h`のH2（`1234567890123457.5#`）・H5（`3333333333333333.5#`）、
16桁目が奇数の腕で`EXACT`・`GW`の予測が一致し、実測もその予測と一致した
（奇数の半端は「1つ上の偶数へ丸める」＝「絶対値の大きい側へ丸める」が
必然的に同じ値になるため）。`l4-s4g`のR5・R7・R8・R11・R17・R19等
（固定表記のまま丸めた腕）も同様の構造を含みうるが、判定はもっぱら
6桁目・16桁目が偶数の半端になる腕（単精度R1〜R20中の該当腕、倍精度
H1・H3・H4・H6・H7）で行っている。

### 5.3a 四則演算結果そのものの丸め（表示の丸めとは別、`l4-s7a`・`l4-s7b`で追記）

前節（5.3）の丸めは`PRINT`が10進数字へ変換するときの丸め（`$FOUT`
手順）だった。ここでの丸めは、**加減乗除の演算そのものが単精度24bit
仮数へどう丸めるか**という、演算結果の内部値の話で、別の測定
（`docs/notes/l4-s7a-single-precision-arithmetic-rounding-results.md`・
`docs/notes/l4-s7b-integer-only-rounding-results.md`）で直接確かめた。

**単精度の加算・減算・乗算・除算は、いずれも厳密値を1回だけ正しく
丸めた結果になる。丸めの半端（ちょうど半分になる値）は0から遠い側
（round-half-away）で、偶数丸め（round-half-even）ではない。** 根拠:
`l4-s7a`（`print cdbl(<式>)`で単精度演算結果を直接測定、24腕）・
`l4-s7b`（整数オペランドのみで再測定、40腕）。両測定を合わせ、
tie（丁度半分、候補の仮数が偶数で偶数丸め/絶対値の大きい側が判別
できる場面）は加算4＋減算4＋乗算3＋対照4の計15腕中14腕でaway側が
的中し（`l4-s7a`の3/4＋`l4-s7b`の11/11）、evenは0腕。除算は分母の
仮数が2進有限小数になる特殊な組合せが無いとtieを作れないため、
tie方向はこの測定では未確認（`trunc`の全面棄却・`false_tie`腕での
正しい丸めは加減乗除いずれでも確認済み）。

**ガードバイト方式の粗い丸め（隠しビットをスティッキー無しで一部だけ
捨てる、既存実装`src/l4_basic/mbf_single.asm`の`$FMULS`再現や`coarse8`
仮説）は、判別力のある全腕（`l4-s7a`の`false_tie`腕・`l4-s7b`の
`false_tie`腕、計17腕）で棄却された。** 単精度の乗算（既存実装の
粗い丸め）についても、単発の乗算1回という条件下では正しい丸めが
勝った。切り捨て（`trunc`）も全演算・全腕で棄却された。

この規則は、超越関数（`SIN`/`COS`/`TAN`、第4.16節を参照）の内部計算
（範囲縮約・多項式評価の乗算・加減算）にもそのまま当てはまることを
`l4-s6g`（後述第4.16節）で確認した。

### 5.4 大きい側（整数部が大きい）: 指数表記への切替

**単精度は、値を有効6桁に丸めた後の値の整数部の桁数が6を超える
（`|v|≧10^6`）と指数表記になり、6以下なら固定表記のままになる。判定は
丸めた後の値で行う（A7参照）。** 根拠: `l4-s4b-h6-results.md`、single_digits群
11腕全て`predicted_match`（`h6_digits_only`。桁数の規則そのものは11腕全一致で
支持された）。

| 腕 | 打鍵文字列 | 実測の出力 | 備考 |
|---|---|---|---|
| E1 | `print 999999` | `999999` | 6桁ちょうど、固定のまま |
| A2（`l4-s4b`） | `print 123456` | `123456` | 6桁、固定のまま |
| A6（`l4-s4b`） | `print 1e5` | `100000` | 6桁、固定のまま |
| E2 | `print 9999999` | `1E+07` | 7桁→6桁に丸められ指数化 |
| A1（`l4-s4b`） | `print 1234567` | `1.23457E+06` | 7桁→6桁に丸められ指数化 |
| A4（`l4-s4b`） | `print 100000*10` | `1E+06` | 演算結果が7桁→指数化 |
| A5（`l4-s4b`） | `print 1e6` | `1E+06` | 7桁相当→指数化 |
| A7（`l4-s4b`） | `print 999999.5` | `1E+06` | 丸めで7桁相当になり指数化 |

**指数表記の書式は、仮数部（符号を除く）の後ろに`E`（単精度）または`D`
（倍精度）、続けて指数の符号（`+`/`-`）、指数を2桁で置く。** 根拠:
`l4-s4a-float-print-results.md`。

| 腕 | 打鍵文字列 | 実測の出力 |
|---|---|---|
| E4 | `print 1e10` | `1E+10` |
| E5 | `print -1.5e+20` | `-1.5E+20` |
| S4 | `print 1e-10` | `1E-10` |

**8桁以上の整数定数は倍精度に昇格するため、単精度の6桁境目では指数化され
ない（第5.1節E3・D4・D5参照）。** 倍精度自身の大きい側の境目は、`l4-s4f`
（候補`LG16`が`unique_survivor`）で確定した。値を有効16桁に丸めて末尾0を
落とし、`v = d.ddd... × 10^E`（`E≥0`）の形にすると、

> **`E < 16`（整数部が16桁以下）なら固定表記、`E ≥ 16`（17桁以上）なら
> 指数表記になる。**

根拠: `l4-s4f-double-large-format-switch-results.md`（`248853c`）、
11腕全てで候補`LG16`だけが`candidate_consistent`（対照`LG15`〔単精度の
「GWより1桁手前」に倣った類推〕は`E=15`〔16桁ちょうど〕の4腕で食い違い、
`candidate_rejected`）。

| 腕 | 打鍵文字列 | 実測の出力 | 桁数/E | 判定 |
|---|---|---|---|---|
| W2（`l4-s4a`） | `print 1d10` | `10000000000` | 11桁、E=10 | 固定 |
| W3（`l4-s4a`） | `print 12345678901234#` | `12345678901234` | 14桁、E=13 | 固定 |
| G1（`l4-s4f`） | `print 123456789012345#` | `123456789012345` | 15桁、E=14 | 固定 |
| G8（`l4-s4f`） | `print 123456789012345.6#` | `123456789012345.6` | 16有効桁、E=14 | 固定 |
| G3（`l4-s4f`） | `print 1234567890123456#` | `1234567890123456` | 16桁、E=15 | 固定（`E<16`ぎりぎり） |
| G5（`l4-s4f`） | `print 1d15` | `1000000000000000` | 16桁、E=15 | 固定（`E<16`ぎりぎり） |
| C2（`l4-s4b`） | `print 1d16` | `1D+16` | 17桁相当、E=16 | 指数（`E≥16`） |
| C3（`l4-s4b`） | `print 1d17` | `1D+17` | 18桁相当、E=17 | 指数 |
| G9（`l4-s4f`） | `print 1d15*10` | `1D+16` | 演算結果17桁相当、E=16 | 指数（`E≥16`） |

**境目の例**: `1234567890123456#`（G3）・`1d15`（G5）はいずれも整数部
16桁ちょうど（`E=15`）で固定表記のままだが、`1d15*10`（G9、10^16＝17桁
相当）は`E=16`になったとたん指数表記（`1D+16`）に切り替わる。単精度で
見られた「GWの境目より1桁手前で切り替わる」という類推（対照`LG15`、
`E<15`）は、G3・G4・G5・G11（いずれも16桁ちょうど）が固定表記のままだった
ことで`l4-s4f`では支持されなかった。

### 5.5 小さい側（`|v|<1`）: 固定⇔指数表記の切替

**単精度は、`LEN7`規則が唯一の生き残り候補として確定した。** 根拠:
`l4-s4c-small-value-format-switch-results.md`、single_small群13腕
（K1〜K13）全てで候補`LEN7`だけが実測と一致（`unique_survivor`）。

`LEN7`の定義（`l4-s4c-small-value-format-switch-preregistration.md`）:
値を単精度の有効桁数（6桁）に丸めて末尾0を落とし、固定表記にしたときの
小数点より右の文字数（先頭の0を含む、符号は数えない）が**7以下なら固定
表記、8以上なら指数表記**にする。

| 腕 | 打鍵文字列 | 実測の出力 | 固定表記の小数点右の文字数 |
|---|---|---|---|
| K3 | `print 1.5e-6` | `.0000015` | 7（固定） |
| K6 | `print 1.23456e-2` | `.0123456` | 7（固定） |
| K8 | `print 1.2345e-3` | `.0012345` | 7（固定） |
| K9 | `print 1.2e-6` | `.0000012` | 7（固定） |
| K10 | `print -1e-7` | `-.0000001` | 7（固定、符号は数えない） |
| K1 | `print 1e-8` | `1E-08` | 8（指数） |
| K4 | `print 1.5e-7` | `1.5E-07` | 8（指数） |
| K5 | `print 1.23e-6` | `1.23E-06` | 8（指数） |
| K7 | `print 1.23456e-3` | `1.23456E-03` | 8（指数） |
| K11 | `print -1.5e-7` | `-1.5E-07` | 8（指数、符号は数えない） |
| K12 | `print 1/3000` | `3.33333E-04` | 演算結果を丸めると8（指数） |
| K2 | `print 1e-9` | `1E-09` | 9（指数） |
| K13 | `print 1/300000` | `3.33333E-06` | 指数（K12と同じ理由） |

**単精度の観測の範囲では、後述（倍精度側）の`k≤1`・`k≤14`という2つの
例外条件は`LEN7`と区別できない（推定、判定には使わない）。** 単精度は
有効桁数`s`が最大6なので、`k≤1`のときは必ず`k+s≤1+6=7`となり`LEN7`の
固定条件（小数点右の文字数`k+s≤7`）をすでに満たす。逆に`k≥7`のときは
`s≥1`なので必ず`k+s≥8`となり、`LEN7`だけで指数表記と判定できる。
つまり単精度の腕（`k`が1〜9程度の範囲）では、「`k≤1`なら常に固定」と
いう例外規則を別立てにしても、しなくても同じ判定結果になり、今回の
観測（K1〜K13）からはどちらの形が実装の規則かを区別できない。単精度・
倍精度を1本の統一規則（下記`RSTAR`のような形）で書けるかどうかは推定で
あり、本節では単精度は`LEN7`のまま、倍精度は別に`RSTAR`として書く
（統一するかどうかの判断は推定の範囲に留め、根拠にしない）。

**倍精度は、`l4-s4c`・`l4-s4d`で候補`S0`・`LEN16`・`LE17`・`LE18`が
いずれも`no_survivor`だった後、`l4-s4e`で新しい候補`RSTAR`が
`unique_survivor`として確定した。** 根拠: `l4-s4e-double-small-format-switch-results.md`
（`4dda102`）、k1_long群5腕・k15_short群4腕・mid_len16群3腕・
mid_len17群2腕の全14腕で`RSTAR`だけが`candidate_consistent`（対照
`RSTAR_B`は4腕で食い違い）。`l4-s4d`（`1e91c83`、追補`e80a55b`で写し
時刻を延長・関門G8を新設）は候補`LE17`・`LE18`がいずれも`no_survivor`
だった（下記「測定の経緯」段落参照）。

`RSTAR`の定義（`l4-s4e-double-small-value-format-switch-preregistration.md`）:
値を倍精度の有効桁数（16桁）に丸めて末尾0を落とし、
`v = d.ddd... × 10^E`（`E<0`）の形にする。`k = -E-1`（小数点直後の0の
個数）、`s`=丸め後の有効桁数とすると、

> **`k≤1`（`|v|≥0.01`）なら常に固定表記。そうでなければ`k+s≤16`かつ
> `k≤14`のとき固定表記、それ以外は指数表記。**

| 腕 | 出所 | 打鍵文字列 | 実測の出力 | k | s | k+s | 判定 |
|---|---|---|---|---|---|---|---|
| Q1 | `l4-s4e` | `print 1#/70` | `.01428571428571429` | 1 | 16 | 17 | 固定（`k≤1`） |
| M7 | `l4-s4d` | `print 1#/30` | `.03333333333333333` | 1 | 16 | 17 | 固定（`k≤1`） |
| L6 | `l4-s4c` | `print 1.234567890123456d-2` | `.01234567890123456` | 1 | 16 | 17 | 固定（`k≤1`） |
| M2 | `l4-s4d` | `print 1.23456789012345d-3` | `1.23456789012345D-03` | 2 | 15 | 17 | 指数（`k>1`かつ`k+s>16`） |
| Q14 | `l4-s4e` | `print 1#/700` | `1.428571428571429D-03` | 2 | 16 | 18 | 指数（同上） |
| L7 | `l4-s4c` | `print 1#/3000` | `3.333333333333333D-04` | 3 | 16 | 19 | 指数（同上） |
| Q10 | `l4-s4e` | `print 1.2345678901234d-3` | `.0012345678901234` | 2 | 14 | 16 | 固定（`k+s≤16`かつ`k≤14`） |
| M8 | `l4-s4d` | `print 1.5d-14` | `.000000000000015` | 13 | 2 | 15 | 固定（同上） |
| L1 | `l4-s4c` | `print 1d-15` | `.000000000000001` | 14 | 1 | 15 | 固定（`k≤14`ぎりぎり） |
| L3 | `l4-s4c` | `print 1.5d-15` | `.0000000000000015` | 14 | 2 | 16 | 固定（`k+s=16`ぎりぎり） |
| Q6 | `l4-s4e` | `print 2d-16` | `2D-16` | 15 | 1 | 16 | 指数（`k+s≤16`だが`k>14`） |
| L4 | `l4-s4c` | `print 1.5d-16` | `1.5D-16` | 15 | 2 | 17 | 指数（`k>14`かつ`k+s>16`） |
| M3 | `l4-s4d` | `print 1.23d-15` | `1.23D-15` | 14 | 3 | 17 | 指数（`k+s>16`） |

**境目の例**: `1#/30`（M7、`k=1`）は`k≤1`の例外により固定表記だが、
`1.23456789012345d-3`（M2、`k=2`）は`k`が1を超えたとたん`k+s=17`が
`k+s≤16`を満たさず指数表記になる（`k=1`と`k=2`の差）。同様に
`1.5d-15`（L3、`k=14`）は`k≤14`ぎりぎりで固定表記だが、`2d-16`（Q6、
`k=15`）は`k+s=16`自体は`≤16`を満たすのに`k>14`のため指数表記になる
（`k=14`と`15`の差）。この2組は、`RSTAR`が単なる「`k+s≤16`なら固定」
（対照`GW16`、第5.7節）では説明できない2つの例外条件をどちらも要求
することを直接示す腕である。

**測定の経緯（`l4-s4d`、写しの時刻）**: `l4-s4d`の本測定は、最初
`l4-s4a`〜`l4-s4c`と同じ写し(後)取得タイミング（`dump=line_end+20`）で
試みたところ、桁数の多い3腕（M1・M5・M10）で出力行の描画がまだ完了して
おらず、`Ok`行との区別がつかない状態のまま`cells`が0件として記録された。
この状態は各腕2走とも同じ位置で切れて再現し、関門G3（決定論性）を素通り
してしまう——「決定論的に再現する」ことと「測定が完了している」ことは
別であり、G3だけでは早すぎた写しを検出できない。この事実に気づいた時点で
測定を止め、写し(後)の時刻を全腕一律で`dump=line_end+300`に延長し、
出力行の後に`Ok`行が現れていることを確認する関門G8（出力完了の確認）を
追補（`e80a55b`）で新設したうえで再測定した（`l4-s4d-double-small-format-switch-results.md`
「経緯（写しが早すぎた走）」節）。`l4-s4e`はこのG8を最初から適用して
測定している。

### 5.6 誤りの形（範囲外・0除算）

**範囲外の値・0除算は、出力が2行にわたる。他の30腕（数値出力）は出力1行
（`Ok`行が相対行+2）だが、この2腕だけ`Ok`行が相対行+3になる。**
根拠: `l4-s4a-float-print-results.md`「原点」節。

| 腕 | 打鍵文字列 | 分類 | `Ok`行の相対位置 |
|---|---|---|---|
| X1 | `print 1e38*10` | `non_numeric_output` | 相対行+3（出力2行） |
| X2 | `print 1/0` | `non_numeric_output` | 相対行+3（出力2行） |

X1・X2は事前登録どおり件数と位置の範囲だけを記録の対象とし、値・文字コード
そのものは記録していない（禁止事項7、エラーメッセージはROMのデータに
あたる）。この2腕の出力の文言そのものは第7.1節（資料の記載）の対応表を
参照する（測定では確かめていない、第10節）。

### 5.7 GW-BASICとの違い（参考）

予測器（`tools/l4_mbf_oracle.py`・`tools/l4_mbf_oracle_v2.py`）は本書の判定
根拠にしていないが、参考として次の違いに触れる。GW-BASICは単精度の有効桁を
7桁として丸めるのに対し、N88（本測定の対象）は**6桁**で丸める、という違いが
観測（第5.3節・第5.4節、D1〜D3・E2・`l4-s4b`のH6確認）から見えている。この
違いはl4-s4aのD1〜D3・E2が「予測（GW-BASIC相当）より有効桁が1桁少ない」形で
食い違ったことが出発点であり（`l4-s4a-float-print-results.md`「食い違った腕の
形」節）、判定そのものはl4-s4b（新しい23腕、`h6_digits_only`）による直接確認で
確定させている。この小節はGW-BASICとの比較という位置づけの補足であり、判定の
根拠には使っていない。

**小さい側（`|v|<1`）の固定⇔指数の切替も、GW-BASICとN88で形が違う。**
GW-BASICのMIT公開ソースだけから導出した判定規則（分析ノート
`docs/notes/l4-gwbasic-fofmt-analysis.md`。**中身・導出過程は本節では
読まない・触らない**、結論の式だけをこの依頼文の引用として書く）は、
`k+s≤N`（`N`は単精度7・倍精度16）なら固定表記という単純な1本の式に
なる。これに対しN88は、単精度側は出力の有効桁が6桁であるにもかかわらず
小さい側の固定判定の閾値は`LEN7`（`k+s≤7`、第5.5節）で出力桁数と1ずれて
おり、倍精度側は`RSTAR`（`k≤1`・`k≤14`という2つの例外条件、第5.5節）を
持つ点で、GW-BASICの単純な`k+s≤N`規則（対照`GW16`、`l4-s4e`で14腕中9腕
が食い違い）とは異なる。この対比はGW-BASICとの比較という位置づけの補足
であり、判定の根拠には使っていない（判定根拠は第5.5節の`l4-s4c`・
`l4-s4d`・`l4-s4e`の測定）。

**大きい側（`|v|≥1`）は、倍精度はGW-BASICと同じ境目、単精度だけが
GWより1桁手前で切り替わる。** `l4-s4f`（候補`LG16`が`unique_survivor`、
第5.4節）で、倍精度の大きい側の境目はGW-BASIC由来の規則そのもの
（`E<16`なら固定）と一致した。対照候補`LG15`（単精度の「GWより1桁手前」
という類推をそのまま倍精度に当てはめた形、`E<15`）は`E=15`の4腕
（G3・G4・G5・G11）で食い違い、`candidate_rejected`だった。単精度・
倍精度×大きい側・小さい側の4通りをまとめると次のとおりになる。

| | 大きい側（`\|v\|≥1`） | 小さい側（`\|v\|<1`） |
|---|---|---|
| 単精度 | 出力有効桁6桁で切替（GWは7桁、1桁手前。第5.4節） | `LEN7`＝`k+s≤7`（GWの`k+s≤7`基準と数値上は同じ式だが、出力桁数〔6〕とは1ずれる。第5.5節） |
| 倍精度 | `E<16`（GW-BASICの規則そのもの。第5.4節） | `RSTAR`＝`k≤1`または（`k+s≤16`かつ`k≤14`）。GWの単純な`k+s≤16`（`GW16`）とは異なる例外を持つ（第5.5節） |

倍精度は大きい側だけGW-BASICと一致し、小さい側は独自の例外（`k≤1`・
`k≤14`）を持つ。単精度は大きい側でGWより1桁手前（6桁）に切り替わるが、
小さい側の`LEN7`はGWの`k+s≤7`と数値としては同じ式になっている（ただし
これは出力桁数6との単純な対応ではない）。この対比はGW-BASICとの比較と
いう位置づけの補足であり、判定の根拠には使っていない。

**丸めの半端（ちょうど半分になる値の丸め方向）も、単精度・倍精度とも
GW-BASICの`$FOUT`手順と一致した。** `l4-s4g`（第5.3節）で単精度の丸め
半端が`GW`（半分は常に絶対値の大きい側へ切り上げ、偶数丸めではない）と
一致し、`l4-s4h`（第5.3節）で倍精度でも同じ`GW`が`unique_survivor`に
なったのは、いずれもGW-BASICの`$FOUT`の手順（`docs/notes/l4-mbf-oracle.md`
・`docs/notes/l4-gwbasic-fofmt-analysis.md`の記載どおり「0.5を足して
切り捨て」）と同じ形である。この対比はGW-BASICとの比較という位置づけの
補足であり、判定の根拠には使っていない（判定根拠は第5.3節の`l4-s4g`・
`l4-s4h`の測定）。

**単精度の定数の読み取り（FIN、第5.1.1節）も、GW-BASICの手順を手がかりに
した推定でしか説明できていない。** GW-BASICの`$FIN`は、積み上げた整数を
倍精度にしたあと倍精度の10のべき乗を**1回**掛ける・割る作りだが、N88の
実測（`l4-s4i`・`l4-s4j`）はこれに合わない。GW-BASICの`$DIV10`（10で割る
操作）は単精度に丸めた`0.1`を掛ける作りになっている（出所:
`docs/notes/l4-fin-model-search.md`。**中身は本節では読まない・触らない**、
結論だけを参考にする）。第5.1.1節の`REP01`（「÷10」を「単精度に丸めた
`0.1`を掛ける」で行う）は、この`$DIV10`の作りを手がかりにした推定であり、
判定の根拠には使っていない（実装はユーザー判断により`REP01`を採用して
いるが、これはGW-BASICとの比較からの類推であって測定による確定ではない）。

**倍精度の定数の読み取り（FIN、第5.1.2節）は、GW-BASICの`$FIN`の倍精度
経路とは合わない。** GW-BASICの`$FIN`は、倍精度の10のべき乗の表を**1回**
掛ける・割る作りだが、`l4-s4k`・`l4-s4l`の実測（第5.1.2節）はこの1回
操作の予測（`DEXACT`・`DGW`）に合わない。単精度の`$DIV10`は単精度に
丸めた`0.1`を掛ける作りだったのに対し、**倍精度の実測は「10で本当に
割る」操作の反復（`DREP10A`）に合う**——単精度と倍精度で「10で割る」の
実装のされ方が違うという非対称な形になっている。この対比はGW-BASICとの
比較という位置づけの補足であり、判定の根拠には使っていない（判定根拠は
第5.1.2節の`l4-s4k`・`l4-s4l`の測定）。

## 6. 観測 — 構文の誤り

**構文の誤りがあると、出力の行（相対+1）の1行だけが変わる。`Ok`の行位置は
ずれない。** 根拠: `l4-s3a-print-format-results.md` Q5。`print 1+`（末尾が
式として不完全）の腕で、走行前後の非空白セル件数を比較したところ:

| 相対行 | 変化前(非空白件数) | 変化後(非空白件数) | 位置範囲(列) |
|---|---|---|---|
| 0(打った行) | 0 | 7 | 0-7 |
| +1(エラー表示行) | 0 | 15 | 0-15 |
| +2(`Ok`の行) | 0 | 3 | 0-2 |

相対行0の非空白7件は打鍵エコー（`print 1+`、空白1文字を除く7文字）と一致する
件数。エラー表示は相対行+1の1行だけに現れ、非空白セル15件・列範囲0〜15
（16列ぶん）。相対行+2は他の腕と同じ`Ok`の並び（非空白3件、列0-2）のまま
だった。**エラーメッセージの文言・文字コードは禁止事項7（ROMのデータテーブル
にあたる）により本測定では一切扱っていない**ため、この節に載せたのは行数・
件数・位置範囲だけである。

## 7. 資料の記載 — PRINT/LPRINTの言語仕様（マニュアル、参考）

以下はマニュアル `refs/manual_squashed.txt` 2-183（PRINT/LPRINTの項の本文）の
記載であり、**判定の根拠にはしていない**（測定と一致した部分のみ、第2〜4節の
観測として別途確認済み）。資料の記載として位置づけを補足するために引用する。

- 区切り記号としてセミコロン(`;`)を使うと、直前に出力したものの直後に続けて
  次の値を出力する。
- `PRINT`で値を出力する領域は、あらかじめ各行が14文字ごとに分割されている。
  区切り記号としてコンマ(`,`)を使うと、この領域ごとに出力が行われる。
- 式の最後にセミコロン・コンマを付けると改行動作を起こさない。
- 数値を出力した場合、その後ろには1文字の空白が挿入される。また、数値の前
  には符号のための桁を確保する（正の数のとき空白、負の数のとき`-`となる）。

## 11. 観測 — FILES（ディスクのファイル一覧）

**本節は冒頭の「測定対象」の記載（ディスク無し）と異なり、ディスクを
入れた状態で測定した。** ドライブ1に参照ディスク（公式ROM起動用の複製）、
ドライブ2に自作の生成器で作った媒体を入れ、`FILES`命令の挙動を測定した。
根拠は`docs/notes/m6f-e-files-display-preregistration.md`（事前登録）・
[追補2](../notes/m6f-e-addendum2-scroll-trailing-rows.md)・
[追補3](../notes/m6f-e-addendum3-full-row-wrap.md)（事前登録）、判定は
`docs/notes/m6f-e-files-display-results.md`・
`docs/notes/m6f-e-addendum2-results.md`・
`docs/notes/m6f-e-addendum3-results-and-addendum4.md`・
`docs/notes/m6f-e-addendum4-results.md`（最終、器具`0169c85`）。

ディレクトリの所在・エントリの探索順（削除済み`0x00`を飛ばし未使用
`0xFF`で止める）・割り当て単位の数え方は`docs/spec/l3-disk-format.md`
第3版第1〜2節に既にあるので、ここでは重複して書かず参照のみ行う。

### 11.1 規則

1. `FILES [<ドライブ番号>]`。ドライブ番号を省略するとドライブ1を対象と
   する。ドライブ番号には数値式を書ける。
2. ディレクトリは(18,1,1)の先頭から順に読み、削除済みのエントリ
   （先頭`0x00`）は飛ばし、未使用のエントリ（先頭`0xFF`）に当たった
   ところで止める（`docs/spec/l3-disk-format.md`第3版1.1節）。生きた
   エントリが1件も無ければ、`FILES`は何も出さない。
3. 各エントリは**16桁のセル**に出し、1行に**5件**並べる。セルの中身は、
   名前欄の先頭6バイト・種別の印1文字・名前欄の末尾3バイト・空白1つ・
   大きさ（10進、最小桁数）の順であり、残りは空白で埋める。種別の印は、
   名前欄直後のバイト（`docs/spec/l3-disk-format.md`第4版1.2節）が
   `0x80`（`SAVE`）または`0xA0`（`SAVE ,P`）ならピリオド、`0x00`（データ・
   `SAVE ,A`）なら空白、`0x01`（`BSAVE`）ならアスタリスクとする
   （`0xA0`・`0x01`は`m6f-g`）。大きさは、そのファイルが
   使っている割り当て単位の個数（同1.2節の鎖をたどった数、同2.3〜2.4節）
   である。
4. 最後のエントリを出した後に改行する。5件で満杯になった行（80桁ちょうど）
   の後では、80桁目でカーソルが次の行へ移り、その後の改行でさらに1行
   進むので**空行が1行入る**（第15.1節、`l3-main.md`）。これは`FILES`に
   限らない画面出力一般の性質であり、`FILES`固有の規則ではない。画面を
   超える件数を出すときは、通常の画面出力と同じくスクロールし、途中で
   止まらない。
5. ドライブ1のディレクトリは記憶されない。`FILES`を実行するたびに媒体を
   読み直す。
6. 媒体が入っていないドライブを指定すると、エラーにはならず、媒体の
   挿入を待つ。
7. ドライブ番号に`0`または`3`を指定すると`ERR 70`、文字列の式を渡すと
   `ERR 13`になる。

### 11.2 注記・未観測の範囲

- **セルの残り（空白埋め）の直接確認はしていない。** 画面の署名は行末の
  空白を含まない形で取っており（行の中身の長さそのものを記録）、
  「セルの残りを空白で埋める」ことは画面上で直接には確認していない。
  ただし規則4（5件目のセルの後にカーソルが80桁目を越えて次の行へ移る
  こと）から、少なくとも5件目のセルは80桁目まで進むと分かる。行末に
  空白を書くか、カーソルだけを進めるかは画面上で区別できないため、
  実装はどちらでもよい。
- **大きさは1〜3桁で最小桁数**（1・10単位は`m6f-e`、100・158単位は
  `m6f-g`で確認）。割り当て可能な単位は最大158なので、4桁にはならない。

### 11.3 未確定

- 名前欄直後のバイトが`0x80`・`0x00`・`0xA0`・`0x01`以外のときの
  種別の印。
- 小文字・半角カナ・制御文字を含む名前の表示。
- 80桁ちょうどの出力の後に改行以外が来たときの挙動（第15.1節、
  `l3-main.md`参照）。
- `LFILES`、鎖が壊れた場合の表示、ドライブ1からの起動に関する規則など、
  `m6f-e-files-display-preregistration.md`第10節の範囲。

## 12. 観測 — LOAD（ASCII 形式）

**本節も第11節と同じくディスクを入れた状態で測定した**（ドライブ1に参照ディスク、ドライブ2に自作の生成器で作った媒体）。
対象は ASCII 形式（種別 `0x00`）のファイル。本体の形は `docs/spec/l3-disk-format.md` 第5版 2.6節。
根拠は `docs/notes/m6f-i-load-ascii-behavior-preregistration.md`（事前登録）、`docs/notes/m6f-i-attempt1-and-addendum1.md`、
`docs/notes/m6f-i-attempt2-and-addendum2.md`、`docs/notes/m6f-i-addendum2-results.md`（最終、器具 `b31e1f4`）。

### 12.1 規則

1. `LOAD "<ドライブ>:<名前>"` は、それまでのプログラムを**置き換える**（元の行は残らない）。
2. 本体の各行を、行の入力（`l4-program.md` 第1節）と同じように取り込む。読み込んだ行は**行番号順**に並ぶ。
3. 読み込みが終わると **`Ok` の行を1行出し**、その後に通常の入力待ちに戻る（画面には `Ok` が2行続く）。
4. 名前がディレクトリに見つからなければ **`ERR 53`**。名前は大文字・小文字を区別する（`l3-disk-format.md` 1.3節）。
5. 行番号の無い行に当たると **`ERR 57`** で止まる。**その行より前に読んだ行は残り**、後ろの行は読まない。
6. `LOAD` はプログラムを置き換えるので、`ON ERROR` の捕捉のプログラムも消え、`LOAD` 中のエラーは直接モードのエラーとして表示される。

### 12.2 注記

- 本体は `0x1A` までを読む（`l3-disk-format.md` 2.6節）。
- 規則6は、捕捉が効かなかったことの観察からの読みで、捕捉の処理がどの時点で消えるかは測っていない。

### 12.3 測っていない範囲と、自作側の判断

- 種別 `0x80`（`SAVE`）・`0xA0`（`SAVE ,P`）・`0x01`（`BSAVE`）のファイルの `LOAD`。**自作は当面これらを読まない。**
  指定されたときは、公式の挙動を測るまでの自作側の判断として `ERR 51`（エラー表の51番。自作の処理系の都合で読めないことを示す）を出す。
  公式は読み込めるので、ここは公式と異なる。
- `LOAD … ,R`、`MERGE`、`RUN "<名前>"`。1行の長さ・行数の限界。

## 13. 観測 — SAVE（ASCII 形式）

第11・12節と同じくディスクを入れた状態で測定した（ドライブ1に参照ディスク、ドライブ2に自作の生成器で作った媒体）。
根拠は `docs/notes/m6f-j-save-ascii-behavior-preregistration.md`（事前登録）、`docs/notes/m6f-j-attempt1-and-addendum1.md`、
`docs/notes/m6f-j-addendum1-results.md`（最終、器具 `1d577b2`）。

### 13.1 規則

1. `SAVE "<ドライブ>:<名前>",A` は、プログラムを ASCII 形式（`l3-disk-format.md` 2.6節。各行は `LIST` の出力と同じ文字列、`CR LF` 区切り、最後に `0x1A`）で書き、
   種別 `0x00` のエントリを作る。
2. 完了しても **`Ok` の行を足さない**（通常の入力待ちに戻るだけ。`LOAD` の第12節規則3とは異なる）。**入力待ちの `Ok` は通常どおり出る**（`cls:save "2:qsb",a` の後の最終画面は0行目の `Ok` だけ。`docs/notes/save-ok-prompt-suppressed-2026-10-02.md`）。
3. 同じ名前のファイルがあれば上書きする（エントリの位置と単位の扱いは `l3-disk-format.md` 1.5節）。
4. 書き込み禁止の媒体では **`ERR 61`**、空きが無ければ **`ERR 68`**。どちらも媒体は変わらない。
5. 媒体が入っていないドライブを指すと、エラーにせず媒体の挿入を待つ。

### 13.2 測っていない範囲

- `,A` の無い `SAVE`（種別 `0x80`）と `SAVE ,P`。**自作は当面 `,A` の無い `SAVE` を受け付けず、自作側の判断として `ERR 51` を出す**（第12.3節と同じ扱い。公式と異なる）。

## 14. 観測 — プログラム行の LIST 表示（小文字で打った語）

根拠: [l4-s5h-list-lowercase-words-preregistration.md](../notes/l4-s5h-list-lowercase-words-preregistration.md)・
[l4-s5h-round1-results-and-addendum1-preregistration.md](../notes/l4-s5h-round1-results-and-addendum1-preregistration.md)・

公式ROM、723腕（予約語180語×3形・文脈60行・追補123行）、全腕2走一致。腕ごとの署名は
`tests/conformance/expected_l4_listkw.tsv`。打鍵は小文字で届く（ハーネスの性質）ので、ここで言う「小文字で打った」は
すべての打鍵である。打った行と LIST の表示は自分で作った行だけで、画面本文ではない。

### 14.1 規則

LIST は、行番号の後ろの本文を次の規則で出す（行番号の直後の空白の扱いは [l4-program.md](l4-program.md) 第2節）。
**「名前の連なり」は、英字で始まり、英数字と `.` が続く最大の並び**。数字で始まる並びは数値で、数字と `.` だけを取り、
その直後から新しい連なりが始まる。

1. 二重引用符の中は打鍵どおり（閉じ引用符が無ければ行末まで）。`'` 以降は打鍵どおり。
2. 連なりが**ちょうど `rem`** なら `REM` にして、以降は行末まで打鍵どおり。**位置は問わない**
   （文頭・`:` の後・`THEN`/`ELSE` の後〔空白で区切られているとき〕・`a=1 rem`・`print rem`・`a$rem` でも）。
   `remabc` `rem.x` `xrem` `a.rem` `thenrem` は名前なので、すべて大文字になる。`rem$` `rem%` `rem=` は REM。
3. 連なりが**ちょうど `data`** なら `DATA` にして、以降は `:`（引用符の外）まで打鍵どおり。REM と同じく位置を問わない。
   `data1` `datax` は名前。
4. `go` + 空白**ちょうど1個** + `to` は `GOTO` に詰める（直後が名前の文字でないとき）。
   `go  to`（空白2個）・`go to10`・`go tox`・`go to.5` は詰めない（`GO  TO` `GO TO10` ...）。
   `go sub` は **G_H** に従う。名前の連なりがちょうど `go` で、その直後が空白1個と `sub` なら、
   `sub` に英数字等が接していても `GOSUB` に詰める。`sub` の直後に文字があれば、何であれ**1文字だけ消費する**。
   消費後の残りの先頭がASCIIの英字・数字・`.`・`&` なら `GOSUB` の後に空白1個を足す。それ以外では足さない。
   残りの空白は読み飛ばさず、残りには本節の語の表示と第14.5節の数値書き直しを適用する。行末なら `GOSUB` だけ。
   文字列・REM・DATA・`'` 以降・名前内部の保護は規則1〜3のとおり。
   例えば `go sub10` → `GOSUB 0`、`go subx.5` → `GOSUB .5`、`go subx&h1` → `GOSUB &H1`、
   `go subx:end` → `GOSUB:END`、`go sub1  x` → `GOSUB  X`。`go  sub10` は詰めない。
   これは入力とLIST表示の規則であり、RUN時の飛び先は未測定。
5. `?` は、文字列・REM・`'` の外ならどこでも `PRINT` に展開する。直後が英数字・`.`・`&` なら後ろに空白を1個、
   直前が英数字・`.` なら前にも空白を1個入れる（`?1` → `PRINT 1`、`?"x"` → `PRINT"x"`、`?-1` → `PRINT-1`、
   `?.5` → `PRINT .5`、`?a?b` → `PRINT A PRINT B`）。
6. それ以外の英字はすべて大文字にする。**予約語も変数名も区別しない**（`for i=1 to 3` → `FOR I=1 TO 3`、`a$` → `A$`）。
   語の前後に空白は足さない（`fora=1to3` → `FORA=1TO3`、`goto10` → `GOTO10`、`print1` → `PRINT1`）。
   打った空白はそのまま保たれる。数字・記号・空白は触らない。

予約語180語それぞれについて、1語だけの行・括弧に包んだ行・識別子に埋め込んだ行（`x<語>y`）を測り、
`GO TO` の詰めを除いてすべてこの規則（大文字になるだけ）に従った。語ごとの特別扱いが要るのは
REM・DATA・`GO TO`/`GO SUB`・`?`・`'` だけである。

### 14.5 数値定数の書き直し（l4-s5i）

根拠: `l4-s5i` の事前登録と追補1〜3（公式ROM、193腕、全腕2走一致。署名は `tests/conformance/expected_l4_listnum.tsv`）。
**公式は行を入力した時点で数値定数を値として読み、LIST はその値を書き直して出す。** 対象は、文字列・REM・DATA の中・`'` 以降を除く場所で、
名前の連なり（14.1節）の途中でない所に現れる、数字か `.` か `&` で始まる並び（`goto` 等の後の行番号も同じ: `goto 0010` → `GOTO 10`）。

**読み取り**

1. 数字の並び、`.` は1個まで、続けて `e`/`d` と任意の符号と数字の指数部。**数の途中の空白は読み飛ばす**（`1 2` → `12`、`1 e5` → `100000!`、
   `a=1 data x` は `1 d` が指数部の始まりになり `A=1#ATA X`）。指数部の `e`/`d` の後に数字が無くても指数部として読む（`1e` → `1!`）。
2. ただし **`e` の直後（空白をはさんでもよい）が `l` なら指数部にしない**。`e` は英字のまま大文字になる（`1else` → `1ELSE`、`1els` → `1ELS`、`1e l` → `1E L`）。
   `d` にはこの扱いが無い（`1d l` → `1# L`）。`e` の後の `l` 以外の英字は指数部の始まり（`1end` → `1!ND`）。
3. 指数部が無い数に限り、直後の `%` `!` `#` を型の印として読む。**指数部の後の印は数の外の文字として残る**（`1e5#` → `100000!#`、`1d5!` → `100000#!`）。
4. `&h` の後は16進数字、`&o` の後と、`&` の直後は8進数字を読む。**`&h` の後の空白は読み飛ばさず、そこで数が終わる**（`&h 10` → `&H0 10`、`&h1 0` → `&H1 0`）。
   `&o`・`&` では空白を読み飛ばす（`&o1 7` → `&O17`、`& 10` → `&O10`）。数字が無ければ値0（`&h` → `&H0`、`&` → `&O0`、`&b101` → `&O0B101`）。
   16進数字でない英字はそこで数を終える（`&h1g` → `&H1G`）。

**型**

5. 印 `%` は整数、`!` は単精度、`#` は倍精度。印が無ければ、指数 `d` は倍精度、指数 `e` は単精度、`.` も指数も無く値が 32767 以下なら整数、
   それ以外は数字（先頭の0を除く）が8桁以上なら倍精度、7桁以下なら単精度。`&` の定数は整数。

**書き出し**

6. 整数は10進の数字（先頭の0を落とす、印なし。`007` → `7`、`1%` → `1`）。`%` の付いた小数は0.5を切り上げて整数にする（`1.5%` → `2`、`2.5%` → `3`、`1.4%` → `1`）。
7. 単精度・倍精度は、その値を **PRINT と同じ桁と書式**（単精度は第5節の書式で有効6桁、倍精度は16桁・指数は `D`）で書き、
   書いた文字列に `.` も指数も無ければ単精度は `!`、倍精度は `#` を付ける。倍精度は `.` があっても `#` を付ける。指数表記には印を付けない。
   （`1e5` → `100000!`、`0.5` → `.5`、`1.` → `1!`、`1234567` → `1.23457E+06`、`3.1415926` → `3.1415926#`、`1d16` → `1D+16`、20桁 → `1.234567890123457D+19`）
8. `&h` は値を大文字の16進で、`&o`・`&` は `&O` と値の8進で、先頭の0を落として書く（`&h0010` → `&H10`、`&10` → `&O10`）。
9. 数の直後に `rem` が接するときは、間に空白1個を入れて `REM`（`1rem` → `1 REM`）。

**入力時のエラー**（行を入力した時点で出る）

10. 単精度・倍精度に収まらない大きい値は、6番 `Overflow` の行を出し、**行は入り**、値はその型の最大値になる（`1e39` → `1.70141E+38`、`1d39` → `1.701411834604692D+38`）。
11. 小さい値は 0 になる（`1e-39` → `0!`、`1d-39` → `0#`、`5e-39` → `0!`。`1e-38` は `1E-38`）。表示は無い。**0 になる境目（5e-39 と 1e-38 の間）は測っていない。**
12. 整数（`%` か `&` の定数）に収まらない値は、6番の文言を含む1行を出し、**行は入らない**（`32768%`、`32767.5%`、`&h10000`、`&o200000`）。
13. `&` の8進の定数に `8` か `9` があると、2番の文言を含む1行を出し、**行は入らない**（`&o8`、`&18`、`&o177778`）。
14. 12・13 の行は、エラー表の文言の後ろに非ASCIIの1文字が付く（文言と完全には一致しない。その文字は記録していない）。10 の行は文言と完全に一致する。
    入力時に行が入らないことは、直接モードで同じ式を打ったときも同じ表示になる（`a=32768%`）。

### 14.6 自作の数値書き換えと照合

`tools/l4_listnum_measure.py check --rom-dir <自作ROM> --expected tests/conformance/expected_l4_listnum.tsv`
は追補2の175腕と追補3の18腕を、元のbuild・行番号で各2走照合する。署名、行の欠落、重複・予期しない行番号、打てない文字、入力時の探りを検査する。
12・13の `exact` は14の未測定文字を再現しない既知差（自作1・公式0）として理由を出す。`contains` は照合する。

整数の `%` は字句の小数第一桁から厳密に丸める。浮動小数点は既存の単精度・倍精度FIN/FOUTを使う。
本体はバンク3の0x6500、直接モードの整数入力拒否の検査入口は0x64C0。mainの既存中継で呼び、バンクの共有処理は `EXT_BANK_MAIN_CALL` を通す。

### 14.7 行番号の読み取り（l4-s5j）

根拠: [l4-s5j-addendum3-results.md](../notes/l4-s5j-addendum3-results.md)。追補1のB群36腕各2走一致から **L_C** を採用する。
小文字ASCIIを新しい行として打鍵した範囲で、行頭の数字とASCII空白を次のように読む。

1. 行番号の値を0から積み上げる。数字なら次の値を「現在値×10＋数字」とし、**65529以下なら採る**。
   途中の空白は読み飛ばして次の数字を読む。数字でも空白でもない文字で止める。
2. 次の数字を採ると65529を超える場合は、その数字を消費せず止める。行番号は直前までに採った値。
   読み取り位置を最後に採った数字の直後へ戻し、以降を本文とする（途中で読み飛ばした末尾の空白も戻る）。
3. 本文の先頭が空白なら**1個だけ**取り除き、残りは保つ。本文の語と数値定数は第14.1・14.5節の規則に従う。
   空白しかない本文はその番号の既存行を削除する。LISTでは番号を10進で書き、本文の前に空白1個を出す。

例えば `1 2 3 4 print 1` は `1234 PRINT 1`、`10   print 1` は `10   PRINT 1`、
`130 1+rem x end` は `1301 +REM x end`。`65530 print 1` は番号6553・本文 `0 print 1` となり、
LISTは `6553 0 PRINT 1`。`6553  0 print 1` も番号6553で止まり、本文は先頭空白1個を残す。
`655290 print 1` は番号65529・本文 `0 print 1`。番号だけの `10 20` は先行入力した1020番の行を削除し、署名は `no_line`。

上限周辺の探り11腕（b11、b27〜b36）では、入力時表示がエラー表2番の文言を含むか／完全一致かは
両走とも0/0。これはその文言を検出しなかった観測であり、他のエラー表示の有無・文言は確定しない。
RUNやスクリーンエディタ経路、全角・カナの行番号読み取りは測っていない。

## 15. 観測 — KILL・NAME

第11〜13節と同じくディスクを入れた状態で測定した（ドライブ1に参照ディスク、ドライブ2に自作の生成器で作った媒体）。
根拠は `docs/notes/m6f-k-kill-name-behavior-preregistration.md`（事前登録）、`docs/notes/m6f-k-round1-results-and-addendum1.md`、
`docs/notes/m6f-k-addendum1-results.md`（最終、器具 `1b724dd`）。媒体の変わり方は `l3-disk-format.md` 1.6節。

### 15.1 規則

1. `KILL "<ドライブ>:<名前>"` はファイルを消す。完了しても **`Ok` の行を足さない**（入力待ちの `Ok` は出る。第13.1節規則2と同じ）。
2. `NAME "<ドライブ>:<旧名>" AS "<ドライブ>:<新名>"` はファイルの名前を変える。完了しても **`Ok` の行を足さない**（入力待ちの `Ok` は出る。第13.1節規則2と同じ）。
3. 名前が見つからなければ **`ERR 53`**（`KILL` の名前、`NAME` の旧名）。名前は大文字・小文字を区別する。
4. `NAME` の新名が既にあれば **`ERR 65`**。
5. `NAME` の新名にドライブを書かないと **`ERR 73`**（旧名がドライブ2のとき）。
6. 書き込み禁止の媒体では、`KILL` は **`ERR 61`**。**`NAME` はエラーにならず改名する。**
7. 規則3〜6のエラーでは媒体は変わらない（規則6の `NAME` を除く）。

### 15.2 測っていない範囲

- ドライブをまたぐ `NAME`、両方ともドライブを省略した `NAME`・`KILL`（省略時の既定ドライブ）。
- 名前の長さの規則、開いているファイルの `KILL`、媒体の無いドライブ。
- エラーの判定の順（例: 旧名が無く新名もある場合）。


## 16. 観測 — RND・RANDOMIZE（l4-s8a）

根拠は [追補4結果ノート](../notes/l4-s8a-addendum4-results.md) とそこからリンクする
1回目・追補1〜3の測定ノート。N88 V2、ディスク無しで自作プログラムのPRINTを
公式ROMで採取した。追補4は22腕×2走すべて関門通過・全整数組2走一致、
R_D全22腕一致、R_Cは5腕・R_Aは6腕・R_Bは13腕で不一致となりR_Dを採用した。
以下は有限の観測列を再現し、登録済み分離腕で確認した規則であり、
未観測の状態まで確認したという意味ではない。

### 16.1 採用規則 R_D

Q(v) は厳密値 v を24ビット仮数の MBF 単精度へ最近接丸めする操作で、
ちょうど半分なら絶対値の大きい側へ丸める。非零の表現を `(σ,E,M)` とし、
`σ=0` は正、`σ=1` は負、値は `(-1)^σ × M × 2^(E-152)`、
`0x800000 ≤ M ≤ 0xffffff` とする。E はバイアス付き指数。
零は `σ=E=M=0`。rev24 は24ビット整数の3バイトの順序を逆にする操作。

```
P(σ,M) = (M & 0x7fffff) | (σ << 23)
T(σ,E,M) = Q(((rev24(P(σ,M) XOR 0x00004f) << 8) | E) / 2^32)
```

状態は単精度値 x、次の乗数位置 i（0〜7）、周期位相 c（0〜170）。
起動と RUN は `x=Q(0xcfc752 / 2^24), i=1, c=0` へ初期化する。
NEW 後の RUN も同じ初期化を行う。NEW 単独の効果は未分離。
初期値を記録器の `(符号,指数,上位12ビット,下位12ビット)` で表すと
`(1,0,3324,1874)`。RND(0) の初回もこの値になる。

8乗数は次のとおり。整数表記は厳密に単精度で表現でき、MBF 表記も併記する。

| i | A_i | σ | E | M |
|---:|---:|---:|---:|---|
| 0 | -26514538 | 1 | 153 | `0xca4a35` |
| 1 | 16129081 | 0 | 152 | `0xf61c39` |
| 2 | -11769122 | 1 | 152 | `0xb39522` |
| 3 | 13098250 | 0 | 152 | `0xc7dd0a` |
| 4 | -20161190 | 1 | 153 | `0x99d153` |
| 5 | -10426890 | 1 | 152 | `0x9f1a0a` |
| 6 | -13483109 | 1 | 152 | `0xcdbc65` |
| 7 | 12482518 | 0 | 152 | `0xbe77d6` |

通常更新は以下の順序で行う。積の仮数へ補正を足すのではなく、
丸めた積のバイト反転後の整数 R に補正を足す。

```
y = Q(A_i × x)                         # 以下の σ,E,M は y のもの
c = (c + 1) mod 171
R = rev24(P(σ,M) XOR 0x00004f)
if c == 0: R = R + 0x00ff01
x = Q(((R << 8) | E) / 2^32)
i = (i + 1) mod 8
```

この式の採用範囲は補正後の R が24ビット以内に収まる場合。
24ビット溢れは未観測であり、器具の便宜的な `mod 2^24` は確定仕様に含めない。
今回の全署名一致はその仮の溢れ処理に依存しない。

- **RND(0)**: 現在の x を返す。x・i・c のどれも変えない。
- **正引数の RND と引数なし RND**: 通常更新を1回行い x を返す。
  正引数の大きさは使わない（2、0.5、1E10を測定）。
- **負引数 RND(-y)**: 正の単精度入力 y の E,M を使い、
  `x=T(1,E,M), i=0, c=0` として x を返す。
  乗算・通常更新・c の加算は行わない。前歴を消す。
  十進入力の読み取りは別の規則であり、ここで観測した入力 MBF を出力から逆算しない。
- **RANDOMIZE n**: n を符号付き16ビット整数へ最近接丸めし、半分なら
  絶対値の大きい側へ丸める（1.5→2）。現在の x の E と仮数の最下位バイト
  `b=M & 255` を保ち、以下の置換後、現在の i,c から通常更新を1回行う。

```
P' = ((n & 65535) << 8) | b
σ' = P' >> 23
M' = (P' & 0x7fffff) | 0x800000
x = (-1)^σ' × M' × 2^(E-152)
```

RANDOMIZE は i,c をリセットしない。内部更新も c に1回数え、
周期境界なら補正を行う。連続 RANDOMIZE もそれぞれ1回数える。
値は出力しない。整数種 -32768〜32767 の測定例に基づく規則であり、
丸め後にこの範囲を外れる n の扱いは未確定。

起動から2000更新の測定では全値が `0<x<1`、零と1は各0個だった。
これは有限列の観測であり、未測定の全状態についての範囲保証ではない。

### 16.2 未確定

## 17. 観測 — 文字列関数 CHR$・SPACE$・STRING$・HEX$・OCT$・INSTR（l4-s9a）

根拠は [事前登録](../notes/l4-s9a-string-functions-preregistration.md)（`5e59c04`）と
[1回目結果](../notes/l4-s9a-round1-results.md)。測定時HEAD・器具は `3dc7bad`。
91腕×2走の全182行が関門通過・2走一致。定数対照4腕を除く87腕で、
事前に固定した S_GW が全一致した。以下はその標本で裏付けた規則であり、
全入力を網羅した観測ではない。文字列の値は文字コード列として採り、表示動作は含めない。

### 17.1 整数化・範囲検査・誤り

数値引数の整数化は最近接整数への丸めで、ちょうど半分なら絶対値の大きい側へ丸める。
`65.4→65`、`65.5→66`、`66.5→67`、`-0.4→0`、`-0.6→-1`
（`chr-13`〜`chr-19`）。`2.5→3`、`3.5→4` は `space-05`・`space-06`、
`hex-12`・`hex-13`、`oct-12`・`oct-13`、`-0.5→-1` は `hex-14`・`oct-14`。

CHR$のコード、SPACE$の長さ、STRING$の長さと数値の文字指定、INSTRの開始位置には、
次の順序の変換を用いる。

1. 数値を要求する位置に文字列があれば誤り13（`chr-21`、型違いの別例は `hex-15`）。
2. 符号付き16ビット整数へ上記の丸めを行う。整数化の範囲 -32768〜32767 を外れると誤り6
   （`chr-20` の32768）。
3. 整数化できても0〜255の範囲外なら誤り5（`chr-17`〜`chr-19`、
   `space-07`・`space-08`、`string-08`〜`string-10`、`instr-11`・`instr-13`）。
4. INSTRの開始位置はさらに0を拒み、誤り5（`instr-10`）。

これは事前登録の変換順序を単独の誤り標本で裏付けた規則である。
複数引数が同時に不正な場合の検査順序は未測定。
番号と文言の対応は既存の `src/l4_basic/errors.tsv` に従い、5は `Illegal function call`、
6は `Overflow`、13は `Type mismatch`、15は `String too long`。
今回採ったのはERR番号であり、公式画面のエラーメッセージ文言を測定したものではない。

### 17.2 CHR$・SPACE$・STRING$

- `CHR$(code)` は変換後のコードを持つ長さ1の文字列を返す。
  0も長さ1であり、終端扱いしない。0、1、7、13、31、32、65、127、128、160、223、255を確認
  （`chr-01`〜`chr-12`）。
- `SPACE$(length)` は変換後の長さだけコード32を並べる。長さ0は空文字列、255は有効
  （`space-01`〜`space-04`）。
- `STRING$(length,code)` は変換後の長さだけ変換後のコードを並べる。
  数値指定0・255も有効。長さ0は空文字列、255は有効
  （`string-01`、`string-03`〜`string-06`）。長さと数値の文字指定の丸めは
  `string-11`・`string-12`で確認した。
- `STRING$(length,text$)` は第2引数の先頭1文字だけを繰り返す。
  `STRING$(3,"ab")` はコード97を3個返し、空文字列指定は誤り5
  （`string-02`・`string-07`）。長さ0でも第2引数を評価してから空文字列を返すのが
  登録規則だが、`STRING$(0,"")` は今回未測定である。

### 17.3 HEX$・OCT$

整数入力の有効範囲は -32768〜65535。16ビット表現を先頭零のない文字列にする。
HEX$は大文字十六進、OCT$は八進。零だけは1桁の `"0"`、負数は16ビットの2の補数として表す。
HEX$では `-1` と65535が `"FFFF"`、-32768と32768が `"8000"`。
OCT$ではそれぞれ `"177777"` と `"100000"` となる
（`hex-01`〜`hex-09`、`oct-01`〜`oct-09`）。65536と-32769は誤り6
（`hex-10`・`hex-11`、`oct-10`・`oct-11`）。文字列引数は誤り13（`hex-15`）。

非整数は17.1の最近接・半分は絶対値の大きい側の丸めを使う
（`hex-12`〜`hex-14`、`oct-12`〜`oct-14`）。登録規則の手順は、
元の値が32768以上65536未満なら先に65536を引き、その値を符号付き16ビットへ整数化し、
それ以外は元の値を整数化して、最後に下位16ビットを表現する。
今回この正の拡張範囲で採ったのは整数だけであり、非整数の境界や半分の扱いは未分離。
「正数を先に丸めてから65536で剰余を取る」と同一視しない。

### 17.4 INSTR

`INSTR(target$,needle$)` は開始位置1、`INSTR(start,target$,needle$)` は
17.1で整数化した開始位置を使う。位置は1始まりで、開始位置自身を含めて後方を検索し、
最初に一致する位置を返す。一致しなければ0
（`instr-01` は3、`instr-02` は開始4から6、`instr-09` は0）。
開始255は有効だが対象長を超えるので0（`instr-12`）。
`INSTR(2.5,"abcabc","b")` は開始3へ丸め、5を返す（`instr-14`）。
対象・検索語は文字列を要求し、数値を渡すと誤り13（`instr-15`）。

開始が対象の長さを超えれば、検索語が空でも0（`instr-05`・`instr-06`）。
対象が空なら検索語が空でも0（`instr-07`・`instr-08`）。
検索語だけが空で開始が対象長以内なら開始位置を返す
（`instr-03`・`instr-04`）。大小区別は資料の登録規則だが、今回の実測では分離していない。

### 17.5 連結と未確定

文字列連結の結果が255文字を超えると誤り15。
255文字と1文字の連結、200文字と56文字の連結で確認した（`long-01`・`long-02`）。

未測定は INKEY$、PRINT CHR$(n)の表示・制御文字の画面動作、漢字（2バイト文字）、
MID$文、文字列比較、FREとガーベジコレクション、INSTRの大小区別。
加えて、長さ0かつ空のSTRING$第2引数、HEX$/OCT$の正の拡張範囲の非整数境界、
複数の不正引数が重なる場合の誤り優先順位は今回決めない。

## 18. 観測 — PEEK・POKE（l4-s9b）

根拠は [事前登録](../notes/l4-s9b-peek-poke-preregistration.md)（`6687333`）と
[1回目結果](../notes/l4-s9b-round1-results.md)。測定時HEAD・器具は `38feeab`。
30腕×2走の全60行が関門通過・2走一致。定数対照3腕を除く27腕でP_GWが全一致した。
全読出しはCLEARの第2引数でBASICの利用上限を下げて確保した利用者領域で行い、
各腕の先行POKEで自分が書いた既知値だけを観測した
（`control-clear`・`control-roundtrip`）。以下の数値番地は測定プログラムが選んだ
利用者データの位置であり、公式ROM内部の領域配置を定義するものではない。
自作実装が使う内部番地は実装側で決める。

### 18.1 番地の整数化

`POKE address,value` の第1引数と `PEEK(address)` の引数は、次の順序で変換する。

1. 元の数値が32768以上65536未満なら、先に65536を引く。それ以外は元の数値を使う。
2. 符号付き16ビット整数へ最近接丸めする。ちょうど半分は絶対値の大きい側へ丸める。
   整数化の範囲 -32768〜32767 を外れると誤り6。
3. 得た整数が負なら65536を足し、0〜65535の実効番地にする。

十進49152・十六進表記・-16384は同じ利用者番地に対応した
（`address-decimal`・`address-hex`・`address-negative`）。
49152.4は-16383.6→-16384→49152、49152.5は-16383.5→-16384→49152となる。
両腕ともPOKEは下側の利用者バイトだけを書き換え、PEEKは下側の既知値を返した
（`address-poke-plus04`・`address-poke-plus05`・`address-peek-plus04`・
`address-peek-plus05`）。正数を先に整数化すると49152.5→49153になるため、
その手順は採らない。

POKEの番地65536・-32769は誤り6
（`address-out-65536`・`address-out--32769`）。これは番地範囲外のPOKEの観測である。
**範囲外PEEKは保留・未測定**。同じ2入力のP_GW予測はERR=6だが、観測済みと扱わない。
番地への文字列入力も今回未測定である。

### 18.2 POKEの値の変換と誤り

番地が有効な場合、値の変換は次の順序を用いる。

1. 値には数値を要求し、文字列は誤り13（`value-16`）。
2. 符号付き16ビット整数へ18.1と同じ最近接・半分は絶対値の大きい側の丸めを行う。
   値には番地の65536減算を適用しない。整数化の範囲を外れると誤り6。
   32768・-32769で確認（`value-14`・`value-15`）。
3. 整数化できた値が0〜255の範囲外なら誤り5。256・-1で確認
   （`value-12`・`value-13`）。範囲内ならその1バイト値を書き込む。

0・1・127・128・255の書込みと読戻しが一致（`value-01`〜`value-05`）。
65.4→65、65.5→66、66.5→67、-0.4→0、255.4→255
（`value-06`〜`value-10`）。255.5は256へ丸めてから誤り5となる（`value-11`）。
下位8ビットだけを取って範囲外値を受理する規則ではない。
この順序は登録した変換規則を単独の不正入力で裏付けたもの。
番地と値が同時に不正な場合の引数間の誤り優先順位は未測定。

番号と文言の対応は既存の `src/l4_basic/errors.tsv` の範囲に限る。
5は `Illegal function call`、6は `Overflow`、13は `Type mismatch`。
今回の観測はERR番号であり、公式画面のメッセージ文言は測定していない。

### 18.3 PEEKの結果と測定範囲

PEEKは実効番地の符号なし1バイトを0〜255の整数として返す。
0・1・127・128・255を確認（`value-01`〜`value-05`）。
正の73のPRINTは整数の先頭空白を持つ数値表示であり、整数変数への代入も成功した
（`type-print`・`type-integer`）。
利用者領域以外のメモリ、特殊番地・保護・セグメント設定、VRAM・画面動作、
INP/OUT、USR/CALL、CLEARの誤りは決めない。
範囲外PEEK、番地の型違い、未採取の小数境界・倍精度との差も未測定。
文字列関数・INSTR・誤り15は別段l4-s9aの第17節を参照し、本段で再測定していない。


## 19. 観測 — INKEY$（l4-s9c）

根拠: [事前登録](../notes/l4-s9c-inkey-preregistration.md)、
[追補1](../notes/l4-s9c-addendum1-preregistration.md)、[結果ノート](../notes/l4-s9c-results.md)。
取り直しの関門通過22腕と追補1の6腕（定数重複を除く25腕）で各2走一致。
事前候補はK_BUFが残り、K_LAST・K_NONEは棄却された。予測なし4腕は観測として記述する。

### 19.1 空文字列と順序付き読出し

INKEY$は、未読の打鍵文字がなければ空文字列を返す。
押した文字は押した順にキューされ、呼出し1回で先頭1文字を取り出して取り除く。
読み尽くした後は空文字列を返す。ab・aabの順序と同一文字の重複も保持された。
追補の5・10・20文字は待ち中に打ち終えてからすべて打鍵順に読み出せた。
**20文字までは上限に当たらない。容量上限は未確定**であり、無限容量や20文字上限を定義しない。

RUN開始に使ったRETURNは未読文字として残らない。
run-returnの最初と待ち後の計9回はすべて空だった。

### 19.2 文字コード

返る1文字のコードは観測した打鍵文字に対応する。

| 打鍵 | ASC値 |
|---|---|
| a / z | 97 / 122 |
| 上段0 / 9 | 48 / 57 |
| 空白 / ! / ? / + / [ | 32 / 33 / 63 / 43 / 91 |
| 実行中の追加RETURN | 13 |
| 追補のa〜t | 97〜116（打鍵順） |

特殊キーや修飾キーをこのコード表から推定しない。

### 19.3 画面表示と長押し

実装ではINKEY$で読んだ文字を画面へ表示しない。
echo-idleとecho-aは他行件数がともに4で増加なし、echo-aはaを1回取得した。
これは行件数による観測であり、既存行内の変化やあらゆる条件での非エコーは確定していない。

長押しのリピートも文字として届く。hold-aの160フレーム押下では10000回の読出し中に
非空34回・最大LEN=1、保存した先頭8文字はすべてASC=97だった。
実装は複数のリピート文字を受け取れるようにするが、この回数・間隔は一般規則にしない。

### 19.4 未確定の範囲

特殊キー、修飾キー、テンキー、カナ、漢字、未測定文字、容量上限・満杯時の動作、
リピート間隔・開始遅延は決めない。


## 20. 観測 — CLEAR の上限番地と FRE（l4-s9d）

根拠: [事前登録](../notes/l4-s9d-memory-limit-preregistration.md)（器具 `5f02a0a`）、
[1回目結果](../notes/l4-s9d-round1-results.md)。73腕×2走。定数対照2腕が関門を通過し、
`fre("")` の1腕を除く72腕が各2走一致した。以下の番地・値は測定プログラムの操作に対する
利用者から見える観測であり、公式ROM内部の領域配置を定義しない。

### 20.1 受理範囲と誤り番号

`clear ,a`（第2引数のみ）の観測は次のとおり。

| a | 結果 |
|---|---|
| 0x8000・0x8400 | 誤り5 |
| 0x8800 | 誤り7 |
| 0x8C00〜0xE400（0x400刻み23点） | 受理 |
| 0xE800〜0xFC00（5点）・0xFFFF | 誤り5 |

受理の下限は 0x8800（誤り7）と 0x8C00（受理）の間、上限は 0xE400（受理）と
0xE800（誤り5）の間にある。格子の外の番地（境界の正確な位置）は未測定。
0x8800 だけが誤り7になる理由と、他の拒否点の誤り5との使い分けは決めない。

### 20.2 FRE との関係

受理された23点すべてで `fre(0) = a − 35098`（傾き1）が一致した。
CLEARを飛ばした既定の `fre(0)` は、測定プログラムの全35対照で 23779 だった。

**定数35098は公式の既定配置に依存する観測値である。** 自作が自作の配置で
`fre(0)` と上限の差が定数になる同じ形の関係を満たせばよいのか、値35098まで
合わせるのかは**未決**。値まで合わせる決定は別の根拠（配置の測定）を要する。

### 20.3 既定上限の推定

観測ではなく推定: 傾き1の関係を既定側へ外挿すると、既定の上限は
23779 + 35098 = 58877（0xE5FD）。格子の受理境界（0xE400受理・0xE800拒否）と
矛盾しない。直接の受理境界は測っていないため、正確な値は追補で詰めるまで確定しない
（整数化・端点の包含も未確認）。

### 20.4 第3引数

`clear ,49151,256` は `fre(0)` が 14309、`clear ,49151,1024` は 13541。
第3引数なしの同じ a の腕は無いが、傾き1から 49151 − 35098 = 14053 と推定すると、
256 は +256、1024 は −512。指定を増やすと FRE が同量だけ減り、
既定のスタック相当は512バイトと推定できる（推定。512の直接指定の腕は無い）。
第3引数の受理範囲（0・極端な値）は未測定。

### 20.5 未確定の範囲

`fre("")` は既定状態で数値が出なかった（関門 gate_failed）。その意味は決めない。
第1引数、`fre(1)`・`fre(2)`、文字列領域の整理、既定上限の正確な値、
ROM内部配置、プログラム本文の置き場所は決めない。

## 21. 観測 — 文字列の比較（l4-s9e）

根拠: [事前登録](../notes/l4-s9e-string-compare-preregistration.md)（器具 `355d422`）、
[1回目結果](../notes/l4-s9e-round1-results.md)。213腕×2走。定数対照4腕が関門を通過し、
本体209腕が全て予測（C_GW）と一致した。以下は測定プログラムの操作に対する
利用者から見える観測である。腕IDは `tests/conformance/expected_l4_strcmp.tsv` のもの。

### 21.1 比較の規則

演算子は `=` `<>` `<` `>` `<=` `>=` の6つ。左右の文字列を**先頭から1バイトずつ
符号なしバイトとして**比べ、**最初に違う位置の大小で決まる**
（最後の1文字違い・最初の1文字違いとも前後入替で逆転: `lit-lastlt-*`・`lit-lastgt-*`・
`lit-firstlt-*`・`lit-firstgt-*`）。

- **接頭辞は短い方が小さい**（`lit-prel-*`・`lit-prer-*`、`var-ab-abc-*`）。
  長さを先に比べるのではない（"ab"<"ba" は先頭の違いで決まる）。
- **空文字列は最小**。空どうしは等しい（`lit-ee-*`・`lit-ene-*`・`lit-nee-*`、`var-e-e-*`）。
- **128以上は0〜127より大きい**（`lit-hil-*`・`lit-hir-*`・`lit-h127-*`・`lit-h128-*`、
  `var-c200-a-*`）。
- **chr$(0) も普通のバイト**で、途中の0で打ち切らない。"a"+chr$(0) は "a" より大きく、
  chr$(0) は空より大きい（`lit-z-pre-*`・`lit-z-prer-*`・`lit-z-e-*`・`lit-z-z-*`・
  `lit-z-1-*`・`lit-z-mid-*`）。
- **大小文字は別のコード**。"a" は chr$(65) より大きい（`lit-case-*`・`lit-caser-*`）。

### 21.2 結果の型と使える場所

結果は**整数**で、真は-1、偽は0（`control-true`・`control-false`）。
左右が変数・関数結果・連結の式でも同じ（`var-*`、`func-01`〜`func-17`）。
`str$(5)=" 5"` は真、`str$(5)="5"` は偽（`func-12`・`func-13`）。

IF の条件に使える（`if-01`〜`if-16`）。`a$=""` は未設定の変数で真、"x"・chr$(0) で偽。
`a$<>""` はその逆。`a$=b$`（両方未設定）は真。AND/OR/NOT との併用、関数結果との
比較、chr$(200) との比較も予測どおり。

### 21.3 論理・算術との組合せと優先順位

結果の整数がそのまま AND/OR/NOT・加算・単項マイナスへ渡る（`logic-01`〜`logic-10`）。
`("a"="a")+1` は0、`("a"="b")+1` は1、`-("a"="a")` は1、`not ("a"="a")` は0、
`not ("a"="b")` は-1。比較結果どうしの比較・比較結果と1の比較も整数として扱われる
（`logic-14`〜`logic-16`）。

測った範囲の優先順位:

- **比較は AND/OR より高い**。括弧なしの `"a"="a" and 1=1` は-1、`"a"="b" or 1=1` は-1、
  `1=1 and "a"="b"` は0（`logic-11`〜`logic-13`）。
- **連結 `+` は比較より先に評価される**。`"a"+"b"="ab"` は真、`"a"+"b"<"ab"` は偽、
  `"a"+"b"<="ab"` は真（`func-09`〜`func-11`）。

比較の連鎖（`"a"<"b"<"c"`）は測っていない。

### 21.4 型混在

文字列と数値の比較は**常に誤り13**（`type-01`〜`type-10`）。左文字列・右数値、
左数値・右文字列の両順、`=` `<` `<>`、`""=0`、`"1"=1`、`1="1"`、変数 `a$=1` を含む。
数字だけの文字列でも数値に変換して比べない。

### 21.5 未確定の範囲

漢字（2バイト文字）の比較、比較の速度、比較の連鎖、倍精度等を含む型混在、
INKEY$ そのものは決めない。自作ROMはIFの文字列比較に既知の未実装があり、
この節は公式ROMの観測であって自作の動作を述べない。
