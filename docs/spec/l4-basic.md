# L4 BASIC — 直接モードの PRINT

仕様書 第3.7版 / 2026-09-15

測定対象: エミュレータ QUASI88 libretro 版、コア既定 N88 V2、ディスク無し、公式ROM一式。

`docs/spec/` の書き方は [l3-main.md](l3-main.md) に倣う。**「観測」と「推定」を節ごとに
分け、実装は観測にだけ従う。** さらに本書では「観測」と「資料の記載」も節を分ける
（測定 > 資料の原則。資料の記載は判定の根拠にしない）。**画面本文
（公式ディスクの一覧・第三者由来の文字列など）はこの文書のどこにも書かない**
（`CLAUDE.md` 禁止事項7）。書いてよいのは、自分で指定した打鍵文字列とその直接の
結果（数値・記号・エコー）、非空白セルの件数・位置範囲、番地・行列番号までである
（`l4-s3a-print-format-preregistration.md`「本文を出さない取り扱い」の区分を踏襲）。

画面出力・行入力・スクロール・キー入力・テキストVRAMの構造は
[l3-main.md](l3-main.md)（第3版）にすでにあるので、ここでは重複して書かず参照のみ行う。

## 1. 観測 — 直接モードの行の扱い

**打った行を確定すると、その直後の行に実行結果が出力され、さらにその次の行に
`Ok` が出る。** 打った行を相対行0とすると、出力の行は相対行+1、`Ok` の行は
相対行+2で、全腕（構文の誤りを含む）で一貫していた。

根拠: `l4-s3a-print-format-results.md` Q4（記述のみ、判定名なし）。P1-7腕を含む
測定した全腕でこの並びが観測された。末尾に `;`・`,` を付けて2文に分けて打った
腕（P3-trail-semi・P3-trail-comma）でも、1文目→出力→`Ok`→2文目→出力→`Ok`という
同一パターンが繰り返された（第4節参照）。

直接モードの各行の先頭の絶対位置・番地は [l3-main.md](l3-main.md) 第2節の式
（`addr = 0xF3C8 + row0*120 + col0`）にそのまま従う。全腕で打った行の先頭セルは
絶対位置 (row0=6, col0=0)、番地 `F698` で一致した（`l4-s3a-print-format-results.md`
「原点」節）。浮動小数点の測定（第5節、`l4-s4a`・`l4-s4b`・`l4-s4c`）でも、全腕で
打った行の先頭セルは同じ絶対位置 (row0=6, col0=0) で一致している。

## 2. 観測 — PRINT: 整数の書式

**整数の前には符号のための1桁が確保される。正の数・0では空白、負の数では
`-`。** 根拠: `l4-s3a-print-format-results.md` Q1（判定`sign_space_before`）。
P1-0・P1-1・P1-7・P1-10・P1-32767の5腕で、出力行の相対列0が変化せず(元の空白
0x20のまま)数字が相対列1から始まった。P1-m1・P1-m32768の2腕では相対列0に
`-`(0x2D)が書き込まれ、数字は相対列1から始まった。

**整数の後ろには空白が1つ付く。符号の正負・桁数によらず一定（`trailing_space_1`）。**
根拠: `l4-s3a-print-format-results.md` Q1・Q3、および
`l4-s3b-print-trailing-results.md` Q1。`print 1;2` の腕（P3-semi-num、第4節）で、
`1`と`2`の間に2列ぶんの空白が生じ、これが「`1`の後置の空白1」＋「`2`の前置の
空白1」で説明できることから、正の数の後置空白がまず間接的に確認された
（l4-s3a）。続く `l4-s3b` では `PRINT n;"q"`（n = 5, -5, 0, 32767, -32768）の
5腕すべてで、数字末尾と`q`の間の未変化セルが1列で一致し、**正の数・0・負の数・
桁数によらず後置空白1であることが直接確認された**（P1Q-m5・P1Q-m32768で
負の数の後置空白を直接確認）。

## 3. 観測 — PRINT: 文字列の書式

**文字列の前後には空白が付かない。** 根拠: 同結果ノートQ2（判定名なし、記述の
み）。1文字列だけを出力する腕で、出力行の相対列0（先頭そのもの）から文字列が
始まった。後ろに何か付くかは単独腕からは直接確認できないが、文字列どうしを
`;` で連結する腕（第4節のP3-semi-str）で2つの文字列が間隔0で隣接したことから、
数値のような前置・後置の空白が無いと分かる。

## 4. 観測 — PRINT: 区切り記号（`;` と `,`）とゾーン幅

| 区切りの形 | 直前出力との間隔 | 判定 |
|---|---|---|
| 数値`;`数値 | 2列（空白2セル） | `no_suppress` |
| 数値`,`数値 | 14列 | `no_suppress`（ゾーン区切り、`zone_14`） |
| 文字列`;`文字列 | 0列（隣接） | `suppresses_between` |
| 文字列`,`文字列 | 14列 | `no_suppress`（ゾーン区切り、`zone_14`） |
| 数値`,`数値`,`数値 | 14列・14列 | `zone_14` |
| 末尾`;`（別々の2文に分けて打つ） | — | `newline_not_suppressed` |
| 末尾`,`（別々の2文に分けて打つ） | — | `newline_not_suppressed` |

根拠: `l4-s3a-print-format-results.md` Q3。

- **数値どうしの`;`は数値自身の書式（前後の空白）をそのまま残すだけで、`;`
  自体が追加の区切りを足すわけではない。** 2列の間隔は「前の数値の後置空白1」
  ＋「後ろの数値の前置空白1」で説明できる（第2節と符合）。
- **文字列どうしの`;`は直前の出力に直後で続く（間隔0）。** 数値の`;`とは
  異なる。
- **`,`はいずれも14列間隔のゾーン区切りになる（`zone_14`）。** 数値・文字列
  どちらも同じ幅で、3個並べても14列ずつだった。資料の記載「14文字ごと」
  （第7節）と一致する。
- **末尾の`;`・`,`は、別々の直接モード文2つに分けて打った構成では、2文目の
  出力を1文目と同じ行には続けなかった（`newline_not_suppressed`）。** これは
  直接モードが1文実行するごとに新しい行で`Ok`を出してから次の入力を待つ
  ためで、末尾の`;`・`,`が本来持つ「改行を起こさない」効果そのものは、この
  構成では`Ok`の改行に隠れて直接には確認できなかった（`l4-s3a-print-format-results.md`
  「言えないこと」）。

**行末の`;`・`,`の改行抑止効果（`l4-s3b`で確認）**: 単一の直接モード行の中で
`:`を使って2文を連結する形（`PRINT "a";:PRINT "b"`・`PRINT "a",:PRINT "b"`）
で追試したところ、`Ok`の改行に隠れずに直接確認できた。根拠:
`l4-s3b-print-trailing-results.md` Q2・Q3。

- **行末の`;`は改行を抑止し、次の出力が同じ行に間隔0で続く（`semicolon_suppresses`）。**
  `PRINT "a";:PRINT "b"` で `a`・`b` が同じ行の隣接列（間隔0）に出た。
- **行末の`,`は改行を抑止し、次の出力が同じ行の次のゾーン境界（列14）から
  始まる（`comma_to_zone_14`）。** `PRINT "a",:PRINT "b"` で `b` が同じ行の
  列14に出た。ゾーン幅14は第4節（数値・文字列間の`,`）と一致する。
- 対照（区切りなし、`PRINT "a":PRINT "b"`）では `b` が次の行の先頭列に出た
  （関門G5）。

## 5. 観測 — PRINT: 浮動小数点の書式

対象は`l4-s4a`（浮動小数点PRINTの出力の形、32腕）・`l4-s4b`（仮説H6＝単精度は
有効6桁で指数表記に切り替わる、23腕）・`l4-s4c`（小さい数〔`|v|<1`〕の固定⇔
指数表記の切替、候補の消去、20腕）の3測定。以下の値・記号は、いずれも自分で
指定した式（`PRINT`の引数）の直接の出力であり、禁止事項7の対象外（各事前登録
「本文を出さない取り扱い」節が明示的に許可、非数値出力〔範囲外・0除算〕の2腕
〔第5.6節〕だけは値を書かない）。

### 5.1 数値定数の型 — 桁数による単精度/倍精度の決まり方

**整数のように書いた定数は、小数点を除いた数字の個数が7桁以内なら単精度、
8桁以上なら倍精度になる。** 根拠: `l4-s4a-float-print-results.md`。

| 腕 | 打鍵文字列（桁数） | 実測の出力 |
|---|---|---|
| E1 | `print 999999`（6桁） | `999999`（固定、丸めなし） |
| E2 | `print 9999999`（7桁） | `1E+07`（単精度6桁に丸められ指数化。第5.4節） |
| E3 | `print 10000000`（8桁） | `10000000`（固定、8桁全部がそのまま出た） |
| D4 | `print 1234567.8`（8桁） | `1234567.8`（固定、8桁全部がそのまま出た） |
| D5 | `print 12345678`（8桁） | `12345678`（固定、8桁全部がそのまま出た） |

E2（7桁）は単精度の丸め（第5.4節、有効6桁）を受けて指数表記になったのに対し、
E3・D4・D5（8桁）はいずれも丸めを受けず全桁がそのまま出た。8桁以上の定数は
単精度では表現しきれない桁数であり、実測では倍精度として扱われていることが
この差から分かる。

**観測していないこと（この規則の適用範囲）**:

- 小数点の左右にある先頭の0（例: `.000015`の`0000`、`0.25`の先頭`0`）を
  この桁数に含めるかどうかは観測していない。E3・D4・D5（8桁以上として
  倍精度になった腕）はいずれも先頭が0でない数字から始まる定数であり、
  先頭0を含む書き方で8桁以上になる定数（例: `.00001234`）が同じ規則に
  従うかは未確認（第10節）。
- `E`指数付きで、仮数部の数字が8桁以上になる定数（例: `1.2345678e-2`）の
  型も観測していない。今回の腕はいずれも仮数部が7桁以内（`e`/`E`使用は
  E4・S4等）か、指数記号を使わない素の整数・小数（E1〜E3・D4・D5）かの
  どちらかで、両方が重なる腕が無い（第10節）。

**`!`（単精度）・`#`（倍精度）の接尾辞、`E`（単精度指数）・`D`（倍精度指数）が
それぞれ型を明示的に決める。** 根拠: 同結果ノート。

| 腕 | 打鍵文字列 | 型の指定 | 実測の出力 |
|---|---|---|---|
| W1 | `print 1#/3` | `#`接尾辞（分母） | `.3333333333333333`（倍精度16桁） |
| W4 | `print 1/3#` | `#`接尾辞（分子） | `.3333333333333333`（W1と同一の並び） |
| W2 | `print 1d10` | `D`指数 | `10000000000`（固定、倍精度） |
| A9（`l4-s4b`） | `print 12345.678!` | `!`接尾辞 | `12345.7`（単精度6桁に丸め） |
| A10（`l4-s4b`） | `print 1234567!` | `!`接尾辞 | `1.23457E+06`（単精度6桁の指数、A1と同一） |
| E4 | `print 1e10` | `E`指数 | `1E+10`（単精度） |

**`e`指数の後ろに`#`を付けた定数（例: `1.5e+10#`のような書き方）は、
数値を出力しなかった。** 根拠: `l4-s4l-double-fin-rep10-rounding-results.md`
（`62e35b4`）、L9〜L12（4腕、いずれも`e`指数の直後に`#`を続けて書いた
定数を含む式）の出力行が、数字・符号・小数点・`E`/`D`・空白の集合に
収まらず`non_numeric_output`に分類された。事前登録「本文を出さない
取り扱い」節の規則どおり、値・文言は記録せず件数と位置の範囲だけを
記録している（例: `print -962467.4715e+15#+962467471500000002048`）。
この形がどう解釈されたか（構文の誤りか、別の解釈になっているか）は
未確定（第10節）。

W1・W4は接尾辞の位置（分子・分母のどちら）によらず同じ倍精度書式になった
（`l4-s4a-float-print-results.md`「観測」節）。英字（`e`・`d`）は小文字で打鍵して
通った（両測定の「器具の確認」節、32腕・23腕・20腕すべてでエコー行に打鍵文字列
がそのまま出現）。

#### 5.1.1 単精度の定数の読み取り（FIN）

**観測**: 10進の文字列（桁の並び・小数点・指数）から単精度浮動小数点の
内部値をどう作るか（`FIN`相当の変換）について、単純な候補はいずれも
実測に合わない腕がある。

- **`EXACT`（10進の値を1回だけ単精度へ丸める）は合わない。** 根拠:
  `l4-s4i-fin-double-rounding-results.md`（`8d76647`、補遺`3b2b01d`）・
  `l4-s4j-fin-reading-results.md`（`7a788c8`）。`l4-s4i`の候補式I1〜I20
  （単精度定数−等しい値の倍精度整数、`EXACT`なら差は`0`になるはず）
  20腕全てで実測は非`0`になった。`l4-s4j`でも候補20腕（J1〜J20）中16腕
  で`EXACT`は実測と食い違った。
- **`GW`（GW-BASICの`$FIN`手順どおり、積み上げた整数を倍精度にし、
  倍精度の10のべき乗を1回掛け/割ってから単精度へ丸める）も合わない。**
  `l4-s4i`では対照C6（`print 5.1e+10-51000000512`、両候補とも予測`0`）
  で実測`4096`という、候補・対照どちらの予測とも異なる値になった
  （`l4-s4i-fin-double-rounding-results.md`「記録の補遺」節）。この
  食い違いにより`l4-s4i`は型のまとめを`other`（対照が食い違ったため
  保留）とし、候補の判定根拠にできなかった。`l4-s4j`では`GW`も`EXACT`
  と全く同じ16腕で実測と食い違った（`EXACT`・`GW`の予測列が本測定の
  全腕で偶然同一だったため）。

| 腕 | 出所 | 打鍵文字列 | 実測の出力 | 備考 |
|---|---|---|---|---|
| C6 | `l4-s4i` | `print 5.1e+10-51000000512` | `4096` | `EXACT`・`GW`とも予測`0`、実測は非`0`（`l4-s4i`が`other`になった直接の原因） |
| J10 | `l4-s4j` | `print -154904.5e-5` | `-1.54905` | `EXACT`・`GW`は`-1.54904`（丸めの最終桁が1違う） |
| J17 | `l4-s4j` | `print -5.17e+5-93.6e+10` | `-9.36001E+11` | `EXACT`・`GW`は`-9.36001E+11`（一致）だが、後述`REP01`の予測`-9.36E+11`とは食い違う |
| J20 | `l4-s4j` | `print 8.418484e+11-784.e+4` | `8.41841E+11` | 同上（`EXACT`・`GW`は一致、`REP01`は`8.4184E+11`で食い違う） |

**推定（実装が従う規則。開発者判断、測定では確定しきれなかったため）**:
`l4-s4j`では、事後に立てた候補`REP10`（数字を先頭から`acc=acc*10+d`で
積み上げ1手ごとに単精度へ丸め、正味の指数`n`〔`e`の値から小数点以下の
桁数を引いたもの〕の分だけ10を掛ける〔`n>0`〕か10で割る〔`n<0`〕操作を
1回ずつ・1手ごとに単精度へ丸めながら繰り返す）が`l4-s4i`の28腕を全て
再現したが、`l4-s4j`の新しい29腕では4腕（J12・J15・J17・J20）で食い違い、
`no_survivor`になった（`l4-s4j-fin-reading-results.md`）。

GW-BASICのソース分析（`docs/notes/l4-fin-model-search.md`、別担当がGW-BASIC
のソースから読んだ内容。**中身は本節では読まない・触らない**、結論だけを
参考にする）によれば、GW-BASICの`$DIV10`（10で割る操作）は単精度に丸めた
`0.1`を掛ける作りになっている。これを手がかりに、`REP10`の「10で割る」を
「単精度に丸めた`0.1`を掛ける」に置き換えた規則を**`REP01`**として立てる。

> **`REP01`**: 数字を先頭から`acc = acc*10 + d`で積み上げ、1手ごとに
> 単精度へ丸める。正味の指数`n`（`e`の値から小数点以下の桁数を引いた
> もの）が正なら10を、負なら単精度に丸めた`0.1`を、それぞれ`|n|`回、
> 1回ずつ掛けて1手ごとに単精度へ丸める。丸めは半分なら絶対値の大きい側
> （第5.3節）。符号は最後に適用する。

`REP01`は、`l4-s4i`・`l4-s4j`を合わせた実測57件（候補・対照とも）中
**55件を再現する。** 再現しないのはJ17（`print -5.17e+5-93.6e+10`）・
J20（`print 8.418484e+11-784.e+4`）の2件で、いずれも`93.6e+10`・
`8.418484e+11`という定数の読み取りが実測と1ビット違う形で食い違う。
**この2件を説明する規則は見つかっていない。** `REP01`は事後に立てた
規則であり前向きに検証する測定は行っていないため、**判定根拠にはせず
推定として書く**。ユーザー判断（2026-09-15）により、実装はこの
`REP01`に従って先へ進む。

#### 5.1.2 倍精度の定数の読み取り

**観測**: 単精度と同様、単純な候補はいずれも倍精度の実測に合わない
腕がある。

- **`DEXACT`（10進の値を1回だけ倍精度へ丸める）・`DGW`（GW-BASICの
  `$FIN`手順どおり、積み上げた整数を倍精度にし、倍精度の10のべき乗を
  1回掛け/割ってから倍精度へ丸める）は合わない。** 根拠:
  `l4-s4k-double-fin-reading-results.md`（`ec794b9`）。候補24腕
  （D1〜D24）中7腕（D1・D2・D9・D13・D15・D17・D18）で実測と食い違った
  （`DEXACT`・`DGW`は本測定の全腕で予測列が完全に同一だったため、
  食い違った腕の集合も同一）。
- **単精度の`REP01`と同じ考え方（正味の指数が負なら単精度に丸めた
  `0.1`を反復して掛ける）を倍精度へ広げた`DREP01`も合わない。** 候補
  24腕中21腕で食い違った。D1〜D24は表groupによらず全24腕とも正味の
  指数が負（割る側）で、`l4-s4k`は`no_survivor`（3候補とも1腕以上
  食い違い）になった。

| 腕 | 出所 | 打鍵文字列 | 実測の出力 | 備考 |
|---|---|---|---|---|
| D1 | `l4-s4k` | `print -94.19109934972081e+9+94191099350` | `.2791919708251953` | `DEXACT`/`DGW`・`DREP01`いずれとも食い違う。有効桁の5桁目から予測とずれる大きな食い違い |
| D2 | `l4-s4k` | `print 653.51840771e+5-65351841` | `-.2289999993517995` | `DEXACT`/`DGW`と食い違うが`DREP01`とは一致 |
| D9 | `l4-s4k` | `print 510408418377240.e-35` | `5.104084183772401D-21` | 同上 |
| D13 | `l4-s4k` | `print -60965.251#+60965` | `-.2509999999992942` | 同上 |

`l4-s4l`（`62e35b4`、事前登録`b7378f1`＋追補`1997358`）では、候補
`DREP10E`・`DREP10A`（正味の指数が正〔掛ける側〕の16腕、対照12腕）を
測った。判定は**`no_survivor`**（`DREP10E`・`DREP10A`とも1腕以上
食い違い）。この`no_survivor`の直接の理由は**L9〜L12（4腕、`e`指数の
後ろに`#`を付けた定数を含む式。第5.1節参照）がいずれも数値を出力
せず`non_numeric_output`になった**ことで、値の水準で候補を比較できない
まま自動的に食い違い扱いになった（`l4-s4l-double-fin-rep10-rounding-results.md`
「まとめ」節）。**`DREP10A`は、この4腕を除く残り24腕（候補12腕・対照12腕）
全てで実測と一致していた。** L9〜L12を除けば`DREP10A`は本測定で1腕も
外していない。

**推定（実装が従う規則。開発者判断、単精度で`REP01`を採ったユーザー
判断と同じ扱い）**: GW-BASICのソース分析（`docs/notes/l4-dfin-model-search.md`。
**中身は本節では読まない・触らない**、結論だけを参考にする）が事後に
当てはめたところ、`DREP10A`は`l4-s4k`の36件（候補24・対照12）も再現
することが分かった。

> **`DREP10A`**: 数字を先頭から`acc = acc*10 + d`で積み上げ、1手ごとに
> 倍精度（仮数56ビット）へ丸める。正味の指数`n`が正なら10を`n`回
> **掛け**、負なら10で`|n|`回**割り**（本当の割り算、単精度の`REP01`の
> ような`0.1`の反復掛け算ではない）、1手ごとに倍精度へ丸める。丸めは
> 半分なら絶対値の大きい側（第5.3節）。符号は最後に適用する。

`DREP10A`は、**`l4-s4k`の36件（事後の当てはめ）と、`l4-s4l`で数値を
出した24腕・対照12腕の全てを再現する。** ユーザー判断（2026-09-15）に
より、実装はこの`DREP10A`に従って先へ進む。

**単精度は「10で割る」を単精度に丸めた`0.1`の反復掛け算（`REP01`）で
行うのに対し、倍精度は「10で割る」を本当の割り算（`DREP10A`）で行う。**
両者の手順が違う理由は分かっていない（第10節）。

### 5.2 整数の演算・定数の範囲外は単精度へ昇格

**整数の範囲（-32768〜32767）を超える定数・演算結果は、エラーにはならず、
単精度浮動小数点の書式で出力される。** 根拠: `l4-s4a-float-print-results.md`
promote群（P1〜P5）、全腕`predicted_match`。

| 腕 | 打鍵文字列 | 範囲外の理由 | 実測の出力 |
|---|---|---|---|
| P1 | `print 40000` | 定数が32767超 | `40000` |
| P2 | `print 30000+30000` | 加算結果が32767超 | `60000` |
| P3 | `print -32768-1` | 減算結果が-32768未満 | `-32769` |
| P4 | `print 200*200` | 乗算結果が32767超 | `40000` |
| P5 | `print 7/2` | 整数どうしの割り算 | `3.5` |

**`/`（除算）は、整数どうしの演算でも常に実数（浮動小数点）の結果になる。**
P5（`7/2`）は範囲内の整数どうしの除算だが、結果は`3.5`という浮動小数点の
書式で出た（整数の`3`や`4`に丸められることはなかった）。

P1〜P4の出力（`40000`・`60000`・`-32769`・`40000`）は、いずれも第2節の整数の
書式（符号のための1桁、後置空白1）と同じ前置き・後置きの形をとった
（`l4-s4a-float-print-results.md`「観測」節、符号位置が相対桁0で正の数は空白
のまま・負の数は`-`）。範囲外に見える数でも、単精度浮動小数点としての桁数
（6桁以内）に収まっていれば固定表記のまま出て、指数表記への切り替え（第5.4節）
は起きない。

### 5.3 固定表記の書式（丸め・桁数・0の省略）

**単精度は有効数字6桁、倍精度は有効数字16桁に丸め、末尾の0は落とす。**
根拠: `l4-s4b-h6-results.md`（single_digits群11腕全て`predicted_match`、
`h6_digits_only`の桁数部分）・`l4-s4a-float-print-results.md`（W1・W3・W4等の
倍精度16桁の観測）。

- 単精度の丸め例: D1（`print 1/3`）→`.333333`（6桁）、A1（`print 1234567`、
  `l4-s4b`）→丸めた上で指数化（第5.4節）。
- 倍精度の丸め例: W1/W4（`print 1#/3`・`print 1/3#`）→`.3333333333333333`
  （16桁）。

**整数部が0のときは`0`を書かず、`.`から始める。** F2（`print .5`）→`.5`、
S1（`print .1`）→`.1`、K3等（`l4-s4c`、`|v|<1`の各腕）も同様に`.`から始まる。

**符号のための1桁・数字後ろの空白1は、整数（第2節）と同じ規則がそのまま
浮動小数点にも適用される。** 正の数・0では相対桁0が空白のまま、負の数では
相対桁0に`-`が書かれ、数字は相対桁1から始まる。根拠:
`l4-s4a-float-print-results.md`「観測（判定を動かさない記述）」節（F1〜F5・
D1〜D3・P1〜P5等、負の数はF3・P3等で確認）。

**単精度・倍精度とも、丸めるとちょうど半分になる値は絶対値の大きい側へ
丸める（偶数丸めではない）。** 根拠: 単精度は
`l4-s4g-single-rounding-tie-results.md`（`e637eca`）、single_round群20腕
（R1〜R20、6桁へ丸めるとちょうど半分になるよう選んだ定数）全てで候補`GW`
（GW-BASICの`$FOUT`手順どおり、半分は常に絶対値の大きい方向へ切り上げ）
だけが`candidate_consistent`（対照`EXACT`〔偶数丸め〕は20腕全てで
`candidate_rejected`）。倍精度は
`l4-s4h-double-rounding-tie-results.md`（`b498a33`、事前登録`ea02e1f`＋
追補`3a0b004`）、9腕（H1〜H9、16桁へ丸めるとちょうど半分になるよう選んだ
定数）全てで候補`GW`だけが`candidate_consistent`（対照`EXACT`は16桁目が
偶数の半端になる5腕〔H1・H3・H4・H6・H7〕で`candidate_rejected`）。単精度
・倍精度いずれも`GW`が`unique_survivor`になり、丸め半端の方向が一致した。

| 精度 | 打鍵文字列 | 実測の出力 | 備考 |
|---|---|---|---|
| 単精度 | `print 1841145` | `1.84115E+06` | 7桁の整数、6桁目が丸めでちょうど半分 |
| 単精度 | `print 5188305` | `5.18831E+06` | 同上（6桁目が`0`から`1`側へ切り上げ） |
| 単精度 | `print -34281.25` | `-34281.3` | 負の数、小数点以下がちょうど半分 |
| 単精度 | `print -266650.5` | `-266650` | 負の数、末尾桁がちょうど半分 |
| 単精度 | `print 990860.5` | `990860` | 正の数、末尾桁がちょうど半分（偶数へは丸めていない） |
| 倍精度 | `print 1234567890123456.5#` | `1234567890123457` | 17桁の値、16桁目が丸めでちょうど半分 |
| 倍精度 | `print 2000000000000000.5#` | `2000000000000001` | 同上（16桁目が`0`から`1`側へ切り上げ） |
| 倍精度 | `print 9007199254740992.5#` | `9007199254740993` | 同上（16桁目が偶数の半端） |
| 倍精度 | `print -1234567890123456.5#` | `-1234567890123457` | 負の数、`1234567890123456.5#`の符号違い |
| 倍精度 | `print 1234567890123456#+.5` | `1234567890123457` | 計算（加算）で半端を作った腕、直接指定と同じ結果 |

いずれも「絶対値の大きい側へ丸める」で一貫しており、`-34281.25`は
`-34281.2`（偶数丸め・値の小さい側）ではなく`-34281.3`（絶対値の大きい
側）に、`2000000000000000.5#`は`2000000000000000`（偶数丸め）ではなく
`2000000000000001`（絶対値の大きい側）になった。既存の観測例（第5.1節・
第5.4節のD1〜D3・E2・A1等の6桁丸め）はいずれも丸めの最終桁がちょうど
半分になる値ではなく、この規則と矛盾しない（D1`.333333`・E2`1E+07`等は
ちょうど半分の桁を含まない）。

**16桁目（単精度は6桁目）が奇数になる半端は、偶数丸め・絶対値の大きい
側への丸めのどちらでも同じ結果になり、候補を区別する材料にはならない。**
根拠: `l4-s4h`のH2（`1234567890123457.5#`）・H5（`3333333333333333.5#`）、
16桁目が奇数の腕で`EXACT`・`GW`の予測が一致し、実測もその予測と一致した
（奇数の半端は「1つ上の偶数へ丸める」＝「絶対値の大きい側へ丸める」が
必然的に同じ値になるため）。`l4-s4g`のR5・R7・R8・R11・R17・R19等
（固定表記のまま丸めた腕）も同様の構造を含みうるが、判定はもっぱら
6桁目・16桁目が偶数の半端になる腕（単精度R1〜R20中の該当腕、倍精度
H1・H3・H4・H6・H7）で行っている。

### 5.4 大きい側（整数部が大きい）: 指数表記への切替

**単精度は、値を有効6桁に丸めた後の値の整数部の桁数が6を超える
（`|v|≧10^6`）と指数表記になり、6以下なら固定表記のままになる。判定は
丸めた後の値で行う（A7参照）。** 根拠: `l4-s4b-h6-results.md`、single_digits群
11腕全て`predicted_match`（`h6_digits_only`。桁数の規則そのものは11腕全一致で
支持された）。

| 腕 | 打鍵文字列 | 実測の出力 | 備考 |
|---|---|---|---|
| E1 | `print 999999` | `999999` | 6桁ちょうど、固定のまま |
| A2（`l4-s4b`） | `print 123456` | `123456` | 6桁、固定のまま |
| A6（`l4-s4b`） | `print 1e5` | `100000` | 6桁、固定のまま |
| E2 | `print 9999999` | `1E+07` | 7桁→6桁に丸められ指数化 |
| A1（`l4-s4b`） | `print 1234567` | `1.23457E+06` | 7桁→6桁に丸められ指数化 |
| A4（`l4-s4b`） | `print 100000*10` | `1E+06` | 演算結果が7桁→指数化 |
| A5（`l4-s4b`） | `print 1e6` | `1E+06` | 7桁相当→指数化 |
| A7（`l4-s4b`） | `print 999999.5` | `1E+06` | 丸めで7桁相当になり指数化 |

**指数表記の書式は、仮数部（符号を除く）の後ろに`E`（単精度）または`D`
（倍精度）、続けて指数の符号（`+`/`-`）、指数を2桁で置く。** 根拠:
`l4-s4a-float-print-results.md`。

| 腕 | 打鍵文字列 | 実測の出力 |
|---|---|---|
| E4 | `print 1e10` | `1E+10` |
| E5 | `print -1.5e+20` | `-1.5E+20` |
| S4 | `print 1e-10` | `1E-10` |

**8桁以上の整数定数は倍精度に昇格するため、単精度の6桁境目では指数化され
ない（第5.1節E3・D4・D5参照）。** 倍精度自身の大きい側の境目は、`l4-s4f`
（候補`LG16`が`unique_survivor`）で確定した。値を有効16桁に丸めて末尾0を
落とし、`v = d.ddd... × 10^E`（`E≥0`）の形にすると、

> **`E < 16`（整数部が16桁以下）なら固定表記、`E ≥ 16`（17桁以上）なら
> 指数表記になる。**

根拠: `l4-s4f-double-large-format-switch-results.md`（`248853c`）、
11腕全てで候補`LG16`だけが`candidate_consistent`（対照`LG15`〔単精度の
「GWより1桁手前」に倣った類推〕は`E=15`〔16桁ちょうど〕の4腕で食い違い、
`candidate_rejected`）。

| 腕 | 打鍵文字列 | 実測の出力 | 桁数/E | 判定 |
|---|---|---|---|---|
| W2（`l4-s4a`） | `print 1d10` | `10000000000` | 11桁、E=10 | 固定 |
| W3（`l4-s4a`） | `print 12345678901234#` | `12345678901234` | 14桁、E=13 | 固定 |
| G1（`l4-s4f`） | `print 123456789012345#` | `123456789012345` | 15桁、E=14 | 固定 |
| G8（`l4-s4f`） | `print 123456789012345.6#` | `123456789012345.6` | 16有効桁、E=14 | 固定 |
| G3（`l4-s4f`） | `print 1234567890123456#` | `1234567890123456` | 16桁、E=15 | 固定（`E<16`ぎりぎり） |
| G5（`l4-s4f`） | `print 1d15` | `1000000000000000` | 16桁、E=15 | 固定（`E<16`ぎりぎり） |
| C2（`l4-s4b`） | `print 1d16` | `1D+16` | 17桁相当、E=16 | 指数（`E≥16`） |
| C3（`l4-s4b`） | `print 1d17` | `1D+17` | 18桁相当、E=17 | 指数 |
| G9（`l4-s4f`） | `print 1d15*10` | `1D+16` | 演算結果17桁相当、E=16 | 指数（`E≥16`） |
| G10（`l4-s4f`） | `print 99999999999999995#` | `1D+17` | 丸めで18桁相当、E=17 | 指数 |
| C4（`l4-s4b`） | `print 12345678901234567#` | `1.234567890123457D+16` | 17桁の定数が16桁に丸め、E=16 | 指数 |

**境目の例**: `1234567890123456#`（G3）・`1d15`（G5）はいずれも整数部
16桁ちょうど（`E=15`）で固定表記のままだが、`1d15*10`（G9、10^16＝17桁
相当）は`E=16`になったとたん指数表記（`1D+16`）に切り替わる。単精度で
見られた「GWの境目より1桁手前で切り替わる」という類推（対照`LG15`、
`E<15`）は、G3・G4・G5・G11（いずれも16桁ちょうど）が固定表記のままだった
ことで`l4-s4f`では支持されなかった。

### 5.5 小さい側（`|v|<1`）: 固定⇔指数表記の切替

**単精度は、`LEN7`規則が唯一の生き残り候補として確定した。** 根拠:
`l4-s4c-small-value-format-switch-results.md`、single_small群13腕
（K1〜K13）全てで候補`LEN7`だけが実測と一致（`unique_survivor`）。

`LEN7`の定義（`l4-s4c-small-value-format-switch-preregistration.md`）:
値を単精度の有効桁数（6桁）に丸めて末尾0を落とし、固定表記にしたときの
小数点より右の文字数（先頭の0を含む、符号は数えない）が**7以下なら固定
表記、8以上なら指数表記**にする。

| 腕 | 打鍵文字列 | 実測の出力 | 固定表記の小数点右の文字数 |
|---|---|---|---|
| K3 | `print 1.5e-6` | `.0000015` | 7（固定） |
| K6 | `print 1.23456e-2` | `.0123456` | 7（固定） |
| K8 | `print 1.2345e-3` | `.0012345` | 7（固定） |
| K9 | `print 1.2e-6` | `.0000012` | 7（固定） |
| K10 | `print -1e-7` | `-.0000001` | 7（固定、符号は数えない） |
| K1 | `print 1e-8` | `1E-08` | 8（指数） |
| K4 | `print 1.5e-7` | `1.5E-07` | 8（指数） |
| K5 | `print 1.23e-6` | `1.23E-06` | 8（指数） |
| K7 | `print 1.23456e-3` | `1.23456E-03` | 8（指数） |
| K11 | `print -1.5e-7` | `-1.5E-07` | 8（指数、符号は数えない） |
| K12 | `print 1/3000` | `3.33333E-04` | 演算結果を丸めると8（指数） |
| K2 | `print 1e-9` | `1E-09` | 9（指数） |
| K13 | `print 1/300000` | `3.33333E-06` | 指数（K12と同じ理由） |

**単精度の観測の範囲では、後述（倍精度側）の`k≤1`・`k≤14`という2つの
例外条件は`LEN7`と区別できない（推定、判定には使わない）。** 単精度は
有効桁数`s`が最大6なので、`k≤1`のときは必ず`k+s≤1+6=7`となり`LEN7`の
固定条件（小数点右の文字数`k+s≤7`）をすでに満たす。逆に`k≥7`のときは
`s≥1`なので必ず`k+s≥8`となり、`LEN7`だけで指数表記と判定できる。
つまり単精度の腕（`k`が1〜9程度の範囲）では、「`k≤1`なら常に固定」と
いう例外規則を別立てにしても、しなくても同じ判定結果になり、今回の
観測（K1〜K13）からはどちらの形が実装の規則かを区別できない。単精度・
倍精度を1本の統一規則（下記`RSTAR`のような形）で書けるかどうかは推定で
あり、本節では単精度は`LEN7`のまま、倍精度は別に`RSTAR`として書く
（統一するかどうかの判断は推定の範囲に留め、根拠にしない）。

**倍精度は、`l4-s4c`・`l4-s4d`で候補`S0`・`LEN16`・`LE17`・`LE18`が
いずれも`no_survivor`だった後、`l4-s4e`で新しい候補`RSTAR`が
`unique_survivor`として確定した。** 根拠: `l4-s4e-double-small-format-switch-results.md`
（`4dda102`）、k1_long群5腕・k15_short群4腕・mid_len16群3腕・
mid_len17群2腕の全14腕で`RSTAR`だけが`candidate_consistent`（対照
`RSTAR_B`は4腕で食い違い）。`l4-s4d`（`1e91c83`、追補`e80a55b`で写し
時刻を延長・関門G8を新設）は候補`LE17`・`LE18`がいずれも`no_survivor`
だった（下記「測定の経緯」段落参照）。

`RSTAR`の定義（`l4-s4e-double-small-value-format-switch-preregistration.md`）:
値を倍精度の有効桁数（16桁）に丸めて末尾0を落とし、
`v = d.ddd... × 10^E`（`E<0`）の形にする。`k = -E-1`（小数点直後の0の
個数）、`s`=丸め後の有効桁数とすると、

> **`k≤1`（`|v|≥0.01`）なら常に固定表記。そうでなければ`k+s≤16`かつ
> `k≤14`のとき固定表記、それ以外は指数表記。**

`1.23456789012345d-3`（M2、`k=2`）は`k`が1を超えたとたん`k+s=17`が
`k+s≤16`を満たさず指数表記になる（`k=1`と`k=2`の差）。同様に
`1.5d-15`（L3、`k=14`）は`k≤14`ぎりぎりで固定表記だが、`2d-16`（Q6、
`k=15`）は`k+s=16`自体は`≤16`を満たすのに`k>14`のため指数表記になる
（`k=14`と`15`の差）。この2組は、`RSTAR`が単なる「`k+s≤16`なら固定」
（対照`GW16`、第5.7節）では説明できない2つの例外条件をどちらも要求
することを直接示す腕である。

**測定の経緯（`l4-s4d`、写しの時刻）**: `l4-s4d`の本測定は、最初
`l4-s4a`〜`l4-s4c`と同じ写し(後)取得タイミング（`dump=line_end+20`）で
試みたところ、桁数の多い3腕（M1・M5・M10）で出力行の描画がまだ完了して
おらず、`Ok`行との区別がつかない状態のまま`cells`が0件として記録された。
この状態は各腕2走とも同じ位置で切れて再現し、関門G3（決定論性）を素通り
してしまう——「決定論的に再現する」ことと「測定が完了している」ことは
別であり、G3だけでは早すぎた写しを検出できない。この事実に気づいた時点で
測定を止め、写し(後)の時刻を全腕一律で`dump=line_end+300`に延長し、
出力行の後に`Ok`行が現れていることを確認する関門G8（出力完了の確認）を
追補（`e80a55b`）で新設したうえで再測定した（`l4-s4d-double-small-format-switch-results.md`
「経緯（写しが早すぎた走）」節）。`l4-s4e`はこのG8を最初から適用して
測定している。

### 5.6 誤りの形（範囲外・0除算）

**範囲外の値・0除算は、出力が2行にわたる。他の30腕（数値出力）は出力1行
（`Ok`行が相対行+2）だが、この2腕だけ`Ok`行が相対行+3になる。**
根拠: `l4-s4a-float-print-results.md`「原点」節。

| 腕 | 打鍵文字列 | 分類 | `Ok`行の相対位置 |
|---|---|---|---|
| X1 | `print 1e38*10` | `non_numeric_output` | 相対行+3（出力2行） |
| X2 | `print 1/0` | `non_numeric_output` | 相対行+3（出力2行） |

X1・X2は事前登録どおり件数と位置の範囲だけを記録の対象とし、値・文字コード
そのものは記録していない（禁止事項7、エラーメッセージはROMのデータに
あたる）。この2腕の出力の文言そのものは第7.1節（資料の記載）の対応表を
参照する（測定では確かめていない、第10節）。

### 5.7 GW-BASICとの違い（参考）

予測器（`tools/l4_mbf_oracle.py`・`tools/l4_mbf_oracle_v2.py`）は本書の判定
根拠にしていないが、参考として次の違いに触れる。GW-BASICは単精度の有効桁を
7桁として丸めるのに対し、N88（本測定の対象）は**6桁**で丸める、という違いが
観測（第5.3節・第5.4節、D1〜D3・E2・`l4-s4b`のH6確認）から見えている。この
違いはl4-s4aのD1〜D3・E2が「予測（GW-BASIC相当）より有効桁が1桁少ない」形で
食い違ったことが出発点であり（`l4-s4a-float-print-results.md`「食い違った腕の
形」節）、判定そのものはl4-s4b（新しい23腕、`h6_digits_only`）による直接確認で
確定させている。この小節はGW-BASICとの比較という位置づけの補足であり、判定の
根拠には使っていない。

**小さい側（`|v|<1`）の固定⇔指数の切替も、GW-BASICとN88で形が違う。**
GW-BASICのMIT公開ソースだけから導出した判定規則（分析ノート
`docs/notes/l4-gwbasic-fofmt-analysis.md`。**中身・導出過程は本節では
読まない・触らない**、結論の式だけをこの依頼文の引用として書く）は、
`k+s≤N`（`N`は単精度7・倍精度16）なら固定表記という単純な1本の式に
なる。これに対しN88は、単精度側は出力の有効桁が6桁であるにもかかわらず
小さい側の固定判定の閾値は`LEN7`（`k+s≤7`、第5.5節）で出力桁数と1ずれて
おり、倍精度側は`RSTAR`（`k≤1`・`k≤14`という2つの例外条件、第5.5節）を
持つ点で、GW-BASICの単純な`k+s≤N`規則（対照`GW16`、`l4-s4e`で14腕中9腕
が食い違い）とは異なる。この対比はGW-BASICとの比較という位置づけの補足
であり、判定の根拠には使っていない（判定根拠は第5.5節の`l4-s4c`・
`l4-s4d`・`l4-s4e`の測定）。

**大きい側（`|v|≥1`）は、倍精度はGW-BASICと同じ境目、単精度だけが
GWより1桁手前で切り替わる。** `l4-s4f`（候補`LG16`が`unique_survivor`、
第5.4節）で、倍精度の大きい側の境目はGW-BASIC由来の規則そのもの
（`E<16`なら固定）と一致した。対照候補`LG15`（単精度の「GWより1桁手前」
という類推をそのまま倍精度に当てはめた形、`E<15`）は`E=15`の4腕
（G3・G4・G5・G11）で食い違い、`candidate_rejected`だった。単精度・
倍精度×大きい側・小さい側の4通りをまとめると次のとおりになる。

| | 大きい側（`\|v\|≥1`） | 小さい側（`\|v\|<1`） |
|---|---|---|
| 単精度 | 出力有効桁6桁で切替（GWは7桁、1桁手前。第5.4節） | `LEN7`＝`k+s≤7`（GWの`k+s≤7`基準と数値上は同じ式だが、出力桁数〔6〕とは1ずれる。第5.5節） |
| 倍精度 | `E<16`（GW-BASICの規則そのもの。第5.4節） | `RSTAR`＝`k≤1`または（`k+s≤16`かつ`k≤14`）。GWの単純な`k+s≤16`（`GW16`）とは異なる例外を持つ（第5.5節） |

倍精度は大きい側だけGW-BASICと一致し、小さい側は独自の例外（`k≤1`・
`k≤14`）を持つ。単精度は大きい側でGWより1桁手前（6桁）に切り替わるが、
小さい側の`LEN7`はGWの`k+s≤7`と数値としては同じ式になっている（ただし
これは出力桁数6との単純な対応ではない）。この対比はGW-BASICとの比較と
いう位置づけの補足であり、判定の根拠には使っていない。

**丸めの半端（ちょうど半分になる値の丸め方向）も、単精度・倍精度とも
GW-BASICの`$FOUT`手順と一致した。** `l4-s4g`（第5.3節）で単精度の丸め
半端が`GW`（半分は常に絶対値の大きい側へ切り上げ、偶数丸めではない）と
一致し、`l4-s4h`（第5.3節）で倍精度でも同じ`GW`が`unique_survivor`に
なったのは、いずれもGW-BASICの`$FOUT`の手順（`docs/notes/l4-mbf-oracle.md`
・`docs/notes/l4-gwbasic-fofmt-analysis.md`の記載どおり「0.5を足して
切り捨て」）と同じ形である。この対比はGW-BASICとの比較という位置づけの
補足であり、判定の根拠には使っていない（判定根拠は第5.3節の`l4-s4g`・
`l4-s4h`の測定）。

**単精度の定数の読み取り（FIN、第5.1.1節）も、GW-BASICの手順を手がかりに
した推定でしか説明できていない。** GW-BASICの`$FIN`は、積み上げた整数を
倍精度にしたあと倍精度の10のべき乗を**1回**掛ける・割る作りだが、N88の
実測（`l4-s4i`・`l4-s4j`）はこれに合わない。GW-BASICの`$DIV10`（10で割る
操作）は単精度に丸めた`0.1`を掛ける作りになっている（出所:
`docs/notes/l4-fin-model-search.md`。**中身は本節では読まない・触らない**、
結論だけを参考にする）。第5.1.1節の`REP01`（「÷10」を「単精度に丸めた
`0.1`を掛ける」で行う）は、この`$DIV10`の作りを手がかりにした推定であり、
判定の根拠には使っていない（実装はユーザー判断により`REP01`を採用して
いるが、これはGW-BASICとの比較からの類推であって測定による確定ではない）。

**倍精度の定数の読み取り（FIN、第5.1.2節）は、GW-BASICの`$FIN`の倍精度
経路とは合わない。** GW-BASICの`$FIN`は、倍精度の10のべき乗の表を**1回**
掛ける・割る作りだが、`l4-s4k`・`l4-s4l`の実測（第5.1.2節）はこの1回
操作の予測（`DEXACT`・`DGW`）に合わない。単精度の`$DIV10`は単精度に
丸めた`0.1`を掛ける作りだったのに対し、**倍精度の実測は「10で本当に
割る」操作の反復（`DREP10A`）に合う**——単精度と倍精度で「10で割る」の
実装のされ方が違うという非対称な形になっている。この対比はGW-BASICとの
比較という位置づけの補足であり、判定の根拠には使っていない（判定根拠は
第5.1.2節の`l4-s4k`・`l4-s4l`の測定）。

## 6. 観測 — 構文の誤り

**構文の誤りがあると、出力の行（相対+1）の1行だけが変わる。`Ok`の行位置は
ずれない。** 根拠: `l4-s3a-print-format-results.md` Q5。`print 1+`（末尾が
式として不完全）の腕で、走行前後の非空白セル件数を比較したところ:

| 相対行 | 変化前(非空白件数) | 変化後(非空白件数) | 位置範囲(列) |
|---|---|---|---|
| 0(打った行) | 0 | 7 | 0-7 |
| +1(エラー表示行) | 0 | 15 | 0-15 |
| +2(`Ok`の行) | 0 | 3 | 0-2 |

相対行0の非空白7件は打鍵エコー（`print 1+`、空白1文字を除く7文字）と一致する
件数。エラー表示は相対行+1の1行だけに現れ、非空白セル15件・列範囲0〜15
（16列ぶん）。相対行+2は他の腕と同じ`Ok`の並び（非空白3件、列0-2）のまま
だった。**エラーメッセージの文言・文字コードは禁止事項7（ROMのデータテーブル
にあたる）により本測定では一切扱っていない**ため、この節に載せたのは行数・
件数・位置範囲だけである。

## 7. 資料の記載 — PRINT/LPRINTの言語仕様（マニュアル、参考）

以下はマニュアル `refs/manual_squashed.txt` 2-183（PRINT/LPRINTの項の本文）の
記載であり、**判定の根拠にはしていない**（測定と一致した部分のみ、第2〜4節の
観測として別途確認済み）。資料の記載として位置づけを補足するために引用する。

- 区切り記号としてセミコロン(`;`)を使うと、直前に出力したものの直後に続けて
  次の値を出力する。
- `PRINT`で値を出力する領域は、あらかじめ各行が14文字ごとに分割されている。
  区切り記号としてコンマ(`,`)を使うと、この領域ごとに出力が行われる。
- 式の最後にセミコロン・コンマを付けると改行動作を起こさない。
- 数値を出力した場合、その後ろには1文字の空白が挿入される。また、数値の前
  には符号のための桁を確保する（正の数のとき空白、負の数のとき`-`となる）。

## 9. 材料どうしの食い違い

- **判定名と記述の区別（本書内では発生していない）。** `l4-s3a-print-format-results.md`
  はQ1の後置空白を「間接確認」、Q2の前後の空白の無さを「間接確認」、Q3の末尾
  区切りの改行抑止効果を「未確認」と明記しており、本書もその区別をそのまま
  引き継いだ（第2〜4節の記述参照）。判定名がある項目（`sign_space_before`・
  `no_suppress`・`suppresses_between`・`newline_not_suppressed`・`zone_14`）と、
  記述のみの項目（後置空白・文字列前後の空白の間接確認、改行抑止効果の
  未確認）を混同しない。
- **測定と資料の一致・不一致（整数・区切り記号）。** 第2節（整数の前後の空白）・
  第4節（`;`の文字列隣接効果、`,`のゾーン幅14）は、いずれも第7節の資料の記載
  と一致した（資料の記載は測定によって独立に裏づけられた形になる）。資料は
  「数値の後ろに1文字の空白が挿入される」と正負を区別せず断定しており、
  `l4-s3a`の時点では**正の数のみ間接確認・負の数は未確認**で資料の断定を
  そのまま観測として採ってはいなかったが、`l4-s3b`で負の数（P1Q-m5・
  P1Q-m32768）を直接確認した結果、資料の記載と一致した（第2節参照、
  測定>資料の原則。一致は`l4-s3b`の測定によるものであり、資料を根拠にして
  いない）。同様に、資料の「式の最後にセミコロン・コンマを付けると改行動作
  を起こさない」も、`l4-s3a`時点では`Ok`の改行に隠れて未確認だったが、
  `l4-s3b`のQ2・Q3（第4節）で直接確認し、資料の記載と一致した。
- **測定と資料の食い違い（整数演算の範囲外→Overflow、第3版で追加）。**
  第7.1.1節の資料の記載「整数演算の結果や整数型変数への代入値が−32768〜32767

## 10. 未確定（材料に無いため、この版では埋めない）

以下は次の測定・段階で扱う。**推測で埋めない。**

1. 構文の誤りのメッセージの文言そのものは、開発者判断により第7.1節の
   マニュアルのエラーメッセージ一覧から採ることに決めた（禁止事項7により
   測定では扱わない、第6節）。**未確定として残るのは、この一覧の文言が
   実機・エミュレータの実際の画面表示と一致するかどうかの確認だけ**
   （本版では未実施）。範囲外（Overflow相当）は第5.2節・第7.1.1節のとおり
   エラーにすらならないことが確定しているため、この項の対象から除く。
2. **数値定数の桁数の数え方（第5.1節、第3.1版で追加）。** 小数点の左右に
   ある先頭の0（例: `.000015`の`0000`、`0.25`の先頭`0`）を単精度/倍精度を
   分ける桁数に含めるかどうかは観測していない。E3・D4・D5（8桁以上として
   倍精度になった腕）はいずれも先頭0を含まない定数だった。
3. **`E`指数付きで仮数部が8桁以上の定数の型（第5.1節、第3.1版で追加）。**
   例えば`1.2345678e-2`のように、指数記号を使いながら仮数部の数字が8桁
   以上になる定数が単精度・倍精度のどちらになるかは観測していない。今回の
   腕は「仮数部が7桁以内で`e`/`E`を使う」腕（E4・S4等）と「指数記号を
   使わない素の整数・小数で8桁以上」の腕（E3・D4・D5）に分かれており、
   両方が重なる腕が無い。
4. **単精度、大きい側の指数表記への切替の境目ちょうどの値。** 第5.4節、
   6桁境目そのものは`l4-s4b`で確定したが（`h6_digits_only`）、境目
   ちょうどの値（丸めで6桁になるかならないかの境界ケース）を網羅的には
   突いていない。倍精度の大きい側の境目は`l4-s4f`（`E<16`、`LG16`が
   `unique_survivor`）で確定した（第5.4節）ため、この項からは外した。
5. **範囲外・0除算（第5.6節）のあとに出力される値の形。** 禁止事項7により
   本文（エラーメッセージ・付随する数値表示があるかどうか）を測定で扱って
   いないため、出力が2行にわたるという行数・件数・範囲の事実以外は未観測。
6. **単精度・倍精度とも、定数の読み取り（FIN）で推定規則に合わない
   腕・未検証の部分が残る（第5.1.1節・第5.1.2節、第3.6版・第3.7版で
   更新）。**
   - 単精度: J17（`print -5.17e+5-93.6e+10`）・J20
     （`print 8.418484e+11-784.e+4`）は`REP01`の予測と食い違う
     （`93.6e+10`・`8.418484e+11`の読み取りが1ビット違う）。実装は
     ユーザー判断により`REP01`（57件中55件を再現）で先へ進んでいるが、
     この2件を説明する規則は見つかっていない。
   - 倍精度: `DREP10A`を前向きに全腕一致させた測定は無い。`l4-s4l`は
     `no_survivor`（判定名としては`DREP10A`も`candidate_rejected`）で、
     L9〜L12（4腕、`#`と`e`指数の組み合わせ、下記参照）が数値を出力
     しなかったことが直接の理由。`l4-s4k`の36件を`DREP10A`が再現する
     のは事後の当てはめ（`docs/notes/l4-dfin-model-search.md`）であり、
     前向きに検証する新しい測定は行っていない。実装はユーザー判断により
     `DREP10A`で先へ進んでいる。
   - `e`指数の後ろに`#`を付けた定数（例: L9`print -962467.4715e+15#+962467471500000002048`、
     第5.1節）が数値を出力しなかった理由（構文の誤りか、別の解釈か）は
     未確定。禁止事項7によりエラーメッセージの内容を測定で扱っていない
     ため、件数・位置の範囲以外は分からない。
7. **二進浮動小数点演算の最終ビットの精度差。** `PRINT`は単精度6桁・倍精度
   16桁にしか丸めて表示しないため、それより細かい桁（実装の丸め処理や
   ビット表現そのものの違い）が結果に現れるかどうかは、直接モードPRINTの
   観測だけでは分からない（R1・R2〔第5.1節との関連では誤差の見え方〕は
   いずれも見える範囲では予測と一致したが、これは「6桁の範囲内で一致した」
   という意味にとどまる）。
8. `PRINT`以外の命令（構文・書式とも本書の対象外）。
