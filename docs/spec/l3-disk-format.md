# L3 ディスク形式（公式形式の媒体）— 仕様書

第1版（2026-09-24）

## 0. この仕様書の位置づけ

自作ROM の `FILES`・`LOAD`・`SAVE` が**既存の N88-BASIC 形式の媒体**を扱えるように、
媒体上のデータの置き方を記す。2026-09-24、利用者の判断により「公式のディスク形式を扱う。
その形式は第三者の解析を読まず、自分で測る」と決めた（`docs/notes/m6f-a-directory-by-save-diff-preregistration.md` §0）。

**すべての項目は、公式ROM に自分の入力（自作プログラム・自分で決めたファイル名）を与え、
参照 diskA の使い捨て複製の前後の差分から導出した。** 変わっていないバイト（公式ディスクの
既存の中身）は読んでいない。古い値は、セクタ内で一様かつ8個以上のときだけ使った
（境界の規則は `m6f-a` 事前登録 §1・追補2）。

**公式ディスク固有の事柄は書かない**（既存ファイルの数、空きの状況、割り当て番号の具体値）。

対象は 2D（40 シリンダ・2 ヘッド・16 セクタ／トラック・256 バイト／セクタ）の媒体である。

## 1. ディレクトリ

### 1.1 所在

**(C=18, H=1, R=3) はディレクトリのセクタである。**
（`m6f-a` の導出 D1。F1・F2・F3 のすべてで変わり、F1 と F2 の新しい値の違いが1バイト
だけのセクタがここだけだった。`m6f-b` の関門 G8 で再確認。）

**未確定:** ディレクトリが (18,1,3) 以外のどのセクタまで続くか。

### 1.2 エントリ

| 項目 | 値 | 根拠 |
|---|---|---|
| エントリ長 | **16 バイト** | m6f-b E3（2件の名前の位置の差） |
| 名前欄の位置 | エントリの**先頭**から | m6f-b E2 |
| 名前欄の長さ | **9 バイト** | m6f-b E4（4文字名と6文字名で、名前＋詰め物の長さが同じ） |
| 名前の詰め物 | **`0x20`**（空白） | m6f-b E4 |
| 名前欄の直後の1バイト | プログラム（`SAVE`）**`0x80`**、データファイル（`OPEN … FOR OUTPUT`）**`0x00`** | m6f-b E8 |
| 削除されたエントリ | 先頭1バイトが **`0x00`**（残りは削除前のまま） | m6f-b E5 |
| 未使用のエントリ | **`0xFF`** で埋まっている | m6f-b E6 |

**未確定:** 名前欄の直後の1バイトより後ろの欄の意味（割り当てに関わるとみられる
バイトがあるが、意味は決めていない）。9バイトの名前欄が「名前＋拡張子」のように
分かれるかどうか。

### 1.3 名前の大文字・小文字

**ROM はファイル名を与えられたとおりに格納する。** 大文字の符号で与えれば大文字、
小文字の符号で与えれば小文字のまま入る（m6f-b E1 `case_stored_as_given`）。

**未確定:** 名前を探すとき（`LOAD`・`KILL` 等）に大文字・小文字を区別するか。

## 2. 割り当て表

**(18,1,14)・(18,1,15)・(18,1,16) の3セクタは、ファイルの作成に伴って3つとも同じ位置が
同じ値に変わる**（m6f-b E7。本体の中身を変えた3腕で変化が完全に一致し、大きいファイルで
より多く変わった）。

**未確定:** 中身の意味（どのバイトがどの割り当て単位に当たるか、空き・終端の印）。
3セクタが複製なのか別の役割なのか。差分からは古い値が伏せられるので読めない。
空の媒体を自作するときに**挙動から再構成する**（`docs/PLAN.md` 5節）。
