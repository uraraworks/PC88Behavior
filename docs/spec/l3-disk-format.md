# L3 ディスク形式（公式形式の媒体）— 仕様書

第2版（2026-09-25）

## 0. この仕様書の位置づけ

自作ROM の `FILES`・`LOAD`・`SAVE` が**既存の N88-BASIC 形式の媒体**を扱えるように、
媒体上のデータの置き方を記す。2026-09-24、利用者の判断により「公式のディスク形式を扱う。
その形式は第三者の解析を読まず、自分で測る」と決めた（`docs/notes/m6f-a-directory-by-save-diff-preregistration.md` §0）。

**第1版の項目は、公式ROM に自分の入力（自作プログラム・自分で決めたファイル名）を与え、
参照 diskA の使い捨て複製の前後の差分から導出した。** 第2版で足した項目は、**自作の生成器で
作った空の媒体**を公式ROM にドライブ2で使わせ、その挙動と測定後の媒体から導出した（`m6f-c`）。 変わっていないバイト（公式ディスクの
既存の中身）は読んでいない。古い値は、セクタ内で一様かつ8個以上のときだけ使った
（境界の規則は `m6f-a` 事前登録 §1・追補2）。

**公式ディスク固有の事柄は書かない**（既存ファイルの数、空きの状況、割り当て番号の具体値）。

対象は 2D（40 シリンダ・2 ヘッド・16 セクタ／トラック・256 バイト／セクタ）の媒体である。

## 1. ディレクトリ

### 1.1 所在

**ディレクトリは (C=18, H=1, R=1) の先頭から始まる。** 空の媒体に最初に作ったファイルの
エントリは (18,1,1) の先頭に入る（`m6f-c` C8）。
**(18,1,3) もディレクトリのセクタである**（`m6f-a` D1、`m6f-b` G8）。

空の媒体にファイルを作り続けると、エントリは (18,1,1) から順に (18,1,11) まで入った
（`m6f-c` A5。単位が尽きて止まったので、これは下限である）。

**未確定:** ディレクトリがどこまで続くか（(18,1,11) までは確か。(18,1,12) まで続く手がかりが
ある — `m6f-c` A6）。

### 1.2 エントリ

| 項目 | 値 | 根拠 |
|---|---|---|
| エントリ長 | **16 バイト** | m6f-b E3（2件の名前の位置の差） |
| 名前欄の位置 | エントリの**先頭**から | m6f-b E2 |
| 名前欄の長さ | **9 バイト** | m6f-b E4（4文字名と6文字名で、名前＋詰め物の長さが同じ） |
| 名前の詰め物 | **`0x20`**（空白） | m6f-b E4 |
| 名前欄の直後の1バイト | プログラム（`SAVE`）**`0x80`**、データファイル（`OPEN … FOR OUTPUT`）**`0x00`** | m6f-b E8 |
| 削除されたエントリ | 先頭1バイトが **`0x00`**（残りは削除前のまま） | m6f-b E5 |
| 未使用のエントリ | **`0xFF`** で埋まっている | m6f-b E6 |

**未確定:** 名前欄の直後の1バイトより後ろの欄の意味（割り当てに関わるとみられる
バイトがあるが、意味は決めていない）。9バイトの名前欄が「名前＋拡張子」のように
分かれるかどうか。

### 1.3 名前の大文字・小文字

**ROM はファイル名を与えられたとおりに格納する。** 大文字の符号で与えれば大文字、
小文字の符号で与えれば小文字のまま入る（m6f-b E1 `case_stored_as_given`）。

**未確定:** 名前を探すとき（`LOAD`・`KILL` 等）に大文字・小文字を区別するか。

### 1.4 空きのエントリの使い方

削除したエントリの枠は、次にファイルを作るときに使い直される（`m6f-c` A5b。作ってすぐ
`KILL` を 400 回繰り返し、毎回同じ枠を使った）。

## 2. 割り当て表

**(18,1,14)・(18,1,15)・(18,1,16) の3セクタは、ファイルの作成に伴って3つとも同じ位置が
同じ値に変わる**（m6f-b E7。本体の中身を変えた3腕で変化が完全に一致し、大きいファイルで
より多く変わった）。

自作の空の媒体でも、3セクタは**変わった位置と新しい値がまったく同じ**だった（`m6f-c` C3）。

### 2.1 空きの印

**割り当て表の値 `0xFF` は「空き」である。** 3セクタの全バイトを同じ値 V にした空の媒体で
ファイルを作れたのは V=`0xFF` のときだけで、他の 255 値では `Disk full`（ERR 68）になった
（`m6f-c` C1、全値掃引）。

### 2.2 割り当て単位に対応しない位置

**割り当て表の位置 160 以降は、割り当て単位に対応しない。** 2D の媒体では単位は 160 個
（下の観察）。ROM はファイルを書くときに位置 160 以降へ**不定の値**を書くことがある
（`m6f-c` §4）。**読む側はこの範囲の値を意味のあるものとして扱ってはならない。**
（その値は記録していない。`docs/notes/contamination-2026-09-25-fat-buffer-overrun-values.md`）

### 2.3 未確定（`m6f-c` §5 の事後の観察。次稿 `m6f-d` で導出する）

- 割り当て単位は 8 セクタ（半トラック）。番号 k の単位は、線形番号
  L = (C×2+H)×16+(R−1) が 8k〜8k+7 のセクタ。
- 鎖: 単位 k の値は、ファイルの次の単位の番号。最後の単位は 0xC0 台の値（規則は未確定）。
- エントリの 10 バイト目（0 始まり）が、ファイルの最初の単位の番号。
- 空の媒体では、ROM は単位 72（(18,0,1〜8)）から番号の小さい方へ割り当てた。
  トラック18の単位（72〜75）を「使用中」にする印が要るかどうかは未確定。

## 3. 媒体の書き込み禁止の印

**(18,1,13) は、媒体の書き込み禁止を決めるセクタである。** 空の媒体で (18,1,13) の全バイトを
同じ値 W にしたとき、書き込みが `File write protected`（ERR 61）にならないのは、**W の 0x10 の
ビットが 0 のとき**だった（`m6f-c` 追補3、全値掃引）。(18,1,1) の値では変わらない。
D88 ヘッダの書き込み保護とは別の、媒体の中身による印である。

**書き込めるデータディスクを作るときは、(18,1,13) を全バイト 0x00 にすれば足りる**
（`m6f-c` 本測定6回目の媒体）。

**未確定:** (18,1,13) のどのバイトが印か。(18,1,13) の他の役割。

## 4. 空のデータディスクの作り方（ドライブ2で受け入れを確かめたもの）

次の規則だけで作った 2D の媒体は、公式ROM がドライブ2で `FILES`・`OPEN`（書き込み・読み込み）・
`SAVE`・`LOAD` を行えた（`m6f-c` C2 `accepted`）:

- 割り当て表の3セクタ (18,1,14)・(18,1,15)・(18,1,16): 全バイト `0xFF`。
- (18,1,13): 全バイト `0x00`。
- それ以外の全セクタ: 全バイト `0xFF`（ディレクトリは全エントリ未使用になる）。

**この媒体から起動することはできない。** 起動用セクタ (0,0,1) の中身によっては BASIC まで
届くが、ディスクを使わない BASIC として立ち上がる（`m6f-c` 追補1・本測定3回目）。
起動できる媒体の作り方は未確定。

**注意:** この媒体では、トラック18のヘッド0（単位 72・73）もファイルに割り当てられる。
ディレクトリ・割り当て表のあるヘッド1（単位 74・75）を空きのままにしておいてよいかは
未確定（2.3）。
