## 0. 位置づけ

ゴール B の入口番地を、ゲーム実走による需要と自作プローブによる働きに分ける。測定 ID は結果ノートの定義に従う。観測の範囲外と推定は実装の確定要件にしない。第5版の追加は G5/G2 実走の観測による。プローブ確認は B88 追補3・B86 追補11 で行う。本人の2026-11-12の判断「実装は Codex に投げてOK」により、プローブ確認より先に実装に入る。自作 main ROM では需要のある番地に入口を置く必要がある。既に浮動小数点処理などがその番地を占める場合は、その処理を退かす。

### 1.1 369A

- B はシリンダ×2＋面、C は1始まりのセクタ番号、HL は256バイトの読み書き先。キャリー0は読み、1は書き。測定した読みの座標と HL への転送は B86-add1・add2・add3、書きの方向は B86・B86-add1 の送受信量に基づく。書き込み先媒体への格納は未確認。
- ドライブは測定した条件では常にドライブ1。自作の両面40シリンダ媒体で B を振り、他のレジスタも一部振った。RAM 介入は途中までであり、任意の状態でドライブが変わらないことまでは測っていない。
- B=80・FF および C=0 の測定腕では送信6・受信1の別経路となった。エラー応答に見えるが意味と戻り値は未確定。B≥80 全域や他の不正値は未測定。
- 戻り時のフラグ・レジスタ、エラー時の契約、未測定の入力条件は未確定。

### 1.2 37C9・37D2・3847

37C9 は A を要求の先頭バイトとして送り、37D2 は A を引数1バイトとして送る。3847 はサブから1バイト受け取り A に返す。追補5では、自作の `0C` 要求で書いた模様を `09` と4引数の後に3847を256回呼んで読み戻すと、A に引数を入れた腕で256/256一致した。C・E・L に引数を入れた腕では全体一致しなかった。戻り時の他のレジスタ・フラグは未確定。

3847 は割り込み許可（IFF）を変えない。B86 追補11（07ed4b7、公式8/8腕）で、DI で呼んだ腕は IFF=0、EI で呼んだ腕は IFF=1 のまま戻った。追補9の「IFF=0 で戻る」は DI で呼んだ腕の結果だった（訂正）。G5 実走で 3847 の待ちの間に割り込みが 7680 回中 68 回受け付けられたのは、ゲームが EI のまま呼んでいるためと読める。待ちの間の受け付けそのものは、追補11 ではサブの送信遅延が短く観測できなかった。

第1版の37D2「2バイト送る」は訂正する。観測した OUT FD 2件をデータ2バイトと読み違えたもので、ハンドシェイクを含む I/O 件数と送信データ数は同一ではない。37C9 の A=01 でも OUT FD は2回観測された。

追補4では 37C9 の A=00・FF の後、37D2 の1回目が戻らなかった。A=02 では4回戻り、5回目が戻らなかった。要求の引数が揃わないうちに3847を呼んだ測定腕では戻らず、公式環境では約340〜377フレーム後に起動からやり直した。無限に戻らないとまでは断定しない。02→15 の腕で3847が128回戻った後に停止した理由は未確定。

### 1.3 ハンドシェイクとの対応

[l3-subrom 1.10節・1.15節](l3-subrom.md)の手順に照らすと、37C9 の要求先頭と37D2 の各引数は main側 SEND 1バイト、sub側 RECV（1.15節手順1〜7）の実データに対応し、3847 の受信は main側 RECV 1バイト、sub側 SEND（同節手順1〜5）の実データに対応すると推定される。入口ごとにこれらの手順との対応を直接検証したわけではなく、連続転送時の手順や切り替え条件も確定していない。詳細な待ちとフェーズは同節および1.19節を参照する。

### 1.4 3391

呼び出し時の HL が指す番地へ飛ぶ。動作は JP (HL) と同じ形で、I/O はなく、369A が記憶した転送先には依存しない。自作の RET 先では呼び出し元へ戻った。根拠は B86-add7 のHL変更・369A省略腕。追補6では転送先へ進むことまでの観測で、HLと記憶値の区別は追補7で確定した。

### 1.5.1 3080（G5 実走での観測）

B93 の公式 G5 実走 N・SP・RT 腕、F7140〜7600 の呼び出し2169回で、次の規則を観測した。未測定の条件への一般化はしない。

- E6CD=0 のとき、I/O の順序は `OUT E4 → OUT 51 → OUT 50 → OUT 50 → IN 0B〜00（降順）→ OUT E4`。G5 では IN 51 は出ない。E6CD≠0 ではキー処理をせず、IN 0B〜00 も行わず、E6D0+r・E6DC+r・EFF9・EFFF を書かない。
- 入口の OUT E4 は自作の毎フレーム処理の OUT E4 と同じ値。出口の値は入口と bit1・bit2 だけ違う。各位置の値は全回同じ。bit1・bit2 の向きは自作の割り込みレベルの意味から決めるため、ハードウェア資料のポート E4 の説明を参照する。E6C3 には OUT E4 のたびにその値を書く。
- OUT 51 は自作の毎フレームの OUT 51 と bit0 だけ違う。OUT 50 の1回目は自作の画面処理の OUT 50 の2種類の値の一方と同じで、どちらかは未確定（自作の画面処理の文脈から特定する）。2回目は自作の続く OUT 50 と同じ。
- 行 r（00〜0B）について、E6DC+r に前回の E6D0+r を写してから、E6D0+r に `NOT(IN r)` を書く。押されたビットが1になる。EFFF は毎回 00。
- EFF9 は毎回一定値に戻す。押し始めには別の一定値、押し続けには FF を書く。押し始めの一定値、および後述の EFC6・EFC7 に書く値は未確定。自作の既存の値で代用してよい。
- 入口 SP の下に最大10バイトを使い、RET で SP は入口から2増える。A=出口の OUT E4 の値、BC・DE・IX・IY・裏レジスタ・I・IM は不変。IFF=0 で入り、出口で EI して IFF=1 で戻る。HL と F は道筋で変わる。第9版の HL=F000 と F の記述はキーが無い回の観測であり、押し続けの回は HL=E6CF、積んだ回は HL=EFCD となる。

**輪バッファとキーの出来事（B94）**

EFD0 は索引のマスク（輪の大きさは EFD0+1）、EFD1・EFD2 は輪の先頭番地の下位・上位、EFCD は書き索引、EFCE は読み索引、EFCF は1文字の先読み枠（0 は空）である。G5 はこれらの値を RAM に持ち込み、ROM は RAM から読む。

押し始め（前回0で今回1になったキーがある回）の順序は次のとおり。

1. キーの行を走査した直後に EFF9 に押し始めの一定値を書く。
2. EFFB・EFFC にその行の E6DC+r の番地の下位・上位、EFFA に押されたビット、EFFD にキー番号（行×8＋ビット番号）を書く。
3. 残りの行の走査を続け、E6D0+r・E6DC+r・EFFF を更新する。
4. その行の E6DC+r を今回の E6D0+r で上書きする。
5. E6CF にリピートの初期値を入れる。
6. RAM のフック ECDF を呼ぶ。観測1回では A=キー番号、HL=E6DC+r の番地、SP=入口SP−10、IFF=1。G5 のフックは RET で戻る。
7. EFFE に文字コードを書く。
8. EFC6・EFC7 に一定値を書く。ファンクションキー文字列の残りを捨てる働きと推定される。
9. E6CB・E6CC がともに0なら、`i = (EFCD+1) AND EFD0` とし、輪の先頭+i に文字コードを書いてから EFCD に i を書く。どちらかが非0なら積まないが、他の処理は同じ。

押し続けの回は EFF9 に FF を書き、E6CF を1減らす。0 になった回は E6CF をリピート間隔の値に戻し、手順8・9で同じ文字コードを再び積む。押し始めの一定値・EFFA〜EFFE の書き込みと ECDF 呼び出しは行わない。文字コードは自作の INKEY$ と同じで、空白と RETURN を観測した。他のキー・SHIFT・カナは未測定。

リピートはフレーム数ではなく 3080 の呼び出し回数で数える。押し始めを0回目とすると28回目に2文字目を積み、以後4回ごとに積む。自作の既存値では初回30回目、以後4回ごとである。

輪が満杯のとき、複数キーの同時押し、SHIFT・カナ・ファンクションキー（EFC4〜EFC7 の働きを含む）、ECDF 呼び出し時の BC・DE の規則は未確定。

以前のプローブでは IN 51 を観測したほか、割り込み受け口内から JP した一部の試験で戻り、受け口の外では起動をやり直した。別のスタック深さでは時間切れとなり、SP=F000 の試験は戻り先と EFFF が重なって戻りを確認できなかった。これらの条件での完全な契約は未確定。

### 1.5.2 35CE（G5 実走での観測）

G5 は 3080 の後、EFCD≠EFCE または EFCF≠0 のときこの固定入口を呼び、1文字を取り出す。自作では既存の浮動小数点処理と重なるため、固定入口（PINNED_ENTRIES）に追加する必要がある。

- EFCF≠0 なら A に EFCF を返し、EFCF を0にする。輪と EFCE は変えない。
- EFCF=0 なら `i = (EFCE+1) AND EFD0`、A に輪の先頭+i の1バイトを読み、EFCF に0を書いてから EFCE に i を書く。
- 観測した戻りは A=文字、F=00、BC・DE・HL・IX・IY 不変、SP は RET により2増加、IFF=0 のまま。
- 読む RAM は EFCD・EFCE・EFCF・EFD0〜EFD2・輪の1バイト・E6CB・E6CC。E6CB・E6CC の扱いと、空（EFCD=EFCE かつ EFCF=0）で呼ばれた場合は未確定。

### 1.6 7071

**確定した働き（B92b）**

- 7071 は呼出し後に RAM の ED36 を実行し、11DF を4回呼んだ後、同じ SP のまま 6F6B に入る。6F6B の RET で 7071 の呼び元へ戻る。11DF の各回は IN 71 を1回行い、その値を OUT 71 で2回出し、HL は作業域 E60D〜E616 を進む。
- (iii) 6F6B 内の画面モード設定では、自作のカラー・80桁・25行設定と同じ順序で CRTC/DMA 関連ポートを出力する。基準走との比較で、後半の設定列は自作設定と一致した。OUT 30 は E6C0 の bit2〜7 に追随し、bit0〜1 はカラー80x25設定と同じ。OUT 40 は E6C1 に追随し、bit3 は起動時の1回目および最後の OUT 40 と同じ関係になる。OUT 64 の2回はそれぞれ E6C4・E6C5 に追随する。OUT 31 はカラー80x25の値から bit3・bit4 を0にした値。
- (iv) 続いて 6F6B 内でテキスト画面を、自作の `CONSOLE ,,,1`、`WIDTH 80,25`、`CLS` 後と同じ状態にする。ただしファンクションキー行と「Ok」は表示しない。EF86・EF87 にはカーソルのホーム位置（行・桁とも1始まりで1）を書く。
- 公式 G5 実走1回での戻り時レジスタは、A 不変、F は Z・H・P/V=1 で他のフラグと bit5・bit3 は0、BC=0000、DE=FF80、HL=E616、IX・IY 不変。BC・DE・HL は観測1回で、作業域が異なる場合も同じかは未確認。6F6B を直接呼んだ場合の戻り値とは異なる（1.7節）。
- 割り込み禁止（IFF=0）で呼ばれても、割り込み許可（EI）で戻る。観測1回。入口時の IFF=1 の場合の挙動は未確認。

**推定・未確定**

- ED36 から 11DF への詳細な呼び出し構造は未確定。
- EF89 が OUT 30 に影響することは観測したが、規則は未分類。E60E〜E616 等の介入条件で戻らなくなる理由と、EACD=FF の別分岐の働きも未確定。
- 3E0D は IFF=0 のまま戻る。他の単独の働きは未確定。追補12・13の各観測を参照する。

### 1.7 6F6B（G5 実走での観測）

- 画面初期化は 7071 の節の (iii) の OUT 群、テキスト域 F3C8〜FFF7 の消去は同節の (iv) に相当する。
- EF83 前後の作業域に書き込むが、内容は未確定。EF86・EF87 のカーソルのホームが 7071 の節の観測と同じとみてよいかも未確定。
- 途中で EI する。観測では割り込み中に 3080 が5回走った。6F6B 自身は 3391 を呼ばず、割り込み処理が HL=3080 で 3391 を呼んだ。
- ゲームから直接呼んだとき、戻り時は A=00、F は Z・P/V が1で他は0、BC=2000、DE=0400、HL・IX・IY は入口のまま、IFF=1。7071 経由の戻り時の観測値とは異なる。

## 第4版追加の戻り時レジスタ規約

追補9の測定条件で得た規約を示す。入力欄は入口直前の値。369Aの異常条件は C=0 かつ B≥80h。測定していない条件へは一般化しない。

| 入口・条件 | 戻り時の変化・値 | 不変・その他 |
|---|---|---|
| 369A 正常 | A=01h、F=00h（全フラグ0）、DE=入力HL+0100h（書き終わりの次） | HL・BC・IX・IY不変。IFF=0（DIで戻る）。媒体の中身によらない |
| 369A 異常（C=0、B≥80h） | A=01h、F=93h（S・H・N・C=1）、HL=EF60h、DE=入力HL | IFF=0。その他のレジスタはこの異常条件での個別規約を確定していない |
| 3847 | A=受けたバイト | F不変（ZはA=0を反映しない）。他レジスタ不変。IFF は呼ぶ前のまま（追補11で訂正） |
| 37C9 | Fのみ変化。Z・C・P/V・H=0、N=1、Sは入力のまま | 他レジスタ不変 |
| 37D2 | 変化なし | 全レジスタ・フラグ不変 |
| 3391 | 変化なし | レジスタ全部不変。飛び先ではSP=呼び出し直前のSP−2（CALLの戻り番地が積まれたまま飛ぶ） |
| 3080 | AF・HLが変化 | IX・IY・DE・BCは保たれる。出口でEIしてRET。B93 の詳細は1.5.1節 |

369Aの初回160腕ではDE=入力HL+00E0hに見えたが、DEが常にHL+20hだったための交絡である。DEを振った16腕で正常時の DE=入力HL+0100h を確定した。369A異常時および他入口の未記載レジスタについて、結果ノートの条件以上の規約は定めない。

## 2. サブ要求との対応（推定）

369A の読みは送信9・受信258、書きは送信267・受信1であり、[l3-subrom.md](l3-subrom.md) の読み出し準備と256バイト転送、または制御6バイトと256バイトの書き込み・1バイト応答に似る。しかし総件数だけでは要求の分割、見出し、座標の符号化や既存要求との同一性は決まらない。既存要求で表せると確定せず、追加測定を要する。
