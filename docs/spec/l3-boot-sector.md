# L3 起動用セクタの受け渡し — 仕様書

第3版（2026-10-26。第2版 2026-10-25、第1版 2026-10-24）

## 0. この仕様書の位置づけ

自作 ROM が、起動時に**ドライブ1の起動用セクタ (C=0, H=0, R=1) を読んで RAM に置き、制御を渡す**ための
受け渡しを記す。ゴール B（市販ソフト）の最初の需要である（`docs/notes/goal-b-policy-addendum1-boot-sector-2026-10-24.md`）。

- **決めること**: 何を・どこへ読み込むか、制御を渡すときの状態、戻ったときの扱い、戻らないときに要求されること。
- **決めないこと**: 番地の互換（ROM 内部の番地を合わせること）。(0,0,1) の中身による分岐の規則の全体。
  2セクタ目以降を ROM に読ませる手段。
- 媒体の作り方・ディレクトリの規則は [l3-disk-format.md](l3-disk-format.md)。この文書はその媒体の (0,0,1) だけを扱う。
- 書き方は `l1-ipl.md` に倣い、**観測**（測って確かめたこと）と**推定**（観測からの読みで、断定しないこと）を節で分ける。
  実装が従うのは観測の節だけ。推定の節は実装への要求ではない。
- 根拠は `docs/notes/b2-boot-sector-handoff-results.md`（`measurements/b2-*.txt`）、
  `docs/notes/m6f-c-addendum1-boot-sector-sweep.md`（9/24 の掃引）、`docs/notes/m6f-d-addendum1-terminal-and-reserve.md`（D9）。
  刺激はすべて自作（自作のセクタのコード・自作の媒体）。公式ディスクは使っていない。

## 1. 起動時に読むもの（観測）

### 1.1 読み込み

- 読むのは**ドライブ1の (0,0,1) の 256 バイトだけ**。読み込み先は **C000〜C0FF**（観測: 書き込み記録の発行元から
  逆算した読み込み先が全12走で C000）。
- (0,0,2) 以降のセクタ・裏面 (0,1,x) は、C000+256k（k=1..8）の位置に**現れなかった**
  （目印を seq・rev・head1 の3通りで置き、none を対照にした全腕で一致）。入口の DE=C100（2.節）とも整合する。
- 読み込みの前後に ROM は C000〜E5EB を含む広い範囲へ別の書き込みを行う（RAM の初期化と連続しており、
  256 バイトの読み込みだけを範囲として切り出せない）。**C100 以降の RAM の内容は、起動用セクタの読み込み時点では
  何も当てにしてはならない。**

### 1.2 読めなかった・無かったとき

- **ドライブ1にディスクが無い**: 起動用セクタの実行は起きず（C000 の実行が無い）、BASIC へ進む。
  何で「無い」と決めているかは 1.4節（第2版）。
- **(0,0,1) を読めない4形**（セクタ無し・CRC エラー・削除マーク・単密度）: **どれも BASIC まで届かなかった**（`no_basic`。D9）。
  この4形でそのあと何が起きるか（再試行・エラー表示の有無）は測っていない。
- **読めて、中身が戻り命令（`RET` の符号）のとき**: 読み込み後に C000 へ制御が渡り、`RET` で戻って BASIC へ進む（第3節）。

### 1.3 (0,0,1) の中身で行き先が変わること（観測。規則は決まっていない）

9/24 の掃引（(0,0,1) の256バイトを全て値 X で埋める。X=00〜FF）で、BASIC に届いたのは
**X = C0・C9・D0・E0・F0 の5値だけ**。読み込みは (0,0,1) の1回きりで、(0,0,2) は読まれなかった。
残る251値は、247値が約 29 フレームごとに (0,0,1) を読み直し続け（3000 フレームで 102 回）、BASIC に届かなかった。
例外の4値（読み直しが 1・1・11・101 回）はここでは扱わない。
**この表からの帰結を実装に求めない。** 規則の全体は第5節。

### 1.4 起動を試みるかどうかの決め方（観測。第2版）

**main は `IN 40` の bit3 で決める。sub とやり取りする前に決まっている。**

| `IN 40` bit3 | main の振る舞い |
|---|---|
| 0 | 起動を試みる。フレーム 13（[l1-ipl.md](l1-ipl.md) 第7節の 64 件目、P3 の入口）で `OUT FF`（sub との PIO の設定）へ進み、sub に起動用セクタの READ を頼む経路に入る |
| 1 | 起動を試みない。同じ位置で `OUT C1` へ進み、**ポート `FC`〜`FF` を一度も読み書きせず**（sub は1命令も動かない。[l3-subrom.md](l3-subrom.md) 1.1節）、BASIC へ進む |

- 根拠: `docs/notes/b3-boot-decision-results.md`（`measurements/b3-boot-decision.txt`）。分岐点より前の main の IN を
  全ポート・全ビットで比べ、ディスクの有無で値が分かれたのは `IN 40` bit3 だけだった。
- **因果は介入で確かめた**: bit3 だけを強制すると、媒体が無くても試みる側へ、媒体が有っても試みない側へ入れ替わる
  （両方向、各2走）。同じ値で上書きする空の介入では変わらない。媒体が有っても bit3 = 1 なら、(0,0,1) は読まれず
  実行もされず、画面は媒体無しと一致した。**main は FDC などの別の経路で媒体の有無を確かめ直さない。**
- このエミュレータ（QUASI88 libretro 版）では、bit3 は**ドライブ1**に媒体があるとき 0、無いとき 1。
  **ドライブ2だけに媒体があっても 1**（起動を試みない）。
- bit3 の値は走の間で変わらなかった。`IN 40` は分岐点より前に繰り返し読まれる（フレーム 1 から。bit5 = VRTC の待ちと
  同じポート。[l1-ipl.md](l1-ipl.md) 第5a節）。

#### 1.4.1 実装への要求

自作 ROM は、起動用セクタの READ を sub に頼む前に `IN 40` の bit3 を見る。

1. bit3 = 1 なら、sub に何も頼まず（ポート `FC`〜`FF` に触れず）BASIC へ進む。ディスク無しの既存の振る舞いのまま。
2. bit3 = 0 のときだけ、起動用セクタの READ を頼み、第1.1節以降の受け渡しへ進む。

自作 ROM が bit3 を何回目の読みで見るか、VRTC の待ちと兼ねるかは自由（公式でどの読みが決め手かは測っていない。第5節）。

#### 1.4.2 推定・言えないこと（実装への要求ではない）

- 実機で bit3 を作るもの（ディップスイッチか、ディスク装置からの信号か）はこの測定からは言えない。このエミュレータは
  リセット時にドライブ1の媒体の有無から決める作りである（エミュレータのソースによる。公式 ROM の観測ではない）。
- 走の途中で媒体を入れた・抜いたときは測っていない（このエミュレータではリセット時に決まる作りなので、測ってもエミュレータを測ることになる）。
- ディスク装置そのものが無い構成は、このエミュレータで作れず測っていない。

## 2. 制御を渡すときの状態（観測）

C000 の最初の命令が実行される直前の状態。**全12走（6腕×2走。HALT・DI+HALT・RET・目印の置き方違い・目印なしを含む）で
完全に一定**で、腕による差も走による揺れも無かった（`measurements/b2-a1.txt`〜`b2-a6.txt`）。

| 項目 | 値 |
|---|---|
| 入口の番地 | C000（読み込み先の先頭。オフセット 0） |
| AF | 0100 |
| BC | 0001 |
| DE | C100 |
| HL | C000 |
| IX | FFFF |
| IY | FFFF |
| SP | E5F4 |
| 割り込み | 許可（`LD A,I` で IFF2=1） |
| I レジスタ | F3 |

### 2.1 実装への要求

自作 ROM は、起動用セクタのコードへ制御を渡す直前に、**上の表の値を全て同じにする**。
市販ソフトがどのレジスタを当てにするかは測っていないので、一部だけの再現にとどめない
（需要の無い値を省く判断は、需要の観測が出てからにする）。

### 2.2 推定（断定しない。実装への要求ではない）

- **DE = C100**: 読み込み先の終わりの次（C000 + 256）。256 バイトの転送を終えた形に読める。
- **HL = C000**: 読み込み先の先頭に一致する。転送の元または先として使われた残りに読める。
- **BC = 0001、AF の上位 = 01**: 最後に読んだセクタ番号 R=1、または残り数に読める。根拠は薄い。
- IX・IY = FFFF は、この時点で使われていない値と読める。
- I = F3 の意味は第5節。

これらの読みは、実装側が「手前の処理の結果としてこうなる」と作ることを意図している。値を表のとおりに設定すれば足り、
意味の推定が当たっているかは要求に影響しない。

## 3. 戻ったとき

### 3.1 観測

- 入口のスタック（SP=E5F4）の先頭2バイトは**ROM 内の番地 45D9**（全12走で一定）。
  `RET` で戻る腕では、境界の記録の RAM→ROM の飛び込み先に、`DI+HALT` 腕には現れない番地が 21 現れ、
  その中に 45D9（jump 型 1 回）が含まれた。つまり **`RET` は実際にその番地へ戻る**。
- 戻ったあとは BASIC が起動する（第1.2節の `RET` 腕で、BASIC へ進んだ。9/24 の掃引でも同じ）。
  残りの20番地は戻った後の ROM 内の分岐で、受け渡しの一部としては扱わない。
- 戻る前にレジスタ・SP を入口の状態へ戻してから `RET` した（試験コードの仕様）。戻る時点の他の状態が
  どこまで効くかは測っていない。

### 3.2 実装への要求

**`RET` で戻れば BASIC へ進む。** ここまでを要求とする。

**戻り先の番地の値（45D9）そのものを合わせることは要求しない。** 番地は ROM 内部の構造であり、
ゴール B の方針（番地は需要のあったものだけ）に従う。市販ソフトがスタックの先頭2バイトの値に
依存する観測が出たときに、別に事前登録して決める。
自作 ROM は、スタックの先頭に「戻れば BASIC へ進む」番地を積んで制御を渡せばよい。

スタックの先頭2バイトより奥は測っておらず、仕様に含まない（第5節）。

## 4. 戻らないとき（観測）

起動用セクタのコードが戻らずに止まる場合、main CPU がその後に要求するもの（ポート番号・方向・件数のみ）。
プローブの最終書き込みより後のフレームについて。

- **`DI` + `HALT`**: main CPU も sub CPU も入出力は **0 行**。ROM は何も要求しない。
  実装は、DI+HALT のまま止まる起動用セクタに対して**何も出力しなくてよい**。
- **`HALT`（割り込み許可のまま、EI+HALT 相当）**: main CPU は割り込みを約 1163 回（1200 フレーム内）受け、
  割り込みごとに次のポート列を繰り返す。
  - `IN` 0000〜000B（12ポート）、`IN` 0051
  - `OUT` 0031 を2回、`OUT` 0050 を2回、`OUT` 0051 を1回、`OUT` 00E4 を2回
  - ディスク用のポート（FC・FD・FE・FF）は一度も現れない。sub CPU の入出力は 0 行。
  割り込みを許可したまま戻らない起動用セクタは、**ディスクへの要求を続けず、割り込み処理（キー走査と画面・割り込み制御）だけが回る**。
  これらのポートの意味の詳細は `l1-ipl.md` および `l3-*` の他の仕様に委ね、ここでは要求を足さない
  （自作 ROM の既存の割り込み処理が `l1-ipl.md` の規則どおりなら、新たな要求は無い）。

## 5. 決まっていないこと

- **(0,0,1) の中身による分岐の規則の全体。** 第1.3節の5値（C0・C9・D0・E0・F0）は、Z80 の戻り命令の符号
  （無条件1つと条件付き4つ）に当たる。ROM が (0,0,1) を命令として実行し、戻ってくれば BASIC へ進む、と
  **読むのが自然だが、断定しない**（一様値の掃引では、どのバイトが効くかも、命令として実行されているのか値を
  検査しているのかも決まらない）。条件付き戻りの条件が成り立たない場合に何が起きるかも測っていない。
  実装の暫定の扱い: 読み込んだコードを実行し、戻ればBASICへ進む。それ以外の値の場合の挙動は要求しない。
- **起動しなかったとき・`RET` で戻ったあとの BASIC で、ディスク命令が働くか（第3版）。**
  公式は、ドライブ1が空で起動したとき・(0,0,1) が戻り命令で戻ったとき、BASIC には届くが FILES・LOAD が
  ディスクに対して働かない（`docs/notes/b4-media-timing-results.md`、`docs/notes/m6f-d-disk-rules-results.md` D9 の
  `nondisk_basic`）。ディスク命令が働く状態は、公式ではシステムディスクからの起動が作っていると読める（推定）。
  **自作 ROM はこの点を公式に合わせず、ディスク命令が最初から働く側にする**（意図した違い。親の判断、2026-10-26）。
  公式に合わせるとシステムディスクが要り、公式ディスクは使えないため。市販ソフトがこの違いに依存する観測が出たら、
  別に事前登録して見直す。**実装への要求にしない**（3.2節の「`RET` で戻れば BASIC へ進む」は変えない）。
  自作 ROM 用の照合器具は「ドライブ1を空で起動し、判定のあとで媒体を入れる」形を取ってよいが、その期待値との一致は
  公式との同値ではなく、この判断を前提にしたものである。
- **2セクタ目以降を ROM に読ませる手段。** ROM の番地を呼ぶ形になるため、ゴール B の「番地の働き」として
  番地ごとに別の事前登録で扱う。この文書は決めない。
- **I = F3 と割り込みベクタの関係。** `l1-ipl.md` 第3節（フレーム 27 以降は IM 2 で受理）と
  照らすと、I はベクタテーブルの上位バイトとして設定された値と読める。ただし I=F3 の指す先の中身は読んでおらず、
  割り込みベクタをどこに置くかは自作 ROM の自由（l1-ipl.md の「実装の目標ではない」注記に同じ）。
  起動用セクタのコードが I を変えたり割り込みを発生させたりしたときの扱いは測っていない。
- **SP=E5F4 より上のスタックの中身。** 先頭2バイト以外は、ROM の内部の呼び出しの連なりに当たり、測らない線
  （`goal-b-policy-addendum1` 第4節）。仕様に含まない。
- 入口レジスタの値が指す先（HL=C000 などの中身を除く）、裏面や2D 以外の媒体での起動は測っていない。
  ドライブ2だけに媒体があるときは起動を試みない（第1.4節、第2版）。
- `IN 40` bit3 のどの回の読みが決め手か、実機で bit3 を作るもの（第1.4.2節）。
- 読み込み前後の C100 以降の RAM の内容、E5EC〜E5EF の ROM 書き込み（取りこぼしの都合で未記録）。

## 6. 適合の判定

実装後、自作 ROM に対して**同じ器具**を回す: `tools/b2_make_boot_probe.py`（媒体生成。`--load-addr C000`・入口0）、
`tools/b2_extract_boot_probe.py`（抽出器）、境界の記録（`--boundary-log`）、止めた腕のポート列。
腕は A1〜A6（RET・HALT・DI+HALT・rev・head1・目印なし）と、対照としてディスク無し。

次が全て一致すれば適合とする（腕ごと2走、走間の揺れ無し）。

1. **J1 読み込み先**: 抽出器が `base_true = C000`、`consistent = yes`、`probe_rows` 完全・不一致0。
2. **J2 入口の状態**: 第2節の表（AF・BC・DE・HL・IX・IY・SP・IFF2・I）が全腕で一致。
3. **J3 読み込む量**: 目印マスクが全腕で全位置 0（(0,0,2) 以降・裏面が C100 以降に読み込まれない）。none 腕も 0。
4. **J4 戻り**: `RET` 腕（A1・A4・A5・A6）で、戻った後 BASIC が起動する
   （自作 ROM の既存の BASIC 起動判定、例えば l4 の標準プロンプトの出力）。
   **戻り先の番地（45D9）と、スタックの先頭2バイトの値は判定に含めない。**
   記録上の飛び先の集合は DI+HALT 腕に無い番地を含むが、番地の一致は求めない。
5. **J5 戻らないとき**: A3（DI+HALT）で main・sub とも入出力 0 行。A2（HALT）でディスク用ポート
   （FC・FD・FE・FF）の入出力が無く、sub の入出力が 0 行。キー走査系のポート列（第4節）は、自作 ROM の
   割り込み処理の仕様どおりで足り、本節ではポートごとの件数までは求めない。
6. **J6 ディスク無し**: 起動用セクタの実行（C000 の実行）が起きず、BASIC へ進む。
   あわせて（第2版）次も満たす。器具は `tools/b3_analyze_boot_decision.py`（分類）と `q88measure --main-in-force`（介入）で、
   腕は `docs/notes/b3-boot-decision-preregistration.md` 第4節と同じ。
   - ディスク無し・ドライブ2だけに有り: main がポート `FC`〜`FF` に一度も触れず、sub の入出力が 0 件（ROM 形）。
   - ドライブ1に有り: ディスク形（sub とのやり取りがあり、起動用セクタのコードが実行される）。
   - 介入: ドライブ1に有り＋`IN 40` bit3 := 1 で ROM 形・起動用セクタのコードが実行されない。
     ディスク無し＋bit3 := 0 でディスク形（sub に READ を頼む経路に入る。その後に sub が媒体を待つことは
     [l3-subrom.md](l3-subrom.md) 1.62〜1.63節の規則のとおりでよい）。
   - 分岐のフレーム・OUT の件数の一致は求めない。
7. **（判定外）読めない4形**: (0,0,1) がセクタ無し・CRC エラー・削除マーク・単密度のとき、公式 ROM は
   BASIC に届かなかった（第1.2節の観測）。この振る舞いは**実装への要求にしない**（壊れた媒体で先へ進めない
   振る舞いを再現する需要は観測されていない。親の判断、2026-10-24）。自作 ROM がこの4形で何をしたかは
   記録だけ残し、適合・不適合を決めない。

測定ログは `private/` 由来のバイト列を含まないので、自作 ROM に対する記録は白リスト（`b2-boot-sector-handoff-preregistration.md` 第5節）の
形でコミットできる。
