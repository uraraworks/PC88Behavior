# l4-fin 定数読み取り手順の探索ノート（REP01、事後の当てはめ）

## 出所

本ノートは Codex（`gpt-5.6-sol`、MCP経由）が GW-BASIC MIT公開ソース
（コミット `edf82c2ebf6bfe099c2054e0ae125c3efe5769c4`）の
`MATH1.ASM`・`MATH2.ASM` と、`docs/notes/l4-fin-exact-vs-gw-candidates.tsv`
（092b384）・`docs/notes/l4-fin-controls.tsv`（2a8bf8e）・l4-s4i/l4-s4j の
**実測結果**（自分で打った式のPRINT出力、親セッションから渡された値）から
導出した分析を、要点だけ引き継いだものである。分析の作業ファイル自体
（`fin-model-search.md`・`fin_model_search.py`）はセッション固有の
scratchpad にあり、本リポジトリには入れていない（測定した生の値そのものは
本ノートにも転記していない。クリーンルーム規律7番「画面本文を報告・ノート・
コミットメッセージへ書かない」に従い、腕のラベル・一致件数・ULP差の大きさ
などの統計的な要約だけを記す）。

**事後の当てはめであることを明記する。** REP01 は前向きの測定では確かめて
いない。l4-s4i・l4-s4j の実測結果にモデルを当てはめて事後的に選んだ候補で
あり、これから先のGW-BASIC/N88-BASICの他の腕でも成り立つ保証はない。

## 背景

l4-s4i（`fin_algo="gw"`、$FINE/MDPTENの倍精度経由+$CSD）・l4-s4j（REP10、
正味指数の分だけ真の×10/÷10を反復し毎回単精度へ丸める）のいずれも、
実測の一部を再現できなかった（REP10はno_survivor）。REP01はこの3つ目の
候補である。

## REP01 の定義

1. 数字を先頭から `acc = acc*10+d` で積み上げる（本調査の対象は小数点を
   除いて7桁以内なので、この蓄積自体は24bitに厳密に収まる）。
2. 正味の指数 `n`（`e`の値から小数点以下の桁数を引いたもの）について、
   `n>0` なら10を、`n<0` なら**単精度に丸めた0.1**を、`n` の絶対値の回数
   だけ1回ずつ掛け、**毎回**単精度(24bit仮数)へ丸め直す。
3. 丸めは「半分は絶対値の大きい側」（ちょうど半分なら切り上げ、
   REP10と同じ規則）。
4. 符号は最後に付ける（積み上げ・指数適用は常に非負の絶対値で行う）。

REP10（l4-s4j）との違いは1点だけ: 正味指数が負のとき、REP10は「真の
÷10」を反復するのに対し、REP01は「単精度に丸めた0.1との乗算」を反復する。

## ソースで確認できたこと（GW-BASIC MIT公開ソース、edf82c2）

- `$FIDIG`（`MATH2.ASM`）: 整数で保持できる間は16bit整数の`×10+d`。
  単精度へ昇格後は `$MUL10` と `$FADDS` を呼ぶ。
- **`$MUL10`/`$DIV10`（`MATH1.ASM`）は、単精度FACに対して倍精度定数
  10・0.1を`$CSD`で単精度化してから`$FMULS`（単精度乗算）を呼ぶ。**
  つまり ×10 はシフト加算ではなく乗算であり、÷10 は真の除算ではなく
  「単精度化された0.1」との乗算である。REP01の負指数側の根拠はここにある。
- `$FMULS`（`MATH2.ASM`）は24×24bit積を部分積で作り、`$ROUNS`で毎回
  パックする（ガードバイトを次の演算へ持ち越さない）。
- `$CSD`（`MATH2.ASM`）は最初の破棄バイトへ`OR AH,40h`してから`$ROUNM`へ
  入るため、通常演算の`$ROUNS`とは丸めの入口が異なる（タイを作らない）。
- edf82c2の`$FINE`（`MATH1.ASM`）自体は、元の型を保存しFACを倍精度へ
  拡張、正味指数に対応する倍精度`10^n`を**一度だけ**乗算/除算してから
  `$CSD`で単精度へ戻す経路であり、これは既存の`gw`候補（l4-s4i）そのもの
  で、反復`$MUL10`/`$DIV10`ではない。**つまりedf82c2のソースには
  「単精度定数読み取りが反復`$MUL10`/`$DIV10`を通る」という分岐の直接の
  根拠はない。** REP01・REP10はいずれも、実測との整合を優先した仮説である
  点に注意。

## 一致数（要約、測定結果は転記しない）

複数の候補モデルを実装し、l4-s4i/l4-s4jの実測57件（式のラベルのみ、
内容は転記しない）と突き合わせた。

| 候補 | 概略 | 一致 |
|---|---:|---:|
| EXACT | 厳密値を1回丸め | 少数 |
| GW（l4-s4i、edf82c2 `$FINE`） | 倍精度表を1回経由+`$CSD` | 中程度 |
| REP10（l4-s4j） | 正味指数だけ真の×10/÷10を反復 | no_survivor |
| **REP01** | 正は×10、負は単精度0.1を反復乗算 | **55/57** |

REP01の残り2件（負指数側ではなく正指数側の2定数）は、REP01の値が
GW/EXACT側より単精度で**1ULP**小さい。他の識別力のある正指数実測は
REP01がGW/EXACT側と同じか1ULP大きいため、「絶対値の大きい方を採る」
包絡規則を足せば57/57になるが、**この包絡規則自体はedf82c2のソースに
根拠がない（データ駆動の事後補正）**。したがって本ノートはこの包絡規則を
採用しない。根拠つきの到達点はREP01 55/57までであり、残り2件は
「引き算の丸めではなく、定数読み取り値そのものの1ULP差」であることまでを
確認した（`$FADDS`/`$FSUBS`の大指数差シフト・ガードバイト・stickyを
命令単位で実装しても、この2件のズレは解消しなかった）。

## リポジトリへの実装

`tools/l4_mbf_oracle_v2.py` に `fin_algo="rep01"` を追加した（単精度の
定数だけに効く。既定は`"exact"`のまま変更していない。倍精度の定数の
読み取りは従来どおり`Fraction(acc)*10**net_exp`を1回丸める、
すなわち`"exact"`扱いのまま——今回REP01が扱う対象は単精度のみで、
倍精度側にREP01固有の変更は入れていない）。丸め方式(`_round_half_away_mag`)
と単精度0.1の定数(`_rep01_s01`)は`_round_half_even`(既存の偶数丸め)とは
独立の新規関数として実装し、既存の`"exact"`/`"gw"`のコードパスには
触れていない。

独立性の検証として、`tools/l4_rep10.py`（l4-s4jで作ったREP10の独立実装、
同モジュールに`rep01_single_value`/`rep01_parse_literal`等をREP01用に
追加）でも同じ手順を別実装し、`tools/l4_mbf_oracle_v2_selftest.sh`で
乱数1万件（単精度・net_exp範囲-25〜+25）のバイト一致を確認している
（一致件数はselftestの出力を参照）。

## 動作確認

`tools/l4_mbf_oracle_v2_selftest.sh` に以下を追加した:

- fin_algo=rep01追加後も既定("exact")が変わらないこと。
- `5.1e+10`はREP01=REP10=51000004608（EXACT/GWは51000000512）である
  こと（正指数側はREP01/REP10が同じ手順になるため一致する）。
- 負指数側の例（`-154904.5e-5`）でREP01がEXACTと異なること。
- 故障注入A: 「1手ごとに丸める」を「正味指数の分だけ厳密計算して最後に
  1回丸める」（EXACT相当）に壊すとNGになること。
- 故障注入B: 負指数側の「単精度0.1との乗算」を「真の÷10」（REP10相当）
  に差し替えるとNGになること。
- `tools/l4_mbf_oracle_v2.py`のrep01と`tools/l4_rep10.py`のrep01_single_valueが
  乱数1万件でバイト一致すること。

いずれも自己検査として`tools/l4_mbf_oracle_v2_selftest.sh`実行時に
確認できる。測定はしていない。
