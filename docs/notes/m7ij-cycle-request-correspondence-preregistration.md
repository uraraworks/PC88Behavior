# m7ij: 入口場面の要求と連続READ周期が1対1かを見る — 事前登録

## 位置づけ

[m7ii](m7ii-bit-flip-runlength-shape-results.md)は判定N2に終わり、**run長の「9」は
交換run36のどの位置のどのビットを壊しても変わらない**ことを確定した。壊れ方は
1種類しかなく、どこを壊しても**9のまとまりが12本から11本へ1本減る**だけだった。

`m7ii`は次の一手として「交換run36の外を見る」を挙げた。**本稿はその探索範囲を、
先に観測されている構造から絞る。**

## 探索範囲を絞る根拠（既に観測済みの事実から）

`m7ie`が記録した交換run一覧（条件O、水準E）を読み直すと、入口場面の交換runは
**「main→sub 長さ6」と「sub→main 長さ1」が交互**に並んでいる。

| 交換run | 方向 | 長さ |
|---:|---|---:|
| 36 | main→sub | 6 |
| 37 | sub→main | 1 |
| 38 | main→sub | 6 |
| 39 | sub→main | 1 |
| …（59まで交互） | | |

**この区間のmain→sub runは12本である。** そして連続READ構造は
**「SEEK1回＋READ DATA 9件」が12周期**（`m7hb`）。**本数が一致している。**

さらに`m7ii`が確定した「交換run36のどこを壊しても9のまとまりが**ちょうど1本**
減る」という事実は、**run36が12周期のうち1周期を駆動している**という描像と整合
する。

**本稿はこの1対1対応が本当に成立するかを測る。** 成立すれば、
**「12」は要求の本数で決まり、「9」は要求では決まらない**ことになり、
`m7hb`が区別できなかったH2（固定回数）とH1派生（1トラック分）の切り分けに
**新しい材料**が入る。

**なお本稿は「9」の出所を決めない。** 決めるのは「12」の側である。

## 段階0（本稿）: 事前登録を測定前にコミットする

本稿は測定を1回も走らせる前に単独でコミットする。測定後の書き換え・amendは
行わない。候補runの列挙も本コミット後に行う。

## 測定条件（`m7if`〜`m7ih`と同一に固定する）

- 条件Oのみ（公式ROM一式）。A:=`disk#8`（`650cfac8`）、B:=`disk#10`
  （`0c6f7a53`）。
- 打鍵は水準E（`--type-at 300 --type '\n' --type-at 700 --type 'FILES 2\n'
  --frames 3000`）。
- 基準（摂動なし）は**FDC総数195・READ DATA 117・単発9本＋run長9が12本**。

## 段階1: 候補runの列挙（規則を先に固定する。決め打ちしない）

**候補の規則（測定前に固定）:**

> 条件Oの交換run列（`analyze_error_exchange_shape.exchange_runs`）のうち、
> **方向が`main→sub`**であり、**開始clockが交換run36の開始clock以上**である
> ものすべて。

この規則で列挙されたrunを、**番号順にすべて**対象とする。**後から候補を足さ
ない。除かない。**

**記録すること**: 列挙された候補runの**個数**と、各runの**番号・長さ・開始
clock**。**個数が12でなかった場合も、規則どおりに列挙されたものをそのまま
使う**（12という予想に合わせて選び直さない）。

## 段階2: 候補runを1本ずつ壊して、周期の本数を数える

各候補runについて、**位置0**に`XOR 0xFF`を当てる（`--request-intervention
<RUN>:0:xor:0xFF`）。位置0を選ぶ理由は、`m7ii`で位置0が**8ビットすべてで**
構造を壊した唯一の位置（位置2を除く）であり、**「その要求を確実に壊す」ため
の位置**として最も当てになるためである。

各armについて記録する（値は出さない）:

- `changed`（介入が届いたか）
- FDCコマンド総数、READ DATA総数
- **READ DATAのrun長の並び（完全な列）**と、その多重集合
- **run長9のrunの本数**

## armの分類（測定前に固定。`m7ih`の定義をそのまま使う）

- **A型（保持）**: 並びが基準と完全一致。
- **B型（本数だけ変化）**: run長が1と9だけで、run長9の本数が**12未満**。
- **C型（run長そのものが変化）**: 9でも1でもないrun長が1本以上現れる。
- **D型**: 上のどれでもない（FDC総数が1950超は無条件にD型）。

## 事前登録する判定（測定前に固定。後から動かさない）

- **P1（1対1対応が成立）**: 候補runの**すべて**でB型となり、かつ**run長9の
  本数がすべて11**（＝ちょうど1本減る）。
- **P2（部分的）**: B型かつ11本になるrunと、そうでないrunが混在する。
- **P3（対応しない）**: どの候補runでもA型（何も変わらない）。
- **P4（別の形）**: 上のどれでもない（C型・D型が混じる等）。
- **O（測定不能）**: 基準が再現しない、決定論性が確認できない。
- **O'（介入が届かなかったarmがある）**: `changed`が0のarmは判定に用いず記録
  する。全armが該当した場合は主判定をO'とする。

**併せて記録する（判定とは別）**: **C型のarmが1本でもあれば、その事実と
run長の並びを必ず書く。** 「9」が動く条件を探すのが上位の目的であり、
本稿の主判定が何であれ、C型は最重要の観測である。

**どの判定になるかは予測しない。**

## 事前登録する合格条件（測定前に固定）

1. `tools/recv_run_field_leak_selftest.sh`が全項目OK・rc=0。
2. `tools/analyze_error_exchange_shape_selftest.sh`がrc=0。
3. **基準の再現**: 摂動なしの条件OがFDC総数195・READ DATA 117・run長9が12本。
4. **`m7ii`との一致**: 候補にrun36が含まれるはずであり、その位置0・`XOR 0xFF`の
   結果が`m7ie`の記録（FDC183・READ108・run長9が11本）と一致すること。
   食い違えば判定O。**これは「同じものを見ている」ことの確認である。**
5. **介入が届いていることをarmごとに確認**: 各armで`changed>=1`。
6. **決定論性**: 基準と、**C型・D型に分類された全arm**、および**候補runのうち
   最初と最後の2本**について、生ログが独立2回でバイト一致すること。
7. **実行したarm数を出力に載せ、候補runの個数と一致することを確認する**
   （`m7ig`でzshの語分割によりループが1回しか回らなかったため）。
8. `tools/check_cleanroom.sh`が全項目OK。

## 実務上の取り決め（測定前に固定）

- 各armの生ログは指標を取り出した直後にscratchpad内で削除する（`m7ig`で
  1.0GBに達したため）。削除するのはリポジトリ外の一時ファイルのみ。
  決定論性の確認対象は**その場で2回走らせて比較**してから消す。
- 測定はフォアグラウンドで行い、測定中に`git stash`・ブランチ切替・`src/`の
  編集をしない。

## 言えないこととして先に書いておくこと

- **P1が出ても「各要求が1周期を駆動している」と断定はしない。** 言えるのは
  「どの要求を壊しても周期がちょうど1本減る」までである。要求と周期の対応が
  1対1であることの十分な証拠にはならない（例えば「壊すと1本減る」が別の機序で
  起きている可能性を排除していない）。
- **本稿は「9」の出所を決めない。** C型が出れば手掛かりになるが、出なければ
  「この探索範囲では動かない」としか言えない。
- **位置0を選んだのは`m7ii`の観測に基づく便宜であり、他の位置で違う結果に
  なる可能性を排除していない。**
- **run長や本数から元の値を逆算しない**（禁止事項5）。
- 条件O・`disk#10`という1本のディスク・1条件である。一般性は主張しない。

  出してよいのは件数・run長・位置番号・交換run番号・clock・**ビットマスクの
  指定値**・真偽値・rcのみ。
