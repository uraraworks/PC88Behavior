# 資料判定 — 『PC-8801 マシン語活用マニュアル』は開かない

作成日: 2026-08-07
判定: L1 実装セッション（`docs/notes/m4-l1-impl.md` の続き）

> 対象: 『PC-8801 マシン語活用マニュアル』（1984年3月 初版、200ページのスキャン PDF）
>
> **開いたのはカバー袖の紹介文（PDF p.4）1 ページのみ。本文・目次は開いていない。**

## 判定

**`CLAUDE.md` 禁止事項2 に該当する。本文は開かない。**

> 2. **逆アセンブルしない。** 逆アセンブラを公式 ROM に対して実行しない。
>    他人が公開している PC-88 ROM の逆アセンブルリスト・解析記事の
>    *コード断片* も読まない（仕様の散文説明は可）。

## 根拠 — 本が自分でそう書いている

カバー袖の「本書を読まれる方へ」に、著者・版元自身の言葉として次がある。

> そのため本書の前半では、読者とともに、**ROM の解読を試みます**。
> それは、マシン語プログラマーが必要とする知識の宝庫です。
> さらに、その知識をもとに各周辺機器を制御する方法を調べます。

**「ROM の解読を試みます」と本が明言している。** これは禁止事項2 が言う
「PC-88 ROM の解析記事」そのものである。推定や状況証拠ではなく、
資料自身の自己申告なので判定に迷う余地が無い。

さらに「**その知識をもとに**各周辺機器を制御する方法を調べます」とあり、
**後半も前半の ROM 解読を前提に組み立てられている**。
「前半だけ避けて後半を使う」という切り分けが成り立たない構造である。

`PC-Techknow 8801 Vol.1` では付録6（I/O ポート一覧表）だけを読み、
付録2・3・4（BASIC インタプリタとモニタルーチンの解説）を
「ROM の中身の解説なので開いていない」として避けた。同じ運用を
この本に適用しようとしたが、**章単位で線を引ける本ではない**と判断した。

## 経緯（近かったので記録する）

置かれた意図は「ROM の解析ではなくマシン語での書き方の本なので汚染はされない
と思うが、どうか」という確認だった。書名からはそう読めるので、
妥当な見立てだったと思う。実際に危なかったのは次の点である。

1. **epub 版は OCR が壊れていて日本語が 1 文字も復元できない**
   （cp932 / euc-jp / utf-8 いずれもデコード不能。OCR エンジンが日本語を
   ラテン文字の羅列として誤認識している）。読めるのは埋め込まれた ASCII 断片だけ。
2. その ASCII 断片（`4-0 N88-BASIC ROM…` / `4-1 N-BASIC ROM…` / `2-2 RST 38H…`）
   から「第4章は ROM 内サブルーチンの一覧らしい」と**推定**した。
   推定なので、本文を開いて確かめたくなる圧力がかかる。
3. **確かめる前にカバー袖で決着した。** 目次ページを開く手前で止まった。

教訓: **資料の可否は、目次や本文より先にカバー・まえがき・序文を見ると
最小の露出で決まることがある。** 本は自分が何をする本かを最初に書いている。
目次から入ると、判定のために中身へ近づいていくことになる。

## 汚染

無し。開いたカバー袖は本の紹介文であって、ROM のコードもアドレスも
ワークエリアも含まない。この文書に引用した箇所がその全部である。

## この本が持っていそうで、まだ要るもの

ASCII 断片から、第0章にメモリマップ、第2章に `RST 38H`（割り込み）の
話がありそうに見えた。`docs/notes/m4-l1-impl.md` の宿題 1・3・4
（定常状態の駆動源／メモリマップ／リセット直後の CPU 状態）に効く題材である。

**この本からは取らない。** 取るべきは `docs/spec/l1-ipl.md` 第4b節の結論どおり、
**テクニカルマニュアル／システムハンドブック／サービスマニュアル（回路図）**の系統。
そちらはハードウェアの仕様書なので、ROM の中身を経由せずに同じことが分かる。

マシン語本が危ないのは、**ROM を呼ぶ前提で書かれているぶん、
ハードウェアの説明と ROM 内部が地続きになっている**ためである。
「ハードウェアの話だから安全」とは限らない。誰が書いた本かではなく、
そのページに ROM の内部が書いてあるかで決める。
