# m6f-a 追補1 — F6 を打鍵上限の内側で組み直す（測定前・器具作成前）

記録日: 2026-09-24  
状態: 測定前。**器具もまだ作っていない。**

## 1. 何が成り立たないか

[事前登録](m6f-a-directory-by-save-diff-preregistration.md) §3 の F6 は

> 100行の `REM` プログラムを `SAVE"QZ7A"`

だった。q88measure は**1走の打鍵が合計512打鍵まで**である（m7cw の事前調査に記録済み）。
100行の REM は1行あたり十数打鍵でも1000打鍵を超え、**打ち込めない。**

打鍵を減らすために行を長くしても、2行×240文字程度でプログラムは数百バイトにしかならない。
**割り当て単位の大きさは未知**なので、数百バイトでは F1（`10 END`）と同じ1単位に収まり、
F6 が F1 と区別できない可能性がある。

## 2. 直し方

F6 を、**短いプログラムで大きなデータファイルを書く**形にする。

```
10 OPEN"QZ7D" FOR OUTPUT AS #1
20 FOR I=1 TO 300:PRINT #1,STRING$(200,"Z"):NEXT
30 CLOSE #1
RUN
```

- 打鍵は100程度で収まる。
- 書かれるファイルは約60KBになり、未知の割り当て単位の大きさに対して十分に大きい。
- プログラム自体は `SAVE` しない。**割り当て表の変化を、BASIC プログラムの SAVE ではなく
  順次ファイルの書き込みから観測する**ことになる。

## 3. D7 の書き直し

割り当て表が SAVE と順次ファイルで共通かは測っていないので、**共通であると仮定しない**。
D7 を次のとおり書き直す。

- **D7 割り当て表**（副問）: **F1 と F6 の両方で変わったセクタから、D1 のセクタを除いたもの。**
  そのセクタで F6 の変わったバイト数が F1 より多いことを要求する。
  - F1 のプログラム本体のセクタは F1 でしか変わらず、F6 のデータファイル本体のセクタは
    F6 でしか変わらないので、「両方で変わった」で本体は自然に除かれる。
  - 候補が0なら `not_found`（SAVE と順次ファイルで割り当て表が共通でない、または
    割り当て表がディレクトリと同じセクタにある、のどちらかで、本稿では区別しない）。

## 4. 変わらないもの

- F0〜F5、境界の規則（§1）、D1〜D6、関門、判定名、行き先。
- F6 の名前 `QZ7D` は他の腕の名前と衝突しない固有名である。
