# l4-s5a — 行の入力とLISTの書式 — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

M7段階5（プログラムモード。`docs/notes/l4-design.md`の段階表「行番号・
LIST・RUN・FOR・GOSUB」）の最初の測定。直接モードの`PRINT`は段階3・4
（`l4-s3a`〜`l4-s4l`）で公式と一致することを確認済み。プログラムモード
の実装に入る前に、行番号つきの行を打ち込んだときの画面の扱いと、
`LIST`の出力の形を測る。

## 問い

- Q1 行番号つきの行を打ったとき、画面に何が起きるか（`Ok`が出るか、
  エコー以外の出力が出るか）
- Q2 `list`の出力で、次の各点がどうなっているか
  - 行番号の書式（前後の空白の有無）
  - 命令語の大小文字（打鍵は小文字で届くが、`list`の出力では処理系が
    組み立て直すため、大文字化されるかどうか）
  - 命令語の後の空白
  - `?`が`PRINT`に展開されるか
  - `:`の前後に空白が入るか
  - 打ったときの余分な空白（例: `print  1`のような2つの空白）が保た
    れるか
- Q3 同じ行番号を打ち直したときに行が**置き換わる**か、行番号だけを
  打ったときに行が**削除される**か
- Q4 `list`が行番号の順に並ぶか（打った順ではなく）

## 腕（12腕＋陽性対照1腕）

打鍵はこのまま使う。英字は小文字で届く（打鍵注入の仕様どおり）。
1腕＝`new`のあと行を打ち、最後に`list`を打つ、という一連の打鍵を
1つの`--type`文字列として与える（`l4-s3a`のP3-trail-semi等、`\n`を
埋め込んだ複数行の連続打鍵と同じ作法）。

| 腕 | 打鍵文字列（`\n`は改行） | 目的 |
|---|---|---|
| A1 | `new`/`10 print 1`/`list` | 基本形 |
| A2 | `new`/`10print1`/`list` | 空白無し |
| A3 | `new`/`10 print  1`/`list`（空白2つ） | 余分な空白の保持 |
| A4 | `new`/`10 ?1`/`list` | `?`の展開 |
| A5 | `new`/`10 print 1:print 2`/`list` | `:`の前後 |
| A6 | `new`/`20 print 2`/`10 print 1`/`list`（打つ順を逆に） | 行番号順の並び |
| A7 | `new`/`10 print 1`/`10 print 2`/`list`（置き換え） | Q3置き換え |
| A8 | `new`/`10 print 1`/`20 print 2`/`10`/`list`（削除） | Q3削除 |
| A9 | `new`/`65529 print 1`/`list` | 大きい行番号 |
| A10 | `new`/`10 print "abc"`/`list` | 文字列を含む行 |
| A11 | `new`/`10 print 1.5`/`list` | 小数を含む行 |
| A12 | `new`/`10 print 1234567890123#`/`list` | 長い倍精度定数を含む行 |

### 陽性対照（1腕、腕数には含めない）

直接モードの`print 7717`（`l4-s4a`以来使ってきた陽性対照と同一）。
プログラムモードには入らず、差分モードの検出力を確認する。

腕の総数: **12腕**（A1〜A12）。各腕2走（決定論性の関門G3）。

## 条件・関門

`l4-s4a`の流儀（[l4-s4a-float-print-preregistration.md](l4-s4a-float-print-preregistration.md)、
`d8cf563`）＋`l4-s4d`追補以来の全腕一律延長を踏襲する。

- 起動settle`--type-at 300 --type '\n'`、実打鍵開始`--type-at 700`
- 1文字あたり`hold+gap=8`フレーム/文字（`\n`も1文字として数える）
- フレーム計算式（全腕一律、`l4-s4d`追補以降と同一の延長）:
  ```
  line_end(k) = 700 + 8 * (その腕で打った文字数の累計。\n も1文字。
                            複数行にわたる打鍵は全体を1つの--type文字列
                            として与え、文字数は改行を含めた合計)
  dump(k)     = line_end(k) + 300
  run(k)      = dump(k) + 200
  ```
- 写しは打鍵前（`--type-at`の10フレーム前=690）と`dump(k)`後の2枚を
  `--diff-before`/`--diff-after`に渡す
- **複数行を打つ腕では、行ごとの打鍵の間隔（次の行の先頭文字が届く
  フレーム）が上記の式で正しく積み上がっていることと、`list`の出力が
  画面の行数（25行）を超えないことを、打鍵文字列を組み立てる時点で
  確かめる。** 超える腕があれば、その腕は関門G1（器具の自己検査）に
  準じて測定前に組み直す（本ノートの12腕はいずれも数行程度であり、
  25行を超える見込みは無いが、念のため明記する）。

## 記録する内容

`list`の後に現れる出力行（打った行より下で`Ok`行より上の範囲）を
**1行ずつ分類**して扱う。

- **数値行として記録してよい行**: 「先頭の空白を除いた最初の文字が
  数字`0`〜`9`であり、かつ行の全セルが表示可能なASCII（`0x20`〜
  `0x7E`）である」行だけ、(相対行, 相対桁, 文字コード)の並びをそのまま
  記録する。`LIST`の各行は行番号で始まるため、この条件は「行番号の桁
  から始まる、まっとうなプログラム行の再現」を捉える。自分で打った
  プログラムを処理系が表示したものであり、内容は自分で打った文字列
  そのもの（処理系が組み立て直すのは書式だけ）なので、`PRINT`の出力
  と同じ扱いで文字コードを出してよい。
- **それ以外の行**（先頭〔空白を除く〕が数字でない行、または`0x20`〜
  `0x7E`の範囲外のコードを1つでも含む行——エラーメッセージ等を含み
  うる）は、**件数と位置の範囲（相対行・相対桁の最小・最大）だけ**を
  記録する。コード・文言は一切出さない（CLAUDE.md禁止事項7）。
- 直接モードの陽性対照（`print 7717`）の出力行は、`l4-s4a`以来の既存
  の数値分類（`tools/l4_s4a_float_classify.py`、`5735eb3`）で扱う
  （`list`の行分類とは別の、既存の仕組みをそのまま使う）。

## 本文を出さない取り扱い

- 上記「記録する内容」節の分類規則そのものが、本文を出さない取り扱い
  の実体である。数字で始まり表示可能ASCIIだけで構成される行だけを
  文字コードごと記録し、それ以外は件数と範囲だけにする。
- **この分類を行う記録器は、記録しない行の文字コードを標準出力・
  標準エラー・ファイルのいずれにも一切出さない設計にする。** 記録器は
  `tools/l4_list_classify.py`という名前で、器具の担当が新しく作る予定
  （本ノートの担当範囲外。測定の前に別コミットで入る）。作るにあたり、
  次の自己検査を備える。
  - **陰性対照**: 数字で始まらない英字の行、および表示可能ASCII範囲外
    のコードを含む行を記録器に渡し、それらのコードが出力に一切現れ
    ないことを確認する
  - **陽性対照**: 数字で始まり表示可能ASCIIだけの行を渡し、正しく
    (相対行, 相対桁, コード)が記録されることを確認する
  この自己検査が通っていることを、関門G1（器具の自己検査）に含める
  （下記「関門」節参照）。
- 写し・記録・iologは使い捨ての作業ディレクトリ（リポジトリ外）に置き、
  結果ノートを書いたら削除する。

## 関門

`l4-s4a`のG1〜G6・`l4-s4d`追補以降のG8を土台にする。

- **G1 器具の自己検査**: 測定時HEADで`tools/harness/vram_dump_selftest.sh`・
  `tools/harness/vram_dump_dynamic_selftest.sh`・
  `tools/harness/key_matrix_selftest.sh`・
  `tools/harness/type_untypable_selftest.sh`・
  `tools/screen_content_leak_selftest.sh`の全項目がOKであることに加え、
  **`tools/l4_list_classify.py`の自己検査（陰性対照・陽性対照、上記
  「本文を出さない取り扱い」節）が通っていること**を含める
- G2 取りこぼし0・打てない文字の警告0（全走のstderrで確認）
- G3 決定論性: 各腕2走とも、写しはファイルのsha256が一致、記録（本
  ノートに載せるデータ行）はsha256が一致
- G4 陰性対照: 何も打たない走（起動settleのみ）で差分0件
- G5 陽性対照: 直接モードの`print 7717`腕で、出力の行に
  `0x37 0x37 0x31 0x37`（`7717`）の並びが相対列の連続した4セルとして
  現れる
- G6（本測定には対になる予測表が無いため適用しない。`l4-s4f`以降の
  「G7は対になる予測表が無いため適用しない」と同じ扱い）
- G8 出力完了の確認: 「後」の写しで、`list`の出力行の後に`Ok`行が
  現れていること。現れない腕は`gate_failed`とし、「写しが早すぎた」
  とだけ記述する

判定の前にG1〜G5・G8がすべて真であること。いずれかが偽の腕は、その
腕を`gate_failed`として判定に含めず、理由を記述する。

## 判定

記述が中心。判定名を付けるのはQ3・Q4のみで、それ以外（Q1・Q2）は
記述のみとする（判定名は付けない）。「記録する内容」節を参照する。

- Q1: 記述のみ。`Ok`の有無、エコー以外の出力の有無をそのまま書く。
- Q2: 記述のみ。行番号の書式・命令語の大小文字・命令語後の空白・`?`の
  展開・`:`の前後・余分な空白の保持それぞれを、記録した内容（数値行
  として記録された文字コードの並び）からそのまま書く。
- Q3（A7・A8）: `replaced`/`not_replaced`（A7）、`deleted`/
  `not_deleted`（A8）。当てはまらない形は`other`とし記述で補う。
- Q4（A6）: `sorted`（`list`の出力が行番号順=10の行が20の行より前）／
  `not_sorted`（打った順のまま=20の行が10の行より前）／`other`。
- `gate_failed`: 関門のいずれかが偽だった腕。判定に含めず、理由を記述
  する。

## 器具の確認（公式ROMは使わない）

測定開始前に、自作main ROM（測定時HEAD`7f3f4b8`から`src/build_main_
rom.py`で組み立て）に対し、12腕＋陽性対照の計13腕すべてを打鍵し、
各行のエコーが打鍵どおりに届くかを`tools/l4_vram_probe.py --marker`
（各腕の打鍵文字列を`\n`で分割し、各行をそれぞれmarkerとして指定）で
確認した。**自作ROMはまだプログラムモードを持たないため、`new`・
`list`・行番号つきの行が実際にどう処理されるかは見ておらず、エコー
（打った文字がそのまま画面に写っているか）だけを確認した。**

結果: **13腕すべてで、各行のエコーが打鍵どおりに出現した**（腕ごとの
全行でmarker一致、打鍵前の走行失敗〔型チェックによる事前拒否〕も
無し）。`?`（A4）、`:`（A5）、`"`（A10）、`.`（A11）、`#`（A12）、
2つ連続する空白（A3）を含め、届かなかった記号は無かった。

作業に使ったROM・写し・スクリプトはリポジトリ外の使い捨てディレクトリ
（scratchpad配下）に置き、確認後に削除した。
