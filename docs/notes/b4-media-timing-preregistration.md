# B4: 自作照合のドライブ1の媒体を、いつ・何を入れれば公式と同値か — 事前登録

記録日: 2026-10-26
位置づけ: [goal-b-policy-addendum1-boot-sector-2026-10-24.md](goal-b-policy-addendum1-boot-sector-2026-10-24.md) の範囲内。
[l3-boot-sector.md](../spec/l3-boot-sector.md) 第2版の実装に伴って、自作 ROM 用の照合器具の前提が崩れたことへの測定。
**このノートは公式 ROM での測定より先にコミットする。** 以降の集計・判定はここに書いた規則に従い、
結果を見てから規則を変えない（変えるときは後続ノートで理由を残す）。
このノートより前の日付で、この問いのために公式 ROM を走らせた測定コミットは存在しない。

## 1. 背景

- 起動用セクタの受け渡しを自作 ROM に実装したあと（ブランチ `impl/l3-boot-sector`）、自作 ROM 用の照合
  `tools/conform_files.sh`・`tools/conform_load.sh` が全腕 NG になった（実装担当の報告）。
- 両器具は「自作 ROM はディスク起動しない」前提で、**最初から**ドライブ1に自作媒体を入れている
  （FILES は `make_m6fe_disk.py` の `D1.d88`、LOAD は `make_m6fi_disk.py` の `ascii.d88`。どちらも
  [l3-disk-format.md](../spec/l3-disk-format.md) 第4節のデータディスクで、(0,0,1) は全 0xFF）。
- 一方、期待値（`tools/files_conform_expected.tsv`・`tools/load_conform_expected.tsv`）を取った公式の測定
  （`tools/measure_m6fe.sh`・`tools/measure_m6fi.sh`）は、ドライブ1に**参照ディスクの複製**を入れて起動していた
  （FILES の D・E 腕だけ、フレーム 650 で D1 へ差し替え）。
- l3-boot-sector 1.3節: (0,0,1) を 0xFF で埋めた媒体では、公式は (0,0,1) を読み直し続け BASIC に届かない。
  1.4節: 起動を試みるかどうかは `IN 40` bit3 で決まり、このエミュレータではリセット時にドライブ1の媒体の有無で決まる。

## 2. 問い

公式 ROM で、自作媒体だけを使って:

- **Q1**: 自作照合と同じ構成（ドライブ1に照合の自作媒体を最初から、ドライブ2に各腕の媒体、同じ打鍵）で
  BASIC に届くか。照合の期待値と一致するか。
- **Q2**: ドライブ1を空で起動し、起動の判定が済んだあと・打鍵の前に照合の自作媒体を入れると、
  FILES・LOAD の結果が期待値の署名と一致するか。
- **Q3（参考）**: (0,0,1) のデータ256バイトだけを C9（戻り命令の符号）で埋めた照合の自作媒体を最初から入れると、
  BASIC に届き、期待値と一致するか。

予測（隠さない）: Q1 は届かない（1.3節の 0xFF 埋めと同じ形のため）。Q2・Q3 は一致すると予想するが、
期待値は参照ディスクで起動した状態で取られており、起動経路の違い（ディスクから起動したか否か）が画面に
残る可能性は否定できない。予測が外れたらそのまま報告する。

## 3. 守る線

- 公式 ROM のバイト列・逆アセンブル・ROM 内部の構造を見ない。iolog の `pc=` 欄は使わない。
- **参照ディスク（公式ディスク）は使わない。** 媒体はすべて自作（照合が使う生成器の出力と、その (0,0,1) だけを埋めた複製）。
  走らせるときは `env -u PC88_REF_DISK_DIR -u PC88_REF_DISKB -u PC88_GAME_DIR` で参照ディスクへの経路を外す。
- 画面本文は出さない。判定は署名（`tools/files_conform_check.py`・`tools/load_conform_check.py` の compare）と、
  自分で打鍵した目印（`tools/check_m6fc_markers.py`）だけ。
- データポートの値は数えるのに使わない（座標だけ取り出す）。生 iolog は作業場から出さず、残すものは
  `tools/redact_iolog.py` で伏せてから gzip する。
- 実装担当の作業ツリー（`PC88Behavior/`、ブランチ `impl/l3-boot-sector`）には触れない。測定は別の worktree
  （`PC88/tmp/b4-worktree`、main）で行い、生ログは `PC88/tmp/b4-media-work/` にだけ置く。
- 公式 ROM は `private/rom` から `*.ROM` だけを作業場へ `cp` して使う（中身は読まない。コアの状態ファイルの持ち越しを避けるため）。

## 5. 条件と腕

共通: 公式 ROM、`nice -n 10`、走ごとに媒体を新しく複製する、同時に1走だけ（他の担当の照合が同じ機械で走っているため）。
打鍵・フレーム数・署名の位置は照合器具（`conform_files.sh`・`conform_load.sh`）と同じ。

### 5.1 構成（ドライブ1の扱い）

| 構成 | ドライブ1 | 問い |
|---|---|---|
| **P** | 照合の自作媒体を最初から（`--disk`） | Q1 |
| **Q** | 空で起動、フレーム **200** で照合の自作媒体を挿入（`--insert-disk1 … --insert-disk1-at 200`） | Q2 |
| **R** | 照合の自作媒体の (0,0,1) を C9 で埋めた複製を最初から | Q3 |
| **Z** | 空のまま（目印の腕だけ） | 目印の陽性対照 |

フレーム 200 の根拠: 分岐はフレーム 13（l3-boot-sector 1.4節）で、最初の打鍵はフレーム 300。その間で、
B3 の測定で分岐後に目立つ入出力の無い位置。他のフレームは振らない。

ドライブ1に入れる「照合の自作媒体」は、FILES 腕で `D1.d88`、LOAD 腕で `ascii.d88`（各照合器具と同じ）。
ドライブ2は各腕の照合器具と同じ（FILES は `--disk2` で最初から、LOAD も同じ）。

### 5.2 腕

照合の全腕ではなく、代表を選ぶ。選び方: hybrid モードで照合器具自身が代表に選んでいる腕
（FILES: D-1・D-2・L96・L11、LOAD: I-1・I-3・I-4'・E-3）を全て採り、FILES にはドライブ1の扱いが効く腕
（D-omit: 既定ドライブ、E-3: エラー経路）と、最も単純な一覧（L1）を足す。

| 種類 | 腕 | 構成 |
|---|---|---|
| FILES | L1・L11・L96・D-1・D-2・D-omit・E-3（7腕） | P・Q・R |
| LOAD | I-1・I-3・I-4'・E-3（4腕） | P・Q・R |
| 目印 M | 打鍵: 300 で改行、500 で `CLS`＋改行、700 で `print chr$(90);chr$(81);"bt"`＋改行。1500 フレーム、`--io-log` と `--out`（画面節は目印の判定器だけが読む）。ドライブ2は無し | P（D1.d88）・Q（D1.d88）・R（D1.d88 の C9 版）・Z |

各腕2走。計 (7+4)×3×2 + 4×2 = 74 走。

## 6. 判定規則（事前に決める）

- **J-insert**（Q の走）: `event insert_disk1 frame=200 success=1` が出ていること。出ていない走は無効（結論に使わない）。
- **J-basic**（構成ごと）: 目印 M の2走とも `ZQbt` が出た → 「BASIC に届く」。2走とも出ない → 「届かない」。食い違い → 「揺れる」。
- **J-read**（構成ごと）: 目印 M の各走の (0,0,1) の READ DATA の回数（フレーム 0〜1500）。取りこぼしがあれば `-`。
- **J-match**（構成×腕）: 2走とも照合の compare が OK → 一致。2走とも NG → 不一致（不一致行数・最初の不一致行番号を記録）。
  食い違い → 揺れる。
- **答え方**:
  - Q1 = P の J-basic と、P の J-match が一致した腕の数／11。
  - Q2 = Q の J-match。**11腕全てが一致**なら「起動後に入れる直し方は、選んだ腕の範囲で公式と同値」。
    1腕でも不一致なら同値とは言わず、その腕を報告する。
  - Q3 = R の J-basic・J-read と J-match（同じ言い方）。
- 照合の期待値が参照ディスクで起動した状態で取られている以上、一致しても「参照ディスクの起動が画面に何も残さない」
  ことの、選んだ腕・選んだ署名の範囲での確認にとどまる（全腕の保証ではない）。

## 7. 止める条件（結果を見てから緩めない）

- 器具の自己検査（`--insert-disk1`・`b4_fill_boot_sector.py`）が通らない: 測定に進まない。
- Z の目印 M が2走とも `ZQbt` を出さない: 目印の器具が働いていないとみなし、J-basic を使わない（照合の J-match は報告する）。
- J-insert を満たさない走が出た: その走を無効とし、同じ腕を再試行しない（器具を疑い、報告する）。
- 白リスト（第8節）に合わない出力、画面本文・`private/` 由来の値・公式ディスク由来のバイト列が作業場の外へ出る気配: 即時停止し、
  [CLAUDE.md](../../CLAUDE.md)「汚染したとき」に従う。
- 起動時クラッシュ（rc=134）に限り、同じ走を2回まで再試行する（既存ドライバと同じ）。

## 8. 記録の白リスト（コミットするもの）

`measurements/b4-media-timing.txt` に、次の行だけ:

- 走ごと: 構成・腕・走・フレーム数・終了コード・J-insert のイベント（フレーム・成否）・compare の結果（OK/NG・不一致行数・最初の不一致行番号）
- 目印 M の走ごと: `ZQbt` の有無、(0,0,1) の読み回数、取りこぼし件数
- 構成×腕の J-match、構成ごとの J-basic・J-read
- 取得条件（器具のコミット、コアの成果物の SHA-256、媒体生成器の名前）

画面署名そのもの・生の iolog・`--out`・媒体はコミットしない。
