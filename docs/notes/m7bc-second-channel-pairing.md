# m7bc: 第2チャンネルの正体は「1バイトずれたペア」だった

測定日: 2026-08-19

## 情報境界

公式ROM一式・公式diskA（使い捨て複製）を**実行して**測定した。読んでいない。
値の突き合わせは使い捨てスクリプトの内部だけで行い、出力は**位置・件数・
一致数**に限る。値そのものは書かない（0x00 は例外的に書くが、これは
「ゼロである」という構造的事実であり、ディスクの内容ではない）。

## 1. やったこと

m7bbで「第2チャンネル（`main IN $FC` = sub OUT `$FD`）が780件目で食い違う」と
分かったので、**公式の第2チャンネルを、自作が持っているデータで説明できるか**を
ずらし総当たりで調べた。自作の`$FC`側は公式と5635件すべて一致している——
つまり**同じディスクデータを持っている**ので、公式の`$FD`側もその中のどこかを
指しているはずだ、という筋である。

## 2. 結果 — 1バイトずれ

| 候補 | 一致 |
|---|---|
| **自作`$FD`列を +1 ずらしたもの** | **2998/3000（99.9%）** |
| 自作`$FC`列を -1 | 117/2999 |
| 自作`$FC`列を +2 | 111/3000 |
| （他のずらし量） | いずれも3%台 |

**公式[i] == 自作[i+1]。** 自作は`$FD`側だけ1バイト手前を送っていた。

第60版までの実装は「偶数バイトを`$FD`、奇数バイトを`$FC`」に振り分けていた。
実測が示すのは **`$FC`に送ったバイトの「次」のバイトを`$FD`に送る**という
組み方である（`$FC[i]=D[2i+1]`, `$FD[i]=D[2i+2]`）。

訂正後、`$FD`側は **4件目以降 2997/2997 で完全一致**した。`$FC`側（適合条件1の
対象、5635件）はこの訂正で1件も変わらない。

## 3. 残っていたプリアンブル3バイト

訂正後に残った食い違いは**先頭3バイトだけ**（バルク本体の前に送る
POSITION1/2/3）。第60版までは`$FC`側と同じ値を両チャンネルへ書いていた。

- **位置1の`$FD`側 = 0x00**（実測）
- **位置2の`$FD`側 = 0x00**（実測）
- 位置3の`$FD`側は、近傍12件のどのバイトとも、直前のFDC読み出し列の末尾8
  バイトとも、0x00/0xFFとも一致しなかった → **BULK_POSITION1と同じ
  ブラックボックス介入（候補総当たり）で決める**ことにし、
  環境変数 `PC88_BULK_POSITION3_FD_CANDIDATE` を追加した
  （既定 -1 = 従来どおり`$FC`側と同じ値）。

位置1・2を実装した時点で、`main IN $FC` の一致プレフィックスは
**779 → 781** へ伸びた（残る食い違いは782件目＝位置3）。

## 4. 位置3を候補総当たりで確定した

`PC88_BULK_POSITION3_FD_CANDIDATE` を 0〜255 で総当たりし、`main IN $FC` の
一致プレフィックス長を指標にした（各候補で混成ROMを組み直して200フレーム実走）。

**当たりは1つだけだった**——255候補は781で止まり、**候補114だけが6414**
（＝自作が出す全イベント数）まで一致した。既定値に採用した。値の意味は未確定
（BULK_POSITION1と同じ扱い）。

### 効果

第2チャンネルは **6414/6414、自作が出している分はすべて一致**するように
なった（公式は6672件なので、残りの258件は「自作がまだそこまで進んでいない」
ぶんである）。

そして**起動の到達点が変わった**。第60版までの混成はファンクションキーの
案内行しか出さずポーリングで固着していたが、いまは画面に
`ID Sector Read Error` が出る——**mainが固着から抜けて、ディスクエラーの
処理まで進んでいる**。FDCコマンド数は47件のままで、SAVEにはまだ届かない。

回帰なし: 適合条件1（5635件・SHA-256）維持、`verify_l3.sh` 全項目OK、
`conform_l3.sh` rc=0。

## 5. 次の一手

`ID Sector Read Error` はmainが出したエラーである。**どの読み出しが失敗したか**
を特定するのが次。第2チャンネルが自作の出力範囲で全一致した以上、次の食い違いは
「自作がまだ出していない258件」の側——つまり**バルク後の要求への応答**にある。

## 6. この節の教訓

**「同じデータを持っているのに出力が違う」なら、データではなく組み方を疑う。**
ずらし総当たりは1回の走査で答えが出た（99.9%対3%台と、差は明確だった）。
最初にFDCの読み出し列との位置対応を試して全滅していたが、それは
**結果フェーズのバイトを混ぜた列**で比べていたためで、比較対象の作り方が
悪かった。自作の出力列（＝同じデータの別の並べ方）を相手にしたら即決した。
