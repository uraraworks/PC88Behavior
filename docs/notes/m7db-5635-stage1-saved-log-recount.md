# m7db: 起動時5635件の第1段再集計と構造selftest

実施日: 2026-08-28

`docs/notes/m7da-5635-origin-preregistration.md` の事前登録に従い、合成selftestを
先に成立させ、その後で第1段の既存保存ログだけを値なし再集計した。
**新規実走、第2段、第3段は実施していない。**

## 情報境界

- 対象は伏せ字済みの既存2走だけであり、公式ROM・公式ディスクを新たに実行していない。
- `$FB/$FC/$FD` の値列は読み出し、表示、保存、転記していない。解析器は対象ポートが
  伏せ字であることを確認し、件数、PC、ポート順、共通クロック区間だけを扱った。
- 値が必要な44セクタ全位置座標対応は、伏せ字済み保存ログからは判定不能である。
  解析不能や0件を合格へ数えていない。

## 合成selftest

`tools/check_5635_origin_structure.py` は、媒体値ではなく44セクタ連続窓内の0-based
座標だけを持つ合成JSONを検査する。陽性対照は次のm7ac確定構造を持つ。

- READ長は1/14/16/16/2セクタで合計49セクタ、除外5セクタ、選択44セクタ
- 各ポートのプリアンブル3件と定常5632件により、各3+5632=5635件
- 定常11264件はFC→FDの交互配置
- 座標列は44セクタの第2位置から末尾まで連続し、最後の1件だけ直前座標を重複

`tools/check_5635_origin_structure_selftest.sh` は外部生成フィクスチャ側で故障を注入した。

| 条件 | 期待 | 結果 |
|---|---|---|
| 正常な3+5632形 | 受理 | 受理 |
| 1件欠落 | 拒否 | 検出 |
| ポート対の入替え | 拒否 | 検出 |
| 末尾重複の欠落 | 拒否 | 検出 |
| READ長を1セクタ増加 | 拒否 | 検出 |

故障注入は**4/4検出、空振り0件**。`LC_ALL=C` と `LC_ALL=ja_JP.UTF-8` の
双方で同じ内訳となり、いずれも期待rc=0だった。これにより事前登録の
「新規走に入る前」のselftest到達条件を満たした。

## 第1段: 既存保存ログの値なし再集計

対象は `m6g-d0-boot-run1` と `run2` の伏せ字済み共通クロックログである。
既存の `analyze_bulk_trigger.py` と `analyze_second_channel_structure.py` を使い、
さらに両者の集計関数を共有する `analyze_5635_stage1.py` で2走一致を機械判定した。
3解析ともrc=0だった。

| 事前登録の条件 | run1 | run2 | 判定 |
|---|---:|---:|---|
| main側バルク総件数 | 5635 | 5635 | 一致 |
| main側PC別内訳 | 5632+3 | 5632+3 | 一致 |
| sub `$FC`総件数 | 5635 | 5635 | 一致 |
| sub `$FC` PC別内訳 | `709E`:5632、`70E5`:3 | 同左 | 一致 |
| sub `$FC` 前／中／後 | 0／5635／0 | 0／5635／0 | 一致 |
| sub `$FD` 前／中／後 | 779／5634／259 | 779／5634／259 | 一致 |
| バルク区間内の隣接FC→FD対 | 5634 | 5634 | 一致 |
| 最終境界をまたぐ隣接対 | 1 | 1 | 一致 |

最後のFCは事前登録した区間定義ではバルク中、直後のFDはバルク後に入る。このため
区間内5634対と境界をまたぐ1対を合わせ、5635件のFCすべてに直後FDが対応する。
余分FDは0件だった。

2走間ではPC別内訳、区間件数、隣接構造が一致し、さらにsubのチャンネル
`(port, pc)` 全列も一致した。従って第1段の「5635=5632+3のPC別内訳」、
「両ポートの隣接対」、「同一条件2走の件数・構造一致」はすべて合格した。

一方、H1の44セクタに対する11263/11264位置の連続一致と末尾座標重複、H3/H4の
媒体データ境界またはD88記述部との値対応は、伏せ字ログでは**判定不能**である。
これはm7daで予告した第1段の限界どおりであり、合格にも不合格にも数えない。

## 全体検査

参照ROM・ディスクの環境変数を明示的に外し、新規公式実走を防いで
`tools/run_all_selftests.sh` を実行した。新設selftestを含め、Cロケールと
UTF-8ロケールの全登録項目が期待rcどおりで、総合**rc=0**だった。公式環境を要する
3項目は既定どおり本体SKIP、自己検査のみrc=0であり、新規実走には数えない。

`tools/check_cleanroom.sh` は全項目OK、**rc=0**。追跡済み測定ログのデータポートが
すべて伏せ字済みであることも再確認した。

## 結論

第1段は合格した。5635件は既存2走の双方で5632+3のPC群に分かれ、2チャンネルは
5634の区間内隣接対と1つの境界横断対を作り、件数・構造・`(port, pc)` 全列が一致した。
値依存の全位置対応は判定不能のまま維持する。次の主実験はm7da第3段のH1/H5識別だが、
本稿では着手しない。
