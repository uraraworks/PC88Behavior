## 保存
- `save "2:x",a`（1文字の名前）も `save "2:t9prog",a` も誤りなし。前回の ERR 56 は名前の長さではなく、起動構成のせいだった。

## MERGE（メモリに行 10・20・30、ファイルに行 20・40、各行が別の値の印）
| 腕 | 結果 |
|---|---|
| merge | 行 10・20・30・40 がある。行 20 は**ファイル側の内容**（印 22）に置き換わる。行 40 が加わる。誤りなし |
| merge-program | プログラム中の `merge` でも同じ結果。MERGE の後の同じ行の続き（`poke &he015,1`）は実行されない（直接モードへ戻る） |
| merge-missing | 無いファイルは ERR 53。メモリのプログラムは変わらない |
| merge-binary | 非ASCII（`,a` なし）で保存したファイルの MERGE は1行の誤り表示。作者の候補「Sequential I/O only」の行署名と一致（自作のエラー表では 59）。メモリのプログラムは変わらない |

## CHAIN（呼ぶ側: 行10 `on error goto 90`、行20 `common …`（腕による）、行30 `dim c(2):a=7:b$="xyz":c(1)=9`、行40 `chain …`）
呼ばれる側（ファイル）: 行10 印=11、行20 `a`・`len(b$)`・`c(1)` を印へ、行40 印=44。

| 腕 | 結果 |
|---|---|
| chain（COMMON なし） | 呼ばれる側が先頭から走る。a=0・len(b$)=0・c(1)=0（変数は消える） |
| chain-common（`common a,b$`） | a=7・len(b$)=3 が渡る。c(1)=0（指定していない配列は渡らない） |
| chain-array（`common c()`） | c(1)=9 が渡る。a=0・len(b$)=0 |
| chain-line（`chain "2:x",40`） | 行 40 から走る（行10・20 は走らない） |
| chain-merge-all（`chain merge "2:x",40,all`） | 行 40 から走る |
| chain-delete（`chain merge "2:x",40,all,delete 10-20`） | ERR 5（呼ぶ側に行 20 が無い腕。DELETE の範囲の端が無いときの ERR 5 と同じ形） |
| 呼ぶ側の `chain` の後の続き | どの腕でも呼ぶ側の `poke &he015,1` は走らない |
