# l4-s1a — 事前登録の追補（測定前）

記録日: 2026-09-15
状態: 事前登録の追補、測定前

本体 [l4-s1a-text-vram-preregistration](l4-s1a-text-vram-preregistration.md)（コミット `25eb8c8`）は書き換えず、測定前に見つかった4点をここで改める。問い（Q1〜Q3）・関門の名前（G1〜G7）・判定の名前は変えない。

## 1. A3r の組み方

本体の A3r は `COLOR@(i,0)-(i,0),…` で0行目の属性を変える形だったが、次の二つの理由で問い Q1 に答えられない。

- 打鍵注入（q88measure の `ascii_to_retrok`）は `@` を打てない。英字、ASCII 32〜63 の文字、シフト表（`!"#$%&'()=+*<>?`）だけが打て、それ以外は「打てない文字を無視」の警告を出して飛ばされる。`COLOR@` は `COLOR` と続きの文字列に化ける。
- 目印 `Q7Z` はカーソルのある行に出るので0行目に乗らない。解析道具（`tools/l4_vram_probe.py`）が属性域40バイトを出すのは目印を含む行だけなので、0行目の属性の変化は見えない。加えて区間数21では、打った行と `Ok` の行で画面がスクロールし、目印が流れる。

改めた A3r は、カラーモードで区間数 N ごとに次の1行を打つ。

`CONSOLE ,,,1:CLS:FOR I=0 TO N-1:COLOR (I MOD 7)+1:PRINT "Q7Z";:NEXT` と改行

- `CLS` の後なので、0行目に目印が N 個、3桁ずつ並ぶ。行末の `;` で改行を抑える。隣り合う目印は色が異なる（1〜7を順に使う）ので、1行の中に属性の区間が N 個できる。
- N = 1, 2, 10, 20, 21。N=21 で63桁となり、1行80桁に収まる。
- 0行目は目印を含む行になるので、解析道具の出力に属性域40バイトが出る。区間の境目は3桁ごとに置かれる。
- 使う記号は `"` `(` `)` `:` `;` `+` `=` と空白・数字・英字で、すべて打てる。
- 打鍵は最長の N=21 でも約60文字なので、S の予算（`--frames 2400`、`--vram-dump-at 2300`）を使う。M の予算は使わない。

## 2. A2 の境界の腕

本体の `LOCATE 77,19:PRINT "Q7Z"` は、表示20行の最下行に印字するので、印字後の改行で画面がスクロールする。Q2 はスクロールを起こさない腕だけで判定するので、この腕は前提を崩す。

77桁目から3文字を打つと79桁目まで埋まり、次の行へ折り返す可能性がある。その後に改行と `Ok` の行が続く。表示20行でスクロールを起こさないよう、目印の下に3行以上の余裕を残して、境界の腕を `LOCATE 77,15:PRINT "Q7Z"` に改める。最下行の振る舞いは A4 で観測する。

`LOCATE 10,5` と `LOCATE 0,0` の腕は変えない。

## 3. G3（決定論性）の比べ方

- VRAM の写しは見出しを持たない生バイナリなので、ファイル全体の sha256 で比べる。
- 書き込み記録と I/O ログは、見出しに作業パスなどが入りうるので、**データ行だけ**（見出し・コメント行を除いた行）の sha256 で比べる。

先行例: m7lt の1回目は I/O ログの指紋をファイル全体で取り、見出しの作業パスのために同一条件でも必ず相違して `gate_failed` になった。

## 4. G2 への追加（打鍵の欠落）

各走の stderr に「打てない文字を無視」の警告が1件でもあれば、その走は打鍵列が欠けているものとして G2 を偽とする。1. のとおり、打てない文字は警告だけを残して飛ばされるので、警告を見なければ欠けた打鍵列のまま走が正常終了する。
