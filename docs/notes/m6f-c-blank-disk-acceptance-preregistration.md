# m6f-c — 自作の空ディスクを公式ROMが受け入れるか、空きの印と割り当ての規則 — 事前登録

記録日: 2026-09-24  
状態: 測定前

## 0. 位置づけと担当

[m6f-b 結果](m6f-b-directory-entry-fields-results.md) §8 の3の次稿である。**空の公式形式
ディスクを自作の生成器で作り、公式ROM がそこへ SAVE・FILES・LOAD を行えるかを測る。**
割り当て表の空きの印など、差分から読めなかったものは**挙動から再構成する**（`docs/PLAN.md` 5節）。

**担当の条件**（[汚染の記録](contamination-2026-09-24-blank-disk-generator.md) §3）:
本稿の事前登録・生成器・導出規則は、`tools/make_n88_blank_disk.py` と QUASI88 の
`src/image.c` を読んでいないセッション（2026-09-24、Claude Opus 5.5 の別セッション）が、
`docs/spec/l3-disk-format.md` 第1版と本稿の測定だけから作る。このセッションは、
`make_n88_blank_disk` を参照しているノート・自己検査の中身も開いていない（ファイル名だけを
`grep -l` で得た）。委譲先にも同じ禁止を渡す。

**既知の値を前提にしない。** 空きの印は 0x00〜0xFF の全値を掃引し、割り当て単位の大きさと
位置の対応は候補を全探索する。特定の値を「本命」として置かない。

### 0.1 本稿の媒体は自作である

m6f-a・m6f-b と違い、**媒体は全セクタが生成器の規則から作られる**。したがって古い値は
すべて既知で、測定後の媒体全体を読んでよい（公式ディスクの中身は含まれない）。ただし、
ROM が書いた構造（割り当て表・エントリ）と、`SAVE` で書かれる中間語のバイト列は
**ROM の出力**なので、生の像・生の差分・入出力ログはリポジトリへ入れない（m6f-b と同じ扱い）。
ノートと仕様書には、導出した規則とその値だけを書く。導出器は本体のセクタの中身を出力しない。

## 1. 問い

- **主問1 受け入れ**: 自作の空ディスクに、公式ROM がデータファイルを作って読み戻せるか。
  `FILES` が働くか。プログラムを `SAVE` して `LOAD` し直せるか。
- **主問2 空きの印**: 割り当て表のどの値を、ROM は「空き」とみなすか。
- **副問**（個別に記録し、総合判定に入れない）:
  割り当て表の3セクタの関係、割り当て単位の大きさとディスク上の位置の対応、鎖のつなぎ方と
  終端の値、エントリの中の先頭単位の欄、ディレクトリの始まり、ディレクトリがどこまで続くか、
  `FILES` が読むセクタ、本体がトラック18（管理領域）へ書かれるかどうか。

## 2. 媒体（生成器）

新しい生成器 `tools/make_m6fc_blank_disk.py` で作る（`make_n88_blank_disk.py` を import・参照・
流用しない）。

- **外形**: 公開 D88 形式。2D、40 シリンダ × 2 ヘッド、1トラックあたり 16 セクタ
  （R=1〜16）、256 バイト／セクタ（N=1）。ヘッダ・トラック表・セクタID の書き方は
  自作の `tools/make_l3_testdisk.py` と同じ（書き込み保護なし、種別 2D、倍密度、削除マーク
  なし、状態 正常）。物理トラック番号 = シリンダ × 2 + ヘッド。
- **中身の規則はこの2つだけ**:
  - 割り当て表の3セクタ (18,1,14)・(18,1,15)・(18,1,16) は、256 バイトすべて値 **V**。
  - それ以外の全セクタは、256 バイトすべて詰め物 **F**。
- 仕様書 第1版のとおり、未使用エントリは `0xFF` である。F=`0xFF` のとき、ディレクトリの
  セクタ (18,1,3) は「全エントリ未使用」になる。

**生成器は上の規則以外の中身を持たない。** 管理用セクタの初期値・予約の印などは置かない
（置くべきかどうかは測定の結果で決める）。

以下、`B(V, F)` と書く。

## 3. 打鍵と目印

- 打鍵は小文字で届く（m6f-b E1）。**打鍵の文字列は小文字で登録する。**
- 目印は `print chr$(90);chr$(81);"xx"` の形で出す。画面では `ZQ`＋2文字のタグ（＋数値）の
  行になる。打鍵のエコーには `ZQ` が連続して現れない（打鍵に大文字が無く、`chr$(90);chr$(81)`
  は字面が違う）ので、`ZQ` で始まる行は**自分のプログラムの出力だけ**である。
- 新しい判定器 `tools/check_m6fc_markers.py` は、画面節から **`ZQ` で始まる行のタグと数値**と、
  **登録した名前（大文字 `QZ7A` 等。打鍵のエコーは小文字なので混ざらない）の出現回数**だけを
  出す。それ以外の画面本文は1文字も出さない（禁止事項7）。本文を含む合成レポートで
  漏れないことを自己検査する（陰性対照つき）。
- ファイル名は `chr$` で大文字の符号を与える（A2・A6 を除く）。

## 4. 腕

起動は m6f-b と同じ（フレーム 300 で改行、刺激はフレーム 700 から）。各腕 2 走、各走は
生成器で作った新しい媒体から始める。打鍵の全文は凍結表 `tools/m6fc_frozen.tsv` に置く。

### 4.1 段階0 — 起動の関門 GB

| 腕 | 媒体 | 打鍵 | フレーム数 |
|---|---|---|---:|
| GB-FF | `B(0xFF, 0xFF)`（全面 0xFF） | `print chr$(90);chr$(81);"bt"\n` | 3000 |
| GB-00 | `B(0x00, 0x00)`（全面 0x00） | 同上 | 3000 |

目印 `ZQbt` が2走とも出た媒体を「BASIC まで届く」とする。**詰め物 F\* は、GB-FF が通れば
0xFF、通らず GB-00 が通れば 0x00。** どちらも通らなければ `m6f_c_boot_blocked` で止める。
GB は目印判定器の陽性対照を兼ねる。

### 4.2 段階1 — 空きの印の掃引 SW

V = 0x00〜0xFF の 256 腕（`SW-00`〜`SW-FF`）。媒体 `B(V, F*)`。フレーム 8000。打鍵は全腕共通:

```
10 on error goto 90:f$=chr$(81)+chr$(90)+chr$(55)+chr$(65)
20 open f$ for output as #1:print #1,"x":close #1
30 open f$ for input as #1:input #1,a$:close #1
40 if a$="x" then print chr$(90);chr$(81);"ok":end
50 print chr$(90);chr$(81);"ng":end
90 print chr$(90);chr$(81);"er";err;erl:end
run
```

各走を目印で `ok` / `ng` / `er`（ERR と ERL を記録）/ `none`（目印なし）に分ける。

### 4.3 段階2 — 受け入れと割り当て

**V\*** は §5 C1 が決めた値（空きの印の集合の最小値）。媒体は `B(V*, F*)`（A6 だけ詰め物を変える）。
`ZQ"xx"` は `print chr$(90);chr$(81);"xx"` の略記。90 行は §4.2 と同じ誤り処理。

| 腕 | 打鍵（要旨） | フレーム数 | 狙い |
|---|---|---:|---|
| A0 | （起動の改行だけ） | 8000 | 陰性対照 |
| A1 | `10 on error goto 90:files:ZQ"ok":end` ＋ 90 行 | 8000 | 空の媒体で FILES |
| A1b | `QZ7A` を作って `"x"` を書き、`files`、`ZQ"ok"` ＋ 90 行 | 8000 | FILES に名前が出るか |
| A2 | `10 ZQ"ld"` と `save"q7l"` → `new` と `load"q7l"` → `run`（区間を分けて打つ） | 12000 | プログラムの SAVE・LOAD |
| A3 | `QZ7B` に 250 件の記録を書いて読み戻し、不一致数を `ZQ"rb"` で出す | 30000 | 大きいファイル、鎖と単位 |
| A4-1・A4-3・A4-6・A4-10・A4-17 | A3 と同じで記録数 n を 1・3・6・10・17 にしたもの | 12000 | 終端の値 |
| A5 | `Q001`〜`Q400` を順に作る（空のまま閉じる）。誤りで止まれば `ZQ"er"` と ERR・件数 | 60000 | ディレクトリの広がり |
| A5b | A5 と同じだが、作るたびにすぐ `kill` する | 60000 | 削除した枠の再利用と広がり |
| A6 | A2 と同じ（媒体は `B(V*, F')`、F' は 0xFF／0x00 のうち F\* でない方） | 12000 | 詰め物への依存、ディレクトリの始まり |

A3・A4 の記録は `right$(str$(100000!+i),5);string$(120,"v")`（5桁の通し番号＋`v` 120個）。
**1記録は1セクタより短いので、本体のどのセクタにも完全な通し番号が少なくとも1つ入る。**
これでセクタのファイル内の順序を中身から決める。

## 5. 導出規則（測定前に固定する）

用語:
- **書いたセクタ** = 刺激の後に WRITE DATA が対象にした (C,H,R)（入出力ログの FDC コマンドから。
  複数セクタの転送は R からデータ長/256 個）。
- **本体のセクタ** = 測定後の媒体で、`[0-9]{5}v` の並びを含むセクタ。順序はその中の最初の
  完全な通し番号で決める。
- **線形番号** L = (C × 2 + H) × 16 + (R − 1)。
- **割り当て表の値** T\_s[k] = 測定後の媒体のセクタ s ∈ {(18,1,14),(18,1,15),(18,1,16)} の
  k バイト目。**変わった位置** P = { k : T[k] ≠ V\* }。

**C0 詰め物**: §4.1 のとおり F\* を決める。

**C1 空きの印**: 2走とも `ok` だった V の集合 Vfree。1個なら `derived`、2個以上なら `ambiguous`
（集合を記録し、V\* はその最小値）、0個なら `not_found`。**2走で分類が食い違った V が1つでも
あれば、その V を Vfree から外し、`run_disagreement` として列挙する。**

**C2 受け入れ**（主問1）: 次の4つがすべて2走で真なら `accepted`、そうでなければ `not_accepted`。
- A1 に `ZQok`。
- A1b に `ZQok`、かつ名前 `QZ7A` の出現が1回以上。
- A2 に `ZQld`（読み込んだプログラムが走った）。
- A3 に `ZQrb` が出て、その数値が 0。

**C3 割り当て表の3セクタ**: A3 で、3セクタの変わった位置と新しい値がまったく同じなら
`replicas_identical`。違えば位置ごとの違いを記録する。以下 C4〜C7 は (18,1,14) を T とする。

**C4 単位の大きさと位置の対応**（A3）: S ∈ 1〜32、整数 o について、本体のセクタの集合
{ ⌊(L − o) / S⌋ } が P と一致し、かつ各 k に属する本体のセクタが S 個以下である組 (S, o) を
すべて挙げる（o は 0 ≤ k ≤ 255 を満たす範囲で探す）。1組なら `derived`（「割り当て番号 k の単位は
線形番号 k·S+o から S セクタ」）、2組以上なら `ambiguous`、0組なら `not_found`（本体の線形番号の
並びと P を記録）。

**C5 鎖**（A3、C4 が derived のとき）: 本体の順序で並べた単位の番号の列 k₁, k₂, …, kₘ について、
i < m のすべてで T[kᵢ] = kᵢ₊₁ なら `link_is_next_index`、違えば `link_other`（組を記録）。
最後の単位の値 T[kₘ] を **終端の値** e とする。

**C6 終端の値の規則**（A3・A4 の6腕、C4 が derived のとき）: 各腕の e と、最後の単位のうち
**書いたセクタ**の数 u を記録する。
- `end_constant`: 6腕の e がすべて同じ。
- `end_plus_used_sectors`: e − u が6腕で同じ（u が2種類以上あるときに限る）。
- `end_other`: どちらでもない。

**C7 エントリの先頭単位の欄**（A3・A4）: 測定後の媒体のトラック18（割り当て表の3セクタを
除く）で大文字の名前 `QZ7B` を探し、その位置をエントリの先頭とする。エントリの 10〜15
バイト目のうち、値が k₁ と等しい位置 j が全腕で同じ1か所なら `derived`。10〜15 バイト目の
値は各腕について記録する。

**C8 ディレクトリの始まり**: A1b・A3 のエントリの (C,H,R, セクタ内の位置) と、A6 の
エントリの位置（小文字の名前 `q7l`）。A1b・A3 で一致すれば `derived`（A6 は別に記録し、
一致・不一致を書く）。

**C9 ディレクトリの広がり**（A5・A5b）: 測定後の媒体のトラック18から、名前 `Q`＋3桁＋`0x20`×5
（未削除）と、`0x00`＋3桁＋`0x20`×5（削除済み、仕様書 1.2）のエントリを集め、番号順の
(C,H,R, 位置) の列を作る。
- A5b の列が1か所に留まれば `deleted_slot_reused`（削除した枠を使い直す）と記録する。
- 各ループについて、`ZQer` で止まり、かつ止まった時点の割り当て表に「段階2のどれかの腕で
  一度でも割り当てられた番号（P の和集合）」のうち値が V\* のものが残っていれば
  `directory_bound`。このときエントリを受けたセクタの集合を**ディレクトリの広がり**とする。
- A5・A5b のどちらも `directory_bound` でなければ `lower_bound_only`（受けたセクタの集合を
  下限として記録）。400 件を作り切った場合も `lower_bound_only`。
- A5 で割り当て表が変わった位置の数も記録する（空のファイルが単位を取るか）。

**C10 FILES が読むセクタ**: A1 で刺激の後に READ DATA が対象にした (C,H,R) の、初出順の列。

**C11 本体の位置**: 段階2の各腕で、本体のセクタがトラック18に1つでもあれば `body_in_track18`、
無ければ `body_outside_track18`。あわせて A3 の k₁（最初に割り当てられた番号）を記録する。

2走で結果が一致しない導出は `ambiguous` とする（C1 は上記の扱い）。

## 6. 関門

- **G1 全自己検査**: `run_all_selftests.sh` rc=0。**腕の前に親が1回だけ通す**（測定ドライバの
  中では回さない）。**ただし `tools/harness/disk2_selftest.sh` と
  `tools/harness/insert_disk2_selftest.sh` を除外する。** この2本は `make_n88_blank_disk` を
  参照しており（ファイル名の grep で確認、中身は開いていない）、回すと禁止した生成器を
  実行することになるため。除外は環境変数 `PC88_SELFTEST_EXCLUDE` で行い、除外した事実を
  表に出す。登録に無い名前を除外しようとしたら NG にする（打ち間違いで黙って通らないように）。
- **G2** クリーンルーム検査（`check_cleanroom.sh`）。
- **G3** 差分器・生成器・目印判定器の自己検査。
- **G4 陰性対照**: A0 の2走で WRITE DATA が0件、媒体が生成直後と同じ SHA-256、目印なし。
- **G5 生成器の決定性**: 同じ (V, F) で2回作った媒体の SHA-256 が一致する。
- **G6** 生の像・差分・入出力ログはリポジトリ外だけに置く。
- **G7 凍結**: 凍結表 `tools/m6fc_frozen.tsv` を照合器 `tools/check_m6fc_preregistration.py` で
  事前登録・導出器・判定器と照合してから走らせる。

## 7. 判定名

- `gate_failed`
- 各導出: `derived` / `ambiguous` / `not_found`（C2・C3・C5・C6・C9・C11 は上の固有名）
- 総合:
  - `m6f_c_boot_blocked`: GB が両方とも通らない。
  - `m6f_c_no_free_mark`: C1 が `not_found`。
  - `m6f_c_blank_disk_accepted`: C1 が `derived` か `ambiguous`、かつ C2 が `accepted`。
  - `m6f_c_blank_disk_not_accepted`: C1 が空でないが C2 が `accepted` でない。

C3〜C11 は個別に記録し、総合判定に入れない。

## 8. 行き先

- `m6f_c_blank_disk_accepted`: 空きの印・割り当ての規則・ディレクトリの始まり（と、得られれば
  広がり）を `docs/spec/l3-disk-format.md` **第2版**に起こす。C9 が `lower_bound_only` なら、
  次稿 m6f-d で**生成器が仕様書どおりに作ったエントリ**を候補セクタに置き、公式ROM が名前で
  見つけるかで広がりを測る（あわせて、自作のエントリ・割り当て表を公式ROM が読めることの検証になる）。
- `m6f_c_blank_disk_not_accepted`: C11（本体が管理領域へ書かれたか）と各腕の目印を記録し、
  予約の印を掃引する追補を置く。
- `m6f_c_no_free_mark`: 一様な表では空きを作れない。位置ごとに値を変える掃引の追補を置く。
- `m6f_c_boot_blocked`: 起動の経路を測る追補を置く（起動用セクタの中身は規則で作る）。

## 9. この測定で決まらないこと

- 管理領域のうち、本稿の操作が触れないセクタの意味。
- 予約の印（管理領域の単位を ROM が避ける印）が要るかどうかは C11 で見えるが、どの値を
  使うべきかは決めない。
- エントリの 10〜15 バイト目のうち、先頭単位以外の欄の意味。
- 2D 以外の媒体。
