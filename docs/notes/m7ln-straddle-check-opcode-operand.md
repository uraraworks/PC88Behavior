# m7ln: 跨ぎ検査がオペコードとオペランドの間の境界を見逃す穴を直した

作成日: 2026-09-11

## これは自作生成器（`src/l3_service/make_subrom.py`）の修正である

**仕様（`docs/spec/`）の内容は変わらない。** [m7lc](m7lc-generator-window-gate-fixed.md)で見つけて記録だけにしていた
「2つ目の穴」を直した。

## 何が穴だったか

アセンブラは`call`・`jp`・`jr`系・`djnz`・`ld hl,ラベル`を、**オペコード（1バイト）とオペランド（1〜2バイト）の
別々の`instr_spans`**として記録する。`find_fetch_window_straddles()`はオペランドの区間だけを見て
「オペランドの先頭 < 境界 < オペランドの末尾」なら跨ぎと判定していたので、**境界がちょうどオペコードと
オペランドの間に来ると「跨ぎ0」と判定した。** 整列パディングはその形を直さなかった。

m7lcで窓の関門を「区間の終了位置」まで見るように直したので、この形は**ビルドが失敗する側**に倒れて
いた（安全側）。**ただ、整列パディングで自動的に直るべきところが直らない状態だった。**

## 何を直したか

**フィックスアップの位置でちょうど終わる区間（＝オペコード）の先頭を命令の先頭とし、オペコードから
オペランドの末尾までを1つの命令として境界と突き合わせる。** オペコードが1バイトだと決め打ちにはしていない
（今の実装では全部1バイトだが、前置きのある命令が加わっても同じ判定になる形にした）。

## 手順と結果（m7lcと同じ手順）

| 段階 | 内容 | 結果 |
|---|---|---|
| 直す前 | 陽性対照6を「跨ぎ検査そのものがこの形を拾うこと」を確かめる形に書き換えて実行 | **赤**（`DIRECT_NG: 跨ぎ検査がオペコードとオペランドの間の境界を拾わない`） |
| 直した後 | 陽性対照1〜6 | **全項目OK**（6は跨ぎ検査が拾い、`build()`も止める） |
| 直した後 | 既定ビルドのサブROMを直す前の控えと`cmp` | **バイト一致** |
| 直した後 | 変種フラグを1つずつ立てた全ビルド（21個）と既定の全長 | **直す前とすべて同じ** |

**出力は1バイトも変わらない。** 既定（2033）も変種（最大2041）も窓（2048）の手前で終わるので、今のコードには
この形の跨ぎが無いからである。**変わったのは、今後この形を踏んだときに、整列パディングで直るようになった
ことだけである。**

| 直した後 | `tools/run_all_selftests.sh` | **rc=0**（全スクリプトOKまたはSKIP） |

## 陽性対照1も、偶然に頼らない形にした

陽性対照1は「幅2以上の最初の`instr_spans`」を命令として選び、その先頭を**跨がない**境界の陰性対照にしていた。
**今回の修正でオペランドの先頭は「命令の途中」になる**ので、選んだ区間がたまたま`call`等のオペランドだと、
陰性対照にならない（跨ぎありと出る）。**直した後も陽性対照1が通ったのは、最初の幅2以上の区間がたまたま
フィックスアップではない命令だったからである。** コードの並びが変われば、落ちるか、意味を失う。
**陽性対照5と同じく、フィックスアップのオペランド位置を候補から外した。** 外した後も全項目OK。

## 情報境界

公式ROM・公式ディスク・`private/`の内容には触れていない。扱ったのは自作コードの命令区間・フィックスアップの位置・
全長・既定ROMのバイト一致だけである。
