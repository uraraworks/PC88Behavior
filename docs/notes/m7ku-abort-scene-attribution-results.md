# m7ku: 自作の`FDC_ABORT`は書き込み経路・LOAD経路では1度も立たない（判定SA1）

実施日: 2026-09-10
事前登録: [m7kt](m7kt-abort-scene-attribution-preregistration.md)（**測定前に単独コミット済み**。
場面・指標・段階0・判定規則・線は本稿で動かしていない）

## 主判定

> **SA1。** **W・L1・L2のすべてで、`READ DATA`直後に`FDC_ABORT`が立った件数は0。**
> **したがって`m7ks`の(b)は消え、(a)が残る。**

**ただし本稿はそこで終わらない。** **SA1は、`m7ks`が立てた(a)と(b)の二択
そのものに穴があることを示す。** 下の「SA1が開けた穴」を参照。

## 段階0（すべて満たした。これを満たさなければ主判定へ進まない約束だった）

| 項目 | 結果 |
|---|---|
| 1. 非侵襲性（印を除けばI/O列が一致） | **真。70本中70本一致** |
| 2. 陽性対照Pで`read_data`が1件以上 | **真。12件** |
| 3. 偽陽性が無い（独立2回で全件数一致） | **真。4場面とも一致** |
| 4. 旗オンのビルドが通る | 真（コード2047バイト。生成器自身の関門を通過） |

**非侵襲性の比較方法**: 印を足すとコードが8バイト伸びるので、
**`seq`・`clock`・`frame`・`pc`は必ずずれる。** ずれてよい列を落とし、
**`(cpu, kind, port, value)`の並びだけ**をSHA-256で突き合わせた。
**sub側の`OUT $F9`（診断ポート）は両側から除いた。**
**この手当てをせずに素の`cmp`で比べていれば、非侵襲性は偽と出て、
測定はここで止まっていた。**

## 主表（`on`側。値は1つも含まない。件数のみ）

| 場面 | total | in側 | out側 | タイムアウト由来 | **`READ DATA`直後** | `$F9`総数 |
|---|---|---|---|---|---|---|
| **W**（書き込み・`SAVE`） | **0** | 0 | 0 | 0 | **0** | 0 |
| **L1**（LOAD混成） | **0** | 0 | 0 | 0 | **0** | 0 |
| **L2**（LOAD既存） | **0** | 0 | 0 | 0 | **0** | 0 |
| **P**（陽性対照・読めない媒体） | **12** | 12 | 0 | 0 | **12** | 12 |

**W・L1・L2では`$F9`のイベントが1件も無い**——**IN側でもOUT側でもなく、
タイムアウトでもない。** **`FDC_ABORT`はこれらの場面で1度も立っていない。**

**Pの12件は、`m7ke`・`m7kg`の「同じ対象について4回・対象は3つ」＝12送信単位と
一致する。** **自作サブROMが1単位につき1回だけ読んで諦めている**
（`m7ju`・`m7kg`）ことの、別の側からの確認になっている。

## 判定の意味（言えることと、言えないこと）

**言えること:**

- **(b)は消えた。** 自作の`FDC_ABORT`は、**書き込み経路・LOAD経路では
  「読み出しの失敗以外の場面で立つ」どころか、1度も立っていない。**
  **`m7kt`が測る前に書いた見立て——`SENSE INTERRUPT STATUS`の2バイト目の
  ような正常な場面で立っているのではないか——は、外れである。**
  見立てを合格条件にしていなかったので、外れても測定は成立している。

**言えないこと:**

- **(a)が証明されたわけではない。** **本稿は自作の実装を測っており、
  公式の振る舞いは1件も測っていない。** `m7kt`が先に引いた線のとおり。
- **「`FDC_ABORT`は正常な場面では立たない」と一般化しない。**
  **測ったのは4場面だけ**である。

## SA1が開けた穴——`m7ks`の二択には第3の枝がある

**ここが本稿のいちばんの収穫である。**

`m7ks`は「実装前が適合だった」ことから、**(a)公式は粘っていない**か
**(b)自作の旗が場面を取り違えている**かのどちらかだ、と書いた。
**SA1は(b)を消した。** **しかし、同時に(a)の側の足場も崩している。**

**理由**: **`FDC_ABORT`がW・L1・L2で1度も立たないなら、
`m7ks`の再試行ループはそれらの場面で1度も回っていない。**

- `m7ks`の2版はどちらも**「`FDC_ABORT`が0なら即座に打ち切る」**形である。
- 再試行版の**最初の`READ DATA`は、実装前と同じパラメータで発行される**
  （パラメータは`REQ_HDR`のメモリから取る。ループの導入で変わらない）。
- **同じ要求なら同じ結果になるので、最初の読み出しで旗が立たない。**
  **立たなければループは1度も回らない。**

> **つまり、W・L1・L2のストリームを変えたのは「再試行したこと」ではない。**
> **再試行は起きていない。**

**したがって、`m7ks`が観測した3つの回帰は「公式が粘っていない証拠」では
ない。** **回帰は、再試行の意味論とは別の何か——(c)——によって起きている。**

**(c)が何かは本稿では測っていない。** 候補は次のとおりで、**どれも未検証で
ある**:

- **コードの位置とサイズが動いたこと。** この実装はフェッチ窓の余白が
  厳しく（`m7ks`は「ルーチン内蔵版とRAM共有フラグ版はフェッチ窓に
  収まらなかった」と書いている）、**8バイトの挿入で後続の配置がずれる。**
  **ただし本稿の器具も8バイト足しているのに70本すべてでI/O列が一致した**
  ので、**サイズ増そのものが自動的に致命的なわけではない。**
- **レジスタの使用。** 絞り込み版は`ld_c(0x09)`でCを書いている。
  **なお「Cレジスタが目的シリンダを壊す」という筋は誤りである**——
  `_general_read_request`の`# A = C のまま`の`C`は**FDCコマンドの
  Cパラメータ（目的シリンダ）**であって**Z80のCレジスタではない**。
  シリンダはAに載り`REQ_HDR + 4`へ置かれる。**Cが他の用途で生きているか
  どうかは、まだ確かめていない。**
- 一律版と絞り込み版で**呼び出し元が違うのに回帰が同一だったこと**
  （`m7ks`の追記）は、**共通の原因が両版にあることを示唆する**が、
  それが上のどれかは決まらない。

## 次に測ること

1. **(c)を切り分ける。** `m7ks`の絞り込み版を**診断印つきで再ビルドし、
   場面Wで印を数える。** **`read_data`が0なら、再試行が1度も回らないまま
   ストリームが変わったことが実測で確定する**——(c)の存在が測定で立つ。
   **これは新しい測定なので、別稿で事前登録する。**
2. **(c)の正体が分かったら、`m7kr`の合格条件3をもう一度試せる。**
   **回帰が再試行の意味論と無関係なら、それを避ける実装が書ける可能性が
   ある**——`m7ks`が「行き止まり」と呼んだものは、**行き止まりではなく
   別の障害物だったかもしれない。**
3. **(a)は依然として未測定である。** 公式が書き込み経路・LOAD経路で
   `READ DATA`を何件出すかは、**まだ1度も測っていない。**
   **`m7ks`と第188版の追記は、それを測ったかのように読める書き方に
   なっていたので、本稿で訂正する。**

## 測定の条件

- **場面は作り直さず、既存の適合テストをそのまま計装した。**
  この測定は「`m7ks`が回帰させた条件と**同一**であること」が要なので、
  条件を組み直すと同一性が主張になってしまう。混成ROMを作る経路は
  `build_mixed_rom`の1箇所に集約されていたので、環境変数1つで全場面へ届く。
- 実行は`off`（印オフ）・`on`（印オン）・`off2`・`on2`の**4回を逐次**。
  **`off`と`off2`、`on`と`on2`は出力がバイト一致した。**
- **`off`の総合判定は「適合」**で、NGは**3件**（いずれも既知の自己検査
  フィクスチャ系。`m7ks`が「実装前」として報告したのと同じ内訳）。
  **SKIPは1件**（`PC88_REF_DISKB`未設定。**本測定の4場面はdiskBを使わない**）。
- **`on`の総合判定は「不適合」**だが、増えたNGは**2件**で、
  **どちらも器具自身を検出したもの**である——
  `自己検査f: DISK.ROMが自作サブROM(通常版)と一致しない`と、
  それを含む`混成ROMディレクトリ構築の自己検査`。
  **本体の判定は1件も落ちていない。**
  **これは器具が正しく見えていることの確認でもある**（印つきROMを
  「通常版と同じ」と黙って通していたら、そちらのほうが問題だった）。
- **`混成入口区間の最初のエラー結果`は`off`・`on`とも「コマンド4件目」**で、
  **`m7ks`が「実装前」として報告した値を再現している**（公式は1件目）。

## 開示（隠さず書く）

**1. 並行実行の干渉を起こした。`m7ks`と同じ型である。**

委譲先が「待機します」で報告を終えたのを**「止まった」と判断して測定を
引き取った**が、**実際には待っていただけ**で、あとから**自分の測定を再開
した。** **同じ作業ディレクトリへ同時に書き込む`conform_l3.sh`が3本**走る
状態になった。

- **原因はこちらの段取りである**——**引き取る前に委譲先を明示的に停止して
  いなかった。** `m7kt`の委譲指示には「実行中ですで報告を終えない」と
  書いたが、**「終えられたら親は何をするか」を書いていなかった。**
- **対処**: 委譲先を停止し、走行中のプロセスを全部落とした。
  **最初の`pkill`はドライバのパターンに当たらず生き残り、新しい実行を
  産んでいた**ので、`kill -9`で確実に落としてから確認した。
- **汚染された`on`は、中身を見ずに破棄した。** 覗いてから「使えそうだ」と
  判断すると、古い成果物が結果を偽る型を踏む。
- **本稿の数字は、すべて干渉を止めたあとに単独で採り直したものである。**
  `off`だけは衝突が始まる前に単独で完走していたので、そのまま使った
  （開始・終了時刻で単独だったことを確認した）。

**2. 事前登録の合格条件2（`tools/run_all_selftests.sh`がrc=0）は満たせない。
ただし、それは本稿の変更が原因ではない。**

**`run_all_selftests.sh`は`HEAD`（`8472ac1`）の時点で既にrc=1**である。
検証用のgit worktreeを`HEAD`に立てて確かめた。**4本が、自作サブROMの生成
コードサイズをハードコードした期待値（`2042`系）と現状（`2039`）の食い違いで
落ちている。**

- `tools/search_error_response_candidate_selftest.sh`
- `tools/response_ready_rom_selftest.sh`
- `tools/early_response_rom_selftest.sh`
- `tools/verify_error_response_bit6_attribution.sh`

**合格条件2を「満たした」と書き換えず、満たせないものとして開示する。**
**代わりに、より決定的な合格条件3（既定ビルドのサブROMが変更前と
バイト一致すること）が真であることを確認した**——`git show HEAD:`から
旧版を出し、空ディレクトリへ両方をビルドして`cmp`で一致
（8192バイト・コード2039バイト）。**既定の成果物が1バイトも変わらないので、
適合テストを測り直さなくても悪化しないと言える。**

**なお、門が赤いまま放置されていること自体は別の問題である**——
**そこを通る新しい回帰が既存の赤に紛れる。** 本稿では直さない
（期待値を現状に合わせて書き換えれば緑になるのは当たり前で、それは検査に
ならない。縮んだ理由が正当かを先に確かめる必要がある）。

**3. 委譲先が「実行中です」で報告を終えたのは3回**（器具の実装1回・測定2回）。
**判定に必要な集計は、すべて親セッションが自分で採った。**

## 情報境界

公式ROMのバイト列、公式ROMの逆アセンブル、`private/`の内容は読んでいない・
出力していない。**公式ディスクのイメージを直接読んでもいない。**
`private/rom`・`private/disk`は**環境変数としてパスを渡しただけ**である。
記録したのは**件数・真偽・FDCコマンドの復号種別名・適合テストの判定名**
だけである。**データポート値・シリンダ値・セクタ番号・結果ステータスの生の値・
診断ポートへ書いた値・時刻・frame番号・画面本文は、表示も転記もしていない。**
集計ツールは出力にこれらが現れないことを自己検査で確認しており、
**その漏れ検査自体の検出力も陰性対照で確かめてある。**
生ログ・使い捨てのドライバはリポジトリ外（`PC88/tmp/m7kt-work/`）に置き、
コミットしない。
