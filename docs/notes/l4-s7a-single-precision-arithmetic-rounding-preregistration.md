# l4-s7a — 単精度四則演算(+-*/)の丸め規則、事前登録

記録日: 2026-09-20
状態: 事前登録(測定前)。

## 位置づけ

l4-s6a〜l4-s6f は SIN/COS/TAN という超越関数の範囲縮約・多項式評価の
「中にある」乗算を通じてしか単精度乗算の丸めを見ておらず、l4-s6fでは
候補M8(多項式評価の乗算も正しい丸めにする)がM7より**悪化する**腕
(`cos(44)`・`tan(44)`)が初めて見つかった。「単精度乗算の丸めが
正しい/粗いの二値で全域を説明できる」という仮説そのものが崩れ始めて
おり、超越関数経由でこれ以上丸め方を逆算するのは筋が悪い
(`docs/notes/l4-s6f-full-single-precision-rounding-results.md`
「結論」節)。

本ノートは超越関数を経由せず、**単精度の四則演算そのもの**を
`print cdbl(a op b)` という直接の式で測る。加算・減算・除算は
これまで一度も直接測ったことがなく、`tools/l4_mbf_oracle_v2.py`が
GW-BASIC(MIT公開ソース)の命令単位の読解から「正しい丸め」と結論して
いるだけで、N88-BASIC(PC-88版)の実機で裏を取ったことがない。

## 候補(手順1)

`tools/l4_mbf_oracle_v9_s7a.py`(新規)に実装。全て「厳密値をFractionで
求め、24bit仮数へ1回だけ、以下いずれかの規則で丸める」形。

| 候補 | 規則 | v2の対応箇所 |
|---|---|---|
| `even` | 正しい丸め・偶数丸め(round-half-even) | 加減除はv2の既定(`gw_binop`)と数学的に等価。乗算はv7_m7が範囲縮約の乗算に導入した規則と同じ |
| `away` | 正しい丸め・0から遠い側(tie相当は常に切り上げ) | v2のREP01(`_round_half_away_mag`、定数リテラル読み取り専用)と同じ丸り方を四則演算の結果に適用したもの |
| `trunc` | 切り捨て(丸めをしない) | 対照(丸めが起きているかどうかの検出用) |
| `coarse8` | ガードバイト方式の粗い丸め。厳密値を(24+8)bit精度へ**スティッキー無しで**切り捨て、残ったガードバイトの上位3bitだけで$ROUNS/$ROUNM同様のtie判定をする | 実際の`$FMULS`(v2の`gw_mul_single`、48bit積の下位16bitをスティッキー無しで破棄)の破棄幅を8bitに一般化し、乗算以外の演算にも仮説として適用したもの |
| `fmuls`(乗算のみ) | v2の`gw_mul_single`をそのまま呼ぶ、既存の実機$FMULS命令単位モデル | l4-s6e/l4-s6fが検証してきたのと同じモデル |

`tools/l4_mbf_oracle_v9_s7a_selftest.sh`で候補間の関係(tieでeven/away
が割れる、false_tieでcoarse8だけ割れる、fmulsが既存v2実装の直接呼び出し
と一致する等)を確認済み(公式ROM不使用)。

探索(scratchpad、コミット対象外)では、乗算について`coarse8`と`fmuls`
が探索した範囲内(4桁以内のオペランド)で常に一致した。理論上は
破棄幅が8bitではなく16bitなので探索範囲外では違いうるが、本測定の
腕では区別できない(申し送り事項として結果ノートに書く)。

## オペランドの選び方(手順2)

`tools/l4_mbf_oracle_v9_s7a.py`の`predict_all()`を使い、候補同士が
割れる(または割れない、対照用)オペランド対を、7桁以内の`!`付き単精度
10進定数の総当たり探索(scratchpad、コミット対象外)で選んだ。腕の
分類:

- `tie`: `even`と`away`が割れる(厳密値が丁度tie、正しい丸めの
  偶数丸め/0から遠い側のどちらかを判定)
- `false_tie`: `even`==`away`(真にtieではない)だが`coarse8`だけが
  割れる(粗いガードバイト方式が偽のtieを作る場面の検出)
- `trunc_only`: `trunc`だけが他の候補全てと割れる(丸めが起きている
  ことそのものの対照、候補間の判別力は無い)
- `control`: 厳密値に誤差が無く、候補全てが一致する(器具の対照)

**除算には`tie`腕が無い。** 除算の商は分母の仮数が2の冪でない限り
2進で有限小数にならないため、7桁以内の10進定数オペランドで厳密な
tie(丁度半分)を作る対は、4桁までの総当たり探索(乗算のときと同じ
探索コード)で1件も見つからなかった。これは解析的にも妥当
(商が2進で有限桁になる=分母の仮数が分子の仮数を割り切るという
特殊な組み合わせが必要で、さらにその上で丁度半ULPになる必要がある
ため、無作為な10進定数では極めて稀)。本ノートでは除算のtie判定は
対象外とし、`false_tie`腕を3本(加減乗より1本多く)に増やして補う。
除算のtieを狙って作る(分母を意図的に構成する)追加測定は次回に
持ち越す。

### 腕数について(規模を縮小したことの記録)

当初の見積もり(演算ごと10〜15腕、合計50腕程度)に対し、本ノートは
24腕にとどめた。理由: (1)候補が数学的に4〜5種類に絞られており、
`tie`・`false_tie`・`trunc_only`・`control`の4分類を各演算で1〜2腕
ずつ押さえれば判別力は確保できる(候補同士の関係は腕を増やしても
質的に変わらない)、(2)測定1腕あたり2走(決定論性の確認)が要るため、
腕数と走行回数・器具負荷が比例する。24腕なら48走で従来のl4-s6e/f
(21腕・42走)と同程度に収まる。腕数を絞った代わりに、腕の選定基準
(tie/false_tie/trunc_only/controlの4分類)を明示し、判定の解像度は
落とさない設計にした。

## 測定方法(従来と同一)

`l4-s3a`以来の条件・器具をそのまま踏襲する。

- 公式ROM一式、ディスク無し、コア既定N88 V2。起動settleは
  `--type-at 300 --type '\n'`、実打鍵の開始は`--type-at 700`。
- 1文字あたりの反映フレームは既定(hold+gap=8フレーム/文字)。
- 各腕は打鍵の前(写し690固定)と、打鍵と実行が終わった後(表の
  写し(後))に`--vram-dump`で写しを取り、`tools/l4_vram_probe.py`の
  差分で出力行を特定する。`tools/l4_s4a_float_classify.py`
  (既存、数字・記号のみを許すNUMERIC_CODES集合)で`numeric_output`
  判定と出力セル列挙を行う。
- 各腕2走(決定論性G3の確認)、公式ROMは環境変数`PC88_REF_ROM_DIR`
  (測定コマンドごとに指定、値は`private/rom`)経由で与える。

## 関門(G1〜G6、l4-s6e/fと同一の枠組み)

- G1 器具の自己検査: `tools/l4_mbf_oracle_v9_s7a_selftest.sh`・
  `tools/check_cleanroom.sh`・従来のharness selftest群
- G2 取りこぼし0・打てない文字の警告0: 全走`rc=0`
- G3 決定論性: 24腕全てでrun1/run2の写しsha256が一致
- G4 陰性対照: 起動settleのみの走を流用
- G5 陽性対照: `print 7717\n`を流用
- G6 予測表の固定: 本ノート(事前登録)のコミット以後、表を変更しない

## 判定

- 24腕それぞれについて、公式出力が`even`/`away`/`trunc`/`coarse8`
  (乗算は`fmuls`も)のどれと一致するかを記録する。
- 演算ごとに集計する: `tie`腕で`even`と`away`のどちらが勝つか
  (round-half-evenかround-half-awayか)、`false_tie`腕で`coarse8`が
  実際に的中するか(=粗いガードバイト方式が加減乗除全てに一般化
  できるか、乗算以外では的中しないか)、`trunc_only`/`control`腕は
  「丸めが起きるかどうか」の一貫性チェックとして使う。
- 4演算全てで`even`が勝ち`coarse8`が的中しなければ、「加減乗除とも
  正しい丸め・偶数丸め」という単純な結論を支持する(v2の既存想定
  そのものが確認されたことになる)。
- 演算によって勝つ候補が割れれば(例: 乗算だけ`coarse8`/`fmuls`が
  勝ち、加減除は`even`が勝つ)、l4-s6e/fの構造(範囲縮約の乗算だけ
  粗い丸めではない)と整合する形で報告する。
- 外れが残れば深追いせず、外れた腕の性質(tie/false_tie/どちらの型か)
  を記述して止める。

## 手順5: 既存実装`src/l4_basic/mbf_single.asm`への申し送り(実装は変えない)

測定結果が出たあと、`src/l4_basic/mbf_single.asm`のMBF_MUL(GWの粗い
丸めを意図的に忠実再現する設計、l4-s6fのdocstring既述)と、本測定で
特定された規則との異同を**予測器上で**指摘する(実装コードは変更
しない)。既存の適合検査l4-c3はこの丸めモードを弁別する腕を持たない
ことがl4-s6fで既に確認済みなので、本測定でも同じ限界がある前提で
記述する。

## 禁止事項7の遵守について

表の数値はいずれも自分で打つ予定の式(`print cdbl(...)`の引数)の
直接の結果の**予測値**であり、測定前の予測器出力。測定はまだ実施
していない。
