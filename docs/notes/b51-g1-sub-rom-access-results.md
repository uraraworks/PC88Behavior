# B51: `0x16` と `0x15` のあいだに、サブの ROM 側がどこを読み書きするかを値なしで測る — 結果

記録日: 2026-11-01
規則: [b51-g1-sub-rom-access-preregistration.md](b51-g1-sub-rom-access-preregistration.md) どおり。測定はクラウドの実行環境で OO・SS 各 2 走。関門 4 項目はすべて通った。値は記録していない。記録は `measurements/b51-g1-sub-rom-access-OO.txt`・`-SS.txt`。

## 結果

- 公式: 窓（番号 76569〜76828）の中に、ROM 側のデータの読み書きは **1 件も無い**
- 自作: 読み書きはすべて番号 76826 以降で、範囲は `7B`〜`7F` 台（作業域とスタック）である。番号 76825 までは無い

## 分かったこと

**ROM の内容を読む行は無い。** 事前登録で止める条件にした「258 回前後の増える読み」は無く、G1 が公式 ROM の内容を読んでいる証拠は出なかった。測定は続ける。

## 読み方（推定）

B50 の「258 バイトは ROM 側の `OUT`」という推定は外れた。番号 76570〜76825 の値は RAM 上のコードが出している。

B49 の B 区間で、番号 76571 と 76572 のあいだに FDC の出来事が約 1 万件ある。公式はその前に `seek` している（B30 の番号 93）。自作は `0x16` を読み違えて別の所を読んでいる可能性がある。B46 の「値まで同じ」とは合わない部分が残っており、そちらは `0x16` の実装のあとで確かめる。
