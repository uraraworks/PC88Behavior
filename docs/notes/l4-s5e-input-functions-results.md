## 進め方

事前登録どおり、16腕（E1〜E16）を各2走、陽性対照（直接モード
`print 7717\n`）を1走、計33走を実施した。E3〜E16は直接モードの1行
（`new`・`run`不要）、E1・E2はプログラムモード（`new`〜`run`）で
`INPUT`を含む。打鍵は`tools/harness/frontend/q88measure`を直接呼び、
`--type-at 300 --type '\n'`（起動settle）→
`--type-at 700 --type "<腕の打鍵文字列>"`（実打鍵）の順で与えた。
写しは打鍵前（frame 690）と、事前登録のフレーム式
（`line_end=700+8*文字数`、`dump=line_end+300`、`run=dump+200`。
陽性対照も同式）で計算した「後」の1枚を取得した（E1・E2を除く）。

E1・E2は事前登録「E1・E2の扱い」節どおり、`run`を打った後プロンプト
が出るまでの余裕（`dump1`）で単独の写しを取り、
`tools/l4_vram_probe.py --nonblank-summary-rows`で、`run`を打った行の
次の相対行（プロンプト行）の非空白セル件数が0でないことを確認した後、
同じフレームから続けて入力値（E1:`21\n`、E2:`3,4\n`）を打鍵し、
`dump2`で最終出力を確認した。写しは3枚（打鍵前・プロンプト確認用・
最終）取得した。

記録には`tools/l4_s4a_float_classify.py`（`5735eb3`）の`NUMERIC_CODES`
集合を、`l4-s5b`〜`l4-s5d`で確立・正式化した行の構造的特定手法と組み
合わせ、出力行ごとに適用した。

## 判定

- **Q1**（E1・E2、`INPUT`）: 両腕とも**`input_ok`**。
  - E1（`input a`、入力`21`、`print a*2`）: プロンプトが出て、入力
    `21`が変数`a`へ入り、出力は`42`（`21*2`）。
  - E2（`input a,b`、入力`3,4`、`print a+b`）: プロンプトが出て、
    入力`3`・`4`がそれぞれ`a`・`b`へ入り、出力は`7`（`3+4`）。
- **Q2**（E3〜E10、文字列関数）: 全腕**`fn_ok`**。
  - E3（`mid$("12345",2,3)`）: 出力`234`。
  - E4（`len("12345")`）: 出力`5`。
  - E5（`left$("12345",2)`）: 出力`12`。
  - E6（`right$("12345",2)`）: 出力`45`。
  - E7（`val("12")+1`）: 出力`13`。
  - E8（`str$(12)`）: 出力`12`で、先頭（col0）は変化せず、数字は
    col1から始まった（`PRINT`の正数の符号位置と同じ、**先頭に空白が
    1つ入る形**）。
  - E9（`asc("1")`）: 出力`49`（文字`1`のASCIIコード）。
  - E10（`"12"+"34"`の連結を`a$`へ代入し`print a$`）: 出力`1234`で、
    col0から始まった（文字列の出力は数値と異なり符号位置の空白を
    持たない）。
- **Q3**（E11〜E14、整数化）:
  - E11（`int(-1.5)`）: 出力`-2`（床関数。`-1.5`以下の最大の整数）。
  - E12（`fix(-1.5)`）: 出力`-1`（小数部の切り捨て、`0`方向への丸め）。
    `INT`と`FIX`で結果が異なり（`-2`対`-1`）、負の数での床関数と
    ゼロ方向切り捨ての違いが確認できた。
  - E13（`cint(2.5)`）: 出力`3`。**`rounds_half_away`**（絶対値の
    大きい側へ丸められた。最近接偶数丸めなら`2`になるはずだが、
    そうならなかった）。
  - E14（`cint(-2.5)`）: 出力`-3`。**`rounds_half_away`**（E13と対称に
    絶対値の大きい側へ丸められた）。`l4-s5c`のC4・C5（整数変数`%`への
    代入の丸め）と同じ`rounds_half_away`の結果だった。
- **Q4**（E15・E16、記述のみ）:
  - E15（`abs(-3);sgn(-3);sgn(0)`）: 出力は`3`・`-1`・`0`。
    `ABS(-3)=3`、`SGN(-3)=-1`、`SGN(0)=0`で、いずれも算術的に期待
    される値と一致した。
  - E16（`sqr(16);sin(0);cos(0)`）: 出力は`4`・`0`・`1`。
    `SQR(16)=4`、`SIN(0)=0`、`COS(0)=1`で、いずれも算術的に期待
    される値と一致した。
- `gate_failed`: 該当する腕は無い（G1〜G5・G8すべて真）。

## 禁止事項7の遵守について

本測定でツール出力・本ノートに載せたのは、(1)自分で打った式・入力値
が`PRINT`または関数呼び出しによって出力した数値（`NUMERIC_CODES`
集合内のみで構成される行に限る。事前登録が明示的に許可する範囲）、
(2)E1・E2のプロンプト行の件数（文字コードは一切見ていない）、
(3)ハードウェア設定に相当するアドレス式・行/列番号のみ。`other`に
分類された出力行は今回の16腕には現れなかった（全て`numeric_output`）。
