## 1. 追補3 の実行と結果

[追補3](m6f-e-addendum3-full-row-wrap.md)に従った。器具 `d1fb1d5`、公式ROM起動14回（7腕×2走）。関門 G0〜G14 はすべて真。
参照 diskA 複製は不変、作業先で画面本文を持つファイルは0件。

- **Q-B: `files_layout_rule_G5_SPLIT63_80DOT_00BLANK_UNITS_W`**（162候補の積集合が一意。L81・L86・L91・L90' のすべてで一致、
  L90' は追補2 L90 と署名が一致＝`l90_reproduced`）。
- **Q-A: `inconclusive_print_control`**（対照 P79・P81 がどちらの候補の予測とも一致しなかった）。
- 最終判定: 追補3 §5 により Q-A が決まらないので、表示規則として採らない。仕様書は改版しない。

### 1.1 Q-A の観測（行番号と文字数のみ）

| 腕 | 観測（行:文字数） | 2走 |
|---|---|---|
| P79 | 0:79、1:1 | 一致 |
| P80 | 0:80、2:1（行1は空） | 一致 |
| P81 | 0:80、1:1、2:1 | 一致 |

行と文字数の形は、3腕とも `wrap_then_newline_blank` の予測と同じだった。

### 1.2 対照が外れた原因（事後の観察、判定には使わない）

予測器は打鍵の文字列リテラルを大文字（`A`・`B`）のまま画面に出るものとして予測していた。
**打鍵は小文字で届く**ことは既に測定済みである（[m6f-a 結果](m6f-a-directory-by-save-diff-results.md) (i)、
[m6f-b 結果](m6f-b-directory-entry-fields-results.md)）。親がメモリ内で小文字（`a`・`b`）として署名し直すと、
3腕・2走とも全行が `wrap_then_newline_blank` の予測と一致した（大文字・小文字を片方だけ変えた組み合わせは不一致）。
本文は出力していない。**器具の誤りであり、画面の規則の問題ではない**が、結果を見てからの修正なので判定には使わない。

## 2. 追補4（事前登録、状態: 測定前）

### 2.1 変更

追補3 の Q-A の予測器だけを、既知の測定事実（打鍵は小文字で届く）に合わせる。文字列リテラルの中身は
`a` の繰り返しと `b` として予測する。**候補（2つ）・腕（P79/P80/P81 の打鍵そのもの）・関門・判定名は追補3 §2.1・§3.1・§4・§5 のまま。**
Q-B は追補3で一意に決まったので測り直さない。

### 2.2 実行

P79・P80・P81 を各2走（公式ROM起動6回）。器具の変更は予測表と凍結値だけとし、変更後の Q-A 予測表の SHA-256 を
`tools/m6fe_add4_frozen.tsv` に凍結してから起動する。

### 2.3 判定

- 追補3 §5 の Q-A の判定名を使う。
- **表示規則として採るのは**、Q-A が `wrap_then_newline_blank` のとき（Q-B は追補3の `..._W`）。
  Q-A が `wrap_absorbs_newline` なら `inconclusive_add3_disagree`、それ以外は Q-A の判定名のまま止まる。
- 大文字の予測に戻した表では P79・P81 が不一致になることを、器具の自己検査の陰性対照として持つ（本件の再発防止）。

### 2.4 行き先

採れた場合は追補3 §6 のとおり（l3-main.md への Q-A の規則、l4-basic.md の `FILES` 節）。
結果ノートは `docs/notes/m6f-e-addendum4-results.md`。
