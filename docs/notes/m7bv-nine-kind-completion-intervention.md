# m7bv: 例外0件の9種を結線すると空振り0Bは消えるが最初の値差は7036件目に残る

実施日: 2026-08-20

## 情報境界

公式main ROM一式＋診断用自作subの一時ROMを、公式diskAの複製で1800フレーム
実行した。公式ROM・ディスクの内容は読まず、`private/`への
`cat`/`xxd`/`od`/`strings`・逆アセンブルは行っていない。生iolog、ROM・
ディスク複製、一時生成器、実行出力はリポジトリ外の`mktemp -d`配下だけに
置き、コミット対象にしていない。`$FC/$FD`値は件数・SHA-256だけを扱い、
値列は出力・記録していない。

解析は既存の`analyze_main_to_sub.parse_iolog`、
`analyze_record_boundaries.window_a_runs`、`analyze_write_path.parse_commands`、
`hash_io_stream.py`を再利用した。新しい解析器は書いていない。

## 一時ROMの結線

m7btと同じく、window(a)のrun内位置と先頭種別を`REQ_HDR/RUN_LEN`から独立に
保持し、`OUT $FB/$FD`で位置を0へ戻した。m7buで列が一意だった9種だけを
確定長で次へ渡した。

- K01は起動stage 1なら既存交換#6、バルク後なら既存一般READ入口
- K09は既存交換#11、K06/K05は既存交換#14の第1/残りREAD入口
- 単発`OUT $FD`の4種とFDCオペコード`04`の1種は既存run完了入口
- K00は二変種が未確定なので結線せず、現行どおり再アーム
- WRITEストリーミング種は表に入れず、今回の介入対象外

応答値、FDCコマンド値、座標参照は現行の既存経路から変更していない。
途中で交換#6/#11の座標参照まで変えた試行はmainの要求列を早期に変えたため、
今回の指示を越えた介入として撤回し、最終結果には採用していない。

一時ROMの容量確保では、今回対象外のWRITE専用コード領域と循環WRITE更新を
診断用カウンタ・分岐器へ置換した。生成コード長は**2044バイト**で、2048
バイトのフェッチ窓内だった。この構造はWRITE経路を保持しないため、そのまま
恒久化できるものではない。

## 介入成立の確認

最初の生成器は一般READ入口へ分岐器を重ねて自己ループし、バルク0件となった。
またm7bt生成器から継承した最初のカウンタ記録器は、2バイト目以降で受信値Aを
位置値へ置換していた。いずれも「介入が狙いどおり効いていない」側の不具合で、
入口の非重複配置とA保存を確認してから再実走した。

最終介入ではバルクへ到達し、subの`OUT $FF=0B`は**66件**、その後の
`IN $FC`へ対応したものも**66件**、`OUT $FB/$FD`まで受信を伴わない空振りは
**0件**だった。従来は対応66件＋空振り14件だったため、介入により
空振りは**14→0（14件すべて消失）**し、必要な受信再アームは欠けていない。

## 4指標

| 指標 | 結果 |
|---|---:|
| 適合条件1 | **5635件・SHA-256一致（合格）** |
| 最初の非データ入力値差 | **7036件目**、`IN $FE`、pc `3853`、公式`0x21`／混成`0x20` |
| 空振り`0B` | **14→0**（バルク到達、対応`0B` 66/66） |
| コード長 | **2044 / 2048バイト** |

最初の値差はm7brの7034件目より2件後ろだが、m7btの7036件目と同じであり、
**7036件目より後ろへは動かなかった**。したがって9種の完了結線は空振り
再アームを全消去しつつ適合条件1を維持するが、次の非データ値差は解消しない。

## 恒久実装を見送った理由・未確定

WRITE経路を保持したまま同じ独立カウンタ・9種分岐を既定生成器へ入れる試作は、
到達可能コードが2048バイト窓を**9バイト超過**し、生成器自身の窓検査に拒否
された。判定や窓を緩めず、その試作は撤回した。したがって
`src/l3_service/make_subrom.py`は変更しておらず、恒久実装時だけ必要な
`tools/verify_l3.sh`も今回は対象外として未実行である。

K00二変種の選択規則、7036件目の値差の原因、WRITE経路を保持して9種結線を
2048バイト内へ収めるコード配置は未確定として残す。仕様書、`docs/PLAN.md`、
`tools/harness/romram_selftest.sh`は変更していない。
