# m7cu: ランダムアクセスファイル需要入口の事前登録

実施日: 2026-08-25

本稿の到達条件は実測前に固定した。公式ROM・公式ディスクの内容は読まず、
生ログ、画面報告、ROM／ディスク複製はリポジトリ外の一時領域だけに置く。

## 自作データと複数レコード

使い捨てdiskA複製を読書き可能にし、`OPEN "Q7R" AS #1` でランダムファイルを
既定128バイトレコードとして開く。`FIELD #1,128 AS A$` とし、レコード1と2へ
互いに異なる自作文字列を`RSET`して、それぞれ`PUT #1,1`、`PUT #1,2`
する。PUT後はいったんCLOSEし、再OPEN・再FIELDする。既存媒体の内容には依存しない。

## PUT（書込み）の到達条件

PUT到達は、(1) OPEN、FIELD、2組のLSET、レコード1・2それぞれのPUT、CLOSEが
画面に反映され各直後に`Ok`、(2) FDCの`WRITE DATA`が1件以上発行、(3) 再OPEN後の
GETで両レコードの自作内容が読み戻され、後述の末端マーカー2個が出る、の全条件と
する。陽性対照は全条件を持つ合成画面とREAD/WRITE発行、陰性対照はPUT直後の`Ok`と
WRITE発行があっても読戻しマーカーの一方を欠く合成画面とする。従って画面上の受理、
書込み要求だけ、片方のレコードだけの保存、セクタ全体を誤って上書きする状態は合格しない。

## GET（読込み）の到達条件

再OPEN・再FIELD後、各GETの直前にFIELDで結び付けた`A$`を、保存値とは異なる
値へ必ずLSET／RSETする。`GET #1,1`後にレコード1の左端が一致した場合だけ`R7A`、
再び変数を別の不一致値へ潰して`GET #1,2`後にレコード2の右端が一致した
場合だけ`R7B`を表示し、最後にCLOSEして`Ok`へ戻す。

到達は、(1) 再OPEN・FIELD、各事前破壊、GET 1・GET 2、CLOSEの画面反映と各直後
`Ok`、(2) FDCの`READ DATA`が1件以上発行、(3) GET後にだけ`R7A`と`R7B`が順に出て
最後の`Ok`へ戻る、の全条件とする。陽性対照は完全形、陰性対照はGET自体と直後`Ok`
があっても事前破壊値のままで`R7N`となる形、および片方だけ成功する形とする。
「Okが出た」だけの失敗状態はマーカーを欠くため、合格条件を強く満たさない。

## 粒度差の観測指標と固定手順

公式一式／混成についてFDCの`READ DATA`・`WRITE DATA`発行件数、FDCコマンド種別列、
main `IN $FC`の件数とSHA-256（既知の8222／7976件との比較を含む）、main `IN $FD`の
件数とSHA-256、画面の行数・文字数・SHA-256を測る。レコード1と2を別々にPUT/GET
するため、128バイト境界を256バイト処理が正しく保持できなければ、片方の末端マーカー、
READ/WRITE件数、または公式／混成の列比較のいずれかに差が出るはずである。

既存`conform_l3.sh`の測定ラッパ、FDC分類、main受信列、画面署名を再利用する。初回
公式実走で署名を出し、期待値を固定してから公式／混成を各2回再検証する。判定器には
合成画面の陽性・陰性対照、期待件数とSHA-256を壊す故障注入を置く。

ここまでを実測前の事前登録とする。

## 初回校正

最初に試した`OPEN "R",#1,"Q7R",128`は、この測定環境では`Syntax error`となり、
PUTはファイル未OPENでWRITE DATA 0件だったため不採用とした。既存の需要表で
ランダムアクセス用として実測済みの`OPEN "Q7R" AS #1`へ改めた。これは既定の
128バイトを用いるため、上で事前登録したレコード粒度と到達条件は変えない。
不採用試行の署名は期待値へ採用しない。

また、全16行を個別入力すると測定終了時の25行画面からPUT側の先頭行が流れることを
不採用試行で確認した。画面判定は末端に残る各GET直前のLSET、GET、条件式、固有
マーカー、最後のCLOSEと各`Ok`を必須とする。PUT側はWRITE DATA発行と、その後の
別OPENで2レコード双方が読める効果を合わせて必須とする。これは到達条件の緩和では
なく、最終画面という既存測定器の観測窓に合わせた証拠の分担である。

直入力でFIELD、LSET、PUT、GETを別々に実行した校正runは、エラーなくREAD/WRITEを
発行したが両読戻しマーカーが不一致となった。FIELD結合の寿命を文間で曖昧にしない
番号付きBASICプログラムへ改め、同一RUN中に全操作を行う。各GET直前の破壊成功を
`R7C`／`R7D`、読戻し成功を`R7A`／`R7B`、最後のCLOSE通過を`R7E`で確認する。
最初の番号付きプログラム全体はq88measureの512打鍵上限を超え、複数時点へ分けても
合計上限は変わらなかった。FIELDを128バイトの1変数とし、同一行へ安全にまとめて
上限内へ短縮した。起動前に拒否された試行は実測署名を持たない。

短縮後の校正runではLSET直後の破壊確認、RSET保存したレコード2の読戻し、最後の
CLOSEは成功したが、LSET保存したレコード1だけ不一致だった。保存内容は両レコード
ともRSETに揃え、LSETはGET1直前の破壊と`R7C`による効果確認に残す。これにより
LSET・RSET双方を実行しつつ、PUTの到達は2レコード双方の読戻しで判定できる。

最終形の単発公式runは、GET前破壊2マーカー、GET後のレコード別2マーカー、最後の
CLOSE後マーカーと`Ok`まで到達し、取りこぼし0件だった。FDCはREAD DATA 28件、
WRITE DATA 12件、main `IN $FC`は9788件で、既知の8222／7976件とは異なる入口固有
の長さになった。この初回署名を期待値へ固定し、公式／混成各2回の再検証は未実走である。

## 行き止まり: 期待値判定器の空振り

初回の公式／混成各2回では期待値一致がOKと表示されたが、直後のSHA-256・件数故障
注入が両方とも一致扱いとなり、`conform_l3.sh`がrc=1で停止した。判定器が常に通る
状態だったため、その上のOKは信用できず、結果を採用せずに済んだ。

原因は表示ラベル`ランダムアクセスファイルPUT/GET判定器`を故障コピーの一時ファイル
名へ直結し、`/`がパス区切りになったことだった。コピー生成に失敗した後、照合側も
期待値0行を成功扱いした。表示名を一時パスに使わず`mktemp`で生成し、生成失敗・期待値
0行を失敗にした。ラベルに同じ`/`を含めた単独selftestで、SHA-256・件数・空期待値の
故障注入3件がすべて不一致となることを固定した。

## 情報境界

記録するのは件数、SHA-256、画面の行数・文字数・SHA-256、自分で打鍵した文字列、
および公開されたμPD765のコマンド名だけとする。画面本文、ディスクのデータ部、
公式の応答値は記録しない。
