# m7dr: 同一セッション逐次オープン対照の実測

実施日: 2026-08-28

**本稿は`m7dq`の事前登録に基づく実測ノートである。** 公式ROM・公式ディスクの
内容は読まず、生ログ、画面報告、ROM／ディスク複製はリポジトリ外の一時領域だけに
置いた。データポート値は1バイトも表示・転記せず、`cmp -l`等でファイル内容を
出力する比較も行っていない。

## 進捗ログ（実施順）

- [x] m7dqの条件Bを、公式一式2回・混成2回の計4runで実測。
- [x] 全4runの到達条件と、各ログ2行（main/sub）の取りこぼし0件を確認。
- [x] 同一モード2回の全イベント列・画面の決定論的一致を確認。
- [x] 公式初回の署名を固定後、4run全てを再判定。
- [x] 画面の陽性／陰性対照、件数・SHA-256・期待値0行の故障注入を確認。
- [x] m7dqの距離規則を変更せずA/B/Cへ適用。
- [x] `tools/check_cleanroom.sh`。

最初の準備runは`P9D`・直後`Ok`へ到達したが、取りこぼしヘッダの末尾注記を許容しない
検査式が、0件の2行を非0と誤分類した。この時点では条件Bを1回も走らせていない。
この準備結果は採用せず、検査式を「`# 取りこぼし: 0件`で始まる行」に修正した上で、
新しい一時領域・使い捨て複製から準備runをやり直した。測定プログラム、フレーム数、
到達条件、距離規則は変更していない。

## 測定条件

`m7do`と同じ準備プログラムでQ9A（A1/A2/A3）とQ9B（B1/B2/B3）を作った
準備済み複製から、runごとに別の使い捨て複製を作った。条件BではQ9Aを`#1`で開き、
3行全てを読んで閉じた後、Q9Bを同じ`#1`で開いて3行全てを読み、閉じた。同時には
開いていない。各runは9000フレーム、打鍵は300F/700Fの二段とし、ディスクへの保存は
準備runの使い捨て複製だけに行った。条件Bのrun間では書込み結果を継承していない。

## 到達条件・不合格条件

公式2回・混成2回の全4runで、プログラムと`RUN`の画面反映、Q9Aの3行読出し後の
`CLOSE #1`、Q9Bの再オープンと3行読出し、一致マーカー`M9M`、全`CLOSE`後の
`M9C`、直後の`Ok`を順に確認した。

構文エラー、Q9Bの再オープン不成立、`M9M`／`M9C`／直後`Ok`の欠落、無反応、
無限ループはいずれも無かった。**全4run到達（合格）**であり、単一走だけを合格へ
数えていない。

## 全run取りこぼし0件

各iologにあるmain/sub各1行、計2行の取りこぼしヘッダを検査した。条件Bの公式2回・
混成2回は、全runで2行とも0件だった。従って不採用runは0、採用runは4である。
準備runもやり直し後は2行とも0件だったが、準備は測定対象へ含めていない。

## 条件Bの実測値と決定論性

| モード | run | main `IN $FD` | main `IN $FC` | READ単位 | WRITE単位 | 取りこぼし |
|---|---:|---:|---:|---:|---:|---:|
| 公式 | 1 | 5635 | **9772** | **25** | 0 | 0 |
| 公式 | 2 | 5635 | **9772** | **25** | 0 | 0 |
| 混成 | 1 | 5635 | **9772** | **25** | 0 | 0 |
| 混成 | 2 | 5635 | **9772** | **25** | 0 | 0 |

main `IN $FD`のSHA-256は全4runで
`e26b22e7eec0d20725b25a34c00bc968820e1c7434c21cc45e0fb61939315ab7`、
main `IN $FC`のSHA-256は全4runで
`4d5d8c1c435e383c2f798c1a5ecd39e986e58fa23390ac88421a82da215651b5`
だった。画面も全4runで19行・303文字・SHA-256
`bd06fca3dea59fc4993dceb065b761bf5dfdbd96d4e237177067d920a1316c0b`
に一致した。

全イベント列のSHA-256は、公式2回が
`3d4399019237ffa897d04c4a01e93c2804e6c03fa955e99cb318e945d04d89df`、
混成2回が
`9d1728ff7d1a62e43abfa24779c954adf1f04bea855b531d3d250bc597d50cd9`
で、それぞれ2回が決定論的に一致した。

公開FDCコマンド種別列は全4runとも115件で、起動前置き15件に続いてREAD単位25、
WRITE単位0だった。公式・混成はコマンド種別列が115件全長一致し、画面、main
`IN $FD`、main `IN $FC`も件数・SHA-256とも一致した。一方、公開FDCパラメータ列は
コマンド1件目のパラメータ1件目から一致しなかった（値は記録しない）。このため
全イベント列の公式対混成一致は主張せず、m7dqどおり同一モード内の決定論性と、
登録した観測指標ごとの一致を記録する。

## 3条件の比較と判定規則の適用

事前登録した一次指標だけを並べる。

| 条件 | 内容 | main `IN $FC`件数 | READ単位 |
|---|---|---:|---:|
| A | 同時オープン | 9254 | 21 |
| B | 同一セッション逐次 | **9772** | **25** |
| C | 別ブート単独2回の合計 | 16444 | 34 |

m7dqどおり、指標ごとにBからA/Cへの絶対距離を取り、任意の件数幅・割合の閾値は
追加しない。

| 指標 | `|B-A|` | `|B-C|` | 指標単独の側 |
|---|---:|---:|---|
| main `IN $FC`件数 | **518** | 6672 | A寄り |
| READ単位 | **4** | 9 | A寄り |

2指標ともAへの距離が厳密に小さいため、事前登録規則による一次判定は
**A寄り**である。これは、固定した条件では「同一セッションであることと整合する」
という判定であり、同一セッションへの集約だけでもm7dpで見つかった削減の大部分が
再現されたことを示す。

## 解釈限界

判定はA寄りだが、m7dqで固定した次の交絡は本測定でも除去できない。

- Bの2回目が引き継ぐバッファ、ディレクトリ検索結果、直前のシーク位置、FDC・
  ドライブ状態の内訳は分離していない。
- A/Bは、同時オープンの有無だけでなく、交互読出し対連続読出し、Q9Bの`#2`対
  再利用した`#1`、Q9Aを閉じる時点も異なる。
- Cだけが別ブート2回の和であり、起動・初期化の固定費を2回含みうる。
- Q9A→Q9Bの順序、物理配置、準備時の作成順を固定したため、順序・配置効果を
  分離していない。

従って、**キャッシュ、バッファ、ディレクトリ検索、シーク位置等の特定機構へは
帰属しない。** また「同一セッション一般」が原因とも、「純粋な同時性は無関係」とも
断定しない。言えるのは、今回固定した複合条件Bが、両一次指標でCよりAへ近かったこと
だけである。

## 固定署名の再判定と故障注入

公式run1の件数・SHA-256・READ単位・画面署名を固定した後、公式run2・混成run1・
混成run2を含む全4runを判定し直し、全て一致した。画面の陽性対照を検出し、`M9M`、
`M9C`、直後`Ok`を各々欠く陰性対照も全て不一致にできた。件数破壊、SHA-256破壊、
期待値0行の3故障も全て検出し、空振りは0件だった。

## 情報境界

記録したのは件数、位置、SHA-256、画面の行数・文字数・SHA-256、自分で打鍵した
文字列・自作データ、および公開されたμPD765のコマンド名だけである。画面本文全体、
ディスクのデータ部、公式の応答値、データポート値列は記録していない。ROM・ディスク
複製、生iolog、stdout/stderrは全てリポジトリ外の一時領域だけで扱った。
