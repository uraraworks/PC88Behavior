# l4-s4l — 倍精度の定数読み取りの新候補DREP10の丸め方 — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

`l4-s4k`（測定`ec794b9`）は`no_survivor`だった（`DEXACT`=`DGW`が24腕中
17腕一致、`DREP01`が24腕中3腕一致。外れはすべて最下位1〜2ulpの差）。
その後、Codexが GW-BASIC のソースと`l4-s4k`の実測36件（候補の式＋
対照）から新しい候補`DREP10`を立て、丸めを「最近接偶数」にしても
「半分は絶対値の大きい側」にしても36件すべてを再現した（分析は
`docs/notes/l4-dfin-model-search.md`として別担当がコミット予定。
**中身は読まない**）。

`DREP10`は`l4-s4k`の実測に事後に合わせた候補なので、`l4-s4b`のH6・
`l4-s4c`〜`l4-s4k`の各候補群を立てたときと同じ理由づけで、`l4-s4k`の
腕を再利用せず新しい式で前向きに検証する。あわせて、`DREP10`の丸め
方（最近接偶数か、半分は絶対値の大きい側か）を、単精度・他の倍精度
候補で確定してきた「半分は絶対値の大きい側」（`l4-s4g`・`l4-s4h`）と
矛盾するかどうかも見る。

## 候補（定義）

倍精度浮動小数点（MBF、仮数56bit）を対象とする。

- **`DREP10E`**: 数字を先頭から1つずつ`acc = acc*10 + d`で積み上げ、
  **1手ごとに倍精度へ丸め**、正味の指数`n`が正なら10を`n`回**掛け**、
  負なら10で`|n|`回**割り**（本当の割り算。`l4-s4k`の`DREP01`のよう
  に丸めた0.1を掛ける近似ではない）、**1手ごとに56bitへ丸める**。
  丸めは**最近接偶数**（銀行丸め）。符号は最後に適用する。
- **`DREP10A`**: `DREP10E`と同じ手順だが、丸めは**半分なら絶対値の
  大きい側**（`l4-s4g`・`l4-s4h`で確定した丸め方向）。
- **`DEXACT`**（参照）: 10進の値を倍精度へ1回で丸める（`l4-s4k`と同一
  定義）。
- **`DREP01`**（参照）: ×0.1の反復（`l4-s4k`の定義をそのまま使う）。

演算（倍精度どうしの演算）と書式は共通で、仕様書`docs/spec/
l4-basic.md`第3.6版（`ca77caf`）どおりとする。

## 腕（候補の式・対照、いずれも別担当が並行で作成中の表から取る）

- **候補の式（L1〜Ln）**: `docs/notes/l4-s4l-candidates.tsv`の全行の
  `typed`列を、表に現れる順のまま腕L1〜Ln（nは行数）として使う。
- **対照（M1〜Mm）**: `docs/notes/l4-s4l-controls.tsv`の全行の`typed`
  列を、同様に腕M1〜Mm（mは行数）として使う。

**両表とも予測の列は読まない・触らない。** 腕の総数・具体的な式は、
両表がコミットされた時点で機械的に決まる（本ノートの時点では特定
しない）。

群（列`group`）は表そのものに書かれている想定であり、本ノートでは
値を書き写さない。両表とも関門G6の対象とする（測定開始前のコミット
に存在し、以後変更されていないこと。**候補表・対照表のどちらか一方
でも測定開始の時点で存在しない場合、測定は始めない**）。

## 条件・器具

`l4-s4k`（`4a85061`）の「条件・器具」「本文を出さない取り扱い」
「関門」節をそのまま踏襲する。写しの時刻は全腕一律
`dump(k)=line_end(k)+300`とし、関門G8（後の写しにOk行が現れている
こと。**全腕で確認する**、`l4-s4k`と同じ扱い）を含めてG1〜G6・G8を
適用する（G7は対になる予測表が無いため本測定にも適用しない）。

```
line_end(k) = 700 + 8 * (その腕で打った文字数の累計、\n も1文字)
dump(k)     = line_end(k) + 300
run(k)      = dump(k) + 200
```

- 分類器は`5735eb3`の`tools/l4_s4a_float_classify.py`を使う
  （`l4-s4a`〜`l4-s4k`と同じ、二重実装しない）。
- 出力が`0`の腕も、他の腕と同じ規則で通常どおり照合する（`l4-s4i`〜
  `l4-s4k`と同じ扱い）。

## 記録する内容

`l4-s4a`〜`l4-s4k`本体の記録規則（腕ごとに、差分モードで得た「前が
空白だったセル」の(相対の行, 相対の桁, 文字コード)の並びと、原点セル
の絶対位置(row0, col0)を記録する）に加え、`l4-s4j`・`l4-s4k`で新設
した規則を踏襲する。

- **`numeric_output`に分類された全腕の出力文字列を、結果ノートの表に
  必ず載せる。**（`l4-s4i`の教訓、`l4-s4j`・`l4-s4k`で継続している
  扱い）。この記録は「本文を出さない取り扱い」節の許容範囲内（自分で
  打った式の直接の計算結果）である。`non_numeric_output`の腕は従来
  どおり件数と位置の範囲だけを記録する。

## 本文を出さない取り扱い

`l4-s4a`〜`l4-s4k`と同一。出力行の全セルの文字コードが「数字0-9・`.`・
`+`・`-`・`E`・`D`・空白」の集合に入る腕だけコードを記録し、1セルでも
集合外があれば件数と位置の範囲だけを記録する。分類器
（`tools/l4_s4a_float_classify.py`）は集合外のコードを標準出力・標準
エラーへ出さない設計であることが`5735eb3`の時点で確認済み。

## 関門

`l4-s4k`のG1〜G6・G8と同一。

- G1 器具の自己検査（本体と同一の自己検査群）
- G2 取りこぼし0・打てない文字の警告0
- G3 決定論性: 各腕2走とも写し・記録のsha256が一致
- G4 陰性対照: 何も打たない走で差分0件
- G5 陽性対照: `print 7717\n`腕で`7717`の並びを確認
- G6 候補表・対照表の固定: `docs/notes/l4-s4l-candidates.tsv`と
  `docs/notes/l4-s4l-controls.tsv`の両方が、測定開始より前のコミット
  に存在し、以後変更されていないことを`git log`で確認する。どちらか
  一方でも測定開始の時点で存在しない場合、測定は始めない
- G8 出力完了の確認: 「後」の写しで、出力行の後に`Ok`行が現れている
  こと（`ok_relative_row`相当の値が得られること）。**全腕で確認する**
  （`l4-s4k`と同じく倍精度の長い定数は写しが遅れがちであるため省略
  しない）。現れない腕は`gate_failed`とし、「写しが早すぎた」とだけ
  記述する

## 判定

判定名は`l4-s4c`〜`l4-s4k`と同じものを使う。「記録する内容」節を参照
する。

- 腕ごとの分類: `numeric_output`/`non_numeric_output`/`gate_failed`
  （`l4-s4a`〜`l4-s4k`と同じ）。
- 候補ごとの判定: 各候補（`DREP10E`・`DREP10A`・`DEXACT`・`DREP01`）
  について、**候補の式（L1〜Ln）と対照（M1〜Mm）を合わせた全腕**で、
  予測文字列を出力行の相対桁0から置いたときの非空白セル(相対桁, コード)
  の並びが実測と完全一致すれば`candidate_consistent`、1腕でも一致し
  なければ`candidate_rejected`。`gate_failed`の腕がある場合、その
  候補は判定不能とし`other`とする（理由を記述）。対照は候補の判定に
  含める（対照が食い違えば候補も`candidate_rejected`になりうる）。
- 型のまとめ: **`DREP10E`・`DREP10A`の2候補のみ**を対象に、
  `candidate_consistent`だった個数で決める。
  - **`unique_survivor`**: ちょうど1つ
  - **`multiple_survivors`**: 2つとも`candidate_consistent`
  - **`no_survivor`**: どちらも`candidate_rejected`
  - `no_survivor`の場合も、`l4-s4c`〜`l4-s4k`と同じく**候補を後から
    足して判定し直すことはしない**。次の事前登録に回す。
- **`DEXACT`・`DREP01`（参照）の扱い**: 型のまとめ（`unique_survivor`
  等）の算出には使わない。候補ごとの判定（`candidate_consistent`/
  `candidate_rejected`）はそのまま記録し、`l4-s4e`の`GW16`対照と同じ
  扱いで、もし参照側が`candidate_consistent`になった場合はその事実を
  結果ノートで特記する。
- **対照が1つでも食い違った場合の扱い（`l4-s4i`〜`l4-s4k`と同じ規則）**:
  対照（M1〜Mm）のうち1腕でも実測が予測と食い違った場合、**候補の式
  （L1〜Ln）の結果を丸め方式を決める根拠には使わない**。この場合、
  型のまとめは算出せず**`other`**とし、「対照が食い違ったため判定を
  保留」と記述する。候補ごとの`candidate_consistent`/
  `candidate_rejected`自体は通常どおり記録する。
- **群ごとの一致数（記述のみ、`l4-s4j`・`l4-s4k`を踏襲）**: 判定その
  ものは全体（候補の式＋対照を合わせた集合）で1つに決めるが、表の
  `group`列ごとと、正味の指数`n`の符号（`n>0`／`n<0`／`n=0`）ごとの
  両方で、候補ごとの一致した腕数を結果ノートに記述する。いずれも型の
  まとめの判定名には影響しない。

## 器具の確認（公式ROMは使わない）

本ノートの作成時点（測定時HEAD`ec794b9`）で、`docs/notes/
l4-s4l-candidates.tsv`・`docs/notes/l4-s4l-controls.tsv`のいずれも
まだコミットされていない。そのため、本ノートでは候補・対照いずれの

エコー確認）は、両表がコミットされた後、測定の担当が行う。**

## 判定後の行き先

- `unique_survivor`なら、その候補（`DREP10E`または`DREP10A`）を倍精度
  の定数読み取り（`FIN`）の方式として確定する（仕様書への反映は本
  ノートの担当範囲外とする）。`DREP10A`（半分は絶対値の大きい側）が
  生き残れば、単精度・他の倍精度丸め規則と同じ丸め方向で一貫すること
  になる。
- `multiple_survivors`なら、`DREP10E`・`DREP10A`を区別できる「ちょう
  ど半分」の式を次の事前登録で立てる。
- `no_survivor`なら、`DREP10`系の候補群を一旦棄却し、`l4-s4k`までの
  全観測を総覧して別の規則を検討する入力とする。
- 参照（`DEXACT`・`DREP01`）が本測定で`candidate_consistent`になった
  場合は、上記いずれの結果になっても、その事実を別途報告する。
- 対照が1つでも食い違った場合は、上記のいずれにもならず、共通経路
  （倍精度どうしの演算・PRINT書式）の再検証を次の作業の入力とする
  （`l4-s4i`〜`l4-s4k`と同じ扱い）。
