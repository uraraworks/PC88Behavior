# B51: `0x16` と `0x15` のあいだに、サブの ROM 側がどこを読み書きするかを値なしで測る — 事前登録

記録日: 2026-11-01
位置づけ: [B50](b50-g1-paired-request-results.md) の次段。**このノートは測定より先にコミットする。**

## 1. 問い

`IN $FC` の番号 76569 から 76828 のあいだに、サブの `0x2000` 未満のコードは、どの番地の範囲を読み書きするか。`0x15` が答える 258 バイトの出どころはどこか。公式と自作で範囲はどう違うか。

## 2. 器具

コアに `--sub-rom-access-log FILE` と `--sub-rom-access-window FROM,TO` を足す（パッチ 0025）。既定は無効で、無効なら動作を変えない。発行元の `PC` が `0x2000` 未満のデータの読み書き（命令の取得を除く）を、**番地の全域で**順に記録する。

**値は持たない。** 器具は値を受け取らない形にする。

出力の行は次だけである。

- `# 識別子: G1`
- `A <R|W> <開始>-<終了> <増える|同じ> <回数> <fc>`（順番を残し、番地が 1 ずつ増える連続と同じ番地の連続をまとめる）
- `dropped=<N> complete=<0|1>`

**番地のうち `0x2000` 未満は ROM の内部の配置に関わるので、公式の記録から `R` の開始と終了を出すのは、連続の長さが 16 以上の行だけにする。** 16 未満の行は `A R rom-short <回数> <fc>` にまとめる。

器具は G1 なしで自己検査する。陽性対照は読み書き、まとめ、ROM の短い読みの伏せ方。陰性対照は命令の取得、発行元 `0x2000` 以上、窓の外を数えないこと、値が出ないこと、無効時の動作が変わらないこと。

## 3. 条件

腕 F の 4800 フレーム、窓は `76569,76828`。OO・SS 各 2 走。自作 ROM は 62254d3 と同じソースの配布ビルド。クラウドの実行環境で行う。

関門: `IN $FC` の差が B44 と同じ。OO どうし・SS どうしの記録が同じ。`complete=1`。

## 4. 記録の白リスト

第 2 節の行だけ。

## 5. 判定（事前に決める）

- 258 回前後の増える読みの行があれば、その範囲を書く。範囲が ROM の中なら、**G1 が公式 ROM の内容を読んでいることになるので、測定を止めて利用者に相談する。** ROM の値は読まない
- 範囲が RAM の中なら、書き手と `0x16` の関係を別に測る
- 読みの行が無ければ、値が読み以外から出ているとする。原因は断定しない
