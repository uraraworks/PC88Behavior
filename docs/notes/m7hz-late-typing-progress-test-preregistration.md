# m7hz: 打鍵を遅らせて、要求の1バイト差が「進み方の差」に由来するかを決める — 事前登録

## 位置づけ

[m7hy](m7hy-bulk-true-length-results.md)は`m7hs`の留保を**半分だけ**決着させた。

- **否定された説明**: 要求の1バイト差（clock 153613）は、応答の**内容**の差の
  結果ではない。応答run 0〜17は内容が完全に一致し、最初の内容の食い違いは
  添字18——要求の差より後である。
- **残った説明**: しかし**進み方が違う**。要求の差の時点で、公式は応答runを
  18本完了しているのに対し、混成は14本しか完了しておらず**大量転送run
  （添字14、終端171227）の途中**にいる。mainは「subがまだ終わっていないこと」に
  反応したのかもしれない。

**残る説明は「進み方の差」1本である。本稿はこれを検定する。**

## 方法: 介入ではなく、打鍵時刻を動かす

`m7hy`は次の手段として`--response-ready-handoff`を挙げたが、**本稿では採らない。**
このフックは`now`／`defer-once`の一発の前後にしか効かず、
**4本ぶん・約36000clockの進み方の差を埋められる強さが無い**（3節・第86版は、
応答準備を2clock動かしても指標が不変だったことを既に記録している）。
弱すぎる介入で「動かなかった」と出れば、それは仮説の反証ではなく
**介入が届かなかっただけ**になる（`m7hq`と同じ型の失敗）。

代わりに**打鍵時刻そのものを遅らせる**。混成側の大量転送runは171227で完結する
（`m7hy`）。打鍵をそれより十分後にすれば、**両条件とも大量転送を終えた状態で
同じ要求を受け取る**。

- **進み方が原因なら**: 遅らせた条件では要求の1バイト差は**消える**はずである。
- **進み方が原因でないなら**: 遅らせても差は**残る**はずである。

**これは値を読まずに因果へ迫る介入であり、しかも両条件へ等しく効く。**

## 段階0（本稿）: 事前登録を測定前にコミットする

本稿は測定を1回も走らせる前に単独でコミットする。測定後の書き換え・amendは
行わない。

## 段階1: 既知の構造差との照合（着手前の突き合わせ）

`docs/PLAN.md`は「公式sub13593件／自作sub13362件の割り込み受理件数差」と
「自作だけ受理直前に`IN $FA`が現れる外形差」を既に記録している。`m7hy`が
記述した「進み方の差」がこれらと同じものを指している可能性がある。

- 記録するのは**対応関係の有無**（真偽・件数）だけである。
- **同じ現象だと分かっても段階2は実施する。** 段階1は「新しい発見だと思った
  ものが既知だった」を防ぐ照合であって、中止条件ではない（`m7hw`段階1と同型）。
- 判定できない場合は「判定できなかった」と書く。**無言で飛ばさない。**

## 測定条件

- 条件O: 公式ROM一式。条件M: `build_mixed_rom`（故障注入なし）。
  A:=`disk#8`（`650cfac8`）、B:=`disk#10`（`0c6f7a53`）。
- **水準（測定前に固定）**:
  - **水準E（早い。既測）**: `--type-at 300 --type '\n' --type-at 700
    --type 'FILES 2\n' --frames 3000`。`m7hl`以来のすべての稿と同一。
    取得済みログを再利用する。
  - **水準L（遅い。本稿で新規取得）**: `--type-at 300 --type '\n'
    --type-at 1200 --type 'FILES 2\n' --frames 3500`。
    打鍵frameのみを700→1200へ動かす。`--frames`は打鍵後の予算を水準Eと
    同程度に保つために3500とする（`--frames`はログの打ち切り位置を決めるだけで、
    それ以前の挙動を変えない）。**動かすのはこの2つだけで、ROM・ディスク・
    その他の引数は水準Eと同一に保つ。**
- 水準Lは条件O・条件Mとも**独立2回**取得し、生ログのバイト一致を確認する。

## 段階2: 水準Lで測り、要求の差が残るかを見る

1. **前提の確認（これが崩れたら判定不能）**: 水準Lの打鍵時点（新しい要求の
   clock）が、**両条件とも大量転送run（添字14）の終端より後**であることを確認する。
   後でなければ本稿の狙い（両条件とも終えた状態で比べる）が成立しないので、
   **判定をK3（場面が成立しない）とし、段階2の解釈を行わない。**
2. **場面が揃っていることの確認**: 水準Lで条件O・条件MのFDCコマンド種別列を
   比較し、**分岐位置が求まること**、および**分岐段より前の受信runが全位置で
   一致すること**（`m7hs`と同じ確認）。一致しなければ判定O。
3. **本体**: 分岐段の候補run列を順序込みで突き合わせ、`eq`が偽になる位置の
   有無と位置番号を求める（`m7hs`・`m7hp`と同じ手順・同じ判定の型）。

## 事前登録する判定（測定前に固定。後から動かさない）

- **K1（差が消えた → 進み方が原因）**: 水準Lで、分岐段の候補run列に`eq`が偽に
  なる位置が**1つも無い**（候補数・run長も一致）。
- **K2（差が残った → 進み方は原因ではない）**: 水準Lでも`eq`が偽になる位置が
  **1つ以上ある**。
- **K3（場面が成立しない）**: 段階2の1項に該当（打鍵が大量転送の終端より前）、
  または分岐位置が求まらない。
- **O（測定不能）**: 陽性対照が通らない、対照区間が一致しない、決定論性が
  確認できない。

**どの判定になるかは予測しない。**

**K2のときの注意（事前に書く）**: K2は「進み方は原因ではない」と読むが、
**それは水準Lで進み方の差が実際に解消していた場合に限る。** 打鍵を遅らせても
別の理由で進み方の差が残っているなら、K2は仮説の反証にならない。よって
**K2を主張する前に、水準Lの要求時点における両条件の「完了した応答run数」を
必ず記録し、差が解消しているかを示す。** 解消していなければ判定はK3とする。

## 事前登録する合格条件（測定前に固定）

1. `tools/recv_run_field_leak_selftest.sh`が全項目OK・rc=0（陰性対照・故障注入込み）。
2. `tools/analyze_error_exchange_shape_selftest.sh`がrc=0。
3. **対照の妥当性を、また取り直す（5度目）。** 水準Lという新しい条件の上で、
   arm 9（`9:xor-all:0xFF`）が比較対象（分岐段の候補run列）を動かすことを確認する。
   動かさなければ`m7hs`段階1と同じ方法でarmを振り直す。**有効な対照が1つも
   無ければ段階2の判定は行わず、主判定をO'（対照を作れなかった）とし、試した
   armの一覧を記録する。** これは`m7hq`・`m7hu`・`m7hw`・`m7hy`に続く5度目である。
4. **対照が比較結果を変えること。**
5. **決定論性**: 水準Lの条件O・条件M・対照armのそれぞれについて、生ログが独立
   2回でバイト一致し、比較結果も一致すること。
6. **水準Eの再現**: 取得済みログで`m7hs`の結果（分岐位置56、対照区間22本一致、
   `eq`偽が候補#3の位置4の1箇所）が再現すること。再現しなければ判定O。
7. `tools/check_cleanroom.sh`が全項目OK。

## 言えないこととして先に書いておくこと

- **K1が出ても「進み方の差が分岐の唯一の原因」とは言えない。** 打鍵時刻を
  動かすと、進み方の差以外の条件（ディスクの回転位相、subの内部状態、mainの
  状態）も同時に変わる。**本稿は単一の変数を分離した介入ではない。**
  言えるのは「打鍵を遅らせると差が消える」までであり、その媒介が進み方で
  あることは**別の測定を要する**。この限界をここに明記する。
- **K2が出ても、進み方の差が無関係だとまでは言えない。** 上記の注意のとおり、
  水準Lで進み方の差が解消していることを示せた場合にのみK2を主張する。
- 値は読まない。差の内容には踏み込まない。
- 条件O・`disk#10`という1本のディスク・1条件である。一般性は主張しない。
- 水準Lで`FILES 2`が水準Eと同じ結果に到達するか（画面）は、本稿の判定に
  用いない。到達判定が要る場合は`tools/check_l3_entry_screen.py`を使い、
  **画面本文は出さない**（禁止事項7）。

## 禁止（本稿の測定中も例外なく適用）

- 公式ROMのバイト列を読まない・出力しない・保存しない。逆アセンブルしない。
- 応答run・受信run・大量転送runのバイト値、FDCデータポート値、シリンダ値、
  PCN値を出力しない。出してよいのは件数・run長・位置番号・`eq`の真偽・
  `cmp`の符号・clock・frame・真偽値・rc・介入armの指定文字列のみ。
- 画面本文の生の行を報告・ノート・コミットメッセージ・ツール出力へ書かない
  （禁止事項7）。
- 公式ディスクの実ファイル名を展開して表示しない。
- 第三者の逆アセンブルリスト・解析記事のコード断片を参照しない。
