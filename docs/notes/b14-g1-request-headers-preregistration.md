# B14: サブの RAM 上のコードが動き出す前の、G1 の要求の見出しを記録する — 事前登録

記録日: 2026-10-31
位置づけ: [追補3](goal-b-policy-addendum3-request-headers-2026-10-31.md) の範囲での測定。
**このノートは測定より先にコミットする。** 結果を見てから規則を変えない（変えるときは後続ノートで）。

## 1. 問い

サブが `0x2000` 以上で最初の入出力をする前に、main は G1 のどんな要求を送るか。公式と自作で同じか。

## 2. 条件

OO・SS 各 2 走（自作は 2a4f910）。条件は B13 と同じで、クラウドの実行環境で行う。B13 と同じ対照を通す。実装は `tools/b14_request_headers.py`。

## 3. 求め方（事前に固定）

- 生の入出力ログの main 節の、B6 と同じ開始の行から後を使う
- **要求:** main の `OUT $FD` の連続。main の `IN $FC` が 1 回でも挟まれば、次の `OUT $FD` は別の要求とする
- 各要求の**先頭の値と件数**だけを取り、他の値は読み捨てる
- サブの節で発行元 PC が `0x2000` 以上の最初の行の `clock` を基準にし、各要求の最後の `clock` が基準より前なら `before`、後なら `after` とする

## 4. 記録の白リスト

全行が次のどれかに fullmatch することをツールが検査する。

- `# 識別子: G1` / `# 走: <name>`
- `hi-start: yes|no`
- `request <番号> <2桁16進> length=<N> <before|after>`（`before` は全件、`after` は最初の 8 件）
- `totals before=<N> after=<N> bytes=<N>`

## 5. 判定（事前に決める）

- **再現:** 同じ腕の 2 走の `before` の行が一致するか
- **最後の要求:** OO の `before` の最後の 3 件を書く。コードを送って走らせる要求の候補はここにある。これは候補であって、働きは決めない
- **公式と自作:** OO と SS の `request` 行を先頭から比べ、最初に違う番号を書く
- 次に、候補の要求を自作のプローブで公式サブへ送り、働きを測る。その事前登録は別に書く
