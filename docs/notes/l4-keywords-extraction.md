# L4 命令語一覧の機械抽出（M7段階3準備）

`docs/notes/l4-token-design.md` 末尾の追記（2026-09-15、e77ddbe）は、トークン番号を
「マニュアル索引の全語を大文字 ASCII 辞書順に並べ、0x80 から振る」という規則で
決めると書いた。その追記は語の出所を `tools/basic_surface.tsv`（186行）とし、
出典の章立て「基本命令166項目・拡張命令16項目」（計182）との差4を「未解消」と
書き残していた。

本ノートは、その語の一覧を `tools/basic_surface.tsv` からではなく
**リファレンスマニュアルの目次から機械抽出し直した**記録である。

## tools/basic_surface.tsv は測定条件表であって命令語一覧ではない

`tools/basic_surface.tsv` は M3（`docs/notes/m3-demand-profile.md`）で
「命令表から測定条件を生成する」ために作った表で、1行＝1測定条件。
中身を読み返すと、命令語の一覧としてそのまま使うには次の混入がある。

- **測定条件名としての造語**: `COLORAT`（`COLOR@ 2:PRINT 1` を打つ条件名）、
  `GETAT`（`GET@`/`PUT@` を使う条件名）など。マニュアルの索引にこの綴りの語は無い
- **2語を1行にまとめた行**: `GETAT` の note 列に「`GET@` / `PUT@`」と書かれている
  とおり、1テスト条件の中に2つの命令語が入っている
- **意図的に除外した行**: `needs=skip` の行（`AUTO` `EDIT` `MON` `TERM` `WAIT`
  `CHAIN` `DSKO$` `LPRINT` 系など、`docs/notes/m3-demand-profile.md` の
  「見送った16命令」）

したがって `tools/basic_surface.tsv` の186行・見出しの「166+16=182」は、
そもそも命令語の個数を数える設計になっていない。今回の「差4」の解消は、
この表を突き合わせても得られない（実際、突き合わせても一致しなかった＝
下記「決着」参照）。

## 抽出のやり方

新しいスクリプト `tools/l4_extract_keywords.py` は、`tools/gen_suite.py`
（M3で命令表を読んで測定条件を生成する既存スクリプト）を土台の作法として
踏襲しつつ（`pathlib` でのパス解決、環境変数経由でのみ私物パスを受け取る、
モジュール docstring に使い方を書く、等）、目的が違う（測定条件生成ではなく
語の抽出）ため中身は新規に書いた。既存に「マニュアルOCRテキストから語を
機械抽出するスクリプト」自体は無かった＝M3の「機械的に抽出した」という
記述は、実際には自動化されたスクリプトの成果物ではなく、`tools/basic_surface.tsv`
は手作業で書き起こされた表だったとみられる（tools/ 配下に該当スクリプトが
見つからないことによる推定）。

### 出典にした箇所

リファレンスマニュアルには命令語の一覧が2箇所ある。

1. **各章の目次**（本ノートで使った方）: 第2章「基本命令」の目次
   （マニュアルのローマ数字ページ ii〜vi 相当）と第3章「拡張命令」の目次
   （ページ vi 相当）。単純に「語＋リーダー（点線）＋頁番号」の1行1語形式
2. **機能別索引**（vii〜xviii、本文1.13.1が「本書 vii~xvii ページ」と
   案内している方）: コマンド・ステートメント・関数・予約変数などに
   細分してあるが、各語の説明文（日本語の一文）が同じ行に混在しており、
   OCRノイズと相まって機械抽出が著しく不安定だった

1.の目次だけを採用した。語と頁番号だけの単純な形式で、説明文を一切含まない
ため「命令語の名前と頁だけを出し、説明の文は写さない」という要件に
機械的に沿う。2.は今回は使っていない（読んではいるが、抽出処理は組んで
いない。理由は下記「機能別索引を使わなかった理由」）。

### 抽出手順（`tools/l4_extract_keywords.py`）

1. マニュアルOCRテキスト中で「第2章基本命令」「第3章拡張命令」「資料1」の
   出現位置を、文字間にOCRの空白ゆらぎを許す正規表現で探し、
   [第2章目次の開始, 第3章目次の開始), [第3章目次の開始, 資料の開始) の
   2区間を切り出す
2. 区間内のテキストから、頁番号らしいパターン（`\d-\d`、ただし数字列の中に
   OCRが空白を挟むことがあるので許容）をすべて見つける
3. 頁番号のマッチとマッチの間のテキストを「その頁番号に対応する語の生テキ
   スト」として切り出す（語の文字種を先に決め打ちすると、`LOAD?` の `?` の
   ような記号でマッチが崩れて後続行を巻き込むため、頁番号という一番安定
   した目印から逆算する方式にした）
4. 生テキストから: 意味を持ちうる文字集合（英数字・記号・空白・リーダー・
   CJK判定用の範囲）以外を除去 → 末尾のリーダー（点線・中黒・句読点）を
   剥ぐ → 空白を除去 → 日本語（見出しバナー等の混入）が残っていたら最後
   に出てくる日本語文字より後ろだけを採る → 小文字 `l` を `1` に正規化
   （マニュアルの命令語は記号を除き大文字のみなので、小文字が残るのは
   OCRノイズと判断できる） → 語頭に残った数字（頁ノンブルの残骸）を削る
   → 大文字化
5. 既知のOCR個別事例（後述）を語＋頁のペアで突き合わせて補正する
6. 頁ごとに同名の語（`MID$` `VIEW` `WINDOW`）を1行に統合し、頁を `;` で連結

出力列は `word / category / pages`。`category` は `基本命令`（第2章目次）
または `拡張命令`（第3章目次）で、これは M3のtsvが独自に付けた分類
（numfunc/strfunc/screen/…）ではなく、**マニュアル自身の章立てそのもの**
（1.13節が言う「基本命令」「拡張命令」の区分）を使っている。細分類
（コマンド／ステートメント／関数／予約変数）は機能別索引側の情報であり、
今回は抽出していない（下記の理由により）。

### 機能別索引を使わなかった理由

機能別索引（vii〜xviii）は、同じ語がカテゴリごとの見出し行に列挙された後、
日本語の説明文とその頁番号が続く形式で、OCRテキスト上では

```
CLS COLOR COLOR@ CONSOLE LOCATE SCREEN WIDTH 画面を消去する・・・2-27 ...
```

のように「語の並び」と「説明文＋頁」が別の行に対応しているが、OCRの
連結でどちらも同じ地の文になっており、語の並びと説明文の対応（何番目の
語が何番目の説明文に対応するか）を機械的に取り違えずに割り当てるのが
困難だった。加えて画面幅で2カラム組になっているページはOCRの読み順が
カラムをまたいで前後する（試しに読んだ範囲では見かけ上アルファベット順
に見えたため実害は無かったが、確証が持てない）。目次（1.の方）は
この問題が無く、かつ全語を含むため、そちらを正典にした。

## 既知のOCR個別事例（`KNOWN_OCR_FIXUPS`）

ページの境目にあるノンブル（ローマ数字のページ番号）がOCRで数字や単独の
アルファベットに化け、直前・直後の語や頁番号に融合する事例が数箇所あった。
一般規則では判別できなかったため、語＋頁のペアをキーにした個別補正表
（`tools/l4_extract_keywords.py` の `KNOWN_OCR_FIXUPS`）で対処した。

| 抽出直後 | 頁 | 正しい語 | 原因 |
|---|---|---|---|
| `CHAIN` | `2-151`(誤) | `CHAIN` | `2-15` の直後にノンブル`ii`→`11`が融合し頁が伸びた |
| `IIILINE` | `2-124` | `LINE` | ノンブル`iii`→`III`が語の直前に融合 |
| `VSET` | `2-213` | `SET` | ノンブル`iv`→`1v`の`v`が語の直前に残った |
| `-VCMDSTOPM` | `3-40` | `CMDSTOPM` | 同上のノンブル残骸＋制御文字混入 |
| `SOR` | `2-218` | `SQR` | 索引の印字自体が`Q`を`O`に見せる字形（`tools/basic_surface.tsv`のSQR行の注記と同じ既知差異） |

このキーはスクリプト内で語＋頁の組として固定してあるので、マニュアルOCR
テキストの版が変わってこの箇所の周辺が変化すれば、自己検査 (b) が
コミット済み `src/l4_basic/keywords.tsv` との不一致として検出する。

## 語の数と「差4」の決着

`tools/l4_extract_keywords.py` を実測にかけた結果:

- 第2章目次（基本命令）: 生の行数 173、うち完全に同名の重複（`MID$` `VIEW`
  `WINDOW` がそれぞれ関数形・文形の2行で載っている）を1語に統合すると
  **170語**
- 第3章目次（拡張命令）: **19語**（`CMDBGM` `CMDOUTM` `CMDPAL` `CMDPCM`
  `CMDPCMLOAD` `CMDPCMPLAY` `CMDPCMRECORD` `CMDPCMSAVE` `CMDPCMSTOP`
  `CMDPLAY` `CMDRHYTHM` `CMDSOUND` `CMDSTOPM` `CMDUNLINK` `CMDVOICE`
  `CMDVOICECOPY` `CMDVOICELFO` `CMDVOICEREG` `STATUS`）
- 合計 **189語**（`src/l4_basic/keywords.tsv` の実データ行数と一致）

マニュアル本文 1.13.2 は拡張命令を「**19個**」と明言している。今回の
抽出値19はこれと**完全に一致**した。`tools/basic_surface.tsv` 冒頭コメント
の「拡張命令16項目」は誤り（過小）だったことになる。

マニュアル本文 1.13.1 は基本命令を「166個」としており、今回の抽出値170
との差は4。この4は、機能別索引（vii〜xviii）を実際に読んだ範囲で照合すると、
**予約変数**（コマンド・ステートメント・関数のいずれにも属さず、機能別索引
で独立の「予約変数」枠に分類されている語）に対応することが分かった。

| 語 | 頁 | 機能別索引での分類 |
|---|---|---|
| `CSRLIN` | 2-46 | 画面制御予約変数（3.画面制御） |
| `DATE$` | 2-51 | 予約変数（7.特殊な命令や関数） |
| `ERL/ERR` | 2-72 | 予約変数（7.特殊な命令や関数） |
| `TIME$` | 2-230 | 予約変数（7.特殊な命令や関数） |

170 − 4 = **166**。本文の主張と一致する。すなわち本文が言う「基本命令166」
は、目次に載っている170語のうち予約変数4語を除いた、コマンド・ステート
メント・関数だけの数と解釈すれば説明がつく。これは機能別索引の実物を
読んで確認した対応であり、当て推量ではない（読んだ頁は下記「読んだ頁」参照）。

**方針として、`src/l4_basic/keywords.tsv` は166ではなく189語すべてを収録する。**
`docs/notes/l4-token-design.md` の決定が「対象の語はマニュアルの全語とする」
としているため、本文が「基本命令」と呼ぶ166語に絞る理由が無い
（予約変数もトークンとして必要になる）。

### `tools/basic_surface.tsv` 186行との対応（参考、非対象）

参考までに、`tools/basic_surface.tsv` の186行・見出しの「166+16=182」との
差4も、上記の予約変数と同じ理屈で説明が付きそうか確認した。tsvは
`CSRLIN`（numfunc扱い？いや実際は見当たらない）を含んでいない、`ERL/ERR`
`DATE$` `TIME$` に相当する行も見当たらない一方で、`COLORAT` `GETAT` の
ような造語2行を含む。tsvは冒頭で述べたとおり測定条件表であって命令語
一覧ではないため、この186という数字と166+16という数字の差の内訳は
「予約変数の有無」だけでは説明しきれず（造語2行、skip行の混入など複数の
要因が重なっている）、**この差はtsv側の設計（測定条件表）に起因するもの
としてこれ以上は追わない**。今回の189語は tsv を経由せず目次から独立に
数え直した値であり、tsvの186とは別の集計である。

  出現）から "第3章拡張命令" まで、および "第3章拡張命令"（2つめの出現）

  ページ表記で vii〜xviii（1.13.1が案内する範囲）。読んだのは分類見出し

  予約変数の小見出し、および各語の並び）であり、日本語の説明文（各語の
  一文解説）はこのノートにも `src/l4_basic/keywords.tsv` にも転記していない

いずれもN88-BASICの言語仕様（命令の分類と頁）であり、CLAUDE.md

を読む」の範囲内。ROM内部構造やコード断片は読んでいない。

## 自己検査

`tools/l4_extract_keywords_selftest.sh`:

- マニュアルテキストが無い環境（`PC88_REF_MANUAL_TXT`未設定）では
  `SKIP: マニュアルテキストなし＝未検査` を出して rc=0
- ある環境では (a) 再実行での決定性（sha256一致）、(b) コミット済み
  `src/l4_basic/keywords.tsv` との一致、(c) 語の重複が無いこと、
  (d) 故障注入（マニュアルテキスト中の `ABS` を1箇所 `ZZZ` に書き換える）
  で出力が変わること、を確認する。手元の環境（`refs/manual.txt` あり）
  では4項目すべてOK
- `tools/run_all_selftests.sh` に登録済み（期待rc=0。マニュアルテキストが
  無いCIでもSKIPでrc=0になり、ラッパを壊さない）
