## 初回で分かったこと（開示。結果ノートに詳しく書く）

- 引数の受理範囲は想定と違った: 第1引数だけ（`console 0`）は ERR 2、`console`・`console ,`・`,,`・`,,,` は ERR 22、第1引数 25 以上は ERR 5（20行・25行とも同じ上限 24）、
  第2引数は 1〜25 が受理（0 と 26 以上は ERR 5）、開始＋行数が行数を超えても受理、第3・第4引数は 0〜255 が受理（−1 は ERR 5）、文字列は ERR 13。
- ウィンドウは予測どおり（窓外を保持し窓内だけスクロール・cls、下端はファンクションキー表示で行数−2 に切られる）。`width` で窓は全画面に戻る。
- カラー切替は `width` と同じ10項目の手順で、**CRTC の P5 は 0x13 → 0x53（bit6 を立てる）**。白黒へ戻すときも同じ手順で P5=0x13・0x30=0x23。切替が実際に起きるときだけ画面が消える。
- 初回の判定関数に欠陥があった（`reset_blocks` が 51:00 の直後に5パラメータが並ぶと仮定していたが、実際は DMAC の書き込みが間に入る）。そのため `cm-c1` の P5 に関する3項目が「外れ」と付いたが、
  観測そのものは P5=0x53。判定関数を直した（記録済みの観測から判定を計算し直すだけ。観測は変わらない）。
- `cls` 腕の `cursor` 判定22件は、終了の印を打つ直前の「サンプルされたカーソル位置」が `cls` の実行より前のもの（`cls` と印字が同じフレームの中で実行されるため、カーソルコマンドが1フレームに1回しか書かれない）で、
  `cls` 後のカーソルを見ていない。器具の限界で、規則の外れではない。カーソルの位置は `cls` のあとに `print "zzz";` を打ち、その位置（z）で読むことに変える（下の `clsz` 腕）。
