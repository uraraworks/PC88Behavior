# B79: F1 の道で、自作が行き詰まる直前の要求を測る — 結果

記録日: 2026-11-04
規則: [b79-g1-f1-requests-before-deadlock-preregistration.md](b79-g1-f1-requests-before-deadlock-preregistration.md) どおり。測定はクラウドの実行環境で rc=0。記録は `measurements/b79-g1-f1-requests-before-deadlock.txt`。

## 結果

| | 要求 | そのあと |
|---|---|---|
| 公式 | `0E`（7）、`15`（5）、`0D`（3） | `15` の応答の 128 バイトを受けて `0D` へ |
| 自作 | `0E`（7）、`15`（5） | **main とサブが `IN $FE` の 2 を読み合う行き詰まり** |

## 分かったこと

自作は `0x15` の応答を返さない。main は応答を待ち、サブは次のバイトを待っている。B72 のプローブ（ドライブ 1、`0E` のあとすぐ `15`）では自作も応答を返したので、G1 の場面との違いがある。

## 読み方（推定）

B65 の腕はドライブ 2 に 2 枚目を入れている。G1 の `0E` がドライブ 2（D=1）を読むなら、B70 で確かめたのは読み先と刻印までで、そのあとの `15` は B70 の器具の不備で確かめられていない。B80 で、D=1 の `0E` のすぐあとの `15` を、自作の走でまず確かめる。
