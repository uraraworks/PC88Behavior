# ext1 — 拡張ROMバンク（4th ROM）の読み分け・欠落・割り込み安全性・中継費用 — 事前登録

記録日: 2026-09-19
状態: 事前登録、測定前

## 位置づけ

[ext-rom-bank-survey.md](ext-rom-bank-survey.md)（`d55a9bf`）の下調べを受け、
ユーザーが配置案C（既存12モジュールの配置は動かさず、今後の新規機能だけを
バンクへ新設する）を選んだ。案Cの前提として、**バンク切り替えの仕組み
そのもの**（読み分け・ファイル欠落時の扱い・割り込み安全性・中継呼び出しの
費用）を、**自作の試験ROMだけ**で確かめる。**本ノートは事前登録のみ。
測定・実装は行っていない。** `src/`・`docs/spec/` は変更していない。

対象は下調べ第2節の `pc88main.c` 実装（ポート`0x71` bit0 = 総スイッチ、
`0x32` 下位2bit = バンク選択、`0x6000`–`0x7FFF` の**読み出し**のみ切替、
書き込みは常にメインRAM）。公式ROMの内容・挙動は一切対象にしない
（下調べ6b節の Q5・Q6 は本ノートの範囲外のまま）。

## 前提とスコープ

- 使うROMは全て自作（後述）。`private/` は参照しない。公式ROMディレクトリを
  `--rom-dir` に渡す経路も使わない。
- 器具は `tools/harness/frontend/q88measure` を直接叩く（`tools/conform_l3.sh`
  系は公式ROM前提のラッパーなので使わない。`tools/harness/romram_selftest.sh`・
  `tools/harness/intlog_selftest.sh` と同型の「自作ROM＋q88measure直叩き」
  スクリプトを新設する想定）。
- 打鍵は使わない（BASICを経由せず、ROM自身のコードが最初からバンク操作を
  行う）。フレーム数は少なくて済む（下記の腕ごとの見積り参照）。

## 試験ROMの設計

`tools/harness/make_test_rom.py` と同じ流儀（生成バイト列は全て自分で
書いたもの、ENTRY等の固定番地方式）で、この測定専用に新しい生成スクリプト
（`tools/harness/make_ext_rom_test.py` 想定、本ノートでは未作成）を書く前提
で設計する。

### N88.ROM（常駐部、32KB）— 中継ルーチンと各腕のドライバ

- `0x0000`: `JP SETUP` → 既知値をRAMへ置いてから各腕のエントリへ分岐する
  定型（`make_test_rom.py` の `SETUP`/`ENTRY` パターンを踏襲）。
- **中継ルーチン `BANK_CALL`（常駐部、番地は `0x5000` 台に置く。窓の外＝
  自分自身が消えない番地であることが要件）**:
  1. `IN A,(0x71)` / `IN A,(0x32)` で現在値を保存（下調べ1節「読んでから
     書き戻す」定型を踏襲）。
  2. 保存値を**ビット単位で書き換えて**バンクを選ぶ（`0x71` bit0=0,
     `0x32` 下位2bitへバンク番号）。他ビットは保存値のまま
     （サウンド割り込みマスク等、無関係なビットを壊さないことを
     設計上の要件にする——ここは測るまでもなく実装の書き方の問題）。
  3. `CALL` で窓の中（バンク側）のルーチンへ飛ぶ。
  4. 戻り値（`A`レジスタ等）を一時退避。
  5. 保存しておいた `0x71`/`0x32` を書き戻す。
  6. 戻り値をRAMの結果マーカーへ書く。
- 各腕の呼び出し元はすべて `BANK_CALL` 経由（呼び出し元自身は常駐部＝
  窓の外に置く。Q3の腕だけ例外として「窓の中から呼ぶ」陰性対照を作る）。

### N88_0.ROM〜N88_3.ROM（拡張ROM、各8KB）— 自作の識別パターン

各バンク `n`（0〜3）は以下の自作パターンを持つ（識別用、公式データとは
無関係）:

- 先頭1バイト（`0x6000`）: `0xA0 + n`（バンク番号を符号化した既知値）。
- 末尾1バイト（`0x7FFF`）: `0xB0 + n`。
- `0x6000` に置く簡易ルーチン（`BANK_CALL` から `CALL` される先）:
  ```
  6000: 3E (A0+n)   LD A,(A0+n)      ; 先頭バイトそのものを戻り値にする
  6002: C9          RET
  ```
  （＝先頭マーカーとルーチンを同じ番地に同居させず、ルーチンは
  `0x6010` に置き、`0x6000`/`0x7FFF` は純粋なデータマーカーとする方が
  検査しやすい。設計時の判断: **ルーチンは `0x6010` 固定、データマーカーは
  `0x6000`＝先頭・`0x7FFF`＝末尾に分離する**。）
- Q3（割り込み安全性）用に、各バンクの `0x6020` にもう1つ簡易ルーチン
  （カウンタをインクリメントして返すだけ）を置く。

## 観測方法

- 結果マーカー: RAM `0xC000`〜（`make_test_rom.py` の `RAM_READ`/`RAM_WRITE`
  と衝突しないよう、この測定専用の番地帯 `0xC100`〜を使う）。
  `BANK_CALL` の戻り値・往復回数・エラーフラグをここへ書く。
- 採取は `--mem-write-log`（`--mem-write-range 0xC100-0xC1FF`）と
  `--io-log`（`0x71`/`0x32` の書き込み列を確認する陽性対照・定型検査用）。
  自作データのみを扱うため、値をそのまま報告してよい（CLAUDE.md禁止事項7の
  「画面本文」は公式ソフトの表示内容が対象であり、本測定はVRAMを一切
  使わない自作RAMマーカーなので該当しない）。
- Q3・Q4では `--int-log` も併用する（受理の有無・時刻＝`clock`列の確認）。
- Q4の「費用」は **`clock`列（M6c、main/sub・iolog/intlogを横断する単調増加
  通し番号）の差分**で定義する。実CPUのT-state数ではなくエミュレータ内部の
  イベント通し番号であることを報告に明記する
  （CLAUDE.md「エミュレータで測った値はエミュレータの実装を測っている」を
  踏まえ、**定性**——中継が成立し戻れること——を主結論にし、この差分は
  参考値として添えるに留める）。

## 問い・腕

判定名は事前に固定する。

### Q1 読み分け（腕 B1〜B3）

- **B1（陽性対照）**: `0x71` を書き換えず（デフォルト＝通常メインROM）、
  `0x6000`/`0x7FFF` を直接読む。**期待**: メインROM側の値（常駐部が
  あらかじめ `0x6000`/`0x7FFF` に置いた既知パターン、バンクの `0xA0+n`
  とは異なる値）が読める → 判定名 `q1_default_reads_main`。
- **B2（読み分け本体）**: バンク0〜3を順に選び、`BANK_CALL` 経由で
  `0x6000`・`0x7FFF` を読む。4バンク×2番地=8回。**期待**: 各バンクで
  `0xA0+n`・`0xB0+n` が読める → 判定名 `q1_bank_reads_match_n`。
- **B3（復帰確認）**: B2の直後に `0x71` を戻し、再度 `0x6000` を読む。
  **期待**: B1と同じメインROM側の値に戻る → 判定名 `q1_restore_reads_main`。
- 保つべきビット: `BANK_CALL` は `0x32`/`0x71` の非対象ビットを保存・復元
  する設計なので、B2実行前後で他ビット（例えば `0x32` bit5のPMODE）を
  意図的に非デフォルト値へ書いておき、B3後も変化していないことを結果
  マーカーへ含める（`q1_other_bits_preserved`）。

### Q2 欠落（腕 B4）

- **B4**: `N88_2.ROM` を欠落させた ROM ディレクトリを別途用意し、B2と同じ
  手順でバンク2を選んで `0x6000` を読む。**期待**: `0xFF`
  （下調べ2節 `memory.c` の `load_rom()` 未発見時 `memset(...,0xff,...)`
  の裏取り）→ 判定名 `q2_missing_bank_reads_ff`。
- 対照: 同じ実行でバンク0（存在する）を読み、`0xA0` が読めること
  （欠落が他バンクへ波及していないことの確認、`q2_other_banks_unaffected`）。

### Q3 割り込み安全性（腕 B5〜B7）

- 設計判断: `--main-interrupt-intervention` は割り込みの抑制/1回遅延しか
  できず、「バンク切替の窓の途中」へ精密に割り込みを打ち込む機能ではない。
  代わりに **VSYNCは毎フレーム自然発生する**ことを使い、`BANK_CALL`
  経由の往復（バンク選択→`0x6020`のカウンタルーチン呼び出し→復元）を
  **多数のフレームにまたがるループ**として実行し（`--enable-int` 相当を
  N88.ROM側にも実装し、IM1ハンドラを常駐部RAM外＝ROM内の固定番地、
  ただし窓の外の番地に置く）、自然にVSYNCが窓の中で発生する試行を
  含める。厳密な同時性は保証できないため、**多数回の往復（例: 200回）
  を通して一度も結果マーカーが破損しないこと**を合否条件にする
  （精密な1回勝負ではなく統計的な網羅で判定する、という設計上の妥協を
  ここに明記する）。
- **B5（陽性対照、割り込みなし）**: `--enable-int` 相当を無効にしたROMで
  200回往復。全て `0xA0+n` 系の期待値と一致 → `q3_no_interrupt_baseline_ok`。
- **B6（本体）**: 割り込み有効化ROMで同じ200回往復。ハンドラは**常駐部の
  番地**（窓の外、例 `0x1300`）に置き、カウンタをインクリメントするだけ
  で `RETI`。**期待**: 200回すべて一致、かつ `--int-log` に受理記録が
  複数件ある（＝割り込みが実際に窓を跨いで発生した証拠）
  → `q3_interrupt_during_window_ok` かつ `q3_interrupt_actually_occurred`。
- **B7（陰性対照、禁止設計の実演）**: ハンドラを**窓の中の番地**
  （例 `0x6030`、いずれかのバンク側にしか実体が無い）へ向けて `CALL` する
  ように書き換えたROMで同じ手順を走らせる。**期待**: 選択中のバンクが
  ハンドラの想定と食い違う瞬間があるため、結果マーカーが破損する
  （想定外の値・ハング・`--frames` 超過のいずれか）→
  `q3_handler_inside_window_breaks`（陰性対照が「壊れる」ことそのものが
  合格条件——CLAUDE.mdの「陽性対照が迂回する／合格条件が失敗状態を好む」
  という過去の教訓を踏まえ、判定スクリプト側で「壊れなかったらNG」に
  しておく）。

### Q4 呼び出しの費用（腕 B8）

- **B8**: `BANK_CALL` 経由の往復を1回だけ行い、直前（バンク切替前の
  マーカー書き込み）と直後（復元後のマーカー書き込み）の `clock` 列の
  差分を `--mem-write-log` から読む。2走で同じ差分になることを決定論性
  として確認する → `q4_relay_cost_clock_delta`（定性: 値が2走で一致し、
  かつ有限であること。定量は参考値として報告するのみで合否条件にしない）。
- 呼び出し元が「窓の中」の場合の可否: 前提として窓の中のコードは
  `BANK_CALL` を**呼べない**（自分自身がバンク切替で消えるため）。
  この設計上の制約自体は測るまでもない自明な帰結だが、**誤って窓の中に
  `BANK_CALL` 相当を置いた場合に何が起きるか**を陰性対照として一応
  確かめる腕は用意しない（Q3のB7で同種の壊れ方を既に確認するため、
  重複を避けて対象外とする——腕数を絞る判断）。

### 任意腕: ROM_VERSION（`0x79D7`）独立性（腕 B9）

- 下調べのQ6は公式ROM必須のため対象外だが、「バンク選択状態と無関係に
  `main_rom[0x79D7]` を直接読めるか」だけなら自作ROMで確認できる。
  **ただし `0x79D7` はメインROM側の予約番地であり、この試験ROM自体も
  同じ番地を（今後の実装のため）予約している**。ここでは値の中身では
  なく「窓が拡張ROM側を指していても、`0x71` を戻せば `0x79D7` を含む
  メインROM側がそのまま読める」という構造だけを確認する（B3の
  `0x7FFF` 読みと本質的に同じ検査なので、**別腕を立てず、B3の対象番地に
  `0x79D7` を追加する**——実施時に決める、ここでは対象外にはしない）。

（腕数: B1〜B8 の8腕。B9はB3への追加として吸収し独立腕にしない。
各腕2走、決定論性G3。）

## 器具・関門

- **G1 器具自己検査**: `--mem-write-log`・`--int-log` の自己検査を
  `tools/harness/mem_write_log_selftest.sh`・`intlog_selftest.sh` と同じHEADで
  再実行し OK であることを確認してから本走に入る。
- **G2 取りこぼし0**: `--mem-write-range` が結果マーカー帯を過不足なく
  covering していること（範囲外の書き込みが無いこと）。
- **G3 決定論性**: 各腕2走、結果マーカーの並び・`clock`差分が一致。
- **G4 陽性対照**: B1・B5・B6のベースライン一致。
- **G5 陰性対照**: B4（欠落→`0xFF`）・B7（窓の中ハンドラ→破損）。
  **G5は「対照が失敗状態になること」自体が合格**であることを判定
  スクリプトのコメントに明記する。
- **G6 故障注入**: B2の判定ロジックを意図的に壊した版（例: バンク番号の
  読み替えを1つずらす）を用意し、正常版と異なる結果になることを確認する
  （`romram_selftest.sh` の3種故障注入と同型）。または、意図的に
  `N88_1.ROM`と`N88_3.ROM`の中身を入れ替えたROMディレクトリを作り、
  B2の判定が「入れ替わった」ことを検出できるかを確認する（後者を採用
  ——コア側の改造が不要で自作ROM側だけで完結するため）。
- **G7（対象外）**: 画面本文・VRAM関連の関門は使わない（本測定はVRAMを
  一切使わないため、l4系ノートのG5〜G7とは無関係）。

## 結果の行き先

測定後、`docs/spec/l1-ipl.md` への追記（ポート`0x32`/`0x71`の既存記述の
すぐ後に「拡張ROMバンクの読み分け・中継呼び出しの型」の節を足す案）と、
新規 `docs/spec/ext-rom-bank.md`（バンク切替の完全な仕様——読み分け表・
欠落時の扱い・割り込み安全性の設計制約・中継ルーチンの定型コード）の
どちらにするかは測定後に決める。後者（新規spec）が有力
（l1-ipl.mdは「起動直後のIPL」というスコープで、バンク切替は本来
L4以降の実行時の話であり、スコープが異なるため）。

## 迷った点・設計判断（実施前に固定しておく）

1. **Q3の精密タイミング化を諦めた**: `--main-interrupt-intervention` は
   抑制/1回遅延のみで、窓の内側ピンポイントへの割り込み注入はできない。
   統計的な多数回往復（200回）へ切り替えた。
2. **ルーチンとデータマーカーを同一番地に置かない**ことにした（先に
   同居案を書いたが、読み出し検査とルーチン呼び出し検査が混ざると
   故障の切り分けが難しくなるため分離）。
3. **B9（ROM_VERSION独立性）を独立腕にせずB3へ吸収**した。腕数を絞る
   （CLAUDE.mdの精神、かつ下調べの「見立てであり決定ではない」という
   慎重さを保ちつつ、腕を無闇に増やさない）。
4. **故障注入はコア側パッチでなくROM側の入れ替えで済ませる**ことにした
   （G6）。`romram_selftest.sh`型のコア再ビルドはこの測定には過剰
   （バンク切替はコアの実装を読んだ範囲で既に単純な配列参照だと分かって
   おり、疑うべきはむしろ「自作ROM・判定スクリプト側の取り違え」の方が
   優先度が高いと判断した）。
