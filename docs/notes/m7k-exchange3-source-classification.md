# m7k: 交換#3応答の生成源切り分け

測定日: 2026-08-13

## 1. 目的

m7jでmain側の値一致プレフィックスが3件で止まった4件目、すなわち
交換#3の応答先頭について、生成源をディスク実データ（説D）、FDC結果
フェーズ（説F）、ROM内部状態（説R）へ切り分けた。値そのものではなく、
媒体差し替えへの連動、応答長、位置別の同一／相違、FDCデータ部・結果部
との一致件数だけを用いた。

## 2. 情報境界

`private/`は直下の名前だけを確認し、参照ROMを`private/rom`、参照ディスクを
`private/disk`と特定した。内容は開いていない。測定プロセスには
`PC88_REF_ROM_DIR`と`PC88_REF_DISK_DIR`で渡した。公式ROM、公式ディスク、
公式ディスクから読み出されたデータのバイト列を表示、保存、逆アセンブル
していない。

参照ディスクと、`tools/make_l3_testdisk.py`が規則から生成した自作D88を、
同じ公式ROM一式で各600フレーム・2走した。生ログ、一時比較器、自作D88、
混成ROMコピーはリポジトリ外の使い捨て領域だけで扱った。出力したのは長さ、
一致長、一致件数、同値グループ数、位置ごとの同一／相違だけである。

## 3. 比較器と再現性の関門

本測定前に`tools/cmp_io_selftest.sh`全27項目、
`tools/cmp_fdc_sectors_selftest.sh`、`tools/diag_l3_mixed.sh`の検出力selftest
a〜lを通した。一時比較器でも同一入力を同一、意図的な1バイト差を相違として
検出した。応答長1だけでは単発経路と応答バッファ経路を分離できないため、
main側のSEND/RECV runによる交換境界と、混成側の`RESP_ACTIVE`状態遷移を
別々に扱った。

参照ディスク2走、自作D88 2走、現行自作subとの混成2走は、それぞれ要求長・
応答長・位置別判定が再現一致した。全6走でtimeout、SIGABRT、その他の実行異常は
0件だった。

## 4. ディスク連動テスト

自作D88でも最初の6交換は参照条件と同じ要求長・応答長の順で発生し、比較対象の
交換#3は同じ8バイト要求グループ、同じ1バイト応答位置として成立した。
自作D88は有効な起動内容ではないため、その後は同系列を反復して600フレームで
120交換となったが、最初の比較窓には影響しない。

媒体差し替えにより、交換#3直前のREAD系FDCデータ部は256位置中254位置が相違し、
媒体操作が実際にFDC入力へ届いた。一方、交換#3の要求8位置と応答1位置はすべて
不変で、応答は1同値グループのままだった。したがって交換#3の対象応答は
ディスク実データへ連動せず、説Dを棄却する。

対照として次の交換#4を調べると、要求長2、応答長256で、応答は直前READの
FDCデータ部と一致長256・一致件数256だった。媒体差し替え時も応答は256位置中
254位置が相違し、FDCデータ部と同じ位置別変化を示した。実ディスクデータの
転送は交換#4であり、交換#3ではないことを独立に確認した。

## 5. 応答長とFDC構造

交換#3は、公式側・混成側とも8バイト要求に対する応答長1だった。直前のFDC操作は
READ系で、データ部256バイトと結果フェーズ7バイトを持つ。交換#3の1位置は、
FDCデータ部の対応先頭位置と不一致であり、結果フェーズの先頭位置とも不一致だった。
さらに結果フェーズ7位置のどの位置とも同値ではなく、一致組数は0だった。

m7jの「`RESP_ACTIVE`多バイト応答バッファ先頭」という分類は、4件目のmain受信を
**現行自作sub側の送信経路**へ帰属したものである。公式側の交換#3自体が複数バイト
だったという意味ではない。今回、交換境界を600フレームまで完成させて、公式側の
実際の256バイト応答は交換#4にあると分かった。応答長1だけで経路を決めない関門が、
この二つの記述を矛盾なく分離する。

## 6. 説D・F・Rの判定

- 説D: 棄却。FDCデータ部は254位置変化したのに、交換#3応答は全位置不変で、
  対応位置も不一致だった。ディスク実データは交換#4で全位置一致した。
- 説F: 直接転送・位置対応説は棄却。応答長1は結果長7と一致せず、先頭対応も
  7位置全探索も一致0だった。
- 説R: 採用。媒体に連動せず、直前FDCのデータ部・結果部のいずれにも位置対応
  しない1バイトである。m6x/m7bが支持した「直接取得できるハードウェア値では
  なく、サブROM内部の保持状態・構成状態から作る」という見立てと整合する。

ただし、FDC結果へ任意の加工を施して内部状態へ保持した後に生成する可能性まで、
I/O境界だけで論理的に排除することはできない。その場合も本分類では、結果バイトの
直接転送である説Fではなく、ROM内部生成である説Rに含める。

## 7. 介入、次の一手、限界

説Rと判定したため、値を推測する介入は行わなかった。したがってm7j条件Cの
値一致プレフィックス長3からの伸長は未確認であり、既知の最前線は3件のままである。

次に攻めるなら交換#3の8バイト要求が表す公開プロトコル上の意味を、マニュアル等の
ROM内部コードに依存しない資料と、ディスク以外の構成変更への同値関係から特定する。
実装上は「交換#3でセクタデータ先頭を返す」のではなく、1バイトの内部状態応答を返し、
実ディスクデータ256バイトは交換#4へ対応付ける必要がある。ただし、その1バイトの
生成規則が測定で確定するまでは実装へ入れない。

- 同一の公式ROM一式、同一コア、参照媒体1種と規則生成媒体1種に限る。
- 自作D88は起動に成功せず同系列を反復したため、最初の6交換だけを比較した。
- ROM内部の保持場所・更新規則はI/O測定境界から観測できない。
- 一過性SIGABRTの既往の根本原因は未特定だが、本採用系列では発生しなかった。
