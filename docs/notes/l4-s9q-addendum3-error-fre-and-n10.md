# l4-s9q 追補3 — 誤りのプローブの fre は整合の対象外、cl-n10 の再走行

状態: 追補2の再判定（`official_run2_rejudged.tsv`）でも `cl-*` 12条件が関門失敗。この追補は再判定と cl-n10 の再走行の前に置く。予測・他の関門は変えない。

## 何が落ちたか

1. **「同じ上限の測定が全て一致する」（整合）で全 `cl-*` が落ちた**。原因は**関門の定義の側**: 整合を (誤り番号, fre) の組の一致で見たが、
   **失敗した CLEAR の後に印字される `fre(0)` は直前までの履歴で変わる**（同じ 0x8000 で 11・13・115・22238 など。
   失敗した CLEAR が前の状態のまま残るためと読める）。誤りのプローブの fre は CLEAR の結果ではなく、整合の対象にすべきでない。
   誤り番号と、**受理のプローブの fre** が同じ上限で一致することを整合とする。本体で関門にした項目（アンカー一致・受理の傾き1・単調性・2反復一致）は変えない。
2. **`cl-n10` は `top_e5` を満たさない**。追補2より前の器具で走らせたため、可変プローブが7本の検証走行に 0xE5FF・0xE600 が入らなかった（追補2で直した）。cl-n10 だけ再走行する（`official_run4.tsv`）。

## 変更

- 整合は誤りのプローブの fre を比べない。受理の fre は比べる（陰性: 受理の fre が走ごとに動く合成モデルを拒否する検査を追加）。
- 再判定は2回目の保存済み観測に、cv-2 の再走行（`official_run3.tsv`）と cl-n10 の再走行（`official_run4.tsv`）を置き換えて行う。結果は `official_final.tsv`。

## 開示

誤りのプローブの fre が履歴で変わることは、2回目の観測を診断のために読んで知った。これは予測にない観測で、結果ノートに事実として書くが、予測の的中には数えない。
