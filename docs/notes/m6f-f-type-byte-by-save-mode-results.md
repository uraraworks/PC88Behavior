# m6f-f — 保存の方法ごとの種別バイト — 結果

記録日: 2026-09-27

## 1. 実行

[事前登録](m6f-f-type-byte-by-save-mode-preregistration.md)（`9b841a8`）と[追補1](m6f-f-addendum1-bsave-address.md)（`388d09f`）に従った。
器具 `6637f4d`、公式ROM起動12回（6腕×2走）。G1〜G7 はすべて真（F-S=0x80・F-D=0x00 の対照が成立、F-0 はエントリなし、
参照 diskA 複製は不変）。読んだのはエントリの 9〜15 バイト目だけで、本体・割り当て表は読んでいない。測定後の像は削除した。

## 2. 判定

| 腕 | 保存の方法 | 種別バイト | 判定 |
|---|---|---|---|
| F-S | `SAVE` | `0x80` | `type_byte_F-S=0x80`（既知の再確認） |
| F-A | `SAVE ,A` | `0x00` | `type_byte_F-A=0x00` |
| F-P | `SAVE ,P` | `0xA0` | `type_byte_F-P=0xA0` |
| F-B | `BSAVE` | `0x01` | `type_byte_F-B=0x01` |
| F-D | `OPEN … FOR OUTPUT` | `0x00` | `type_byte_F-D=0x00`（既知の再確認） |
| F-0 | 何もしない | — | エントリなし |

いずれも2走一致。**F-II: `bytes11_15_unchanged`**（全腕で 11〜15 バイト目は `0xFF`）。10 バイト目（先頭単位）は全腕で同じ値だった
（空の媒体に最初に作ったファイル。m6f-d D4 の規則どおり）。

## 3. 観察

- `SAVE ,A`（ASCII 保存）とデータファイルは同じ `0x00`。マニュアル（物理161頁）の「空白＝ASCII 保存のプログラムまたはデータ」と矛盾しない。
- `SAVE ,P` の `0xA0` は `SAVE` の `0x80` に `0x20` が加わった値だが、ビットの意味は決めない（事前登録 §8）。

## 4. 行き先

- `docs/spec/l3-disk-format.md` 1.2節の「名前欄の直後の1バイト」に `SAVE ,A`・`SAVE ,P`・`BSAVE` の値を足す（第4版）。
- 次稿 m6f-g で、`0xA0`・`0x01` を種別バイトに持つエントリの `FILES` の印と、大きさが3桁のときの表示を測る。
