# m6i-a 追補1 — 関門 G8 の未確定値を凍結する

記録日: 2026-09-22
状態: 測定前（腕 A0〜A5 はまだ1つも回していない）

事前登録 `m6i-a-main-sub-link-preregistration.md`（`ab03d13`）の関門 G8 は、
A2 の main 側上限、各腕の測定期限、A5 の保存対象レジスタ集合、キー入力の
既存シナリオ名、画面ベースライン署名を測定開始前に固定することを求めている。
本追補でそれらを凍結する。腕・到達指標・判定名・判定後の行き先は据え置きで、
結果条件は一切緩めない。

凍結値は `tests/conformance/m6ia_g8.tsv` に置く。駆動
`tools/measure_m6ia_main_sub.sh` はこのファイルが無い、または値が下表と
合わない場合、エミュレータを起動する前に `gate_failed` で止まる。

| 項目 | 値 | 根拠 |
|---|---|---|
| `timeout_limit` | 65535 | 実装 `src/l3_main/main_sub_read.asm` の各待ちループの上限。16bit で表せる最大で、正常な FDC 処理へ余裕を残しつつ有限復帰を保証する。4MHz 換算で約 0.75 秒に相当し、A2 の測定期限 600 フレーム（約 10 秒）に収まる |
| `a0_frames`〜`a4_frames` | 600 | 1回の既知 READ と、媒体未挿入時の打ち切り復帰の両方が収まる長さ |
| `a5_frames` | 6000 | 200 回の READ 反復と、終了後のキー入力場面1回が収まる長さ |
| `a5_registers` | AF,BC,DE,HL,IX,IY | 入口 `MAIN_SUB_READ_KNOWN` が保存すると宣言している主レジスタの集合 |
| `key_scenario` | base_Q | 既存のキー入力場面をそのまま流用する |
| `screen_line_count` | 3 | 下記の対照走から |
| `screen_char_count` | 20 | 下記の対照走から |
| `screen_sha256` | 580684fb…83f8e | 下記の対照走から |

## 画面ベースラインの採り方

READ を有効にしていない対照ビルド（通常の `src/build_main_rom.py` 構成）を
A5 と同じ 6000 フレーム・同じキー入力場面 `base_Q` で走らせ、行数・文字数・
SHA-256 だけを取った。`tools/measure_m6ia_main_sub.sh --baseline` は走ごとに
ROM ディレクトリを新規に作り、2走して完全に一致したときだけ署名を出す。
2走とも `deterministic: true` で一致し、走の前の `.srm` は両走とも 0 件だった。

これは腕の結果ではなく対照の採取であり、A0〜A5 の観測は本追補の時点では
1件も見ていない。画面本文は採取・記録のどの段階でも出していない。
