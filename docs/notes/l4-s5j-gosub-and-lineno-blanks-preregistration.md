# l4-s5j — GO SUB の詰めと行番号途中の空白 — 事前登録

記録日: 2026-10-03  
状態: **測定前**（公式ROMでの測定は未実施）

## 背景

[l4-s5h-round3-results.md](l4-s5h-round3-results.md) で、`go sub10` は `GOSUB 0`、
`go sub 10` は `GOSUB 10`、`go to10` は `GO TO10` と観測された。
また `130 1+rem x end` は行1301、本文 `+REM x end` として受けられ、位置での対応づけが破綻した。
本段はこの2件のLIST表示・入力時の行の扱いを測る。仕様の根拠は l4-basic 第14〜14.5節、
l4-program 第2・第3節。数値の後続処理は l4-s5i の候補N_Dを共有する。

## 測り方

器具の正本は `tools/l4_s5j_measure.py` の `build_arms()`。A群28腕、B群26腕、計54腕。
すべて小文字ASCIIの自分で作った入力。A群の本文は数字で始めない。
既存の `run_chunk`・`extract_list_lines`・`sig` をimportし、`new`、先行入力、対象入力、
`cls`、`list` の順で打つ。各腕2走。B群は同じ番号帯になる腕があるため、全腕を単独chunkに分ける。
A群も単独chunkとし、毎走の `new` で他腕との衝突を防ぐ。削除腕は表の先行入力を毎走に打つ。
番号だけの先行入力は対象番号に `print 7` を入れる（置き換え・削除を識別するため）。

B群は、取り出した全LIST行から腕の番号帯内の行をすべて拾い、表示順に改行で連結する。
番号帯は、連続数字だけを読んだ番号と空白を読み飛ばした番号と先行入力の番号の最小〜最大（両端含む）。
位置・予測した単一の番号では対応づけない。本文が数字または`.`で始まる腕も、LIST先頭の数字だけを
行番号として帯を判定する。帯外は件数だけ記録する。各chunkには当該腕しか入っていない。
行が1本も無ければ空文字列の署名を作らず `no_line`。それ以外は行番号つき連結文字列のSHA-256先頭16桁。
A群は当該番号の行がちょうど1本であることも関門にする。打てない警告・重複LIST行は `gate_failed`。

上限超えのb11は、同じ入力を `new` 後に単独で探る2走も行い、エラー表の2番の文言を
「含む」「完全一致する」の2値だけで記録する（l4_listnumのprobe-entryと同じ）。LIST行の有無は
本測定の `no_line` で判断する。探りの画面本文は読まない・出力しない。2値が2走で違えば `unstable`。
エラー文言の2値は候補のLIST署名判定とは別の観測項目であり、候補を選ぶ根拠に追加しない。
その他の画面行は件数だけ記録し、本文を出力しない。生の画面写しはリポジトリ外の一時ディレクトリに置き終了時に削除する。

## A群の候補

- **G_A**: `go`＋空白ちょうど1個＋`sub` の直後に文字があり、その1文字が英字でなければ、
  その1文字を消費して空白1個に置き換え、`GOSUB` に詰める。英字なら詰めない。
  行末は消費せず既存規則（`GOSUB`）とする。
- **G_B**: 直後が数字のときだけG_Aと同じ。数字以外は、空白なら詰め、それ以外は詰めない。
  行末は既存規則（`GOSUB`）。
- **G_0**: 既存規則のまま。`go sub10` は `GO SUB10`。
  既知の観測と矛盾するが陰性対照として置く。

文字列・REM・DATA・`'`以降・名前の内部は変更しない。GO TOは既存規則のまま。
候補の詰めを行った後、残った本文の数値定数には既存N_Dの書き直しを掛ける。

## B群の候補

- **L_A**: 行頭の数字の並びは数字間の空白を読み飛ばし、数字でも空白でもない文字または行末まで読む。
  全数字を行番号とする。番号後ろの空白はすべて読み飛ばし、LISTは「行番号＋空白1個＋本文」。
  本文が空ならその番号の行を削除する。
- **L_B**: L_Aと同じだが、番号後ろの空白は1個だけ読み飛ばし、2個目以降は本文に残す。
  l4-program 2.5の空白保持がこの位置にも及ぶ候補。空白だけの本文は削除として扱う。
- **L_0**: 現状の自作と同じ。行番号は連続した数字だけ、直後の空白はすべて読み飛ばす。

3候補とも、番号の上限は65529、上限超えなら行は入れず既存行も変更しない。
本文の書き直しには既存N_Dを使う。先行入力も各候補で処理し、最後に保存される全行を予測する。
このためL_0で削除にならない場合は、先行行と別番号の行が2本残る予測となる。

## 判定

腕ごとに、2走で一致した署名（または `no_line`）と各候補の予測署名を比較し、
一致は `agree`、不一致は `differ`。2走の署名または探り2値が違えば `unstable`。
関門不成立は `gate_failed` として候補の支持数に入れない。候補ごとに各分類の腕数を数える。
全腕agreeかつunstable・gate_failedゼロの場合だけ、その候補が全腕を説明すると判断する。
予測を観測後に変更しない。未説明腕の次の候補は追補で事前登録してから測り直す。

通常の測定TSVは打った行、2走署名、一致判定、候補ごとのagree/differ等、探り2値、他行件数だけ。
観測LIST本文は `--show-differs` を明示した場合に限り、全候補がdifferの安定した腕だけ標準出力する。
これは自分で打った行のLIST表示のみに限る。予測TSVはROM不要で、候補の予測行と署名を出す。

## 自己検査と使用方法

`selftest` は合成陽性・陰性対照、番号帯の内外、数字本文の番号対応、削除・空白保持、2走判定を検査する。
G_Aの既知2例とL_Aの行1301の再現、およびG_0/L_0がそれを再現しないことを確認する。
一時ビルドした自作ROMで少数6腕各2走を測り、G_0/L_0との一致と新候補との差を陰性対照として確認する。
自作ROMだけをビルドし、公式測定は親が行う。src/・tests/conformance/は変更しない。

```sh
python3 tools/l4_s5j_measure.py predict --out /tmp/l4s5j-predictions.tsv
python3 tools/l4_s5j_measure.py measure --rom-dir "$PC88_REF_ROM_DIR" --official --out /tmp/l4s5j-signatures.tsv
tools/l4_s5j_selftest.sh
```

作業先の既定は `../tmp/l4s5j-work/`。環境で書き込めない場合は
`--work-dir /private/tmp/l4s5j-work` で明示的に置き換える（selftestラッパーも引数を渡す）。
本作業ではこの置き換えを用いる。上記の公式測定コマンドは手順例であり実行しない。
全selftestは回さず、l4_s5j・l4_listnum・l4_listkwの3本のみ実行する。
