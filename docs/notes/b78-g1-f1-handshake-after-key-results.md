# B78: F1 の道で、後半のキーのあとの受け渡しの制御を公式と自作で比べる — 結果

記録日: 2026-11-04
規則: [b78-g1-f1-handshake-after-key-preregistration.md](b78-g1-f1-handshake-after-key-preregistration.md) どおり。測定はクラウドの実行環境で rc=0。データのポートの値は記録していない。記録は `measurements/b78-g1-f1-handshake-after-key.txt`。

## 結果

フレーム 12060〜12120 の最初の 400 件:

- 公式: main がキーのポート（`IN $00`〜`$09`）と音源（`$44`・`$45`）を回すいつもの繰り返し。受け渡しは無い
- 自作: **main が `IN $FE` を読んで値 2、サブが `IN $FE` を読んで値 2、を交互に繰り返すだけ**（202 件中 201 件）

## 分かったこと

自作では、キーのあと main とサブの**両方が受け取る側で待っている**（行き詰まり）。B49 の並びでは、`IN $FE` の 2（bit 1）は相手の受信可を表す。main も サブも「相手が送ってくる」のを待っていて、どちらも送らない。B77 で割り込みが減ったのは、この待ちを割り込みを止めて回しているためと考える。

公式はこの時刻にまだ要求を始めていない。自作だけ、キーのあと早く要求のやり取りに入り、そこで行き詰まった。

## 読み方（推定）

その前の要求で、公式は応答を返す（または返さない）のに、自作は逆をしている可能性がある。main は応答を待ち、サブは次の要求のバイトを待っている。B79 で、キーから行き詰まるまでの要求の並び（先頭バイトと形）を出す。
