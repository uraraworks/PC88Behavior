## 測定で裏付けた規則

資料と読んだ範囲は事前登録の「資料と読んだ範囲」「利用者領域の選択」に従う。
新たな資料閲覧は行っていない。GW-BASICの変換規則と、N88マニュアルのCLEARによる
利用者領域確保を、登録した操作の観測で裏付けた。

- POKEの値は最近接整数へ丸め、半分は絶対値の大きい側へ丸める。
  65.4→65、65.5→66、66.5→67、-0.4→0、255.4→255
  （`value-06`〜`value-10`）。符号付き16ビット整数化の後に0〜255を検査する。
  255.5、256、-1は誤り5、32768、-32769は誤り6、文字列は誤り13
  （`value-11`〜`value-16`）。0・1・127・128・255の往復も一致（`value-01`〜`value-05`）。
- 番地は符号付き16ビットへ同じ整数化を行い、負の整数は65536を足して対応させる。
  正の32768以上65536未満は先に65536を引く。十進・十六進・負の表記が同じ利用者番地を
  指す（`address-decimal`・`address-hex`・`address-negative`）。
  49152.4と49152.5はともに49152へ対応し、POKEは下側だけを77へ変更、
  PEEKは下側の17を返した（`address-poke-plus04`・`address-poke-plus05`・
  `address-peek-plus04`・`address-peek-plus05`）。特に半分の腕は、正数を先に
  丸めるモデルと区別する。範囲外POKEの65536と-32769は誤り6
  （`address-out-65536`・`address-out--32769`）。
- PEEKは0〜255の整数を返す。上記往復に加え、正数のPRINTの先頭空白と整数変数への
  代入成功を確認（`type-print`・`type-integer`）。読出しはCLEARで確保した利用者2番地に
  限り、各腕で先行POKEした既知値だけを記録した。

誤りはERR番号の観測。既存の `src/l4_basic/errors.tsv` の対応は
5＝`Illegal function call`、6＝`Overflow`、13＝`Type mismatch`。
公式画面のメッセージ文言は測定・転記していない。誤り15・文字列関数・INSTRは
本段の対象ではなく、既測定のl4-s9a（l4-basic第17節）のままである。

## 期待値の固定と照合

根拠の鎖は、自作PRINT整数組の測定TSV → 本ノート →


照合一致、終了値0。腕集合・各2走・関門・印列が一致した。
別途、全60行の登録打鍵列・P_GW・失敗/未実行フラグも確認した。
公式ROMの再測定、git add、コミットは実行していない。

## 決めなかったこと

- 範囲外PEEKは保留・未測定。65536と-32769のP_GW予測はERR=6だが、確定観測にしない。
- 画面動作・VRAM・I/O（INP/OUT）、ROM領域、機械語（USR/CALL）、CLEARの誤り。
- 特殊番地の処理・保護・セグメント設定、自作実装の内部領域配置。
- PEEKの文字列番地、複数引数が同時に不正な場合の誤り優先順位、
  今回採らなかった小数境界・倍精度入力の差。
