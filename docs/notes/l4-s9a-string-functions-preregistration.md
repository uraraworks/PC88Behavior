610–707、710–738、841–956、GWEVAL.ASM 1572–1638、MATH1.ASM 90–145、
2540–2585、MATH2.ASM 230–294、GWMAIN.ASM 3065–3118、
GWDATA.ASM 340–418。以下はコードの転載でなく、処理の散文要約である。

CHR$は整数化した0～255のコードを1文字にする。SPACE$の長さとSTRING$の
長さ・数値の文字指定も同じ範囲を使う。まず符号付き16ビットへ最近接整数化し、
半分は絶対値の大きい側へ丸め、その後高位バイトが零か調べる。
よって-0.4は0、-0.6は-1、65.5は66、66.5は67となる。
整数化の範囲外は6、整数化できても0～255外なら5、文字列を数値指定へ渡すと13。
SPACE$(0)とSTRING$(0,65)は空文字列。STRING$の文字列指定は先頭1文字だけを使い、
空文字列指定はASCの空文字列検査によって5になる（長さ0でも第2引数を評価する）。

HEX$/OCT$は16ビットのビット表現を、先頭零を省いた大文字十六進／八進文字列にする。
零だけは1桁の0。負数は2の補数を用いる。FRQINTは正の数で指数が16のとき
65536を引いてから同じ整数化を行うので、今回の整数標本は-32768～65535が通る。
65536、-32769は6。非整数は同じ最近接・半分を絶対値の大きい側へ丸める。
ただし正の32768～65536未満は減算後の負数を丸める手順をそのまま候補にする。
単純な「先に正数を丸めてmod 65536」と同一視しない。
文字列引数は13。文字列連結で長さ255を超えると15。

INSTRの2引数形式は開始1。3引数形式の開始は上記の0～255変換を行い、0を拒み5。
開始255は有効だが、256・負数は5（16ビット超過なら6）。文字列引数の型違いは13。
開始が対象文字列長を超える場合は0を返す。対象が空なら検索語も空であっても0。
検索語だけが空なら、開始が対象長以内のとき開始を返す。
検索は文字コードの完全一致なので大小は区別するが、その区別の実測は今回行わない。

## 取り出しと打鍵

全腕を同じプログラム行＋RUNで実行する。1標本を1腕、腕内番号n=1とする。
小文字の行だけを打ち、全行80文字未満。数値の非整数は器具上で正確な分数式へ
書き換える（65.5なら131/2など）。数字始まりは登録用の行番号だけにする。
`@`は使わない。手本と同じ8フレーム/文字、行間240、公式起動改行300・入力開始700、
自作入力開始100、RUN後15000フレーム、採取前200フレームを固定する。

結果文字列は直接表示しない。`x$=<式>`の後、成功時だけGOSUB 900を呼ぶ。
長さ0～8は `s9 n 長さ 各文字コード`。長さ9～255は `s9s n 長さ 全文字コードの和
先頭 1/4地点 1/2地点 3/4地点 末尾` を1行にする。各地点は1始まり、端数切捨て。
今回長い正常結果は255文字。INSTRは `s9v n 値`。
`on error goto 950`で `s9e n err` をPRINTし、f=1にしてRESUME NEXTする。
後続行はfで正常値の採取を抑制し、古いx$を誤って採らない。
最後に `s9d n 1` をPRINTするのでRESUME NEXTによる復帰も確認できる。
エラーメッセージの文言は採らない。印の大小は同一視、正のPRINT数の先頭空白と
負数のマイナスを要求し、印行は整数のみの完全一致。その他の画面行は件数だけ。
一時画面写しは例外・失敗時も削除し、フロントエンドの標準出力・標準エラー本文は出さない。

## 腕と固定候補

測定候補は **S_GW** だけ。上記の手順を固定し、全標本の整数列を下表で事前予測する。
CHR$20、SPACE$8、STRING$12、HEX$14、OCT$14、INSTR14、長さ上限2、型誤り3で
測定87腕、定数対照4腕を別に付け計91腕、各2走。
STRING$(3,"AB")は小文字で届くのでSTRING$(3,"ab")へ変更する。
INSTRの大小区別標本は除外する。ソース手順に今回の標本の未決点はない。

定数対照は `"ab"`→長さ2・97,98、`""`→長さ0、`mid$("hello",2,3)`→長さ3・101,108,108、
`error 5`→ERR=5と後続の完了印。関門の合格は既知の整数列との一致だけとする。
ERROR文だけが使えない場合も、今回の全体関門は失敗のまま残す。
代替を試すには、既測定で確実に誤る最小形（例えばASCの空文字列）とERR番号を
別の追補で事前登録し、対照を2走で検証してから全腕を測り直す。
ON ERROR/ERR/RESUMEが使えない場合、画面のエラー本文から番号を推測しない。
別の番号採取経路が検証できるまで誤りの測定は保留し、本段はgate_failedとする。

## 判定・器具検証

`predict --out FILE` はROM不要の全腕S_GW予測TSV。
`measure --rom-dir DIR --out FILE [--official]` は全腕2走の打った全行、
整数PRINT列、他行の件数、打鍵・採取失敗、関門、agree/differを記録する。
私物DIRは環境変数PC88_REF_ROM_DIR経由で親が指定し、公式測定は親が行う。
既定作業場はリポジトリ外 `../tmp/l4s9a-work`、`--work-dir`で変更できる。
標本番号・形式・件数不正、打鍵・採取失敗、2走不一致はgate_failed。
全定数対照が既知の列と一致しなければ全腕gate_failed。
関門通過時だけ腕ごとにS_GWとagree/differを判定する。
外れたら本登録の予測は変更せず、追補を事前登録してから測り直す。
`check --expected FILE --measured FILE` は予測TSVまたはprint_values列の期待TSVと、
測定TSVの腕集合・2走・関門・整数列を厳密照合する。

selftestは合成画面で全予測列の陽性、印の破壊、長さと文字数の不一致、1文字改変、
ERR番号改変を検査する。GW予測器は手計算の固定値を照合する。
自作ROMは一時ビルドし、既測定の文字列関数だけからなる定数3腕を各2走検査する。
自作ROMのON ERROR/ERRORは未測定のためここでは登録しない（950行は実行しない）。
誤り関門は合成対照で検証し、公式測定時にはERROR 5対照の実測が必須。
CHR$等の腕は自作ROMでは測らない。誤った期待値をcheckで拒み、定数の不一致が
全体をgate_failedにすることも確かめる。
実行は `bash tools/l4_strfunc_selftest.sh < /dev/null` のみ。
run_all_selftests.shにはrndの次にbashから実行可能な形で登録するが全体は実行しない。
