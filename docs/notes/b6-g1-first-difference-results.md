## 再現

| 走 | events | 畳んだ要素 | 取りこぼし | 開始 |
|---|---|---|---|---|
| official-1,2 | 3706126 | 941113 | 0 | boot-sector |

公式どうし、自作どうしとも畳んだ列が最後まで一致（`same`）。

## 判定 — **自作が先に途切れる**（位置 13510）

自作の列は、公式の列の先頭 13510 要素とそのまま一致する。自作はそこから先の 3600 フレームの終わりまで、main CPU の入出力を1回もしない。

最後の共通部分（前後の全文は `measurements/b6-g1-io-compare.txt`）:

| 位置 | 公式 | 自作 |
|---|---|---|
| -3 | IN $FE ×2 | IN $FE ×2 |
| -2 | IN $FC ×1 | IN $FC ×1 |
| -1 | OUT $FF **×3** | OUT $FF **×1** |
| 0 | IN $FE ×4 | （なし） |
| +1 | OUT $FF ×1 | （なし） |
| +2 | OUT $FD ×1 | （なし） |

畳むときに回数は比較しないので、位置 -1 の回数の違いは比較の判定とは別の観察である。

## 分かったこと・言えないこと

分かったこと:
- 起動用セクタ以降の約 1.35 万要素、ゲームとサブ CPU の通信の並びは公式と同じ
- 自作は `OUT $FF` の1回目のあと、main の入出力を止める。公式はそこで `OUT $FF` をあと2回出して通信を続ける
- この区間までの入出力はすべて `hi`（`0x8000` 以上の発行元）。ROM 領域から出た入出力は公式にも無い

言えないこと:
- 止まった理由。main CPU は RAM 上で走り続けている（B5 の `instr`）が、何をしているかはこの測定に無い
- 問題が main 側とサブ側のどちらにあるか
- 値が同じか。比べたのはポートと方向の並びだけである
