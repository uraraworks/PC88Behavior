# B93 事前登録：G5 の 7071 帰還後の R 介入

[方針追補8](goal-b-policy-addendum8-r-register-2026-11-13.md) に基づく測定前の計画。公式 ROM・ゲーム由来の値、画面本文、媒体データを公開記録に含めない。Mac に公式 ROM・ゲームは無く、以下は器具の自己検査までであり、実走の結果ではない。

## 腕と介入点

- 独立起動の介入なし基準を2回、R に 00、01、02、03、10、40、7F、80、FF をそれぞれ設定する腕を各1回。媒体も腕ごとに複製する。
- RAM から main ROM 7071 への最初の対象横断で入口の SP とスタック先頭を捕捉する。B92b と同じく PC が戻り先、SP が入口時の SP+2（16ビット）になった命令の fetch 時、命令実行前に1回だけ介入する。入口から30フレーム以内に帰還しない場合は未帰還。R 本体と bit 7 保存用の R_saved の両方を設定する。戻り先の命令自身の fetch による進行はこの後に起きる。
- 入口の命令実行前、ROM から RAM サブルーチンへの寄り道、同じ PC でも SP が違う場合、二度目以降の呼出しでは介入しない。入口判定では割込み・拡張 ROM を除外する。

## 記録と比較

- 既定 36000 フレーム。対象未到達・未帰還でも指定フレームまで測定を続け、他の腕も実行する。
- boundary-timeline の番地・種類と、main/sub 各 I/O の種類・ポート・発行元 PC の列を比較する。最初に違う1始まりの件数を出す。長さだけ異なる場合は短い列の次の件。フレーム・時計は比較対象外。CPU 間の全順序は比較しない。
- I/O 見出しは既存 io-log と同じフック・PC 算出で専用記録 `events` に流す。値は API の引数にも含めない。同一 CPU・フレームの連続する同じ見出しは回数で保存し、集計も展開せず比較する。既存 io-log の固定容量を使わないため、長時間のポーリングで先頭だけの記録になることを避ける。境界の上限は10億件で、欠落した記録は欠測にする。
- 基準も全腕も、I/O 件数、最終フレーム、最終フレームにも I/O があるか、末尾と最大の連続無通信フレーム数を記録する。末尾無通信の最初のフレーム末と測定終了時の両 CPU の ROM/RAM 分類・待機ポート候補を示す。フレームは0始まり。
- 「待機ポート候補」は、そのフレームの I/O が同じ PC・ポートの IN のみで2件以上ある場合。候補なしは null。ポーリングも I/O 継続に数える。無通信だけで CPU/ゲームの停止を断定せず、処理待ちの確定に命令列や値を読まない。分類は最後に fetch した命令の実体で、未実行なら未取得。main はバンクの実体、sub は ROM ミラーを含む既存の実体判定を使う。
- main の 3E0D・3080 は ROM/RAM を問わず任意の命令先頭 fetch で初到達を検出する。境界横断に限らない。
- 基準2回の見出し列が一致し、両方が帰還・無介入で、腕も帰還・介入1回である場合だけ「介入効果の比較可能」を真にする。欠測・介入未成立・基準変動も結果に明記し、同じ道だったという判定に置き換えない。
- 実行終了コード、全フレームの連番、末尾、I/O 総件数、境界総件数を照合する。切断・形式不正・境界上限/戻り追跡の欠落は欠測。公開集計には比較元の PC・見出し列・値・画面本文・媒体名を出さない。待機候補のポート番号と指定済みの到達番地は出す。

## 器具と実行

パッチ `0030-b93-r-after-return.patch` を0029の後に適用する。自前コア部品 `tools/harness/core/b93_intervention.*` と更新した frontend も必要。専用指定は `--b93-log FILE`、`--b93-entry 7071`（既定）、`--intervene-r-after-rom-return 7071=80`。基準では最後の指定を省く。旧暫定版の `7071:FFFF=値` は使わない。B92 の FFFF メモリ介入の意味を変更しない。B92 と B93 の併用は拒否する。版シンボル2を frontend とランナーの両方で検査する。

クラウドでは全パッチ適用済みコアと更新済み frontend を用意し、`PC88_REF_ROM_DIR`、`PC88_GAME_DIR`、`PC88_CORE` を設定する。`PC88_FRONTEND` は任意。`PC88_GAME_DIR` は従来の `games.tsv` を含む媒体置場。`B93_FRAMES` は既定36000。

```sh
B93_FRAMES=36000 tools/b93_run.sh "$B93_OUTPUT"
```

`B93_OUTPUT` は新規のリポジトリ外ディレクトリ。出力は `summary.json`、再集計設定 `config.json`、非公開の `raw/`。生記録・stderr・媒体はすべて外部に閉じ、公開するのは集計のみ。再集計は `python3 tools/b93_summary.py "$B93_OUTPUT"`。既存出力先を上書きしない。

## Mac の自己検査

`tools/b93_selftest.sh` は固定上流から全パッチを適用・ビルドし、0030の状態機械単体検査と自作 ROM/起動セクタだけの結合検査を行う。単体検査とビルドだけなら `tools/b93_build_selftest.sh`。ネットワーク不要。上流置場は `B93_UPSTREAM`（未指定なら従来の vendor）。ビルド済みコアを使う場合は `B93_TEST_CORE` と、必要に応じ `PC88_FRONTEND` を指定する。

陽性9腕、無介入基準2回、bit 7 と下位7bitの周回、二度目は非介入、入口では非介入、SP の16bit周回、未到達・未帰還、任意 fetch 到達、ROM/RAM・待機候補、切断・欠落・基準変動・値漏洩検出の陽性対照、実走ランナー全11腕と再集計を検査する。自作 sub の分類検査だけは `--sub-cpu-mode 2` で確実に走らせ、実走ランナーは既存の既定モードを保つ。上流の `LD R,A` は R_saved を更新しないため、二度目の陰性対照はその既存動作を含めて検査する。エミュレータ自体の命令実装は変更しない。

公式データ・run_all は使わず、src/・docs/spec は変更しない。
