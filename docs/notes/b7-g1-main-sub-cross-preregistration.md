# B7: G1 の途切れが main 側かサブ側かを、ROM の組み合わせで切り分ける — 事前登録

記録日: 2026-10-31
位置づけ: [b6-g1-first-difference-results.md](b6-g1-first-difference-results.md) の次段。
**このノートは測定より先にコミットする。** 結果を見てから規則を変えない（変えるときは後続ノートで）。

## 1. 問い

自作の入出力の列は位置 13510 で途切れた。途切れは自作の main ROM と自作のサブ ROM のどちらによって起きるか。

中身を見ずに答えられる介入は、組み合わせの入れ替えである。

## 2. 条件

| 腕 | main 側（`DISK.ROM` 以外） | サブ側（`DISK.ROM`） | 走 |
|---|---|---|---|
| OO | 公式 | 公式 | 2 |
| SS | 自作 | 自作 | 2 |
| OS | 公式 | 自作 | 2 |
| SO | 自作 | 公式 | 2 |

- 腕ごとに ROM の置き場を分け、`DISK.ROM` だけを入れ替える。他の条件は B6 第2節と同じ
  （G1 の1枚目、打鍵なし、`--frames 3600`、走ごとにディスクを複製し直す、クラウドの実行環境）
- 自作は、このノートをコミットした時点の HEAD の配布ビルド
- 記録は `--io-log` と `--boundary-log`。濾過と要約は B1 の `tools/b1_whitelist_boundary.py` と B6 の `tools/b6_io_sequence.py`

## 3. 対照

- OO・SS の境界記録の濾過後が、それぞれ `b1-g1-demand-official-1.txt`・`b5-g1-self-boot-self-1.txt` とバイト一致
- OO・SS の入出力の要約が、それぞれ `b6-g1-io-official-1.txt`・`b6-g1-io-self-1.txt` と、走の名前の行を除いて一致
- 通らなければ組み合わせの結果を根拠にしない

## 4. 判定（事前に決める）

各腕の列を OO の列と比べる（`compare`）。腕の走どうしも比べ、揺れるなら一致している範囲だけを使う。
「**届く**」は、OO に対して `same`、または `position` が 13510 より大きく、かつ記録 A が空でないこととする。

| OS | SO | 読み方 |
|---|---|---|
| 届く | 届かない | 途切れは自作の main 側で起きる。自作サブは少なくともここまで足りる |
| 届かない | 届く | 途切れは自作のサブ側で起きる。自作 main は少なくともここまで足りる |
| 届かない | 届かない | どちらにも足りないものがある、または組み合わせを変えたこと自体の影響。切り分けは別に事前登録する |
| 届く | 届く | SS の組み合わせでだけ起きる。切り分けは別に事前登録する |

別の位置で分かれた場合は、その位置と前後を腕ごとに報告する。上の表に当てはめず、そのまま書く。
腕ごとに `instr` と、B1 の需要 8 番地への到達も報告する。

## 5. 記録しないもの

B6 第5〜6節のとおり。コミットするのは白リストを通った要約と比較、および境界記録の濾過後だけである。
