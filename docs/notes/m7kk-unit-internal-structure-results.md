**バイト位置1〜6のそれぞれについて、送信単位の内容の間で相異なる値が

## 総合の線（`m7kj`で先に引いたものをそのまま当てる）

> **NA1のとき——「対象の区別は6バイトのうち1箇所に載っており、残り5箇所は
> 3種類で共通である」と言える。単位が意味を持つ方向の強い傍証になる。**

**これが成立した。**

- **無意味な切り方であれば、区別がちょうど1箇所に集まる理由が無い。**
  **`m7kd`以来の留保——「覆えていることと、単位が意味を持つことは別」——は
  大きく弱まった。** ただし**完全には消えない**（事前登録どおり）。
- **混成でも可変なのは同じ位置5だけ**（基数5。5本すべて内容が違う）で、
  **他の5位置は共通**だった。**mainは両条件とも同じ公式ROMなので、
  同じ位置を動かしている。** これも単位の意味づけを支える。

**ただし「位置5が何を表すか」は言わない**（事前登録どおり）。
**値を見ていないので、「対象を指す番号」なのか「別の量」なのかは
区別できない。** 位置の番号から中身も推測しない。

  **傍証が強まっただけである。**

## ここまでで分かった構造（値を含まない形）

`m7hb`から本稿までで、**読めない媒体に対する振る舞いの骨格**が値を1つも
出さずに組み上がった。

```
main → sub : 6バイトの送信単位（うち1箇所だけが対象ごとに変わる）
                 ↓
sub → FDC  : SEEK → SENSE INTERRUPT STATUS → SENSE DRIVE STATUS
             → READ DATA ×9（9件とも同じ対象・同じ結果）
                 ↓
sub → main : 1バイトの応答（3種類の対象すべてで同一）
                 ↓
       これが同じ対象について4回繰り返され、次の対象へ移る
       （対象は3つ。3 × 4 = 12単位）
```

**この骨格に、値は1つも含まれていない。**

## 次に何を測れば絞れるか

1. **この骨格を仕様に起こす。** 1単位の内側の構造は確定し、単位の内部も
   固定部と可変部に分かれた。**9の依存関係は「潰した軸の一覧」として
   書ける**——定数を写すのではなく、**何に依存しないかを列挙した形**なら
   測定に基づく仕様になる。**これを次にやる。**
2. **結果以外の入力を潰す**（`m7ki`の残り）——位置ごとのsub側ポーリング
   回数。位置9だけ違えばそこに合図がある。
3. 1と2が済んだら、**自作サブROMに粘りを実装する**。**仕様が先である。**
