# m6i-j 追補5 — 最初の WRITE の手前（`0x14, D`）と応答の位置を採る

記録日: 2026-09-30  
状態: **測定前**（公式ROM起動0のまま置く）

## 0. 経緯

`l3-subrom.md` 1.35a節は、WRITE DATA の直前に sub が受信する列の末尾を `S, 0x11, 0x01, D, T, R`＋256（最初の WRITE では S＝D、以降 S＝`0x06`）と述べる。
S の手前は測っていない。実装側から「最初の WRITE の前に main は `0x14, D` の長さ2の run を送り、sub はそれに応答しない」という**仮説**が出た（1.36節に `0x14`・長さ2が1件ある）。
これを公式一式で確かめる。応答（sub の `OUT $FD`）が S の前後どちらにあるかも決める。

## 1. 問い

- 主問: 各走の**最初の WRITE**について、sub が `0x11` の直前に受信した2バイトは `0x14, D` か（D＝ドライブ。ドライブ1で0、2で1）。
  1.35a節の S が、この2バイト目にあたる（最初の WRITE では S＝D）。
- 副問1: その1バイト目（`0x14`。主問が偽でも同じ位置）から `0x11` の受信までの間の sub `OUT $FD` は何件か。
- 副問2: 2回目以降の WRITE について、(a) S＝`0x06` の受信から `0x11` の受信までの間、(b) 直前の WRITE の完了（FDC の結果相の終わり）から S の受信までの間、の sub `OUT $FD` は何件か。

## 2. 腕・打鍵・媒体

追補3・追補4（`docs/notes/m6i-j-addendum3-results.md`）と**同じ**（10腕×2走、ドライブ1・2、器具 `tools/m6ij_add3.py` の腕・打鍵・媒体・フレーム）。変えるのは解析だけ。
公式ROM起動は20回。打鍵は小文字で届く。

## 3. 定義（解析器 `tools/m6ij_add5.py`）

- **受信** ＝ `sub IN $FC`。**run** ＝ 連続する受信（間に `sub OUT $FB`／`sub OUT $FD` が無い。1.36節・`analyze_record_boundaries.py` 窓(a)と同じ切り方）。
- **最初の WRITE** ＝ FDC コマンド列で最初の WRITE DATA（opcode 5）。その直前の受信列のうち、データ部256を除いた前6バイトが `S, 0x11, 0x01, D, T, R`（追補3の H1 と同じ位置）。
  **`0x11` の1つ前が S、S の1つ前が「S の手前のバイト」**（以下 P）。主問は「P＝`0x14` かつ S＝D」。
- 応答の件数は、`clock`（共通のイベント順序）で区間を切って数える。区間は開区間（両端の事象を含まない）。
- **出力してよいもの**は、制御バイトと件数だけ。最初の WRITE について: P＝`0x14` か（真偽）、S＝D か（真偽）、
  P を含む run の**先頭バイト・run 内での P の位置・run 長**。run の途中・末尾のバイト値、データ部、READ で返る値、`$FB`/`$FC`/`$FD` の一般の値列は出さない。
  最初の WRITE の手前の受信はすべて READ 要求などの制御で、WRITE のデータ部を含まない（最初の WRITE より前に WRITE は無い）ことを解析器が確かめる。
  2回目以降は件数と S＝`0x06` の真偽だけ。生の I/O ログはコミットしない。

## 4. 判定

### 4.1 主判定（名前は排他的）

| 名前 | 条件 |
|---|---|
| `first_write_prefixed_by_14_D` | 全20走で、最初の WRITE の P＝`0x14` かつ S＝D |
| `first_write_other_prefix` | 対照 G1〜G3 が成立し、かつ 1走でも P＝`0x14` かつ S＝D でない。P を含む run の先頭バイトと run 長の分布を制御バイトとして報告する |
| `inconclusive` | 対照 G1〜G3 のいずれかが不成立、最初の WRITE が見つからない走がある、または器具の関門（凍結・自己検査・起動）が止まった。「不一致」とは扱わない |

### 4.2 副判定（件数の分布をそのまま記録。判定名は付けない）

- 副問1: 最初の WRITE の P→`0x11` の sub `OUT $FD` 件数の分布（腕ごと・全体。走ごとに全て同じでもよい）。あわせて S→`0x11` の件数。
- 副問2: 2回目以降の WRITE の (a) S→`0x11` の件数、(b) 直前の WRITE の完了→S の件数の分布。
  1.35a節の「WRITE ごとに応答1バイト」が S の前後どちらにあるかは、(a)(b) の分布から読む（読みは結果ノートに書き、判定名にはしない）。
- 参考: 最初の WRITE について、直前の READ の完了→P の件数も記録する（READ で返る値は記録しない。件数のみ）。

## 5. 対照

対照の条件に主問の成否（P・S の値、応答の件数）は混ぜない。

- **G1**: 追補3の H1・H3（`m6ij_add3.analyze` の `failed` に H1・H3 が無い。H2 は見ない）が全20走で再現する。H1 は末尾 `S,0x11,0x01,D,T,R`＋256・2回目以降 S＝`0x06`。
- **G2**: 同一腕の2走の観測（本追補の出力のすべて）が一致する。
- **G3**: I/Oログの取りこぼし0件。`analyze_m6ij.load`（伏せ字0・clock と seq の単調増加）と `exchanges`（main 送信と sub 受信の全単射）が全走で通る。
- **G4**（解析器の検出力。測定前に自己検査で確認）: 合成ログに次の3種を注入し、それぞれ**狙いの欄**が変わること。
  (i) 手前が `0x14` でない → `first_write_other_prefix`、かつ「P＝0x14 か」だけが偽。
  (ii) 最初の WRITE の D が違う（S≠D）→ `first_write_other_prefix`、かつ「S＝D か」だけが偽。
  (iii) 応答件数が違う（追加の sub `OUT $FD` を S→`0x11` に入れる）→ 主判定は変わらず、副問の分布の該当欄だけが変わる。
  加えて正の対照（`0x14, D` が付いた合成ログ）で `first_write_prefixed_by_14_D` と想定した件数が出ること、
  READ で返るデータ・WRITE のデータ部・本文の目印を出力へ混ぜると出力監査が拒否することを確かめる。
- 関門（`m6ij_add3.preflight`＝凍結の検査、本体の G0〜G4、器具の自己検査、媒体・本文の検査、走後の媒体差分・画面完了）は追補3・4と同じ。器具の凍結表 `tools/m6ij_add5_frozen.tsv` を測定前にコミットする。

## 7. 訂正（測定前・2026-09-30）

器具の自己検査を書いて分かったこと。**§5 の G4(ii) の期待を訂正する**（腕・判定名・条件は変えない）。

- 最初の WRITE では S は P の次の1バイトで、追補3の H1（S＝D）の対象そのものである。したがって「S≠D」の注入は G1（H1）も落とす。
  §4.1 のとおり対照が不成立なら判定は `inconclusive` になるので、G4(ii) の期待は `first_write_other_prefix` ではなく
  **判定名が `first_write_prefixed_by_14_D` から `inconclusive` に変わり、かつ観測欄のうち「S＝D か」だけが偽になる**（「P＝0x14 か」は真のまま）。
- 実測で S≠D が出た場合も同じく `inconclusive`（追補3の H1 と矛盾するため）。`first_write_other_prefix` に落ちるのは、G1〜G3 が成立したうえで P≠`0x14` の走がある場合である。
- G4(i)・(iii) の期待は §5 のとおり（(iii) は run の切れ目が変わるので P を含む run の先頭・長さの欄も変わるが、主判定は変わらない）。
