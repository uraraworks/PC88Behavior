# B12: 公式サブが 1024 バイトのセクタを読むときの動きを、自作の媒体で測る — 結果

記録日: 2026-10-31
規則: [b12-sub-1024-byte-read-preregistration.md](b12-sub-1024-byte-read-preregistration.md)（325c25e）どおり。変更なし。
器具: d98d944。測定はクラウドの実行環境で 12 行各 2 走。全行で走どうしが一致した。記録: `measurements/b12-sub-1024-read-*`。

## 判定: **対照が通らず、第5節の判定はしない**（`controls_passed: false`）

故障注入の行11 も、他の 1024 バイトの行と同じく何も受け取れなかった。事前登録は「刻印の座標がずれること」で検出する形だったので、データが 1 バイトも渡らないと成り立たない。事前登録の欠陥である。

## 判定に数えない観察

| 行 | 要求 | 受け取り | READ DATA（C,H,R,N,EOT） | 結果 |
|---|---|---:|---|---|
| 1 | T=0,R=1,P1=1 | 256 | 1回 0,0,1,1,16 | 正常 |
| 2〜9,11 | T=2 | 0 | 9回 1,0,R,**1**,16 | 異常、No Data |
| 10 | T=3 | 0 | 9回 1,1,1,1,16 | 異常、No Data |
| 12 の 1 つ目 | T=0,R=2,P1=1 | 256 | 1回 0,0,2,1,16 | 正常 |
| 12 の 2 つ目 | T=2,R=1,P1=2 | 0 | 9回 1,0,1,1,16 | 異常、No Data |

- 読み要求 `0x02` の公式サブは、媒体が 1024 バイトでも **N=1（256 バイト）、EOT=16 で READ DATA を出す**
- READ ID は 1 回も出ない。媒体の大きさを問い合わせていない
- したがって 1024 バイトのセクタは、この経路では読めない

## 読み方（推定）

G1 は公式の上で track 0 の外も読めているので、この `0x02` とは別の経路を使っている。候補は、別の要求か、サブへ送った自前のコードである。**どちらかはこの測定からは言えない。** 次の [B13](b13-g1-sub-fdc-preregistration.md) で測る。
