# m6i-c 副問の訂正 — `gate_never_released` は誤った帰属だった

記録日: 2026-09-23

## 1. 何を訂正するか

[m6i-c 結果](m6i-c-b5-b6a0-divergence-results.md) §5「副問」は、C0・C3 の
副問判定を `gate_never_released` とし、

> ゲート run へは入り（`gate_entered` = 真）、測定終了まで一度も抜けていない
> （`gate_released` = 偽）。

> つまり sub は、main の通常SEND開始を最後まで検出できないまま、ゲートの中で
> 回り続けていた。

と書いた。**この帰属は誤りである。**

**訂正するのは副問だけである。**

- **総合判定 `m6i_c_sub_gate_only` は訂正しない。**
- §3 の腕ごとの結果（C0/C3 が timeout・要求run 0件、C1/C2 が256位置一致・
  要求run 1件）も訂正しない。
- §2 の関門、G4 のバイト照合の結果も訂正しない。

## 2. 事実

[m6i-d 第1回の試行](m6i-d-attempt1-instrument-failure.md) §3 の診断による。

観測していた長い `IN $FE` の連続は、**ゲートではなく sub の通常の待ちループ
`IDLE_DISPATCH`** だった。ゲートを持たない腕（B0）でも同じ長さの run が出る。

各腕のゲート番地を `src/l3_service/make_subrom.py` のラベル表から引き、
その番地での sub の I/O を数えると、**ゲートは最初のポーリングで抜けている**。
ゲートは `IN $FE` / `AND` / `JR Z` の3命令であり、待ちビットが既に立っていれば
1回読んで通過する。

したがって `gate_entered` / `gate_released` として記録していた量は、
**ゲートの入場と解除を表していなかった。**

## 3. なぜ総合判定が影響を受けないか

m6i-c の総合判定は、4腕の通常READの成否だけで決まる。
[m6i-c 追補2](m6i-c-addendum2-reach-and-release.md) §1 が、到達指標から
ゲート観測を外していたからである。追補2 はそのとき

> 主問が使える結果を、従属する問いの都合で捨てない。

を理由に挙げた。**その判断がここで効いた。** 副問の観測が丸ごと誤っていても、
`c0_reproduced` / `c1_reproduced` / `c2_success` / `c3_failure` と、そこから
決まる `m6i_c_sub_gate_only` は1つも動かない。

もし追補2 を置かず、事前登録どおり C3 の到達指標に「ゲート入場1件以上」を
残していたら、**誤った観測が到達判定を通じて主問を汚染していた。**

## 4. 訂正後に言えること・言えないこと

**言えること**（m6i-c から変わらない）:

- sub のゲートの有無だけが通常READの成否を決めていた。main の枝タグは無関係。
- m6i-b の B5 の timeout は、ゲートという測定用の介入に由来する。

**言えないこと**（本訂正で取り下げる）:

- 「sub がゲートの中で回り続けていた」は取り下げる。
- 「sub が main の通常SEND開始を最後まで検出できなかった」も取り下げる。
- m6i-b 結果 §6 が挙げた2つ目の切り分け対象（「sub 側の停止ゲートが
  ラウンド#0の後に置かれたとき、main の通常SEND開始を取りこぼすことがあるか」）
  は、**決着していない。** m6i-c 結果 §5 が「取りこぼす、という形で決着した」と
  書いたのを取り下げる。

**新たに問いになること**（ここでは決めない）:

- ゲートは詰まらないのに成否を変えている。実害は「止めること」ではなく
  **`IN $FE` を1回余分に行うこと**にあると考えられるが、**測っていないので
  確定しない。** 別稿で測る。

## 5. 直し方の記録

m6i-c の結果ノートは書き換えない。§5 の冒頭に本ノートへの参照を足すだけに
する。**測定の記録は記録のまま残す。** 読み方の訂正は本ノートが引き受ける。
