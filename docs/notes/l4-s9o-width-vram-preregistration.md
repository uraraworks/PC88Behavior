3. `width` が消す範囲（自作の印が消えるかで測る）。

## 起動時の画面について（観測済みの手がかり）

起動直後のDMAC転送長が2400バイト（20行×120）であることから、**起動時の画面は80桁・20行**と読める（`width 80,25` で3000バイトへ増える）。
従って `layout-rem`（`width` を実行しない対照）は 80桁・20行、`width 80,25` は25行へ変わる腕である。

## 測り方（画面本文を扱わない設計）

自作の既知の印を `locate` で決めた位置へ `print` し、写し（`--vram-dump`、F3C8〜FF7F の3000バイト）の中で**自作の印のバイトがどの位置にあるか**だけを数値で採る。
公式が出した文字（プロンプト・ファンクションキー行）の中身は採らず、出力・保存もしない。

**印**は小文字2字＋数字1字（`qa1` など）。プログラムを打ち込んで（80桁のまま）、`cls` のあと `run` で実行する（打鍵の跡に印が残らないようにするため）。
プログラムの1行目に `width` を置き、その後で印を打つ。

layout 腕のプログラム（桁数 W、最終桁−2 を L とする。W=40 なら L=37、80 なら 77）:

    10 <モード行>              (rem / width 40 / width 40,20 / width 40,25 / width 80,20 / width 80,25)
    20 locate 0,6:print "qa1";
    30 locate 0,7:print "qb2";
    40 locate 0,8:print "qc3";
    50 locate 10,9:print "qd4";
    60 locate 20,10:print "qe5";
    70 locate L,11:print "qf6";
    80 locate 0,12:print "qg7";
    90 locate 5,12:color 2:print "qh8";:color 7     # 属性域を見るための印。行12の桁5に色
    100 locate 0,16:print "qz9";                    # この後の行17に公式のプロンプトが出る

各印の最初の文字の位置 off(c,r) から、行ストライド S = off(0,7)−off(0,6)、桁の間隔 k、基準位置、文字の間隔 g を求める。
**線形（全印が同じ S・k に載る）でなければ線形と認めず、当て推量しない。** 印が1つでも欠ける・重複するなら腕は関門落ち。

属性域は、印の行（6〜12・16）の**印のセルの外にある、空白（0x20）でも0x00でもないバイト**の行内位置と値を採る
（印の行は自作の印しか書かれない行なので、公式の本文は混じらない）。色の付いた行12と、付いていない行11の差で属性域の形を読む。
印の行以外で、空白でないバイトを含む行は**行番号と領域（文字域 c／属性域 a）だけ**を採る（値・長さは採らない）。これでファンクションキー行の行番号を知る（行0は `run` の打鍵の跡、行17は公式のプロンプトとして除く）。

erase 腕（消去範囲）: まず `width 80,25` にして印 `qk1`（桁0・行6）・`qm3`（桁60・行8）・`qn4`（桁0・行21）を置き、
次にモード行（rem / width 40 / width 40,20 / width 80,20 / width 80,25）を実行し、その後 `qz9`（桁0・行14）を打つ。
モード行の後も写しの中に `qk1`・`qm3`・`qn4` が残っているかを、**文字の間隔1〜4のどれでも**探して判定する（残っていれば位置を採る）。

**制御ポート**: `--io-log` で第1フレームからメインCPUの OUT を採り、`run` を打ったフレームから写しを取るフレームまでの窓の中の
(a) `0x30`・`0x31`・`0x32`・`0x34`・`0x35`・`0x53`・`0x64`〜`0x68` の値を順序つきで、(b) CRTC は `0x51` のコマンドごとに続く `0x50` のパラメータを束ね、
カーソル位置コマンド `0x80` は件数だけ、それ以外のコマンドは連続する同一のものを畳んで、記録する。
窓には `layout-rem`（`width` なし）の同じ窓の記録を対照として添え、結果ノートでは対照との差だけを書く。

### CLAUDE.md 禁止事項5（データポートの値列を伏せる）に当たるかの判断

**当たらないと判断し、記録する。** 理由: 伏せる対象は公式ディスク・ROM から読み出した実データが載る**データポート**
（`$FB`・`$FC`・`$FD`）で、`tools/redact_iolog.py` の説明も CRTC ポート等の制御・設定のポートを「ハードウェアの事実そのもの」として残すと定めている。
今回採る `0x30`・`0x31`・CRTC・DMAC は画面の寸法・転送長を決める設定値で、論理アナライザで実機から測れる種類の値（5.6節も同じ種類を既に記録している）。
データポートは採らない（採取対象の一覧に入れていない）。CRTC の `0x50` はコマンド `0x51` に続くパラメータだけを束ね、カーソル位置は件数だけに落とす。
生の記録（`port.txt`）と写し（`vram.bin`）は作業置き場の一時ファイルで、採取後に器具が消し、コミットしない。コミットするのは要約（印の位置・設定値の短い列）だけ。

## 予測（事前登録）

予測が立たない量は「予測なし」とし、予測と違っても形式が正しければ differ として記録する（関門には使わない）。

| 腕 | 行ストライド S | 桁の間隔 k | ファンクションキー行 | DMAC `0x65`（窓の最後の2値） |
|---|---|---|---|---|
| layout-rem（起動の80桁20行） | 120 | 1 | 19 | 予測なし（窓に無い） |
| layout-w80-20 | 120 | 1 | 19 | `5F`・`89` |
| layout-w80-25 | 120 | 1 | 24 | `B7`・`8B` |
| layout-w40・layout-w40-20 | 120 | 2 | 19 | `5F`・`89` |
| layout-w40-25 | 120 | 2 | 24 | `B7`・`8B` |

根拠: ストライド120は上の「DMAC転送長＝行数×120」の算術（`width 40` で `0x65` が起動時と同値だったことの素直な読み。4.22の論理桁とは別の量）。
**桁の間隔 k=2 は記憶（未確認）による弱い予測**で、候補は他に「k=1 で40文字＋その後ろが属性域（Sの前半に詰める）」「S=80」がある。外れたときは外れた腕を説明する規則（数値）を結果ノートに書く。
ファンクションキー行は「表示行数−1」（`l3-main.md` 第13節の row0=24 の読み）。

属性域の形・位置は**予測なし**（80桁側は既知の「行の後ろ40バイトに (桁,値) の組」〔5.4〕と一致するかを見る）。

erase 腕の予測: `rem` は `qk1`・`qm3`・`qn4` が全て残る。`width` が受理される腕（40・40,20・80,20・80,25）は 4.22.3 の「受理されると画面を消す」から、
`qk1`・`qm3` は消える。`qn4`（行21）は 25行を保つ腕（40・80,25）では消える。**20行へ変える腕（40,20・80,20）の `qn4` は予測なし**
（表示外の行までVRAMを消すかは分からない）。

制御ポートの値（`0x30` の bit0 が桁数に対応するか、CRTC の RESET パラメータ等）は**予測なし**。観測を結果ノートへ数値で書く。

## 腕と走

本体: layout 6腕（rem・w40・w40-20・w40-25・w80-20・w80-25）、erase 5腕（rem・w40・w40-20・w80-20・w80-25）。各2走。
**陽性対照**: `layout-rem` は既知の並び（S=120・k=1）、`erase-rem` は3つの印が全て残ること。これが崩れたら全腕を関門落ちにする（較正の関門）。
自作ROMでの既知値対照は、同じ解析を自作ROMの起動画面（80桁、既知の並び 120/1）に当てて通ること（selftest）。

**関門**: 2走ともに採取成功、全印が一意に見つかる（layout）・3印とも `post` の印が一意（erase）、全印が線形、2走の観測が完全一致、較正の関門。
関門が落ちたら、器具を曲げず追補の事前登録を先にコミットしてから再測定する。
