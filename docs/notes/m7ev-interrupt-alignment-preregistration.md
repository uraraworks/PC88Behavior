# m7ev: 割り込み受理の食い違いを共通軸で整列するための事前登録

実施日: 2026-09-02

本稿は、条件O（公式ROM一式）と条件M（公式main＋自作サブROM）の割り込み受理の
食い違いを、両条件に共通して定義できる軸の上で整列して比較するための事前登録である。
本稿の作成時には新しい測定を行わず、実測結果を含めない。適合条件3の条件文を
書き換えるものでも、差を埋める実装を行うものでもない。

## 前提の検査

整列比較には、条件Oと条件Mの双方で同じ意味を持つ共通軸が必要である。本稿が候補とする
共通軸は、subが発行する**公開FDCコマンド種別の通し番号**である。コマンド番号と、後述の
`$FB` run番号・run内位置は全て0始まりとする。従って、差の分布を比較する前に次の検査Pを
行い、その成否を先に確定する。

- **検査P:** 条件Oと条件Mで、subの公開FDCコマンド種別列が一致するかを検査する。
  種別名だけを先頭から完全一致で比較し、両側の総コマンド数、一致prefix長、最初の
  不一致位置を整数で記録する。片側の列が先に終わった場合は、その終了位置を最初の
  不一致位置とする。両列が全長一致した場合だけ、不一致位置を`なし`と記録する。
- 種別列が全長一致した場合は全長を整列範囲とする。全長一致せず一致prefix長`L`が
  1以上の場合は、先頭`L`段だけを整列範囲とする。本稿では、1段でも種別名が一致すれば、
  その段は共通軸上の比較単位として定義できるため、**十分長い一致prefixの固定整数条件を
  `L>=1`**とする。実測後にこの境界を変更せず、不一致後のsuffixを整列範囲へ加えない。
- 一致prefix長`L=0`、すなわち最初のコマンド種別から食い違う場合は、共通軸を作れないため
  整列比較を不成立として打ち切り、**H-X支持**とする。この場合も、両側の総コマンド数、
  一致prefix長0、最初の不一致位置0、両側の先頭コマンド種別名を記録する。「差が無かった」
  または「一様だった」とは記録しない。実測後に別の軸を探して整列し直さない。

検査Pが全長一致または`L>=1`なら、総数を`N_O`、`N_M`として、整列範囲が各総数の
どれだけを占めるかを`L/N_O`、`L/N_M`という**整数の分子・分母**で記録する。百分率、
小数、近似値には変換しない。検査Pが`L=0`の場合にも同じ形式で`0/N_O`、`0/N_M`を記録する。
これにより、検査Pの結果がどちらであっても、事前に定めた記録と判定を残せる。

## 背景と問いの立て直し

`m7eu`では、条件Oと条件Mの割り込み受理件数がたまたま231しか違わない一方で、
受理直前ポートと受理frameは大きく異なることが分かった。frame粒度の符号付き差分が
231となったのは、条件間の差がframe間でほぼ相殺した結果であり、局在させるべき
「231件の差」という実体は無い。同時に、`m7et`が事前登録した幅100 frame・18区間の
分割では、全ての受理がframe 13〜79の1区間へ入り、規則上の判定は自明に成立したものの、
差の形を識別できなかった。

しかし、本稿は「差が一様か局在か」という同じ問いを、より細かいframe分割で問い直さない。
`m7eu`の結果により、「231件の差がどこに分布するか」という問いの前提そのものが失われた
ためである。前稿の判定が空だったことだけを理由に解像度を上げれば、問いの前提が消えた
ことを見落とす。

そこで問いを立て直す。本稿が問うのは、**割り込み受理の食い違いをframeではなく、両条件に
共通して定義できる公開FDCコマンド種別の通し番号上で整列したとき、食い違いがコマンド列の
全域に及ぶのか、特定のコマンド段に限られるのか**である。検査Pで共通軸が作れない場合は、
その不成立自体を結果とする。

## 仮説

- **H-G（全域）:** 整列できた範囲で、受理の食い違いはコマンド列の全域に及ぶ。
- **H-S（特定段）:** 整列できた範囲で、食い違いが特定のコマンド段に限る。
- **H-X（整列不能）:** 検査Pで先頭から種別列が食い違い、共通軸が作れない。

H-GとH-Sは排他とし、H-Xはその手前の検査Pで決まる。後述の固定整数条件の境界上に
ある場合は、H-G/H-Sのどちらも支持せず判定不成立とする。「自作の設計がこうだから
こうなるはず」という予断で仮説を絞らず、実測前に三つ全てを残す。

## 固定条件

- `m7et`から条件を変更しない。公式diskAを起動し、`tools/conform_l3.sh`の適合条件3と
  同じ`--frames 1800`、`--io-log`、`--int-log`を使う。
- 条件Oは公式ROM一式（公式main＋公式sub）、条件Mは混成（公式main＋自作サブROM）とする。
  コア、ディスク、打鍵、フレーム数、ROMディレクトリ以外の引数を完全に同一とし、
  ROMディレクトリだけを入れ替える。
- 各条件を2run実行する。各条件内でI/Oログと割り込みログの全イベント列のSHA-256、
  受理件数、および解析出力が`label`を除いて完全一致した場合だけ採用する。単一走は
  採用しない。2run不一致は欠測とし、同条件で再実行する。
- 割り込みログの`dropped`が0でなく、`missing_before`または`missing_after`が0でないrunも
  欠測とする。片方の条件だけを判定へ使わない。

## 観測量と割り当て

検査Pでは、subの公開FDCコマンド種別列、両側の総コマンド数`N_O`・`N_M`、一致prefix長
`L`、最初の不一致位置を記録する。扱うのは**種別名だけ**であり、パラメータ、データ、
結果バイトは読まない。種別判定に必要なコマンドバイトは器材内部で直ちに公開種別名へ
変換し、生の値を出力、保存、診断表示しない。未知種別が現れた場合は推測で名前を付けず、
器材不成立による欠測とする。

整列比較では、整列範囲の各コマンド段`j`（`0<=j<L`）について次を記録する。

- 条件O・条件Mの受理件数、符号付き差分`d_j=M_j-O_j`、絶対差分`a_j=|d_j|`。
- `$FB` runごとの受理件数、方向、run長、run内の受理位置。run長はイベント数だけを扱い、
  中身は読まない。run番号とrun内位置は`fb_runs()`と同じ0始まりとする。
- 受理を1件以上含むrun数と受理を含まないrun数。直前イベントが`$FB`でないためrun内位置を
  持たない受理件数も整数で別記し、都合よく除外しない。

コマンド段は、公開コマンドの発行開始から次の公開コマンドの発行開始直前までとする。
列末尾の段は測定終了までとする。部分一致の場合も、先頭`L`段だけをこの規則で数え、
不一致後の段を比較しない。最初のコマンド発行より前の受理件数は整列範囲外として条件別に
整数で記録し、いずれの段にも付け替えない。これらの境界は共通clock上のイベント順で決め、
frameを割り当てに使わない。

記録対象はポート名、方向、コマンド種別名、件数、位置、長さ、SHA-256だけとする。
データポートの値列は読み出し結果にも診断にも出さない。

## 器材追加の順序と限界

現在の`tools/analyze_sub_interrupt_shape.py`は、内部の`fb_runs()`で`$FB`のrun番号とrun内位置を
保持している。しかし`analyze()`の出力では、それらを「IN run 途中」「OUT run 末尾」
「OUT run 途中」という3分類へ潰しており、run単位・コマンド単位の集計を出力していない。
従って、現行器材だけでは本稿の観測量を取得できず、集計出力の追加が必要である。

順序は、**本稿の事前登録、器材追加、実測**の順とし、器材追加は本稿の作成後に行う。
追加するのは集計出力だけであり、既存の出力項目、3分類の定義、SENSE候補の判定、
長run閾値、判定規則、値を出さない設計は変更しない。追加したコマンド単位・run単位の
集計には、合成入力への故障注入によって誤集計を検出できる自己検査を用意し、
`tools/run_all_selftests.sh`から実行できるようにする。**故障注入で検出力を確認していない
集計は本稿の判定に使わない。** 器材追加時にも測定を行わず、器材と自己検査を先に確定する。

## 判定の固定規則

1. 検査Pを必ず先に行う。種別列が完全一致した場合は全長を整列範囲とする。完全一致しない
   場合は一致prefix長`L`だけを整列範囲とし、`L/N_O`と`L/N_M`を整数の分子・分母で記録する。
   整列範囲を実測後に広げず、別の軸へ差し替えない。
2. `L=0`の場合は**H-X支持**とし、整列比較を行わず打ち切る。`L>=1`の場合はH-Xを支持せず、
   その範囲だけで以下を判定する。部分一致であることを全長一致とは呼ばない。
3. 各コマンド段の`O_j`と`M_j`を整数で突き合わせ、`d_j=M_j-O_j`と`a_j=|d_j|`を両方
   記録する。全段の符号付き差分総和`D=sum(d_j)`と絶対差分総量`A=sum(a_j)`も記録し、
   `|D|`を`A`の代用にしない。
4. 整列段数を`L`、両条件とも受理件数が0でない段数を`B`、片側だけ0の段数を`Z`、
   両側0の段数を`E`として、`B+Z+E=L`を完全一致で検算する。**「大半」は`2Z>L`、
   「少数」は`2Z<L`という整数条件に固定する。** `2Z>L`の場合だけH-G支持、`2Z<L`の
   場合だけH-S支持とする。`2Z=L`の場合はどちらも支持せず判定不成立とする。この境界は
   実測後に変更しない。
5. 全コマンド段、全runを対象とし、外れ値を除かない。都合のよい段を選び直さず、割合、
   近似、誤差許容を判定に使わない。「近い」「ほぼ同じ」を判定語に使わず、整数の
   完全一致と上記の整数不等式だけで判定する。

## 言えること／この事前登録で決まらないこと

現時点で言えるのは、`m7eu`の固定条件で条件Oと条件Mの受理直前ポートと受理frameが
大きく異なり、符号付き差分231が差の大きさを表さないこと、および`m7et`の幅100 frame・
18区間では差の形を識別できなかったことまでである。本稿は、その同じ問いを細分化せず、
公開FDCコマンド種別列を共通軸の候補として前提から検査する。

本稿で差の**原因**は決まらない。公式subの内部実装、割り込みモード、受理の契機、
自作subのどこを直せば一致するか、そもそも一致させられるかは決まらない。整列できても
同じ内部経路である証明にはならず、整列できなくても自作subが誤っている証明にはならない。
適合条件3は既に合格しており、受理件数一致も直前ポート一致もその条件文に含まれない。

共通軸に使うのはFDCコマンドの**種別名だけ**である。パラメータ、データ、結果バイトの値は
読まない。種別列が一致しても、同じセクタ、同じ座標、同じ内容を読んだ証明にはせず、
処理速度や内部状態の一致も導かない。種別列が一致しない場合も、適合条件3の合格を覆さない。

## 情報境界

記録するのは件数、位置、長さ、コマンド種別名、ポート名、方向、SHA-256だけとする。
データポートの値列、画面本文、公式応答値は表示も転記もしない。生ログと解析成果物は
リポジトリ外の永続作業領域に置き、コミットしない。ROMとディスクのパスは環境変数経由で
のみ受け取り、絶対パスをリポジトリへ焼き込まない。`private/`を開かず、逆アセンブルを
行わない。

## 欠測の扱い

一過性のプロセス異常終了、ログの取りこぼし、直前・直後イベントの欠落、未知コマンド種別、
器材の自己検査不合格、または2run不一致は**欠測**とし、同条件で再実行する。欠測を
「差が無い」「整列できた」「整列できなかった」のいずれへも読み替えず、両条件で採用可能な
2runが揃うまで検査PとH-G/H-S/H-Xを判定しない。

## 検証（事前登録時点）

本稿の作成時には新しい測定を行わず、エミュレータを起動していない。既存ログの再解析も
行っていない。`src/`、`tools/`、`docs/spec/`は変更していない。
`tools/check_cleanroom.sh`を実行し、全項目OK、rc=0を確認した。
