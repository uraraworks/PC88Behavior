## 目的

1. **塗られる画素の集合**: 閉じた図形（枠・円・多角形）、凹形・穴・細い通路（1ドット幅を通るか）、斜め隣接（4連結か8連結か）、領域内の障害物（領域色と同じ・別の色・境界色）、境界色と領域色が同じ／違う、境界色の省略時の既定、画面の端まで開いた領域、開始点が境界上・画面外。
2. **境界の判定**: カラーモードで「どの画素値を境界とみなすか」（3プレーンの値の完全一致か、ビットの包含か）。白黒モードでの境界。
3. **タイル塗り**（`PAINT (x,y),タイル文字列[,境界色][,バックグラウンド文字列]`）の画素パターン、位相（どこから数えるか）、文字列の長さの誤り、バックグラウンドストリングの効果。
4. **色・省略・LP（開始点になるか）・STEP・誤り番号**。
5. **作業領域**: 複雑な領域（櫛・点線格子・蛇行路）での誤り番号と、途中で止まるときの画素。`CLEAR ,,スタックの大きさ` で変わるか。
6. **速さの比較（補助の腕）**: 全画面の塗り、円の内側、枠の内側、櫛・蛇行路・タイル塗りのフレーム数（公式と自作 HEAD 218d984）。

## 読んだ資料（(a) 言語仕様のみ）

- **N88-BASIC リファレンスマニュアル**（`refs/manual_squashed.txt`、判定「可」）。PAINT(1) の項（印字 2-171、行 927）、PAINT(2) の項（印字 2-172〜2-174、行 931・935・939）、CLEAR の項（印字 2-23、行 335 のスタックの大きさの説明）、エラー一覧の Out of memory [7]（行 1531 の原因欄）を、`sed -n` の行指定で切り出して読んだ（これまでの段と同じテキスト切り出し）。事実だけを書く（表現は写さない）:
  - PAINT(1): `PAINT [STEP](x,y)[,領域色][,境界色]`。(x,y) を含む、境界色で囲まれた領域を領域色で塗る。領域色省略は COLOR のフォアグラウンド。**境界色省略は領域色と同じ番号**。開始点がすでに境界色なら何もしない。ビューポート内でのみ働き、ビューポートの境界は動作の境界とみなされる。**開始点がビューポートの外なら Illegal function call（ERR 5）**。注意書き: 複雑な図形では Out of memory になることがある。
  - PAINT(2): `PAINT [STEP](x,y)[,タイル文字列][,境界色][,バックグラウンド文字列]`。タイルは横8ドット固定、縦はタイル文字列の長さで決まる（白黒は n バイト＝n 行、**カラーは 3n バイト**）。各バイトのビットパターンで描く。カラーは**先頭から 青・赤・緑 の順の3バイトで1行**を成し、3つのバイトの同じ位置のビットを縦に読んで各ドットのパレット番号にする（例の `CHR$(&H55)+CHR$(&H33)+CHR$(&H0F)` は左から 0,1,2,…,7 の8色の1行）。**余りの文字は無視、カラーで3文字に満たなければ ERR 5**。バックグラウンドストリングは「領域内にすでにある色／パターン」で、白黒1バイト・カラー3バイトが使われ、超える分は無視。省略は COLOR の背景色に対応する文字列。**バックグラウンドの8ドットがタイル中に3回以上連続して現れると ERR 5**。バックグラウンド未指定だとタイリングが中断することがある。すでにタイリングされた領域を別のパターンで塗り直すと時間がかかったり Out of memory になることがある。
  - CLEAR の第3引数「スタックの大きさ」は FOR・GOSUB・**PAINT** 等が使うスタック領域のバイト数で、**リセット直後の既定は 512**。
  - Out of memory の原因欄に「PAINT 文で複雑な図形をペイントしようとした」。
- **GW-BASIC の公開ソース**（`refs/GW-BASIC/`）。`grep -il "paint\|SCANL\|TILE" *` で調べた結果、`OEM.H` の **49 行目**（"Queued painting algorithm (vs. stack)" という構成フラグのコメント1行）のほかには PAINT の記述が無い。**PAINT の本体は公開ツリーに含まれておらず、読んでいない**。この段の塗りの手順（走査線方式・境界判定・スタックの扱い）はGW-BASICから取れない。予測は言語仕様（マニュアル）と常識的な幾何に基づく。
- ハードウェア資料・ROM の解析記事・ROM の逆アセンブルは開いていない。
