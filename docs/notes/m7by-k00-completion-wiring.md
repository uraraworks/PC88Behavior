# m7by: K00列Bの完了状態をバルク完走時に畳み、空振り再アームを0件にした

実施日: 2026-08-22

## 情報境界

公式ROM一式＋公式diskA、および公式main ROM一式＋自作sub ROMを同じ
1800フレーム条件で同期実行した。公式ROM・ディスクの内容は読まず、
`private/`への`cat`/`xxd`/`od`/`hexdump`/`strings`・逆アセンブルは
行っていない。生iolog、混成ROM、一時ROM、実行出力はリポジトリ外の
`mktemp -d`配下だけに置いた。データ経路およびFDCデータの値は成果物・
標準出力へ出さず、件数、SHA-256、K00〜K09、差位置だけを扱った。

## 等価な5規則と選定

`measurements/m7bx-k00-equivalence.tsv`の20標本に対し、次の5規則は
すべてA/B誤り0件、規則間不一致0件だった。

- リセットepoch内でK00初回ならA、以後B
- 直前runがK05ならB、それ以外A
- SPECIFY未発行ならA、発行済みならB
- READ DATA未完走ならA、完走済みならB
- 完了FDCコマンド0件ならA、1件以上ならB

この等価性は`tools/check_k00_rule_equivalence.py`で常時検査する。自己検査は
無傷20件で合格し、B標本の直前runだけをK05以外へ変える故障注入で規則間不一致を
1件検出して不合格になった。したがって「5規則のどれが公式subの実際の状態か」
を推測せず、観測可能範囲で等価な実装を選べる。

採用したのは**READ DATA完走履歴**である。理由は、列Bを出すK00は既存の
READ準備群を完走して`BULK_SEND`へ入る経路そのものであり、新しいカウンタ、
前回種別RAM、SPECIFY/FDC履歴フラグを一切追加しなくてよいからである。
必要な内部状態と追加コードが5規則中で最小になる。

## 結線点と長さ1ゲート

m7bwの状態を値非表示で追跡すると、K00列Bはすでに高速バルクを起動していた。
問題は、通常の単発SENDが`WINDOW_RUN_POS`を0へ畳むのに対し、二つのデータ窓を
使う`BULK_SEND`はこの状態を畳まないことだった。長さ1のK00列Bで残った位置1が
次のrunへ持ち越され、確定長判定が1件遅れ、そこで空振り再アームを1件出していた。

そこでバルク完走時、既にA=0で受信進行状態を畳む箇所へ
`WINDOW_RUN_POS=0`を追加した。これは**READ完走後にK00列Bが起動した
バルク経路だけ**に効く。K00列Aはバルクへ入らず、WRITE自己検証の長いrunも
`BULK_SEND`へ入らないため、先頭K00や位置1だけを見て早期打ち切りすることはない。
すなわち「長さ1のK00列Bを完了した状態を畳む」ゲートであり、WRITEの
255件目以前には到達不能である。

途中、一般完了表でK00を早期打ち切る試行は、必要な再アームが66件から
14〜20件へ減って主経路が進まなかったため採用しなかった。これはm7bwに記録された
相互待ちと同型であり、最終実装には残していない。

## 容量圧縮

m7bw時点は2038/2048バイトだった。今回の完了状態クリアは3バイト増える。
容量確保のため、15箇所の末尾`CALL callee; RET`を`JP callee`へ置換し、
各1バイト、合計15バイト削減した。calleeの`RET`が戻る先は、置換前も
置換後も元の呼び出し元で同じであり、レジスタ・フラグ・スタックの最終状態も
同一なので挙動不変である。内訳は次のとおり。

| 置換群 | 箇所数 | 削減 |
|---|---:|---:|
| SEND待ち・起動単発送信 | 2 | 2バイト |
| FDCコマンド／結果／TC／バルクREAD | 8 | 8バイト |
| バルクSEND末尾待ち | 5 | 5バイト |
| 合計 | 15 | 15バイト |

よって生成コード長は `2038 + 3 - 15 = 2026` バイトで、2048バイト以内に
22バイトの余裕を残した。

## 検査器と検出力

`tools/check_k00_completion_metrics.py`は公式・混成ログを読み、データ値を
表示せず次を判定する。

- `OUT $FF=0B`の総数、次の受信へ対応した件数、`OUT $FB/$FD`まで受信が無い
  空振り件数、未解決件数
- mainの非データ入力列を同じ添字の`(port, pc, value)`で比較した最初の差位置

`tools/check_k00_completion_metrics_selftest.sh`は合成ログで、無傷が合格し、
空振りを1件挿入した故障と非データ差を1件前進させた故障がそれぞれ不合格に
なることを両ロケールで確認した。値を表示するコード経路は持たない。

## 実測結果

| 必須項目 | 結果 | 判定 |
|---|---:|---|
| 適合条件1 | 公式5635件・混成5635件、SHA-256一致 | 合格 |
| 再アーム | 総数66、対応66/66、空振り0、未解決0 | 合格 |
| 最初の非データ差 | 7036件目、`IN $FE`、pc `3853` | 合格（m7bwから後退なし） |
| WRITEデータ窓 | 256/256位置一致 | 合格 |
| WRITE座標 | 一致 | 合格 |
| WRITE応答 | 1件、観測応答と一致 | 合格 |
| `tools/verify_l3.sh` | 通常版適合、既存故障注入をすべてNG検出 | 合格 |
| 全`*_selftest.sh` | C / `ja_JP.UTF-8`とも全項目rc=0 | 合格 |
| 生成コード長 | 2026/2048バイト | 合格 |
| 等価性検査 | 20標本・5規則すべて誤り0、規則間不一致0 | 合格 |

`tools/conform_l3.sh`では適合条件4もディスク無しI/O 0件、陽性対照2549件で
合格した。条件2はdiskB未指定、条件3は割り込み受理0件で判定不能、条件5は
従来どおりSAVE未到達であり、今回の合格に含めない。
