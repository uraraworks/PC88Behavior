# l4-s1h — キーリピート（自動繰り返し）— 事前登録

記録日: 2026-09-19
状態: 事前登録、測定前。**今回はエミュレータの実行（測定）そのものは
行わない。器具・関門・判定名を固定するところまで。**

## この番号を選んだ理由

段階1（main側L3の測定）は `l4-s1a`〜`l4-s1g` まで進んでいる
（[l4-design](l4-design.md)）。本ノートはその続きで、次の空き記号
`s1h` を使う。

## 位置づけ

`docs/spec/l3-main.md` 第16節「→（境界、列79を長押しで越える）」は、
600フレームの長押しで次の行へ継続的に進む挙動（`wrap_to_next_line`）を
観測したが、**開始までの遅延・間隔そのものは測っていない**
（同節「未実施・未確定」、第18節項5）。この未確定部分が、自作ROM
との適合テスト `l4-c6`（`tools/conform_l3_editor.sh`、
[結果](l4-c6-screen-editor-conformance-results.md)）で唯一の不一致
（22腕中21腕一致、B4のみ不一致）として現れた——自作ROMにはキーリピート
の実装が無く、公式ROMは同じ600フレーム押しっぱなしに対して行1・列64
まで進むのに対し、自作ROMはほぼ動いていない（行0・列1）。

**本ノートは、この差を埋めるために要る「キーリピートの遅延・間隔」を
測る事前登録である。実装は行わない。測定のみ。今回は事前登録のみ。**

### 測る値の位置づけ（注記、先に明記する）

- フレーム数は**エミュレータ（QUASI88）上の値**であり、実機の時間の
  精度は主張しない（既知の注意、`feedback_emulator_measurement_measures_the_emulator.md`）。
  QUASI88のCPUエミュレーションとタイミングの厳密さは本ノートの検証範囲外。
- ただし、**リピートはROM（自作mainが模倣すべき対象）の処理であり、
  自作ROMの実装と`l4-c6`のような適合テストは、同じエミュレータ・同じ
  フレーム単位で比較する**。したがって「実機の遅延・間隔として正確か」
  は主張しないが、「このエミュレータ上でのフレーム値として、自作ROMが
  同じ値を再現できているか」を確かめる目的には使える、という位置づけ
  で測る。

## 対象キー・問い

| # | キー | port:bit |
|---|---|---|
| 1 | Q（文字キー、代表） | `04:1` |
| 2 | → | `08:2` |

- **Q1（文字キーの繰り返しの時系列）**: `Q`を長く押しっぱなしにし、
  押している間の写しを複数枚取り、「押す前に空白だったセルに現れた
  文字の件数」の時系列から、リピート開始までの遅延（フレーム数）と
  リピートの間隔（フレーム数）を読む。
- **Q2（→キーにも同じ繰り返しが効くか）**: →の押す長さHを数点振り、
  離した後の着地列（目印挿入で確認）が、Q1から予測される移動数
  （`1 + floor((H-遅延)/間隔)`、H<遅延なら移動数1）と一致するかを見る。
- **Q3（→を1回だけ押して列79を越える）**: 真の列79（境界）に置いた
  状態で、リピートが起きない短さの→を1回だけ押し、着地セルを候補
  （次の行の列0／列79で止まる／その他）と照合する。

## CAPSを使わない理由（Q1の打鍵）

`l4-s1f`はマーカー文字列（`QXZJK`）を打つ際、SHIFTの副作用
（約22セルの変化）を避けるためCAPSを保持していた
（`l4-s1f-screen-editor-preregistration.md`「打鍵の作り方」節）。
本ノートのQ1は**単一の文字キー`Q`を繰り返し打つだけ**で、予約語や
既存の画面文字列との衝突を心配する必要が無い（`QXZJK`のような
「予約語に含まれにくい5文字」を選ぶ理由がそもそも存在しない）。
CAPSを保持しないことで`--key-matrix`の枠を1つ節約し（CAPS用の
`0A:7`押しっぱなしエントリが不要）、`--vram-dump`の写し枚数に
余裕を持たせる。したがって**Q1は無修飾（小文字`q`、コード`71`）で
打つ**。大文字か小文字かは繰り返しの時系列とは無関係（`l3-main.md`
第7・10節により文字コードが変わるだけで、リピートの有無・間隔に
影響するとは資料上も測定上も示唆されていない）。

## 器具（既存の再利用の確認）

- `--key-matrix PORT:BIT:FRAME:HOLD`（既存、`tools/harness/frontend/main.c`
  1301行・235行の`KEY_MATRIX_MAX`）で対象キーを1回だけ指定し、HOLDで
  押しっぱなしの長さを作る。`--type`とは併用しない（既存の設計判断、
  `l4-s1f`と同じ）。
- `--vram-dump PATH --vram-dump-at FRAME`を最大16組（`VRAM_DUMP_MAX`、
  `main.c` 231行）。押す直前に1枚（基準、D0）、押している間・離した
  後に残り最大15枚を、下記「予備走」で決めた間隔で取る。
- 解析は`tools/l4_vram_probe.py`の差分モード（`--diff-before D0
  --diff-after Di`）を、D0と各Diの組で繰り返し呼び出す（1回のPython
  実行では1組の差分しか出せないため、写し枚数ぶんだけ呼び出す。新しい
  解析道具は不要——出力してよいものは既存の差分モードの規則
  （押す前が空白だったセルの件数・座標・その位置の文字コード）の
  範囲内に収まる）。
- 着地列の確認（Q2・Q3）は、`l4-s1f`のQ3と同じ「対象キーの後に別の
  目印文字を1文字打ち、差分で座標を取る」手順を使う。目印文字は
  `W`（コード`57`、`l4-s1f`と同じ選定理由）。
- settle手順（起動時入力待ちの切り分け、`l4-s1g`追補で確定）を、
  各腕の先頭に必ず入れる: RETURN(`01:7`)を frame700 で1回、300フレーム
  後にもう1回押し、**関門G11**で非空白件数が変化しないことを確認して
  から HOME/CLR(`08:0`無修飾)で画面を初期化する
  （`l4-s1g-screen-editor-return-preregistration-addendum.md`
  「settle手順の訂正」節をそのまま流用。本ノートは`l4-s1f`本体・追補1〜3
  のように settle 抜きの入力待ち中で測るという誤りを繰り返さない）。
- 隣接行・対象行の非空白確認（**関門G9**）は`l4-s1f`と同じ
  `--nonblank-summary-rows`を使う。

**器具に足りない機能は無い。** `--key-matrix`のHOLD・`--vram-dump`の
複数指定・差分モードの既存3点で、Q1〜Q3すべてに足りる。新設が要るのは
「1回の押しっぱなし（1つの`--key-matrix`エントリ）に対して、その保持
期間中に多数の写しを取る」という新しい使い方の自己検査だけである
（下記「器具の自己検査」）。

## 器具の自己検査（新規に要る分、G1で確認する）

- **単一HOLD中の多数写しの自己検査**: 短いHOLD（例: 20フレーム）の
  キー押下に対し、押す前1枚・保持中2枚・離した後1枚の計4枚の写しを
  取り、離した後の写しの非空白件数が保持中最後の写しと同じ（それ以上
  増えない）ことを確認する。これは「押しっぱなし中に複数回`--vram-dump`
  で覗いても、コアの入力処理やキー状態が乱れない」ことの確認であり、
  測定は本ノートの範囲外だが、実施担当への申し送りとして関門に含める。
- 既存の`tools/harness/vram_dump_selftest.sh`・
  `vram_dump_dynamic_selftest.sh`・`key_matrix_selftest.sh`・
  `tools/screen_content_leak_selftest.sh`は流用する（新規追加なし）。

## 予備走（本走の腕数には数えない）

**目的: 本走で使う写しのフレーム間隔を決めるためだけに、粗い間隔で
1回だけ様子を見る。** 予備走自体の結果は判定に使わない
（`l4-s1g`の予備走「切り分け」と同じ位置づけ）。

- 手順: settle→HOME/CLR→`q`を450フレーム押しっぱなし
  （HOLD=450、リピートの遅延・間隔について何も分かっていない段階
  なので、`l4-c6`のB4が使った600フレームより短いが十分に長い値を
  最初の当たりとして採る）。
- 写し: D0（押す直前）に加え、保持期間中に**30フレーム間隔**で15枚
  （フレーム+30, +60, ..., +450。合計16枚、`VRAM_DUMP_MAX`ちょうど）。
- 予備走で決めること:
  1. **リピート開始までの遅延のおおまかな範囲**: D0との差分件数が
     「1」から「2以上」に変わった最初の写しの前後30フレームの区間を、
     遅延の存在範囲とする。
  2. **リピート間隔のおおまかな見積もり**: 遅延を過ぎた後の区間で、
     件数が「1」増えるごとに何フレーム進んだかを、隣接する写しの差分
     件数の増分から平均する（例: 遅延終了後300フレームでN回増えた
     ならおおよそ300/N フレーム/回）。
  3. **本走のHOLDとサンプリング間隔**: 遅延の範囲を2枚の写しで
     ±15フレーム以内に絞れるよう、遅延推定区間の前後を**間隔5フレーム**
     で密に取る（目安4枚）。残りの写し（目安10枚）は、間隔見積もりの
     半分程度の間隔で、遅延を過ぎた後の区間に配置し、複数回分の
     リピートを跨ぐようにする（間隔の平均をより正確にするため）。
     HOLDは、写しの最後（16枚目）が「遅延終了後、間隔見積もりの
     8〜10回分」をカバーできる長さに設定する。
  4. 予備走で件数がまったく増えなかった場合（450フレームでリピートが
     一度も起きなかった場合）は、HOLDを900フレームに倍にして予備走を
     取り直す（`l4-c6`のB4が600フレームで複数回のリピートを示している
     ため起こりにくいと想定するが、念のため手順として明記する）。

**予備走はQ1のみに対して行う。** Q2（→キー）の本走は、Q1で決めた
遅延・間隔の推定値を使って設計するため、Q2独自の予備走は行わない
（Q1の結果を流用する）。

## 離した後の確認（Q1に含める）

Q1-mainの写しのうち、最後の2〜3枚（16枚の枠のうち終盤）は**離した後**
に取る。離した後の写しどうしで差分件数（D0基準の累積件数）が増えて
いなければ、「離すとリピートが止まる」を支持する
（`no_survivor`にはならない——離した後の写しが2枚以上あり両方とも
件数が同じなら`unique_survivor(stops_on_release)`、増え続けていれば
`unique_survivor(continues_after_release)`）。

## 陽性対照・陰性対照・故障注入

- **陽性対照（G4）**: 短いHOLD（4フレーム、既定）で`q`を1回だけ押す
  走を用意し、D0との差分件数が常に1のまま増えないことを確認する
  （リピートが起きない条件で「1文字だけ出る」ことの確認）。
- **陰性対照（G5）**: settle→HOME/CLR後、何も打鍵しない走で、Q1-mainと
  同じ写しの枚数・間隔を取り、全ての写しでD0との差分件数が0であることを
  確認する。
- **故障注入（G8）**: Q1-mainの同じ生データ（写し）に対し、正しい
  解析（D0＝押す直前を基準にした差分）ではなく、わざと誤った基準
  （例: 1つ前の写しを基準にする代わりに、常に最初から2番目の写し
  D1を基準にする、または「押す前に空白だったセル」の条件を外して
  全ての変化セルを数える）で集計し、遅延・間隔の読み取り結果が
  正しい解析と食い違う（無意味な値になる、または既に埋まっている
  セルまで数えて件数が過大になる）ことを確認する。使い捨ての検査で
  あり、判定結果には含めない（`l4-s1f`のG8と同じ位置づけ）。

## 判定

- **Q1（遅延・間隔）**: 予備走で絞った区間の中で、差分件数が「1」から
  「2」に変わった写しの直前・直後のフレームから、遅延（フレーム数、
  範囲として記録——ちょうどの値は2枚の写しの間に挟まれる形になり得る
  ため、区間として書く）を求める。間隔は、遅延後の複数回の増分の
