## 2. 器具の食い違い（D7・D8）

測定ドライバは各走の `entry_fields` に**欄そのもの**（`{"pos":…,"bytes9_15":…}`）を入れた。
事前に決めた形は**名前をキーにした辞書**（`{"QZ7A": {…}}`）で、導出器は名前で引いた。
そのため D7 がどの腕でもエントリを見つけられず Rused が空になり、ドライバの途中で R\* が決まらず、
IV-fill-res を回さなかった。通し検査は試験用の逃げ道（R\* の上書き、エントリ読み取りの省略）を
使っていたので、このつなぎ目を通っていなかった。

**措置:**
1. ドライバを、決めた形（名前をキー）で書くように直す。通し検査に、逃げ道を使わずに
   エントリ読み取り→`r_star` までを通す項を足す。
2. **2回目の記録は値を変えずに包み直して D7 を導出し直す**（IV-R の腕は `QZ7A`、I の腕は
   `QZ7B` をキーにする）。値は記録されたものをそのまま使う。
3. 包み直した記録から `r_star` で R\* を決め、§3.2 の IV-fill を回す。

### 3.1 終端の規則の前向きの確認（E-n）

D3 は、本体の最後のセクタに完全な通し番号が入らないとき最後の単位を見落とす（I-17 で起きた。
その単位の値ではなく、一つ前の単位の「次の番号」を終端として拾った）。**規則の欠陥**なので
規則を直す。2回目の5腕（I-1・I-3・I-6・I-10・I-250）では「終端の値 − 最後の単位の書いたセクタ数」が
すべて 0xC0 だったが、**これはデータを見てから気づいたこと**なので、同じデータでは確かめない。
新しい記録数の腕で前向きに確かめる。

腕 E-n（n = 2・4・8・12・20・33）: I-n と同じ打鍵で記録数だけ変える。フレーム 12000。

**D3' 終端**（事前に固定）: 測定後の像のエントリ（`QZ7B`）の 10 バイト目を先頭 k₁ とし、
T[k] < 160 のあいだ T をたどる（D2・D5 で確かめた規則）。最初に T[k] ≥ 160 となった単位を最後の
単位 kₘ、その値を e とする。u は、装置番号1の WRITE DATA の座標のうち、線形番号が 8kₘ〜8kₘ+7 の
ものの数（重複は1つに数える）。

- `end_plus_used_sectors`: 6腕すべてで e − u が同じ値。**予想は 0xC0**（2回目から）。予想と違っても、
  6腕で同じなら `end_plus_used_sectors` とし、値を記録する。
- `end_constant`: 6腕の e がすべて同じ。
- `end_other`: どちらでもない。たどれない（160 未満のまま一周・範囲外・0xFF に当たる）腕があれば
  `chain_broken` として列挙する。

あわせて、2回目の I の6腕にも D3' を当てた結果を**事後の記録**として残す（判定には使わない）。
