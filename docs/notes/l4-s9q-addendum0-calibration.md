# l4-s9q 追補0 — CLEAR 較正の関門の書き換え（公式の測定前）

状態: **測定前**（2026-10-08）。公式ROMで s9q の腕は未実行。本体の事前登録（a97d0df）は変えず、関門の1項目だけを置き換える（器具 59065c0 は既にこの形で作ってある）。

## 理由（器具を作ってから気づいた隙間）

本体の「CLEAR 較正」は、複数プローブ方式の `cv` チャンクと `cl-base` の探索が `0x8400`＝誤り5・`0x8800`＝誤り7・`0x8C00`＝受理を再現することとした。
しかし複数プローブ方式は本文が s9d の単独プローブ（約13行）より数百バイト長く、T（本文＋スタック等の合計）が大きいので、
**`0x8C00` が受理される保証が無い**（s9d の `fre(0)` は 0x8C00 で 742 しか余らない）。較正が測りたい量（本文の長さ）で落ちてしまう。

## 置き換え

CLEAR 較正は **s9d の既存器具（`tools/l4_memlimit_measure.py`、打鍵行はそのまま）で `limit-8400`・`limit-8800`・`limit-8c00` の3腕を2走**し、
既知値（誤り5・誤り7・受理で `fre(0)`＝742）を再現することにする（腕 `kn-8400`・`kn-8800`・`kn-8c00`）。1つでも違えば全腕を関門落ちにする。
複数プローブ方式そのものの妥当性は、本体どおり次で見る: アンカー（先頭・末尾）の T の一致、受理プローブの傾き1、全プローブの単調性、
および `cf-plain`（最小の本文で最初のプローブだけを試す確認腕）が base の式 `b7 = T + m`・`b5` 固定で通ること。
`cv` の `&h8400`・`&h8800`・`&h8c00` は関門でなく観測として記録する。

予測・他の関門は変えない。
