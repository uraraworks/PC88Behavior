# B38: スペース後の G1 で、値が違う直前のサブ RAM のどこが公式と違うかを値なしで測る — 結果

記録日: 2026-11-01
規則: [b38-g1-sub-ram-diff-preregistration.md](b38-g1-sub-ram-diff-preregistration.md) どおり。測定はクラウドの実行環境で OO・SS 各 2 走と対照各 1 走。関門 10 項目はすべて通った。値は記録していない。記録は `measurements/b38-g1-sub-ram-diff.txt`。

## 陽性対照

`W` の行は OO で 3280、SS で 17101 だった。器具は G1 の走で働いている。したがって **B37 の 0 件は根拠にしてよい。** 窓の中で ROM 側は RAM をデータとして読んでいない。

## RAM の違い

合計 303 バイト。書き手の組ごとの合計は次のとおり。

| 公式の書き手 | 自作の書き手 | バイト数 | 区間 |
|---|---|---:|---|
| 未書き込み | ROM | 272 | `7B00-7B06` の一部、`7C00-7D0B` の一部 |
| ROM | 未書き込み | 31 | `7F00-7FED` の一部 |

`ram-written` の違いは無い。RAM 上のコードが自分で書いた範囲と、ROM の読みが入る範囲に違いは無い。

## レジスタの違い

`BC`・`HL`・`R` が違う。`PC`・`SP`・`AF`・`DE`・`IX`・`IY`・裏レジスタ・`I`・`IFF`・`IFF2`・`IM`・`HALT` は同じである。

## 読み方（推定）

- 同じ `PC`、同じ `SP` にいて、RAM 上のコードの作業範囲は同じなのに、`BC` と `HL` だけが違う。違いの出どころは RAM の内容よりレジスタに寄っている
- `R` は実行した命令数で当然違う。`R` や待ちの回数を使って値を作るコードなら、公式との違いは不具合と限らない
- 原因はまだ書かない。`BC`・`HL` が最初に違う時点を B39 で測る
