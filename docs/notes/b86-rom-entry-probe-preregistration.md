# B86 ROM 入口プローブ事前登録（未測定・器具未完成）

需要の出所は B84 の起動用セクタ由来 RAM コードからの CALL（369A、37C9、37D2、3847、最後は数千回）だけとする。ゲームから入力値を採らず、資料や ROM の内容も読まない。働きは自作入力による外部入出力から測定後に決める。トークン互換とゲームの逆アセンブルは対象外。

各入口につき毎走を独立起動し、ゼロ（A・BC・DE・HL・F=0）、A・BC・DE・HL・F の各1のみを1にする腕、HL=D000 または DE=D100 とし指す自作 RAM の値を 0/1 に振る腕を設ける。比較対象としてSP=F000、割り込み禁止。自作 RAM の RET と、RAM 書き込み・OUT・キャリー設定を行う自作 RAM ルーチンを陰性・陽性対照とする。戻らない腕は時間上限内に戻らなかったとだけ判定し、無限ループと断定しない。

判定名: J_start（自作セクタ到達）、J_return（所定の戻り先到達）、J_regs（戻り時 A・BC・DE・HL・F・SP）、J_ram（呼び出し前後の RAM の変化番地と前後値）、J_io（呼び出し中のポート・方向・回数）、J_cycles（呼び出しから戻りまでのサイクル）。取りこぼしや開始未確認は欠測とし、戻らないことの証拠にしない。出力値と RAM の前後値はリポジトリ外の非公開保存先だけに保存する。公開するのは番地、件数、介入への応答規則であり、値の並びや ROM 内部 PC は公開しない。I/O 値も外部に保存し、公開しない。測定後に結果ノートを作り、再現できる規則だけを docs/spec/ へ渡す。

現状の生成器は初期入力と対照のセクタを作るが、呼び出し区間の RAM 全体の前後差・I/O・サイクルを捕捉する器具は未実装。既存 --boundary-log はこれらの値を採らず、既存 I/O とメモリ記録も異なる時計を使う。完成・自己検査まで公式 ROM では実行しない。

## 器具完成時の追補（測定前）

印は未使用ポート 7F の OUT、写しは 7D の OUT で送る。I/O 記録の main の印の間だけを数える。mem_write_log は I/O と共通順序を持たないため区間の切り出しには使わず、結果領域 C0C0-C0CA の回収に使う。RAM の前後写しは C100-EFFF の CPU から見える範囲を対象とし、この範囲外やバンクの背後は欠測とする。写し取りと CALL のスタック操作に伴う EFF8-EFFF 付近の変化を含むため、呼び先だけの変更と断定しない。C000-C0FF は器具・結果領域として比較から除く。写しの読み出し自体による装置やメモリマップへの影響は別途考慮する。

既存 I/O の clock はイベントの順序番号であり CPU サイクルではない。フレームも印間の正確なサイクルには換算できないため J_cycles は欠測とする。印の未確認、写しの欠落、ログの取りこぼしは欠測とする。生データはリポジトリ外の非公開ディレクトリに置き、集計は値を含めない。自作 ROM の対象入口は RET の代用であり、公式入口の動作の証拠にはならない。

結果領域は C0C0-C0C1 が F・A、C0C2-C0C3 が C・B、C0C4-C0C5 が E・D、C0C6-C0C7 が L・H、C0C8-C0C9 が SP（下位・上位）、C0CA が記録完了印。値は生データ側にのみ保存する。
