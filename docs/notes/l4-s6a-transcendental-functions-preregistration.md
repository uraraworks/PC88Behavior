# l4-s6a — 数値関数(SQR・SIN・COS・TAN・ATN・EXP・LOG)の割り切れない値 — 事前登録

記録日: 2026-09-19
状態: 事前登録、測定前

## 位置づけ

`l4-s5e`（`docs/notes/l4-s5e-input-string-numeric-functions-results.md`）で
`SQR`・`SIN`・`COS`は「答えが割り切れる入力だけ」を測り、`docs/spec/
l4-program.md` 4.16節・第8節21項に「割り切れない値を使う関数の精度検証は
別の測定に回す」と明記して未確定のまま残した。本ノートはその続きとして、
`SQR`・`SIN`・`COS`・`TAN`・`ATN`・`EXP`・`LOG`の7関数について、割り切れ
ない(無理数・超越数になる)入力を公式ROMで測り、GW-BASICの手順どおりの
予測(`tools/l4_mbf_oracle_v3.py`)と一致するかを判定する。これは拡張ROM
バンクへこれらの関数を実装する前段の測定であり、本ノートでは実装は
行わない。

## 予測器

`tools/l4_mbf_oracle_v3.py`(コミット直後にsha256を記す)。v2(四則演算、
`l4-s4a`・`l4-s4c`等で使用)を土台に、GW-BASIC(MIT公開ソース、コミット
`edf82c2ebf6bfe099c2054e0ae125c3efe5769c4`)のMATH1.ASM/MATH2.ASMから
`$SIN`/`$COS`/`$TAN`/`$ATAN`/`$SQR`/`$EXP`/`$LOG`を命令単位で読んで再現
した。詳細・読んだ行番号はファイル冒頭のdocstring参照。**SQRだけは
近似**（同docstring「SQRの扱い」節）で、高精度厳密平方根を単精度へ偶数
丸めする方式に置き換えている。SQR以外は、位取り縮約・多項式評価の各段で
v2の(命令単位で確認済みの)四則演算プリミティブへ委譲しているため、
近似は経由しない。

## 問い

- Q1（SQR、S1〜S7）: `SQR(2)`・`SQR(3)`・`SQR(.5)`・`SQR(123456)`の値。
  倍精度引数(`SQR(2#)`・`SQR(1000000#)`)が単精度で返るか。`SQR(-1)`の
  エラー
- Q2（SIN、N1〜N7）: `SIN(1)`・`SIN(.5)`・`SIN(-1)`の値。大きい引数
  (`SIN(100)`・`SIN(1000000)`)での位取り縮約。`SIN(6.283185)`(ほぼ2π)
  でのゼロ近傍の値。倍精度引数(`SIN(1#)`)が単精度で返るか
- Q3（COS、C1〜C4）: `COS(.5)`・`COS(1)`・`COS(-1)`の値、大きい引数
  `COS(100)`
- Q4（TAN、T1〜T4）: `TAN(1)`・`TAN(.5)`・`TAN(-1)`の値、大きい引数
  `TAN(100)`
- Q5（ATN、A1〜A6）: `ATN(1)`・`ATN(-1)`・`ATN(.5)`の値、範囲縮約が
  効く大きい引数`ATN(100)`・小さい引数`ATN(.001)`、倍精度引数
  `ATN(1#)`
- Q6（EXP、E1〜E7）: `EXP(1)`・`EXP(-1)`・`EXP(.5)`・`EXP(10)`・
  `EXP(.1)`の値。倍精度引数`EXP(1#)`。オーバーフロー`EXP(100)`
- Q7（LOG、L1〜L7）: `LOG(2)`・`LOG(.5)`・`LOG(100)`・`LOG(10)`の値。
  倍精度引数`LOG(2#)`。エラー`LOG(0)`・`LOG(-1)`

## 条件・器具

`l4-s4a`（`5f7e6d0`系列、`docs/notes/l4-s4a-float-print-preregistration.md`）
の「条件・器具」節をそのまま踏襲する。要点のみ再掲する。

- 公式ROM一式、ディスク無し、コア既定N88 V2。起動settleは
  `--type-at 300 --type '\n'`、実打鍵の開始は`--type-at 700`。
- 英字は打鍵注入がシフト無しで小文字として送るため画面では小文字になる。
  打鍵文字列の英字(`print`・`sqr`・`sin`・`cos`・`tan`・`atn`・`exp`・
  `log`)はすべて小文字で書く。
- 1文字あたりの反映フレームは`hold+gap=8`フレーム/文字(既定値)。
- 各腕は打鍵の前(`--type-at`の10フレーム前=690)と、打鍵と実行が終わった
  後に写しを取り、`tools/l4_vram_probe.py --diff-before/--diff-after`で
  差分を取る。
- フレーム計算式(l4-s4aと同じ、各腕独立):
  ```
  line_end = 700 + 8 * (その腕で打った文字数、\n も1文字)
  dump     = line_end + 20   (実行の余裕)
  run      = dump + 200      (走行フレームの余裕)
  ```
- 出力の行は「打った行の次の行」として相対の行で特定し、原点は打った行の
  先頭のセル(打鍵のエコーの最初の文字)とする。

### 陽性対照(1腕、腕数には含めない)

`l4-s4a`以来使ってきた陽性対照と同一: `print 7717\n`(文字数11)。
`line_end = 700 + 8*11 = 788`、`dump = 788+20 = 808`、`run = 808+200 = 1008`。

### 陰性対照(腕数には含めない)

起動settleのみ(何も打たない走)。差分0件を期待する(G4)。

## 記録する内容

- 各腕の出力行は、「本文を出さない取り扱い」節の分類に従う。
  `numeric_output`と分類された行は、差分モードで得た「前が空白だった
  セル」の(相対行, 相対桁, 文字コード)の並びをそのまま記録する
  (`l4-s4a`・`l4-s5e`と同じ)。複数行にわたる出力は行ごとに記録する。
- `non_numeric_output`(エラー表示を含む)は件数と位置の範囲(相対行・
  相対桁の最小・最大)のみを記録する。

## 本文を出さない取り扱い

`l4-s4a`と同一の規則を使う。

- 出力行の全セルの文字コードが「数字0-9・`.`・`+`・`-`・`E`・`D`・
  空白」の集合に入る腕だけ、(相対行, 相対桁, コード)を記録する。
- 1セルでも上記集合外の文字コードがあれば、その腕は件数と位置の範囲
  だけを記録し、コード・文言は一切出さない(エラーメッセージはROMの
  データであり、禁止事項7の対象)。
- 上記の分類・記録を行うスクリプトは、集合外の文字コードを標準出力・
  標準エラーへ一切出さない設計にする
  (`tools/l4_s4a_float_classify.py`、`5735eb3`時点で自己検査済み。
  本測定でもこれをそのまま使う)。
- 写し・記録・iologは使い捨ての作業ディレクトリ(リポジトリ外)に置き、
  結果ノートを書いたら削除する。

## 判定

判定名はこの事前登録に書いたものだけを使う。

- 腕ごとの分類:
  - `numeric_output`: 出力行の全セルの文字コードが「数字0-9・`.`・
    `+`・`-`・`E`・`D`・空白」の集合に入る
  - `non_numeric_output`: 上記集合外の文字コードが1つでもある
    (エラー表示を含む)
  - `gate_failed`: 関門G1〜G6のいずれかが偽だった腕
- 予測との照合: 予測表`docs/notes/l4-s6a-gwbasic-predictions.tsv`
  (列: id, group, typed, kind〔numeric|error〕, predicted〔二重引用符で
  囲んだ出力行の文字列〕, approx〔0|1〕)を使う。
  - kind=numericの腕: 予測文字列を出力行の相対桁0から置いたときの
    非空白セル(相対桁, コード)の並びが実測と完全一致すれば
    `predicted_match`、一致しなければ`predicted_mismatch`。
  - kind=errorの腕: 実測の分類が`non_numeric_output`なら
    `predicted_error_consistent`、そうでなければ
    `predicted_error_inconsistent`。
  - `gate_failed`の腕は照合しない。
- `predicted_mismatch`が出た腕は、`l4-s4a`のH6事後分析のような深追いは
  せず、**腕ごとの「最後の桁のずれ」(±1ULP相当か、それより大きいか)
  だけ**を記述し、件数と傾向(SQR近似に集中しているか等)を結果ノートに
  まとめる。

比べるものは以上のみ。最下行(ファンクションキー表示行)とバナーの行は
比べない。

## 器具の確認(公式ROMは使わない)

測定開始前に、自作main ROM(測定時HEADのコミットハッシュを結果ノートに
記す)に対し、42腕すべて+陽性対照1腕の計43腕を打鍵し、エコー行(打った
行そのもの)が打鍵文字列どおりに届くかを`tools/l4_vram_probe.py
--marker`(打鍵文字列そのものをmarkerに指定)で確認する。出力行の中身は
見ない。記号`(`・`)`・`.`・`-`・`#`はすでに`l4-s4a`・`l4-s5e`で届くことを
確認済みだが、本測定でも念のため全腕で再確認する。

作業に使ったROM・写し・スクリプトはリポジトリ外の使い捨てディレクトリ
(scratchpad配下)に置き、確認後に削除する。
