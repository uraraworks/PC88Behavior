# B25: G1 の直後の 2 バイトを、サブが送っているかを順番で確かめる — 結果

記録日: 2026-11-01
規則: [b25-g1-two-bytes-source-preregistration.md](b25-g1-two-bytes-source-preregistration.md)（直前のコミット）どおり。測定はクラウドの実行環境で既存の生ログを再利用（SS は 008d75f のビルド）。値は読んでいない。記録: `measurements/b25-g1-two-bytes-*`。

| `IN $FC` の番号 | OO: sub_fd / new_fd / out_ff / in_fe | SS: sub_fd / new_fd / out_ff / in_fe |
|---:|---|---|
| 3839 | 4100 / 1 / 3 / 4 | 4096 / 1 / 3 / 4 |
| 3840 | 4101 / 1 / 1 / 2 | 4097 / 1 / 1 / 2 |
| 3841 | 4102 / 1 / 2140 / 4262 | 4098 / 1 / 2140 / 4266 |

## 判定: 両腕とも **サブが送っている**

番号 3840・3841 の `new_fd` は 1。発行元はどちらも `lo`。

## 読み方（推定）

- 番号 3840 は 3840 バイトのデータに続けて届く
- 番号 3841 までの間に `OUT $FF` が 2140 回ある。`0x0C` の 709 バイトの送信と数が合うので、この間に `0x0C` が送られている。B22 の `request=02` という表示は、この 2 番目については正しくない可能性がある（器具の確認が要る）
- 自作も同じ位置で 1 バイトずつ送っているが、値が違う（公式 `00`・`14`、自作 `31`・`31`）
- OO の `sub_fd` は SS より 4 多い。起動の途中に公式だけの送信が 4 件ある
