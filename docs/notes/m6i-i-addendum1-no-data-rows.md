# m6i-i 追補1 — データが返らない行を「未到達」にしない（測定前）

記録日: 2026-09-24  
状態: 測定前。実装層（`6d5c705`）は置いたが、**腕は1走も回していない。**

## 1. 何が抜けていたか

[事前登録](m6i-i-arbitrary-coordinate-read-preregistration.md) §5 の到達指標は

> 11行すべてで一般READ が呼ばれ、256位置を受け取った（成否は問わない）

だった。**「256位置を受け取った」を到達の条件にすると、読み出しそのものが
失敗した行が「未到達」に分類される。**

これは2か所で結論を歪める。

- **故障注入腕 I-F-R**（R を1ずらす）。座標列には R=16 の行が3つ（#4・#5・#10）
  あり、ずらした先の R=17 は試験ディスクに**存在しない**。sub はデータを返さず、
  その行は「256位置を受け取っていない」ので未到達になる。**誤りを見抜いた行が、
  見抜けなかった扱い（`unreached`）になる。** 事前登録 §4 は I-F-R について
  「すべての行で不一致」を要求しているので、この腕は必ず `unreached` へ落ちる。
- **本測定 I-S**。実装が壊れていて何も返らない行は、**実装の不合格**として
  数えるべきであって、測定の未到達ではない。今の定義だと、壊れ方が激しい
  ほど「測れなかった」ことになる。

「未到達」は**測定の器具が行に届かなかった**ことを表すべきで、**READ が
失敗したこと**を表すべきではない。

## 2. 直し方

### 到達の定義（器具がその行に届いたか）

- 行の開始を示すマーカーが、座標列の順に11個すべて観測される
- 各行で一般READ の入口が1回以上観測される（入口で成功印を0に戻す書き込みで
  数える）
- 2走の結果が一致する

**256位置を受け取ったかどうかは、到達の条件から外す。**

### 行の結果を3値にする

| 結果 | 意味 |
|---|---|
| `row_match` | 256位置を受け取り、§3 の期待値とバイト単位で一致した |
| `row_mismatch` | 256位置を受け取ったが、期待値と一致しない（先頭4バイトから実際に読んだ座標を記録する） |
| `row_no_data` | その行では256位置を受け取れなかった |

### 判定名への反映

- `sweep_all_match`: I-S の11行すべてが `row_match`。
- `sweep_mismatch`: I-S の1行以上が `row_mismatch` **または `row_no_data`**。
  どちらだったかは行ごとに記録する。
- 故障注入腕の `fault_detected`: §4 の表の「必ず不一致になるべき行」が
  すべて **`row_match` でない**（`row_mismatch` または `row_no_data`）。
- `fault_missed`: それらの行の1つ以上が `row_match`。

総合判定の名前と組み立て（事前登録 §7）は変えない。

## 3. 行の区切り方（器具の都合で決まることを先に固定する）

1回の走で11行を順に読むので、どの受信がどの行のものかを決める必要がある。

- 掃引側が、各行の READ を呼ぶ**前**に、行番号（1〜11）を RAM の1バイトへ
  書く。メモリ書き込み記録で、行番号の書き込みから次の行番号の書き込みまでを
  その行の区間とする。
- 区間内の受信域（`MAIN_SUB_SECTOR_BUF` = `0xDF00`〜`0xDFFF`）への書き込みの
  うち、**最後の完全な256位置**をその行の受信結果とする。再試行で1回目が
  途中まで書いてから失敗しても、2回目の完全な受信で上書きされる。
- 行番号を置く番地は、メモリ書き込み記録の範囲内で、既存のどの番地とも
  重ならないものを器具側で選んで凍結する。**重ならないことを関門で確かめる。**
- 再試行の有無は、区間内の一般READ 入口の回数（1回か2回か）で記録する。
  記録するだけで、判定には使わない。

## 4. 凍結値の追加

| 項目 | 凍結値 |
|---|---|
| ドライブA用ディスクの識別値 | `0xA1` |
| ドライブB用ディスクの識別値 | `0xB2` |
| 測定期限 | 1800 frames |
| 反復数 | 各腕2走 |

測定期限は、m6i-a の A5 が 200回の READ に 6000 frames を要した（1回あたり
約30 frames）ことから、11行・シークを伴う座標列・再試行の余裕を見て置いた。
**予備走で決めた値ではない。** 足りずに行が欠ければ、それは到達の不成立として
現れる（§2 の定義）。

## 5. I-F-RETRY の扱い（事前登録のまま）

事前登録 §4 のとおり、再試行がドライブB の行で起きなければ
`fault_not_exercised` とし、総合判定に入れない。本追補で座標列の順は変えない
（#1 はドライブA の基準行のまま）。再試行口がドライブを保つことは、
実装層の Z80 実走検査（`tools/disk_read_chr_z80_selftest.sh`）が押さえている。

## 6. 変わらないもの

- 座標列11行とその順、故障注入の対応表（「必ず不一致になるべき行」の欄を含む）、
  期待値の取り出し方（D88 像から、生成器を呼ばずに）、関門 G1〜G10、
  総合判定の名前と組み立て、行き先、本文・値列を出さない規律。
