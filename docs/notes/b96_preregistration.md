# B96 事前登録：G5 で自作漢字 ROM の字形が画面に出るか

記録日: 2026-11-17。G5 は漢字 ROM を通しで読む（B84）。自作の KANJI1.ROM・KANJI2.ROM（[kanji-rom-layout.md](kanji-rom-layout.md)、東雲フォントから生成）を置いたとき、ゲームがその字形を画面に描くかを確かめる。公式 ROM・ゲーム由来の値、画面本文、スクリーンショットは公開記録に含めない。

## 前提の確認（先に行う）

[l2-font 仕様](../spec/l2-font.md) のとおり、QUASI88 の libretro 側の読み込み経路は `has_kanji_rom` を参照しない。漢字 ROM が実際にコアへ読み込まれているかを、自作 ROM だけの短い自己検査（OUT E8/E9 で既知の JIS の番地を指し、IN E8/E9 が `tools/make_kanji_rom.py` の出力と一致するか）で先に確かめる。読み込まれていなければ以降は測らず、読み込み経路の問題として記録する。

## 腕

すべて自作 ROM（main dbe1b37）、G5 は B94 と同じ配置、無入力、36000 フレーム。

| 腕 | 漢字 ROM |
|---|---|
| KJ-ON | 自作 KANJI1.ROM・KANJI2.ROM を置く |
| KJ-OFF | 置かない（読むと0） |
| KJ-SHIFT | 自作 ROM を1文字分（32バイト）ずらした版を置く（陰性対照：字形は出るが別の字になる） |

## 記録すること（値は出さない）

- 漢字 ROM ポート（E8〜EF）の IN 件数、そのうち自作 ROM の非0バイトを返した件数、読んだ番地の種類数（第1 ROM・第2 ROM 別）。返した値は自作 ROM の内容なので件数として扱えるが、ゲームが選んだ番地の列は出さない。
- 600 フレームごとの画面ハッシュ（グラフィック VRAM とテキストの両方）の、KJ-ON と KJ-OFF、KJ-ON と KJ-SHIFT の一致数。
- 漢字 ROM を読んだフレームの後で、KJ-ON と KJ-OFF のグラフィック VRAM が初めて異なるフレーム。
- KJ-ON で読んだ各字形（16行×2バイト）が、その後のグラフィック VRAM のどこかにそのままのビット列で現れるか（自作 ROM 側の字形と照合し、現れた字形の割合だけを出す。VRAM の内容・位置は出さない）。

## 判定

- KJ-ON で漢字ポートを読み、読んだ字形の多くが VRAM に現れ、KJ-OFF・KJ-SHIFT と画面ハッシュが違えば「自作漢字 ROM の字形が表示される」とする。
- 正しい字が出ているか（JIS → 番地の対応が正しいか）は、この測定では言えない。本人が WebQ88 で G5 を動かし目で見る確認を別に行う（本人の手元だけで行い、画面は記録しない）。
- 陰性対照として、KJ-ON の VRAM を「読んだ番地の1文字隣の字形」とも照合する。この出現割合が読んだ字形の割合と同程度なら照合が字形を区別できていないとみなし、結論を出さない。
- KJ-SHIFT は画面ハッシュが KJ-ON と違うこと（字形の中身が画面に効いていること）の確認に使う。
