# m6f-h — ASCII 形式のファイル本体 — 結果

記録日: 2026-09-28

## 1. 実行

[事前登録](m6f-h-ascii-file-body-preregistration.md)（`156d1c1`）・[追補1](m6f-h-addendum1-none-candidate.md)（`c753536`）に従った。

- **1回目（器具 `8c6219d`）は判定に使わない。** 公式ROM起動7回目（H-0 の1走目）で、本体読取器が鎖の終端を `0xC1`〜`0xC8` しか受け付けず
  例外になり `gate_failed G6` で停止した。H-0（空のプログラム）の終端が `0xC0` 以上 `0xC8` 以下の範囲の外ではなく、使ったセクタ数0の `0xC0`
  だったためと読める（2回目で `used_sectors=0` を確認）。読取器を直した（`a1fbb35`、候補・判定・凍結値は不変）。
- **2回目（器具 `a1fbb35`）**: 公式ROM起動8回（4腕×2走）。関門 G1〜G7 はすべて真。G7（本体を読んだ最大位置）は全腕で上限（予測の長さ＋1、H-0 は読まず）以内。
  測定後の像は削除した。本体のバイト値は出力していない。

## 2. 判定

| 腕 | 判定 | 使ったセクタ数 |
|---|---|---:|
| H-1（2行のプログラム、`SAVE ,A`） | **`LIST_CRLF_1A`** | 1 |
| H-2（70行、`SAVE ,A`） | **`LIST_CRLF_1A`**、H-IV **`chain_concatenates`** | 15 |
| H-3（`OPEN … FOR OUTPUT` と `PRINT #`） | **`CRLF_1A`**、H-V **`data_same_as_ascii_program`** | 1 |
| H-0（空のプログラム、`SAVE ,A`） | **`EMPTY`**（使ったセクタ数0、終端 `0xC0`） | 0 |

いずれも2走一致・一意。

## 3. 採った規則

- ASCII 形式のプログラム（種別 `0x00`）の本体は、各行を **`LIST` の出力と同じ文字列**（l4-program.md 第2節）で、**`CR LF` 区切り**で並べ、
  最後の行の区切りの直後に **`0x1A`** を置く。
- 順次データファイル（`PRINT #` で書いた行）も同じ区切りと終わりの印。
- 本体が複数の単位にまたがるときは、鎖の順に単位をつなげ、最後の単位は終端が示すセクタ数までを使う（l3-disk-format 第4版 2.3〜2.4節）と、連続した文字列になる。
- 行が1つも無いプログラムを `SAVE ,A` すると、エントリはでき、先頭単位の割り当て表の値は `0xC0`（使ったセクタ数0）になる。

## 4. 行き先

- `docs/spec/l3-disk-format.md` 第5版に「ASCII 形式の本体」節を新設し、2.4節の終端に `0xC0`（0セクタ）の観測を足す。
- 次稿で `LOAD` の画面の反応とエラー（存在しない名前、データファイルの LOAD 等）を測ってから、自作 `LOAD` を実装する。

## 5. 決めないこと

- 最後のセクタの余り（読んでいない）。通常の `SAVE`（`0x80`）・`SAVE ,P`・`BSAVE` の本体。
