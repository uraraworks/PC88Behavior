# m7m: 起動時単発応答規則の恒久実装と到達点

測定日: 2026-08-13

## 1. 目的と情報境界

m7hで確定した要求グループから応答グループへの決定関数と、m7j条件Cで
一時介入にだけ使っていたラウンド#0応答を恒久実装へ移した。公式ROM・
公式ディスクのバイト列は読まず、表示せず、保存せず、逆アセンブルしていない。
`private/`は直下の名前だけを確認し、参照先は`PC88_REF_ROM_DIR`と
`PC88_REF_DISK_DIR`で測定プロセスへ渡した。

公式側応答、候補値、候補順、要求内容は介入器のメモリと使い捨て自作ROMだけで
扱った。本稿には値を記録しない。確定値を書く場所は、採用方針どおり
`docs/spec/l3-subrom.md`と`src/l3_service/make_subrom.py`に限定した。

## 2. ブラックボックス介入

ラウンド#0と未確定の応答同値グループごとに、全256候補を非表示のランダム順で
介入し、公式側との対象位置一致が初めて成立した候補で停止した。発見走とは別の
2走でも同じ一致を再現した。比較器は既知の同一入力と意図的な差を事前に判別した。

先頭側の応答グループは、公式mainと自作subの通常起動系列で、既に確定した応答を
先行位置へ順に適用しながら値一致プレフィックスを伸ばした。後半側は、交換#4の
多バイト応答が先に不一致となって通常系列では対象位置を評価できなかった。
m7hが確定した要求から応答への関数性を直接検証するため、ラウンド#0完遂後に対象
要求だけを提示する自作main治具を使い、公式subと候補subの同位置応答を比較した。
最初に公式系列全体を再演する治具も試したが、多バイト応答へ到達しなかったため
採用せず、単独要求治具へ切り替えた。

## 3. 恒久実装

起動系列最初の単発応答は、起動ハンドシェイクが要求先頭を消費して要求バッファ
だけでは識別できないため、メインループ開始後の最初の単発送信へ一度だけ適用する。
後続単発応答は、受信run長と要求バッファ内容の完全一致からm7hの応答グループを
選ぶ。m7hの分類にはmain側サイト種別も含まれていたが、観測した全要求グループの
要求内容は相互に異なるため、subから見える要求内容だけで同じ決定関数を実装した。

いずれも意味未特定・挙動から再構成した観測応答である。意味が判明した場合は、
観測定数と完全一致表を廃止し、要求の意味に基づくルール生成へ差し替える。

## 4. 恒久実装での一致長

600フレームの公式対照と恒久実装を新規実走して比較した。main側`IN $FC`の
値一致プレフィックス長は0件から4件へ伸びた。最初の不一致は5件目で、交換#4の
多バイト実データ応答に属する。今回の単発応答規則の対象外である。

専用の構造診断を1800フレームで再実走した結果、main側の構造的一致
プレフィックス長は258件から258件で変化せず、最初の構造分岐は259件目だった。
sub側は172件まで一致し、173件目で分岐した。値一致の改善と構造分岐の位置が
変わらないことは両立する。

## 5. 最終検証

- `tools/run_all_selftests.sh`: 参照環境ありで終了コード1。伏せ字検査を含む
  各selftestは両ロケールで成功した。`conform_l3.sh`の混成不適合だけが、
  宣言した期待終了コードとの不一致として集約結果を失敗にした。
- `tools/verify_l3.sh`: 終了コード1。交換#3/#4境界と既存回帰は合格し、別件の
  既知未達成「ディスク無しでもsubがI/Oを発行する」だけを不適合として検出した。
- `tools/conform_l3.sh`: 終了コード1。公式ROM一式の本番照合は件数・ハッシュとも
  一致した。公式mainと自作subの混成ではバルク受信対象を1件も抽出できず、
  通し番号1件目より前で分岐した。本体のSKIPは無い。
- `tools/diag_l3_mixed.sh`: 終了コード0。比較器selftestは合格し、上記のmain/sub
  構造分岐位置を再現した。診断ツール自体は適合合否を返さない設計である。

各コマンドには10分の自前タイムアウトを付け、打ち切りは0件だった。期待値の変更、
判定緩和、失敗の握りつぶしは行っていない。

## 6. 残った不適合と限界

- 交換#4の多バイト実データ応答が公式側と一致せず、値一致は5件目で止まる。
- 起動時バルク転送は未適合で、混成適合テストの対象イベントは通し番号1件目より
  前のままである。単発応答規則だけではこの経路を実装できない。
- 構造的一致はmain側259件目、sub側173件目で分岐し、今回の値規則では動かない。
- 後半応答グループの確定は単独要求条件であり、公式起動系列の途中状態を完全再演
  した結果ではない。別媒体・別ROM版・実機も横断していない。
- ディスク無し不適合は今回の仕事とは別件として残る。
