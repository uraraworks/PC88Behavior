# m7dq: 同一セッション逐次オープン対照の事前登録

実施日: 未実施（本稿は事前登録のみ。測定はまだ行っていない）

本稿は`m7dp`で未確定となった削減要因を切り分ける対照を、実測前に固定する。
公式ROM・公式ディスクの内容は読まず、生ログ、画面報告、ROM／ディスク複製は
リポジトリ外の一時領域だけに置く。データポートの値列は表示・転記せず、比較は
件数、位置、clock、SHA-256だけで行う。`cmp -l`等でファイル内容を出力しない。

## 対照の設計と自作データ

条件を次の3つに固定する。

- **A（同時）**: `m7dp`測定本体。Q9AとQ9Bを同時に開き、3行ずつ交互に読む。
  既測値はmain `IN $FC` 9254件、READ単位21。
- **B（同一セッション逐次、本稿の測定対象）**: Q9Aを開いて3行読み、閉じてから
  Q9Bを開いて3行読み、閉じる。同時には開かない。
- **C（別ブート単独2回の合計）**: `m7dp`分解基準のQ9A単独とQ9B単独の和。
  既測値はmain `IN $FC` 16444件、READ単位34。

Bでは、`m7do`の準備runで作ったQ9A（A1/A2/A3）とQ9B（B1/B2/B3）をそのまま
使い、完成した同一の`prep.d88`からrunごとに新しい使い捨て複製を作る。準備runは
測定へ含めず、各runは書込みを行わない。打鍵するプログラムを次に固定する。

```basic
10 OPEN "Q9A" FOR INPUT AS #1
20 S$=""
30 FOR I=1 TO 3
40 LINE INPUT #1,A$
50 S$=S$+A$
60 NEXT I
70 CLOSE #1
80 OPEN "Q9B" FOR INPUT AS #1
90 FOR I=1 TO 3
100 LINE INPUT #1,B$
110 S$=S$+B$
120 NEXT I
130 IF S$="A1A2A3B1B2B3" THEN PRINT "M9M"
140 CLOSE #1
150 PRINT "M9C"
RUN
```

比較可能性のため、A/B/Cで自作ファイル、その内容、各ファイルから読む行数3、
`LINE INPUT#`、内容一致マーカーを出してから全て閉じる構造、全`CLOSE`後の`M9C`と
直後の`Ok`を揃える。内容一致マーカーはA/Bが`M9M`、既測Cは`M9A`/`M9B`とする。
フレーム数は9000、打鍵開始は起動プロンプト待ちに合わせた300F/700Fの二段、
ディスクは同じ準備済み原本からrun単位に作り直す。ROM構成以外のハーネス引数も
`m7dp`と同じにする。意図的な差は、BではQ9Aを全て読んで閉じた後にQ9Bを開くこと、
および同時オープンを避けるため両方に`#1`を使うことだけとする。

Bは公式一式2回・混成2回を測る。三条件の一次判定にはA/Cと由来を揃えた公式2回の
一致値を用い、混成2回は自作subとの入口適合確認に用いる。

## 到達条件・対照

Bの到達条件は次の4項目のANDとする。

1. 上記プログラムと`RUN`が画面へ反映される。
2. Q9Aを3行読んだ後に`CLOSE #1`を通過し、Q9Bを再び`#1`で開いて3行読む。
3. 連結結果の一致マーカー`M9M`、両ファイルを閉じた後の`M9C`が順に表示される。
4. `M9C`の直後に`Ok`が表示される。

陽性対照は4条件を全て持つ合成画面、陰性対照は(a)最初の`CLOSE`後へ進まない、
(b)`M9M`を欠く、(c)`M9C`を欠く、(d)`M9C`直後の`Ok`を欠く形とする。

**不合格条件**は、構文エラー、最初の`CLOSE`後のQ9Bオープン不成立、`M9M`欠落、
`M9C`欠落、直後の`Ok`欠落、無反応または無限ループのいずれかとする。単なる構文受理、
片方だけの読出し、または`Ok`だけでは合格させない。

## 判定規則

一次指標はmain `IN $FC`件数とREAD単位数の2つとする。Bの各指標値を`b`、同じ
指標のA/C既測値を`a`/`c`とし、各指標について`|b-a|`と`|b-c|`を比較する。
任意の件数幅や割合の閾値は置かない。

- 2指標ともAへの距離がCへの距離以下で、少なくとも1指標がAへ厳密に近ければ、
  **A寄り**とし、「同一セッションであることと整合する」と判定する。
- 2指標ともCへの距離がAへの距離以下で、少なくとも1指標がCへ厳密に近ければ、
  **C寄り**とし、「同時オープン状態であることと整合する」と判定する。
- 一方の指標がA寄りで他方がC寄り、または2指標とも等距離なら、**中間／不一致**と
  判定し、どちらの説明も採択しない。片方だけ等距離なら、他方の厳密な側を採る。

距離比較は整数の生件数ごとに行う。補助記述としてA--C間におけるBの正規化位置を
各指標で示してよいが、一次判定を変更しない。BがA/Cの区間外でも同じ距離規則を適用し、
区間外である事実を併記する。SHA-256は決定論性・列一致の検査にだけ使い、A/B/Cの
近さ判定には使わない。

## 交絡と解釈限界

次の交絡は本対照だけでは除去できない。

- Bの2回目は、1回目が残したバッファ、ディレクトリ検索結果、直前のシーク位置、
  FDC・ドライブ状態を引き継ぎうる。これは検証対象の「同一セッション効果」に含まれ、
  内訳を分離できない。
- AとBでは、同時オープンの有無だけでなく、交互読出しかファイル単位の連続読出しか、
  Q9Bが`#2`か再利用した`#1`か、Q9Aの`CLOSE`がQ9B読出し前か後かも異なる。
  BASIC上で同時性だけを変えて他を完全に同一にはできないため除去不能である。
- Cは別ブート2回の和、A/Bは1ブートなので、起動・初期化の固定費をCだけ2回含みうる。
  指定されたCを一次比較から外さないが、この固定費をアクセス内訳から分離しない限り、
  A寄りをキャッシュ等の特定機構へ帰属できない。
- Q9A→Q9Bの順序、両ファイルの物理配置、準備時の作成順は固定されるため、順序効果・
  近接配置効果は除去できない。逆順や別配置は本稿の範囲外とする。

従って言えるのは、固定した複合条件BがA/Cのどちらに近いか、および単一セッションへの
集約だけでm7dpの削減を再現できるかである。A寄りでも「同一セッション一般」や特定の
バッファ機構が原因とは断定せず、C寄りでも純粋な同時性だけが原因とは断定しない。
中間／不一致なら両仮説を未確定のまま残す。

## 観測指標と固定手順

`m7dp`と同じ測定・分類器を使い、公開FDCコマンド種別列と件数、`READ DATA`・
`WRITE DATA`件数、main `IN $FD`・`IN $FC`の件数とSHA-256、画面の行数・文字数・
SHA-256だけを記録する。データポート値列は記録しない。

全4runで取りこぼし0件を必須とし、同一モード2回の全イベント列・画面の決定論的一致を
確認する。公式1回目の到達runでBの署名を固定した後に全runを再判定する。判定器には
件数、SHA-256、期待値0行の故障を注入し、全て不一致になることを確認する。

## 打ち切り条件

次のいずれかで測定系列を打ち切り、そのrunの署名を期待値・三条件判定へ採用しない。

- 9000フレーム、300秒、または512打鍵の上限に達しても到達条件を満たさない。
- 不合格条件のいずれかに該当する。
- 取りこぼしが1件以上あり、原因を除いた再測定でも0件にできない。
- 同一モード2回が決定論的一致せず、原因を切り分けた再測定でも一致しない。
- 準備済み原本と異なるディスク状態、run間の書込み継承、または固定ハーネス条件からの
  逸脱が判明する。
- 公式ROM・公式ディスクの内容、またはデータポート値列を表示・転記するおそれが生じる。

本対照には別入口への切替先を設けない。打ち切り時は理由と、内容を出さない件数・位置・
clock・SHA-256だけを記録し、A/B/Cの因果判定を「未判定」とする。

## 情報境界

記録するのは件数、位置、clock、SHA-256、画面の行数・文字数・SHA-256、自分で打鍵した
文字列・自作データ、および公開されたμPD765のコマンド名だけとする。画面本文全体、
ディスクのデータ部、公式の応答値は記録しない。ROM・ディスク複製、生iolog、標準出力は
リポジトリ外の一時領域だけで扱う。
