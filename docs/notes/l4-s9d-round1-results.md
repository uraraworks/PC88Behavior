# l4-s9d 1回目結果 — CLEAR の上限番地と FRE

2026-10-04。記録担当。公式ROMは測定済みで、本作業は既存TSVの集計と
仕様・期待値の編集のみ。ROMのバイト列や画面本文を読まず、自作プログラムの
PRINT整数組だけを使った。src/・tools/ は変更していない。

## 集計と関門

事前登録は [メモリ境界の事前登録](l4-s9d-memory-limit-preregistration.md)
（器具 `5f02a0a`）。測定時HEADは `5f02a0a`。
元TSVはリポジトリ外の `../tmp/l4s9d-work/official_round1.tsv`。
73腕×2走＝146行。2走の印列・他行件数は全73腕で一致、打鍵・採取失敗と未実行は0。

| 区分 | 腕数 | 行数 | 結果 |
|---|---:|---:|---|
| 定数対照（control-value=73、control-error=ERR 5） | 2 | 4 | gate=pass、P_MANUAL=agree |
| 観測（limit 33＋stack 2、既定対照 35） | 70 | 140 | gate=pass、P_MANUAL=observe |
| `default-empty`（既定状態の `fre("")`） | 1 | 2 | 2走とも gate_failed |

関門（定数対照2腕）は通過した。`default-empty` だけが gate_failed。
2走とも完了印 `s9dd` と CLEAR 成功印 `s9da` は出たが、FRE値の印 `s9dv` は出ず、
他行件数は5（他の全行は4）だった。数値が出なかったことを示すが、
その行の中身は記録せず、数値以外の何だったかは決めない。
CLEAR を実行した70腕（33点×2＋stack 2腕）では、既定対照35腕とも `s9da` が出て
FRE値が採取できた。

## P_MANUAL の判定

事前登録は番地・既定FRE値・境界ERR番号を予測せず、観測する枠だった。
予測のあった項目だけ照合する。

- 傾き1（候補）: CLEAR第2引数 a が受理された23点（0x8C00〜0xE400、0x400刻み）すべてで
  `fre(0) = a − 35098` が一致した（0x8C00→742、0xC000→14054、0xE400→23270）。
  23/23一致、不一致0。マニュアルの領域説明からの推論は、この格子で支持された。
- 第3引数: 推論どおり、stackを増やすとFREが減る向きで観測された（下記）。
- 既定対照F0は全35腕で 23779 に一致し、F0の安定性の前提は成り立った。
- 定数対照は予測（73、ERR 5）に一致。

## 測定で裏付けた規則

**受理範囲**（`clear ,a`、a は第2引数のみ指定）:

| a | 結果 |
|---|---|
| 0x8000、0x8400 | ERR 5 |
| 0x8800 | ERR 7 |
| 0x8C00〜0xE400（23点） | 受理。`fre(0) = a − 35098` |
| 0xE800〜0xFC00（5点）、0xFFFF | ERR 5 |

0x8800 の ERR 7 は他の拒否点（ERR 5）と番号が違う。この1点の観測だけで、
境界付近の誤り番号の規則は決めない。受理の上側境界は 0xE400（受理）と
0xE800（拒否）の間、下側境界は 0x8800（ERR 7）と 0x8C00（受理）の間にある。

**既定の上限の推定**（推定。直接の観測ではない）: CLEARを飛ばした既定の
`fre(0)` は 23779。傾き1と `fre(0) = a − 35098` を既定側へ外挿すると
a = 23779 + 35098 = 58877（0xE5FD）。格子の受理境界（0xE400受理・0xE800拒否）と
矛盾しない。受理された格子点だけからの外挿で、既定上限そのものは測っていない。

**第3引数**（第2引数 a = 49151）:

| 腕 | fre(0) |
|---|---:|
| `clear ,49151,256` | 14309 |
| `clear ,49151,1024` | 13541 |

第3引数なしの `a = 49151` の腕は無い。傾き1から同じ a の第3引数なしを
49151 − 35098 = 14053 と推定すると、256 は +256、1024 は −512 になる。
差が (既定 − 指定) に一致するので、既定のスタック相当は512バイトと推定できる
（マニュアルの「リセット時初期値512」と整合するが、本測定は推定であり、
512の腕を直接測ってはいない）。

## 期待値の固定と照合

根拠の鎖は、自作PRINT整数組の測定TSV → 本ノート →
[l4-basic 第20節](../spec/l4-basic.md#20-観測--clear-の上限番地と-frel4-s9d)。
[期待値](../../tests/conformance/expected_l4_memlimit.tsv) は gate_failed の
`default-empty` を除く72腕について、1走目の `print_values` を保存した
（列は `arm`・`prediction`。器具の check が読む列名）。
器具 check は「期待値の腕集合＝測定の腕集合」を要求し、予測なしも不合格にする。

- 元TSV（73腕）に対する check は 照合不一致（rc=1）。腕集合が1腕違うため。想定どおり。
- `default-empty` の2行を除いたコピー（作業用・非コミット、72腕）に対する check は
  照合一致（rc=0）。
- `tools/` は変更していない。`default-empty` を期待値に入れる場合は、
  数値が出ない腕を許す check の拡張が要る。ここでは決めない。

公式ROMの再測定、git add、コミットは実行していない。

## 決めなかったこと

- 既定上限の正確な値（58877＝0xE5FD は格子の外挿の推定）。直接の受理境界は
  0xE400〜0xE800 の間、0x8800〜0x8C00 の間で、追補で詰める必要がある。
  整数化・端点の包含による差も未確認。
- 定数35098が何で決まるか（公式の既定配置に依存する観測値）。
- `fre("")` の意味（数値が出なかった。受理・値とも未確定）。
- 第1引数（ストリング領域の大きさ）の効き方、`fre(1)`・`fre(2)`、文字列領域の整理。
- ROM内部の作業領域配置、プログラム本文の置き場所、機械語。
- 0x8800 の ERR 7 と他の拒否点の ERR 5 の使い分け。
- 第3引数の受理範囲（0・極端な値）、512を直接指定した腕。
