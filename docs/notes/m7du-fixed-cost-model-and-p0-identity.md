# m7du: SB/SC実測による固定費モデル判定とP0起動列の同一性

実施日: 2026-08-28

**本稿は`m7ds`で事前登録し、`m7dt`でSB/SC未測定のため保留したH-F（固定費）を、
同じadjacent媒体のSB/SC実測で正式判定する。** あわせて、m7dtのP0=6672件が
1.6節の起動バーストに随伴する第2チャンネル6672件そのものか、単なる同値かを、
値非表示SHA-256と区間構造で判定する。判定式・完全一致規則は変更していない。

公式ROM・公式ディスクの内容は読まず、生ログ、画面報告、ROM／ディスク複製は
リポジトリ外の一時領域だけに置いた。データポート値は1バイトも表示・転記せず、
`cmp -l`等でファイル内容を出力する比較も行っていない。`src/`は変更していない。

## 測定条件と到達

公式diskA原本から作った使い捨て複製へ、Q9A（A1/A2/A3）、Q9B（B1/B2/B3）、
Q9C（C1/C2/C3）をこの順で作った。書込み保存は作成runの複製だけに行い、検証runと
測定runは完成媒体からrunごとに新しい複製を作って保存しなかった。原本は変更していない。

作成runは`P9D`と直後`Ok`へ到達し、WRITE DATA 24件、取りこぼし0件だった。別プロセスの
検証runはQ9A/B/Cの各3行の連結一致を表す`P9A`、全CLOSE後の`P9C`、直後`Ok`へ到達し、
取りこぼし0件だった。

SB/SCはm7dsのR1単独読出しテンプレートを使い、ファイル名、期待連結、自作固有マーカー
だけを置換した。各runは9000フレーム、300F/700Fの二段打鍵、300秒・512打鍵上限である。
全4runで対象3行の内容一致マーカー、`S9C`、直後`Ok`へ到達し、`S9N`は出なかった。
構文エラー、内容不一致、CLOSE未通過、無反応、無限ループは無かった。

起動のみ対照は公式diskA原本からrunごとに使い捨て複製を作り、1800フレーム、打鍵なしで
2run測った。これはファイル操作の無いP0が持つ6672件を、既報値の同値だけで起動列へ
帰属しないための独立対照である。

## 全run取りこぼし0件と決定論性

SB/SC各2runと起動対照2runの全6runで、iologのmain/sub各1行、計2行の取りこぼし
ヘッダは全て0件だった。不採用runは0で、単一走を合格に数えていない。

SB/SCはそれぞれ、全イベント列、main `IN $FC`の件数・SHA-256、FDCコマンド種別列、
READ/WRITE単位、画面の行数・文字数・SHA-256が2runで完全一致した。起動対照も
全イベント列、main `IN $FC`、FDCコマンド種別列、区間構造が2runで完全一致した。

## SB/SCの実測値

2runで一致した値を条件ごとに1行へまとめる。

| 条件 | main `IN $FC` | SHA-256 | READ単位 | WRITE単位 | FDCコマンド | 取りこぼし | 2run |
|---|---:|---|---:|---:|---:|---:|---|
| SB（Q9B単独） | **8222** | `20a7c84cb234ee1b99b64eef009f122d731ed37a8069c719501770b45239adce` | **17** | 0 | 83 | 0 | 完全一致 |
| SC（Q9C単独） | **8222** | `ffcf1567500d1e99faf6cb865be3695bf16259b6f2da48aa3072127683dac7d6` | **17** | 0 | 83 | 0 | 完全一致 |

SBとSCは件数・READ単位・公開FDCコマンド種別列が等しいが、main `IN $FC`のSHA-256は
異なる。従って、Q9B/Q9Cのファイル固有部分を同一列と取り違えた結果ではない。

## H-F（固定費モデル）の正式判定

m7dsで固定した`Z=P0`、`A=R1`、`B=SB`、`C=SC`と式をそのまま使う。

| 入力 | main `IN $FC` | READ単位 |
|---|---:|---:|
| Z = P0 | 6672 | 9 |
| A = R1 | 8222 | 17 |
| B = SB | **8222** | **17** |
| C = SC | **8222** | **17** |

SB/SCはいずれもm7dtで逆算した必要値8222件・17単位に、両指標とも完全一致した。

```text
pred(R2) = A + B - Z
         = 8222 + 8222 - 6672 = 9772件
           17   + 17   - 9    = 25単位

pred(R3) = A + B + C - 2*Z
         = 8222 + 8222 + 8222 - 2*6672 = 11322件
           17   + 17   + 17   - 2*9    = 33単位
```

予測R2=9772件・25単位は実測R2、予測R3=11322件・33単位は実測R3へ、両指標とも
完全一致した。また`R3-R2=1550件・8単位`は`C-Z=1550件・8単位`と等値である。
従って登録規則により、**H-Fだけで逐次1→2→3ファイルの非加法性を説明できるとして
H-Fを支持する。** これは観測量に対する十分性であり、内部にキャッシュ等が存在しない
ことや、別機構同士の相殺が無いことの証明にはしない。

## P0と起動時6672件の同一性

起動のみ対照2runは、main `IN $FC`が6672件、SHA-256が
`38b6729d075500b9512063f6838f7664012eb1ccce90f2218261ffa9da63fc0f`で一致した。
これはm7dtのP0全6672件のSHA-256と完全一致する。件数だけでなく全列署名が一致した。

起動のみ対照の第2チャンネル（sub `OUT $FD` = main `IN $FC`）の区間構造は、
バルク前779件、バルク中5634件、バルク後259件で、合計6672件だった。対応する
第1チャンネルはバルク中5635件、前後0件である。公開FDC列も51コマンド・READ 9単位で、
m7dtのP0の51コマンド・READ 9単位と一致した。

さらにSB/SC各2runでは、main `IN $FC`の**先頭6672件**が起動対照全列と、値列SHA-256
だけでなく`frame/kind/port/pc`の正規化位置SHA-256
`b9a16427f278148718af7144fca516dbcb123a9a81c2045b77a4d580d83c8ce2`でも完全一致した。
このprefixはframe 20〜77にあり、後続1550件はframe 2416から始まったため、入口側と
区間も分離している。従って、**P0の6672件は1.6節の起動バーストに随伴する
第2チャンネル列と同じ観測列であり、たまたま同値なのではない**と判定する。
内部で同じコード経路が実行されたという実装帰属までは主張しない。

## 非加法性の説明の分解

別ブート単独A+Bの合計16444件・34単位から、同一セッション逐次R2の
9772件・25単位を引くと、**6672件・9単位**でZ=P0と完全一致する。
従って逐次条件については、「アクセスが同一セッションで削減された」というより、
各単独値に同じ起動列・起動READが含まれ、別ブート2回の単純加算が固定費を二重計上した
ものを、1回分だけ除いた」と記述するのが正確である。

一方、同時オープン実測9254件・21単位は、固定費だけの2ファイル予測
9772件・25単位よりさらに**518件・4単位**少ない。別ブート合計から同時条件への全差
7190件・13単位は、固定費で説明できる6672件・9単位と、固定費では説明できない
残差518件・4単位に分ける必要がある。従って1.54節の非加法性を全て固定費へ置換する
ことはできず、逐次部分を「固定費の二重計上」と改めた上で、同時条件固有の残差を
別に残すのが妥当である。この残差をキャッシュ、ディレクトリ検索、SEEK等の特定機構へ
帰属しない。

## 解釈限界

- H-F支持は、QUASI88上の同じadjacent媒体、同じ3行ファイル、同じ打鍵条件の
  `IN $FC`件数とREAD単位に対する算術上の説明である。
- P0同一性は値列SHA、位置SHA、区間構造、FDC件数で確かめた観測列の同一性であり、
  公式ROM内部の実装経路同一性を意味しない。
- 同時条件の残差518件・4単位は固定費だけで説明できないが、A/Bはファイル番号、
  OPEN期間、交互／連続読出し、CLOSE時点も異なる。純粋な同時性だけの効果とは断定しない。
- 大きなファイル、別配置、逆順、同一ファイル再読、実機一般へは一般化しない。

## 固定判定の故障注入

集計値だけを受ける独立判定器へ、SB件数破壊、SC READ単位破壊、0件入力を注入し、
H-F判定の3/3を不一致または入力不備として検出した。P0同一性判定には件数、値列SHA、
位置SHAを各1項目ずつ破壊し、3/3を不一致として検出した。空振りは0件だった。

## 情報境界

記録したのは件数、位置・frame区間、SHA-256、画面の行数・文字数・SHA-256、自分で
打鍵した文字列・自作データ、および公開されたμPD765コマンド名だけである。画面本文全体、
ディスクのデータ部、公式応答値、データポート値列は記録していない。ROM・ディスク複製、
生iolog、stdout/stderrは全てリポジトリ外の一時領域だけで扱い、集計後に削除した。
