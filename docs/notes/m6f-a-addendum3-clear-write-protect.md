## 2. 原因

SAVE を打鍵しても **WRITE DATA が1件も出ず、複製の像も変わらなかった。** 既存の適合検査
`tools/conform_l3.sh` は、SAVE の場面で参照 diskA の複製を作った直後に

```bash
printf '\x00' | dd of="$WDISK" bs=1 seek=26 count=1 conv=notrunc
```

として、**D88 ヘッダの書き込み保護フラグ（26バイト目）を外してから** SAVE している。
同じ検査には、保護したまま SAVE して「ライトプロテクト違反」になる場面（`write_protect`）
もある。**参照 diskA の像は書き込み保護付き**であり、本稿の器具はこの作法を引き継いで
いなかった。

**参照ディスクのヘッダを読んで保護フラグを確かめることはしていない。** 既存器具の作法と
症状（WRITE DATA 0件）が一致することからの推定であり、§3 の直しで到達するかどうかが、
この推定の検証になる。

## 3. 直し方

測定ドライバで、各腕の使い捨て複製について次の順にする。

1. 参照を複製し、**複製の SHA-256 が参照と一致すること**を確かめる（G5、変更なし）
2. **複製の D88 ヘッダ26バイト目へ `0x00` を書く**（`conform_l3.sh` と同じ。書くだけで、
   元の値は読まない）
3. **G5b（新設）**: 複製と参照で違うバイトの**位置だけ**を数え、違いが「無い」か
   「オフセット26の1か所だけ」であることを確かめる。値は出さない。

差分器は D88 のセクタのデータ部だけを比べる（`D88Reader` 経由）ので、ヘッダの1バイトの
変化は差分に入らない。

## 4. 変わらないもの

- 境界の規則（事前登録 §1・追補2）、刺激 F0〜F6、導出規則 D1〜D7、関門 G1〜G7、
  判定名、行き先。
- **F0 は保護を外した状態でも陰性対照として働く**（SAVE しない走で差分が空であること）。
  保護を外したことで、F0 が「保護されているから書かれなかった」ではなく「刺激が無いから
  書かれなかった」ことを示す対照に戻る。全腕を取り直す。
