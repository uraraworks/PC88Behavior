# B99 結果：公式 ROM は途中リセットでグラフィック VRAM を3面とも0にする

実施: 2026-11-17、クラウド（公式 ROM と自作 ROM、全30走正常）。手順は [事前登録](b99_preregistration.md) のとおり。補足として、R-G・R-T は F300 で RETURN を1回入れてから F700 で本文を打った。媒体を抜く操作はリセットと同じフレームでプローブから行った。値・画面本文は出さない。

- R-G・R-G5-OUT: 公式はリセット後、R+300・R+1800 ともグラフィック VRAM の3面がすべて0。自作は消さずに残る。表示の設定（ポート 31 bit3・53）は公式・自作とも表示ありのままなので、公式は表示を切るのではなく VRAM そのものを消している。
- 書き込みの順: 公式はリセット後にポート 5C→5D→5E（各面の選択）を1回ずつ書く（R+13・R+18・R+22 フレーム）。自作は R+4 にまとめて書いている。
- R-T・R-COLD: グラフィック VRAM は公式・自作とも0。
- FDC: R-G5-OUT はリセット後の FDC コマンドが公式・自作とも0件。R-G5-IN は公式・自作とも同じ件数（SPECIFY 1・RECALIBRATE 5・SENSE INTERRUPT STATUS 30・SEEK 25・SENSE DRIVE STATUS 23・READ DATA 23）。
- 入力待ち: 自作は全腕で Ok まで着く。公式は DISK.ROM ありの構成で起動時の問い合わせ行の入力待ちになる（既知の差）。
- R-COLD: 公式の main の OUT 列（12747 件）は自作の先頭と全件一致し、器具は正常。他の腕は R-G・R-T・R-G5-OUT が 159 件目、R-G5-IN が 64 件目で分かれる。

## 判定

1. 自作の起動処理に、グラフィック VRAM 3面の消去を入れる。公式は面の選択（5C・5D・5E）を1面ずつ書いて間を空けており、1面ずつ0で埋めていると読める。電源投入時（R-COLD）は VRAM が元から0なので、この働きはこれまでの測定に現れなかった。
2. リセット後にディスクを抜いた状態での FDC コマンドは公式・自作とも0件で、ROM は原因ではない。WebQ88 で見えたアクセスランプの点滅は、エミュレータ（FDC の処理中の扱い）か WebQ88 側の表示の問題として別に調べる。
