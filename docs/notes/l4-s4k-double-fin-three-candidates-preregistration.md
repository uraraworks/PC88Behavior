# l4-s4k — 倍精度の定数読み取り（候補DEXACT/DGW/DREP01） — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

単精度の定数の読み取り方は、`l4-s4i`・`l4-s4j`の測定を経て、開発者
判断により推定`REP01`が採用された（仕様書`docs/spec/l4-basic.md`第3.6版
`ca77caf`第5.1.1節、既存観測57件中55件を再現）。倍精度の定数の読み取り
は同ノート第10節に**未測定**として残っている。

本ノートは、段階4b（倍精度の実装）に入る前の測定として、単精度の
`l4-s4i`・`l4-s4j`と同じ組み立てで、倍精度の定数読み取りの方式を新しい
候補の式・対照で前向きに検証する。

## 候補（定義）

倍精度浮動小数点（MBF、仮数56bit）を対象とする。丸めは半分なら絶対値
の大きい側（`l4-s4g`・`l4-s4h`で確定した丸め方向、単精度・倍精度共通）。

**倍精度の定数**とは、ソース上の数値定数のうち、小数点を除く数字が
8桁以上、または`#`が付いている、または`d`指数が付いているものを指す
（この条件のいずれかに当てはまれば倍精度として読み取られる）。

- **`DEXACT`**: 10進の値を倍精度へ1回で丸める。
- **`DGW`**: GW-BASICの`$FIN`の倍精度経路（積み上げた整数部を倍精度に
  し、倍精度の10のべき表を**1回**掛け/割りして倍精度へ丸める。単精度
  版`GW`の倍精度版）。
- **`DREP01`**: 数字を先頭から1つずつ`acc = acc*10 + d`で積み上げ、
  **1手ごとに倍精度へ丸め**、正味の指数`n`が正なら10を`n`回、負なら
  倍精度に丸めた0.1を`|n|`回、**1回ずつ掛けて1手ごとに倍精度へ丸める**。
  符号は最後に適用する（単精度で採用された`REP01`の倍精度版。ただし
  単精度`REP01`の定義〔仕様書第5.1.1節〕を確認するのではなく、依頼文
  で与えられたこの定義をそのまま使う）。

演算（倍精度どうしの演算・単精度から倍精度への変換が絡む場合の扱い）
と書式は3候補共通で、仕様書`docs/spec/l4-basic.md`（`ca77caf`）どおり
とする。

## 腕（候補の式・対照、いずれも別担当が並行で作成中の表から取る）

- **候補の式（D1〜Dn）**: `docs/notes/l4-s4k-candidates.tsv`の全行の
  `typed`列を、表に現れる順のまま腕D1〜Dn（nは行数）として使う。
- **対照（E1〜Em）**: `docs/notes/l4-s4k-controls.tsv`の全行の`typed`
  列を、同様に腕E1〜Em（mは行数）として使う。

**両表とも予測の列は読まない・触らない。** 腕の総数・具体的な式は、
両表がコミットされた時点で機械的に決まる（本ノートの時点では特定
しない）。

群（列`group`）は表そのものに書かれている想定であり、本ノートでは
値を書き写さない。両表とも関門G6の対象とする（測定開始前のコミット
に存在し、以後変更されていないこと。**候補表・対照表のどちらか一方
でも測定開始の時点で存在しない場合、測定は始めない**）。

## 条件・器具

`l4-s4j`（`d5becf3`）の「条件・器具」「本文を出さない取り扱い」
「関門」節をそのまま踏襲する。写しの時刻は全腕一律
`dump(k)=line_end(k)+300`とし、関門G8（後の写しにOk行が現れている
こと）を含めてG1〜G6・G8を適用する（G7は対になる予測表が無いため本
測定にも適用しない）。

```
line_end(k) = 700 + 8 * (その腕で打った文字数の累計、\n も1文字)
dump(k)     = line_end(k) + 300
run(k)      = dump(k) + 200
```

- 分類器は`5735eb3`の`tools/l4_s4a_float_classify.py`を使う
  （`l4-s4a`〜`l4-s4j`と同じ、二重実装しない）。
- 出力が`0`の腕も、他の腕と同じ規則で通常どおり照合する（`l4-s4i`・
  `l4-s4j`と同じ扱い）。
- **倍精度の長い定数は写しが遅れがちである**（`l4-s4d`の教訓、
  `e80a55b`）。写しの時刻をすでに全腕一律`+300`フレームへ延長して
  いるが、それでも足りない腕が出うるため、**関門G8（後の写しに`Ok`
  行が現れていること）を必ず確認する**。G8が偽の腕は`gate_failed`
  とし、「写しが早すぎた」とだけ記述する（値は出さない）。

## 記録する内容

`l4-s4a`〜`l4-s4j`本体の記録規則（腕ごとに、差分モードで得た「前が
空白だったセル」の(相対の行, 相対の桁, 文字コード)の並びと、原点セル
の絶対位置(row0, col0)を記録する）に加え、`l4-s4j`で新設した規則を
踏襲する。

- **`numeric_output`に分類された全腕の出力文字列を、結果ノートの表に
  必ず載せる。**（`l4-s4i`で対照が食い違ったときに出力文字列が本体の
  記録に残っておらず、補遺での測り直しが必要になった教訓、
  `l4-s4j`で導入した扱いをそのまま引き継ぐ）。この記録は「本文を出さ
  ない取り扱い」節の許容範囲内（自分で打った式の直接の計算結果）
  である。`non_numeric_output`の腕は従来どおり件数と位置の範囲だけを
  記録する。

## 本文を出さない取り扱い

`l4-s4a`〜`l4-s4j`と同一。出力行の全セルの文字コードが「数字0-9・`.`・
`+`・`-`・`E`・`D`・空白」の集合に入る腕だけコードを記録し、1セルでも
集合外があれば件数と位置の範囲だけを記録する。分類器
（`tools/l4_s4a_float_classify.py`）は集合外のコードを標準出力・標準
エラーへ出さない設計であることが`5735eb3`の時点で確認済み。

## 関門

`l4-s4j`のG1〜G6・G8と同一。

- G1 器具の自己検査（本体と同一の自己検査群）
- G2 取りこぼし0・打てない文字の警告0
- G3 決定論性: 各腕2走とも写し・記録のsha256が一致
- G4 陰性対照: 何も打たない走で差分0件
- G5 陽性対照: `print 7717\n`腕で`7717`の並びを確認
- G6 候補表・対照表の固定: `docs/notes/l4-s4k-candidates.tsv`と
  `docs/notes/l4-s4k-controls.tsv`の両方が、測定開始より前のコミット
  に存在し、以後変更されていないことを`git log`で確認する。どちらか
  一方でも測定開始の時点で存在しない場合、測定は始めない
- G8 出力完了の確認: 「後」の写しで、出力行の後に`Ok`行が現れている
  こと（`ok_relative_row`相当の値が得られること）。**倍精度の長い
  定数は写しが遅れがちであるため、この確認を省略しない**。現れない
  腕は`gate_failed`とし、「写しが早すぎた」とだけ記述する

## 判定

判定名は`l4-s4c`〜`l4-s4j`と同じものを使う。「記録する内容」節を参照
する。

- 腕ごとの分類: `numeric_output`/`non_numeric_output`/`gate_failed`
  （`l4-s4a`〜`l4-s4j`と同じ）。
- 候補ごとの判定: 各候補（`DEXACT`・`DGW`・`DREP01`）について、
  **候補の式（D1〜Dn）と対照（E1〜Em）を合わせた全腕**で、予測文字列
  を出力行の相対桁0から置いたときの非空白セル(相対桁, コード)の並びが
  実測と完全一致すれば`candidate_consistent`、1腕でも一致しなければ
  `candidate_rejected`。`gate_failed`の腕がある場合、その候補は判定
  不能とし`other`とする（理由を記述）。対照は候補の判定に含める
  （対照が食い違えば候補も`candidate_rejected`になりうる）。
- 型のまとめ: `DEXACT`・`DGW`・`DREP01`の3候補のうち
  `candidate_consistent`だった個数で決める。
  - **`unique_survivor`**: ちょうど1つ
  - **`multiple_survivors`**: 2つ以上
  - **`no_survivor`**: 0（3候補とも`candidate_rejected`）
  - `no_survivor`の場合も、`l4-s4c`〜`l4-s4j`と同じく**候補を後から
    足して判定し直すことはしない**。次の事前登録に回す。
- **対照が1つでも食い違った場合の扱い（`l4-s4i`・`l4-s4j`と同じ規則）**:
  対照（E1〜Em）のうち1腕でも実測が予測と食い違った場合、**候補の式
  （D1〜Dn）の結果を定数の読み取り方式を決める根拠には使わない**。
  この場合、型のまとめは算出せず**`other`**とし、「対照が食い違った
  ため判定を保留」と記述する。候補ごとの`candidate_consistent`/
  `candidate_rejected`自体は通常どおり記録する。
- **群ごとの一致数（記述のみ、`l4-s4j`を踏襲）**: 判定そのものは全体
  （候補の式＋対照を合わせた集合）で1つに決めるが、表の`group`列
  ごとに、候補ごとの一致した腕数を結果ノートに記述する。**加えて、
  `l4-s4j`で表の群と実際の演算経路（正味の指数の符号）がずれていた
  教訓を踏まえ、正味の指数`n`の符号（`n>0`／`n<0`／`n=0`）でも同様に
  一致数を数え、結果ノートに記述する**（表の`group`列だけに頼らず、
  実際の指数の符号という独立した軸でも診断できるようにする）。いず
  れも型のまとめの判定名には影響しない。

## 器具の確認（公式ROMは使わない）

本ノートの作成時点（測定時HEAD`c2e8a3a`）で、`docs/notes/
l4-s4k-candidates.tsv`・`docs/notes/l4-s4k-controls.tsv`のいずれも
まだコミットされていない。そのため、本ノートでは候補・対照いずれの
腕についてもエコー確認を行っていない。**器具の確認（自作ROMでの
エコー確認）は、両表がコミットされた後、測定の担当が行う。**

## 判定後の行き先

- `unique_survivor`なら、その候補（`DEXACT`・`DGW`・`DREP01`のいずれ
  か）を倍精度の定数読み取り（`FIN`）の方式として確定する（仕様書へ
  の反映は本ノートの担当範囲外とする）。単精度で採用された`REP01`と
  同種の方式（`DREP01`）が生き残れば、単精度・倍精度で一貫した読み
  取り方式として仕様書にまとめられる。
- `multiple_survivors`なら、生き残った候補どうしを区別できる式を次の
  事前登録で立てる。
- `no_survivor`なら、`DEXACT`・`DGW`・`DREP01`のいずれでもない読み
  取り方式を次の事前登録で検討する入力とする。
- 対照が1つでも食い違った場合は、上記のいずれにもならず、共通経路
  （倍精度どうしの演算・PRINT書式）の再検証を次の作業の入力とする
  （`l4-s4i`・`l4-s4j`と同じ扱い）。
