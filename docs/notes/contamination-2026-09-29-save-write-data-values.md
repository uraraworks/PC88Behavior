# 汚染の記録 — SAVE の書き込みデータ部を、割り当て表の位置 160 以降まで出力した（2回目）

記録日: 2026-09-29

## 1. 何が起きたか

自作 SAVE ,A（ブランチ wip/save-ascii-2）が「自作 main ＋公式 sub」（`tools/conform_save.sh hybrid`）の J-1 で
失敗する原因を調べるため、メインセッション（Claude Opus 5.5、2026-09-29 夜のセッション）が、比較用に
**公式ROM一式**で J-1 と同じ打鍵の `SAVE` を入出力ログ付きで走らせ（リポジトリ外の診断、事前登録なし）、
main→sub の受信列（`sub IN $FC`）を要約して標準出力へ出した。

要約器は「main の送信は自作 main の値なので出してよい」という前提で作ってあり、公式一式の走らせ方に
そのまま流用した。その結果、SAVE の WRITE のデータ部（256バイト）の値まで出力され、割り当て表
(18,1,14) の書き込みの**位置 160 以降に ROM が書いた値**（命令列または作業域の中身のように見える
約 100 バイト）が、3回ぶん表示された。2026-09-25 の記録
（`contamination-2026-09-25-fat-buffer-overrun-values.md`）と同じ箇所・同じ種類の値である。

## 2. 見た範囲

- 公式一式の J-1 相当の走の、割り当て表 (18,1,14) への WRITE のデータ部。位置 160 以降の値。
- 表示はこのセッションの標準出力だけである。**リポジトリ・ノート・コミットメッセージには値を転記していない。**
- 同じ内容を含む入出力ログと要約・測定後の像は、気づいた直後にメインセッションが削除した
  （`PC88/tmp/save-work/dbg2/` の io.log・要約・drive2.d88、および診断用に複製した公式ROM・公式ディスク）。

## 3. 措置

1. **値はどの文書にも書かない。**
2. **このセッションを実装から外す。** 何のバイト列かは特定していない（特定しようとすると中身へ近づくため）ので、
   範囲を絞れない。以後の SAVE・読み要求まわりの `src/` の実装は、このセッションの文脈を持たない別の担当
   （Codex 等の新しいセッション）に渡す。このセッションは測定の設計・事前登録・記録までに留める。
3. 公式一式の入出力ログを要約するときは、**WRITE（FDC `0x45`）の直前に受信する列を制御部と
   データ部に分け、データ部は件数だけを出す**。「自作 main の送信だから安全」という前提は、
   公式一式に流用した時点で崩れる。

## 4. 教訓

2026-09-25 の教訓（「出力する値は、意味が分かっている欄に限る」）を持っていたのに、**道具の前提
（誰の出力か）が、道具を別の条件に流用したときに引き継がれなかった**。安全の判断は値の出所ごとに
行うもので、道具ごとに一度だけ行うものではない。
