# m7dx: 自作ファイル本数ラダー後半実測

実施日: 2026-08-28

本稿は`m7dv`の事前登録と`m7dw`のN=0〜8実測を引き継ぎ、保存済みN=8アンカーから
N=9以降を探索する結果ノートである。公式ROM・公式ディスクの内容、データポート値列は
表示・転記せず、生ログ、媒体複製、チェックポイント、manifestは全てリポジトリ外へ置く。
`src/`は変更しない。

## 測定前補遺: 後続ブロックの適用範囲確認

`m7dw`で、`m7dv`記載のBASIC側`CHR$`式は登録済み自作名を生成できないことが測定前に
判明した。N=1〜8ではホスト側で同じ規則から生成した8名のリテラルOPENへ表記訂正した。
後続ブロックでも同じ問題を避け、かつ512打鍵上限を守るため、**N=9の測定前に**次を固定する。

- 各8本ブロック末端K=16,24,...,64で、そのブロックに新規追加したK-7〜Kの8名を
  名前規則どおりホスト側で生成し、作成順に各1行のリテラルINPUT OPEN/CLOSEで検証する。
  8名全てを開いたときだけ固有末端マーカーと直後`Ok`へ到達する。
- 直前アンカーまでの全名は、過去ブロックの受理済み検証と媒体SHA-256で保持する。
  新規8名の検証を加える帰納形なので、当該ブロックまでの全追加名が存在するという
  適用範囲は`m7dv`から狭めない。
- 前半で介入成立の独立確認に使った固定`FILES`を**各Nで公式2run**実行し、画面本文を
  出力せず、行数・文字数・SHA-256のいずれかがN-1から変化すること、同一Nの2run一致、
  READ非0、WRITE 0、取りこぼし0件を必須とする。全指標がN-1と同じなら当該Nは
  介入不成立とし、差分系列へ入れない。
- 作成runのWRITE非0、固有マーカー、直後`Ok`、媒体SHA差異も従来どおり必須とする。
  作成エラー、WRITE 0、全名OPEN失敗、または`FILES`不変なら容量／作成上限候補として
  そのNで停止し、数値境界や「上限まで境界なし」へ読み替えない。
- 名前、作成順、空内容、9000フレーム、二段打鍵、公式各2run、到達条件、
  `Delta_N`とジャンプの判定規則、最初のジャンプで停止する規則は変更しない。

## 実測結果

### 進捗と停止点

- [x] 保存済みN=8アンカーの媒体SHA-256と受理状態をmanifestへ再照合。
- [x] N=9〜16を1本ずつ作成。全作成runで固有マーカー、直後`Ok`、WRITE DATA非0、
  取りこぼし0件、隣接媒体SHA-256差異を確認。
- [x] N=9〜16の各Nで`FILES`を公式2run。全Nで前段から画面成果物が変化し、同一Nの
  2run一致、READ非0、WRITE 0、取りこぼし0件を確認。
- [x] N=9〜16の新規8名を別プロセスで全てINPUT OPENし、末端マーカー`V016`と
  直後`Ok`、取りこぼし0件を確認。ブロックを受理。
- [x] N=9、10、11を公式各2run測定。全6runで到達、取りこぼし0件、決定論的一致を確認。
- [x] **N=11で最初の正方向ジャンプ候補を観測し、登録どおりそこで停止。**
- [ ] N=12〜64の測定。N=12〜16は準備・介入確認済みだが、停止規則により測定していない。

原本は変更せず、作成・`FILES`検証・測定の各runには保存アンカーからの新しい使い捨て
複製を渡した。チェックポイントN=9〜16、manifest、安全な集計、生ログはリポジトリ外の
既存`PC88_M7DV_WORK_DIR`へ保存した。

### 隣接差分と登録規則の適用

| N | `Delta_N` main `IN $FC` | `Delta_N` READ | 直前差分との判定 | FDC種別列 |
|---:|---:|---:|---|---|
| 9 | **0** | **0** | ゼロ差分（変化なし） | 同一 |
| 10 | **0** | **0** | ゼロ差分（変化なし） | 同一 |
| 11 | **+258** | **+1** | **正方向ジャンプ候補** | **構造的延長** |

Delta_9/10は、m7dtの非ゼロ一定費用とは異なるアクセス件数のゼロ差分である。
Delta_11は直前Delta_10=(0,0)に対し、両成分が以上で両方とも厳密に大きいため、登録規則
2をそのまま適用して**正方向の数値ジャンプ候補**とした。方向不一致や負方向変化ではない。
FDCコマンド種別列はN=10の28件をstrict prefixとして4件増え、READとSEEKが各1単位
増えた。未見の公開FDCコマンド名は無い。

`FILES`側もN=10の16 READからN=11の17 READへ同じ位置で増え、N=11の作成・画面署名
変化・全名OPENはいずれも成立した。従って介入不成立や容量上限による見かけのジャンプでは
ない。ただし`m7dv`が要求する独立再構築によるN=10/11の再現確認は、最初のジャンプで
停止する今回の指示に従いまだ行っていない。従って現時点では**確認済み境界ではなく候補**
と呼ぶ。内部のディレクトリ形式や、追加READがどの管理表を読んだかへは帰属しない。

### 完了範囲と未了範囲

- 本測定の完了範囲は**N=0〜11**である。今回追加した測定はN=9〜11、各2runである。
- N=12〜16は媒体作成、`FILES`各2run、ブロック末端全名OPENまで成立したが、ジャンプ後の
  停止規則により不存在OPEN測定は未実施である。
- **未了測定範囲はN=12〜64**である。未実施Nを実施済み、ゼロ差分、容量上限とは扱わない。
- 次の測定は、事前登録どおり直前8本アンカーからN=10/11を独立再構築し、同じ符号・
  件数差・構造分類が再現するかを確認する段階である。

## 情報境界

記録したのはN、件数、位置、SHA-256、画面の行数・文字数・SHA-256、自分で打鍵した
文字列・自作ファイル名、公開FDCコマンド名だけである。画面本文、公式媒体の既存名・内容、
公式応答値、データポート値列は表示・転記していない。`private/`は開かず、`cmp -l`等で
ファイル内容を出力していない。
