# m7ei: ドライブ2公式媒体ラダーの容量端点

実施日: 2026-09-01

本稿は`m7eh`で周期`P_O=16`・`V_O=(+258,+1)`が成立した系列A（`m7ed`の系列O）を、
次予測位置N=59の四点目を検査するためN=48から延長し、容量端点と後続周期の判定を記録する。
ドライブ1を公式システムディスク（起動用）、ドライブ2を公式diskAの使い捨て複製
（ラダー対象）とし、全ファイル名へ`2:`を前置して`FILES 2`を用いた。手順、名前、媒体、
判定規則、固定条件は変更していない。`src/`は変更していない。

## 測定中補遺: 延長に必要だった器材訂正

延長のため測定器を次の2点で訂正した。どちらも本測定より前にコミット済みであり、判定規則、
差分規則、到達条件、陽性・陰性の両対照は変更していない。

### `probe-create`への名前接頭辞適用

`probe-create`は名前接頭辞を適用せず、引数の名前を生のまま打鍵していた（コミット
`8455911`）。`build_block`、`rebuild-candidate`、`single-open`は`file_ref`を経由して
`PC88_LADDER_NAME_PREFIX`を前置していたが、`probe-create`だけがこの経路を通って
いなかった。このためドライブ2系列の容量端点を切り分ける対照が別ドライブを見てしまい、
使えなかった。

実打鍵行、`analyze_one`へ渡す期待文字列、記録する名前の三つに同じ参照名を使うよう訂正した。
接頭辞が空の系列（`m7ea`相当）では`file_ref`が素通しするため、挙動は不変である。
**この訂正が無ければ、ドライブ2条件での容量端点の切り分けは成立しなかった。**

### `m7ed-verify`の終端K入力範囲

`m7ed-verify`の入力検査はKを8の倍数に限定していた（コミット`586715b`）。しかし`m7ed`は、
終端が8の倍数の途中なら最後に作成成立したKへ同じ分割版と両対照を適用すると定めており、
この入力検査ではK=52を実行できなかった。入力範囲を`full-verify`と同じ1〜64へ広げた。
陽性対照、陰性対照、その実行順は変更していない。同型の器材訂正は`m7ea`に前例がある。

## 作成の結果

`tools/ladder_dirfiles.sh build 56`を実行した。N=49、50、51、52は作成成立し、各Nで
作成マーカー到達、WRITE非0、媒体SHA-256差、`FILES 2`各2run一致を満たした。
**N=53の作成runは不合格となり、そこで停止した。** スクリプトのrcは1だった。

N=53作成runは`accepted=false`、`screen_classification=error_display`、
`ok_after_error=true`、`write_count=0`、`reach=false`で、main/sub取りこぼしは0/0件だった。
未受理のN=53チェックポイント残骸は作業領域の`archive`へ退避し、系列へ採用していない。
受理済みチェックポイントはN=0〜52の53件である。

## 容量端点の切り分け

`probe-create`で6本の対照を取り、全て事前登録の期待分類と一致した。名前は全て`2:`を
前置して打鍵した。次表の名前欄は接頭辞を除いた自作名である。

| 対照 | 基準N | 名前 | フレーム | 期待 | 分類 | Ok直後 | WRITE | 媒体差 | 取りこぼし |
|---|---:|---|---:|---|---|---|---:|---|---|
| 陽性（N=51→52作成） | 51 | `QDBZ` | 9000 | success | normal_success | False | 7 | あり | 0/0 |
| N=53 同名1回目 | 52 | `QDCA` | 9000 | failure | error_display | True | 0 | なし | 0/0 |
| N=53 同名2回目 | 52 | `QDCA` | 9000 | failure | error_display | True | 0 | なし | 0/0 |
| N=53 同名3回目 | 52 | `QDCA` | 9000 | failure | error_display | True | 0 | なし | 0/0 |
| N=53 系列外の別名 | 52 | `QDZZ` | 9000 | failure | error_display | True | 0 | なし | 0/0 |
| N=53 同名・長フレーム | 52 | `QDCA` | 30000 | failure | error_display | True | 0 | なし | 0/0 |

この6本から言えるのは、N=53の不成立が単発の揺らぎではないこと（同名3回とも同分類）、
名前固有ではないこと（系列外の別名でも同分類）、フレーム不足による未到達ではないこと
（30000フレームでも同分類）、直前段の作成能力が失われたわけではないこと
（N=51→N=52は同条件で成立）までである。

## 終端K=52の全名OPEN検証

`tools/ladder_dirfiles.sh m7ed-verify 52`を実行し、次の順で全て成立した。

- 陽性対照は、受理済みK=8チェックポイントの全名OPEN検証に合格した。
- 陰性対照は、K=8の使い捨て複製から`QDAA`をKILLし、WRITE非0と媒体SHA-256差を
  先に確認したうえで、同じ全名OPEN検証が実際に不合格となった。
- 対象は、修正版全名OPEN検証がK=52（N=1〜52、省略なし、最大8名ずつの分割）で
  合格した。

## 容量端点と周期性の判定

1. `m7ed`は、N<128で作成が容量／作成上限エラーとなった場合、最後に成立したNを当該系列の
   容量端点として打ち切ると定める。受理済み終端はN=52であり、N=53の作成不成立は上記
   6対照で再現した。従って、**N=52をこの媒体・この手順での容量端点と確定する。**
2. `m7eh`で成立した周期の次予測位置は`43+16=59`だが、容量端点がその手前にあるため
   到達できなかった。`m7ed`の周期性の固定判定規則は、予測位置より前の容量端点による
   打ち切りを周期破れでなく後続周期の検査不能と定める。従って**四点目は検査不能**であり、
   `m7eh`で確定した`P_O=16`・`V_O=(+258,+1)`は撤回しない。N=44〜52のゼロ差分を
   「周期が消えた」「周期なし」へ読み替えない。
3. `m7eh`で成立した媒体間比較（H-M支持）も撤回しない。今回はNの範囲を延ばしただけで、
   確認済みジャンプの位置、間隔、増分は変わっていない。

## `m7ea`との比較

`m7ea`はドライブ1、接頭辞なし、同じ公式diskA複製という条件で、受理済み終端N=52、
N=53作成不成立、予測位置N=59へ未到達という同じ結果を得た。今回はドライブ2、`2:`接頭辞
という条件で、**端点の位置が同じN=52／N=53だった。**

これは観測事実として記録する。ただし、同じ位置になったことから原因が同じであること、
ドライブ番号と接頭辞が無影響であること、媒体の総容量やディレクトリ容量を逆算できることは、
いずれも導かない。媒体が同じ公式diskA複製である条件下で端点位置が一致した、という以上の
ことを言わない。

## 言えること／言えないこと

言えるのは、固定した起動媒体、ドライブ2の公式媒体複製、`2:`接頭辞、固定した名前と作成順、
QUASI88という条件でN=49〜52の作成と測定が成立し、N=53の作成不成立が6対照で再現して、
この媒体・この手順の容量端点がN=52となったことまでである。

N=53の作成不成立の内部原因は決まらない。データポートの値列を見ていないため、どの判定で
どう失敗したかを決めない。端点N=52から媒体の総容量、ディレクトリ領域の大きさ、エントリ長、
セクタ長、クラスタ数、既存項目数、バイト数、アドレスのいずれも逆算しない。
`error_display`は画面の形の分類であり、エラーの種別や番号を読んだものではない。
実機一般性も決まらない。

## 情報境界

記録したのはN、件数、差分、位置、SHA-256、公開FDCコマンド名、画面の行数・文字数・
SHA-256、自分で打鍵した文字列・自作名だけである。画面本文、公式媒体の既存名・内容、
公式応答値、データポート値列は転記していない。`private/`は開かず、規定パスを測定器へ
渡しただけである。

生ログ、媒体複製、チェックポイント、manifestはリポジトリ外の永続作業領域に置き、
コミットしない。作業領域は`PC88_M7ED_WORK_DIR`で指定し、その絶対パスは記録しない。
