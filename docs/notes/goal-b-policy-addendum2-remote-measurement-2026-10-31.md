# ゴール B 方針 追補2 — 公式 ROM と G1 をリモートの実行環境でも使う

記録日: 2026-10-31
位置づけ: [goal-b-policy-2026-10-24.md](goal-b-policy-2026-10-24.md) の後続。方針ノート本体は書き換えない。
このノートより前に、公式 ROM・公式ディスク・ゲームのディスクをクラウドへ置いた記録はない。

---

## 1. 経緯と決定

理由は手元の Mac の負荷である。2026-10-31 に利用者と次のとおり決めた。

- 自作 ROM だけの自己検査と照合は GitHub Actions で回す
- 公式 ROM とゲームのディスクは、**利用者本人だけが参加する非公開プロジェクトのライブラリ**に置き、
  そこからリモートの実行環境へ取得して測定する

`.github/workflows/selftests.yml` の「公式 ROM・公式ディスクはクラウドへ一切出さない」は、
**公開リポジトリの Actions についての規則としてそのまま残す**。Actions のログと成果物は公開され得るので、
私物を使う測定は Actions では行わない。

## 2. 変えないこと

[CLAUDE.md](../../CLAUDE.md) の禁止事項と、[方針ノート](goal-b-policy-2026-10-24.md)第4節の「記録しないもの」は
置き場が変わっても同じである。

- 公式 ROM・ゲームのディスクのバイト列を読まない、出力しない、リポジトリへ持ち出さない
- 生の出力は開かず、濾過後の記録だけを読む。リモートでもコマンドの出力は会話の記録に残る
- 画面本文は署名ツールの真偽でだけ語る
- ゲームは識別子で呼ぶ

## 3. 置き方と取り出し方

- ライブラリでの名前は中立にする（`G1-1.d88`、ROM は器具が要求するファイル名）。元のファイル名は使わない
- 中身を会話に流す読み方をしない。`/mnt/project-files/` からファイルとして複製し、ハッシュだけを照合する
- 照合用の SHA-256 の一覧はライブラリに一緒に置き、リポジトリへは書かない。これが検出するのは取得の破損であって、改ざんではない
- 実行環境の作業場は使い捨てとし、私物と生ログをコミット対象の木に入れない
- 公式の実走の前に必ず `git status` で混入がないことを確かめる

ダミーファイルでは、Mac とリモートの両方でハッシュの一致と、中身が会話に載らないことを確かめた（2026-10-31）。
ただし実物での確認はこのノートの時点でまだしていない。

## 4. 器材の差

Linux 版のコアは手元の macOS 版と別の器材である。
リモートで公式の結果を採用する前に、次の対照を通す。

- G1 の公式 1 走の濾過後の記録が、`measurements/b1-g1-demand-official-1.txt` とバイト単位で一致すること
- 一致しなければ、差の件数だけを記録し、原因が分かるまでリモートの公式の走を測定の根拠にしない

## 5. Mac に残るもの

- 私物の元ファイルの管理と、ライブラリへの登録
- リモートの対照が通らなかった場合の公式の走
- WebQ88 の実機ブラウザでの最終確認

## 6. 戻し方

利用者がライブラリからファイルを削除すれば、以後の実行環境には届かなくなる。すでに終わった実行環境の複製は
環境の回収で消える。問題が見つかったら測定を Mac に戻し、このノートの後続に経緯を書く。
