# m7gl: WRITE経路にドライブ軸を通す — 事前登録

## 位置づけ

[m7gi](m7gi-remaining-callers-stage12-results.md)は、`_recv_dispatch_write_sector`
（WRITE経路）に到達したが、条件Wが単一ディスク構成（B:を使わない）だったため、
B:の内容を変える条件軸を適用できなかった、と記録した。[m7gk](m7gk-save-drive-syntax.md)
は、`SAVE"<ドライブ番号>:<ファイル名>"`という打鍵構文を言語リファレンス
（(a)言語仕様の範囲）から特定したが、実測での裏取りは行っていない。

本稿は、その打鍵構文が実際に書き込み先ドライブを切り替えるかを測定で確認した
うえで（段階A）、確認できた場合に限り`recv_dispatch_write_sector`へB:の条件軸を
使った探針（`cyl`/`clear`/`set`）を当てる（段階B）、という2段階の事前登録である。
測定は本稿コミット後に開始する。

## 段階A: 打鍵が効いているかを、探針と独立に確かめる

[m7gi](m7gi-remaining-callers-stage12-results.md)の訂正節が指摘したとおり、
「探針を当てて差が出た」を無条件に条件軸が効いた証拠と読むと誤る。今回は
探針を当てる前に、**探針なしのベースラインだけで**、打鍵`SAVE"1:<名前>"`
（A:へ保存）と`SAVE"2:<名前>"`（B:へ保存）が異なる結果を生むかを見る。

### 測定条件

- ROM: 公式main一式 + 自作サブROM（`build_mixed_rom`、probe引数なし＝
  探針なしのベースライン）。
- ディスク: A:に`private/disk/N88_FE.D88`相当（`m7gi`条件Wと同じ起動用
  ディスク）の使い捨て複製、ライトプロテクトを外す（D88ヘッダoffset26を
  `\x00`にする、`m7az`/`m7gi`条件Wと同じ手順）。B:には**同じ複製ディスク
  をもう1本複製したもの**（`m7gb`のwrite_protectシナリオが使うA:と同内容の
  使い捨て複製、というタスク指示どおり）を入れ、ライトプロテクトを外す。
  `--disk`にはA:/B:2行のm3uファイルを渡す（`conform_l3.sh`のdrive1/drive2
  シナリオと同じ形）。
- 打鍵: `--type-at 300 --type '\n' --type-at 700 --type '10 PRINT
  "T"\nSAVE"1:TQ"\n'`（A:条件）と、同様に`SAVE"2:TQ"`（B:条件）。
  `--frames 4200`（`m7gi`条件Wと同じ）。

### 判定に使う器材（既存、新規実装なし）

- `tools/hash_write_stream.py`（WRITE系コマンドの件数・総バイト数・SHA-256）
- `tools/compare_l3_entry_fdc.py --after-frame 700`（FDCコマンド種別列・
  ポート値列の一致prefix、およびunit/head分類——`recv_dispatch_write_sector`
  へ到達した区間がA側かB側かを、値を出さずに分類する）
- `tools/check_l3_screen_output.py --compare-report`（画面出力比較）

### 判定

1. **A:条件・B:条件それぞれのベースラインを2run測り、自己一致することを
   先に確認する。**（判定規則自体が偽陽性を作らないことの確認。
   `m7gi`・`m7gj`と同じ作法）
2. A:条件run と B:条件run を比較する。
   - **異なる**（WRITE系コマンド件数/バイト数/SHA-256のいずれか、または
     FDCコマンド種別列・ポート値列に差がある）⇒ ドライブ指定の打鍵が
     WRITE経路で何かを変えている。**段階Bへ進む。**
   - **完全に同一** ⇒ `m7gk`の構文仮説が外れている（構文が効いていない）。
     **段階Bへ進まない。** 「構文が効かなかった」と記録して終える。
3. あわせて、`compare_l3_entry_fdc.py`のunit/head分類（値ではなく
   `A`/`unit2`等の分類名）を両条件で記録する。A:条件がA側、B:条件がB側に
   分類されれば、1.46節のドライブ指定伝播がWRITE経路でも働いている観測に
   なる。**この記録は段階Aの合否とは独立に行う**（合否はコマンド列・
   バイト列・画面出力の一致/不一致で決める。unit/head分類は付随情報）。
4. `SAVE`がB:候補側でエラーになった場合（書き込み可能・N88形式でない場合
   にありうる）も、「エラーになった」ことをそのまま記録する。今回は
   B:にA:と同内容の使い捨て複製（既知の書き込み可能・N88形式）を使うため、
   エラーは想定していないが、出た場合は打ち切らず記録する。

## 段階B: 探針を当てる（段階Aが通った場合のみ）

`recv_dispatch_write_sector`に対し、`--probe-site recv_dispatch_write_sector
--probe-mode {cyl|clear|set}`（コミット`24d7e62`で実装済み、`src/`は変更
しない）を使う。

- 打鍵は段階Aで差が出たほう（B:へ保存する`SAVE"2:TQ"`）に固定する。
- A:は起動用ディスクの使い捨て複製（固定）。B:には`m7gg`が確保した独立7本
  （`disk#1`・`#2`・`#4`・`#5`・`#7`・`#9`・`#10`）のうち、ライトプロテクト
  を外した使い捨て複製を入れて`SAVE"2:TQ"`が通る（＝書き込み可能な形式で
  ある）ものを条件軸として使う。`SAVE`が通らない候補は「使えなかった」と
  記録し、無理に7本を揃えない。
- 各B:候補について:
  1. **`cyl`**（到達検査）を、探針なしベースライン（同じB:候補）と比較する。
     差が出なければ、その候補では段階Bの残り（`clear`/`set`）を解釈しない。
  2. **`clear`**と**`set`**の両方を、同じベースラインと比較する。
     - `clear`が相違 ⇒ その条件でbit0は1（自然状態で立っている）
     - `set`が相違 ⇒ bit0は末端に効く（強制しても壊れない/変わる、の
       いずれであれ末端へ届いている）
     - 両方を測ることで、`m7gi`が残したP1（実際に効く/壊れる）とP4
       （強制しても壊れない）の区別を、この箇所についてだけは付ける。

## 事前登録する合格条件（測定前に固定。後から動かさない）

判定に数値比較を使わない。

1. 判定規則を先に各条件のベースライン2run同士へ当て、「差なし」と出ることを
   確認する（段階A・段階Bとも）。
2. 段階Aが通らなければ段階Bを解釈しない。
3. `cyl`が差を出さなければ、その候補の`clear`/`set`を解釈しない。
4. ROMの取り違え防止: `build_mixed_rom`が出す混成ROMディレクトリ内の
   サブROMのSHA-256が、全runで毎回ビルド直後の期待SHAと一致すること。
5. 決定論性: 差が出た条件は2run測って自己一致を確認する。1runにとどめた
   条件は結果ノートに明記する。
6. 元ディスクイメージ（`private/disk`配下の複製元）のハッシュが、測定前後
   で不変であること。全測定の最後に確認する。
7. 成果物（本稿・結果ノート・コミットメッセージ）に実ファイル名を含めない
   （通し番号disk#Nとダイジェストのみで呼ぶ）。

## 事前登録する予測（測定前に書く。どれになるかは決め打たない）

- **W0**: 段階Aで`SAVE"1:.."`と`SAVE"2:.."`が同一 ⇒ 構文が効いていない。
  `m7gk`の仮説は実測では裏が取れなかった。
- **W1**: 段階Aで差が出て段階Bへ進み、`cyl`到達・`set`が差を出す ⇒
  WRITE経路でもbit0は末端に効く。
- **W2**: 段階Bで到達するが`clear`/`set`とも差を出さない ⇒ この箇所では
  bit0を強制してもWRITE経路の末端は変わらない。
- **W3**: 段階Bで`cyl`が差を出さない ⇒ この条件ではWRITE経路の当該注入位置
  に（この打鍵・このB:候補では）到達していない。

## ディスクを壊さないこと

すべての複製は`/private/tmp/claude-501/.../scratchpad`配下（リポジトリ外）
に作る。`private/`配下のファイルへは書き込まない。複製元のハッシュは
全測定終了後に確認し、結果ノートに「不変だった」と記録する。

## 禁止（本稿にも適用）

- 結果が予測と合わなくても、上記の合格条件・判定規則を動かさない。
- 値（バイト値・データポート値・シリンダ値・画面本文）を書かない。
- リポジトリに存在しないファイル名を引かない。実ファイル名は書かない。
