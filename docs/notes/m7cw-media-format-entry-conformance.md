# m7cw: 媒体初期化需要入口の事前登録

実施日: 2026-08-27

本稿の到達条件は実測前に固定した。公式ROM・公式ディスクの内容は読まず、
生ログ、画面報告、ROM／ディスク複製はリポジトリ外の一時領域だけに置く。
書込みと初期化には、参照diskAから`mktemp -d`配下へ作るrunごとの使い捨て複製だけを用いる。

## 第1候補と到達手段の事前調査

第1候補は媒体初期化とし、公開μPD765の`FORMAT TRACK`（WRITE ID系）を踏む需要入口を
探す。公開N88-BASICリファレンスマニュアルの前付ページiii--xiv（PDFページ画像11--24）で
全命令索引を確認したが、`DSKI$`、`DSKO$`、`DSKF`は掲載される一方、FORMAT命令は
掲載されていなかった。このためBASICの直接命令である可能性は低く、公式ディスク上の
別プログラムまたは別の起動操作が必要かを、使い捨て複製の画面観測と自分で打鍵する候補だけで
校正する。画面本文やファイル名一覧はノートへ記録せず、候補の採否だけを残す。

q88measureは合計512打鍵が上限で、既存需要入口の上限は9000フレーム、1run 300秒である。
直接候補の打鍵はこの上限内に収まる。全面初期化しかない場合も40トラックの完了を9000フレーム
以内と見積もり、超過する候補は採用しない。1トラック単位の入口が分かった場合はそちらを優先する。

## 媒体初期化の到達条件・対照

校正では、まず使い捨て複製へ固有名の自作BASICファイルを保存し、別値を持つプログラムへ
破壊してから読み戻して、初期化前に自作ファイルが存在することを確認する。その同じ複製だけを
初期化候補へ渡す。初期化後は旧ファイルのLOADが失敗したことを自作エラーハンドラで確認し、
新しい固有名の自作ファイルを保存する。さらにメモリ上の自作値を別値へ破壊してから新ファイルを
LOADし、自作値が戻った場合だけ`F8R`、全操作の末端へ到達した場合だけ`F8E`を表示する。

媒体初期化の到達は、(1) 初期化前の旧自作ファイルを読み戻せた、(2) 公開μPD765の
`FORMAT TRACK`が1件以上発行された、(3) 初期化後に旧自作ファイルが消失した、
(4) 初期化後の媒体へ新自作ファイルを書き、メモリを別値へ破壊した後のLOADで`F8R`、
末端で`F8E`が順に出た、の全条件とする。`Ok`だけは到達条件にしない。

陽性対照はFORMAT発行と`F8R`、`F8E`を持つ合成画面、陰性対照はFORMAT 0件、旧ファイルが
残る形、新ファイルの読戻しが不一致で`F8R`を欠く形、末端の`F8E`を欠く形とする。
従って構文受理、初期化要求、旧ファイル消失、新規書込みのいずれか単独では合格しない。

## 不採用条件と切替先

BASIC直命令が構文不受理、公式ディスク上の到達可能な初期化プログラムを確認できない、
全面初期化が9000フレームまたは300秒を超える、512打鍵を超える、あるいは上記の効果条件を
満たさない場合、その試行の署名は期待値へ採用しない。不採用理由だけを本稿へ残し、未測の
「削除済みファイルのLOAD」エラー入口へ切り替える。

切替時は使い捨て複製上で固有名の自作プログラムをSAVEし、そのプログラム自身をRUNする。
プログラムは`ON ERROR GOTO`を設定してから自分のファイルをKILLし、同じ名前をLOADする。
KILLを通過後、LOAD行でだけエラーハンドラへ入り、エラー発生行が自作LOAD行と一致した場合だけ
`M8E`、それ以外は`M8N`を表示する。到達は、対象のSAVE・RUN・KILL・LOADの打鍵反映、
FDCのコマンド種別列、`M8E`と末端復帰を全て必須とし、`Ok`だけを条件にしない。

この切替入口の陽性対照は自作LOAD行と`M8E`を持つ短いエラー画面形、陰性対照はLOAD不実行、
KILL不成立、別行のエラー、`M8E`欠落、または`M8N`出現とする。事前に存在させた自作ファイルを
同一runで削除してから読むため、原本のディレクトリ内容には依存しない。

## 観測指標と固定手順

採用入口について公式一式／混成を各2回実走し、FDCコマンド種別列、main `IN $FC` / `IN $FD`
の件数とSHA-256、画面の行数・文字数・SHA-256を測る。同一モード2回の全イベント列と画面の
決定論性、および公式／混成の全長一致を確認する。最初の公式到達runで署名を出し、期待値を
固定してから4runを判定し直す。

期待値は専用TSVへ置く。判定器は表示ラベルを一時パスへ使わず`mktemp`を使い、SHA-256破壊、
件数破壊、期待値0行を全て不一致とする。合成画面の陽性対照と各マーカー欠落を区別し、
故障注入の空振り0件を必須とする。

ここまでを実測前の事前登録とする。

## 情報境界

記録するのは件数、SHA-256、画面の行数・文字数・SHA-256、自分で打鍵した文字列、
参照した公開マニュアルのページ番号、および公開されたμPD765のコマンド名だけとする。
画面本文、ディスクのデータ部、公式ROM／公式ディスクの応答値やバイト列は記録しない。

## 媒体初期化候補の校正と不採用

使い捨て複製に対し、BASIC直接候補として自分で`FORMAT`、`FORMAT 1`、
`FORMAT "A:"`を各1回打鍵した。各runは9000フレーム・300秒・512打鍵の上限内で
rc=0まで走ったが、3候補とも構文不受理であり、`FORMAT TRACK`発行は各0件だった。
従って旧自作ファイル消失、新規SAVE／LOAD、`F8R`、`F8E`の効果条件へ進む入口ではない。
公式ディスク上のプログラム候補は、公開命令索引から呼出手段を特定できなかった。
BASIC直接候補の構文不受理だけで事前登録の切替条件を満たしたため、媒体内容や一覧を
探索して名前を推測することはせず、3試行の署名も期待値へ採らなかった。

以上により媒体初期化は不採用とし、事前登録済みの「削除済みファイルのLOAD」へ
切り替えた。上限超過による不採用ではなく、構文不受理による不採用である。

## 削除済みファイルのLOAD入口

使い捨て複製へ、自作行`10 ON ERROR GOTO 100`、`20 KILL"Q8M"`、
`30 LOAD"Q8M"`と自作エラーハンドラを持つプログラムを`SAVE"Q8M"`して`RUN`した。
KILL行での失敗は別行扱いとなって`M8N`へ進む。LOAD行だけでエラーになり、`ERL=30`の
場合だけ`M8E`を出して、末端行の`M8X`へ復帰する形である。画面判定はSAVE、RUN、KILL、
LOADの全打鍵反映と`M8E`、`M8X`を必須とし、`M8N`や途中の別行を許さない。
`Ok`は到達条件に採っていない。

公式一式／混成を各2回実走した。全4runで対象行だけのエラー捕捉と末端復帰を確認し、
I/Oログ取りこぼしは各0件だった。同一モード2回のmain/sub全イベント列と画面は
決定論的に一致した。公式／混成間もFDCコマンド種別列221件、main受信列、画面が
全長一致した。

FDCコマンド種別列は、`SENSE INTERRUPT STATUS` 58件、`SEEK` 53件、
`SENSE DRIVE STATUS` 53件、`READ DATA` 36件、`WRITE DATA` 15件、
`RECALIBRATE` 5件、`SPECIFY` 1件だった。main `IN $FD`は5635件・SHA-256
`e26b22e7eec0d20725b25a34c00bc968820e1c7434c21cc45e0fb61939315ab7`、
main `IN $FC`は10571件・SHA-256
`ad42427321c15e54e0c0292cff8b6ee628a39822f728da23a89404e57f26c5a5`だった。
画面は19行・316文字・SHA-256
`d77d0f8b40d3e0d27d5e68ad7f33f05c69098b1cfe4b8e862d178b0c74f918da`である。

判定器の故障コピーは表示ラベルをパスへ使わず`mktemp`で作った。SHA-256破壊、
件数破壊、期待値0行を3/3で不一致検出し、空振り0件だった。合成画面でも陽性形を
到達とし、SAVE、KILL、LOAD、RUN、`M8E`、`M8X`の各欠落と、別行エラーを示す
`M8N`への置換の7故障を全て未到達とした。

判定器実装中の行き止まりも残す。中断時の書きかけはKILL／LOADと両マーカーに加えて
`Ok`を必須としていたため、事前登録より強さの向きが違っていた。SAVE反映を追加し、
`Ok`依存を除いた。そこでSAVE、KILL、LOADをこの順に探す制約まで加えた初回全走は、
プログラム行のKILL／LOADを打鍵した後にSAVEコマンドを打つ実際の順序と逆だったため、
今回入口の公式runを4回とも画面未到達と誤判定しrc=1になった。各試行の取りこぼしは
0件だったが署名には採らない。全4要素必須を保ったまま相互順序だけを外し、単発校正後に
全入口を先頭から再実走してrc=0を得た。

公式／混成差は無く、`src/l3_service/make_subrom.py`の実装変更は不要だった。
