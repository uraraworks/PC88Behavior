# l4-s6b — 単精度SIN/COS/TAN(・ATN/EXP/LOG)の食い違いの規則探し — 事前登録

記録日: 2026-09-19
状態: **事前登録のみ。測定は未実施。**

## 重要な制約(測定実施前に明記する)

本ノートを書いたセッションには、公式ROMへのアクセス手段が無かった
(`PC88_REF_ROM_DIR`が未設定、かつ`.claude/settings.json`の
`Read(**/private/**)` deny規則により`private/`配下の閲覧そのものが
機構的に拒否される環境だった)。CLAUDE.md「パスの扱い」は「私物の
パスは環境変数経由でのみ受け取る」と定めており、本セッションは
そのパスを与えられなかったため、**公式ROMに対する測定(手順4)を
実施していない**。本ノートは手順1〜3(ソース再読・候補列挙・腕設計)
までを事前登録として固定し、測定(手順4)は`PC88_REF_ROM_DIR`を持つ
別セッションに引き継ぐ。

ソース再読・自己整合性チェックの結果は
[l4-s6b-source-reread-and-selfcheck.md](l4-s6b-source-reread-and-selfcheck.md)
参照。要点:

1. `tools/l4_mbf_oracle_v3.py`の範囲縮約・SIN/COS/TANはGW-BASICソース
   (MATH1.ASM 952-1143)と命令単位で再突合し、食い違いは見つからな
   かった。
2. ソースに「COSの範囲縮約は1982年6月に倍精度へ変更された」という
   変更履歴コメントがあり、N88がこの変更を反映していない可能性を
   仮説として立てられる。
3. TAN(.5)不一致は`tools/l4_mbf_oracle_v2.py`の除算実装のバグでは
   ないことを自己整合性チェックで確認した(sin(.5)/cos(.5)の予測値
   同士を割ると、v3のtan(.5)予測値とビット単位で一致する)。
4. 3の帰結として、**PRINTの6桁表示では候補モデル同士の下位ビット差を
   弁別できない場合がある**。腕は「候補間で6桁表示が実際に割れる」
   ものを選ぶ必要がある。

## 位置づけ

`l4-s6a`(`docs/notes/l4-s6a-transcendental-functions-results.md`)の
不一致11腕(S5,N4,N5,N6,N7,C4,T2,T4,A5,E5,L4)のうち、種類1(倍精度
引数が倍精度で返る、5腕)は既に原因が分かっている(予測器の想定誤り)。
残る種類2(N4,C4,T4,T2、末尾数ULP)・種類3(N6,N7、大きなずれ)の
6腕について、1つの規則で説明できる計算手順を候補として挙げ、次回の
測定で弁別する腕を設計する。

## 候補モデル

### M0: v3そのまま(現行実装、コード化済み)

`tools/l4_mbf_oracle_v3.py`をそのまま使う。範囲縮約は倍精度、
多項式評価は単精度、TANはSIN/COSの単精度除算。ソース再読で構造上の
不一致は見つからなかった(上記1)ので、**この候補が実機と食い違う
場合、原因はアルゴリズムの読み違いではなく、別の要因(M1〜M4)を疑う**。

### M1: COSが旧式(単精度寄り)の範囲縮約を使う(コード化せず、質的仮説)

ソースの変更履歴コメント(上記2)に基づく仮説。N88のCOS(・COSに依存する
TAN)だけが、1982年6月の修正前の、SINより精度の低い範囲縮約を使って
いる可能性。**具体的な旧アルゴリズムのバイト列は現存するMIT公開ソース
(コミット1個のみ)からは入手できない**ため、旧アルゴリズムそのものを
コード化した予測器は作らない(存在しない実装を推測で埋めることは
「候補の係数を測定値から当てはめない」の精神に反する)。

弁別は次の**符号**で行う: 同じ引数を持つ「SINだけの腕」と「COS・TAN
を含む腕」を対にして測る。M1が正しいなら、大きい引数でSINは一致し
続けCOS・TANだけ食い違う頻度が有意に高くなるはずである。M0(COSも
SINと同じ精度)ならSIN・COS・TANの食い違い率に差が出ないはずである。

### M2: TAN=SIN/COSをそれぞれ単精度に丸めてから割る

事前の想定はM0と別候補だったが、ソース再読の結果、**M0のTAN実装は
既にこの手順そのもの**(SIN・COSをそれぞれ単精度で計算してから
`$FDIVS`で割る)であることが分かった。よってM2はM0と同一候補になり、
独立候補としては扱わない(候補表から統合)。

### M3: 多項式評価を倍精度で行い、最後だけ単精度に丸める(コード化可能)

ASM上の`$POLYX`/`$POLY`は単精度の`$FMULS`/`$FADDS`を使うと明記されて
おり(M0はこれに忠実)、この候補はソースと矛盾する。しかし「実機の
ROMがソース(IBM PC版)と完全に同一とは限らない」という前提に立ち、
弁別のためだけの対抗候補として残す。実装: 範囲縮約後の倍精度の
reduced angle(`$CSD`を経ない)をそのまま倍精度係数(単精度係数を
そのまま倍精度へ拡張)でHorner評価し、最後に1回だけ単精度へ丸める。
次回セッションでコード化する(本ノートでは未実装、設計のみ)。

### M4: 多項式の次数・係数が異なる(候補として保持するのみ、当てはめ禁止)

事前登録どおり、測定値から係数を逆算することはしない。M0〜M3がすべて
外れた場合の「その他」の受け皿として保持するだけで、独自の予測は
出さない(不一致の分布を記述するにとどめる)。

## 腕の設計方針

上記「PRINTの6桁は弁別できない」問題を踏まえ、腕は以下の基準で選ぶ:

1. **M0とM3の予測が6桁表示で実際に異なる入力を優先する。** 判定時に
   M3をコード化し、M0との差が6桁目に出る入力を機械的に探索してから
   腕を確定する(測定前に候補ごとの予測表を作る=事前登録の要件を
   満たす)。
2. **SINだけの腕とCOS・TANを含む腕を、同じ引数(大きさ)で対にする。**
   M1(COS旧式仮説)を弁別するため。例: `SIN(50)`と`COS(50)`・
   `TAN(50)`、`SIN(200)`と`COS(200)`・`TAN(200)`のように、l4-s6aで
   使っていない引数も追加し、SIN側だけが一致し続けるかを見る。
3. **TAN(.5)近傍を追加密度で測る。** l4-s6aのT2(`TAN(.5)`)が
   「大きくない引数」で不一致だった原因不明のケースなので、
   `TAN(.3)`・`TAN(.7)`・`TAN(1.2)`等、象限内の別の点を足して
   「.5固有」か「象限内で広く起きる」かを弁別する。
4. **`N6`(`SIN(6.283185)`、ほぼ2π)近傍の密度を上げる。** `6.283185`
   ちょうどではなく、`6.28`・`6.29`・`6.2831853`(より2πに近い)
   ・`6.3`のように2πからの距離を振り、「ほぼゼロ近傍で相対誤差が
   拡大する」現象(種類3)が距離に対して連続的に悪化するか、
   特定の距離で急に悪化するかを見る。連続的なら「単純な相対誤差
   拡大」(M0のままで説明可、実装は近似的に許容)、不連続なら
   「$IN2PIの精度限界を超えた特定のビット」を示唆する。
5. **`N7`(`SIN(1000000)`)近傍も同様に、`100000`・`10000000`等、
   桁数を振って腕を追加する。** 引数の大きさに対して誤差がどう
   増えるか(線形か、ある桁数で急激か)を見る。

preregistration.md`)のG1〜G6・記録方法・「本文を出さない取り扱い」・
