# B37: スペース後の G1 で、サブの ROM 側が読む RAM の番地を値なしで測る — 事前登録

記録日: 2026-11-01
位置づけ: [B36](b36-g1-sub-port-values-results.md) の次段。**このノートは測定より先にコミットする。**

## 1. 問い

B30 の `IN $FC` の違い（257 件、最初は番号 76570、続けて 132 件）が出る区間で、サブの `0x2000` 未満のコードは RAM のどの番地をデータとして読むか。読む番地を最後に書いたのは誰か。公式と自作で番地か書き手が違うか。

B36 では、サブの RAM 上のコードへの入力は FDC 番号 95 まで同じだった。違いの出どころが ROM 側の応答かどうかの手がかりを、値を見ずに得る。

## 2. 器具

コアに `--sub-rom-read-log` と `--sub-rom-read-window FROM,TO` を足す（パッチ 0020）。既定は無効で、無効なら動作を変えない。

- 発行元の PC が `0x2000` 未満のデータ読み（命令の取得を除く）のうち、`0x4000` 以上の番地だけを数える。**ROM の領域を読むものは記録しない。**
- 窓は main の `IN $FC` の通し番号（0 始まり）で切る。今回は `76500,76766`
- 分類は B34 と同じ `unwritten`・`rom-written`・`ram-written`。書き込みの追跡は起動から窓の外でも続ける
- 順番を残し、同じ番地の連続と番地が 1 ずつ増える連続をまとめる
- **値は持たない。** 器具は値を受け取らない形にする

器具は G1 なしで自己検査する。陽性対照は 3 分類それぞれ、陰性対照は「命令の取得を数えない」「発行元が `0x2000` 以上の読みを数えない」「ROM 領域の読みを数えない」「窓の外を数えない」。

## 3. 条件

腕 F の 4800 フレーム。OO・SS 各 2 走。条件は B30 と同じで、クラウドの実行環境で行う。自作 ROM は ff113bf の配布ビルド。

関門: 同じ走の `--io-log` から出した `IN $FC` の差が B30 と同じ（257 件、最初 76570、連続 132）で、OO どうし・SS どうしの濾過後の記録が一致すること。外れたら差の件数だけを書き、解釈しない。

## 4. 記録の白リスト

- `# 識別子: G1`
- `W <main_fc> <開始>-<終了> <unwritten|rom-written|ram-written> <増える|同じ> <回数>`（番地は 4 桁 16 進）
- `dropped=<N> complete=<0|1>`

## 5. 判定（事前に決める）

- OO と SS の記録の最初の違いの行番号と、その行の番地の区間と分類を書く
- 差が無ければ「ROM 側の読みの番地と書き手は窓の中で同じ」と書く
- 差があっても原因は書かない。読み取った値には触れず、次に何を測るかは別のノートで決める
