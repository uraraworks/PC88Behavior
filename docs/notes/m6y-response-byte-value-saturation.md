# M6y — 単発応答バイトの値スキャンと258件での飽和

測定期間: 2026-08-12〜13

## 目的

`docs/notes/m6x-session-2026-08-12-summary.md`が「値の壁」と整理した
main側分岐点259について、直前の単発1バイト応答の値を変えれば構造的
一致プレフィックス258件を突破できる、という仮説を検証した。

## 実験設計

混成ROMの自作sub側だけを変更し、各候補について変更、ビルド、実測を
順に行った。比較は`tools/diag_l3_mixed.sh --brief`のスピン畳み込み後の
「構造的一致プレフィックス」と「最初の構造的分岐点」だけを用いた。
診断の値列・ダンプは読んでいない。

最初の定数実験には、送出値の差し替えと同時にFDCコマンド発行も消える
交絡があった。そこで本測定では、`FDC_SENSE_DRIVE_STATUS`を実発行する
構造を残し、その結果を得た直後に自作側の定数をロードして、mainへ送る
1バイトだけを上書きした。事前対照と最終復帰対照では、定数ロードを
除去してST3実測値をそのまま送り、いずれも258件・分岐点259を再現した。

補助対照として、応答源をPCN、保持したST0、MSR直読へ替えた場合も、
ST3と同じ258件・分岐点259だった。送出定数では、上位4ビットの立ち数が
0の群は102件、1〜3の全14組み合わせは258件、4の群は171件となった。
下位4ビットだけを1本立てた4候補は、いずれも102件だった。

## 結論と従来記録の訂正

試した定数の中に258件を超えるものは無く、上位4ビットの立ち数1〜3の
14組み合わせすべてが258件で飽和した。したがって、分岐点259は直前の
応答1バイトの値を選び直すだけでは突破できない。

`m6w`は、分岐直前の要求・応答構造が一致することから原因を応答値に
絞り、`m6x`はこれを「値の壁」と整理した。今回の介入実験はその読みを
反証した。両ノートは当時の推論と行き止まりを隠さず残し、本ノートで
訂正する。値の層は258件で飽和しており、259件目の原因は別にある。

次は、診断が報告する「構造一致・回数不一致」の回数差一覧14件を候補に、
分岐点より前の反復回数差が後続状態へ影響していないかを調べる。

## クリーンルーム上の注記

表に掲載した送出値は、すべて実験のため自作sub側へ明示的に設定した定数
である。公式ROM・公式ディスク・診断ログの値列から得た値は一切含まない。
一致件数と分岐点は値列を読まず、診断出力の該当行だけを抽出した結果である。
