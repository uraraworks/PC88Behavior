## 4. 判定

**総合判定 `m6f_a_directory_ambiguous`。**

| 導出 | 結果 | 候補数 |
|---|---|---:|
| D1 ディレクトリのセクタ | **derived** — (C=18, H=1, R=3) | 1 |
| D2 名前欄の位置 | not_found | 0 |
| D3 エントリ長 | not_found（D2 に依存） | 0 |
| D4 詰め物と欄の長さ | not_found（D2 に依存） | 0 |
| D5 削除の印 | not_found（D2 に依存） | 0 |
| D6 未使用エントリの表現 | not_found（D2 に依存） | 0 |
| D7 割り当て表 | not_found（理由: 古い値が境界で伏せられた） | 0 |

**D1 はちょうど1つに決まった。** F1・F2・F3 のすべてで変わり、F1 と F2 の新しい値の違いが
1バイトだけのセクタは (18, 1, 3) だけだった。

## 5. D2 が見つからなかった理由 — 事前登録の前提が1つ外れていた

D2 は F1 の新しい値の中に `QZ7A` の ASCII（`51 5A 37 41`）が連続して現れる位置を探した。
**D1 のセクタで変わったバイトの新しい値を見ると、名前は小文字の `qz7a`（`71 7A 37 61`）で
入っていた。** 大文字を探したので見つからず、D3〜D6 が連鎖して not_found になった。

打鍵に使ったハーネス（`tools/harness/frontend/main.c`）の注記は「英字は小文字の RETROK
コードを送れば大文字として入る」であり、**大文字で打ったつもりの名前がディスク上で小文字に
なっている。** 次のどちらかだが、**本測定では決まらない。**

- (i) ハーネスの注記が誤りで、打鍵は実際には小文字で届いていた
- (ii) ROM が名前を小文字へ変換して格納する

**同じデータで D2 を小文字探索へ書き換えて「導出」し直すことはしない。** 見えた答えに
規則を合わせることになるため。次稿 m6f-b で、名前の各バイトを `CHR$` で指定する刺激を
使って (i)(ii) を切り分け、導出規則を先に固定したうえで新しい走から取る。

## 6. D7 の前提も外れていた

追補1 は D7 を「F1 と F6 の両方で変わったセクタから D1 を除いたもの」とし、「F1 の
プログラム本体は F1 でしか変わらず、F6 のデータファイル本体は F6 でしか変わらないので、
本体は自然に除かれる」と書いた。**これは誤りだった。** 各腕は新しい使い捨て複製から始める
ので、F1 のプログラム本体と F6 のデータファイル本体は**同じ最初の空き位置から**割り当てられ、
その位置のセクタは両方で変わった。本体が除かれず、候補に混ざった。

さらに、両方で変わったセクタのうち3つ（(18,1,14)・(18,1,15)・(18,1,16)）は、**3つとも
まったく同じ件数ずつ**変わった（F1 で各91バイト、F6 で各120バイト）。これらの古い値は
**非一様として伏せられた**（既存ファイルの割り当て情報が入っているはずであり、境界が
意図どおりに働いた）。

## 7. 観測として記録すること（導出ではない）

以下は、**事前登録の導出規則を通っていない観測**である。境界の内側（変わったバイトの位置と
新しい値、セクタ単位で一様な古い値）で見えたことを記録する。**規則として採るのは m6f-b の
導出を通ってからにする。**

- ディレクトリのセクタ (18, 1, 3) の中で、1件の SAVE は**11バイトの連続区間**を変えた。
- 名前は区間の先頭から**9バイト**で、短い名前は **`0x20`（空白）で詰められる**
  （F1 の4文字名は4文字＋空白5、F3 の6文字名は6文字＋空白3）。
- 名前の後ろに2バイト続く。1バイト目は F1・F2・F3・F4 の全エントリで同じ値、
  2バイト目は F4 の2件で異なる値だった（割り当てに関わる値とみられるが、意味は決めない）。
- F4 の2件は、ディレクトリのセクタ内で**16バイト離れて**並んだ。
- F5（SAVE の後 KILL）では、そのエントリの**先頭1バイトだけが `0x00`** になり、残りは
  SAVE 直後のまま残った。
- D1 のセクタで変わったバイトの古い値はセクタ単位で一様に **`0xFF`**（追補2 の条件を満たし
  出力された）。

**公式ディスク固有の事柄は記録しない。** 何番目のエントリが空いていたか（既存ファイルの数）、
本体がどのセクタへ割り当てられたか（空きの状況）、割り当て番号の具体値は、仕様書がこれまで
「既存項目数を逆算しない」としてきたのに合わせ、ノートにも書かない。

## 8. 行き先

事前登録 §7 の `m6f_a_directory_ambiguous` の行き先（候補の分布を記録し、刺激を足す）に従い、
**別稿 m6f-b** を事前登録する。

1. 名前の各バイトを `CHR$` で与える刺激で、大文字・小文字の扱いを切り分ける。
2. D2〜D6 を、切り分けの結果ごとに**先に**固定した規則で導出する。
3. D7 は「両方で変わった」ではなく、**本体の中身で本体セクタを見分ける**規則に直す
   （データファイルの本体は自分が書いた `Z` で埋まっている）。
4. 割り当て表の空きの印は、古い値が伏せられるので差分からは読めない。空の公式形式ディスクを
   自作する段階で、**挙動から再構成する**（候補の値で作ったディスクを公式ROM が受け入れるか
   を測る。`docs/PLAN.md` 5節「規則が無いものは挙動から再構成する」）。

## 9. この測定で決まらないこと

- 名前の大文字・小文字の扱い（§5）。
- エントリ内の名前以外の欄の意味。
- 割り当て表の所在と空きの印（§6）。3セクタが同じ件数ずつ変わったことから複製を持つ
  ようにも見えるが、**そう結論しない**。
- プログラム本体の保存形式。
