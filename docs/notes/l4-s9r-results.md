## 予測の的中

判定項目 **71件中 70件が的中、1件が外れ**（`_group` の `port54_distinct`）。外れは予測の書き方の誤り: 「0x54 の**最後の値**が b=0〜7 で互いに異なる」と書いたが、
`color ,b` は 0x54 を**2回**書き、b の3ビットが2回の書き込みに分かれて入る（下の 3.）。最後の値は 192 と 199 の2通りしかない。

## 1. 0x80 と 0x81 の使い分け（確定）

**0x81 は「カーソルが出る状態」、0x80 は「カーソルを出さない状態」。窓の終わりの60フレームでは、どの腕も片方のコマンドだけが160回（毎フレーム）書かれた。**

| 状態（80桁） | コマンド | パラメータ（桁,行） |
|---|---|---|
| 起動直後の入力待ち（idle） | 0x81 | (0,6) |
| 文字を打っている最中（`print 12` を改行なしで） | 0x81 | (8,6)＝打った文字数の直後 |
| 直接モード実行の直後: `width 40`／`width 80`／`locate 10,5`／`cls`／`a=*3`（構文エラー）／プログラム終了（`10 print 1`） | 0x81 | 桁は全て 0（行は 1・1・7・1・9・4。Ok の次の行頭。`locate` の引数 (10,5) は反映されない） |
| `input` 待ち（`10 input a$`） | 0x81 | (2,2)＝`? ` の直後 |
| `input` 待ちで `ab` を打鍵中 | 0x81 | (4,2) |
| 実行中: `goto` の自己ループ・`for` の二重ループ・`a$=inkey$:goto` のループ | **0x80** | (0,2)（実行開始時の行頭。動かない） |

- l4-program 5.6.5 の食い違いの原因は**場面の違い**だった: s9p は `locate` の後に実行中の自己ループ（0x80＝カーソル非表示）、s9o は `width` を直接モードで打った窓（直後に Ok のプロンプトが出る＝0x81）。0x80 と 0x81 のコマンド番号そのものの意味はハードウェア資料のとおり（CM ビット）。
- 実行中でも `input` 待ちは 0x81（カーソルが出る）。`inkey$` ループは出ない（0x80）。
- **実装向けの規則**: 直接モードのプロンプト・行入力・`input` 待ちの間は 0x81、プログラム実行中（`input` 待ち以外）は 0x80。パラメータは現在の文字出力位置（桁,行。40桁は 2×桁）で、毎フレーム書き直す。実行中のパラメータが動くか（`locate` を含むプログラムで 0x80 のパラメータが追随するか）は s9p の cur 腕で既に確認済み（locate の引数どおり）。
- **画素で見えるカーソル**: カーソルのセル（8×20）が**全面白（160画素が ffffff）**になる位相と、背景の黒だけの位相があった（`st-idle` は採取位置で白・19フレーム後で黒、`st-input` は逆）。点滅する■カーソルで、
  0x81 の腕だけが見える。0x80 の `st-goto` は2位相とも黒のまま（見えない）。なお `st-typing`・`st-width80`・`st-locate`・`st-err`・`st-inputtyped` は採取位置が白位相、`st-cls`・`st-progend`・`st-width40`(画素なし) などは黒位相のものがあり、位相は腕により違う（点滅周期は測っていない）。

## 2. COLOR の値と描画（白黒モード＝起動既定、カラーモード＝`console ,,,1`）

セル（桁11、行10）の画素。背景は黒（000000）、前景は白（ffffff）。個数は 8×20=160 画素中。属性域は印の区間の組（終端桁, 値）。

**白黒モード（起動既定）**: 色は付かず、`color n` は**ファンクションコード**として働く（値バイトは n そのもの）。

| n | 属性値 | セルの画素 | 読み |
|---|---|---|---|
| 0 | 組なし（印の前の区間 (10,0) のみ） | 黒120＋白40 | 通常（白い字形） |
| 1 | 1 | 黒160（単色） | シークレット（字形が見えない） |
| 2 | 2 | 黒120＋白40 | ブリンク（採取位置では見えた。位相は測っていない） |
| 3 | 3 | 黒160 | シークレット（＋ブリンク） |
| 4 | 4 | 白120＋黒40 | リバース（字形と背景が逆） |
| 5 | 5 | 白160（単色） | リバース＋シークレット（全面前景色） |
| 6 | 6 | 白120＋黒40 | リバース＋ブリンク |
| 7 | 7 | 白160 | 全部（リバース＋シークレット＋ブリンク） |

→ bit0=シークレット、bit1=ブリンク、bit2=リバースと一致（マニュアルの言語仕様どおり）。前景は常に白で、n で色は変わらない。属性域の値の表しかたは s1c と同じ（白黒の既定 (0x80,0x00)）。

**カラーモード（`console ,,,1`）**: 属性値は **0x08 | (色のGRB 3ビットを bit7–5 に)** で、n=7（白）だけ既定 (0x80,0xE8) と同じで組が書かれない。

| n | 属性値（印の組の値） | 字形の前景色 | 色名 |
|---|---|---|---|
| 0 | 0x08 | 黒（背景と同じで見えない。セルは単色） | 黒 |
| 1 | 0x28 | 0000ff | 青 |
| 2 | 0x48 | ff0000 | 赤 |
| 3 | 0x68 | ff00ff | 紫 |
| 4 | 0x88 | 00ff00 | 緑 |
| 5 | 0xA8 | 00ffff | 水色 |
| 6 | 0xC8 | ffff00 | 黄 |
| 7 | 組なし（既定の 0xE8） | ffffff | 白 |

→ 属性バイトは bit3=カラー指定、bit5=青(B)、bit6=赤(R)、bit7=緑(G)。COLOR n の n は B=1・R=2・G=4 の3ビットを bit5・6・7 に移した値（n<<5 | 0x08）。マニュアルの色名の並びと一致。
印の前の区間の組の値は 0xE8（既定の白）、終端桁 10。カラーモードの `console ,,,1` は画面を書き換える（l3-main 第11節）。

## 3. COLOR の第2〜4引数（`color ,b`・`color ,,,f`）

- **画面の画素は変わらない**: `bg-b0〜b7`・`fg-f0〜f7` の全てで、印のセル・空白セル・画面全体の色ヒストグラム（黒 246716・白 9284）が `bg-base` と同一。テキスト画面の空白セルにも字形にも背景色・前景色は出ない（描画はこのエミュのスナップショットで、グラフィック面の背景は出ていないと読めるが、これはエミュの実装を測っている）。
- **制御ポート 0x54 は動く**: `color ,b` で 0x54 に**2回**書く。1回目は 0x80 | (b の bit0 なら +7, bit1 なら +56) → b=0〜3 で 128・135・184・191。2回目は 192 | (b の bit2 なら +7) → b=0〜3 で 192、b=4〜7 で 199。
  つまり b の3ビットを2回の書き込みの下位6ビットに割り当てる（bit6 の違い〔0x80 台と 0xC0 台〕がどちらの書き込みかの区別）。b=0 は 128,192（`color n` だけでも同じ書き込みが出る＝既定の背景黒）。`color ,,,f`（f=0〜7）は 0x54 に影響せず 128,192（基準 `color` と同じ）。
- 属性域: `bg-b*`・`fg-f*` の行10は全て組なし（予測どおり）。
- 0x52・0x53・0x30（モード切替以外）は動かない。0x30 はカラーモード（`console ,,,1`）で 33（0x21、bit1=0）が書かれる以外、白黒モードでは書かれない。

## 4. 自作ROM（現状。同じ器具で49腕×2走）

- **カーソルコマンド**: 直接モードの状態（idle・typing・直接モード直後6腕・`print` 終了）は公式と**同じコマンド 0x81・同じ桁**（桁 0/8/0/0/0/0/0 一致。行は banner の分だけ違い 2 対 6 など）。
  実行中（goto・for・input・inkey）は**窓の終わりにカーソルコマンドを書かない**（最後に書いたのは 0x81 でパラメータなし）。公式は実行中も毎フレーム 0x80（input 待ちは 0x81）＋位置を書く。
- **画素（白黒）**: `color n` の見え方は公式と同じ分類（n=0・2 は字形、1・3 は単色、4・6 は反転字形、5・7 は全面前景）で、字形の画素数だけ違う（フォントが違う: 黒92＋白68 対 黒120＋白40）。
- **カラーモード**: `console ,,,1` が実行できず（プログラムが止まり印が出ない）、px1 の8腕は関門落ち。**未実装**。
- **ポート**: `color ,b` の 0x54 の2回書き込みは**公式と完全に同じ**（b=0〜7 の8通りとも 128/135/184/191 と 192/199 の組）。`color ,,,f` も同じ。0x32 の値の初出順だけ違う（無関係）。
- 背景・前景の第2〜4引数は画素に出ない点は公式と同じ。

## 実装への含意（src/ は触っていない）

1. 実行中のカーソル: プログラム実行中（`input` 待ち以外）は CRTC に 0x80＋現在位置を、直接モードの入力待ち・`input` 待ちは 0x81＋位置を、毎フレーム書く。自作は実行中に何も書かない。
2. カラーモード（`console ,,,1`）と、属性値 `0x08 | n の3ビットを bit5〜7` への書き直し。白黒モードの属性値は現状どおり（n そのもの）で画素も同じ分類。
3. l4-program 5.6.5 の「コマンド番号の食い違い（未確定）」は、本ノートの 1. で解決（場面の違い）。次回の仕様改訂で書き換える。
