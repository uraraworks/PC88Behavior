# B33: 違う区間の値が ROM の内容かを、値を出さずに確かめる — 結果

記録日: 2026-11-01
規則: [b33-g1-rom-origin-preregistration.md](b33-g1-rom-origin-preregistration.md) どおり。測定はクラウドの実行環境で B30b の生ログを再利用。値は出力していない。

```
length=132
official-in-official-rom offset=none
self-in-self-rom offset=none
official-in-self-rom offset=none
```

## 判定

違う区間 132 バイトの全体は、公式の値も自作の値も、それぞれの `DISK.ROM` の先頭 0x800 に**そのまま並んではいない**。第3節の規則により、ROM とは言わない。RAM の内容の可能性として扱う。

器具は別に長さ 2 の区間も調べ、公式で番地 `0002`、自作で番地 `02B2` と一致した。2 バイトの一致は偶然でも起きるので、根拠にしない。

## 汚染の疑いの扱い

B32 の 8 バイトが ROM からそのまま写されたものだという証拠は無くなった。ただし次の 2 つが残るので、**疑いは解かない。** 値は引き続き使わず、リポジトリにも入れない。

- 8 バイトだけが ROM の別の所と一致するかは確かめていない
- 公式 ROM が RAM へ書いた内容なら、ROM 由来である

## 読み方（推定）

G1 のコードが main へ送る区間が、公式と自作で違う。サブの RAM の、ゲームが書いていない所を読んでいる可能性がある。その場合、番地が需要になる。次は値を見ずに、RAM 上のコードがどの番地を読むかを測る。
