# 汚染の記録 — m6f-c 準備中に第三者実装由来のディスク形式定数を見た

記録日: 2026-09-24

## 1. 何が起きたか

m6f-b 結果 §8 の次稿(空の公式形式ディスクを自作の生成器で作り、公式ROM が
SAVE・FILES・LOAD を行えるかを測る)の準備で、メインセッション(Claude Opus 5.5、
2026-09-24 のセッション)が既存の `tools/make_n88_blank_disk.py`(`d9be9af`、
2026-08-31)の先頭80行を読んだ。

この生成器は m7eb 事前登録 §(第10段)のとおり、GPL 第三者実装 QUASI88 の公開
`src/image.c` の空媒体生成規則を写したものである。先頭80行には、媒体の形状の定数に
加えて、**N88-BASIC データディスクの管理領域の初期値**(ディレクトリとみなされる
トラック・セクタの範囲、未使用エントリの値、管理用セクタの初期値、割り当て表の
初期値)が含まれていた。

2026-09-24 の決定(`m6f-a-directory-by-save-diff-preregistration.md` §0)は
「公式のディスク形式は第三者の解析を読まず、自分で測る」である。第三者実装の
生成規則はこの「第三者の解析」に当たると扱う。**判断は保守側に倒した**
(`CLAUDE.md`「汚染したとき」)。

## 2. 見た範囲

- `tools/make_n88_blank_disk.py` の1〜80行(定数定義、`sector_data`、
  `sector_header`、`build_disk` の冒頭)。
- QUASI88 の `src/image.c` そのものは開いていない。
- 本ノートには、見た定数の値を転記しない(転記すると経路が増える)。

## 3. 措置

1. **このセッションを、ディスク形式の管理領域(ディレクトリの範囲・割り当て表の
   意味と空きの印・管理用セクタ)の導出規則の設計と実装から外す。**
   m6f-c の事前登録・生成器・導出規則は、`tools/make_n88_blank_disk.py` と
   QUASI88 の `src/image.c` を読んでいない担当が、`docs/spec/l3-disk-format.md`
   と測定だけから作る。
2. m6f-c の生成器は `make_n88_blank_disk.py` を import・参照・流用しない。
   新しい生成器を別名で作る。
3. このセッションが見た定数と m6f-a・m6f-b の結果の一致・不一致は、
   どの文書にも書かない(照合すると、測定の結論に第三者の値が混ざる)。

## 4. 未決(利用者の判断を仰ぐ)

- 既存の `tools/make_n88_blank_disk.py` と、それで作った媒体を使った過去の測定
  (m7eb 以降の空媒体ラダー等)の扱い。当時は「測定器の媒体」として使い、
  仕様の出所にはしていなかったが、2026-09-24 の決定との関係を整理する必要がある。
