# B49: main の読みが 1 回重なる前後の、受け渡しの順を測る — 事前登録

記録日: 2026-11-01
位置づけ: [B48](b48-g1-fc-position-results.md) の次段。**このノートは測定より先にコミットする。**

## 1. 問い

`IN $FC` の番号 76568〜76573 の範囲で、main とサブのポートの出来事はどの順に起きるか。公式と自作でどう違うか。自作で番号 76571 の読みの前に、main は何を見て進むか。

## 2. 器具

コアは変えない。`--io-log` の生の記録から、番号 76568 の読みの 40 件前から番号 76573 の読みの 20 件後まで（両方の CPU を clock の順に並べたもの）を腕ごとに出す。

行は次だけである。

`E <腕> <clock の差> <main|sub> <IN|OUT> <ポート> <発行元の組> <値または ->`

- **値を出すのは `IN $FE`・`OUT $FF`・`IN $FF`・`OUT $FE` の下位 4 ビットだけである。** これらは受け渡しの制御で、データではない。`$FB`・`$FC`・`$FD` などのデータのポートは `-` にする
- 発行元の組は腕の中で初めて現れた順の番号で、番地は出さない
- 同じ行が続くときは `x<回数>` でまとめる

器具は G1 なしで自己検査する。陽性対照は順の判定と制御の値の抜き出し、まとめ。陰性対照はデータのポートの値が出ないこと、番地が出ないこと。

## 3. 条件

腕 F の 4800 フレーム。OO・SS 各 2 走。自作 ROM は 62254d3 と同じソースの配布ビルド。クラウドの実行環境で行う。

関門: `IN $FC` の差が B44 と同じ。OO どうし・SS どうしの出力が同じ。取りこぼしが無い。

## 4. 記録の白リスト

第 2 節の行だけ。

## 5. 判定（事前に決める）

- 番号 76570 と 76571 の読みのあいだの出来事を腕ごとに並べ、違いを書く
- main が制御を見ずに読んでいるなら、そう書く
- 制御の値が違うなら、その値を最後に変えた出来事を書く。原因は断定しない
