# l4-s4k — 倍精度の定数読み取り3候補（DEXACT/DGW/DREP01）の探索

記録日: 2026-09-15。段階4b（倍精度の実装）の前に、N88が倍精度の定数
（小数点を除く数字が8桁以上、または`#`付き、または`d`指数）をどう読むかを
決めるための候補探しである。**測定はしていない。判定には使わない。**

## 3候補と実装

`tools/l4_dmodels.py` に、`tools/l4_mbf_oracle_v2.py` とは独立に実装した。

- **DEXACT**: 10進の厳密値を倍精度(56bit仮数)へ1回だけ丸める。
- **DGW**: GW-BASICの$FINE/MDPTENの倍精度経路(単精度REP10/REP01探索で
  確認したのと同じ構造)。10のべき定数自体を先に56bitへ丸め、その不正確な
  定数で1回スケーリングしてから、結果をもう一度56bitへ丸める(二段階の
  精度落とし)。
- **DREP01**: l4-s4jの単精度REP01を倍精度へ移したもの。数字を先頭から
  `acc=acc*10+d`で積み上げて1手ごとに倍精度へ丸め、正味の指数`n`(`e`の値
  から小数点以下の桁数を引いたもの)について`n>0`なら10を、`n<0`なら
  **倍精度に丸めた0.1**を`|n|`回、1回ずつ掛けて1手ごとに倍精度へ丸める。

**丸めの前提(未確認、仮定)**: l4-s4hで倍精度の丸めの半端(タイ)は
出力側(PRINTの桁生成)で「絶対値の大きい側(常に切り上げ)」と確定した。
本探索は**読み取り側もこれと同じ規則だと仮定**し、3候補すべてで
round-half-away(半分は絶対値の大きい側)を使う。`encode_mbf`(既存の
偶数丸め)とは意図的に異なる丸め関数を独立実装している。

## 食い違う率（乱数、測定ではない）

符号・小数点位置・`e`指数をランダムに振った倍精度の打鍵可能な定数
(小数点を除いて8〜16桁)で、3候補のMBF倍精度エンコード(符号・指数バイト・
56bit仮数)を比較した(50000件、seed固定で再現可能、`tools/gen_l4_s4k_candidates.py`
と同じ生成規則)。

| 指数の範囲 | 3候補のうち1つでも食い違う | DGWとDREP01が食い違う |
|---|---:|---:|
| `e±8` | 64.90% | 64.90% |
| `e±20` | 65.75% | 65.75% |
| `e±40` | 59.92%(29961/50000) | 59.68%(29841/50000) |

指数の範囲によらず**約60〜66%**が食い違う(単精度の0.5%程度と比べて
桁違いに高い)。DEXACTとDGWは、正味指数`n`の絶対値が小さく`10^|n|`が
56bit内に厳密に収まる範囲(だいたい`|n|<=16`)では数学的に同じ値になる
(下記の手検算参照)。3候補すべてが同時に食い違う組合せ(DEXACT・DGW・
DREP01が3者3様)は50000件中2618件(約5.2%、`e±20`相当の探索)で、
DEXACT/DGWが揃ってDREP01だけ外れる組合せが大半を占める。

候補・対照の生成: `tools/gen_l4_s4k_candidates.py` /
`tools/gen_l4_s4k_controls.py`。結果:
`docs/notes/l4-s4k-candidates.tsv`(24件、group pos/neg/hash/intdec各6件、
DEXACTとも異なるものは今回の探索では0件だった)・
`docs/notes/l4-s4k-controls.tsv`(12件、各group 3件、10件は答えが0でない)。

## 手で検算できる形（候補表2行の途中の値）

いずれも`tools/l4_dmodels.py`の`_round_away_frac`(56bit・半分は絶対値の
大きい側)を1回だけ使う最小の例(正味指数`|n|=1`)を選んだ。

### 1. `print 300.8#-301`（group hash）

定数 `300.8#`: 桁文字列`"3008"`、小数点以下1桁、指数無し(`#`は倍精度を
強制するだけで指数には無関係)なので正味指数`n=-1`。

- 積み上げ: `acc=3008`(厳密、丸め不要)。
- **DEXACT**: `round_away(3008 * 10^-1) = round_away(1504/5)`
  → 仮数(56bit)は分数 `21166918248641331/70368744177664`
  (`= 21166918248641331 / 2^46`。分母`70368744177664=2^46`。厳密値
  `1504/5=300.8`に最も近い56bit値)。
- **DGW**: `fac=round_away(3008)=3008`(丸め不要、既に整数)。
  `pow10=round_away(10^1)=10`(丸め不要、10は2進で厳密に表せる整数)。
  `fac/pow10 = 3008/10 = 1504/5`(DEXACTと厳密に同じ分数、10のべき表が
  この指数では丸め誤差を持たないため)。`round_away(1504/5)` も
  DEXACTと同じ `21166918248641331/70368744177664` になる。
  **→ DEXACT=DGW(数学的に同一の丸め対象を丸めているため)。**
- **DREP01**: `S01=round_away(1/10,56bit)
  =57646075230342349/576460752303423488`(`=57646075230342349/2^59`)。
  `round_away(3008 * S01) = 42333836497282663/140737488355328`
  (`=42333836497282663/2^47`)。
  DEXACT/DGWの値を同じ分母`2^47`に揃えると`42333836497282662/2^47`
  になるので、**DREP01はDEXACT/DGWよりちょうど1(仮数の最下位1ビット
  分)だけ大きい**。

### 2. `print -6248673318.3+6248673318`（group intdec）

定数 `-6248673318.3`: 桁文字列`"62486733183"`、小数点以下1桁、
正味指数`n=-1`(符号は最後に付けるので、以下は絶対値`6248673318.3`で
計算する)。

- 積み上げ: `acc=62486733183`(厳密)。
- **DEXACT**: `round_away(62486733183 * 10^-1)
  = round_away(62486733183/10)`
  → `26208835493638963/4194304`(`=26208835493638963/2^22`)。
- **DGW**: `fac=round_away(62486733183)=62486733183`(丸め不要)。
  `pow10=round_away(10^1)=10`(丸め不要)。`fac/pow10=62486733183/10`
  (DEXACTと厳密に同じ分数)。丸めた結果も同じ
  `26208835493638963/4194304`。**→ DEXACT=DGW。**
- **DREP01**: `round_away(62486733183 * S01)
  = 52417670987277927/8388608`(`=52417670987277927/2^23`)。
  DEXACT/DGWの値を同じ分母`2^23`に揃えると`52417670987277926/2^23`
  になるので、**DREP01はDEXACT/DGWよりちょうど1だけ大きい**(絶対値側、
  符号を戻すと実際の定数は負なので、符号込みではDREP01の方が絶対値が
  大きい＝0に近い側)。

両例とも「正味指数の絶対値が1で、10^1が56bit内に厳密に収まる」ため
DEXACT=DGWになる典型例であり、DREP01だけが仮数の最下位1ビットぶん
ずれる。候補表・対照表に載せた大きい指数の腕(`|n|`が10を超えるもの)は、
DGWの10のべき表自体が丸め誤差を持ちうる領域だが、今回の24件では
たまたまDEXACTとDGWの食い違いは1件も見つからなかった(DEXACTとも
異なる行が0件、`docs/notes/l4-s4k-candidates.tsv`のヘッダコメント参照)。
DEXACT・DGWが食い違う倍精度の例は、既存の`docs/notes/
l4-fout-exact-vs-gw-candidates.tsv`(倍精度は200000件中0件)でも同様に
出にくいことが分かっており、本探索の結果とも整合する。
