結果である。事前登録は測定開始前に単独コミット（`be5a38f`）してあり、
本稿では条件・指標・到達の定義・判定規則を後から動かしていない。
`src/`・`tools/`は変更していない。

**結論を先に書く: 主判定はEA2（一部一致）である。そして本稿がいちばん大きい
——8軸で1度も動かなかった3・9・4が、サブROMを替えた途端に全部動いた。**

## 結果

| 指標 | **条件O（公式一式）** | **条件M（混成: 公式main + 自作サブROM）** |
|---|---|---|
| **K（対象の数）** | **3** | **5** |
| **多重度／記号列** | **`4,4,4`**／`A A A A B B B B C C C C` | **`1,1,1,1,1`**／`A B C D E` |
| **run長** | **`{9:12}`** | **`{1:5}`** |
| **run内基数 C/H/R（全run同一か）** | `1/1/1`（真） | **`1/1/1`（真）** |
| FDC総数／`READ DATA`総数 | 144／108 | 20／5 |
| エラー真／公開ビット復号名 | 108／`NO DATA` 108 | 5／`NO DATA` 5 |
| SEEK件数／目的Cの基数 | 12／1 | 5／1 |
| `R'`（不一致） | 108（0） | 5（0） |
| 最終frame／全イベント数 | 2999／202,427 | 2999／242,925 |

判定規則に当てると:

- EA1（K・L・M・Iの4つとも一致）: 不成立。
- **EA2（一部一致）: 成立。** **一致したのは`I`（run内基数`1/1/1`）だけ**で、
  **K（3対5）・L（9対1）・M（4対1）はすべて違う。**
- EA3（4つとも違う）: 不成立（`I`が一致している）。
- EA4（土俵が成立しない）: 不成立。**混成でも土俵は成立した**
  （エラー真5件・`NO DATA`）。
- O: 不成立（合格条件10項目すべて通過）。

**主判定はEA2である。**

## 記述（判定ではない）

**言えること:**

- **サブROMを替えると、3も9も4も変わる。** 外側の8軸（セクタ数・シリンダ・
  ヘッド・セクタ番号の起点・失敗の原因・打鍵の命令・打鍵の回数・実行量）で
  1度も動かなかった量が、**ROMを替えた1回で全部動いた。**
- **自作は「5つの対象を1回ずつ読んで終わる」。** 公式は「3つの対象を、
  9回×4周＝36回ずつ読む」。**合計の`READ DATA`は108件対5件。**
- **run内の基数だけは両方`1/1/1`。** ただし意味は違う——**公式は同じ対象を
  9回繰り返しているから1**であり、**自作はそもそもrunの長さが1だから1**である。
  **同じ数字だが、同じ現象ではない。**
- **混成でも土俵は成立した**（`NO DATA`のエラーが出る）。中止規則には
  該当しなかった。

**言えないこと:**

- **「公式の9・4・3はサブROMの中に書かれた定数である」と即断しない**
  （事前登録どおり）。**言えるのは「サブROMを替えると数が変わる」までである。**
  数が変わった理由は、サブROMが**再試行しない**からかもしれないし、
  **要求のまとめ方が違う**からかもしれない。本稿はそこを分けていない。
- **自作が公式と違う振る舞いをすることは、この測定では「差がある」以上の
  ことを言わない。** どちらが正しいかは適合の話であって本稿の判定ではない。
- **セクタ番号・シリンダ値・画面本文・ROMのバイト列は出していない。**
- 条件O・A:=`disk#8`固定・打鍵1種・ディスク1本という1つの使い方しか
  見ていない。

## 自作サブROMのソースを読んだ記録（判定には使わない。事前登録どおり）

`src/l3_service/make_subrom.py`（**自作なので読んでよい**。3,402行）を
`retry`・`リトライ`・`再試行`で検索したが、**再試行に相当する固定回数の
ループは見当たらなかった。**

- **`grep`で見つからないことは「無い」の証明ではない**が、**測定結果
  （`{1:5}`＝1回読んで終わり）とは整合する。**
- **公式側のコードは読んでいない。**

## これは適合の課題でもある

本稿は「9の追跡」のための測定だが、**副産物として実装の差分がはっきりした。**

| | 公式 | 自作 |
|---|---|---|
| 読めない対象への対応 | **36回試す**（9×4） | **1回で諦める** |
| 窓内で扱う対象の数 | **3** | **5** |

**自作サブROMは、読めないときの粘りを実装していない。** これは
`docs/spec/l3-subrom.md`の適合条件が現状カバーしていない領域であり、
**「測って仕様に起こす」対象がまだ残っていることを示している。**
本稿は差の存在を記録するだけで、**どう実装するかは決めない**
（先に仕様が要る）。

## 次に何を測れば絞れるか

1. **「数が変わった理由」を分ける。** 自作が再試行しないこと（L=1）と、
   対象の数が違うこと（K=5対3）は別の話である。**Kの差は要求のまとめ方の差**
   かもしれず、そちらはサブROMより手前（main→subの要求列）に出るはずである。
2. **既存の故障注入で、公式側の9・4を動かせるか試す。**
   `--break-run-continuation`など、名前からして連続読み出しの継続に触れる
   フラグがある（**自作サブROM向けの注入なので公式側は動かせない**点に注意。
   使えるのは混成条件だけ）。
3. **公式の36回（9×4）が何で打ち切られるかを測る。** 対象を替えるきっかけが
   回数なのか別の条件なのかは、まだ分けていない。

## 開示

- **委譲先が、公式ディスクのSHA-256の値を自分の作業ログへ出力した。**
  「`disk#8`の原本ダイジェスト不変」を確かめる自作スクリプトの試行錯誤の
  過程で起きたもので、**対象はディスク全体の内容ハッシュ**（セクタ値でも
  ROMバイト列でもない）だが、**事前登録が「値は出さない」とした領域に
  触れている。** 委譲先は気づいた時点で該当出力を破棄し、
  **`stage_disk_by_digest.sh`で作った複製どうしを`cmp -s`で比べる方式
  （値を出さず真偽だけ）へ差し替えて検査をやり直した。** 測定データ・
  `src/`・`tools/`への影響は無い。**本稿・コミットメッセージ・仕様書には
  その値を転記していない。**
- **委譲先の報告に、サブROMのファイル名が1つ現れた。** コア（第三者の公開
  エミュレータ）が両条件で同じく出す定型の標準エラー（探索の試行）に含まれる
  もので、**そのファイル名は`vendor/`の公開ソースに現れる識別子**である。
  中身には触れていない。**本稿には転記しない。**
- **自作サブROMのソースを読んだのは判定が出たあとである**（事前登録で
  「解釈のために読む。判定には使わない」と先に決めてあった）。
- 測定の実行と集計はSonnetのAgentへ委譲した。**委譲したのは実行と集計のみで、
  判定・解釈は親セッションが行った。** 中止規則（混成で土俵ができなくても
  故障注入や打鍵を足さない）は指示に明記し、該当しなかった。
- 実行した条件数（2）を出力に載せ、期待値と一致することを確認した。
- 上記以外の手順逸脱・事故は無い。無言でSKIPした分岐は無い。
