# B94 — G5 のスペース押下後のずれ

記録日: 2026-11-13。クラウド測定の値なし報告に基づく。

公式の 3080 は押し始めとリピート時に文字コードを RAM の輪バッファに積み、G5 は索引と先読み枠を確認して 35CE から1文字取り出す。自作の 3080 は積まないため、G5 からはスペースが押されていないように見える。リピート間隔の差は主因ではない。

36000 フレームを600フレームごとに比較した60点の画面ハッシュ一致数は、公式・自作の無入力同士が38、スペース入力同士が4、公式のスペース入力と無入力が12。公式で積む処理を止めたスペース入力と自作のスペース入力は34、同じ公式の腕と公式の無入力は31だった。R 由来の散発差があるため、ハッシュ一致数は傾向の裏付けとして扱う。

G5 は 3080 の直後に EFCD・EFCE・EFCF を読み、EFCD≠EFCE または EFCF≠0 なら 35CE に飛ぶ。観測範囲 F7215〜7330 でゲームが読むキー関係の番地はこの3つだった。

測定は公式 ROM（漢字なし）と自作 ROM（main ce3ccbd、46533ae と同じ ROM）を使い、無入力と、F3600・F7200 以降にスペースを300フレーム押す腕を比較した。G5 の3枚連結 D88 を分割し、1枚目・2枚目をドライブ1・2に置いた。RAM 書き込み、ゲーム側の読み、ROM 境界と RAM 読みのログを取得し、3080 初回前の単一番地への介入も行った。測定用に改変した手元 core で 3080・35CE・F0D3・ECDF のレジスタを観測した。画面本文や ROM・ゲームの値は転記しない。

未確定は、輪が満杯の場合、複数キー同時押し・SHIFT・カナ・ファンクションキー、ECDF 呼び出し時の BC・DE、35CE の E6CB・E6CC の扱いと空のときの動作。EFF9 の押し始めの一定値と EFC6・EFC7 に書く値も未確定。自作の既存の値で代用してよい。詳細な規則は [main ROM 入口仕様](../spec/main-rom-entry.md#151-3080g5-実走での観測) に記す。

## 追補1: entry16 と輪バッファの指し先の訂正（2026-11-14、値なし）

entry16（03afcf3）の G5 比較は、N が38/60（entry15 と同じ）、SP が4/60（entry15 と同じ）、RT が33/60（entry13 は28/60）。SP 腕では押し始めを検知し、EFF9・EFFA〜EFFE・E6CF の初期化が公式と同じ並びで、ECDF も呼んだが、輪バッファへ一度も積まず、35CE も呼ばれなかった。entry16 は第11版に記した「E6CB・E6CC が非0なら積まない」を実装した結果であり、その条件は測定側の読み違いだった。G1・G2・G3 の N・SP・RT 各36000フレームでは、entry15（main）と9本すべて60/60一致し、回帰はなかった。

E6CB・E6CC は輪バッファの制御ブロックの番地を指す。`P = (E6CB) + 256×(E6CC)` とし、P+0 は書き索引、P+1 は読み索引、P+2 は先読み文字、P+3 は索引マスク、P+4・P+5 は輪の先頭番地（下位・上位）。G5 では P=EFCD。P を EF40 に向けて同形のブロックを置く介入では、そのブロックを使って積み、EFCD〜EFD2 には触れなかった。

3080 は `i = (P+0+1) AND (P+3)` を計算し、i=P+1 なら満杯として積まない。それ以外は `[(P+4/P+5)+i]` に文字を書き、P+0=i とする。P+2 が非0でも積みには影響しない。E6CB・E6CC が0であることを条件とする規則はない。

35CE は P+2 が非0ならその値を返し、P+2=0 にする。P+2=0 かつ P+0≠P+1 なら `i=(P+1+1) AND (P+3)` とし、輪の `[(P+4/P+5)+i]` を返し、P+2=0、P+1=i とする。空（P+2=0 かつ P+0=P+1）でも戻り、Z=1（観測1回）。空時の A は未確定。文字を返すときのフラグは OR A と同じ形で、Z=0、S・P/V は値に従い、H・N・C は0。P=EF40、P+2 が非0の介入でも、その値を返してP+2を0にした。その他の戻り時条件は仕様第12版に記す。
