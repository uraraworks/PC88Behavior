# m6i-c — B5 と B6-A0 の食い違いの切り分け — 事前登録

記録日: 2026-09-22  
状態: 測定前

対象は、[m6i-b 結果](m6i-b-first-request-timing-results.md) §6 が残した
「B5 と B6-A0 が逆の結果を出した」である。両腕は main 側と sub 側の2点で
同時に違っており、m6i-b の比較は交絡していた（前提の訂正は
[m6i-c 準備](m6i-c-arm-difference-correction.md)）。本稿は2要因を直交させて
切り分ける。測定対象は自作 main と自作 sub だけであり、公式 ROM は使わない。

## 1. 問い

B5（timeout、要求 run 0件）と B6-A0（256位置一致、要求 run 1件）を分けたのは、
次のどちらか。

- **要因S（sub）**: sub ROM がラウンド#0応答の直後に持つスピンゲート
  （`M6IB_B5_AFTER_ROUND0_GATE`）の有無。B5 は持ち、B6-A0 は持たない。
- **要因M（main）**: main ROM の枝タグ格納とそれに伴う配置のずれの有無。
  B6-A0 は持ち、B5 は持たない。

副問は、要因S のゲートが働いた腕で、**main の通常SEND開始を取りこぼしているか**
である。ゲートへ入ったか、ゲートを抜けたか、要求 run が走ったかを別マーカーで
観測して切り分ける。

## 2. 腕（arm）

2要因2水準の完全要因設計である。全腕で m6i-a と同じ規則生成D88、同じ
シリンダ0・ヘッド0・セクタ1、同じ交換列、同じ期待SHA-256 を使い、通常READの
発行はフレーム60に揃える。main 側の前置きは4腕とも `b→a→c`（起動専用送信の
消化、FDC初期化7 batch、ラウンド#0完了）である。

| 腕 | main | sub | m6i-b の対応 |
|---|---|---|---|
| C0 | 枝タグなし | ゲートあり | B5 と同一 |
| C1 | 枝タグあり | ゲートなし | B6-A0 と同一 |
| C2 | 枝タグなし | ゲートなし | 新規（要因S だけを B5 から外す） |
| C3 | 枝タグあり | ゲートあり | 新規（要因S だけを B6-A0 へ足す） |

### C0 `b5_reproduction`

- **何をするか**: m6i-b B5 の ROM 一式をそのまま使う。
- **到達指標**: `b→a→c` が各1回この順に完了し、発行フレームが60である。
- **期待の形**: m6i-b B5 と同じく timeout し、要求 run は0件。再現腕であり、
  この期待と違っても他腕の結果へ読み替えない。

### C1 `b6a0_reproduction`

- **何をするか**: m6i-b B6-A0 の ROM 一式をそのまま使う。
- **到達指標**: 同上。
- **期待の形**: m6i-b B6-A0 と同じく256位置一致、要求 run 1件。再現腕である。

### C2 `b5_main_without_sub_gate`

- **何をするか**: C0 の main ROM と、C1 の sub ROM を組み合わせる。
  main 側は C0 とバイト一致、sub 側は C1 とバイト一致でなければならない。
- **到達指標**: 同上。加えて、sub のゲート入場マーカーが0件である。
- **期待の形**: 成立すれば要因S が効いている側の証拠になる。

### C3 `b6a0_main_with_sub_gate`

- **何をするか**: C1 の main ROM と、C0 の sub ROM を組み合わせる。
  main 側は C1 とバイト一致、sub 側は C0 とバイト一致でなければならない。
- **到達指標**: 同上。加えて、sub のゲート入場マーカーが1件以上である。
- **期待の形**: timeout すれば要因S が効いている側の証拠になる。

### 副問の観測（C0・C3 のみ）

ゲートを持つ2腕について、次の3つを別マーカーで数える。値列は採らない。

- `gate_entered`: ゲートのラベルへ到達した回数（1件以上か）
- `gate_released`: ゲートの条件が成立して次へ進んだ回数（1件以上か）
- `request_runs`: 通常READの要求 run が走った件数

## 3. 関門（gate）

いずれかが偽なら測定腕へ進まず、全体を `gate_failed` として止める。

- **G1 自己検査**: `tools/run_all_selftests.sh` が rc=0 で終わる。
- **G2 クリーンルーム検査**: `tools/check_cleanroom.sh` が rc=0 かつ NG 0件。
- **G3 凍結値**: 媒体SHA、期待SHA、timeout上限、発行フレーム、反復数が
  m6i-a 追補1 および m6i-b の凍結表と一致する。
- **G4 要因直交のバイト照合**: 本測定でいちばん効く関門である。4腕の ROM 一式に
  ついて、次をすべてバイト単位で確認する。1つでも崩れたら腕へ進まない。
  - C0 の一式が m6i-b B5 の一式とバイト一致
  - C1 の一式が m6i-b B6-A0 の一式とバイト一致
  - C2 の `N88.ROM` が C0 のものとバイト一致、`DISK.ROM` が C1 のものとバイト一致
  - C3 の `N88.ROM` が C1 のものとバイト一致、`DISK.ROM` が C0 のものとバイト一致
  - 4腕の `N88.ROM` は2種類、`DISK.ROM` は2種類しか存在しない
  - `N88.ROM` 以外・`DISK.ROM` 以外の5ファイルは4腕で全て同一
  - サイズと命令境界の検査を通る
  陰性対照として、意図的に組み合わせを入れ替えた一式で false になることを示す。
- **G5 時刻と順序**: 4腕とも通常READ発行がフレーム60で、前置きが `b→a→c` の順に
  各1回完了している。前置きの通信を要求 run へ数えない。
- **G6 腕の検出力**: 測定前に故障注入を行い、解析器が該当腕を `unreached` に
  するか関門を落とすことを確認する。最低限、次の4種を実駆動で回す。
  前置きマーカー削除、発行フレームの改変、ゲート入場マーカーの削除、
  要求 run 計数器の固定化。検出されない腕は開始しない。
- **G7 結果検出力**: 合成入力で、256位置一致、1位置欠落、SHA不一致、timeout、
  定常入力待ち未復帰を別々に識別することを確認する。
- **G8 副問の検出力**: ゲートを強制的に素通りさせた合成入力と、ゲートから
  永久に抜けない合成入力で、`gate_never_released` と
  `gate_released_but_request_lost` が別々に出ることを確認する。
- **G9 未確定値の凍結**: 次項の値と腕名・判定名を測定前に器具の設定ファイルへ
  固定し、本稿と違えばエミュレータ起動前に `gate_failed` で止める。

### 測定前に凍結する

| 項目 | 凍結値 |
|---|---|
| 通常READ発行 | frame 60 |
| 測定期限 | 各腕600 frames |
| 反復数 | 各腕2走。2走の判定が一致しなければ `unreached` |
| timeout上限 | 65535 |
| 正常媒体SHA-256 | `d3becfe5051f7002d268824a2da2824f543442e71ae3226e4d22139e0adce05c` |
| セクタ1 SHA-256 | `4ed6e24a1fb78f8c79423740e05a311c438bae0f09b9974e50619050fdb8540a` |
| C0 期待ROM一式 | m6i-b B5 の一式（測定前に器具で再生成し SHA-256 を凍結表へ記録） |
| C1 期待ROM一式 | m6i-b B6-A0 の一式（同上） |

## 4. 判定名

判定は関門、到達、結果の順で付ける。到達条件を満たさない腕を結果条件へ
読み替えない。2走が一致しない腕も `unreached` である。

腕の結果は、通常READが「256位置一致かつ期待SHA一致かつ定常入力待ちへ復帰し、
要求 run が1件」であるときに `success`、そうでないときに `failure` とする。

- `gate_failed`: G1〜G9 のいずれかが偽。
- `unreached`: 関門通過後に腕の到達指標を満たさない。
- `c0_reproduced` / `c0_not_reproduced`: C0 が `failure` か否か。
- `c1_reproduced` / `c1_not_reproduced`: C1 が `success` か否か。
- `c2_success` / `c2_failure`、`c3_success` / `c3_failure`。

総合判定は、`c0_reproduced` と `c1_reproduced` がともに成立することを共通の
前提とする。どちらかが崩れたら `m6i_c_inconclusive` とし、要因の帰属をしない。

- `m6i_c_sub_gate_only`: `c2_success` かつ `c3_failure`。
  **要因S だけで成否が決まる。** 枝タグは効いていない。
- `m6i_c_branch_tag_only`: `c2_failure` かつ `c3_success`。
  **要因M だけで成否が決まる。** ゲートは効いていない。
- `m6i_c_interaction_required`: `c2_failure` かつ `c3_failure`。成立には
  要因M と要因S の両方が要る。単独因子では説明できない。
- `m6i_c_no_single_factor`: `c2_success` かつ `c3_success`。単独の水準変更で
  いずれも成立し、C0 の組み合わせだけが失敗する。
- `m6i_c_inconclusive`: 関門は通過したが、1腕以上が `unreached` であるか、
  再現腕が再現しなかった。

副問は総合判定と独立に、C0・C3 のうち到達した腕についてのみ記録する。

- `gate_not_entered`: `gate_entered` が0件。この腕では副問の帰属をしない。
- `gate_never_released`: `gate_entered` が1件以上、`gate_released` が0件。
  **ゲートは main の通常SEND開始を検出できていない。**
- `gate_released_but_request_lost`: `gate_released` が1件以上、
  `request_runs` が0件。**ゲートは抜けたが要求が走っていない。**
- `gate_released_and_request_ran`: `gate_released` と `request_runs` が
  ともに1件以上。

## 5. 判定後の行き先

- `m6i_c_sub_gate_only`: **B5 の timeout は測定器具の副作用である。** m6i-b の
  B5 の結果を、状態境界の証拠として使わない。ゲートを使わない B5 相当腕
  （＝C2）で m6i-b の境界判定7種を取り直す追補を別稿で事前登録する。
  m6i-b の結果ノートと総合判定は書き換えない。
- `m6i_c_branch_tag_only`: 枝タグ格納という無害なはずの差が成否を変えている。
  配置依存を疑い、main 側の配置を動かす腕を別稿で切り分ける。
  どちらにせよ、この状態で仕様へ規則を起こさない。
- `m6i_c_interaction_required`: 2要因の交互作用である。要因を1つずつ足す順序を
  変えた腕を別稿で立てる。m6i-b の境界判定は取り直さない。
- `m6i_c_no_single_factor`: C0 の組み合わせだけが失敗する形であり、
  どちらの単独因子でも説明できない。別の隠れ要因を探す稿を立てる。
- `m6i_c_inconclusive`: 到達器具か期限だけを直す追補を先に置き、結果条件と
  判定名は緩めない。
- 副問が `gate_never_released` または `gate_released_but_request_lost` の
  いずれであっても、それは**器具の性質についての知見であり、公式の挙動に
  ついての知見ではない。** 仕様書へ書かない。

**いずれの判定でも、本稿は `docs/spec/l3-subrom.md` 1.65節へ新たな規則を
起こさない。** 本稿が決めるのは m6i-b の B5 をどう扱うかだけである。

## 6. 本文に出さないもの

- 測定終了時のテキスト画面本文、main↔sub のデータポート値列、セクタ本文は、
  標準出力、標準エラー、結果ノート、コミットメッセージへ出さない。件数、順序、
  真偽、SHA-256、判定名だけを扱う。
- ROM の相違を示すときはバイト列を転記せず、一致／不一致と相違バイト数だけを扱う。
- I/Oログを残す場合は `tools/redact_iolog.py` で値列を伏せ、
  `tools/check_cleanroom.sh` を通す。ログの `--out` ファイルは直接開かない。
- 本文またはデータ列の漏えいを検出した走は結果に使わず `gate_failed` とする。

### この測定で決まらないこと

- 公式ROM内部の実装、公式の送受信値、実機での絶対時間は決まらない。
- 通常READを許してよい最早時点（1.65節が未確定として残した点）は決まらない。
  本稿は m6i-b の B5 が使える証拠かどうかだけを決める。
- m6i-b の B6-A2 が到達しなかったことは本稿の対象外であり、ここでは扱わない。
- 別媒体、WRITE、複数セクタREAD、BASIC命令一般へ一般化しない。
- 要因S のゲートは測定専用の介入であり、公式 sub がそのような待ちを持つとは
  主張しない。
