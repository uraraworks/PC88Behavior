# m7bu: runを閉じる出力は9種で一意だが1バイト種別1種に二つの列がある

測定日: 2026-08-20

## 情報境界

公式ROM一式・公式diskAの複製を、m7bjと同じ3条件（起動1800フレーム、
`FILES` 2400フレーム、`SAVE` 3600フレーム）で新規実行した。SAVE条件も
原本ではなく複製だけを実行対象とした。公式ROM・ディスクの内容は読まず、
`private/`への`cat`/`xxd`/`od`/`strings`・逆アセンブルは行っていない。
生iolog、ディスク複製、実行出力はリポジトリ外の`mktemp -d`配下だけに置き、
コミット対象にしていない。

解析には既存の`analyze_main_to_sub.parse_iolog`、
`analyze_record_boundaries.window_a_runs`、
`analyze_write_path.parse_commands`をそのまま用いた。新しい解析器は書いて
いない。以下では要求先頭バイトをm7bjの記号版と同じ`K00`〜`K09`で示す。
`$FC/$FD`の値、FDCデータフェーズの値は出力・記録していない。

## 測定方法

window(a)の各runについて、最後の`sub IN $FC`の直後から、最初の
`sub OUT $FB`または`sub OUT $FD`（run終端）までにsubが発行したOUTだけを
抽出した。`$FF`はフェーズコードを、終端が`$FB`なら既存FDCパーサが認識した
コマンドのオペコードを示す。データポートは値を示さず件数だけとした。

3条件のrun数はm7bjと同じ**25 / 49 / 74、合計148件**だった。全148 runに
終端があり、解析対象の取りこぼしは0件だった。

### 1バイト種別

1.36節の1バイト4種は合計**99件**だった。K02/K03/K07の93件はすべて
`FF:0D, FF:0C`の後に値を記録しない単発`OUT $FD`で閉じた。この応答値の
規則は既存仕様1.24節を参照し、ここでは再掲しない。

残るK00の6件は一意ではない。3条件とも、実行最初のrunに現れたK00は列A、
後段でK05の直後に現れたK00は列Bだった（各3/3、文脈まで含めれば例外0件）。
しかし、**K00という種別だけからはA/Bを決められず、種別ごとの列という
今回の問いには2変種・例外3件が残る**。また、K00列Bだけがrun終端前に
`OUT $FC`を1件伴うが、その値は扱っていない。

### READ種別

1.36節のREAD 4種（K01/K05/K06/K09）は合計**39件**で、全39件が
`FF:0D, FF:0C, F8×1, FB:0F`の同一列だった（例外0件）。すなわち最後の
受信後、単発TCを1件出してからFDCのSEEKを開始する。これは1.26節の単発TCと、
1.27〜1.29節の準備列がSEEKから始まる記述に一致する。window(a)は最初の
`OUT $FB`で終わるため、それ以後のSENSE系・READ DATA本体は今回の列には
含めていない。

### その他

K04の9件は単発`OUT $FD`、K08の1件はFDCオペコード`04`でrunを閉じた。
これらはいずれも観測範囲では例外0件だった。

## 介入を行わなかった理由・未確定

10種中9種は種別ごとの出力列が一意だったが、K00だけは同一種別6件が二列へ
3件ずつ分かれた。したがって問2の前提である「種別ごとの完了遷移が例外0件」
は成立しない。文脈差を内部状態へどう写すかは今回の測定だけでは未確定であり、
推測で遷移を選ばず、一時ROM介入も恒久実装も行わなかった。

仕様書、`docs/PLAN.md`、`src/`、`tools/harness/romram_selftest.sh`は変更して
いない。
