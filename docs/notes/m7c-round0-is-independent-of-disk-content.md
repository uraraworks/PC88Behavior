# m7c: ラウンド#0はディスク内容に依存しない

測定日: 2026-08-13

## 1. 目的と情報境界

m7bでは、参照ディスクを使う既存4条件でラウンド#0の要求2バイトと
応答1バイトが固定であることを確認した。しかし全条件が同じディスクを
使っていたため、固定性がディスク内容に由来する可能性は残っていた。

今回は、ディスク無しのN88-BASIC ROM起動と、
`tools/make_l3_testdisk.py`で規則から生成した自作D88を追加して比較した。
`private/`配下はディレクトリ名の一覧だけで所在を確認し、公式ROM・公式
ディスクのパスは`PC88_REF_ROM_DIR`と`PC88_REF_DISK_DIR`を介して測定
フロントエンドへ渡した。内容を直接開く操作は行っていない。

生ログは一時ディレクトリだけに置き、比較終了時に削除した。値は比較器の
内部だけで扱い、標準出力、本稿、コミットメッセージには残していない。
記録したのは交換の有無、長さ、同値グループ数、位置ごとの同一・相違だけ
である。実装コードは変更していない。

## 2. 条件とフレーム数

次の3条件を35フレームで測定した。

- 参照ディスク起動: m7bの既存4条件が属する同値群の代表
- ディスク無し起動
- 規則生成した自作D88を挿入した起動

ディスク無し条件は、35フレームでラウンド#0が観測されなかったため、
単なる遅延でないことを確かめる対照として600フレームでも再測定した。
これは既存`measure_suite.sh`の`idle-noinput`と同じフレーム数である。

## 3. 比較器の検出力

本測定前に、既存`tools/cmp_io_selftest.sh`を実行し、全項目が通過した。
さらにラウンド#0だけを抽出する一時比較器を用意し、次を確認した。

- 既知の同一入力を一致と判定する
- 応答を意図的に1バイト変えた入力を相違と判定する
- 要求を意図的に1バイト変えた入力を相違と判定する

3項目とも通過した後に本測定へ使用した。一時比較器は測定後に削除し、
リポジトリには残していない。

## 4. 測定結果

35フレームの参照ディスク条件と自作D88条件では、どちらもラウンド#0が
観測された。

- 応答長は両条件とも1バイトだった。
- 応答は1同値グループで、位置1は同一だった。
- 要求長は両条件とも2バイトだった。
- 要求は1同値グループで、位置1・位置2とも同一だった。

m7bで参照ディスクの既存4条件がすでに1同値グループと確認されているため、
推移的に、既存4条件と自作D88条件の全条件で要求・応答が同一である。

ディスク無し条件では35フレーム、600フレームのどちらでもラウンド#0が
観測されなかった。この条件には比較対象となる要求・応答値自体が存在せず、
値の同一・相違は判定不能である。フロントエンドがディスク無し起動を拒否
したのではなく、起動は完了した上で交換が発生しなかった。

## 5. 判定

**ラウンド#0が発生するディスク挿入起動では、要求2バイト・応答1バイトは
ディスク内容に依存しない固定交換である。** 参照ディスクと、内容を規則から
生成した別系統の自作D88が全位置で一致したため、m7bに残った「同じ参照
ディスクだから固定に見えただけ」という交絡は除けた。

一方、ディスク無し起動では同じ交換を別値で行うのではなく、観測範囲内で
交換そのものを行わない。したがって「ディスクの有無にかかわらず必ず行う
固定交換」とまでは言えず、固定性の主張は交換が発生する条件に限定する。

## 6. 限界

- 別ディスク条件は規則生成した自作D88の1種類であり、複数のフォーマット、
  ライトプロテクト状態、ドライブ構成までは横断していない。
- 同じ公式ROM一式と同じエミュレータ設定での測定であり、ROM版や機種構成を
  またぐ固定性は未確認である。
- ディスク無しの非発生確認は600フレームまでであり、無限時間の非発生を
  証明するものではない。
- 交換の意味論は今回も特定しておらず、値を実装へ焼き込む根拠にはしない。
