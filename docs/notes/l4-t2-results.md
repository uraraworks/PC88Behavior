## 確定した観測規則と限界

全操作は番号付きプログラム内で行い、finish後もGOTOで実行待機を続けて採取した。以下はこの状態の文字セル・公開CSRLIN/POS・ERRの観測規則である。描画属性、KEY状態の内部値、直接モードへ戻った後の更新は測っておらず、文字セル残存から実表示の点灯/消灯や一般的なKEY OFFの効力を断定しない。

1. 起動無打鍵のbootは20行・80桁、最下行19に21非空白セル。行20..24は非表示。WIDTH 80,20の最下行セル署名と一致した。WIDTH 80,25/40,25は最下行24、80,20/40,20は19。80桁の最下行は21セル、40桁は20セル。表示行数は腕の予定値ではなくCRTC設定、桁数はポート0x30から確定した。

2. KEY OFF/ON/OFF→ONはいずれも受理、全表示行の文字セル署名・個数はWIDTH 80,25直後と同じで、最下行24は21セル。OFF後の消去という事前予測は外れた。OFF後CLS、ON後CLSも文字セルは各対応腕と同一。OFF後WIDTH 40,25/80,20は、KEYなしの対応WIDTH腕と全表示行が同一（20/21セル）。これらの文字セルだけからON/OFF状態の保持・復帰は判定できない。

3. KEY ON/OFFのどちらでもLOCATEで行24を指定した印字は受理、CSRLIN24/POS5、最下行26セル。最下行は基準21から26セルに増えた。ONなら最下行指定を制限するという予測は外れた。一方、行22から3行PRINTすると両腕とも作者入力から作った候補ID scroll-marker-a/b/cが行20/21/22にそれぞれ一致し（各5セル）、CSRLIN23/POS0、行23は0セル、最下行24は基準21セルを保持した。自動スクロール下端は両腕とも23で、最下行の明示LOCATE受理とは別の規則である。

4. CONSOLE 5,10後のKEY ON/OFFはともに受理。行14からのPRINT後はCSRLIN14/POS0、行13に作者入力の候補ID bottom-markerが一致（5セル）、行14は0セル、最下行24は21セル。両腕の全表示行署名・個数は同じで、この操作では窓の下端14が維持された。上端5でのスクロール作用は直接試験していない。

5. KEY番号は0/11がERR5（段40、1回）、1/5/6/10は受理。測った端点と代表点は1..10の仮説に一致するが、2/3/4/7/8/9は個別には未測定。assign-1は候補assignedが開始桁6、assign-5は開始桁62に一致、contrastは双方0一致。最下行はそれぞれ21/22セル。assign-6/10は受理だが変化セル0で表示比較不明、最下行21セル。押下・Shift切替・割り当て内容の展開は未測定。

6. KEY 1へのSTRING$長0/15/16/17/255は全て受理。長0の最下行は16セル、15/16/17/255は27セルで全表示行の署名も一致した。長256はERR5、最下行21セル。STRING$境界を含むため256のエラーをKEY専用上限とは断定しない。15を越えた文の受理は確定するが、保存長・保存内容の切詰め・押下時展開長は不明。表示セルの飽和は保存の飽和を意味しない。数値を第2引数にした腕はERR13。

7. KEY LISTは受理、CSRLIN6/POS0。基準の最下行24（21セル）を除く非空行は1..5の5行、個数は10/7/9/10/9、合計45セル。全表示中では6非空行・66セル。内容・列挙されたキーの範囲は解釈せず、出力された非空行数とセル数だけを確定する。
