# l4-dfin 倍精度定数読み取り手順の探索ノート（DREP10、事後の当てはめ）

## 出所

本ノートは Codex（`gpt-5.6-sol`、MCP経由）が GW-BASIC MIT公開ソース
（コミット `edf82c2ebf6bfe099c2054e0ae125c3efe5769c4`）の
`MATH1.ASM`・`MATH2.ASM` と、l4-s4k の**実測結果**（自分で打った式の
PRINT出力、親セッションから渡された値、候補表
`docs/notes/l4-s4k-candidates.tsv`・対照表
`docs/notes/l4-s4k-controls.tsv`）から導出した分析を、要点だけ引き継いだ
ものである。分析の作業ファイル自体（`dfin-model-search.md`・
`dfin_model_search.py`）はセッション固有の scratchpad にあり、本
リポジトリには入れていない（測定した生の値そのものは本ノートにも転記
していない。クリーンルーム規律7番「画面本文を報告・ノート・コミット
メッセージへ書かない」に従い、腕のラベル・一致件数・丸めの違いといった
統計的・構造的な要約だけを記す）。

**事後の当てはめであることを明記する。** DREP10（の2変種DREP10E/
DREP10A）は前向きの測定では確かめていない。l4-s4k の実測36件（候補24件
+対照12件）にモデルを当てはめて事後的に選んだ候補であり、これから先の
GW-BASIC/N88-BASICの他の腕でも成り立つ保証はない。

## 背景

l4-s4k で検証した3候補（DEXACT・DGW・DREP01、いずれも
`docs/notes/l4-s4k-double-fin-candidates.md`参照）は、l4-s4kの実測
36件のどれも完全には再現できなかった（no_survivor）。DREP10はこれに
続く4つ目の候補である。

## DREP10 の定義

1. 数字を先頭から `acc = acc*10+d` で積み上げる（$FIDIGどおり、
   `$MUL10`と`$FADDD`を別々に呼び、桁ごとに2回丸める）。
2. 正味の指数 `n`（`e`の値から小数点以下の桁数を引いたもの）について、
   `n>0` なら10を、`n<0` なら**真の10**を、`n` の絶対値の回数だけ
   1回ずつ掛ける/割り、**毎回**倍精度(56bit仮数)へ丸め直す。
3. 丸めの半端（タイ）の扱いには2変種がある: **DREP10E**は最近接偶数
   （round-half-even）、**DREP10A**は絶対値の大きい側
   （round-half-away）。l4-s4kの実測36件はどちらでも全件一致するため、
   この2変種では区別できなかった。
4. 符号は最後に付ける。

l4-s4kのDREP01（負の正味指数側は「倍精度に丸めた0.1」との反復乗算）との
違いは負側だけである: **DREP10は真の除算を反復する。**

## ソースで確認できたこと（GW-BASIC MIT公開ソース、edf82c2）

- `$FIDIG`: 整数は16bit整数の厳密な`×10+d`、単精度が100万以上なら倍精度へ
  昇格。倍精度では`$MUL10`と`$FADDD`を別々に呼ぶ。
- **`$FMULD`/`$ROUND`（倍精度乗算・正規化・丸め）と`DDIV`（倍精度除算）
  は、拡張byte（ガード）へ`80h`を加えてcarryを伝播し、厳密な半分では
  保持仮数のLSBを0にする——最近接偶数であることが命令列から確認でき、
  かつ捨てる下位バイトの非ゼロをstickyへ畳み込む構造になっている。**
  DREP10Eの丸め規則の根拠はここにある。
- `$DIV10`/`$MUL10`（倍精度版）はいずれも`$FMULD`を呼び、`$DIV10`は
  丸め済み倍精度定数`0.1`を掛ける（真の除算ではない）。つまり
  **ソースの`$DIV10`自体はDREP10ではない**（DREP01の根拠であって、
  DREP10の「真の÷10」はソースの`$DIV10`とは別の手順である）。
- `$FINE`/`MDPTEN`（定数の指数適用）自体は、倍精度`10^n`表を使う
  **一括**乗算/除算であり、1桁ずつ反復する分岐ではない。**つまり
  「1桁ずつ反復する」というDREP10の手順自体は、l4-s4kの実測36件から
  得た事後の推測であり、edf82c2のソースに直接の根拠はない。**

## 一致数（要約、測定結果は転記しない）

l4-s4kの実測36件（候補24件+対照12件、ラベルのみ、内容は転記しない）に
複数の候補モデルを当てはめたところ、DREP10（丸め方は最近接偶数・絶対値の
大きい側のどちらでも）だけが全36件を再現した。DEXACT/DGWは約8割
（29/36）、l4-s4kのDREP01は半分に満たない一致率だった。丸め済み倍精度
0.1をそのまま使う版・0.1定数を1ULPだけ下げた版など、他の反復パターンも
複数試されたが、いずれもDREP10には届かなかった。

## リポジトリへの実装

`tools/l4_dmodels.py` に `drep10e`/`drep10a` を追加した（l4-s4kのDEXACT/
DGW/DREP01と同じ独立実装の方針。`tools/l4_mbf_oracle_v2.py`は変更して
いない）。Codexの`dfin_model_search.py`（scratchpad）と乱数1万件で
バイト単位の完全一致を確認した（突き合わせの過程で、数字の積み上げを
「1回でまとめてround」していた自分の実装ミスを見つけ、`$MUL10`→`$FADDD`
を別々に呼ぶ構造どおり「2回round」に直して一致させた）。

候補・対照・手検算の詳細は
`docs/notes/l4-s4l-double-drep10-variants.md`参照。DREP10E/DREP10Aを
見分ける式は正の指数側（×10の反復）でしか見つからず、負の指数側
（真の÷10の反復）は10万件以上探索しても1件も見つからなかった
（理由の見立ても同ノートに記載）。

測定はしていない。判定には使わない。
