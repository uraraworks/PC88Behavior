# l4-s1g — 事前登録への追補（settle手順の訂正、起動時入力待ちの切り分け）

記録日: 2026-09-19
状態: 本走（settleを訂正した後の本走）の**前**にコミット。判定名・関門の
意味は事前登録本体と同じ。

## 経緯

本走の直前、RETURN(`01:7`)単体の切り分けで、**完全に空白の行で
RETURNを押しても、内容に関係なく毎回同じ4行分の反応（非空白件数が
固定のパターン）が出る**ことが分かった。`print 12`を打ってから押した
場合と、何も打たずに押した場合とで、この反応が同一だった
（コーディネータへの報告のとおり）。

## 切り分け（予備走、本走の腕数には数えない）

コーディネータの仮説H1「起動時の入力待ちが残っている」・H2「`01:7`が
ROMにとってのRETURNではない／コアの癖」を、件数・座標だけで切り分けた。

- **a. 無打鍵での起動画面**: 何も押さずにframe700で写しを取ると、
  非空白はrow1（19件、列0〜20の範囲）とrow19（ファンクションキー表示、
  21件）のみ。目印文字を直接押すと**row1・列22**に現れた（起動画面の
  非空白セルの直後）。700フレームからさらに待っても内容は変化しない
  （安定した状態、起動処理中ではない）。
- **b.（H2の確認）**: `01:7`単体の押下で反応が出ること自体は、RETURNが
  無反応な訳ではないことを示す（無反応なら陰性対照相当になるはず）。
  `--type`との比較（`--type-at`+`'\n'`）は今回は行わず、bの代わりに
  cで直接H1を検証した（効率のため）。
- **c. RETURNを2回押す**: 1回目（frame700）を押すと、row1の内容は
  変化せず、その直後（row2〜row5、既存のrow1の下）に4行分の反応が
  現れた（件数はrow2=22・row3=27・row4=14・row5=3、a.で観測した反応と
  同一）。続けて2回目のRETURN（frame1000、十分な間隔を空けて）を
  押しても、**非空白件数はどの行も一切変化しなかった**（1回目の反応が
  出た後の状態で2回目が無反応＝直接モードに入ったことと整合）。
  さらに続けて`print 12`+RETURNを打つと、出力行の署名が候補表の
  `print_12`（`docs/notes/l4-s1g-candidate-table.json`）と**完全一致**
  した。
- **H1の判定: 支持された。** frame700時点の画面は、直接モードの入力
  受付ではなく、何らかの起動時の入力待ち（`docs/spec/l3-main.md`
  第9節が「row1、列0〜18付近の非空白19件」とだけ記録していた内容が
  その問いの表示だったとみられる）の状態だった。最初のRETURNがその
  問いへの応答として働き、起動が先へ進む（4行の反応、`Ok`相当の行を
  含む）。2回目のRETURNは、その後の真の直接モードでの「空行RETURN」
  として無反応だった。
  **H2（`01:7`がRETURNでない・コアの癖）は棄却する**: `01:7`は
  2回目以降・`print 12`後、期待どおりRETURNとして機能している
  （`print_12`候補と一致）。

## l4-s1f（第1弾）への影響の確認

[l4-s1f-screen-editor-results](l4-s1f-screen-editor-results.md)
「前提についての注記」節（コミット`69be0ef`）に記録したとおり、代表
8項目（矢印4種・INS/DEL無修飾・SHIFT+INS/DEL・HOME/CLR無修飾を行の
途中で各1腕、境界B2・B3）を、RETURNを2回押して真の直接モードに入った
ことを確認した状態で取り直し、**判定名はすべて一致**した
（`no_change`・`row_move`・`del_left`・`ins_mode_only`・`clear`・
`wrap_prev_line_end`・`boundary_no_op`）。絶対座標（row0=1・col_start=22

（マーカーは列0から始まる）。l4-s1fの判定名は撤回せず、座標だけを
「入力待ち中の値」と明記し直した。

## settle手順の訂正

事前登録本体「器具の使い方」節の「HOME/CLR（無修飾）で画面を初期化して
から各腕を始める」の**前に**、次の手順を追加する（判定名・関門・候補・
腕数は変更しない。前提の具体化のみ）。

1. RETURN(`01:7`)を1回押す（frame700目安）。
2. 十分な間隔（300フレーム目安、反応が収まるのを待つ）を置いて、
   RETURNをもう1回押す。
3. **関門G11（新設、settle確認）**: 2回目のRETURN前後で、画面全体の
   非空白件数が変化しないことを`--nonblank-summary-rows`で確認する。
   変化していれば、まだ直接モードに入っていないので、3回目のRETURNを
   同様に押して再確認する（本ノートの実測では2回で収まった）。
4. 以降、事前登録本体どおりHOME/CLR初期化 → 各群の手順、に進む。

各腕の打鍵計画は、この settle 手順（RETURN×2、G11確認）をHOME/CLRの
前に付加するだけで、それ以外（HOME/CLR以降の手順・候補・判定名）は
事前登録本体を一切変更しない。
