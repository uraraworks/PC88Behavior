# l4-s1f — スクリーンエディタ（カーソル移動・INS/DEL・HOME/CLR・RETURN再読込）— 事前登録

記録日: 2026-09-19
状態: 事前登録、測定前
改訂1（2026-09-19、測定前のレビューによる修正）: 親によるレビュー
（コミット`e07096a`に対する指摘）を反映。INS/DEL・HOME/CLRの候補を
それぞれ4種・2種に増やし無修飾/SHIFTどちらの条件にも同じ候補集合を
当てるよう変更、SHIFT腕の差分モードに`--count-only-rows 19`を全腕
共通で付けるよう変更、←の行頭・↑↓の各腕に前後の行へ移る候補を追加、
腕数の記述の食い違い（誤って「72腕」「64腕」としていた箇所）を24腕に
統一。詳細は本版の各節、および該当コミットメッセージ。

## この番号を選んだ理由

既存の段階1測定ノートは `l4-s1a`（テキストVRAMの属性・カーソル位置・
スクロール）〜`l4-s1e`（既定の属性域とスクロール範囲）まで進んでいる
（[l4-design](l4-design.md)）。本ノートはそれらの続きで、`l4-s1a`〜`l4-s1e`
いずれも対象外としてきた「編集キー（カーソルキー・INS/DEL・HOME/CLR）が
画面編集に対して何をするか」を扱うため、次の空き記号 `s1f` を使う
（`m7*`ではなく`l4-s1*`とする理由は[l4-design](l4-design.md)本文に既述の
とおり、M7という節目の中の「main側L3の測定」段階1に属するため）。

## 位置づけ

[l4-design](l4-design.md) 段階1（main側L3の測定）のうち、`l4-s1b`
（[key-matrix](l4-s1b-key-matrix-preregistration.md)）が測ったのは
「キーを1回押すとカーソル位置に何の文字コードが書かれるか」（無修飾・
修飾込み）だけである。そこでは `01:7`（RETURN）・`08:0`（HOME/CLR）・
`09:0`〜`09:5`（STOP・f1〜f5）・`0B:0`・`0B:1`（ROLL UP/DOWN）の10キーは
押すと複数セルが変化するため「未判定」のまま
（`docs/spec/l3-main.md` 第9節・第16節項4）、`08:1`〜`08:7`（↑/→/INS・
DEL/GRPH/カナ/SHIFT/CTRL）と`0A:0`〜`0A:4`（TAB/↓/←/HELP/COPY）は
「書かない」（`no_write`）で判定が止まっている。

**本ノートはこの「未判定」「no_write」の中身、すなわちこれらのキーが
画面編集（カーソル移動・挿入・削除・消去・再読込）として何をするかを
測る事前登録である。実装は行わない。測定のみ。今回はエミュレータの
実行（測定）そのものは行わず、器具・関門・判定名を固定するところまで。**

## 対象キー

`docs/spec/l3-main.md` 第9節（Q1文字コード対応表）と、
[refs-pc8801ma-manual](refs-pc8801ma-manual.md)（キーマトリクス表、
PDF p.233）の対応から、次の6キー・8「キー条件」（INS/DELとHOME/CLRは
無修飾／SHIFTの2条件ずつ数える）を対象とする。

| # | キー | port:bit | 修飾 |
|---|---|---|---|
| 1 | ← | `0A:2` | 無 |
| 2 | → | `08:2` | 無 |
| 3 | ↑ | `08:1` | 無 |
| 4 | ↓ | `0A:1` | 無 |
| 5 | INS/DEL | `08:3` | 無 |
| 6 | INS/DEL | `08:3` | SHIFT(`08:6`) |
| 7 | HOME/CLR | `08:0` | 無 |
| 8 | HOME/CLR | `08:0` | SHIFT(`08:6`) |

根拠: `docs/spec/l3-main.md` 第9節の `no_write`／未判定の内訳
（`08:1`〜`08:7`＝↑/→/INS・DEL/GRPH/カナ/SHIFT/CTRL、`0A:0`〜`0A:4`＝
TAB/↓/←/HELP/COPY、`08:0`＝HOME/CLR）と、
[refs-pc8801ma-manual](refs-pc8801ma-manual.md) 1節のキーマトリクス表
（`08H`列: D0=HOME/CLR, D1=↑, D2=→, D3=INS/DEL, D4=GRPH, D5=カナ,
D6=SHIFT, D7=CTRL。`0AH`列: D0=TAB, D1=↓, D2=←, D3=HELP, D4=COPY,
D5=テンキー−, D6=テンキー/, D7=CAPS）。

`INS/DEL`は物理的に1キー・1ビット（`08:3`）で、無修飾／SHIFTのどちらが
INSでどちらがDELかは資料からは決め打ちしない（下記「資料との照合」参照）。
同様に`HOME/CLR`も1ビット（`08:0`）で、無修飾／SHIFTのどちらが画面消去
（CLS相当）でどちらがカーソルホームかを測定で決める。

### 対象外（第2弾以降）

- CTRL+`C`・`L`・`M`・`U`（`docs/spec/l3-main.md` 第16節項4。複数セル変化で
  未判定のまま）。制御文字系は別の事前登録に回す。
- `09:0`〜`09:5`（STOP・f1〜f5）・`0B:0`・`0B:1`（ROLL UP/DOWN）。ファンクション
  キーの既定割り当て文字列はROMのデータ表の再構成になり扱いを先に決める
  必要があるため（`l4-s1b-key-matrix-preregistration.md`と同じ理由）、ROLL
  UP/DOWNはプログラムモードのEDITコマンド（複数行）が前提になるため、
  いずれも本ノートの対象外。
- 数字・記号キーへの編集キー適用（対象は英大文字マーカーのみ）。
- **RETURNによる「画面の行を読み直して実行する」動作は、当初案では本ノートに
  含める予定だったが、腕数を抑えるため第2弾に回す。** 理由:
  (1) 下記Q1〜Q3だけで8キー条件×3位置=24腕（後述）になり、RETURN再読込
  （最低でも「戻って書き換える」×複数腕）を足すと判定モデルが混ざる、
  (2) RETURN自体は`01:7`が押すと複数セル変化する（未判定）キーであり、
  `l4-s1b`のQ3で`0CH`〜`0EH`のRETURN(JIS)/(10KEY)とは別に、`01:7`の
  RETRUN本体の判定（単独で押したときの効果、エコー行の実行）をまず
  固めてから、カーソル移動後の再読込という複合動作に進むほうが、
  `l4-s1b`の`reflow`誤判定（判定名に無い名前を使ってしまった事故、
  `l4-s1b-key-matrix-results-q1q3.md`追記）と同じ轍を踏まずに済む。

## 問い

- Q1（行内容）: 各キー条件を、マーカー文字列の行頭・行中・行末で押したとき、
  その行の文字域の内容（末尾空白を除いた並びの署名）はどう変わるか。
  変化しない／削除される／挿入位置が変わる、のいずれかを候補の生存で判定する。
- Q2（カーソル位置、経路A＝CRTC）: 同じ操作で、CRTC（ポート`50`/`51`、
  LOAD CURSOR POSITIONコマンド）に書かれる位置パラメータはどう変わるか。
- Q3（カーソル位置、経路B＝目印挿入）: 同じ操作の直後に別の目印文字を
  1文字打ち、その文字がどのセルに現れるかで、実際のカーソル位置を
  独立に確かめる。
- Q2とQ3が食い違った場合、どちらか一方を勝手に採らず、判定を割る
  （「関門G7」参照）。

## 資料との照合（候補の出所）

読んだのは『PC-8801FA／MA プログラマーズガイド』（PDFファイル名
`PC-8801FA／MA プログラマーズガイド.pdf`、`_emulator/PC88/refs/`
配下、`docs/notes/refs-nec-manuals-2026-09-04.md`で「条件付き可」判定済み・
禁止範囲はp.413-438と p.443-末尾のみで今回読んだ範囲の外）の
**第4章「スクリーンエディタ」冒頭、印字ページ39〜42**（PDFページ55〜58。
オフセット+16は同PDFの印字p.29＝PDFページ45との対応から確認した）。
節「2. 編集に使うキー」（p.39）・「3. ダイレクトモードにおけるスクリーン
エディタ 1.新規入力」（p.40）・「2.訂正」「3.削除」（p.41）・
「3.削除（続き）」「4.挿入」冒頭（p.42）を画像（`pdftoppm -r 100`）で読んだ。
本文はキーボードの一般的な使い方解説（第4章の目次にROM内部構造・
メモリマップの節は無く、`refs-nec-manuals-2026-09-04.md`が挙げる禁止範囲
（機械語モニタ・メモリマップ）より大幅に手前）であり、(a)の「使い方の事実」
に当たる。抜き書きはせず、以下は自分の言葉でまとめた事実（候補の根拠）。

- 「編集に使うキー」表（p.39）: 矢印4キーは「カーソルを上下左右に動かす」。
  「後退」（BS、本ノートでは対象外）は「カーソルの前にある文字を1文字削除」。
  「削除」キーも「カーソルの前にある文字を1文字削除」と同じ説明文。
  「挿入」キーは「インサートモードに入る/抜けるときに使用」（単独では
  文字を消さない・増やさない、モード切替のみ）。
  「画面消去」キー（本ノートのHOME/CLRに相当）は「単独で押すとテキスト
  画面(文字)を消去。SHIFTを押しながら押すとカーソルを画面の左上
  （ホームポジション）に移動」。
- p.40「ダイレクトモードにおけるスクリーンエディタ」冒頭の実行例:
  「入力の間違いに気がついたら、カーソルを間違っている位置に移動して
  入力しなおしてください」——上書き（オーバータイプ）が既定モードで
  あることを示す実行例（後述）。
- p.41「2.訂正」実行例: `LINE(0,0)-(300,100)` の `1` の位置へカーソルを
  移動し、`2` を打つと `100` が `200` に変わる（挿入ではなく上書き）、
  という具体例。RETURNを押すと編集後の行がそのまま実行される
  （画面上の文字列を読み直して実行、という設計の実行例）。
- p.41〜42「3.削除」実行例: カーソル位置で「削除」キーを押すと、その
  位置の文字が1つ減り、後続文字が詰まる。
- p.42「4.挿入」冒頭の実行例: 「挿入」キーを押すとインサートモードになり、
  文字を打つと「カーソルの位置から右側にある文字が1つ右にずれる」
  （右方向へのシフト、上書きと逆の詰め方）。

これらは(a)使い方の事実であり、(b)ROM内部構造ではない。**ただし、これは
汎用88キーボード図の解説であり、本節の「挿入」「削除」は別々の物理キー
として描かれている（本ノートの対象キーである、1ビットに同居した
`INS/DEL`とは配置が異なる可能性がある）。無修飾／SHIFTのどちらがINS
相当・DEL相当かは、この資料からは決め打ちしない。測定で決める。**
資料の格付け（測定>書籍>出典無しWeb）に従い、これらは**候補（仮説）の
出所**としてのみ使う。測定と食い違えば測定を採る。

**「削除」の説明文自体にも読みの曖昧さがある。** p.39の「削除」キーの
説明「カーソルの前にある文字を1文字削除」は、「前」を「カーソルより
手前（左）＝BSと同じ」と読むか、「カーソルの位置そのもの（画面表示上
カーソルの手前にある＝カーソルが乗っている文字）」と読むかで、削除
される文字が変わる。（余談として、同じ表で「後退」キーにも一字一句
同じ説明文が使われており、後退＝BS相当が「カーソルより左を消す」で
あることは疑いが薄いため、資料の文言だけでは「削除」キーがBSと同じ
挙動なのか、BSとは違う挙動（カーソル位置そのもの）なのかを資料からは
決め打ちできない。）このため下記候補では、削除系を`del_left`
（カーソルの左の文字を除いて詰める＝BS型）と`del_at`（カーソル位置の
文字を除いて詰める）の2候補に分けて両方当てる。挿入系も、p.42の実行例
（「挿入」キーでモードに入り、続けて打った文字が右に文字をずらす＝
INSキー単独では文字を増やさない）を素直に読めば`ins_mode_only`
（モード切替のみ、キー単独では行内容は不変）だが、本ノートの対象キーは
汎用図の「挿入」キーと配置が異なる可能性がある1ビットのキーなので、
対抗候補として`ins_space`（キー単独でカーソル位置に空白を1つ挿入し
右へずらす）も用意する。

CRTCのLOAD CURSOR POSITIONコマンド書式（`51`←`80`/`81`でカーソン表示
ON/OFF、続けて`50`←列、`50`←行の2バイト）は
[refs-vraminfo](refs-vraminfo.md) 第1節（μPD3301のコマンド定義、
ハードウェアの事実）による。これは既に`docs/spec/l1-ipl.md`・
`l4-s1a-text-vram-results.md`が使ってきた既存の解釈であり、本ノートが
新しく採用するものではない。**`l4-s1a`は「毎フレームのカーソン位置
再設定」を観測しただけで、編集キーを押した直後にこの値がどう変わるかは
まだ測っていない。** これが経路A（Q2）である。

## 打鍵の作り方（器具の使い方、既存確認）

- `tools/harness/frontend/main.c` 1766〜1776行: **`--key-matrix`と`--type`は
  同時指定できない**（同じ`key_scan`を書き換えるため、コア側の処理順に
  依存すると末端検査が不安定になる、という既存の設計判断）。したがって
  マーカー文字列も、押すキー（矢印・INS/DEL・HOME/CLR・目印文字）も、
  **すべて`--key-matrix`の複数指定で作る**（`--type`は使わない）。
- `--key-matrix`は1回のq88measure実行につき最大64個指定できる
  （`KEY_MATRIX_MAX`、`main.c` 235行）。1腕あたり「CAPS押しっぱなし
  （1）＋マーカー5文字＋位置決めの矢印キー数回＋測定対象キー1回＋
  目印文字1回」で見積もって20個前後、64個の枠に十分収まる。
- 英大文字での打鍵: `docs/spec/l3-main.md` 第7節（既定は英字小文字）・
  第10節（CAPS保持中は大文字化。例`Q`=`71`→`51`）による。**CAPSは
  保持型（トグルではない）**なので、マーカーを打つ全期間、CAPS
  （`0A:7`）を押しっぱなしにする。**SHIFTではなくCAPSを使う理由**:
  同節「SHIFT列」の記述により、SHIFT保持自体が単体でも約22セルの
  変化を伴う（原因未確定、恐らくファンクションキー表示行などへの
  副作用）ことが分かっている。CAPSは英字以外の38キーで「変化なし」
  （副作用なし）と確認済みのため、マーカーの行内容以外に余計な変化を
  持ち込まないCAPSを採用する。
- マーカー文字列: `QXZJK`（英大文字5文字、`docs/spec/l3-main.md` 第9節の
  Q1コード表でCAPS込みのコードが判明済み——`Q`=`51`、`X`=`58`、`Z`=`5A`、
  `J`=`4A`、`K`=`4B`——な、かつN88-BASICの予約語・一般的な画面文字列
  （`Ok`・`Syntax error`等)に含まれにくい5文字の並びとして選ぶ）。
- カーソル位置決め: マーカーを打つと、カーソルは自然に行末（マーカーの
  次の桁、列5）に来る。「行頭」（列0）へは`←`を6回（マーカー長5+余裕1）
  押して寄せる。「行中」へは`←`を3回押す（列2、マーカーの中央付近）。
  **この位置決めに使う`←`／`→`自体も対象キーだが、位置決めの押下は
  測定対象に含めない**（前後の写しは最後の1回＝測定対象キーの押下の
  前後だけで取る）。したがって「←キー自身」の行頭腕は、位置決めで
  ←を規定回数より1回多く押し（列0に達したあとさらに1回）、**その
  最後の1回だけ**を測定対象として写しを取る、という形にする（境界を
  超えて押したときの挙動を見る）。
- **マーカー行の行番号(row0)は決め打ちしない。** 起動シーケンスは決定論的
  だが（`l4-s1a`・`l4-s1b`で確認済み）、本ノートの打鍵列は`l4-s1a`・
  `l4-s1b`のどの既存シナリオとも異なる（マーカー5文字＋位置決め＋対象
  キー＋目印1文字の1本の連続チェーン）ため、マーカーが実際に何行目に
  入るかを走行前に断定しない。**測定担当は、走行後の写しからマーカーが
  実際に書かれたrow0を特定し、その行を「マーカー行」として以後の解析
  （row-signature・診断）に使う。**
- **マーカー行の上下（row0−1・row0+1）が空白であることを関門で確かめる
  （G9）。** ←の行頭腕（前の行末へ回り込む候補）と↑↓の各腕（前後の行へ
  移る候補、下記「候補」節）は、隣接行に何か書かれているとQ1の行内容
  判定・Q3の目印探索が汚染される。マーカー行の直前・直後の行が
  「非空白セル0件」であることを、対象キーを押す前の写しに対して
  `--nonblank-summary-rows`（追加B）で確認してから本測定に進む。
  空白でなければ、その回のマーカー開始フレームを前後にずらして
  隣接行が空くタイミングを探し直す（下書きの700フレームに固執しない）。
- HOME/CLR・INS/DELの無修飾／SHIFT腕は、`l4-s1b`のQ2（修飾×文字キー）
  と同じ形（修飾キーを対象キーの開始10フレーム前から押し始め、対象
  キーの保持期間を通じて下げたままにする）を踏襲する。
- 目印文字（経路B、Q3）: 対象キーを押した後に、マーカーとは別の1文字
  （`W`、コード`57`）を打つ。差分モード（`--diff-before`/`--diff-after`）で
  「押す前が空白だったセルに現れた文字」としてその位置を特定する。
- **`--count-only-rows 19`を24腕すべてに共通で付ける。** SHIFT修飾腕
  （6・8）はSHIFT保持自体がファンクションキー表示行（最下行、row0=19。
  `l4-s1b-key-matrix-preregistration-addendum2.md`14〜19行の数え方に
  合わせて確認する）を変化させることが分かっている
  （`docs/spec/l3-main.md` 第10節「SHIFT」の記述、`l4-s1b`のSHIFT対照）。
  無修飾腕とSHIFT腕を同じ解析条件で比べられるよう、SHIFT腕だけでなく
  無修飾腕も含めた全腕で`--count-only-rows 19`を付け、row0=19は文字
  コード・座標を出さず件数だけにする（`tools/l4_vram_probe.py`
  61〜71行の設計どおり）。
  **目印（Q3）がrow0=19に現れた場合の扱い**: `--count-only-rows`の
  指定により、その目印の位置・文字コードは出力されない（件数のみ）ため、
  経路B（Q3）では位置を確定できない。この場合は当該腕を「Q3欠測
  （row0=19、件数のみ）」と記録し、判定は経路A（Q2、CRTC）の値だけで
  行う。G7（経路一致）はQ3が欠測の腕には適用しない（不一致ではなく
  「片経路のみ」として区別する）。
- フレーム・保持・写しのタイミングは`l4-s1b`の値をそのまま流用する:

- 既存の`tools/harness/vram_dump_selftest.sh`・
  `tools/harness/vram_dump_dynamic_selftest.sh`・

## 候補（仮説）とその作り方

各腕について、次の手順で候補の期待値をあらかじめ計算し、実測の
`row_signature`（Q1）・CRTCパラメータ（Q2）・目印位置（Q3）と照合する。
候補は**測定の前に**このノートの範囲で書き出す。実測後に候補を後出しで
足さない（`l4-s1b`の判定名固定の作法を踏襲）。

### Q1（行署名）の候補の作り方

1. マーカー行の無編集時の文字コード列を、`docs/spec/l3-main.md` 第9節・
   第10節（CAPS列）の対応表から機械的に組み立てる（`QXZJK`→
   `51 58 5A 4A 4B`、列0〜4）。
2. 対象キーごとに、資料（上記「資料との照合」）から導いた候補操作を
   この列に適用し、結果の80バイト（列5以降は空白`0x20`）を作る。
   - **矢印4キー（無修飾）**: 候補「no_change」（カーソル移動のみ、行内容は
     元のマーカー列と同じ）。境界腕（←の行頭、→の行末、↑↓の全位置）には
     以下の対抗候補も用意する。
     - ←の行頭腕: 対抗候補「wrap_prev_line」（前の行の行末へカーソルが
       回り込む。この場合、マーカー行自体の内容は変わらないため
       `row_signature`だけでは`no_change`と区別できない——後述のQ2・Q3で
       区別する）。
     - →の行末腕: 対抗候補「wrap_next_line」（次の行の行頭へ回り込む。
       同様に`row_signature`だけでは`no_change`と区別できない）。
     - ↑↓の全位置: 対抗候補「row_move」（マーカー行の1行上/下へカーソルが
       移る。`row_signature`だけでは`no_change`と区別できない）。
     いずれも、`row_signature`が`no_change`と一致しても、Q2・Q3（後述）で
     実際にカーソルが移動先の行にあることが分かれば`wrap_prev_line`
     `wrap_next_line``row_move`を採用する。`row_signature`が「未判定」相当
     （複数セル変化、`l4-s1b`のreflow事故と同じ扱いで判定名は使わない）に
     なれば`boundary_reflow`と記録する。
   - **INS/DEL（無修飾・SHIFTの両条件に同じ4候補を当てる。どちらの条件が
     どの候補かは決め打ちしない）**:
     - `del_left`: カーソルの**左**の文字を1つ除いて後続を詰める（BS型。
       行頭では左に文字が無いため`no_change`とみなす）。
     - `del_at`: カーソル**位置そのもの**の文字を1つ除いて後続を詰める
       （行末では位置に文字が無い＝末尾の空白を除いても変化しないため
       `no_change`とみなす）。
     - `ins_mode_only`: キー単独では行内容は変わらない（モード切替のみ、
       `no_change`。p.42の実行例どおり）。
     - `ins_space`: カーソル位置に空白を1つ挿入し、右側の文字を1つ右へ
       ずらす（行末では右にずらす文字が無いため`no_change`とみなす）。
     4候補のうち`del_left`と`ins_mode_only`／`del_at`と`ins_space`は
     行頭・行末で`no_change`に縮退する組がある点に注意し、行中の腕
     （4候補が互いに異なる結果になる）を判定の主根拠にする。
   - **HOME/CLR（無修飾・SHIFTの両条件に同じ2候補を当てる。どちらの条件が
     どちらの候補かは決め打ちしない）**:
     - `clear`: 行全体が空白になる（署名は0バイト列のSHA-256）。
       `l4-s1b-key-matrix-results-q1q3.md`の`08:0`が複数セル変化だった
       既存観測（未判定）と整合するかどうかも見る。
     - `home`: 行内容は変わらない（`no_change`）。カーソルが画面左上
       （row0=0, col0=0）へ移る（Q2・Q3で区別）。
3. 各候補の80バイト列から、末尾の`0x20`を除いてSHA-256を取る
   （`tools/l4_vram_probe.py`の`row_signature()`と同じ正規化規則、
   84〜94行）。この値を判定表に事前に書き込む。

### Q2（CRTC）の候補の作り方

各候補は、Q1の候補と1対1で対応させ、[refs-vraminfo](refs-vraminfo.md)
第1節の書式（`51`←`80`/`81`、`50`←列、`50`←行）に沿って機械的に作る。
文言（実測値そのもの）はハードウェア設定値なので出力してよい
（`tools/l4_vram_probe.py`冒頭コメント5.、`docs/spec/l3-main.md`と同じ扱い）。

| Q1候補 | Q2候補（カーソル位置） |
|---|---|
| `no_change`（矢印、境界でない位置） | 列±1（←/→）または行±1（↑/↓）、行内容は元のマーカー行のまま |
| `wrap_prev_line` | 前の行（row0−1）の行末（列＝前の行の非空白末尾+1、もしくは列79）へ移動 |
| `wrap_next_line` | 次の行（row0+1）の行頭（列0）へ移動 |
| `row_move` | 同じ列のまま、行だけ±1 |
| `boundary_reflow` | 実測値をそのまま記録し候補としては扱わない（次の事前登録の材料にする） |
| `del_left` | 列−1（削除した分カーソルも左に詰まる） |
| `del_at` | 列は不変 |
| `ins_mode_only` | 列は不変 |
| `ins_space` | 列は不変（挿入した空白の上にカーソルが乗る） |
| `clear` | 列0・行0（画面消去後の既定位置。実測して次の候補生成に使う） |
| `home` | 列0・行0 |

### Q3（目印位置）の候補の作り方

- Q2の候補パラメータをそのまま列・行に変換し、「目印文字`W`(`57`)が
  現れるべきセルの(row0, col0)」を候補にする（上表の「Q2候補」列に
  対応する(row0, col0)を機械的に作る）。
- `wrap_prev_line`・`wrap_next_line`・`row_move`・`clear`・`home`の候補で
  移動先がrow0=19（最下行）になる場合は、上記「`--count-only-rows 19`」の
  節のとおりQ3では位置を確定できないため、候補表には載せるが判定は
  Q2のみで行う。

## 判定

- Q1: 各腕ごとに、`unique_survivor(候補名)`／`no_survivor`
  （どの候補とも一致しない）／`multiple_survivors(候補名の列挙)`
  （複数候補が同時に一致。候補設計が粗すぎたことを示す）。
- Q2・Q3: 各腕ごとに、実測したCRTCパラメータ・目印座標をそのまま記録し
  （ハードウェア設定値・自分で打った文字の位置なので出してよい）、
  Q1の候補判定との整合（「行内容の変化とカーソル移動の向きが矛盾しない
  か」）を注記する。
- G7で経路不一致となった腕は、Q2・Q3のどちらの値も採用せず
  「経路不一致」とだけ記録する。Q3が最下行(row0=19)への移動で欠測の
  腕は、上記「`--count-only-rows 19`」節のとおりG7を適用せず、Q2のみで
  判定する。
- **INS/DEL（4候補: `del_left`／`del_at`／`ins_mode_only`／`ins_space`）**:
  無修飾・SHIFTそれぞれの条件について、3位置（行頭・行中・行末）の
  `unique_survivor`結果が一貫していれば、その候補名をその条件の機能名
  とする（行頭・行末は`del_left`/`ins_mode_only`または`del_at`/
  `ins_space`が`no_change`に縮退するため、行中の腕を主根拠にし、
  行頭・行末は「縮退により`no_change`」であることの確認に使う）。
  無修飾とSHIFTで異なる候補（片方がdel系、もう片方がins系）に決まれば
  「無修飾=<候補名>、SHIFT=<候補名>」と記録する。同じ候補に決まった、
  一貫しなかった、あるいはどちらも`no_survivor`だった場合は「未決定」
  と記録し、次の事前登録で候補を作り直す。
- **HOME/CLR（2候補: `clear`／`home`）**: 無修飾・SHIFTそれぞれの条件で
  `unique_survivor`が一貫すれば、その候補名を機能名とする。両条件が
  同じ候補、あるいは`no_survivor`の場合は「未決定」と記録する。
- 行き先: `docs/spec/l3-main.md` のキー入力の節（第9節の`no_write`・
  未判定の記述を、本ノートの結果で更新する形。判定後の担当が行う）。
