# B67: F1 の腕で、自作が移らなくなる前後の要求の形を測る — 事前登録

記録日: 2026-11-02
位置づけ: [B66](b66-g1-f1-cross-table-results.md) の次段。[方針追補3](goal-b-policy-addendum3-request-headers-2026-10-31.md) の範囲で、要求の先頭バイトと長さ・形だけを記録する。**このノートは測定より先にコミットする。**

## 1. 問い

B65 の F1 の腕で、公式が 72・73 回目に移る前後に main が送る要求は何か（先頭バイト、大きさ、1 バイトずつか 2 バイトずつか）。自作は同じ要求を受けて何をするか。

## 2. 条件

B65 の F1 の腕と同じ打ち方とディスク。io ログがあふれないよう、フレームの窓に分けて走る。窓は 12000〜19800、19800〜27600、27600〜35400、35400〜43200 で、窓ごとに `--frames` を窓の終わり、`--io-log-from-frame` を窓の始めにする。公式・自作とも窓ごとに 1 走。クラウドの実行環境で行う。

## 3. 記録の白リスト

- `window <始め>-<終わり> cross=<公式> <自作> complete=<0|1> <0|1>`（窓の終わりの移る回数と、io ログの取りこぼしの有無）
- `req <O|S> <窓の始め> <番号> head=<2桁16進> size=<N> shape=<形> fc=<N>`（main が `OUT $FF` に下位 4 ビット 1 を書く所で切った要求ごと。B50 と同じ形の書き方。fc はその要求の前の `IN $FC` の回数）

**先頭バイト以外の値は出さない。**

## 4. 判定（事前に決める）

- 公式が 72 に移る窓で、公式と自作の要求の並びを比べ、最初に違う要求を書く
- 自作に実装の無い先頭バイトがあれば、その働きを自作のプローブで測る事前登録を書く
- 原因は断定しない
