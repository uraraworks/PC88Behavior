# B3: 起動を試みるかどうかを main が何で決めるか — 事前登録

記録日: 2026-10-25
位置づけ: [goal-b-policy-addendum1-boot-sector-2026-10-24.md](goal-b-policy-addendum1-boot-sector-2026-10-24.md) の範囲内
（起動用セクタの受け渡しの手前側）。[l3-boot-sector.md](../spec/l3-boot-sector.md) 第1版 1.2節の穴を埋めるための測定。
**このノートは公式 ROM での測定より先にコミットする。** 以降の集計・判定はここに書いた規則に従い、
結果を見てから規則を変えない（変えるときは後続ノートで理由を残す）。
このノートより前の日付で、この問いのために公式 ROM を走らせた測定コミットは存在しない。

## 1. 問い

公式の main は、起動用セクタの READ を sub に頼むかどうか（＝起動を試みる経路へ進むかどうか）を、
**何によって決めているか。** 外から観測できる入出力（ポートの番号・方向・読んだ値の別・フレーム）だけで答える。

### 1.1 背景

- 自作 ROM の配布ビルドに起動用セクタの受け渡しを試作したところ、ドライブ1にディスクが無いと sub が媒体待ち
  （[l3-subrom.md](../spec/l3-subrom.md) 1.62〜1.63節）に入り BASIC へ届かない（実装担当の報告。ブランチ `impl/l3-boot-sector`）。
- 公式 ROM はディスク無しのとき sub を一度も動かさず（l3-subrom 1.1節）、それは main 側（またはハード側）が作っている
  （同節 m7ar の 2×2）。
- [l1-ipl.md](../spec/l1-ipl.md) 第7節: ディスク無し・有りの main の OUT 列は 64 件目（無し `OUT C1`／有り `OUT FF`）で分かれる。
  つまり main は **sub と1度もやり取りする前に**決めている。その入力が docs/spec/ に無い。

### 1.2 結果を見る前に置く予測と、その出所（隠さない）

器具（第3節）を作るため、エミュレータ QUASI88 の**ソース**（`vendor/quasi88-libretro/src/pc88main.c`。公式 ROM ではない）を読んだ。
そこでは `IN 40` の bit3 がリセット時にドライブ1の媒体の有無から決まる（1 = ROM、0 = ディスク）作りになっていた。
**予測: 分岐を決める入力は `IN 40` bit3。ディスク有りで 0、無しで 1。**
これはエミュレータの実装を読んで立てた仮説であって、公式 ROM が何を見ているかの観測ではない。
だから第5節の規則は `IN 40` を特別扱いせず、全ポート・全ビットから機械的に候補を選ぶ。予測が外れたらそのまま報告する。
エミュレータで測った値はエミュレータの実装を測っている（実機の信号の名前・由来は言わない）。

## 2. 守る線

- 公式 ROM のバイト列・逆アセンブル・ROM 内部の構造（入口番地・ワークエリア）を見ない。
- **内部の実行経路（発行元 PC）は記録しない・出力しない。** iolog の `pc=` 欄は解析器の中でも使わない
  （分岐点はポートの並びで決める）。出すのはポート・方向・ビットの値の別・件数・フレームだけ。
- データポート（`FB`・`FC`・`FD`）の値は候補の探索に使わず、出力もしない（禁止事項5）。値の要る比較は件数だけにする。
- 画面本文は出さない。比較が要るときは署名（`tools/check_l3_screen_output.py` 系）だけ。
- 媒体は自作だけ（`tools/b2_make_boot_probe.py` の生成物）。公式ディスク・ゲームのディスクは使わない。
- 生ログは作業場 `PC88/tmp/b3-nodisk-work/` にだけ置く。

## 3. 器具

| 器具 | 役割 | 状態 |
|---|---|---|
| `q88measure --main-in-force PORT:BIT:VALUE` | main CPU の `IN PORT` の返り値の bit BIT だけを VALUE（0/1）に置き換える。sub CPU には効かない。走の終わりに `matched`（該当 IN の回数）・`changed`（実際に値が変わった回数）を標準エラーへ出す。iolog には置き換え後（CPU が受け取った値）を記録する | **これから作る**（コアのパッチ `tools/patches/0017`、フロントエンド）。公式 ROM を使わない自己検査（陽性・空の介入・別ポート）を通してから測定に使う |
| `--insert-disk2 M --insert-disk2-at 0` | ドライブ1を空のまま、ドライブ2にだけ媒体を入れる（既存。`--disk2` は二本起動専用でドライブ1が要るため） | 既存 |
| `tools/b3_analyze_boot_decision.py` | iolog から第5節の分類と候補探索を行う。`pc=` 欄とデータポートの値を読まない | これから作る（自己検査つき） |
| `tools/b2_make_boot_probe.py --arm ret --load-addr C000 --marker-layout none` | 自作媒体 M（(0,0,1) に戻る自作コード。b2 の A6 と同じ形） | 既存 |

コアは共有の `vendor/quasi88-libretro` の dylib を他の担当が使っているため、作業場で私用にビルドする。
0017 は機能を指定しない限り何もしない（既定の走に影響しない）ことを自己検査に含める。

## 4. 条件と腕

| 項目 | 値 |
|---|---|
| ROM | 公式 ROM（`PC88_REF_ROM_DIR` 相当の `private/rom`）。触るのは q88measure だけ |
| 打鍵 | なし |
| 走の長さ | `--frames 600` |
| 記録 | `--io-log`（main・sub）、`--mem-write-log`（`C000-C0FF` のみ。自作コードの控えの有無を b2 の抽出器で見るため）、終了時の画面署名 |
| 反復 | 腕ごとに2走 |
| 実行 | `env -u PC88_REF_DISK_DIR -u PC88_REF_DISKB -u PC88_GAME_DIR nice -n 10 …` |

| 腕 | ドライブ1 | ドライブ2 | 介入 | 目的 |
|---|---|---|---|---|
| N | 無し | 無し | なし | 基準（起動を試みない側） |
| D1 | M | 無し | なし | 基準（起動を試みる側） |
| D2 | 無し | M（フレーム0で挿入） | なし | ドライブ2だけに有るとき |
| X1 | 無し | 無し | 候補ビットを D1 の値に置換 | 陽性: 無しでも起動を試みる側へ入れ替わるか |
| X2 | M | 無し | 候補ビットを N の値に置換 | 陽性: 有っても試みない側へ入れ替わるか |
| C1 | 無し | 無し | 候補ビットを N の値（もともとの値）に置換 | 陰性（空の介入）: 器具そのものが分岐を変えないか |
| C2 | M | 無し | 候補ビットを D1 の値（もともとの値）に置換 | 陰性（空の介入） |

- **ディスク装置そのものが無い構成**は作れない。QUASI88 libretro 版のコア設定（`q88_*`）に、ディスク装置や sub CPU を
  外す項目が無い（2026-10-25 に設定名の一覧で確認）。この腕は「作れない」と記録する。
- X1・X2・C1・C2 は第5節 R1 で候補が決まってから回す。候補が予測と違っても、R1 が選んだものを使う。

## 5. 導出規則（事前に決める）

### R0 分岐の分類（1走ごと）

- **K1**: main の OUT のうち、ポートが `C1` か `FF` の最初のもの（どちらが先か）。
- **K2**: main の、ポート `FC`〜`FF` への IN/OUT の件数（値は見ない）。
- **K3**: sub の入出力の件数。
- **K4**: (0,0,1) の自作コードが実行されたか（b2 の抽出器が `C000-C0FF` の書き込み記録から控えを見つけたか。媒体の無い腕は「該当なし」）。
- 分類: **ROM 形** = K1 が `C1` かつ K2 = 0 かつ K3 = 0。**ディスク形** = K1 が `FF` かつ K2 > 0 かつ K3 > 0。どちらでもなければ **混在**（そのまま報告）。
- 分岐点のフレーム = K1 の OUT のフレーム。

### R1 候補の入力（N と D1 の4走から）

- 各走で、分岐点の OUT より前（iolog の順序で手前）にある main の IN を対象にする。ポート `FB`〜`FD` は除く。
- (ポート, ビット) ごとに、その走で読まれた値の集合を作る。
- **候補** = 次を全て満たす (ポート, ビット): N の2走とも集合が {a}、D1 の2走とも集合が {b}、a ≠ b、
  かつ4走の全てで分岐点より前に1回以上読まれている。
- 報告するのは候補の (ポート, ビット, a, b)、各走で分岐点より前に読まれた回数、そのポートが分岐点より前に
  初めて読まれたフレーム。候補でない (ポート, ビット) は「両条件で値の集合が同じ」「揺れる（片側で 0 と 1 の両方）」
  の件数だけ。
- 候補が 0 個: 止める（第6節）。1〜3 個: 各候補について X1・X2・C1・C2 を回す（候補ごとに別の走。同時には振らない）。4 個以上: 止める。

### R2 因果（候補ごと）

- **入れ替わった** = X1 の2走ともディスク形、X2 の2走とも ROM 形、C1 の2走とも N と同じ形、C2 の2走とも D1 と同じ形。
- 介入の末端検査: X1・X2 で `changed` > 0。C1・C2 で `matched` > 0 かつ `changed` = 0。満たさない走は結論に使わず、そのまま報告する。
- X1・X2 の一方だけが入れ替わった場合は「片方向だけ」と報告し、断定しない。

### R3 ドライブ2だけ

D2 の2走の分類と、候補ビットの値の集合を報告する（N・D1 のどちらに一致するか）。

### R4 走の中での変化

N・D1・D2 の各走で、候補ビットの値の集合を**走全体**（分岐点の後も含む）についても報告する。
走の途中で変わったか（媒体を後から入れたときの振る舞い）は、この測定では振らない（第7節）。

### R5 補助: 画面

N と X2、D1 と C2 の終了時（フレーム 600）の画面署名が一致するかだけを報告する（本文は出さない）。判定には使わない。

## 6. 止める条件（結果を見てから緩めない）

- R1 の候補が 0 個、または 4 個以上: 介入に進まず、その事実を結果ノートに書く。
  **候補を探すために ROM 内部（発行元 PC・実行経路）を見ることはしない。** それが要るなら「仕様に書けない」として止めて報告する。
- 同じ腕の2走で分類が食い違う: その腕は「揺れる」として結論に使わない。
- 介入の末端検査（R2）を満たさない: 器具を疑い、結論に使わない。
- 白リスト（第8節）に合わない出力、`private/` 由来の値・画面本文・ゲーム名が作業場の外へ出る気配: 即時停止し、
  [CLAUDE.md](../../CLAUDE.md)「汚染したとき」に従う。

## 7. この測定で言わないこと

- 実機の信号の名前・由来（何がこのビットを作るか）。エミュレータでは、その作りを読んで予測を立てた（1.2節）が、
  実機について述べる根拠にならない。
- 走の途中で媒体を入れた・抜いたときに分岐が変わるか（リセット時に決まるのか、読むたびに決まるのか）。ここでは振らない。
- 分岐の後の ROM の内部の手順。

## 8. 記録の白リスト（コミットするもの）

`measurements/b3-boot-decision.txt` に、次の行だけ:

- 走ごとの R0（K1 のポート、K2・K3 の件数、K4、分類、分岐点のフレーム）
- R1 の候補行（ポート・ビット・a・b・回数・初回フレーム）と、候補でないものの件数
- 介入の `matched`・`changed`
- R5 の署名の一致／不一致
- 各走の取得条件（腕・走・フレーム数・コアのパッチの版）

生の iolog・`--out`・書き込み記録はコミットしない。
