# m7bx: リセットで実行全体通番説は棄却したがK00のA/B規則は一意に定まらない

実施日: 2026-08-22

## 情報境界

公式ROM一式と公式diskAの複製を使い、既知3条件と追加8条件を新規実行した。
公式ROM・ディスクの内容は読まず、`private/`への`cat`/`xxd`/`od`/
`hexdump`/`strings`・逆アセンブルは行っていない。SAVE/KILL条件は原本でなく
使い捨て複製だけを書き込み対象とした。生iolog、ディスク複製、実行出力は
リポジトリ外の`mktemp -d`配下だけに置き、コミット対象にしていない。

解析では`$FC/$FD`値およびFDCデータ値を内部の分類以外に出さず、成果物と
標準出力にはK00〜K09、列A/B、件数、公開FDCコマンドの種類だけを出した。
diskBは`PC88_REF_DISKB`が未設定だったため使っていない。仕様書、PLAN、`src/`
は変更していない。

## 測定方法と検出力

`tools/analyze_k00_variants.py`を新設し、既存の
`analyze_record_boundaries.window_a_runs`と`analyze_write_path.parse_commands`
を再利用した。各K00について、最後の受信後から最初の`OUT $FB/$FD`までを
m7buの列A/Bへ構造分類し、K00通番、直前run、リセット以後のSPECIFY発行履歴、
READ DATA完走履歴と件数、完了FDCコマンド件数を対応づけた。READ DATA完走は
公開コマンド表に基づき、データ256件＋結果7件の入力が完了した場合とした。

`tools/analyze_k00_variants_selftest.sh`は公式データを使わない合成ログで次を確認した。

- 無傷ではA/B各1件と履歴状態を正しく分類する。
- データポートへ置いたダミー値が解析出力へ混入しない。
- B列の終端ポートを故障注入すると、無傷では0件だった「未知」が1件になり、
  陽性対照が実際の症状で不合格になる。

自己検査は無傷合格・注入不合格を確認してから実測へ用いた。

## 候補規則と判定

| 候補規則 | 例外 | 判定 |
|---|---:|---|
| 実行全体でK00初回ならA、以後B | 1 | d10の3件目がAなので棄却 |
| 各リセットepochでK00初回ならA、以後B | 0 | 残る |
| 直前runがK05ならB、それ以外A | 0 | 残る |
| SPECIFY未発行ならA、発行済みならB | 0 | 残る |
| READ DATA未完走ならA、1件以上完走済みならB | 0 | 残る |
| 完了FDCコマンド0件ならA、1件以上ならB | 0 | 残る |

リセット介入により、単なるフロントエンド実行全体の通番は反証できた。しかし、
subが保持可能な状態だけに限っても**5規則が例外0件で残り、一意に定まらない**。

これは標本数だけの問題ではない。列A自身が最後にSPECIFYを発行するので、通常の
到達可能列では「epoch初回A」と「以後SPECIFY済み」が因果的に共線になる。また、
観測した列Bはすべて固定した起動prefixのK05直後で、その時点にはREAD DATA 8件と
FDCコマンド47件が完了していた。ディスク操作を反復しても新しいK00は生じず、
ディスク無しではK00が生じず、V1H/V1SではAだけだったため、この共線性を崩せなかった。

識別に必要なのは、(a) epoch最初なのにB、(b) K05直後・READ完走後なのにA、
(c) K05以外の直後またはREAD未完走でB、のいずれかを公式subで生じさせる条件である。
観測対象のsubを診断ROMへ置き換えると公式sub自身の規則を測れないため、その介入は
採らなかった。利用可能な条件では該当例を作れず、推測で1規則を選ばない。

## 未確定事項

- 残った5規則のどれが公式subの実際の分岐状態か。
- diskBは今回未設定で未測定。ただし既存測定では`$FC`を使わない別経路なので、
  K00標本を与える保証はない。
- K00を起動prefix以外から発生させる、公式subを保ったままの安全な介入条件。

以上から、K00のA/Bをsub内部状態から一意に決める規則は**今回確定できない**。
