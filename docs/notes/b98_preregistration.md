# B98 事前登録：G5 の打鍵なしのずれは ROM の処理時間（割り込みの受理位置）から来るか

記録日: 2026-11-17。[B93](b93-results.md) で 7071 帰還直後の R は原因でないと分かった。残る候補は、自作 ROM の入口（3080・35CE・7071・6F6B など）の処理時間が公式と違い、その後の割り込みがゲームの別の命令の位置で受理される「時刻ずれ」である。値・画面本文・媒体名は公開記録に含めない。

## 腕

G5 は B93 と同じ配置、無入力、36000 フレーム。

| 腕 | ROM | 介入 |
|---|---|---|
| T-OFF-0a / 0b | 公式 | なし（基準2回） |
| T-OFF-4 / 8 / 40 | 公式 | 3080 の各呼び出しで、RET の後の最初の命令を fetch する前に CPU を 4・8・40 T ステート余分に止める（命令は変えない） |
| T-OFF-7071 | 公式 | 7071 の帰還時だけ 40 T ステート止める |
| T-SELF | 自作（main dbe1b37） | なし |

## 記録すること

- 各腕の boundary-timeline・main/sub I/O の見出し列（B93 と同じ器具）。基準との最初に分かれる件目と、そのフレーム番号。
- 公式と自作のそれぞれで、固定入口（3080・35CE・369A・37C9・37D2・3847・3391・6F6B・7071）の呼び出しごとの所要 T ステート（入口の命令 fetch から呼び元へ戻った最初の fetch まで）。番地ごとに件数・最小・最大・最頻値を出す。所要時間は振る舞いの測定値であり、ROM の内容ではないので公開してよい。
- 3080 は「キーなし」「押し始め」「押し続け」別に分けて出す（G5 の無入力では「キーなし」だけになる見込み）。

## 判定

- T-OFF-4/8/40 のどれかが基準と分かれ、T-SELF と同じ程度の画面ハッシュ不一致を出せば、ずれは処理時間由来と判断する。その場合、自作の各入口の所要 T ステートを公式の最頻値にそろえる（待ちの命令で埋める）実装へ進む。
- 余分な待ちを入れても公式が分かれないなら、処理時間説も否定し、T-SELF と公式の最初に分かれる件目の直前の区間を次に調べる。
- 基準2回が一致しなければ、公式自身に揺れがあるとして判定しない。
