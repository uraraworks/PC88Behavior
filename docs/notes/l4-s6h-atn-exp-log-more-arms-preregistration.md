# l4-s6h: ATN/EXP/LOGを腕数を増やして再測定する、事前登録

記録日: 2026-09-20
状態: 事前登録。**本ノートまでは測定未実施。**

## 位置づけ

l4-s6g(`docs/notes/l4-s6g-away-rounding-transcendentals-results.md`)で、
SIN/COS/TANの内部単精度演算はM9(round-half-away)で確定したが、
ATN(3腕)/EXP(2腕)/LOG(3腕)は割れる腕が少なすぎて決定できなかった
(ATNはM0(even)が2/3、EXPはM9(away)が2/2、LOGはM0が1/3・M9が2/3、と
関数ごとに逆方向・低確度の結果)。SQRは候補間で予測が1件も割れず、
判別不能のまま残っていた。本ノートはl4-s6gの申し送り
「割れる腕をそれぞれ10腕以上に増やして再測定すれば決定できる可能性が
ある」を実行する。

## 0. GW-BASICソース再読(改修履歴コメントの有無)

`tools/l4_mbf_oracle_v3.py`のdocstringが既に読了済みの範囲
(MATH1.ASM 1080-1143行=`$TAN`/`$ATAN`、3028-3092行=`$EXP`、
MATH2.ASM 998-1050行=`$LOG`)について、l4-s6b(`docs/notes/l4-s6b-
source-reread-and-selfcheck.md`)が見つけた「Changed COS to double
precision range reduction 24-JUN-82/NGT」のような、Microsoft社内の
日付・イニシャル付き変更履歴コメントが他にも無いかを確認した(MIT公開
ソース自体の再取得・再読、GW-BASICソースを読む行為自体は許可事項。
禁止事項2の対象である「逆アセンブルリスト・解析記事のコード断片」では
ない)。

結果: **ATN/TAN(1080-1143行)・EXP(3028-3092行)・LOG(998-1050行)の
いずれの範囲にも、精度・丸め方式に関する変更履歴コメントは見つから
なかった。** MATH2.ASM全体を走査しても、該当範囲外にある2件の変更履歴
コメント(1106-1107行「8-Mar-82/ngt Fix / Balance number of PUSHes and
POPs」・1449-1450行および1506-1507行「9-Aug-82/MLC - Good for LODC,
MOVW, ... / LODWs.」)はいずれもレジスタの退避・命令列のバグ修正に
関するもので、精度・丸め方式とは無関係だった。**l4-s6bが見つけたCOSの
「倍精度化」改修は、ATN/EXP/LOGには同種の手がかりが存在しない**
(=これらの関数がSIN/COSと同じ経緯で改修された形跡は、少なくとも
コメントからは見出せない)。

## 候補

l4-s6gと同じM0(`tools/l4_mbf_oracle_v3.py`、内部演算はround-half-even)
とM9(`tools/l4_mbf_oracle_v10_m9.py`、内部演算はすべてround-half-away)
を使う。SIN/COS/TANで使ったのと同一の候補対で、ATN/EXP/LOGの腕数だけを
広げる。

SQRについては、7桁以内の整数・小数(符号付き)を計算的に約76000通り
探索したが、M0とM9の予測が割れる入力は1件も見つからなかった
(`scan()`スクリプト、公式ROM不使用。整数1〜4999・負整数・.001刻みの
小数・ランダム生成の7桁小数、計約76000通り)。SQRは無理数のままなら
偶数丸め(M0)とaway丸め(M9)がタイに触れることは測度0で、7桁以内の
定数からはタイに触れる入力を作れないとみられる。**候補間で予測が
割れないため、本ラウンドではSQRを測定対象から外す**(l4-s6gの結論を
追認するだけになる)。

## 測定方法(l4-s6a/l4-s6g以来と同一)

- 公式ROM一式、ディスク無し、コア既定N88 V2。起動settleは
  `--type-at 300 --type '\n'`、実打鍵の開始は`--type-at 700`。
- 1文字あたりの反映フレームは既定(hold+gap=8フレーム/文字)。
- 各腕は打鍵の前(写し690固定)と、打鍵と実行が終わった後(表の
  写し(後))に`--vram-dump`で写しを取り、`tools/l4_vram_probe.py`の
  差分で出力行を特定する。`tools/l4_s4a_float_classify.py`で
  `numeric_output`判定と出力セル列挙を行う。
- 各腕2走(決定論性G3の確認)、公式ROMは環境変数`PC88_REF_ROM_DIR`
  (測定コマンドごとに指定、値は`private/rom`)経由で与える。
- 走行フレームは`写し(後)+200`。

## 関門(測定後に埋める)

| 関門 | 内容 |
|---|---|
| G1 器具の自己検査 | 測定直前に`tools/l4_mbf_oracle_v3_selftest.sh`・`tools/l4_mbf_oracle_v10_m9_selftest.sh`・`tools/harness/vram_dump_selftest.sh`・`tools/harness/key_matrix_selftest.sh`・`tools/harness/type_untypable_selftest.sh`・`tools/screen_content_leak_selftest.sh`・`tools/check_cleanroom.sh`実施、全項目OK |
| G2 取りこぼし0・打てない文字の警告0 | 84走全てrc=0 |
| G3 決定論性 | 42腕全てでrun1/run2の出力セル列挙(digit/symbolコードの並び)が一致 |
| G4 陰性対照 | l4-s6a以来の起動settleのみの走を流用(器具・条件不変) |
| G5 陽性対照 | l4-s6b追補1で確認済み(`print 7717`)を流用、器具・条件は不変 |
| G6 予測表の固定 | 本ノートのコミット時点で固定、以後変更しない |

判定は`predicted_match`(M9と一致)・`m0_match`(M0とのみ一致)・
`neither_match`(どちらとも不一致)・`both_match`(割れない対照腕で
両方一致)の4つ。
