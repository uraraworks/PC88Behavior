# m7gp: ディスク名がツール出力に出る経路を、ヘルパで1点に閉じた

実施日: 2026-09-04

## 何が2回起きたか

[m7gg](m7gg-data-disk-screening.md)の開示節と[m7go](m7go-write-data-unit-results.md)
の開示節に、それぞれ独立に記録されているとおり、`private/disk`配下の
実ファイル名が担当セッションの作業端末出力へ一時的に表示される事故が
2回起きている。いずれも成果物（コミット対象ファイル・ノート本文・
コミットメッセージ）には転記されておらず、気づいた時点で名前を出さない
方式に切り替えているが、**同じ形の事故が2回別々のセッションで起きた**
という事実は残る。

## 個々の不注意ではなく経路の問題である

2件の開示を並べると、原因は毎回違う（`echo`によるループ内容表示、
`declare -p`による配列内容表示、`while read`ループでの一覧表示）。
つまり「今回は気をつける」を積み重ねても、次に別の形で同じ事故が起きうる。

共通しているのは、**測定コマンド(q88measureへの`--disk`引数)を組み立てる
には、その時点でディスクの実パス（＝実ファイル名を含むパス）を扱わざるを
得ない**という構造である。名前を扱う場面が毎回のディスク選別作業に
存在する限り、デバッグ目的の一時的な表示コマンド1行が実ファイル名を
経由してしまう可能性は、人間の注意力だけでは閉じきれない。

これは`docs/notes/m7gd-boot-disk-screening.md`が確立した「ダイジェスト
だけで識別する」設計そのものは正しく機能している
（`tools/screen_boot_disks.sh`本体の標準出力・標準エラーには実際に
一度も実ファイル名が出ていない）こととは別の問題である。漏れが起きたのは
いずれも**成果物のスクリプトの外側**、その場限りのデバッグ操作でだった。

## ヘルパの設計

**ダイジェストを渡すと、中立な名前の使い捨て複製を作り、その中立パスだけを
返すヘルパを作った（`tools/stage_disk_by_digest.sh`）。** 以降のコマンドは
この中立パスしか扱わないので、実ファイル名が現れうる箇所が「ヘルパの内部で
`PC88_REF_DISK_DIR`配下を1回だけ照合する処理」の1点に閉じる。デバッグの
その場のコマンドが実ファイル名に触れる余地自体が構造的に無くなる。

- ダイジェストの計算は再実装せず、`tools/lib_screen_boot_disks.sh`の
  `digest_basename`（basename文字列のSHA-256先頭8桁、m7gdと同じ規約）を
  そのまま`source`して使う。
- `PC88_REF_DISK_DIR`（未設定時のフォールバックは`private/disk`）配下の
  `*.d88`/`*.D88`を走査し、basenameのダイジェストが一致する1本を探す。
- 一致0件・一致2件以上は**エラー終了**（`rc!=0`）にする。無言で1本を
  選ぶことはしない。エラーメッセージにも件数とダイジェストだけを書き、
  実ファイル名は書かない。
- 見つかった1本を、出力ディレクトリ（省略時は使い捨ての一時ディレクトリ）
  へ**`<ダイジェスト>.d88`という中立な名前で複製**する。元ファイルは
  読むだけで書き込まない（書き込みを伴う測定で複製が必要という既存の
  要件——`tools/screen_boot_disks.sh`が起動測定のたびに`disk_copy`を
  作っているのと同じ理由——も同時に満たす）。
- **標準出力へ出すのは、複製先の中立パス1行だけ。** `set -x`は使わず、
  候補一覧のデバッグ表示もしない。

以降の運用: **測定でディスクを扱うときは、まずこのヘルパでダイジェストから
中立パスを得てから、そのパスをq88measure（や他の測定スクリプト）へ渡す。**
例:

```
path="$(tools/stage_disk_by_digest.sh <ダイジェスト8桁>)"
q88measure ... --disk "$path" ...
```

## 自己検査（`tools/stage_disk_by_digest_selftest.sh`）

公式ROM・公式ディスク無しで、実物ではない合成フィクスチャ（わざと目立つ
`TOPSECRET_*`という名前の非実データファイル）だけを使い、以下を検査する:

- ダイジェストを与えると中立名の複製ができること、標準出力が複製先パス
  ちょうど1行であること
- 標準出力・標準エラーのどこにもフィクスチャの実ファイル名が現れないこと
- 複製が元とバイト一致すること、実行前後で元ファイルのハッシュが不変で
  あること（書き込んでいないこと）
- 一致0件・一致2件以上（`digest_basename`を固定値に差し替えたテスト用の
  複製`lib`で意図的に再現）がいずれもエラー終了(`rc!=0`)し、そのエラー
  出力にも実ファイル名が現れないこと
- 引数無し・不正な形式のダイジェストがエラー終了すること
- 出力ディレクトリを省略しても既定の一時ディレクトリへ複製できること
- **陰性対照**: 複製先パスを返す直前に`echo "...$MATCH_NAME" >&2`を注入
  した壊れた版を用意し、上の「実ファイル名が現れないこと」の検査が
  その壊れた版に対しては確かに**落ちる**ことを確認した（常に通過する
  検査ではないことの確認。壊れた版は本体スクリプトの一時コピーで、
  `tools/`配下の実体は変更していない）。

実行結果: 全項目OK、終了コード0（陰性対照が検出力を持つことも確認済み）。

## 限界

この対策は**このヘルパを使う限りにおいて**有効である。測定コマンドを
`PC88_REF_DISK_DIR`から直接パスを組み立てて呼べば、従来どおり実ファイル名
はコマンドライン・変数・エラーメッセージに現れる。ヘルパはその経路を
「使えば安全」にするだけで、**直接パスを組み立てる経路そのものを技術的に
禁止するものではない。** 強制はできない——今後の測定作業でも、まず
このヘルパでダイジェストから中立パスを得る、という運用上の徹底が引き続き
必要である。

## 情報境界 / 根拠リンク

公式ROM・公式ディスクのバイト列、公式ROMの逆アセンブル、`private/`の
内容（実ファイル名を含む）は本稿の作業・成果物に含めていない。本稿の
担当セッションは`private/`配下を`ls`していない。使用した合成フィクスチャ
はいずれも非実データ（`DUMMY-...`という文字列）で、公式ディスクの中身
ではない。

根拠（`ls`で存在確認済み）:
[m7gd](m7gd-boot-disk-screening.md)（ダイジェストの決め方の出所）・
[m7gg](m7gg-data-disk-screening.md)（開示節、1回目の事故）・
[m7go](m7go-write-data-unit-results.md)（開示節、2回目の事故）・
`tools/lib_screen_boot_disks.sh`（`digest_basename`・`list_disk_basenames`、
本稿では変更していない）・`tools/measure.sh`（`PC88_REF_DISK_DIR`の
フォールバック規約）・`tools/screen_boot_disks.sh`（中立パスへ複製する
発想の踏襲元）。
