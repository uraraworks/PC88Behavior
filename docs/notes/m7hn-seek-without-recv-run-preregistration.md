# m7hn: 受信runが先行しないSEEK段は何に駆動されているか — 事前登録

## 位置づけ

[m7hm](m7hm-recv-run-count-field-results.md)（訂正節込み）は、条件O・
`disk#10`の`FILES 2`ログに**受信runが1本も先行しないSEEK段が4件ある**ことを
確定した。m7hmの訂正節が示したとおり、この4件は**性質の異なる2種類の混合**
である。

| 群 | 定義 | 段数 |
|---|---|---:|
| 群A | 単発の段（`read_count == 1`）で候補0件 | 3 |
| 群B | READ DATAを1件も発行しない段（`read_count == 0`）で候補0件 | 1 |

さらにm7hmは、`read_count == 0`の段が全体で2段あること自体を見落として
いた（訂正済み）。**READ DATAを発行しないSEEK段という構造は、まだ一度も
記述されていない。**

**本稿はこの2群を別々に扱い、SEEKの引き金を値を出さずに切り分ける。**
`m7hm`が挙げた「次に測るべきもの」3項に対応する。受信runに駆動されない
SEEKが存在する以上、`general_read_request`が「要求ごとにSEEKし直す」と
いう構造（1.57節）を直す前に、**そもそもSEEKの引き金が要求だけではない**
可能性を潰しておく必要がある。

本稿は測定と記録だけを行い、`src/`は修正しない。新規ツールも原則作らない
（既存APIの組み合わせで足りる見込み。足りなければ結果ノートに明記する）。

## 段階0（本稿）: 事前登録を測定前にコミットする

本稿は解析を1回も走らせる前に単独でコミットする。測定後の書き換え・amendは
行わない。

**なお本稿は追加の実測を行わない**——m7hmが取得した条件Oのログ
（run1・run2、`cmp`でバイト単位一致）の**再解析のみ**で実施する
（`m6j`と同じ型）。ログが失われていた場合は、同一コマンドで再取得し、
バイト一致することを確認してから使う（一致しなければ判定Oとする）。

## 測定条件

- ログ: m7hmの条件O（A:=`disk#8`＝`650cfac8`、B:=`disk#10`＝`0c6f7a53`、
  `--type-at 300 --type '\n' --type-at 700 --type 'FILES 2\n' --frames 3000`）
  のrun1・run2。
- 群の同定には`tools/compare_recv_run_fields.py`の`stage1`が内部で持つ
  段・候補対応をそのまま使う（判定器を新たに作らない）。
- 使う既存API: `compare_l3_entry_fdc.command_names` /
  `status_fields` / `describe_status` / `is_error_status`、
  `analyze_write_path.parse_commands`。
  **`is_error_status`は真偽だけを返す既存関数であり、値を出さない。**

## 記述する項目（すべて値を出さない）

群A・群Bの各段について、次を記録する。

1. 段番号（起動からの通番）と、その段のSEEKが発行された**frame**。
2. その段の**直前のコマンドの種別名**（公開μPD765名）。
3. その**直前コマンドの結果相にエラーが立っているか**
   （`is_error_status`の真偽。立っている場合は`describe_status`が返す
   **公開ビットの復号名**のみを書き、値は書かない）。
4. その段に含まれるコマンド**種別の並び**（公開名の列）。
5. 直近の`RECALIBRATE`との段番号差（`RECALIBRATE`は全体で5件）。

対照として、**候補が1件以上あるSEEK段**についても同じ項目を集計し、
「候補0件の段だけに見られる特徴」かどうかを判定できるようにする。

## 候補（測定前に固定。真なら／偽なら観測されることを先に書く）

### G1: エラー回復仮説
「受信runが先行しないSEEKは、直前のFDCコマンドがエラーで終わったことに
駆動される再試行である。」

- 真なら: 群A・群Bの**全4段**で、直前コマンドの`is_error_status`が真。
  かつ、候補1件以上の段では真の割合が明らかに低い。
- 偽なら: 4段のうち1段でも直前コマンドがエラーでない。

### G2: RECALIBRATE随伴仮説
「受信runが先行しないSEEKは、`RECALIBRATE`後の位置決めである。」

- 真なら: 全4段が`RECALIBRATE`の直後（段番号差が最小の値で一定）にある。
- 偽なら: `RECALIBRATE`と隣接しない段が1つでもある。

### G3: 場面仮説
「受信runが先行しないSEEKは起動段階に固有で、`FILES 2`入口には現れない。」

- 真なら: 全4段のframeが打鍵frame（700）より前。
- 偽なら: frame 700以降の段が1つでもある。
- **G3が真なら、この現象は連続READ移行の規則とは別の話であると結論でき、
  1.57節の追跡から切り離してよい。** G3が偽なら切り離せない。

### G4: いずれでもない
上のどれも成立しない。その場合は「成立しなかった」とだけ書き、新しい仮説を
測定後に立てて同じ稿で検定しない（次稿へ回す）。

**群Aと群Bで結論が割れることを許す。** 両者は別の群であり、同じ答えに
なるとは仮定しない。

## 追加で記述すること（構造の記述。仮説検定ではない）

`read_count == 0`の段2件について、段に含まれるコマンド種別の並びを記述する。
**この構造はまだ一度も仕様書に書かれていない。** 何であるかを決めつけず、
観測された並びだけを書く。

## 事前登録する合格条件（測定前に固定）

1. **判定器の陽性対照**: `is_error_status`が、m7hmで既に観測されている
   エラー（条件O入口区間の最初のエラー結果＝READ DATAの`IC=異常終了`・
   `ST1=NO DATA`）に対して真を返し、正常終了のコマンドに対して偽を返す
   ことを、同じログ上で先に確認する。**両方向を確認する**（真だけ確認
   すると、常に真を返す実装でも通ってしまう）。
2. **決定論性**: run1・run2で上記の全記述項目が完全一致すること。
   一致しなければ判定はOとする。
3. **群の同定が訂正後の内訳と一致すること**: 群A=3段・群B=1段であること
   を解析の最初に再確認する。一致しなければ判定はOとする。
4. `tools/check_cleanroom.sh`が全項目OK。

## 言えないこととして先に書いておくこと

- 本稿は条件O・`disk#10`という1本のディスク・1条件の再解析である。
  他候補・他条件への一般性は主張しない。
- `is_error_status`が真であっても、それが「再試行の原因」であることまでは
  言えない（前後関係は因果ではない）。本稿が言えるのは同時に成り立って
  いるかどうかだけである。因果を言うには介入が要り、それは次稿の仕事とする。
- 公式ROM内部でどの状態がSEEKを起こしているかは、本稿の方法では届かない。
