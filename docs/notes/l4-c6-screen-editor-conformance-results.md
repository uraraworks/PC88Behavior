# l4-c6 — スクリーンエディタ適合の場面固定 — 結果

記録日: 2026-09-19

## 位置づけ

別担当が`docs/spec/l3-main.md`第4.1版 第16・17節だけを見て自作main
ROM（コミット`4e373c9`、自己検査`c4c9d53`）にスクリーンエディタ
（カーソル移動・INS/DEL・HOME/CLR・RETURN再読込）を実装した。自作
どうしの自己検査は両側に同じ誤解が入りうるため、公式ROM（環境変数
`PC88_REF_ROM_DIR`経由。`private/`への`ls`・`cat`・`find`等は一切
実施していない）と実際に打鍵を流して突き合わせる。**測定・照合のみを
行う。不一致が見つかっても自作ROMは直さない**（実装の修正は別担当）。

器具: `tools/l4_editor_conform_record.py`（打鍵計画の実行・座標記録、
`fe197e4`の前段`e359376`）・`tools/l4_editor_conform_normalize.py`
（件数・SHA-256への正規化、`fe197e4`）・`tools/conform_l3_editor.sh`
（実行スクリプト、`fe197e4`）。期待値
`tests/conformance/expected_l4_editor.tsv`は公式ROMで採取した
（`c424577`）。画面本文は一切記録していない（座標・件数・SHA-256のみ）。

## 対象・除外

`docs/spec/l3-main.md`第16節（矢印・INS/DEL・HOME/CLR、行の途中8腕＋
真の境界6腕〈B1・B2・B2'・B3・B3'・B4〉）・第17節（RETURN再読込、
R1a・R1b・R1c・U1・E1・T1・T2＋陽性対照PC1）の計22腕を対象とした。

以下は`docs/spec/l3-main.md`第18節「未確定」に当たるため、照合対象から
**除外した**（別担当が実装時に仮決めした部分と対応する）:

- **挿入モードで列79まで実文字が詰まった行への挿入**（未測定のまま。
  実装側の「RETURNで解除」は挿入モードを抜ける条件の仮決めであり、
  そもそも「抜ける条件」自体が未確定〈第16節「未実施・未確定」〉）。
- **挿入モードを抜ける条件**（同上）。
- **→単発での列79越え**（測定は長押し〈自動繰り返し〉でのみ行っており、
  単発押下での境界越えは未測定。実装側の「長押しと同じ」は仮決め）。
- **行0・最終行の境界の組み合わせ**（例: 最上行で↑、最終行で↓）
  （第16節はB1〜B4・B2'・B3'〈列0/列79の境界〉のみを対象とし、行方向
  〈行0・最終行〉の境界は測定していない。実装側の「無反応」は仮決め）。
- 80文字を越える論理行・CTRL系編集キー・G7（CRTC/iolog）は元々の
  第16・17節でも対象外。

## 結果

**22腕中21腕が一致、1腕（B4）が不一致。**

| 腕 | 一致 |
|---|---|
| arrow_left_mid・arrow_right_mid・arrow_up_mid・arrow_down_mid | 一致 |
| insdel_noshift_mid・insdel_shift_mid | 一致 |
| homeclr_noshift_mid・homeclr_shift_mid | 一致 |
| B1・B2・B2'（`B2p`）・B3・B3'（`B3p`） | 一致 |
| B4 | **不一致** |
| R1a・R1b・R1c・U1・T1・T2・E1・PC1 | 一致 |

### 不一致: B4（→を列79を越えるまで長押し）

最初に違うセルの位置（目印文字を打った差分。内容は書かない）:

- 公式ROM: 行1・列64
- 自作ROM: 行0・列1

自作ROMは、公式ROMと同じ長さ（600フレーム）の押しっぱなしに対して、
目印がほぼ動いていない（列1のみ）。公式ROMは自動繰り返し（キーリピート）
により継続的に列79を越えて次の行へ進むが、自作ROMではこの自動繰り返し
が働いていない、という座標の違いとして観測された（件数・座標のみで
判定。内容には触れていない）。

`docs/spec/l3-main.md`第18節項5「キーリピート（...リピート開始までの
遅延・リピート間隔そのものは測定していない）」のとおり、公式ROMの
キーリピートの正確な挙動（開始遅延・間隔）はこの適合テストの対象外
の測定に依存する部分であり、本テストは「同じ打鍵計画に対する結果が
一致するか」だけを見ている。

## 判定名との対応

一致した21腕は、いずれも判定名（`no_change`・`row_move`・`del_left`・
`ins_mode_only`・`clear`・`home`・`wrap_prev_line_end`・
`boundary_no_op`・`whole_line`・`reexec_overwrites_below`・
`line_registration_updated`・`reads_whole_row`）に対応する座標・出力
署名が公式・自作間で完全一致した。B4（`wrap_to_next_line`）のみ、
着地位置が一致しなかった。

## 追補: キーリピートの適合（l4-s1hの腕）

記録日: 2026-09-19

### 位置づけ・B4についての注記

実装担当が`docs/spec/l3-main.md`第4.2版 第8節（コミット`05576c9`）を
見てキーリピートを実装した（`25def6d`、自己検査`42e061e`）。報告に
よれば、遅延は仕様の範囲（[l4-s1h-key-repeat-results](l4-s1h-key-repeat-results.md)
が確定した26〜31フレーム、中心値26）の中から、**B4（本ノート上段の
境界適合テスト、公式ROM実測=行1・列64・移動数144）の期待値に一致する
よう30フレームを選んだ**とのこと。範囲内の値なので仕様違反ではないが、
これによって**B4は遅延の独立な検証ではなくなった**（B4の期待値に
合わせて選んだ値をB4で確認しても、円環（合わせ込んだ値で合わせ込んだ
テストが通る）にしかならない）。

そこで、l4-s1hがそもそも遅延・間隔を測るために使った腕そのもの
（Q1のqキー時系列・Q2の→6腕・Q3の→単発の列79越え・G4/G5の対照）を
本適合テストへ直接追加し（`caaaacf`・`8d6a9cf`、`s1h_*`の10腕、
計32腕）、B4を経由しない独立な照合経路を作った。

器具: 追加10腕とも`tools/l4_editor_conform_record.py`の
`run_q88`/`build_tokens`/`diff_cells`/`SETTLE`をそのまま再利用
（`tools/l4_key_repeat_record.py`と同じフレーム設計）。期待値は公式
ROM（`PC88_REF_ROM_DIR`経由、`private/`への直接アクセスは無し）で
採取した（`8d6a9cf`）。`s1h_q1_main`の期待値`nonblank_count=547`は、
[l4-s1h-key-repeat-results](l4-s1h-key-repeat-results.md)の生データ
（1+3+4+5+7+8+9+16+31+46+61+76+92+94+94）の合計と一致することを確認
済み。

### 結果

**32腕中31腕が一致、1腕（`s1h_q1_main`）が不一致。B4を含む他の31腕
（既存22腕＋新規9腕: `s1h_g4_pos`・`s1h_g5_neg`・`s1h_q2_a`〜`f`・
`s1h_q3_main`）は一致。**

| 腕 | 一致 |
|---|---|
| `s1h_g4_pos`（陽性対照）・`s1h_g5_neg`（陰性対照） | 一致 |
| `s1h_q2_a`〜`s1h_q2_f`（→の6腕、HOLD=4/26/34/40/60/600） | 一致 |
| `s1h_q3_main`（→単発の列79越え） | 一致 |
| `s1h_q1_main`（qキーの繰り返し時系列） | **不一致** |

### 不一致: `s1h_q1_main`（qキーの繰り返し時系列）

最初に違う写し（offsetとD0との差分件数のみ。座標・内容は書かない）:

- offset=50フレーム: 公式ROM=7件、自作ROM=6件（自作が1件少ない）。

これは自作ROMの遅延（30フレーム）が公式ROMの中心値（26フレーム）より
4フレーム（間隔1回分）長いことと整合する（自作は公式より約1回分
リピートが遅れて始まる）。offset=55〜330の区間は量子化（サンプリング
間隔5〜60フレームと間隔≈4フレームの端数）の巡り合わせで一致する
オフセットも複数あったが、offset=390で再び公式92件・自作91件と1件差が
出た（自作が引き続き1回分遅れている一貫した傾向）。offset=420・450は
両方とも94件で一致（HOLD=400で両ROMとも同じ時点で離しており、離した
後は増えないため、遅れの差が最終値には残らない）。

### Q2（→の6腕）が一致した理由についての注記

`s1h_q2_c`（HOLD=34フレーム）は、[l4-s1h-key-repeat-results](l4-s1h-key-repeat-results.md)
が遅延の中心値を28ではなく26に絞り込む根拠になった腕（実測移動数3が
遅延26・間隔4の予測と一致し、遅延28・間隔4の予測とは不一致だった）
だが、自作ROMの遅延（30）でも`floor((34-30)/4)=1`→移動数`1+1=2`…
とはならず、実測は3件で一致した。自作ROM側の間隔が公式と完全に同じ
ではない可能性、またはHOLD=34における端数の丸まり方が偶然一致した
可能性があるが、**本追補はQ1の不一致を報告するに留め、この一致の
理由を追加測定はしない**（不一致でも自作ROMは直さない、独立検証の
記録に徹する方針のため）。

### 判定・対応

**不一致があっても自作ROMは直さない。** 実装の修正判断は別担当が行う。
本追補は「B4を合わせ込んだことで失われた独立検証」を別の腕で回復し、
その結果（q88キー時系列のみ、遅延の量子化に起因する1回分の差）を
記録することが目的である。

## 追補: キーリピートの時系列で何を比べるか

記録日: 2026-09-19

### (b) これは不一致を見た後で決めた変更である

**この追補は事前に決めておくべき方針ではなく、`s1h_q1_main`の不一致
（本ノート上段の追補、offset=50で公式7・自作6）を見た後で、その原因を
[l4-s1h-key-repeat-results](l4-s1h-key-repeat-results.md)「訂正」節の
実測で切り分けた結果として決めた方針変更である。** 先に方針を決めて
から測ったものではない。

### 経緯・原因

[l4-s1h-key-repeat-results](l4-s1h-key-repeat-results.md)「訂正」節の
実測により、`s1h_q1_main`の不一致の原因は次のとおりと分かった:

- qキーの**遅延（1回目のリピートまでの31フレーム）は公式・自作で完全
  に一致**していた。
- 差は**間隔の刻み方**: 公式は3・4・5・3・4フレームと回ごとに揺れる
  のに対し、自作は毎回きっちり4フレームで固定。offset=50は、公式が
  たまたま短い間隔（3フレーム）を挟んだ回の直後にあたり、公式だけが
  先にその境目を越えたために生じた1件差だった。

さらに、→キー（`s1h_q2_*`、カーソル移動のみでリピート中はVRAMを
書かない）の間隔は**常に4フレームで完全に固定**であり、別の文字キー
`x`（`04:1`ではなく`05:0`、q以外の文字キーで確認のため追加測定、
未コミットの一時測定）でも**qと同様に3・4・5・4フレームと揺れる**
ことを確認した。VRAMへ文字を書く処理を伴うキー（q・x）は間隔が揺れ、
書かないキー（→）は揺れない、という対応がここまでの観測で一貫して
いる。**これは「文字を画面に書く処理時間が挟まることでROMのキー走査
の間隔がわずかにずれるため」という推定であり、確定した仕組みの説明
ではない**（ROM内部の処理経路は見ていない・見ることができないため、
これ以上は測定でしか裏を取れない）。ただし、この推定が正しいなら、
`s1h_q1_main`の途中の写しの件数（offsetごとの差分件数の時系列）は、
「キー入力に対する応答の正しさ」ではなく**「画面書き込みにかかる
処理時間」**、すなわち[l4-c5追補4](l4-c5-representative-programs-conformance-scene-preregistration-addendum4.md)
が「速さは比べない」と定めたのと同じ種類の量を比べていることになる。

### (a) 方針: 途中の写しは適合の対象から外す

`l4-c5追補4`第1節の考え方をそのまま踏襲する。**キーリピートの適合で
比べるのは「離した後に確定した最終状態」であり、繰り返しの途中経過
（各offsetでの件数の時系列、間隔が何フレームで刻まれたか）は比較の
対象に含めない。** 自作ROMの画面書き込み処理が公式と1フレームも違わ
ず一致する保証は無く、そこを適合の判定に使うと、キー入力そのものの
正しさとは別の理由（処理速度の違い）で不一致になりうるため。

### (c) 代わりに比べるもの

- **`s1h_q1_main`・`s1h_g4_pos`・`s1h_g5_neg`（qキー系3腕）**: 離した後
  （`HOLD`フレーム経過後、写しの最後2枚がどちらも同じ値であることを
  ここでも確認する）の**最終件数のみ**を比較対象にする（従来の
  「offsetごとの差分セル列すべてのsha256」から変更）。
- **遅延・間隔は、判定とは別の観察として`l4-s1h-key-repeat-results.md`
  に記録済み**（Q4節・訂正節）。適合テストの関門・sha256には含めない
  （`l4-c5追補4`第4節と同じ扱い）。
- **`s1h_q2_*`・`s1h_q3_main`（→系7腕）は変更しない。** これらは元々
  「離した後の着地列」だけを比較しており（HOLD中の写しを撮っていない）、
  時系列の途中経過を比較に含めていなかったため、本追補の対象外。

### 実施: 正規化の変更・期待値の採り直し・自作の再照合

`tools/l4_editor_conform_normalize.py`のS1H_SWEEP正規化を、offsetごと
の差分セル列全体のsha256から、**最後のoffset（離した後）の差分セル列
だけ**のsha256に変更した（`s1h_q1_main`はoffset450、`s1h_g4_pos`・
`s1h_g5_neg`も同じ形式に統一）。期待値
`tests/conformance/expected_l4_editor.tsv`は公式ROM
（`PC88_REF_ROM_DIR`経由）で採り直した。

自作ROM側を`tools/conform_l3_editor.sh`で再照合した結果:
**32腕すべて一致**（`s1h_q1_main`を含む）。

