# l4-s9w 追補4 — 空きメモリを減らして PAINT の作業領域の不足を起こす腕（事前登録の追補）

状態: 2026-10-09。追補3の公式の走り（`official_add3.tsv`、6腕×2走、関門通過）の観測を読んだあとに書く。

## 動機

歯 300 本の櫛・画面幅の点線格子（639×99）を、スタックの大きさ 16〜60000 バイトの全てで塗り終えた。**どの腕も ERR 7 が出なかった**。`CLEAR` のスタックの大きさは PAINT の作業領域に効いていないらしい。マニュアルは Out of memory の原因として「配列が大きすぎる」などの空きメモリ不足を挙げ、FRE で空きを調べるよう勧めている。そこで**配列で空きメモリを減らしたうえで**同じ形を塗って、不足時の誤り番号と途中の画素を見る。

## 足す腕（`tools/l4_paint_measure.py`）

`ws-8a`〜`ws-8d`: 先頭に `on error goto 900`（guard）、`dim a(N)`（N = 4000・8000・12000・16000。単精度配列）の文を実行し（その誤り番号を印字する）、点線格子 2 つ（100×40・200×80）と歯 80 本の櫛を置いて、3つを塗る。
予測: **すべて予測なし**（空きメモリの量を知らずに N を選んだ。DIM 自体が ERR 7 になる N もありうる）。観測した誤り番号・LP・最終画面のハッシュと画素数を記録するだけで、的中数には数えない。
空きメモリの量そのものの測定は別の段の仕事で、この段では扱わない。

ここで ERR 7 が出なければ「この範囲の条件では作業領域の不足を起こせなかった」と結果ノートに書く。
