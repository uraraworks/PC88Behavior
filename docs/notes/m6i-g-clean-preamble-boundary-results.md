## 2. 何を決める測定で、何を決めない測定か

事前登録 §0 から引き継ぐ。**本測定は自作 main を自作 sub に対して測る。**
決まるのは**自作どうしの統合条件**であって、**公式 sub が何を要求するかではない。**

**本ノートの結果を `docs/spec/l3-subrom.md` 1.65節へ書かない。** 1.65節は
公式の観測に基づく節であり、本稿はそこへ規則を1つも起こさない。公式 sub への
適合は `tools/conform_l3.sh` の系統で別に確かめる。

### G4（sub 無改変と main の直交をバイトで示す）

- 4腕の `DISK.ROM` はすべてバイト一致し、**素のサブROM**
  （`make_subrom.py` を介入フラグ無しで呼んで得たもの、SHA-256 `d8b2e64b…`）と

- 4腕の `FONT.ROM`・`N88_0`〜`N88_3` はすべて同一

**したがって4腕は `N88.ROM` 以外が完全にバイト一致する。** 振っているのは
main の前置きだけである。G-N の ROM 一式 SHA-256 は m6i-b の B0 と、G-L2 の
それは m6i-e の E1（= m6i-c の C2）と一致した。

### G10（窓の端の検査）

第1回・第2回で落ちた形そのものを、合成入力で3件検査している。

1. 初期化が起きず、sub が起動ハンドシェイクで `OUT $FD` を出す入力で、
   `c` の整合検査が真になる（第1回の形）
2. 初期化が起きず、main が起動専用SENDを1件出した入力で、起動専用SEND数が
   正しく1と数えられる（空の窓なら0になる形）
3. **初期化が通常READ の発行より後に始まる入力**で、起動専用の窓が発行時刻で
   切られ、発行後の main 送信を数えない（第2回の形）

3件とも、**直す前の実装では失敗すること**を実走で確かめてある。
本ノートの器具では、窓の上限切り（`min`）を外すと自己検査が rc=1 になる。

## 4. 腕ごとの結果

いずれも2走で同一。

| 腕 | main の前置き | 発行フレーム | 観測状態 (a,b,c) | 結果 | 要求run | 判定 |
|---|---|---:|---|---|---:|---|
| G-N | なし（即発行） | 6 | 0,0,0 | timeout | 0 | `g_n_reproduced` |
| G-L0 | 送信せず待つ | 60 | 0,0,0 | timeout | 0 | `g_l0_failure` |
| G-L1 | 起動専用SEND 1件 | 60 | 1,1,0 | **256位置一致** | 1 | `g_l1_success` |
| G-L2 | SEND＋ラウンド#0 | 60 | 1,1,1 | 256位置一致 | 1 | `g_l2_reproduced` |

**再現腕2つがどちらも再現した。** G-N は m6i-b の B0 を、G-L2 は m6i-c の C2
（= m6i-e の E1）を再現した。

## 5. 総合判定

**`m6i_g_ab_sufficient`**。

`g_l0_failure` かつ `g_l1_success` である。すなわち:

- **待つだけでは足りない。** G-L0 は G-L1・G-L2 と同じフレーム60で発行し、
  状態を1つも進めずに待ったが、timeout した。**「60フレーム待てば通る」では
  説明できない。**
- **起動専用SENDを1件出し、sub の FDC 初期化7 batch が完了すれば足りる。**
  G-L1 は256位置一致で成立した。
- **ラウンド#0は必要条件ではない。** G-L2 も成立するが、G-L1 で既に成立して
  いるので、(c) は必要ではない。

## 6. 得られたこと

- **自作 main が自作 sub へ初回の通常READ を出す前に必要な前置きは、
  起動専用SEND 1件と、それに続く sub の初期化完了までの待ちである。**
- **sub 側に介入を一切持たない腕でこれを測れた。** 4腕は `N88.ROM` 以外が
  バイト一致しており、m6i-b が抱えていた「停止ゲートが結果を作る」経路
  （m6i-c・m6i-e で特定した `IN A,($FE)` 1回）は、本測定の腕には存在しない。
- **m6i-b の陰性対照は、別の作り方で再び立った。** m6i-b の B1 は sub を
  ゲートで止める形だったが、本稿の G-L0 はゲートを持たず、それでも timeout
  した。**「待ち時間だけでは足りない」は、汚染されていない腕で改めて示された。**

## 7. この測定で決まらないこと

- **公式 sub が何を要求するかは決まらない**（§2）。自作どうしの統合条件である。
- **`b` 単独で足りるかは決まらない。** 素のサブROMは起動ハンドシェイクの後に
  自律的に初期化を行うので、sub を改変せずに「`b` だけで `a` を伴わない状態」
  を作れない（事前登録 §5末尾）。**境界は「(b)+(a) 以前のどこか」までである。**
- **なぜ (b)+(a) で足りるのかは決まらない。** 成立するかどうかだけを測った。
- 公式ROM内部の実装、公式の送受信値、実機での絶対時間は決まらない。
- **通常READを許してよい最早時点（1.65節）は決まらない。**
- 別媒体、WRITE、複数セクタREAD、BASIC命令一般へ一般化しない。
- m6i-b の腕の結果を、本稿の結果で上書きしない。m6i-b は記録として残る。

## 8. 行き先

事前登録 §5 の `m6i_g_ab_sufficient` の行き先に従う。

1. **`src/` の統合実装で、通常READ の前に「起動専用SEND 1件＋sub の初期化
   完了待ち」の前置きを採る。** ラウンド#0を一般的な前提にしない。
2. 前置きの実装は、**待ちを固定フレーム数で行わず、初期化完了を観測して
   進む形**にする。本稿はフレーム60で発行しているが、**60という値を実装へ
   直結しない**（本稿は待ち時間の下限を測っていない）。
3. `b` 単独で足りるかを詰める必要が出たら、ラウンド#0より**前**に置く介入の
   無害性を先に確かめる稿を立てる。m6i-e はラウンド#0の**後**についてしか
   測っていない。
4. 1.65節への規則の追加は行わない（§2）。
