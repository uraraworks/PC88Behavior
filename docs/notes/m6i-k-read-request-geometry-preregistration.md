# m6i-k — 公式 sub は読み要求 0x02 の論理トラックをいつ C*2+H として扱うか — 事前登録

記録日: 2026-09-30  
状態: **測定前・器具未作成**

## 0. 何を決める測定で、何を決めない測定か

診断（`docs/notes/save-hybrid-read-request-diagnosis-2026-09-29.md`、事前登録なし）で、自作 main が送る
読み要求 `0x02, P1, D, T, R` を、公式 sub は **T をシリンダ・H=0 として**扱うことがあると分かった
（T=37 に対して C=37・H=0 を読んだ）。公式一式では、公式 main は位置1（P1）を `0x01` で送り、かつ
起動直後・最初の `0x02` より前に `0x17, 0x0F` を送っていて、公式 sub は C=18・H=1 を読んだ。
診断で P1 だけを `0x01` にしても直らなかった。

- **決まること**: 公式 sub が `0x02` 要求の T を「論理トラック（C=T>>1, H=T&1）」として扱うか
  「シリンダ（C=T, H=0）」として扱うかが、(a) 事前の `0x17, x` の有無、(b) P1 の値 のどちらで
  決まるか。
- **副次**: `0x17` の2バイト目が、ドライブごとのマスクとして効くか（`0x17, 0x01` の1腕だけ）。
- **決まらないこと**: `0x17` の意味の全体（他のビット、他の値）、`0x0B` など公式 main が起動時に送る他の要求の意味、
  P1 の意味（件数かどうか）、複数セクタ読み、WRITE 要求（`0x11`）側の扱い。

本稿は**公式 sub の挙動の測定**であり、結果は仕様書 l3-subrom へ起こす。

### 0.1 診断で既に見えているもの（開示）

診断では、腕 K-00・K-01 に相当する条件（`0x17` なし、P1=0x00／0x01）で、ドライブ2・T=37 の読みが
「シリンダ」として扱われるのを1回ずつ見ている。**この2腕の結果は予測ではなく既知であり、判定の
根拠としては再現の確認としてだけ数える。** 未知なのは `0x17` を送った腕である。

## 1. 公式から持ち込むもの・持ち込まないもの

- **公式 sub ROM（`DISK.ROM`）だけを使う。** `PC88_REF_ROM_DIR` から取る。main は自作の測定ROM。
- **公式ディスクは使わない。** 両ドライブとも §2 の自作合成ディスク。
- 公式 main は走らせない。`0x17, 0x0F` と P1=0x01 は、診断で観測した**入出力の値**であり、ROM の内容を読んだものではない。

## 2. 試験ディスク

m6i-i の新規則（`tools/make_l3_testdisk.py` の座標刻印オプション。各セクタの先頭4バイトが
[ディスク識別値, C, H, R]）で作った2枚を、ドライブ1・2に入れる。**m6i-i と同じ引数・同じ像**（SHA-256 を凍結値として照合する）。

- 2D（40シリンダ×2ヘッド、R=1〜16）なので、T=37 を「シリンダ」と読むと C=37・H=0 の実在セクタに届く。
  **「読み違え」がエラーではなく別の中身として返りうる**ので、刻印で区別する。

## 3. 腕（arm）

各腕は**別の起動**（sub の状態が腕をまたがないように）。起動後、m6i-g で確定した前置き（起動専用 SEND 1件＋初期化完了）を
済ませたあと、腕ごとの「事前送信」を1回だけ行い、続けて §4 の6行を順に読む。

| 腕 | 事前送信 | P1 | 役割 |
|---|---|---|---|
| K-00 | なし | 0x00 | 既知（診断の再現）。現行の自作と同じ |
| K-01 | なし | 0x01 | 既知（診断の再現） |
| K-F0 | `0x17, 0x0F` | 0x00 | 本命 |
| K-F1 | `0x17, 0x0F` | 0x01 | 本命。公式 main と同じ |
| K-M1 | `0x17, 0x01` | 0x01 | 副次（マスクの見立て） |
| K-FR | `0x17, 0x0F` | 0x01 | **故障注入**: 要求の R を +1 する |

- 事前送信の送り方: 先頭 `0x17` を通常 SEND、2バイト目を要求の続き（`0x02` 要求の位置1以降と同じ送り方）で送る。
  **応答は待たない・読まない。** 事前送信のあと、次の要求までに sub が `OUT $FD` を何回したかを件数だけ記録する。
- 読みは一般READ（`MAIN_SUB_READ_CHR` 相当）に P1 を差し替えた測定ROM内のルーチンで行う。**配布ビルドの `src/` は変更しない。**
  再試行は m6i-h の結論どおり1回まで。

## 4. 各腕で読む座標（この順）

| # | ドライブ | T | R | 論理として読めば (C,H) | シリンダとして読めば (C,H) | 狙い |
|---:|---|---:|---:|---|---|---|
| 1 | 1 | 0 | 1 | (0,0) | (0,0) | **対照**: 両解釈が一致。読み経路が生きていることの確認 |
| 2 | 1 | 37 | 13 | (18,1) | (37,0) | ドライブ1の分岐 |
| 3 | 2 | 37 | 13 | (18,1) | (37,0) | 診断と同じ座標 |
| 4 | 2 | 1 | 1 | (0,1) | (1,0) | T の最下位ビットだけ |
| 5 | 1 | 1 | 1 | (0,1) | (1,0) | 同上・ドライブ1 |
| 6 | 2 | 0 | 1 | (0,0) | (0,0) | **対照**: ドライブ2でも経路が生きている |

K-FR では各行の R を +1 して送る（行1・6 は R=2、行2・3 は R=14、行4・5 は R=2）。

## 5. 観測と行ごとの分類

### 5.1 主指標: FDC の引数

各行の要求のあと、**最初に sub が発行した READ DATA（`0x46`／`0x66` 系）の引数** US（ドライブ・ヘッドビット）・C・H・R と、
その直前の SEEK の C を取る。これは公式 sub が FDC へ書いたコマンド列であり、データではない。

行の分類（R は **§4 の表の R**（腕が実際に送った値ではない）と一致することも条件。K-FR は R+1 を送るので、sub が送られたとおりに読めば R が表と食い違い `other` になる。これが K-FR の検出の仕組みである）:

- `logical`: C=T>>1 かつ H=T&1
- `cylinder`: C=T かつ H=0（T=0・1 の行では `logical` と区別できない行がある。行1・6 は `agree` とする）
- `other`: 上のどれでもない、または R が §4 の表の R と違う
- `no_read`: 要求のあと READ DATA が発行されなかった

### 5.2 副指標: 受け取った中身の刻印

main が受け取った256位置の先頭4バイト（自作合成ディスクの刻印）から、実際に読まれた (ディスク, C, H, R) を得る。
**主指標と食い違ったら `index_disagree` として記録し、その行は判定に使わない。**
受け取れなかった（再試行後も失敗）行は `failed`。**失敗しても主指標（FDC の引数）で分類はできる**ので、
解釈の判定は主指標で行い、成否は別欄に記録する（診断では P1=0x00 のとき失敗、0x01 のとき成功していた）。

`index_disagree` の判定は、**実際に読んだ座標どうし**で行う。刻印から得た (ディスク, C, H, R) と、§5.1 で取った READ DATA の引数（US のドライブ、C、H、R）を比べ、食い違えば `index_disagree` とする。§4 の表とは比べない（表との比較は §5.1 の分類だけで行う）。したがって K-FR の行は、sub が R+1 を送られたとおりに読めば `index_disagree` にはならず、§5.1 で `other` に分類される。

### 5.3 記録するもの

行ごとに: 分類、成否、刻印から得た座標、FDC の READ DATA の回数（内部再試行の件数）、結果ステータス ST0・ST1 の公開ビットの復号名。
腕ごとに: 事前送信のあとの sub `OUT $FD` の件数。

## 6. 関門（gate）

いずれかが偽なら腕へ進まず `gate_failed`。

- **G1** `tools/run_all_selftests.sh` が rc=0。
- **G2** `tools/check_cleanroom.sh` が rc=0 かつ NG 0件。
- **G3 試験ディスク**: 2枚の像の SHA-256 が m6i-i の凍結値と一致する。加えて、§4 の行2〜5について、
  「論理として読んだ場合」と「シリンダとして読んだ場合」のセクタのデータ部が像の中で**異なる**ことを、
  生成規則を呼ばない D88 読み取り器（m6i-i §3 のもの）で確かめる。
- **G4 sub**: 全腕の `DISK.ROM` が `PC88_REF_ROM_DIR` の `DISK.ROM` とバイト一致する（SHA-256 を結果に記録する。値は ROM の中身ではない）。
- **G5 main**: 腕ごとの測定ROM（`N88.ROM`）の SHA-256 を測定前に凍結する。K-FR は K-F1 と「R に +1 する1箇所」だけが違うことを、
  アセンブル結果の差分位置の数で確かめる。
- **G6 既存成果物の不変**: `src/build_main_rom.py` の既定の出力（生成される全ファイル）の SHA-256 が、器具を入れる直前のコミット（本稿の最後の訂正のコミット）と器具のコミットとで一致する。両コミットを `git archive` で取り出してそれぞれビルドし比べる。m6i-i の凍結値とは比べない（その後の実装でビルドが変わっているため。m6i-i の凍結値は測定コミットを取り出してビルドする既存の方式で守られている）。
- **G7 解析器の検出力**: 解析器に合成の入出力ログを与え、(a) C/H を入れ替えたもの、(b) R をずらしたもの、(c) READ DATA を欠いたもの
  がそれぞれ `other`／`other`／`no_read` に分類されることを自己検査で示す（陰性対照）。
- **G8 凍結**: 腕の表・座標表・分類名・判定名を測定前に器具の設定ファイルへ固定し、本稿と違えばエミュレータ起動前に `gate_failed`。
- **G9 出力の制限**: 解析器が標準出力・結果ファイルへ出すのは §5.3 の欄だけである。**READ DATA のデータ部、main↔sub のデータ部の値列は
  出さない**（件数・SHA-256・刻印4バイトのみ）。自己検査で、合成ログに入れた目印の値が出力に現れないことを確かめる
  （`contamination-2026-09-29-save-write-data-values.md` の措置3）。

## 7. 到達

- 全腕で6行すべての要求が送られ、各行で要求のあと 2000 フレーム以内に分類が1つ決まる。
- 各腕2走し、§5.3 の欄が2走で一致する（決定論性）。一致しなければその腕は `unreached`。

## 8. 判定名

腕ごとの要約: 行2〜5 の分類が全部同じならその名前（`logical`／`cylinder`）、ドライブで分かれたら `split_by_drive`、それ以外は `mixed`。
行1・6 は `agree` かつ成功であること（対照）。対照が崩れた腕は `control_failed`。

総合判定:

- `m6i_k_conversion_by_17`: K-F0・K-F1 が `logical`、K-00・K-01 が `cylinder`。**P1 は解釈に効かない。**
- `m6i_k_conversion_needs_both`: K-F1 だけが `logical`、K-F0 は `cylinder`。
- `m6i_k_conversion_by_p1_after_17`: 上の二つ以外で、`logical` が出た腕がすべて P1=0x01。
- `m6i_k_other`: 関門・到達・対照は通ったが、上のどれにも当てはまらない。腕ごとの表を記録する。
- `m6i_k_measurement_blind`: K-FR のどれかの行（行1〜6）が `other` 以外に分類された。**他の腕の結果は数えない。**
- `m6i_k_inconclusive`: 1腕以上 `unreached` または `control_failed`（K-FR を除く）。
- `gate_failed`

副次（総合判定に入れない）: K-M1 が `split_by_drive`（ドライブ1だけ `logical`）なら「2バイト目のビット0がドライブ1」と記録する。
それ以外は表だけを記録する。成否（§5.2）は腕×P1 の表として別に記録する。

## 9. 判定後の行き先

- `m6i_k_conversion_by_17` または `m6i_k_conversion_needs_both`: 仕様書 l3-subrom に「`0x02` の T の解釈は事前の `0x17` で決まる」
  （必要なら P1 も）を起こす。1.36節の「`0x17` 長さ7」の行は、`0x17, 0x0F` と `0x02` 要求の連結の可能性を注記する
  （本測定だけでは連結を確定しない）。そのあと実装（自作 main の起動時送信と読み要求）を、**このセッションの文脈を持たない担当**へ渡す
  （`contamination-2026-09-29-save-write-data-values.md` §3）。FILES・LOAD・SAVE の適合器具に hybrid 腕を足すことも同じ担当へ。
- `m6i_k_other`: 表を見て次の問いを立て、追補で測る。仕様書へは書かない。
- `m6i_k_measurement_blind`／`m6i_k_inconclusive`: 器具を直す追補を先に置き、同じ本稿で取り直す。

## 10. 本文に出さないもの

- 画面本文は使わない・出さない。
- main↔sub・FDC のデータ部の値列は出さない。出すのは FDC コマンドの引数、結果ステータスの復号名、件数、SHA-256、
  自作合成ディスクの刻印4バイトだけ。
- 公式ディスクは使わないので、その内容が混ざる経路は無い。公式 sub が自前の作業域の値を main へ返す可能性はあるので、
  受け取った256位置は刻印4バイトと SHA-256 以外を出さない。
