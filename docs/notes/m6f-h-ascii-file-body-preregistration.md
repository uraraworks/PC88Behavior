# m6f-h — ASCII 形式のファイル本体（SAVE ,A と順次データファイル）— 事前登録

記録日: 2026-09-28  
状態: **測定前**

## 0. 位置づけ

自作BASICに `LOAD` を入れる前段。プログラムの保存形式のうち、**ASCII 形式（`SAVE ,A`、種別バイト `0x00`）だけ**を先に扱う。
通常の `SAVE`（`0x80`）の本体は RAM 上の番地に由来する値（行の連結）を含みうるので、本稿では扱わない（読まない）。

本体の位置は l3-disk-format.md 第4版の規則（エントリ10バイト目の先頭単位、鎖、単位8セクタ、終端 `0xC0`＋使ったセクタ数）で決まる。
本稿は、その本体セクタの**中身の並び**（行の区切り・終わりの印）を測る。

担当・禁止は m6f-d 事前登録 §0 と同じ（`make_n88_blank_disk.py`・`vendor/`・QUASI88 の image.c・m7eb 系ノートを開かない）。

### 0.1 出力の制限（本体の余白を読まない）

- 本体は、**予測した文字列の長さ＋1バイト（終わりの印の候補）までだけ**を器具の中で候補と照合し、出力するのは
  「一致した候補名」「最初に食い違った位置（予測の範囲内のオフセット）」だけとする。本体のバイト値は出力しない。
- 予測の長さ＋1バイトより後ろ（最後のセクタの余り）は、読んでも比較にも使わない。ROM がメモリの内容を書いている可能性がある
  （[汚染の記録 2026-09-25](contamination-2026-09-25-fat-buffer-overrun-values.md) と同じ型の危険）。
- 使ったセクタの数（割り当て表の終端から分かる、第4版 2.4節）は出力してよい。
- 測定後の像は導出の後に削除する。

## 1. 問い

- **H-I 本文の形**: 各行が `LIST` の出力（l4-program.md 第2節）と同じ文字列で書かれるか、打鍵したままか。
- **H-II 行の区切り**: `CR LF`・`CR`・`LF` のどれか。
- **H-III 終わりの印**: 最後の行の区切りの直後が `0x1A`・`0x00`・印なし（区切りで終わり、使ったセクタ数で長さが決まる）のどれか。
- **H-IV 鎖**: 本体が複数の単位にまたがるとき、鎖の順につなげると連続した文字列になるか。
- **H-V 順次データファイル**: `OPEN … FOR OUTPUT` と `PRINT #` で書いた行の区切り・終わりの印が H-II・H-III と同じか。

## 2. 候補（18）

`<本文>_<区切り>_<終わり>`: 本文 {`LIST`, `TYPED`} × 区切り {`CRLF`, `CR`, `LF`} × 終わり {`1A`, `00`, `NONE`}。

- `LIST`: 行ごとに、l4-program.md 第2節の規則で作った `LIST` の出力の文字列（行番号・命令語の大文字化・空白の保持）。
- `TYPED`: 打鍵した文字列そのまま（小文字で届く。m6f-a 結果 (i)）。
- `NONE`: 最後の区切りの直後に印を置かない。この候補の照合は予測の長さまで（＋1バイトを見ない）とし、
  代わりに「使ったセクタ数 × 256 − 予測の長さ」が 0〜255 に収まることを条件にする。

データファイル（H-V）の腕では、本文は `PRINT #` で書いた文字列そのもの（`LIST`/`TYPED` の区別なし）とし、区切り×終わりの9候補を照合する。

## 3. 構成と腕（各2走）

m6f-f と同じ: ドライブ1＝参照 diskA の使い捨て複製で起動、ドライブ2＝`tools/make_m6fc_blank_disk.py` の空の媒体。打鍵はすべて自分で決めたもの。

| 腕 | 打鍵（`\n` は RETURN） | 目的 |
|---|---|---|
| H-1 | `new\n10 print 1\n20 print "ab"\nsave "2:qha",a\n` | H-I〜H-III（1セクタに収まる） |
| H-2 | `new\n` の後、`10 print "<40文字>"` 形式の行を行番号 10〜700 まで 70 行（文字列は行番号から自分で作る英大文字）、`save "2:qhb",a\n` | H-IV（2単位以上＝2048バイト超にまたがる） |
| H-3 | `open "2:qhd" for output as #1:print #1,"abc":print #1,"de":close #1\n` | H-V |
| H-0 | `new\nsave "2:qhz",a\n` | 空のプログラムの本体（行が無いとき何が書かれるか） |

H-0 の候補は、`1A`（印だけ）・`00`（`0x00` だけ）・`EMPTY`（使ったセクタ数が0、または本体の先頭が予測できない）の3つとし、
`EMPTY` の場合は本体のバイト値を一切出力せず、使ったセクタ数だけを記録する。

H-2 の予測は行が多いので、器具が打鍵列と予測の両方を同じ規則から作る（打鍵列の SHA-256 を凍結する）。
打鍵は長くなるので、打鍵が取りこぼされていないことを `LIST` を使わずに確かめる関門を置く（§4 G6）。

## 4. 関門

- **G1**: 自己検査を腕の前に1回。**G2**: 空の媒体が m6f-c B0 と同じ規則。**G3**: 凍結値（媒体・各腕の打鍵列・予測表）の照合を公式ROM起動前に行い、偽なら起動回数0。
- **G4**: 各腕2走で判定が一致。**G5**: 参照 diskA 複製は不変。
- **G6**: エントリが見つかり、種別バイトが H-1・H-2・H-0 で `0x00`（m6f-f の `SAVE ,A`）、H-3 で `0x00`。
- **G7**: 本体の読み取りが §0.1 の範囲を越えない（器具が読む位置の最大を記録し、予測の長さ＋1以下であること）。

## 5. 判定

- 各腕: 2走とも一意に一致した候補名。0件なら `inconclusive_<腕>_no_candidate`、複数なら `inconclusive_<腕>_multiple`。
- H-IV: H-2 が一意に一致すれば `chain_concatenates`（鎖の順につなげた文字列が一致した）、一致しなければ H-2 の判定名のまま。
- H-V: H-3 の区切り×終わりが H-1 と同じなら `data_same_as_ascii_program`、違えば `data_differs`。

## 6. 行き先

- 自作BASICの `LOAD "<ドライブ>:<名前>"` を、種別 `0x00` のファイルについて実装する前提の仕様を `docs/spec/l4-basic.md` に起こす
  （`LOAD` の画面の反応や、読み込んだ行の扱いは別稿で測る）。

## 7. 決めないこと

- 通常の `SAVE`（`0x80`）の本体。`SAVE ,P`（`0xA0`）・`BSAVE`（`0x01`）の本体。
- 最後のセクタの余り（読まない）。
- `LOAD` 時の画面の反応・エラー。
