# m7v: 263位置目は交換#7の未接続READデータ

測定日: 2026-08-13

## 情報境界

公式ROM・公式ディスクおよびディスク由来データの値は表示・記録していない。公式側と
混成側を各1800フレーム新規実走し、値の位置対応は比較器のメモリ内だけで判定した。
外へ出したのは交換番号、要求・応答長、I/O構造長、一致件数、一致プレフィックス、
同一／相違だけである。

## 263位置目の帰属

main `IN $FC`の1〜4位置は交換#0〜#3、5〜260位置は交換#4の256件応答、261・262位置は
交換#5・#6の単発応答だった。最初に不一致となる263位置目は、交換#7の2件要求に続く
256件応答の先頭である。

公式側では交換#6が6件要求・1件応答で、その要求窓の中にFDC READ系アクセスがある。
続く交換#7は2件要求・256件応答で、応答中のFDCアクセスは0件だった。交換#6のFDC
部分と交換#3のFDC部分は、`$F7/$F8/$FA/$FB`の方向・ポート列が569件で完全一致した。
したがって交換#6でデータを準備し、交換#7で保持済みデータを返す状態遷移は、既に確定
した交換#3/#4の組と同型である。

## データの位置対応

公式交換#7の256件応答は、交換#6中の直前READ DATAデータ部と256/256位置一致した。
混成側の同じ応答位置は直前READデータと1/256だけ一致し、一致プレフィックスは0だった。
これは263位置目の直接生成源がROM内部値ではなく、直前READ DATAのデータ部であること、
および混成側がそのバッファを交換#7へ接続していないことを示す。

交換#6のREADパラメータ位置1は直前SEEK対象と一致した。観測要求内では要求位置1と2が
同値であるため、どちらが意味上の生成源かは未確定である。READパラメータ位置4は要求
位置3と一致し、他の要求位置とは一致しなかった。実装規則は、区別不能な前者について
観測済みの要求位置1をSEEK/Cへ、後者をR/EOTへ転記する。未観測要求への外挿はしない。

## 現行実装の欠落

現行状態機械は交換#3の分節要求だけを`SECTOR_READY`へ接続し、交換#4送信完了後は状態を
消去する。その後の交換#6（6件要求）は汎用単発応答へ落ち、FDC READと`SECTOR_READY`を
開始しない。このため交換#7の2件要求でも`RESP_ACTIVE`が立たず、256件応答先頭で値が
分岐する。ポート取り違えではなく、二組目のREAD準備・送信状態が未実装なのが原因である。

## 4指標

- 値一致プレフィックス長: 262件
- main側構造一致プレフィックス: 258件
- sub側構造一致プレフィックス: 752件
- 混成main `IN $FD`: 0件

次は本測定だけを根拠に、交換#6の6件要求で交換#3と同じFDC構造を実行して保持し、交換#7
の2件要求で既存の二位置SENDへ接続する。期待値・比較条件は変更しない。
