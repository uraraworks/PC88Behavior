# m7cs: RUN"file" / MERGE 需要入口の事前登録と適合結果

実施日: 2026-08-25

本稿の到達条件は実測前に固定した。公式ROM・公式ディスクの内容は読まず、
生ログ、画面報告、ROM／ディスク複製はリポジトリ外の一時領域だけに置く。

## RUN"file"

公式一式の準備runで、自作した `10 PRINT "R7X"` を `Q7U` として使い捨て
diskA複製へ保存する。完成複製を公式一式／混成の別プロセスへ同一入力として渡し、
`RUN"Q7U"` だけを打鍵する。

到達は (1) `RUN"Q7U"` の画面反映、(2) その後の実行固有マーカー `R7X`、
(3) さらに後の `Ok` の三条件すべてとする。陽性対照はこの順を持つ合成画面、
陰性対照はコマンド反映と `Ok` はあるが実行マーカーだけを欠く合成画面とする。
従って、未実行、ファイル不在、構文エラー、単なるコマンド受理は合格しない。

## MERGE

公式一式の準備runで、自作した `20 PRINT "M7B"` をMERGE可能なASCII形式の
`Q7M` として使い捨てdiskA複製へ保存する。測定runでは `10 PRINT "M7A"` を
入力後、`MERGE"Q7M"`、
`RUN` の順に打鍵する。

到達は (1) `MERGE"Q7M"` の画面反映と直後の `Ok`、(2) 後続 `RUN` の反映、
(3) 実行後に元の行のマーカー `M7A`、併合行のマーカー `M7B`、`Ok` がこの順に
現れることの全条件とする。陽性対照はこの完全形、陰性対照は併合側マーカーだけを
欠く形とする。従って構文受理だけ、エラー終了、LOAD相当の置換、何もしない成功は
合格しない。

## 固定手順

既存の測定ラッパ、FDC分類、main受信列、画面署名を再利用する。初回公式実走では
件数・SHA-256と画面の行数・文字数・SHA-256を出し、期待値へ固定した後に
公式／混成を同条件で再検証する。各条件は2回の決定論性と取りこぼし0件を確認し、
件数およびSHA-256を壊した期待値コピーも不一致検出させる。

## 初回校正

期待値未登録の状態で公式一式を各入口1回だけ実走し、署名を得て
`tests/conformance/`へ固定した。RUNは準備・本番とも事前条件へ到達した。
MERGEの最初の準備は通常SAVE形式だったため、打鍵は反映されたが併合側マーカーを
欠き、陰性条件として不採用にした。準備をASCII形式へ直した再校正では、
MERGE直後Ok、元行・併合行の両マーカー、後続Okまで到達した。

ここまでを実測前の事前登録とした。

## 公式環境での適合結果

`tools/conform_l3.sh`はrc=0だった。出力中のNG 3件は故意に壊したfixtureを
検出した陽性対照である。

`RUN"file"`は公式・混成とも各2回で決定論的に一致し、取りこぼしは0件だった。
main `IN $FD`は5635件、main `IN $FC`は8222件で、公式・混成の件数と
SHA-256が一致した。画面は公式・混成で完全一致し、固定済み期待値とも一致した。
混成は入口終端まで到達し、FDC種別列とmain受信列はいずれも公式と全長一致した。

`MERGE`も同じく公式・混成各2回で決定論的一致、取りこぼし0件だった。
main `IN $FD`は5635件、main `IN $FC`は8222件で、件数・SHA-256が一致した。
画面は公式・混成で完全一致し、固定済み期待値とも一致した。混成は入口終端まで
到達して、FDC種別列とmain受信列も公式と全長一致した。判定器は件数故障と
SHA-256故障の双方を検出した。

`tools/run_all_selftests.sh`はrc=0で、53項目すべてOK、NG 0、SKIP 0、
Traceback 0だった。`src/l3_service/make_subrom.py`は変更しておらず、既定ROMは
基準とバイト一致した。従って、**両入口とも実装追加なしで一致した。**

## 解釈と次境界

両入口のmain `IN $FC`はともに8222件で、既存単独LOADと同じだった。これは
m7ciの結論、すなわち自作subが256バイト単位の読み書きという汎用プリミティブを
既に提供しているため、BASICの入口を増やしても同じ経路を別名で踏むだけ、という
説明の追加実例である。**入口の名前が違っても下は同じ道**である。

従って、入口を増やす方向をこれ以上潰しても同じ結果が続く見込みが高い。
次に測る価値がある境界は、256バイト単位の読み書きとは違う経路を踏みそうな
`BSAVE`/`BLOAD`と、ランダムアクセスの`FIELD`/`GET`/`PUT`とする。

## 行き止まり

MERGEは最初、保存形式がASCIIでなかったため目的経路を踏めなかった。ASCII保存へ
直して到達した。前周の`FILES "B:"`構文エラーと同じ型の空振りであり、単発の
到達確認によって本測定前に潰した。この不採用試行は事前登録の初回校正にも残す。

## 情報境界

記録したのは件数、SHA-256、画面の行数・文字数・SHA-256、および公開された
μPD765のコマンド名だけである。画面本文、ディスクのデータ部、公式の応答値は
記録していない。
