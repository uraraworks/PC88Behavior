# B87 入口版の比較と G3 ハンドシェイク追跡

2026-11-12。測定はクラウドで実施。入口版 `10a47cc`（ent）・`3f2aab1`（ent2）と `af55823`、旧版 b84 を比較した結果と、公式・自作の G3 実走の制御信号追跡をまとめる。データポートの値列や画面本文は記録しない。

## 入口版の比較

G2・G3・G5 は無入力、スペース、リターンの各腕を 36000 フレーム走らせ、600 フレームごとに画面署名を比較した。両入口版とも最初の F600 から最後まで公式と一致しない。自作の署名列は b84 と同じで、G2・G5 は起動画面とカーソル点滅、G3 は停止した画面に対応する。ent と ent2 は G2・G5 の全腕で署名ファイルがバイト単位で一致し、G3 は ent・`af55823`・b84 で一致した。

- **G2**: 無入力で `17` → `12` → `0D` の後、sub はゲームの RAM コードから sub ROM `0010` を呼び戻らない。以後 `0038` への移動と FDC 状態読みを繰り返し、main も待つ。公式では 3000F までにゲーム側から `0010`、`00ED`、`048F`、`06A6` の利用を観測し、`0038` は使われなかった。ゲームが固定番地を直接使うことを示す。
- **G5**: `17` → `12` → `02` → `12` → `0C` の後、main の送信 228 件と sub の受信 228 件は対応したが、sub は要求待ちに戻り、main は受信呼び出しを繰り返す。公式の受信呼び出しは165回、自作は211回以上で異なり、`0C` の引数解釈が異なる可能性が残る。公式ではゲームの sub コードから複数の sub ROM 固定番地を利用するが、自作では 3000F までゲームコードへの移行を記録していない。
- **G3**: 入口比較では `17` → `12` → 見かけ上 `0E` 26 バイト → `09` 1 バイトの後、main と sub がともに待っていた。後述の追跡で、この見かけの区切りと停止原因を訂正した。

G1 は5腕・各60点の比較で、I1・I2・I3 は全版で公式同士を含め差0点。S1 は `af55823`・ent・ent2 で各1点（F25800）、F1 は `fc61024`・`af55823`・ent・ent2 で各1点（F28200）の差があった。ent2 の変更による差は600F間隔では見えない。細かい時間幅での一致はこの比較からは言えない。

## G3 の停止原因

クラウドで公式・自作を実走し、制御ビットの順序を追跡した。**停止するのは2回目の `09`** で、1回目は自作でも通過する。公式 sub は要求待ち中に RFD を下げ、main の ATN を見てから RFD を上げる。自作 sub は直前の `09` で4096バイト送った後も RFD を上げたまま要求待ちに入る。main は ATN を上げるとすぐ下げて見出しの送信を始めるため、sub は ATN を取りこぼし、双方が待つ。公式が `09` 直後に特別な合図を出すわけではない。

見かけ上の `0E` 26 バイトは、main が `FC` を読まずに続けて送った `0E`（7バイト）×3 と `09`（5バイト）であり、`0E` の長さは既存仕様どおり。G3 のゲームコードから sub ROM への移動は 36000F で0件だった。この走の停止を sub ROM 固定番地への依存で説明する根拠はない。
