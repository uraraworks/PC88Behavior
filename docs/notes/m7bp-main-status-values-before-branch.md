# m7bp: main分岐前のステータス値差とループ継続を特定した

実施日: 2026-08-20

## 情報境界

公式ROM一式・公式diskAを、公式一式と公式main＋自作subの2構成で各1回、
1800フレーム実行した。内容は読んでおらず、`private/`への
`cat`/`xxd`/`od`/`strings`・逆アセンブルは行っていない。生iologは
`mktemp -d`で作ったリポジトリ外の一時ディレクトリだけに置き、コミット
対象にしていない。256件のディスク実データは値を出力・記録していない。

測定は`tools/lib_l3_measure.sh`、256件完了位置は
`tools/analyze_post_read_response.py`、パースと畳み込みは既存の
`analyze_main_to_sub.parse_iolog`と`tools/diag_l3_mixed.py`を再利用した。
新しい解析器は作っていない。`src/`、仕様書、`docs/PLAN.md`、
`tools/harness/romram_selftest.sh`には触れていない。

## 1. 分岐前にmainが読んだステータス値

基準区間は、mainが1.37節の256件目を受け終えた直後から、畳み込み後
71件目の分岐イベント直前までである。`$FC/$FD`の256件値は対象外とした。
この区間の非データ入力は公式33件、混成35件だった。

### 1.1 `IN $FE`

同じポート・PCサイトごとの値列は次のとおりだった。

| PC | 公式 | 混成 | 判定 |
|---|---|---|---|
| `37DC` | `80 80 80 82` | `80 80 80 82` | 4/4一致 |
| `37FF` | `12 14` | `12 14` | 2/2一致 |
| `381C` | `04 00` | `04 02` | 2件目で不一致 |
| `3853` | `20 21` | `22 22 22 23` | 先頭から不一致、件数も2対4 |
| `386F` | `41 40` | `43 42` | 先頭から不一致 |

非データ入力を生の時系列で並べた最初の値不一致は**8件目**で、同一サイト
`main IN $FE`・PC `381C`の公式`0x00`対混成`0x02`だった。差はbit1である。
その後のRECV前サイト`3853`では、m7bnで数えた2対4の回数差だけでなく、
値列も公式`20 21`対混成`22 22 22 23`だった。

### 1.2 その他のmain入力

分岐前にmainが読んだ非データポートは`$FE`、`$32`、`$71`だけだった。

- `IN $32`: 10件。2サイト各5件で、両側とも全件`0xA9`（10/10一致）
- `IN $71`: 11件。3サイト合計で、両側とも全件`0xFF`（11/11一致）

したがって、未比較だった値の差は`$FE`で見つかり、`$32/$71`には無かった。
`$FE`値差が71件目の分岐を直接決めたかは、今回の比較だけでは未確定である。

## 2. 分岐前後10件

比較キーはmain側の`(種別, port, pc)`、位置は256件受信完了後の畳み込み列で
ある。この窓には`$FE/$FF`が無いため、値欄は無い。

| 位置 | 公式 | 混成 |
|---:|---|---|
| 61 | `OUT $71 pc=3AA6` | `OUT $71 pc=3AA6` |
| 62 | `IN  $71 pc=3A92` | `IN  $71 pc=3A92` |
| 63 | `IN  $32 pc=3A95` | `IN  $32 pc=3A95` |
| 64 | `OUT $71 pc=3A9A` | `OUT $71 pc=3A9A` |
| 65 | `IN  $32 pc=3A36` | `IN  $32 pc=3A36` |
| 66 | `IN  $71 pc=3A39` | `IN  $71 pc=3A39` |
| 67 | `OUT $32 pc=3A60` | `OUT $32 pc=3A60` |
| 68 | `OUT $71 pc=3A64` | `OUT $71 pc=3A64` |
| 69 | `OUT $32 pc=3DC2` | `OUT $32 pc=3DC2` |
| 70 | `OUT $71 pc=3DC5` | `OUT $71 pc=3DC5` |
| **71** | **`OUT $31 pc=E7F5`** | **`OUT $32 pc=3AA2`** |
| 72 | `OUT $E4 pc=3088` | `OUT $71 pc=3AA6` |
| 73 | `OUT $51 pc=3092` | `IN  $71 pc=3A92` |
| 74 | `OUT $50 pc=30A0` | `IN  $32 pc=3A95` |
| 75 | `OUT $50 pc=30A6` | `OUT $71 pc=3A9A` |
| 76 | `IN  $51 pc=3F47` | `IN  $32 pc=3A36` |
| 77 | `IN  $0B pc=32F3` | `IN  $71 pc=3A39` |
| 78 | `IN  $0A pc=32F3` | `OUT $32 pc=3A60` |
| 79 | `IN  $09 pc=32F3` | `OUT $71 pc=3A64` |
| 80 | `IN  $08 pc=32F3` | `OUT $32 pc=3DC2` |
| 81 | `IN  $07 pc=32F3` | `OUT $71 pc=3DC5` |

公式の72件目は`OUT $E4`であり、`OUT $32`ではない。混成の71〜81件目は、
混成自身の60〜70件目と**11/11で同一**だった。したがって混成は公式の
`OUT $31`を1件だけスキップして公式72件目へ合流したのではない。
公式は70件目のあとループを抜けて`OUT $31`以降の別列へ進み、混成は
直前の11件周期をもう一周している。

## 結論・未確定

- 最初の未比較値差は、分岐前入力8件目の`IN $FE`、`0x00`対`0x02`。
- `$32`は10/10、`$71`は11/11で値まで一致した。
- 混成は1件抜けではなく、公式が抜けたループを継続している。
- `IN $FE`のbit1差がループ継続の直接条件かは未介入なので、まだ断定しない。
