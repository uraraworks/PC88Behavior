# B71: G1 の F1 の道で、`0x0E` が書くサブ RAM の範囲を値なしで測る — 結果

記録日: 2026-11-02
規則: [b71-g1-0e-target-range-preregistration.md](b71-g1-0e-target-range-preregistration.md) どおり。公式 2 走は一致した。記録は `measurements/b71-g1-0e-target-range.txt`。

## 結果

`0x0E` のあいだに公式の ROM 側が増える番地で書いたのは **`4000-4FFF` の 4096 バイト（16 セクタ）** だけだった。ほかの書きは `7F` 台（スタックと作業域）の同じ番地への書きである。

## 分かったこと

G1 の `0x0E` の読み先は自作の作業域（`7B00`〜`7D0B`）と重ならない。B70 の推定は外れた。

## 読み方（推定）

自作の `0x0E` の経路は、BASIC の交換 #14 のための既存の入口を流用していて、読み終えると `SECTOR_READY` を立て、同じ要求の続きを受ける状態で待つ。公式の `0x0E` は応答が無く、すぐ次の要求（G1 では `0x15`）を受ける。自作は次の `0x15` を `0x0E` の続きか、応答の要求として取り違えている可能性がある。

B70 の器具は最後の `0x15` で公式も時間切れになっていて、`0x0E` のあとの要求を確かめられていなかった。B72 で `0x0E` のあとの `0x15` と `0x0D` を、受け取り方を B24 の形に直したプローブで公式と自作の両方で測る。
