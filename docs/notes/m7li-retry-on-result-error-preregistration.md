# m7li: 再試行の条件に「結果が正常終了でない」を足す——m7krの更新の条件による作り直し — 事前登録

## 位置づけ

[m7lh](m7lh-data-crc-error-results.md)で、**公式はデータのCRCエラーでもREAD DATAを9件出すが、
採用した自作（[m7lf](m7lf-judgment-line-identity-results.md)）は1回も読み直さない**ことが分かった。
自作の再試行の条件は`FDC_ABORT`（データフェーズを最後まで受け取れなかった）だけで、**データを最後まで
渡してから結果フェーズでエラーを返す失敗を見逃す**からである。

**これは[m7kr](m7kr-implement-retry-decision.md)の更新の条件「公式の振る舞いと食い違う条件が見つかった
とき」に当たる。** 本稿はその作り直しである。

## 何を変えるか（`src/l3_service/make_subrom.py`、差分22行）

1. **`FDC_IN_7`**（結果フェーズ7件の共通読み捨て）で、**1件目（ST0）だけを新しい1バイト変数
   `LAST_ST0`（`0x4325`。空き番地）に残す。** 残り6件は従来どおり読み捨てる。
2. **単発READの再試行判定**を、「`FDC_ABORT`が立っている」**または**「`LAST_ST0`のIC（上位2ビット）が
   00でない」なら読み直す、に変える。ICの意味（00＝正常終了）は**公開μPD765データシートのハードウェアの
   事実**である。
3. **`FDC_ABORT`が立っているとき**は`FDC_IN`が読まずに戻るので`LAST_ST0`の値に意味は無いが、判定は
   `FDC_ABORT`も見るので必ず失敗として扱われる。**A以外のレジスタは壊さない。**

**全長2033→2046（+13バイト）、関門を通過、窓までの余白は2バイト**（測定前に確認）。

**「ICが00でなければ読み直す」は規則ではない。** 測った3種類の失敗（トラック不在・セクタ不在・データの
CRCエラー）と成功に**同時に合う最小の形**を選んだだけである（`m7kr`の約束2と同じ扱い。コメントに明記）。
**実装の根拠は1.58節（第198版）と公開データシートだけである**（`m7kr`の約束1）。

## 合格条件（**測定前に固定する。1つでも偽なら採用しない**）

**m7krの7項目は、m7le・m7lfの数え方のまま使う。**

1. ビルドが通る（2046バイトで関門通過を確認済み）。
2. `tools/run_all_selftests.sh`がrc=0（worktreeの切り離したHEADへ使い捨てでコミットして回す。置き場由来の
   `check_cleanroom.sh`の1件を除く。m7ldの開示どおり）。
3. **既存の適合テストが悪化しない**——同じ実行群のBASE（いま採用している版）と比べ、**m7lfの同一性**
   （判定＋数字を`#`にした本文、多重度つき）で(a)適合・(b)BASEのOK行を失わない・(c)NGが増えない・
   (d)`--`が増えない。**数字を伏せたおかげで一致とみなされた行はすべて列挙し、それぞれ「判定はOKのまま、
   件数だけが変わった理由」を説明できなければ採用しない。**
4. 読めない媒体（適合テスト`unreadable_disk`の混成側）でREAD DATAが連続96対・最長9のまま。
5. 読める媒体（drive1・drive2・書き込み・LOAD混成・LOAD既存の混成側）で連続0対のまま。
6. `src/`以外を変えない（採用のコミットは`src/`だけ）。
7. `tools/check_cleanroom.sh`が全項目OK（本体の作業ツリーで）。

**今回の変更の目的に当たる条件（新設）:**

8. **G-CRC（m7lhのデータCRCエラー媒体）で、混成のREAD DATAの件数・連続・最長が公式と一致する**
   （公式はm7lhで117件・96対・最長9）。
9. **G-OK（m7lhの読める同形媒体）で、混成は連続0対のまま**（成功で読み直さない）。

**加えて**: 決定論性——候補を独立2回、判定行の集合とm7lhの3媒体の数が一致すること。

## 記述として載せるもの（合否に使わない）

- **P（m7lhのセクタ不在媒体）で、混成の数がどう変わるか**（m7lhでは54件・40対・最長9で、公式の117件・
  96対と送信単位の数が違っていた）。**この変更で直ることは期待していない**——セクタ不在はもともと
  `FDC_ABORT`で読み直していたからである。**次に別稿で扱う。**
- 判定行の差分の全部。

## 言えないこととして先に書いておくこと

- **エミュレータの上での振る舞いである。** データのCRCエラーでデータを最後まで渡すかどうかはエミュレータの
  実装に依存する（m7lhのとおり）。
- **「9」を決める規則は依然として書けていない。** 本稿が変えるのは「どの失敗で読み直すか」の条件だけで、
  回数9は観測に合わせた値のままである。
- **公式がICを見て判断しているとは言わない。** 3種類の失敗と成功に合う最小の形を選んだ、までである。

## 採用したら

**測定のコミット（本稿の結果）を先に、`src/`の変更を後に**、単独でコミットする。1.58節は引き続き
適合条件にしない。

## 禁止（本稿の測定中も例外なく適用）

公式ROM・公式ディスクのバイト列を読まない・出力しない・逆アセンブルしない。公式ディスクは`cp`で使い捨ての
複製を作るだけ。`private/`の中身・ファイル名を出力しない。FDCデータポート値・シリンダ値・セクタ番号・
結果ステータスの生の値・時刻・frame番号・画面本文を出力しない（エラー結果は公開ビットの復号名だけ）。
