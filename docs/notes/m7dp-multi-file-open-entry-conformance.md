# m7dp: 複数ファイル同時オープン需要入口の実測

実施日: 2026-08-28

**本稿は`m7do`の事前登録に基づく実測ノートである。** 公式ROM・公式ディスクの
内容は読まず、生ログ・ROM/ディスク複製はリポジトリ外の一時領域（セッションの
scratchpad配下）だけに置いた。データポート値は1バイトも本稿へ転記していない。
`cmp -l`等でファイル内容を直接比較する操作も行っていない。

## 進捗ログ（実施順）

- [x] 環境準備: `PC88_REF_ROM_DIR`/`PC88_REF_DISK_DIR`を指定し、
      `tools/lib_l3_measure.sh`の`build_mixed_rom`で混成ROM一式を1回構築。
- [x] 準備run（公式のみ、1回）: 使い捨てdiskA複製（ライトプロテクト解除）に対し、
      `OPEN "Q9A" FOR OUTPUT AS #1`〜で自作ファイルQ9A（A1/A2/A3）、
      Q9B（B1/B2/B3）を作成し`--save-to-disk-image`で複製へ反映。`P9D`表示と
      直後`Ok`まで到達、構文エラーなし。**この結果は測定対象に含めない
      （下ごしらえ）。**
- [x] 校正run（公式のみ、1回、期待値には未採用）: 準備済み複製に対し
      m7do記載の測定本体プログラムを打鍵・RUN。**初回で構文エラー0件、
      `M9M`・`M9C`・直後`Ok`が順に出現し、事前登録どおりに到達した。**
      不採用時の切替先（ランダムアクセスの複数同時オープン）は使わずに済んだ。
- [x] 測定本体: 公式2回・混成2回、全4run到達・決定論的一致を確認。
- [x] 分解基準: Q9A単独・Q9B単独を公式各2回、全4run到達・決定論的一致を確認。
- [x] 3つの焦点への回答（4節）。
- [x] `tools/check_cleanroom.sh`。

## 測定条件

いずれも準備runで作った同一の複製`prep.d88`から、run単位に個別の複製を
作り直して使った（複製間で結果を継承しない）。フレーム数はm7do登録どおり
9000。打鍵開始は起動プロンプト待ちに合わせて300F/700Fの二段。

- **測定本体**（m7doの`10 OPEN "Q9A" FOR INPUT AS #1`〜のプログラム）:
  公式一式2回、混成（公式main ROM一式＋自作サブROM）2回。
- **分解基準（内部対照）**: Q9A単独版・Q9B単独版を各2回、公式一式のみ。

## 到達条件の判定（m7do 3節、4項目AND）

測定本体4run全てで、次の4条件すべてを満たした。**後から条件を緩めていない。**

1. プログラム入力・`RUN`の画面反映 — 全4run: 反映あり
2. 一致マーカー`M9M`の表示 — 全4run: 表示あり
3. 両`CLOSE`後の`M9C`表示 — 全4run: 表示あり
4. `M9C`直後の`Ok` — 全4run: あり

**判定: 到達（合格）。全4run一致。** 不合格条件（構文エラー・`M9M`欠落・
`M9C`欠落・`Ok`欠落）はいずれも観測されなかった。

分解基準（Q9A単独・Q9B単独）も同型の到達条件（`M9A`/`M9B`→`M9C`→`Ok`）を
全4runで満たした。

## 全run取りこぼし0件の確認

`.iolog.txt`先頭の`# 取りこぼし: N件`行（main・sub各1行、計2行）を全8run
（準備run含めると9run）で確認し、**全て`0件`だった。** 1件でもあれば
その回を不採用にする前提条件だったが、該当は無かった。

`tools/check_l3_screen_output.py`・`tools/compare_l3_entry_fdc.py`・
`tools/hash_io_stream.py`で値を出さずに比較した。

### 公開FDCコマンド種別列

測定本体（公式・混成とも）: 99件、`SPECIFY → RECALIBRATE → SENSE INTERRUPT
STATUS → SEEK → SENSE INTERRUPT STATUS → RECALIBRATE → SENSE INTERRUPT

INTERRUPT STATUS →（起動前置き15件）→ READ単位×21`。公式・混成間、
公式2回間、混成2回間のいずれも**全長一致**（`compare_l3_entry_fdc.py`の
一致prefix=99件、最初の差「なし」）。`READ DATA`発行は全4runとも21件、

分解基準（Q9A単独・Q9B単独）はいずれも83件、`起動前置き15件 → READ単位×17`

**起動前置き15件は、m7cf/m7cgが表記していた「P」（起動前置き）の実体で
あることを本測定で確認した。** これは新しい観測ではなく、既存の記法の
中身を初めて明示的に展開しただけである。

## 3つの焦点への回答

**1. 未見のFDCコマンド種別が現れるか。** **現れなかった。** 測定本体で
出現したコマンド名は`SPECIFY`/`RECALIBRATE`/`SENSE INTERRUPT STATUS`/
`SEEK`/`SENSE DRIVE STATUS`（READ単位内）/`READ DATA`の6種類で、これは
分解基準（単独オープン、m7cgの既踏経路と同型）で観測される集合の部分集合
であり、真に新規のコマンド名は0件だった。

**2. 切替に伴う説明不能な追加アクセスが生じるか。** **「追加」方向の
説明不能な差分は無かった。** むしろ逆方向の差分が見つかった——3.の
とおり、総アクセス量は単独オープンの合計よりも**少ない**。「#1↔#2切替の
たびに余分なSEEK等が挟まる」という当初想定した形の新規性は確認されず、
観測された差分はすべて「削減」側だった。

**3. 単独オープン合計との一致可否。** **一致しなかった。** 単独オープン
2回分の単純合計は、
- `IN $FC`件数: 8222 + 8222 = 16444件
- READ単位数: 17 + 17 = 34単位（136コマンド）

に対し、同時オープン時の実測は
- `IN $FC`件数: **9254件**（合計の56.3%）
- READ単位数: **21単位**（84コマンド、合計の61.8%）

であり、**単純な合計として説明できない。** 起動前置き15件は両者とも
1回分しか払っていない（そもそも1ブート内の測定なので当然）ため、
これを除いた読み取り本体だけで比較しても17+17=34単位に対し21単位で、
なお加法的ではない。

**m7do 3節の判定規則に従い、これは「新しい経路を踏んだ」と判定する。**
2ファイルを同時に開いた状態は、単独オープンを2回連続で行うのとは異なる、
より少ないFDCアクセスで完結する制御構造を通っている。

## 解釈上の留意点（未確定として残す）

上記の「削減」がどの段階で起きているか（ディレクトリ検索の使い回し、
2ファイルの物理配置が近接していることによるSEEK省略、あるいは他の要因か）
は、本測定の事前登録の範囲外であり、切り分けていない。単独オープンの
基準はいずれも「別々のブート」で取ったため、「同時オープン」と「同一
セッション内で逐次オープン（同時には開かない）」を切り分ける対照は
まだ無い。次に測るとすれば、この2条件目（同一セッション内でQ9Aを開いて
読んで閉じ、続けてQ9Bを開いて読んで閉じる、同時には開かない版）を追加し、
「同時性」と「同一セッションであること」のどちらが削減の原因かを
分離するのが筋である。これは未確定事項として残し、本稿の範囲では
追跡しない。

公式・混成の間には**いかなる差分も見つからなかった**（画面・`IN $FD`・
`IN $FC`・FDCコマンド種別列のすべてが全長一致）。したがって、この新しい
経路についても自作subは既にカバーしており、`src/l3_service/make_subrom.py`
への実装追加は不要である（実装は変更していない）。

## 情報境界

記録したのは件数、SHA-256、画面の行数・文字数・SHA-256、自分で打鍵した
文字列・自作データ（`A1`〜`A3`、`B1`〜`B3`、`Q9A`/`Q9B`等のファイル名）、
および公開されたμPD765のコマンド名だけである。画面本文全体、ディスクの
データ部、公式の応答値は記録していない。ROM・ディスクの複製、生iolog、
標準出力はすべてセッションのscratchpad（リポジトリ外）だけで扱った。

なお、測定環境準備の過程で一度、`PC88_REF_DISK_DIR`配下のファイル名一覧を
`ls`で確認した。これはROMバイト列・データポート値・ディスクのデータ部
ではなく、ファイル名だけであり、規律が明示的に禁止する対象
（ROM/ディスクのバイト列、逆アセンブル、データポート値列）には該当しない
と判断するが、既存の測定手順（`tools/measure_suite.sh`で確定済みの
`N88_FE.D88`という名前を使い回す）から逸脱した不要な確認だったため、
ここに記録する。得たファイル名はいずれも本稿・他のどのファイルにも
転記していない。
