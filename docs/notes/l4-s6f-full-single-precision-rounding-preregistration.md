# l4-s6f — 候補M8(単精度の乗算を多項式評価まで正しい丸めに広げる)の事前登録

記録日: 2026-09-19
状態: 事前登録(測定前)。(i)は記録済み83腕への事後照合(参考)、(ii)が
測定前に固定する本命の判定。

## 位置づけ・段階設計(手順1)

l4-s6e(`docs/notes/l4-s6e-single-precision-multiply-rounding-results.md`)
で候補M7(範囲縮約の乗算だけ正しい丸め)は記録済み62腕中50腕(81%)・
新規21腕中17腕(81%)で一致したが、残り4腕(COSの±1〜2ULP、TANへ伝播)
が残った。`tools/l4_mbf_oracle_v2.py`のdocstring(v1→v2の変更点)に
よれば、**加算・減算・除算(単精度・倍精度とも)はいずれも正しい丸めと
既に確認済み**で、正しい丸めでないのは単精度乗算だけである。よって
「段階を分けて広げる」対象は単精度乗算のみに限られ、SIN/COS/TANの
計算で単精度乗算が現れる箇所は範囲縮約(M7で対応済み)の他に、多項式
Horner評価(`$POLY`/`$POLYX`)の各ステップの乗算と、偶関数変形の自乗
だけである。

- 段階1(=M7): 範囲縮約の乗算だけ正しい丸め(既に測定済み)。
- **段階2(M8)**: 範囲縮約に加え、多項式評価(Horner・自乗)の乗算も
  正しい丸めにする。
- 段階3(加算・除算も正しい丸めに広げる): v2の確認済み事実により
  段階2と数学的に同一になるため、別実装はしていない。

`tools/l4_mbf_oracle_v8_m8.py`(新規、v3・v5・v6・v7は無改変)。COSは
M6・M7と同じ構造(角度領域でπ/2を単精度加算しSINをやり直す)のまま。
TANの除算もM0以来変更していない(v2で正しい丸めと確認済みのため)。
係数の当てはめは行っていない。

## (i) 記録済み83腕への事後照合

l4-s6b(19腕)+l4-s6c(21腕)+l4-s6d(22腕)+l4-s6e(21腕)の記録済み83腕
全てに対し、M7・M8の予測を単精度ビットで照合した(公式ROM未使用、
既に記録済みの数値文字列のみ使用)。

**83腕中M8は76腕(92%)がビット完全一致した(M7は67腕、81%)。**
M7→M8で新たに一致した9腕はいずれも±1ULP級の小さい食い違いが解消
されたもので、**既に一致していた腕を壊した例は無かった**(全ての
変化がULP差→0への改善)。

新たに一致した9腕: A07(`sin(50)`)・A09(`tan(50)`)・C07(`sin(88)`)・
C09(`tan(88)`)・C11(`cos(500)`)・D04(`tan(50)`)・D18(`tan(54321)`)・
E11(`cos(514)`)・E12(`tan(514)`)。

残る7腕(83-76): A15(`tan(1.2)`,+6ULP)・A16(`sin(6.28)`,+3217ULP、
2π極近傍)・D06(`tan(77)`,+1)・D11(`cos(999)`,+2)・D12(`tan(999)`,-2)・
E05(`cos(65)`,+1)・E06(`tan(65)`,-2)。手順3の「残り4腕」のうち
E11・E12(cos/tan(514))はM8で解消したが、E05・E06(cos/tan(65))は
**M8でも変わらなかった**(ビット単位で完全に同一、poly評価の乗算
訂正では動かない残差であることを確認した)。

## 手順4: 既存の自作単精度乗算(mbf_single.asm)への申し送り

「N88の単精度乗算は(少なくとも範囲縮約・多項式評価では)GW $FMULSの
粗い丸めでなく正しい丸め」という結果は、既存の自作ROM実装
(`mbf_single.asm`、GW手順ベース)の乗算にも関わりうる。既存の適合
(l4-c3等)が通っているかどうかとは別に、**乗算の丸めを直接狙った腕が
既存ノートにあったかどうかだけ**を確認する(実装は変更しない)。

`src/l4_basic/mbf_single.asm`の`MBF_MUL`(単精度乗算)を確認したところ、
コメントに「単精度乗算は加減算・除算と違って『厳密値を求めて1回偶数
丸め』とは等価ではない——8086実装は24bit×24bitの厳密48bit積のうち
下位16bitをスティッキーへ畳み込まずにそのまま捨てる」と明記されており、
**既存の自作実装は、本測定でN88の実際の範囲縮約・多項式評価と食い
違うと判明した「GW $FMULSの粗い丸め」を、意図的に忠実再現する設計に
なっている**(`tools/l4_mbf_oracle_v2.py`の確認済み事項として記録)。

`docs/notes/l4-c3-*`系列(浮動小数点PRINT適合)・`tools/l4_mbf_z80_
selftest.sh`を確認した結果、既存の適合検査は四則演算の結果の値を
既知の期待値と照合する形式であり、**粗い丸めと正しい丸めが割れる
特定のビットパターンの乗算を狙った腕は見当たらなかった**(l4-c3の
腕は主にPRINT書式の適合が目的で、乗算の丸めモード自体を弁別する設計
ではない)。つまり、既存の適合(l4-c3等)が通っていることは、**乗算の
丸めモードがN88の実態と一致していることの証拠にはならない**
(弁別力の無い腕だったため)。実装は変更しない、確認結果だけを記録する。
