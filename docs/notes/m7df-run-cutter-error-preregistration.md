# m7df: run切り出し誤差を2系統の陽性対照で切り分ける事前登録

実施日: 2026-08-28

`docs/notes/m7cx-open-items-inventory.md`のD区分に残る同型3件について、
「本当の例外か、run切り出し手法の誤差か」を判定する前に、出典、実際の
切り出し実装、誤差モデル、合成陽性対照の予測値、到達条件を固定する。
**本稿では合成selftestの実装も公式環境の実測も行わない。**

対象は次の3件である。

1. main視点RECV前後のbit0規則に対する0.11〜0.18%の例外
2. main側SEND runで`OUT $FF 0F`がrun先頭だけに属する率が100%でない理由
3. SEND run長の偶奇と終端pcの対応を反例が崩す理由

## 出典と解析経路

| 未確定項目 | 仕様上の場所 | 測定ノート | 解析器と数字の生成経路 |
|---|---|---|---|
| RECV前後の例外 | `docs/spec/l3-subrom.md` 1.19節、3節 | `docs/notes/m6m-fe-bit-analysis.md` 2節 | `tools/analyze_sub_fe.py`の`parse_iolog()`が共通clock順へ整列し、`analyze_sub_fe()`がCPU別列上で同一pc・同一`IN $FE`の**隣接列**を1スピンにする。`bit_significance()`は各スピン末尾をexit、同一スピン内で次の読取りが続いた値をloop継続として比較する |
| `0F`先頭専有 | 同1.20節、3節 | `docs/notes/m6n-run-boundary.md` 1節 | `tools/analyze_run_boundary.py`の`main_send_runs()`がmain `OUT $FD`かつ既知2pcを選び、二つの選択イベント間に`$FE/$FF`以外のmain I/Oが無ければ同一runにする。`send_run_ff_positions()`が直前の選択`OUT $FD`から現在位置までの窓に`OUT $FF 0F`が1件でもあるかを先頭／継続別に数える |
| run長偶奇とpc | 同1.20節、3節 | `docs/notes/m6n-run-boundary.md` 2節 | 上と同じ`main_send_runs()`の出力を`send_run_last_pc_parity()`へ渡し、長さ1を除外してrun長の偶奇と末尾pcを数える |

### 「1回で3件に効く」という前提の確認

3件は**単一のrun切り出し手法を共有していない**。後二件は同じ
`main_send_runs()`を共有するので一つの境界誤認が両指標を同時に動かし得る。
一方、RECV前後は別ファイルの`analyze_sub_fe()`が作るスピンであり、選択ポート、
境界条件、集計単位のすべてが異なる。

`analyze_run_boundary.py`の説明文は`analyze_main_to_sub.py`の
`classify_transactions()`も再利用すると書くが、対象二指標の実装は
`main_send_runs()`が独自に切り出しており、共有しているのはパーサ、イベント型、
SEND pc集合だけである。従って「一つの切り出し関数へ一種類の故障を入れれば3件を
同時に帰属できる」という棚卸し時の強い前提は崩れる。次フェーズでは一つのselftest
入口から**FEスピン系とSEND run系の2系統**を別々に試験する。片方の結果を他方へ
一般化しない。

## 切り出し手法が作り得る誤差

### A. FEスピン系

1. **偽結合**: 同じpcを使う別々の待ち呼出しの間に同CPUのI/Oが無いと、末尾値と
   次回入口値を同一スピン内遷移として結合する。別CPUイベントはCPU別列を作る時点で
   消えるため境界にならない。
2. **不可視の割り込み境界**: 二呼出し間に割り込み受理やI/Oを伴わないハンドラが
   あってもiologだけには現れず、偽結合する。intlogが別ファイルなら、共通clockで
   統合しない限り同じである。
3. **偽分割**: 真の一回の待ちの途中へ同CPUの別I/Oが入ると、隣接条件が切れて二つの
   スピンになる。割り込みハンドラがI/Oを行う場合も同型である。
4. **先頭／末尾打切り**: ログ開始前から続くスピン、またはログ終了後も続くスピンの
   端を真のentry/exitとして数える。m6m 4節では起動時専用SEND手順6の末尾1件が
   ログ打切りで不完全になった実例がある。
5. **同一pcの役割再利用**: 同じpcが複数の論理局面で使われれば、pc一致だけでは
   呼出し境界も役割も区別できない。

### B. SEND run系（後二件共通）

1. **偽結合**: 真のrun境界に`$FE/$FF`しか現れない場合、`main_send_runs()`は境界を
   許容イベントとして通過し、二runを結合する。I/Oを伴わない割り込みも見えない。
2. **偽分割**: 真のrun途中に非同期処理の別ポートI/Oが1件入ると、内容と無関係に
   runを分割する。
3. **`0F`の窓帰属ずれ**: `send_run_ff_positions()`は直前の選択`OUT $FD`から現在位置
   までを広く走査し、直近隣接だけを要求しない。この窓に別プリミティブの`0F`が
   入ると現在バイトへ誤帰属し、逆にログ端や誤分割では本来の先頭`0F`を失う。
4. **先頭／末尾打切り**: 途中から始まるrunを先頭扱いし、途中で終わるrunの長さと
   末尾pcを確定値として数える。偶奇集計は長さ1だけを除くため、不完全な長さ2以上は残る。
5. **順序空間の混同**: パーサは共通clock順へ並べた後にCPU別列へ落とす。CPU内seq、
   共通clock、intlogの割り込み受理という三つの順序空間を統合しないと、非同期境界を
   I/O列の単純な前後だけで表現できない。

### 過去の同型事故を候補へ入れる理由

`docs/notes/m7bn-post-read-main-branch.md`では、RECV前ポーリングが2回対4回だったため
生列の同一添字比較が18件目からずれたが、スピン畳み込み後は70件目まで再整列した。
これは反復回数差が偽の早期分岐を作る実例である。
`docs/notes/m7br-earliest-nondata-and-interrupt.md`では、VSYNC割り込み受理の直後に
一方だけ別のI/O分岐へ入った局面を共通clockで確認した。割り込みはI/O列へ非同期に
経路を挿入し得るため、同一添字やCPU別iologだけの境界判定にはintlog統合が必要である。
本稿の陽性対照には「割り込み受理だけがあり、同CPU I/O境界が無い」条件と
「割り込みハンドラの別ポートI/Oが入る」条件の両方を含める。

## 仮説

- **M（手法由来）**: 真の呼出し／run境界では規則に例外が無く、現在の隣接・許容ポート
  ヒューリスティックが偽結合または偽分割を作っている。
- **R（実挙動由来）**: 独立な境界アンカーでも同じ呼出し／runとして確定する位置に、
  bit0規則、`0F`位置、偶奇とpcの対応の本当の反例がある。
- **X（混在または識別不能）**: 一部だけ手法由来、アンカー不足、または二切り出し器の
  結果が不一致で、M/Rのどちらか一方へ全数帰属できない。

3件は別実装なので、M/R/XはFEスピン系とSEND run系で別々に判定する。
SEND run系でも`0F`と偶奇が同じ境界誤認へ同時に帰属しなければ、二指標を別判定にする。

## 合成陽性対照と事前予測

合成ログは公式ログを加工せず、seq、clock、cpu、kind、port、pc、フェーズ語彙を
規則から生成する。`$FC/$FD`のpayload値は位置番号から作り、解析出力では常に伏せる。
intlogも規則生成し、iologと同じ合成clock空間を使う。

### 1. FEスピン系: 0.11〜0.18%を境界誤認だけで作る

正常形はRECV前を2読取り、RECV後を2読取りの独立スピンとして生成し、各スピン間を
同CPUの明示境界イベントで区切る。正常形の規則違反は0件とする。

- RECV前は真の5517呼出しから6境界イベントを除き、6組を偽結合させる。
  現cutは5511スピンを検出し、真の前回exit→次回entryをloop内遷移として**6件**数える。
  予測例外率は`6/5511 = 0.1089%`（表示0.11%）。
- RECV後は真の5523呼出しから10境界を除き、10組を偽結合させる。
  現cutは5513スピン、規則違反**10件**、`10/5513 = 0.1814%`（表示0.18%）と予測する。
- 同じ位置へintlogの割り込み受理だけを置き、iolog境界を置かない条件でも現cutの予測は
  上と同じ。intlog-aware cutは6件／10件を真の境界として分離し、例外0件に戻る。
- 真のスピン途中へ別ポートI/Oを6件／10件挿入する偽分割条件では、現cutのスピン数が
  それぞれ+6／+10となる。端点を不完全として除外するcutだけが基準件数へ戻る。

この設計は「0.11〜0.18%程度は、少数の境界欠落だけで機械的に生成できるか」を
先に固定するものであり、率が似ただけで実ログの原因までMとしない。

### 2. SEND run系: `0F`率と偶奇を同じ誤境界で動かす

正常形は1000本の真の3バイトrunとする。各runの先頭だけに`0F`を置き、pc列は
奇数長の末尾が期待pcになる規則列とする。基準予測は、先頭`0F`あり1000/1000、
継続`0F`なし2000/2000、偶奇反例0件である。

**偽分割腕:** 真のrun途中へ別ポートI/Oを`s`件挿入する。各挿入は後半を新runにし、
その偽先頭には`0F`が無い。`s=100`なら現cutの先頭`0F`率は
`1000/(1000+100)=90.91%`、偶奇反例は100件と予測する。
`s=10/53/100/190`の段階注入では先頭率を99.01/94.97/90.91/84.03%と予測し、
m6nの84〜95%域を境界誤認だけで横断できる。

**偽結合腕:** 真のrun間の境界を`m`箇所で`$FE/$FF`だけへ置換し、現cutに許容させる。
二つの3バイトrunが6バイトrunになり、後半の真の先頭`0F`が継続位置へ誤帰属する。
`m=100`なら検出runは900本、先頭`0F`率900/900、継続`0F`なし率
`2000/(2000+100)=95.24%`、偶奇反例100件と予測する。
`m=20`では継続率99.01%、`m=353`では85.00%となり、m6nの85〜99%域を横断する。

割り込み受理だけを真のrun間へ置く条件は偽結合腕と同じ予測とする。
割り込みハンドラの非`$FE/$FF` I/Oをrun途中へ置く条件は偽分割腕と同じ予測とする。
intlog-aware／明示境界cutではいずれも基準の100%・反例0件へ戻る。

### 3. 検出力と空振り

- 正常形を各cutが無傷で受理し、偽の例外を0件とする。
- 上記すべての注入腕で、現cutが予測した分子・分母を**完全一致**で返す。
- 注入していない指標を変えない。FE注入をSEND runの結果へ、またはその逆へ数えない。
- 1件欠落、境界位置1件ずれ、先頭／末尾打切りを別故障として全件検出する。
- `LC_ALL=C`と利用可能なUTF-8ロケールで期待rcと集計が一致する。
- 故障注入は全件検出、空振り0件。SKIP、解析不能、0件入力は合格に数えない。

## 次フェーズの観測方法

1. 先に上記の規則生成selftestを実装し、予測値とrcを固定する。
2. 現cutの結果を既存4条件で再現する。ただしm6cログは共通clock付きintlogとの統合に
   制約があるため、再現だけをM/R判定には使わない。
3. d0/d1/d2/d5相当を共通clock付きiolog/intlogで各2走し、CPU別seq、共通clock、
   割り込み受理を統合した境界アンカーを作る。生データ値は使わない。
4. 各現行例外位置について、現cutとアンカーcutの境界が一致するか、直近に割り込み、
   ログ端、別ポートI/O、許容`$FE/$FF`だけの境界があるかを件数で分類する。
5. SEND run系では、一つの境界差が`0F`位置と偶奇反例の双方を予測どおり動かしたかを
   同じ注入ID／実ログclock窓で対応付ける。

境界アンカーは判定対象の`0F`有無、run長偶奇、末尾pc、bit0の成否を使って作らない。
結果を境界定義へ循環利用しない。

## 到達条件・不合格条件

### 例外が手法由来（M）だと結論する条件

対象系ごとに次を**すべて**満たすこと。

1. 合成正常形、段階注入、割り込み注入、端点故障が全予測値に一致し、空振り0件。
2. 新規2走の現cut例外が全件、アンカーcutとの偽結合／偽分割境界差、割り込み境界、
   またはログ端のいずれかへ一意に帰属する。
3. アンカーcutでは例外が0件になり、正常位置の分子・分母を不必要に変えない。
4. 同一条件2走で、例外件数だけでなく帰属カテゴリと補正後構造が一致する。
5. SEND run系では境界補正による`0F`率と偶奇反例の変化が合成予測と同方向・同件数で、
   両指標の異常が同じ境界差へ対応する。

率が0.11〜0.18%または84〜99%へ似ただけではM合格にしない。

### 例外が本当の実挙動（R）だと結論する条件

対象系ごとにMと対称に、次を**すべて**満たすこと。

1. 同じ合成selftestが全予測値に一致し、アンカーcutが注入誤差を除去できる。
2. 新規2走の例外位置で現cutとアンカーcutの開始・終了境界が全件一致する。
3. 例外位置の直近に割り込み受理、ログ端、別ポートI/O、許容イベントだけの曖昧境界が0件。
4. 境界が一致した同じ論理呼出し／runで、bit0反例、先頭`0F`欠落／継続`0F`混入、
   または偶奇反例が2走とも同じ構造として再現する。
5. SEND run系では`0F`と偶奇を別々に判定し、片方だけ残る場合は残った指標だけをRとする。

### どちらにも転ばない場合

一部だけ境界差へ帰属する、アンカー自体が作れない、2走で位置またはカテゴリが揺れる、
補正が正常標本まで変える、二指標が同じ境界差へ対応しない場合はXとする。
「混在」「識別不能」を件数付きで残し、3件を一括解消しない。SKIP、0件、解析不能、
単一走はM/Rの合格に数えない。

## 情報境界

- 今回読むのは公開リポジトリ内の仕様、ノート、解析器だけであり、`private/`、公式ROM、
  公式ディスク、生ログは開かない。実測は次フェーズまで行わない。
- 合成ログは規則生成し、公式由来のpayload値、データポート値列、ROM内部バイト列を使わない。
- 次フェーズで公式ログを扱う場合も、`$FB/$FC/$FD`の値列は表示、ノート転記、コミットしない。
  公開するのは件数、率、pcカテゴリ、port/kind、clock差、境界帰属、SHA-256、構造だけとする。
- 本稿は測定の事前登録だけであり、解析器、selftest、`src/`、`docs/spec/`を変更しない。

以上を実測前の事前登録とする。
