# l4-s1b — キーマトリクスのビットと入力される文字の対応 — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

[l4-design](l4-design.md) 段階1（main側L3の測定）のうち、l4-s1a（テキストVRAMの
属性・カーソル位置・スクロール）で対象外としたキー割り当てを測る事前登録である。
**実装は行わない。測定のみ。**

## 問い

- Q1 各キー（`00H`〜`0BH` の各ビット）を単独で押したとき、公式ROMがカーソル位置に
  書く文字コードは何か（書かないキーは「書かない」と記録）。
- Q2 修飾（SHIFT `08H` D6、カナ `08H` D5、GRPH `08H` D4、CTRL `08H` D7、
  CAPS `0AH` D7）を同時に押したとき、または切り替えた後に、Q1 の文字コードが
  どう変わるか。
  - 既知（l4-s1a 追補2 の切り分け）: 起動直後に英字キーを無シフトで押すと
    小文字が入る。CAPS の既定の状態がそれに関わる見込み（見込みであって
    前提ではない）。
  - CAPS とカナが「押している間だけ」か「押すたびに切り替わる」かを
    予備走で確かめ、切り替えなら「切り替える→文字キー→戻す」の順にする。
- Q3 `0CH`〜`0EH` のビット（MA 世代で増えた f6〜f10・BS・INS・DEL・変換・決定・
  PC・全角・RETURN/SHIFT の左右）を押したとき、公式ROMが反応するか（測定対象の
  ROM は 12 ポートしか走査しないと予想。予想であって前提ではない）。
- 対象外: キーリピートの時間、ファンクションキーの既定の割り当て文字列
  （別の事前登録。ROM のデータ表の再構成になるので扱いを先に決める）。数字・
  記号キーへの修飾の組み合わせ（Q2 は文字キー＝英字26種に絞る。必要なら次の
  事前登録で扱う）。

## 資料との照合

- マニュアル（PC-8801MA ユーザーズマニュアル p.233、`refs-pc8801ma-manual.md`）
  の表と、コアのキー対応表（QUASI88 `keyboard.c` の `keyport`、BSD-3）は、
  読み取りに自信の無かった6セル（`01H` D5・D6、`02H` D0、`05H` D3・D5、
  `07H` D7）を含めて一致する（`02H` D0=`@`、`05H` D3=`[`、D5=`]`、
  `07H` D7=`_`、`01H` D5・D6=テンキーの `,` `.`）。
- これは「どのキーがどのビットか」の資料どうしの一致であり、「そのビットで
  ROM が何の文字を書くか」ではない。Q1 はこれを測る。

## 条件

- 公式ROM一式、ディスク無し、コア既定 N88 V2。
- 押し方: `--key-matrix PORT:BIT:FRAME[:HOLD]`（コミット `cf677dc`）。
  `--type` とは同時指定不可（`main.c` 1721行以降で禁止）なので、settle も
  RETURN の直接押下（`01H` D7、`--key-matrix 0x01:7:300`）で行う。
- HOLD を省略した腕は、`main.c` の `--key-hold` 既定値である 4 フレームが
  使われる（1645〜1647行）。l4-s1a で `--type` の既定 hold=4 のまま文字が
  正しく反映された実績（`l4-s1a-text-vram-results.md` G3・G4 とも真）を
  そのまま流用し、単独押下・0CH〜0EHの腕はすべて HOLD を省略する。
- 1走で押すキーは1つ（＋修飾）。押す前と後の写しを1回の走行に含める
  （`--vram-dump` は最大16組指定できる、`main.c` 231行 `VRAM_DUMP_MAX`）。
  差分は `tools/l4_vram_probe.py --diff-before/--diff-after`（コミット
  `02035a4`）で取り、押す前後の写しの1組を渡す。

### 押すフレーム・保持・写しのフレーム

- 押すフレーム: 単独腕・0CH〜0EH腕は 700。根拠: l4-s1a の実コマンド打鍵開始
  フレームおよび `tools/conform_l3.sh` の全シナリオが統一して使う値をそのまま
  流用する（起動が確実に完了している時点であることは l4-s1a で確認済み）。
- 修飾×文字キー腕: 修飾を 700 で押し、HOLD=30 で保持したまま、文字キーを
  710（修飾開始の10フレーム後）で押す。文字キーの HOLD は省略（既定4）。
  根拠: 修飾は文字キーが押されている全期間（710〜714）下がっている必要が
  あるため、修飾の HOLD は「文字キー開始オフセット10＋文字キーHOLD4＋
  余裕16」＝30に決める。10フレームの前置きは、修飾ビットの書き換えが
  次のretro_run直前に確実に1回は反映されてから文字キーを押すための余裕
  （器具は同一フレームでの同時押しも扱えるが、修飾→文字の順に分けたほうが
  「切り替えてから押す」CAPS/カナの手順と揃うため統一する）。
- 写し（押す前）: 押すフレーム − 10（修飾腕は 690、修飾の押下より前）。
  下書きの式をそのまま採る。
- 写し（押した後）: 押すフレーム + HOLD + D。D は「反映の遅れ」で、以下の
  予備走で決めて固定する（関門G6）。
- 予備走（反映の遅れDの決定）: G4 の陽性対照キー（`04H` D1、`Q`）を frame 700・
  HOLD 省略（4）で押し、写しを 690（前）と 714+10, 714+20, 714+40, 714+60
  の4点（同一走行内、`--vram-dump` を5回指定）で取る。差分モードで目印
  （前が空白だったセルへの文字コード）が最初に現れる最小の候補値を D として
  以後の全腕に固定する。この予備走そのものは測定対象キー（Q）を使うが、
  Q1 の90腕には数えず、G6 の根拠としてのみ報告に残す。
- 走行フレーム数: 900（写し(後)の最大見積り 714+60=774 に十分な余裕を
  持たせた値。BASICコマンドの実行完了を待つ必要が無く、レジスタ直接操作の
  反映を見るだけのため、l4-s1a のS予算(2400)より短くてよい）。
- 各腕は2回走らせる（G3）。乱数要因は無いため、同一の指定をそのまま
  再実行するだけでよい。

### CAPS・カナの切り替え確認（予備走）

Q2 のCAPS・カナ腕を「押している間だけ」か「切り替え」かで手順を分けるため、
本測定前に次の予備走で確かめる。結果はQ2の判定に使う指標であって、Q1〜Q3の
判定そのものは動かさない。

- CAPS: T1「タップ」— CAPS(`0AH` D7)を700・HOLD 4（既定）で押してすぐ離し、
  Q(`04H` D1)を720・HOLD既定で押す。T2「保持」— CAPS を700・HOLD 60で
  押しっぱなしにし、Qを720・HOLD既定で押す（720〜724もCAPSは下がったまま）。
  写しは690（前）・724+D（後）を共通で使う。T1とT2で出た文字コードが
  無CAPS基準（l4-s1a追補2の`q`=0x71）と異なるかどうかを比べ、タップ後に
  変わればトグル、保持中だけ変わればホールド型と判定する。
- カナ: 同じ形（T3タップ／T4保持）を、カナ(`08H` D5)とQで行う。加えて
  T3の直後（Qの反映を見たあと）にもう一度別の文字キー（`05H` D0、`X`）を
  760・HOLD既定で押し、写しを690（前）・764+D（後）で取る。2つめの文字
  キーでも同じ変化が残っていればトグル（押すたびに切り替わり、次のキーにも
  効き続ける）、残っていなければ単発（そのキー1回だけに効く）と判定する。
- この予備走で「トグル」と判定した修飾は、Q2の本走でも「切り替える→文字
  キー→（必要なら）戻す」の順（下書きどおり）にする。「保持型」と判定した
  修飾は上記の修飾×文字キー腕の手順（修飾を押しっぱなしのまま文字キー）を
  そのまま使う。

### 腕

- **Q1（単独押下）**: マニュアル表（`refs-pc8801ma-manual.md` 1節）の
  `00H`〜`0BH`（12ポート×8ビット=96）のうち「—」でない位置。`0BH` の
  D2〜D7の6セルが「—」のため、90腕。
- **Q2（修飾×文字キー）**: 修飾5種（SHIFT・カナ・GRPH・CTRL・CAPS）×
  文字キー26種（`A`〜`Z`。マニュアル表で英字が並ぶ `02H`〜`05H` の各ビット）
  ＝130腕。文字キーを英字26種に絞る根拠: マニュアル表でA〜Zが連続して
  並ぶ唯一の集合であり、修飾の効果（大文字化・カナ化等）を見るのに十分な
  代表集合であるため。数字・記号キーへの拡張は対象外（上記「対象外」参照）。
- **Q3（0CH〜0EH）**: マニュアル表で「—」でない位置。`0CH` は8（f6〜f10・
  BS・INS・DEL）、`0DH` は4（変換・決定・PC・全角）、`0EH` は4
  （RETURN(JIS)・RETURN(10KEY)・SHIFT左・SHIFT右）＝16腕。`0DH`・`0EH` の
  「—」8セル（キーの割り当てが資料に無い）は、Q1・Q3と同じ「表の「—」を
  除く」規則に揃え、対象外とする。
- 合計 90 + 130 + 16 = 236腕、各2走（G3）＝472走。

## 本文を出さない取り扱い（禁止事項7）

- 写しと記録は使い捨ての作業ディレクトリ（リポジトリ外）に置き、コミット
  しない。終わったら削除する。
- 解析道具（`tools/l4_vram_probe.py` の差分モード、コミット `02035a4`）が
  出してよいもの: 押す前後で値が変わったセルの (row0, col0, 番地) と、
  **押す前が空白（0x20）だったセル**の押した後の文字コード。押す前が
  空白でないセルが変わった場合は「空白でないセルが変化」と件数だけ出す
  （起動画面の文字を出さないため）。属性域の変化は (row0, 属性域内位置,
  番地) と前後の値（ハードウェア設定値のため出してよい）。
- キーを押して出る1文字の文字コードは、入力に対するROMの応答の観測であり、
  `docs/spec/` へは「挙動から再構成した対応表」として記録する（禁止事項4
  後段、L2 のコード割り当てと同じ扱い）。
- 解析道具は `screen_content_leak_selftest.sh` の対象に加え、陰性対照つきで
  本文が漏れないことを確かめてから使う。

## 関門

- G1 器具: `key_matrix_selftest`・`vram_dump_selftest`・leak selftest
  （差分モードの陰性対照を含む）が OK。
- G2 取りこぼし0、打鍵系の警告0。
- G3 決定論性: 各腕2走で差分の結果が一致（VRAM写しはファイル全体sha256、
  差分出力はJSON全体で比較。l4-s1a追補1の作法に合わせ、見出しに作業パス等
  可変値が入る出力は使わない）。
- G4 陽性対照: `04H` D1（Q）を押すと、差分の「前が空白だったセル」に1文字
  現れる。その文字コードが、`--type 'Q'` で打った別の走（l4-s1a 追補2の
  切り分けでは小文字 `q`＝0x71 が入る）と同じ位置・同じコードであること。
  0x51 か 0x71 かを事前に決め打ちしない。
- G5 陰性対照: 何も押さない走（`--key-matrix` を指定しない、settleのみの
  走）で差分0。
- G6 反映の遅れ: 上記の予備走で決めたD（フレーム数）で、G4のセルが
  現れていること。以後の全腕でDを固定して使う。

## 判定

- Q1: 各ビットについて `writes_code(xx)`／`no_write`／`nondeterministic`
  （G3の2走で結果が割れた場合）。
- Q2: 修飾ごとに、Q1 との対応表（変化なし・別コード・書かない）。CAPS・
  カナは「トグル」か「保持」かの判定結果（予備走 T1〜T4 の結果）を併記する。
- Q3: `0CH`〜`0EH` の各ビットで `no_reaction`（差分0かつ I/O の読み取りに
  該当ポートが現れない）／`reacts`。
- 行き先: `docs/spec/l3-main.md` のキー入力の節。
