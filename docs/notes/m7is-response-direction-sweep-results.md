# m7is: 応答（sub→main）を掃引して、「9」が動くかを見る — 結果

実施日: 2026-09-07

## 位置づけ

[m7ir](m7ir-response-direction-sweep-preregistration.md)が事前登録した測定の
結果である。事前登録は測定開始前に単独コミット（`4e7bd20`）してあり、本稿では
候補規則・モード・分類・判定規則を後から動かしていない。`src/`・`tools/`は
本稿では変更していない。

**結論を先に書く: 主判定はT2（「9」は動かないが影響はある）である。**
60armすべてを測ったが**C型（9以外のrun長）は1本も出なかった。**
**現れたrun長は`1`と`9`の2種類だけ**である（`m7iq`と同じ）。

**これで方向の非対称も埋まった。** 累計**191arm**、C型は**0本**である。

**さらに`main→sub`側との対比で新しいことが1つ分かった**——応答を壊しても
**周期数（12）すら動かない。** `main→sub`側では11本・13本が現れたが、
本稿では**12本のまま保たれるか、入口へ到達しないかの二択**だった。

- **長さ256が4本**（run 9・15・25・33）
- **長さ5632が1本**（run 29。`m7hy`が全長一致を確認した大量転送）

## 記述（判定ではない）: 応答を壊しても周期数すら動かない

**run長9の本数の分布が、`main→sub`側と際立って違う。**

| run長9の本数 | 本稿（応答・60arm） | `m7iq`（要求・70arm） |
|---:|---:|---:|
| 0（入口未到達） | **4** | 20 |
| 11（1本減る） | **0** | 0 |
| **12（基準どおり）** | **56** | 45 |
| 13（1本増える） | **0** | 5 |

**応答側では、周期数が12から動いたarmが1本も無い。** 動くのは「入口へ到達
できたかどうか」だけで、到達できたなら**必ず12本**である。

一方`main→sub`側（`m7io`・`m7iq`）では、要求を壊すと**11本に減ったり13本に
増えたり**した。

### 長いrunの結果（256・5632）

| run | 長さ | `xor-first` | `xor-all` |
|---:|---:|---|---|
| 9 | 256 | D型（FDC218・READ119・9が12本） | D型（FDC214・READ118・9が12本） |
| 15 | 256 | **A型**（基準と完全一致） | B型（FDC23・READ2・9が0本） |
| 25 | 256 | D型（FDC222・READ120・9が12本） | B型（FDC27・READ3・9が0本） |
| **29** | **5632** | B型（FDC47・READ8・9が0本） | B型（FDC47・READ8・9が0本） |
| 33 | 256 | **A型**（基準と完全一致） | **A型**（基準と完全一致） |

- **run 33（256バイト）は`xor-all`でも基準と完全一致**——256バイト全部を反転
  しても、FDCから見た結果が1つも変わらない。
- **run 29（大量転送5632バイト）は`xor-first`でも`xor-all`でも同じ結果**に
  なり、どちらも入口へ到達しない。**先頭1バイトを壊すだけで起動が続かない。**

**言えること:**

- **C型は1本も無い。** 応答を壊しても、強い摂動（`xor-all`）でもrun長9は動かない。
- **現れたrun長は`1`と`9`だけ**（`m7iq`と同じ）。
- **応答側では周期数（12）すら動かない。** 到達できれば必ず12本である。
- 全armで`changed>=1`。介入は全部届いている。
- 道具の検算（長さ1で両モードが一致）が25本すべてで通った。

**言えないこと:**

- **位置を選べないので、`main→sub`側と同じ密度では触れていない**（事前登録に
  明記した限界）。押さえたのは`xor-first`（先頭1バイト）と`xor-all`（全体）の
  2点だけで、**中間の位置だけを変えた場合を測っていない。**
  **「応答の全位置を触った」とは言えない。**
- **`xor-first`と`xor-all`の中間が空いている以上、「9」を動かす位置が
  その間にある可能性を排除していない。**
- **4armは入口へ到達していない可能性がある**ため証拠として弱い。有効なのは
  56armである。
- run 33が`xor-all`でも無反応な理由は測っていない。
- run長や本数から元の値を逆算していない（禁止事項5）。
- 条件O・`disk#10`という1本のディスク・1条件である。一般性は主張しない。

**それでもrun長9は一度も動かず、現れたrun長は常に`1`か`9`だけだった。**

## この結果の使い道（事前登録が先に定めたとおり）

`m7ip`／`m7ir`が定めたとおり、**「要求のバイト列を触る経路では『9』に届かない」**
に加えて、**「応答を触る経路でも届かない」**を3節へ記録する。

**ただし「『9』の出所はROM内部である」とは主張しない。** 言えるのは
**「これらの経路では届かない」**までである（3節・第28版の書き方に揃える）。

**残る未閉経路:**

1. **ビットの非対称**（要求側）——入口場面より前の18本には`XOR 0xFF`しか
   当てていない。全ビットへ広げると560arm。
2. **位置の非対称（応答側）**——本稿の新しい未閉。`xor-first`と`xor-all`の
   中間が空いている。道具に位置指定を足せば埋まる
   （`--request-intervention`と同じ拡張を`sub→main`側にも作る）。
3. **ディスクの側**——`m7il`が土俵無しと記録したまま。

## 開示

- 掃引は60armで時間がかかったため**バックグラウンドで実行した**（事前登録の
  取り決めどおり）。測定中に`git stash`・ブランチ切替・`src/`の編集は行って
  いない。
- 各armの生ログは指標を取り出した直後にscratchpad内で削除した。決定論性の
  確認対象は**その場で2回走らせて比較**してから削除した。
- 実行したarm数（60）を出力に載せ、候補個数×2（60）と一致することを確認した。
- 事前登録は`xor-tail`・`replace-*`を使わないと明記しており、使っていない。
- 本稿は委譲を行っていない。測定・解釈・判定はすべて親セッションで行った。
- 上記以外の手順逸脱・事故は無い。無言でSKIPした分岐は無い。

## 情報境界

公式ROM・公式ディスクのバイト列、公式ROMの逆アセンブル、`private/`の内容は
読んでいない・出力していない。**公式ディスクのイメージを直接読んでもいない。**
記録したのは公開μPD765コマンド種別名、件数、run長とその多重集合、交換run
番号・方向・長さ・開始clock、**当てたビットマスクの値とモード名**、真偽値、

逆算してもいない。** 資料は参照していない。生ログ・ディスク複製・使い捨て
スクリプトはリポジトリ外（scratchpad配下）に置き、コミットしない。
