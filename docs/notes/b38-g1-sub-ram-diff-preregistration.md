# B38: スペース後の G1 で、値が違う直前のサブ RAM のどこが公式と違うかを値なしで測る — 事前登録

記録日: 2026-11-01
位置づけ: [B37](b37-g1-sub-rom-reads-results.md) の次段。**このノートは測定より先にコミットする。**

## 1. 問い

`IN $FC` の最初の違い（番号 76570、0 始まり）の直前に、サブの RAM とレジスタのどこが公式と違うか。違う番地を最後に書いたのは誰か。

B34 では RAM 上のコードは ROM の領域も未書き込みの RAM も読まない。B36 ではポートからの入力も分かれ目まで同じである。B37 では窓の中に ROM 側の RAM の読みが見えなかった。残る出どころを、値を見ずに絞る。

## 2. 器具

コアに `--sub-snapshot FILE` と `--sub-snapshot-at-fc N` を足す（パッチ 0021）。既定は無効で、無効なら動作を変えない。

main の `IN $FC` の通し番号が N になった時点で、サブの `0x4000-0x7FFF` の内容、書き手の分類（B34 と同じ）、Z80 のレジスタを作業場のファイルへ書く。**この生のファイルは開かず、コミットせず、ライブラリへ置かない。**

比較ツールは 2 つの生のファイルを読み、次の行だけを出す。**値は出さない。**

- `# 識別子: G1`
- `D <開始>-<終了> <左の書き手> <右の書き手> <バイト数>`（書き手の組が同じで連続する違いをまとめる）
- `REG <名前> <same|differ>`
- `total differ=<N>`

器具は G1 なしで自己検査する。陽性対照は 1 バイトと 1 レジスタの違いの検出、陰性対照は同じ内容で `D` が 0 行になること、値が出力へ出ないこと、無効時の動作が変わらないこと。

## 3. 条件

腕 F の 4800 フレーム。N=76569（最初の違いの 1 つ前の読み）で OO・SS 各 2 走。自作 ROM は ff113bf の配布ビルド。クラウドの実行環境で行う。

関門: 同じ走の `IN $FC` の差が B30 と同じ（257 件、最初 76570、連続 132）。OO どうし・SS どうしの比較の `total differ` が 0 で、`REG` がすべて `same`。

B37 の陽性対照: 同じ条件で `--sub-rom-read-window 0,2000` の走を OO・SS 各 1 走し、`W` の行の数だけを書く。

## 4. 記録の白リスト

第 2 節の比較ツールの行と、陽性対照の `control <OO|SS> W=<N>` だけ。

## 5. 判定（事前に決める）

- `D` の行を番地順にそのまま並べ、`REG` の `differ` を書く
- 書き手の組ごとの合計バイト数を書く
- `D` が RAM 上のコードの読む区間（B34）と重なる行を別に挙げる
- 原因は断定しない。自作 ROM の作業域の違いは当然出るので、違いがあること自体を不具合としない
- 陽性対照の `W` が SS で 0 なら、B37 の 0 件は根拠にしない
