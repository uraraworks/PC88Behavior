# m7dv: 自作ファイル本数ラダーによるディレクトリ拡張境界の事前登録

実施日: 未実施（本稿は事前登録のみ。測定はまだ行っていない）

本稿は`m7dn`が次点候補としたディレクトリ拡張境界を、公開仕様から境界本数を
仮定せず、自作ファイルを1本ずつ増やす介入で探索する手順を固定する。焦点は、
ファイル数Nの増加に対して、追加READ、未見の公開FDCコマンド種別、または異なる
値非表示制御構造が階段状に現れるかである。`m7dt`と同じく、実測後に割合閾値や
近さを導入せず、隣接段階の整数差をそのまま判定する。`src/`は変更しない。

公式ROM・公式ディスクの内容は読まず、生ログ、画面報告、媒体複製、準備チェック
ポイントは全てリポジトリ外へ置く。データポート値は1バイトも表示・転記せず、
`cmp -l`等でファイル内容を出力する比較も行わない。参照先は
`PC88_REF_ROM_DIR`/`PC88_REF_DISK_DIR`だけで測定器へ渡し、`private/`を開かない。

## 仮説と識別境界

- **H-P（同一管理範囲内の定常費用）**: 追加した自作ファイルが同じディレクトリ管理
  範囲へ収まる間、固定した不存在OPENのmain `IN $FC`件数・READ単位・FDCコマンド
  種別列は同じで、隣接差分は0になる。もしファイル1本ごとの一定費用が出る実装なら、
  差分ベクトルが複数Nで完全に同じ値を反復する。
- **H-X（管理範囲拡張）**: あるNで管理領域の新しい読出し範囲へ跨ぐと、不存在検索が
  追加管理領域を読むため、main `IN $FC`またはREAD単位が正方向へ跳ねる。公開FDC
  コマンド列ではREAD単位の追加、場合によってはSEEK等の追加が現れ、その後は次の
  境界まで新しい水準へ留まると予測する。
- **H-C（未見制御構造）**: 境界で従来の列に無い公開FDCコマンド種別、または既存列の
  単純な延長ではない値非表示イベント構造が現れる。これは「境界候補で新しい経路を
  踏んだ」ことを支持するが、ディレクトリ内部形式や特定ROM機構の証明とは呼ばない。

媒体上の管理形式、1管理単位に収まるエントリ数、境界の絶対ファイル数は仮定しない。
本稿のNは「固定した公式diskA複製へ追加した自作ファイル数」であり、元から存在する
項目数を読まず、総項目数とも呼ばない。

## 媒体と自作ファイル

公式diskA原本からリポジトリ外へ使い捨て複製を作り、公開D88ヘッダの保護フラグを
複製だけで解除する。原本は変更しない。N=0を自作ファイル追加前の基準チェックポイント
とし、N=1〜64では次の規則で作る空のシーケンシャルファイルを順に1本ずつ追加する。

```text
名前(N) = "QD" + CHR$(65 + INT((N-1)/26)) + CHR$(65 + ((N-1) MOD 26))
```

従ってN=1は`QDAA`、N=64は`QDCL`である。各準備runは対象名を
`OPEN ... FOR OUTPUT AS #1`して直ちに`CLOSE #1`し、内容を一切書かない。
空ファイルにするのはデータ領域消費を抑え、ファイル本数／ディレクトリ管理だけを
主に振るためである。名前、作成順、空内容は全Nで固定し、KILLや上書きは行わない。

公式媒体の既存ファイル名・内容は一覧化も判定にも使わない。元媒体は全Nで同じなので、
隣接差分を生む操作上の介入は上記自作ファイル1本だけである。ただし元媒体の初期占有は
固定された交絡として残るため、見つけたNを他媒体の絶対境界へ一般化しない。

## 各Nで固定する測定操作

FILESは公式媒体の既存ファイル名一覧を出力し、その内容へ判定が依存しうるため使わない。
全Nで、作成集合に含めない固定自作名`QZ9X`をINPUTでOPENし、存在しないことによる
エラーを自作エラーハンドラで捕捉する。同じ不存在名を検索させることで、見つかった
項目の内容や位置ではなく、検索終端までの管理領域アクセスを比較する。

```basic
10 ON ERROR GOTO 100
20 OPEN "QZ9X" FOR INPUT AS #1
30 PRINT "D9N":END
100 IF ERL<>20 THEN PRINT "D9N":END
110 PRINT "D9E"
120 RESUME 130
130 PRINT "D9C":END
RUN
```

N=0の校正で`D9E`へ到達せずOPENが成功した場合、固定不存在名という介入が成立しない
ため全系列を実測前不成立として打ち切る。実測後に別名へ交換しない。

測定runは完成チェックポイントの新しい使い捨て複製を使い、媒体へ保存しない。
全Nを公式一式で各2run、計130run測る。境界発見を目的とする一次系列は公式だけとし、
混成との入口適合比較は境界Nが確定した後の別事前登録へ分ける。単一走は採用しない。
全条件を9000フレーム、300F/700Fの二段打鍵、300秒・512打鍵上限、同じハーネス
引数に固定する。

## 観測量と区間

全runで次だけを集計する。値そのものは出力しない。

- main `IN $FC`/`IN $FD`の件数とSHA-256
- 公開FDCコマンド種別列、その総件数、READ DATA・SEEK・WRITE DATA件数
- 700F以後の入口区間について、main `IN $FC`件数、READ単位、FDCコマンド種別列
- 値を除いた`cpu/kind/port/pc`イベント列の件数・SHA-256、隣接N間の一致prefixと
  最初の差の位置
- 画面の行数・文字数・SHA-256、取りこぼし件数

境界判定の一次指標は、入口区間の
`X_N = (main IN $FC件数, READ単位)`とする。全runで起動列を含む全体値も記録するが、
判定は同じ700F境界で切った入口区間を使う。SHA-256は同一Nの決定論性と適用範囲確認に
使い、大小・近さの判定へは使わない。測定操作は読出しだけなのでWRITE DATAが1件でも
出たrunは不採用とする。

## 差分と「跳ねる」の固定判定規則

隣接差分を2指標それぞれについて次のとおり定義する。

```text
Delta_N = X_N - X_(N-1)    (N=1..64)
```

任意の件数幅・割合・誤差許容は置かず、整数の完全一致と共通方向だけで判定する。
`Delta_1`は最初の1本追加に対する基準差分とし、それ単独では数値境界と呼ばない。
N=2〜64では`Delta_N`と`Delta_(N-1)`を次の規則で比較する。

1. 2指標とも完全一致なら**定常差分**であり、Nで新しい数値境界を跨いでいないとする。
   差分が非0でも、同じ1本当たり費用が反復しただけなら境界とは数えない。
2. `Delta_N`の両成分が`Delta_(N-1)`以上で、少なくとも一方が厳密に大きければ、
   **正方向の数値ジャンプ候補**とする。一方が等しく他方だけが大きい場合も含む。
3. 両成分が以下で少なくとも一方が厳密に小さければ**負方向変化**、一方が大きく
   他方が小さければ**方向不一致**とし、H-Xの支持へ数えず未確定の変化点として記録する。
4. FDCコマンド種別列に過去Nで0件だった公開コマンド名が初出すれば、数値方向に
   関係なく**未見経路候補**とする。コマンド語彙が同じでも、N-1の入口FDC列を
   strict prefixとして保って後続コマンドが増えれば**構造的延長**、prefixを保たず
   種別順が変われば**構造変化**として分けて記録する。

N=1で構造的延長・構造変化・未見コマンドが出た場合は「探索下端の構造候補」として
記録するが、直前差分が無いため数値ジャンプとは呼ばない。N=64でも同じ隣接差分規則を
適用し、上端だから判定を緩めない。

数値ジャンプまたは未見経路候補を得たNは、保存チェックポイントとは別に、直前の
8本境界アンカーからN-1/Nを独立に再構築して各2run再測定する。再構築でも同じ符号・
件数差・構造分類が完全再現した場合だけ**確認済み境界候補**とする。再現しなければ
媒体系列固有または非決定として支持にも反証にも数えない。複数候補が出れば全て同じ
規則で確認し、最初の候補だけを恣意的に採らない。

## 到達条件・陽性／陰性対照

各測定runの到達条件は次のANDとする。

1. 固定プログラムと`RUN`が画面へ反映される。
2. OPEN行だけでエラーを捕捉したことを示す`D9E`へ到達し、`D9N`が出ない。
3. `RESUME`後の`D9C`と直後`Ok`へ順に到達する。
4. 入口区間のmain `IN $FC`またはREAD DATAが1件以上で、不存在検索がI/O 0件の
   空振りになっていない。
5. main/sub各ヘッダの取りこぼしが0件である。

陽性対照は固定プログラム、`RUN`、`D9E`、`D9C`、直後`Ok`、非0入口I/Oを持つ合成形、
陰性対照はOPEN行欠落、別行エラー、`D9E`欠落、`D9N`出現、`D9C`欠落、直後`Ok`欠落、
入口I/O 0件とする。件数、SHA-256、期待値0行の故障も全て不一致にする。

## 介入成立とチェックポイント検証

N段階の介入成立は、測定到達とは別に次を全て要求する。

1. N=0は原本から作った使い捨て複製で、固定名`QZ9X`が不存在エラーになる。
2. N>0の準備runは、N-1チェックポイントの複製へ名前(N)を1本だけ作り、固有作成
   マーカーと直後`Ok`へ到達し、WRITE DATA 1件以上、取りこぼし0件となる。
3. 各チェックポイントの媒体SHA-256をリポジトリ外manifestへ記録し、N-1とNが
   不一致である。SHA-256は媒体内容を表示せず、再開時の取り違え検出にだけ使う。
4. N=8,16,...,64の各ブロック末端で別プロセス検証runを行い、N=1から当該Nまでの
   自作名を生成して各々INPUTでOPEN直後CLOSEする。全て通過した場合だけ固有ブロック
   マーカーを表示する。内容は読まず、公式既存名も参照しない。
5. ブロック内各Nの作成マーカー、WRITE非0、媒体SHAが揃い、ブロック末端の全名OPEN
   検証が通った後に、その8チェックポイントを測定へ使う。1つでも欠ければ当該ブロック
   全体を不成立として直前アンカーから作り直す。

ブロック末端Kの検証プログラムは次の形へ固定し、`K`と末端マーカーだけをブロックごとに
置換する。欠落ファイルが1本でもあれば実行時エラーでマーカーへ到達しない。打鍵文字数は
K=64でも512上限内である。

```basic
10 K=8
20 FOR I=1 TO K
30 F$="QD"+CHR$(65+INT((I-1)/26))+CHR$(65+((I-1) MOD 26))
40 OPEN F$ FOR INPUT AS #1:CLOSE #1
50 NEXT I
60 PRINT "V008":END
RUN
```

同一Nの2runは、全イベント列、画面、main受信件数・SHA-256、FDCコマンド種別列が
完全一致することを必須とする。介入不成立、到達失敗、取りこぼし1件以上、2run非一致の
Nは差分系列へ入れず、隣接差分も欠測とする。欠測を0差やジャンプへ読み替えない。

## 準備の分割・再開

長い準備をN=1〜8、9〜16、…、57〜64の**8ブロック**へ分割する。実行者が明示した
リポジトリ外の`PC88_M7DV_WORK_DIR`に、読出し専用化した各Nのチェックポイント、
ブロック末端アンカー、件数・SHA-256だけのmanifestを保存する。生iolog、画面、標準出力、
標準エラーは同じ外部領域のrawサブディレクトリへ置き、ノートには持ち込まない。

各Nは直前の受理済みチェックポイントを複製し、その複製へ1本だけ追加して作る。
準備runが落ちてもN-1を変更せず、候補Nだけを捨てて再実行できる。8本を作り終えたら
ブロック末端の全名OPEN検証を済ませ、そのブロックのNを各2run測定し、安全な集計表を
manifestへ追記してから次ブロックへ進む。中断後はmanifestのN・媒体SHA・完了フラグを
再検査し、最後に完了したブロック末端から再開する。原本やN=0からやり直さない。

通常系列の実行予算は、N=0測定2runに加え、各8本ブロック当たり準備8run・末端検証
1run・測定16runの25run、8ブロックで合計**202run**と事前に見積もる。確認済み候補の
独立再構築はこの外数とする。1回で全てを完走させず、ブロック完了ごとに安全な集計を
ノートへ追記できる単位で進める。

チェックポイントは公式ディスク由来の複製なのでリポジトリへ置かず、コミットしない。
測定完了後の削除時期は実行者が結果確認後に決め、途中で自動削除して再開不能にしない。

## 不合格条件・打ち切り条件

次のいずれかに該当するrunは不採用とし、受理済み直前チェックポイントから同じNを
再実行する。規則、上限、名前、操作は変えない。

- 固有作成／検証／測定マーカー、`D9E`、`D9C`、直後`Ok`のいずれかを欠く、または
  `D9N`が出る。
- 作成runのWRITE DATAが0件、測定runのWRITE DATAが1件以上、測定入口I/Oが0件。
- 取りこぼしが1件以上、同一Nの2runが決定論的一致しない。
- 固定した原本、作成順、空内容、N、フレーム数、打鍵時点、ROM構成、ハーネス引数から
  逸脱する。
- q88measureの既知の起動時クラッシュ以外でrc非0となる。

同じブロックを直前アンカーから1回再構築しても全名OPEN検証に通らない、9000フレーム・
300秒・512打鍵で到達できない、取りこぼし0件または2run決定論性を得られない、
あるいは公式媒体内容・データポート値を表示する危険が生じた場合は、そのブロックで
系列を打ち切る。N<64で空ファイル作成が容量／ディレクトリ上限エラーになった場合も、
それ自体を「ジャンプ」や未見経路支持へ数えず、**容量端点として最後に成立したNで
打ち切る。** 以後を欠測とし、64まで探索したとは書かない。

## 上限到達時の結論

上限は**N=64**とし、実測後に延長しない。N=0〜64の全段階が成立し、確認済みの数値
ジャンプ、未見FDCコマンド、構造変化が1件も無ければ、**「固定した公式diskA基準へ
自作空ファイルを64本追加する範囲では、観測可能なディレクトリ拡張境界を踏まなかった」**
と記録して打ち切る。これは境界が存在しないという反証ではなく、境界が64より先、
初期占有より手前、または今回の不存在OPENと観測指標では見えない可能性を残す。

全`Delta`が同じ非0値で境界を一意に選べない場合も、「1ファイル当たり定常費用は観測
したが、0〜64で差分変化点は識別できない」と記録する。方向不一致や負方向変化だけが
出た場合は未確定とし、都合よく正方向ジャンプへ読み替えない。

## 解釈限界

- Nは固定した元媒体への追加本数であり、元媒体の既存項目数やディレクトリ内部形式を
  読んでいない。確認済み候補を「総ファイル数Nの仕様境界」とは呼ばない。
- 不存在OPENは検索終端まで管理領域を調べるという操作上の予測で選ぶが、内部で何を
  検索したかを直接観測しない。追加READをディレクトリ、アロケーション表、SEEK等の
  1機構へ帰属しない。
- 空ファイル、固定作成順、同じ媒体、QUASI88上の結果であり、内容ありファイル、削除・
  再利用、別媒体、実機一般へ一般化しない。
- 本探索で新しい公式経路を見つけても、自作subとの適合や実装要件への採否は別測定・
  別事前登録で決める。

## 情報境界

記録するのはN、件数、差分、位置、frame、clock、SHA-256、画面の行数・文字数・
SHA-256、自分で打鍵した文字列・自作ファイル名、公開μPD765コマンド名だけとする。
画面本文、公式ディスクの既存ファイル名・内容、公式応答値、データポート値列は記録
しない。生ログ、媒体複製、チェックポイント、manifestは全てリポジトリ外で扱う。
