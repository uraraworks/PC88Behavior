## 資料と読んだ頁

CLAUDE.md全文、docs/notes/l4-s9b-peek-poke-preregistration.md全文、
tools/l4_peekpoke_measure.py全文、tools/l4_peekpoke_selftest.sh、共通器具
tools/l4_strfunc_measure.pyを読んだ。コミットa0f958bのメッセージを確認した。
自作CLEARは第2引数を受理するが配置には反映しないという既知の制約を踏まえる。
公式ROM内部の作業領域・エントリ番地を記した資料（CLAUDE.mdの分類(b)）は読んでいない。

資料は ../refs/NEC PC-8801mkIIMR N88-BASIC N88-日本語BASIC REFERENCE MANUAL 1986年.pdf。
前段の表紙・まえがきによるNEC純正言語仕様書という判定を継承する。
今回はPDF物理11・12頁（目次iii・iv）、105・106頁（本文2-23・2-24、CLEAR）、
167頁（本文2-85、FRE）だけを pdftoppm の150dpiページ画像で読んだ。
FREは索引を使わず、目次12頁の2-85から物理167頁を特定した。
PDFのテキスト抽出・本文走査は行っていない。

CLEARの第1引数はストリング領域の大きさという書式だが、意味を持たず、指定しても
影響はない。必要なストリング領域は自動確保する。
第2引数はBASICが使うメモリの上限番地。その番地以後の利用者データ等をBASICが
破壊しないと説明する。第3引数はFOR・GOSUB・PAINT用スタックの大きさをバイト数で
指定し、リセット時初期値は512。スタックは上限を起点に低い番地側へ確保する。
CLEARは数値変数を0、文字変数を空文字にし、配列宣言とDEFによる定義・指定を無効にする。

FREの引数は0・1・2。0は単純変数・配列・ストリングに利用可能な未使用変数領域の
バイト数、1は未使用プログラムテキスト領域、2は両者の和。0・2は文字列領域の整理を
必ず行う。掲載値は構成によって異なるので固定値予測にしない。
`fre("")`の受理・意味はこの頁に記載がなく、予測しない。

## 候補と決めないこと

候補名は **P_MANUAL**。同じプログラム量・変数量・スタック設定で上限だけを下げた
場合、未使用変数領域が同じ差だけ減るという候補を比較する。
ただしFREはテキストと変数の領域を区別するので、傾き1は前提として確定せず観測する。
第3引数の増分だけFREが減ることも比較候補とする。これらはマニュアルの領域説明からの
推論であり、文面が数式を保証しているという主張ではない。

受理境界の番地・既定FRE値・境界でのERR番号は **予測なし（観測する）**。
指定が過大・過小の場合に誤る可能性は観測対象で、具体的なERR番号は先取りしない。
受理された点で F(a2)-F(a1)=a2-a1 を確認し、各同形既定対照F0(a)が安定していて
同じ作業量の仮定が成り立つ場合だけ、既定上限の候補式
`U0 = a + F0(a) - F(a)` を結果ノートで評価する。
整数化・端点の包含による差も結果で検討し、ここでU0の値を決めない。

ROM内部の作業領域配置、プログラム本文の置き場所、機械語は決めない。
PEEK・POKE・機械語呼出しは生成しない。格子の境界を細かく詰める場合は別の追補を登録する。

## 腕と採取

定数対照2腕（PRINT 73、ERROR 5→ERR=5）。観測71腕と合わせて **73腕、各2走**。
格子は0x8000から0xFC00まで0x400刻みの32点＋0xFFFFの端点、計33点。
各点1腕1値で独立起動する。第3引数は `clear ,49151,256` と
`clear ,49151,1024` の2点。今回の2点同士は同形既定対照との差を使い、受理される場合に768バイト差の候補を比較する。

各CLEAR腕には同じ全プログラムを保持し、行10の `goto 20` を `goto 30` に変えて
CLEARを飛ばす既定対照を用意する（35対）。これでプログラム量の差を避ける。
既定対照はNEW後に短い測定プログラムだけがある状態。未実行CLEAR行も本文には含む。
引数値の内部表現の長さが同じという前提は断定せず、F0の安定性を必ず結果で検査する。
既定状態の `fre("")` は別の1腕。数値・誤りのどちらも採る。

行5でCLEAR前にON ERRORを張り、成功後の行30で張り直す。変数を用いず、
ERL=20ならCLEARの誤りを `s9de 1 ERR`、その他は `s9de 2 ERR` として
RESUME 800で完了印へ進む。CLEAR成功（既定腕では採取段への到達）は `s9da 1 1`、
FRE数値は `s9dv 2 値`、完了は `s9dd 1 1`。CLEARが誤った腕ではFREを実行しない。
定数対照の値・誤りは添字1。自分のPRINTした数値とERR番号だけを記録する。
印は整数のみの完全一致、正数の先頭空白を要求する。その他の画面本文は件数だけ。

全行小文字・80文字未満・@なし。直接モードはnew/cls/runのみ。
8フレーム/文字、行間240、公式起動改行300・入力開始700、自作入力開始100、
RUN後15000、採取前200。各腕各走で起動を独立にする。
画面写しは単一名または `.f<6桁フレーム>` の指定フレームを読み、全写しをfinallyで削除する。
フロントエンドの両出力は捕捉し画面本文を表示しない。

## 関門・照合・自己検査

関門の合格は定数73とERR=5の既知値への一致だけ。2走の一致・印の妥当性は採取の
整合性検査であり、境界値の正しさの証明ではない。対照失敗で後続を停止し、
未実行も2行ずつTSVへ記録、全体gate_failedにする。SKIPは合格にしない。
観測腕のP_MANUAL欄はobserve。predictの数値予測はnullで、checkはnullを一致扱いしない。
数値期待値を別の結果ファイルに固定した場合にのみ、checkで全腕集合・2走・失敗なし・
SKIPなし・印列の既知値完全一致を照合する。誤りの捕捉不能や採取不能はgate_failed。

自己検査は合成の陽性・陰性（完了印欠落、値添字不正、定数不一致、関門停止、
CLEAR/FRE誤りの区別）、フレーム名識別、自作ROMを一時ビルドした定数3腕×2走。
自作対照はPRINT 73、CLEAR ,49151後のPRINT 73、LEN("ab")=2。
自作のFREとON ERRORは本段の既知対照に含めない。FREの実装有無を成功扱いにはしない。
自作CLEAR対照は受理だけを確認し、配置に反映したとは判定しない。
期待値との不一致・SKIPを陰性として拒否する。

器具の作業先既定は ../tmp/l4s9d-work。書けない場合は既定を変更せず
`--work-dir /private/tmp/l4s9d-work` を明示して自己検査する。
実行する検査は `bash tools/l4_memlimit_selftest.sh < /dev/null` のみ
（必要時に上記の作業先オプションを付ける）。公式測定・git add・コミットは行わない。
