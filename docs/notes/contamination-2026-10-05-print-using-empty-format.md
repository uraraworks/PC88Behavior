# 汚染の記録 — PRINT USING の空の書式の診断で公式の内部表現らしいバイトを見た（2026-10-05）

## 何が起きたか

`l4-s9h` 追補2（PRINT USING）の公式測定で、書式が空文字列の4腕（`empty-lit`・`empty-var`・`empty-lit-probe`・
`empty-var-probe`）が2走とも採取に失敗した。親セッション（Claude、2026-10-05 のセッション）が原因を調べるため、
器具の外で公式ROMを動かし、画面の写しから**自作の印 `s9hb|` と `|s9hz` のあいだの文字コード**を会話の出力へ出した。

その結果、公式の `PRINT USING` は空の書式を受け取ると、何らかのメモリの中身を文字として出力し、そのあとで
Illegal function call(5) になることが分かった。

- `empty-var`（`a$="":print using a$;1;`）: 0xFF が続く（2行にまたがる）。
- `empty-lit-probe`（`print using "";1;`）: 8バイト。プログラム本文の一部を公式の内部形式で読んだものと見られ、
  **0x80 以上の値が1つ**含まれていた（内部の語の番号に当たる可能性がある）。

## 範囲

- 見たのは上の2腕の画面の1回分。0x80 以上の値は1つ。値そのものはこの文書に書かない。
- 器具の TSV（`../tmp/l4s9h-work/official_add2.tsv`）にはこの中身は入っていない（その腕は採取に失敗して `null`）。
- 診断に使った一時の画面写しは削除済み。
- 中身は CLAUDE.md の資料の区分で (b) ROM 内部の構造（語の番号の表）に当たりうる。

## 措置

1. **このセッションは、公式の内部表現（語の番号・中間コード形式）に依存する実装から外れる。** 具体的には今後の
   「通常 SAVE 形式（中間コード）」の段の実装と仕様化を担当しない。
2. 空の書式の腕は、出力の**中身を採らない**。記録するのは「印のあいだに何か出力があったか（有無）」と
   誤り番号だけにする（l4-s9h 追補2の結果ノートと器具に反映する）。
3. 自作の `PRINT USING` は空の書式で何も出力せず Illegal function call(5) にする（公式の「不定の出力」は
   測定もしないし再現もしない）。

## 教訓

器具の外での「原因の切り分け」でも、公式ROMの画面から自作の印の**あいだ**を出すと、その中身が自分のプログラムの
出力である保証は無い。誤り経路・境界の腕では、公式が何を出力するかを事前に決められないので、切り分けでは
有無・長さ・印の位置だけを出す。
