実施日: 2026-09-08

## 位置づけ

[m7it](m7it-response-position-preregistration.md)が事前登録した測定の結果で
ある。事前登録は測定開始前に単独コミット（`253ff27`）してあり、本稿では代表
位置・分類・判定規則・格上げ条件を後から動かしていない。`src/`は本稿では変更
していない（`tools/`は事前登録どおり拡張した）。

**結論を先に書く: 主判定はU2（「9」は動かないが影響はある）である。**
45armすべてを測ったが**C型（9以外のrun長）は1本も出なかった。**
**現れたrun長は`1`と`9`の2種類だけ**である。

**事前登録が定めた格上げ条件（C型が0本）が満たされたので、
「連続READのrun長『9』は、main⇔subの交換を触る経路では動かせない」を
3節へ格上げする。** 併記すべき3点も事前登録どおり付ける（後述）。

## 記述（判定ではない）

**現れたrun長は`1`と`9`だけ。** run長9の本数の分布は**0が7本・12が37本・
14が1本**である。

**唯一12以外になったのは run 9 の位置2**（FDC250・READ139・`{1:13, 9:14}`）。
**周期が12本から14本へ増えている。** これまでで最大の増分だが、
**run長そのものは9のまま**である。

**効くのは先頭寄りに偏っている。** 非A型10本のうち9本が位置0・1・2・L/4に
集中し、**L/2より後ろで効いたのは run 15 の位置128（L/2）1本だけ**である。
**末尾3位置（L-3・L-2・L-1）は5本すべてでA型**——256バイトや5632バイトの
応答の末尾を壊しても、FDCから見た結果は1つも変わらない。

**run 33 は9位置すべてでA型**だった（`m7is`で`xor-all`でも無反応だったのと
整合する）。

## 言えること・言えないこと

**言えること:**

- **C型は1本も無い。** 位置指定で応答を壊しても、run長9は動かない。
- **応答の末尾は、壊してもFDCから見た結果に影響しない。**
- 効く位置は先頭寄りに偏る。
- 全armで`changed>=1`。介入は全部届いている。

**言えないこと:**

- **代表位置は全位置ではない。** 9位置で漏れる可能性は残る（未測は
  256×4＋5632−45＝**6355位置**）。
- **摂動は`XOR 0xFF`のみ**で、ビットの非対称は本稿でも埋まらない。
- run 9 の位置2で周期が14本に増える理由は測っていない。
- **「『9』の出所はROM内部である」とは主張しない。**
- run長や本数から元の値を逆算していない（禁止事項5）。
- 条件O・`disk#10`という1本のディスク・1条件である。一般性は主張しない。

## 格上げ（事前登録が定めた条件が満たされたので実行する）

**格上げする項目:**

> **連続READのrun長「9」は、main⇔subの交換を触る経路では動かせない。**
> 根拠は累計**236arm**で、**交換run列60本すべてを両方向とも壊し、
> 現れたrun長は常に`1`か`9`だけだった**こと。

| 稿 | 方向 | 触った範囲 | arm数 | C型 |
|---|---|---|---:|---:|
| `m7ii` | 要求 | 交換run36の位置0〜4 × 8ビット | 40 | 0 |
| `m7ik` | 要求 | 入口場面12本 × 位置0 | 12 | 0 |
| `m7im` | 要求 | 交換run36の位置5 × 9通り | 9 | 0 |
| `m7iq` | 要求 | 入口場面より前18本 × 全位置 | 70 | 0 |
| `m7is` | 応答 | 全30本 × 強弱2モード | 60 | 0 |
| `m7iu`（本稿） | 応答 | 長さ2以上5本 × 代表9位置 | 45 | 0 |
| **合計** | | | **236** | **0** |

**事前登録どおり、次の3点を必ず併記する。**

1. **「『9』の出所はROM内部である」とは主張しない。** 言えるのは
   **「これらの経路では届かない」**までである（3節・第28版が231条件の全滅を
   「直接読めるハードウェア状態からは導けなかった」と書いたのと同じ書き方）。
2. **測っていない範囲（数字で明記する）:**
   - **要求側のビットの非対称**——入口場面より前の18本には`XOR 0xFF`しか
     当てていない。全ビットへ広げると**560arm**が未測。
   - **応答側の非代表位置**——長さ2以上の5本で**6355位置**が未測。
   - **ディスクの側**——`m7il`が土俵無しと記録したまま。
3. U1が出た場合は格上げしない、と定めていた。**U1は出なかった。**

## 次に何を測れば絞れるか

**「9」を要求・応答から動かす道は、236armぶん塞がった。** 残るのは上記2の
3つだが、いずれも費用か土俵の問題を抱える。**方向を変えるほうが筋が良い。**

1. **`m7hb`が挙げた「トラックあたりセクタ数」説へ戻る。** `m7il`は
   「連続READが出るのは`disk#10`だけで比較対象が無い」として見送ったが、
   **本稿までの結果は「9は交換では決まらない」を強く示しており、ディスク側の
   性質である可能性が相対的に上がった。** 土俵の作り方（何が`disk#10`を
   特別にしているか）を改めて設計する価値がある。
2. **`disk#10`の何が特別かを、値を見ずに切り分ける。** `m7hf`が記録した
   `bad allocation table`（新規ファイルを一切書けない状態）との関係を、
   BASIC言語仕様の範囲で確認する（`m7hj`が挙げていた方向）。
3. 未測の560arm・6355位置は、**1・2が行き詰まったときの保険**として残す。

読んでいない・出力していない。**公式ディスクのイメージを直接読んでもいない。**

スクリプトはリポジトリ外（scratchpad配下）に置き、コミットしない。
