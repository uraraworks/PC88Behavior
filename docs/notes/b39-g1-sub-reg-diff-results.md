# B39: スペース後の G1 で、サブの BC と HL が最初に違う時点を値なしで測る — 結果

記録日: 2026-11-01
規則: [b39-g1-sub-reg-diff-preregistration.md](b39-g1-sub-reg-diff-preregistration.md) どおり。測定はクラウドの実行環境で OO・SS 各 2 走。関門 10 項目はすべて通った。値は記録していない。記録は `measurements/b39-g1-sub-reg-diff.txt`。

## ROM から RAM 上のコードへ移る時点

移る回数は公式 71 回、自作 30 回である。

| 項目 | 最初に違う番号 | そのときの公式の `PC` |
|---|---|---|
| `AF` | 0 | `790E` |
| `DE` | 5 | `7812` |
| `PC`・`HL` | 29 | `7800` |
| `BC`・`SP`・`IX`・`IY`・裏レジスタ・`I`・`IFF`・`IM` | 違わない | |

自作の 30 回目（番号 29）は、公式と違う番地へ移っている。これが自作の最後の移りである。

## `IN $FC` の時点

同じ `PC` の行で最初に違うのは番号 4103（`AF`・`BC`・`HL`）と 11271（`DE`）である。B30 の 76570 よりずっと前で、76569 以下で `BC`・`HL` が同じ行は無かった。

## RAM 上のコードの命令

`LD A,R`・`LD A,I` は公式・自作とも 0 回だった。R の値を使って分かれているのではない。

## 読み方（推定）

- `IN $FC` の時点の比較は実行位置の位相に左右され、ここだけでは分かれ目を示さない。B38 の `BC`・`HL` の違いが値の違いの原因だとは言えない
- 手がかりは移る時点である。`AF`（番号 0）と `DE`（番号 5）は、値の差の前にすでに違う。B35 は `A` だけを見ていて `F` を見ていない。`DE` は `0` と記録したが、G1 の 6 回目の移りの条件は B35 に無かった可能性がある
- 番号 29 が `IN $FC` のどの時点かは、この記録に無い。B40 で移りの表を出す
