# B18: `0x0C`・`0x0D`・`00C1` を実装した自作サブで G1 を走らせる — 結果

記録日: 2026-10-31
規則: [b18-g1-after-load-run-preregistration.md](b18-g1-after-load-run-preregistration.md)（6e03674）どおり。測定はクラウドの実行環境。対照は毎回通過し、各腕の 2 走は一致した。
記録: `measurements/b18b-g1-*`（bd359ac の系列）、`measurements/b18c-g1-*`（09dc99a）。

## 経過

| 実装 | 対 OO の位置 | 備考 |
|---|---|---|
| 5d24c96 | 85 | **退行。** 読みの経路を変えたため。自作プローブの判定はすべて通っていた |
| bd359ac | 35721 | 読みの経路を戻し、作業域を移した。RAM 上のコードが走り、記録 A に `00C1` が 2 回 |
| 09dc99a（モード 0、`0x06` の応答を反映） | 35721 | `0038` の割り込みは消えた。位置は変わらない |

## 判定（09dc99a）

- **途切れ:** 位置 35721 は残る。ただし意味は変わり、RAM 上のコードが動いて 1024 バイトのセクタを読むところまで来ている
- **RAM 上のコード:** `hi-start: yes`、記録 A は `00C1` が 2 回（OO は 17 回）
- **FDC:** OO の `read_data hi` 15 回に対し SS は 3 回。最初に違うのは番号 27（OO は `seek hi`、SS は `sense_drive_status lo`）
- **値:** `IN $FC` は 8962 件中 2 件だけ違う（最初は番号 3840）。`OUT $FD` は違いなし。`OUT $FF` は番号 20106 の 1 件だけ違う
- **次の止まる所:** 自作は `OUT $FF` のあと `IN $FE` を待ち続ける（636 万回）。公式は `IN $09` へ進む

## 残っていること

`IN $FC` の 2 件が何かは、値を記録していないので分からない。件数の内訳からは ROM 側の応答に見える（**推定**）。B21 で `0x06` の応答を公式に揃えたが、位置は変わらなかったので、`0x06` ではない要求の応答か、別の場面の値の可能性がある。

## 教訓

自作プローブの合格は G1 の合格を保証しない（5d24c96）。プローブは 1 通りの手順しか通らない。読みの経路を触る変更は、G1 の短い走行でも確かめる。
