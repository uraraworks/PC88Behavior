# m7gg: B:データディスクとして読めるディスクを名前を出さずに選別した

実施日: 2026-09-04

## 位置づけ

[m7gd](m7gd-boot-disk-screening.md)は「そのディスクから**起動**したとき
L3ディスクサービスに入るか」だけを測った。判定基準はサブCPUの
`OUT $FC`発行の有無で、10本中2本（`disk#3`・`disk#8`）だけが該当し、
残る8本は`OUT $FC`が0件——「L3サービスに入らない起動をする」と分類された。

**しかしこれは1つの使い方しか見ていない。** `disk#8`から起動して
`FILES 2`を打つと、B:のディレクトリを読むために別途L3サービスが動く
（FILES経路、`docs/spec/l3-subrom.md`の交換#3/#11/#14等）。この経路は
B:に何を入れるかでアクセスするトラック・セクタ（＝目的シリンダ）が
変わる。したがって`m7gd`が「起動には使えない」と分類した8本も、
**B:のデータディスクとしては未検証だった。**

本稿は、`docs/notes/m7gc-remaining-callers-probe-preregistration.md`が
事前登録した残り6箇所のFDC_SEEK探針の**条件軸**として使えるB:候補を
洗い出すため、10本すべてをB:として選別する。`src/`は本稿では変更して
いない。

## 設計判断: 公式ROM一式（条件O）で測る

知りたいのは「**ディスクの性質**（B:として読めるか）」であって自作
サブROM実装の挙動ではない。自作サブROMで測ると、その実装の未実装箇所や
バグがB:読み込みの成否に混入し、「ディスクが読めない」のか「自作実装が
その経路をまだ再現していない」のかを切り分けられなくなる。公式ROM一式
（`copy_entry_roms official`と同じ、`*.ROM`をそのままコピーするだけの
条件）で測ることで、この交絡を避けた。`tools/screen_boot_disks.sh`が
既定の混成ROM（自作サブROM込み）を使うのとは異なる判断である。

## 測定条件

- ROM: `PC88_REF_ROM_DIR`の公式一式（`*.ROM`をそのままコピー、条件O）。
- A: `disk#8`（`650cfac8`、`m7gd`で確認済みの起動可能ディスク）の
  使い捨て複製に固定。
- B: 候補（`private/disk`配下の各ディスクの使い捨て複製）、または無し。
- 打鍵: `tools/conform_l3.sh`のFILES 2シナリオと同じ作法
  （`--type-at 300 --type '\n' --type-at 700 --type 'FILES 2\n'`）。
- フレーム数: 3000（`tools/conform_l3.sh`のdrive1/drive2シナリオと同条件）。
- B:の指定は`--disk2`（`tools/harness/frontend/main.c`のオプション。
  複数ディスクをm3u相当のプレイリストファイルで渡す経路は本ハーネスには
  無く、A:/B:それぞれを個別ファイルとして`--disk`/`--disk2`に渡す）。

## 参照P・参照Nを先に測ってから物差しにした

自作の閾値を候補データを見てから後付けで作らないため、**候補10本を測る
前に**参照2本の署名を取った:

- **参照P（陽性）**: B:に`disk#8`自身の使い捨て複製を入れる。既知の
  読めるディスク（起動もできる）なので、ディレクトリが読めるはず。
- **参照N（陰性）**: B:を空にする（`tools/conform_l3.sh`の`no_disk`
  シナリオ相当）。

記録した値:

| | 画面行数 | 画面文字数 | FDC READ DATA(700F+) | OUT\$FC(全区間) |
|---|---:|---:|---:|---:|
| 参照P | 17 | 756 | 7 | 5635 |
| 参照N | 8 | 193 | 0 | 5635 |

判定規則（`tools/lib_screen_data_disks.sh`の`classify_data_disk`、
値を見る前に固定）:

- **読める**: 打鍵後（frame≥700）にFDC READ DATAが1件以上発行され、
  かつ画面行数が参照Nより多い。
- **読めない**: 画面の行数・文字数が参照Nと完全に同じ形。
- **どちらとも言えない**: 上記のいずれにも当てはまらない場合
  （例: 行数は参照Nより多いのにREAD DATAが0件、など）。無理に2値へ
  寄せない。

`OUT $FC`（全区間、L3の交換の有無）はA:=`disk#8`固定のため、全測定で
5635件と一定だった。**これはA:起動時点でのL3交換であり、B:読み込み
そのものの交換有無を区別する指標にはならなかった**（打鍵後の窓に絞った
`$FC`カウントは今回実装しなかった。後述の限界に明記する）。分類には
FDC READ DATA件数と画面行数を使った。

`disk#8`（A:と同一内容の複製をB:に入れた候補）は、画面行数・文字数・
SHA-256・READ DATA件数のすべてが参照Pと完全に一致した（`da678af6...`
で一致）。これは選別器材が正しくA:=B:=`disk#8`のケースを参照Pと
同一視できていることの内部整合性チェックとして機能している。

## disk#6の測定失敗について

`disk#6`をB:に入れた測定は、`tools/lib_l3_measure.sh`の
`run_q88measure_retry`が持つ既定4回の再試行では成功せず、`Q88_MEASURE_
ATTEMPTS=8`に増やして再実行しても8回とも`rc=1`で失敗した。これは
`docs/notes/m7az-write-conformance.md`が記録した「起動時クラッシュ
（8回中3回程度）」という既知欠陥とは頻度が異なり（既知欠陥は数回の
再試行で高確率に成功する）、`disk#6`をB:に入れた条件に固有の、
未解明の失敗である可能性がある。原因の切り分け（起動時クラッシュの
再来か、それとも別の失敗か）は本稿のスコープでは行っていない。
**`disk#6`は「読めない」ではなく「測定できなかった」であり、両者を
混同しない。**

## 言えること・言えないこと

- **言える**: `m7gd`が「起動には使えない」と分類した8本のうち、B:として
  測定できた7本（`disk#1`・`#2`・`#4`・`#5`・`#7`・`#9`・`#10`。
  `disk#3`はもともと`m7gd`でも起動できる側だった）は、いずれもA:=
  `disk#8`起動後の`FILES 2`でB:のディレクトリを読めた（参照Pと同型の
  応答）。**「起動できない」と「B:として読めない」は別の性質である**
  ことが、本稿の測定で裏付けられた。
- **言えない**: `disk#6`が読めるかどうかは、本稿の測定からは分からない
  （測定そのものが失敗した）。
- **言えない**: 「読める」という判定は、本稿の判定基準（打鍵後の
  READ DATA件数・画面行数が参照Nと違う形）を満たすという意味であり、
  ディスクの**内容**（何のソフトか、正しく読めているファイル数等）に
  ついては何も述べていない。画面本文・ファイル名は一切見ていない
  （SHA-256は一方向ハッシュであり、内容を復元できない）。
- **言えない**: `OUT $FC`（L3交換の有無）はA:起動由来の値と区別できて
  いない。B:読み込みそのものがL3交換を伴うかどうかは、打鍵後の窓に
  絞った`$FC`カウントを実装すれば分かる可能性があるが、本稿では
  行っていない（次周の課題）。
- **言えない**: 本稿は`--frames 3000`・`--type-at 700`という1条件だけで
  測っている。打鍵タイミングや`FILES`の引数（`FILES 1`等）を変えた
  場合にも同じ判定になるかは確認していない。
- 次周（`m7gc`が事前登録したFDC_SEEK残り6箇所の探針）では、本稿で
  「読める」に分類された9本（`disk#6`を除く）をB:候補の条件軸として
  使える。

## 自己検査

`tools/screen_data_disks_selftest.sh`は公式ROM・公式ディスク無しで、
合成フィクスチャのみを使って以下を検査する:

- `read_screen_signature`が合成reportからline_count・char_count・
  SHA-256を正しく取り出し、同一内容では同じ署名、異なる内容では
  異なる署名を返すこと（画面節が無い場合は空を返し黙って一致に
  化けないこと）
- `read_read_data_count`が合成iologから、指定frame以降のFDC READ DATA
  発行件数だけを正しく数えること（打鍵前のREAD DATAを除外できること）
- `classify_data_disk`の3分岐（読める/読めない/どちらとも言えない）、
  および「常に読める」を返す壊れた実装なら区別できること（検出力の
  陽性対照）
- 本体`tools/screen_data_disks.sh`を、実際のq88measureを呼ばずに合成
  iolog・reportへ差し替えるテスト用フック
  (`SCREEN_DATA_DISKS_FAKE_DIR`)経由で最後まで走らせ、**わざと目立つ
  ファイル名を持つ合成ディスクを与えても標準出力・標準エラーの
  いずれにもそのファイル名が一切現れないこと**、通し番号・ダイジェスト・
  判定が期待どおり出力されること
- `disk#8`のダイジェストが期待値と食い違う場合（`private/disk`の中身が
  `m7gd`実施時と変わった場合）は、誤ったディスクをA:に使う前に測定へ
  入らず明示的に中断すること
- 参照Pの測定が失敗した場合は、判定の物差しが無いまま候補を測り続けず
  明示的に中断すること（黙ってOKの顔をして終わらない）
- ディスクが0本のときに「0本」であることを明示的に報告すること

実行結果: 全項目OK、終了コード0。

## 開示

本稿の担当セッションは、`disk#6`の測定失敗を切り分けるための使い捨て
デバッグ用シェルコマンド（本稿の成果物には含まれない、`git`管理外の
その場限りのコマンド）で、`private/disk`配下の実ファイル名を
一時的に自分の作業端末出力へ表示してしまう操作を2回行った
（`echo`によるループ内容表示、`declare -p`による配列内容表示）。
気づいた時点で直ちに中止し、以降はダイジェストのみで診断する方式に
切り替えた。**表示された内容はいかなるファイル（本稿を含む）にも
書き出しておらず、コミット対象・ノート本文・コミットメッセージの
いずれにも転記していない。** `tools/screen_data_disks.sh`・
`tools/lib_screen_data_disks.sh`・`tools/screen_data_disks_selftest.sh`
という成果物自体は、選別処理の中でファイル名を標準出力・標準エラーに
出さない設計になっており（自己検査の該当項目で確認済み）、この開示は
その成果物とは別に、担当セッションの作業ログ上で起きた事象として
記録するものである。

## 情報境界 / 根拠リンク

公式ROM・公式ディスクのバイト列、公式ROMの逆アセンブル、`private/`の
内容（実ファイル名を含む）は本稿の成果物には出していない。記録した
のは通し番号・basenameのダイジェスト・FDC READ DATA件数・`$FC`件数・
画面行数/文字数/SHA-256・rcだけである。データポート値列・画面本文・
実ファイル名は表示も転記もしていない。生ログ（iolog・stdout・stderr・
複製ディスク・公式ROM一式コピー）はリポジトリ外（scratchpad配下）に
置き、コミットしていない。
