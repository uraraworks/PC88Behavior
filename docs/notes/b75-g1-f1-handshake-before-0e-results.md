# B75: G1 の F1 の道で、`0x0E` の直前の受け渡しの制御を公式と自作で比べる — 結果

記録日: 2026-11-02
規則: [b75-g1-f1-handshake-before-0e-preregistration.md](b75-g1-f1-handshake-before-0e-preregistration.md) と追補どおり。2 回目で rc=0。データのポートの値は記録していない。記録は `measurements/b75-g1-f1-handshake-before-0e.txt`。

## 結果

- 公式: `0x0E` の直前の 197 件は、main の `OUT $5C`〜`$5F`・`$E4`・`$45` の繰り返しのあと、`OUT $FF` 1・F で要求の始まりを出し、サブが `OUT $FF` B で受信可を示して、main が `0x0E` の送信に入る
- 自作: フレーム 12000 からの 300 件は、main がキーのポート（`IN $00`〜`$09`）、`$44`・`$45`、`$5C`〜`$5F`・`$E4` を繰り返すだけで、**main が要求の始まり（`OUT $FF` 1）を出さない**。サブはこの区間に出てこない

## 分かったこと

自作で止まっているのはサブではなく **main 側の G1** である。G1 は `0x0E` を送る前の場面（キーを読み、`$44`・`$45` を使う繰り返し）から抜けていない。B73 で自作のサブがアイドルの待ちに入っていたのは、要求が来ないためだった。

## 読み方（推定）

B64 のとおり、この場面でもキーを読む位相の差で、後半のキーを読み落としている可能性がある。B66 では 0〜5 フレームのずらしで変わらなかったが、この場面の読みの周期がもっと長い可能性がある。`$44`・`$45`（音源）の回数の差（B63）が、待ちの長さに効いている可能性もある。どちらかは、次に測る。
