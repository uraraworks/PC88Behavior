## 進め方

事前登録どおり、12腕（A1〜A12）を各2走、陽性対照（直接モード
`print 7717\n`）を1走、計25走を実施した。記録器
`tools/l4_list_classify.py`は事前登録どおり測定前の別コミット
（`d330dd2`）で先に入れ、自己検査
（`tools/l4_list_classify_selftest.sh`、陽性対照・陰性対照2種・
故障注入の全項目）が測定前にOKであることを確認した。

打鍵は `tools/harness/frontend/q88measure` を直接呼び、
`--type-at 300 --type '\n'`（起動settle）→
`--type-at 700 --type "<腕の打鍵文字列>"`（実打鍵）の順で与えた。
写しは打鍵前（frame 690）と、事前登録のフレーム式
（`line_end=700+8*文字数`、`dump=line_end+300`、`run=dump+200`）で
計算した「後」の1枚を、各腕で個別に取得した（`--diff-before`/
`--diff-after`相当の2枚1組）。

## 腕ごとの構造

各腕の記録器出力は、`new`後の`Ok`行（相対行1、`other_line`）と、
`list`の入力エコー行（`other_line`、数字始まりのプログラム行入力は
それ自体も`list_line`として現れる）を挟んで、`list`エコー行より後・
最終`Ok`行（`ok_relative_row`）より前の範囲だけを「LISTの出力行」と
みなした（`list`より前に現れる`list_line`は、自分で打った行の
エコーであり、LISTの出力ではない）。

## 腕ごとの記録（LISTの出力行、事前登録が許す範囲）

打鍵文字列は事前登録の腕定義そのもの（`98abcdf`）。出力行は
「先頭が数字で全セル表示可能ASCII」の条件を満たした`list_line`の
デコード結果（事前登録「記録する内容」節が明示的に許可する範囲）。

| 腕 | 打鍵文字列 | LIST出力行(相対行) |
|---|---|---|
| A1 | `new`/`10 print 1`/`list` | 4: `10 PRINT 1` |
| A2 | `new`/`10print1`/`list` | 4: `10 PRINT1` |
| A3 | `new`/`10 print  1`/`list` | 4: `10 PRINT  1` |
| A4 | `new`/`10 ?1`/`list` | 4: `10 PRINT 1` |

| A6 | `new`/`20 print 2`/`10 print 1`/`list` | 5: `10 PRINT 1` / 6: `20 PRINT 2` |

## 判定

- **Q1**（記述のみ）: 12腕全てで、`new`の直後に`Ok`行が現れ（相対行1、
  `other_line`）、以後の入力行のエコーの後、`list`入力後に
  上表のLIST出力行が現れ、最後に`Ok`行（`ok_relative_row`）が現れた。
  エコー・LIST出力・`Ok`以外の出力は現れなかった（記録器の
  `classification`はいずれも`ok`）。
- **Q2**（記述のみ、上表の実測文字列からそのまま書く）:
  - 行番号の書式: 前後に余分な空白は付かない（A1〜A12いずれも行番号の
    直後は1個の空白か、元の打鍵どおりの間隔）。
  - 命令語の大小文字: 小文字で打った`print`は、LISTの出力では
    `PRINT`と大文字化された（A1〜A12全腕で一貫）。
  - 命令語の後の空白: 元の打鍵に空白があれば保持され（A1: `PRINT 1`）、
    元の打鍵に空白が無ければ挿入されない（A2: `PRINT1`、空白無しの
    まま）。ただし`?`を`PRINT`に展開する場合（A4）は、元の打鍵
    `10 ?1`（`?`と`1`の間に空白無し）に対し出力が`PRINT 1`（空白
    あり）となり、`?`展開のときだけ空白が挿入される、という
    キーワードの後の空白の扱いに関する食い違いが見られた（下記
    「観測」節参照）。
  - `?`の展開: A4で`?`は`PRINT`に展開された（上記のとおり）。
  - `:`の前後の空白: A5で、元の打鍵`1:print`のとおり`:`の前後に
    余分な空白は入らなかった（`1:PRINT`のまま）。
  - 打ったときの余分な空白の保持: A3で、`print`の後の2個の空白
    （`print  1`）がそのまま2個で保持された（`PRINT  1`）。
- **Q3**（A7・A8）:
  - A7: **`replaced`**。同じ行番号`10`を`print 1`→`print 2`で
    打ち直した結果、LIST出力は1行だけ（`10 PRINT 2`、後から打った
    内容）で、`print 1`の内容は残らなかった。
  - A8: **`deleted`**。`10 print 1`・`20 print 2`を打った後に行番号
    `10`だけを打った結果、LIST出力は1行だけ（`20 PRINT 2`）で、
    行番号`10`の行は消えた。
- **Q4**（A6）: **`sorted`**。`20 print 2`→`10 print 1`の順に打ったが、
  LIST出力は`10 PRINT 1`（相対行5）→`20 PRINT 2`（相対行6）の順で、
  行番号の小さい方が先に現れた（打った順ではなく行番号順）。
- `gate_failed`: 該当する腕は無い（G1〜G5・G8すべて真）。

## 観測（判定を動かさない記述）

- A2とA4の食い違い: 空白無しで打った`10print1`（A2）はLIST出力でも
  `PRINT`の後に空白が入らなかった（`PRINT1`）が、`10 ?1`（A4、`?`と
  `1`の間も空白無し）は`PRINT`展開後に空白が入った（`PRINT 1`）。
  同じ「キーワードの直後、空白無しで打った」場面でも、`print`と
  打った場合と`?`と打った場合とで、LISTの出力の空白挿入の有無が
  異なった。原因の推定（内部表現の違い等）はROM内部構造の話になる
  ため立ち入らず、観測された表面の形だけを記す。
- A9（大きい行番号`65529`）は先頭に余分な0や空白を挿む書式にはならず、
  `65529 PRINT 1`とそのまま出力された。
- A10（文字列リテラル`"abc"`）・A11（小数`1.5`）・A12（`#`付きの長い
  倍精度定数`1234567890123#`）は、いずれも打った内容がそのまま
  LIST出力に再現され、書式の変換（引用符の追加削除、小数点位置の
  変更、`#`の省略等）は起きなかった。
- A6・A7・A8を通じて、行番号を打っただけの入力行自体も、記録器の
  「先頭が数字で全セル表示可能ASCII」の条件（`list_line`の判定基準）
  を満たすため、LISTの出力行と紛れうることを確認した（本ノートでは
  `list`の入力エコー行の後・`Ok`行の前という位置で切り分けて対処した。
  「腕ごとの構造」節参照）。

## other_lineが出た腕

12腕全て。ただしいずれも想定どおりの2行（`new`直後の`Ok`行、`list`の
入力エコー行）であり、LISTの出力行そのものが`other_line`に化けた腕は
無かった。件数・桁範囲のみを記録し、文字コードは出していない
（記録器の設計どおり）。

## 事前登録から外れた点

- 陽性対照（直接モード`print 7717`）のフレーム計算は、事前登録が
  12腕に定めた式（`dump=line_end+300`、`run=dump+200`）をそのまま
  適用した。事前登録は陽性対照を「`l4-s4a`以来使ってきた陽性対照と
  同一」とのみ記し、フレーム式を個別に明記していなかったため、
  本測定の12腕と同じ式を一律で当てはめる形で補った。判定（G5）には
  影響しない（`Ok`行・`7717`の並びとも問題なく検出できた）。
- それ以外は事前登録どおり（腕の打鍵文字列・関門・判定名を変更した
  箇所は無い）。

## 禁止事項7の遵守について

本測定でツール出力・本ノートに載せたのは、(1)自分で打ったプログラム
行をLISTが表示した行（事前登録「記録する内容」節が明示的に許可する
範囲。数字で始まり表示可能ASCIIだけで構成される行に限る）、
(2)`other_line`（`Ok`行・`list`入力エコー行）の件数と桁範囲だけ
（文字コード・文言は一切出していない）。陽性対照の`7717`は数値の
直接の結果として`l4-s4a`以来許可されている扱いと同じ。
