# l4-s9i 結果 — 普通の PRINT の行端の折り返し

記録日: 2026-10-05
事前登録: [l4-s9i-print-wrap-preregistration.md](l4-s9i-print-wrap-preregistration.md)（候補 W_FULL・W_ITEM・W_GW・W_75。追補なし、観測後の候補追加・予測変更なし）
器具: `tools/l4_wrap_measure.py`。公式測定: `../tmp/l4s9i-work/official_round1.tsv`（96腕×2走=192行、全行 status=pass・typing_or_capture_failed=0、2走の観測は全腕で一致）。
観測は自作プログラムが出した既知文字（p・a・b・c・数字・z）のコード列と位置のみ。画面本文は扱っていない。

## 判定

**採用: W_GW。96腕すべてで一致。** 規則は次のとおり。

- 文字列・数値の項目は、現在の桁が0でなく、現在桁＋項目の長さが80を超えるなら、項目の前で改行する。
  ちょうど80に収まるときは改行しない（80セルを書いた直後は次行の0桁になる）。
  数値の項目の長さには前後の空白を含む（`12345` は7セル）。
- 行頭から始める項目が80を超えるときは、先に改行せず80セルごとに折る。
- 連結式は評価後の一つの文字列として同じ検査を受ける。
- コンマは、現在桁が56以上なら改行して次行の0桁へ。56未満なら次の14の倍数の桁へ進む。
- 末尾の区切りが無ければ、現在位置から改行1回。

期待値は `tests/conformance/expected_l4_wrap.tsv`（候補 W_GW の96行）。
`python3 tools/l4_wrap_measure.py check --expected tests/conformance/expected_l4_wrap.tsv --measured ../tmp/l4s9i-work/official_round1.tsv` が rc=0（照合一致）。

## W_ITEM と W_GW を分けた5腕（コンマ）

comma-56・comma-57・comma-69・comma-tail-56・comma-tail-69。いずれも前印 p を k 個出した後のコンマ。

- 現在桁が56・57・69（W_ITEM と W_FULL は次の14境界の70へ進む）の場合、公式は**行を改め**、
  次の項目 c は次行の0桁に出た（終了位置は(1,1)、末尾付きは(1,0)）。
  完了した1行目の末尾空白は 24（k=56）、23（k=57）、11（k=69）。つまり前行は k 桁で止まり、残りが空白。
- 境界の対照は一致: k=55 は56桁へ進んで同じ行に続き（終了(0,57)）、k=70・71・79 は W_ITEM とも W_GW とも同じ（改行）。
  したがって切り替わりは**現在桁55と56の間**で、ちょうど最後の完全な欄の開始桁56。

## W_FULL が外れた29腕の型

- 一つの項目が現在桁から収まらず、公式は項目の前で改行した: 文字列10腕（k=1/5/69/70/74/75/79 の境界越え）、
  二項目3腕、数値6腕（k=74〜79、7セル）、連結2腕、末尾なしの2腕（newline-05-076・newline-70-011）、
  旧器具の35文字分割1腕（5＋35＋35＝75桁の後の次項目）。計24腕。W_FULL は項目の途中で80桁に達して
  次行へ続ける（項目を割る）ので、位置が一致しない。
- コンマ5腕: 上記。W_FULL は56以上でも次の14境界（70）へ進む。
- W_FULL が合う腕は、行頭で始まる長い項目（k=0 の 80/81/95/161 文字）や、収まる範囲の腕。

## l4-s9h の折り返し対照の観測は W_GW で説明できるか

説明できる。l4-s9h の control-wrap（印5＋72文字＋後続）・control-long（95文字＋後続）は、旧器具が長い定数を
35文字ずつ**別の PRINT** に分けて出していた（`tools/l4_pusing_measure.py` の chunks）。
印5＋35＋35＝75桁に達した後、次の項目（control-wrap は6セル、control-long は25＋空白2の27セル）が
残り5セルに収まらず項目の前で改行する。結果は「75桁目から空白5セル、次行の8桁目・27桁目に終了」で、観測と一致する。
本測定の control-old-chunks（5＋35＋35＋8）も W_ITEM・W_GW で一致、W_FULL は不一致で、同じ再現になっている。
「70文字目で折る」のではなく、**折る位置は項目境界が決める**。W_75（75桁で折る）は一致腕が21しかなく、不採用。

数値項目＋コンマの組合せは腕に含めていない。自作ROMは未修正（W_FULL のまま）で、この記録は実装を述べない。
