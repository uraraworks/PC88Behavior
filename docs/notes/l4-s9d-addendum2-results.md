# l4-s9d 追補2 結果 — CLEAR の上限 a の表記（16進・負の10進・非整数・範囲外）

根拠: [事前登録](l4-s9d-addendum2-preregistration.md)。公式ROMの測定は
`../tmp/l4s9d-work/official_add2.tsv`（13腕×2走）。画面本文は記録せず、
自作PRINTの整数とERR番号だけを採った。

## 数え上げ

13腕×2走。関門4腕（定数対照2＋既知 e400→fre 23270・e800→ERR 5）は全て通過、
観測9腕は skipped 0・採取失敗 0。全13腕で2走の印列が一致した。
`tests/conformance/expected_l4_memlimit_add2.tsv`（13腕）を固定し、
`tools/l4_memlimit_measure.py check` が rc=0（照合一致）を返した。

## 結果（TSVで検算済み。食い違いなし）

| 表記 | 観測 | 備考 |
|---|---|---|
| &hd000 | 受理 fre(0)=18150 | 53248−35098 |
| -12288 | 受理 18150 | &hd000 と同一 |
| 53248.5 | 受理 18150 | 非整数 |
| &hcfff | 受理 18149 | 53247−35098（マニュアルの例） |
| &he5ff | 受理 23781 | 58879−35098（追補1の 0xE5FF と一致） |
| -6657 | 受理 23781 | &he5ff と同一 |
| -1 | ERR 5 | 0xFFFF 相当。最大 0xE5FF 超 |
| 65536 | ERR 6 | 範囲外 |
| -32769 | ERR 6 | 範囲外 |

- 受理6点すべてで `fre(0) = a − 35098`（傾き1）が成立。
- 16進と対応する負の10進は同じ結果（&hd000 = -12288、&he5ff = -6657）。
- 53248.5 の結果は、負へ寄せてから最近接（-12287.5 → 絶対値の大きい側 -12288 → 53248）
  と一致。「正のまま整数化」（53249 → fre 18151）は採らない。第18節の番地と同じ向き。

## 判定

仮説 C_NEG（CLEAR の上限は PEEK/POKE の番地と同じ変換を受ける）は**支持**。
反例条件（16進と負の10進の不一致、&hd000 の拒否、傾き1からの逸脱）はいずれも出なかった。
-1 の ERR 5 は「変換後 0xFFFF が最大 0xE5FF を超える」と整合する（誤り番号が
範囲外の ERR 6 でなく 5 になる点は、変換後の値の拒否として観測）。

## 未測定

32768 ちょうど（-32768 へ変換）・&h8000 付近の下限側、-32768 や 32767 周辺の端点、
`&h` 以外（&o）の表記、第3引数側の同種の変換は測っていない。
