# l4-s5b — RUNと流れの制御（GOTO・FOR・GOSUB・STOP・実行中の誤り） — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

`l4-s5a`（測定`53183e0`）で、行の入力と`LIST`の出力の形を測った。本
ノートはその続きとして、プログラムを`RUN`したときの実行の流れ
（行番号順の実行、`FOR`〜`NEXT`、`GOSUB`〜`RETURN`・`END`、変数、
`STOP`、実行中の構文の誤り、空のプログラム）を測る。

## 問い

- Q1 `RUN`で各行が行番号の順に実行されるか（B1・B6）
- Q2 `FOR`〜`NEXT`の回数・`STEP`・初めから終わりを越えている場合に
  本体を何回実行するか（B2〜B4）
- Q3 `GOSUB`〜`RETURN`・`END`（B5）
- Q4 変数（B7・B8）
- Q5 `STOP`と実行中の誤りの出力の形（B9・B10。**件数と範囲だけ**、
  文言は記録しない。行番号が付くかどうかも文字では記録しない）
- Q6 空のプログラムの`RUN`（B12）

## 腕（12腕＋陽性対照1腕）

打鍵はこのまま使う（英字は小文字）。1腕＝`new`のあと行を打ち、最後に
`run`を打つ、という一連の打鍵を1つの`--type`文字列として与える
（`l4-s5a`と同じ作法）。

| 腕 | 打鍵文字列（`\n`は改行） | 目的 |
|---|---|---|
| B1 | `new`/`10 print 1`/`20 print 2`/`run` | Q1 順序 |
| B2 | `new`/`10 for i=1 to 3`/`20 print i`/`30 next`/`run` | Q2 基本 |
| B3 | `new`/`10 for i=1 to 10 step 3`/`20 print i;`/`30 next`/`run` | Q2 STEP |
| B4 | `new`/`10 for i=3 to 1`/`20 print i`/`30 next`/`40 print 9`/`run` | Q2 初めから越えているFOR |
| B5 | `new`/`10 gosub 100`/`20 print 2`/`30 end`/`100 print 1`/`110 return`/`run` | Q3 |
| B6 | `new`/`10 goto 30`/`20 print 1`/`30 print 2`/`run` | Q1 GOTO |
| B7 | `new`/`10 a=5`/`20 print a*2`/`run` | Q4 整数変数 |
| B8 | `new`/`10 i=1.5`/`20 print i+1`/`run` | Q4 小数変数 |
| B9 | `new`/`10 print 1`/`20 stop`/`30 print 2`/`run` | Q5 STOP |
| B10 | `new`/`10 print 1+`/`run` | Q5 実行中の誤り |
| B11 | `new`/`10 print 1`/`20 goto 10`/`run` | 止まらないループ（下記「B11の扱い」参照） |
| B12 | `new`/`run` | Q6 空のプログラム |

### 陽性対照（1腕、腕数には含めない）

直接モードの`print 7717`（`l4-s4a`以来使ってきた陽性対照と同一）。

腕の総数: **12腕**（B1〜B12）。各腕2走（決定論性の関門G3）。ただし
B11は下記のとおり判定から外れ、決定論性の確認（G3）にも通常の腕とは
異なる扱いをする。

## B11の扱い（止まらないプログラム）

B11（`10 print 1` / `20 goto 10`）は無限ループであり、`Ok`行が現れる
ことがない。以下の扱いを事前に定める。

- 写しの時刻は、他の腕と同じ計算式で求めた`dump(k)`をそのまま使う
  （行の打鍵が終わった直後の固定フレーム。`run`の実行がどこまで進んだ
  かによらない、決まった時刻での1回の写しとする）。
- 記録は、`tools/l4_vram_probe.py --nonblank-summary-rows`（単独写し）
  で得られる、出力領域（打った行より下の範囲）の**非空白セルの件数**
  だけにする。位置の範囲・文字コードは記録しない。
- **判定はQ1〜Q6のいずれにも含めない**（記述のみ、判定名を付けない）。
  「画面が`PRINT`の出力で埋まっている（非空白セル件数が0でない）か
  どうか」だけを記述する。
- 関門G8（`Ok`行の確認）はB11には適用しない（`Ok`行が現れないことが
  想定どおりであるため）。
- **STOPキーの注入は使わない**（`tools/harness/frontend/main.c`の
  `q88measure`に、実行を途中で止めるための専用オプションが無いことを
  確認した。`--trap-mode`はコアのトラップ機構であり、キー入力による
  停止とは別物のため使わない）。
- 決定論性（G3）は、上記の非空白セル件数が2走とも一致することで確認
  する（他の腕のようなセル列そのもののsha256一致ではなく、件数の一致
  とする）。

## 条件・関門

`l4-s5a`（`98abcdf`）の「条件・関門」節をそのまま踏襲する。

- 起動settle`--type-at 300 --type '\n'`、実打鍵開始`--type-at 700`
- 1文字あたり`hold+gap=8`フレーム/文字（`\n`も1文字として数える）
- フレーム計算式（全腕一律、B11を除く）:
  ```
  line_end(k) = 700 + 8 * (その腕で打った文字数の累計。\n も1文字。
                            複数行にわたる打鍵は全体を1つの--type文字列
                            として与え、文字数は改行を含めた合計)
  dump(k)     = line_end(k) + 300
  run(k)      = dump(k) + 200
  ```
- 写しは打鍵前（`--type-at`の10フレーム前=690）と`dump(k)`後の2枚を
  `--diff-before`/`--diff-after`に渡す（B11を除く。B11は単独写しの
  `--nonblank-summary-rows`のみ）
- **複数行を打つ腕では、行ごとの打鍵の間隔が上記の式で正しく積み上が
  っていることを確認する。** `FOR`の腕（B2〜B4）は`RUN`の出力が複数行
  になるため、**`RUN`の後の実行と表示が写しの時刻`dump(k)`までに終わ
  っていること**（関門G8で確認）を特に確認する。B3（`STEP 3`で最大4回
  出力）・B4（越えているFORで本体の実行回数がQ2の対象）のように出力
  行数が読めない腕は、`dump(k)`の余裕（`+300`フレーム）で足りるかを
  関門G8で確認し、足りなければ`gate_failed`として扱う。

## 記録する内容

- **`Ok`行の位置（打った行からの相対行）と、`RUN`の後に出た行の数を、
  すべての腕（B11を除く）で必ず記録する。**
- 出力行のうち、`l4-s4a`の数値分類器（`tools/l4_s4a_float_classify.py`、
  `5735eb3`。文字コードが「数字0-9・`.`・`+`・`-`・`E`・`D`・空白」の
  集合に入る行だけコードを記録する）で`numeric_output`と分類された行
  は、(相対行, 相対桁, 文字コード)の並びをそのまま記録する。
- それ以外の行（`Break`・エラー・`Ok`自身の文字列等）は、件数と位置の
  範囲だけを記録する。コード・文言は一切出さない。
- **`l4-s5a`のLIST記録器（`tools/l4_list_classify.py`、`d330dd2`）は
  本測定では使わない。** 理由: 本測定は`RUN`の出力（`PRINT`が生成した
  値の並び）を対象としており、`LIST`が再構成したプログラム文そのもの
  を対象とする`l4-s5a`とは記録すべき行の性質が異なる（`RUN`の出力は
  既存の数値分類器がそのまま対応できる形式であり、二重に道具を作る
  必要が無い）。

## 本文を出さない取り扱い

`l4-s4a`〜`l4-s5a`と同一の考え方。「記録する内容」節の分類規則に
従い、`numeric_output`の行だけコードを記録し、それ以外は件数と範囲
だけにする。分類器（`tools/l4_s4a_float_classify.py`）は集合外の
コードを標準出力・標準エラーへ出さない設計であることが`5735eb3`の
時点で確認済み。

- Q5（B9・B10）: `STOP`・実行中の誤りの出力行は、値・文言を一切出さず
  件数と範囲のみを記録する。行番号が付くかどうかも、文字としては記録
  しない（「行番号らしき数字が含まれるかどうか」を真偽値としてのみ
  記述してよい——数字の並びそのもの・具体的な行番号の値は記録しない）。

## 関門

`l4-s5a`のG1〜G5・G8と同一（G6は対になる予測表が無いため本測定にも
適用しない）。

- G1 器具の自己検査: 測定時HEADで`tools/harness/vram_dump_selftest.sh`・
  `tools/harness/vram_dump_dynamic_selftest.sh`・
  `tools/harness/key_matrix_selftest.sh`・
  `tools/harness/type_untypable_selftest.sh`・
  `tools/screen_content_leak_selftest.sh`の全項目がOK
- G2 取りこぼし0・打てない文字の警告0（全走のstderrで確認）
- G3 決定論性: 各腕2走とも、写しはファイルのsha256が一致、記録は
  sha256が一致（B11のみ非空白セル件数の一致で代える。上記「B11の扱い」
  参照）
- G4 陰性対照: 何も打たない走（起動settleのみ）で差分0件
- G5 陽性対照: 直接モードの`print 7717`腕で`7717`の並びを確認
- G8 出力完了の確認: 「後」の写しで、出力行の後に`Ok`行が現れている
  こと（B11を除く）。特に`FOR`の腕（B2〜B4）で出力が複数行になる場合
  に確認する。現れない腕は`gate_failed`とし、「写しが早すぎた」とだけ
  記述する

判定の前にG1〜G5・G8（該当する腕のみ）がすべて真であること。いずれか
が偽の腕は、その腕を`gate_failed`として判定に含めず、理由を記述する。

## 判定

記述が中心。判定名を付けるのはQ1〜Q3のみで、それ以外（Q4〜Q6、B11）は
記述のみとする。「記録する内容」節を参照する。

- Q1（B1・B6）: `in_order`（行番号の順に実行された結果が出力に現れる）
  ／`other`
- Q2（B2〜B4）: `body_runs_N`（本体がN回実行された、Nは記録した出力
  行数から読み取る）／`body_skipped`（本体が1回も実行されなかった）／
  `other`
- Q3（B5）: `gosub_returns`（`GOSUB`で分岐し`RETURN`で戻り、`END`で
  終了したとおりの順で出力が現れる）／`other`
- Q4（B7・B8）: 記述のみ。変数への代入・参照が期待どおりの値を出力
  するかをそのまま書く。
- Q5（B9・B10）: 記述のみ。`STOP`・誤りの出力行の件数と位置の範囲を
  そのまま書く（文言・行番号の値は書かない）。
- Q6（B12）: 記述のみ。空のプログラムの`RUN`で何が起きるか（`Ok`の
  みか、エラーが出るか）をそのまま書く。
- B11: 記述のみ（「B11の扱い」節参照。Q1〜Q6のいずれにも数えない）。
- `gate_failed`: 関門のいずれかが偽だった腕。判定に含めず、理由を
  記述する。

## 器具の確認（公式ROMは使わない）

測定開始前に、自作main ROM（測定時HEAD`53183e0`から`src/build_main_
rom.py`で組み立て）に対し、12腕（B11・B12を含む）＋陽性対照の計13腕
すべてを打鍵し、各行のエコーが打鍵どおりに届くかを`tools/
l4_vram_probe.py --marker`（各腕の打鍵文字列を`\n`で分割し、各行を
それぞれmarkerとして指定）で確認した。**自作ROMはまだプログラムモード
を持たないため、実際の`RUN`の挙動は見ておらず、エコーだけを確認した。**

結果: **B5を除く12腕（B1〜B4・B6〜B12＋陽性対照）は、全行のエコーが
打鍵どおりに出現した**（`=`・`;`・`+`を含め、届かなかった記号は無し）。

**B5のみ、最終写しの時点で先頭行`new`のmarkerが見つからなかった。**
別途、`new`だけを打った直後（`--type-at 700`の60フレーム後）に単独で
写しを取って確認したところ、`new`は正しくエコーされていた
（marker一致1件）。B5は`gosub`・`end`・`return`という自作main ROMが
まだ認識しない語を複数行含むため、各行ごとにエラー応答が出て画面の
行数が嵩み、**最終写しの時点では先頭の`new`が画面外へスクロールして
いたと考えられる**（自作ROMがまだプログラムモードを持たないことに
よる想定内の副作用であり、打鍵そのものが届かなかったわけではない）。
届かなかった記号は無い。

作業に使ったROM・写し・スクリプトはリポジトリ外の使い捨てディレクトリ
（scratchpad配下）に置き、確認後に削除した。
