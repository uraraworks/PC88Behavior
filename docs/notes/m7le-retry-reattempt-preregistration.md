# m7le: 「9」の再試行を再挑戦する——余白を作った後で、m7krの合格条件をそのまま使う — 事前登録

## 位置づけ

[m7kr](m7kr-implement-retry-decision.md)は「規則が未確定のまま1.58節の構造に合わせて実装する」と
**条件つきで**決め、合格条件7項目を先に固定した。[m7ks](m7ks-implement-retry-dead-end.md)は
**合格条件3（適合テストが悪化しない）が偽**になり、行き止まりとして記録した。

**その後の追跡で、行き止まりの正体は再試行とは無関係だったと分かった**:

- 回帰した3場面では**再試行ループは1度も回っていなかった**（[m7kw](m7kw-third-branch-results.md)）
- **不活性な詰め物11バイトだけで同じ回帰が出た**（[m7ky](m7ky-cause-ladder-results.md)）
- 原因は**生成器の関門の穴と、既定ビルドの余白9バイト**だった（[m7lb](m7lb-window-tail-confirm-results.md)で確定）
- 関門を直し（[m7lc](m7lc-generator-window-gate-fixed.md)）、**余白を26バイトにした**（[m7ld](m7ld-margin-factor-eot-gpl-dtl-results.md)）

**本稿は、同じ合格条件で再挑戦する。** **合格条件は動かさない。数え方だけを、今の器具に合わせて
先に具体化する。**

## 候補（1つに絞る）

**`m7ks`が保存した一律版**（`PC88/tmp/m7ks-impl/make_subrom.after.py`）の再試行部分を、
今の`src/`へ当てたもの。**`FDC_READ_SECTOR`の中で、READ DATAを発行し、`FDC_ABORT`が立って
いれば最大9件まで発行し直す。立っていなければそこで止まる。**

- **差分はそのまま当たった。全長2033バイト、関門を通過、窓までの余白15バイト**（測定前に確認）。
- **絞り込み版は候補にしない。** 絞り込み版は再試行を入れる呼び出し元を**適合テストの結果を見て**
  選んでいた（`m7ks`の記録）。**これは「1.58節だけを根拠に実装する」という`m7kr`の約束1に反する。**
  **一律版は呼び出し元を選ばず、1.58節の構造そのままである。**
- **「9」は規則ではなく、観測に形だけ合わせた値である**（`m7kr`の約束2。実装のコメントに書いてある）。

## 合格条件（`m7kr`の7項目。**番号と中身は変えない。数え方だけを具体化する**）

1. **ビルドが通る**——生成器自身の関門に任せる（2033バイトで通過を確認済み）。
2. **`tools/run_all_selftests.sh`がrc=0。**
   **数え方**: HEAD基準の検査はコミット済みでないと通らず、`check_cleanroom.sh`は本体の置き場で
   ないと通らない（[m7ld](m7ld-margin-factor-eot-gpl-dtl-results.md)の開示）。**そこで、worktreeの
   切り離したHEADへ使い捨てでコミットして門の全体を回し（置き場由来の`check_cleanroom.sh`の1件を
   除いてすべてOK）、`check_cleanroom.sh`は本体の作業ツリーで回す。** この手順を先に決めておく。
3. **既存の適合テストが、実装前より悪くならない。**
   **数え方**（同じ実行群のBASEと、色コードを落とした判定行で比べる）:
   - (a) 総合判定は**適合**
   - (b) **BASEで`OK`だった判定行が、1本も`OK`以外にならない**（消えるのも「悪化」と数える）
   - (c) **`NG`の本数が増えない**
   - (d) **`--`（未到達・判定不能）の本数が増えない**
   **BASEで`--`だった行が`OK`になる／消えるのは許す**（改善の方向）。**新しく現れた行は
   すべて記録する。**
4. **読めない媒体で、1つの送信単位の内側が`READ DATA`×9になる。**
   **数え方**: 経路測定`unreadable_disk`の混成側で、**`READ DATA`の連続が最長9、連続した対が96**
   （12送信単位×8）。[m7kw](m7kw-third-branch-results.md)のFで出た値と同じ。
5. **読める媒体で`READ DATA`が1件のまま**（回帰させない）。
   **数え方**: **drive1・drive2・書き込み・LOAD混成・LOAD既存**の混成側で、**`READ DATA`の連続した
   対が0のまま**（BASEはすべて0）。
6. **`src/`以外を変更しない**（採用するなら、実装のコミットに含めるのは`src/`だけ）。
7. **`tools/check_cleanroom.sh`が全項目OK**（本体の作業ツリーで）。

**加えて（`m7kr`には無かったが、以降の稿で必ず見ているもの）**: **決定論性**——候補を独立2回
走らせ、判定行の集合が一致すること。

**`m7kr`は「4が満たせなくても3と5が守られていれば途中まで」と書いた。この線も動かさない。**
**3が1つでも破れたら採用しない。**

- **`src/`の変更として単独でコミットする。** **測定のコミット（本稿の結果）を先にする。**
- **`m7kr`の「更新の条件」はそのまま生きる**——9を決める規則が書けたとき、9を動かす軸が
  見つかったとき、公式と食い違う条件が見つかったときは、実装を作り直す。
- **1.58節の「現時点では適合条件にしない」は変えない。** **実装したのは観測に合わせた構造であって、
  仕様として確定した規則ではない。**
