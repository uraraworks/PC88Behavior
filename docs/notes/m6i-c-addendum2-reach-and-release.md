# m6i-c 追補2 — 到達指標からゲート観測を外し、解除の定義を一意にする（測定前）

記録日: 2026-09-23  
状態: 測定前。**腕は1走も回していない。**

器具の実装中に、事前登録の記述に矛盾1件とあいまいさ1件が見つかった。
いずれも測定前に直す。値を見てから直すのではない。

## 1. 到達指標からゲート観測を外す（矛盾の解消）

### 何が矛盾しているか

[事前登録](m6i-c-b5-b6a0-divergence-preregistration.md) §2 は、C2・C3 の
到達指標に次を含めていた。

- C2: 「sub のゲート入場マーカーが0件である」
- C3: 「sub のゲート入場マーカーが1件以上である」

これは [追補1](m6i-c-addendum1-gate-observation.md) §3 と矛盾する。追補1 は

> 主問が使える結果を、従属する問いの都合で捨てない。

と決め、ゲート観測が崩れても総合判定には影響させないことにした。ところが
到達指標にゲート観測が入っていると、**`gate_run_min_length` の選び方を誤った
だけで C3 が `unreached` になり、総合判定が `m6i_c_inconclusive` へ落ちる。**
副問の都合で主問を捨てる形になっており、追補1 の決定が効かない。

### なぜ外してよいか

**同じことを関門 G4 がもっと強く保証しているからである。**

- C2 の `DISK.ROM` は C1 のものとバイト一致 → C2 の sub ROM にゲートは無い
- C3 の `DISK.ROM` は C0 のものとバイト一致 → C3 の sub ROM にゲートはある

到達指標のゲート条件は「その腕が意図した sub ROM で走っているか」を確かめる
ためのものだったが、それは**成果物のバイト一致で既に、実行時の観測より強く
確かめられている**。外しても失うものが無い。

### 直し方

C2・C3 の到達指標から、ゲート入場に関する条件を削る。到達指標は4腕とも
次の3つだけになる。

1. 前置き `b→a→c` が各1回この順に完了している
2. 通常READの発行フレームが60である
3. 前置きの通信を要求 run へ数えていない

ゲート run の観測は、**副問と G8-2 でのみ使う**。総合判定はゲート観測に
一切依存しない。

## 2. `gate_released` の定義を一意にする（あいまいさの解消）

追補1 §2 は

> `gate_released`: ゲート run の終端より後に、sub の `$FE` 以外の I/O が1件以上ある

と書いた。**ゲート run が複数本あるときにどの run を指すかが書かれていない。**
「どれか1本でも後続 I/O があれば真」と読むと、途中の run が解除された時点で
真になり、最後の run で永久に止まっていても `gate_released` が真になる。
これでは `gate_never_released` が検出できない。

副問が知りたいのは「sub が最終的にゲートから出たか」である。したがって
**最後のゲート run を指すものとする。**

- `gate_released`: **最後の**ゲート run の終端より後に、sub の `$FE` 以外の
  I/O が1件以上ある。

ゲート run が0本のときは `gate_entered` が偽なので、`gate_released` も偽とする
（追補1 のとおり）。

## 3. 変わらないもの

- 腕 C0〜C3 の ROM 構成、関門 G1〜G9、通常READの結果条件（`success` /
  `failure`）、総合判定5種、副問判定5種、判定後の行き先は変更しない。
- `gate_run_min_length` = 32 も変更しない。
- G8-2（ゲートを持たない C1・C2 でゲート run が0本）はそのまま残す。**到達指標
  から外したぶん、ゲート観測の妥当性検査はこの G8-2 が一手に引き受ける。**
  ここで崩れたときに `gate_observation_unusable` として副問だけを捨てる形も
  変えない。
- 本文・値列を出さない規律も変えない。
