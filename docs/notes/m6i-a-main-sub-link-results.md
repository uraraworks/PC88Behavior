## 4. 総合判定

関門 G1〜G8 は全て通過したが、A0、A1、A2、A4、A5 が `unreached` である。事前登録の定義に従い、総合判定は **`m6i_a_inconclusive`** とする。

合格側の判定として確定したのは、A3 の **`wait_negative_detected`** だけである。到達条件を満たさなかった腕について、結果条件を緩めて別の合格判定へ読み替えない。

## 5. 得られたこと

A0 の単発実行は timeout となった一方、起動から同じ時点に最初の要求を出す A5 では、200回中199回について要求 run、256位置受信、成功完了が成立した。実測の時系列と合わせると、初回の要求だけが成立せず、2回目以降の要求は成立した形である。

成立した199回では、受信256位置の SHA-256 が全回同一であり、規則生成媒体のセクタ1とも一致した。この範囲では、自作 main と自作 sub の通信経路そのものが通っている。

A5 の観測では、保存対象レジスタ、拡張 ROM バンク窓、終了後のキー入力、画面に退行は見られなかった。ただし、A5 の事前登録上の到達条件は200回全ての完了であるため、この観測を `integration_regression_free` の確定には用いない。

## 6. 残った問い

A0 の初回要求が timeout となり、A5 では同じ入口の残り199回が成功した。A1 も同じ形であり、A2 が SENSE DRIVE STATUS の反復にも READ DATA にも到達しなかったこと、A4 の PAIR 破壊枝が故障箇所へ到達しなかったことも、媒体や故障箇所より手前で初回要求が成立していないことで説明できる。

この結果が示したのは、`docs/spec/l3-subrom.md` にまだ定義されていない「main が最初の要求を出してよい時点」という問いである。本測定はその時点を決めていない。sub の起動時初期化との競合は疑われるが、未確認である。次にこの問いを測るには、今回の条件を事後変更するのではなく、別の事前登録が必要である。

## 7. 器具不具合と再測定

最初の A0〜A3 は、macOS の bash 3.2 における `set -u` と空配列展開の組合せにより、エミュレータ起動前に停止した。この器具不具合を修正した後、A0〜A3 を測り直した。修正は引数展開の互換性だけであり、判定条件、腕、期待値には触れていない。起動前に停止した試行は測定結果へ含めていない。
