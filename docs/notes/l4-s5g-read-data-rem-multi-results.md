core sha256先頭 `6c915e832379`、frontend sha256先頭 `97e023e7ca6e`

## 進め方

事前登録どおり、12腕（G1〜G12）を各2走、陽性対照（直接モード
`print 7717\n`）を1走、計25走を実施した。打鍵は
`tools/harness/frontend/q88measure`を直接呼び、
`--type-at 300 --type '\n'`（起動settle）→
`--type-at 700 --type "<腕の打鍵文字列>"`（実打鍵）の順で与えた。
写しは打鍵前（frame 690）と、事前登録のフレーム式
（`line_end=700+8*文字数`、`dump=line_end+300`、`run=dump+200`。
陽性対照も同式）で計算した「後」の1枚を取得した。

記録には`tools/l4_s4a_float_classify.py`（`5735eb3`）の`NUMERIC_CODES`
集合を、`l4-s5b`〜`l4-s5f`で確立・正式化した行の構造的特定手法（打った
行数から`run`の入力エコー行を特定し、その後・最終`Ok`行の前の範囲を
`RUN`の出力とみなす）と組み合わせ、出力行ごとに適用した。本測定の
腕は全て「`new`〜`run`」の単純な構造（`LOCATE`等による出力位置の移動
は含まない）だったため、`l4-s5f`で必要だった絶対位置の個別判断は
不要だった。

## 腕ごとの記録

`Ok`行の位置（相対行）と`RUN`後に出た行の数は、全12腕で記録した。
`numeric_output`（`NUMERIC_CODES`集合内のみ）と分類された行はデコード
した内容を、それ以外（`other`）は件数と桁範囲だけを記す。

| 腕 | 打鍵文字列 | `run`エコー(相対行) | `Ok`行(相対行) | 出力行 |
|---|---|---|---|---|
| G1 | `new`/`10 read a,b`/`20 print a+b`/`30 data 3,4`/`run` | 5 | 7 | 6:`7` |
| G2 | `new`/`10 for i=1 to 3`/`20 read a`/`30 print a;`/`40 next`/`50 data 5,6,7`/`run` | 7 | 9 | 8:`5`,`6`,`7`(1行に3値) |
| G3 | `new`/`10 read a`/`20 restore`/`30 read b`/`40 print a;b`/`50 data 8,9`/`run` | 7 | 9 | 8:`8`,`8`(1行に2値) |
| G4 | `new`/`10 read a$`/`20 print a$`/`30 data 12`/`run` | 5 | 7 | 6:`12` |
| G5 | `new`/`10 if 1 then a=5`/`20 print a`/`run` | 4 | 6 | 5:`5` |
| G6 | `new`/`10 dim a(3)`/`20 a(0)=7`/`30 print a(0)`/`run` | 5 | 7 | 6:`7` |
| G7 | `new`/`10 a=1:b=2:print a+b`/`run` | 3 | 5 | 4:`3` |
| G8 | `new`/`10 read a`/`20 print a`/`run` | 4 | 6 | 5:other(件数14、桁0-17) |

（具体的な数字・文言は記録しない）。

## 判定

- **Q1**（G1〜G4、`READ`/`DATA`）: 全腕**`read_ok`**。
  - G1（`read a,b`/`data 3,4`）: 出力`7`（`a+b`=`3+4`）。
  - G2（ループ内`read a`、`data 5,6,7`）: 出力は`5`・`6`・`7`の3値
    （`FOR`のループ3回それぞれで`DATA`の値を順に読んだ）。
  - G3（`read a`→`restore`→`read b`、`data 8,9`）: 出力は`8`・`8`
    （2回目の`read b`が`9`ではなく最初の値`8`を再び読んだ）。詳細は
    Q2参照。
  - G4（`read a$`、`data 12`）: 出力は`12`（文字列変数として`"12"`を
    正しく読み込んだ、文字列出力なので符号位置の空白は無かった）。
- **Q2**（G3、`RESTORE`）: **`restore_ok`**。`restore`を挟んだ2回目の
  `read`が、`data`の2番目の値`9`ではなく最初の値`8`を再び読んだ
  （出力が`8`,`8`）。`RESTORE`が読み取り位置を先頭へ戻すことを確認
  した。
- **Q3**（G5、`THEN`の代入）: **`then_assign_ok`**。`if 1 then a=5`の
  後、`print a`の出力は`5`だった。`THEN`の後に代入文（`a=5`）を直接
  書け、実行されることを確認した。
- **Q4**（G6、添字0）: **`index0_ok`**。`dim a(3)`で宣言した配列に
  `a(0)=7`を代入し、`print a(0)`の出力は`7`だった。添字`0`への代入・
  参照が期待どおりに機能した。
- **Q5**（G7、1行に複数の文）: **`multi_ok`**。`10 a=1:b=2:print a+b`
  の出力は`3`（`1+2`）。`:`で区切った3つの文（代入・代入・`PRINT`）
  がすべて実行された。
- **Q6**（G8、`DATA`切れ、記述のみ）: `10 read a`/`20 print a`で
  `DATA`文が無い状態から`read`すると、出力行は1行（相対行5、`other`、
  件数14・桁0-17）で、`Ok`は相対行6に現れた。`20 print a`に相当する
  数値出力（`read`が失敗したはずの`a`の値）は現れなかった。
- **Q7**（G9・G10、`REM`と`'`）: 両腕とも**`rem_ok`**。
  - G9（`10 print 1:rem 9`/`20 print 2`）: 出力は`1`（相対行5）・
    `2`（相対行6）の2行。`rem 9`の後に何か追加の文があるかのように
    見えても、それ以降は実行されず、`20 print 2`は影響を受けずに
    実行された。
  - G10（`10 ' 9`/`20 print 3`）: 出力は`3`（相対行5）の1行。`'`
    コメント単独の行（`10 ' 9`）は実行に影響せず、`20 print 3`が
    そのまま実行された。
  - 両腕とも、`REM`・`'`の後の文字列がプログラムの実行に影響しな
    かったため`rem_ok`と判定した。
- **Q8**（G11・G12、`IF`と同じ行の残り）:
  - G11（`a=2:if a=2 then print 1:print 2`、真）:
    **`rest_runs_when_true`**。出力は`1`（相対行4）・`2`（相対行5）の
    2行。`THEN`が真のとき、`THEN`の後の`print 1`だけでなく、その後
    `:`で続く`print 2`も実行された。
  - G12（`if 0 then print 1:print 2`/`20 print 3`、偽）:
    **`rest_skipped_when_false`**。出力は`3`（相対行5）の1行だけ
    だった。`10`行の`print 1`・`print 2`のどちらも出力に現れず、
    `IF`が偽のとき、`THEN`の後の文だけでなく、同じ行の`:`以降
    （`print 2`）も含めてすべて飛ばされた（`print 2`だけが実行される
    `rest_runs_when_false`ではなかった）。
- `gate_failed`: 該当する腕は無い（G1〜G5・G8すべて真）。

## 判定から外した腕

無し。全12腕がG1〜G5・G8を満たし、判定に含めた。

## 事前登録から外れた点

無し。腕の打鍵文字列・フレーム式・関門・判定名は事前登録
（`3cd23ed`）から変更していない。「記録する内容」節が定める、
`NUMERIC_CODES`集合を出力行ごとに適用する手法（`l4-s5b`で確立・
正式化済み）をそのまま踏襲した。

## 禁止事項7の遵守について

本測定でツール出力・本ノートに載せたのは、(1)自分で打ったプログラム
が`RUN`によって`PRINT`した数値（`NUMERIC_CODES`集合内のみで構成
される行に限る。事前登録が明示的に許可する範囲）、(2)G8の`other`
分類の行の件数・桁範囲、および「数字0-9のコードを持つセルが含まれ
るか」という真偽値のみ（事前登録が明示的に許可する範囲）、
(3)ハードウェア設定に相当するアドレス式・行/列番号のみ。`DATA`切れ
の誤りメッセージの文言・具体的な数字は、分類の過程でも一度も
デコード・出力していない。
