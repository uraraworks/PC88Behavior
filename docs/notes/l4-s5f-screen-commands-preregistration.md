# l4-s5f — 画面の命令（CLS・LOCATE・COLOR・WIDTH・スクロール） — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

開発者判断により、代表プログラム群は典型的なテキスト画面のプログラム
（数当て・九九・素数・ソート等）に決まった。これらには`CLS`・
`LOCATE`・`COLOR`・`WIDTH`と、実行中の画面のスクロールが要る。本ノート
はこれらを測る。

## 問い

- Q1 `CLS`（F1・F10）: 画面が消えるか
- Q2 `LOCATE`（F2・F3・F12）: 指定した位置に出力されるか、引数の順序
  （x,yかy,xか）、既存の行への上書きが起きるか
- Q3 行の端での折り返し（F4）: `LOCATE`で行の右端付近を指定したときの
  挙動
- Q4 `COLOR`（F5・F6）: 出力したセルの属性の値
- Q5 `WIDTH`（F7・F8）: 画面の桁数・行数を変えたときの出力位置と、
  CRTC・DMAへのI/O書き込みの列
- Q6 実行中のスクロール（F9）: 出力が画面の行数を超えたときの挙動
- Q7 `CHR$(12)`（F11）: 制御文字による画面消去の有無

## 腕（12腕＋陽性対照1腕）

打鍵はこのまま使う（英字は小文字）。F9・F10は`new`のあと行を打ち
`run`を打つ。それ以外は直接モードの1行または連続する数行。

| 腕 | 打鍵文字列（`\n`は改行） | 目的 |
|---|---|---|
| F1 | `print 1`/`cls` | Q1 消去（消えた後の非空白件数とOk位置） |
| F2 | `locate 10,5:print 7` | Q2 絶対位置指定 |
| F3 | `locate 0,0:print 7` | Q2 原点 |
| F4 | `locate 78,5:print 12` | Q3 行の端での折り返し |
| F5 | `color 2:print 7` | Q4 属性の値（色2） |
| F6 | `color 7:print 7` | Q4 属性の値（色7） |
| F7 | `width 40`/`print 7` | Q5 桁数変更 |
| F8 | `width 80,25`/`print 7` | Q5 行数変更 |
| F9 | `new`/`10 for i=1 to 25`/`20 print i`/`30 next`/`run` | Q6 実行中のスクロール |
| F10 | `new`/`10 cls`/`20 print 7`/`run` | Q1 プログラム内のCLS |
| F11 | `print chr$(12);7` | Q7 制御文字による消去 |
| F12 | `print 1`/`print 2`/`locate 0,1:print 9` | Q2 既存の行への上書き |

### 陽性対照（1腕、腕数には含めない）

直接モードの`print 7717`（`l4-s4a`以来使ってきた陽性対照と同一）。

- 打鍵文字列: `print 7717\n`（文字数11）
- フレーム計算式は下記「条件・関門」節の全腕共通の式をそのまま使う:
  `line_end = 700 + 8*11 = 788`、`dump = line_end + 300 = 1088`、
  `run = dump + 200 = 1288`（`l4-s5c`〜`l4-s5e`の作法を踏襲し、陽性
  対照のフレーム式も本文に明記する）。

腕の総数: **12腕**（F1〜F12）。各腕2走（決定論性の関門G3）。

## WIDTH腕（F7・F8）の解釈の前提

`docs/spec/l3-main.md`の既存測定（第5節・第6節、131〜132行・555〜
558行）では、`WIDTH80,20`が120バイト×18行（表示、既定表示で19行との
記載もある）、`WIDTH80,25`が120バイト×23〜24行という結果が確認済み
である。**この既存測定はいずれも80桁のときのものであり、`WIDTH40`
（40桁）でテキストVRAMのアドレス空間・1行あたりのストライドがどう
なるかは未確認である。**

本ノートでは次を前提とし、測定でこの前提を裏付けるか、外れるかを
確かめる（前提を裏付けの根拠として押し通さない）。

- F7（`WIDTH40`）の写しは、`WIDTH80,25`と同じストライド（120バイト/
  行、文字域80バイト+属性域40バイト）で読み、実際に`7`が現れる絶対
  桁位置（col0）が0〜39の範囲に収まるかどうかを、解釈を決める材料の
  1つとして使う（40桁時に1行の文字域が40バイトに詰められる設計なら、
  120バイトストライドのままでは`7`が予期しない位置に現れるはずであり、
  その場合は本ノートの前提が外れたことになる。外れた場合は結果ノート
  にその旨を記述し、ストライドの再測定を次の作業に回す）。
- F8（`WIDTH80,25`）は、既存測定（120バイト×23〜24行）をそのまま前提
  として使える。

## 条件・関門

`l4-s5e`（`0627571`）の「条件・関門」節をそのまま踏襲する。

- 起動settle`--type-at 300 --type '\n'`、実打鍵開始`--type-at 700`
- 1文字あたり`hold+gap=8`フレーム/文字（`\n`も1文字として数える）
- フレーム計算式（全腕共通。陽性対照にも同じ式を適用する）:
  ```
  line_end(k) = 700 + 8 * (その腕で打った文字数の累計。\n も1文字)
  dump(k)     = line_end(k) + 300
  run(k)      = dump(k) + 200
  ```
- 写しは打鍵前（`--type-at`の10フレーム前=690）と`dump(k)`後の2枚を
  `--diff-before`/`--diff-after`に渡す。F5・F6は加えて`--attr-only-
  rows`（単独写しに対して、下記「記録する内容」節参照）、F7・F8は
  `--iolog`（下記参照）を併用する。

## 記録する内容

- **数値の出力のセル**は、`l4-s5c`（`09c933a`）の数値分類器
  （`tools/l4_s4a_float_classify.py`、`5735eb3`）を出力行ごとに適用
  した範囲で、(絶対行, 絶対桁, 文字コード)を記録する。**本測定は位置
  そのものが主題であるため、これまでの段階5の測定（相対位置中心）と
  異なり絶対位置(row0, col0)を必ず記録する。**
- **F5・F6（属性の値）**: `7`が出力されたセルの、テキストVRAM属性域
  の値を記録する。器具・書式は`l4-s1c`
  （[l4-s1c-attribute-values-preregistration.md](l4-s1c-attribute-values-preregistration.md)）
  が使った`--attr-only-rows`（単独写しから、指定行の属性域40バイトを
  文字域に触れずそのまま列挙する）をそのまま踏襲する。属性はハード
  ウェアの設定値であり画面本文ではないため、値を出してよい
  （`tools/l4_vram_probe.py`のヘルプに明記された既存の許容範囲）。
- **F7・F8（CRTC・DMAへのI/O書き込み）**: `tools/l4_vram_probe.py
  --iolog`が対象とするCRTC（ポート`0x50`/`0x51`）・DMA（ポート
  `0x60`〜`0x68`）へのOUTの列（ポート番号・値・PC・seq・frame）を
  記録する。**この記録はCLAUDE.md禁止事項5（データポートの値列を伏せ
  る）の対象外である。** 禁止事項5が対象とするのは、公式ディスクから
  読み出した実データがそのまま載る**データポート**（`measurements/
  *.iolog.txt`の`$FB`/`$FC`/`$FD`等）であり、CRTC・DMAは**画面の桁数・
  行数・アドレスを設定するハードウェアの制御ポート**であって、公式
  ディスクや公式ROMのデータそのものを運ぶポートではない。実際、
  `tools/l4_vram_probe.py`のヘルプ自体が「これはハードウェア設定値
  であって画面本文ではない」としてCRTC・DMAへのOUT列を出力してよい
  項目に挙げている（上記ツールの`--help`記載の「出力してよいもの」
  第5項）。この区別は本ノート独自の判断ではなく、既存の器具の設計に
  すでに反映されている。
- それ以外の行（誤り・`Ok`等）は、件数と位置の範囲だけを記録する。
  コード・文言は一切出さない。
- **`Ok`行の位置と、出力の行数を、すべての腕で必ず記録する**
  （`l4-s5c`〜`l4-s5e`と同じ扱い）。

## 本文を出さない取り扱い

`l4-s4a`〜`l4-s5e`と同一。「記録する内容」節の分類規則に従い、
`numeric_output`の行だけコードを記録し、それ以外は件数と範囲だけに
する。分類器（`tools/l4_s4a_float_classify.py`）は集合外のコードを
標準出力・標準エラーへ出さない設計であることが`5735eb3`の時点で確認
済み。属性値・CRTC/DMAのI/O列は、上記「記録する内容」節のとおり本文
の対象外（ハードウェアの設定値）として扱う。

## 関門

`l4-s5e`のG1〜G5・G8と同一（G6は対になる予測表が無いため本測定にも
適用しない）。

- G1 器具の自己検査: 測定時HEADで`tools/harness/vram_dump_selftest.sh`・
  `tools/harness/vram_dump_dynamic_selftest.sh`・
  `tools/harness/key_matrix_selftest.sh`・
  `tools/harness/type_untypable_selftest.sh`・
  `tools/screen_content_leak_selftest.sh`の全項目がOK
- G2 取りこぼし0・打てない文字の警告0（全走のstderrで確認）
- G3 決定論性: 各腕2走とも、写しはファイルのsha256が一致、記録は
  sha256が一致
- G4 陰性対照: 何も打たない走で差分0件
- G5 陽性対照: 直接モードの`print 7717`腕で`7717`の並びを確認
- G8 出力完了の確認: 「後」の写しで、出力行の後に`Ok`行が現れている
  こと。特にF9（実行中のスクロール、25行の出力）で確認する。現れない
  腕は`gate_failed`とし、「写しが早すぎた」とだけ記述する

判定の前にG1〜G5・G8がすべて真であること。いずれかが偽の腕は、その
腕を`gate_failed`として判定に含めず、理由を記述する。

## 判定

判定名はこの事前登録に書いたものだけを使う。「記録する内容」節を
参照する。当てはまらない形はすべて`other`とし、記述で補う。

- Q1（F1・F10）: `clears`（`cls`の後、それ以前の出力が画面から消える。
  非空白セル件数が`cls`前より減る）／`other`
- Q2（F2・F3・F12）: 記述に加え判定を付ける。`locate_x_then_y`
  （`LOCATE`の第1引数が桁・第2引数が行として働く）／`locate_y_then_x`
  （逆）／`other`。腕ごとの絶対位置をそのまま記述する。
- Q3（F4）: 記述のみ（判定名は付けない）。行の端でどう折り返すか
  （次の行の先頭に続くか、その行の末尾で止まるか等）をそのまま書く。
- Q4（F5・F6）: 記述のみ（判定名は付けない）。属性の値をそのまま書く。
- Q5（F7・F8）: 記述のみ（判定名は付けない）。出力位置とI/O列の違い
  をそのまま書く。
- Q6（F9）: 記述のみ（判定名は付けない）。最後に見えている数値の行と
  `Ok`の位置をそのまま書く。
- Q7（F11）: `clears`（`CHR$(12)`の後、それ以前の出力が消える）／
  `other`
- `gate_failed`: 関門のいずれかが偽だった腕。判定に含めず、理由を
  記述する。

## 器具の確認（公式ROMは使わない）

測定開始前に、自作main ROM（測定時HEAD`198d023`から`src/build_main_
rom.py`で組み立て）に対し、12腕＋陽性対照の計13腕すべてを打鍵し、
各行のエコーが打鍵どおりに届くかを`tools/l4_vram_probe.py --marker`
（各腕の打鍵文字列を`\n`で分割し、各行をそれぞれmarkerとして指定）で
確認した。**自作ROMはまだ画面命令（`CLS`・`LOCATE`・`COLOR`・
`WIDTH`）・プログラムモードを持たないため、実際の挙動は見ておらず、
エコーだけを確認した。**

結果: **13腕すべてで、全行のエコーが打鍵どおりに出現した**（腕ごとの
全行でmarker一致、打鍵前の走行失敗〔型チェックによる事前拒否〕も
無し）。`,`（F2・F4・F8）、`:`（F2〜F7・F12）、`$`・`(`・`)`・`;`
（F11）を含め、届かなかった記号は無かった。

作業に使ったROM・写し・スクリプトはリポジトリ外の使い捨てディレクトリ
（scratchpad配下）に置き、確認後に削除した。
