# B30・B31: G1 でスペースを押したあとの分かれ目 — 結果

記録日: 2026-11-01
規則: [b30-g1-space-key-preregistration.md](b30-g1-space-key-preregistration.md)、[b31-g1-later-requests-preregistration.md](b31-g1-later-requests-preregistration.md) どおり。7200 フレームでは自作の main の入出力が記録の上限を超えたので、4800 フレームでも取り直した（取りこぼしなし）。測定はクラウドの実行環境。記録: `measurements/b30-g1-*`、`b30b-g1-*`、`b31-g1-requests-*`。

## 結果（4800 フレーム）

| 項目 | 公式 | 自作 |
|---|---|---|
| 要求の連続 | 38 本、6365 バイト | 22 本、987 バイト（**先頭から 22 本は同じ**、そこで終わる） |
| `read_data hi` | 35 回 | 24 回 |
| `sense_drive_status lo` | 2 回 | 3 回 |
| サブの記録 A `00C1` | 70 回（7200 F） | 29 回（7200 F） |
| main の記録 A | 8 件 | 0 件 |
| 値の違い | - | `IN $FC` 257 件（最初は番号 76570）。`OUT $FD`・`OUT $FF` は差なし |

- FDC の最初の違いは番号 93。公式は `seek hi`、自作は `sense_drive_status lo`
- 要求の先頭バイトは公式も `02`・`0C`・`0D` だけで、自作に無い種類は無い。長さの連続の中に別の要求が入っている形である

## 読み方（推定）

`IN $FC` の 257 件の違いのあと、main が別の道へ進んでいるように見える。257 は「応答 1 バイト＋256 バイト」の形に見える。次は 22 本目までの連続の中身を見ないと、どの要求かが決まらない。

## 訂正

B28 の結果ノートの「割り込みの順番の差に見える」は、推定のままである。スペース後の不一致とは別の話である。
