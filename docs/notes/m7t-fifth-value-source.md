# m7t: 5件目の値の生成源切り分け

測定日: 2026-08-13

## 情報境界

公式ROM・公式ディスクのバイト列は表示・保存せず、生I/Oログはリポジトリ外の
使い捨て領域だけで扱った。比較器が出力したのは要求・応答長、一致件数、
一致プレフィックス、同値グループ数、位置ごとの同一／相違だけである。
参照媒体と規則生成した自作D88を各600フレーム、混成を600フレーム実走した。

## 位置と生成源

main側`IN $FC`の5件目は、交換#4の2件要求に対する256件応答の先頭位置である。
公式側では、この256件応答が直前READ DATAのデータ部256位置と256/256一致し、
同値グループ数も双方81だった。先頭は直前要求2位置、READ結果7位置、直近SEEK対象、
直近SENSE INTERRUPT STATUSのPCNのいずれとも一致0だった。

媒体を規則生成D88へ差し替えると、応答と直前READデータはともに256位置中254位置が
変化し、両者の位置対応は差し替え後も256/256一致した。同値グループ数は双方256で
一致した。よって媒体連動する説Dを上流として支持し、直接生成源はREAD DATAの
データ部を同位置で転送する説Fと判定する。説P・説Sは位置一致0で棄却し、説Rは
構成・媒体に連動しないという前提と反するため棄却する。値の探索は行っていない。

## 混成側の分離診断

同じ参照媒体で、公式subと自作subが直前READ DATAから取得した256位置は256/256一致し、
同値グループ数も双方81だった。一方、自作subからmainへ見えた交換#4応答は1同値
グループで、直前READデータとの同位置一致は1/256、先頭からの一致は0だった。
したがってREAD座標やFDC取得値は既に正しく、`SECTOR_BUF`を交換#4送信へ接続する
状態遷移だけが未達である。

構造ログでは、公式側は交換#4応答中のFDCアクセスが0件なのに対し、混成側は
`$FA` 512件・`$FB` 384件だった。`RESP_ACTIVE`中にも汎用アイドル判定がRECVを
優先し、次のREAD処理へ再入している。応答バッファが有効な間は外部ビットの曖昧な
同時成立より内部の送信継続状態を優先し、256件を送り切る規則が必要である。

## このサイクルの4指標

- 値一致プレフィックス長: 4件
- main側構造的一致プレフィックス: 258件
- sub側構造的一致プレフィックス: 752件
- 混成main `IN $FD`: 0件

比較条件・期待値は変更していない。
