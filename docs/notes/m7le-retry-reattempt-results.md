## 条件3を偽にした1行

判定行の差分は3行だけだった。

| | 行 |
|---|---|
| BASEにだけある | `--` B:規則生成媒体: FDCコマンド種別列は表示した位置で分岐 |
| BASEにだけある | `OK` 陽性対照: 試験用mainドライバ構成では **2566** 件と数えられた（0件判定は空検査ではない） |
| 候補にだけある | `OK` 陽性対照: 試験用mainドライバ構成では **10774** 件と数えられた（0件判定は空検査ではない） |

**1行目（`--`が消えた）は改善で、(d)が許している。** **2・3行目が(b)を偽にした。**

**この行は何か**: 適合条件4（ディスク無しならサブは無音）の**数え方そのものを確かめる陽性対照**
である。わざとディスク無しでもサブを動かしてしまう試験用mainドライバの構成を組み、**「数えれば
0でない件数が出る」ことだけ**を確かめる（`tools/conform_l3.sh` 524行付近。合否の条件は
「0件でないこと」）。

**なぜ件数が変わったか**: ディスクが無いので、自作サブROMの読み出しは必ず失敗する。
**再試行を入れると1回で諦めずに最大9回読み直すので、サブのI/Oが増える。**
**2566→10774は、再試行が「読めないときにだけ粘る」という設計どおりに働いた結果である。**

**判定はOKのまま**である。**本命の適合条件4（公式main＋自作サブ・ディスク無し→0件）の行は
差分に出ておらず、OKのまま変わっていない。**

**登録した数え方は判定行を文字列の集合として比べる**ので、本文の件数が変わると
「OK行が1本消え、別のOK行が1本現れた」と数える。**「判定行の同一性」をどう決めるかを
事前登録に書いていなかった。** m7lbで判定行の比較を初めて登録したときは、比べる相手に
件数の変わる行が無かったので、この曖昧さが表に出なかった。
