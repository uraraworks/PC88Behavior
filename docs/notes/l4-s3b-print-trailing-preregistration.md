# l4-s3b — 直接モードの PRINT: 数の後ろの空白と、行末の区切り — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

[l4-s3a](l4-s3a-print-format-results.md)（`497ff8c`）が確かめられなかった2点を測る。l4-s3a で分かっていることは次のとおり。文字列は前後に空白が付かない。`;` で文字列どうしをつなぐと隣接する。正と0の整数は前に空白1、負の整数は前に `-` が付く。腕 P3-semi-num（`print 1;2`）で、出力行の`1`が相対列1、`2`が相対列4に現れ、間の2列(相対列2-3)が変化せず空白のままだったことから、正の数の後置の空白1つを間接的に確かめた（`;`を挟んでも数値自身の後置の空白は消えないため）。

## 問い

- Q1 数の後ろ: `PRINT n;"q"` で、数の最後の数字と `q` の間に何桁の空白があるか。n = 5、-5、0、-32768、32767。文字列の前後に空白が付かないことから、この間隔は数の後ろに付く空白の数である
- Q2 行末の `;`: `PRINT "a";:PRINT "b"` を1行で打つと、`a` と `b` が同じ行に並ぶか、並ぶならその間隔
- Q3 行末の `,`: `PRINT "a",:PRINT "b"` を1行で打つと、`b` が同じ行のどの桁に来るか（l4-s3a のゾーンの幅14と比べる）
- 対照: `PRINT "a":PRINT "b"`（区切りなし）で、`b` が次の行の先頭に来ること

## 条件と器具

- 公式ROM一式、ディスク無し、コア既定。打鍵は `--type-at 700`（英字は画面では小文字になる。文字列は `"q"`・`"a"`・`"b"` を使い、目印は小文字の `q`・`a`・`b`）
- 写しは打鍵の前と、実行と `Ok` の表示の後（l4-s3a と同じ計算:
  ```
  line_end(k) = 700 + 8 * (その腕で打った文字数の累計、\n も1文字)
  dump(k)     = line_end(k) + 20   （実行の余裕。根拠は l4-s1c 同節）
  run(k)      = dump(k) + 200      （走行フレームの余裕。l4-s1a・l4-s1c の踏襲）
  ```
  ）
- 差分は `tools/l4_vram_probe.py --diff-before/--diff-after --count-only-rows 19`

## 記録する内容

- 腕ごとに、出力の行（打った行の次の行から）の「前が空白だったセル」の (相対の行, 相対の桁, 文字コード) の並びそのもの。原点は出力の最初のセル
- Q1 は、最後の数字のセルと `q` のセルの相対の桁の差を、腕ごとに表にする
- どの行を出力の行として見たか（打った行からの相対の行）を記録する

## 判定（この節の名前だけを使う。当てはまらなければ `other` とし形を記述する）

- Q1: 各 n について `trailing_space_1`（間隔1）／`trailing_space_0`（間隔0）／`other`
- Q2: `semicolon_suppresses`（同じ行に隣接）／`semicolon_not_suppress`（`b` が次の行）／`other`
- Q3: `comma_to_zone_14`（`b` が同じ行の14桁目）／`comma_not_suppress`／`other`
