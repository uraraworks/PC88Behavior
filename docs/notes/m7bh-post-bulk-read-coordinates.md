# m7bh: バルク直後の読み出しは、6バイトレコードとは別の座標で行われている

測定日: 2026-08-19

## 情報境界

公式ROM一式・公式diskA（使い捨て複製）を**実行して**測定した。読んでいない。
座標（C/H/R）はFDCコマンドのパラメータであり、ディスクの内容ではない。

## 1. 絞り込みの経過

m7bgで一般読み出し経路が動き出したあと、応答列は依然として**6416件目**で
食い違っていた。バルク終端を基準に測り直すと:

| | 公式 | 自作 |
|---|---:|---:|
| バルク後の受信 | 2176件 | 28件（**28件すべて一致**） |
| バルク後の送信 | 1563件 | 520件（**一致は2件目まで**） |

**受け取っているものは同じ**で、**3件目の送信**——つまり256バイト応答の
先頭データ——から違う。読み出したセクタが違うということになる。

なお途中で一度、比較の窓を「READ直前の受信6バイト」に取ったせいで
「要求レコードが違う」と誤読した。バルク後の受信列で取り直すと先頭8バイトは
完全一致しており、**誤りだったのは比較の窓の取り方**だった。

## 2. 座標が違う

バルク後**最初の**READを両者で取り出した。

| | 座標 (C,H,R) | データ長 | そのREADまでに受信した件数 |
|---|---|---:|---:|
| 公式 | **(18, 1, 13)** | 263 | **5** |
| 自作 | (6, 1, 6) | 263 | 6 |

自作は6バイトレコードから規則どおりに導いている
（レコード末尾2バイト = `[論理トラック13, R=6]` → `C=13>>1=6`、`H=13&1=1`、
`R=6`）——**m7axで確定した規則には従っている**。

公式はそうではない。**受信5件の時点で読んでおり**、しかも座標が違う。
注目すべきは **公式の R(=13) が、自作が論理トラックとして使った値(13)と
同じ**ことである。つまり**同じレコードを別のフィールド割り当てで読んでいる**
可能性がある（例: このレコードは6バイトではなく、境界の取り方が違う）。

## 3. まだ分かっていないこと

- 公式の C=18 がどこから来るのか（このレコードの中には見当たらない）
- 公式が**受信5件の時点で**読み始める根拠（レコードの区切りが自作と違う）

**推測で実装しない。** 次は「バルク直後の要求の区切り方」を測る——
どこからどこまでが1つのレコードなのかを、`$FF`のフェーズコードの並びから
決め直す必要がある。m7axで確定した「データ部の直前2バイト」という規則は
**書き込みでは15/15・64/64で成立している**ので、規則そのものが誤りとは
考えにくい。バルク直後だけ別の形式が使われている可能性を含めて測る。

## 4. この節の教訓

**比較の窓を変えたら、結論も変えて確かめ直す。** 「READ直前の6バイト」で
測ったときは「要求レコードが違う」と読めたが、「バルク後の受信列」で測ると
先頭8バイトは完全一致だった。同じデータでも切り出し方で逆の結論が出る。
**窓の取り方そのものを、別の切り方で検算する。**
