# m7id: 要求の位置を壊して、連続READを決めている位置かを見る — 事前登録

## 位置づけ

[m7ic](m7ic-late-typing-retry-results.md)は`m7hs`の留保を決着させた。要求の
1バイト差（分岐段の候補#3＝run長5の要求、**run内位置4**）は、応答の内容の差の
結果でも（`m7hy`）、応答の進み方の差の結果でもない（`m7ic`）。**下流の説明は
両方潰れた。**

**次は「その位置が連続READを決めているか」を見る段階である。**

## 手段の確認（事前登録の前に済ませた。コードを読んだだけで測っていない）

`tools/harness/core/q88h_exchange_intervention.c`の
`q88h_exchange_intervention_process`は、run番号を両方向で数える一方、
**値を書き換えるのは`direction == DIR_SUB_TO_MAIN`のときだけ**である。

**すなわち現状の道具には、main→subの要求（受信run）の特定位置を差し替える手段が
無い。** よって本稿は`tools/`のハーネスを拡張する。`src/`（自作サブROM）は
変更しない。

## 値を読まずに意味へ迫る設計

対象位置の**値は分からないし、分かろうとしない。** 公式が送っている値を知る
には全256掃引で「基準と同じ振る舞いになる値」を探すことになるが、それは
**禁止事項5が伏せ字にしているデータポート値を推論で復元する行為**にあたる。
**本稿は掃引しない。**

代わりに、**内容を見ない固定の摂動**（`XOR 0xFF`）を当て、**連続READ構造が
保たれるかどうか**という真偽だけを見る。

**特異性は位置どうしの比較で得る。** run長5の要求の位置0〜4それぞれに同じ
摂動を当て、**位置4だけで構造が壊れるのか、どの位置でも壊れるのか**を見る。
どの位置でも壊れるなら、この摂動は「その位置が効いている」ことの証拠にならない。

## 段階0（本稿）: 事前登録を測定前にコミットする

本稿は測定を1回も走らせる前に単独でコミットする。測定後の書き換え・amendは
行わない。ハーネスの拡張と対象runの同定も本コミット後に行う。

## 測定条件

- **条件Oのみ**（公式ROM一式）。本稿が壊すのは**公式subが受け取る要求**である。
  A:=`disk#8`（`650cfac8`）、B:=`disk#10`（`0c6f7a53`）。
- 打鍵は水準E（`--type-at 300 --type '\n' --type-at 700 --type 'FILES 2\n'
  --frames 3000`）。`m7hs`・`m7hw`・`m7hy`・`m7ic`が使い、条件Oの生ログが独立
  2回でバイト一致することを確認済みの水準である。
- 構造の指標は`m7hb`以来の**READ DATAのrun長の並び**（`compare_l3_entry_fdc.
  command_names`から求める）。基準（摂動なしの条件O）は**単発9本＋run長9が12本**
  である。

## ハーネスの拡張（`tools/`のみ。`src/`は触らない）

`--request-intervention RUN:POS:MODE:VALUE`（名称は実装時に確定してよい）を
新設する。要件:

- **`DIR_MAIN_TO_SUB`のrunにのみ適用する**（既存の`--exchange-intervention`は
  sub→main専用のまま変更しない。**既存の挙動を変えない**）。
- **run内の位置を指定できる**（`POS`）。既存の`xor-all`等は位置を選べないため
  流用できない。
- 適用件数（`matched_events`・`applied_events`・`changed_events`相当）を
  取得できること。**「介入が届いたか」を件数で確認できないと、`L3`と
  「介入が空振り」を区別できない。**
- 出力に値を載せない（既存の規律を踏襲）。

## 段階1: 手段が効くことの確認（本体より先。ここが通らなければ本体はやらない）

1. **対象runの同定**: 介入フックのrun番号づけ（両方向を通し番号で数える）で、
   分岐段の候補#3（run長5のmain→sub要求）が**何番か**を求める。
   求め方は、摂動を当てずに件数だけを観測する形とする。
2. **届いていることの確認**: 対象run・位置4へ`XOR 0xFF`を当て、
   **`applied_events`と`changed_events`がいずれも0より大きい**こと、かつ
   **生ログが摂動なしと異なる**ことを確認する。
3. **基準の再現**: 摂動なしの条件Oで、READ DATAのrun長の並びが
   「単発9本＋run長9が12本」であることを再確認する。

**中止規則（測定前に固定）:** 2項で`changed_events`が0、または生ログが
摂動なしと同一なら、**本体は実施しない。** 主判定を**O'（介入が届かなかった）**
とし、その事実を記録する。**無言でSKIPしない。**

## 段階2: 本体（段階1が通った場合のみ）

run長5の要求の**位置0・1・2・3・4**それぞれについて、条件Oに`XOR 0xFF`を当て、
READ DATAのrun長の並びを求める。位置ごとに次を記録する（値は出さない）。

- `applied_events`・`changed_events`（介入が届いたか）
- READ DATAの総件数、run長の並び、**run長9のrunが12本あるか**（真偽）
- FDCコマンド種別列の総件数

## 事前登録する判定（測定前に固定。後から動かさない）

- **L1（位置4に特異性あり）**: 位置4で連続READ構造が壊れ（run長9×12が成立
  しない）、**位置0〜3では壊れない**。
- **L2（特異性なし）**: 位置4を含む**複数の位置**で壊れる。どの位置が効いて
  いるかを本稿では決めない。
- **L3（どこも壊れない）**: 全位置で構造が保たれる。段階1で介入が届いている
  ことを確認済みなので、これは「この摂動ではこの構造は変わらない」という結果で
  ある（介入の空振りとは区別される）。
- **L4（位置4だけ壊れない）**: 位置0〜3の一部で壊れるが位置4では壊れない。
  予期しない形として記録し、解釈しない。
- **O（測定不能）**: 基準が再現しない、決定論性が確認できない。
- **O'（介入が届かなかった）**: 段階1の中止規則に該当。

**どの判定になるかは予測しない。**

## 事前登録する合格条件（測定前に固定）

1. `tools/recv_run_field_leak_selftest.sh`が全項目OK・rc=0（陰性対照・故障注入込み）。
2. `tools/analyze_error_exchange_shape_selftest.sh`がrc=0。
3. **既存挙動の非回帰**: 拡張後も`--exchange-intervention`の既存の振る舞いが
   変わらないこと。具体的には、`m7ic`で使ったarm 9（`9:xor-all:0xFF`、条件M・
   打鍵F=2200）の生ログが**拡張前と同じ**であること。異なれば判定O。
4. **決定論性**: 摂動なしの条件Oと、位置ごとの摂動を当てた条件Oのそれぞれに
   ついて、生ログが独立2回でバイト一致すること。
5. **介入が届いていることを位置ごとに確認**: 各位置で`changed_events > 0`で
   あること。0の位置があれば、その位置は「壊れなかった」ではなく
   **「介入が届かなかった」**として別に記録する（`L`判定の材料に使わない）。
6. `tools/check_cleanroom.sh`が全項目OK。

## 言えないこととして先に書いておくこと

- **L1が出ても「その位置の値が連続READの回数を指定している」とは言えない。**
  言えるのは「その位置を壊すと連続READ構造が壊れ、他の位置を壊しても壊れない」
  までである。**意味（レコード数なのか、別の何かなのか）は本稿では決まらない。**
- **`XOR 0xFF`という摂動は内容を見ない代わりに、壊し方として乱暴である。**
  構造が壊れたとき、それが「その位置が連続READを決めていた」からなのか
  「要求そのものが不正になって別経路へ落ちた」からなのかを、本稿は区別しない。
- **本稿は値を掃引しない。** 対象位置の値を推論で復元しない（禁止事項5）。
- 条件O・`disk#10`という1本のディスク・1条件である。一般性は主張しない。

## 禁止（本稿の測定中も例外なく適用）

- 公式ROMのバイト列を読まない・出力しない・保存しない。逆アセンブルしない。
- 受信run・応答run・大量転送runのバイト値、FDCデータポート値、シリンダ値、
  PCN値を出力しない。出してよいのは件数・run長・位置番号・真偽値・clock・
  frame・rc・介入指定の文字列のみ。
- **対象位置の値を掃引・推論で復元しない。**
- 画面本文の生の行を報告・ノート・コミットメッセージ・ツール出力へ書かない
  （禁止事項7）。
- 公式ディスクの実ファイル名を展開して表示しない。
- 第三者の逆アセンブルリスト・解析記事のコード断片を参照しない。
