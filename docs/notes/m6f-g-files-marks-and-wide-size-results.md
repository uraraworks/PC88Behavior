# m6f-g — FILES の種別の印（0xA0・0x01）と3桁の大きさ — 結果

記録日: 2026-09-28

## 1. 実行

[事前登録](m6f-g-files-marks-and-wide-size-preregistration.md)（`121b4ae`）に従った。器具 `21cb4eb`、公式ROM起動10回（5腕×2走）。
関門 G0〜G14 はすべて真。参照 diskA 複製は不変、作業先で画面本文を持つファイルは0件。追補は無い。

## 2. 判定

| 腕 | 判定 |
|---|---|
| G-P（種別 `0xA0`） | **`mark_2E`**（印はピリオド、大きさを表示する） |
| G-B（種別 `0x01`） | **`mark_2A`**（印はアスタリスク、大きさを表示する） |
| G-M（`0x80`・`0x00`・`0xA0`・`0x01`・`0x80` の混在1行） | **`mixed_row_consistent`** |
| G-Z1（100単位）・G-Z2（158単位） | **`size_min_digits`** |

いずれも2走一致で、191候補の中で一意だった。

## 3. 採った規則

- 種別バイト `0x80`（`SAVE`）と `0xA0`（`SAVE ,P`）の印はピリオド、`0x00`（データ・`SAVE ,A`）は空白、`0x01`（`BSAVE`）はアスタリスク。
  マニュアル（物理161頁）の3種の説明と矛盾しない。
- 大きさは3桁（100〜158）でも最小桁数の10進（m6f-e の1桁・2桁と同じ規則）。セルは16桁に収まる（名前6＋印1＋拡張子3＋空白1＋3桁＝14）。

## 4. 行き先

- `docs/spec/l4-basic.md` 11.1節の規則3に追記し、11.3節の未確定から「3桁以上の大きさ」「0x80・0x00 以外の種別」（`0xA0`・`0x01` の分）を外す。
- 自作 FILES の印の組み立てを仕様に合わせ、`tools/conform_files.sh` に本稿の5腕を足す。

## 5. 決めないこと

- `0x80`・`0x00`・`0xA0`・`0x01` 以外の種別バイト。種別バイトのビットの意味。`LFILES`。
