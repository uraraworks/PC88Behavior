# B33: 違う区間の値が ROM の内容かを、値を出さずに確かめる — 事前登録

記録日: 2026-11-01
位置づけ: [汚染の疑いの記録](contamination-2026-11-01-b32-values.md) の措置 4。**このノートは測定より先にコミットする。**

腕 F の 4800 フレームの `--io-log`（再利用してよい）。実装は `tools/b33_rom_origin.py`。**値は 1 バイトも出さない。** 器具の中で比べ、番地だけを出す。

- 公式の走の `IN $FC` の、最初に違う区間（番号 K から 132 バイト）を、公式の `DISK.ROM` の先頭 0x800 の中から探す
- 自作の走の同じ区間を、自作の `DISK.ROM` の中から探す
- 公式の走の同じ区間を、自作の `DISK.ROM` からも探す（対照）
- 同じ確認を K の直前の 2 バイト、B22 の 2 箇所（0 始まりの番号 3840、3841 それぞれ 1 バイトは短すぎるので、前後を含む範囲は作らず、結果を出さない）

白リスト: `official-in-official-rom offset=<4桁16進|none>`、`self-in-self-rom offset=<4桁16進|none>`、`official-in-self-rom offset=<4桁16進|none>`、`length=<N>`。

判定:
- 自作と公式が同じ番地で ROM と一致するなら、「G1 はサブ ROM のその番地を読む」と書き、汚染として確定する
- 一致しなければ、RAM の内容の可能性として書く。汚染の疑いは残すが ROM とは言わない

結果は `docs/notes/b33-g1-rom-origin-results.md`。
