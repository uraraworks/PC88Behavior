# m7hp: 分岐点直前の要求が公式と混成で同一かを、場面を揃えて測る — 事前登録

## 位置づけ

[m7hm](m7hm-recv-run-count-field-results.md)は、連続READ移行の規則を
「要求の内容から読む」方向で測って判定Nに終わり、次の2つを宿題に残した。

1. **場面の交絡**: 群S（単発）は起動段階、群R（連続）は`FILES 2`入口に
   あり、比較すると「連続か単発か」と「起動か入口か」が混ざる。
2. **候補2本の同点解消**: 連続READ入口12段のうち11段で候補が2本あり、
   一意に定まらない（中止規則によりN判定）。

[m7ho](m7ho-seek-without-recv-run-results.md)は宿題1の前提を片付けた。
受信runが先行しないSEEKは**起動段階に固有**で、入口場面（frame≥700）の
12段はすべて受信runが先行する。**したがって入口場面だけを見れば、
対応づけの穴は無い。**

**本稿は、宿題1・2を両方まわりこむ設計で測る。**

## 設計の中心: 対比を「単発 vs 連続」から「公式 vs 混成」へ移す

入口場面には、公式条件（条件O）には連続READ（run長9）しか無く、単発が
無い。だから条件O内部では対比が取れない。

しかし**混成条件（条件M。公式main ROM一式＋自作サブROM）では、同じ入口
場面で自作`general_read_request`がレコードごとに再SEEKする**（1.57節）。
そして**要求を出す側のmainは、条件Oでも条件Mでも公式ROMである。**

```
条件O: 公式main ──要求──▶ 公式sub  → 連続READ(run長9)
条件M: 公式main ──要求──▶ 自作sub  → 単発READ(run長1)
              ↑ 同じ側・同じ場面・同じディスク
```

したがって**分岐点より手前では、同じmainが同じ場面で出した要求どうしを
比べられる**。1.57節は、FDCコマンド種別列が**55件目まで公式・混成で一致
し、56件目で分岐する**ことを確定している（`m7gz`）。この一致区間が、
場面が揃っていることの実測上の裏づけである。

**同点解消の問題も、この設計では起こらない。** 候補が2本あるなら、
**2本を順序込みの列としてそのまま比較する**。どちらか1本を選ぶ規則を
後知恵で決める必要が無い。

## この測定が決めること

- **要求が公式と混成で同一なら、要求は差の原因ではありえない。** 同じ
  バイト列を受け取った2つのsubが、一方は連続READへ移行し、他方は
  レコードごとに再SEEKしているのだから、差はsubの内部にある。
  H1（要求がレコード数を伝える）は反証され、H2（内部状態）側に寄る。
- **要求が違うなら、H1は生き残る。** どの位置が違うかが次の測定の入口に
  なる。

**どちらでも前進する。** ただし前者の場合、差の所在はROM内部のワーク
エリア構造に当たり、3節の第23版（`SEND_DISPATCH_IDLE`の応答値）と同じく
**クリーンルーム規律上は測定では届かない**領域に入る。そのときは
「届かないことを測定で示した」として、この軸の追跡を打ち切る根拠にする。

## 段階0（本稿）: 事前登録を測定前にコミットする

本稿は比較を1回も走らせる前に単独でコミットする。測定後の書き換え・
amendは行わない。**条件Mに対して`stage1`を走らせるのも本稿のコミット後
とする**（走らせてから群の定義を決めれば事前登録の意味が無い）。

## 測定条件

- 条件O: 公式ROM一式。A:=`disk#8`（`650cfac8`）、B:=`disk#10`（`0c6f7a53`）。
- 条件M: `build_mixed_rom`（故障注入なし）。ディスク・打鍵は条件Oと同一。
- 打鍵: `--type-at 300 --type '\n' --type-at 700 --type 'FILES 2\n'
  --frames 3000`（m7gy以来すべての稿と同一）。
- `m7hl`で取得済みのログ（`O-run1`・`O-run2`・`M-mixed`）を再利用してよい。
  失われていれば同一コマンドで再取得し、条件Oはバイト一致を確認する。
  条件Mも独立2回取得して一致を確認する（条件Mの決定論性は本稿で初めて
  確認する項目である）。
- 使うAPI: `compare_recv_run_fields.stage1_report`（段・候補対応）、
  `compare_l3_entry_fdc.command_names`、`analyze_write_path.parse_commands`。
  比較には`compare_recv_run_fields`の`_eq`／`_cmp_sign`と同じ値非公開の
  規律を使う。**新規に値を出す経路を作らない。**

## 比較の対象（測定前に固定）

1. **分岐段の同定**: FDCコマンド種別列を条件O・条件Mで先頭から比較し、
   最初に種別が食い違う位置を求める（1.57節の56件目に一致するはず。
   一致しなければ判定Oとする）。この位置を含む段を**分岐段**と呼ぶ。
2. **比較する受信run列**: 分岐段について、`stage1_report`が返す候補run
   （順序込みの列）を条件O・条件Mそれぞれから取る。
   - 候補数が条件O・条件Mで異なる場合は、**それ自体を結果として記録し**、
     位置ごとの比較は行わない（D3）。
   - 候補数が同じなら、i番目どうしを対応させ、run長の一致を見たうえで
     位置ごとに`eq`を取る。
3. **対照区間**: 分岐段**より前**の段についても同じ比較を行う。ここは
   種別列が一致している区間なので、**要求も一致するはず**である。
   ここで不一致が出るなら、比較方法そのものが場面を揃えられていない
   （判定O）。

## 事前登録する判定（測定前に固定。後から動かさない）

- **D1（要求は同一。H1反証）**: 分岐段の候補run列が、候補数・run長・
  全位置の`eq`すべてで一致する。
- **D2（要求が違う。H1存続）**: 候補数とrun長は一致するが、`eq`が偽に
  なる位置が1つ以上ある。**その位置番号のみを記録する**（値は出さない）。
- **D3（比較不能）**: 候補数またはrun長が条件O・条件Mで異なる。
- **O（測定不能）**: 陽性対照が通らない、分岐位置が56件目でない、
  対照区間で不一致が出る、決定論性が確認できない。

**どの判定になるかは予測しない。**

## 事前登録する合格条件（測定前に固定）

1. **陽性対照（比較より先に通す）**
   - `tools/recv_run_field_leak_selftest.sh`が全項目OK・rc=0
     （comparatorの故障注入と、値を出す改変版で検査が落ちる陰性対照を含む）。
   - `tools/analyze_error_exchange_shape_selftest.sh`がrc=0。
   - **故障注入との対比**: `--break-drive-selector`で作った条件（以下
     条件M-broken）を条件Mの代わりに置いたとき、**分岐位置または対照区間
     の比較結果が条件Mのときと変わること**。変わらなければ、この比較は
     実装差に反応していないことになるので判定Oとする。
     **これは「差が出ること」を確認する対照であり、D1（一致）を主張する
     ための必須の裏づけである**——差を検出できない方法で「一致した」と
     言っても意味が無い。
2. **場面が揃っていることの確認（合格条件1とは別）**: 分岐位置が1.57節の
   56件目（1起点）と一致すること。対照区間（分岐段より前）の受信run比較が
   全位置一致すること。
3. **決定論性**: 条件Oはrun1・run2でログがバイト一致。条件Mも独立2回で
   全比較結果が一致。
4. `tools/check_cleanroom.sh`が全項目OK。

## 言えないこととして先に書いておくこと

- **D1が出ても「公式subが固定カウンタを持つ」ことの証拠にはならない。**
  言えるのは「要求の内容では差を説明できない」までである。内部状態の
  形（カウンタか、トラック境界の計算か、別の何か）は区別しない。
- **分岐点より後の比較はしない。** 分岐後はmainがsubの応答に反応して
  分岐するため、場面が揃っているとは言えない。この境界を越えない。
- 条件O・`disk#10`という1本のディスク・1条件である。一般性は主張しない。
- 本稿は介入を行わない。因果は言わない。

## 禁止（本稿の測定中も例外なく適用）

- 公式ROMのバイト列を読まない・出力しない・保存しない。逆アセンブルしない。
- 受信runのバイト値・FDCデータポート値・シリンダ値・PCN値を出力しない。
  出してよいのは件数・run長・位置番号・`eq`の真偽・`cmp`の符号・真偽値のみ。
- 画面本文の生の行を報告・ノート・コミットメッセージ・ツール出力へ書かない
  （禁止事項7）。
- 公式ディスクの実ファイル名を展開して表示しない。
- 第三者の逆アセンブルリスト・解析記事のコード断片を参照しない。
