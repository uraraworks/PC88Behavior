## 1. 誤りの番号（`on error goto`・`err` が使える。番号の方法が成立）

参照5つは標準の番号どおり: `a$=chr$(300)`=**5**、構文誤り=**2**、`goto 999`=**8**、型の不一致=**13**、`a%=40000`=**6**（5つとも的中。方法の検証を兼ねる）。

| COLOR の文 | 結果 |
|---|---|
| `color 8`・`color 256`・`color -1`・`color ,8` | 誤り **5**（本体の署名一致と同じ。的中） |
| `color "a"` | 誤り **13**（的中） |
| `color`（引数なし）| 誤り **22**（的中。弱い予測だった） |
| `color 2,`（末尾のカンマ）| 誤り **22**（予測は続行で外れ。引数が空のまま終わると同じ誤り） |
| `color 5,1,1,2,3`（5引数）| 誤り **5**（確認として的中） |
| `color 3,0,0,0,0`（5引数・穏当な値）| 誤り **2**（予測の5は外れ）。**5引数であること自体は構文誤り（2）**。`5,1,1,2,3` が 5 になるのは第2〜4引数の値の検査が先に起きるため |
| `color 3,1,1,2`（4引数）| 誤り **5**（予測は続行で外れ）。本体の `color 3,0,0,6` は続行したので、**第2〜4引数のうち (1,1,2) のどれかが範囲外（5）になる**。どれが原因かは測っていない（グラフィック側の引数で、事前登録で「決めない」とした範囲） |

## 2. 20組を超える色替え（m6 N=24・m7 N=20・m8 N=21、80桁・40桁とも同じ形）

- 先頭19組は規則どおり (pos(i), v_i)（pos は80桁 i、40桁 2i−1。i=1..19）。
- **20組目は常に位置 0x80（行末）で、値は最後の区間（N番目）の値**: m6 → (0x80, v24=4)、m8 → (0x80, v21=1)、**m7（ちょうど20区間）→ (0x80, v20=7)**。
  m6・m8 は予測どおり。**m7 は予測 (20, 7) が外れ、20区間のときも20組目の終端は行末 0x80 になる**（19区間のときは終端 pair が書かれない m2 と矛盾しない: 本体 m2 は (0x80, 2)、19区間以下では最後の組の後ろは (0x80,0x00) の未使用組）。
- 本体の曖昧さ（20番目の値か最後の値か）は解決: **最後の区間の値**（m6: 24番目の4、20番目は7）。
- 規則: 区間が20以上になると、先頭19組の後ろは「20組目 = (行末 0x80, 最後の区間の値)」。21番目以降の区間の終端位置は記録されない（20組目に潰れる）。

## 3. 自作ROMの現状（参考。`ownrom`、62腕、関門は失敗）

自作は **CRTC のカーソル位置コマンドにパラメータを付けない**（最後の 0x81 がパラメータなし）ため cur 10腕すべて differ。
COLOR は val で n=0 のみ一致、混在腕（mix 16腕）は全て differ（自作は行全体に値を書く形）、範囲外 `color 8` 等は誤りにならず続行、引数形（`color ,3` 等）は続行せず、5引数・`color "a"` は一致。
判定項目 97件中 34件一致。**自作の COLOR・カーソル位置の実装が公式の規則に追いついていない**（次の実装段の材料）。

## 公式の確定規則のまとめ（実装向け）

1. CRTC カーソル位置: `locate c,r` の後に **コマンド 0x80 ＋パラメータ（桁, 行）**。80桁は (c, r)、40桁は (2×c, r)。
2. `color n`: n=0〜7 の整数（小数は四捨五入）。範囲外（8以上・負）は誤り5、文字列は誤り13、引数なし・末尾が空のカンマは誤り22、5引数は誤り2。第2〜4引数は範囲検査があり、(1,1,2) のような値は5になる場合がある。
3. 属性域: 印字した区間の終端位置と値の組。n=0 は組なし、n=1〜7 は値 n。色は次の COLOR まで持続。位置は80桁が終端桁、40桁が 2×終端桁−1。
4. 混在・上書き・スクロール: 区間終端規則で組み直す（行の途中の上書きも）。スクロールで組は行と一緒に動く。20区間以上は 20組目が (0x80, 最後の値)。
5. COLOR 以外の属性変更文は読んだ頁に無い（測っていない）。
