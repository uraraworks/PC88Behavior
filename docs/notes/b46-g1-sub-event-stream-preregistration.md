# B46: スペース後の G1 で、RAM 上のコードの読み書きが最初に違う所を値なしで測る — 事前登録

記録日: 2026-11-01
位置づけ: [B45](b45-g1-sub-out-stream-results.md) の次段。**このノートは測定より先にコミットする。**

## 1. 問い

サブの発行元 `0x2000` 以上のコードについて、メモリの読み・書きと `OUT` を起きた順に並べたとき、公式と自作で最初に違うのはどこか。

## 2. 器具

コアに `--sub-event-log FILE` を足す（パッチ 0024）。既定は無効で、無効なら動作を変えない。発行元 `0x2000` 以上のコードの次の出来事を、種類・発行元 `PC`・番地またはポート・値の順で作業場の生のファイルへ書く。あわせて、その時点の main の `IN $FC` の回数を持つ。**生のファイルは開かず、コミットせず、ライブラリへ置かない。**

- `R`: メモリの読み（命令の取得を除く）
- `W`: メモリの書き
- `O`: `OUT`

待ちの回数で列がずれないよう、`IN` は列に入れない。比較ツールは 2 つの生のファイルを読み、次の行だけを出す。**値は出さない。** 出す番地は RAM 上のコードの `PC` と、読み書きの番地だけである。

- `# 識別子: G1`
- `count <左> <右>`
- `first-diff none`、または `first-diff <番号> <違う欄をカンマで> <左の種類> <右の種類> <左の PC> <右の PC> <左の番地> <右の番地> <左の fc> <右の fc>`（欄は `kind`・`pc`・`addr`・`value`）
- `before <番号> <種類> <PC> <番地>`（最初の違いの直前の 16 件）

器具は G1 なしで自己検査する。陽性対照は読み・書き・OUT のそれぞれの値の違いと、番地の違いの検出。陰性対照は同じ列で `none`、ROM 側の発行元を数えないこと、命令の取得を数えないこと、`IN` の回数で列が変わらないこと、値が出力へ出ないこと、無効時の動作が変わらないこと。

## 3. 条件

腕 F の 4800 フレーム。OO・SS 各 2 走。自作 ROM は 62254d3 と同じソースの配布ビルド。クラウドの実行環境で行う。

関門: `IN $FC` の差が B44 と同じ（257 件、最初 76570、連続 132）。OO どうし・SS どうしの比較が `first-diff none` で、`count` が同じ。

## 4. 記録の白リスト

第 2 節の行だけ。

## 5. 判定（事前に決める）

- `first-diff` の行をそのまま書き、fc を 76570 と並べる
- 違う欄が `value` だけで読みなら、読む番地を B38 の違いの区間と比べる。書きか `OUT` なら、その前の読みが同じなので計算の入力を次に測る
- 違いがあっても原因は断定しない
