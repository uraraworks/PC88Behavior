# m7ja: セクタ数の違う自作ディスクで、run長が追随するかを測る — 結果

実施日: 2026-09-08

## 位置づけ

[m7iz](m7iz-selfmade-disk-runlength-preregistration.md)が事前登録した測定の
結果である。事前登録は測定開始前に単独コミット（`7ac644a`）してあり、本稿では
候補・窓・指標・判定規則を後から動かしていない。`src/`・`tools/`は本稿では
変更していない。

**結論を先に書く: 主判定はY2（9のまま）である。**

**1トラック8セクタの自作ディスクが、run長`9`を出した。** ディスクの
セクタ数（8）とrun長（9）が一致しない。**run長はディスクのセクタ数に
追随しない。**

**さらに大きいのは副産物のほうである——自作8セクタのディスクは、
`disk#10`と数値が完全に一致した。** すなわち**この現象の土俵が、
公式ディスクなしで作れるようになった。**

|---|---|---:|---:|---:|---:|---:|---:|---|

| **B3** | `disk#10`（公式・参照） | （不明。読まない） | **144** | **108** | **108** | **12** | **1** | **`{9:12}`** |

**エラーの内訳（公開ビットの復号名のみ）:**

| | 内訳 |
|---|---|
| B1 | `READ DATA ×108`: `IC=異常終了 / B/head1 / MISSING ADDRESS MARK` |

## 判定

- **Y1（追随する）**: B1でrun長8、B2でrun長16が現れること → **不成立**
  （B1は`9`、B2は長さ2以上のrunが無い）。
- **Y1a（部分的に追随）**: → **不成立**（8も16も現れない）。
- **Y2（9のまま）**: B1・B2の少なくとも一方でrun長9が現れ、8も16も現れない →
  **成立。主判定はY2である。**
- Y3・Y4は不成立（B1でエラーが出て長さ9のrunが現れているため）。

## 記述（判定ではない）: 自作ディスクが`disk#10`と完全に一致した

**B1とB3は、測ったすべての指標で一致した。**

- FDCコマンド総数 **144**
- READ DATA総数 **108**（うちエラー真 **108**）
- SEEK **12**
- 相異なるシリンダ数 **1**
- run長の多重集合 **`{9:12}`**

**違うのはエラーの種類だけ**である——B1は`MISSING ADDRESS MARK`、
B3は`NO DATA`。

**言えること:**

- **run長`9`は、ディスクのトラックあたりセクタ数ではない。**
  8セクタのディスクでも9になる。
- **原因の違う2種類のエラー（`MISSING ADDRESS MARK`と`NO DATA`）が、
  同一のFDCコマンド構造を生む。** 読めない理由が違っても、公式ROMの反応は
  同じ形になる。
- **`disk#10`の現象は、公式ディスクなしで再現できる。**
  `tools/make_l3_testdisk.py`が生成する自作D88（公開規則から生成。公式媒体を
  入力していない）で、指標が完全一致する土俵が手に入った。
- **読める自作ディスク（B2）は、公式の読める候補（`m7iy`の`#1`〜`#9`）と
  同じ振る舞いをする**——READ 5件・エラー0件・連続構造なし。

**言えないこと:**

- **「9は内部固定カウンタである」とは断定しない。** 言えるのは
  「自作ディスクのセクタ数を8にしても9のまま」までである。`m7hb`のH2を
  支持する向きだが、**セクタ数以外のディスクの性質（トラック数・形・
  IDフィールドの並び）が効く可能性を排除していない。**
- **公式ディスクのセクタ数は測っていない**（イメージを読まないため）。
  したがって「公式でも9≠セクタ数」とは言っていない。
- B1は8シリンダしかない小さな自作ディスクで、公式と形が違う。
  **形の違いが結果に効く可能性を排除していない**（事前登録に明記した限界）。
- B2でエラーが出なかったのは、**ブランクディスクが正しく読めるから**であって、
  16セクタだからではない。**B2は「16でrun長16が出るか」を試せていない**
  ——土俵が成立していない条件である。
- エラーの種類が違っても構造が同じ、という観察は2種類しか見ていない。

## これが「9」の追跡に対して持つ意味

`m7hb`が区別できないまま残した2説のうち、

- **H1派生（1トラック分＝トラックあたりセクタ数）**: **弱まった。**
  8セクタのディスクで9が出た以上、「run長＝そのディスクのセクタ数」ではない。
- **H2（内部固定カウンタ）**: **相対的に強まった**が、**確定していない。**

**そして追跡の土俵が公式ディスクから自作ディスクへ移った。** これは大きい——
**`disk#10`という1本に縛られず、自作ディスクの性質を振って測れる。**
セクタ数以外（トラック数、IDフィールドの構成、エラーの種類、読めない範囲の
広さ）を振る道が開いた。

## 次に何を測れば絞れるか

1. **自作ディスクのセクタ数を振る。** `make_l3_testdisk.py`の
   `SECTORS_PER_TRACK`は定数なので、**これを引数化すれば**8以外
   （4・16・26など）で測れる。**run長が9のままなら、H2はかなり固くなる。**
   `tools/`の変更で済み、`src/`は触らない。
2. **読めない範囲の広さを振る。** 現在は全トラックが読めない状態だが、
   **1トラックだけ読めない**ディスクを作れば、12周期が何に対応するかが見える
   （`m7ik`は「12周期＝要求12本」と確定しているので、要求の数が変わるはず）。
3. **エラーの種類をもう1〜2種類増やす**（`CRC ERROR`等）。同一構造になるなら、
   「読めなければ形は同じ」がより強く言える。

**1がいちばん直接的で、費用も小さい。**

## 開示

- **本稿の土俵は既存の`unreadable_disk`シナリオ**（`tools/conform_l3.sh`）と
  同じ組み立てである。`m7il`が「ディスク側に土俵が無い」と書いたが、
  **実際には既存のシナリオが土俵そのものだった。** 見落としていたことを記録する。
- 集計スクリプトは事前登録の取り決めどおり、例外を型名だけ記録し標準エラーを
  結果ファイルへ混ぜない形で書いた（`m7iw`のトレースバック混入の再発防止）。
- 公式ディスクは`tools/stage_disk_by_digest.sh`経由でのみ扱い、**実ファイル名を
  扱う経路を作っていない。** 自作ディスクは公開規則から生成したもので、
  公式媒体を入力していない。
- 実行した条件数（3）を出力に載せ、期待値と一致することを確認した。
- 本稿は委譲を行っていない。測定・解釈・判定はすべて親セッションで行った。
- 手順逸脱・事故は無い。無言でSKIPした分岐は無い。

## 情報境界

公式ROM・公式ディスクのバイト列、公式ROMの逆アセンブル、`private/`の内容は
読んでいない・出力していない。**公式ディスクのイメージを直接読んでもいない。**
**自作ディスクの構造（セクタ数・シリンダ数）は読んだ**が、これは`tools/`が
公開規則から生成したもので公式媒体を入力していない。記録したのは公開μPD765
コマンド種別名、件数、run長とその多重集合、**結果ステータスの公開ビット復号名**
（`IC=異常終了`・`MISSING ADDRESS MARK`・`NO DATA`・`エラービットなし`と
unit/head）、エラー真偽の集計、SEEK件数、**相異なるシリンダの個数（基数のみ）**、
自作ディスクのSHA-256、rc、公式ディスクの通し番号・ダイジェストだけである。
結果ステータスの**生の値**、FDCデータポート値列、シリンダ値、PCN値、
受信run・応答runのバイト値、画面本文、公式ディスクの実ファイル名は表示も転記も
していない。**件数や基数から公式ディスクの値を逆算していない。** 資料は参照して
いない。生ログ・ディスク複製・自作ディスク・使い捨てスクリプトはリポジトリ外
（scratchpad配下）に置き、コミットしない。
