# B19: `0x0D` で移ったときの割り込みの状態を、自作のコードで測る — 結果

記録日: 2026-10-31
規則: [b19-sub-entry-state-preregistration.md](b19-sub-entry-state-preregistration.md)（785089a）どおり。測定はクラウドの実行環境で 5 行×2 走、走どうしは全行一致。公式のものは `DISK.ROM` だけを使った。記録: `measurements/b19-sub-entry-*`。

## 手順についての開示

クラウドの判定器は `controls: false` を返した。判定器が事前登録に無い条件（全行で時間切れなし）を対照に足していたためで、行3 は読み要求の受け取りの上限まで読むので時間切れが正常である。B17 と同じ型の誤りである。判定器を事前登録に合わせ、**走り直さず同じ TSV へ**掛け直した。

## 判定

対照: 行4（`EI` のあと調べる）で `7810` が書かれた。2 走が全行で一致した。通過。

| 行 | 狙い | 結果 |
|---|---|---|
| 1 | `0x0D` で移った直後 | **禁止**（`7811`） |
| 2 | `00C1` へ戻り、2 回目の `0x0D` | **禁止**（`7821`） |
| 3 | 読み要求のあとの `0x0D` | **禁止**（`7821`） |
| 5 | コードが `EI` して `00C1` へ戻り、2 回目の `0x0D` | **許可のまま**（`7820`） |

全行で記録 A の割り込みは 0 回。

## 分かったこと

- 公式サブは割り込みを禁止したまま `0x0D` で移る
- `00C1` へ戻っても許可の状態を変えない。`EI` したコードから戻ると許可のまま次の `0x0D` へ進む

仕様は `docs/spec/l3-subrom.md` 1.36c 節（第225版）。
