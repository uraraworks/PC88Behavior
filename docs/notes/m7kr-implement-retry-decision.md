# m7kr: 「9」を規則が未確定のまま実装する — 決定と、その条件

作成日: 2026-09-09

## これは測定ではない。方針の記録である

[m7kq](m7kq-other-ports-results.md)で、**`m7hb`から続いた「9」の追跡が
一区切り**になった。**規則は書けず、「9が依存しないもの」が10軸ぶん
列挙できた**状態である（1.58節）。

**自作サブROMは、読めない対象を1回で諦める**（`m7ju`・`m7kg`）。
公式は**1つの要求の内側で`READ DATA`を9件**発行する（1.58節）。
**この差をどうするかは測定で決まらないので、方針として決める。**

## 決定

> **規則が未確定のまま、1.58節が記述する構造に合わせて実装する。**
> **そのことを、コード・ノート・コミットメッセージに明示して残す。**
> **後で規則が分かったら、そのとき更新する。**

**採らなかった選択肢と理由:**

- **規則が書けるまで実装しない**——きれいだが、**10軸潰しても規則が出て
  いない**ので、いつ書けるようになるかの見通しが無い。適合の穴が無期限に
  残る。
- **別の土俵へ移る**——測定の運動量は保てるが、「9」は宙に浮いたままになる。

**この決定のいちばん危ないところは、「定数を写す」ことと見分けがつかなく
なることである。** だから下の3つを守る。

## 守ること（この決定に付ける条件）

1. **根拠は`docs/spec/l3-subrom.md` 1.58節だけとする。**
   **実装する者（人間でもエージェントでも）は、公式ROMも測定ログも
   参照しない。** `CLAUDE.md`の情報の流れのとおり、**仕様書から右側だけを
   見る。**
2. **「規則は未確定である」ことをコードのコメントに書く。**
   1.58節の**「9が依存しないもの」10軸の一覧を根拠として指し示す。**
   **数字だけを置いて済ませない。**
3. **更新の条件を先に書く**（下記）。**「後で直す」を口約束にしない。**

## 何を実装するか（1.58節から読める範囲）

1.58節が記述しているのは次の2つである。

- **読めない媒体**: 1つの送信単位の内側で
  `SEEK → SENSE INTERRUPT STATUS → SENSE DRIVE STATUS → READ DATA ×9`
- **読める媒体**: `READ DATA`は1件（`m7ji`の読める側・`m7jo`の陰性対照）

**この2つに同時に合う最小の形は、「読んで、失敗したら再試行し、
最大9件で打ち切る。成功したらそこで止める」である。**

**これは規則の証明ではない。** 観測された2点に同時に合う最小の形を選んだ、
というだけである。**「失敗したら再試行する」という因果も測っていない**
（`m7ki`が示したのは「9件の結果はすべて同じ」までで、
**再試行かどうかは`m7jk`の「9件は同じ対象への要求」から推測している**）。
**この推測をコメントに明示する。**

## 事前に決める合格条件（実装前に固定する）

1. **ビルドが通ること。** 判定は**生成器自身の関門**（`build()`の検査）に
   任せる。**容量などの数値条件を自分で発明しない**——過去にそれで
   2回、有効な介入を誤って止めている。
2. **`tools/run_all_selftests.sh`が通ること。**
3. **既存の適合テスト（`tools/conform_l3.sh`）の結果が、実装前より
   悪くならないこと。** 実行前の結果を先に採り、突き合わせる。
4. **読めない媒体で、1つの送信単位の内側が`READ DATA ×9`になること**
   （混成条件・D3のディスク）。
5. **読める媒体で`READ DATA`が1件のままであること**（回帰させない）。
6. **`src/`以外を変更しないこと**（`tools/`・`docs/`は別コミット）。
7. **`tools/check_cleanroom.sh`が全項目OK。**

**4が満たせなくても、3と5が守られていれば「途中まで」として記録する。**
**当たるまで数字をいじらない。**

## 更新の条件（口約束にしないために先に書く）

**次のいずれかが起きたら、この実装とコメントを更新する。**

- **「9」を決めている規則が測定から書けたとき**——そのとき
  **1.58節を規則の記述へ書き換え、実装をそれに合わせる。**
- **1.58節の「9が依存しないもの」の一覧に、`9`を動かす軸が見つかったとき**
  ——**実装が観測に合わなくなるので、そのとき作り直す。**
- **公式の振る舞いが本稿の記述と食い違う条件が見つかったとき**——
  **条件を限定するか、実装を分ける。**

**更新するまでの間、この実装は「観測に合わせただけ」であり、
仕様として確定していない。** 1.58節にもその旨を書き足す。
