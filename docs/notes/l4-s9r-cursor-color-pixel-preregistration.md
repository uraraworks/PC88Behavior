# l4-s9r — CRTC カーソル位置コマンド 0x80/0x81 の使い分けと、COLOR の値が描画に与える色: 事前登録

状態: **測定前**（2026-10-08）。この段の腕は公式ROMで未実行。`src/` は変更しない。候補・予測・関門の変更には追補の事前登録を要する。
公式の保存観測（`tests/conformance/` の期待値・`../tmp` の生ログ）と、l4-s9o/p の結果ノート本体の個別数値は、予測を書くためには使っていない
（使った既存知識は `docs/spec/` の記述 l4-program 5.4・5.6.5、l1-ipl 第5d節と CRTC の節、l3-main 第3・4・11・12節、`docs/notes/refs-vraminfo.md`〔採用済み資料の要約〕）。

## 目的

1. **0x80 と 0x81 の使い分け**（l4-program 5.6.5 の「コマンド番号の食い違い」の原因）。
2. **COLOR n が描画に与える色**（属性域の値 → 実際の画素）と、COLOR の第2〜4引数が画面の色を変えるか。

## 読んだ資料（(a) 種別・ハードウェアの事実のみ）

- 新たに開いた資料は無い。CRTC μPD3301 のコマンド書式は l1-ipl.md の CRTC の節（`docs/notes/refs-vraminfo.md` が出典、判定「採用」）に既に記録されている:
  **LOAD CURSOR POSITION = `1000 000 CM`、CM=1 でカーソル表示・CM=0 で非表示、直後に `50` へ X, Y**。すなわち 0x81=表示つき、0x80=表示なしの位置設定。
  ここから、s9o（0x81）と s9p（0x80）の食い違いは**測定の場面の違い（カーソルが出る状態か、出ない状態か）**で説明できるという仮説（H0）を立てる。
- 属性ビットの定義（ハードウェア資料）: refs-vraminfo の出典ページ（Web）を取りに行ったが証明書の不一致で取得できなかった（取得の迂回はしない）。
  従って**ハードウェア側の属性ビット定義は今回読んでいない**。使うのは N88-BASIC マニュアルの COLOR 文（PDF 111・112、s9p で読み済み）の言語仕様だけ:
  白黒モードのファンクションコード 0〜7 は、bit0=シークレット・bit1=ブリンク・bit2=リバース の組合せ（1 シークレット・2 ブリンク・3 シークレット・4 リバース・5 リバースシークレット・6 リバースブリンク・7 全部）。
  カラーモードの 0〜7 は色（黒・青・赤・紫・緑・水色・黄色・白）。色番号とビットの対応は B=1・R=2・G=4 と読めるが、これはマニュアルの並びからの読みで、画素で確かめる。
- GW-BASIC の公開ソース・ROM 内部の解析記事は開いていない。

## 測り方（画面本文を扱わない）

新器具 `tools/l4_crtcpix_measure.py`（s9p の型。`tools/l4_colorattr_measure.py` の走り方・窓・io-log・自己検査を踏襲）。打ち込むのは自作のプログラムだけ。
採るのは次の数値だけで、公式が出した文字・画面本文は一切採らない。

- **カーソルコマンド**: 窓の終わり（採取の直前60フレーム〜採取後）の、CRTC コマンド 0x80/0x81 の件数と、最後のコマンドのパラメータ2つ。制御ポートの値で禁止事項5のデータポートに当たらない（s9o/p と同じ判断）。
- **画素**: ハーネス `--screenshot`（640×400 PPM、採取走の最後に1枚）から、**数セル分の矩形（8×20 画素）の画素値の頻度**（RGB 16進と個数の上位4色）だけを数値で記録する。
  対象は、自作が印字した記号 `MMM` のセル、公式の画面に触れない空白の参照セル、カーソル位置のセルとその参照セル（同じ行の20桁離れた空白セル）。
  画面全体の色ヒストグラム（RGB と個数の上位6色、位置情報なし）も採る。画像そのものはコミットせず、器具が採取後に消す（作業置き場は PC88/tmp 下でリポジトリ外）。
  描画は QUASI88 の実装が作った画素で、「エミュで測った値はエミュの実装を測っている」ので、**定性的な対応（見える／見えない、どの色名の帯域か、反転か）だけを結論にする**。RGB の数値は参考として記録する。
- **制御ポートの値**: 窓内のメイン OUT のうち 0x30・0x32・0x52・0x53・0x54〜0x5B の、値の初出順（重複除く）と最後の値（s9q と同じ区分）。
- **属性域**: 自作のみが書かれる行（行10）の属性域の組（s9p と同じ読み方）。px・bg 腕だけ（vram 写しを採る）。

## 腕（各腕2走。カーソル状態の腕は `-b` で採取を19フレーム遅らせた位相違いを足す）

**st（カーソルの状態、80桁）** — 直前に `new`・`cls`（idle は起動直後のまま）。
- `st-idle` 起動直後の入力待ち／`st-typing` `print 12` を改行なしで打鍵中
- 直接モード実行の直後: `st-width40`（`width 40` ）・`st-width80`（`width 80`）・`st-locate`（`locate 10,5`）・`st-cls`（`cls`）・`st-err`（`a=*3` で構文エラー）・`st-progend`（`10 print 1` を run して終了）
- 実行中: `st-goto`（`10 goto 10`）・`st-for`（`10 for i=1 to 30000:for j=1 to 30000:next:next`）・`st-input`（`10 input a$`）・`st-inkey`（`10 a$=inkey$:goto 10`）・`st-inputtyped`（input 待ちで `ab` を改行なしで打鍵）
- 位相違い: `st-idle-b`・`st-input-b`・`st-goto-b`（採取を+19フレーム）

**px（COLOR の画素、80桁）** — `10 [console ,,,1]`／`20 locate 10,10:color n:print "MMM";`／`30 goto 30`。`px0-n`（白黒＝起動既定）・`px1-n`（`console ,,,1`＝カラー）、n=0〜7 の16腕。

**bg（第2〜4引数）** — `20 <文>`／`30 locate 10,10:print "MMM";`／`40 goto 40`。`bg-base`（`rem`）・`bg-b`（`color ,b`、b=0〜7）・`fg-f`（`color ,,,f`、f=0〜7）。17腕。

## 関門

2走とも採取成功（PPM・必要なら vram 写し・io-log）、2走の観測が完全一致。
- **画素の較正**: `bg-base` と `px0-n0` で、`MMM` のセル（桁11、行10）が2色以上（字形が見える）、空白参照セル（桁30、行10）が1色。かつ `MMM` の位置が vram 写しで（行10、桁10、間隔1）。これが崩れたら px・bg の全腕を関門落ち。
- **カーソルの較正**: st の全腕で 0x80/0x81 が窓の終わりに1件以上。`st-idle` の最後のコマンドが採れていること。
- 関門が落ちたら、**器具を曲げず追補の事前登録を先にコミット**してから再測定する。
- 自作ROMでの対照（selftest）: 合成のPPM・合成のio-logで解析と判定の陽性・陰性、自作ROMで `st-goto`・`bg-base`・`px0-n0` が走ること、故障注入（PPM のセルを書き換えると判定が変わる）。
