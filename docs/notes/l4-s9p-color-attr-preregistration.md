## 目的

l4-program 5.6.2・5.6.5・第8節23項の未確定を測る。

1. **40桁時の CRTC カーソル位置パラメータ**（桁そのものか 2×桁か、行は何か）。
2. **COLOR の引数**: 受理範囲・誤りの種類・省略形、属性域へ書かれる値。
3. **1行内に複数の色が混ざるとき**の属性域の組（s9o で決まった区間終端規則の検証、20組超、行の途中への上書き、スクロール）。
4. COLOR 以外の属性変更が BASIC から可能か。

## 読んだ資料（(a) 種別・言語仕様のみ）

- `refs/NEC PC-8801mkIIMR N88-BASIC N88-日本語BASIC REFERENCE MANUAL 1986年.pdf`（判定「可」、refs-nec-manuals-2026-09-04.md）。
  ページ画像（`pdftoppm -r 40〜80`）で読んだ PDF ページ: 9・11・14・15（目次・コマンド索引）、100（章内のページ番号の較正に1枚。CHR$ の頁）、**111・112**（印字 2-29・2-30、COLOR 文）。
  目次から COLOR の頁を引いただけで、他の節には入っていない。COLOR 2-31（`COLOR=`）・2-33（`COLOR@`）はパレット系で、読んでいない（今回の対象外）。
- 読んで分かった言語仕様（表現は写さず事実だけ）: 書式は `COLOR [ファンクションコード][,バックグラウンドカラー][,ボーダカラー][,フォアグラウンドカラー]`。
  ファンクションコードは**白黒モード（CONSOLE ,,,0）で 0〜7 の8通り**（0 ノーマル・1 シークレット・2 ブリンク・3 シークレット・4 リバース・5 リバースシークレット・6 リバースブリンク・7 リバースブリンクシークレット）、
  カラーモード（CONSOLE ,,,1）では 0〜7 が色（黒・青・赤・紫・緑・水色・黄色・白）。第2〜4引数はグラフィック画面側の指定でテキスト属性ではない。
  **範囲外の値の扱いと誤りの種類はこの頁に書かれていない**（測定で決める）。
- **COLOR 以外にテキスト属性を変える文は、読んだ頁（COLOR・目次）には無い**（4 の答え。ATTR$ は読み出し側の関数と索引で見えたが、頁は開いていない）。
  従って 4 は測らない。CONSOLE ,,,1 によるモード切替は属性値の意味を変えるが今回の対象外（決めないこと）。
- ハードウェア資料（属性ビット・CRTC コマンド）は**今回は開いていない**。GW-BASIC の公開ソースも開いていない（予測は既存仕様・上のマニュアル・一般的な記憶による）。

## 測り方（画面本文を扱わない）

作法は l4-s9o と同じ（`tools/l4_widthvram_measure.py` の型。新器具 `tools/l4_colorattr_measure.py`）。プログラムを打ち込み、`cls` のあと `run`、写し（F3C8〜、3000バイト）と I/O ログを採る。
**アンカー**: 全腕の先頭で `qa1`（桁0行6）・`qb2`（桁0行7）・`qc3`（桁10行8）を印字し、行ストライド S と桁の間隔 k を回復する（s9o と同じ線形の関門）。
採るのは (1) 自作の印と、自作の印しか書かれない行（行13・14、val 腕は行9〜16、mix 腕は行13/14）の属性域40バイトの生値（0x00 と 0x20 を区別）、
(2) 誤り腕では**画面本文を採らず**、非空白行の（行番号・非空白文字数・SHA-256 先頭12桁）の署名だけ。既知の誤りを起こす参照腕（下記）の署名と一致するかを見る（`tools/check_l3_screen_output.py` と同じ署名化の考え方で、本文は出力しない）、
(3) CRTC カーソルコマンド（0x80・0x81）に続く2パラメータの列（連続同一は件数に畳む）。**制御ポートの値で、禁止事項5のデータポートに当たらない**（s9o と同じ判断。理由は l4-s9o-width-vram-preregistration.md）。
プログラムは最後に `goto` の自己ループで止め、プロンプトが出ないようにして写しを取る。`run` の前に `cls`。生ログ・写しは作業置き場の一時ファイルで、採取後に器具が消す。

## 腕

**cur（カーソル位置、10腕）** — `locate c,r` の後に自己ループ。cur-80（起動の80桁）: (c,r)=(0,0)(1,3)(10,7)(39,12)(79,15)。cur-40（先頭行 `width 40`）: (0,0)(1,3)(10,7)(20,9)(39,12)。
採るのは窓の最後のカーソルコマンドの2パラメータ（と最後の3項目）。

**val（1腕）** — 行 9+n に `color n:print "zzz";`（n=0〜7、80桁）。行ごとの属性域。

**stmt（`20 <文>`、続けて行13に `qi9`、行14に `qz9` を印字）** — 続行したか（qi9 が写しにあるか）、行13・14の属性域、誤りの署名。
- 参照: `rem`（基準）、誤り参照 `fc`＝`a$=chr$(300)`、`sn`＝`a=*3`、`ul`＝`goto 999`、`tm`＝`a$=1`、`ov`＝`a%=40000`（各誤りの署名を採る。`rem` との差が誤りの行）。
- 範囲: `color 8`、`color 255`、`color 256`、`color -1`、`color 2.5`、`color ,8`、`color "a"`。
- 形: `color ,3`、`color 2,3`、`color ,,,5`、`color`（引数なし）、`color 5,1,1,2,3`（引数5個）、`color 3,0,0,6`、`color 3:color 5`。

**mix（80桁・40桁、各5腕）** — 行13（m5 は行14）に印字。
- m1: `color 2:"zzz";:color 4:"zzz";`
- m2: `for i=1 to 24:color 2+(i and 1):print "z";:next`（1文字ごとに色替え、24区間）
- m3: m1 の最後に `color 6:"zzz"` を足した行13を作り、後で `locate 3,13:color 5:print "yy";` で行の途中を上書き
- m4: `color 2:"zzz";:color 0:"zzz";:color 4:"zzz";`
- m5: 行14に `color 2:print "qs1";:color 4:print "qs2";:color 0` の後、`locate 0,15` から `print` を6回（スクロールを起こす）。`qs1` の写し内の行を採り、その行の属性域を読む。

各腕2走。腕数: cur 10＋val 1＋stmt 参照6・範囲7・形7＝20＋mix 10＝41腕。

## 予測（外れてよい。外れは規則を数値で書く）

| 量 | 予測 | 強さ |
|---|---|---|
| cur-80 の2パラメータ | (c, r) | 強（s9o で「（桁,行）と一致」） |
| cur-40 の2パラメータ | (2×c, r)。候補は (c, r) | **弱**（属性域の位置が 2×桁−1 と倍の単位で書かれることからの類推。桁0のとき 0 か） |
| val の n=1〜7 | 行 9+n の属性域は (3, n) の1組＋残りは (0x80, 0x00) | 中（l3-main 第12節・l4-program 5.4・5.6.2） |

| `color 3,0,0,6` | 続行。(3,3) | 中 |
| `color 3:color 5` | (3,5) | 中 |

誤りの「署名」の予測が当たるのは、参照腕の署名と一致したときだけ。どの参照とも一致しない誤りは `none` として署名の差を記録する（本文は書かない）。
陰性対照: 参照どうし（`fc`・`sn`・`ul`・`tm`・`ov`）の署名が互いに異なること。異なれば署名が誤りの種類を区別できる。

## 関門

2走とも採取成功、アンカー3つが一意で線形、2走の観測が完全一致（走ごとの差が出たら腕は関門落ち）、cur 腕は窓にカーソルコマンドが1つ以上、
mix・val・stmt（続行した腕）は属性域の生値が採れていること。
較正の関門: `stmt-rem`（基準）が続行で行13・14の属性域がともに全て (0x80,0x00)、かつ S=120・k=1（起動の80桁）。崩れたら全腕を関門落ち。参照腕どうしの署名が互いに異なることも必要。
自作ROMでの既知値対照（selftest）: `stmt-rem` と `cur-80` の一部が自作ROMで通ること（自作に WIDTH・COLOR の一部が既にあることを使う）。
関門が落ちたら、器具を曲げず追補の事前登録を先にコミットしてから再測定する。
