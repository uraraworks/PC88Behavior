# l4-s9w 追補3 — ws-4/4b の待ち時間の不足と、大きなスタックの腕の追加（事前登録の追補）

状態: 2026-10-09。追補2の公式の走り（`official_add2.tsv`、9腕×2走）の観測を読んだあとに書く。

## 何が起きたか

- `ws-6a`〜`ws-6e`（`clear ,,16`・`64`・`128`・`256`・`64`）と較正（`cal-vis` 110 画素・`base-cls3`）は関門を通った。**どの腕も誤りなし**で、歯 20・40・80 本の櫛も、点線格子も蛇行路も、スタックを 16 バイトにしても完全に塗られた（最終画面のハッシュは既定のスタックの腕 `ws-1`・`ws-3` の対応する画素と同じ配置）。`CLEAR` のスタックの大きさは PAINT の作業領域の不足に効いていない、または効く量にまだ届いていない。
- `ws-4`・`ws-4b`（画面幅の点線格子）は**関門が落ちた**: 2 走一致だが終了の印がない（`sent=0`）。プログラムが終わる前に写しを取った。小・中の格子の2つは誤りなしで塗り終わり、大（639×99）の塗りが待ち時間（30000+3000 フレーム）に収まらなかった。**原因は器具の待ち時間の不足**で、PAINT の挙動ではない。

## 直し・足すもの

1. `ws-4`・`ws-4b` の待ちを 30000 → 150000 フレームにする（打ち込むプログラムは変えない）。
2. 大きなスタックで作業領域が足りなくなるかを見る腕を足す: 小・中の点線格子（`ws-4` と同じ2つ）と歯 80 本の櫛を置き、`clear ,,32000`（`ws-7a`）と `clear ,,60000`（`ws-7b`）。`clear` 自体が誤りでも走りが止まらないよう先頭に `on error goto 900`（追補2と同じ `guard`）。待ち 30000。
3. 予測（弱 w。表にない量は予測なし）: `ws-4`（大の格子・既定）・`ws-4b`（4096）は誤りなし（追補2の予測のうち ERR 7 は外れる見込みだが、大が走り終わるまで確定していないので、追補2の予測の表のとおり判定に載せる）。`ws-7a` は3つとも誤りなし、`ws-7b` は3つとも ERR 7。ERR 7 のあとに塗られた画素は予測なし。

結果は同じ期待値ファイルに載せる。ここまでで ERR 7 が出なければ、「この範囲の条件では作業領域の不足を起こせなかった」と結果ノートに書く（出せたことにしない）。
