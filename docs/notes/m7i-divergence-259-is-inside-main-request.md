# m7i: 分岐点259はmain→sub要求中のmainローカル制御分岐

測定日: 2026-08-13

## 1. 目的

main側の構造的一致プレフィックス258の次、259番目の構造要素を共通クロック上で
再構成し、単発1バイト応答、`RESP_ACTIVE`応答バッファ、main→sub要求、通信制御、
FDCのどの経路に属するかを分類した。m7hまでに単発1バイト応答の介入では259を
越えないことが確定しているため、直前ラウンドと分岐位置を同一視せず、259を含む
交換窓も調べた。実装コードは変更していない。

## 2. 情報境界と入力

`private/`配下の内容は開いていない。参照ROM・参照ディスクの環境変数は今回の
セッションでは未設定だったため、新しい公式実走は行わなかった。公式側は既存の
伏せ字済み共通クロックログ2走、混成側は現行実装の最終変更後に取得済みの伏せ字済み
ログ2走を再解析した。m7系列では実装変更が無いため、この2本は現行混成と同じ実装である。

公式ROM・公式ディスクのバイト列を読まず、表示せず、保存せず、逆アセンブルしていない。
解析キーはCPU、方向、ポート、PC、seq、clockだけで、value列は分類にも表示にも使って
いない。記録するのは経路、長さ、位置、同一／相違だけである。

## 3. 分類器selftestと再現性

既存`tools/diag_l3_mixed.sh`の検出力selftest a〜lを先に通した。完全一致を分岐なし、
途中1要素のポート変更をその位置の分岐として検出する項目を含む。さらに一時経路分類器で、
同一イベントの複製を同一署名、ポートだけを変えたイベントを相違署名と判定するselftestを
通した後に本解析へ進んだ。

公式2走は全構造列が一致した。混成2走も259前後、要求窓、分岐後を含め同一だった。
両側とも、259を挟む要求窓の長さと位置関係を2回再現した場合だけ採用した。

長さ1だけでは単発経路と応答バッファ経路を分類しなかった。公式側は送信サイト、混成側は
要求run長と`RESP_ACTIVE`を設定する現行実装の状態遷移を併用した。この条件により、後述の
ラウンド#3で最初に見える1バイトを単発経路へ誤分類していない。

## 4. 259の直接分類

259直前の5構造要素は両側で同じmainローカルI/O列だった。259番目は両側とも同じ
mainローカルのシステム制御／DIP読み出しポートだが、公式側は出力、混成側は入力であり、
同じ公式main ROMが別のPCへ進んだ最初の構造差である。直後も別々のmainローカルI/O列へ
進む。

したがって、**259番目のバスイベントそのもの**は、sub→mainの単発応答、
`RESP_ACTIVE`応答バッファ、main→subのデータバイト、`$FF`/`$FE`通信制御、FDCの
いずれでもない。main ROM内の制御フローが外部へ初めて表面化したローカル制御I/Oである。

## 5. 共通クロック上の交換窓の帰属

直前の単発応答ラウンド#2が完了した後、mainは次のラウンド#3の要求送信を開始している。
259はその要求の先頭と末尾の間にあり、公式2走・混成2走とも要求長は8バイトだった。
よって**交換窓としての259の帰属はmain→sub要求**であり、より正確には「後に
`RESP_ACTIVE`応答を要求する8バイト要求をmainが組み立てている途中のmainローカル
制御分岐」である。

この8バイト要求の完了後、公式側は応答バッファ送信サイトへ入り、混成側も現行仕様の
`run長==8`条件により`RESP_ACTIVE`を設定する。ラウンド境界上で最初に1バイトだけ見える
区間があっても、それは応答バッファの先頭であり単発応答ではない。しかし259はその送信より
前にあるため、**259を応答バッファの出力バイトとして分類することは時間順序に反する**。

## 6. ディスク由来かROM由来か

259までにmainが受け取ったデータは既存m7aが確定した3件の単発応答だけで、FDCセクタの
応答バッファはまだmainへ届いていない。最初のセクタ座標不一致も259より後である。m7hまでの
介入結果により単発1バイト応答経路は259の突破条件ではないことも確定済みである。

したがって、**259の直接原因を「公式ディスクから読み出した実データの転送」とする仮説は
棄却する。** 応答バッファ経路ではないため、公式応答バッファとセクタ内容の値非表示比較は
条件不成立として実施していない。後続の応答バッファがディスク由来かどうかは、259の原因
判定とは別問題である。

残る分類はROM側の内部制御である。ただし「ROM由来の特定バイト」を発見したという意味では
ない。同一main ROMが要求生成中に異なる内部状態から別コード経路へ進み、その差がローカル
制御I/Oとして現れた、という構造までである。分岐判断に使ったレジスタ／RAM状態はI/Oログに
現れず、クリーンルーム測定からは特定できない。m6xの「内部ワークエリアは測定では届かない」
という限界とは整合するが、m6xが当時結び付けた直前単発応答値の原因説はm6z〜m7hで反証済み
であり、復活させない。

## 7. 実装判断

ディスク読み出し／転送バグを示す証拠は得られなかったため、`FDC_READ_SECTOR`、
`SECTOR_BUF`、`RESP_PTR`、`RESP_ACTIVE`を259突破目的で変更してはならない。
また、main ROM内部の分岐条件を推測してサブROMの応答や要求解釈へ定数を足す根拠も無い。
今回確定した仕様上の注意点は、8バイト要求の途中にmainローカル分岐があり、その完了後に
応答バッファへ入るという順序と、応答長1だけでは経路分類できないことだけである。

## 8. 判定・限界・異常

判定は「259の直接イベント＝mainローカル制御」「所有交換窓＝main→sub要求」
「ディスク実データ由来ではない」「分岐入力はmain内部状態で未特定」である。

- 同一の公式ROM一式、同一コア、同一参照媒体、既存ログ2走ずつの再解析であり、別ROM版、
  別エミュレータ、実機を横断していない。
- 環境変数未設定のため新規実走は行えず、既存の伏せ字済みログを採用した。
- I/Oログではmain内部の分岐判断材料を観測できず、ROM内部値か実行時RAM状態かをさらに
  分解できない。
- 一時解析の最初の削除処理は包括的な再帰削除として安全フィルタに拒否され、測定開始前に
  停止した。個別`unlink`と空ディレクトリの`rmdir`へ変更して最初から実行した。採用結果への
  影響は無い。
- 採用解析でSIGABRT、timeout、その他の測定器異常は0件。過去の一過性SIGABRTの根本原因は
  未特定のままである。

## 9. ツール状態

経路分類器は一時ツールとして使用し、測定後に削除した。恒久ツール、実装コード、判定基準は
変更していない。
