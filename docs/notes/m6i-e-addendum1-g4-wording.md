# m6i-e 追補1 — 関門G4 の書き方の誤りを直す（測定前）

記録日: 2026-09-23  
状態: 測定前。**腕は1走も回していない。**

器具の実装中に、[事前登録](m6i-e-gate-harm-mechanism-preregistration.md) §3 の
関門G4 に**成り立たない要求**が2つ見つかった。測定前に直す。

## 1. 「互いにちょうど6バイトだけ相違」は成り立たない

事前登録 §3 は G4 に

> E0・E2・E3 の `DISK.ROM` は、互いにちょうど6バイトだけ相違し、
> その6バイトはすべて同一の連続領域（挿入位置）に収まる

と書いた。**前半は誤りである。** 挿入6バイトには共通部分があるためである。

| 組 | E0 `DB FE E6 08 28 FA` | E2 `DB FE 00 00 00 00` | E3 `00 00 00 00 00 00` | 相違 |
|---|---|---|---|---:|
| E0 対 E2 | | | | 4バイト（先頭 `DB FE` が共通） |
| E2 対 E3 | | | | 2バイト（後ろ4バイトが共通） |
| E0 対 E3 | | | | 6バイト |

**「ちょうど6」を要求すると、正しく作れた一式でも関門が落ちる。**

### 直し方

要求を、本当に言いたかったことへ置き換える。

- **3腕の `DISK.ROM` の相違は、挿入位置の連続6バイト領域の中にしか無い。**
  すなわち、3組（E0-E2、E0-E3、E2-E3）の相違位置の**和集合**が、
  ちょうど6バイトの連続領域になる。
- その領域の各腕の中身が、登録値と一致する。

こちらのほうが**強い主張である**。組ごとの相違数は挿入バイトの中身で決まる
自明な数だが、「領域の外が1バイトも違わない」は、**後続コードの配置が3腕で
完全に同じであること**を示す。本測定が要るのはそちらである。

登録値も本追補で確定させる（事前登録は `nn`・`ee` をビルドに委ねていた）。

| 腕 | 挿入6バイト |
|---|---|
| E0 | `DB FE E6 08 28 FA`（`IN A,($FE)` / `AND 08h` / `JR Z,-6`） |
| E1 | 挿入なし |
| E2 | `DB FE 00 00 00 00` |
| E3 | `00 00 00 00 00 00` |

## 2. 「E1 は6バイト短い」は固定長ROMでは成り立たない

事前登録 §3 は

> E1 の `DISK.ROM` は E3 のものと、挿入位置より前が一致し、長さが6バイト短い

と書いた。**`DISK.ROM` は 0x2000 バイトの固定長**であり、短くならない。
短いのは**コードの長さ**（2038 対 2044）であって、ROM は後ろが埋め草になる。

さらに、E1 と E3 は「挿入位置より前が一致する」とも限らない。
**挿入位置を跨ぐ相対分岐の変位が、再配置で変わる**ためである。

### 直し方

E1 と E3 の関係は、次のとおり検査する。

- `DISK.ROM` の長さは両者とも等しい（固定長）。
- 挿入位置より前の相違は**ちょうど1バイト**である
  （挿入位置を跨ぐ相対分岐の変位1個）。
- 挿入位置以降は、E1 の当該位置からと E3 の「当該位置＋6」からを突き合わせて、
  相違が**ちょうど1バイト**である（同じく再配置による変位1個）。

**E1 の役割は、もともと「既に測ってある成功腕」の再現である。** そちらは
G4 の別項目（`E1 の DISK.ROM が m6i-c の C2 のものとバイト一致する`）が
バイト単位で押さえており、こちらのほうが強い。上の1バイト検査は、E1 と E3 の
関係が意図どおり（挿入の有無だけ）であることの補助的な確認として置く。

## 3. 変わらないもの

- 腕の構成4種、main ROM を4腕でバイト一致させること、挿入位置をラウンド#0応答の
  直後に固定すること、到達指標、結果条件、関門 G1〜G3・G5〜G9、判定名5種、
  行き先、本文・値列を出さない規律は変更しない。
- **E2 と E3 の比較が `IN A,($FE)` 1回だけを振った比較である**という本測定の
  肝も変わらない。むしろ §1 の直しによって、その根拠（領域の外が1バイトも
  違わない）が明示的な関門項目になった。
