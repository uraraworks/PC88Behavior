# B81: `0x0E` のあとを新しい要求として受ける自作 ROM で、G1 の道を確かめる — 結果

記録日: 2026-11-04
規則: [b81-g1-0e-new-request-preregistration.md](b81-g1-0e-new-request-preregistration.md) どおり。測定はクラウドの実行環境で rc=0。記録は `measurements/b81-g1-0e-new-request.txt`。

## 結果

| 腕 | 画像 | テキスト | 移る回数 公式 / 自作 | `IN $FC` 公式 / 自作 |
|---|---|---|---|---|
| I1 | 違う | 同じ | 93 / 93 | 127799 / 127795 |
| I2 | 同じ | 同じ | 87 / 87 | 124725 / 124721 |
| I3 | 同じ | 同じ | 87 / 87 | 124725 / 124721 |

## 分かったこと

**F1 の腕は公式と同じに進むようになった。** 移る回数 74、画像とテキストも一致し、`IN $FC` の差は B48 の位相の 4 に戻った。ほかの 4 腕は B69 から変わらない（I1 の画像の違いは B64 の位相の差の可能性）。

B80 の追補に書いた見立て（バルクの読みのあとの `0x0E` を、自作は前の要求の続きとして扱っていた）は、この結果で裏付けられた。
