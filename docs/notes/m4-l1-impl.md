# M4 — L1 IPL の実装（実装セッションの記録）

作成日: 2026-08-07
作成: `docs/notes/m4-handoff-l1-impl.md` を受けた実装セッション

## 結果

`docs/spec/l1-ipl.md` 第6節の適合条件を満たした。

```
$ tools/verify_l1.sh
[2段階（初期化 350 件の完全一致 ／ 以降 7 件周期）] 一致
  ① 初期化区間 350 件が完全一致
  ② 定常状態の周期: 31<-19 / E4<-01 / 51<-81 / 50<-16 / 50<-01 / E4<-FF / 31<-19
     基準側 30 周 ／ 対象側 54 周
```

自作 IPL は BASIC の初期化を行わないぶん早く定常状態に入るので、
同じ 60 フレームで 54 周する（公式版は 30 周）。周回数は適合条件ではない。

### 目に入った公式版の番地（軽微・記録する）

比較器が不一致を報告するとき、基準側の前後 5 件を `pc=` 付きで表示する。
P0 段階の比較で公式版の `pc` が 4 件ほど画面に出た。

- **バイト列ではなく番地である。** 逆アセンブルもダンプもしていない。
- 仕様書 第0節が「`pc=` は実装の目標ではない」「自作 IPL がこの番地に
  何かを置く必要は無い」と明記しており、ゴール A では番地配置は自由。
  実際この実装の番地配置は公式版と何の関係も無い。
- **ゴール B（番地互換）に進むときは、この番地を見たセッションが
  番地配置を決めてはいけない。** その時点で担当を分けること。

比較器に「基準側の `pc` を伏せる」選択肢を足すと、この経路自体が消える。
仕様セッション側は `pc` を使うので既定は変えないほうがよい（宿題に載せた）。

## 作ったもの

| | |
|---|---|
| `src/l1_ipl/make_ipl_rom.py` | N88.ROM を組み立てる。外部依存ゼロ |
| `tools/verify_l1.sh` | 組み立て → 実行 → 適合判定を1本にしたもの。公式 ROM 不要 |
| `tools/cmp_io.py` の `--init` / `--cycle` | 第6節の 2 段階の適合条件を扱えるようにした |

### なぜ Python でバイト列を組むのか

この環境に Z80 アセンブラが無い。外部依存ゼロなら第三者が
`python3 make_ipl_rom.py <出力先>` だけで同じ ROM を再生成できる。
出自の主張が「信じてくれ」ではなく再現性で立つ。

### 構造にした箇所と、していない箇所

意味が読めている箇所はループ・サブルーチンにした
（パレット、USART 初期化、CRTC/DMA、拡張 ROM スキャン、キースキャン、VRTC 待ち）。

**意味が読めていない箇所は `out_range(lo, hi)` で付録A の範囲をそのまま並べた。**
どこを理解せずに置いたのかが、コードを読めば範囲で分かるようにしてある。

| 範囲 | 状態 |
|---|---|
| 付録A 79-82 | `32`/`71` の操作。前後の文脈が読めない |
| 付録A 108-173 | 4th ROM バンク切り替えに割り込み設定が挟まる区間。切り替えが何を呼んでいるか不明 |
| 付録A 189-314 | 7 件の組を 18 回。**18 回何をしているのか分からない** |
| 付録A 315-343 | 同上の断片＋CRTC カーソル設定 |

公式版はバンクを切り替えた先の 4th ROM 内ルーチンを呼んでいるはずだが、
自作 IPL には呼ぶ相手が居ない。**分かったふりをせず範囲参照のまま残した。**
L3 でサービスルーチンを実装するときに再訪すべき箇所である。

## 検査

### 二重の検査になっている

1. **組み立て時**: 生成器が「出す予定の OUT 列」を同時に記録し、
   `SPEC_INIT`（仕様書 付録A の転記）と一致しなければ ROM を書き出さない。
2. **実行時**: `q88measure --io-log` で走らせ、`tools/cmp_io.py` で比較する。

1 だけでは「そう出すつもりのコードを書いた」ことしか言えない。
**両者が独立であることを実測で確かめた**（下記の壊し方D）。

### わざと壊して落ちることを確かめた

検査を足したら壊して確かめてから信用する、という規律に従った。
`docs/notes/feedback` 系で繰り返し出ている「不自然に揃った数字は観測系の故障を疑う」
の実践でもある。

| 壊し方 | 期待 | 結果 |
|---|---|---|
| A. `cmp_io.py` の周期検査を素通りさせる | selftest 12・14 が NG | NG になった |
| B. 「1 周も回っていない」の判定を外す | selftest 14 が NG | NG になった |
| C. ① 初期化区間を比べないようにする | selftest 13 が NG | NG になった |
| D. 生成器の `GROUP_REPEAT` を 18→17 | 組み立て時検査が落ちる | 312 件目で落ちた |
| E. 生成器のパレット値 `37`→`36` | 組み立て時検査が落ちる | 9 件目で落ちた |
| F. 生成器の P2 を 2 回→1 回 | 組み立て時検査が落ちる | 46 件目で落ちた |
| **G. 記録は 8 スロットのまま、吐くコードだけ 7 スロットにする** | **組み立て時は通り、実行時が落ちる** | **組み立て時 OK ／ 実行時が 19 件目で捕捉** |

G が二重検査の意味そのものである。「出すつもり」と「実際に出たもの」は別物で、
1 だけを信じていたらこの細工は通っていた。

### 段階比較（第6節「実装の順序」）

`tools/verify_l1.sh --stages` が P0 → P2 → P3 → P4 → 全段階を順に走らせ、
**食い違いが後ろへ動くこと**を確認する。動かなければそこで止まる。

```
段階 P0   → 一致 22 件
段階 P2   → 一致 63 件
段階 P3   → 一致 107 件
段階 P4   → 一致 188 件
段階 full → 一致 560 件
```

途中段階は「基準側が長い（対象に足りない）」で不一致になるのが正常。

## 比較器を直した理由（物差しのほうが間違っていた）

最初に全段階を走らせたとき、既定モードは**不一致**を報告した。

```
不一致: 561 件目で食い違い
  種類: 対象側が長い（余分）
  基準側: 総 560 件 / 対象側: 総 728 件
  ここまで一致: 560 件
```

560 件まで完全に一致したうえでの「余分」である。自作側は 728 件
（初期化 350 + 7×54 周）で、公式版は 560 件（350 + 7×30 周）。
**周回数が違うだけで、仕様書 第6節はそれを明示的に「比較しないもの」に入れている。**

つまり実装ではなく物差しが条件に追いついていなかった。
仕様書 第6節が第1版の「全 560 件が一致すること」を第4版で撤回した経緯を
残しているのと同じ種類の誤りで、**その撤回が `cmp_io.py` に反映されていなかった**。

## 仕様書に足りなかったもの（仕様セッションへ戻す）

引き継ぎが「足りない箇所は実装が詰まるという形で露見する」ことを
狙いとしていたので、遠慮せず書く。**実装は完了しているので、どれも急ぎではない。**

### 1. 定常状態の周期が何で駆動されるのか書かれていない（一番大きい）

第3節は 20 イベントを列挙しているが、それが**なぜ 1 フレームに 1 回起きるのか**が無い。
列に `IN 40` が含まれないので割り込み駆動だと思われる
（P4 で `E6 ← 03` = RTMF + VRMF を許可している）が、
**推測で実装しない規律なので割り込みは組まなかった。**
代わりに VRTC（`IN 40` bit5）の立ち上がりを待つポーリングで 1 周させている。

その結果、**自作側の定常状態には仕様書に無い `IN 40` が混ざる。**
適合条件は OUT のみなので合否には影響しないが、構造は公式版と違う。

測れば決まるはず: 定常状態のイベントの `pc` が `0038h` 近傍に集まっていれば
IM 1 の割り込み駆動である。**仕様セッションは測定ログを見られるので、
第3節に「この周期は割り込みで駆動される／されない」を 1 行足してほしい。**

### 2. 「付録A で自己完結している」は正確ではない

引き継ぎの表は「見る: `docs/spec/l1-ipl.md`（付録A で自己完結している）」と書くが、
付録A は **OUT だけ**で IN を含まない（第6節「比較しないもの」に従った結果）。

`IN 40` の VRTC 待ちが OUT 列のどこに挟まるかは**第2節 P2 の散文からしか取れない**。
第2節は「読みやすさのために要約と省略を含む」と断り、「適合の基準は付録A」と
書いてあるので、実装者は付録A だけを見ればよいと読める。実際には両方要る。

提案: 付録A に IN を灰色で（または別列で）併記した版を足すか、
第2節の冒頭に「待ちの位置は第2節を見ること。付録A には IN が無い」と書く。

### 3. メモリマップの記述が無い

スタックポインタをどこに置くかを決める根拠が仕様書に無い。
`0xF000` にしたが、これは `tools/harness/make_test_rom.py` が `0xC000` を
RAM として使っていたことと、第5a節②のテキスト VRAM が `F3C8` にあることからの
消去法であって、**仕様書からは導けなかった**。

L1 は「起動時のハードウェア初期化」なので、
**どこが RAM でどこが ROM か**は本来この仕様書の守備範囲だと思う。
L3・L4 では必ず要る（ワークエリアの置き場が決まらない）。

### 4. リセット直後の CPU 状態の記述が無い

開始番地を `0x0000` と仮定した。Z80 の仕様上そうなるので実害は無かったが、
割り込みモード・`I` レジスタ・`SP` の初期値がどうなっているかは書かれていない。
1 と合わせて、割り込みを組むときに必要になる。

### 5. 比較器の出力に公式版の `pc` が出る

上の「汚染記録」のとおり。`tools/cmp_io.py` に `--no-base-pc` のような
選択肢を足すと、実装セッションが公式版の番地に触れる経路が消える。
仕様セッションは `pc` を使うので既定は今のままでよい。

## 汚染

無し。逆アセンブル・ダンプ・`private/` の参照はいずれも行っていない。
上記「目に入った公式版の番地」は番地であってバイト列ではなく、
ゴール A の実装には影響しない。ゴール B に進む際の注意として記録した。
