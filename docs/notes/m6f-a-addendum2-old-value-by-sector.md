# m6f-a 追補2 — 古い値を出す単位を「区間」から「セクタ」へ広げ、最小件数を課す（測定前）

記録日: 2026-09-24  
状態: 測定前。器具は作ったが、**実測は1走も回していない。**

## 1. 何が漏れうるか

[事前登録](m6f-a-directory-by-save-diff-preregistration.md) §1-3 は、古い値を出す条件を

> 連続して変わった区間の古い値がすべて同じ1値である場合に限り

とした。**長さ1の区間では、この条件は必ず真になる**（値が1つしか無いので「すべて同じ」は
自明に成り立つ）。

これは2つの点で意図とずれる。

- **長さ1の区間の古い値は、詰め物の証拠にならない。** 事前登録が出してよいとしたのは
  「空き領域の詰め物＝形式の定数」だったが、1バイトは何とでも一致する。
- **散在した1バイトの変化を通じて、古い値が1バイトずつ漏れうる。** たとえば SAVE が
  割り当てた空きセクタに**削除済みファイルの残骸**（公式ディスクの中身）が残っていた場合、
  自分の書いたデータと偶然一致するバイトに挟まれた1バイトの変化は、それぞれ長さ1の区間に
  なり、古い値がそのまま出る。長い区間が非一様で伏せられても、この経路は塞がれない。

## 2. 直し方

古い値を出す単位を**セクタ**にし、**最小件数**を課す。

- **あるセクタで変わったバイトの古い値が、そのセクタ内ですべて同じ1値であり、かつ
  そのセクタで変わったバイトが8個以上あるときに限り**、その1値をセクタについて出す。
- それ以外は、**そのセクタのすべての区間の古い値を伏せる**（区間ごとに出し分けない）。
- 新しい値と位置の扱いは変えない。

これは事前登録 §1-3 より**厳しい**（事前登録が出してよいとした範囲の部分集合しか出さない）。

8個という下限は、**詰め物とみなすには一定の長さが要る**ことを表すための値で、予備走では
決めていない。これで出せなくなるのは、変わったバイトが7個以下のセクタの古い値だけである。

## 3. 導出規則への影響

- **D6（未使用エントリの表現）**: F1 のディレクトリのセクタで古い値が §2 の条件を満たす
  ときに限り導出する。満たさなければ `not_found` とする（候補が無いのではなく、境界により
  出せなかったことを、`not_found` の理由として区別して記録する）。
- **D7（割り当て表）**の空きの印も同じ扱い。F1 は小さく、割り当て表で変わるバイトが
  8個未満になりうるので、**空きの印は F6（約60KBのファイル）から読む**ことになる。
  F6 を置いた理由がここでも効く。
- D1〜D5 は新しい値と位置だけで導出するので影響を受けない。

## 4. 関門 G3 への追加

差分器の自己検査に次を足す。

- **1バイトだけの変化が散在するセクタ**（古い値がそれぞれ違う）で、古い値が1つも出ないこと。
  **事前登録どおりの区間単位の実装ではここで古い値が漏れる**ことを、変異版で確かめる。
- 変わったバイトが7個で古い値が一様なセクタで、古い値が出ないこと（最小件数）。
- 変わったバイトが8個以上で古い値が一様なセクタで、その値が出ること。

## 5. 変わらないもの

- 使い捨て複製だけを使うこと、差分以外を見ないこと、変わっていないバイトを出さないこと、
  画面を読まないこと、生出力をコミットしないこと。
- 刺激 F0〜F6、D1〜D5、D7 の導出の仕方、関門 G1・G2・G4〜G7、判定名、行き先。
