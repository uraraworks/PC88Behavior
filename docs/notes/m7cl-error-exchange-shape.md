# m7cl — エラー交換run構造の公式環境測定

日付: 2026-08-24

## 目的

第80版で次境界とした `no_disk` / `unreadable_disk` のエラー応答経路を、
FDCコマンド種別とmain⇔sub交換runの構造だけで分離する。両条件を同じ
「エラー応答経路」と仮定せず、値差か制御構造差かを判定する。

## 実走結果

公式環境で `tools/measure_error_exchange_shape.sh` を実走し、rc=0だった。
`no_disk` / `unreadable_disk` を公式・混成各1走し、全runで取りこぼしは0件だった。

### no_disk

- FDCコマンド種別の一致prefixは54件で、55件目が分岐だった。
- 公式は SENSE DRIVE STATUS、unit/headはB/head0、ST3分類はREADY/B/head0だった。
- 混成は READ DATA、unit/headはB/head1で、結果分類はなかった。
- 交換run構造の先頭一致prefixは36件（公式37件、混成58件）だった。
- 分岐直前の要求形から異なり、公式は main→sub 長さ5、混成は長さ6だった。
- 公式は分岐後、観測窓内に応答runを一度も返さなかった。混成は相対位置+1で
  sub→main 長さ1を返した。
- 相対位置-4〜-1は両者で完全に同形で、順に main→sub 2、sub→main 256、
  main→sub 1、sub→main 1だった。
- 公式は SENSE DRIVE STATUS を反復し続け、その件数はm7ciの測定で51800件だった。

### unreadable_disk

- FDCコマンド種別の一致prefixは55件で、56件目が分岐だった。
- 公式は READ DATA、unit/headはB/head1、ST0分類はIC=異常終了/B/head1、
  ST1分類はMISSING ADDRESS MARKだった。
- 混成は SEEK、unit/headはB/head0で、結果分類はなかった。
- 交換run構造の先頭一致prefixは38件（公式60件、混成58件）だった。
- 分岐直前の共通要求は main→sub 長さ6だった。
- 両者とも相対位置+1/+3/+5で sub→main 長さ1の応答を返し、
  +0/+2/+4の main→sub 長さ6の要求と交互になった。構造は+5まで一致した。
- +6で、公式は main→sub 長さ6を続け、混成は main→sub 長さ2の
  データ取得要求へ進んだ。

## 解釈

`no_disk` と `unreadable_disk` は別種の宿題だった。

`unreadable_disk` は、+5まで交換構造が一致しており、同位置の1バイト応答の
**値だけが違う**。公式は1バイト応答でエラーを示し続ける一方、混成は読めた側の
応答を返すため、mainが+6で2バイトのデータ取得要求へ進む。

`no_disk` は値の問題ではなく**時間的な振る舞い**である。公式は分岐後に観測窓内で
一度も応答せず、SENSE DRIVE STATUSを反復する。「準備できるまで待ち続ける」という
制御構造そのものが混成と異なる。

m7ciは「比較可能な同位置のエラーステータス値は得られない」と記録したが、その制約は
少なくとも `unreadable_disk` では外れた。前周で要求byte2のドライブ指定をFDC unitへ
伝播した結果、公式・混成のunit経路が揃い、交換run位置も揃ったため、同位置の1バイト
応答を比較できる場所が生じた。前周の実装が今回の測定を可能にした、という因果である。

## 次周の境界

1. `unreadable_disk`: 自作sub自身のFDC結果にある、公開μPD765の
   ST0 IC=異常終了とST1 MISSING ADDRESS MARKでエラーを判定し、1バイト応答を
   エラー側へ切り替える。応答値はブラックボックス探索で決める。
2. `no_disk`: 応答を返さずSENSE DRIVE STATUSを反復する待ちを作る。
   こちらは値ではなく制御構造の問題として扱う。

公式が返す1バイト値は読まない。値をそのまま実装へ写す由来の鎖を避けるため、m7lが
交換#3（1.23節）で採った方法と同じく、自作sub側で候補値を振り、mainの下流の画面、
FDC種別列、交換run構造が公式と一致する値をブラックボックスで再構成する。今回は
交換run構造が既に揃っているため、m7lより探索条件がよい。この探索と実装は次周とする。

## 情報境界

解析器は値を保持しない構造で、出力に含まれるのはrunの向き・長さ・件数・位置・
公開ビット名の分類だけである。応答値およびFDC結果の生値は記録していない。

生iologはリポジトリ外の一時ディレクトリのみで扱い、リポジトリへ持ち込んでいない。
私物のパス、ディスクデータ、画面本文も記録していない。
