# m6i-g 追補1 — 初期化が起きない腕の窓を、番兵ではなく意味で定義する（取り直し前）

記録日: 2026-09-23  
状態: 取り直し前。[第1回の試行](m6i-g-attempt1-window-sentinel.md)は
`m6i_g_inconclusive` であり、その結果は使わない。

## 1. 直す対象

[事前登録](m6i-g-clean-preamble-boundary-preregistration.md) の関門G7
（状態観測の独立性）を支える整合検査が、**FDC 初期化が起きない腕で壊れる**。
原因は[第1回の試行](m6i-g-attempt1-window-sentinel.md) §2 のとおり、
`shape` が `None` のときの番兵 `-1` である。

**直すのは到達器具だけである。** 事前登録 §5 の
`m6i_g_inconclusive` の行き先（「到達器具か期限だけを直す追補を先に置き、
結果条件と判定名は緩めない」）に従う。

## 2. 直し方

初期化が完了したか否かで、窓を場合分けする。**番兵の数値に意味を持たせない。**

### 初期化が完了した場合（`shape` あり）

現行どおり。

- 起動専用の窓: 走の先頭から `init_start` まで
- ラウンド#0応答の窓: `init_end` から通常READ発行まで
- 整合条件: `起動専用SEND数 == 起動専用RECV数 == b` かつ
  `ラウンド#0応答数 == c`

### 初期化が完了しなかった場合（`shape` なし）

- 起動専用の窓: **走の先頭から通常READ発行まで**（`clock < -1` という
  空の窓にしない）
- ラウンド#0応答の窓: **定義しない**。初期化を終えていない走に
  「初期化より後」の区間は存在しない。
- 整合条件: `起動専用SEND数 == 起動専用RECV数 == b` かつ **`c == 0`**

`c == 0` を要求することで、窓を1つ落としたぶんの検出力を補う。
**「ラウンド#0応答をI/Oで数える」代わりに「マーカー側が0である」ことを
要求する**形であり、初期化が起きていない腕では後者のほうが直接的である。

## 3. 関門の追加（G10）

**器具が「窓を番兵で作っていないか」を検査する関門を足す。**

- **G10 窓の番兵検査**: 状態観測の窓を作る全ての箇所について、
  観測対象の事象が0件だった場合に、その窓が
  （a）走全体へ広がる、または（b）空になる、のどちらにもならないことを、
  合成入力で確認する。具体的には少なくとも次の2件を自己検査に置く。
  - 初期化が起きず、かつ sub が起動ハンドシェイクで `OUT $FD` を出す入力で、
    `c` の整合検査が真になる（第1回で偽になった形）
  - 初期化が起きず、main が起動専用SENDを1件出した入力で、
    起動専用SEND数が正しく1と数えられる（空の窓なら0になってしまう形）

第1回の不備を二度と通さないための関門である。

## 4. 変わらないもの

- 腕の構成4種、sub を4腕でバイト一致させること、main だけを振ること、
  腕ごとの発行フレームと期待状態、結果条件、総合判定4種、行き先、
  関門 G1〜G9、本文・値列を出さない規律は変更しない。
- **事前登録 §0（本測定は自作どうしの統合条件を決めるものであり、
  公式 sub の要求を決めない。1.65節へ書かない）も変更しない。**

## 5. 修正の波及範囲

**修正は初期化が完了しなかった経路にしか触れない。** 第1回で到達した
G-L1・G-L2 は初期化が完了しており、判定は修正の影響を受けない。

それでも**全4腕を取り直す。** 一部の腕だけ旧器具の結果を流用しない。
**第1回の観測値を取り直しの結果として使わない。**
