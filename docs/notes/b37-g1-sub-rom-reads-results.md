# B37: スペース後の G1 で、サブの ROM 側が読む RAM の番地を値なしで測る — 結果

記録日: 2026-11-01
規則: [b37-g1-sub-rom-reads-preregistration.md](b37-g1-sub-rom-reads-preregistration.md) どおり。測定はクラウドの実行環境で OO・SS 各 2 走。値は記録していない。

1 回目は関門で止まった（rc=1、ファイルなし）。ドライバに事前登録に無い「`IN $FC` の長さの一致」が入っていたためと考え、外した（B30 でも長さは違う）。同じドライバは ROM 置き場とディスクを 4 走で使い回し、ROM 置き場に保存ファイルができていたので、走ごとの複製に直した。2 回目は新しい作業場で取り直し、関門 14 項目はすべて通った。

## 結果

4 走とも窓の中の `W` の行は 0 だった。比較の出力は `none` である。

## 読み方

- 事前登録どおりに書けば、**ROM 側の読みの番地と書き手は窓の中で同じ**である。ただし両方とも 0 件である
- 0 件が本当に「読んでいない」のか、G1 の走で器具が働いていないのかは、この記録だけでは分からない。自己検査は通っているが G1 の走の陽性対照が無い。**B38 で別の窓の陽性対照を取る**
- 本当に 0 件なら、窓の中で main へ返す値を ROM 側は RAM から取っていない。B36 の「ROM 側のコードが返している可能性」は弱くなる（**推定**）
