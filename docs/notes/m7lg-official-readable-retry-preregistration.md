# m7lg: 読める媒体の場面で、公式はREAD DATAを繰り返すか——(a)を測る — 事前登録

## 位置づけ

[m7ks](m7ks-implement-retry-dead-end.md)は、再試行の実装が適合を壊したことから、
**(a)「公式は書き込み経路・LOAD経路では9回粘っていない（＝9は場面に依存する）」**か
**(b)「自作の`FDC_ABORT`が場面を取り違えている」**かのどちらかだ、と書いた。
(b)は[m7ku](m7ku-abort-scene-attribution-results.md)が消し、回帰の原因は再試行ではなかったと
[m7kw](m7kw-third-branch-results.md)〜[m7lb](m7lb-window-tail-confirm-results.md)で分かった。
再試行は[m7lf](m7lf-judgment-line-identity-results.md)で採用した。

**(a)は1度も測っていない。** 回帰の説明としては不要になったが、**問いとしては残っている**:

> **読める媒体の場面（書き込み・LOAD・drive1/drive2）で、公式はREAD DATAを繰り返すか。**

**採用した実装は「`FDC_ABORT`が立ったとき（読めないとき）だけ粘る」。** 読める場面では
1件ずつ（m7leの条件5）。**公式がそれらの場面で繰り返していたら、採用した実装はそこで公式と
食い違う。** **本稿はそれを測る。**

## 測るもの（値を出さない。件数と真偽のみ）

各場面の**公式一式の側**の生ログで、**FDCコマンドのうち`READ DATA`の件数・連続した対の数・
最長連続**を数える（[m7kw](m7kw-third-branch-results.md)で使った「再試行の署名」と同じ数え方。
コマンド種別の復号は`tools/analyze_write_path.py`を共有する）。**比較のため、同じ場面の混成側
（採用済みの自作サブROM）も同じく数える。**

| 記号 | 場面 | 公式側の生ログ |
|---|---|---|
| **W** | 書き込み（`SAVE`） | **別に1本走らせる**（適合テストは条件5で公式側を走らせていない）。引数は適合テストの条件5と同一 |
| **L1** | LOAD（混成と同じ打鍵の公式一式） | 適合テストの`load.official` |
| **L2** | LOAD既存ファイル | 適合テストの`load_existing.official` |
| **D1** | drive1（`FILES 1`、B:に読める媒体） | 適合テストの経路測定`drive1`公式側 |
| **D2** | drive2（`FILES 2`、B:に読める媒体） | 同`drive2`公式側 |
| **P** | **陽性対照**: 読めない媒体（`FILES 2`、B:に規則生成媒体） | 同`unreadable_disk`公式側 |

**Pは「数え方が公式の繰り返しを拾える」ことの確認である。** **1.58節の観測（1送信単位の内側で
READ DATA×9）が公式で出ていれば、連続した対が0より大きく、最長が9になるはず。**
**Pで連続が0なら器具が働いていないので、主判定は`O`。**

## 事前登録する判定（**測定前に固定する**）

- **XA1**: **W・L1・L2・D1・D2の公式側で、`READ DATA`の連続した対がすべて0。**
  → **読める場面では、公式も繰り返さない。** 採用した実装（読める場面では1件ずつ）と食い違わない。
- **XA2**: **いずれかの場面で、公式側の連続した対が1以上。** → **公式は読める場面でも繰り返す
  ことがある。** 採用した実装はそこで公式と食い違う。**場面ごとに件数を記録する。**
- **O（測定不能）**: 陽性対照Pで連続が0、決定論性が偽、生ログが取れない（W の公式側の実行が
  失敗する等）。

**どの判定になるかは予測しない。**

## 決定論性

**適合テストを2回、公式のSAVEを2本**走らせ、**各場面の3つの数が1回目と2回目で一致すること。**

## 言えないこととして先に書いておくこと

- **XA1でも「公式は読めるか読めないかで粘るかを決めている」とは書かない。** 読める場面で繰り返さ
  ないことと、読めない場面で繰り返すこと（1.58節）が両方観測された、までである。**その間を
  決めている規則は測っていない**（`m7kr`の「9を決める規則」と同じく未確定）。
- **XA2でも、なぜ繰り返したかは言わない。** 繰り返しの件数と場面だけを記録する。
- **コマンド種別の名前と件数だけを扱い、コマンドのバイト値・パラメータ・結果ステータスの生の値は
  出さない。**

## 合格条件（測定の成立）

1. 陽性対照Pで連続した対が0より大きい。
2. 決定論性（上記）。
3. 6場面すべての公式側・混成側の生ログがそろう（実行した場面の数を出力に載せ、期待値6と一致）。
4. `tools/check_cleanroom.sh`が全項目OK。**`src/`・`tools/`は変えない。**

## 禁止（本稿の測定中も例外なく適用）

公式ROM・公式ディスクのバイト列を読まない・出力しない・逆アセンブルしない。公式ディスクのイメージを
直接読まない（**`cp`で使い捨ての複製を作り、書き込み可のフラグを立てるだけ**。適合テストの条件5と
同じ扱い）。`private/`の中身・ファイル名を出力しない。FDCデータポート値・シリンダ値・セクタ番号・
結果ステータスの生の値・時刻・frame番号・画面本文を出力しない。
