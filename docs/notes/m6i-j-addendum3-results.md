# m6i-j 追補3・追補4 — 結果（書き込み要求の構造を採る）

記録日: 2026-09-29

## 1. 実行

[追補3](m6i-j-addendum3-request-structure.md)（`46ac480`）・[追補4](m6i-j-addendum4-relocate-media.md)（`c6b77db`）。器具 `19f1434`、公式ROM起動20回（10腕×2走）。
関門はすべて真、2走はすべて一致。追補3の1回目（`17d810c`、起動17回）は T-D2-S の媒体の設計で止まった（追補4）。

## 2. 判定

**`inconclusive_structure`**（H2 が T-D2-X で成り立たなかった）。**H1・H3 は10腕20走のすべてで成り立った。**

| 仮説 | 結果 |
|---|---|
| H1（WRITE の受信列 `S, 0x11, 0x01, D, T, R` ＋256、S は SAVE の最初の WRITE で D・以降 `0x06`） | 全腕で成立（本体をトラック17に置いた T-D2-S、3単位の T-D2-X を含む） |
| H2（要求順序） | T-D2-X（17セクタ・3単位）だけ不成立。ほかの9腕は成立 |
| H3（各 WRITE に応答1バイト） | 全腕で成立 |

## 3. 採るもの

H1・H3 を main 側の書き込み送信の規則として採る（`l3-subrom.md` に節を新設）。H2 は採らない。

## 4. 観察（判定には使わない）

- T-D2-X の順序: 最初の単位の8セクタは1セクタごとに割り当て表3枚を書き直すが、2つ目以降の単位のセクタは続けて書き、最後に割り当て表3枚を書いては読み直す。
  9セクタの腕はこの形の特別な場合として読める。単位は 72→71→68（2.5節の「2つ取っては2つ飛ばす」と合う）。
- T-D2-S（72・73・71・70 を使用中）では本体は単位69へ。追補3の1回目（72・71・68・67 を使用中）では単位73へ置かれた。**2.5節の割り当て順の記述は不完全**。
- 要求の順序は、公式 sub が各要求を独立に処理する限り、自作 main が合わせる必要は無い（媒体の最終的な中身で確かめる）。
