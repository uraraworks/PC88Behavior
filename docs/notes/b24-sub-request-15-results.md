# B24: 要求 `0x15` の働きを、自作のプローブで公式サブから測る — 結果

記録日: 2026-11-01
規則: [b24-sub-request-15-preregistration.md](b24-sub-request-15-preregistration.md)（f891add）どおり。測定はクラウドの実行環境で 8 行×2 走、走どうしは全行一致。公式のものは `DISK.ROM` だけを使い、値は記録していない。記録: `measurements/b24-sub-15-*`。

## 判定: 対照は通過、`transfer` は **not_confirmed**

| 行 | 要求 | 受け取り | 先頭の一致 | 刻印 |
|---:|---|---:|---:|---|
| 1 | `15 78 00 00 10` | 16 | 16 | - |
| 2 | `15 78 00 00 01` | **0** | 0 | - |
| 3 | `15 78 08 00 10` | 16 | 16 | - |
| 4 | `15 78 00 01 00` | 256 | 256 | - |
| 5 | `02 01 00 00 01` のあと `15 50 00 01 00` | 256 | 256 | (0,0,1) |
| 6 | `02 02 00 00 01` のあと `15 50 00 02 00` | 512 | 512 | (0,0,1)(0,0,2) |
| 7 | `15 78 00 00 00` | 0 | 0 | - |
| 8 | 故障注入 `15 78 01 00 10` | 16 | 0（検出） | - |

判定が not_confirmed なのは、行2（長さ 1）で何も受け取れなかったためである。

## 分かったこと

- 長さ 16・256・512 では、`0x15` は番地 A から L バイトを main へ渡す。番地も長さも上位が先で、`0x06`・`0x12` は要らない
- 読み要求のデータは `0x5000` に置かれ、`0x15` で受け取れる
- **L を超えて受け取ろうとしても何も来ない。** 測定器の手順では 16 のあとは時間切れになった
- 長さ 0 と長さ 1 は受け取れなかった。長さ 1 の理由は分からない

## 分からないこと

G1 の 3840 バイトの直後の 2 バイト（公式 `00 14`）は、この手順では出ない。G1 の受け取りの手順は測定器と違う可能性がある（**推定**）。次は、サブがこの 2 バイトを実際に送っているかを、値を見ずに件数で確かめる。
