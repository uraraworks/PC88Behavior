# l4-s9w 追補2 — 作業領域が足りなくなる条件を探す腕の追加（事前登録の追補）

状態: 2026-10-09。**公式の最初の走り（較正で gate_failed になった走り。追補1）の観測を、診断のために読んだあと**に書く。公式の 2 走目（追補1の訂正後の全腕）はまだ終わっていない。この追補の腕は公式で未実行。

## 動機

最初の走りで、作業領域の腕 `ws-1`〜`ws-3b` は**どれも誤りなし**で、歯 300 本の櫛も既定のスタック（512）のまま完全に塗られた（`ws-2`・`ws-2b`・`ws-2c` の最終画面のハッシュが同じ）。事前登録の予測（歯 160・300 本で既定スタックなら ERR 7）は外れる見込みで、**作業領域不足時の振る舞い（誤り番号・途中で止まるか）が一度も観測できていない**。この段の目的 5 を満たすため、不足を起こす条件を探す腕を足す。予測・既存の腕・関門は変えない。

## 足す腕（`tools/l4_paint_measure.py`）

- 先頭に `on error goto 900` を置いてから `clear ,,N` を実行する（`guard`。`clear` 自体が誤りでも走りが止まらないように）。既存の `ws-*` のプログラムは変えない。
- **スタックを縮める**: 歯 20・40・80 本の櫛の3つを同じ画面に置き（`ws-1` と同じ配置）、`clear ,,N` の N を 16・64・128・256 に（`ws-6a`〜`ws-6d`）。点線格子（300×80）と蛇行路（40 往復）を `clear ,,64` で（`ws-6e`）。
- **より重い領域**: 画面幅いっぱいの点線格子（偶数行に 1 ドット置きの点）を、小（100×40）・中（200×80）・大（639×99）の3つ置く腕を、既定のスタック（`ws-4`）と `clear ,,4096`（`ws-4b`）で。

## 予測（外れてよい。すべて弱 w。表にない量は予測なし）

| 量 | 予測 |
|---|---|
| `ws-6a`（スタック 16） | 3つとも ERR 7 |
| `ws-6b`（64） | 歯 80 本だけ ERR 7、20・40 本は誤りなし |
| `ws-6c`（128）・`ws-6d`（256） | 3つとも誤りなし |
| `ws-6e`（64） | 点線格子・蛇行路とも ERR 7 |

| 誤りなしの腕の画素 | 完全に塗られる（`ws-1` と同じモデル） |
