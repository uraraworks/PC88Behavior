# m7dc: 起動時5635件のH1再現対照を公式diskA 2走で確認

実施日: 2026-08-28

`docs/notes/m7da-5635-origin-preregistration.md` 第2段に従い、介入前の対照として
m7acの既存結果を公式diskAの新規run1/run2で再現確認した。これは未知規則の探索では
なく、次段の媒体形状介入に先立ち同じ環境・解析手法が既知結果を再現するかの確認である。
**第3段の合成媒体介入は実施していない。**

## 情報境界と実行条件

- 公式ROM・公式diskAは `q88measure` で実行しただけで、ファイル内容を直接読んでいない。
- 各走1800フレーム。生ログ、標準出力、stderr、解析器出力はリポジトリ外の
  `/tmp` 一時領域だけに置き、コミットしない。
- `tools/analyze_exchange14_read_rules.py` は既存の値非表示モードのまま使った。
  解析器による公式ディスク由来値の照合は比較器メモリ内だけで行い、解析器の標準出力、
  ノート、コミット対象へ1バイトも出していない。ただし、後記の情報境界上の失敗では
  解析器外のコマンドが差分バイト5件をツール出力へ出しており、この例外を隠さない。
- run1/run2とも測定rc=0、解析rc=0。main 95046件、sub 78798件で、取りこぼしは
  両CPU・両走とも0件だった。

最初のrun1起動前に、環境変数をコマンド前置代入しながら同じコマンドライン内で参照した
ため、シェル展開時には空となり引数エラーrc=2になった試行が1回ある。測定開始前に終了し、
生ログは生成されなかった。環境変数を同一シェルでexportしてからrun1をやり直した。
この失敗試行をrun1には数えない。

絶対パスが別で、inodeも異なり、リンク数は各1なので、同一ファイルまたはハードリンクを
2回ハッシュしたものではない。mtimeは約26.4秒離れ、実行順とも一致する。

### 陽性対照

出力先を `/tmp/pc88-m7dc.CZCDVC/positive-1801.iolog.txt` に分け、diskAは同じまま
フレーム数だけ1800から1801へ変えて1走した。起動記録は
2026-08-28 09:11:15.043344 JST、終了は09:11:15.614787、rc=0。生ログは
inode 170563622、サイズ9042337で、SHA-256は
`324d2b8539384b87be55c4920af6a8cdbd295e21e05c969bd7b8d1edea1047fb`となり、
run1/run2のSHAから変化した。main件数も95046から95066へ変わった。
従ってハッシュ手順と出力先は条件差を検出しており、同じファイルを見続けてはいない。

以上から、今回の同一SHAは、現ビルドの入力なし・読取り専用diskA・1800フレームという
同一条件で生iolog全体までバイト決定論的だった結果と採る。解析器出力も全文の直接比較で
一致し、解析結果SHA-256は両走とも
`786db3d9a17bbdbe2aa3e2ec52419601a07b4b0c85941e933c02919a97cc585e`だった。

### m7czとの関係

m7czのd1/d5同一条件ペアは生iologのSHAが各runで異なる一方、判定対象だった起動時
FDC初期化区間の値なし正規化署名は各ペアで一致した。m7czの「取得時のビルド時点が
異なる」という記述は、保存済みd0と新規d1/d5の**正規化署名どうし**の差を条件差や
揺れと解釈しないための注意であり、d1 run1/run2またはd5 run1/run2の生ログSHA差を
説明した記述ではない。

従って結論は食い違わない。m7czが確定したのは同一ビルド・同一条件における対象区間の
正規化構造の決定論性であって、生iolog全体が常にバイト一致するという主張ではない。
今回のd0は入力や書込みを伴わない別条件で、別実体・別時刻の2走が生ログ全体まで一致した。
この一致を他条件や実機へ一般化しない。

### 情報境界上の失敗

陽性対照との差が生じる先頭位置を調べようとして、生ログへ
`cmp -l | head -5` を誤って実行し、ファイル上の差分バイト5件をツール出力へ出した。
公式ディスク由来値を含む可能性を排除できないため、これは情報境界違反として扱う。
差分値は本ノートその他のファイルへ転記しておらず、判定にも使用していない。
以後の切り分けはinode・link・サイズ・mtime・完了記録・SHA-256だけで行った。
このセッションは当該箇所の実装を担当せず、測定結果は値を出さない既存解析器から
独立に再取得できる構造量だけに限定する。

## m7da H1再現確認 (a)〜(f)

| 条件 | run1 | run2 | 判定 |
|---|---|---|---|
| (a) 49セクタ中5セクタ除外 | READ長 `1/14/16/16/2`、計49。第1 READ 1セクタと第2 READ先頭4セクタを除外 | 同左 | 再現 |
| (b) 残り44セクタ＝11264一意バイト | 第2 READ第5セクタから第5 READ末尾まで44×256=11264 | 同左 | 再現 |
| (c) 2チャンネル交互配置 | FC→FD。定常先頭は第2 READ第5セクタ第2位置。順序対応11263/11264 | 同左 | 再現 |
| (d) 片側5632件 | 候補総長11264、FC側5632、FD側5632 | 同左 | 再現 |
| (e) プリアンブル3件 | main `$FD` 5635件を先頭3件＋定常5632件へ分離 | 同左 | 再現 |
| (f) 末尾重複1位置 | 11264位置目は直前座標と一致し、残差1件を説明 | 同左 | 再現 |

(b)と(c)はm7abの無加工・同位置対応ではない。今回も256件境界で出力セクタがそのまま
一致した数は0/22だった。一方、両チャンネルをFC→FDの組へ戻して順序制約を加えると、
第2 READ第5セクタ第2位置から11263位置が連続一致し、最後の1位置は直前座標の重複で
説明できた。m7acと同じ順序制約付き座標対応の再現である。

44セクタの第1位置は既存m7acどおりプリアンブル第3位置に属し、定常部は第2位置から
始まる。このため、プリアンブルを含む一意媒体窓は44×256=11264バイト、定常2ポート
出力も11264件だが、定常末尾の1件は直前座標を重複する。
