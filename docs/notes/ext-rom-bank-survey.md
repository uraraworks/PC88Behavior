# 拡張ROMバンク（4th ROM）下調べ — メインROMの空き対策

作成日: 2026-09-19
調査: 下調べセッション（実装なし。src/・docs/spec/ は変更していない）

## 背景

`src/build_main_rom.py` でビルドした N88.ROM（自作、32768バイト）は
使用済み 30543バイト・末尾アドレス `0x774C`。予約番地 `0x79D7`
（`docs/spec/l1-ipl.md` 第2節 P4 該当部、ROM_VERSION 判定用に空けてある）
手前までの空きが `0x774D`–`0x79D6` で **650バイト**、`0x79D8`–`0x7FFF` が
**1576バイト**（実測。以下「約649B」「1576B」は依頼文の丸め）。
今後 L4 BASIC の機能を増やすと近い将来これを使い切る。
拡張ROMバンク（メインROMの `0x6000`–`0x7FFF` に重ねて見える 8KB×4本、
QUASI88 では `N88_0.ROM`〜`N88_3.ROM`）へコードを逃がす案の下調べを行う。

本ノートは**事実（測定・エミュレータソース由来）と推定を分けて書く**。
公式ROMの内部構造・逆アセンブルは一切見ていない（`private/` 未参照）。

## 1. ハードウェアの事実 — ポート `0x32` / `0x71`

出所は `docs/spec/l1-ipl.md`（第5a・5c節）で、すでに仕様書側にある事実の
引用（第5a節はメーカー資料・NEC『PC-8801MA ユーザーズガイド』、
第5c節は出典記載のある個人サイト2件、測定と独立に符合済み）。
新たな資料は開いていない。

### ポート `0x32`（OUT/IN） — 「各種設定」

| bit | 信号 | 意味 |
|---|---|---|
| 7 | SINTM | サウンド割り込みマスク |
| 6 | GVAM | グラフィックVRAMアクセスモード |
| 5 | PMODE | パレットモード（0=デジタル8色 / 1=アナログ512色） |
| 4 | TMODE | 高速RAMアクセスモード |
| 3-2 | AVC | 画面出力モード |
| **1-0** | **EROMSL** | **内蔵拡張ROMバンク選択（4th ROM）。4本から1本選ぶ** |

### ポート `0x71`（OUT/IN） — 「4th ROMコントロール」

第5a節の書籍（1982年）は「b0-7 が ROM1〜ROM8」（8スロット）と書くが、
**PC-8801MA の機能仕様（NECユーザーズガイド、第4b節）は
「8Kバイト×7バンク」**で、測定（付録A）も `FD FB F7 EF DF BF 7F` の
7パターン（b1〜b7）しか歩かせていない。**測定と機種仕様が一致し、
1982年の書籍と食い違う**（測定を優先、というCLAUDE.mdの原則の実例）。
本タスクの対象（QUASI88の `EXT0〜3.ROM`＝4バンク）は `0x71` の
イネーブル/セレクトとは**別の粒度の話**であることに注意（次節）。

### `0x31` は無関係

`0x31` はメモリの ROM/RAM 切り替え（bit1）・グラフィック/N-BASIC等の
全体制御であり、拡張ROMバンクの選択そのものには関与しない
（`docs/spec/l1-ipl.md` 5d節）。依頼文にあった「0x31・0x32・0x71」のうち
**0x31 はバンク選択に直接は使われていない**、というのが確認結果。

### `docs/spec/l1-ipl.md` に載っている自作IPL・公式IPLの書き込み

L1 仕様書（付録A・第4節）には「`32`/`71` を読んでから書き、何かを行い、
元へ戻す」定型が記録されている。これは**拡張ROMバンクではなく内蔵の
4th ROM（辞書ROM等）の切り替え**として観測されたもので、EROMSL経由で
`main_rom_ext[]`（後述）を切り替える経路とビット位置は共有するが、
**測定条件（ディスク無し・キー入力無し）では拡張ROMバンクの中身へ
実際に分岐した形跡は仕様書に明記されていない**（第4節は「回」の定型を
記録しただけで、遷移後に何を実行したかまでは踏み込んでいない）。
つまり「公式IPLが拡張ROMバンクへ実際に処理を渡す場面」はこのノートの
範囲では**未確認**（推定 — 測定で裏を取っていない）。

## 2. エミュレータの実装（QUASI88、`../vendor/quasi88-libretro/src`）

以下はエミュレータ（BSD-3、公式ROMではない）のソースコードそのもので、
禁止事項1-2の対象外。ただし同ファイル中に公式ROMのエントリアドレス・
ルーチン名を書いたコメント（無関係な別テーブル、BASICコマンド処理系と
思われるもの）が近くにあるのを見かけたため、**そこは一切転記していない**
（依頼文の指示どおり）。

### ROMファイル名と読み込み — `memory.c`

```
memory.c:88   enum {... EXT0_ROM, EXT1_ROM, EXT2_ROM, EXT3_ROM ...}
memory.c:94-97  rom_list[]: "N88EXT0.ROM"/"n88ext0.rom"/"N88_0.ROM"/"n88_0.rom" (以下 EXT1-3 も同型)
memory.c:111  byte (*main_rom_ext)[0x2000];  /* 拡張ROM [4][0x2000](8KB*4) */
memory.c:334  main_rom_ext = mem_alloc(0x2000*4);   -- 起動時に確保
memory.c:361-364  load_rom(EXT0_ROM..EXT3_ROM, main_rom_ext[0..3], 0x2000, DISP_RESULT)
```

**ファイルが無いときの扱い（`memory.c:205-260` `load_rom()`）**:
見つからなければ `memset(ptr, 0xff, size)` で **0xFF 埋め**にするだけで、
戻り値は `-1`。呼び出し側（上記 361-364 行）は戻り値を**見ていない**——
つまり **拡張ROMが1本も無くても起動は止まらない**。窓の中身は全バイト
`0xFF`（Z80 では `RST 38H` に解釈される）になる。

**結合形式ROM（`file_compatrom` 指定時、`memory.c:386-389`）**でも
`EXT0〜3` はオフセット `0x0c000`/`0x0e000`/`0x10000`/`0x12000` から
各 `0x2000` バイト読むだけで、失敗しても致命扱いにはならない
（`load_compat_rom_success` の判定対象は N88.ROM・EXT0-3・N-BASIC上位・
サブROM全体の成否で、個別失敗の扱いまではこの下調べでは未確認）。

### バンク切り替え — `pc88main.c`

```
pc88main.h:58   #define MISC_CTRL_EBANK   (0x03)   /* EROM BANK 00..11 */
pc88main.h:78   #define EXT_ROM_NOT       (0x01)   /* 拡張ROM 非セレクト */
pc88main.c:855  case 0x32: ... misc_ctrl = data; main_memory_mapping_0000_7fff(); ...
pc88main.c:1062 case 0x71: ext_rom_bank = data; main_memory_mapping_0000_7fff(); return;
pc88main.c:1333 case 0x32: return misc_ctrl;      （IN 32）
pc88main.c:1409 case 0x71: return ext_rom_bank;   （IN 71）
```

```
pc88main.c:285-300（main_memory_mapping_0000_7fff 内、N88 BASIC・ROM/RAMモード時）
  if ( ext_rom_bank & EXT_ROM_NOT ) {        /* 通常ROM */
    read_mem_6000_7fff = &main_rom[0x6000];
  } else {                                    /* 拡張ROM */
    read_mem_6000_7fff = &main_rom_ext[ misc_ctrl & MISC_CTRL_EBANK ][0];
  }
```

**要するに**: `0x71` の bit0（`EXT_ROM_NOT`）が **1=通常メインROM /
0=拡張ROM有効**の総スイッチ、有効時にどの1本（4本中）を見せるかを
`0x32` の下位2ビット（`MISC_CTRL_EBANK`）で選ぶ。書き込み対象は
`read_mem_6000_7fff` という関数ポインタで、`0x6000`–`0x7FFF` の**読み出し**
だけが切り替わる（**書き込みは常にメインRAM**、`main_memory_mapping_0000_7fff`
の別分岐 `write_mem_0000_7fff` 側。ROM/RAMモードの通常ROM窓と同じ扱い）。

これは `docs/spec/l1-ipl.md` 第5c節（ポート32のEROMSL）・第5a節
（ポート71の4th ROM）と**独立に一致**する（Web資料＋メーカー資料の
ビット定義と、エミュレータの実装がビット位置まで合う）。

**ROM_VERSION（`main_rom[0x79d7]`）はバンク状態と独立か**: `main_rom` と
`main_rom_ext` は別配列（`memory.c:120-121`）であり、`main_rom[0x79d7]`
自体はバンク切り替えの影響を受けない——**が**、`0x79D7` は `0x6000`–
`0x7FFF` の範囲内なので、**拡張ROMを選択している間は `main_rom[0x79d7]`
を直接読むことはできない**（読み出しがバンク先へ切り替わっているため）。
ROM_VERSION 判定コード自身が `0x71` の切り替えを一時的に戻して読んでいる
かどうかは、このソースの範囲では確認していない（未確認・推定）。

### `main_rom_ext` の内部かどうかの判定（デバッガ用、`pc88main.c:3056-3058`）

```
if( main_rom_ext && p >= (const byte*)main_rom_ext &&
    p < (const byte*)main_rom_ext + 0x2000*4 ) return 1;
```

範囲判定のみで内部構造の記述はない。

## 4. 自作ROMの現状配置（実測、`src/build_main_rom.py` をビルド）

scratchpad にビルドし、`tools/asm/z80text.py` のリスト出力
（`--list`、番地・バイト・「INCLUDE先ファイル内の行番号」）を、
`build_combined_asm()` のモジュール構成（12個の `INCLUDE`）と突き合わせた。
z80text 自体はファイル名をリストへ出力しないため、`load()` と同じ
再帰展開を行毎にファイル名付きで複製し、`pass2` が実際に出力する行
（`blank`/`label_only`/`equ`/`ORG` を除く、`asm.listing` と同じフィルタ）
に対応付けて集計した（下調べ用のスクリプトはスクラッチパッドに置き、
コミットしていない）。

| モジュール（INCLUDE単位） | 内容 | バイト数 | アドレス範囲 |
|---|---|---:|---|
| n88_main_gen.asm | L1 IPL 本体 | 1,065 | 0000-0428 |
| screen_gen.asm | L3 画面出力 | 360 | 0429-0590 |
| keyboard_gen.asm | L3 キー入力 | 855 | 0591-08E7 |
| key_table_gen.asm | L3 キーコード表 | 576 | 08E8-0B27 |
| l4_tokens_gen.asm | L4 トークン表 | 1,213 | 0B28-0FE4 |
| l4_print_dispatch_gen.asm | L4 PRINT振り分け | 7 | 0FE5-0FEB |
| l4_errors_gen.asm | L4 エラー処理 | 889 | 0FEC-1364 |
| l4_lexer_gen.asm | L4 字句解析 | 296 | 1365-148C |
| l4_mbf_gen.asm | L4 単精度数値部 | 7,443 | 148D-319F |
| l4_mbf_double_gen.asm | L4 倍精度数値部 | 5,222 | 31A0-4605 |
| l4_interp_gen.asm | L4 直接モード解釈 | 3,985 | 4606-5596 |
| l4_program_gen.asm | L4 プログラム保持 | 783 | 5597-58A5 |
| **l4_run_gen.asm** | **L4 RUN（プログラム実行系）** | **7,849** | **58A6-774E** |

合計使用 30,543 バイト、末尾 `0x774C`（第0節の空き計算と一致）。

**`0x6000`–`0x7FFF` に載っているのは `l4_run_gen.asm` だけ**（同モジュール
のうち `58A6`–`5FFF` の 1,882 バイトは `0x6000` 未満、`6000`–`774E` の
**5,967 バイト**がこの窓に入る）。現状は他モジュールに跨りはない
（`l4_run_gen.asm` 一つが境界を跨いでいるだけ）。

### アセンブラ（z80text）の対応状況

- `ORG`・`EQU` は対応（`tools/asm/z80text.py` の `DIRECTIVES`）。
  現在のビルドは**どのモジュールも `ORG` を使っておらず**、
  先頭から連続して敷き詰める素朴な方式。
- **`SECTION`/`AREA`/`PHASE`/`BANK` に相当する仕組みは無い**
  （`z80text.py` を検索して確認、該当キーワード無し）。
  シンボル表はモジュール横断の単一名前空間（`self.labels`）で、
  ファイルをまたいでも重複ラベルはエラーになる（`pass1`）。
  **バンクという概念自体をアセンブラは知らない**——バンクROMは
  「別ファイルとして `assemble()` を複数回呼ぶ」形になる（次節）。

## 5. 配置の作り直し — 案（3つ、手間とリスクの見立て）

前提: バンクROMは物理的に「`0x6000`–`0x7FFF` に重ねて見える別の8KB」
なので、**バンクROM自身のコードも `0x6000` 番地からアセンブルする**
（ORGを`0x6000`に置くか、常駐部と同じ base で assemble してから
先頭`0x6000`バイトを切り捨てるか）。常駐部からバンクへは**中継
（トランポリン）ルーチン**を常駐部（`0x0000`–`0x5FFF`）に置き、
「現在のバンク状態を保存 → `0x71`/`0x32` を書いて切替 → CALL → 戻り値
保持 → 元のバンク状態を復元」という定型にする（第1節で確認した
公式IPLの「読んでから書き戻す」定型と同じ形）。

### 案A: `l4_run_gen.asm`（RUN実行系）をバンク1本に丸ごと移す

- **内容**: 現在唯一 `0x6000` を跨いでいる `l4_run_gen.asm`
  （7,849バイト、8KB バンクに収まる）を EXT0 バンクへ移動。
  常駐部の `0x58A6`–`0x774E`（約2KB弱ぶん）が丸ごと空く。
- **手間**: 中継ルーチンが 1 箇所（RUN実行系の呼び出し口は
  インタプリタのディスパッチから来る想定で、呼ばれ方が局所的
  ——現状のモジュール分割がすでにこの単位で切れている）。
- **リスク**: 低い。**測定していない**が、VSYNC割り込みハンドラは
  RAM上（`E7EE`–`E809`）にあり `0x6000`–`0x7FFF` の外なので、
  RUN実行中にバンクを切り替えてもハンドラ自体は消えない
  （第1節・`docs/spec/l1-ipl.md`第3節）。ただしRUN実行系が呼び出し中に
  VSYNC割り込みを受理し、ハンドラが**常駐部の別関数を呼ぶ**ような
  設計だと、その関数がバンク切替中で見えなくなる可能性がある
  （ハンドラ自体は資料上「カーソル追従とキースキャンだけ」で
  `0x6000`–`0x7FFF` を読みには行かないはずだが、**要確認**）。
- 常駐部の空きが劇的に増える（RUN実行系ぶんそのまま）ので、
  次の機能追加（FOR/NEXT、配列、文字列関数など）を大量に常駐へ積める。

### 案B: 数値変換系（`l4_mbf_gen.asm` + `l4_mbf_double_gen.asm`）をバンクへ

- **内容**: 単精度・倍精度の数値部（合計 12,665バイト、8KBバンク1本には
  収まらないので2バンクに分割するか、単精度用と倍精度用を別バンクにする）。
- **手間**: 中〜大。数値変換ルーチンは PRINT・RUN・直接モード評価など
  **多くの箇所から呼ばれる**ため、中継ルーチンの呼び出し点が多い。
  呼び出し頻度も高く（PRINT文の数値整形など）、切替のたびに
  レジスタ退避・ポート`I/O`が挟まるオーバーヘッドが効いてくる可能性がある。
- **リスク**: 中。呼ばれ方が非局所的（インタプリタのあちこちから）なので
  中継の入れ忘れ・戻り値レジスタの破壊などのミスが起きやすい。
  性能面の懸念もある（測定が要る）。
- 利点: 現在最大の2モジュール（7,443B・5,222B）を追い出せるので、
  常駐部の空きは案A以上に増える。将来 L4 の残り機能を全部常駐に
  積みたい場合はこちらが本命。

### 案C: 今後の新規機能だけをバンクへ新設し、既存配置は動かさない

- **内容**: 既存12モジュールの配置はそのまま（`l4_run_gen.asm` が
  境界を跨いでいる現状も維持）。**新しく追加する機能
  （FOR/NEXT、配列、文字列関数など）だけを最初からバンク前提で書く。**
- **手間**: 最小（既存の適合済みコードに触れない）。
- **リスク**: 最小。ただし `0x79D7` 予約や残り約650B/1576Bの制約は
  変わらないので、**常駐部に置く「中継ルーチン」自体のぶんの余白は
  今のうちに削っておく必要がある**（中継ルーチンは常駐部に居座る）。
- 欠点: 既存の2,227バイトの空きをほぼ食い潰すまで「常駐に足す」判断を
  先延ばしにするだけで、案A/Bのような抜本的な空き確保にはならない。

**見立て**: 案C→案A→（必要なら）案Bの順で進めるのが手間対効果が良さそう。
案Cで当面の機能追加を続けつつ、中継ルーチンの土台（バンク保存・復元・
呼び出しの型）を作る。空きが逼迫したら案Aで `l4_run_gen.asm` を追い出す
（モジュール境界が既にきれいなので移設コストが低い）。案Bは数値変換系の
呼び出し頻度・性能への影響を測ってからで良い。**ただしこれは下調べの
時点での見立てであり、決定ではない**（測定の要否は次節）。

## 6. 測定の要否 — 問いの候補（事前登録が要る前提。実施はしていない）

### 6a. 公式ROM不要 — 自作の試験ROMで確かめられる問い

- **Q1**: `0x71` に `EXT_ROM_NOT`（bit0）を落として書き、`0x32` の下位2bit
  を 0〜3 まで変えたとき、`0x6000` 番地の読み出し内容が
  期待どおり4本のバンクファイルを切り替えるか（エミュレータの実装は
  読んだが、実際に4本の異なる内容のバンクROMを用意して読み分けを
  確認していない）。
- **Q2**: バンクROMファイルが1本だけ存在しない場合（`N88_2.ROM`欠落等）に
  そのバンクを選択したときの読み出し値が本当に全バイト `0xFF` になるか
  （ソースからは読めたが実機・実エミュレータでの確認はしていない）。
- **Q3**: バンク切替中（`0x71`書き込み直後〜復元前）にVSYNC割り込みが
  発生した場合、ハンドラの実行と復帰が正しく行われるか
  （第5節・案Aのリスク見立ての検証）。IM2ハンドラは資料上RAM常駐なので
  影響は無いはずだが、**「はず」を測定で確かめる**（M4cと同種の
  `intlog` 計測が使える）。
- **Q4**: 中継ルーチン経由の呼び出し・復帰でCPUサイクル数がどの程度
  増えるか（案Bのリスク見立ての検証、PRINT文一回あたりのオーバーヘッド）。

### 6b. 公式ROM必要（I/Oログ観測） — 公式がどう使っているかの問い

- **Q5**: 公式ROMが `0x71`/`0x32` へ書く場面（ディスクあり・キー入力あり
  など条件を広げた測定）で、**メインROMの `0x6000`–`0x7FFF` を拡張ROM側へ
  切り替えて処理を実行しているケースが実在するか**（第1節「未確認」の
  解消）。存在するなら、どのタイミング（起動直後／辞書ROM参照時／
  disk BASIC実行時等）で、書き込み列がどんな定型になっているか。
  値の列そのもの（データポートの実データ）はコミット前に
  `tools/redact_iolog.py` で伏せる（CLAUDE.md 禁止事項5）。
- **Q6**: 公式が拡張ROM側へ切り替えている間、`main_rom[0x79d7]`
  （ROM_VERSION判定）をどう扱っているか（切替前に読み済みか、
  切替を戻してから読むか）——これは番地そのものへの言及になるため、
  **観測結果を「切替の有無」「前後関係」という構造的な事実としてのみ
  仕様書に書く**（`docs/PLAN.md`・第0節「pc=欄の扱い」と同じ扱い）。

いずれも実施前に事前登録（`docs/notes/l4-s*-preregistration.md` と同型の
形式）が要る。本ノートは候補の列挙に留め、実施はしていない。

## まとめ（事実 / 推定の再掲）

- **事実**: `0x32` 下位2bit＝拡張ROMバンク選択、`0x71` bit0＝拡張ROM
  有効/無効の総スイッチ（メーカー資料・Web資料・エミュレータ実装の
  3者が独立に一致）。拡張ROMファイルが無くても起動は止まらず
  `0xFF` 埋めになる（エミュレータソース）。WebQ88のコアは
  `N88_0〜3.ROM` を任意ファイルとして読む処理を既に持つが、
  PC88Behavior側の生成・WebQ88側の取り込みスクリプトは未対応。
  自作ROMは現在 `l4_run_gen.asm` のみが `0x6000` を跨いでおり、
  そのうち5,967バイトが窓の中にある。z80text にセクション/バンクの
  概念は無い。
- **推定（未確認）**: 公式ROMが実際に拡張ROMバンクへ処理を渡す場面が
  あるかどうか、バンク切替中の割り込み安全性、中継呼び出しの
  性能コスト——いずれも測定で裏を取っていない。
