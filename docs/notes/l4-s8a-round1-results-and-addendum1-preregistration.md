### 関門落ちの理由

- start-0 / start-137: 20個を一画面で採取し、標本1〜3が画面外へ流れた。
  両走とも番号4〜20の17個だけ。両待ち条件の採れた17個は完全一致するが、
  1〜20がそろう関門は満たさない。
- rerun: 各RUNの番号が1〜6になり、予定15個に対して18個。
  各ブロックの標本6は標本5と同値。登録プログラムは10行のFORの後にENDがなく、
  FOR終了後のj=6で900〜970行の記録処理へ流れ、残ったxをもう一度PRINTした。
  `other_line_counts` は各走 `[5,5,5]`。既存器具は `[5,5,5]` 個と
  各ブロック番号1〜5を要求するため、この余分な標本で落ちた。
  追補では20行のENDを明示する。元のmeasureの腕・出力は変更しない。

### 観察と限界

以下は自分で打ったプログラムがPRINTした値だけの記録である。
表記 `(e,h,l)` の値は正値なら `(h*4096+l)/2^24 * 2^e`。
零・負値はTSVの符号列も用いる。

| 腕・条件 | 観測例（先頭から最大3個） |
|---|---|
| 最初のRND(0) | (0,3324,1874) |
| RND(1)の後のRND(0)2回 | (-2,4016,286) が計3回 |
| 引数なし / 2 / 0.5 / 1E10、およびRUNの先頭 | (-2,4016,286), (-1,2498,2401), (-1,2554,3303) |
| RND(-1) / RND(-2)と後続 | (-1,2528,257), (-1,4086,3059), (0,2744,3446) |
| RND(-1.5)と後続 | (-1,2528,385), (0,2907,1530), (0,2699,47) |
| RND(-1)を連続2回と後続 | (-1,2528,257), (-1,2528,257), (-1,4086,3059) |
| RANDOMIZE 1.5 / RANDOMIZE 2 | (-4,2873,2522), (0,3651,1805), (0,3281,3978) |

RND(1)の最初の5個は、上表の3個に (0,2110,448), (-4,3821,2617) が続く。
引数なし・正引数各条件は採取した5個が同じ列。
待ち0 / 137フレームの番号4〜20は一致し、待ちで列が変わる証拠はない。
rerunの3ブロックそれぞれの先頭5個は一致し、RUNで列が先頭へ戻ることを
示す部分観察になっている。ただし両起動腕とrerun全体の関門落ちを免除しない。

RND(0)はRND(1)の直後の値を繰り返す。負引数-1と-2は初回も後続も一致。
-1.5は-1に比べ初回の下位lだけ128大きいが、後続は大きく変わる。
同じ負引数を繰り返すと同値が出る。RANDOMIZE 1.5と2の5個は同じ列。

小さい値にも非零の下位ビットがある。例えば起動列の番号12は
(-7,3582,4044)、番号14は(-9,3672,3888)。24ビット固定小数の格子から
正規化した値なら必要になる下位零が見られず、当初の24ビット固定小数状態を
そのまま返す候補と合わない。より広い状態から仮数を取る可能性はあるが、
これだけで状態幅・更新則は確定しない。

rangeは2000個で最小(-10,2628,3664)、最大(0,4095,3721)。
零、1、範囲外の計数はすべて0。有限標本の範囲観察である。

### 登録する26腕（各2走）

| 区分 | 腕数 | 操作・採取 |
|---|---:|---|
| 長い起動列 | 1 | 起動後最初のRNDからRND(1)400個。16個ずつ25画面 |
| 負引数の種応答 | 12 | RND(-x)1個と後続RND(1)10個、さらに入力xのPRINT1個 |
| RANDOMIZEの種応答 | 11 | RANDOMIZE n直後のRND(0)1個、後続RND(1)10個 |
| 修正版rerun | 1 | RUN3回の各5個、3画面。3回目はNEW後に記録器も再登録 |
| 修正版start-0 | 1 | 最初のRND(1)20個を10個ずつ2画面 |

負引数のxは 1, 1.5, 1.25, 1.125, 1+2^-23, 1+2^-16, 1+2^-8,
0.5, 4, 3, 1E-10, 65536。`1.0000001`という十進近似に依存せず、
器具はBASICで `y=1+1/8388608` として1の隣の単精度数を作る。
この腕の入力xのPRINTは `(標本0,符号1,e=1,h=2048,l=1)` を要求する。
これは入力操作の関門であり、RND値の予測ではない。各負引数腕では
標本0が正の入力x、標本1がRND(-x)、標本2〜11が後続10個。
仮数のどのバイトが状態のどこに影響するかを探索する。

RANDOMIZEのnは 0, 1, 2, 3, 255, 256, 257, -1, -2, -32768, 32767。
標本0が直後のRND(0)、標本1〜10が後続。整数の境界と符号を探索する。
RND(0)を挟んだ操作自体が登録条件であり、呼出しを省略した列と同一だと
事前に仮定しない。

長い起動列・start-0・種応答ではRUNを呼ばず、直接モードで採る。
「起動直後」は起動settleと記録器登録後の最初のRNDという当初の意味。
余分な待ちは0フレーム。rerunだけプログラムを使い、10行のFORの次に
`20 end` を置く。各RUNの番号は1〜5であり、RUN番号はページ番号で区別する。
総採取値は1走700組（RND688組、負引数の入力x12組）、53ページ。

### 器具・関門・出力

```sh
python3 tools/l4_rnd_measure.py measure-add1 \
  --rom-dir "$PC88_REF_ROM_DIR" --out ../tmp/l4s8a-work/official_add1.tsv --official
```

このコマンドは親が実行するための記載であり、本作業では実行しない。
作業ファイル置き場の既定は `../tmp/l4s8a-work`。
`--work-dir`で変更できる。打鍵は小文字。直接モードの行頭は数字にしない。
番号付き行は登録するプログラムだけに限定する。

各ページはCLSで前の画面を消し、PRINTの終了待ち後、次のCLSより前に採取する。
既存q88measureの上限は1プロセス16画面。そのため400個の腕では、
同じ起動・打鍵列を2プロセスで再生して画面1〜16と16〜25を採取する。
後者でもRNDは起動から400回連続で呼び、画面17のために種を途中で入れ直さない。
画面16のPRINT整数組の一致を継ぎ目の関門にする。これを各走で独立に行う。
他の25腕は各走1プロセス。再生ごとの生画面は抽出後または失敗時に削除する。
画面本文はTSV・標準出力・標準エラーに転記しない。

判定は採取関門と**2走一致のみ**。候補の予測列・agree/differ列は設けない。
ページ数、ページごとの標本番号と順序、件数、符号・指数・12ビット仮数の形式を
要求し、欠け・重複・余分な標本、入力最小差の不成立、打鍵・採取失敗、
再生境界の不一致、2走不一致はgate_failed。
長い列の番号は1〜400を通して使用する。rerunだけ、登録済みの別ページで
1〜5の再開を認める。値の規則への適合を関門に加えない。

TSVには腕名・走番号、打った行、ページごとの予定番号、連結したPRINT整数組、
ページ別PRINT整数組、その他の画面行の件数、関門・理由、実行予定フレーム数を記録する。
RND呼出しと画面分割の条件を登録時点で固定し、追補1の値に合わせて変えない。
既存の `measure` / `predict` の腕と出力形式は維持する。

### 自己検査

実行する検査は `tools/l4_rnd_selftest.sh` のみ。
自作ROMにRNDは未実装なのでRND測定の代用にしない。
区切り採取の陽性対照は、自作プログラムが定数0.75を36個PRINTする3画面を各2走。
番号付きの各行で1件ずつ出力し、ENDで記録器への流れ落ちを止める。
合成画面および実採取の整数組から標本を除去・境界で重複させる陰性対照を設ける。
合成検査ではページ欠落と、形式が正しくても値が2走で違う場合も拒否する。
当初の定数7腕各2走とGW固定値・陰性対照も維持する。

初回の検査では自作ROMのFOR/GOSUBの組合せで各画面の先頭1個しか採れず、
区切り採取関門が落ちた。検査プログラムを1標本1行の定数PRINTに修正した。
公式用の直接モードFORの採取可否は公式測定の採取関門で判断する。

25画面の合成採取では実際の実行引数と画面ファイルの読取り経路を通し、
各プロセスの採取数が16以下であること、連結後の番号1〜400、再生境界の
PRINT値を改変すると関門が落ちることも確かめる。
