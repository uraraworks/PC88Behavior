# m7cm — unreadable_diskエラー応答のbit6帰属

日付: 2026-08-24

## 目的と設計

`unreadable_disk`の同位置1バイト応答を、公式の応答値を読むことなく下流挙動から
帰属する。自作subが発行したREAD DATAが、公開μPD765のST0 IC=異常終了かつ
ST1 MISSING ADDRESS MARKで終わった場合だけ、交換#3型応答へ0〜255の候補を介入した。

探索順は暗号学的乱数seedでシャッフルし、候補と実行ordinalの対応を全走完了まで
表示しない。候補ごとに独立ROM・媒体複製・作業ディレクトリを使い、8並列で実行した。
先に`calibrate --frames 900`を通し、短縮窓でも既知の構造prefix=38と相対+6の
6対2が再現することを関門にした（校正3.8秒）。その後、同じ900Fで全256候補を完走した。

## 結果

最良群は256候補中ちょうど128個で、その集合は8ビット各片側集合との照合において
**bit6=0とだけ完全一致**した。bit6=0群は交換run構造が60件の全長一致、画面が
10行・215字・固定済みSHA-256署名と一致した。bit6=1群は交換prefix=38、画面3指標は
すべて不一致だった。

一方、bit6=0群でもFDCコマンド種別列はprefix=55で全長不一致だった。このため探索器の
`exact_match`（交換・画面・FDCのすべてを要求）は成立せず、`result=not_found`は正しい。
末端の交換構造と画面は一致し、内部のFDC発行列だけが残差として残った。

## 採用値と測定限界

測定が決めたのは**bit6=0という1ビットだけ**である。残る7ビットはこの条件では区別
できない。既定値は自作側の単純な選択として`0x00`（bit6=0、他7ビットも0）を採る。
これは公式と同じ値だという主張ではない。分かるのは、bit6=0の候補ならこの900F条件で
公式と同じ末端挙動になることだけである。再現用の`--error-response-candidate`は残す。

陰性対照として`--break-error-response-bit6`を追加し、既定値のbit6だけを1へ倒す。
`tools/verify_error_response_bit6_attribution.sh`は「既定の交換全長・画面一致」と
「故障注入版のprefix=38・画面不一致」を同時に要求する。合成selftestは判定器の
既定側と故障注入側をそれぞれ逆転させ、どちらも不合格になることを確認する。

## 情報境界と次の確認

探索結果へ保存したのは候補番号、交換runの向きと長さ、FDCコマンド名、画面の行数・
文字数・SHA-256だけである。公式応答値、FDC生値、画面本文、生iolog、私物のパスは
保存・記録していない。候補順は乱順・実行中非表示とし、由来の鎖を公式値へつながない。

900Fは探索用の短縮窓である。既定値の3000F末端一致と、diskA起動、FILES、LOAD、
seqfile、KILL、NAME、write_protect、no_disk、drive1、drive2への非回帰は未実走である。
また、no_diskで応答せず待つ制御構造と、unreadable_diskのFDC発行列差も未解決である。
