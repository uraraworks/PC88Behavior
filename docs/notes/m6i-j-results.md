## 2. 判定

- **`inconclusive_control_other`**。6位置の制御のうち、位置1〜3は候補が一意に残ったが、位置0がどの候補にも当てはまらなかった。
  - 位置1: `constant`、位置2: `constant`、位置3: `drive`、位置4・5: 論理トラック・R（事前登録どおり）。位置0: 候補なし。
- 読まれない送信: `inconclusive_unread_send`（腕の間で位置がそろわない）。

## 3. 観測（制御の値と順序。判定には使わない事後の読みを含む）

- 位置1は全 WRITE で `0x11`、位置2は全 WRITE で `0x01`、位置3はドライブ（ドライブ1で0、ドライブ2で1）。
- 位置0は、**`SAVE` の最初の WRITE（ディレクトリ）だけドライブと同じ値**、2回目以降の WRITE はすべて `0x06`。
- 1.35節（第67版）の「位置1〜5は通常の受信、6〜261は2バイト一組」と合わせると、**要求の本体は5バイト `[0x11, 0x01, ドライブ, 論理トラック, R]`** で、
  事前登録が6バイトのレコードと見た位置0は、前のやりとりの末尾か区切りの `0x06` と読める（事後の読み）。
- `SAVE ,A` の要求の順序（1セクタ・9セクタ、新規・上書き、ドライブ1・2で同じ形）:
  READ 割り当て表 (18,1,14)(15)(16) → READ 書き込み禁止の印 (18,1,13) → READ ディレクトリ (18,1,1) →
  WRITE ディレクトリ → WRITE 割り当て表 ×3 →［WRITE 本体1セクタ → WRITE 割り当て表 ×3］を本体のセクタ数だけ繰り返し、
  最後の割り当て表の3枚は WRITE の直後にそれぞれ READ で読み直す。READ は計8回、WRITE は 1セクタで8回・9セクタで40回。
- 書き込みの応答は各 WRITE に1バイト（`response_count` 1）。
