# m7lg: 読める媒体の場面では、公式もREAD DATAを繰り返さない（判定XA1）

実施日: 2026-09-11（10:09〜10:20）
事前登録: [m7lg-...-preregistration](m7lg-official-readable-retry-preregistration.md)
（**測定前に単独コミット済み**。場面・数え方・判定規則は本稿で動かしていない）

## 主判定

> **XA1。** **書き込み・LOAD・LOAD既存・drive1・drive2の5場面すべてで、公式一式の側の
> `READ DATA`の連続した対は0（最長連続1）。** 読める場面では、公式も1件ずつしか出さない。
> **採用した再試行（読めないときだけ粘る。読める場面では1件ずつ）と食い違わない。**

**陽性対照（読めない媒体）では、公式側で連続96対・最長9**——1.58節の×9がそのまま出ており、
**数え方は公式の繰り返しを拾える。**

## 測定の成立

| 項目 | 結果 |
|---|---|
| 1. 陽性対照Pで連続が0より大きい | **真（96対・最長9）** |
| 2. 決定論性（各場面の3つの数が2回で一致） | **真（12行すべて一致）** |
| 3. 6場面の公式側・混成側の生ログがそろう | **真（6場面×2側×2回）** |
| 4. `tools/check_cleanroom.sh` | 全項目OK。`src/`・`tools/`は変えていない |

公式一式の`SAVE`（書き込み経路の公式側。本稿で別に走らせたもの）は**2回ともWRITE DATAが8件**で、
適合テストの条件5の期待値と同じ件数まで届いている。適合テストは2回とも「適合」。

## 記述（事前登録していない。合否に使わない）

**6場面すべてで、採用した自作サブROMの`READ DATA`の件数・連続・最長が公式と同じだった。**
**ただしこれは`READ DATA`の件数の一致であって、発行したコマンド列やデータの一致ではない。**

## 言えること・言えないこと（事前登録で先に書いたとおり）

- **言えること**: 読める場面では公式も繰り返さず、読めない場面では繰り返す（1.58節）。**両方が
  観測された。** 採用した実装は、測った6場面で`READ DATA`の出し方が公式と食い違わない。
- **言えないこと**: **「公式は読めるか読めないかで粘るかを決めている」とは書かない。** その間を
  決めている規則は測っていない。**「9」を決める規則も、依然として書けていない。**
- **m7ksの(a)は、ここで答えが出た**——**公式は読める場面では粘っていない。** ただし(a)が当初
  説明しようとした回帰は、再試行とは無関係だった（m7kw〜m7lb）。

## 次に測ると効くこと（本稿ではやらない）

**まだ試していない失敗の原因がある**——**データのCRCエラー**。これまでに測った「読めない」は
「アドレスマークが無い（トラック不在）」と「セクタが無い（NO DATA）」の2種類だけである（m7jo）。
μPD765の公開仕様では、データのCRCエラーはデータを渡し終えてから結果フェーズで報告されうる。
**その場合`FDC_ABORT`は立たず、採用した実装は読み直さない。公式が読み直すなら、そこで食い違う。**
**これは「9を動かす軸」を探す新しい軸でもある。**

## 情報境界

公式ROM・公式ディスクのバイト列を読んでいない・出力していない。公式ディスクは`cp`で使い捨ての複製を
作り、書き込み可のフラグを立てただけ（適合テストの条件5と同じ扱い）。記録したのはFDCコマンドの
種別名と件数だけで、コマンドのバイト値・パラメータ・結果ステータスの生の値・時刻・frame番号・
画面本文は出していない。生ログはリポジトリ外（`PC88/tmp/m7lg-work/`）に置き、コミットしない。
