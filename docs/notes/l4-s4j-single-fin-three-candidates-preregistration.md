# l4-s4j — 単精度の定数読み取り（候補EXACT/GW/REP10） — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

`l4-s4i`（測定`8d76647`、補遺`3b2b01d`）で、対照C6
（`print 5.1e+10-51000000512`、予測0・実測4096）が食い違い、型のまとめ
は`other`として保留になった。その後、親が事後に当てた読み方`REP10`が、
`l4-s4i`で使った28腕すべて（候補・対照とも）を再現することが分かった
（`GW`は27腕を再現、`EXACT`は8腕のみ）。

`REP10`は**事後に既存観測へ合わせて立てた仮説**なので、`l4-s4b`の
H6・`l4-s4c`〜`l4-s4h`の各候補群を立てたときと同じ理由づけで、
`l4-s4i`の28腕を再利用せず、新しい式で前向きに検証する。

## 候補（定義）

- **`EXACT`**: 10進の値を単精度へ1回で丸める（`l4-s4i`と同一定義）。
- **`GW`**: GW-BASICの`$FIN`の手順（積み上げた整数を倍精度にし、倍精度
  の10のべき乗を**1回**掛け/割り、`$CSD`で単精度へ丸める。`l4-s4i`と
  同一定義）。
- **`REP10`**（新設）: 数字を先頭から1つずつ`acc = acc*10 + d`で積み
  上げ、**1手ごとに単精度へ丸め**、正味の指数`n`の分だけ10を掛ける
  （`n>0`のとき）／10で割る（`n<0`のとき）を**1回ずつ繰り返し**、
  **1手ごとに単精度へ丸める**。丸めは半分なら絶対値の大きい側
  （`l4-s4g`・`l4-s4h`で確定したのと同じ丸め方向）。符号は最後に
  適用する。

演算（単精度どうしの演算・単精度を倍精度へ広げる変換・倍精度の演算）
と書式は3候補共通で、仕様書`docs/spec/l4-basic.md`第3.5版
（`bcf6b46`）どおりとする。

## 腕（候補の式・対照、いずれも別担当が並行で作成中の表から取る）

- **候補の式（J1〜Jn）**: `docs/notes/l4-s4j-candidates.tsv`の全行の
  `typed`列を、表に現れる順のまま腕J1〜Jn（nは行数）として使う。
- **対照（K1〜Km）**: `docs/notes/l4-s4j-controls.tsv`の全行の`typed`
  列を、同様に腕K1〜Km（mは行数）として使う。

**両表とも中身（予測の列、および候補の式の`typed`列以外の内容）は
読まない・触らない。** 腕の総数・具体的な式は、両表がコミットされた
時点で機械的に決まる（本ノートの時点では特定しない）。

群（列`group`。`a`=10を掛ける側、`b`=10で割る側、`c`=単精度どうしの
演算）は表そのものに書かれている想定であり、本ノートでは値を書き写さ
ない。群ごとの一致数を結果ノートに記述する際は、この列をそのまま参照
する。

両表とも関門G6の対象とする（測定開始前のコミットに存在し、以後変更
されていないこと。**候補表・対照表のどちらか一方でも測定開始の時点で
存在しない場合、測定は始めない**）。

## 条件・器具

`l4-s4i`（`e41f0dc`）の「条件・器具」「本文を出さない取り扱い」
「関門」節をそのまま踏襲する。写しの時刻は全腕一律
`dump(k)=line_end(k)+300`とし、関門G8（後の写しにOk行が現れている
こと）を含めてG1〜G6・G8を適用する（G7は対になる予測表が無いため本
測定にも適用しない）。

```
line_end(k) = 700 + 8 * (その腕で打った文字数の累計、\n も1文字)
dump(k)     = line_end(k) + 300
run(k)      = dump(k) + 200
```

- 分類器は`5735eb3`の`tools/l4_s4a_float_classify.py`を使う
  （`l4-s4a`〜`l4-s4i`と同じ、二重実装しない）。
- 出力が`0`の腕も、他の腕と同じ規則で通常どおり照合する（`l4-s4i`と
  同じ扱い）。

## 記録する内容

`l4-s4a`〜`l4-s4i`本体の記録規則（腕ごとに、差分モードで得た「前が
空白だったセル」の(相対の行, 相対の桁, 文字コード)の並びと、原点セル
の絶対位置(row0, col0)を記録する）に加え、**次を新設する**。

- **`numeric_output`に分類された全腕の出力文字列を、結果ノートの表に
  必ず載せる。** `l4-s4i`で対照C6が食い違ったとき、実測の値（4096）
  そのものが本体の記録には残っておらず、後から補遺（`3b2b01d`）で
  測り直す必要が生じた（教訓）。同じ事態を防ぐため、本測定では最初
  から`numeric_output`の腕の出力文字列（数字・小数点・符号・指数記号
  の並びそのもの）を記録する。この記録は「本文を出さない取り扱い」
  節の許容範囲内（自分で打った式の直接の計算結果であり、l4-s4a以来
  一貫して出力を許してきた対象と同じ種類の値）である。`non_numeric_
  output`の腕は従来どおり件数と位置の範囲だけを記録する。

## 本文を出さない取り扱い

`l4-s4a`〜`l4-s4i`と同一。出力行の全セルの文字コードが「数字0-9・`.`・
`+`・`-`・`E`・`D`・空白」の集合に入る腕だけコードを記録し、1セルでも
集合外があれば件数と位置の範囲だけを記録する。分類器
（`tools/l4_s4a_float_classify.py`）は集合外のコードを標準出力・標準
エラーへ出さない設計であることが`5735eb3`の時点で確認済み。

## 関門

`l4-s4i`のG1〜G6・G8と同一。

- G1 器具の自己検査（本体と同一の自己検査群）
- G2 取りこぼし0・打てない文字の警告0
- G3 決定論性: 各腕2走とも写し・記録のsha256が一致
- G4 陰性対照: 何も打たない走で差分0件
- G5 陽性対照: `print 7717\n`腕で`7717`の並びを確認
- G6 候補表・対照表の固定: `docs/notes/l4-s4j-candidates.tsv`と
  `docs/notes/l4-s4j-controls.tsv`の両方が、測定開始より前のコミット
  に存在し、以後変更されていないことを`git log`で確認する。どちらか
  一方でも測定開始の時点で存在しない場合、測定は始めない
- G8 出力完了の確認: 「後」の写しで、出力行の後に`Ok`行が現れている
  こと（`ok_relative_row`相当の値が得られること）。現れない腕は
  `gate_failed`とし、「写しが早すぎた」とだけ記述する

## 判定

判定名は`l4-s4c`〜`l4-s4i`と同じものを使う。「記録する内容」節を参照
する。

- 腕ごとの分類: `numeric_output`/`non_numeric_output`/`gate_failed`
  （`l4-s4a`〜`l4-s4i`と同じ）。
- 候補ごとの判定: 各候補（`EXACT`・`GW`・`REP10`）について、**候補の
  式（J1〜Jn）と対照（K1〜Km）を合わせた全腕**で、予測文字列を出力行
  の相対桁0から置いたときの非空白セル(相対桁, コード)の並びが実測と
  完全一致すれば`candidate_consistent`、1腕でも一致しなければ
  `candidate_rejected`。`gate_failed`の腕がある場合、その候補は判定
  不能とし`other`とする（理由を記述）。対照は候補の判定に含める
  （対照が食い違えば候補も`candidate_rejected`になりうる）。
- 型のまとめ: `EXACT`・`GW`・`REP10`の3候補のうち`candidate_consistent`
  だった個数で決める。
  - **`unique_survivor`**: ちょうど1つ
  - **`multiple_survivors`**: 2つ以上
  - **`no_survivor`**: 0（3候補とも`candidate_rejected`）
  - `no_survivor`の場合も、`l4-s4c`〜`l4-s4i`と同じく**候補を後から
    足して判定し直すことはしない**。次の事前登録に回す。
- **対照が1つでも食い違った場合の扱い（`l4-s4i`と同じ規則）**: 対照
  （K1〜Km）のうち1腕でも実測が予測と食い違った場合、**候補の式
  （J1〜Jn）の結果を定数の読み取り方式を決める根拠には使わない**。
  この場合、型のまとめは算出せず**`other`**とし、「対照が食い違った
  ため判定を保留」と記述する。候補ごとの`candidate_consistent`/
  `candidate_rejected`自体は通常どおり記録する。
- **群ごとの一致数（新設、記述のみ）**: 判定そのものは全体（候補の式
  ＋対照を合わせた集合）で1つに決めるが、群`a`（10を掛ける側）・`b`
  （10で割る側）・`c`（単精度どうし）それぞれについて、候補ごとの
  一致した腕数を結果ノートに記述する（診断の手がかりとして残す。
  型のまとめの判定名には影響しない）。

## 器具の確認（公式ROMは使わない）

本ノートの作成時点（測定時HEAD`3b2b01d`）で、`docs/notes/
l4-s4j-candidates.tsv`・`docs/notes/l4-s4j-controls.tsv`のいずれも
まだコミットされていない。そのため、本ノートでは候補・対照いずれの
腕についてもエコー確認を行っていない。**器具の確認（自作ROMでの
エコー確認）は、両表がコミットされた後、測定の担当が行う。**

## 判定後の行き先

- `unique_survivor`なら、その候補（`EXACT`・`GW`・`REP10`のいずれか）
  を単精度の定数読み取り（`FIN`）の方式として確定する（仕様書への
  反映は本ノートの担当範囲外とする）。`REP10`が生存すれば、`l4-s4i`
  で対照C6が食い違った理由（1手ごとの丸めという事後仮説）が前向きに
  裏付いたことになる。
- `multiple_survivors`なら、生き残った候補どうしを区別できる式を次の
  事前登録で立てる。
- `no_survivor`なら、`EXACT`・`GW`・`REP10`のいずれでもない読み取り
  方式を次の事前登録で検討する入力とする。
- 対照が1つでも食い違った場合は、上記のいずれにもならず、共通経路
  （単精度どうしの演算・単精度→倍精度変換・倍精度の演算・PRINT書式）
  の再検証を次の作業の入力とする（`l4-s4i`と同じ扱い）。
