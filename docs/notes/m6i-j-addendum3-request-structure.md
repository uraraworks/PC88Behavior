## 1. 凍結する仮説

- **H1（WRITE の受信列）**: 各 WRITE DATA の直前に sub が受信した列の末尾は、`S, 0x11, 0x01, D, T, R` ＋256バイトのデータ部である。
  D はドライブ（ドライブ1=0、ドライブ2=1）、T は論理トラック C×2+H、R はセクタ番号。
  **S は、その `SAVE` の最初の WRITE では D と同じ値、2回目以降の WRITE では `0x06`**。
- **H2（要求順序）**: `SAVE ,A` 1回の READ/WRITE の順序は次のとおり（n は本体のセクタ数、本体は l3-disk-format 2.5節の割り当て順）。
  READ (18,1,14)(15)(16) → READ (18,1,13) → READ (18,1,1)〜ファイルのエントリのあるディレクトリのセクタまで →
  WRITE ディレクトリ（エントリのセクタ）→ WRITE (18,1,14)(15)(16) →（WRITE 本体 k → WRITE (18,1,14)(15)(16)）を k=1..n、
  ただし最後の (18,1,14)(15)(16) の3回は、各 WRITE の直後に同じセクタの READ が入る。
- **H3（応答）**: 各 WRITE に sub の応答が1バイトあり、main がそれを1回受け取る。

## 3. 判定

- 全腕・全走で H1〜H3 がすべて成り立てば **`write_request_structure_confirmed`**。
- どれかが成り立たなければ、成り立たなかった仮説と腕を記録し `inconclusive_structure`。候補を後から変えない。
- 読まれない送信は記録だけ残し、判定に使わない（自作 main が同じ送信をする必要があるかは、自作 main＋公式 sub の適合で確かめる）。

## 4. 凍結して残すもの（自作 main の適合の期待値）

各腕について、main が sub へ送った列のうち **sub が受信したもの**を、要求ごとに「区切り S・5バイトの要求・データ部の長さ」と、READ 要求の受信列（長さと値。値は制御の値として扱う）に還元して記録する。
データ部の値は記録しない（自作の本文との一致だけ）。この表を `docs/spec/l3-subrom.md` の新しい節（main 側の書き込み送信）に起こし、自作の書き込み送信の適合試験の期待値にする。
