# l4-s9d 追補1 結果 — 上限の受理境界と、第3引数が決める GOSUB の深さ

根拠: [事前登録](l4-s9d-addendum1-preregistration.md)（器具修正の追記を含む）。
公式ROMの測定は取り直し後の `official_add1b.tsv`（31腕×2走）。
画面本文は記録せず、自作PRINTの整数とERR番号だけを採った。

## 経緯

1. 1回目の追補測定（`official_add1.tsv`）は全体関門が落ち、大半が skipped だった。
   原因は器具で、既知3腕（e400・e800・stack-256）の打鍵が CLEAR を飛ばす既定腕の形
   （`10 goto 30`）になっていた。期待値（23270・ERR 5・14309）は1回目の観測そのままで、
   値は元から正しかった。
2. 器具を直し（known 腕を CLEAR 実行形 `10 goto 20` に）、腕・仮説・関門の定義は変えずに取り直した。
   これが `official_add1b.tsv`。

## 数え上げ

31腕×2走。関門5腕（定数対照2＋既知3）が通過し、観測26腕のうち skipped 0・採取失敗 0。
全31腕で2走の印列が一致した。FOR の5腕を除く25腕（関門通過）を
`tests/conformance/expected_l4_memlimit_add1.tsv` に固定し、
`tools/l4_memlimit_measure.py check` が rc=0（照合一致）を返した（check は腕IDの集合を
見るだけで追補にもそのまま使えた）。

## 腕1: 上限の受理境界（TSVで検算済み）

| a | 結果 |
|---|---|
| 0xE500・E580・E5C0・E5E0・E5F0・E5F8・E5FC・E5FD・E5FE・E5FF | 受理 |
| 0xE600・E601・E700 | ERR 5 |

- 受理10点すべてで `fre(0) = a − 35098` が成立（例: 0xE500→23526、0xE5FD→23779、0xE5FF→23781）。
  食い違いはない。
- 既定対照（CLEAR を飛ばす）の `fre(0)` は 23779 で、追補の形でも1回目と同じ。
  `clear ,&he5fd` の値と一致し、既定上限 0xE5FD の推定と整合する（直接の証明ではない）。
- **仮説 B_MAX（最大 0xE5FD）は棄却**。受理の最大は 0xE5FF（0xE5FE・0xE5FF は受理）。
  受理から拒否へ 0xE5FF/0xE600 で1点だけ切れた（観測した点の範囲では単調）。

## 腕2: 第3引数と GOSUB の深さ

GOSUB（`clear ,49152,n` の後、溢れは ERR 7。深さ d は成功した GOSUB の数）:

| n | 深さ |
|---|---|
| 64 | CLEAR 自体が ERR 7（深さ未測定） |
| 128 | 5 |
| 256 | 23 |
| 512 | 60 |
| 1024 | 133 |
| 第3引数なし | 60（n=512 と一致。既定はスタック512相当という1回目の推定を支持） |

差分: 128→256 は +18（128あたり。1段約7.1バイト）、256→512 は +37（約6.9）、
512→1024 は +73（約7.0）。**1段あたり約7バイト**。

当てはめ `d = floor((n − c) / 7)` は、c が 89〜92 のとき4点（128・256・512・1024）すべてで成立する
（各点の許容 c は [87,93]・[89,95]・[86,92]・[87,93] で、共通部分が [89,92]）。
定数 c と除数7は**推定**で、4点からの当てはめにすぎない（別の n では未検証）。
仮説 H_PROP は「比例」ではなく**一次式（切片あり）**として読む。ただし切片込みで
n を倍にした差が厳密に2倍にならないのは床関数の丸めの範囲に収まる。

## FOR の腕（測れていない）

全 n で ERR 26、深さ0。**FOR の深さは測れていない。器具の失敗**。
打った行を見ると、入れ子プログラムは FOR だけを開いて **NEXT を1つも書いていない**
（`for a0=0 to 0:l=1:for a1=0 to 0:...` と続け、行600の PRINT へ流れて END する）。
ERR 26 は FOR に対応する NEXT が無いときの誤りと推定され、深さを測る前にその誤りが
出た形になる。l=0 のまま誤りが出ているため、FOR 文の実行時に前方へ NEXT を探す方式か、
少なくとも本体の最初の代入より前に検出されている。NEXT を持つ入れ子（段数ぶんの NEXT を
行末に並べる）に作り直せば測れる見込みだが、これも推定で、本追補では取り直していない。

## 決めなかったこと

- FOR の入れ子の深さ（1段のバイト数・第3引数との関係）。
- GOSUB 以外の再帰（関数・ON GOSUB 等）。
- 下側の受理境界（0x8800 の ERR 7 と 0x8C00 の受理の間）の詳細。本追補は上側だけを詰めた。
- n = 64 で CLEAR が ERR 7 になる境界（64〜128 の間のどこか）。
- 定数 35098 や c≈90・除数7を自作配置で値まで合わせるか（配置の測定が別途要る）。
