# m7da: 起動時5635件の由来を公開D88仕様と構造測定で判定する事前登録

実施日: 2026-08-28

本稿は、`docs/spec/l3-subrom.md` 3節の区分Cに最後に残った「5635という
数値の由来」について、公開D88仕様との算術照合、到達条件、仮説、観測指標、
不合格条件を追加実測より先に固定する。**このコミットでは実測しない。**

## 背景と既知事実

- diskA起動を含む既存4条件で `sub OUT $FC` は厳密に5635件であり、起動直後の
  21フレーム（1秒未満）に一度だけ集中する。発行元PCは `709E` が5632件、
  `70E5` が3件で、単一の定常ループと境界3件に分かれる。
- 末尾73件は0パディングで、5635件目ちょうどで終わる。固定長枠を示唆するが、
  73はセクタ数やトラック数とはまだ対応付けない。
- diskA固有の経路であり、正常起動するdiskBでは同じ `sub OUT $FC` が0件である。
  従って全起動媒体に共通するサブROM単独の定数ではない。
- 交換#14直前のREAD DATAは256バイト単位で `1, 14, 16, 16, 2` セクタ、合計49
  セクタである。既存の全位置対応では第1 READ全体と第2 READ先頭4セクタを
  バルクへ配置せず、第2 READ第5セクタから第5 READ末尾まで44セクタを使う。
- m7ab時点では、先頭3件を除く各チャンネルの定常5632件をREAD 49セクタへ
  **無加工・同位置**で照合すると一致0件で、変換規則は未確定だった。その後m7acで
  両チャンネルを組に戻し、順序制約を加えた座標対応として全位置の規則が確定した。
- 両データポートを組に戻すと、定常部は `$FC`, `$FD` の順の交互配置である。
  第61版で確定した生成式は `$FC[i]=D[2i+1]`, `$FD[i]=D[2i+2]` である。
  各チャンネルの定常部は5632件、合算11264件で、末尾だけ直前の媒体位置を
  両ポートへ重複送出する。プリアンブルは各チャンネル3件である。
- 現HEADのdiskAでは第1チャンネル5635件、第2チャンネル全体6672件が公式・混成で
  全長一致する。第2チャンネルのうちバルク前779件、バルク中5634件、バルク後259件
  という区間構造も既存測定で確定している。従って6672全体を5635の倍数とみなさない。

## 公開仕様から得る定数

公開資料として、QUASI88の `document/FORMAT.TXT` と、公開GitHub文書
`yas-sim/floppy_image_library_d88_d77` の `README.md` を2026-08-28に確認した。
いずれもROM解析ではなくD88コンテナ形式の散文仕様である。

- D88ヘッダは `0x2b0 = 688` バイト。内訳は固定部32バイトと、164要素×4バイトの
  トラックオフセット表である。2Dではトラック番号0〜83を使用可能、84〜163は
  不在として0にする、とQUASI88文書は説明する。
- D88の各セクタ部は16バイトの記述部と可変長データ部からなる。トラック部は
  セクタ部の連結であり、**D88形式自体は1トラックのセクタ数もデータ長も固定しない**。
- PC-88の通常の2D媒体として用いる公開形状は1トラック16セクタ、1セクタ256バイト
  （FDCのN=1）である。従って媒体データだけなら1トラック4096バイト、D88上で
  16個のセクタ記述部も含むトラック部なら4352バイトである。
- 算術上、`5632 = 0x1600 = 22 * 256`、`11264 = 44 * 256` である。
  5632は媒体データ1トラック4096バイトとも、D88トラック部4352バイトとも一致しない。
  ただし `5632 = 4096 + 6 * 256 = 4352 + 5 * 256` という偶然一致候補は残す。

- <https://github.com/libretro/quasi88-libretro/blob/master/document/FORMAT.TXT>
- <https://github.com/yas-sim/floppy_image_library_d88_d77/blob/main/README.md>

## 仮説

### H1（既存測定で確定済み）: 44セクタを2チャンネルへ交互配置した片側長

交換#14の49セクタから、既存位置対応が除外した5セクタを引いた44セクタが
`44 * 256 = 11264` バイトとなり、2チャンネルへ交互配置して片側5632件となる。
そこへ境界用プリアンブル3件を加え、`3 + 5632 = 5635` になる。m7acで
11263/11264位置の連続一致と末尾1位置の直前座標重複まで確定済みであり、
本稿で未知なのはこの直接対応ではなく、44セクタという長さを選ぶ上流理由である。

### H2: 各チャンネル独立の22セクタ枠

5632を先に `22 * 256` と決め、各ポートが独立した22セクタを運ぶ。合算44セクタは
結果的に一致しただけで、両チャンネルを一つの連続媒体窓へ戻す必要はない。
m7acで単一の44セクタ連続窓への交互対応が全位置で確定したため、これは既に棄却済みである。

### H3: 1トラックを基礎にした媒体データ長

5632は、媒体データ1トラック4096バイトと追加6セクタ1536バイトの合計である。
トラック境界がカウンタの基礎で、22セクタ一致はその派生だとする。

### H4: D88コンテナ上のトラック部長

5632は、D88上の標準トラック部4352バイトと追加5セクタ分1280バイトの合計である。
ポート列へD88の16バイトセクタ記述部またはトラック部境界が混入するとする。

### H5: 媒体形状と独立した固定0x1600バイトのバッファ／カウンタ

5632は単に内部の固定長 `0x1600` であり、現媒体ではたまたま22セクタまたは
44セクタの半分と一致したとする。末尾73件の0パディングはこの仮説とも整合する。

## 到達条件と観測方法

判定は次の三段に分ける。どの段でもデータポート値は比較器のメモリ内だけで扱い、
標準出力とノートには件数、位置、座標、一致数、SHA-256、構造だけを出す。
本稿の焦点は、確定済みH1の44セクタ対応が**媒体形状の変更へ追随する**のか、
H5の固定 `0x1600` カウンタが不足分をパディングするのかを識別することにある。
従って新規実走の主目的は第3段であり、第1・第2段はその前提と対照を固定する。

1. **既存保存ログだけで行う値なし再集計。** 伏せ字済みの
   `measurements/m6g-d0-boot-run{1,2}.iolog.txt.gz` を使い、
   `tools/analyze_bulk_trigger.py` と `tools/analyze_second_channel_structure.py` で、
   5635が5632+3のPC別内訳を持つこと、両ポートがバルク中に隣接対を作ること、
   同一条件2走で件数と構造が一致することを再確認する。値が必要なH1〜H4の
   位置対応は伏せ字ログでは判定不能と明記し、0件や解析不能を合格にしない。
2. **介入の対照となる既存結果の再現確認。** 新規diskA走で
   `tools/analyze_exchange14_read_rules.py` を、公式ディスク由来値を表示しない
   既存モードのまま用いる。これは未知の規則を検証する段ではなく、m7acで確定済みの
   同一手法と結果が、第3段の介入直前にも再現することを示す対照である。交換#14のREAD長が
   1/14/16/16/2セクタ、バルクの各ポートが3+5632件、組へ戻した定常部が
   11264件であることを得る。第2 READ第5セクタから第5 READ末尾までの
   44セクタとの順序制約付き対応を、11263/11264位置の連続一致と末尾1位置の
   直前座標重複として再現する。run1/run2の2走を必須とする。
3. **主実験: H1とH5を識別する新規合成媒体介入。** 公開D88規則だけから作る自作媒体で、READの
   セクタ数またはEOTを変えた少なくとも2条件と対照1条件を用意する。媒体内容は
   規則生成し、公式ディスクから複製しない。観測量は5回のREAD長、選択された
   一意セクタ数、両ポートの定常件数、末尾パディング件数とする。起動経路へ
   到達せずバルク0件となった条件は介入不成立であり、H5の支持にも反証にも数えない。

新規走に入る前に、解析器の合成selftestで、3+5632の正常形、1件欠落、ポート対の
入替え、末尾重複の欠落、READ長を1セクタ変えた形をすべて識別する。故障注入は
全件検出・空振り0件を必須とする。

## 判定基準

- **H1再現確認の合格:** 新規diskA 2走の双方で、m7acが確定した (a) 49セクタ中
  5セクタ除外、(b) 残り44セクタ＝11264一意バイト、(c) 2チャンネルへの交互配置、
  (d) 片側5632件、(e) プリアンブル3件、(f) 末尾重複1位置、の六条件がすべて
  再現する。これは `3 + (44 * 256 / 2) = 5635` の新規確定ではなく、介入対照の合格である。
- **H1再現確認の不合格:** 44セクタ窓との対応に候補なし位置が1件以上ある、順序違反が
  1件以上ある、末尾重複で残差を説明できない、または2走の構造が一致しない場合。
  第3段へ進まず、環境差または解析器差を先に解消する。
- **H2:** m7acの単一44セクタ連続窓への交互全位置対応により棄却済み。再現確認で
  この対応が崩れた場合もH2を復活させず、まず対照不成立として扱う。
- **H3合格:** 出力の開始・折返し・終端のいずれかが4096バイト境界とREADの
  トラック境界へ2走とも一致する場合。単に `4096 + 1536 = 5632` だけでは不合格。
- **H4合格:** D88の16バイトセクタ記述部に対応するイベントが検出され、4352バイト
  境界がポート構造またはFDCデータ境界と一致する場合。全出力がFDCの256バイト
  データ部だけへ対応し、記述部0件なら棄却する。
- **H5合格:** 成立した媒体形状介入で選択セクタ数が変わっても定常部が各5632件を
  保ち、不足分のパディング件数だけが補償的に変わる場合。定常件数が
  `選択一意バイト数 / 2` に追随すれば棄却する。

複数仮説が算術上だけ成立しても、**全位置の順序対応を持つ仮説を優先**する。
H1の再現対照が合格し、H3/H4が境界一致を持たない場合、「1トラック由来」
「D88コンテナ長由来」とは書かない。H1とH5は既存diskAだけでは観測等価なので、
合成媒体介入が成立するまで
「44セクタ配置が現在の直接説明、固定カウンタの上流理由は未確定」として止める。

## 情報境界

- 公式ROM・公式ディスクは実行による測定だけに用い、バイト列を直接読まない。
  `private/` 配下を開かず、`xxd`、`od`、`hexdump`、`strings`、逆アセンブラを使わない。
- `$FB/$FC/$FD` の値列は、公式由来・自作候補由来を問わず表示、保存、ノート転記、
  コミットしない。生ログはリポジトリ外に置き、保存する場合は既存手順で伏せ字化する。
- 公開するのは件数、PC別内訳、セクタ座標の構造、位置対応の成立数、SHA-256、
  パディング長だけとする。公開D88仕様と公開FDC仕様は参照してよい。
- 本稿は判定基準の事前登録だけであり、実装および `docs/spec/` は変更しない。
