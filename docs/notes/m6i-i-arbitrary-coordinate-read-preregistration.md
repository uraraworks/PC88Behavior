# m6i-i — 任意座標の単一セクタREADを検証する — 事前登録

記録日: 2026-09-24  
状態: 測定前・**実装前**

## 0. 何を決める測定で、何を決めない測定か

m6i-a〜m6i-h は、自作 main から自作 sub への通常READを **既知の1座標
（論理トラック0・R=1）でしか**通していない。`MAIN_SUB_READ_KNOWN` は座標を
即値で焼き込んでいる。

本稿は、座標を入力として受け取る READ（以下「一般READ」）を**実装する前に**、
それが正しいと言える条件を先に固定する。**期待値は試験ディスクの像から
決まり、実装を見て決めない。**

- **決まること**: 自作 main の一般READ が、要求した (ドライブ, C, H, R) の
  セクタを、自作 sub（無改変）を通して正しく受け取れるか。
- **決まらないこと**: 公式 sub が何を要求するか。本稿は自作どうしの統合
  条件である（m6i-g 事前登録 §0 と同じ）。**`docs/spec/` へ規則を起こさない。**

要求の形そのものは既に公式の測定から仕様書に確定している。本稿はそれを
**使う**側であり、仕様を作る側ではない。

- 要求先頭 `0x02`・長さ5、末尾2バイトが `[論理トラック=C*2+H, R]`
  （`docs/spec/l3-subrom.md` 1.36節、公式 148 run で例外0件）
- ドライブ選択は要求 byte2 の bit0（同 1.46節）

## 1. なぜ今の試験ディスクでは検証にならないか

m6i-a〜h が使ってきた規則生成ディスク（`tools/make_l3_testdisk.py`）の
セクタ内容は

```python
def sector_pattern(cyl, sec):
    return bytes(((cyl*97 + sec*57 + i*7 + 13) & 0xFF) for i in range(256))
```

であり、**ヘッドにも、ドライブにも依存しない。** したがって:

- **ヘッド0とヘッド1の同じ (C, R) は中身が完全に同じ**である
- 同じ引数で作ったドライブA用とドライブB用のディスクは**バイト一致**する

このディスクで一般READを検証すると、**H を無視して読む実装も、ドライブ選択を
無視する実装も、期待SHA-256と一致して合格する。**

これは直前の実装（`b37cad0`）で捕まえた欠陥と同じ型である。あのときは
再試行が入力のドライブ選択を壊し、**必ずドライブAを読んで「成功」して
いた**。測定が `XOR A`（ドライブA）しか通していなかったので捕まらなかった。
**今回は、検査の側がドライブとヘッドを区別できない。**

さらに、式が `(k + i*7) & 0xFF` の形なので、セクタの中身はオフセット k
（256通り）で決まってしまい、**ディスク全体では中身の衝突が避けられない**。
一部の座標だけ区別できても、読み違えた先が偶然同じ中身なら合格する。

## 2. 試験ディスクを作り直す（既定の出力は変えない）

`tools/make_l3_testdisk.py` に**新しい内容規則を選ぶオプション**を足す。
**既定の出力は1バイトも変えない**（m6i-a〜h の凍結値
`normal_media_sha256 = d3becfe5…` を守るため）。

新しい規則では、**各セクタの先頭4バイトに自分の座標を書く。**

| バイト | 中身 |
|---|---|
| 0 | ディスク識別値（ドライブA用とB用で異なる値。凍結する） |
| 1 | C |
| 2 | H |
| 3 | R |
| 4〜255 | 座標から決まる規則的な詰め物 |

これにより:

- **ディスク全体（両ドライブ）のすべてのセクタが互いに異なる**ことが構成上
  保証される
- 受け取った256バイトの先頭4バイトを見れば、**実際にどの (ディスク, C, H, R)
  を読んだのか**が分かる。読み違えたときに**何を取り違えたか**まで診断できる

これは自作の規則で生成した合成ディスクであり、公式ディスクの内容は含まない
（`make_l3_testdisk.py` 冒頭の方針のまま）。

## 3. 期待値の決め方（実装から独立させる）

**期待値は、生成した D88 像を直接読んで決める。** 生成規則の関数を呼んで
期待値を作ると、生成規則と検証が同じ誤解を共有しうる。D88 の構造
（ヘッダ・トラック表・セクタごとの16バイトID）を読んで (C, H, R) が一致する
セクタのデータ部を取り出す小さな読み取り器を、検証側に**別に**置く。

- 期待値 = D88 像のうち、要求した (C, H, R) に一致するセクタのデータ部256バイト
- ドライブA用の読み取りはドライブA用の像から、B用はB用の像から引く

## 4. 腕（arm）

sub ROM は素のもの（`d8b2e64b…`）を使う。媒体は §2 の新規則で作った2枚
（ドライブA・B）。**全腕で同じ2枚を使う。**

### I-S `sweep` — 本測定

1回の走の中で、次の座標を**この順に**一般READで読む。初回の失敗は
m6i-h の結論どおり再試行1回で吸収する（一般READ用の再試行口を使う）。

| # | ドライブ | C | H | R | 狙い |
|---:|---|---:|---:|---:|---|
| 1 | A | 0 | 0 | 1 | 既知READと同じ座標（基準） |
| 2 | A | 0 | 1 | 1 | **H だけを変える**（H を無視すると #1 を読む） |
| 3 | A | 1 | 0 | 1 | C だけを変える |
| 4 | A | 0 | 0 | 16 | R の上端 |
| 5 | A | 39 | 1 | 16 | すべて上端（論理トラック79 = 0x4F） |
| 6 | A | 20 | 0 | 8 | 中ほど |
| 7 | A | 5 | 1 | 11 | 奇数の混在 |
| 8 | B | 0 | 0 | 1 | **ドライブだけを変える**（#1 と同座標） |
| 9 | B | 0 | 1 | 1 | ドライブBでもHを変える |
| 10 | B | 39 | 1 | 16 | ドライブBの上端 |
| 11 | A | 0 | 0 | 1 | **B を読んだ後に A へ戻る**（#1 と同座標） |

#2・#8・#11 は、**直前の座標と1軸だけ違う**ように並べてある。どれか1軸を
無視する実装は、その行で直前と同じ中身を返すので必ず捕まる。

### 故障注入腕（測定そのものの検出力を示す）

一般READ の実装に**わざと**次の欠陥を1つずつ入れた版を作り、I-S と同じ
座標列を走らせる。**それぞれが不一致として検出されなければ、本測定は
その種の誤りに対して盲目である。**

| 腕 | 注入する欠陥 | 必ず不一致になるべき行 |
|---|---|---|
| I-F-H | 論理トラックを `C*2` にする（H を無視） | #2, #5, #7, #9, #10 |
| I-F-D | ドライブ選択を常に0にする | #8, #9, #10 |
| I-F-R | R を1ずらす | すべての行 |
| I-F-RETRY | 再試行時にドライブ選択を0に戻す（`b37cad0` 以前の型） | 再試行が起きた行のうち、ドライブBのもの |

I-F-RETRY は再試行が起きた行にしか効かない。再試行がドライブBの行で
起きなければ検出できないので、**この腕は「再試行がドライブBの行で起きた
ときに限り」検出力の証明として数える**。起きなかった場合は「I-F-RETRY は
本測定の条件では踏まれない」と記録し、合格扱いにも不合格扱いにもしない。
（再試行口がドライブを保つことは、別途 Z80 実走の単体検査で押さえる。
§6 G7。）

## 5. 到達指標と結果条件

### 到達（I-S・故障注入腕とも）

- 11行すべてで一般READ が呼ばれ、256位置を受け取った（成否は問わない）
- 呼び出し順が上の表の順である
- 2走の結果が一致する

### 結果（行ごと）

- `row_match`: 受け取った256バイトが、§3 の期待値と**バイト単位で一致**する
- `row_mismatch`: 一致しない。このとき先頭4バイトから読んだ (ディスク, C, H, R)
  を記録する（診断用。値は自作合成ディスクの座標であり公式データではない）

## 6. 関門（gate）

いずれかが偽なら腕へ進まず `gate_failed`。

- **G1** `tools/run_all_selftests.sh` が rc=0。
- **G2** `tools/check_cleanroom.sh` が rc=0 かつ NG 0件。
- **G3 既定の試験ディスクが変わっていない**: 既定引数（m6i-a〜h と同じ引数）で
  生成した像の SHA-256 が `d3becfe5051f7002d268824a2da2824f543442e71ae3226e4d22139e0adce05c`
  のままである。
- **G4 新しい試験ディスクの一意性**: 2枚の像について、**両ドライブを通した
  全セクタのデータ部が互いに異なる**ことを、§3 の D88 読み取り器で全数
  確認する。**§1 の穴を塞いだことを、測定の前に像の側で示す関門である。**
  陰性対照として、旧規則（`sector_pattern`）で作った2枚ではこの検査が偽になる
  ことを示す。
- **G5 期待値の独立性**: 期待値の取り出しが、生成規則の関数を呼ばずに
  D88 像のバイト列だけから行われていることを、生成規則の関数を壊した状態でも
  期待値が変わらないことで示す。
- **G6 sub 無改変**: 全腕の `DISK.ROM` が素のサブROM（`d8b2e64b…`）と
  バイト一致する。
- **G7 再試行口の引数保存**: 一般READ用の再試行口が、再試行時に
  **ドライブ・論理トラック・R の3つすべて**を2回目の呼び出しへ届けることを、
  Z80 実走（`tools/l4_mbf_conform.py` と同じやり方、呼び先スタブで引数を記録）
  で確かめる。3つそれぞれについて、壊した版で検査が落ちることも示す。
- **G8 既存成果物の不変**: `--enable-main-sub-read` 単独の `N88.ROM` が
  `7646c2d418dc9f33f30670b9638368fcfb5614e67ec26000cdd7c4106b258f5d`、
  `--enable-disk-read-retry` のビルドも本稿の実装前と同じ SHA-256 である。
  **既存の `MAIN_SUB_READ_KNOWN` と `MAIN_SUB_READ_KNOWN_RETRY` は変更しない。**
- **G9 凍結**: 座標列・故障注入の対応表・ディスク識別値・判定名を測定前に
  器具の設定ファイルへ固定し、本稿と違えばエミュレータ起動前に `gate_failed`。
- **G10 到達判定の自己汚染検査**: 到達判定が、走によって書き換えられうるもの
  を参照していない（m6i-d の G8 と同じ）。

## 7. 判定名

- `gate_failed` / `unreached`
- 腕ごと: `sweep_all_match`（I-S の11行すべて `row_match`）／
  `sweep_mismatch`（1行以上 `row_mismatch`）
- 故障注入腕ごと: `fault_detected`（§4 の表の「必ず不一致になるべき行」が
  すべて `row_mismatch`）／`fault_missed`（1行以上が `row_match`）／
  `fault_not_exercised`（I-F-RETRY で再試行がドライブBの行に起きなかった）

総合判定:

- `m6i_i_general_read_verified`: `sweep_all_match`、かつ I-F-H・I-F-D・I-F-R が
  すべて `fault_detected`。
- `m6i_i_general_read_wrong`: `sweep_mismatch`。どの行で何を取り違えたかを記録する。
- `m6i_i_measurement_blind`: I-F-H・I-F-D・I-F-R のいずれかが `fault_missed`。
  **I-S が合格していても、その合格は検証として数えない。**
- `m6i_i_inconclusive`: 関門は通過したが1腕以上 `unreached`。

I-F-RETRY は総合判定に入れない（§4 のとおり踏まれない場合があるため）。
結果は別に記録する。

## 8. 判定後の行き先

- `m6i_i_general_read_verified`: 一般READ を BASIC 側の接続（ディレクトリ
  読み出し、FILES）へ使ってよい。次の稿で BASIC からの経路を測る。
- `m6i_i_general_read_wrong`: 取り違えた軸を先頭4バイトの診断から特定し、
  実装を直して**同じ事前登録で**取り直す。
- `m6i_i_measurement_blind`: 実装ではなく**検証を**直す。見えていない誤りの
  種類を特定し、座標列かディスク規則を追補で直してから取り直す。
- `m6i_i_inconclusive`: 到達器具だけを直す追補を先に置く。

## 9. 本文に出さないもの

- 画面本文、main↔sub のデータポート値列は出さない。件数・真偽・SHA-256・
  判定名・座標だけを扱う。
- 受け取ったセクタの先頭4バイトから読む座標は、**自作合成ディスクに自作の規則
  で書いた値**であり、公式ディスク由来ではない。診断に使ってよい。

### この測定で決まらないこと

- 公式 sub が何を要求するかは決まらない（§0）。
- 複数セクタREAD、WRITE、BASIC 命令からの経路は決まらない。
- 座標列の11行以外の座標で正しいことは、規則として主張しない
  （軸ごとに1軸だけ変える並びにしたので、軸を無視する型の誤りには
  強いが、特定の値だけで起きる誤りは網羅していない）。
- 再試行が「どの行で」起きるかは決まらない。起きた行を記録するだけである。
