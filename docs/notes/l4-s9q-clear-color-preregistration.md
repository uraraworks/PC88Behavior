## 目的

1. **CLEAR 第2引数の下限境界**。既知（l4-basic 20.1）: `clear ,&h8400` は誤り5、`&h8800` は誤り7、`&h8C00` は受理。
   境界の番地を数値で決め、本文の長さ・文字列変数・配列・第3引数（スタック域）・第1引数（文字列領域）で動くかを振って、**境界を式で書く**。
2. **COLOR の第2〜第4引数**の受理範囲・誤り番号、そして I/O ポートへの効果。s9p の観測（`color 3,1,1,2`＝誤り5、`color 3,0,0,6`・`color 2,3`・`color ,3`・`color ,,,5` は受理、`color ,8`＝誤り5）が出発点。

## 読んだ資料（(a) 種別・言語仕様のみ）

- `refs/NEC PC-8801mkIIMR N88-BASIC N88-日本語BASIC REFERENCE MANUAL 1986年.pdf`（判定「可」、refs-nec-manuals-2026-09-04.md）。
  ページ画像（`pdftoppm -r 60〜80`）で読んだ PDF ページ: **9**（目次先頭）・**11**（基本命令の索引。CLEAR は 2-23、COLOR は 2-29）・**105・106**（印字 2-23・2-24、CLEAR 文）。
  COLOR の頁（PDF 111・112、印字 2-29・2-30）は s9p で読み済みで、今回は読み直していない。
- CLEAR の頁から分かった言語仕様（表現は写さず事実だけ）: 書式は `CLEAR [文字列領域の大きさ[,メモリの上限]][,スタックの大きさ]`。
  文字列領域の大きさは**意味を持たず指定しても影響しない**（必要な領域は自動確保）。メモリの上限は BASIC が使う番地の上限で、それ以降のデータや機械語は壊されない。
  スタックの大きさは FOR・GOSUB・PAINT 等が使う域のバイト数で、リセット直後は 512。スタックは上限から番地の小さい方へ取られる。変数は全て初期化され配列宣言も無効になる。
  **下限境界・誤り番号はこの頁に書かれていない**（測定で決める）。
- COLOR の第2〜4引数は s9p の読みどおり（背景色・ボーダ・前景色。グラフィック画面側の指定でテキスト属性ではない、白黒モードでは 0〜7 の範囲）。
- **ハードウェア資料・GW-BASIC の公開ソースは今回は開いていない**。ハードウェア資料は Web ページで、カバー・まえがきが無く、判定係（使い捨てのエージェント）を先に立てる手順が要る。
  背景色・ボーダは I/O ポートで観測できるが、**ポートの意味は資料に頼らず測定で採る**（どのポートが動くかを基準腕との差で見る）。予測にポート番号の意味は使わない。

## 測り方（画面本文を扱わない）

器具 `tools/l4_clearcolor_measure.py`（s9d・s9p の型）。打ち込むのは自作のプログラムだけで、採るのは自作の印字（印・整数）と、制御ポートの書き込み列だけ。

### 複数プローブ方式（CLEAR・COLOR の誤り番号）

1回の走行に複数のプローブ（文）を直列に並べ、1プローブ=2行にする。

    5   on error goto 950
    10  print "s9qa";1;1
    100 e=0:<文>                       ← CLEAR のときは `clear ,&hXXXX[,n]`
    101 on error goto 950:print "s9qr";i;e;fre(0)
    ... （i=1..N）
    900 print "s9qd";1;1:end
    950 e=err:resume next
    cls / run

文が誤りなら 950 が `e` に誤り番号を入れて次へ進み、101 が「プローブ番号・誤り番号（0＝誤りなし）・`fre(0)`」を出す（CLEAR は成功すると変数を 0 にするので `e` も 0）。
成功した CLEAR は ON ERROR を解除すると読めるため 101 で張り直す。1走行のプローブは 20 以内（画面が 25 行のため）。
**複数プローブが単独走行と同じ結果を返すこと**を関門にする（下記）。印は自作の印字だけを `s9q[ard]` の形で読む（画面本文は採らない）。

### CLEAR 境界の探索（k分探索）

`cl-*` の各条件で、プローブの先頭と末尾は**アンカー** `clear ,&hE000[,n]`（受理されるはず）、その間 14 本が可変プローブ（`cl-n10` は 8 本）。
アンカーの `fre(0)` から **T = 0xE000 − fre(0)** を取る（s9d で `fre(0) = 上限 − 定数` の傾き1。T は本文・スタックの合計を表す）。
走行ごとに可変プローブの上限値を変えて、境界を挟む区間を k 分割で絞る（粗い格子 0x8000〜0x9A00 を 0x200 刻み → 各境界 7 本ずつ → … → 幅1）。
採るのは次の数値（番地は16ビットなので数値印そのもの）:

- **b5**: 誤り5でない最小の上限（それ未満は誤り5）。
- **b7**: 受理される最小の上限（b5 以上 b7 未満は誤り7）。
- **m = fre(0) at b7**: 受理の最小の上限で出る `fre(0)`（実装は「予測の fre(0) がこれ以上なら受理」と書ける）。

最後に境界の両側（b5−1・b5・b7−1・b7）と、各領域の内部（0x8000、b7+0x200、0xE5FF、0xE600）の検証走行を行う。
単調性（誤り5 → 誤り7 → 受理の順）が全プローブで成り立つこと、受理プローブでは `fre(0) = 上限 − T`（傾き1）が成り立つこと、先頭アンカーと末尾アンカーの T が等しいこと（失敗プローブが後続に影響しない）を関門にする。

### 腕

**CLEAR の探索条件（各 2 反復＝2 回の独立な探索。反復の全プローブ列の一致が関門）**
- `cl-base`: 本文 = 上の枠＋プローブ16本。
- `cl-n10`: プローブ10本（本文が短い）。
- `cl-padrem`・`cl-padrem2`: base に `rem` 行を足して本文を約 800 / 2400 バイト伸ばす。`cl-paddata`: padrem と同じ長さを `data` 行で（内容の種類が効かないことの確認）。
- `cl-stk128`・`cl-stk256`・`cl-stk1024`・`cl-stk2048`: プローブの CLEAR に第3引数 n を付ける（`clear ,&hXXXX,n`）。
- `cl-str1000`・`cl-str20000`: 第1引数を付ける（`clear 1000,&hXXXX`）。
- `cl-var`: 各 CLEAR の直前に文字列変数を代入しておく（変数がある状態での CLEAR）。
- `cf-arr500`・`cf-arr3000`: プログラム先頭で `dim a(500)` / `dim a(3000)`（2KB / 12KB）。CLEAR は配列を消すので、**最初のプローブだけ**が配列のある状態で走る。
  base の b5・b7・m から作った予測値 b5−1・b5・b7−1・b7（T は同じ走行のアンカーから取る）を最初のプローブに置いた 8 走行（アンカーは2本目）。

**CLEAR の文の種類（`cv-*`、複数プローブ方式、2走）**: `clear`（引数なし）、`clear 0`・`1000`・`20000`・`65535`・`-1`・`70000`、
`clear ,&hE000,n`（n = 0・64・72・80・88・96・104・112・120・124・126・127・128・129・1024・32767・-1・32768）、`clear ,,128`・`clear ,,64`（上限を省略）。

**COLOR の誤り番号（`co-*`、複数プローブ方式、各チャンクの先頭に参照 `a$=chr$(300)`・`a$=1`）**:
- 単独位置: 第2・第3・第4引数に v = -1・0・1〜9・255・256 を1つだけ置く（`color ,v`・`color ,,v`・`color ,,,v`、39文）。
- 4引数の格子 `color 3,b,bo,fg`（b・bo・fg ∈ {0,1,2}、27文）。`color 3,1,1,2` が誤り5になる理由を絞る。
- 部分形 `color 3,1,1`・`color 3,1`・`color 3,,1`・`color 3,,,2`・`color ,1,1`・`color ,,1,2`・`color ,1,,2`、
  非整数・文字列 `color ,2.5`・`color ,,,2.5`・`color ,"a"`・`color ,,"a"`・`color ,,,"a"`、対照 `color 0`・`color 7`。

**COLOR のポート効果（`cp-*`、各腕は単独走行 2走）**: 本文は `print "s9qa"`、`on error goto` の枠、`20 <文>`、`print "s9qd"`。
`run` を打ってから写しを取るまでの窓の、**メイン側 OUT のうち次のポートの書き込み値列**（連続同一は畳む、件数は採らない）を採る:
0x30・0x31・0x32・0x34・0x35・0x52・0x53・0x54〜0x5B（システム制御・表示制御・背景・パレット。いずれも制御ポートで、禁止事項5のデータポートに当たらない。s9o・s9p と同じ判断）。
腕: 基準 `rem`、`color ,b`・`color ,,b`・`color ,,,b`（b=0〜7、24腕）、`color 2`・`color 7`、陽性対照 `out &h52,&h40`。

各腕2走。腕数（走行数でなく腕）: cl 12条件 + cf 2 + cv ≈ 2チャンク + co 6チャンク + cp 28 腕。

## 関門

2走（CLEAR の探索は2反復）の観測が完全一致、アンカー（`cl-*`・`co-*` の参照）で採取が成立していること。
- **CLEAR 較正**: 複数プローブ方式が s9d の既知値を再現すること（`cv` のチャンクに `clear ,&h8400`＝5・`&h8800`＝7・`&h8C00`＝受理を含め、`cl-base` の探索で 0x8400 は誤り5・0x8800 は誤り7・0x8C00 は受理になること）。
  アンカーが先頭・末尾で同じ T、受理プローブで傾き1、全プローブが単調。
- **COLOR 較正**: 各チャンクの参照 `a$=chr$(300)`＝5・`a$=1`＝13 が採れること。`cp` は基準走で `s9qa`・`s9qd` が採れ、窓内に CRTC（0x50/0x51）の書き込みがあること、陽性対照が 0x52 に 0x40 を示すこと。
- 関門が落ちたら、**器具を曲げず追補の事前登録を先にコミット**してから再測定する。
- 自作ROMでの既知値対照（selftest）: 合成の写し・合成のポート記録で解析と判定の陽性・陰性、自作ROMで `cv`（`clear ,&h8400` 等）と `cp` 基準を通す。
