# m6i-d — m6i-b の各腕で停止ゲートが解除されたかの監査 — 事前登録

記録日: 2026-09-23  
状態: 測定前

[m6i-c 結果](m6i-c-b5-b6a0-divergence-results.md) は、m6i-b の B5 が示した
timeout が、測定のために置いた sub 側スピンゲートが解除されなかったことに
よる器具の副作用だと確定した。その後の確認で、**同じ停止ゲートの生成ヘルパ
`_emit_m6ib_release_gate` を B1・B2・B3・B4・B5 の5腕すべてが使っている**
ことが分かった。置かれる場所だけが違う。

| 腕 | ゲートの位置 |
|---|---|
| B1 | リセット直後（`M6IB_B1_RESET_GATE`） |
| B2 | FDC 初期化の手前（`M6IB_B2_BEFORE_FDC_GATE`） |
| B3 | 初期化7 batch の後（`M6IB_B3_AFTER_INIT_GATE`） |
| B4 | ラウンド#0の手前（`M6IB_B4_BEFORE_ROUND0_GATE`） |
| B5 | ラウンド#0の後（`M6IB_B5_AFTER_ROUND0_GATE`） |

**ゲートは一律に致命的ではない。** m6i-b で B2 と B4 は256位置一致で成立して
おり、それらのゲートは解除されている。解除されなかったことが確かめられて
いるのは B5 だけである。**まだらに効くので、腕ごとの状態の違いに見える。**

本測定は、**どの腕のゲートが解除され、どの腕が解除されなかったかを測る**。
測定対象は自作 main と自作 sub だけであり、公式 ROM は使わない。

## 1. 問い

m6i-b の B1〜B5 の各腕について、sub 側の停止ゲートは解除されたか。

副問は、解除されなかった腕があるとき、**m6i-b のどの結論が生き残るか**である。
とくに次の2つが賭かっている。

- **B1 の陰性対照。** B1 は「sub をリセット直後で停止し、状態を進めずに
  60フレーム待ってから解除と同時に READ を出す」腕であり、その timeout を
  根拠に m6i-b は「**待ち時間だけで初回問題が消える**という説明は否定された」
  と書いた。**ゲートが解除されなければ sub は再開しない。** そのとき出る
  timeout は状態の話ではなく器具の話であり、この陰性対照は成立していない。
  m6i-b が出した結論のうち、いちばん強く効いていたものである。
- **B2・B4 の成立。** m6i-b は B2（起動専用送信の消化のみ）と B4（初期化＋消化）
  が成立したことから「起動専用送信の消化が効いている形である」と書いた。
  両腕が解除されているなら、この観察は器具の副作用ではない。

## 2. 腕（arm）

**ROM は m6i-b のものを1バイトも変えずに使う。** 観測は
[m6i-c 追補1](m6i-c-addendum1-gate-observation.md) と同じく、既存の I/O ログの
構造からのみ行う。マーカーも探針も足さない。

腕は m6i-b の7腕をそのまま再走させる。

| 腕 | ゲート | 役割 |
|---|---|---|
| D-B1〜D-B5 | あり | 監査対象 |
| D-B0 | なし | 陰性対照（前置きなし・ゲートなし） |
| D-B6-A0 | なし | 陰性対照（`b→a→c` 前置きあり・ゲートなし） |

各腕2走。走らせ方・フレーム数・媒体・打鍵は m6i-b の凍結値をそのまま使う。

### 到達指標（7腕共通）

- 腕の ROM 一式が、m6i-b の対応する腕のものとバイト一致する
- I/O ログが伏せ字化されておらず、sub の行が1件以上ある
- 2走の判定が一致する

**m6i-b の結果条件（256位置一致・期待SHA・要求run）を到達指標に入れない。**
本測定が問うのはゲートの解除だけであり、通常READの成否は問わない。

### 観測（m6i-c 追補1・追補2 の定義を引き継ぐ）

- **sub run**: I/O ログの sub 行だけを時刻順に並べ、`IN $FE` が連続する区間。
  sub の別ポートの I/O で切れる。main 側の行は切らない。
- **ゲート run**: 長さが `gate_run_min_length`（32）以上の sub run。
  **m6i-c と違い、走の全区間を対象にする**（腕ごとにゲートの位置が違うため、
  ラウンド#0応答を基準にできない）。
- `gate_entered`: ゲート run が1本以上ある。
- `gate_released`: **最後の**ゲート run の終端より後に、sub の `$FE` 以外の
  I/O が1件以上ある。
- ゲート run の本数と最大長も記録する。

## 3. 関門（gate）

いずれかが偽なら測定腕へ進まず、全体を `gate_failed` として止める。

- **G1 自己検査**: `tools/run_all_selftests.sh` が rc=0 で終わる。
- **G2 クリーンルーム検査**: `tools/check_cleanroom.sh` が rc=0 かつ NG 0件。
- **G3 凍結値**: 媒体SHA・フレーム数・反復数が m6i-b の凍結表と一致する。
  `gate_run_min_length` = 32 が m6i-c の凍結表と一致する。
- **G4 ROM 同一性**: 7腕の ROM 一式が、`tools/check_m6ib_rom_gate.py` の
  検査を通る。**m6i-b の ROM と同じものを使っていることを、成果物の側から
  示す。** 通らなければ腕へ進まない。
- **G5 観測の検出力**: 合成入力で、次の3つを別々に識別することを確認する。
  ゲート run なし／ゲート run があり解除される／ゲート run があり最後まで
  解除されない。**m6i-c の自己検査で使った合成入力を再利用してよいが、
  「走の全区間を対象にする」定義へ変えたぶんは作り直す。**
- **G6 陰性対照の事前確認（測定中）**: ゲートを持たない D-B0・D-B6-A0 で
  ゲート run が0本であること。これは関門ではなく帰属条件として扱う
  （次節の `m6i_d_observation_unusable`）。
- **G7 未確定値の凍結**: 腕名・判定名・`gate_run_min_length` を測定前に
  器具の設定ファイルへ固定し、本稿と違えばエミュレータ起動前に
  `gate_failed` で止める。

## 4. 判定名

判定は関門、到達、観測の順で付ける。2走が一致しない腕は `unreached`。

- `gate_failed`: G1〜G5・G7 のいずれかが偽。
- `unreached`: 関門通過後に腕の到達指標を満たさない。
- 腕ごと（D-B1〜D-B5）:
  - `arm_gate_released`: `gate_entered` が真かつ `gate_released` が真。
  - `arm_gate_never_released`: `gate_entered` が真かつ `gate_released` が偽。
  - `arm_gate_not_entered`: `gate_entered` が偽。**ゲートを持つはずの腕で
    これが出たら、観測かROMの取り違えを疑う。**
- 陰性対照（D-B0・D-B6-A0）:
  - `control_no_gate_run`: ゲート run が0本。期待どおり。
  - `control_gate_run_observed`: ゲート run が1本以上。観測が使えない。

総合判定は、D-B0・D-B6-A0 がともに `control_no_gate_run` であり、
D-B1〜D-B5 がすべて到達していることを共通の前提とする。

- `m6i_d_observation_unusable`: 陰性対照のいずれかで
  `control_gate_run_observed`。**帰属をしない。** `gate_run_min_length` が
  通常のポーリングを拾っている。
- `m6i_d_inconclusive`: 関門は通過したが、1腕以上が `unreached` である。
- `m6i_d_only_b5_never_released`: D-B5 だけが `arm_gate_never_released` で、
  D-B1〜D-B4 はすべて `arm_gate_released`。**m6i-b の汚染は B5 に限られる。**
- `m6i_d_b1_control_void`: D-B1 が `arm_gate_never_released`。
  **m6i-b の陰性対照は成立していない。** 他腕の結果にかかわらずこの判定を付け、
  下の `m6i_d_multiple_arms_never_released` とは併記する。
- `m6i_d_multiple_arms_never_released`: `arm_gate_never_released` の腕が
  2つ以上ある。どの腕がそうだったかは結果として記録するが、組み合わせごとの
  判定名は作らない。
- `m6i_d_no_arm_never_released`: D-B1〜D-B5 がすべて `arm_gate_released`。
  **m6i-c の結果と食い違う**（m6i-c は B5 と同じ sub ROM を持つ C0・C3 で
  `gate_never_released` を観測している）。この場合は器具の取り違えを疑い、
  m6i-c と本測定のどちらが誤っているかを別稿で切り分ける。**m6i-c の結果を
  この判定で上書きしない。**

副問の帰属は総合判定と独立に記録する。

- `m6i_b_b2_b4_survive`: D-B2 と D-B4 がともに `arm_gate_released`。
  m6i-b の「起動専用送信の消化が効いている形である」という観察は、
  ゲートの副作用では説明されない。
- `m6i_b_b2_b4_do_not_survive`: D-B2・D-B4 の一方以上が
  `arm_gate_never_released`。

## 5. 判定後の行き先

- `m6i_d_only_b5_never_released`: m6i-b のうち汚染されたのは B5 だけである。
  **B5 相当の腕だけをゲートなしで取り直せば、境界判定7種を再構成できる。**
  取り直しは別稿（m6i-e）で事前登録する。m6i-c の C2 が既にその条件で
  成立しているが、B0〜B4 と同じ器具で取り直すまで境界を確定させない。
- `m6i_d_b1_control_void`: **m6i-b の陰性対照は使えない。** 「待ち時間だけでは
  足りない」という主張を m6i-b の根拠で述べない。陰性対照そのものを、
  解除に他方の進行を要しない停止方式で作り直す稿を立てる。
- `m6i_d_multiple_arms_never_released`: 汚染が広いので、m6i-b の腕を個別に
  救わない。**停止方式を設計し直してから全腕を取り直す。** 解除条件が
  被介入側の挙動に依存しない方式（反復回数で抜ける等）を候補にする。
- `m6i_d_no_arm_never_released`: 本測定と m6i-c が食い違う。どちらの観測が
  誤っているかを切り分ける稿を先に立てる。**どちらの結果も書き換えない。**
- `m6i_d_observation_unusable`: `gate_run_min_length` の決め方を、
  陰性対照の run 長分布から事前登録し直す。本稿の結果は使わない。
- `m6i_d_inconclusive`: 到達器具か期限だけを直す追補を先に置き、観測条件と
  判定名は緩めない。

**いずれの判定でも、本稿は `docs/spec/l3-subrom.md` 1.65節へ新たな規則を
起こさない。** 本稿が決めるのは m6i-b のどの腕が使えるかだけである。

## 6. 本文に出さないもの

- 測定終了時のテキスト画面本文、main↔sub のデータポート値列、セクタ本文は、
  標準出力、標準エラー、結果ノート、コミットメッセージへ出さない。件数、順序、
  真偽、SHA-256、判定名だけを扱う。
- ROM の相違を示すときはバイト列を転記せず、一致／不一致と相違バイト数だけを扱う。
- I/Oログを残す場合は `tools/redact_iolog.py` で値列を伏せ、
  `tools/check_cleanroom.sh` を通す。
- 本文またはデータ列の漏えいを検出した走は結果に使わず `gate_failed` とする。

### この測定で決まらないこと

- 公式ROM内部の実装、公式の送受信値、実機での絶対時間は決まらない。
- **通常READを許してよい最早時点は決まらない。** 1.65節は未確定のままである。
- **ゲートが解除されなかった理由は決まらない。** 本測定が出すのは解除されたか
  否かだけであり、なぜ解除されないかの機序は問わない。
- ゲートは測定専用の介入であり、公式 sub がそのような待ちを持つとは主張しない。
  解除の有無は器具の性質についての知見であり、公式の挙動についての知見ではない。
- 解除された腕について、m6i-b の結果が正しいと積極的に主張するものではない。
  **ゲートの副作用という説明が外れる、というところまでである。**
- 別媒体、WRITE、複数セクタREAD、BASIC命令一般へ一般化しない。
