# m7cz: 共通クロックで3問を閉じる測定の事前登録

実施日: 2026-08-27

本稿は、`docs/notes/m7cx-open-items-inventory.md` 区分Cのうち、共通クロックが
あれば答えられる3問について、到達条件・観測指標・対照・打ち切り条件を実測前に
固定する。新規ログは1回の測定キャンペーンで取得し、3問へ使い回す。

## 測定条件と共通前提

既存条件から `d1-files`（読取り需要）と `d5-seqfile`（書込みを含む需要）を選ぶ。
各条件を同一設定で2回ずつ実行し、公式main・公式subを同じ単調増加clockで記録する。
条件は `tools/measure_suite.sh` と同じものとし、前者は2400フレーム、後者は6000フレームで
使い捨てディスク複製だけを書込み可能にする。生iolog・通常出力・媒体複製はすべて
リポジトリ外の一時領域へ置き、コミットしない。既存の同一条件2本
`measurements/m6g-d0-boot-run{1,2}`はC-2の直接突き合わせと解析器の回帰確認に使う。

全問に共通して、0件、共通clock欠落、clockの重複または逆転、必要な起動区間・
SEND/RECV境界の欠落は成功扱いしない。解析器はデータポート値を内部で境界対応に
使うことも出力することもせず、cpu・kind・port・pc・seq・clockだけを使う。

これは実機の測定ではなく、**QUASI88の現行ビルドの実装を測るもの**である。過去に
ポート一致率100%を実機特性へ一般化して誤った前例があるため、採るのは相関の有無、
同一ビルド内の決定論性の有無、遅延がおおよそどの桁かという定性的結論だけとする。
clock差の個数値・統計量は再現用に記録するが、その定量精度や実機一般性は主張しない。

## C-1: d0-boot以外でのFDC時間相関

### 到達条件と観測指標

`tools/analyze_boot_exchange.py`と同じPC分類で、バルク本体までのmain SEND→RECVを
ラウンドへ分ける。各ラウンドを、SEND開始から最初の応答直前までの「応答前窓」と、
最初から最後の応答までの「応答本体窓」に分け、sub `$FA`/`$FB`アクセス件数を数える。
条件別・run別に、ラウンド数、要求長・応答長の組、応答前／本体のFDC件数、
ラウンド外FDC件数を得る。

次の3点が追加2条件の各2runで成立すれば、1.18節の定性的相関はd0-boot固有でないとする。

1. 起動対象区間のFDCアクセスが全件いずれかの応答前窓に入り、応答本体窓と
   ラウンド外は0件である。
2. 同じ応答長のラウンドは同一run内で同じFDC件数組を持つ。
3. 単発応答、256件応答、バルク応答の順で、FDC件数の桁が単調に増える。

1点でも反すれば「相関不成立」と結論する。どちらも区分Cを閉じる結論であり、
都合のよい部分集合だけを採らない。

### 対照と打ち切り

陰性対照は、合成入力のFDCイベントを応答本体窓またはラウンド外へ移し、集中判定が
不合格になること、応答長を保ったまま同種ラウンドのFDC件数を変え、一致判定が
不合格になることとする。陽性対照は既知の複数ラウンドを持つ合成入力で全条件が
合格することとする。「常に相関あり」を返す故障を注入して不合格になることを必須とし、
故障注入は空振り0件とする。

追加2条件のどちらかで起動ラウンドを切れない、または必要窓が重なって一意に帰属できない
場合は、その条件を増やして推測せず「この手法では届かない」と境界を記録してC-2へ進む。

## C-2: 1.22節の決定論性の直接確認

### 到達条件と観測指標

主条件は、同一条件の既存`m6g-d0-boot-run1`と`run2`から起動時FDC初期化区間を
独立に切り出し、データ値を除く正規化署名が完全一致することとする。署名は区間境界、
各イベントの相対clock・相対seq・cpu・kind・port・pc、`$FB`のOUT/IN run長列、
batch境界に対する単発TC位置を含む。単に「4条件で変化しなかった」ことは主根拠にしない。

一致すればQUASI88の同一ビルド・同一条件で決定論的、不一致なら非決定論的と結論する。
追加2条件のrun1/run2も同じ方法で副次確認するが、d0-bootの直接突き合わせを代替しない。

### 対照と打ち切り

陽性対照は同一の合成署名2本を一致と判定すること。陰性対照は片方のrun長、TC位置、
相対clockをそれぞれ1箇所ずつ壊し、3故障を3/3検出することとする。「常に決定論的」を
返す故障を不合格にし、空振り0件を必須とする。

既存2本のどちらかが現解析器で区間を切れない、またはclock列の健全性検査に落ちる場合は、
別条件の一致で代用せず「保存済みログでは直接確認不能」と記録してC-3へ進む。

## C-3: SEND/RECV 1回ごとの応答遅延

### 操作上の起点・終点

「`$FE`応答」は、subが`$FF`へフェーズを返した後、mainが対応する`IN $FE`待ちを
最初に脱出できる状態を観測したイベント、と定義する。値そのものは出力せず、既知の
SEND/RECV待ちPCとフェーズ順序で脱出イベントを同定する。

- main SEND / sub RECV: 起点はsub `IN $FC`（1バイト要求を受領）、終点は対応する
  main SEND後`IN $FE`待ちの脱出イベント。
- main RECV / sub SEND: 起点はsub SEND前`IN $FE`待ちの脱出イベント
  （mainの受信要求を認識）、終点は対応するmain RECV前`IN $FE`待ちの脱出イベント。

起点と終点のclock差を1プリミティブ1標本とする。負値、次プリミティブとの交差、
起点または終点の多重対応は不正標本として件数を別記し、統計へ混ぜない。

### 到達条件と観測指標

条件別かつSEND/RECV別に、有効件数、除外件数、clock差の最小・中央値・最大を出す。
中央値は昇順列の中央（偶数件は中央2値の算術平均）とする。個々のclock差列、データ値、
前後の値窓は出力しない。各条件・各方向で有効標本が1件以上あり不正標本0件なら到達とする。
桁は最小・中央値・最大が属する10進桁から定性的に述べる。

### 対照と打ち切り

陽性対照は既知のSEND/RECVを複数含む合成入力で、件数と3統計量が期待どおりになること。
陰性対照は終点欠落、終点を起点より前へ移す、別プリミティブの終点と交差させる3故障を
3/3検出することとする。「常に0clock」「全イベントを同じ対へ結ぶ」故障を不合格にし、
空振り0件を必須とする。

実ログで一意対応できない標本が1件でも出た場合、都合よく除外して分布を確定せず、
条件別に不正件数を記録する。全条件・全方向が0件または多重対応であれば、起終点の定義が
このログ粒度では届かない境界として記録する。片方向だけ成立した場合は成立側の分布と
不成立側の境界を分けて記録し、他の2問は止めない。

## 情報境界

記録してよいのは件数、位置、clock差の集計統計、SHA-256、公開μPD765のコマンド名だけで
ある。公式ROM・公式ディスクの内容を直接読まず、`private/`配下を開かない。`xxd`、`od`、
`hexdump`、`strings`、逆アセンブラを公式媒体へ使わない。`$FB`/`$FC`/`$FD`等の
データポート値列は1バイトも標準出力・ノート・テスト結果・コミットへ出さない。

ここまでを実測前の事前登録とする。
