# B28: エミュレータの機種の印を置いた自作 ROM で G1 を走らせる — 事前登録

記録日: 2026-11-01
位置づけ: 確認走行で、自作 ROM の `N88.ROM` の `0x79D7` を `'4'` にすると、G1 の入出力の要素が 215451 から 938280 へ進んだ（公式 941113）。`IN $44` は要素の数でも公式に近い。
この番地はコア（`memory.h` の `ROM_VERSION`）が機種を判定する印で、`'4'` 未満だと音源のポート `$44`・`$45` が無効になり `0xFF` を返す。**公式 ROM の値は読まない。** `'4'` はコアのソースから選んだ、音源ポートが有効になる最小の値である。
**このノートは測定より先にコミットする。**

## 1. 問い

自作 ROM（`0x79D7` = `'4'`）の上の G1 は、公式とどこまで同じか。

## 2. 条件

OO・SS 各 2 走（ブランチ `impl/l3-sub-load-run` の先頭）。条件は B18 と同じで、クラウドの実行環境で行う。B6・B8・B13・B14・B15 の器具と、`tools/check_l3_screen_output.py` の画面の署名の比較を使う。

## 3. 判定（事前に決める）

対照: OO の境界記録と入出力の要約が B1・B6 と一致する。

- **位置:** OO に対する `result` と `position`
- **サブ:** `read_data hi` の回数、記録 A の `00C1` の回数、W の区間
- **main:** 記録 A の飛び先。B1 の 8 番地の扱いの材料にする
- **値:** `b8_io_values.py` の 4 ポートの `differ`・`first`
- **画面:** 署名の一致／不一致の真偽だけ。本文は書かない

白リストは各器具のとおり。結果は `docs/notes/b28-g1-after-rom-version-results.md`、記録は `measurements/b28-g1-*`。
