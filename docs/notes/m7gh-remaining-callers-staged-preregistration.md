# m7gh: 残り6箇所の探針を段階に分けて当てる事前登録

実施日: 2026-09-04

## 位置づけ

事前登録: 残り6箇所の探針を段階に分けて当てる

本稿は[m7gc](m7gc-remaining-callers-probe-preregistration.md)（実装は
コミット`24d7e62`で完了済み。`--probe-site`/`--probe-mode`で6箇所×3モード
=18通りがビルドでき、SHAが既定とも互いにも重複しないことは親が独立に
検証済み）の**実施計画**である。`m7gc`は書き換えない。本稿は`m7gc`に
**条件軸（B:ディスク）を足す**位置づけで、[m7gg](m7gg-data-disk-screening.md)
が選別した独立署名を持つB:候補7本（`disk#1`・`#2`・`#4`・`#5`・`#7`・
`#9`・`#10`）を条件軸として使う。

本稿では**測定を1回も走らせる前にコミットする**。測定後に書き換えたり
amendしたりしない。

## 実施順

- **段階1（本タスクで実施）**: `cyl`モードだけを6箇所に当て、末端に差が
  出るかで到達可能性を判定する。
- **段階2（本タスクで実施）**: 段階1で到達が確認できた箇所についてのみ、
  B:の7本を条件軸として`clear`を当て、ベースラインと比較する。
- **段階3（本タスクでは実施しない）**: 奇数条件が見つかった場合の公式ROM
  との比較は次稿に回す。

## 段階1の条件（少数で6箇所を覆う設計）

`tools/conform_l3.sh`の既存シナリオを読解した結果、6箇所は次の2群に
分かれる（`m7gc`の分類に基づく）。

- **読み出し系5箇所**: `general_read_request`・`bulk_read_do`・
  `recv_dispatch_hdr_done`・`exchange11_fallthrough`・
  `exchange14_prepare_first_read`。いずれも`FDC_SEEK`（または共有
  ルーチン経由）へ読み出し用の目的シリンダを渡す経路であり、`m7gc`は
  これらが起動区間（`N88_FE.D88`起動）またはFILES経路で踏まれる可能性
  があると読解した。
- **書き込み系1箇所**: `recv_dispatch_write_sector`。WRITE経路専用で、
  `SAVE`系のシナリオでないと踏まない。

**条件R（読み出し系5箇所用）**: `tools/conform_l3.sh`の`drive2`
シナリオと同じ作法。A:に`disk#8`（＝`N88_FE.D88`、既知の起動可能
ディスク）の使い捨て複製、B:に候補ディスクの使い捨て複製を入れ、
`--type-at 300 --type '\n' --type-at 700 --type 'FILES 2\n'`、
`--frames 3000`。起動区間（frame<700）でも5箇所のうち起動時に踏まれる
ものがあれば反映され、打鍵後（FILES 2）でB:読み込み経路が踏まれれば
それも反映される。**1条件で「起動区間で踏むもの」「FILES経路で踏む
もの」の両方を一度に検出できる**（区別は`--list-all-stages`の段位置で
行う）。

**条件W（書き込み系1箇所用）**: `tools/conform_l3.sh`の適合条件5と同じ
作法。使い捨て複製のライトプロテクトを外し（オフセット26を`0x00`に）、
`--type-at 300 --type '\n' --type-at 700 --type '10 PRINT "T"\nSAVE"TQ"\n'`、
`--frames 4200`。B:ディスクは使わない（単一ディスク構成）。

**この条件選択で6箇所を覆えると考える理由**: 読み出し系5箇所は
いずれもREAD要求（一般READ・バルクREAD・ヘッダ処理後・交換#11
フォールスルー・交換#14）に対応し、起動＋FILES 2の打鍵列はREAD要求を
複数回発生させる（`m7fz`が交換#6で確認したとおり、起動区間だけでも
複数のREAD単位が発生する）。書き込み系1箇所はSAVE以外では踏まれない
ため、専用のWRITE条件を別に置く。**覆えない可能性がある箇所**: `m7gc`
自身が「到達するかも不明」と記した`recv_dispatch_hdr_done`（#4）は、
条件Rでも踏まないかもしれない。その場合は正直に「この条件では覆えない
（P3）」と結果に書き、追加条件は次稿に委ねる（無理に条件を増やして
複雑化しない）。

## 書き込み系（#5）へのB:条件軸適用に関する留保

段階2はB:の7本を条件軸として`clear`を当てるが、`recv_dispatch_write_sector`
はWRITE経路であり、`SAVE"TQ"`のようなファイル名だけの指定は既定ドライブ
（A:）へ書くと考えられる（`docs/spec/l3-subrom.md` 1.35節はSAVE経路の
構造を記録しているが、ドライブ指定構文の言及は無い）。**B:ディスクの
内容を変えてもWRITE経路の末端が変わらない可能性がある。** この場合、
段階2の`recv_dispatch_write_sector`行は「ディスク軸を当てたが変化なし
（=B:の内容に依存しない書き込み経路である可能性。bit0が奇数かどうかを
本条件では判定できない）」として記録し、無理に奇数/偶数を結論しない。

## 事前登録する合格条件（測定前に固定。後から動かさない）

判定に数値比較を使わない。

1. **判定規則を先にベースラインへ当てる**: 各条件（R・W）のベースライン
   （`--probe-site`未指定）2run同士に`tools/compare_l3_entry_fdc.py`・
   `tools/check_l3_screen_output.py`を当てて「差なし」と出ることを確認
   してから、注入版に当てる。
2. **`cyl`が到達検査である**（`m7gc`の設計）。差が出ない箇所の`clear`
   結果を解釈しない。「差なし＝偶数」と読まない。
3. **ROMの取り違え防止**: `--rom-dir`へ渡したサブROMのSHA-256が、全runで
   毎回ビルド直後の期待SHAと一致することを確認する。
4. **決定論性**: 差が出た条件は2run測って自己一致を確認する。重すぎて
   1runにとどめた条件があれば、どれを1runにしたか結果ノートに明記する。
5. **名前の非記録**: 成果物（本稿・結果ノート・コミットメッセージ・
   スクリプト・端末出力）に実ファイル名が1文字も含まれないこと。
   ディスクは`disk#N`と`m7gg`のダイジェストでのみ呼ぶ。

## 事前登録する分類（`m7gc`の枠をそのまま使う）

- **P1**: `cyl`が差を出し、`set`も差を出す（本稿では`set`は測らないので
  P1/P4は区別しない）
- **P2**: `cyl`は差を出すが`clear`も`set`も差を出さない
- **P3**: `cyl`が差を出さない＝到達しない
- **P4**: `cyl`が差を出し、`set`は差を出すが`clear`は差を出さない
  （交換#6と同型）

**`set`を測らない理由**: 段階を分けて無駄な組み合わせを落とすため。
`cyl`（到達検査）→到達した箇所だけに`clear`（偶奇判定の半分）を当てる
という順で、到達しない箇所への`clear`/`set`測定という無駄を避ける。
本稿で得られるのは「到達したか」と「到達した箇所でbit0が0か1か
（`clear`との一致/相違）」だけであり、**P1とP4の区別（bit0が1のとき
`set`が実際に壊れるかどうか）は次稿に残す。**

## 測定の実務・生成物の扱い

- 混成ROMは`tools/lib_l3_measure.sh`の`build_mixed_rom`（`--probe-site`・
  `--probe-mode`を追加引数としてそのまま`make_subrom.py`へ渡せる）で作る。
- フォアグラウンドで実行する（`run_in_background`は使わない）。測定中は
  `git stash`・ブランチ切替・ファイル編集を行わない。
- 測定用の駆動コマンドは`tools/`へは追加せず、スクラッチパッド配下の
  使い捨てシェルコマンド列として都度実行する（`tools/conform_l3.sh`・
  `tools/lib_l3_measure.sh`が提供する関数・ツールをそのまま呼ぶだけで、
  新しい判定ロジックを実装しないため、自己検査を要する新規`tools/`
  成果物は本稿では作らない）。
- 生ログ・混成ROM・使い捨てディスク複製はリポジトリ外
  （scratchpad配下）に置き、コミットしない。
- 出力は件数・一致/不一致・rcに絞る。値の列・実ファイル名は画面に出さない。
- SKIP・リトライ失敗が出たら件数を数えて記録する。
