# B96 結果：G5 は自作漢字 ROM を読み、画面はその中身で変わる。字形のそのままの写しは見つからない

実施: 2026-11-17、クラウド（自作 ROM main dbe1b37 のみ、G5 無入力、36000 フレーム）。手順は [事前登録](b96_preregistration.md) のとおり。3腕とも最終フレームまで正常に走った。

## 前提

自作 KANJI1/2.ROM は libretro 経路で読み込まれる。OUT/IN で読んだ値は生成物と一致した。ROM を置かないときに返る値は、事前登録に書いた 0 ではなく FF だった（[l2-font 仕様](../spec/l2-font.md) の記述と合わせて直す必要がある場合は別に扱う）。

## 結果

- 漢字ポートの IN は3腕とも第1 ROM で 68256 件、読んだ番地は 6680 種（約420字分、F386 から）。第2 ROM は0件。
- 非0を返した件数は KJ-ON 50087、KJ-SHIFT 51067、KJ-OFF 68256（すべて FF）。
- 600 フレームごとの画面ハッシュ60点は、どの2腕を比べても一致24点。KJ-ON と KJ-OFF が初めて違うのは F444。漢字 ROM の中身が画面に効いている。
- 字形の照合（16行×2バイトが VRAM に縦にそのまま並ぶか、7時点で採取）は KJ-ON 0/419、陰性対照の1文字隣 9/419、KJ-OFF 0/419。ビットずれ・半分の高さ・太字化など60字形での変形も試したが、ほとんど現れなかった。

## 判定

事前登録の「読んだ字形の多くが VRAM に現れる」は満たさない。陰性対照も低いので、照合の方法がゲームの描き方に合っていない（G5 は字形を加工して描いている）とみられ、**字形が表示されるかの判定は保留**とする。言えるのは「G5 は自作漢字 ROM を通しで読み、その中身によって画面が変わる」ことまで。

正しい字が出ているかは、本人が WebQ88（compat-rom に自作 KANJI1/2.ROM を同梱済み）で G5 を動かし、目で見て確かめる。画面は記録しない。
