## 3. 採った規則（本体・追補1〜4をあわせて）

根拠の腕を括弧内に記す。

1. `FILES [<ドライブ番号>]`。省略時はドライブ1。ドライブ番号には数値式を書ける（本体 D-omit・D-1・D-2・D-expr）。
2. ディレクトリを (18,1,1) の先頭から順に読み、削除済み（先頭 `0x00`）を飛ばし、未使用（先頭 `0xFF`）で止める
   （本体 L11、`directory_order_skips_deleted`）。生きたエントリが0件なら何も出さない（L0）。
3. 各エントリを**16桁のセル**に出し、1行に5件並べる。セルの中身は、名前欄の先頭6バイト、種別の印1文字、
   名前欄の末尾3バイト、空白1つ、大きさ（10進、最小桁数）の順で、残りを空白で埋める。
   種別の印は、名前欄直後のバイトが `0x80` ならピリオド、`0x00` なら空白。大きさはファイルの割り当て単位の個数
   （本体 L1〜L11、追補2 L80、`G5_SPLIT63_80DOT_00BLANK_UNITS`）。
4. 最後のエントリの後に改行する。5件で満杯の行（80桁ちょうど）の後では、80桁目でカーソルが次の行へ移り、
   その後の改行でさらに1行進むので空行が1行入る（追補3 Q-B `_W`、追補4 Q-A `wrap_then_newline_blank`）。
   画面超過時は通常の出力と同じくスクロールし、途中で止まらない（本体 L96、追補2・3）。
5. ドライブ1のディレクトリは記憶せず、`FILES` のたびに媒体を読む（本体 D-1・D-omit の READ 件数）。
6. 媒体が入っていないドライブを指すと、エラーにせず媒体の挿入を待つ（本体 N-wait）。
7. ドライブ番号 0 と 3 は ERR 70、文字列の引数は ERR 13（本体 E-0・E-3・E-str）。

## 4. 行き先

- `docs/spec/l3-main.md`: 80桁ちょうどまで出力した直後の改行で空行が1行入る規則（FILES と無関係な画面出力の性質）。
- `docs/spec/l4-basic.md`: `FILES` 節の新設（§3 の 1〜7）。
- 画面の署名は行末の空白を含まない形で取られている（本体 L1 の `w1=12` が、セル幅16ではなく中身の長さだった）。
  したがって「セルの残りを空白で埋める」ことは直接は観測していない。5件目のセルの後にカーソルが80桁目を越えて
  次の行へ移ること（規則4）から、少なくとも5件目のセルは80桁目まで進むと分かる。行末の空白を書くか、カーソルだけを
  進めるかは画面上で区別できないので、実装はどちらでもよい。
- 3 のセルの中身の並びは、候補 `SPLIT63`・`80DOT_00BLANK`・`UNITS` の定義（本体 §3.2〜3.4）をそのまま文章にしたもの。
  数値の桁揃えは最小桁数（本体 §3.4）で、2桁の大きさ（本体 L11 の10単位）まで確認済み。3桁以上は測っていない。

## 5. 決まらないこと

- 大きさが3桁以上のときの表示。`0x80`・`0x00` 以外の種別バイト（アスタリスク等）。小文字・半角カナ・制御文字を含む名前。
- 80桁ちょうどの出力の後に改行以外が来たときの挙動。
- 本体 §10 の各項目（`LFILES`、壊れた鎖、ドライブ1からの起動規則など）。
