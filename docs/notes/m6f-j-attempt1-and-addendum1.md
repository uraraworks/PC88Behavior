# m6f-j 1回目の結果と追補1（エラー行の形と、未挿入の「待つ」の判定を直す）

記録日: 2026-09-29

## 1. 1回目（器具 `f5009f4`）

最初の2回の起動試行はドライバがコアの場所を受け取れず `gate_failed core_missing`（公式ROM起動0）で止まった（器具は環境変数 `M6FJ_CORE` で受け取る作りで、
ほかのドライバの `find_l3_core` を使っていなかった）。3回目にコアの場所を渡して、公式ROM起動12回（6腕×2走）で最後まで通った。
G1〜G9 はすべて真（G8: 割り当て表の読み取りは全走で位置159以下、本体は予測長＋1以下）。2走はすべて一致。

| 腕 | 判定 | 観測 |
|---|---|---|
| J-1 | **`no_line`**、本体 **`body_matches_2_6`** | 新しいエントリ `qsb`（種別 `0x00`、先頭単位72）、新たに使われた単位 72 |
| J-2 | **`overwrite_same_slot_frees_old`**、本体 **`body_matches_2_6`** | 同じ位置のエントリへ書き、古い単位は空きに戻った |
| J-3 | **`first_free_in_2_5_order`** | 単位 0〜9 が使用中でも、新しいファイルは 2.5節の順の最初の空き（単位72）へ |
| J-4 | `other` | 画面は物理行0に20文字の1行、媒体は不変 |
| J-5 | `other` | 画面は物理行0に9文字の1行、媒体は不変 |
| J-6 | `other` | 画面にエントリ行なし、挿入後に単位72が使われた |

### 1.1 採るもの

J-1〜J-3 の判定（完了時に `Ok` の行を足さない、同名は同じ位置に上書きして古い単位を解放、割り当ては 2.5節の順の最初の空き）と、
J-1・J-2 の本体が 2.6節の形であること。

### 1.2 J-4〜J-6 が `other` になった理由（事後、判定には使わない）

- 判定器はエラーの行を `?` ＋メッセージとして予測していた。m6f-i のエラー（`direct_msg_<N>`）はメッセージだけの行で一致しており、この前提は器具の誤り。
  J-4 の行はエラー表61番のメッセージ（20文字）、J-5 の行は68番のメッセージ（9文字）の、メッセージだけの行の署名と一致した。
- J-6 の `waits_for_media` の判定は「挿入後に `Ok` の行が出る」ことを条件にしていたが、SAVE は `Ok` の行を足さない（J-1）。条件が J-1 と矛盾していた。

## 2. 追補1（状態: 測定前、公式ROM起動0のまま置く）

- J-4・J-5 の `error_<N>` の予測を、**メッセージだけの行**（m6f-i `direct_msg_<N>` と同じ形、物理行0）に直す。媒体不変の条件はそのまま。
- J-6 の `waits_for_media` を、「挿入の前に画面にエラーの行が無い」かつ「挿入の後に新しいエントリが作られ、エラーの行が無い」に直す（`Ok` の行を条件にしない）。
  挿入前にエラーの行が出れば `error_<N>`、挿入後もエントリが無ければ `stuck`。
- ドライバはコアの場所をほかのドライバと同じ `find_l3_core` で求める。
- 取り直すのは J-4・J-5・J-6（各2走）。J-1〜J-3 は1回目を採る。
