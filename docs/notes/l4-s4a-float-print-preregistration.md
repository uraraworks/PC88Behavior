# l4-s4a — 直接モードの PRINT: 浮動小数点の出力の形 — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

M7段階4（GW-BASIC 数値部の移植）の最初の測定。段階3（`l4-s3a`・`l4-s3b`・
`l4-c2`/`l4-c2b`/`l4-c2c`）で整数・文字列の `PRINT` の出力の形はすでに
公式と一致することを確認済み。本ノートはその続きとして、浮動小数点の値を
`PRINT` したときの出力の形（小数点の位置、有効桁の丸め、指数表記への切り
替え、単精度/倍精度の書式差、誤差の見え方、オーバーフロー時の挙動）を
公式ROMで測る。

条件・器具（起動settle、実打鍵開始、1文字あたりのフレーム、フレーム計算式、
写しの取り方、原点の定義）は `l4-s3a`
（[l4-s3a-print-format-preregistration.md](l4-s3a-print-format-preregistration.md)）
をそのまま踏襲する。腕だけがPRINTの浮動小数点表現に合わせて新しい。

## 問い

- Q1 小数（`decimal`群）: `print 1.5`・`print .5`・`print -.5`・`print 0.25`・
  `print 123.456` の出力の形。小数点の位置、前置きの空白/符号、後置きの
  空白の有無
- Q2 有効桁（`digits`群）: `print 1/3`・`print 2/3`・`print 10/3`・
  `print 1234567.8`・`print 12345678` で、何桁まで表示され、どこで丸められる
  か。整数値に見える大きな数が単精度に昇格した場合の桁落ちも含む
- Q3 大きい数の指数表記（`exp_large`群）: `print 999999`・`print 9999999`・
  `print 10000000`・`print 1e10`・`print -1.5e+20` で、どの大きさから指数
  表記に切り替わるか、その書式（`E`の位置、指数の符号・桁数）
- Q4 小さい数の指数表記（`exp_small`群）: `print .1`・`print .01`・
  `print .001`・`print 1e-10` で、どの小ささから指数表記に切り替わるか
- Q5 整数からの昇格（`promote`群）: `print 40000`・`print 30000+30000`・
  `print -32768-1`・`print 200*200`・`print 7/2` のように整数の範囲
  （-32768〜32767）を超える／割り切れない演算結果が、単精度浮動小数点の
  書式で出るか
- Q6 倍精度（`double`群）: `print 1#/3`・`print 1d10`・
  `print 12345678901234#`・`print 1/3#` で、`#`サフィックス・`D`指数が
  倍精度の書式（単精度と桁数が違う、指数記号が`D`になる等）を起こすか
- Q7 誤差の見え方（`error_view`群）: `print .1+.2`・`print 1/3*3` のように
  二進浮動小数点の丸め誤差が結果に現れるかどうか（現れるならその形）
- Q8 範囲外（`out_of_range`群）: `print 1e38*10`・`print 1/0` が、出力の行を
  何行・何桁ぶん変えるか（**文字の値は出さない**。l4-s3a Q5・l4-c2b P6と
  同じ扱いで、件数と位置の範囲だけを記録する。エラーメッセージの文言は
  ROMのデータであり出さない）

## 条件・器具

`l4-s3a`「条件・器具」節と同一。要点のみ再掲する。

- 公式ROM一式、ディスク無し、コア既定N88 V2。起動settleは
  `--type-at 300 --type '\n'`、実打鍵の開始は`--type-at 700`。
- 英字は打鍵注入がシフト無しで小文字として送るため画面では小文字になる。
  打鍵文字列の英字（`print`・`e`・`d`を含む）はすべて小文字で書く。
- 1文字あたりの反映フレームは`hold+gap=8`フレーム/文字（既定値）。
- 各腕は打鍵の前（`--type-at`の10フレーム前）と、打鍵と実行が終わった後に
  写しを取り、`tools/l4_vram_probe.py --diff-before/--diff-after`で
  差分を取る。Q8のみ`--nonblank-summary-rows`を単独写し（実行後の1枚）に
  対して使う。
- フレーム計算式（l4-s3a・l4-s1c・l4-s1eと同じ）:
  ```
  line_end(k) = 700 + 8 * (その腕で打った文字数の累計、\n も1文字)
  dump(k)     = line_end(k) + 20   （実行の余裕）
  run(k)      = dump(k) + 200      （走行フレームの余裕）
  ```
- 出力の行は「打った行の次の行」として相対の行で特定し、原点は打った行の
  先頭のセル（打鍵のエコーの最初の文字）とする。

下記参照）。

## 記録する内容

- decimal・digits・exp_large・exp_small・promote・double・error_view の
  各腕は、差分モードで得た「前が空白だったセル」の(相対の行, 相対の桁,
  文字コード)の並びそのもの。原点に選んだセルの絶対位置(row0, col0)も
  記録する（l4-s3a・l4-c1の作法を踏襲）。複数行にわたる出力は行ごとに
  記録する。
- out_of_range群は、`--nonblank-summary-rows`が返す件数と位置の範囲
  （相対行・相対列の最小・最大）のみを記録する。値・文字コードは記録
  しない。
- 機械可読な表で結果ノートに載せる。

## 本文を出さない取り扱い

- 出力行（打った行より下で`Ok`行より上の、前が空白だったセル）の文字
  コードが**すべて「数字0-9・`.`・`+`・`-`・`E`・`D`・空白」の集合に入る
  腕だけ**、(相対行, 相対桁, コード)を記録する。自分で打った式の直接の
  結果なので、l4-s3a（Q1〜Q4、自分で指定した数値・記号のエコー/出力）と
  同じ扱いになる。
- 1セルでも上記の集合外の文字コードがあれば、その腕は件数と位置の範囲
  （相対行・相対桁の最小・最大）だけを記録し、コード・文言は一切出さない
  （エラーメッセージはROMのデータであり、禁止事項7の対象）。
- out_of_range群（X1・X2）は、上記の分類にかかわらず件数と範囲のみを
  記録する（Q8で定めたとおり）。
- 上記の分類を行う記録器（結果ノート作成時に使うスクリプト）は、集合外の
  文字コードを標準出力・標準エラーへ一切出さない設計にする。既存の
  `tools/l4_vram_probe.py --nonblank-summary-rows`・`--row-signature`と
  同じ流儀（値を出さずに件数・範囲・署名だけを返す）に倣う。
- 写し・記録・iologは使い捨ての作業ディレクトリ（リポジトリ外）に置き、
  結果ノートを書いたら削除する。

## 判定

判定名はこの事前登録に書いたものだけを使う。

- 腕ごとの分類（「記録する内容」節・「本文を出さない取り扱い」節を参照）:
  - `numeric_output`: 出力行の全セルの文字コードが「数字0-9・`.`・`+`・
    `-`・`E`・`D`・空白」の集合に入る（out_of_range群を除く）
  - `non_numeric_output`: 出力行に上記集合外の文字コードが1つでもある
    （エラー表示を含む）
  - `gate_failed`: 関門G1〜G6のいずれかが偽だった腕
- 予測との照合: 別担当が用意する予測表
  `docs/notes/l4-s4a-gwbasic-predictions.tsv`（列: id, typed, kind
  〔numeric|error〕, predicted〔二重引用符で囲んだ出力行の文字列〕）を
  使う。
  - kind=numericの腕: 予測文字列を出力行の相対桁0から置いたときの
    非空白セル(相対桁, コード)の並びが実測と完全一致すれば
    `predicted_match`、一致しなければ`predicted_differs`。複数行の出力は
    行ごとに同様に照合し、全行が一致した場合のみ`predicted_match`とする。
  - kind=errorの腕: 実測の分類が`non_numeric_output`なら
    `predicted_error_consistent`、そうでなければ（`numeric_output`だった
    場合）`predicted_error_inconsistent`。
  - out_of_range群（X1・X2）は、予測表のkindがerrorであることを前提に
    上記と同じ規則で照合する。`numeric_output`/`non_numeric_output`の
    分類自体は「本文を出さない取り扱い」節の規則どおり行うが、値を
    伴わない件数・範囲比較にとどめる（predicted側にも文言を出さない
    比較法を別途定める。ここでは分類の一致・不一致だけを記録する）。
  - `gate_failed`の腕は照合しない。

比べるものは以上のみ。最下行（ファンクションキー表示行）とバナーの行は
比べない（l4-c2b・l4-c2cと同じ理由。ROMのデータ表であり、本測定の対象
外）。

## 器具の確認（公式ROMは使わない）

測定開始前に、自作main ROM（測定時HEAD `90ab7ce`から
`src/build_main_rom.py`で組み立て）に対し、32腕すべてを打鍵し、エコー行
（打った行そのもの）が打鍵文字列どおりに届くかを
`tools/l4_vram_probe.py --marker`（打鍵文字列そのものをmarkerに指定）で
確認した。出力行の中身は見ていない。

結果: **32腕すべてでエコー行に打鍵文字列がそのまま出現した**（marker一致
1件ずつ）。記号`.`・`/`・`+`・`-`・`#`・`e`・`d`を含め、SHIFTが要る記号
（`.`・`#`等）も含めて全て届いており、打てなかった記号は無かった。
l4-s3aで「未確認」としていた`-`（マイナス）も、本確認では`print -.5`・
`print -32768-1`・`print -1.5e+20`の3腕で正しく届いている
（打鍵注入のシフト無し送出でも`-`はASCII 0x2Dのまま通ることが、これで
実測として裏付いた）。

作業に使ったROM・写し・スクリプトはリポジトリ外の使い捨てディレクトリ
（scratchpad配下）に置き、確認後に削除した。

## 判定後の行き先

仕様書`docs/spec/l4-basic.md`に、浮動小数点PRINTの書式規則の節を新設し、
Q1〜Q8の判定結果を反映する。`predicted_differs`/`predicted_error_inconsistent`
が出た腕があれば、その原因（予測アルゴリズムの誤りか、実装すべき丸め・
書式規則の見落としか）を切り分けて次の作業への入力とする。
