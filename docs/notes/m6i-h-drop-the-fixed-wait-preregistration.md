# m6i-h — 固定フレーム待ちを外せるか — 事前登録

記録日: 2026-09-23  
状態: 測定前

[m6i-g 結果](m6i-g-clean-preamble-boundary-results.md) は、自作 main ＋ 自作 sub
（無改変）で初回の通常READ が成立する前置きを **`m6i_g_ab_sufficient`**
（起動専用SEND 1件＋sub の FDC 初期化完了）と確定した。同 §8 は行き先として

> 前置きの実装は、**待ちを固定フレーム数で行わず、初期化完了を観測して
> 進む形**にする。（中略）**60という値を実装へ直結しない**

と決めた。**しかし main は sub の FDC I/O を直接観測できない。** 本測定は、
その「観測して進む形」を実装できるかを測る。

## 0. 何を決める測定で、何を決めない測定か

[m6i-g 事前登録](m6i-g-clean-preamble-boundary-preregistration.md) §0 を
引き継ぐ。**本測定も自作 main を自作 sub に対して測る。** 決まるのは
**自作どうしの統合条件**であって、公式 sub が何を要求するかではない。
**本稿の結果を `docs/spec/l3-subrom.md` へ書かない。**

## 1. 問い

`MAIN_SUB_SEND` は有限ポーリング（各待ちループ 65535 回上限）を持つ。
main が待つ必要があるとしても、**その待ちは送信の有限ポーリングが
肩代わりしている可能性がある。**

- **主問**: 起動専用SEND を1件出した直後に、フレーム待ちを1回も挟まずに
  通常READ を出して成立するか。
- **副問**: 起動専用SEND を出さず、**通常READ を1回失敗させてからもう一度
  出す**（再試行1回）だけで成立するか。成立するなら、実装に「意味の説明が
  つかない空送信」を置かずに済む。

## 2. 腕（arm）

**4腕すべてで `DISK.ROM`・`FONT.ROM`・`N88_0`〜`N88_3` をバイト一致させる。**
m6i-g と同じ素のサブROM（`d8b2e64b…`）を使う。違うのは `N88.ROM` だけである。
媒体・セクタ・期待SHA-256・打鍵・測定期限は m6i-g の凍結値と同じ。

| 腕 | main の前置き | 由来 |
|---|---|---|
| H-N | なし、即 READ | m6i-b B0 の main（= m6i-g G-N）。再現腕 |
| H-W | 起動専用SEND 1件 → フレーム60まで待つ → READ | m6i-b B4 の main（= m6i-g G-L1）。再現腕 |
| H-A | 起動専用SEND 1件 → **待たずに即 READ** | **新規** |
| H-B | 前置きなし → READ → 失敗なら**もう一度 READ** | **新規** |

H-A・H-B の main は新規に書く。**フレーム計数器を持たないこと**が要件であり、
関門G4 が main のバイトを固定することで担保する。

### 到達指標

腕ごとに異なる。**測っていない量を到達条件にしない。**

| 腕 | 到達条件 |
|---|---|
| H-N | `b=0`、`c=0`、発行フレーム = 6 |
| H-W | `b=1`、`c=0`、発行フレーム = 60 |
| H-A | `b=1`、`c=0`。**発行フレームは記録するが条件にしない** |
| H-B | `b=0`、`c=0`、**`MAIN_SUB_READ_KNOWN` が2回呼ばれたこと** |

- H-N・H-W の発行フレームは、m6i-g で同じ main を2走ずつ測って
  6・60 が観測されているので凍結できる。
- **H-A・H-B の `a`（sub の FDC 初期化完了）を到達条件にしない。**
  発行時点で初期化が終わっているかどうかは、本測定が問うている当のもので
  あるため。`a` は記録する。
- H-A の発行フレームを凍結しないのは、**前置きの所要時間を測っていない**
  からである。推測値を凍結しない。

### 結果条件

- **H-N・H-W・H-A**: 通常READ が「256位置一致かつ期待SHA一致かつ定常入力待ちへ
  復帰し、要求 run が1件」であるとき `success`、そうでないとき `failure`。
  m6i-g から変更しない。
- **H-B のみ結果条件が異なる。** READ を2回呼ぶので要求 run の件数を
  他腕と同じには扱えない。H-B は「`MAIN_SUB_MARK_SUCCESS` が立ち、256位置を
  受信して期待SHAと一致し、定常入力待ちへ復帰した」とき `success`、
  そうでないとき `failure` とする。**要求 run の件数は記録するが条件にしない。**

**H-B は結果条件が他腕と違うので、他腕との数値比較には使わない。副問としてのみ
扱う。**

## 3. 関門（gate）

- **G1**: `tools/run_all_selftests.sh` が rc=0。
- **G2**: `tools/check_cleanroom.sh` が rc=0 かつ NG 0件。
- **G3**: 媒体SHA・セクタSHA・測定期限・反復数が m6i-g の凍結表と一致する。
- **G4 sub 無改変と main の直交をバイトで示す**。
  - 4腕の `DISK.ROM` がすべてバイト一致し、素のサブROMと一致する
  - 4腕の `FONT.ROM`・`N88_0`〜`N88_3` がすべて同一
  - 4腕の `N88.ROM` は互いに相異する
  - H-N の `N88.ROM` が m6i-b B0 のものと、H-W のそれが m6i-b B4 のものと
    バイト一致する
  - **H-A・H-B の main に、フレーム計数の待ちループが無いこと**を、
    生成した asm のラベル表とコード列から機械的に確認する
  - 7ファイルすべてが所定サイズ
  陰性対照として、1腕の `DISK.ROM` を介入ありのものに差し替えた一式で
  false になることを示す。
- **G5 時刻と状態**: 各腕の到達条件（§2）を満たす。
- **G6 結果検出力**: 合成入力で、256位置一致、1位置欠落、SHA不一致、timeout、
  定常入力待ち未復帰を別々に識別する。**H-B の結果条件についても、
  1回目失敗・2回目成功と、2回とも失敗を別々に識別する。**
- **G7 状態観測の独立性**: `a`・`b`・`c` を別事象で観測し、同じ事象を2状態へ
  重複計上しない。
- **G8 器具の自己汚染検査**: 到達判定が、走によって書き換えられうるものを
  参照していない。
- **G9 凍結**: 腕名・判定名・到達条件・結果条件を測定前に器具の設定ファイルへ
  固定し、本稿と違えばエミュレータ起動前に `gate_failed`。
- **G10 窓の端の検査**: m6i-g 追補1・追補2 で置いた3件を引き継ぐ。
  発行直前の状態を数える窓が、**基準の事象が起きない場合にも、基準の事象が
  発行より後に起きる場合にも**壊れないことを合成入力で確認する。

## 4. 判定名

判定は関門、到達、結果の順で付ける。2走が一致しない腕は `unreached`。

- `gate_failed` / `unreached`
- `h_n_reproduced` / `h_n_not_reproduced`（H-N が `failure` なら再現）
- `h_w_reproduced` / `h_w_not_reproduced`（H-W が `success` なら再現）
- `h_a_success` / `h_a_failure`
- `h_b_success` / `h_b_failure`

総合判定は `h_n_reproduced` と `h_w_reproduced` がともに成立することを共通の
前提とする。どちらかが崩れたら `m6i_h_inconclusive`。

- `m6i_h_no_wait_sufficient`: `h_a_success`。**起動専用SEND 1件の直後に
  待たずに出して成立する。** 実装にフレーム待ちを置かない。
- `m6i_h_wait_required`: `h_a_failure`。**待ちが要る。** どう待つかは
  本稿では決まらず、別稿へ送る。
- `m6i_h_inconclusive`: 関門は通過したが、1腕以上が `unreached` であるか、
  再現腕が再現しなかった。

副問は総合判定と独立に記録する。

- `m6i_h_retry_without_send_sufficient`: `h_b_success`。
  **空送信を置かず、再試行1回で足りる。**
- `m6i_h_retry_without_send_insufficient`: `h_b_failure`。

## 5. 判定後の行き先

- `m6i_h_no_wait_sufficient` かつ `m6i_h_retry_without_send_sufficient`:
  **再試行1回を採る。** 意味の説明がつかない空送信を実装に置かずに済む。
- `m6i_h_no_wait_sufficient` かつ `m6i_h_retry_without_send_insufficient`:
  **起動専用SEND 1件を前置きとして採り、待ちは置かない。**
- `m6i_h_wait_required`: 待ちの実装方法を別稿で事前登録する。
  **本稿から待ちの値を実装へ直結しない。**
- `m6i_h_inconclusive`: 到達器具か期限だけを直す追補を先に置き、結果条件と
  判定名は緩めない。

**いずれの判定でも `docs/spec/l3-subrom.md` へ規則を起こさない**（§0）。

## 6. 本文に出さないもの

- 測定終了時のテキスト画面本文、main↔sub のデータポート値列、セクタ本文は、
  標準出力、標準エラー、結果ノート、コミットメッセージへ出さない。件数、順序、
  真偽、SHA-256、判定名だけを扱う。
- ROM の相違はバイト列を転記せず、一致／不一致と相違バイト数だけを扱う。
- I/Oログを残す場合は `tools/redact_iolog.py` で値列を伏せる。
- 本文またはデータ列の漏えいを検出した走は結果に使わず `gate_failed` とする。

### この測定で決まらないこと

- **公式 sub が何を要求するかは決まらない**（§0）。
- **待ちの下限は決まらない。** 本稿は「待たなくても成立するか」を問うだけで、
  成立した場合でも余裕がどれだけあるかは測らない。
- **H-A が成立した場合、なぜ待たなくてよいのかは決まらない。**
  送信の有限ポーリングが肩代わりしているという説明は自然だが、本稿はそれを
  測っていない。
- H-B は結果条件が他腕と異なるので、他腕との数値比較に使わない。
- 別媒体、WRITE、複数セクタREAD、BASIC命令一般へ一般化しない。
