# m7gd: 追加された起動ディスクがL3サービスに入るかを名前を出さずに選別した

実施日: 2026-09-04

## 位置づけ

[m7gb](m7gb-odd-cylinder-condition-search-results.md)は「使える起動ディスクは
事実上1択（`PC88_REF_DISK_DIR/N88_FE.D88`）」であることを前提に探索を行った
（同稿52-66行）。理由は、当時 `private/disk` に置かれていたもう1本
（本稿でいう「diskB」相当）が[m6-sub-invariant.md 第2版](m6-sub-invariant.md)
の実測により L3ディスクサービスに一切入らないと分かっていたためである。

その後、ユーザーが `private/disk` に新たなディスクイメージを追加した。
**何本追加されたか、名前が何かは、本稿の担当セッションも知る必要が無い
（実際、権限設定上 `private/` 配下を `ls` すること自体ができない）。**
本稿の目的は、その中に m7ga/m7gb が「事実上1択」と呼んだ状態を崩す
——つまりもう1本、L3ディスクサービスへ入る起動ディスクがあるかどうか——
を、**名前を一切扱わずに**機械的に選別することである。

## 判別基準（根拠: m6-sub-invariant.md 第2版の実測）

[m6-sub-invariant.md 第2版](m6-sub-invariant.md)（152行目以降）が実測した
とおり:

- diskA（`N88_FE.D88`、N88-BASIC）起動: サブCPUの `OUT $FC` が多数
  （実測5,635件、frames=1800）発行される
- diskB（市販ソフト、名前は記録しない）起動: `OUT $FC` が
  frames=600/1800/3600のいずれでも**0件**。サブCPU側の総I/O量は
  diskAの約5.2倍あるにもかかわらず、応答経路(`$FC`)を一度も使わない

これは`tools/conform_l3.sh`の適合条件2（520-556行付近）が実際に検査に
使っている条件と同じ数え方である。本稿の選別も同じ数え方（
`tools/hash_io_stream.py --cpu sub --port FC --kind OUT`）を、
`tools/conform_l3.sh`の`count_sub_fc`と同じ引数・同じ「抽出0件はエラーに
なるので0として扱う」規約で呼ぶ（`tools/lib_screen_boot_disks.sh`の
`count_sub_fc`。二重実装ではなく同じPython器材を呼んでいる）。

判定規則: frames=600・1800のいずれかで`OUT $FC`が1件でもあれば
「L3に入る」、両方とも0件なら「入らない」とする（1つのフレーム数の値だけに
判定を依存させない。m6-sub-invariant.md第2版が600/1800/3600の複数点で
確認したのに倣う）。

## 名前を出さない設計にした理由

1. `private/disk`配下の市販ソフトディスクは、実ファイル名・タイトルを
   リポジトリにもノートにも残さない方針が既に確立している
   （m6-sub-invariant.md第2版、m7gb 56-64行の踏襲）。
2. 名前が一度セッションの文脈やコミットメッセージに入ると、後段のノートへ
   コピー＆ペーストで書き写される事故の種になる。「今回は書かない」を
   毎回人間の注意力で守るより、**出力そのものが名前を持てない形**に
   しておくほうが確実（`CLAUDE.md`の情報流の設計思想と同じ）。

このため`tools/screen_boot_disks.sh`は、各ディスクを「ファイル名で
ソートした順の通し番号(`disk#N`)」と「ファイル名(basenameのみ、パスを
含まない)のSHA-256先頭8桁のダイジェスト」だけで識別し、**標準出力にも
標準エラーにもファイル名を一切出さない**。この性質自体を
`tools/screen_boot_disks_selftest.sh`が検査している（後述）。

## 結果

`PC88_REF_ROM_DIR`の既定混成ROM（`tools/lib_l3_measure.sh`の
`build_mixed_rom`を引数なし＝探針フラグ無しで呼んだもの）で、
`private/disk`配下の全D88イメージをA:に挿入して1回ずつ起動測定した
（frames=600と1800の両方）。

| 通し番号 | ダイジェスト | OUT $FC (600F) | OUT $FC (1800F) | 判定 |
|---|---|---:|---:|---|
| disk#1  | 0cd0727b | 0    | 0    | 入らない |
| disk#2  | 3c218749 | 0    | 0    | 入らない |
| disk#3  | c29e67d4 | 5635 | 5635 | **L3に入る** |
| disk#4  | f314f59f | 0    | 0    | 入らない |
| disk#5  | 9054ca7b | 0    | 0    | 入らない |
| disk#6  | 93694fad | 0    | 0    | 入らない |
| disk#7  | 39c2fbeb | 0    | 0    | 入らない |
| disk#8  | 650cfac8 | 5635 | 5635 | **L3に入る** |
| disk#9  | 6acfca05 | 0    | 0    | 入らない |
| disk#10 | 0c6f7a53 | 0    | 0    | 入らない |

10本中2本（disk#3、disk#8）がL3ディスクサービスに入ると判定された。
両者とも件数が5,635件でぴったり一致しており、diskA（`N88_FE.D88`）の
実測値と同じ形（frames=600でも1800でも件数が変わらない＝早い段階で
バーストが打ち止めになる、m6-sub-invariant.md第1版(b-1)と同型）である。
残る8本は600/1800フレームのいずれでも0件で、diskBと同型（応答経路を
一度も使わない）だった。測定失敗は0本。

## 言えること・言えないこと

- **言える**: disk#3・disk#8の2本は、既定の混成ROM・A:起動という条件で
  サブCPUが`OUT $FC`を発行する＝L3ディスクサービスに入る種類の起動を
  行っている。他の8本はこの条件では発行しない。
- **言えない**: `OUT $FC`が0件であることは「そのディスクが壊れている」
  「読めない」ことを意味しない。`tools/conform_l3.sh`の適合条件2は
  むしろ**diskBが0件になることを公式ROM自身の挙動として前提**にしている
  （520-534行のコメント参照）。0件は「L3ディスクサービスとは別の経路で
  ディスクを読む起動をしている」ことを示すだけで、ディスクの内容や
  起動の成否そのものについては本稿は判定していない
  （m6-sub-invariant.md第2版(c)が明記するとおり、画面を見て起動できて
  いることまでは別稿で確認済みなのはdiskAとdiskBの2本のみで、
  今回の8本については確認していない）。
- **言えない**: disk#3とdisk#8が互いに同一内容のディスク（同じソフトの
  複製）なのか、別々のN88-BASIC系ディスクなのかは、本稿の測定
  （ポート番号・件数のみ）からは分からない。名前を見ない設計上、
  それを確かめる手段自体を持たない。
- **言えない**: 600/1800フレームより先（例えば3600フレーム）まで測れば
  結果が変わる可能性は、m6-sub-invariant.md第2版のdiskAでは否定されている
  （1800と3600で同数）が、本稿の10本全部について3600フレームまでは
  確認していない。

## 自己検査

`tools/screen_boot_disks_selftest.sh`は公式ROM・公式ディスク無しで、
合成フィクスチャのみを使って以下を検査する:

- `digest_basename`が既知のファイル名から期待どおりのSHA-256先頭8桁を
  計算すること、異なる名前で異なるダイジェストになること
- `list_disk_basenames`が拡張子の大小混在を1本ずつとして数え、
  ソート済みで返すこと
- `count_sub_fc`が合成iologから`OUT $FC`の件数を正しく数えること
  （非0件・0件の両方）
- `classify_l3_entry`の判定ロジック、および「常にL3に入る/常に入らない」
  と返す壊れた実装なら区別できる（検出力の陽性対照）こと
- 本体`tools/screen_boot_disks.sh`を、実際のq88measureを呼ばずに合成
  iologへ差し替えるテスト用フック(`SCREEN_BOOT_DISKS_FAKE_IOLOG_DIR`)
  経由で最後まで走らせ、**わざと目立つファイル名を持つ合成ディスクを
  与えても標準出力・標準エラーのいずれにもそのファイル名が一切現れない
  こと**、通し番号・ダイジェスト・判定が期待どおり出力されること
- 全ディスクを0件のフィクスチャに差し替えると集計も0本に変わること
  （判定が固定値を返す壊れた実装ではないことの陽性対照）
- ディスクが0本のときに「0本」であることを明示的に報告すること
  （黙って正常終了の顔をして終わらない）

実行結果: 全項目OK、終了コード0。

## 情報境界 / 根拠リンク

公式ROM・公式ディスクのバイト列、公式ROMの逆アセンブル、`private/`の
内容（ファイル名を含む）は読んでいない。本稿の測定・出力に含まれるのは
ポート番号(`$FC`)・方向(`OUT`)・件数・ファイル名から計算したダイジェスト
（元のファイル名には戻せない）だけである。生ログ（iolog・stdout・stderr）
は `/private/tmp/claude-501/-Users-haruurara-MyProject--emulator-PC88/30d2f560-3e79-495c-8136-de6318bc1b91/scratchpad`
配下に置き、コミットしていない。
