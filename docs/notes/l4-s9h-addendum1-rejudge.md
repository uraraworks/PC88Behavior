## 経緯

公式の1回目（140腕×2走）は全280行が gate_failed になった。原因は定数対照7腕のうち
行が折り返す2腕（control-wrap・control-long）の観測が器具の想定と違ったこと。
2走は一致している。他の5対照は予測と一致した。

器具は「80桁いっぱいで折り返す」と仮定していた。自作ROMはその仮定どおりなので
自己検査（自作ROMの定数7腕）は通っていた。公式は印の後ろ70文字の位置で、
次の5セルを空白にして次の行へ続けた。これは PRINT USING ではなく普通の PRINT の
行端の折り返し規則の差で、`docs/spec/l4-program.md` 第8節
「行の端での折り返し」の未確定項目に当たる。

## 対照の仮定の誤り

折り返しの規則は事前に測定していない性質であり、予測値は自分の実装の仮定を写したにすぎない
（自作を自作で測った対照は誤解を両側に入れる）。PRINT USING の書式を測る腕は
出力が印を含め80セルに収まるので、「印の間を取り出せるか」の検証に折り返し対照は不要だった。
折り返しを含む対照を関門にしたのは過剰だった。

## 再判定の規則（観測を見直す前に固定）

1. control-wrap・control-long は関門から外し、観測として残す（status=observed_only）。
2. 関門は残り5対照（empty・spaces・symbols・newline・comma）の「2走一致・形式が有効・
   打鍵失敗0・予測と一致」と、全腕の2走一致・形式。
3. それ以外の比較（U_GW/U_N88 との一致、differ、gate_failed）は事前登録のまま。
4. 腕の出力が1行に収まる前提を、観測と予測の印込みセル数（前印5＋コード列）が
   80を超えないこと、および末尾区切りありなのに後印が2行目以降へ出ていないことで確かめる。
   これに反する腕は折り返し規則に依存するので、予測と一致しても `unpredicted`
   （pass にしない）とする。
5. 腕の欠落、打鍵失敗（観測 null）、2走不一致は従来どおり gate_failed。

器具: `tools/l4_pusing_measure.py rejudge --measured IN --out OUT`。
selftest に陽性（折り返し対照が予測外でも他が一致なら通る）と陰性
（5対照の改変、2走不一致、打鍵失敗、予測外の値、折り返し依存、腕の欠落）を足した。

## 保存済み観測から再判定する理由

測定は決定的な2走一致で、器具の採取経路・前後印・形式検査は壊れていない
（折り返し2腕も形式は有効で2走一致）。関門の定義だけを変えるので、
公式ROMを再実行する必要はない。再実行すると同じ観測が出るだけで、
判定規則を観測後に動かした事実は再実行でも消えない。だから事前に規則をここへ固定し、
動かした事実を記録する。

  折り返し対照2腕を除いて**0腕**だった。

別の段で測る。この段では結論を出さない。
