# M6w — main側分岐点259直前の応答構造

日付: 2026-08-12
根拠: 伏せ字済み診断結果`/Users/haruurara/pc88-diag/last.txt`、
共通クロック付き既存ログ
`measurements/m6g-d0-boot-run{1,2}.iolog.txt.gz`、および診断時に保存された
伏せ字済み混成ログ
`/Users/haruurara/pc88-diag/diag-l3-mixed-d0-boot.20260812-231002.iolog.redacted.txt`
の再解析。**追加測定は行っていない。** `$FB`/`$FC`/`$FD`のvalue列は
一切見ず、CPU・方向・ポート・PC・seq・clockだけを用いた。

## 目的

最新の混成ROM診断では、main側の構造的一致プレフィックスが258件で、
次のI/Oから分岐する。

```
基準[258] OUT port=0071 pc=3A64
基準[259] OUT port=0031 pc=E7F5
混成[259] IN  port=0031 pc=7752
```

`$31`は公開ハードウェア仕様上、OUTではシステム制御、INではDIPスイッチ
読み出しのポートである。両側とも同じ公式main ROMなので、分岐より前に
subから受け取った応答の**構造**が違うかを調べる。

## 解析器の検出力と決定論性

既存の`tools/analyze_boot_exchange.py`を使用した。新しい解析器は書いて
いない。先に`tools/analyze_boot_exchange_selftest.sh`を実行し、合成した
3ラウンド（FDC 0件、FDC 10往復、5バイト応答）をすべて非0件で検出し、
clockシャッフルとSEND PC破壊で期待どおり結果が崩れることを確認した
（全項目OK）。その後run1/run2へ適用し、レポートはラベル行以外完全一致
した。

## 分岐直前のラウンド

共通クロック上で分岐点を逆向きにたどると、直前に完了したmain⇔sub往復は
1.18節のラウンド#2である。値を使わない件数比較は次のとおり。

| 対象 | main SEND | sub SEND / main RECV | 応答clock | 応答後の`$31`分岐clock |
|---|---:|---:|---:|---:|
| 公式run1 | 5バイト | 1バイト | sub `OUT $FD`=7422 / main `IN $FC`=7427 | 7555 |
| 公式run2 | 5バイト | 1バイト | run1と同一 | run1と同一 |
| 混成 | 5バイト | 1バイト | sub `OUT $FD`=7459 / main `IN $FC`=7464 | 7592 |

ラウンド#0〜#2をまとめても、公式・混成とも要求長は`2,1,5`、応答長は
`1,1,1`で一致する。混成subは各単発応答の直前に
`IN $FA, OUT $FB, IN $FA, IN $FA, OUT $FB, IN $FA, IN $FB`
という7件のFDCアクセスを追加しており、公式subのラウンド#1・#2は
FDCアクセス0件である。このため混成の応答は遅いが、mainは待ちを完遂して
公式と同じ1バイトを受信し、その後も`OUT $32→OUT $71`まで進んでから
`$31`で分岐している。待ちのタイムアウトや応答バイト数不足を示す構造は
無い。

## 結論

- 分岐点259直前にsubが返すべき長さは**1バイト**であり、自作subも
  **1バイト**返している。要求・応答のラウンド構造は一致する。
- mainから見える最初の構造差は応答受信時ではなく、その後の`$31`の
  OUT/IN分岐である。両側のmain ROMが同一であることと合わせると、原因は
  直前の1バイトの**値**の違いに絞られる。
- その値はデータポート`$FD`/`$FC`の伏せ字対象であり、規律上確認できない。
  公式subがFDCアクセス0件で作る値を、公開I/O構造だけから一意に導く方法も
  見つからない。したがって**確定できる実装変更は無く、推測実装はしない。**
