# m6i-e — ゲートの実害の機序 — 事前登録

記録日: 2026-09-23  
状態: 測定前

[m6i-c 結果](m6i-c-b5-b6a0-divergence-results.md) は、sub のラウンド#0直後の
ゲートの**有無だけ**で通常READの成否が変わることを、バイト直交で確定した。
[m6i-d 結果](m6i-d-gate-release-audit-results.md) は、そのゲートが**一度も
詰まっていない**ことを、ゲート番地を踏んだ回数で確定した。

**止めないのに成否を変えている。** 本測定はその機序を切り分ける。
測定対象は自作 main と自作 sub だけであり、公式ROMは使わない。

## 1. 問い

ゲートは次の3命令・6バイトである。

```
DB FE      IN A,($FE)
E6 nn      AND n
28 ee      JR Z,（自分自身）
```

このうち何が成否を変えているか。候補は2つに絞れる。

- **候補R（読み）**: `IN A,($FE)` が1回余分に行われること。
- **候補L（配置・時間）**: ラウンド#0直後に6バイト入ることで、後続コードの
  配置がずれること、あるいは実行が数サイクル遅れること。

## 2. 腕（arm）

**main ROM は4腕すべてでバイト一致させる。** m6i-c の C0・C2 が使ったもの
（枝タグなし、`b→a→c` 前置き、フレーム60で通常READを1回）をそのまま使う。
媒体・セクタ・期待SHA-256・打鍵も m6i-c と同じ。

sub ROM だけを変える。**挿入位置はラウンド#0応答の直後**（m6i-b B5 のゲートと
同じ場所）で固定する。

| 腕 | 挿入する6バイト | 意味 |
|---|---|---|
| E0 `full_gate` | `DB FE` `E6 nn` `28 ee` | 完全なゲート（= m6i-c の C0 と同一） |
| E1 `no_insertion` | **挿入なし** | 介入なし（= m6i-c の C2 と同一） |
| E2 `single_read` | `DB FE` `00 00` `00 00` | `IN A,($FE)` 1回 ＋ NOP 4個 |
| E3 `nops_only` | `00 00` `00 00` `00 00` | NOP 6個。I/O を一切行わない |

`nn` と `ee` は E0 の既存ゲートが生成する値をそのまま使い、本稿では固定しない
（ビルドが決める値であり、凍結表へは E0 の sub ROM の SHA-256 として入れる）。

**E0・E2・E3 は、挿入した6バイトを除いてバイト一致する。** 挿入の長さが等しい
ので、後続コードの配置も完全に同じになる。したがって:

- **E2 と E3 の比較は、`IN A,($FE)` 1回だけを振った比較である。**
  配置も長さも命令数も同じで、違うのは「ポートを読むか、何もしないか」だけ。
- **E3 と E1 の比較は、6バイトの配置ずれだけを振った比較である。**

### 到達指標（4腕共通）

- 前置き `b→a→c` が各1回この順に完了している
- 通常READの発行フレームが60である
- 前置きの通信を要求 run へ数えていない
- 2走の判定が一致する

m6i-c と同じである。**ゲート番地の観測を到達指標に入れない**
（[m6i-c 追補2](m6i-c-addendum2-reach-and-release.md) と同じ理由。従属する
観測の都合で主問を捨てない）。

### 結果条件

通常READが「256位置一致かつ期待SHA一致かつ定常入力待ちへ復帰し、要求 run が
1件」であるとき `success`、そうでないとき `failure`。m6i-c から変更しない。

## 3. 関門（gate）

いずれかが偽なら測定腕へ進まず、全体を `gate_failed` として止める。

- **G1 自己検査**: `tools/run_all_selftests.sh` が rc=0 で終わる。
- **G2 クリーンルーム検査**: `tools/check_cleanroom.sh` が rc=0 かつ NG 0件。
- **G3 凍結値**: 媒体SHA・セクタSHA・発行フレーム・測定期限・反復数が
  m6i-c の凍結表と一致する。
- **G4 挿入の直交をバイトで示す**。本測定の主張を支える関門である。
  - 4腕の `N88.ROM` がすべてバイト一致し、m6i-c の C0 のものと一致する
  - E1 の `DISK.ROM` が m6i-c の C2 のものとバイト一致する
  - E0 の `DISK.ROM` が m6i-c の C0 のものとバイト一致する
  - **E0・E2・E3 の `DISK.ROM` は、互いにちょうど6バイトだけ相違し、
    その6バイトはすべて同一の連続領域（挿入位置）に収まる**
  - その6バイトの中身が、上の表の登録値と一致する
  - E1 の `DISK.ROM` は E3 のものと、挿入位置より前が一致し、長さが6バイト短い
  - `N88.ROM`・`DISK.ROM` 以外の5ファイルは4腕で全て同一
  - 7ファイルすべてが所定サイズ
  陰性対照として、挿入バイトを1つ書き換えた一式で false になることを示す。
- **G5 時刻と順序**: 4腕とも通常READ発行がフレーム60で、前置きが `b→a→c` の
  順に各1回完了している。
- **G6 結果検出力**: 合成入力で、256位置一致、1位置欠落、SHA不一致、timeout、
  定常入力待ち未復帰を別々に識別する。
- **G7 腕の検出力**: 故障注入（前置きマーカー削除、発行フレーム改変、
  要求run計数の固定化）で該当腕が `unreached` になることを確認する。
- **G8 器具の自己汚染検査**: 到達判定が、測定の走によって書き換えられうるもの
  （ROM ディレクトリの列挙など）を参照していないことを確認する。
  [m6i-d 第1回](m6i-d-attempt1-instrument-failure.md) の不備を二度と通さない。
- **G9 未確定値の凍結**: 腕名・判定名・挿入バイト・凍結値を測定前に器具の
  設定ファイルへ固定し、本稿と違えばエミュレータ起動前に `gate_failed`。

## 4. 判定名

判定は関門、到達、結果の順で付ける。2走が一致しない腕は `unreached`。

- `gate_failed` / `unreached`
- `e0_reproduced`: E0 が `failure`。/ `e0_not_reproduced`: E0 が `success`。
- `e1_reproduced`: E1 が `success`。/ `e1_not_reproduced`: E1 が `failure`。
- `e2_success` / `e2_failure`、`e3_success` / `e3_failure`

総合判定は、`e0_reproduced` と `e1_reproduced` がともに成立することを共通の
前提とする。どちらかが崩れたら `m6i_e_inconclusive` とし、機序の帰属をしない。

- `m6i_e_single_read_is_the_cause`: `e2_failure` かつ `e3_success`。
  **ラウンド#0直後にポート $FE を1回読むことが、単独で成否を決めている。**
  配置ずれは効いていない。
- `m6i_e_layout_is_the_cause`: `e2_success` かつ `e3_failure`。
  **6バイトの配置ずれだけで壊れる。** 読みは効いていない。
- `m6i_e_any_insertion_breaks`: `e2_failure` かつ `e3_failure`。
  この位置に何を入れても壊れる。読みと配置を分離できない。
- `m6i_e_single_read_insufficient`: `e2_success` かつ `e3_success`。
  **1回の読みでも配置ずれでも再現しない。** 完全なゲートの害は、
  `AND` と `JR Z` を含む形でしか出ない。
- `m6i_e_inconclusive`: 関門は通過したが、1腕以上が `unreached` であるか、
  再現腕が再現しなかった。

## 5. 判定後の行き先

- `m6i_e_single_read_is_the_cause`: **ポートCの読みが、この時点で何かを
  消費している。** 消費されるものが何か（ラッチ、受信可フラグ、ハンドシェイクの
  一段）を、`docs/spec/l3-subrom.md` の既存記述と突き合わせる稿を立てる。
  **ただし「$FE 固有か、どの `IN` でも同じか」は本稿では決まらない**ので、
  別ポートを読む腕を m6i-f で足す。
- `m6i_e_layout_is_the_cause`: 配置ずれが効いているなら、m6i-b の腕の比較は
  **挿入の有無そのものが交絡している**。停止方式を作り直すのではなく、
  **全腕に同じ長さの詰め物を入れて配置を揃える**方向で設計し直す。
- `m6i_e_any_insertion_breaks`: この位置は何も足せない。停止・観測の両方を
  この位置から外す設計へ移る。
- `m6i_e_single_read_insufficient`: 害は3命令の組み合わせにある。
  `AND` だけ、`JR Z` だけを足す腕へ分解する稿を立てる。
- `m6i_e_inconclusive`: 到達器具か期限だけを直す追補を先に置き、結果条件と
  判定名は緩めない。

**いずれの判定でも、本稿は `docs/spec/l3-subrom.md` 1.65節へ新たな規則を
起こさない。** 本稿が決めるのは器具の害の機序だけである。

## 6. 本文に出さないもの

- 測定終了時のテキスト画面本文、main↔sub のデータポート値列、セクタ本文は、
  標準出力、標準エラー、結果ノート、コミットメッセージへ出さない。件数、順序、
  真偽、SHA-256、判定名だけを扱う。
- ROM の相違を示すときはバイト列を転記せず、一致／不一致と相違バイト数、
  相違位置だけを扱う。**ただし本稿が登録した挿入6バイトは自作コードの
  オペコードであり、公式ROM由来ではないので、上の表に書いたものは扱ってよい。**
- I/Oログを残す場合は `tools/redact_iolog.py` で値列を伏せ、
  `tools/check_cleanroom.sh` を通す。
- 本文またはデータ列の漏えいを検出した走は結果に使わず `gate_failed` とする。

### この測定で決まらないこと

- 公式ROM内部の実装、公式の送受信値、実機での絶対時間は決まらない。
- **「$FE 固有か、どの `IN` でも同じか」は決まらない。** 本稿は別ポートを読む
  腕を持たない。無害と確かめられたポートが無いため、推測で選ばない。
- **読みが何を消費しているかは決まらない。** 成否が変わるかどうかだけを測る。
- **通常READを許してよい最早時点は決まらない。** 1.65節は未確定のままである。
- ゲートも挿入も測定専用の介入であり、公式 sub がそのような命令を持つとは
  主張しない。**本稿で分かるのは器具の性質である。**
- 別媒体、WRITE、複数セクタREAD、BASIC命令一般へ一般化しない。
- 挿入位置をラウンド#0直後に固定しているので、**他の位置へ一般化しない**
  （m6i-b の B2・B4 はラウンド#0より前にゲートを持ち、成立していた）。
