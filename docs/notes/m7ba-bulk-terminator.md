# m7ba: バルク終端の合図（`$FF=0x91`）を確定・実装。固着点はmain側へ移った

測定日: 2026-08-19

## 情報境界

公式ROM一式・公式diskA（使い捨て複製）を**実行して**測定した。読んでいない。
本ノートに書く値は、**プロトコルのフェーズコード**（`$FF`に書かれる語彙。
仕様書1.12節・1.16節で既に確定・記載済みのもの）と、ゼロだけである。
ディスクの内容は扱っていない。

## 1. 固着していた場所

混成ROM（公式main + 自作サブROM）は公式diskAでBASICの起動途中までしか進まない
（m7az）。どこで止まるかを見たところ、**バルク転送(5635件)を終えた直後**に
main と sub が互いに `$FE` をポーリングし合って固着していた
（sub側 `IN $FE` 994,525件・main側 1,005,277件でログが飽和）。

## 2. 公式はバルク終端で何をしていたか

バルク最後のバイトのあと、公式subは次を出す:

```
OUT $FD = 00  →  OUT $FF = 08  →  OUT $FF = 91
```

`0x08` は SEND手順5（1.15節）、**`0x91` は起動手順2（1.16節）と同じ値**で、
意味は未確定のまま。**4条件で1バイトも違わず一致した**——同一条件の独立3実行
（`off`/`off_run2`/`off_run3`）と、別条件の `d3_rw`。

自作subは `$FF=08` までは出していたが、**`0x91` を出していなかった**。

## 3. 実装と効果

`BULK_SEND_FINAL_DUPLICATE` の末尾に `OUT $FF,0x91` を追加した（4バイト）。

**効果: バルク終端前後のsub側の並びが公式と完全に一致するようになった。**

```
公式: sub OUT $FD=00 → $FF=08 → $FF=91 → sub IN $FE=01 → main IN $FE=10 →
      main IN $FD=00 → main IN $FC=00 → main OUT $FF=08 → main OUT $FF=91 → …
混成: （main OUT $FF=08 まで完全に同じ）→ main IN $FE=00 → 以後ポーリング
```

**固着は解けていない**が、**分岐点がsub側からmain側へ移った**。公式mainは
`OUT $FF=08` の次に `OUT $FF=91` を書いて先へ進むのに対し、混成のmainは
そこで `$FE` を読みに行き、以後ポーリングに入る。

回帰なし: 適合条件1（5635件・SHA-256）は維持、`verify_l3.sh` も全項目OK。

## 4. 「割り込みが来ていないのでは」は否定された

mainが待ちに入るので「自作subが割り込みを上げていないのでは」と疑ったが、
割り込みログを取って**否定した**:

| 条件 | main割り込み受理（全体） | バルク終端直後20万clock |
|---|---:|---:|
| 公式 | 1161件 | 1138件 |
| 混成 | 756件 | **39件** |

混成でもmainは割り込みを受理している（ハンドラ番地も同じ）。受理点の戻り番地は
公式が`C162`〜`C164`、混成が`C257`〜`C25A`と**別のループ**を指しており、
「割り込みが来ない」のではなく「**mainが別のコードにいる**」ことを示す。

## 5. 次の一手

mainが別ループへ入る原因は、この直前までの可視入力（`$FD`/`$FC`/`$FE`の値）が
公式と一致しているのに分岐が違うことから、**もっと手前にある**と考えられる。
既存の `diag_l3_mixed.sh` の構造的一致プレフィックス（main側258件）は
**バルクより手前**の指標なので、**バルク終端以降に限定した比較**を作る必要が
ある。それが条件5（書き込み）到達の前提になる。
