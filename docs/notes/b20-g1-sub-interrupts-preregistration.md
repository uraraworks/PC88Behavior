# B20: 公式の上の G1 で、サブの割り込みのモードと飛び先を見る — 事前登録

記録日: 2026-10-31
位置づけ: 自作サブの上の G1 では記録 A に `0038` への割り込みの移動が 15366 回あるが、公式には無い（[B15](b15-g1-sub-boundary-results.md)、B18b）。[B19](b19-sub-entry-state-results.md) で公式は禁止のまま移ると分かった。
**このノートは測定より先にコミットする。** 結果を見てから規則を変えない（変えるときは後続ノートで）。

## 1. 問い

公式の上の G1 で、サブの割り込みは受理されるか。受理されるなら、モードと飛び先は何か。自作とどう違うか。

## 2. 条件

OO・SS 各 2 走（SS は `impl/l3-sub-load-run` bd359ac）。条件は B13 と同じで、クラウドの実行環境で行う。既存の `--int-log` を使う。実装は `tools/b20_sub_interrupts.py`。
B13 と同じ対照を通し、`--int-log` が走を変えていないことを main の境界記録の一致で確かめる。

## 3. 記録

`--int-log` の sub 節から次だけを出す。全行を白リストで検査してから書く。

- `accepted: N`、`dropped: N`
- `int <im> <handler の 4 桁 16 進> <lo|hi> <回数>`（モード、飛び先、割り込まれた場所の領域。`0x2000` で分ける）

割り込まれた場所の番地は記録しない。飛び先の番地は記録する（方針ノート第2節の「どこを」）。

## 4. 判定（事前に決める）

OO について排他的に 1 つ選ぶ。

- **受理なし:** `accepted` が 0。公式では割り込みが入らない
- **受理あり:** モードと飛び先の組を全部並べる

SS を並べ、組の差を書く。原因と働きはこの測定では決めない。
