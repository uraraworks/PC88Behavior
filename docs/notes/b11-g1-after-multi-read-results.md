# B11: 複数セクタの読み出しを実装した自作サブで G1 を走らせる — 結果

記録日: 2026-10-31
規則: [b11-g1-after-multi-read-preregistration.md](b11-g1-after-multi-read-preregistration.md)（3c108bf）どおり。変更なし。
実装: `impl/l3-sub-multi-read` 2a4f910（公式の観測を見ていない担当が 1.36b 節から実装）。測定はクラウドの実行環境で 4 腕各 2 走、すべて rc=0。
記録: `measurements/b11-g1-*`（白リスト通過のみ）。

## 対照

OO は B1・B6 と一致。SO は B7 の SO と一致。各腕の走1と走2は入出力の列が一致した。

## 判定

| 腕 | 対 OO | 位置 | 判定 |
|---|---|---|---|
| OO | same | 941113 | 対照 |
| SS | **diverged** | **35721** | **途切れは解消**（B7 では 13510） |
| OS | self-ends-first | 13510 | **途切れは残る** |
| SO | self-ends-first | 215451 | 変わらず（サブが公式なので当然） |

- **座標:** SS の 15 ブロックは OO と同じ `(0,0,2)〜(0,0,16)`。OS は B9 と同じ（none×2、全部同じ値×13）で変わらない
- **値:** OO 対 SS の `IN $FC` は 32766 件比べて 28819 件違い、**最初の違いは番号 3840**。つまり track 0 の 15 セクタの 3840 バイトは公式と一致した
- **`IN $FE`:** 違いは B8 と同じ形（番号 43 から）

## 次の分かれ目（位置 35721）

| 位置 | 公式 | SS |
|---|---|---|
| -2 | IN $FC ×1 | IN $FC ×1 |
| -1 | OUT $FF ×1 | OUT $FF ×2 |
| 0 | IN $09 ×1 | IN $FE ×4 |
| +1 | OUT $31 ×1 | OUT $FF ×1 |
| +2 | OUT $E4 ×1 | IN $FC ×1 |

公式はここで通信をやめて次の処理へ進み、自作はデータの受け取りを続ける。

## 読み方

- G1 は track 0 の読み込みを終え、次の読みに進んでいる。その値が最初のバイトから違う
- **推定（確認していない）:** G1 の track 0 の外は 1024 バイトのセクタで、B10 は 256 バイトしか測っていない。自作サブがこの形を読めていない可能性がある。[B12](b12-sub-1024-byte-read-preregistration.md) で測る
- OS が直らない理由はこの測定にない。目標は SS なので今は追わない。公式 main と自作サブの組み合わせで何かが足りないことだけを記録する
