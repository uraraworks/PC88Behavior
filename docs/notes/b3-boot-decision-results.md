# B3: 起動を試みるかどうかを main が何で決めるか — 結果

記録日: 2026-10-25
規則: [b3-boot-decision-preregistration.md](b3-boot-decision-preregistration.md)（1202d82）どおり。規則の変更なし。
器具: 78d5c89（`--main-in-force`・コアのパッチ 0017・解析器）、9948139（解析器の読み方の修正。下の「器具の不具合」）。
記録: `measurements/b3-boot-decision.txt`（白リスト通過分のみ）。生ログは作業場 `PC88/tmp/b3-nodisk-work/` にだけ置いた。
全14走（7腕×2走）で、main・sub の入出力記録と書き込み記録の取りこぼしは 0 件。同じ腕の2走は全項目で一致した。

## 結論

**公式 main は、`IN 40` の bit3 で起動を試みるかどうかを決めている。bit3 = 0 なら試み（sub に頼む経路へ進む）、
1 なら試みない（sub と一度もやり取りせず BASIC へ進む）。**
このエミュレータでは、bit3 はドライブ1に媒体があるとき 0、無いとき 1 で、**ドライブ2の媒体は効かない。**
`IN 40` の bit3 だけを振ると、媒体の有無と逆の側へ分岐が入れ替わる（両方向）。同じ値で上書きする空の介入では変わらない。

## R0 分岐の分類

| 腕 | ドライブ1 | ドライブ2 | 介入 | K1（C1/FF の先） | 分岐のフレーム | K2 | K3（sub） | 分類 | K4（C000 の自作コード） |
|---|---|---|---|---|---|---|---|---|---|
| N | 無し | 無し | なし | C1 | 13 | 0 | 0 | ROM 形 | 該当なし |
| D1 | M | 無し | なし | FF | 13 | 1782 | 2192 | ディスク形 | 実行された |
| D2 | 無し | M | なし | C1 | 13 | 0 | 0 | ROM 形 | 実行されない |
| X1 | 無し | 無し | bit3 := 0 | FF | 13 | 191 | 5121640 | ディスク形 | 該当なし |
| X2 | M | 無し | bit3 := 1 | C1 | 13 | 0 | 0 | ROM 形 | 実行されない |
| C1 | 無し | 無し | bit3 := 1（もとの値） | C1 | 13 | 0 | 0 | ROM 形 | 該当なし |
| C2 | M | 無し | bit3 := 0（もとの値） | FF | 13 | 1782 | 2192 | ディスク形 | 実行された |

（各腕2走で同値。K2 = main の FC〜FF の入出力件数、K3 = sub の入出力件数。）

- 分岐のフレーム 13 は [l1-ipl.md](../spec/l1-ipl.md) 第7節の「64 件目、P3 の入口」と同じ位置。
- X1 の sub の大きな件数は、媒体の無いドライブに対する sub の媒体待ち（[l3-subrom.md](../spec/l3-subrom.md) 1.62節）と同じ形に見える
  （件数だけの観測。中身は見ていない）。X1 はフレーム 599 の画面署名が N と一致しなかった（BASIC へ届いていない側）。

## R1 候補の入力

N の2走と D1 の2走から、分岐点より前の main の IN（FB〜FD を除く）を (ポート, ビット) ごとに調べた。

- **候補は1つだけ: `IN 40` bit3（N で常に 1、D1 で常に 0）。** 4走とも分岐点より前に 7012 回読まれ、初回はフレーム 1。
- 候補でないもの: 両条件で値の集合が同じ 38、同じ腕の中で 0 と 1 の両方をとる（揺れる）1。
- 結果を見る前に置いた予測（`IN 40` bit3。エミュレータのソースを読んで立てたもの。事前登録 1.2節）と一致した。
  規則は全ポート・全ビットから機械的に選ぶもので、`IN 40` を特別扱いしていない。

## R2 因果

- X1（無し＋bit3 := 0）が2走ともディスク形、X2（有り＋bit3 := 1）が2走とも ROM 形。**両方向とも入れ替わった。**
- C1・C2（空の介入）は2走とも基準と同じ形。介入の器具そのものは分岐を変えない。
- 介入の末端: X1・X2 は `matched=7012 changed=7012`、C1・C2 は `matched=7012 changed=0`。判定の条件を満たす。
- X2 では、ドライブ1に媒体が入っていても (0,0,1) の自作コードは実行されず、フレーム 599 の画面は N と一致した。
  **媒体の有無を、`IN 40` bit3 以外の経路（FDC 等）で確かめ直すことはしていない**（K2・K3 とも 0）。

## R3 ドライブ2だけ

D2 は2走とも ROM 形で、`IN 40` bit3 は 1（N と同じ）。自作コードは実行されず、画面は N と一致した。
**ドライブ2にだけ媒体があっても、起動を試みない。**

## R4 走の中での変化

N・D1・D2 の各走で、`IN 40` bit3 の値は走全体で1種類（分岐点の後も同じ）。なお 600 フレームのうち `IN 40` が読まれたのは
分岐点より前だけだった（7012 回、全腕同じ）。

## R5 画面（判定外）

フレーム 599 の画面署名: N＝X2、D1＝C2、N＝D1＝D2＝C1 は一致、N と X1 は不一致。
（D1 は自作コードが `RET` で戻るので、BASIC まで届いて N と同じ画面になる。b2 と同じ。）

## 器具の不具合（隠さない）

78d5c89 の解析器は合成ログの7欄（clock 欄なし）にだけ合わせてあり、本物の iolog（8欄）を全行読み飛ばした。
基準走 N・D1・D2 の最初の解析が「全走 K1=none・候補 0」になって気づき、9948139 で直した（8欄だけを受け付け、
main のイベントが 0 件なら止める）。最初の解析の出力には分類も候補も無く、結論には使っていない。直したあとは同じ生ログを解析し直した。
走は取り直していない（器具の不具合は解析器だけで、q88measure の走には関係しない）。

## 言えないこと

- **実機の信号について。** このエミュレータの `IN 40` bit3 はリセット時にドライブ1の媒体の有無から決まる作り
  （エミュレータのソースによる。公式 ROM の観測ではない）。実機で何がこのビットを作るか（ディップスイッチか、装置からの信号か）は
  この測定からは言えない。
- **どの回の読みで決まるか。** `IN 40` は分岐点より前に 7012 回読まれ、介入は全回に効かせた。決め手になる読みの位置は振っていない。
  bit5（VRTC）の待ちと同じ読みに載っているかどうかも分けていない。
- **走の途中で媒体を入れたとき。** 振っていない。このエミュレータではリセット時に決まる作りなので、測っても
  エミュレータの作りを測ることになる。
- **ディスク装置そのものが無い構成。** QUASI88 libretro 版のコア設定に該当する項目が無く、作れなかった。
- 分岐の後の ROM の内部の手順。発行元 PC は解析器でも使っていない。
