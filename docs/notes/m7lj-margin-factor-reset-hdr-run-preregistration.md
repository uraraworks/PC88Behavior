# m7lj: 余白をもう10バイト作る——ヘッダ受信位置とRUN_LENの初期化列を集約する（純粋なコード移動） — 事前登録

## 位置づけ

[m7li](m7li-retry-on-result-error-results.md)で、再試行の条件の作り直し（+13バイト）は**容量が足りずに不採用**になった。
**自己検査は故障注入などの変種も同じ生成器でビルドしており、変種は既定より最大+8バイト大きい。**
候補を入れて変種も窓に収めるには、**既定で21バイト以上の余白が要り、あと6バイト足りなかった。**

**本稿は[m7ld](m7ld-margin-factor-eot-gpl-dtl-results.md)と同じ流儀で余白を作る**——一字一句同一の命令列を
サブルーチンへ集約する。命令列は1バイトも変えない。

## 何をするか

**次の4命令が、`SEND_BOOT_SINGLE_TRACKED`・`RECV_DISPATCH`・`_bulk_tail_item`の3箇所に一字一句同じ形で
置かれている**（今のHEADで重複する命令列を数え直して見つけた。節約の見積もり10バイトで最大）。

```
ld hl,REQ_HDR ; ld (HDR_PTR),hl ; xor a ; ld (RUN_LEN),a
```

これを`RESET_HDR_RUN`（末尾に`ret`）へ集約し、3箇所を`call RESET_HDR_RUN`に置き換える。
**`MAIN_LOOP`の初期化は最初の3命令だけ同じで4命令目が違うので、触らない。**

**レジスタと状態**: 共有列から戻った時点のA=0・HL=REQ_HDR・フラグ（`xor a`の結果。`ret`と`ld (nn),a`は
フラグを変えない）は元の列と同じ。違うのは**共有列の実行中にスタックが1段深い**ことだけ。

**試しの書き換えで測った（測定前。自作コードの大きさだけ）**:

| 版 | 既定 | 余白 | 変種の最大増分 | 関門が拒否した変種 |
|---|---|---|---|---|
| HEAD | 2033 | 15 | +8 | 0個 |
| **この書き換え** | **2023** | **25** | +8 | **0個** |
| この書き換え＋m7liの候補 | 2036 | 12 | +8 | **0個** |

**m7liの候補を重ねても、変種21個がすべて窓に収まる。**

## 合格条件（**測定前に固定する。1つでも偽なら採用しない**）

1. **判定行の全集合が、同じ実行群のBASEと一致し、総合判定は適合**（色コードを落とした判定行。m7ld・m7lbと同じ）。
2. **データを運ぶポート（main IN `$FD`・`$FC`、sub OUT/IN `$FB`）のイベント列が、全iologでBASEと一致**
   （m7ldの比較器`PC88/tmp/m7ld-cmp.py`。ポーリングのポートは比べない——サイクル数で回数が変わりうるため。
   範囲はm7ldで決めたとおりで、後から動かさない）。
3. **決定論性**: 書き換え版を独立2回、判定行の集合が一致。
4. **全長2023で関門を通る**。**変種フラグを1つずつ立てた全ビルドが関門を通る（拒否0個）**——**m7liで見落とした
   点を合格条件にした。** `tools/run_all_selftests.sh`がrc=0（worktreeの切り離したHEADへ使い捨てでコミットして回す。
   置き場由来の`check_cleanroom.sh`の1件を除く）。`tools/check_cleanroom.sh`は本体の作業ツリーで全項目OK。

## 採用したら

`src/`の変更として単独でコミットする（**測定のコミットを先に**）。**余白は25バイトになり、m7liの再挑戦の
容量の前提が満たされる。** ただしm7liのもう1つの阻害要因（送信単位の数の食い違い）は残るので、
**再挑戦はそれを測ってから**にする。

## 言えないこととして先に書いておくこと

- **実行のタイミングが同じだとは言わない**（ポーリングは比べていない）。
- **本稿は自作の実装を測っている。公式の振る舞いは測っていない。**

## 禁止（本稿の測定中も例外なく適用）

公式ROM・公式ディスクのバイト列を読まない・出力しない・逆アセンブルしない。`private/`の中身を見ない。
データポート値・時刻・frame番号・画面本文を出力しない（比較器はハッシュの一致・不一致と本数だけを出す）。
