# m7x: 523位置目は交換#12の第三READデータ

測定日: 2026-08-13

## 情報境界

公式ROM・公式ディスクおよび公式ディスク由来データの値は表示・記録していない。
公式環境と公式main＋現行自作subを各1800フレーム新規実走し、生ログはリポジトリ外の
使い捨て領域だけで比較後に削除した。外へ出したのは交換番号、長さ、構造一致長、
位置一致件数、要求内の同値位置だけである。

## 523位置目の帰属

main `IN $FC`の交換別累積は、交換#7まで518位置、交換#8〜#11の単発4位置が
519〜522位置である。523位置目は交換#12の2件要求に続く256件応答の先頭である。
直前の交換#11は8件要求・1件応答で、その要求窓にFDC READ系がある。

公式の交換#3、#6、#11から`$F7/$F8/$FA/$FB`だけを方向・ポート順に抽出すると、
各569件で三者が完全一致した。交換#11/#12は、交換#3/#4、交換#6/#7と同じ
「前の交換でREADデータを保持し、次の2件要求で256位置を返す」第三の組である。

## 生成源と現行差分

公式交換#12の256件応答は、交換#11中の直前READ DATAデータ部と256/256位置一致した。
混成交換#12も混成側の直前READデータと256/256位置一致した。したがって送信バッファ接続と
二位置SENDは正しく、523位置目の直接生成源は第三READのデータ部である。

公式と混成の交換#11要求列は8/8位置一致したが、第三READのC/H/R座標ではCとHが相違し、
Rだけが一致した。データ部は3/256位置一致、一致プレフィックス0だった。構造上も、公式の
交換#11は先頭から交換#3/#6と同じ569件列なのに対し、混成は先頭制御を欠く566件の別列へ
入っていた。現行実装が交換#11を観測済みREAD対ではなく汎用8件要求へ落としていることと
一致する。

要求位置は0始まりで記す。公式Cは要求位置3だけと同値だった。Rは要求位置5と6が同値で、
値比較だけではどちらが意味上の生成元か区別できない。交換#6で同じ曖昧さを公開FDCの
パラメータ順に整合する早い位置へ解決した規則を適用し、位置3をSEEK/C、位置5をR/EOTへ
転記する。位置6との意味上の区別は未確定と明記し、他の8件要求へ外挿しない。

## 実装判断と4指標

交換#11の8件要求だけを第三READ準備として識別し、交換#3/#6と同じ観測済みFDC構造で
データ部を保持する。続く交換#12の2件要求は既存の二位置SENDへ接続する。期待値・比較条件は
変更しない。
