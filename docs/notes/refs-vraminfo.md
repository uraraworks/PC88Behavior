## 判定 — 採用する。今まで見た資料のなかで一番効く

**`docs/spec/l1-ipl.md` 第5節「推定（未確認）」の大半が、この資料で
観測の裏付けを得た。** 特に CRTC（`50`/`51`）と DMAC（`60`–`68`）は
ビット定義まで揃っており、**測定値がそのまま復号できた**。

第5b・5c節の Web 資料（出典の記載なし）より扱いは上。ただし個人サイトなので
書籍・メーカー資料より下、**測定より下**であることは変わらない。

## 禁止事項2 の確認

**ROM の逆アセンブルリスト・ROM 内ルーチンのアドレス表は無い。**
HTML を自分で取得して確認した（Z80 ニーモニックの並びの機械検出は 0 件）。

掲載されているコードは著者自身のもので、次の 2 種類。

- BASIC のサンプルプログラム（速度計測、画面設定の実演）
- 著者が書いた機械語ルーチン（BASIC の `DATA` 文の形、および V-Blank 待ちの短い断片）

**ROM のコードではないので禁止事項2 に当たらない。**
なお V-Blank 待ちの断片は `in a,($40) / and $20 / jr` という 4 行の定型で、
**自作 IPL が既に同じ形で実装しているもの**と一致した
（`src/l1_ipl/make_ipl_rom.py` の `sub_wait_vrtc`、コミット `11f6ee5`）。
こちらは資料を見る前に第5a節①のビット定義だけから書いており、
コミット順序がそれを示す。ハードウェアの定型なので一致は当然だが、記録しておく。

## 1. 測定した CRTC パラメータが全部読めた

第5節は `50`/`51` を「CRTC。`51` がコマンド、`50` がパラメータの連続書き込み」
としか言えず、値の意味は不明のままだった。μPD3301 のコマンド／パラメータ定義が
載っていたので、付録A の値を復号した。

### CRTC RESET のパラメータ 5 バイト（付録A 37-41）

| | 値 | 復号 |
|---|---|---|
| P1 | `CE` | C/B=1（キャラクタモード。必ず 1）／ H6-H0=78 → **1行 80 文字** |
| P2 | `93` | B1-B0=10（点滅間隔）／ L5-L0=19 → **画面 20 行** |
| P3 | `73` | S=0（通常表示）／ C1-C0=11（点滅する■カーソル）／ R4-R0=19 → **1文字 20 ライン** |
| P4 | `38` | V2-V0=1 → **垂直帰線幅 2 行** ／ Z4-Z0=24 → **水平帰線幅 26 文字** |
| P5 | `13` | AT1-AT0,SC = 00,0 → **トランスペアレント白黒・特殊制御文字有効** ／ A4-A0=19 → **最大アトリビュート 20 個** |

R4-R0=19（1文字 20 ライン）と V=2 行は、資料の表で
**「20 行・24KHz（高解像度）」の設定**にあたる。

### CRTC コマンド（付録A のあちこち）

| 値 | 復号 |
|---|---|
| `51 ← 00` | RESET（パラメータ 5 バイトが続く）／ パラメータ無しなら STOP DISPLAY |
| `51 ← 43` | SET INTERRUPT MASK。ME=1 MN=1 = **両方無効**。資料いわく「DMAC をオートロードモードで使う場合は両方 1 にする」 |
| `51 ← 20` | START DISPLAY。DM=0 = 通常表示 |
| `51 ← 80` | LOAD CURSOR POSITION。CM=0 = **カーソルを表示しない** |
| `51 ← 81` | 同上。CM=1 = **カーソルを表示する** |

### DMAC（付録A 32, 43）

`68` の出力は bit7 オートロード／bit6 TC ストップ／bit5 拡張ライト／
bit4 回転優先／bit3-0 が ch3-ch0 のイネーブル。

| 値 | 復号 |
|---|---|
| `68 ← A0` | オートロード=1、拡張ライト=1、**EN=0000（全チャネル禁止）** |
| `68 ← E4` | オートロード=1、TC ストップ=1、拡張ライト=1、**EN=0100（ch.2 のみ許可）** |

第5a節②の読み（全チャネル禁止にしてから触り、最後に ch.2 だけ許可）が
ビット単位で確認できた。オートロードが最初から立っている点が新しい。

### DMA ターミナルカウント（付録A 35-36）

`65` は bit7-6 が動作モード、bit5-0 が TC 上位。

```
65 ← 5F  (下位)      TC = 0x095F = 2399  → 転送量 2400 バイト
65 ← 89  (上位)      bit7-6 = 10 = リード
```

## 2. **80桁×20行が、3 つの独立な測定値から一致して出た**

これがこの調査で一番強い結果である。**別々の量から別々の計算で同じ結論が出た。**

| 根拠 | 導出 | 結論 |
|---|---|---|
| DIP スイッチ `IN 30 → DB` | bit3=1 → 20行、bit2=0 → 80桁 | 80桁×20行 |
| CRTC パラメータ `93` / `CE` | L5-L0=19 → 20行、H6-H0=78 → 80文字 | 80桁×20行 |
| DMA ターミナルカウント `095F` | 2400 = (80桁 + 40アトリビュート) × 20行 | 80桁×20行 |

`docs/notes/feedback_measure_the_end_not_the_signal.md` は
「不自然に揃った数字は観測系の故障を疑う」と言う。今回は**同じ値の使い回しではなく、
異なる量を異なる計算で突き合わせて一致した**ので、これは本物の裏付けである。

なお資料は「25 行のときは 24 を設定します」「テキスト VRAM なら 3000-1 など」と
25 行を標準として説明しているが、**測定対象は 20 行で起動している**。
DIP スイッチがそう設定されていたということ。
第8節の宿題「DIP スイッチ設定を変えたときに P0 の読み出し値が変わるか」に対し、
**`IN 30 → DB` の読み値と、その後の CRTC/DMA 設定が矛盾なく繋がっている**ことが確認できた。

## 3. **定常状態の 7 件の正体が分かった**

第3節は毎フレームの 20 イベントを列挙するだけで、何をしているのかは書かれていない。
CRTC コマンドが読めたので、意味が通る。

```
OUT 31 ← 19      画面モード（後述）
OUT E4 ← 01      割り込みレベル
OUT 51 ← 81      LOAD CURSOR POSITION、CM=1 = カーソルを表示する
OUT 50 ← 16      パラメータ1: X = 0x16 = 22 桁目
OUT 50 ← 01      パラメータ2: Y = 1 行目
IN  51           READ STATUS
IN  0B..00       キースキャン
OUT E4 ← FF      割り込みレベルを戻す
OUT 31 ← 19
```

**毎フレーム、カーソルを (22, 1) に置き直している。** アイドル状態の
BASIC プロンプトでカーソルが点滅している、その実体である。

初期化中の同じ形も読める。

| 付録A | 値 | 復号 |
|---|---|---|
| 165-167 | `51←80` `50←00` `50←00` | カーソル**非表示**、位置 (0, 0) |
| 321-323 | `51←80` `50←12` `50←01` | カーソル**非表示**、位置 (18, 1) |
| 344-350 | `51←81` `50←16` `50←01` | カーソル**表示**、位置 (22, 1) |

起動メッセージを出しながらカーソルが進み、最後に表示 ON になって定常状態に入る、
という筋が通る。

**ただし「なぜ毎フレーム 1 回なのか」は依然として分からない。**
資料は V-Blank 待ちにポーリングと割り込みの両方があると書くだけで、
公式 ROM がどちらを使っているかは資料からは決まらない。
`docs/notes/m4-l1-impl.md` の宿題1 は**測定でしか解けない**（定常状態の `pc` を見る）。

## 4. ポート `31` が読めた — メモリマップの宿題に効く

第5a節は `31` OUT を「b0 200LINE、b1 MMODE、b2 RMODE…」と略号で載せるだけだった。
この資料は意味を書いている。

| bit | 意味 |
|---|---|
| 5 | 専用高解像度 CRT のラインコントロール 0=20行 1=25行 |
| 4 | グラフィック画面カラー 0=白黒 1=カラー |
| 3 | グラフィックディスプレイ 0=表示しない 1=表示する |
| 2 | ROM モード 0=N88-BASIC 1=N-BASIC |
| 1 | **RAM モード 0=ROM/RAM モード 1=64KB RAM モード** |
| 0 | グラフィックモード 0=640x400x1 1=640x200x3 |

測定値 `31 ← 19` = `0001 1001`:
bit0=1 → 640x200x3、bit3=1 → グラフィック表示する、bit4=1 → カラー、
**bit1=0 → ROM/RAM モード**（`0000-7FFF` が ROM）、bit2=0 → N88-BASIC。
bit5=0 → 20行。**第2節の 20 行と一致する。**

`docs/notes/m4-l1-impl.md` の宿題3「メモリマップの記述が無い。スタックの置き場を
仕様書から導けなかった」に対して、**`31` bit1 が ROM/RAM の切り替えである**ことが
分かった。自作 IPL は `31 ← 19` を出しているので bit1=0、
つまり `0000-7FFF` は ROM のまま。スタックを `F000` に置いた判断と矛盾しない。

資料には V1/V2 モードのバンク構成（テキスト VRAM がバンクメモリになる、
同じアドレス領域にメイン RAM・テキスト VRAM・グラフィック VRAM が同居する）の
説明もある。**宿題3 はこの資料でかなり埋まる。**

## 5. テキスト VRAM が `F3C8` である理由

第5a節②は「`F3C8` は計測ハーネスがテキスト画面を読み出している番地と同じ。
別々に決めた 2 つの値が一致したので確からしい」としていた。**算術的な理由が判明した。**

> (80 桁 + 40 アトリビュート) × 25 行 = 3000 byte (`$BB8`) とすると、
> `$F3C8` + `$BB8` = `$FF80` ということで、終わりの部分に揃えてある

25 行ぶんの領域が `FF80` で終わるように先頭を決めた結果が `F3C8`。
N-mode では `F300` ちょうど、とも書かれている。

## 6. 資料の誤記を測定が正した（1 点）

パラメータ4 の Z4-Z0 について、資料は見出しで「**水平帰線幅-2**」と書きながら、
本文では「文字数-1 で指定します」「24KHz では 26-1=25 を設定します」と書いている。

測定値は `Z4-Z0 = 24`。`26 - 2 = 24` なので、**見出しの「-2」が正しく、
本文の「-1」「26-1=25」が誤記**である。

**測定と食い違ったら測定を優先する**（第5a節・第5b節）。
この資料も例外ではない、という実例として記録する。

## 仕様書 第2版への提案（仕様セッションへ）

1. **第5節の推定表から `50`/`51`・`60`–`68`・`31`・`40` を外し、
   観測＋資料の節へ移す。** ビット定義まで揃った。
2. **第2節 P2 に復号を併記する。** 「CRTC パラメータ 5 バイト」ではなく
   「80桁×20行・24KHz・白黒テキスト・アトリビュート20個」と書ける。
3. **第3節に定常状態の意味を書く。** 「毎フレーム、カーソルを (22,1) に置き直す」。
4. **第0節に測定条件として機種・DIP スイッチ設定を足す。**
   `IN 30 → DB` が 80桁×20行・N88-BASIC を意味することが分かったので、
   条件の一部は測定値から復元できる。
   （`refs-pc8801ma-manual.md` の「ポートは 12 個でなく 15 個」の指摘と同じ宿題）
5. **第8節の宿題を 2 つ減らせる。**
   - 「`IN 30`/`IN 31` は 1 条件でしか測っていない」→ 何のビットかが分かった
   - メモリマップ（`m4-l1-impl.md` 宿題3）→ `31` bit1 と V1/V2 バンク構成で埋まる

**残るのは宿題1（定常状態が割り込み駆動か）だけで、これは測定でしか解けない。**
