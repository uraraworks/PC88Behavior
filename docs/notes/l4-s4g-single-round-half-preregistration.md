# l4-s4g — 単精度の丸めの半端の扱い（候補EXACT/GW） — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

予測器の桁生成には2種類ある。`EXACT`（値の厳密な10進値を偶数丸めで6桁
に丸める）と`GW`（GW-BASICの`$FOUT`の手順どおり、「0.5を足して切り
捨て」＝半分は常に絶対値の大きい側へ丸める）である。この2つの手順が
食い違う打鍵可能な定数を、予測器の担当が乱数で探索し、単精度で20個
見つけた（`1d57966`・`826f69e`、
`docs/notes/l4-mbf-oracle.md`）。この20個はいずれも、6桁へ丸めると
ちょうど半分（0.5の位置）になる値である。

N88の`PRINT`が単精度の出力でこの「半端」をどちら側へ丸めるかは、これ
までの`l4-s4a`〜`l4-s4f`の測定では突き止めていない（`LEN7`等の候補は
固定⇔指数の切替境目を見るものであり、半端の丸め方向は別の軸）。本
ノートは新しい20腕で、Z80の出力変換がどちらの手順に合わせているかを
前向きに検証する。

## 候補（定義）

書式の他の規則（有効桁6桁、末尾0除去、固定⇔指数切替の境目`LEN7`、
大きい側の切替規則）は仕様書`docs/spec/l4-basic.md`第3.3版
（`4df3908`）どおりで、両候補に共通する。異なるのは6桁目を決める
「ちょうど半分」の丸め方向だけである。

- **`EXACT`**: 6桁への丸めが偶数丸め（銀行丸め。5の次の桁が偶数になる
  方向へ丸める）
- **`GW`**: GW-BASICの`$FOUT`の手順どおり（半分は常に絶対値の大きい
  方向へ切り上げる）

## 腕

20腕、すべて`single_round`群。打鍵文字列は`print <値>`の形で、値は
依頼文の20個をそのまま使う（`R1`〜`R20`）。文字数（`\n`を1文字として
含む）・写し(前)=690固定・写し(後)・走行フレームは、`l4-s4f`
（[l4-s4f-double-large-value-format-switch-preregistration.md](l4-s4f-double-large-value-format-switch-preregistration.md)、
`bbaea36`）と同じ式（全腕一律`dump(k)=line_end(k)+300`・
`run(k)=dump(k)+200`）でそのまま計算する。

```
line_end(k) = 700 + 8 * (その腕で打った文字数の累計、\n も1文字)
dump(k)     = line_end(k) + 300
run(k)      = dump(k) + 200
```

## 条件・器具

`l4-s4f`（`bbaea36`）の「条件・器具」「記録する内容」「本文を出さない
取り扱い」「関門」節をそのまま踏襲する。写しの時刻は全腕一律
`dump(k)=line_end(k)+300`（`l4-s4d`追補以来の扱い）とし、関門G8
（後の写しにOk行が現れていること）を含めてG1〜G6・G8を適用する（G7は
対になる予測表が無いため本測定にも適用しない）。

- 分類器は`5735eb3`の`tools/l4_s4a_float_classify.py`を使う
  （`l4-s4a`〜`l4-s4f`と同じ、二重実装しない）。
- 予測表は`docs/notes/l4-fout-exact-vs-gw-candidates.tsv`（列: typed,
  type, exact, gw。コミット`826f69e`で事前登録に先立ってすでにコミット
  済み。**中身は読まない・触らない**）とする。G6（予測表が測定開始
  より前のコミットに存在し、その後変更されていないことを`git log`で
  確認する）を適用する。**照合では、予測表の`typed`列の値と腕の打鍵
  文字列（`print`と改行を除いた、打った値そのもの）を対応づけて使う**
  （腕IDとの対応ではなく、`typed`列の値そのものをキーにする）。

## 記録する内容

`l4-s4a`〜`l4-s4f`本体と同一。腕ごとに、差分モードで得た「前が空白
だったセル」の(相対の行, 相対の桁, 文字コード)の並びと、原点セルの
絶対位置(row0, col0)を記録する。複数行にわたる出力は行ごとに記録する。

## 本文を出さない取り扱い

`l4-s4a`〜`l4-s4f`と同一。出力行の全セルの文字コードが「数字0-9・`.`・
`+`・`-`・`E`・`D`・空白」の集合に入る腕だけコードを記録し、1セルでも
集合外があれば件数と位置の範囲だけを記録する。分類器
（`tools/l4_s4a_float_classify.py`）は集合外のコードを標準出力・標準
エラーへ出さない設計であることが`5735eb3`の時点で確認済み。

## 関門

`l4-s4f`のG1〜G6・G8と同一。

- G1 器具の自己検査（本体と同一の自己検査群）
- G2 取りこぼし0・打てない文字の警告0
- G3 決定論性: 各腕2走とも写し・記録のsha256が一致
- G4 陰性対照: 何も打たない走で差分0件
- G5 陽性対照: `print 7717\n`腕で`7717`の並びを確認
- G6 予測表の固定: `docs/notes/l4-fout-exact-vs-gw-candidates.tsv`が
  測定開始より前のコミットに存在し、以後変更されていないことを
  `git log`で確認する
- G8 出力完了の確認: 「後」の写しで、出力行の後に`Ok`行が現れている
  こと（`ok_relative_row`相当の値が得られること）。現れない腕は
  `gate_failed`とし、「写しが早すぎた」とだけ記述する

## 判定

判定名は`l4-s4c`〜`l4-s4f`と同じものを使う。「記録する内容」節を参照
する。

- 腕ごとの分類: `numeric_output`/`non_numeric_output`/`gate_failed`
  （`l4-s4a`〜`l4-s4f`と同じ）。
- 候補ごとの判定: 予測表の各候補列（`exact`・`gw`）について、**全20腕**
  で、予測文字列を出力行の相対桁0から置いたときの非空白セル(相対桁,
  コード)の並びが実測と完全一致すれば`candidate_consistent`、1腕でも
  一致しなければ`candidate_rejected`。`gate_failed`の腕がある場合、
  その候補は判定不能とし`other`とする（理由を記述）。
- 型のまとめ: `EXACT`・`GW`の2候補のうち`candidate_consistent`だった
  個数で決める。
  - **`unique_survivor`**: ちょうど1つ
  - **`multiple_survivors`**: 2つとも`candidate_consistent`
  - **`no_survivor`**: どちらも`candidate_rejected`
  - `no_survivor`の場合も、`l4-s4c`〜`l4-s4f`と同じく**候補を後から
    足して判定し直すことはしない**。次の事前登録に回す。

## 負の数の扱い

`l4-s4c`追補1・`l4-s4d`〜`l4-s4f`の手順をそのまま使う。

- **負の数（R1・R3・R7・R8・R9・R11・R12・R13・R15・R16・R17・R18・
  R20の13腕）**: 実測側・予測側の双方について、非空白セル列の先頭に
  `-`（コード`0x2D`）があれば、そのセルだけを一旦除く（無ければ何も
  除かない）。除いた残りのセル列どうしを、`-`を除いた後の並びの中の
  相対順序で突き合わせる。符号`-`の有無と位置は、判定と別に記述として
  記録する。
- 計算値（除算等）の腕は本測定には含まれない（すべて定数の直接指定）。

## 器具の確認（公式ROMは使わない）

測定開始前に、自作main ROM（測定時HEAD `826f69e`から
`src/build_main_rom.py`で組み立て）に対し、20腕すべてを打鍵し、エコー行
（打った行そのもの）が打鍵文字列どおりに届くかを
`tools/l4_vram_probe.py --marker`（打鍵文字列そのものをmarkerに指定）で
確認した。出力行の中身は見ていない。

結果: **20腕すべてでエコー行に打鍵文字列がそのまま出現した**（marker
一致1件ずつ、打鍵前の走行失敗〔型チェックによる事前拒否〕も無し）。
負の数（`-`）を多数含め、届かなかった記号は無かった。

作業に使ったROM・写し・スクリプトはリポジトリ外の使い捨てディレクトリ
（scratchpad配下）に置き、確認後に削除した。

## 判定後の行き先

- `unique_survivor`なら、その候補（`EXACT`または`GW`）を単精度の丸め
  半端の規則として確定する（仕様書への反映は本ノートの担当範囲外と
  する）。
- `multiple_survivors`なら、`EXACT`・`GW`を区別できる腕（さらに別の
  「ちょうど半分」の定数）を次の事前登録で立てる。
- `no_survivor`なら、`EXACT`・`GW`のいずれでもない丸め規則（例えば
  常に切り捨て・常に切り上げ等）を次の事前登録で検討する入力とする。
