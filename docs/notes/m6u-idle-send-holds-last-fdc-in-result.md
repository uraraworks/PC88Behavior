# M6u — 単発1バイト応答: 直近のFDC_IN結果を持ち越す構造の裏付け

日付: 2026-08-12
根拠: 既存ログ `measurements/m6c-sub-d0-boot.iolog.txt.gz`（sub節）の
再解析。**追加測定は行っていない**。値（`$FB`/`$FC`/`$FD`のデータ）は
見ていない。見たのはポート番号・方向（IN/OUT）・発生順（seq）・PCのみ。

## 背景

`docs/notes/m6t-idle-send-no-fdc-and-rearm-timing.md`で、
`SEND_DISPATCH_IDLE`（単発1バイト応答）を「FDCを叩かない構造」に
戻したところ（第20版）、送る値を無意味な`0x00`固定にした結果、
混成ROM実走診断でmain側の構造的一致件数が258件→102件へ後退した
（第9版のFDC問い合わせ構造・258件よりも悪化）。つまり**構造だけ
合わせても値がmainの分岐を左右する**ことが分かった。

「構造（FDCを叩かない）」と「値（FDCから実際に得た値）」を両立
させるため、「過去にFDC_INが実際に読んだ結果バイトをRAMに保持し、
1バイト応答時にはFDCを叩かずその保持値を返す」という方針を検討する。
どの時点のどの結果を保持するかを、既存ログの構造だけから確認する。

## 手順

`measurements/m6c-sub-d0-boot.iolog.txt.gz`のsub節（`# sub`以降、
ハッシュ検証用サマリより前）から、`OUT $FD`（1バイト応答送信、
`SEND_BYTE`が発行するポート）が最初に現れる箇所を探し、その直前で
最後に`$FA`/`$FB`（FDCの制御・データポート）へアクセスしたのが
どの命令列かを、ポート番号・方向・PCだけで確認した。値は見ていない。

```
seq   port  dir  pc
7243  00FD  OUT  071E   ← 最初のOUT $FD（1バイト応答）
```

直前のFDCアクセス（時系列を遡る）:

```
seq   port  dir  pc
7214  00FA  IN   029A
7215  00FB  IN   02A1   ← これがOUT $FDより前の最後のFDCアクセス
```

seq7215以降、seq7243（OUT $FD）までの間はFDCポート（`$FA`/`$FB`）への
アクセスが1件も無い（`$FE`/`$FF`のハンドシェイクのみ）。

## 直前のFDCアクセスの構造的な位置づけ

seq7215の`IN $FB`（pc=02A1）に先行する区間（seq7112〜7214）は、
`IN $FA`（ポーリング、pc=02A8）→`OUT $FB`または`IN $FB`（pc=02B1/02A1）
という単位が繰り返し現れる構造で、これは起動時FDC初期化バッチ
（1.22節、`FDC_RECALIBRATE`→`SENSE INTERRUPT STATUS`の反復）と一致する。
直近の単位は、`IN $FA`(pc=029A)→`IN $FB`(pc=02A1)が2回連続する形
（seq7211〜7215）であり、これは`SENSE INTERRUPT STATUS`の結果2バイト
（ST0・PCN）を読む構造と一致する（μPD765/8272データシート、
1.22節参照）。すなわち**OUT $FDの直前にFDC_INが最後に読んだのは、
起動時FDC初期化バッチの最後のSENSE INTERRUPT STATUS呼び出しの
結果2バイト目（PCN相当）**である。

## 結論

- 「FDCを叩かない」構造（第20版で確定）と、「OUT $FDより前の最後の
  FDCアクセスはFDC_INの結果読み出しであり、それ以降追加アクセスは
  無い」という本ノートの観測は矛盾しない。
- したがって、「FDC_INが結果フェーズを読むたびにRAM（`LAST_FDC_RESULT`）
  へ保持しておき、`SEND_DISPATCH_IDLE`はFDCへ新規アクセスせずこの
  保持値を送る」という構造は、d0-bootのこのケースでは実走の構造と
  矛盾しない。
- **ただしこれは「d0-boot」という1条件・1箇所からの一般化である。**
  他の局面（`d1-files`等の別条件、あるいは同条件内の別ラウンド）で
  「直近のFDC_IN結果」がどのコマンドの何バイト目に対応するかは、
  本ノートでは確認していない。「直近のFDC_IN結果を汎用的に持ち越す」
  という設計自体は、6節14項が要求する「実際にFDCから得た値を返す」
  ことは満たすが、「どの値を持ち越すべきか」の一般則としての正しさ
  までは測定で裏を取れていない（未確定のまま`docs/spec/l3-subrom.md`
  3節に明記する）。
