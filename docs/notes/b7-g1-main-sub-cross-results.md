# B7: G1 の途切れが main 側かサブ側かを、ROM の組み合わせで切り分ける — 結果

記録日: 2026-10-31
規則: [b7-g1-main-sub-cross-preregistration.md](b7-g1-main-sub-cross-preregistration.md)（570d877）どおり。変更なし。
測定はクラウドの実行環境で 4 腕各 2 走、すべて rc=0。以下の入力は白リストを通った要約だけで、生ログは誰も開いていない。
記録: `measurements/b7-g1-*`。

## 対照

- OO・SS の境界記録の濾過後が B1・B5 の記録とバイト一致。入出力の要約も B6 と（走の名前の行を除いて）一致
- 各腕の走1と走2は入出力の列が `same`、境界記録もバイト一致

## 結果

| 腕 | main | サブ | 対 OO | 位置 | 記録 A の飛び先 | instr ram / rom | 取りこぼし |
|---|---|---|---|---|---|---|---|
| OO | 公式 | 公式 | same | 941113 | 8 | 26179347 / 150587 | 0 |
| OS | 公式 | 自作 | 自作が先に途切れる | 13510 | 8 | 27325211 / 150476 | 0 |
| SO | 自作 | 公式 | 自作が先に途切れる | 215451 | 0 | 30585038 / 47909 | **1615877** |
| SS | 自作 | 自作 | 自作が先に途切れる | 13510 | 0 | 27071660 / 510375 | 0 |

第4節の表の判定: OS は位置 13510 で届かない。SO は位置が 13510 を超えるが記録 A が空なので、定義の上で届かない。
よって「**届かない・届かない**」（どちらにも足りないものがある）に当たる。

## 1. 位置 13510 はサブ側で決まる

サブが自作の腕（OS・SS）はどちらも同じ位置 13510 で途切れ、要約のポート別の集計も同じである。
公式サブの SO はここを越える。main の組み合わせによらないので、**この途切れは自作のサブ ROM で起きる。**
なぜ途切れるかは、この測定からは言えない。比べたのは並びだけで、値は比べていない。

## 2. その先は main 側で別に止まる

SO は位置 215451 まで公式と同じ並びで進む。その最後の要素は `IN $44` で、公式はこれを1回で次へ進むところ、
SO は **8077161 回続けて読み、ログの上限（8388608 件）に達した**。取りこぼしはここで起きているので、
位置 215451 より後は記録が無く、最後まで `IN $44` だけだったとは言えない。
サブは公式なので、**この止まり方は自作の main ROM の組み合わせで起きる。**

## 3. 記録 A は main ROM だけで決まる（B1 の需要の読み直しが要る）

飛び先の数は OO・OS で 8、SO・SS で 0 で、サブによらない。そして次の2つが分かった。

- **SO は記録 A が 0 のまま 215451 要素進む。** G1 はここまで、自作 main の上で ROM の領域へ一度も横断しない
- **OS は途中で止まるのに 8 番地が出そろう。** 飛び先も OO と少し違う（OO の `3827`・`6B62` に対し、OS は `382B`・`3865`。他の 6 番地は同じ）

B1 では記録 A を「ゲームが要る番地」として次段へ渡した。この結果は、その読み方が正しいとは限らないことを示す。
RAM 上で走る公式 ROM 自身のコードが自分の領域へ戻る横断を、記録 A が拾っている可能性がある（**推定。未確認**）。
確かめるまで、8 番地を実装の需要として扱わない。方針ノート第5節の「置いた番地には根拠の測定 ID が付く」を、
この 8 番地についてはまだ満たしていない。

## 器具についての補足

q88measure は `--rom-dir` に「ディスク名.srm」を書き出す。B6 の走では公式 ROM の置き場に残っていたが、ディスク名が走ごとに違い、
B7 では消してから走らせて OO が B6 と一致したので、結果への影響は見えない。手元の `private/rom` に多数の `.srm` が
たまっていた原因もこれとみられる（件数のみ確認。名前は見ていない）。

## 次段（別に事前登録する）

1. **サブ側:** 位置 13510 までに、OO と OS で値が同じかを、値を出さずに比べる。最初に違うポートと位置だけを得る
2. **main 側:** `IN $44` の待ちが何で決まるかを、自作の刺激と介入で測る
3. **記録 A:** 8 番地がゲームの需要か、公式 ROM 自身の動きかを切り分ける
