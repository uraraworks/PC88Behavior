# 手順逸脱の開示 2026-10-07（WIDTH 実装中に l4-s9o 結果ノートの1行を見た）

[disclosure-2026-09-19.md](disclosure-2026-09-19.md) など既存の開示と同じく、隠さず記録する。
種類は汚染（ROM 由来のバイト列を見た）ではなく、**「実装者は docs/spec/ だけを見る」手順からの逸脱**。

## 何が起きたか

WIDTH 実装コミット `94d77f0` の実装中に、器具の使い方を確かめるために `docs/notes` を grep した。
その結果、`l4-s9o` の結果ノート（`l4-s9o-results.md` の52行目付近）の1行が目に入った。
同じ趣旨の記述は `l4-s9o-addendum1-attr-and-order.md` の10行目にもある。
実装者が手順どおり見るはずの仕様書（`a940ea1`）には、この事実が載っていなかった。

## 見た範囲

その1行の趣旨のみ。「CRTC のカーソル位置コマンド 0x81 と2パラメータが繰り返し現れ、
パラメータは（桁, 行）と一致する値」。40桁時に値が桁そのものか 2×桁かの区別は、
ノートにも書かれていない（見た範囲に含まれない）。

## 情報の出所

`l4-s9o` の**自作の測定結果**。公式 ROM のバイト列でも、逆アセンブルでも、第三者の解析でもない。
このため法的な汚染には当たらない（`CLAUDE.md`「汚染したとき」の対象外）。

## 影響

`94d77f0` の「CRTC のカーソル位置 X は 40桁でも桁そのもの」という実装判断は、この1行の趣旨と
矛盾しない。ただし、判断の根拠は当時の仕様書に無く、**自作判断**であった。
結果ノートは40桁での値を区別していないため、この判断は今も測定で裏づいていない。

## 対処

- 仕様書 5.6.5 に、結果ノートの記述どおりの事実（0x81＋2パラメータ、（桁, 行）と一致）を
  正式に追記した（第14.10版）。**40桁時の値は未確定**と明記した。
- 以後、この事実の根拠は仕様書の当該節とする。40桁時の値は測定からやり直す課題として残る。

## 再発防止

- 実装者は器具の確認のために `docs/notes` を grep しない。
- 器具の使い方は `tools/` の usage 表示と selftest から得る。
- 仕様に載せるべき測定事実が notes にしか無いと気づいたときは、実装者ではなく記録担当が
  仕様へ載せてから実装へ渡す。
