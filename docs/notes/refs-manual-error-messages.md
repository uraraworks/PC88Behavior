## 追記 2026-09-15 — 表示の形の規則、および l4-c2 の件数との突き合わせ

l4-c2（`docs/notes/l4-c2-print-conformance-results.md`、診断
`docs/notes/l4-c2-error-signature-diagnosis.md`）で、公式の署名が一覧の文言
だけの行と一致しないと分かったのを受け、マニュアルで表示の形の説明を確認した。

### 読んだ場所

- `manual.txt` 1125行目付近／`manual_squashed.txt` 1499行目付近。「資料6
  エラーメッセージ」の項の**冒頭の説明文**（一覧の表より前、資ー6、PDF頁
  382付近）。既存の記録（一覧本体）と同じ項の中だが、今回は冒頭の説明文だけ
  を新たに読んだ。
- `manual_squashed.txt` 1527行目付近（`Missing operand[22]`、資ー13、PDF頁
  389付近）と1539行目付近（`Syntax error[2]`、資ー16、PDF頁392付近）。
  それぞれの「意味・原因」の説明。

### 1. 表示の形の規則

冒頭の説明文（要旨）: ダイレクトモードでのエラーメッセージの書式は
「メッセージ本体」、プログラムモードでの書式は「メッセージ本体 + `in` +
行番号」である、と述べている。ただしOCR上、メッセージ本体を指すプレース
ホルダの前に記号が本当は付いていたのか（他の箇所、たとえば `?Redo from
start` の項では `?` がOCRで残っている）、今回の冒頭説明の箇所では読み取れ
なかった。**「メッセージの前後に付くもの」を資料の文面から断定はできない**
（OCR崩れで有無を判定できない1箇所として記録する。断定的な記述は避ける）。

行番号の付き方については、資料の文面どおり「ダイレクトモード＝行番号なし、
プログラム実行中＝`in <行番号>` が付く」という直接モード/プログラムモードの
違いは明記されている。

### 2. メッセージと誤りの対応

- `Missing operand[22]`「ステートメント中必要なパラメータが指定されていない」
  の原因の1つに「演算子があるのに被演算子がない」と明記されている。
  すなわち**式が演算子で終わって続きがない誤りは `Missing operand` に対応する**
  という記載がある。
- `Syntax error[2]`「文の記述が文法どおりになっていない」の原因は
  「タイプミスで文法に合わないものが紛れ込んでいる」「変数名が英字で始まって
  いない」等、複数列挙されているが、**未知の語（コマンド名の綴り間違い等）を
  個別には挙げていない**。ただし列挙の最初が「タイプミスで文法に合わない
  ものが紛れ込んでいる」であり、これが該当しうる（資料は網羅列挙ではなく
  代表例の列挙）。

### 3. 件数（12・15）との突き合わせ

l4-c2診断にある「空白でない文字数」は `Syntax error` で11、`Missing operand`
で14。観測された署名の空白でない文字数は `printx 1` で12、`print 1+` で15
——**どちらも一覧の文言ちょうど+1文字**になっている。

冒頭説明文の書式規則そのもの（メッセージ本体の前後に付くもの）はOCRで断定
できなかったが、+1文字という**差分の大きさ**は、他の箇所で確認できる
先頭1文字の記号（`?Redo from start` の `?` 等、この資料内でエラーに類する
メッセージの先頭に付くとされる記号）が両方に付くと仮定すれば説明がつく
——ただし、資料6冒頭の説明文自体からこの記号の有無を直接読み取れていない
ため、この一致は**傍証**であって確定ではない。行番号は今回の件（直接モード
実行）では付かない前提（資料の記述どおり）なので、+1文字は行番号側の要素
ではない。

## 追記 2026-09-15（2） — 資料6冒頭をPDF頁画像で確認、上の推測を訂正

上の「傍証」はOCRテキストで記号の有無を断定できなかったための推測だったが、
指摘を受けて `pdftoppm -f 382 -l 382 -r 150 -png` でPDF頁382（資ー6）を
画像化し、縮小（`sips -Z 1600`）してから該当箇所を直接読んだ。

### 読めた形

書式説明は組版上、以下のように**独立した行**として示されている。

- ダイレクトモードでの書式: 「XX」（`XX` という2文字の記号だけの行。前にも
  後ろにも他の文字は無い）
- プログラムモードでの書式: 「XX in IIIII」（`in` という単語と、行番号の
  桁を表すプレースホルダ `IIIII` が続く。同じく前後に他の文字は無い）

**「XX」の前後に `?` などの記号が付くという記述はこの書式説明には無い。**
OCRが記号を消していたのではなく、そもそも書式説明の行に記号は組まれていない
（画像で直接確認したので、OCR崩れの可能性は排除できる）。

### 件数（12・15）と合うか

**合わない。** 上の追記で立てた「傍証」（`?` 等の先頭1文字が両方に付けば
+1文字を説明できる、という仮説）は、書式説明そのものには根拠が無いと分かった。
資料6冒頭が定める書式（ダイレクトモード＝メッセージ本体のみ）を文字どおりに
適用すると、`Syntax error`（11文字）・`Missing operand`（14文字）はそのまま
の文字数になるはずで、観測された12・15（一覧文言+1）を資料のこの書式規則
では説明できない。**+1文字の由来は、この資料の書式説明からは分からなかった**
——別の要因（本文でカバーされない挙動、あるいはマニュアルの他の版・箇所）を
探す必要がある。
