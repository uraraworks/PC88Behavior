# l4-s9n 追補1 — ポート0x40の「最初の書き込み」が立ち上がりに数えられない器具の隙間

状態: **再測定前**（2026-10-07）。本追補は器具の修正と再測定の前に固定する。
公式第1回測定（`../tmp/s9n-work/official_round1.tsv`、138腕×2走、関門は全腕通過）は
[事前登録](l4-s9n-widthbeep-preregistration.md)（9da209e）と[器具](../../tools/l4_widthbeep_measure.py)（a625dcc）で行った。

## 経緯

BEEP 腕（ポート採取つき13腕）で、鳴らす腕の観測が「bit 5 の立ち下がりだけ」になり、立ち上がりが一度も出なかった（`beep-1-only` は書き込み1件で変化なし）。
bit 5 を立てる書き込みが窓の中の**最初の書き込み**になっており、器具は「窓の手前の記録（手前 600 フレームから）に $40 への書き込みが無い」ため
比較相手を持たず、最初の書き込みを変化に数えない規則だった（事前登録に書いた規則どおり）。つまり**立ち上がりの検出が構造的に落ちる器具の欠陥**で、
ハードウェアの事実ではない。BEEP の腕の differ（8腕）は全て、この欠陥の影響下にある（予測は立ち上がり・立ち下がりの両方）。無音対照（`rem`）は欠陥を踏まない形だったので素通りした。
器具の欠陥であって、予測が外れたのではない。第1回の BEEP 腕の観測は結果ノートに残し、予測は書き換えない。
他の腕（比較式・WIDTH）はポートを使わないので影響を受けない。

## 修正の内容

- 記録の開始を窓の手前 600 フレームから**第1フレームから**に変える（`--io-log-from-frame 1`）。起動時のROMの書き込みが比較相手になる。
- それでも窓の手前に書き込みが無い腕があれば、最初の書き込みは比較相手なしとして数えず、その腕は「手前の書き込みなし」と観測に記録する（`prior` 欄。値列ではなく有無）。
- 集計の陽性・陰性の自己検査は、窓の手前の書き込みがあれば最初の窓内の書き込みが立ち上がりに数えられること、手前に書き込みが無ければ `prior=0` になることを加える。
