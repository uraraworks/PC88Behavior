# m7lh: データのCRCエラーでも公式の「9」は変わらない（ZA1）——ただし採用した自作は読み直さない

実施日: 2026-09-11
事前登録: [m7lh-...-preregistration](m7lh-data-crc-error-preregistration.md)
（**測定前に単独コミット済み**。媒体・数え方・判定規則は本稿で動かしていない）

## 主判定と副判定

> **主判定 ZA1。** 公式一式は、**データのCRCエラーの媒体でも、READ DATAを1送信単位の内側で9件
> 出す**（117件・連続96対・最長9）。**1.58節の「9が依存しないもの」の「失敗の原因」は3種類になる**
> ——トラック不在・セクタ不在・データのCRCエラー。
>
> **副判定: 食い違いが見つかった。** **採用した自作サブROMは、同じ媒体で1回も読み直さない**
> （14件・連続0）。**これは`m7kr`の更新の条件「公式の振る舞いと食い違う条件が見つかったとき」に
> 当たる。** 実装の作り直しは本稿ではやらない（事前登録どおり）。

## 主表（値は1つも含まない。件数と公開ビットの復号名のみ）

| 媒体 | 側 | READ DATA | 連続した対 | 最長連続 | 最初のエラー結果（公開ビットの復号名） |
|---|---|---|---|---|---|
| **G-OK**（40シリンダ・両面・起点1・16セクタ） | 公式 | 14 | 0 | 1 | エラーなし |
| | 混成 | 14 | 0 | 1 | エラーなし |
| **G-CRC**（G-OK＋全セクタがデータCRCエラー） | **公式** | **117** | **96** | **9** | コマンド4件目(READ DATA)、ST1=DATA ERROR、ST2=DATA ERROR |
| | **混成** | **14** | **0** | **1** | 同じ |
| **P**（m7joのD3。セクタ不在） | 公式 | 117 | 96 | 9 | コマンド4件目(READ DATA)、ST1=NO DATA |
| | 混成 | 54 | 40 | 9 | 同じ |

**すべて2回で完全に一致した。** 生ログは12本とも3000フレームまで進み、取りこぼし0。

## 段階0（すべて真）

| 項目 | 結果 |
|---|---|
| G-OK: 公式側の連続が0（読める形） | **真**（エラー結果なし） |
| G-CRC: 公式側の最初のエラー結果にデータのCRCエラー | **真**（ST1・ST2ともDATA ERROR） |
| P: 公式側で連続96対・最長9 | **真** |
| 決定論性 | **真**（12行すべて一致） |

**G-OKとG-CRCの違いはCRCエラーの有無だけ**（媒体の違いは全セクタの状態バイトだけ。生成器の自己検査で
確かめてある）。**G-OKで公式が1件ずつ・G-CRCで×9になったので、公式の粘りを引き起こしたのはCRCエラー
そのものである。**

## なぜ自作は読み直さないか

採用した実装は**`FDC_ABORT`が立ったとき**——データフェーズを最後まで受け取れなかったとき——だけ
読み直す。**計測に使うエミュレータのFDCは、データのCRCエラーでもデータを最後まで渡し、エラーは結果
フェーズで報告する**（`vendor/quasi88-libretro/src/fdc.c`のREAD DATA）。**だから`FDC_ABORT`は立たず、
自作は結果にエラーが載っていても読み直さない。** 公式は読み直す。

**測る前にこの見立てを書いたが、予測としては登録しなかった。** 見立ては当たった。

**つまり、採用した実装の再試行の条件（`FDC_ABORT`）は、公式が粘る条件と一致していない。**
公式は少なくとも「結果にデータのエラーが載ったとき」にも粘る。**条件をどう直すかは別稿で扱う。**

## 登録していない観察（合否に使わない）——Pで混成の要求の回数が少ない

**陽性対照P（セクタ不在）で、混成側は54件・連続40対・最長9だった**（公式は117件・96対・最長9）。

- **1送信単位あたり9件読むところは同じ**（最長9）。
- **違うのは送信単位の数**——連続40対は8対×5単位、公式の96対は8対×12単位にあたる。
  **mainから来る要求の回数が、公式一式より少ない。**
- **適合テストの「読めない媒体」（既定の規則生成媒体。トラック不在）では、混成は公式と一致していた**
  （[m7lg](m7lg-official-readable-retry-results.md)のP・[m7le](m7le-retry-reattempt-results.md)の条件4で117件・96対・最長9）。

**失敗の原因（トラック不在／セクタ不在）によって、9件をやり尽くしたあとに自作が返す応答が公式と
ずれ、mainの要求の回数が変わっている可能性がある。** **本稿は測っていない。** 次に測る候補として残す。

## 言えないこと

- **エミュレータで測った振る舞いは、エミュレータの実装を測っている。** とくにデータのCRCエラーで
  データを最後まで渡すかどうかは、このエミュレータのFDCの実装に依存する。**実機のμPD765が同じだとは
  言わない。**
- **「公式はIDが見つかるかどうかに関係なく粘る」とまでは書かない。** 3種類の失敗で粘った、までである。
- **「9」を決める規則は依然として書けていない。** 動かない軸が増えただけである。

## 情報境界

公式ROM・公式ディスクのバイト列を読んでいない・出力していない。A:の公式ディスクは`cp`で使い捨ての複製を
作っただけ。B:は自作の規則生成媒体。記録したのはFDCコマンドの種別名と件数、エラー結果の公開ビットの
復号名だけで、コマンドのバイト値・パラメータ・結果ステータスの生の値・時刻・frame番号・画面本文は
出していない。生ログはリポジトリ外（`PC88/tmp/m7lh-work/`）に置き、コミットしない。

## 開示

**最初の起動は、1本も走らずに止まった。** 測定の駆動スクリプトで連想配列を使ったが、macOSの`/bin/bash`は
3.2で連想配列に対応しておらず、起動直後に`unbound variable`で落ちた。**生ログは1本も作られていないので、
測定に影響は無い。** 連想配列をやめ、**作ったB:媒体の大きさを期待値と照合して違えば止まる**確認を足して
起動し直した。
