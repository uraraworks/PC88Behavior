# M3 需要プロファイル

測定日: 2026-08-07
対象: 公式 N88-BASIC ROM（32KB, メイン CPU）と DISK.ROM（2KB, サブ CPU）。
測定結果の実体: `measurements/*.txt`（アドレスとアクセス種別のみ。ROM の内容は含まない）

---

## 結論

**メイン ROM 32KB のうち実行されたのは 13458 バイト = 41.1%。**
**サブ ROM（DISK.ROM）2KB のうち 648 バイト = 32%。**

条件は 198 件（手書き 28 + 命令表から生成した 170）。
リファレンスマニュアルの索引に載っている命令をひととおり叩いた時点で、
分類ごとの増分は末尾でほぼ 0 に収束している（下表）。
ただしこれは**正常系だけ**を叩いた結果である。

測定は 2 系統ある。どちらも `measurements/` に出力し、第三者が再導出できる。

- `tools/measure_suite.sh` — 手書きの 28 条件（起動・ディスク・複合操作）
- `tools/basic_surface.tsv` + `tools/gen_suite.py` — 命令表から生成する 170 条件

### 命令表から生成する

網羅の根拠を「思いついた条件」から**公開されたリファレンスの索引**に移した。
出典は PC-8801FA/MA のリファレンスマニュアル（第2章 基本命令 166 項目、
第3章 拡張命令 16 項目）。表に入れたのは命令名という事実と、こちらで書いた
テストコードだけで、マニュアルの本文は転記していない。

**1 命令 = 1 条件にしてある。** まとめれば速いが、帰属（どの番地がどの命令の
実装か）が消える。それは L3/L4 の実装単位を切る材料であり、差分実行で
食い違ったときにどこを見るかの手がかりでもあるので、まとめない。

170 条件が 80 秒で回る。

## 分かったこと

### アイドル起動は 60 フレームで飽和する

フレーム数を 60 / 300 / 600 / 1800 / 3600 と変えても、実行された番地は
2225 バイトから 1 バイトも増えなかった。ROM はキーボードを走査して待つ
ループに入るだけで、入力が無い限り新しい経路は踏まれない。

**測定は短くてよい。** ファジングの回転数を上げられる。
需要を広げるのはフレーム数ではなく入力の種類である。

### 触れられた I/O ポート

```
メイン 入力: 00-0B 30 31 32 40 51 6E 70 71 F4 F8 FC FD FE
メイン 出力: 10 30 31 32 34 35 40 50 51 53-5F 64 65 68 70 71 C1 C3 C8 CA E4 E6 EB F3 F8 FD FF
サブ   入力: F8 FA FB FC FE
サブ   出力: F7 F8 FB FC FD FF
```

`00`〜`0B` はキーボードマトリクスの走査。`50`〜`5F` の連続は CRTC 系。
`FC`〜`FF` はディスク側で、メインとサブの両方が触っている＝2 つの CPU の
やりとりの窓口。L3 の実装単位を切るときの手掛かりになる。

## 手順上の失敗を 2 つ踏んだ（どちらも画面を見て気づいた）

数字だけを見ていたら、どちらも「そういうものだ」と受け入れて先へ進んでいた。
`q88measure` が測定結果に**終了時のテキスト画面を必ず含める**ようにしたのは、
条件が意図どおりだったかを結果自身で検証できるようにするため。

### ① 打鍵が起動プロンプトに食われていた

最初の測定では BASIC のどの機能を試しても実行番地が 3159 バイトで揃った。
FOR ループと文字列処理と三角関数が同じ経路しか踏まないはずがない。
画面を見たらこうなっていた。

```
 1| How many files(0-15)? print 1
 2| NEC N-88 BASIC Version 2.3
 5| Ok
```

起動時の `How many files(0-15)?` プロンプトに全部食われていた。
BASIC が立ち上がる前に打ち終わっていたので、コマンドは 1 文字も届いていない。
→ `--type-at` / `--type` を複数回指定できるようにし、先に RETURN で
プロンプトを抜けてから打つようにした。

### ② シフトが要る記号が別の文字になっていた

プロンプトを抜けた後も、プログラムがこうなっていた。

```
10 for j-1 to 3      ← FOR J=1 のはずが '=' が '-' に
20 print j:j         ← J*J のはずが '*' が ':' に
run
Syntax error in 10
```

コアは KEY88 コードをそのまま受け取るので、ASCII をそのまま送ると
「そのキーの**非シフト側**の文字」が入る。PC-88（JIS 配列）では
`=` は `-` の、`*` は `:` のシフト側にある。
→ シフトが要る文字の対応表を持たせ、土台のキーと同じ区間だけ
`RETROK_LSHIFT` も押すようにした。

修正後は `run` → `1 !` / `4 !` / `9 !` / `Ok` まで正しく動いている。

> これは [[定数の一致は経路の証明にならない]] と同じ形の失敗である。
> 「キーコードは正しく送っている」ことと「意図した文字が入力された」ことは
> 別の話で、後者は末端（画面）を見ないと分からない。

### ③ 原本のディスクに書かせてしまうところだった

`SAVE` を測るとき、最初は原本のディスクイメージをそのまま渡していた。
結果的には D88 のライトプロテクトフラグが立っていて `File write protected` で
弾かれ、何も書かれなかった。**運が良かっただけである。**

測定が原本を変えてしまうのは二重にまずい。27 年物のディスクが壊れるという話と、
原本が変われば以後の測定条件が変わって再現性が壊れるという話。
→ `--disk-name` は必ず使い捨ての複製を作ってそちらを渡すようにした。
書き込み経路を測るときは `--disk-writable` で**複製側の**プロテクトだけを外す。

### ④ 打ち込んだだけで実行していなかった（170 条件すべて）

命令表から生成した最初の 170 条件は、**すべて末尾の改行が抜けていた**。
コマンドは画面に出るが RETURN が届いていないので実行されない。
出力もエラーも出ないので、数字だけ見ていたら気づけない。

これを機に `gen_suite.py` に検証を組み込んだ。BASIC はコマンドを実行し終えると
`Ok` を返すので、**画面の最終行が `Ok` でなければ「実行されていない」と判定する**。
「測定できた」と「条件が成立した」は別だという当たり前のことを、
毎回機械が確かめるようにした。

検証器自身も一度間違えた。プログラム行 `20 ERROR 5` の "ERROR" を
「エラーが起きた」と誤認していた。打ち込んだ内容の echo は実行結果ではないので、
行番号で始まる行は判定対象から外した。

### ⑤ サブ CPU を測っていなかった

PC-88 は Z80 を 2 個持ち、ディスク側はサブ CPU（DISK.ROM）が担当する。
サブ ROM も再実装の対象なのに、最初のフックはメイン CPU にしか入れていなかった。
ディスク測定を始めるまで気づかなかった。

しかも `pc88sub_bus_setup()` にはメインと**まったく同じ別名化の罠**があった
（`memory_wait` が無効だと `fetch` が `sub_mem_read` に潰れる）。
同じ落とし穴が 2 箇所にあり、片方だけ塞いでいた形になる。
→ `0003-bus-trace-sub.patch` で塞ぎ、採取バッファも CPU ごとに分けた。

### 連続実行時にまれに終了処理が異常終了する

170 条件を連続で回すと、ディスクを使う条件で終了コード 134 (SIGABRT) が
まれに出る。レポートはその前に書き出されているのでデータは無傷であり、
同じ条件を単独で 5 回回しても再現せず、結果も完全に一致する。
握りつぶさず記録した上で、中身の検証は続ける扱いにしてある。

## 測って分かった ROM の挙動（`docs/spec/` に起こす候補）

まだ仕様書に昇格させる段階ではないが、観測として記録しておく。
いずれも QUASI88 のエミュレーション由来である可能性を排除できていないので、
実機または別のエミュレータでの再現を確認してから仕様として扱うこと。

- **`OPEN "O",#1,"名前"` を受け付けない。** `Syntax error` になる。
  `OPEN "名前" FOR OUTPUT AS #1` 形式なら通る。MS-BASIC 系では前者も一般的なので、
  この N88-BASIC V2.3 の方言差ということになる
- **`CALL` は定数を受け付けない。** `CALL 60000` は構文エラー。
  マニュアルの書式が `CALL <変数名>` なので、`AD=60000:CALL AD` とする必要がある
- **`MOTOR` のスイッチは数値。** `MOTOR ON` ではなく `MOTOR 1` / `MOTOR 0`
- **`ON KEY GOSUB` にキー番号は付かない。** `ON KEY(1) GOSUB` は構文エラーで、
  正しくは `ON KEY GOSUB <行番号>,...`（並びの順序がキー番号に対応する）
- **`SEARCH` は配列を検索する関数。** プログラムの文字列検索ではない
- **`MAP` は座標変換の関数。** 命令ではない
- **シーケンシャルファイルを読み戻すと先頭バイトが `0xFF` になる。**
  `PRINT#1,"ABCDE"` → `CLOSE` → `INPUT#1,Q$` としたとき、`LEN(Q$)` は 5 だが
  `ASC(Q$)` が 255、2 文字目以降は `b` `c` `d` `e` と正しい。
  ファイル種別のマーカーらしきバイトを `INPUT#` が読み飛ばしていないように見える。
  画面表示の不具合ではなく、値として 255 が入っている（`ASC` で確認）

**正常系はほぼ出尽くした。** ここから先は受動観測の効率が落ちるので、
M2（未実装領域をトラップで埋めた ROM 足場）に移って、
