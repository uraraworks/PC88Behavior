## 分かったこと

### アイドル起動は 60 フレームで飽和する

フレーム数を 60 / 300 / 600 / 1800 / 3600 と変えても、実行された番地は
2225 バイトから 1 バイトも増えなかった。ROM はキーボードを走査して待つ
ループに入るだけで、入力が無い限り新しい経路は踏まれない。

**測定は短くてよい。** ファジングの回転数を上げられる。
需要を広げるのはフレーム数ではなく入力の種類である。

### 触れられた I/O ポート

```
メイン 入力: 00-0B 30 31 32 40 51 6E 70 71 F4 F8 FC FD FE
メイン 出力: 30 31 32 34 35 40 50 51 53-5F 64 65 68 70 71 C1 C3 C8 CA E4 E6 EB F3 F8 FD FF
サブ   入力: F8 FA FB FC FE
サブ   出力: F7 F8 FB FC FD FF
```

`00`〜`0B` はキーボードマトリクスの走査。`50`〜`5F` の連続は CRTC 系。
`FC`〜`FF` はディスク側で、メインとサブの両方が触っている＝2 つの CPU の
やりとりの窓口。L3 の実装単位を切るときの手掛かりになる。

## 手順上の失敗を 2 つ踏んだ（どちらも画面を見て気づいた）

数字だけを見ていたら、どちらも「そういうものだ」と受け入れて先へ進んでいた。
`q88measure` が測定結果に**終了時のテキスト画面を必ず含める**ようにしたのは、
条件が意図どおりだったかを結果自身で検証できるようにするため。

### ① 打鍵が起動プロンプトに食われていた

最初の測定では BASIC のどの機能を試しても実行番地が 3159 バイトで揃った。
FOR ループと文字列処理と三角関数が同じ経路しか踏まないはずがない。
画面を見たらこうなっていた。

```
 1| How many files(0-15)? print 1
 2| NEC N-88 BASIC Version 2.3
 5| Ok
```

起動時の `How many files(0-15)?` プロンプトに全部食われていた。
BASIC が立ち上がる前に打ち終わっていたので、コマンドは 1 文字も届いていない。
→ `--type-at` / `--type` を複数回指定できるようにし、先に RETURN で
プロンプトを抜けてから打つようにした。

### ② シフトが要る記号が別の文字になっていた

プロンプトを抜けた後も、プログラムがこうなっていた。

```
10 for j-1 to 3      ← FOR J=1 のはずが '=' が '-' に
20 print j:j         ← J*J のはずが '*' が ':' に
run
Syntax error in 10
```

コアは KEY88 コードをそのまま受け取るので、ASCII をそのまま送ると
「そのキーの**非シフト側**の文字」が入る。PC-88（JIS 配列）では
`=` は `-` の、`*` は `:` のシフト側にある。
→ シフトが要る文字の対応表を持たせ、土台のキーと同じ区間だけ
`RETROK_LSHIFT` も押すようにした。

修正後は `run` → `1 !` / `4 !` / `9 !` / `Ok` まで正しく動いている。

> これは [[定数の一致は経路の証明にならない]] と同じ形の失敗である。
> 「キーコードは正しく送っている」ことと「意図した文字が入力された」ことは
> 別の話で、後者は末端（画面）を見ないと分からない。

### ③ 原本のディスクに書かせてしまうところだった

`SAVE` を測るとき、最初は原本のディスクイメージをそのまま渡していた。
結果的には D88 のライトプロテクトフラグが立っていて `File write protected` で
弾かれ、何も書かれなかった。**運が良かっただけである。**

測定が原本を変えてしまうのは二重にまずい。27 年物のディスクが壊れるという話と、
原本が変われば以後の測定条件が変わって再現性が壊れるという話。
→ `--disk-name` は必ず使い捨ての複製を作ってそちらを渡すようにした。
書き込み経路を測るときは `--disk-writable` で**複製側の**プロテクトだけを外す。

### ④ サブ CPU を測っていなかった

PC-88 は Z80 を 2 個持ち、ディスク側はサブ CPU（DISK.ROM）が担当する。
サブ ROM も再実装の対象なのに、最初のフックはメイン CPU にしか入れていなかった。
ディスク測定を始めるまで気づかなかった。

しかも `pc88sub_bus_setup()` にはメインと**まったく同じ別名化の罠**があった
（`memory_wait` が無効だと `fetch` が `sub_mem_read` に潰れる）。
同じ落とし穴が 2 箇所にあり、片方だけ塞いでいた形になる。
→ `0003-bus-trace-sub.patch` で塞ぎ、採取バッファも CPU ごとに分けた。
