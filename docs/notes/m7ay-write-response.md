# m7ay: 書き込みに対する応答は1レコード1バイトの固定値だった

測定日: 2026-08-19

## 情報境界

m7axで取った既存ログ（公式ROM一式・公式diskAの使い捨て複製、8回SAVE、
WRITE DATA 64件）の**再解析のみ**。追加測定なし。値は出力せず、件数・
一致件数・種類数だけを扱う。応答の値は**既にリポジトリにある観測定数と
同一**であることの確認に留め、値そのものは書かない。

## 1. 測定

各WRITE DATAの発行から次のWRITEまでの区間で、subが送ったバイト数を数えた。

- 制御6バイト（＝レコード1つ）のWRITE: sub送信 **1バイト**
- 制御12バイト（＝レコード2つ）のWRITE: sub送信 **2バイト**
- SAVEの区切りにあたるWRITEでは多数（ディレクトリ更新等の別処理を含む）

**レコード1つにつき応答1バイト**という、既知のラウンド構造（1.18節「ラウンド
ごとに応答が返る」）と同じ形である。

## 2. 応答1バイト目の性質

対象57件（応答が1〜2バイトに収まったWRITE）で:

- **相異なる値の個数 = 1**（全件同じ固定値）
- **FDCの結果フェーズより後に送られた: 57/57**
- ST0・ST1・ST2・結果のC・結果のR・要求のR・0x00 のいずれとも**一致しない**
- **その値は、m7hで既に観測していた「要求グループ2の応答」と同一**

つまり新しい値を持ち込む必要はない。意味は未確定のままである。

2バイト目（レコード2つの場合）は、`EXCHANGE3_OBSERVED_RESPONSE` と
同じ値だった（要求グループ4/5/8/9の応答とも同値）。**どちらのレコードに
どちらの応答が対応するかは、この測定範囲では確定できない**ので、
実装では1バイト目だけを扱う。

## 3. 実装

`_recv_dispatch_write_sector` で、書き込み完了後に
`WRITE_ACK_RESPONSE`（= 既存の要求グループ2の応答定数）を1バイト送る。
コードは 1903 → **1908バイト**。

## 4. 検査で踏んだ落とし穴（2回）

新しい検査（(4) 応答）の陽性対照 `--break-write-ack`（応答を送らない版）が
**2回続けて空振り**した。

1. **窓を切っていなかった。** 「WRITE以降のsub送信をすべて数える」形にして
   いたため、応答を送らない版でも後続の通信を拾って件数1以上になった。
   → 窓を「WRITE発行〜次にsubが受信を始めるまで」に限定した。
2. **件数だけでは区別できなかった。** 窓を切ってもなお件数1になる——
   **アイドルディスパッチャ経由でも1バイト出る**からである（自作subは
   mainが受信待ちに転じると既存の単発応答経路で1バイト返す）。
   → 実測が「57/57すべて同一の固定値」だったことを使い、**値まで見る**
   検査に変えた。これで陽性対照が落ちるようになった。

**「応答が出ているか」ではなく「観測した応答が出ているか」を見ないと、
既存経路の副作用と区別できない。**

## 5. 残っていること

- 制御レコード先頭4バイト（idx0〜idx3）の意味（3節）
- 2レコードのときの応答2バイトの対応関係
- 書き込みの適合判定（公式main相手）
