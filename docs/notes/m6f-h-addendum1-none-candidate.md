# m6f-h 追補1 — 終わりの印「なし」（NONE）の定義を直す

記録日: 2026-09-28  
状態: **測定前**（公式ROM起動回数 0）

## 1. 穴

事前登録 §2 の `NONE` は「予測の長さまでを照合し、＋1バイトを見ない」と定義した。このため、本体に `0x1A` や `0x00` の
印が実際にあっても `NONE` が同時に一致し、判定が必ず `inconclusive_<腕>_multiple` になる（器具を実装した担当の報告）。

## 2. 直した定義

`NONE`: 予測の長さまでが一致し、**かつ**次のどちらか。

- (a) 予測の長さ＋1バイト目が使ったセクタの範囲内にあり、その値が `0x1A` でも `0x00` でもない。
- (b) 予測の長さがちょうど使ったセクタの末尾（使ったセクタ数×256 と等しい）。

＋1バイト目は事前登録 §0.1 の範囲内（予測の長さ＋1）なので、読む範囲は変わらない。値は出力せず、候補の判定にだけ使う。
ほかの候補・腕・関門・判定名は変えない。
