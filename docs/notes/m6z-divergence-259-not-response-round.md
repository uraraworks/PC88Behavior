# M6z — 分岐点259は直前の単発応答ラウンドに由来しない

日付: 2026-08-13

## 目的

`docs/notes/m6y-response-byte-value-saturation.md`で応答値の軸が258件で
飽和したことを受け、分岐点259が直前の単発1バイト応答のバイト数、
タイミング、またはポーリング回数差に由来するかを介入測定で切り分けた。
これは仕様変更の提案ではない。m6t/m6vで確定済みの「公式subは単発
1バイト応答」という仕様は維持する。

## 応答バイト数とタイミングへの介入

送出値はFDCへSENSE DRIVE STATUSを実発行して得たST3のままとし、
`SEND_DISPATCH_IDLE`だけを一時的に変更した。X1/X2は同じST3を2回・3回
送り、X3はST3を取得するが応答を送らなかった。Y1/Y2は1バイト応答を
維持し、送出直前にI/Oを伴わない有限ウェイトループを挿入した。

| 条件 | 構造的一致プレフィックス | 最初の分岐点 |
|---|---:|---:|
| X1: 2バイト応答 | 108 | 109 |
| X2: 3バイト応答 | 108 | 109 |
| X3: 0バイト応答 | 97 | 98 |
| Y1: 短いウェイト | 258 | 259 |
| Y2: 長いウェイト | 258 | 259 |
| 復帰対照: ST3・1バイト・ウェイト無し | 258 | 259 |

0/2/3バイトはいずれも大きく後退したため、1バイト応答という構造自体は
必要である。一方、短長どちらのウェイトでも258件・分岐点259から動かず、
測定した範囲の応答タイミングは259の原因ではない。258件を超える条件は
無かった。

読まずに取得した。14件すべてが`IN $FE`のポーリング回数差で、畳み込み後
#97〜#184、すなわち分岐点259より前にある。`$FC`/`$FD`を含むデータ

合わせ、回数差を含むタイミング軸は259の直接原因として支持されない。

## 分岐点259の窓

次の表はkind、port、pcだけを掲載し、データ値を含まない。

| 番号 | 基準側 | 混成側 |
|---:|---|---|
| 254 | `OUT $E6 pc=7331` | `OUT $E6 pc=7331` |
| 255 | `IN $32 pc=3A36` | `IN $32 pc=3A36` |
| 256 | `IN $71 pc=3A39` | `IN $71 pc=3A39` |
| 257 | `OUT $32 pc=3A60` | `OUT $32 pc=3A60` |
| 258 | `OUT $71 pc=3A64` | `OUT $71 pc=3A64` |
| **259** | **`OUT $31 pc=E7F5`** | **`IN $31 pc=7752`** |
| 260 | `OUT $E4 pc=3088` | `OUT $32 pc=3DC2` |
| 261 | — | `OUT $71 pc=3DC5` |

分岐直前の一致窓はバンク切替・割り込み制御系のI/Oで、サブROM通信
ポートではない。259では同一main ROMがまったく別のPCへ進んでいる。

## 結論とm6wの訂正

m6yの値スキャン、本ノートのバイト数介入、ウェイト介入の3軸すべてで、
分岐点259を突破する条件は無かった。バイト数は1であることが必要だが、
正しい1バイト構造に到達した後の259は、値・バイト数・タイミングの
いずれにも乗っていない。

`docs/notes/m6w-main-divergence-259.md`が直前の単発応答ラウンドへ原因を
絞った着目は外れていた。m6wは当時の推論として書き換えず、本ノートで
明示的に訂正する。259の原因は、それ以前のバルク転送でmainがRAMへ
読み込んだ内容、すなわち自作subがFDCから読み出したセクタ側にある
可能性が高い。

## 次の一手と人間による判断事項

次は、バルク転送でmainが受け取る内容の妥当性、とくに自作subがどの
セクタを読みに行っているかを検証する。FDCへ出すC/H/R（シリンダ、
ヘッド、セクタ番号）はディスク内容そのものではなくアクセス位置であり、
`docs/notes/disclosure-2026-08-10.md`の分類に立ち返れば、現在の伏せ字
運用を引き直して扱える可能性がある。これはm6xの選択肢1へ接続する。

ただし、C/H/Rを開示可能な「位置情報」と再分類するかどうかは情報境界の
変更である。**人間が判断すべき事項であり、エージェントが勝手に決めて
値を読んだり伏せ字運用を変更したりしてはならない。**
