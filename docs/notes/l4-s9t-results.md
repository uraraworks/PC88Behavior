## 予測の的中（初回60腕）

判定項目 **462件中 446件が的中、16件が外れ**。強さ別: 強 213/213、中 118/123、弱 115/126。外れ16件の原因は6つ（下の「外れ」）。追補1の23腕は事後の記述的な腕で的中数に数えない。

## 1. グラフィックVRAM（確定）

- **3プレーン**（0＝青・1＝赤・2＝緑）、メインCPUの C000〜FFFF に重なる。**1ライン80バイト、200ライン＝1プレーン 16000 バイト**。点 (x,y) は**オフセット y×80＋x÷8、x%8==0 が bit7（左端）**。
  `map-a` の17点（(0,0)(1,0)(7,0)(8,0)(15,0)(16,0)(0,1)(0,2)(9,1)(100,100)(319,51)(320,50)(638,198)(639,199)(0,199)(639,0)(400,150)）が全て仮説どおりの位置・ビットに立った。
- **色**: パレット番号 c の点は、プレーン0に c の bit0、プレーン1に bit1、プレーン2に bit2（B=1・R=2・G=4）。`map-col` で c=1〜7 が全て一致、c=0 は何も立たない（背景 0 に対する黒）。
- **オフセット 16000〜16383 は一度も光らない**（`cls 3`・`cls 2` の塗りも 16000 バイトちょうどで止まる。残り 384 バイトは触れない）。
- **上書き**: 同じ点へ別色を `pset` すると3プレーンとも新しい色に置き換わる（7→2 は赤だけ、7→0 は消える、1→6、5→5 は変わらず）。
- **起動直後**: グラフィックVRAMは全 0、0x31＝0x19 のまま、VRAM 切替系ポートの書き込みは窓内に無い。`cls 3` のあとも全 0。
- **ROM の書き方（カラーモード）**: 初回の予測「0x5C〜0x5E のいずれかを書く」は**外れ**。`pset`／`preset` は **OUT 0x34 ← 色（0〜7。preset の既定は背景色）** の前後に **OUT 0x35 ← 0x80, 0x00 の組**を出して VRAM へ書く（0x5C〜0x5E は使わない）。
  0x35 の 0x80/0x00 の組は `cls 3` の塗りで 200 組（1ラインに1組）、描画1回ごとに +1 組（組の位置が 0x34 の前か後かは未切り分け）。
  `point(x,y)`（読み）は **OUT 0x5C←0, 0x5F←0x40, 0x5D←1, 0x5F←0x40, 0x5E←3, 0x5F←0x40**（3プレーンを順に選んで読み、毎回 0x5F に戻す。値は観測のまま。意味づけはしない）。
- **ROM の書き方（白黒モード）**: アクティブページ p（0〜2）が**プレーン p**（青・赤・緑）。`pset` は **OUT 0x34 ← 0xEF（ページ0）/0xDF（1）/0xBF（2）**（色 0 は 0xEE/0xDD/0xBB 側）。読みは 0x5C/5D/5E のうちアクティブページの1つ＋0x5F。
  色が 0 以外なら色によらずそのページのプレーンに1ビット（7・6・5・3・1 とも）。色 0 で消える。`point` は 1／0。`screen 1` のあと `screen 0,0` に戻すとカラーの書き方に戻る（`mono-back`: 5 と 3 がそのまま立つ）。

## 2. 座標系（確定）

- **画面は 640×200**。範囲内の整数座標は誤りなしで立つ。(639,199)(0,199)(639,0)(0,0) 全て。
- **範囲外（640以上・200以上・負・1279・1280・−640 等、−32768〜32767 の範囲）は誤りなし、何も描かれない、LP は指定した座標へ移る**（巻き戻り・切り詰めなし）。
- **座標の範囲は −32768〜32767**: 32768・−32769・65535・65536・70000・`1e10`・−1e5 は **ERR 6（Overflow）**で LP は直前のまま。**−32768 は受理**（予測は誤りにしていた）。
- **小数は四捨五入（0.5 は切り上げ）**: (10.4,20.6)→(10,21)、(10.5,20.5)→(11,21)、(11.5,21.5)→(12,22)、(12.49,22.51)→(12,23)、(13.6,23.4)→(14,23)、(−0.4,24)→(0,24) が立つ、(−0.6,25)→(−1,25) は範囲外、(639.6,27)→(640,27) は範囲外、(28,199.4)→立つ、(29,199.6)→(29,200) 範囲外。LP も丸めた値。
- **STEP**: LP からの相対。`screen 0,0`＋`cls 3` 直後の LP は (0,0)。`point(300,100)`（文）は LP だけ動かす、`point step(50,0)` は相対。LP は範囲外へも進み続ける（(640,199)から step(−1000,−1000) で (−360,−801)）。
- **`POINT(0)(1)` は LP の X・Y。`POINT(2)(3)` も同じ値**（ワールド＝スクリーン）。n が 4・−1・5 は **ERR 5**、0.5 は 1 に丸まる。
- **LP の更新はスキャン時**（GW-BASIC の SCAND と同じ）: 色引数の誤り（ERR 5・13・22）や、座標の組を読み終えたあとの構文誤り（`pset(14,40),1,2`・`pset(16,40) 3`・`pset(18,40),,`・`pset(19,40);3`）でも、LP は新しい座標に移る。
  座標の組を読み終える前の構文誤り（`pset 12,40`・`pset(13)`・`pset(,41)`・`pset(21,)`・`pset()`・`pset`）は LP が動かない。オーバーフローで LP が動かない点は座標の読み取りが失敗するため。

## 3. PSET・PRESET・POINT（確定）

- **色**: 0〜7 を受理（0 は点を消す）。**−1・8・9・15・16・255・256・1000 は ERR 5**（点は立たず LP は新しい座標）。文字列は ERR 13、`1e10` は ERR 6。小数は四捨五入（0.4→0 で消す、0.5→1、0.6→1、1.5→2、2.5→3、−0.5→−1 で ERR 5）。
- **省略時の色は COLOR 第4引数**（初期値 7）: `color ,,,f` で f（0〜7 全て確認）。`color 5`（第1引数）も `color ,2`（第2引数）も `pset` の色を変えない。`color ,,,0` のあとは黒（立たない）。
- **`preset` の既定は背景色（`color ,b` の b）**: 背景0なら消える、背景3のときは3（`pr-bg3` の VRAM に 0x7F 等が出て、`preset(40,10),0` は黒で穴が開く）。`preset(..),c` は PSET と同じ。`preset(700,10)` は誤りなし。
- **構文**: 受理は `pset(10,40)`・`pset (15,40),3`（空白可）・`pset step(17,40),4`・`pset(20.5,40)`。**ERR 2**: `pset 12,40`・`pset(13)`・`pset(14,40),1,2`・`pset(16,40) 3`・`pset(18,40),,`・`pset(19,40);3`・`pset(,41)`・`pset(21,)`・`pset()`・`pset`。
  **`pset(11,40),`（色が空）だけ ERR 22（Missing operand）**（予測は ERR 2）。
- **`point(x,y)`（関数）**: 描いた点は色 c（1〜7 全て）、描いていない範囲内は背景色（背景0なら0、`color ,5: cls 3` のあとは5）、**範囲外は −1**（−1,10 / 640,10 / 10,200 / 10,−1 / 1000,1000 / −1,−1）。小数は丸める（15.4,10.4→(15,10)）。
  `pset(100,100),2` のあとは2、背景5の上へ `pset(..),0` したあとは 0（背景色ではなく黒）。白黒モードは 1／0。

## 4. グラフィックの色・背景（確定）

- **描画色は COLOR の第4引数（フォアグラウンド）**。第1引数はテキストのファンクションコード／色（s9r）で、グラフィックに効かない。
- **背景は第2引数**: `color ,b` のあとの `cls 3` と `cls 2` が、b の bit0・1・2 に当たるプレーンを 16000 バイトだけ 0xFF にする（b=0〜7 全て一致。他のプレーンは全 0）。`cls 1` と `color ,5` だけでは塗られない。`color ,,,3`＋`cls 3` は全 0。
- 白黒モードの書き込みは 1. のとおり（プレーン＝アクティブページ）。

## 6. 表示の切替・SCREEN 文（確定）

- **表示 ON/OFF は 0x31 の bit3**: `screen 0,2`・`screen 0,3`（画面スイッチ bit1＝グラフィックマスク）で **OUT 0x31 ← 0x11**（0x19 から bit3 を落とす）。画素の点は**見えなくなる**が、VRAM の点は**残る**。`screen 0,0`・`0,1` はポートを動かさない（`0,1`＝高速書き込みは V1S 専用）。
- **白黒（`screen 1`）**: OUT 0x31 ← 0x09（bit4＝0 白黒、bit3＝1 表示、bit0＝1 640×200）を2回。**第4引数（ディスプレイページ d）は OUT 0x53 ← 0xF0 | ((7−d)<<1)**（d=7→0xF0、0→0xFE、1→0xFC、2→0xFA、3→0xF8、4→0xF6、5→0xF4。bit0 は0のまま）。
- `screen 0,0` のあとの 0x31 は bit0・3・4 が立つ（0x19）。
- **誤り番号**: `5`・`-1`・`0,4`・`0,-1`・`0,0,3`・`0,0,-1`・`0,0,0,8`・`0,0,0,-1` は ERR 5（LP は変わらない）。`1,0,2,5` は受理（LP→(0,0)）、`"a"` は ERR 13、`0,0,0,0,0` は ERR 2、小数（`0.5`・`1.5`）は受理（丸め）。
  **`screen`（引数なし）は ERR 22**（予測は誤りなし）。**`screen ,1`・`screen ,,1`（画面モード省略）は受理するが LP を (0,0) に戻さない**（予測は戻す）。モードを書いた `screen 0,0`・`1,0`・`0,1` は LP を (0,0) へ戻す。
- **`screen 2`（400ライン）は受理**（LP→(0,0)）。OUT 0x31 ← 0x08（bit0＝0 で 640×400、bit4＝0）を2回、0x53 ← 0xF8、0x34 ← 0xEE×3, 0xDD, 0xEE×2（プレーンの初期化らしい。意味づけはしない）。VRAM の点はそのまま。
  **`screen 3`・`screen 4` は ERR 5**（N88-日本語BASIC の日本語モードはこの ROM に無い）。
- 初回の判定: 画素の点は画面スイッチ 0・1 で見える／2・3 で見えない（的中）。

## 外れ（16件・原因6つ）

1. **座標 −32768 は受理**（予測は ERR 6）: co-out2 の p2_e と、その後の LP 6件（連鎖）。範囲は −32768〜32767。
2. **`pset(11,40),` は ERR 22**（予測 ERR 2）、LP は (11,40) へ移る。LP の更新が座標を読み終えた時点であることが分かった（ps-syn の p1_e・p7_lp・lit の3件はこの連鎖）。
3. **`cls 0` は受理**（予測 ERR 5）。何も消さない。
4. **`cls 1.5` は 2 に丸まる**（弱い判定「点は残る」が外れ）。
5. **`screen ,1`・`screen ,,1` は LP を戻さない**（scr-e0 の p8_lp・p9_lp）。
6. **`screen`（引数なし）は ERR 22**（scr-e1 の p5_e・p5_lp）。群の項目 `acc_uses_5c_5e` の外れ（カラーモードは 0x34/0x35）が7つ目。

## 追補の理由

初回の公式観測で 0x5C〜0x5E を使う予測が外れ、`pset` 1回分のポート列が先頭60件に載らなかった。そこで、`evx`（0x31・0x34・0x35・0x53・0x5C〜0x5F の全列）を腕に足し、`pset`／`preset`／`point`／白黒／`screen` 各引数のポートを切り分けた（追補1、23腕）。
器具の欠陥による再測定ではない。

## 自作ROM（現状。同じ器具で83腕×2走）

- 初回60腕の判定項目 465件（強中弱の合計）中 **109件一致、356件不一致**。理由は未実装: **`pset`・`preset`・`point`（文・関数）・`screen`・`cls n`（引数あり）が全て ERR 2**（構文誤り）。引数なしの `cls` だけ受理。
  グラフィックVRAMは起動直後から全 0 のまま、描画も画面スイッチも起こらない（0x31 は 0x19 のまま、0x53・0x34・0x35・0x5C〜0x5F の書き込みなし）。
- `color ,b` の 0x54 の2回書き込みは s9r で公式と一致済みだが、VRAM の塗りつぶし（`cls 2`・`cls 3`）は未実装。

## 実装への含意（src/ は触っていない）

1. グラフィックVRAMは 3 プレーン×16000 バイト（C000〜FFFF 窓、80バイト/ライン、MSB 左）。`cls 2`/`cls 3` は背景色 b のビットのプレーンを 16000 バイト 0xFF、他を 0（384 バイトは触らない）。
2. `pset`／`preset`／`point`: 座標は四捨五入、範囲 −32768〜32767（外は ERR 6、LP 不変）、画面外は無視（LP は移る）、色 0〜7（外は ERR 5、LP は移る）、省略色は COLOR 第4引数／背景色、構文誤り（ERR 2）でも座標を読み終えていれば LP を更新、`pset(x,y),` は ERR 22。
3. `point(n)`（n=0〜3、他は ERR 5）、`point(x,y)`（範囲外 −1、白黒 1/0）、`point(x,y)` 文。
4. `cls n`: 1/省略＝テキスト、2＝グラフィック（LP→(0,0)）、3＝両方、0 は何もしない（受理）、n は四捨五入、4 以上・負は ERR 5、文字列 ERR 13。
5. `screen`: 第1引数 0/1/2（3・4 は ERR 5）、第2引数 0〜3（bit1 で 0x31 の bit3 を落とす）、第3引数 0〜2、第4引数 0〜7（0x53）。モードを省略したときは LP を戻さない。引数なしは ERR 22。
6. 書き方（ポート列）は上のとおり。ROM を同じ I/O 列にする必要はない（同じ画素が立てばよい）が、適合試験でポート値を比べるなら 0x34 の色・0x31 のビットは合わせる。
