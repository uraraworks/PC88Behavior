# l4-s1a — テキストVRAMの属性の並び・カーソル位置の対応・スクロールの仕方 — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

[l4-design](l4-design.md) 段階1（main側L3の測定）のうち、テキストVRAMの文字と
属性の配置・カーソル位置の対応・スクロールの3点をまとめて測る事前登録である。
**実装は行わない。測定のみ。**

## 問い

- Q1 属性: 1行120バイトのうち後ろ40バイト（属性域）は、どの書式で何を表すか。
  `COLOR` の指定と、目印文字を置いた桁が、属性域のどのバイトをどう変えるか。
- Q2 位置: `LOCATE x,y` と、目印文字が書かれるVRAMの番地
  （F3C8 + y*120 + x か）の対応。
- Q3 スクロール: 画面下端で改行したとき、VRAMの中身を動かすのか
  （書き込み記録にブロック転送が出る）、DMA/CRTCの開始番地を変えるのか
  （I/Oログの DMA CH-2 アドレスポートに書き込みが出る）、その両方か。
- 対象外: キー割り当て（別の事前登録 l4-s1b、キーマトリクスの直接押しの器具が要る）。

## 条件

- 公式ROM一式、ディスク無し、既定の BASIC モード（コア既定 N88 V2。報告に明記する）、
  既定のDIP。
- 目印: 自分で打つ文字列 `Q7Z`（公式の起動画面に現れにくい並び）。打鍵は英数と
  改行のみ。
- 読んだマニュアルの頁: 2-29〜2-30（COLOR）、2-33（COLOR@）、2-39（CONSOLE。
  カラー／白黒スイッチ 0=白黒・1=カラーは 2-29 の COLOR の項の記述から）、
  2-135（LOCATE）、2-244（WIDTH）。出所は `refs/manual_squashed.txt`
  （FA/MA リファレンスマニュアル）。
- 起動時の実際の表示行数は20行（[l4-design](l4-design.md) の実測を踏襲。
  VRAM確保サイズの25行は逆算用の仮想サイズであり、既定の表示行数ではない）。
  A2の境界とA4のWIDTH条件はこれに合わせる。

### 打鍵と走行フレームの決め方

- 起動settle: 全腕共通で `--type-at 300 --type '\n'`。
  根拠: `tools/conform_l3.sh` の全入口シナリオ（`files`/`load`/`kill`/… )が
  採る値をそのまま流用する。
- 実コマンドの打鍵開始: 全腕共通で `--type-at 700`。
  根拠: 同上。`conform_l3.sh` のどのシナリオでも実コマンドの打鍵開始は700で
  統一されている。
- `--mem-write-from-frame 700`。打鍵開始フレームと一致させ、起動時（0〜699）
  の書き込みを走査対象から外す。
- `--key-hold` / `--key-gap` は指定せず、`tools/harness/frontend/main.c` の
  既定値（各4フレーム、1文字あたり8フレーム）をそのまま使う。以下の走行
  フレーム数は、この1文字8フレームの見積もりを基に、`conform_l3.sh` の
  既存シナリオのうち打鍵量・実行内容が近いものへ揃えて決める。
- `--vram-dump-at` は「走行フレーム数 − 100」に固定する（打鍵完了後の余裕を
  持たせつつ、`--frames` 超過の警告を避ける）。

打鍵量・実行内容でグループ分けし、走行フレーム数を既存シナリオへ揃える:

| グループ | 対象腕 | `--frames` | `--vram-dump-at` | 根拠 |
|---|---|---|---|---|
| S | A0・A1・A2（3境界）・A3m（n=0〜7）・A3c（n=0〜7） | 2400 | 2300 | `conform_l3.sh` の `files` シナリオ（`--type-at 700` で `FILES\n` のみ、`frames=2400`）と同等以下の打鍵量・即時実行（ディスクアクセス無し）のため、同じ予算を流用する |
| M | A3r（各区間数） | 4800 | 4700 | `load` シナリオ（3行のプログラム入力＋SAVE/NEW/LOAD、`frames=4800`）と行数・文字数の桁が近いため、同じ予算を流用する |
| L | A4（WIDTH 80,20 / 80,25 の2条件） | 9000 | 8900 | `random_file` シナリオ（9行・約400文字のプログラム入力＋RUN、`frames=9000`）と打鍵文字数の桁が近い（`PRINT"Q7Z"\n` を26回で約364文字、WIDTH文を加えても同程度）ため、同じ予算を流用する |

各腕は2回走らせる（G3）。乱数要因は無いため、同一の打鍵列をそのまま再実行する
だけでよい。

### 腕

- **A0** 無打鍵（陰性対照）。settleの `\n` のみで実コマンドは打たない。Sの
  予算をそのまま使う。
- **A1** `--type-at 700 --type 'PRINT "Q7Z"\n'`。
- **A2** 位置の境界。3腕、いずれもSの予算:
  - `--type-at 700 --type 'LOCATE 10,5:PRINT "Q7Z"\n'`
  - `--type-at 700 --type 'LOCATE 0,0:PRINT "Q7Z"\n'`
  - `--type-at 700 --type 'LOCATE 77,19:PRINT "Q7Z"\n'`
    （表示20行・80桁の既定で、Y最大19・目印3文字が収まるようX=77に置く）
- **A3m** 白黒モード、n=0〜7の8腕（Sの予算）:
  `--type-at 700 --type 'CONSOLE ,,,0:COLOR n:PRINT "Q7Z"\n'`
  （2-29: 0ノーマル／1シークレット／2ブリンク／3=1／4リバース／
  5リバース・シークレット／6リバース・ブリンク／7=5）
- **A3c** カラーモード、n=0〜7の8腕（Sの予算）:
  `--type-at 700 --type 'CONSOLE ,,,1:COLOR n:PRINT "Q7Z"\n'`
  （2-29: 0黒 1青 2赤 3紫 4緑 5水色 6黄 7白）
- **A3r** 範囲属性。`PRINT "Q7Z"` のあと `COLOR@(x1,y)-(x2,y),n` で行の一部だけ
  属性を変え、属性が「桁ごと」か「(位置,値)の対」かを分ける（2-33）。
  1行に置く属性区間の数を 1・2・10・20・21 と振る（CRTC のアトリビュート20個、
  [refs-vraminfo](refs-vraminfo.md) と照合するため）。区間はどの区間数でも
  「列0から幅1列ずつ、`n` を1〜7で循環させながら並べる」規則で作る。
  区間数Nの打鍵文字列は
  `PRINT "Q7Z"\n` の後に `COLOR@(i,0)-(i,0),(i mod 7)+1\n` を i=0..N-1 まで
  並べたものになる。N=2の具体例:
  `--type-at 700 --type 'PRINT "Q7Z"\nCOLOR@(0,0)-(0,0),1\nCOLOR@(1,0)-(1,0),2\n'`
  Mの予算を使う。
- **A4** スクロール。`PRINT "Q7Z"` を26回連続（表示20行でもスクロールを
  起こす）。WIDTHの2条件（2-244: 行数は20か25、WIDTHは画面を消す）:
  - WIDTH80-20: `--type-at 700 --type 'WIDTH 80,20\n' + ('PRINT "Q7Z"\n' を26回連結)`
  - WIDTH80-25: `--type-at 700 --type 'WIDTH 80,25\n' + ('PRINT "Q7Z"\n' を26回連結)`
  Lの予算を使う。

- 採るもの: 打鍵完了後の VRAM の写し（F3C8〜FF7F）、F3C8〜FF7F への書き込み
  記録、I/Oログ。
  - 器具（コミット `04201be`）: `--vram-dump PATH --vram-dump-at F`
    （retro_run 直前、属性込み3000B）、`--mem-write-log PATH
    --mem-write-range 0xF3C8-0xFF7F --mem-write-from-frame 700`、`--io-log`。
  - 解析は `tools/l4_vram_probe.py`（本文を出さない。コミット `929c95a`。
    行・桁を0始まりに統一する修正が別担当で進行中のため、測定時のHEADで
    G5を確かめてから使う）。
  - 写しのフレームは上表の `--vram-dump-at` を使う。打鍵完了は
    `tools/check_l3_entry_screen.py` の判定で確かめる。

## 関門

- G1 器具: 同じHEADで vram_dump / mem_write_log の自己検査（陽性の末端検査・
  故障注入）が OK。
- G2 取りこぼし0（書き込み記録・I/Oログとも）。
- G3 決定論性: 各腕2回で写しの sha256 と書き込み記録の sha256 が一致する。
- G4 陰性対照: A0 で目印 `Q7Z` のセルが0件、A1 で1件以上（目印検出器が
  効くこと）。
- G5 起点: 解析道具の出力の見出しが origin=0 で、同じHEADの
  `screen_content_leak_selftest.sh` の f2（0始まりの既知位置）と起点取り違えの
  陰性対照が OK。
- G6 本文漏れ: 同じHEADで `screen_content_leak_selftest.sh` 全項目 OK
  （f1・g を含む）。
- G7 実装不変: 測定に使う公式ROM一式は変えない。自作側の生成物を使う腕は無い
  （本測定は公式ROMのみ）ことを報告に明記する。

## 本文を出さない取り扱い（禁止事項7）

- 写しと記録は使い捨ての作業ディレクトリ（リポジトリ外）に置き、コミットしない。
  終わったら削除する。
- 解析道具が出してよいもの: 目印セルの (行, 桁, 番地)、目印を含む行の属性域
  40バイト、目印の無い行の属性域の「既定値かどうか」の真偽と件数、書き込み
  記録の要約（番地範囲・件数・発行元PCの範囲・ブロック転送らしき連続の長さ）、
  I/Oログの DMA/CRTC ポートの書き込み（ハードウェア設定値）。
- 出してはいけないもの: 目印以外のセルの文字の値、行の本文、画面署名以外の
  画面の再構成。
- 解析道具は `screen_content_leak_selftest.sh` の対象に加え、陰性対照つきで
  本文が漏れないことを確かめてから使う。

## 指標と判定

- Q1: 属性域の変化を「(位置バイト, 値バイト) の対か／桁ごとか／その他」に
  分類する。判定 `attr_pairs`／`attr_per_column`／`attr_other`／`inconclusive`。
- Q2: 全腕で 番地 = F3C8 + y*120 + x が成り立つか。判定 `linear_120`／`other`。
  - **起点**: x, y は LOCATE の座標（0始まり、2-135）。解析道具の出力は
    `row0`/`col0`（0始まり、origin=0 を見出しで確認してから使う）。判定前に、
    道具の見出しの origin が 0 であることを関門に含める（G5）。
  - スクロール後は行と番地の対応がずれうる（DMA開始番地を変える方式なら）。
    Q2 はスクロールを起こさない腕だけで判定する。
- Q3: `scroll_moves_vram`（書き込み記録に行単位のブロック転送、DMAアドレス
  不変）／`scroll_moves_dma`（DMAアドレス書き込みあり、VRAM移動なし）／
  `both`／`inconclusive`。
- 判定後の行き先: 仕様書 `docs/spec/l3-main.md`（新設）へ観測として記録する。
  段階2の実装はその仕様書だけを見る別担当が行う。
