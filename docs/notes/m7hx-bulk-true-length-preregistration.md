# m7hx: 混成側の大量転送runの真の長さを求め、順序を決着させる — 事前登録

## 位置づけ

[m7hw](m7hw-bulk-prefix-ordering-results.md)は判定F3（共通prefixに不一致なし）
に終わり、**残る穴を1点に絞った**——「混成側の大量転送run（添字14）の真の長さと、
4759位置より後ろの内容」である。

これまでに確定していること:

| 事実 | 出所 |
|---|---|
| 要求の差が現れるclock = **153613**（分岐段の候補#3） | `m7hs` |
| 応答run 0〜13は両条件で完結し内容が完全一致 | `m7hu` |
| 大量転送run（添字14）の共通prefix4759位置に不一致0件 | `m7hw` |
| 公式の大量転送run: 開始44470・終端134906・run長5632 | `m7hu` |
| 混成の大量転送run: 開始58187・**終端clockが窓の終端153707と一致**（打ち切り） | `m7hu` |

**混成側の4759という長さは、窓による打ち切りを含む値であり、真の長さではない。**
ここが埋まれば、`m7hs`が残した留保「要求の1バイト差は原因か結果か」が決着する。

本稿は測定と記録だけを行い、`src/`は修正しない。

## 二段構えにする理由（場面を揃える必要の有無が段で違う）

- **段階1は比較ではない。** 混成側のrun 14が**いつ終わるか**を求めるだけである。
  比較しないので、窓が分岐点より後ろへ出ても「場面が揃っている」という前提は
  要らない。
- **段階2は比較である。** ここで初めて場面の問題が出るので、後述のとおり
  **どちらの条件のclockで判定するかを事前に固定する**。

## 段階0（本稿）: 事前登録を測定前にコミットする

本稿は測定を1回も走らせる前に単独でコミットする。測定後の書き換え・amendは
行わない。

## 測定条件

- 条件O・条件M・対照arm 9は`m7hw`と同一（取得済みログを再利用する。いずれも
  独立2回のバイト一致を確認済み）。
- 応答runの定義・抽出器は`tools/compare_recv_run_fields.py`の`_response_runs`を
  そのまま用い、**定義を変えない**。窓（`until_clock`）だけを変える。

## 段階1: 混成側の大量転送runの真の終端を求める（比較しない）

- 窓を`--frames 3000`のログ全体まで広げ（実務上は十分大きいclock値を渡す）、
  混成側の応答run列を取り直して**添字14のrun長と終端clock**を求める。
- 同じ操作を条件Oにも行い、**公式側のrun長5632・終端134906が窓を広げても
  変わらないこと**を確認する（変われば`m7hu`の値の解釈が誤っていたことになる
  ので、その場合は判定Oとする）。
- **中止規則**: 窓を広げても混成側のrun 14が完結しない（ログ末尾で切れる）
  場合は、段階2を実施せず主判定をO''（真の長さが求まらなかった）とし、
  その事実を記録する。**無言でSKIPしない。**

## 段階2: 大量転送runの全長比較（段階1で真の長さが求まった場合のみ）

- 添字14について、条件Oと条件Mを**全位置**（`min(公式run長, 混成真run長)`まで）
  比較する。
- `min`を超える部分は**長さの差**として別に扱い、内容の不一致とは混ぜない。

### clockの扱い（測定前に固定）

不一致位置が見つかったとき、その位置は条件Oと条件Mで**別のclock**を持つ。
公式の大量転送は134906で完結済み、混成は153707時点でまだ続いているため、
同じ位置でも両者のclockは大きく離れうる。**`m7hv`が採用した規則をそのまま
踏襲し、`max(公式clock, 混成clock)`をしきい値153613と比べる。**
（`max`を採るのは、「両条件でその位置に到達した後」でなければ差が観測可能に
ならないためである。この規則は`m7hv`で既に使っており、本稿で新しく作らない。）

## 事前登録する判定（測定前に固定。後から動かさない）

- **J1（内容も長さも一致 → 要求の差が窓内で最も早い食い違い）**: 全位置で
  不一致が無く、公式run長と混成真run長が等しい。このとき`m7hu`の応答run 0〜13
  完全一致と併せて、**窓内の応答はすべて一致**する。
- **J2（内容の不一致あり）**: 不一致位置があり、`max(両clock)`を153613と比べる。
  - **J2a**: `max < 153613` → **応答の差が先**（要求の1バイト差は結果）。
  - **J2b**: `max > 153613` → **要求の差が先**。
  - **J2c**: 等しい → 順序を主張しない。
- **J3（内容は一致するが長さが違う）**: 長さの差が何を意味するかは決めず、
  記録のみ行う。**この場合、順序は主張しない**——長さの差も差であり、
  「内容が一致したから応答に差が無い」とは言えないため。
- **O（測定不能）**: 陽性対照が通らない、公式側の値が窓を広げると変わる、
  決定論性が確認できない。
- **O''（真の長さが求まらなかった）**: 段階1の中止規則に該当。

**どの判定になるかは予測しない。**

## 事前登録する合格条件（測定前に固定）

1. `tools/recv_run_field_leak_selftest.sh`が全項目OK・rc=0（陰性対照・故障注入込み）。
2. `tools/analyze_error_exchange_shape_selftest.sh`がrc=0。
3. **対照の妥当性を、また取り直す（4度目）。** 比較対象が「共通prefix4759位置」
   から「全長」へ変わるため、arm 9がこの比較対象を動かすことを先に確認する。
   動かさなければarmを振り直す。**有効な対照が1つも無ければ段階2は実施せず、
   主判定をO'（対照を作れなかった）とし、試したarmの一覧を記録する。**
   これは`m7hq`・`m7hu`・`m7hw`に続く4度目の適用である。
4. **対照が比較結果を変えること**（不一致の有無または最初の不一致位置が変わる）。
5. **決定論性**: 条件O・条件M・対照armのそれぞれについて、段階1の値と段階2の
   比較結果が独立2回で一致すること。
6. `tools/check_cleanroom.sh`が全項目OK。

## 言えないこととして先に書いておくこと

- **J1が出ても「要求の差が分岐の原因」とは言えない。** 言えるのは「窓内の応答は
  すべて一致しており、要求の差が窓内で最も早い食い違いである」までである。
  因果には介入が要る。また窓の外（分岐点より後ろ）は見ていない。
- **J1が出ても、公式subの内部でその応答がどう作られているかは分からない。**
  値を読まないため、差の内容には踏み込まない。
- **J3は「差が無い」ではない。** 長さの差は差である。
- 段階2で`min`を超える部分を比較しないため、**混成側が公式より長い場合、
  その超過部分の内容は見ていない。**
- 条件O・`disk#10`という1本のディスク・1条件である。一般性は主張しない。
