# M1 調査メモ — QUASI88-libretro

調査日: 2026-08-07

## 2. フックを差す場所 — 一点に寄っている

Z80 コアは関数ポインタ経由でバス操作を呼ぶ。`src/z80.h`:

```c
byte (*fetch)(word);              /* 命令フェッチ    = 実行アクセス */
byte (*mem_read)(word);           /* メモリリード    = データアクセス */
void (*mem_write)(word,byte);
byte (*io_read)(byte);
void (*io_write)(byte,byte);
```

これらは `pc88main.c:2946 pc88main_bus_setup()` の 1 箇所で設定される。
**ここで自前のラッパを噛ませれば、コア本体に手を入れずに全アクセスを観測できる。**
`PLAN.md` の開発ループ ① が要求する「実行アクセスとデータアクセスの区別」が、
`fetch` と `mem_read` の分離によって構造的に取れる。

### ただし落とし穴が 1 つ

```c
if( memory_wait || highspeed_mode ){
    z80main_cpu.fetch = main_fetch;      /* 専用のフェッチ関数 */
}else{
    z80main_cpu.fetch = main_mem_read;   /* ← mem_read に潰される */
}
```

**既定の設定では `fetch` が `mem_read` に別名化され、実行とデータの区別が消える。**
ハーネスでは `memory_wait` の設定に関わらず、常に自前の `fetch` フックを入れること。
ここを見落とすと「需要ログは取れているのに実行/データが混ざっている」という、
気づきにくい壊れ方をする。

> 過去に同じ形の失敗をしている（[[定数の一致は経路の証明にならない]]）。
> フックを入れたら、既知のアクセスを 1 つ仕込んで**末端のログに現れることを実測**してから先へ進む。

## 3. 規律上の注意 ①：コアに逆アセンブラが同梱されている

`src/z80-debug.c`（1508 行）に `z80_line_disasm()` がある。`monitor.c` と合わせて
Z80 モニタ／デバッガ一式が入っており、**既定のビルドでリンクされている**
（リンク行に `z80-debug.o` が入ることを確認）。

これは危険である。私たちのハーネス自身が、公式 ROM に向けられる逆アセンブラを内蔵することになる。
`CLAUDE.md` の禁止事項 2 が「実行しない」という運用規律に留まってしまう。

**方針: 計測ハーネスのビルドから逆アセンブラとモニタを外す。** 能力そのものを消す。
「使わない」ではなく「持っていない」にするのが本プロジェクトの流儀
（[[出自は証明せず、証明が要らない構造にする]]）。
ビルド設定でそれが達成できていることも `check_cleanroom.sh` の検査項目に足す。

## 4. 規律上の注意 ②：`pseudo_bios.h` の扱いを決める必要がある

`src/LIBRETRO/pseudo_bios.h`（212KB / 2909 行）に、公式 ROM 無しで起動するための
バイト列が 2 つ入っている。

```
/* Pseudo BIOS for PC-8801 created by cisc (http://www.retropc.net/cisc/m88) */
const unsigned char pbios_n88[]  = { ... };   /* 32KB 相当 */
const unsigned char pbios_disk[] = { ... };   /*  2KB 相当 */
```

`libretro.c:551` で公式 ROM が無いときにこれを `main_rom` / `sub_romram` へ流し込む。
**M88 の作者 cisc 氏による疑似 BIOS**であり、公式 ROM のダンプではない（と冒頭コメントは言っている）。

**調査にあたりバイト列そのものは読んでいない。** 非データ行だけを抽出して構造を見た。

これは本プロジェクトにとって二重の意味を持つ。

- **良い知らせ**: 「公式 ROM 無しでディスクから起動させる」ことは既に前例がある。
  ゴール A の一部は実現可能だと分かっている。
- **決めるべきこと**: これを**使うのか、読むのか、避けるのか**。
  中身を読んで参考にすると、こちらの成果物が「cisc 氏の実装からの独立実装」ではなくなる。
  加えて、cisc 氏がどういう手法で作ったかを私たちは知らない。仮にそれが公式 ROM の解析由来だと、
  取り込んだ時点で「証明が要らない構造」という設計の前提が崩れる。

  **暫定方針: 中身を読まない。取り込まない。** 存在は前例として記録するに留める。
  疑似 BIOS が既定で有効なままだと測定時に混入しかねないので、
  ハーネスではこの経路を明示的に無効化する（公式 ROM が無ければ起動しない、が正しい挙動）。

  これは確定ではなく、ライセンスと出自を確認した上で見直してよい。見直すなら履歴に残す。

## 5. ビルド — 通った

```
make platform=osx -j8   →  quasi88_libretro.dylib (Mach-O arm64)
```

`platform` の自動判定が壊れている。`Makefile:13` が `uname -a` に `win` を含むかで
win32 判定しているが、**"Dar*win*" が一致してしまう**。macOS では `platform=osx` を明示する。
（放置すると `-static-libgcc` で clang がこけるので気づけるが、原因は分かりにくい。）

`emscripten` 分岐も存在する（`Makefile:297`）。Web 版に持っていく道は繋がっている。
