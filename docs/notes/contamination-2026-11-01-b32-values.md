# 汚染の疑い: B32 で公式 ROM 由来かもしれない値を出力した

記録日: 2026-11-01
規則: [CLAUDE.md](../../CLAUDE.md)「汚染したとき」。隠さず記録する。**このノートにも値は書かない。**

## 何が起きたか

[B32](b32-g1-differing-block-preregistration.md) の器具は、違う区間がディスクの中身と一致しなければ先頭 8 バイトを出す設計だった。結果はディスクと不一致で、公式側の 8 バイトと自作側の 8 バイトが出力された。

自作側の 8 バイトは、自作サブ ROM の機械語に見える。**同じ要求で公式側が返した 8 バイトは、公式サブ ROM の内容である可能性がある。** 事前登録はディスクとの一致しか確かめておらず、ROM との一致を確かめていなかった（事前登録の欠陥）。

## 範囲

- 見た者: この測定スレッド、取りまとめ役のセッション、親のこのセッションの会話の記録
- 置き場: プロジェクトのライブラリの `b32-g1/`。**リポジトリには入れていない**
- 値は利用者への報告に書いていない
- 実装の担当（Codex）には渡していない

## 措置

1. この 8 バイトを実装・仕様の根拠にしない。リポジトリに入れない
2. このセッションと測定スレッドは、該当箇所の実装をしない（もともとの分担のとおり）
3. ライブラリの `b32-g1/` は利用者に削除を依頼する
4. 公式の値が ROM の内容かを、**値を出さず**に確かめる（[B33](b33-g1-rom-origin-preregistration.md)）
5. 追補4・追補6 の「値を記録してよい」は、ROM との一致を先に確かめる形に直すまで使わない

## B22 について

[B22](b22-g1-differing-replies-results.md) の 2 バイトは push 済みのブランチの `measurements/` にある。これも同じ確認に含める。ROM の内容と分かったら、履歴の扱いを利用者に相談する。
