# l4-s5h — 小文字で打った語の LIST 表示 — 事前登録

記録日: 2026-10-01

## 背景（観測された症状）

WebQ88 上の自作互換 ROM で、`new` → `10 print 1` → `20 end` → `30 print 2` → `list` の表示が
`10 PRINT 1` / `20 end` / `30 PRINT 2` になった（END だけ小文字のまま）。RUN では `1` だけ出て止まる。

## 自作側の原因（自作のコードなので読んでよい）

- 自作 BASIC はプログラムを**打鍵どおりの文字列**で保存する（`src/l4_basic/program.asm` 冒頭。中間コードは持たない）。
  `LIST`（`LIST_RENDER_TEXT`）が大文字にするのは文頭の `PRINT` と `?` の展開だけである。
  `src/l4_basic/tokens.asm` のトークン表は字句解析の自己検査にだけ使われ、`LIST` も `RUN` も引いていない。
  なので END に限らず、`PRINT` 以外はすべて、小文字で打てば小文字のまま出る
  （自作ROMで `goto` `for` `to` `next` 変数名なども小文字のまま出ることを確認した）。
- RUN が END で止まるのは、実行側が `TRY_MATCH_END`（大文字小文字を区別しない固定語照合、`run.asm`）で
  文頭の `end` を認識するため。トークンで止まっているのでも偶然でもなく、文として認識されている。
  つまり「入力時のトークン化が取りこぼした」のではなく、「そもそもトークン化していない設計の、LIST 側の
  整形が PRINT 1語しか知らない」のが原因である。

## 既存の測定で決まっていたこと

- `l4-program.md` 2.2節: 小文字の命令語は LIST で大文字になる。**ただし根拠の12腕（l4-s5a）は
  `print` と `?` だけ**を打っていて、ほかの語・変数名・文字列・REM・DATA・語の連結は測っていない
  （同 第8節1「命令語以外の英字の扱い」は未確定のまま）。
- `m6f-h`（SAVE ,A の本体は LIST と同じ文字列）も、打ったのは PRINT 系だけ。

したがって「小文字で打った END を LIST でどう出すか」は**既存の測定では決まっていない**。測る。

## 試走（予測ではない）

事前登録の前に、公式 ROM で1回だけ、次の自作7行を打って `list` を見た（本文は自分で打った行のみ）:
`print 1` / `end` / `print 2` / `goto 10` / `for i=1 to 3:next i` / `a=1:b$="x"` / `rem print end`。
結果は、**語と変数名の英字が大文字になり、文字列の中身と REM の後ろは打鍵どおり**だった。
下の候補 M_A はこの試走を見たうえで作った**規則の候補**であり、盲目の予測ではない。
検証力は、試走で見ていない腕（語の連結・括弧内・識別子への埋め込み・REM/DATA/`'` の境界・
THEN の直後の REM など）が担う。

## 測るもの

自分で作った BASIC 行を `new` の後に打ち、`cls` → `list` で出る行を取る。腕は600本。

| 群 | 内容 | 本数 |
|---|---|---:|
| w1 | 予約語1語だけの行 `<語>`（keywords.tsv の英字語。190語から記号語10個を除く） | 180 |
| w2 | 括弧に包む `(<語>)` | 180 |
| w3 | 識別子への埋め込み `x<語>y` | 180 |
| c01〜c60 | 文脈つきの60行（REM・`'`・DATA・文字列・連結・変数名・数値定数・`?`・演算語・`GO TO` ほか） | 60 |

（語数は器具が keywords.tsv から数える。`predict` の出力が正本。）
腕の全体は `tools/l4_listkw_measure.py` の `build_arms()`。

## 画面本文を出さない取り扱い

- 取り出すのは、`cls` のあとの画面で「先頭の空白を除いた最初の文字が数字で、80セルすべてが
  表示可能 ASCII」の行だけ。これは自分で打った行の LIST 表示で、`l4-program.md` 第2節と同じく
  禁止事項7の対象外として扱う（l4-s5a 事前登録と同じ取り扱い）。
- それ以外の行（`Ok`・`list` のエコー・属性域・範囲外コードを含む行）は、**中身を読まず件数だけ**数える。
  自己検査（`tools/l4_listkw_measure.py selftest`）に陰性対照（英字始まりの行・範囲外コードの行が出力に
  現れない）と陽性対照を持たせた。
- 結果ノートとコミットする期待値（`tests/conformance/expected_l4_listkw.tsv`）には、腕ごとの**署名
  （sha256先頭16桁）だけ**を置く。観測行の本文は、候補と食い違った腕を調べるときに限り、自分で打った
  行との対として作業中に見る。

## 候補 M_A

次の規則で「打った本文」から「期待する LIST 表示」を作る。

1. 行番号の直後の空白は1個に正規化（既存規則）。それ以外の空白は打鍵どおり。
2. 二重引用符の中は打鍵どおり（閉じ引用符が無ければ行末まで）。
3. 文頭（行の先頭または `:` の直後。空白を飛ばす）の `rem` は `REM` にして、以降は打鍵どおり。
4. `'` 以降は打鍵どおり。
5. 文頭の `data` は `DATA` にして、以降は `:`（引用符の外）まで打鍵どおり。
6. 文頭の `?` は `PRINT ` に展開（既存規則）。
7. 上記以外の英字はすべて大文字にする。記号・数字・空白は触らない。語の前後に空白は足さない。

M_A は変数名も大文字にする（試走に合わせた）。語の連結や識別子への埋め込みで公式が空白を足す・
語の途中で REM/DATA を認識する、などがあれば M_A と食い違って現れる。

## 関門と判定

- G1 器具の自己検査（上記 selftest と、既存の `tools/screen_content_leak_selftest.sh`）が通る。
- G2 全走で「打てない文字」の警告が0。
- G3 決定論: 公式ROMで全腕を2走し、腕ごとの署名が全て一致する。
- G4 数え合わせ: 各走で、取り出した行数が打った行数と一致する（画面に収まらず消えた行が無い）。
  一致しない走は `gate_failed`。
- G5 陽性対照: 自作ROMの現行版（PRINT だけ大文字化）で測り、M_A と**多数の腕で食い違う**こと
  （器具が差を検出できる）。同じ器具で公式の観測を M_A と比べる。
- 腕ごとの判定は `match`（観測 = M_A の予測）／`differs`／`gate_failed`。
  `differs` の腕は、規則を足した追補の候補を**測定の後で**立て、追補として登録してから採る
  （事後の候補は事後と明記する）。

## 判定後の行き先
