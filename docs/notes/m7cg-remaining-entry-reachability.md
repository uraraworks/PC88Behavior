# m7cg: 残り4需要入口も終端まで一致していた

実施日: 2026-08-23

## 情報境界

公式ROM一式＋公式diskAの使い捨て複製、および公式main ROM一式＋自作sub ROMを
同条件で実行した。公式ROM・公式ディスクの内容や`private/`配下は読んでいない。
生iolog、画面報告、ROM複製、ディスク複製、標準出力・標準エラーはすべて
リポジトリ外の`mktemp -d`配下だけに置いた。本稿へ残すのは件数、SHA-256、
公開μPD765コマンド名、位置と記号化した分類だけで、データポートやFDCデータの
値は出していない。公式ディスク原本へは書き込んでいない。

`tools/check_l3_entry_screen.py`は一時画面報告を内部で読み、自分で打鍵した
コマンドの反映と直後の`Ok`だけを終了コードへ分類する。画面本文は表示しない。

## 測定条件と何を測っているか

全入口で300FにRETURN、700Fから打鍵し、9000F、実行ごと300秒上限とした。
各実行は新規ROMディレクトリとdiskAの新規使い捨て複製を使い、書込み入口では
複製だけのライトプロテクトを解除した。

- **既存ファイル単独LOAD**: 準備runは公式一式で短いBASICプログラムをSAVEし、
  公開コア設定を明示して使い捨てD88複製そのものへ保存した。完成複製を二分し、
  別プロセスの公式／混成runへ同一入力として渡した。2回目は`LOAD`だけを打鍵した。
  従って測るのは、同一実行内SAVE直後の読戻しでなく、起動直後に既存ファイルを
  単独で読む経路である。最初の試行はコア既定の差分`.srm`保存を理解せずD88だけを
  渡したため両構成ともエラーとなった。これは未到達として破棄し、期待値には
  採用していない。準備runのSAVE反映・直後`Ok`・WRITE DATA非0を確認した上で、
  2回目のLOAD反映・直後`Ok`を到達指標にした。
- **シーケンシャルファイル出力・入力**: `OPEN ... FOR OUTPUT`→`PRINT#`→
  `CLOSE`→`OPEN ... FOR INPUT`→`INPUT#`→`CLOSE`。m6cのseqfile測定と同じ系統で、
  6命令すべての画面反映と各直後`Ok`を到達指標にした。
- **KILL**: 同一run内でSAVEして削除対象を作り、続けてKILLした。従ってSAVEを
  前置きに含む複合条件だが、KILL反映・直後`Ok`と、SAVE後に続く第2のFDC書込み列で
  削除入口への到達を分離した。
- **NAME**: 同一run内でSAVEして変更元を作り、続けて別の自作名へNAMEした。
  NAME反映・直後`Ok`と、SAVE後の末尾WRITE単位で名前変更入口への到達を確認した。

## 公式・混成の比較

m7cfと同じく、`R`をSEEK→SENSE INTERRUPT STATUS→SENSE DRIVE STATUS→READ DATA、
`W`を末尾だけWRITE DATAにした4件組、`P`を起動前置き15件とする。

| 入口 | 公式・混成のFDCコマンド種別列 | 一致prefix |
|---|---|---:|
| 既存ファイル単独LOAD | `P → R×17`（83件） | 83件（全長） |
| シーケンシャル出力・入力 | `P → R×16 → SENSE DRIVE STATUS → W×6 → R → W → R → W → R×9`（156件） | 156件（全長） |
| KILL | `P → R×16 → SENSE DRIVE STATUS → W×6 → R → W → R → W → R×8 → SENSE DRIVE STATUS → W×5 → R → W → R → W → R`（193件） | 193件（全長） |
| NAME | `P → R×16 → SENSE DRIVE STATUS → W×6 → R → W → R → W → R×7 → W`（152件） | 152件（全長） |

| 入口・列 | 公式件数 | 混成件数 | SHA-256 |

公開FDCコマンド種別列とmain受信列に最初の差は無く、全長一致した。全入口で
対象コマンド直後の`Ok`まで到達し、その後9000Fまで完走したため、観測区間に
停止・デッドロックは無い。内部FDCポート値列は全入口とも一致prefix 1件、
最初の差は2件目、最初のSPECIFYのパラメータ1件目における同方向の値差だった。
値は出していない。m7cfと同じ内部設定差であり、5.1節の条件へ追加しない。

## 決定論性・判定器・実装境界

公式／混成×4入口を各2回実行した。パスを含むヘッダを除くmain/sub全イベント列、
FDC種別列、件数、SHA-256は各組で完全一致した。既存LOADの準備SAVEも2回の
全イベント列が一致した。

`conform_l3.sh`は混成列が公式件数に届かなければ「失格」でなく「未到達」、
公式件数へ届いてSHAだけ違えば到達後の不一致とする。各入口の公式ログへ、
期待SHA末尾と件数を壊したコピーを通し、8故障すべてを不一致検出した。
画面到達判定器も合成陽性対照を到達、直後`Ok`を壊した陰性対照を未到達とした。

4入口とも新たに実装すべき分岐は観測されず、追加実装境界は見つからなかった。
`src/l3_service/make_subrom.py`は変更していない。5.2節の適合条件1〜5も変更しない。

## 検証結果

環境変数設定下の`conform_l3.sh`はrc=0で、新4入口の到達・全長一致と8故障の
検出を確認した。既存のdiskB条件は環境変数未設定のためSKIPであり、再合格とは
数えない。全自己検査の結果は本作業の最終報告時点の実走結果を採る。
