# m6i-a — 自作 main と自作 sub の単一セクタ READ 接続 — 事前登録

記録日: 2026-09-21  
状態: 測定前

対象は M6 統合の案Aである。自作 main ROM に main 視点の SEND/RECV、継続
SEND、PAIR と、既知の1セクタを READ する入口だけを加え、自作 sub ROM と
接続する。BASIC の `FILES` / `LOAD` / `SAVE` への接続は範囲外とする。sub ROM
は変更しない。根拠は `docs/spec/l3-subrom.md` 1.10、1.12、1.13、1.19、
1.31、1.36、1.37、1.63節と、同じ仕様を独立にコード化した既存治具
`tools/make_l3_test_main.py` に限る。

## 1. 問い

自作 main ROM に最小の main↔sub 通信プリミティブと単一セクタ READ 経路を
載せると、自作 sub ROMから媒体に応じた256バイトを受け取り、異常時には有限時間で
復帰し、既存の割り込み・拡張ROM・入力・画面機能を退行させずに反復できるか。

## 2. 腕（arm）

全腕で自作 main ROMと現行の自作 sub ROMだけを使う。正常媒体は
`tools/make_l3_testdisk.py --cylinders 40 --double-sided --sectors-per-track 16`
で作る規則生成D88とする。READ要求は先頭`0x02`、長さ5、末尾2位置を
`[論理トラック, R]`とする。READ後は`0x06`送信、`0xC0`受信、`0x12`送信、
256位置受信の順とする。5バイト要求の先頭だけ通常SEND、残る4位置は
`$FF=0F`を省略した継続SENDとし、256位置受信は1フェーズ2位置のPAIRを128回
行う。

### A0 `read_sector_1`

- **何をするか**: シリンダ0・ヘッド0・セクタ1を1回READし、受信した256位置の
  SHA-256だけを求める。
- **到達指標**: 5位置の要求run、FDCの`READ DATA`到達、READ後の3交換、
  256位置の受信、main側の完了印がこの順に各1回成立する。要求座標と完了印は
  自作RAMマーカーまたは本文を含まない解析結果で確認する。
- **期待の形**: 受信件数は256、受信SHA-256は
  `4ed6e24a1fb78f8c79423740e05a311c438bae0f09b9974e50619050fdb8540a`
  で、有限の測定期限内に定常入力待ちへ戻る。

### A1 `read_sector_2`

- **何をするか**: A0からRだけを2へ変え、シリンダ0・ヘッド0・セクタ2を
  1回READする。
- **到達指標**: A0と同じ交換列が完了し、要求のRが2であったことと256位置の
  受信完了を確認できる。
- **期待の形**: 受信SHA-256は
  `f0cb8924325dbf2dece67fbebf41a9ee1ffbcd88fe8493ca18cbb49129d3ab0f`
  でA0と異なる。これにより、mainまたはsubが媒体と無関係な固定値を返す形を
  陰性にする。

### A2 `no_media_return`

- **何をするか**: 媒体を挿入せずA0と同じREAD入口を呼ぶ。sub側の1.63節の
  媒体待ちは変えず、main側の固定上限で呼び出しを打ち切って定常入力待ちへ戻す。
- **到達指標**: 5位置の要求runが完了し、subが媒体待ちへ入ったことを
  `SENSE DRIVE STATUS`の反復と`READ DATA`未到達で確認したうえで、main側の
  timeout完了印が立つ。
- **期待の形**: 成功完了印も256位置受信も無く、timeout完了印だけが立ち、
  キー入力を再び受理できる。上限値は**未確定**であり、G8を満たすまでは
  この腕を開始しない。

### A3 `broken_wait_bit`

- **何をするか**: 陰性対照専用ビルドで、SEND前の終了条件を仕様の
  `$FE bit1=1`から反対の`bit1=0`へ1箇所だけ変え、A0を行う。ほかの命令列、
  媒体、期限はA0と同じにする。
- **到達指標**: 故障注入された判定箇所を少なくとも1回通ったことを専用の
  自作RAMマーカーで確認する。
- **期待の形**: A0の到達指標または期待SHA-256の少なくとも一方を満たさず、
  正常READとしては落ちる。正常に完了した場合は陰性対照のすり抜けとする。

### A4 `broken_continuation_and_pair`

- **何をするか**: 独立した2つの陰性対照を同じ腕の枝として行う。
  `A4-cont`は5位置すべてで`OUT $FF,0F`を出し、継続4位置での省略を壊す。
  `A4-pair`は2位置PAIRを単発RECV 2回へ置き換える。それぞれ変更は1種類だけで
  A0を行う。
- **到達指標**: `A4-cont`は第2位置の故障SEND、`A4-pair`は最初の故障受信へ
  到達したことを、それぞれ別の自作RAMマーカーで確認する。
- **期待の形**: 両枝ともA0の到達指標または期待SHA-256の少なくとも一方を
  満たさず、正常READとしては落ちる。片方でも正常完了した場合は、その枝の
  陰性対照がすり抜けたものとする。

### A5 `interrupt_repeat_regression`

- **何をするか**: 割り込みを有効にした定常状態でA0のREADを200回繰り返す。
  各回の前後で呼出規約上保存対象のレジスタ、`0x71`/`0x32`で選ばれる拡張ROM
  バンク窓の識別署名、完了回数を検査し、終了後に既存のキー入力場面を1回
  実行する。
- **到達指標**: READ完了が200回、測定中のmain割り込み受理が1回以上、
  READ前後の拡張ROMバンク窓プローブが各200回、終了後の打鍵受理が1回、
  いずれも本文を含まないマーカー、署名または件数で観測される。どれかが
  不足すれば、この腕は回帰の判定対象へ届いていない。
- **期待の形**: 各回の受信SHA-256がA0と一致し、完了回数の欠落が無い。
  保存対象レジスタに差が無く、`0x71`/`0x32`と窓の識別署名が各回の事前値へ
  戻る。既存のキー入力判定が成功し、画面の行数・文字数・SHA-256が同じ
  ベースライン腕と一致する。保存対象レジスタの集合は**未確定**であり、G8を
  満たすまではこの腕を開始しない。

## 3. 関門（gate）

いずれかが偽なら測定腕へ進まず、全体を`gate_failed`として止める。

- **G1 自己検査**: `tools/run_all_selftests.sh`がrc=0で終わる。
- **G2 クリーンルーム検査**: `tools/check_cleanroom.sh`がrc=0かつNG 0件である。
- **G3 媒体生成器**: `python3 tools/make_n88_blank_disk_selftest.py`と
  `tools/make_l3_testdisk_selftest.sh`がともにrc=0である。
- **G4 画面本文の非漏えい**: `tools/screen_content_leak_selftest.sh`、
  `tools/check_l3_screen_output_selftest.sh`、`tools/check_l3_entry_screen_selftest.sh`
  がすべてrc=0である。
- **G5 媒体同一性**: 正常媒体を独立に2回生成してバイト一致し、全体の
  SHA-256が
  `d3becfe5051f7002d268824a2da2824f543442e71ae3226e4d22139e0adce05c`
  に一致する。併せて、既定の空媒体のSHA-256が
  `2adb9833e0170aa9dfa5c5eb7c4b180307520cb8b2a671d6ee9db0903a3e8deb`
  に一致する。
- **G6 ROM境界**: sub ROMのビルド成果物SHA-256が案A導入前と一致し、sub側の
  差分が0である。main ROMと拡張ROMバンク1〜3は所定サイズ内で、配置検査、
  窓外中継検査、命令境界検査をすべて通る。main末尾1160Bを超える場合は、
  測定で既成事実にせず`gate_failed`とし、配置方式を事前登録し直す。
- **G7 器具の検出力**: 正常な合成入力でA0/A1の到達指標と異なる2つのSHAを
  識別でき、要求run欠落、受信1位置欠落、完了印欠落、故障注入マーカー欠落を
  それぞれ不合格にする自己検査が通る。
- **G8 未確定値の凍結**: A2のmain側上限値、全腕の測定期限、A5の保存対象
  レジスタ集合、キー入力の既存シナリオ名、画面ベースライン署名を測定開始前の
  追補で固定する。追補時点でも測定結果は見ない。

## 4. 判定名

判定は関門、到達、結果の順で付ける。対象へ届かなかった腕は解析例外にせず、
腕名、最後に成立した到達指標、理由とともに`unreached`として記録する。

- `gate_failed`: G1〜G8のいずれかが偽。腕ごとの成否は付けない。
- `unreached`: 関門通過後に、その腕の到達指標を満たさなかった。タイムアウト、
  完了印欠落、故障注入箇所未通過もここに含む。
- `read_matches_generated_sector`: A0が到達し、256位置の件数とSHA-256が期待値に
  一致し、定常入力待ちへ戻った。
- `read_data_mismatch`: A0は到達したが、件数、SHA-256、復帰のいずれかが不一致。
- `sector_select_changes_signature`: A0/A1がともに到達し、各SHA-256が各期待値に
  一致し、互いに異なる。
- `fixed_value_suspected`: A0/A1がともに到達したが、SHA-256が同じ、または
  片方以上が対応する期待値と不一致。
- `no_media_returns`: A2が到達し、成功受信なしでtimeout完了印が立ち、
  後続キー入力を受理した。
- `no_media_hangs_or_completes`: A2が到達したが、期限内に復帰しない、または
  媒体なしで成功完了した。
- `wait_negative_detected`: A3の故障箇所へ到達し、A0の正常完了条件が落ちた。
- `wait_negative_escaped`: A3の故障箇所へ到達したのにA0と同じ正常完了になった。
- `sequence_negative_detected`: A4の2枝が各故障箇所へ到達し、両方ともA0の
  正常完了条件が落ちた。
- `sequence_negative_escaped`: A4の少なくとも1枝が故障箇所へ到達したのに
  A0と同じ正常完了になった。
- `integration_regression_free`: A5が到達し、200回のREAD、レジスタ、拡張ROM
  バンク窓、キー入力、画面署名の全条件が期待の形に一致した。
- `integration_regressed`: A5が到達し、上記の少なくとも1条件が不一致。
- `m6i_a_pass`: `read_matches_generated_sector`、`sector_select_changes_signature`、
  `no_media_returns`、`wait_negative_detected`、`sequence_negative_detected`、
  `integration_regression_free`がすべて成立し、`gate_failed`と`unreached`が無い。
- `m6i_a_fail`: 関門通過後、失敗側の判定名が1つ以上成立し、`unreached`が無い。
- `m6i_a_inconclusive`: 関門は通過したが、1腕以上が`unreached`である。

## 5. 判定後の行き先

- `m6i_a_pass`: 案Aを採用し、単一セクタREAD入口を固定する。次の別事前登録で
  BASIC命令への接続へ進む。案Bへは進まない。
- `read_data_mismatch`または`fixed_value_suspected`: 1.36〜1.37節の要求種別、
  座標、READ後交換、256位置対応を分けて再測定する。sub実装や期待SHAを結果に
  合わせて変えない。
- `no_media_hangs_or_completes`: main側の有限復帰方式を変更し、1.63節のsub側
  媒体待ちとの境界を別稿で事前登録する。sub ROMへコードを足す案は、残り10Bの
  容量を理由に無登録では採らない。
- `wait_negative_escaped`: 待ち判定の検出力が無いので、1.13・1.19節の4条件を
  個別の陰性対照へ分解して測り直す。
- `sequence_negative_escaped`: 省略規則なら1.10節、PAIRなら1.31節を対象に、
  すり抜けた枝を単独で測り直す。
- `integration_regressed`: レジスタ、バンク窓、キー入力、画面の最初に落ちた
  項目へ責任範囲を絞り、常駐部配置または拡張バンク配置を変えた案Aを再登録する。
- `m6i_a_inconclusive`: 到達器具または期限だけを直した追補を先に置き、同じ腕と
  判定条件で再走する。結果条件は緩めない。
- main末尾1160B内に収まらず、窓外中継を含む配置案Aも関門を通せない場合に限り、
  案Bへ進む。容量超過だけを理由にsub側へ無登録で機能を追加しない。

## 6. 本文に出さないもの

- 測定終了時のテキスト画面の行本文は、標準出力、標準エラー、結果ノート、
  コミットメッセージのいずれにも出さない。画面比較は行数、文字数、SHA-256、
  および本文を返さない真偽判定だけを使う。
- ROM由来のバイト列は出力、保存、転記しない。main↔subのデータポート値列と
  セクタ本文も列として出さず、件数とSHA-256だけを残す。
- I/Oログを使う場合、結果へ残す前に`tools/redact_iolog.py`を通し、`$FB`、
  `$FC`、`$FD`の値列が伏せられていることを`tools/check_cleanroom.sh`で検査する。
- 測定ログの`--out`ファイルは開かない。解析器が返す到達真偽、件数、署名、
  判定名だけを扱う。
- 画面本文またはデータ列を含む出力を検出した時点で、その走は判定に使わず
  `gate_failed`として停止する。
