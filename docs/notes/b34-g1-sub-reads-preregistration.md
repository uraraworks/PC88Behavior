# B34: G1 のサブ RAM 上のコードが読む番地を、値なしで測る — 事前登録

記録日: 2026-11-01
位置づけ: [B33](b33-g1-rom-origin-results.md) の次段。方針ノート第3節の「どこを」をサブ側で測る。**このノートは測定より先にコミットする。**

## 1. 問い

サブの `0x2000` 以上で動くコードは、どの番地をデータとして読むか。ROM の領域を読むか。誰も書いていない RAM、公式 ROM が書いた RAM を読むか。公式と自作でどう違うか。

## 2. 器具

コアに `--sub-read-log` を足す（パッチ 0019）。既定は無効で、無効なら動作を変えない。

発行元の PC が `0x2000` 以上のデータ読み（命令の取得を除く）について、番地ごとに回数を数える。読んだ番地を、その時点の状態で分類する。

- `rom`: `0x2000` 未満（ROM の領域）
- `unwritten`: 起動から誰も書いていない RAM
- `rom-written`: 最後に書いたのが発行元 `0x2000` 未満のコード
- `ram-written`: 最後に書いたのが発行元 `0x2000` 以上のコード

**値は持たない。** 書き込みの追跡も番地と発行元の別だけである。

器具は G1 なしで自己検査する（自作の試験コードで 4 分類の陽性対照、命令の取得が数えられないこと、値が出ないこと）。

## 3. 条件

腕 F の 4800 フレームと、打鍵なしの 3600 フレーム。OO・SS 各 2 走。条件は B30 と同じで、クラウドの実行環境で行う。main の境界記録が B1 / B28 と一致することで、器具が走を変えていないことを確かめる。

## 4. 記録の白リスト

`R <開始>-<終了> <rom|unwritten|rom-written|ram-written> <回数>`（連続区間にまとめる）と走の条件の行だけ。

## 5. 判定（事前に決める）

- 公式で `rom` があれば、その番地は G1 の需要の候補である。**ROM の値は読まない。** 働きやデータの扱いは方針ノート第5節のとおり別に判断する
- 公式で `rom-written` の区間を並べ、自作と比べる。自作が同じ番地に別のものを置いているか、書いていないかを書く
- 違いが B30 の分かれ目より前にあるかは、この記録の順番が無いので言わない。原因は書かない
