## 第1走の結果（予測は全て的中）

登録した予測は、ストライド・桁の間隔・ファンクションキー行・DMAC 転送長・消去の有無の全てが一致した（予測なしの2腕〔20行へ変える腕の行21の印〕は観測のみ）。

### テキストVRAMの並び（観測。すべての腕で全印が一意・線形・2走一致）

テキストVRAMは F3C8 から1行120バイト、25行ぶん3000バイト。写しの位置は F3C8 を 0 とする。

| 桁数 | 文字の位置（行 r、桁 c） | 文字の間隔 | 文字域 | 属性域 |
|---|---|---|---|---|
| 80 | 120×r + c | 1バイト | 行内 0〜79 | 行内 80〜119（20組×2バイト） |
| 40 | 120×r + 2×c | 2バイト（文字の次の1バイトは 0x20） | 行内 0〜79（40文字×2バイト） | 行内 80〜119（20組×2バイト。80桁と同じ位置） |

- **行ストライドは桁数・行数によらず 120**（`layout-rem`・w40・w40-20・w40-25・w80-20・w80-25 の全てで、行6の桁0の印が 720、行7が 840）。
  従って 5.6節の「120バイト/行の前提が崩れる」は**当たっていない**。崩れたのは文字の間隔（2バイトおき）の前提だった（推定: 旧測定は文字を1バイトおきで読んだため隣の桁が混ざって見えた。旧測定の生データは読み直していない）。
- 40桁時の桁 c の印は 120×r + 2×c（例: 行6桁0 → 720、行9桁10 → 1100、行11桁37 → 1394。80桁は桁10 → 1090、桁77 → 1397）。文字と文字の間（奇数番目のバイト）は 0x20。
- 空行の内容（`width` 直後、行0〜5。20行・25行とも）: 文字域は全て 0x20、属性域は未使用の組が 20組とも「先頭バイト 0x80・次バイト 0x00」。
  **属性域の既定は表示行数（20行）の外の行（行20〜24。25行ぶんの3000バイト全体）にも書かれる**（20行の腕でも行20〜24の属性域に既定の組がある。文字域は空白）。
- ファンクションキー行（文字域に内容のある行。値・長さは採っていない）: **20行の腕は行19、25行の腕は行24**（40桁・80桁とも）。それ以外に文字域に内容のある行は、直後のプロンプト（行17。器具の都合）だけ。
  25行の腕の行20〜23、20行の腕の行20〜24 の文字域は空白（20行の腕で属性域だけ既定の組がある）。
- 色（`color 2` で印を描き `color 7` に戻す）の行の属性域: 80桁では印の桁5・終わりの桁8に対して、行内位置 80 が 5、82 が 8、83 が 2（81 は空白相当）、
  40桁では行内位置 80 が 9、82 が 15、83 が 2（81 は空白相当）。位置バイトは 80桁で桁そのもの（5・8）に見えるが、**40桁では 9・15（＝2×桁−1）に見え、桁の2倍ではない**。
  最初の組の値バイト（行内 81）が 0x00 か 0x20 か、組の意味（開始桁なのか終端桁なのか）は第1走だけでは確定できない（0x00/0x20 を区別せず除外した器具の隙間）→ 追補1。

### 消去の範囲（erase 腕。観測）

- **`width` が受理されると、事前に置いた3つの印（行6桁0・行8桁60・行21桁0）が全て消える**。`width 40`・`width 40,20`・`width 80,20`・`width 80,25` の全てで。
  行21は 20行の表示（行0〜19）の外だが、20行へ変える腕（`width 40,20`・`width 80,20`）でも消えた。**消去は3000バイト（25行ぶん）に及び、表示行数で打ち切られない**
  （上の「行20〜24の属性域に既定の組」とも整合）。
- 現在と同じ指定（25行のまま `width 80,25`）でも消える（`erase-w80-25`。4.22.3 の再確認）。`rem` 腕（`width` なし）は3つとも残る（陽性対照）。
- 消去後に打った印（行14桁0）は、桁数に応じた並び（80桁は 1680、40桁は 1680＝120×14。印の2文字目以降の間隔は 40桁で2）で書かれる。

### 切替の制御ポート（窓の中のメインCPUの OUT。`rem` 腕に無い、`width` で現れるもの）

禁止事項5の判断は事前登録のとおり（制御・設定ポートでありデータポートではない）。記録したのは次のとおり。

- **ポート 0x30**: `width` を実行するたびに1回書かれる（現在と同じ桁数でも書く。`width 80,25` を2回なら 0x23 が2回）。
  値は **80桁で 0x23、40桁で 0x22**（差は bit0 だけ。1＝80桁）。`width` を実行しない腕（`rem`）では窓の中に書かれない。行数（20/25）は 0x30 に現れない
  （`width 40`・`width 40,25` ともに 0x22、`width 80,20`・`width 80,25` ともに 0x23）。
- **ポート 0x31**: 窓の中で約6900回、同じ値が繰り返し書かれる（ROM が定期的に書き直す）。値は **20行で 0x19、25行で 0x39**（差は bit5 だけ。1＝25行）。
  桁数（40/80）では変わらない。切替の時点で値が 0x19→0x39（20→25行）または 0x39→0x19 に変わる（`erase-w40-20`・`erase-w80-20`）。
- **DMAC**: 切替ごとに 0x64（アドレス、下位 0xC8・上位 0xF3＝F3C8）、0x65（転送長、下位・上位）、0x68（0xA0 のあと 0xE4）を書く。
  0x65 は **20行で 0x5F・0x89（2400バイト＝20行×120）、25行で 0xB7・0x8B（3000バイト＝25行×120）**。桁数では変わらない（40桁・80桁とも）。
  0x64・0x68 は行数・桁数によらず同じ。
- **CRTC**（カーソル位置の更新は別。0x81＋2パラメータが繰り返し現れ、パラメータは（桁, 行）と一致する値）: 切替ごとに
  RESET（コマンド 0x00）＋5パラメータ、続けてコマンド 0x43（パラメータなし）、0x20（パラメータなし）。
  5パラメータは **20行で 0xCE・0x93・0x73・0x38・0x13、25行で 0xCE・0x98・0x6F・0x58・0x13**。**桁数（40/80）でパラメータは変わらない**
  （40桁でも 0xCE は80桁と同じ）。つまり 40桁と80桁の違いはポート 0x30 の bit0 だけで、CRTC の桁設定・DMAC の転送長・行ストライドは同じ。
- ポート 0x32 は erase 腕のすべて（`erase-rem` を含む）で 0xAA／0xA9 を交互に多数回書いていた。`layout` 腕にはない。`width` とは無関係（`erase-rem` にもある）で、原因は調べていない。

注意: 上は窓の中の**ポートごとの順序**で、ポート間の順序（DMAC と CRTC と 0x30 のどれが先か）は第1走の集計が持っていなかった（器具の隙間）→ 追補1。

## 予測との照合（第1走）

| 量 | 予測 | 観測 |
|---|---|---|
| 行ストライド | 120（全腕） | 120（全腕）一致 |
| 桁の間隔 | 80桁1・40桁2（弱い予測） | 一致 |
| ファンクションキー行 | 20行→19、25行→24 | 一致（`rem` 腕は起動の20行で 19） |
| DMAC 0x65（窓の最後の2値） | 20行 5F 89・25行 B7 8B | 5腕すべて一致 |
| 消去（erase） | 受理で全消去、`rem` は残る、20行へ変える腕の行21は予測なし | 一致。予測なしの腕でも消えた |

判定の実装に誤りがあった: ファンクションキー行を「空白でないバイトのある行」で探したところ、全行の属性域に既定の組があるため全行が該当して `fkey` が differ になった。
観測は正しく、登録した予測（行番号は文字域に内容のある行）に合わせて判定を直した（d8e1d4c）。観測データは変更していない。
