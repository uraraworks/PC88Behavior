# ゴール B 方針 追補7 — G5 の実走の中で、作業域の番地へ自作の値を入れて応答を見る

記録日: 2026-11-13
位置づけ: [追補6](goal-b-policy-addendum6-differing-block-2026-11-01.md) の後続。これまでのノートは書き換えない。

## 何が起きたか
G5 が呼ぶ main ROM の 7071 は、起動時と同じ画面初期化（OUT 31/30/40/51/50/64/65/68、18件）を、
ゲームが作業域へ書き込んだ設定で走らせ直す部品と見られる（B90 entry7 の観測、B86 追補12・13）。
自作のプローブで公式 BASIC の起動後の状態から呼ぶと、7071 は G5 と別の道に入り戻らない（追補13b、60F/200F/2010F）。
ゲームが書いた作業域の状態でないと本来の道を通らないため、プローブだけでは働きを決められない。

## 2026-11-13 に利用者と決めた線
**G5 の実走の中で、7071 を呼ぶ直前に、作業域の番地を1つずつ自作の値へ書き換え（介入）、7071 の外に出る結果がどう変わるかを見てよい。**
（利用者がこのスレッドで直接「追補7 OK」と返答、2026-11-13 02:06）

- ゲームから採るのは、これまでどおり**番地だけ**（どの番地を 7071・11DF が読むか＝パッチ0028 の記録）。
- 介入する値は**こちらが選んだ値**。記録するのは「入れた値と、7071 の OUT の値・テキスト画面への書き込み範囲・戻りとの関係」（そのまま出る、ビットが対応する、無関係、等）。
- **介入しない基準の走**（＝ゲームそのままの 7071）の OUT の値・画面の中身・ゲームが書いた作業域の値は記録しない・出力しない。基準との比較は「変わったか／変わらないか」の真偽と、入れた値との関係だけで行う。
- 入れた値と無関係に決まる値（ROM の定数やゲームのデータ由来）は「定数（値はリポジトリ外）」として扱う（B88 追補3 の集計の作法）。
- 画面本文・ディスクのバイト列・タイトル名は従来どおり出さない。

## 線の理由
- 働きは「介入への応答の規則」で決めるという第5節の方法は変えない。変わるのは、介入の土台を「自作プローブが作った状態」から「ゲームが作った状態」に替えることだけ。
- ゲームの作った状態そのもの（値）は採らない。採るのは「その番地に別の値を入れると外に何が出るか」で、これは第三者が同じゲームで再現できる。

## 進め方
1. 器具（G5 の実走で、指定フレームに指定番地へ値を書き込む介入）と事前登録を Mac で作る。
2. クラウドの測定スレッドで走らせ、値なしの集計をライブラリへ。
3. 規則を仕様 main-rom-entry に書き、自作 main の 7071 を実装する。
