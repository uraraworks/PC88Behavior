# l4-s1e — 属性域の既定のバイト値と、スクロールの範囲 — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

段階2a（`f858553`・`da4617d`）の実装担当は、仕様書 `docs/spec/l3-main.md` 第1版だけでは決められない項目として次を挙げ、実装側で選んだ:

- 属性域40バイトの「既定の並び」の具体的なバイト値（全ゼロを選んだ）
- スクロールの範囲（ファンクションキーの行を取らず20行全部を選んだ。書き写しの量が公式の実測〔20行で120B×18行〕と合わない）

いずれも測れば決まる外形なので、推測で埋めずに測る。l4-s1b の Q2（`d8eb0a1`）で SHIFT を単独で押すと最下行を中心に22セルが変わった観察があり、最下行がファンクションキーの表示である推定を補強する材料になっているが、これも推定のままである。

**実装は行わない。測定のみ。**

## 問い

- Q1 既定の属性の並び: 何も打たない起動後の画面で、目印の無い行の属性域40バイトは何か。白黒（既定）とカラー（`CONSOLE ,,,1` の後）で別々に測る。
  - l4-s1c の記述（B2 の既定の並びは B0/B1 と異なる）と照合する。
- Q2 スクロールの範囲とファンクションキーの行: `CONSOLE` の第3引数（ファンクションキー表示スイッチ、2-39: 1で表示、0で非表示）を 0／1 と振り、表示行数（`WIDTH 80,20`／`WIDTH 80,25`）と組にして、スクロールで書き写す行数を測る。
  - 見込み（l4-s1a 訂正の追記の推定）: 表示ありなら範囲は表示行数−1、書き写しは範囲−1。表示なしなら範囲は表示行数、書き写しは表示行数−1。
- Q3 ファンクションキーの行の中身の形: 表示ありのとき、最下行の文字域のうち空白でないセルの数と位置の範囲（文字の値は出さない。ファンクションキーの既定の割り当ては ROM のデータなので、本測定では値を扱わない）と、その行の属性域。

## 器具の点検（測定前に済ませておく事前チェック）

Q1・Q3 に要る出力を、現行の `tools/l4_vram_probe.py` の既存モードで得られるか確かめた。

- 既存の解析モード（`analyze_dump`）は、目印の無い行について「目印の無い行で最も多い属性域の並び（`non_marker_attr_mode`、1個だけ）と一致するかどうかの真偽（`non_marker_rows[].matches_mode`）」しか出さない。**行ごとの属性域40バイトの値そのものは、目印を含む行（`marker_row_attrs`）以外には出力しない設計**になっている（`tools/l4_vram_probe.py` 冒頭のコメント「出力してよいもの」3.、および `analyze_dump` 実装）。Q1 は目印を打たない走（目印0件）を含むため、この既存モードのままでは属性域の値そのものが一件も取れない。
- 既存の差分モード（`diff_vram_dumps`、`--count-only-rows` 追補含む）は2枚の写しの比較用で、単独の1枚から「ある1行の文字域のうち空白でないセルの数と位置範囲」を出す機能を持たない。Q3 が要る形の出力ではない。

したがって、**測定の前に、以下を器具として追加する必要がある**（器具そのものはこの事前登録では作らない。別コミットで足し、leak 検査〔`screen_content_leak_selftest.sh`〕に対照を追加して確認してから本測定に使う）:

- 追加A（Q1向け）: 文字域を一切出さず、指定した行（または全行）の属性域40バイトの値をそのまま行ごとに列挙するモード。属性域はハードウェアの設定値であり画面本文ではないため、既存の「属性は出してよい」方針（冒頭コメント2.・5.）の延長として問題ない。
- 追加B（Q3向け）: 1枚の写しについて、指定した行の文字域のうち空白(0x20)でないセルの**数**と、**最小col0・最大col0**（＝位置の範囲）だけを出し、文字コードそのものは出さないモード。`--count-only-rows` が差分モードで採る「値を出さず件数だけ」の考え方を、単独写しの空白判定に転用する形。

## 条件

- 公式ROM一式、ディスク無し、既定の BASIC モード（コア既定 N88 V2）、既定の DIP。l4-s1a・l4-s1c と同条件。
- 目印: `q7z`（l4-s1a 追補2で確定した表記。打鍵注入は英字をシフト無しで小文字として送るため `--type` にも小文字で書く）。C0・C1 は目印を打たない（Q1 は「目印の無い行」そのものを見るため）。C2 は目印として `q7z` を使う。
- 読んだマニュアルの頁: `refs/manual_squashed.txt` 2-39（CONSOLE）。**本セッションでは `refs/manual_squashed.txt` が作業ツリーに存在せず、直接は開けなかった。** 代わりに、同じ頁を根拠として既に引用している本リポジトリ内の記述（`docs/notes/l4-s1a-text-vram-preregistration.md` の「読んだマニュアルの頁」節、および `docs/notes/l4-s1a-text-vram-results.md` の「ファンクションキー表示の有無（`CONSOLE`第3引数）」という既存の呼び方）で書式を確認した。CONSOLE の引数順は、既存の測定が使ってきた `CONSOLE ,,,0`／`CONSOLE ,,,1`（カラー／白黒スイッチ、2-29 の COLOR の項に記述、CONSOLE の4番目の引数）と、本測定が使う `CONSOLE ,,0`／`CONSOLE ,,1`（ファンクションキー表示スイッチ、2-39 に記述、CONSOLE の3番目の引数）が別の位置であることに対応している。この確認は測定担当が実測前に `refs/manual_squashed.txt` 2-39 で裏を取ること。

### 打鍵と写しのフレーム

- 起動settle: l4-s1a・l4-s1c と同じ `--type-at 300 --type '\n'`。
- 実コマンドの打鍵開始: l4-s1a・l4-s1c と同じ `--type-at 700`。
- `line_end` / `dump` の計算式は l4-s1c と同じ:
  ```
  line_end(k) = 700 + 8 * (その行までに打った文字数の累計、\nも1文字)
  dump(k)     = line_end(k) + 20   （実行の余裕。根拠は l4-s1c の同節）
  ```
- `--key-hold` / `--key-gap` は指定せず既定値（各4フレーム）。

## 腕

- **C0** 何も打たない（白黒の既定）: 打鍵は起動settleの `\n` のみ。写し1枚、`--vram-dump-at 720`（settle後の余裕。打鍵が無いため line_end=700、dump=700+20=720）。
- **C1** `CONSOLE ,,,1\n`（13文字、カラーの既定）のみ:
  `--type-at 700 --type 'console ,,,1\n'`
  `line_end = 700 + 8*13 = 804`、`dump = 824`。写し1枚（`--vram-dump-at 824`）。
- **C2** スクロール: {`WIDTH 80,20` / `WIDTH 80,25`} × {`CONSOLE ,,0` / `CONSOLE ,,1`}（第3引数だけ指定）の4条件で、`PRINT "q7z"` を表示行数＋6回打つ。
  - 打鍵文字列（1行にまとめず改行区切り、`width` は数字のみ英小文字化、`console` も同様）:
    - `WIDTH 80,20` は `width 80,20\n`（11文字）
    - `WIDTH 80,25` は `width 80,25\n`（11文字）
    - `CONSOLE ,,0` は `console ,,0\n`（12文字）
    - `CONSOLE ,,1` は `console ,,1\n`（12文字）
    - `PRINT "q7z"` は `print "q7z"\n`（12文字、l4-s1a・l4-s1cと同じ）
  - 4条件の打鍵列（`width` → `console` → `print` を N 回、N はその条件の表示行数＋6）:
    - C2-20-off: `width 80,20\nconsole ,,0\n` + `print "q7z"\n` × 26
    - C2-20-on:  `width 80,20\nconsole ,,1\n` + `print "q7z"\n` × 26
    - C2-25-off: `width 80,25\nconsole ,,0\n` + `print "q7z"\n` × 31
    - C2-25-on:  `width 80,25\nconsole ,,1\n` + `print "q7z"\n` × 31
  - 累計文字数は `width`(11) + `console`(12) + `print`行×12ずつ、を各 `print` の出現順に足し込んで `line_end`／`dump` を算出する（式は上記の共通式のまま。個々の `print` 完了時点で写しは取らない。スクロールの発生自体は書き込み記録〔`--mem-write-log`〕から数える）。
  - 最終写しは、最後の `print "q7z"\n` の `dump` 時点で1枚（表示が安定した後の画面全体を1回だけ見る。l4-s1c のB0/B1/B2と同じ「実行後の状態を1回捉える」考え方）。
  - 走行フレーム数: 最終写し＋200以上（l4-s1a・l4-s1cの余裕の踏襲）。
  - 各腕2走。

腕の総数: C0(1) + C1(1) + C2(4) = **6腕**。

- 採るもの:
  - `--vram-dump PATH --vram-dump-at F`（腕ごとの写し枚数ぶん指定）。
  - `--mem-write-log PATH --mem-write-range 0xF3C8-0xFF7F --mem-write-from-frame 700`（C2 のスクロール検出・関門G7に使う）。
  - `--io-log`。
  - 解析は「器具の点検」節で足した追加A・追加Bのモードを持つ `tools/l4_vram_probe.py`。既存モード（目印の位置・目印行の属性域）も引き続き併用する。

## 本文を出さない

- Q1・Q3 は属性域のバイトと、空白でないセルの数・位置の範囲だけを出す。**目印の無い行の文字の値は出さない**。「器具の点検」節の追加A・追加Bも、この境界を超えない設計にする（文字コードそのものを出さず、追加Aは属性域のみ、追加Bは件数と位置範囲のみ）。
- Q3 のファンクションキーの行の文字は ROM のデータ表（既定の割り当て）にあたる可能性があるので、値を出さず、扱いは別に決める。
- 写し・記録・iolog は使い捨ての作業ディレクトリ（リポジトリ外）に置き、結果ノートを書いたら削除する。
- 解析道具は `screen_content_leak_selftest.sh` の対象に、追加A・追加Bぶんの陰性対照を足してから使う。

## 判定

- Q1: 白黒・カラーそれぞれの既定の並び（記述）と、`all_zero`（実装が選んだ全ゼロと一致）／`nonzero_pattern`（ゼロでない既定パターンが存在する）。
- Q2: 4条件の書き写し行数の表と、`fkey_row_reserved`（表示ありで範囲が1行減る）／`not_reserved`（表示の有無で範囲が変わらない）／`other`（上のどちらにも当てはまらない形。記述する）。
- Q3: 記述のみ（判定名は付けない。最下行の非空白セル数・位置範囲・属性域をそのまま書く）。
