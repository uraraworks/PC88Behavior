## 予測なし16腕の観測（記述のみ、規則の根拠として使う）

| 腕（GOTO と GOSUB の対） | 観測 |
|---|---|
| `large`（選択式 1000000000） | ERR 6、p=1。GOSUB も同じで、次の文の印 0 は出ない（終端印は出る） |
| `f14`（1.4） | 選択値 1（GOTO は 1、GOSUB は 1,0） |
| `f15`（1.5） | 選択値 2（GOTO は 2、GOSUB は 2,0） |
| `f25`（2.5） | 選択値 3（GOTO は 3、GOSUB は 3,0） |
| `f05`（0.5） | 選択値 1（GOTO は 1、GOSUB は 1,0） |
| `fm05`（-0.5） | ERR 5、p=1 |
| LET の `a%=2.6`（LET あり・なし×プログラム・直接の4腕） | 全て 3 |

注: 「GOSUB の large で次の文の印 0 が出る」ことは本ノートの観測にない（出たのは ERR 6 のみ）。親からの報告にあった「戻って印 0 が出る」は GOSUB の f14/f15/f25/f05 の観測であり、`large` では ERR 6 を捕捉して END した。

以上は「CINT と同じ四捨五入（0.5 は絶対値の大きい方へ）で整数化し、0〜255 の範囲検査（外は ERR 5）、整数にできない大きさは ERR 6」と整合する（2.5→3 は偶数丸めではないことを示す。-0.5 は四捨五入で -1 になり範囲外）。-0.5 の整数化が -1 であるという中間値は観測していない。観測は「ERR 5 になる」までである。

## 副次的な発見（未測定の差）

捕捉した構文の誤り（ERR 2）の処理が END したあと、直接モードで次に打った行が実行されなかった（3腕×2走）。同じ形の ERR 13・ERR 5・ERR 29・ERR 30 の腕では終端印が出ている。原因は未確定で、自作ROMとの差の有無も未確認。
