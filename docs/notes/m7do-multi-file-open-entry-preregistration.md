# m7do: 複数ファイル同時オープン需要入口の事前登録

実施日: 未実施（本稿は事前登録のみ。測定はまだ行っていない）

本稿の到達条件は実測前に固定する。公式ROM・公式ディスクの内容は読まず、
生ログ、画面報告、ROM／ディスク複製はリポジトリ外の一時領域だけに置く。
使用するファイル内容はすべて自作データであり、公式ディスクの既存内容には
一切依存しない。

## この入口で新しく踏みたいもの

`m7dn`（未踏の需要入口サーベイ）で指摘したとおり、既踏の17入口
（diskA起動＋FILES/SAVE-NEW-LOAD/既存ファイル単独LOAD/シーケンシャル出力・
入力/KILL/NAME/RUN"file"/MERGE/BSAVE/BLOAD/ランダムアクセスPUT-GET/DSKI$-
DSKO$/削除済みLOADエラー＋B:系エラー3種＋正常B:FILES）は、いずれも
「一度に1ファイルだけを開く」という制御構造の範囲に収まっている。

本入口の焦点は、**同時に開いたファイル数という、これまで一度も振っていない軸**
である。具体的には、2つのファイルを同時にOPENし、交互に読み書きしたときに、

1. これまでの17入口のどれにも出現していない公開μPD765コマンド種別が
   新たに現れるか、
2. ファイル切替（#1↔#2の往復）に伴って、単独オープン時には説明できない
   追加のFDCアクセス（例: 切替のたびに余分なSEEK/SENSE系が挟まる）が
   生じるか、
3. 2ファイル分の`main IN $FC`件数が、各ファイルを単独で開いて同じ内容を
   読んだ場合の件数の単純な合計として説明できるか、できないか。

**何も新しく踏まなかった場合の扱い（先に決めておく）**: 3節「到達条件」を
満たし、かつ上記1〜3のいずれについても「未見のコマンド種別は0件」「切替に
伴う説明不能な差分は0件」「2ファイル分の`IN $FC`件数が単独オープンの合計と
一致する」が揃った場合は、**「新しい経路は踏まなかった」と判定し、そのまま
記録する。** これは失敗ではなく、「自作subの256バイト単位プリミティブは
同時オープン数に関わらず使い回せる」という実装境界がさらに1件確認された
という、それ自体価値のある結果として扱う。逆に、1〜3のいずれかが崩れた
場合は「新しい経路を踏んだ」と判定し、差分の内訳（コマンド種別・件数・
発生タイミング）を記録する。

## 対象入口と自作データ

第1候補は、2つの自作シーケンシャルファイルを同時にOPENし、交互に
`LINE INPUT#`で読み進める入口とする。公式ディスクの既存内容には依存しない。

### 準備（公式一式のみ、混成は不要）

使い捨てdiskA複製に対し、次を打鍵して2つの自作ファイルを作る。

```
10 OPEN "Q9A" FOR OUTPUT AS #1
20 PRINT #1,"A1"
30 PRINT #1,"A2"
40 PRINT #1,"A3"
50 CLOSE #1
60 OPEN "Q9B" FOR OUTPUT AS #1
70 PRINT #1,"B1"
80 PRINT #1,"B2"
90 PRINT #1,"B3"
100 CLOSE #1
110 PRINT "P9D"
RUN
```

到達は、`P9D`表示と直後の`Ok`。この準備runは第75版のシーケンシャル出力・
入力と同じ構造（単独ファイルのOUTPUT）であり、新規性はない。**準備runの結果は
測定対象に含めない**（純粋な下ごしらえ）。完成複製を公式一式／混成の別プロセスへ
同一入力として渡す。

### 測定本体（本稿の主対象）

完成複製に対し、次を打鍵する。

```
10 OPEN "Q9A" FOR INPUT AS #1
20 OPEN "Q9B" FOR INPUT AS #2
30 S$=""
40 FOR I=1 TO 3
50 LINE INPUT #1,A$
60 LINE INPUT #2,B$
70 S$=S$+A$+B$
80 NEXT I
90 IF S$="A1B1A2B2A3B3" THEN PRINT "M9M"
100 CLOSE #1
110 CLOSE #2
120 PRINT "M9C"
RUN
```

`#1`と`#2`を同時にOPENしたまま、`FOR`ループ内で3往復、交互に
`LINE INPUT#1`→`LINE INPUT#2`を行う。片方のファイル位置がもう片方の
読み出しに巻き込まれて壊れていれば、`S$`は`"A1B1A2B2A3B3"`という
期待どおりの順にならず、`M9M`は出ない。

### 分解基準（内部対照・公式一式のみでよい）

3節の判定3「単独オープンとの合計一致」を検証するために、次の2つの
単発条件も同じ手順（公式一式のみ、決定論性確認のため各2回）で測る。
これらは新しい需要入口ではなく、**加算基準を作るための内部対照**である。

```
' Q9A単独版
10 OPEN "Q9A" FOR INPUT AS #1
20 S$=""
30 FOR I=1 TO 3
40 LINE INPUT #1,A$
50 S$=S$+A$
60 NEXT I
70 IF S$="A1A2A3" THEN PRINT "M9A"
80 CLOSE #1
90 PRINT "M9C"
```

```
' Q9B単独版（OPEN先をQ9Bに、マーカーをM9Bに差し替えるだけ）
```

## 到達条件・対照

**測定本体の到達条件**は次の全条件とする。

1. `OPEN "Q9A" FOR INPUT AS #1`・`OPEN "Q9B" FOR INPUT AS #2`を含む
   プログラム入力が画面へ反映され、`RUN`が反映されること。
2. 交互読み出し後の一致マーカー`M9M`が表示されること。
3. `CLOSE #1`・`CLOSE #2`の反映後、`M9C`が表示されること。
4. `M9C`の直後に`Ok`が表示されること。

**不合格条件**（いずれか1つでも該当すれば不合格）:

- 構文エラーで実行が止まる。
- `M9M`を欠く（読み出し内容が2ファイル間で混線した証拠）。
- `M9C`を欠く（CLOSEの後続処理が完了しない・停止する）。
- `M9C`はあるが直後に`Ok`が無い（CLOSE自体はマーカーまで届いたが
  異常終了する）。
- 単なる構文受理や、`RUN`直後の無反応・無限ループ。

陽性対照は、上記4条件をすべて満たす合成画面とする。陰性対照は、
(a) `M9M`だけを欠く形、(b) `M9C`と直後`Ok`だけを欠く形の2種とする。
分解基準（内部対照）の到達条件は、`M9A`（またはM9B）表示と直後の
`M9C`・`Ok`とする。

## 観測指標と固定手順

既存の測定ラッパ、FDC分類（`P`: 起動前置き、`R`: SEEK→SENSE INTERRUPT
STATUS→SENSE DRIVE STATUS→READ DATAの4件組、`W`: 末尾WRITE DATA、
これで説明できない種別はそのまま公開コマンド名で記録する）、main受信列、
画面署名を再利用する。

測定するのは次の量だけとする。値そのもの（データポートの値列）は出さない。

- 公開FDCコマンド種別列とその件数
- `READ DATA`・`WRITE DATA`の発行件数
- main `IN $FD`・`IN $FC`の件数とSHA-256
- 画面の行数・文字数・SHA-256

**測定本体は公式一式／混成それぞれ2回ずつ実走し、4run全てで取りこぼし0件・
決定論的一致（同一モード2回が完全一致）を前提条件とする。** 取りこぼしが
1件でもあれば、その回の署名は期待値へ採用せず、原因を切り分けてから
測り直す。分解基準（内部対照）は公式一式のみで良いが、同じく各2回の
決定論性を確認する。

初回公式実走で件数・SHA-256と画面の行数・文字数・SHA-256を得て
`tests/conformance/`の期待値として固定した後に、公式／混成を同条件で
再検証する。期待値の件数・SHA-256を壊した故障コピーが不一致を検出することも
確認する（表示ラベルに`/`を含む名前を一時ファイル名へ使わない。`m7cj`・
`m7cu`と同型の判定器バグを再発させないため、故障コピー生成は`mktemp`で行い、
期待値0行は無条件で失敗として扱う）。

## 不採用条件と切替

`FOR`ループ内での`#1`/`#2`交互`LINE INPUT`が`Syntax error`等となり、
公式一式でも上記入口へ到達しない場合、その試行の署名は期待値へ採らず、
不採用の事実だけを本稿へ残す。その場合の切替候補は、ランダムアクセス
（`FIELD`/`GET`/`PUT`は既踏だが、複数ファイルを同時に`AS #1`/`AS #2`で
開いてレコード単位に交互アクセスする形はまだ踏んでいない）へ移す。
切替時は、その実測より前に本稿と同じ型で到達条件・対照を追加固定する。

## 情報境界

記録するのは件数、SHA-256、画面の行数・文字数・SHA-256、自分で打鍵した
文字列・自作データ（`A1`〜`A3`、`B1`〜`B3`等）、および公開されたμPD765の
コマンド名だけとする。画面本文全体、ディスクのデータ部、公式の応答値は
記録しない。ROM・ディスクの複製、生iolog、標準出力はすべてリポジトリ外の
一時領域だけで扱う。
