# B73: G1 の F1 の道で、`0x0E` の前後のサブの ROM 側の動きを公式と自作で比べる — 結果

記録日: 2026-11-02
規則: [b73-g1-f1-sub-after-0e-preregistration.md](b73-g1-f1-sub-after-0e-preregistration.md) どおり。公式どうし・自作どうしは一致した。記録は `measurements/b73-g1-f1-sub-after-0e.txt`（22MB。集計はクラウドで取り、その出力だけを読んだ）。

## 結果

- 公式: `A` の行 1098。fc 112686〜112816 で、`seek`、`sense_interrupt`、`sense_drive_status`、`read_data` などの FDC コマンド 7 つ
- 自作: `A` の行 699103。最後は fc 112684 で、作業域 `7C04` と `7C29` を読む行が続く（待ちの繰り返し）。io ログは取りこぼしで FDC の並びは出せない。`4000-4FFF` への書きは無い

## 分かったこと

**自作は G1 の `0x0E` の読みを始めていない。** `0x0E` を受け取る前後で、自分の作業域を見る待ちに入って出てこない。

## 読み方（推定）

B72 のプローブでは自作も `0x0E` を受けられた。違いは場面である。G1 は `0x0D` で RAM 上のコードへ移り、コードが `0x00C1` へ戻ってから次の要求を送る。自作の `0x00C1` からの受け取りは、`0x0C`・`0x0D`・`0x15`・`0x16` だけを見分けていて、`0x0E` を知らない可能性が高い。B74 で、`0x00C1` へ戻ったあとの `0x0E` を公式と自作で比べる。
