# l4-s4h 事前登録 追補 — 除外規則は半端の腕H1〜H7のみ、対照H8・H9は判定に含める

記録日: 2026-09-15
状態: 事前登録の追補、測定前
対象: [l4-s4h-double-round-half-preregistration.md](l4-s4h-double-round-half-preregistration.md)
（`ea02e1f`）を上書きする形で追補する。本体は書き換えない。

## 経緯

本体には次の2つの規定が並んでいた。

- 「判定」節: 予測表の`exact_binary`列が`no`の腕は、候補の判定
  （`candidate_consistent`/`candidate_rejected`）から除き、記述だけに
  する。
- 「判定」節の「対照（H8・H9）の扱い」: H8・H9は`EXACT`・`GW`のどちらで
  も同じ予測になるはずの腕として、**通常の候補判定にそのまま含める**
  （除外しない）。

対照H8・H9（`1234567890123456.4#`・`1234567890123456.6#`）は、小数部
`.4`・`.6`が2進で正確に表せないのが普通であり、`exact_binary=no`に
なりうる。その場合、上記2つの規定が衝突する——1つ目の規定に従えば
H8・H9は判定から除かれるが、2つ目の規定は明示的に「含める」としている。

この衝突は、依頼文が「除外はexact_binary=noの腕全般」「対照は判定に
含める」の両方を並べ、**どちらを優先するかを明示していなかった**こと
が原因である。測定開始前（予測表の中身を見る前）に、この優先関係を
確定しておく。

## 1. 除外規則の適用範囲を確定する

**「`exact_binary`が`no`の腕は候補の判定から除く」という規則は、半端を
狙った腕（H1〜H7）だけに適用する。**

対照（H8・H9）には、この除外規則を適用しない。H8・H9は、
`exact_binary`列の値にかかわらず、常に候補の判定（`candidate_
consistent`/`candidate_rejected`の対象）に含める。

理由: 除外規則の趣旨は「2進で正確に半端を表せない腕は、そもそも
`EXACT`・`GW`のどちらの丸め方向を採っても同じ結果になるはずで、半端の
丸め方向を判定する材料にならない」という点にある。この趣旨はH1〜H7
（値を`.5`ちょうどに寄せて半端を作ろうとした腕）には当てはまるが、
H8・H9は最初から「半端でないこと」を確かめるための対照であり、値が
2進で正確に表せるかどうかは対照としての役割（両候補が同じ予測に
なるはずかどうか）とは無関係である。よって対照には除外規則を適用しない。

## 2. 本体の「判定」節の読み替え

本体「判定」節の該当箇所は、以後次のとおり読み替える。

- 「予測表の`exact_binary`列が`no`の腕（略）は、候補の判定から除き、
  記述だけにする」→ **「H1〜H7のうち、予測表の`exact_binary`列が`no`
  の腕は、候補の判定から除き、記述だけにする」**
- 「候補ごとの判定: 予測表の各候補列（`EXACT`・`GW`）について、
  `exact_binary`が`no`でない腕全部で（略）」→ **「候補ごとの判定:
  予測表の各候補列（`EXACT`・`GW`）について、H8・H9の全2腕と、H1〜H7
  のうち`exact_binary`が`no`でない腕とを合わせた集合の全部で（略）」**
- 「対照（H8・H9）の扱い」節はそのまま有効（本追補と矛盾しない。
  「通常の候補判定にそのまま含める」という記述が、本追補で明確化した
  「`exact_binary`の値にかかわらず」という条件を含んでいたことになる）。
