# m7en: 系列Cを登録上限N=128へ引き直す事前登録

実施日: 2026-09-02

本稿は、系列C（`ALPHA-MINI DOS 1.5`複製、ドライブ2、`2:`接頭辞）について、
N=65〜128を測定する前に、予測、判定規則、停止規則、媒体間比較規則を固定し直す
事前登録である。本稿の作成時には新しい測定を行わず、実測結果を含めない。

## 背景

`m7em`では、測定器の入力検査がN=64までしか受け付けなかった状態をコミット`39ec819`で
訂正し、N=128まで受け付けるようにした。これは系列Bについて`m7ed`が登録済みだった
上限N=128へ器材を合わせた訂正であり、系列Bの上限を延長したものではない。

一方、系列C・D・Eは`m7ej`が上限をN=64と事前登録していた。系列CはN=1〜64を受理し、
確認済みジャンプN=15・31・47・63を得たが、停止理由は器材上限であり、容量端点には
達していない。`m7em`は、訂正後の器材なら系列CをN=128まで延長し得るものの、延長する
場合は別稿で事前登録し直すと定めた。**本稿がその別稿である。**

これは、`m7ej`の上限N=64を実測後に延長する操作ではない。既存の上限を事後に書き換えず、
新しい上限N=128を次の実測より前に固定する、**事前登録のやり直し**である。系列Dと系列Eは
それぞれ容量端点N=60、N=23へ既に達しており、同じ固定介入のまま延長する余地が無い。
従って、本稿の対象は**系列Cだけ**とする。

## 問い

系列Cは、公式媒体で四点目まで確認済みジャンプを得て、なお容量端点へ達していないため
五点目以降を検査できる唯一の系列である。本稿の問いは、固定条件の公式媒体で五点目以降の
確認済みジャンプが得られるか、あるいはその前後で容量端点へ当たるかである。

## 事前登録する予測

系列Cで既に確認済みのジャンプはN=15・31・47・63であり、観測範囲N=1〜64では
`P_C=16`、`V_C=(+258,+1)`が成立している。この周期が同じ間隔と増分で続く場合、
五点目以降の候補位置を次のとおり予測する。

| 点 | 予測位置N | 予測増分 |
|---:|---:|---:|
| 5 | **79** | **(+258,+1)** |
| 6 | **95** | **(+258,+1)** |
| 7 | **111** | **(+258,+1)** |
| 8 | **127** | **(+258,+1)** |

九点目の予測位置はN=143であり、本稿の登録上限N=128の外にある。上表の予測は本稿の
作成時に固定し、実測後に書き換えない。予測位置が外れても、位置が外れた事実と、確認済み
ジャンプ間の間隔および増分が完全一致したかどうかを分けて記録する。絶対位置の一致を
H-Mの判定へ用いない。

## 系列の定義と固定介入

系列Cは`m7ej`と同じく、ドライブ1を公式システムディスク（起動用、読出し専用、固定）、
ドライブ2を`ALPHA-MINI DOS 1.5`の使い捨て複製とする。全ファイル名へ`2:`を前置し、
一覧操作を`FILES 2`へ固定する。準備runでも測定runでもドライブ1を変更しない。

自作名と作成順は`m7ed`から継承した次の式へ固定する。

```text
名前(N) = "QD" + CHR$(65 + INT((N-1)/26)) + CHR$(65 + ((N-1) MOD 26))
```

N-1チェックポイントの新しい複製へ、1runで1本だけを登録順に作成し、内容は空とする。
実際の指定には`2:`を前置する。KILL、上書き、順序変更、名前変更、接頭辞変更を行わない。

N=0校正も`m7ed`・`m7ej`から変更しない。固定不存在名のOPENが所定の画面分類と直後の
`Ok`へ到達することを確認し、判定区間の入口計数を校正値として記録する。この値から
既存項目数、占有量、バイト数、管理形式または容量を逆算しない。

## 測定操作と観測量

測定操作と観測量は`m7ed`・`m7ej`から変更しない。各Nの完成チェックポイントの新しい
使い捨て複製をドライブ2へ置き、N=0校正と同じ固定不存在OPENを公式2run測る。各runは
9000フレーム、300Fで改行、700Fで固定プログラム打鍵とし、判定区間は700F以後とする。
単一走は採用しない。

一次指標は次の整数対へ固定する。

```text
X_(C,N) = (700F以後のmain IN $FC件数, 700F以後のREAD単位)
```

併記する量も変更しない。main `IN $FC` / `IN $FD`の件数・SHA-256、公開FDCコマンド種別列と
総件数、READ DATA・SEEK・WRITE DATA件数、値を除いたイベント構造の件数・SHA-256、
隣接N間の一致prefixと最初の差の位置、画面の行数・文字数・SHA-256、main/sub取りこぼし
件数を記録する。SHA-256は同一性確認だけに使う。測定runでWRITE DATAが1件でも出れば
不採用とする。

## 差分とジャンプの固定判定規則

差分とジャンプは`m7ed`・`m7ej`の規則を変更せず、そのまま継承する。

```text
Delta_(C,N) = X_(C,N) - X_(C,N-1)    (N=1..128)
```

`Delta_(C,1)`は基準差分であり、単独ではジャンプと呼ばない。N=2〜128へ次を適用する。

1. 2成分とも直前差分へ完全一致すれば**定常差分**とし、境界へ数えない。
2. 両成分が直前差分以上で、少なくとも一方が厳密に大きければ
   **正方向ジャンプ候補**とする。
3. 両成分が以下で少なくとも一方が厳密に小さければ**負方向変化**、一方が大きく他方が
   小さければ**方向不一致**とし、H-M支持へ数えない。
4. 過去Nで0件だった公開FDCコマンド名の初出を**未見経路候補**とする。語彙が同じでも
   N-1列をstrict prefixとして後続が増えれば**構造的延長**、prefixを保たず順序が
   変われば**構造変化**として分ける。

候補Nでは通常走を止め、直前の受理済み8本境界アンカーからN-1とNを独立再構築して
各2run再測定する。同じ符号、差分ベクトル、FDC構造分類が完全再現した場合だけ確認済み
ジャンプへ採用する。不一致は支持にも反証にも数えず欠測とする。数値の幅、割合、誤差許容を
導入せず、「近い」「ほぼ同じ」を判定語に使わない。

## 周期性の固定判定規則

周期性も`m7ed`・`m7ej`の規則を変更せず、そのまま継承する。系列Cの確認済みジャンプを
昇順に`J_(C,1),...,J_(C,k)`、ジャンプベクトルを`V_(C,i)=Delta_(C,J_(C,i))`、
隣接間隔を`P_(C,i)=J_(C,i+1)-J_(C,i)`とする。

1. **k=1:** 単発ジャンプであり周期を算出しない。
2. **k=2:** 唯一の間隔は周期候補だが、反復が無いため周期とは確定しない。
3. **k>=3:** 全隣接間隔が同じ正整数`P_C`へ完全一致し、全ジャンプベクトルが同じ
   `V_C`へ完全一致し、ジャンプ間の成立済みNに別ジャンプ、負方向変化、方向不一致が
   無い場合だけ、系列Cの観測範囲で周期成立とする。
4. 間隔または増分が1回でも違えば、外れ値を除かず**非等間隔／増分不一致**とする。
   都合のよい3点や部分列を選び直さない。
5. FDC追加suffix、未見コマンド、値非表示イベント構造は併記する。同じPとVでも構造が
   混在すれば、数値周期は成立、経路の同一性は未確定と分ける。

周期成立後の次予測位置まで全介入が成立しても同じVの確認済みジャンプが無ければ、
その位置を通過した時点で周期破れとする。予測位置より前の容量端点、介入不成立、欠測、
登録上限による打ち切りは周期破れでなく後続周期を**検査不能**とする。全て整数の完全一致で
判定する。

## 介入成立と全名OPEN検証

介入成立と全名OPEN検証も`m7ed`・`m7ej`から変更しない。各Nは作成run、媒体SHA-256差、
`FILES 2`各2run一致、修正版全名OPEN検証が成立した場合だけ採用する。`FILES 2`は直後
`Ok`、READ非0、WRITE 0、main/sub取りこぼし0件、2run完全一致、N-1から画面の行数・
文字数・SHA-256のいずれかが変化することを要求する。画面本文と公式媒体の既存名は
記録しない。

全名OPEN検証では、ホスト側でN=1〜Kの全自作名へ`2:`を前置し、最大8名ずつのリテラル
INPUT OPENへ分割する。全chunkの固有マーカー、WRITE 0、取りこぼし0件が揃った場合だけ
K全体を合格とする。

ブロック末端K=72・80・88・96・104・112・120・128では、対象Kより先に毎回次の両対照を
取る。

- **陽性対照**: 系列Cの受理済みK=8チェックポイントで全名OPENが合格すること。
- **陰性対照**: そのK=8の使い捨て複製から`2:QDAA`をKILLし、WRITE非0、ドライブ2の
  媒体SHA-256差、ドライブ1のSHA-256不変、main/sub取りこぼし0件を確認した後、同じ
  全名OPEN検証が実際に不合格になること。
- 両対照の成立後だけ対象Kを判定する。対照失敗時は対象Kを走らせず器材不成立とする。

容量端点が8の倍数の途中にある場合は、最後に作成成立したKへ同じ分割版と両対照を適用する。
不合格なら直前の受理済み8本境界からKを1ずつ増やし、最初の不合格Kと最後の合格Kを
特定する。検証対象を減らさず、一部名で代用しない。

同一Nの2runは全イベント列、画面、main受信件数・SHA-256、FDCコマンド種別列の完全一致を
必須とする。介入不成立、到達失敗、取りこぼし、2run不一致、独立再構築不一致は欠測とし、
ゼロ差分、ジャンプ、周期破れへ読み替えない。

## 再開点、上限、停止規則

系列CはN=64まで受理済みであり、最後の受理済み8本境界アンカーはN=64である。本稿では
そこからN=65〜128を測る。既存のN=1〜64の測定値と確認済みジャンプ4点は再利用し、
再測定しない。中断後は系列名、N、両媒体SHA-256を照合し、最後の受理済み8本境界
アンカーから再開する。系列別・8本ごとのチェックポイント、媒体SHA-256、安全集計、
完了フラグはリポジトリ外の永続作業領域へ記録する。

本稿で固定する上限は**N=128**であり、実測後に延長しない。作成が容量または作成上限で
成立しなくなった場合、それ自体をジャンプや周期破れへ数えず、最後に成立したNを系列Cの
容量端点として打ち切る。次予測位置より手前で打ち切られた場合は**周期破れではなく
検査不能**とする。欠測をゼロ差分または境界なしへ読み替えない。

N=128まで走り切っても、九点目の予測位置N=143には届かないため九点目は検査不能である。
この場合も「周期がN=128で終わった」または「五点目以降が無い」へ読み替えない。五点目から
八点目までの予測位置はN=79・95・111・127であり、これらと九点目N=143を混同しない。

## 媒体間比較

現在、k>=3の4系列（A・B・C・D）は全て`P=16`、`V=(+258,+1)`へ完全一致し、媒体間比較
規則1によりH-M（媒体不変）支持となっている。本稿でも`m7ed`・`m7ej`の媒体間比較規則を
変更せず、次のとおり適用する。

1. 比較する系列のPとVが完全一致すればH-M支持とする。絶対位置と絶対値は使わない。
2. 比較する系列で周期が成立しても、PまたはVの少なくとも一方が完全一致しなければ
   H-M'支持とする。
3. 一方で周期が成立し、他方はk>=3かつ成立済み範囲内の間隔または増分が内部不一致なら、
   一定PとVが媒体不変というH-Mは不支持、H-M'支持とする。不一致側に存在しない単一の
   PまたはVを作らない。
4. どちらかがk<3、欠測、端点前の打ち切り、または両系列とも単一PとVを成立させられ
   なければ、媒体間比較は**不成立**とし、H-M、H-M'のどちらにも数えない。
5. 数値の幅、割合、誤差許容を使わず、外れ値を除かず、位置合わせや部分列の選び直しを
   行わない。絶対位置と絶対値は比較に使わない。

系列Cを延長して反復回数が増減しても、規則1の判定はPとVの完全一致で決まり、反復回数を
根拠に規則を書き換えない。系列Cで間隔または増分が1回でも違えば、周期性の規則4により
非等間隔／増分不一致とし、外れ値を除かない。その結果の媒体間比較には上記5規則だけを
適用する。

## 変更しない事項と本稿で変える唯一の点

次の事項は`m7ed`・`m7ej`から**変更せず、そのまま継承する。**

- 系列Cの媒体、ドライブ配置、`2:`接頭辞、`FILES 2`、空内容という固定介入
- 名前生成式、作成順、KILL・上書き・順序変更等を行わない規則
- N=0校正
- 9000フレーム、300F改行、700F打鍵、700F以後の判定区間、公式2run、単一走不採用
- 一次指標`X`と全ての併記観測量
- 差分とジャンプの固定判定規則1〜4、および候補の独立再構築
- 周期性の固定判定規則1〜5
- 8本境界ごとの修正版全名OPEN検証、K=8の陽性対照と`2:QDAA`欠落の陰性対照
- 両対照成立後だけ対象Kを判定する順序
- 媒体間比較規則1〜5
- 独立再構築、固定条件、再開時の照合、欠測の扱い
- 情報境界

**本稿で変える唯一の点は、系列Cの登録上限をN=64からN=128へ引き直すことである。**
下限、判定規則、対照、独立再構築、固定条件、観測量は変えない。

## 情報境界

情報境界は`m7ed`・`m7ej`から変更しない。対象媒体には市販ソフトのディスクイメージが
含まれるが、使うのは私物の使い捨て複製であり、リポジトリへ持ち込まない。媒体、生ログ、
チェックポイント、manifest、画面はリポジトリ外の永続作業領域へ置き、コミットしない。

記録するのはN、件数、差分、位置、frame、clock、SHA-256、画面の行数・文字数・SHA-256、
自分で打鍵した文字列・自作名、公開FDCコマンド名だけとする。媒体の既存名、画面本文、
公式応答値、データポート値列は表示も転記もしない。`private/`を開かず、逆アセンブルせず、
媒体は測定器へパスで渡すだけとする。媒体と作業領域の絶対パスをリポジトリへ記録しない。

## 言えること／この事前登録で決まらないこと

現時点で言えるのは、既存測定で系列CのN=1〜64が受理され、確認済みジャンプ4点と
`P_C=16`、`V_C=(+258,+1)`が成立し、N=64では容量端点へ達していなかったことまでである。

本稿は実測前の登録であるため、五点目以降の有無、系列Cの容量端点、延長結果によるH-M
またはH-M'の支持・不支持は決まらない。管理単位の内部形式、ジャンプや容量端点の原因、
実機一般性も決まらない。P、V、ジャンプ位置、反復回数からエントリ長、セクタ長、バイト数、
アドレス、既存項目数または媒体の総容量を逆算しない。

## 検証（事前登録時点）

本稿の作成時には新しい測定を行わず、エミュレータを起動していない。`src/`、`tools/`、
`docs/spec/`は変更していない。`tools/check_cleanroom.sh`を実行し、全項目OK、rc=0を確認した。
