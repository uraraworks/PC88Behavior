# m7aq: 交換#14のREAD#3〜#5が通り、適合条件1（main `IN $FD` 5635件）を達成

測定日: 2026-08-18

## 情報境界

公式main ROM一式と公式ディスク（diskA）を**実行して測定した**。読んで
いない——`build_mixed_rom()` は中身を一切見ずに `cp` するだけであり、
比較は `tools/cmp_io.py --location-only`（値を出力しないモード）と
`tools/conform_l3.sh`（件数とSHA-256のみ）の内部で完結している。
本ノートに書く数値は**件数・位置・一致長**だけで、値は1バイトも載せない。
生ログはリポジトリ外（セッションのスクラップパッド）に置き、
リポジトリには入れていない。

## 1. 結果 — LIMIT=4 で全件一致

m7ap でサブROMフェッチ窓（0x0800）の超過を解消したので、m7ao の宿題3
「LIMIT=3 → LIMIT=4 を一段ずつ測る」を実施した。混成ROM（公式main ROM
一式＋自作サブROM）で diskA を 1800フレーム起動し、main が `IN $FD` で
受け取る値の列を公式環境の実測と突き合わせた
（`tools/cmp_io.py --cpu main --port FD --kind IN --location-only`）。

| `PC88_BULK_READ_INTERVENTION_LIMIT` | 先頭一致 | 前回（m7ao時点） |
|---|---|---|
| 1 | 1282 / 5635 | 1282（一致。回帰なし） |
| 2 | 3330 / 5635 | 3330（一致。回帰なし） |
| 3 | **5378 / 5635** | 0（クラッシュで退行していた） |
| 4 | **5635 / 5635（全件一致）** | 0（同上） |

対象側の到達件数はどのLIMITでも5635件（公式と同数）。

`tools/conform_l3.sh` の `[混成(自作サブROM)]` は、
`tests/conformance/expected.tsv` を**一切変更せずに**件数(5635)・SHA-256
とも一致して合格した。**適合条件1（`docs/spec/l3-subrom.md` 5.2節1項）を
達成した。** 2回連続で同じ結果になることも確認済み。

LIMIT=1 が `[混成]` NG のままであることが、この判定の陽性対照になっている
（テストが何でも通すわけではない）。混成ROMの組み立て自体も
`conform_l3.sh` の自己検査e/f/g（main側ファイルが保たれていること・
`DISK.ROM` が自作品に差し替わっていること・「公式」ダミーのままでない
こと）が全項目OKで、「実は公式サブROMを走らせていた」線は潰れている。

## 2. なぜ動くようになったのか

m7al〜m7ao で追っていた LIMIT=3/4 の0件退行の原因は、m7ao の結論どおり
**`_observed_request_next_6`〜9 が丸ごとフェッチ窓の外に置かれていた**
ことだった。窓の外は一様な `0xFF`（RST 38）なので、そこへ実行が入ると
即座に空転する。m7ap でコードを420バイト縮めて全LIMITを窓内に収めた
結果、READ#3〜#5 が初めてそのまま実行されるようになった。

つまり **READ#4/#5 のロジック自体は以前から正しく書けていた**。
実行できていなかっただけである。m7al が「未特定のクラッシュ」として
残した現象は、新しい不具合ではなく窓の制約の影であった。

## 3. 既定を LIMIT=4 へ上げた

m7ak が既定を上げなかった理由は「READ#4が未実装のため測定が無限ループ的に
長引く（ログ2097180行、1800フレームを終えられない）」だった。この理由は
消えた——LIMIT=4 の実走は LIMIT=1 より**短い**（適合テスト全体で約6秒、
LIMIT=1 は約9秒）。既定を `1` → `4` へ変更した。

既定を上げた状態で `tools/run_all_selftests.sh` を公式環境つきで実行し、
24本すべてが期待どおりの結果になることを確認した（`verify_l3.sh` の
既知のNG1件＝適合条件4のネガティブコントロールを含め、判定は
LIMIT=1時代のベースラインと1文字も違わない）。

## 4. 一致していないもの（正直に書く）

- **main側の構造的一致プレフィックスは258件のまま**、sub側は752件のまま
  （`tools/diag_l3_mixed.sh`）。適合条件1は「mainが `IN $FD` で受け取る
  値の列」であって、pcや他ポートを含む構造列の一致ではない
  （仕様書1.14節・5.1節）。**値の列が全件一致したことと、構造列が258件で
  分岐することは矛盾しない。** ここを混同して「全部一致した」と書かない。
- 適合条件2（diskB起動時に `$FC` を使わないこと）・条件3・条件4
  （ディスク無しでsubが無音）は**未達成のまま**。条件4は
  `verify_l3.sh` が既知のNGとして報告し続けている。
- 書き込み経路（SAVE）は未着手。
