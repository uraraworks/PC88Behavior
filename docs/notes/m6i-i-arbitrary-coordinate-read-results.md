## 4. 腕ごとの結果

2走で同一。表の `R` はその行で再試行が起きたことを表す（記録のみ、判定には
使わない）。`@[id, C, H, R]` は不一致の行で**実際に受け取ったセクタの先頭4バイト**
（自作合成ディスクに自作の規則で書いた座標。公式データではない）。
識別値は 0xA1=161（ドライブA用）、0xB2=178（ドライブB用）。

### I-S（本測定）— `sweep_all_match`

| # | 要求 (ドライブ, C, H, R) | 結果 |
|---:|---|---|
| 1 | A, 0, 0, 1 | match（再試行1回） |
| 2 | A, 0, 1, 1 | match |
| 3 | A, 1, 0, 1 | match |
| 4 | A, 0, 0, 16 | match |
| 5 | A, 39, 1, 16 | match |
| 6 | A, 20, 0, 8 | match |
| 7 | A, 5, 1, 11 | match |
| 8 | B, 0, 0, 1 | match |
| 9 | B, 0, 1, 1 | match |
| 10 | B, 39, 1, 16 | match |
| 11 | A, 0, 0, 1 | match |

**11行すべてが、D88 像から取り出した期待値とバイト単位で一致した。**
再試行は行1（起動後の初回の要求）でだけ起きた。m6i-h の結論（初回は失敗しうるので
再試行1回で吸収する）と同じ形である。

### 故障注入腕 — 測定そのものの検出力

| 腕 | 注入した欠陥 | 判定 | 不一致になった行と、実際に読んだ座標 |
|---|---|---|---|
| I-F-H | 論理トラックの bit0 を落とす（H を無視） | `fault_detected` | #2 → (A1,0,**0**,1)、#5 → (A1,39,**0**,16)、#7 → (A1,5,**0**,11)、#9 → (B2,0,**0**,1)、#10 → (B2,39,**0**,16) |
| I-F-D | ドライブ選択を常に0 | `fault_detected` | #8 → (**A1**,0,0,1)、#9 → (**A1**,0,1,1)、#10 → (**A1**,39,1,16) |
| I-F-R | R を1足す | `fault_detected` | 全11行が match でない。R=16 の #4・#5・#10 は `no_data`、他は R が1大きいセクタ |
| I-F-RETRY | 再試行口の入力 A の退避を外す | `fault_not_exercised` | 11行すべて match。再試行が起きたのは行1（ドライブA）だけ |

**どの故障も、事前登録 §4 の「必ず不一致になるべき行」がちょうど不一致になり、
それ以外の行は一致した。** しかも受け取った先頭4バイトが、**何を取り違えたかを
そのまま名乗っている**（H 無視なら H が 0、ドライブ無視なら識別値が A1）。

**I-F-R は追補1 が無ければ `unreached` へ落ちていた。** R=16 の3行は R=17 という
存在しないセクタを読みに行き、データが返らない。事前登録の元の到達定義
（「256位置を受け取った」）のままだと、**誤りを見抜いた行が未到達扱い**になって
いた。

**I-F-RETRY は予測どおり踏まれなかった。** 再試行が起きるのは起動後の初回の要求
（行1、ドライブA）だけで、入力 A を失っても0（ドライブA）が送られるので結果は
変わらない。事前登録 §4 はこれを予期して `fault_not_exercised` を置き、総合判定に
入れていない。再試行口がドライブを保つことは、G7 の Z80 実走検査が押さえている。

## 5. 総合判定

**`m6i_i_general_read_verified`**。

- I-S が `sweep_all_match`
- I-F-H・I-F-D・I-F-R がすべて `fault_detected`

したがって、**自作 main の一般READ は、要求した (ドライブ, C, H, R) のセクタを
自作 sub を通して正しく受け取る**。そしてこの合格は、**H を無視する誤り・ドライブを
無視する誤り・R がずれる誤りのいずれに対しても、検出力を示したうえでの合格**である。

## 6. 得られたこと

- **任意座標の READ が自作どうしで通った。** これまで既知の1座標しか通していなかった
  経路を、両ドライブ・両ヘッド・C と R の端まで通した。
- **試験データの穴を実装前に塞いだことが、検出力として現れた。** 旧規則のディスクでは
  ヘッド0と1、ドライブAとBの中身が同じなので、I-F-H と I-F-D は**必ず合格していた**。
  新規則では、読み違えた先の先頭4バイトが取り違えた軸をそのまま示した。
- **故障注入が「測定の目が開いていること」の証拠になった。** I-S の全行一致だけでは、
  測定が盲目である可能性を排除できない。故障注入3種がすべて狙った行で捕まった
  ことで、I-S の合格を検証として数えられる。

## 7. この測定で決まらないこと

- **公式 sub が何を要求するかは決まらない**（§2）。
- **座標列の11行以外の座標で正しいことは、規則として主張しない。** 軸ごとに1軸だけ
  変える並びにしたので、軸を無視する型の誤りには強いが、特定の値だけで起きる誤りは
  網羅していない。
- **I-F-RETRY の型の誤り（再試行でドライブを失う）は、本測定の条件では踏まれない。**
  その防御は G7 の Z80 実走検査に依っている。
- 複数セクタREAD、WRITE、BASIC 命令からの経路は決まらない。
- ドライブB の媒体を抜いた場合など、媒体の無い座標の扱いは決まらない。

## 8. 行き先

事前登録 §8 の `m6i_i_general_read_verified` の行き先に従う。

1. **一般READ を BASIC 側の接続へ使ってよい。**
2. 次の稿で、**ディレクトリ（FILES）の読み出し**を BASIC からの経路として測る。
   ディレクトリの置き場所（どのトラック・セクタか）は、公式の測定に基づく仕様書の
   記述から取る。**推測で決めない。** 仕様書に無ければ、先にそれを測る。
3. 1.65節・1.36節への規則の追加は行わない（§2）。
