# m7hw: 大量転送runの共通prefixで、応答の差が要求の差より先かを決める — 結果

実施日: 2026-09-07

## 位置づけ

[m7hv](m7hv-bulk-prefix-ordering-preregistration.md)が事前登録した測定の結果
である。事前登録は測定開始前に単独コミット（`1b1055a`）してあり、本稿では
段階・中止規則・判定規則・clockしきい値を後から動かしていない。`src/`・
`tools/`は本稿では変更していない。

**結論を先に書く: 主判定はF3（共通prefixに不一致なし）である。** 大量転送run
（添字14）の共通prefix**4759位置すべてで、公式と混成の応答内容が一致した**
（不一致0）。したがって**順序はこの方法では決まらない**。`m7hs`の留保
「要求の1バイト差は原因か結果か」は、**本稿でも未解決のまま残る。**

**ただしF3は事前登録が「この方法が偏る側」と明記した判定である。**
混成側の大量転送runは`m7hu`の窓で切られており（終端clockが窓の終端153707と
一致）、**共通prefixの外に差がある可能性を排除できない。** F3を「応答は一致
している」と読んではならない——事前登録に書いたとおりである。

run列」から「大量転送runの共通prefix」へ変わったため、arm 9がこの新しい比較
対象を動かすことを改めて確認した。前2回で有効だったことを根拠にせず、毎回
取り直している。

## 段階1: 既知の差との照合 — 対応関係は確認できなかった

`docs/PLAN.md`が記録する「公式sub13593件／自作sub13362件」と、本稿の添字14
（公式run長5632／混成4759）を照合した。

| 項目 | 既知差 | 本稿の添字14 |
|---|---|---|
| 数えている量 | **割り込み受理件数** | **応答runの長さ（バイト数）** |
| 公式／自作 | 13593／13362 | 5632／4759 |
| 比（自作÷公式） | 約0.983 | 約0.845 |

**数えている量が違い、比も一致しない。対応関係は確認できなかった。**
ただし混成側の4759は窓による打ち切りを含む値であり、**真の長さが分かって
いない以上、「別物である」と断定もしない。** 判定できなかったものとして記録
する。事前登録どおり、段階1は中止条件ではないため段階2を実施した。

| 項目 | 結果 |
|---|---:|
| 大量転送run（添字14）のrun長（公式／混成） | 5632／4759 |
| 共通prefix長 | **4759** |
| 共通prefix内の不一致 | **無し（0件）** |
| **判定** | **F3（共通prefixに不一致なし）** |

対照（条件O vs 条件M+arm 9）は共通prefix長1・位置0で不一致となり、F1を返した。
**比較は差に反応する。**

## 言えること・言えないこと

**言えること:**

- 窓内で比較できた範囲について、**公式subと自作subの応答内容は一致している**。
  内訳は、応答run 0〜13（`m7hu`で完全一致を確認済み）と、大量転送run（添字14）
  の先頭4759位置（本稿で不一致0を確認）である。
- **応答の差が要求の差より先に立っているという証拠は、本稿では得られなかった。**
- この比較は差に反応する（対照でF3→F1に変わる）。**差を検出できない方法で
  「一致した」と言っているのではない。**

**言えないこと:**

- **F3は「応答が完全に一致している」ではない。** 混成側の大量転送runは窓で
  切られており（終端clockが窓の終端と一致）、**4759位置より後ろは見ていない。**
  事前登録が明記したとおり、**この方法はF3へ偏る。**
- したがって**F1・F2・F2cのいずれも主張しない。順序は決まっていない。**
  `m7hs`の留保は残る。
- run長5632対4759という差が実体か打ち切りの産物かは、本稿でも分かっていない
  （`m7hu`から変わらない）。
- 段階1の照合が付かなかったことは、既知差と本稿の対象が別物であることの証明
  ではない。

## 次に何を測れば絞れるか

**残っている穴はただ1つ、「混成側の大量転送runの真の長さと、4759位置より後ろの
内容」である。** ここが埋まれば、留保は片付く。

1. **混成側の大量転送runが完結するまで窓を延ばし、その完結clockとrun長だけを
   測る。** 内容の比較ではなく**runの終端を求めるだけ**なので、比較の場面を
   揃える必要が無い（比較していないため）。これで4759が打ち切りの産物かどうかが
   決まる。
2. 1で真の長さが公式と同じ5632だと分かれば、**共通prefixは全長になり、本稿の
   不一致0は「大量転送runは完全一致」を意味する**ことになる。そのとき窓内の
   応答はすべて一致し、**要求の1バイト差（clock 153613）が窓内で最も早い
   食い違いとなる**——すなわちF2（要求の差が先）へ確定する道が開く。
   **ただしそれは本稿の判定ではなく、次稿で事前登録して測るべきものである。**
3. 1で真の長さが違う、または4759位置より後ろに不一致があると分かれば、
   その位置のclockを153613と比べて順序を決める。
4. いずれの場合も、**対照の妥当性は4度目の取り直しを行う**（比較対象がまた
   変わるため）。
