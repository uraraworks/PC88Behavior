# m6f-c 追補2 — 自作の空媒体をドライブ2で測る — 事前登録

記録日: 2026-09-25  
状態: 測定前（本測定は3回回し、いずれも本来の問いに届いていない）

## 1. 経緯

### 1.1 本測定2回目（器具の不具合）

追補1 §4 に従い `--boot-fill 0xC0` で回し直した（2026-09-24）。総合判定は再び
`m6f_c_boot_blocked` だった。原因は**測定ドライバの不具合**である。区間の打鍵文字列が
本物の改行を含んだまま bash の `read` に渡り、Enter の打鍵がすべて落ちていた
（`6475d76` で修正し、偽フロントエンドの通し検査を足した）。**1回目の GB もこの不具合の
影響を受けていた。** ただし「自作媒体では (0,0,1) を読み続ける」ことは、Enter 込みの
診断走（追補1 §1）で別に確かめてあるので、追補1の結論は変わらない。
結果は `~/_claude_work/m6fc-run2-2026-09-24/`（リポジトリ外）。

### 1.2 本測定3回目（ディスクBASIC にならない）

器具 `6475d76`、G1 は除外2件で rc=0。`--boot-fill 0xC0`。結果は
`~/_claude_work/m6fc-run3-2026-09-24/`（リポジトリ外）。

- GB-FF・GB-00 の4走とも `ZQbt` が出た（打鍵と起動は直った）。
- **SW の 512 走はすべて目印なし**（`ok`・`ng`・`er` のどれも出ない）。刺激の後の READ DATA・
  WRITE DATA は全走で0件。総合判定は `m6f_c_no_free_mark` と出たが、**これは空きの印の
  結論ではない**（プログラムがディスクに触れていない）。

事前登録外の診断（1走ずつ、`B(0xFF,0xFF)`＋起動用セクタ 0xC0）:

| 打鍵 | 目印 | 刺激の後のサブCPU の入出力 |
|---|---|---|
| 短いプログラム、`on error goto` | 出た | — |
| `open "zz" for output as #1:close #1` の後に目印 | 出た | なし |
| `open … :print #1,"x":close #1` の後に目印 | 出ない | なし |

サブCPU（FDC 側）の入出力の記録は、自作媒体ではフレーム 36 で途切れ、`OPEN`・`CLOSE` の間も
一切なかった。**解釈（決定ではない）:** 起動用セクタを「戻り」で抜けると、ROM は
ディスクを使わない BASIC として立ち上がり、ファイルの入出力がディスクへ向かっていない。
ディスクBASIC として起動させる起動用セクタの中身を探すことは、ROM の内部の入口を探す
ことに近づくので、本稿ではそれをしない。

### 1.3 ドライブ2の構成の確認（診断）

- ドライブ1に参照 diskA の使い捨て複製、ドライブ2に自作 `B(0xFF,0xFF)`（起動用セクタは
  詰め物のまま）を入れて起動し、`open "2:qz" for output …` を走らせると、サブCPU が動き、
  90 行の誤り処理の目印が出た。**ディスクBASIC として動く。** どちらの像も変わらなかった。
- ドライブ1・2に参照 diskA の複製を入れ、`save"2:qz7x"` をすると、**ドライブ2の像だけが
  書き戻され、ドライブ1は変わらなかった。** 刺激の後の READ DATA・WRITE DATA の装置番号
  （第1パラメータの下位2ビット）はすべて 1、起動時の READ DATA はすべて 0 だった。

## 2. 変更（事前登録 §2〜§6 への差分）

本来の問い（公式ROM が自作の空媒体を**データディスクとして**受け入れるか）に戻すため、
**自作の媒体から起動することをやめ、ドライブ2で測る。**

1. **全腕で、ドライブ1に参照 diskA の使い捨て複製**（`PC88_REF_DISK_DIR` の `N88_FE.D88`。
   **書き込み保護は解除しない**）を入れて起動する。**ドライブ2に生成器の媒体 `B(V, F)`** を
   入れる。起動用セクタの規則（追補1の `--boot-fill`）は使わない（生成器の既定のまま）。
2. **打鍵のファイル名に `2:` を付ける。** `f$="2:"+chr$(81)+…`、`open "2:…"`、`save"2:q7l"`、
   `load"2:q7l"`、`files 2`、A5・A5b の名前は `"2:"+chr$(81)+right$(…)`。その他の打鍵は
   事前登録と同じ。打鍵数は 512 以内であることを照合器で確かめる。
3. **書いたセクタ・読んだセクタ**（事前登録 §5 の用語、C10 を含む）は、装置番号が 1 の
   FDC コマンドだけを数える。**測定後の媒体**はドライブ2の像を指す。
4. **GB** は同じ構成（ドライブ1で起動、ドライブ2に `B(0xFF,0xFF)`／`B(0x00,0x00)`）で
   `ZQbt` を見て F\* を決める（規則は事前登録 §4.1 のまま）。
5. **関門の追加 G8**: 各走の後、ドライブ1の複製の SHA-256 が複製直後と同じであること
   （参照 diskA は読むだけで、書き換えない）。変わっていたら `gate_failed`。
6. **G4 陰性対照（A0）** は、装置番号 1 への WRITE DATA が0件、ドライブ2の像が生成直後と同じ、
   目印なし、を要求する。

導出規則（事前登録 §5・§5.1）・判定名（§7）・行き先（§8）は変えない。

## 3. この構成で決まらないこと

- 自作の媒体から**起動**できるか（起動用セクタに何が要るか）。本稿の問いから外す。
- ドライブ1とドライブ2で ROM の扱いが違う可能性。ドライブ2で得た規則をドライブ1の媒体へ
  当てはめてよいかは、別に確かめる。
