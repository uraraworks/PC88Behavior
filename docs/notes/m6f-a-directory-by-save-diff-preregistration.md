# m6f-a — 公式ディスク形式のディレクトリを、自分の SAVE が変えたバイトから測る — 事前登録

記録日: 2026-09-24  
状態: 測定前

## 0. 位置づけと方針の決定

ゴールA の達成判定（`docs/PLAN.md` 1節）には「ファイル入出力が公式ROM上と同じ出力を
返す」が含まれるが、2026-09-16 の判定は**ファイル入出力を対象外**にしていた。
m6i-i までで自作 main から任意座標のセクタを読めるようになったので、次は BASIC の
`FILES` をディスク上のディレクトリにつなぐ。**それにはディスク上のディレクトリの形式が
要るが、仕様書は確定していない**（これまでの FILES 測定はデータポートの値を見ずに行い、
「ディレクトリ領域の大きさ・エントリ長を逆算しない」と明記してきた）。

2026-09-24、利用者の判断により、**自作ROM は公式のディスク形式を扱う**（既存の
N88-BASIC ディスクが読めること）とし、**その形式は第三者の解析を読まず、自分で測る**
と決めた。本稿はその最初の測定である。

## 1. 境界 — 何を見て、何を見ないか

媒体形式は、公式ROM に自分の入力を与えたときに**媒体へ現れる外部から観測できる副作用**
であり、`docs/PLAN.md` 5節の「採ってよい」（外部から観測できる副作用）に当たる。
ただし公式ディスクの複製を使う以上、**公式ディスクの既存の中身**（既存ファイルの名前・
本体）に触れる危険がある。これを次の規則で機械的に断つ。

1. **使う媒体は、参照 diskA（`$PC88_REF_DISK_DIR/N88_FE.D88`）から走ごとに一時領域へ
   作る使い捨て複製だけ。** 複製はリポジトリ外に置き、走が終われば消す
   （m7cw と同じ扱い）。
2. **観測は、走の前後の D88 像の差分だけ。** 変わっていないバイトは比較のために
   読むが、**1バイトも出力しない**。
3. 変わったバイトについて出力してよいもの:
   - 位置（C, H, R, セクタ内オフセット）
   - **新しい値**（自分の刺激に対する公式ROM の応答であり、自分が与えた名前と
     自分が書いたプログラムと、ROM が計算した割り当て番号等からなる）
   - **古い値は、連続して変わった区間の古い値がすべて同じ1値である場合に限り**
     その値だけを出力する（空き領域の詰め物＝形式の定数とみなせる）。
     **1つでも違う値が混じる区間の古い値は出力しない**（「非一様のため伏せた」とだけ
     記録する）。既存ファイルの上書き等で公式の中身を指してしまう場合は、ここで
     自動的に伏せられる
4. **公式ROM の画面本文は読まない**（禁止事項7）。到達の判定は I/O ログ（WRITE DATA の
   件数）と差分の有無で行う。
5. 仕様書・ノートへは**規則**（どのトラック・セクタか、エントリ長、名前欄の位置と長さ、
   空き・削除の印）として書き、**差分の生出力はコミットしない**（`~/_claude_work/` に置く）。
   規則に現れる個々の定数（例: 空きの印の値）は、これまで仕様書にプロトコル定数
   （`0x02`・`0xC0` 等）を書いてきたのと同じ扱いとする。

## 2. 問い

- **主問**: 公式形式のディスクで、ディレクトリはどのセクタにあり、1エントリは何バイトで、
  名前はエントリのどこに何文字分入るか。
- **副問**: 名前の詰め物、削除したエントリの印、未使用エントリの表現、割り当て表の所在と
  空きの印。

## 3. 刺激（腕）

すべて自分で書いたプログラムと、自分で決めた固有名だけを使う。プログラムは既定で
`10 END` の1行。名前は既存ファイルと衝突しにくい固有名にする（衝突しても §1-3 で
古い値は伏せられる）。

| 腕 | 刺激 | 狙い |
|---|---|---|
| F0 | 起動して待つだけ（SAVE しない） | **陰性対照**。差分が空であること |
| F1 | `SAVE"QZ7A"` | 基準のエントリ |
| F2 | `SAVE"QZ7B"` | **名前の4文字目だけを変える** |
| F3 | `SAVE"QZ7ABC"` | 名前を6文字に伸ばす（名前欄の長さ） |
| F4 | `SAVE"QZ7A"` の後に `SAVE"QZ7B"`（1走で2件） | エントリの間隔 |
| F5 | `SAVE"QZ7A"` の後に `KILL"QZ7A"` | 削除の印 |
| F6 | 100行の `REM` プログラムを `SAVE"QZ7A"` | 割り当て表（複数単位を使わせる） |

各腕2走。各走は新しい使い捨て複製から始める。

## 4. 導出規則（測定前に固定する）

発見を後から都合よく読まないため、**何をどう導出するかを先に決める。**

- **D1 ディレクトリのセクタ**: F1・F2・F3 のすべてで変わったセクタのうち、
  **F1 と F2 の新しい値の違いが1バイトだけ**のセクタ。ちょうど1つに決まれば
  それをディレクトリのセクタとする。
- **D2 名前欄の位置**: D1 のセクタの、F1 の新しい値の中で、`QZ7A` の ASCII
  （`51 5A 37 41`）が連続して現れる位置。ちょうど1か所に決まれば、名前は ASCII で
  そこから格納されるとする。F2 との違いの1バイトがこの4文字目に当たることも要求する。
- **D3 エントリ長**: F4 の2件の名前の開始位置の差（セクタを跨ぐ場合は同じトラックの
  R を連続とみなした通し位置で数える）。
- **D4 名前の詰め物と名前欄の長さ**（副問）: F1 の名前の直後から、F3 の6文字目までの位置の
  F1 の新しい値。一様なら詰め物の値とする。
- **D5 削除の印**（副問）: F5 で、F1 のエントリのうち変わったバイトの位置と新しい値。
- **D6 未使用エントリの表現**（副問）: F1 のエントリ全体の古い値が §1-3 で一様と判定された
  場合の、その値。
- **D7 割り当て表**（副問）: F1 と F6 の両方で変わり、D1 でも、プログラム本体を含むセクタでも
  ないセクタ。F6 で変わるバイト数が F1 より多いことを要求する。

## 5. 関門

いずれかが偽なら腕へ進まず `gate_failed`。

- **G1** `tools/run_all_selftests.sh` が rc=0。
- **G2** `tools/check_cleanroom.sh` が rc=0 かつ NG 0件。
- **G3 差分器の自己検査**: 合成した2つの D88 像で、(a) 変わっていないバイトを1つも出力
  しないこと、(b) 古い値が一様な区間ではその値を出し、非一様な区間では伏せること、
  (c) 新しい値と位置が正しいこと、を確かめる。**非一様な古い値を出してしまう変異**で
  検査が落ちることを示す（§1-3 の境界そのものの検出力）。
- **G4 陰性対照 F0**: SAVE しない走で差分が空であること。**空でなければ、起動や時間経過
  だけで媒体が書き換わっている**ので、以後の差分を刺激の応答と読めない。
- **G5 複製の独立性**: 各走の開始時の複製の SHA-256 が参照 diskA と一致すること。
  （前の走の書き込みを持ち越していないこと。）
- **G6 生出力を置かない**: 差分の生出力の書き出し先がリポジトリの外であることを器具が
  確かめ、リポジトリ内なら起動前に止める。
- **G7 凍結**: 腕・プログラム・名前・導出規則・判定名を測定前に設定ファイルへ固定する。

## 6. 判定名

- `gate_failed` / `unreached`（SAVE の WRITE DATA が0件、または差分が空）
- 各導出: `derived`（ちょうど1つに決まった）/ `ambiguous`（候補が2つ以上）/
  `not_found`（候補0）。**「一意に定まらない」を1つにまとめない**（0件と多数は意味が
  逆である）。
- 総合:
  - `m6f_a_directory_located`: D1・D2・D3 がすべて `derived`、2走一致。
  - `m6f_a_directory_ambiguous`: D1〜D3 のどれかが `ambiguous` または `not_found`。
  - `m6f_a_inconclusive`: 関門は通ったが1腕以上 `unreached`。

副問 D4〜D7 は個別に記録し、総合判定に入れない。

## 7. 行き先

- `m6f_a_directory_located`: 次稿 m6f-b で、**導出した規則から空の公式形式ディスクを自作の
  生成器で作り**、公式ROM がそれに `SAVE`・`FILES`・`LOAD` を行えるかを確かめる。
  公式ROM が自作生成のディスクを受け入れれば、規則は足りている。**以後の測定は自作生成の
  ディスクで行い、公式ディスクは使わない**（画面にも自分のファイル名しか出ない）。
  D7 が導出できていなければ、空の割り当て表を作れないので、m6f-b の前に割り当て表の
  測定を足す。
- `m6f_a_directory_ambiguous`: 候補の分布（0件か多数か）を記録し、刺激を足す追補を置く。
- `m6f_a_inconclusive`: 到達（打鍵・期限）だけを直す追補を置く。

## 7.1 この測定で決まらないこと

- 公式ROM がディレクトリを**どう探すか**（読む順序、キャッシュ）は決まらない。
- 名前以外のエントリ内の欄（開始位置・属性・大きさ等）の意味は、本稿では位置と値を
  記録するだけで、意味は決めない。
- プログラム本体の保存形式（LOAD/SAVE の互換に要る）は決まらない。
- 別の形式の媒体（2HD 等）へは一般化しない。
