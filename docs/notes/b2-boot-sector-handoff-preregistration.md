# B2: 起動用セクタの受け渡し — 事前登録

記録日: 2026-10-24
位置づけ: [goal-b-policy-addendum1-boot-sector-2026-10-24.md](goal-b-policy-addendum1-boot-sector-2026-10-24.md)
第3・4・6節（順序の2〜3）。
**このノートは公式 ROM での測定より先にコミットする。** 以降の集計・判定はここに書いた規則に従い、
結果を見てから規則を変えない（変えるときは後続ノートで理由を残す）。
このノートより前の日付で、起動用セクタの受け渡しを公式 ROM で測ったコミットは存在しない。

## 1. 目的

公式 ROM が起動用セクタ (0,0,1) を **RAM のどこへ読み込み、どんな状態で制御を渡し、戻ったらどこへ行くか**を、
自作のセクタのコードで測る。追補1第3節の5項目をそのまま測り、第4節の禁止（自作コードから ROM 領域・
スタックの2バイト目より奥・レジスタの指す先を読まない）を構造で守る。

## 2. 刺激と器具（段階1で作り、自己検査済み）

| 器具 | 役割 |
|---|---|
| `tools/b2_make_boot_probe.py` | (0,0,1) に置く自作の Z80 コードと媒体を作る。組み立て時に第4節の禁止を検査して通らなければファイルを出さない |
| `tools/b2_extract_boot_probe.py` | 書き込み記録 (`--mem-write-log`) から控えを白リストで復元する |
| `tools/harness/b2_boot_probe_selftest.sh` | 上の2つを、公式 ROM を使わず自作の試験 ROM で検査する（陰性対照・故障注入つき、run_all に登録） |
| `q88measure --boundary-log` (0016) | 戻った後の RAM→ROM の飛び先（番地と回数だけ） |
| `tools/redact_iolog.py` | 入出力ログの値を伏せる（止めた腕のポート列） |

コードは入った直後に AF・BC・DE・HL・IX・IY・SP・I・割り込みの許可状態（`LD A,I` の P/V）を控え、
`CALL`→`POP` で自分の番地を知り、スタックの先頭2バイトだけを読み、自分のセクタの中の
`B2P1` 見出しの領域に書く。自分の領域の続き（番地+256×k、k=1..8 の先頭4バイトだけ）に自作の目印が
現れるかを調べ、**一致したビット（コピーでなく比較結果）**だけを書く。
腕により最後に `RET`（レジスタ・SP を入口の状態へ戻してから）／`HALT` で止まる／`DI`+`HALT` で止まる。

### 2.1 番地の扱い（段階1で分かった制約。判断を仰ぐ点でもある）

Z80 には番地を相対で得る命令が無く、`CALL` のオペランドは絶対番地になる。**コードは読み込み先 X を
仮定して組む**（`--load-addr`）。実際の読み込み先が違えば `CALL` は別の所へ飛び、控えは現れない
（抽出器は `no_record` を返し、控えを捏造しない: 自己検査 N1）。したがって読み込み先は次の段階0で
**番地だけを使って**先に知る。控えの「自分の番地」は `CALL` のオペランド由来なので、
**真の番地の独立な出所は書き込み記録の発行元 PC**であり、抽出器が三者（発行元 PC から逆算・控えの自己申告・
控えの置き場）を照合する。

## 3. 条件

| 項目 | 値 |
|---|---|
| ROM | 公式 ROM（`PC88_REF_ROM_DIR`）。ドライブ1に自作媒体（l3-disk-format 第4節の規則、(0,0,1) と目印セクタだけ追加） |
| 打鍵 | なし（`--type` 系・`--key-matrix` を一切付けない） |
| 走の長さ | `--frames 1200`。フレーム数で区切る（実時間の時間切れは無い） |
| 記録 | 同一の走で `--mem-write-log`（範囲 `0000-FFFF`）・`--boundary-log`・`--io-log`（止めた腕のみ）を併用 |
| 反復 | 腕ごとに2走（同一条件の反復で再現性を見る） |
| 実行 | `env -u PC88_REF_DISK_DIR -u PC88_REF_DISKB -u PC88_GAME_DIR nice -n 10 …`。生の出力は作業場 `PC88/tmp/b2-boot-work/` にだけ置く |
| 取りこぼし | `取りこぼし: 0件` でない走は使わない（抽出器が拒否する）。出たら範囲を二分して別走（同条件2走ずつ）にする |

公式 ROM を触るのは q88measure だけ。ROM のバイト列・公式ディスクは読まない・開かない。

## 4. 腕

媒体は共通の規則（割り当て表 0xFF・74/75 は 0xA0・(18,1,13) は 0x00・他 0xFF）に、(0,0,1) と目印セクタを足したもの。
目印は4バイト `B 2 M <タグ>`（タグ = `1`〜`8`）＋残り 0xFF、1セクタに1個。

| 腕 | (0,0,1) | 目印セクタの置き方 | 目的 |
|---|---|---|---|
| P0 | 全バイト 0xC9（9/24 の掃引の戻り命令。BASIC まで届く） | seq: (0,0,2〜9) にタグ1〜8 | 段階0: 読み込み先 X の番地だけを知る |
| A1 | 控え＋`RET` | seq | 受け渡しの全項目。戻り先・戻った後の飛び先 |
| A2 | 控え＋`HALT`（割り込み許可はそのまま） | seq | 戻らなかったとき ROM の割り込み処理が何をするか |
| A3 | 控え＋`DI`＋`HALT` | seq | A2 の対照（main CPU は以後何もしないはず） |
| A4 | 控え＋`RET` | rev: (0,0,9〜2) にタグ1〜8 | セクタの並びが RAM でどうなるか（順序） |
| A5 | 控え＋`RET` | head1: (0,1,1〜8) にタグ1〜8 | 裏面・次トラックが読まれるか |
| A6 | 控え＋`RET` | none: 目印なし | 目印の検出が古い RAM の内容由来でないことの対照（全マスク 0 のはず） |

各腕2走。P0 は X を決めるために先に回し、A1〜A6 は P0 の結果の X で生成器に `--load-addr` を与えて組む。
**P0 は段階0であり、ここで X が決まらなければ A1〜A6 には進まない（第7節）。**

## 5. 記録の白リスト

コミットするのは次の行**だけ**。実装は `tools/b2_extract_boot_probe.py` と既存の `tools/b1_whitelist_boundary.py`、
`tools/redact_iolog.py`。上に合わない行は内容を表示せず捨て、件数だけを出す。

- 抽出器の出力: `probe:` `base_true/base_reported/consistent` `regs:` `intr:` `ret=` `markers:` の各行
  （自作コードが自作の値として書いた控えだけ）、`rom_pc_writes:` の件数と `rom_range`（**番地の範囲と件数だけ**）、
  `ram_pc_other_writes:` の件数
- 境界の記録: `A <addr> …` 行、`instr` 行（`b1_whitelist_boundary.py` と同じ濾過）
- 入出力ログ: `redact_iolog.py` で値を伏せたもののうち、**main CPU のポート番号・方向・件数**だけ
  （止めた腕。公式ディスク由来のデータポートの値列は載せない。禁止事項5）
- 次は出さない・書かない: 発行元 PC が ROM の書き込みの値（ROM が RAM に書いた値には ROM 内部の
  テーブルやバッファ外の内容が混ざりうる。[汚染の記録](contamination-2026-09-25-fat-buffer-overrun-values.md)）、
  画面本文（禁止事項7）、`--out` の写し、生の `--mem-write-log`
- 抽出器が読み込み先の確認に使う `--near LO-HI` は、窓に重なる ROM 書き込みの範囲を件数の上限なしで先に出す

読み込み先 X が 0x8000 未満の場合、発行元 PC の「RAM 上」の判定（`--ram-pc-lo`、既定 0x8000）が成り立たない。
その場合は**測定を止めて**判断を仰ぐ（第7節）。

## 6. 導出規則（事前に決める）

### D0 読み込み先の確定（P0）
P0 の2走で、`mem_exec_ram`（`--out` のトレースの節 `[main 実行された番地 (fetch, RAM)]` だけを機械的に切り出す。`--out` の他の節は開かない）と ROM 書き込みの範囲を取る。
X の候補 = 「RAM 上で実行された番地を含み、長さ 256 以上の連続した ROM 書き込みの範囲」の中で、**RAM 上で実行された
最初の番地 E**。その範囲の先頭を S とし、`X := S`、入口オフセット `E − S` で生成器に与える
（親の追記: E を読み込み先と同一視しない。入口が先頭でない場合に備える。自己検査の入口0/5/17がこの形を確かめている）。
2走で E または S が一致しなければ `not_found`（第7節）。
確認: X で組んだ A2（HALT 腕）の1走で抽出器が `base_true == X` を返す。返さなければ仮定は誤り。

### D1 読み込み先
`base_true`（A1〜A6 の全走）。同じ値かどうかを走間で比べる。ROM 書き込みの範囲は、`--near` で
`[base_true-0x100, base_true+0x1000)` に重なるものを全て報告する（読み込まれた量の上限の見積り）。

### D2 入口のレジスタ
AF・BC・DE・HL・IX・IY・SP・I・IFF2 を、A1〜A6 の全12走で比べ、フィールドごとに分類する:
**一定**（全12走で同じ）／**腕で変わる**（各腕の2走では同じだが腕の間で違う。媒体の内容に依存しうる
→ 値を採るが「入力依存の可能性」と注記）／**揺れる**（同じ腕の2走で違う → 値は採らず「揺れる」とだけ書く）。
値そのものは受け渡しの観測として記録してよい（追補1第4節）。

### D3 戻り先と戻った後
控えた RET（スタックの先頭2バイト）を D2 と同様に分類する。A1/A4/A5/A6（RET 腕）と A3（DI+HALT、戻らない）の
境界の記録を比べ、**RET 腕にだけ現れる RAM→ROM の飛び先（記録 A の行）**の集合を求める。
予測（結果を見る前に置く）: その集合は控えた RET の値を含む。含まなければ両方を報告する（一致を前提にしない）。

### D4 読み込まれた量
目印マスクを、腕（seq/rev/head1/none）ごとに2走で比べる。`k` 番目が `F` ＝タグ k のセクタが `base+256k` に現れた。
- seq で連続して `F` の最大の k = 連続して読まれたセクタ数の下限（(0,0,1) を含め +1）
- rev: `F` の位置からセクタの置かれ方の順序を決める（昇順か降順か）
- head1: 裏面が読まれたか
- none: 全マスクが 0 でなければ、マスクの意味を疑う（古い RAM の内容を拾っている）。結果を採らない
ROM が RAM へ書いた番地の範囲は D1 の `--near`、ROM 書き込みの総件数と範囲数は `rom_pc_writes:` を報告する。

### D5 戻らなかったとき
A2（割り込み許可あり）と A3（DI 済み）の main CPU の入出力のポート列（番地・方向のみ、`redact_iolog.py` 後）を、
プローブの最終書き込みのフレーム以降について比べる。A3 に行が無く A2 にあれば「割り込み処理が
動いている」とだけ書く。ポート別の件数と並びの周期だけ報告する。A3 にも行がある場合は NMI など別経路を疑い、
そのまま報告して結論を保留する。

### D6 再現性
各腕2走で、抽出器の出力（rom_range・件数まで）が一致するかを報告する。一致しない項目は「揺れる」と注記する。
D2 の分類と合わせて、揺れる項目を結論に使わない。

## 7. 止める条件（結果を見てから緩めない）

- D0 で X が決まらない（E が2走で違う、候補が 0 または 2 以上）: A1〜A6 に進まず結果ノートに「X 不明」を書く。
  **X を決めるために新たな値の総当たりはしない**（追補1第5節）。
- X < 0x8000: 発行元 PC による RAM/ROM の判定が成り立たない。止めて判断を仰ぐ。
- 抽出器が `no_record`（rc=3）／不完全・三者不一致（rc=4）: その走の結論は採らず、そのまま報告する。
  不一致の組合せ（どの三者が食い違ったか）だけ書く。
- 取りこぼしあり: 第3節の手順で範囲を二分して取り直す。それでも出る走は使わない。
- 白リストに合わない出力が混ざる、または `private/`・公式 ROM 由来の値が作業場の外へ出る気配: 即時停止し、
  [CLAUDE.md](../../CLAUDE.md)「汚染したとき」に従う。

## 9. 守る線（再確認）

- 自作コードは自分のセクタ・目印を調べる範囲（`base+256k+0..3`, k=1..8）・スタックの先頭2バイト以外を読まない。
  ROM のバイト列を RAM へ写す・ROM の番地を呼ぶ・レジスタの指す先を読む命令を、コードに入れない
  （生成器の実行器が受け付けない命令は組み立てが止まる）
- 戻った後に ROM のどこへ進んだかは、境界の記録の番地だけから取る。内部の実行経路は取らない
- 新たな値の総当たりの掃引はしない（9/24 の掃引結果は、P0 の 0xC9 の根拠としてだけ使う）
- ゲームのディスクは使わない。この測定は自作媒体だけで閉じる

## 10. 段階1の自己検査（2026-10-24 時点）

`tools/harness/b2_boot_probe_selftest.sh`（公式 ROM・公式ディスク不使用、run_all 登録済み）:
正常3走（ret/halt/dihalt × X=C000・B123・9A00 × 入口 0・5・17 × EI/DI）が全判定合格、陰性対照（別番地へ置くと no_record）、
故障注入3種（自分の番地の申告をずらす→J_base だけ FAIL／BC・DE の順序入れ替え→J_regs だけ FAIL／ROM の書き込みを
抽出器に通す→J_whitelist と J_regs が FAIL）、組み立て時の検査の故障注入2種（範囲外読み出し・戻り先の奥の読み出し）が rc=4 で止まる。
