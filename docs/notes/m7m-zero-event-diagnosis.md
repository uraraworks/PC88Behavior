# m7m: 混成適合テストの対象0件診断

測定日: 2026-08-13

## 1. 情報境界と目的

`tools/conform_l3.sh` の混成実行で、公式mainがバルク応答を受け取る対象イベントを
1件も抽出できない原因を、観測系、ビルド差、起動条件、実装の順で切り分けた。
`private/` は直下の名前だけを確認し、参照先を環境変数で測定プロセスへ渡した。
公式ROM、公式ディスク、通信値のバイト列は読まず、表示せず、保存していない。
全実行は自前タイムアウトで監視し、打ち切りは無かった。

## 2. 切り分け

### 観測系

混成ログを新規取得し、値を伏せてからCPU、方向、ポートだけを集計した。mainのINは
多数記録され、単発応答用ポート、ハンドシェイク、周辺I/Oもポート別に分類できた。
公式基準ログでは同じ表記でバルク用INを抽出でき、混成側だけが0件だった。したがって
CPU名、方向、ポートの桁数、ログ書式の不一致ではない。診断器selftest a〜lは、同一、
意図的な値差、構造差、対象0件をすべて所期どおり判別した。0件拒否も実際に働いた。

### ビルド差

混成版は `src/l3_service/make_subrom.py` を追加オプション無しで実行する通常版である。
m7jは同生成器相当の一時コピーで単発送信経路だけを差し替え、m7lは第29版後の同じ
アセンブラAPIへ先頭応答の位置カウンタと候補介入を加えた一時ROMだった。したがって
同じ生成器・同じオプションではない。m7j/m7lの4件一致はmainの単発応答用IN列の値一致で、
conformの対象はその後のバルク用IN列である。一時介入構成へconformを合わせても未確定の
バルク遷移を実装したことにはならず、到達実績のある構成として代用できない。

### 起動条件

conformと専用診断は共通関数で混成ROMを組み、同じ公式ディスク、diskA起動、1800
フレームで実走した。両者とも0件と同じ構造分岐を再現した。m7j/m7lの候補側は短い
観測窓、公式対照は長い観測窓だったが、4件一致の対象自体が単発応答用INであるため、
フレーム差はconformのバルク用INが0件になる説明ではない。

### 実装

原因分類は実装である。ただしsubは停止しておらず、無応答デッドロックでもない。
混成側ではmain、subとも測定終了までI/Oを継続した。mainの構造列は畳み込み後258件まで
公式と一致し259件目で分岐、subは172件まで一致し173件目で分岐した。通常生成器は
固定長要求後にデータを準備して単発応答を返し、続く要求を認識した場合にだけ
`RESP_ACTIVE`を立てて多バイト送信する。しかし構造分岐はその多バイト送信系列より前で、
公式mainはバルク受信サイトへ入らない。混成側で単発応答用INは発生するが、バルク用IN
だけが0件であることもこの状態遷移と一致する。

## 3. 対処と現在の到達点

観測条件と期待値は変更していない。通常版を一時介入ROMへ差し替えることもしていない。
未確定なのは、構造分岐後に公式mainを次の要求とバルク受信へ進める外部応答規則であり、
既知の単発値を追加するだけでは構造一致長が伸びないことはm7l/m7mで再現済みである。
推測で状態遷移を足すことはクリーンルーム実装にならないため、今回は停止位置の確定まで
とした。混成照合は対象0件、すなわち値一致は1件目より前のままである。

## 4. 検証3種と残件

- `tools/conform_l3.sh`: 終了コード1。公式一式の本番は件数・ハッシュとも一致。
  混成はバルク用INが0件で不適合。比較器と混成差し替えのselftestは合格した。
- `tools/verify_l3.sh`: 終了コード1。交換境界などの回帰は合格し、別件の既知未達成で
  あるディスク無し時のsub I/Oを検出した。
- `tools/run_all_selftests.sh`: 終了コード1。`conform_l3.sh` の未宣言失敗を受けて総合NG。
  `verify_l3.sh` の既知終了コードは集約上の想定内である。

残る不適合は、構造分岐後の要求・応答規則、交換#4以降の多バイト応答、バルク受信0件、
ディスク無しでもsubがI/Oを発行する点である。同一ROM版、同一媒体、同一エミュレータの
測定に限り、別媒体、別ROM版、実機は横断していない。
