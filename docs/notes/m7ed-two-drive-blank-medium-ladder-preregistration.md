# m7ed: 二ドライブ自作空媒体ラダーの事前登録

実施日: 未実施（本稿は事前登録のみ）

本稿は`m7eb`のN=0校正が自作データディスク単体装着による起動不成立で打ち切られた
`m7ec`の診断を受け、起動用媒体とラダー対象媒体を別ドライブへ分けて再登録する。
測定と器材実装はまだ行わない。`m7dv`、`m7dy`、`m7ea`、`m7eb`の整数完全一致規則と
情報境界を引き継ぎ、実測後に条件、上限、名前、比較対象を変更しない。`src/`は変更しない。

## 仮説と識別境界

- **H-P（同一管理範囲内の定常費用）**: 各媒体系列内で、追加した自作ファイルが同じ
  管理範囲へ収まる間、固定不存在OPENのmain `IN $FC`件数、READ単位、FDCコマンド
  種別列は同じで、隣接差分は0になる。非0の一定差分が反復しても新しい境界とはしない。
- **H-X（管理範囲拡張）**: あるNで新しい管理読出し範囲へ跨ぐと、main `IN $FC`または
  READ単位が正方向へ跳ね、公開FDC列にREAD、場合によってはSEEK等の追加が現れる。
- **H-M（媒体不変）**: 二系列で得た確認済みジャンプの間隔Pと増分ベクトルVは媒体に
  よらず同じである。
- **H-M'（媒体依存）**: 二系列で得た確認済みジャンプの間隔Pまたは増分ベクトルVの
  少なくとも一方が媒体によって変わる。

H-MとH-M'のどちらも実測前に残し、整数の完全一致だけで判定する。絶対ジャンプ位置は
初期占有に依存し得るため媒体間比較へ使わない。管理形式、管理単位、エントリ数、容量を
公開仕様から仮定しない。

## 二ドライブ構成と二つの媒体系列

全runで**ドライブ1を公式システムディスク（起動用、固定）**、**ドライブ2をラダー対象**
とする。ドライブ1は読出し専用の固定起動媒体とし、準備runでも測定runでも変更しない。
ドライブ2について次の二系列を別々にN=0から構築する。

1. **系列O（公式媒体対照）**: 公式diskAの独立した使い捨て複製をドライブ2のN=0媒体と
   する。公開D88ヘッダの保護フラグはこの複製だけで解除し、原本とドライブ1を変更しない。
   `m7ea`系列との橋渡しであり、二ドライブ・明示接頭辞条件の対照でもある。
2. **系列B（自作空媒体）**: `tools/make_n88_blank_disk.py`で公式媒体を入力せず生成した
   自作空媒体をドライブ2のN=0媒体とする。`m7ec`が合格を記録した2回生成SHA-256一致、
   公開D88構造、使用中項目0件、陰性対照2件の自己検査を再実行し、全て通った生成物だけを使う。

両系列で、ドライブ番号、BASICのドライブ接頭辞、名前、作成順、空内容、不存在名、
フレーム数、打鍵時点、観測区間を同じにする。従って系列間で意図的に変えるのはドライブ2の
N=0媒体だけである。公式媒体の既存名・内容は一覧化せず、判定にも使わない。

## BASICのドライブ指定と固定介入の変更

N88-BASICのディスクファイル名書式`<ドライブ番号>:<ファイル名>`に従い、ファイル名の
ドライブ指定を**数値ドライブ接頭辞**へ固定する。ドライブ2の自作名`QDAA`は
`"2:QDAA"`、固定不存在名は`"2:QZ9X"`と書く。番号と物理ドライブの対応根拠は既存の
二ドライブ実測`m7ci`、`m7cj`で、`FILES "B:"`は構文不受理かつ入口後FDC 0件だった一方、
`FILES 1`がA-unit、`FILES 2`がB-unitへ到達したことである。検証用の一覧操作も`FILES 2`
へ固定し、文字ドライブ名形式へ実測後に変更しない。

`m7dv`のファイル指定は接頭辞なしの`"QDAA"`であり、本稿は`"2:QDAA"`へ変えるため、
**同じ固定介入ではない。** さらに対象媒体をドライブ1からドライブ2へ移す。従って系列Oの
絶対値`X_(O,N)`が`m7ea`の絶対値へ一致する保証はなく、一致を期待値へ固定しない。
`m7ea`と系列Oの橋渡しで比較するのは、確認済みジャンプの全隣接間隔と全増分ベクトルだけ
であり、絶対値と絶対ジャンプ位置は比較しない。

## 器材の前提条件

現行`tools/harness/frontend/q88measure`は`--disk`を1本だけ受け取るため、本稿の実行前に
2本目を渡す機能が必要である。コア側では
`vendor/quasi88-libretro/src/LIBRETRO/disks.c`の`retro_disks_ready()`が渡された1本目を
`DRIVE_1`、2本目を`DRIVE_2`へ挿入し、
`vendor/quasi88-libretro/src/LIBRETRO/libretro.c`の`retro_load_game_special()`が複数
イメージを受け取る。器材はこの順序を使い、少なくとも次を全て満たした後だけ採用する。

1. 1本目と2本目を順序付きでコアへ渡し、欠落、重複、順序交換を器材エラーにする。
2. 公式媒体を使わないローダー自己検査として、SHA-256の異なる自作D88を2本渡し、
   `quasi88_disk_insert`呼出しの公開引数を捕捉して、1本目が`DRIVE_1`、2本目が
   `DRIVE_2`へ各1回入ることを完全一致で確認する。順序交換と2本目欠落を陰性対照にし、
   同じ検査が不合格になることを要求する。
3. 統合陽性対照では、ドライブ1から起動後、ドライブ2の自作空媒体の使い捨て複製へ
   `OPEN "2:QZ8V" FOR OUTPUT AS #1:CLOSE #1`を行う。固有マーカー、直後`Ok`、B-unitの
   WRITE DATA 1件以上、ドライブ2の媒体SHA-256変化、ドライブ1のSHA-256不変、取りこぼし
   0件を全て要求する。判定対象の名と変更媒体は自作物だけとし、公式媒体の既存名・内容を
   使わない。
4. 同じ統合操作で2本目を欠いた陰性対照は、固有マーカーへ到達せず、ドライブ1の
   SHA-256が不変であることを要求する。陽性・陰性のどちらかが外れればラダーを開始しない。
5. 従来の1本指定を使う既存器材検査が不変であることを確認し、二本指定の追加によって
   既存runのディスク順序を変えない。

前提条件の検査は器材適格性の判定であり、ラダーのN=0へ数えない。器材実装時に条件を
弱めたり、パス順の表示だけで実装先ドライブの確認を代用したりしない。

## N=0校正と自作ファイルの固定規則

両系列のN=0で、次の固定プログラムを使ってドライブ2の自作不存在名をINPUT OPENする。

```basic
10 ON ERROR GOTO 100
20 OPEN "2:QZ9X" FOR INPUT AS #1
30 PRINT "D9N":END
100 IF ERL<>20 THEN PRINT "D9N":END
110 PRINT "D9E"
120 RESUME 130
130 PRINT "D9C":END
RUN
```

`D9E`、`D9C`、直後`Ok`、`D9N`なし、入口I/O非0、WRITE 0、main/sub取りこぼし0件を
全て要求する。系列Bでは、これにより`m7ec`で未検査だったN88-BASICから見た不存在OPENを
初めて校正する。どちらかの系列が不成立でも他方へ結果を移さず、当該系列を実測前不成立と
して記録する。媒体間比較は二系列とも成立した場合だけ開始する。

N=1〜128の自作名は`m7eb`から次の式を引き継ぐ。

```text
名前(N) = "QD" + CHR$(65 + INT((N-1)/26)) + CHR$(65 + ((N-1) MOD 26))
```

N=1は`QDAA`、N=128は`QDEX`である。実際のファイル指定は名前へ`2:`を前置し、各準備
runでN-1チェックポイントの新しい複製へ`OPEN "2:<名前(N)>" FOR OUTPUT AS #1`して
直ちに`CLOSE #1`する。内容は書かず1runで1本だけを作る。KILL、上書き、順序変更、
名前変更、接頭辞変更は行わない。

## 測定操作と観測量

各Nの完成チェックポイントの新しい使い捨て複製をドライブ2へ入れ、N=0校正と同じ固定
不存在OPENを各系列・各Nで2run測る。全条件を9000フレーム、300Fで改行、700Fで固定
プログラム打鍵、300秒、512打鍵上限、同じROM構成とハーネス引数へ固定する。判定区間は
700F以後である。単一走は採用しない。

各測定runは固定プログラムと`RUN`の画面反映、`D9E`、`D9C`、直後`Ok`、`D9N`なし、
入口I/O非0、WRITE 0、main/sub取りこぼし0件をANDで要求する。OPEN成功、別行エラー、
マーカー欠落、入口I/O 0件、WRITE非0の合成陰性対照を全て不合格にできる判定器だけを使う。

系列`s`を`O`または`B`として一次指標を次の整数対へ固定する。

```text
X_(s,N) = (700F以後のmain IN $FC件数, 700F以後のREAD単位)
```

併記するのはmain `IN $FC`/`IN $FD`の件数・SHA-256、公開FDCコマンド種別列と総件数、
READ DATA・SEEK・WRITE DATA件数、値を除いたイベント構造の件数・SHA-256、隣接N間の
一致prefixと最初の差の位置、画面の行数・文字数・SHA-256、取りこぼし件数である。
SHA-256は同一性確認にだけ使い、大小や近さへ使わない。測定runでWRITE DATAが1件でも
出れば不採用とする。

## 差分とジャンプの固定判定規則

系列ごとに隣接差分を独立に定義する。

```text
Delta_(s,N) = X_(s,N) - X_(s,N-1)    (N=1..128)
```

`Delta_(s,1)`は基準差分であり単独ではジャンプと呼ばない。N=2〜128では`m7dv`規則を
系列ごとにそのまま適用する。

1. 2成分とも直前差分へ完全一致すれば**定常差分**とし、境界へ数えない。
2. 両成分が直前差分以上で、少なくとも一方が厳密に大きければ**正方向ジャンプ候補**とする。
3. 両成分が以下で少なくとも一方が厳密に小さければ**負方向変化**、一方が大きく他方が
   小さければ**方向不一致**とし、H-X支持へ数えない。
4. 過去Nで0件だった公開FDCコマンド名の初出を**未見経路候補**とする。語彙が同じでも
   N-1列をstrict prefixとして後続が増えれば**構造的延長**、prefixを保たず順序が
   変われば**構造変化**として分ける。

候補Nでは当該系列の通常走を止め、直前の8本境界アンカーからN-1/Nを独立再構築して
各2run再測定する。同じ符号、差分ベクトル、FDC構造分類が完全再現した場合だけ確認済み
ジャンプへ採用する。不一致は支持にも反証にも数えず欠測とする。任意の件数幅、割合、
誤差許容、近さは導入しない。

## 周期性の固定判定規則

系列`s`の確認済みジャンプを昇順に`J_(s,1),...,J_(s,k)`、ジャンプベクトルを
`V_(s,i)=Delta_(s,J_(s,i))`、隣接間隔を`P_(s,i)=J_(s,i+1)-J_(s,i)`とする。

1. **k=1:** 単発ジャンプであり周期を算出しない。
2. **k=2:** 唯一の間隔は周期候補だが、反復が無いため周期とは確定しない。
3. **k>=3:** 全隣接間隔が同じ正整数`P_s`へ完全一致し、全ジャンプベクトルが同じ
   `V_s`へ完全一致し、ジャンプ間の成立済みNに別ジャンプ、負方向変化、方向不一致が
   無い場合だけ、当該系列の観測範囲で周期成立とする。
4. 間隔または増分が1回でも違えば、外れ値を除かず**非等間隔／増分不一致**とする。
   都合のよい3点や部分列を選び直さない。
5. FDC追加suffix、未見コマンド、値非表示イベント構造は併記する。同じP・Vでも構造が
   混在すれば、数値周期は成立、経路の同一性は未確定と分ける。

周期成立後の次予測位置まで全介入が成立しても同じVの確認済みジャンプが無ければ、その
位置を通過した時点で周期破れとする。予測位置より前の容量端点、介入不成立、欠測による
打ち切りは周期破れでなく後続周期を**検査不能**とする。

## 媒体間比較とm7eaへの橋渡し

二系列ともk>=3の確認済みジャンプを得た場合に、成立した`P_O`と`P_B`、`V_O`と`V_B`、
または内部不一致の分類を次の規則で比較する。

1. `P_O=P_B`かつ`V_O=V_B`ならH-M支持とする。絶対位置と絶対値は使わない。
2. 両系列で周期が成立しても、`P_O`と`P_B`または`V_O`と`V_B`の少なくとも一方が
   完全一致しなければH-M'支持とする。
3. 一方で周期が成立し、他方はk>=3かつ成立済み範囲内の間隔または増分が内部不一致なら、
   一定P・Vが媒体不変というH-Mは不支持、H-M'支持とする。不一致側に存在しない単一の
   PまたはVを作らない。
4. どちらかがk<3、欠測、容量端点前の打ち切り、または両系列とも単一P・Vを成立させられ
   なければ、媒体間比較は**不成立**とし、H-M、H-M'のどちらにも数えない。
5. 件数幅、割合、誤差許容、「近い」「ほぼ同じ」「同程度」を使わない。外れ値を除かず、
   位置合わせや部分列の選び直しを行わない。

系列Oと`m7ea`の橋渡しは、`m7ea`の固定値`P=16`、`V=(+258,+1)`に対して同じ完全一致
規則を別枠で適用する。一致すれば二ドライブ・接頭辞変更後にも間隔と増分が再現したと記録
する。一致しなければ、媒体が同じ公式diskA複製でもドライブと接頭辞を変えた条件差がある
ため、**ドライブ／接頭辞条件による差の可能性**と**媒体差では説明できない不一致**を分けて
記録する。系列Oを`m7ea`へ寄せて選び直さず、`m7ea`を撤回せず、系列Bとの媒体間比較も
この橋渡し結果へ都合よく寄せない。系列Oがk<3なら一致・不一致ではなく橋渡し検査不能とする。

## 介入成立と全名OPEN検証

各Nは作成run、媒体SHA-256差、`FILES 2`各2run、修正版全名OPEN検証が成立した場合だけ
採用する。`FILES 2`は直後`Ok`、READ非0、WRITE 0、取りこぼし0、2run完全一致、N-1から
画面の行数・文字数・SHA-256のいずれかの変化を要求する。画面本文と公式既存名は記録しない。

全名OPEN検証には`m7ea`で訂正した分割版を使う。ホスト側でN=1〜Kの全自作名へ`2:`を
前置し、最大8名ずつのリテラルINPUT OPENへ分割する。例えば先頭は
`OPEN "2:QDAA" FOR INPUT AS #1:CLOSE #1`とする。全chunkの固有マーカー、WRITE 0、
取りこぼし0件が揃った場合だけK全体を合格とする。動かなかった`CHR$`生成版は使わない。

ブロック末端Kは8,16,...,128とする。各系列・各Kで、対象Kより先に次の対照を取る。

- 陽性対照は、当該系列の受理済みK=8チェックポイントで`"2:QDAA"`〜`"2:QDAH"`の
  全名OPENが合格すること。
- 陰性対照は、そのK=8の使い捨て複製から`"2:QDAA"`をKILLし、固有マーカー、B-unitの
  WRITE非0、ドライブ2の媒体SHA-256差、ドライブ1のSHA-256不変、取りこぼし0件を確認後、
  同じ全名OPENが不合格になること。
- 両対照の成立後だけ対象Kを判定する。対照失敗時は対象Kを走らせず器材不成立とする。

終端が8の倍数の途中なら最後に作成成立したKへ同じ分割版と両対照を適用する。不合格なら
直前の受理済み8本境界からKを1ずつ増やして最初の不合格Kと最後の合格Kを特定する。
最後の合格Kを受理済み終端とし、先を欠測とする。検証対象の削減や一部名による代用はしない。

同一Nの2runは全イベント列、画面、main受信件数・SHA-256、FDCコマンド種別列の完全一致を
必須とする。介入不成立、到達失敗、取りこぼし、2run不一致、独立再構築不一致は欠測とし、
ゼロ差分、ジャンプ、周期破れへ読み替えない。

## 準備、再開、上限、打ち切り

上限は`m7eb`から引き継いで**N=128**とし、実測後に延長しない。128は8の倍数で、
`m7ea`で未到達だったN=59を数値上69本超え、16本間隔なら複数区間を探索できる固定幅で
ある。これは両媒体がN=128まで作成可能という容量仮定ではない。

作業領域は実行者が絶対パスで指定する`PC88_M7ED_WORK_DIR`とし、既定値を焼き込まない。
系列別・8本ごとにドライブ2のチェックポイント、媒体SHA-256、安全集計、完了フラグを外部
manifestへ記録する。ドライブ1、生ログ、画面、媒体複製も外部領域だけに置く。中断後は
系列名、N、両媒体SHA-256を照合し、最後の受理済みアンカーから再開する。

N<128で空ファイル作成が容量／作成上限エラーになった場合、それ自体をジャンプや周期破れへ
数えず、最後に成立したNを当該系列の容量端点として打ち切る。次予測位置より前なら検査不能
とする。一方の端点を他方へ適用せず、欠測を0差や「境界なし」に読み替えない。上限到達後に
名前、媒体、接頭辞、作成順、空内容を変えたり延長したりしない。

## 解釈限界

- 結果は公式システムディスクから起動し、ドライブ2の固定媒体へ数値接頭辞付きの空ファイルを
  固定順で作り、QUASI88上で不存在OPENした条件に限る。他のBASIC、実機、内容ありファイル、
  削除・再利用、異なる順序、別媒体へ一般化しない。
- 系列間でPとVが一致しても、観測管理単位がディレクトリエントリ、セクタ、クラスタ、
  割付表、検索ブロック等のどれかは決まらない。PやVから長さ、バイト数、アドレスを逆算しない。
- 系列Oと`m7ea`の不一致は、ドライブ変更と接頭辞変更をこの計画内で分離していないため、
  どちらの効果か決められない。媒体差へ帰属せず、別介入なしに原因を断定しない。
- 系列BのN=0校正が成立すれば、固定不存在OPENに対する操作上の受理を示すが、N88-BASIC
  ファイルシステム一般の完全な妥当性や全機能適合を証明しない。
- 新しい公式ROM経路を観測しても、自作subへの実装採否は別事前登録へ分ける。

## 情報境界

記録するのはN、件数、差分、位置、frame、clock、SHA-256、画面の行数・文字数・SHA-256、
