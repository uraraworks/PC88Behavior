# m6i-b — 初回要求を許す状態境界の切り分け — 結果

記録日: 2026-09-22

## 1. 位置づけ

本測定は、[事前登録](m6i-b-first-request-timing-preregistration.md)（`7d52319`）に従った。測定器具は `42de236`・`25bcd6b`・`0e48f82`、判定器は `35bf5c7` である。**判定器は測定を走らせる前に固定した。** 腕、判定条件、期待値、判定名は測定後に変更していない。

結果は測定器具が生成した結果 JSON を、固定済みの判定器 `tools/judge_m6ib_first_request.py` に通した出力に基づく。画面本文、受信バイト列、測定ログそのものは本ノートへ転記していない。判定器出力の SHA-256 は `3f741a337ce2dad495c82e6de3d356e32c2d336fad161d7d99ddd77f7c0f71b6`。

全12腕を各2走、計24走を実施した。**いずれの腕も2走が同じ形になった。**

## 3. 腕ごとの結果

いずれも2走で同一。`a`・`b`・`c` は発行直前に完了していた状態を表す。

### B0 — 前置きなし（再現腕）

- 判定: `immediate_failure_reproduced`。
- `a/b/c` = 0/0/0、発行 frame 6、結果種別 timeout、受信0位置、要求 run 0件。
- m6i-a A0 の timeout を再現した。ROM 一式は m6i-a A0 とバイト一致である。

### B1 — 状態を進めず同じ時間だけ待つ（陰性対照）

- 判定: `elapsed_only_rejected`。
- `a/b/c` = 0/0/0、発行 frame 60、結果種別 timeout、受信0位置、要求 run 0件。
- 停止中（frame 0〜59）の sub の CPU 進行、FDC I/O、main→sub SEND はいずれも0件。
- **60フレーム待っただけでは初回要求は成立しない。** 後続腕の成立を「待ち時間が延びたから」で説明する読みは、この腕で否定された。

### B2 — 起動専用送信の消化のみ

- 判定: `b_only_sufficient`。
- `a/b/c` = 0/1/0、発行 frame 60、結果種別 256位置一致、要求 run 1件。
- 発行前の FDC I/O とラウンド#0応答はいずれも0件。

### B3 — FDC 初期化のみ（状態直交化の介入）

- 判定: `a_without_b_insufficient`。
- `a/b/c` = 1/0/0、発行 frame 60、結果種別 timeout、受信0位置、要求 run 0件。
- この腕は状態を直交化するための介入であり、公式起動で `a→b` の順が許されるとは主張しない。

### B4 — 初期化と起動専用送信、ラウンド#0の手前

- 判定: `ab_without_c_sufficient`。
- `a/b/c` = 1/1/0、発行 frame 60、結果種別 256位置一致、要求 run 1件。

### B5 — ラウンド#0まで完了

- 判定: `abc_insufficient`。
- `a/b/c` = 1/1/1、発行 frame 60、結果種別 timeout、受信0位置、**要求 run 0件**。
- 前置きは `b→a→c` の順に各1回完了し、FDC 初期化は7 batch だった。前置き自体は成立している。
- 要求 run が0件であるため、**要求そのものが一度も走っていない**。

### B6 — `b→a→c` 前置きの後に m6i-a の腕を再走

| 枝 | 結果種別 | 要求 run | 備考 |
|---|---|---:|---|
| B6-A0 | 256位置一致 | 1 | |
| B6-A1 | 256位置一致 | 1 | 別セクタ選択で署名が変わる |
| B6-A2 | **未到達** | 1 | `analysis_ok=false`、`other_incomplete`、受信0位置 |
| B6-A4-cont | 256位置一致 | 1 | |
| B6-A4-pair | SHA不一致 | 1 | 故障注入の陽性側 |
| B6-A5 | 256位置一致 | 200 | **成功200/200**、256位置受信200件 |

B6-A2 が2走とも到達指標を満たさないため、副問の `m6ia_arms_reached_after_abc` は記録しない。到達しなかった枝を到達したものとして読み替えない。

## 4. 総合判定

関門 G1〜G9 は全て真だが、B6-A2 が `unreached` である。事前登録の定義に従い、総合判定は **`m6i_b_inconclusive`** とする。

境界判定7種（`m6i_b_startup_consumption_boundary` ほか）は**どれも成立しなかった**。7種はいずれも `abc_sufficient` を共通の要件に含むが、B5 は `abc_insufficient` だったためである。`m6i_b_elapsed_time_only` も `m6i_b_no_registered_boundary` も成立しない。

## 5. 得られたこと

- **陰性対照が効いた。** B1 は timeout であり、「状態ではなく待ち時間だけで初回問題が消える」という説明は否定された。後続腕の成立を経過時間で説明することはできない。
- **初期化だけでは足りない。** B3（`a` のみ）は timeout だった。
- **起動専用送信の消化が効いている形である。** B2（`b` のみ）と B4（`a`+`b`）はいずれも256位置一致で成立した。ただし総合判定は `inconclusive` なので、境界がどこかをここで確定させない。
- **abc 前置きの下で B6-A5 が 200/200 成功した。** m6i-a A5 は 199/200 で初回だけが失敗していたので、対照的な形である。ただしこれは B6 の1枝の観測であり、m6i-a 全体の合格や案A採用を決めるものではない。

## 6. 残った問い

> **後日の訂正（2026-09-22）**: 本節が下で述べる「sub 側の停止ゲートが同一」は誤りである。
> B5 と B6-A0 は sub ROM も異なる。詳細と裏取りは
> [m6i-c 準備 — 本ノート §6 の前提の訂正](m6i-c-arm-difference-correction.md) を見よ。
> §1〜§5 の数値と総合判定は訂正しない。以下の本文は記録として当時のまま残す。

**B5 と B6-A0 が逆の結果を出した。** 両者は sub 側の停止ゲートが同一（どちらも `inject_m6ib_b5`）で、main 側も枝タグの格納が増える以外はほぼ同一である。それにもかかわらず、B5 は要求 run が0件で要求が一度も走らずに timeout し、B6-A0 は要求 run 1件で256位置一致に至った。

**原因は未特定である。** これが器具の不具合なのか、測定した現象なのかを、本測定は決めていない。そして B5 が `abc_insufficient` になったことにより、境界判定7種がどれも成立しなかった。**つまりこの食い違いが総合判定を左右している。**

本測定の条件・結果条件・判定名を事後に変更してこれを解消しない。**別の事前登録（m6i-c）で切り分ける。** 切り分けるべきは、少なくとも次の2つである。

1. B5 と B6-A0 の ROM 差分（枝タグの格納）が要求の成否に効いているか。
2. sub 側の停止ゲートがラウンド#0の後に置かれたとき、main の通常SEND開始を取りこぼすことがあるか。

B6-A2 が到達しなかったことも残る。m6i-a A2 も到達しておらず、同じ形が再現している。

## 7. この測定で決まらないこと

事前登録から引き継ぐ。

- 公式ROM内部の実装、公式の送受信値、実機での絶対時間は決まらない。
- `a`・`b`・`c` を実現する命令列や、ラウンド#0の意味論は決まらない。
- B3 は状態直交化の介入であり、公式起動で `a→b` 順が許されるとは主張しない。
- 別媒体、WRITE、複数セクタREAD、BASIC命令一般に同じ境界を一般化しない。
- 本測定は `docs/spec/l3-subrom.md` 1.65節が未確定として残した「通常READを許してよい最早時点」を確定していない。境界判定が1つも成立していないため、仕様へ新たな規則を起こさない。
