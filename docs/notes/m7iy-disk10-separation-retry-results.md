# m7iy: 窓を`m7gg`と揃えて、何が`disk#10`を特別にしているかを測り直す — 結果

実施日: 2026-09-08

## 位置づけ

[m7ix](m7ix-disk10-separation-retry-preregistration.md)が事前登録した測定の
結果である。事前登録は測定開始前に単独コミット（`8290110`）してあり、本稿では
候補・窓・指標・判定規則を後から動かしていない。`src/`・`tools/`は本稿では
変更していない。

**結論を先に書く: 主判定はX1（エラーが分離軸である）である。**

**`disk#10`の入口区間では、READ DATA 108件が108件ともエラーで終わっている。**
他の測定できた8本は**エラー0件**である。しかも**エラーの内訳は全108件が同一**
——`IC=異常終了 / NO DATA`。

**`disk#10`の「連続READ」は、正常なディレクトリ読み出しではなく、
1本のシリンダ上で9件ずつ12回くり返される、全件失敗の読み出しだった。**

## 判定

- **X1（エラーが分離軸である）**: `disk#10`のエラー件数108が、測定できた
  他8本すべて（いずれも**0**）より大きい → **成立。主判定はX1である。**
- X2は不成立。

**`disk#6`は測定できなかったため、判定の範囲は「測定できたディスクすべてより
大きい」である**（事前登録どおり、「10本すべて」とは書かない）。

## 記述（判定ではない）: 「連続READ」の正体

**言えること:**

- **`disk#10`の入口では、READ DATAが1件も成功していない。** 108件が108件とも
  `NO DATA`で終わる。他8本は**エラー0件**で、READ DATAは5〜7件すべて成功する。
- **相異なるシリンダ数は10本すべて1**である。**`disk#10`は同じ1本のシリンダを
  108回読んでいる。** 読み出しが広い範囲へ散っているのではない。
- **SEEKは`disk#10`だけ12件**（他は5〜7件）で、**run長9のrunの本数と一致する。**
  `m7ik`が確定した「12周期＝要求12本」と整合する。
- したがって**`disk#10`の「連続READ」は、9件ずつ12回くり返される、
  1シリンダ上の全件失敗の読み出しである。**
- **`m7gg`が記録した「READ DATA 108件なのに画面は10行/215文字」という逆転も、
  これで説明がつく**——たくさん読んで少ししか表示しないのではなく、
  **読めていない。**

**言えないこと:**

- **「エラーが連続READの原因である」とは言えない。** 本稿は観察であって介入
  していない。エラーと連続READが同じ場面に同居していることまでが観測である。
- **`disk#10`のどこが読めないのか、なぜ読めないのかは分からない。**
  `m7hf`が記録した`bad allocation table`との関係も、本稿では確かめていない。
- **`disk#6`が測定できない理由は本稿の対象外**（`m7gg`と同じく再現したことだけ
  記録する）。
- 条件O・水準E・A:=`disk#8`固定という1つの使い方しか見ていない。
- 10本という母集団は`m7gg`が選んだものであり、一般性は主張しない。

## これが「9」の追跡に対して持つ意味（慎重に書く）

`docs/spec/l3-subrom.md` 3節（第163版）は、**run長「9」は交換を触る経路では
動かせない**（累計236arm）と記録し、次に有望なのはディスク側だとした。

**本稿は、その「9」が現れる場面が全件失敗の読み出しであることを示した。**
これは`m7hb`が挙げた2説の見え方を変える。

- **H1派生（1トラック分＝トラックあたりセクタ数）**: 読めないトラックを
  **端から端まで走査**しているなら、9はトラック上のセクタ数でありうる。
  **1シリンダ上で9件ずつという観測は、この向きと整合する。**
- **H2（内部固定カウンタ）**: 依然として否定されていない。

**本稿はどちらも主張しない。** 観察のみである。ただし
**「9」を動かす土俵の作り方が具体的になった**——`m7il`が「連続READが現れるのは
`disk#10`だけで比較対象が無い」と書いた壁に対し、**「読めない領域を持つ
ディスクを作れば再現しうる」**という道が見えた（`m7iv`が仮説Eを立てるときに
予想した方向である）。

## 次に何を測れば絞れるか

1. **土俵を作る。** `disk#10`と同じ「全件`NO DATA`」を、**自作ディスクで
   再現できるか**を試す。自作D88のセクタを読めない状態にする手立てが要る
   （`tools/`にD88を作る道具があるかを先に確認する）。**再現できれば、
   セクタ数の違うディスクを作って「9」が変わるかを測れる**——これが
   `m7hb`のH1派生とH2を区別する道になる。
2. **1が難しければ、`disk#10`の中で条件を振る。** 例えばA:とB:を入れ替える、
   打鍵を`FILES 2`以外にする等で、**同じディスクでも「9」が変わる条件が
   あるか**を探す。
3. `m7hf`の`bad allocation table`との関係を、BASIC言語仕様の範囲で確認する
   （`m7hj`が挙げていた方向。**ディスクのバイト列は読まない**）。

スクリプトはリポジトリ外（scratchpad配下）に置き、コミットしない。
