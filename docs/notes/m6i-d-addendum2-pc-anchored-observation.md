器具の不備で不成立とし、その結果は使わない。

## 0. 先に開示すること

**本追補は、第1回の診断で「どの腕でもゲートは最初のポーリングで抜けている」
ことが見えた後に書いている。** 観測方法を、答えが見えた後に選んでいる形である。
これは方法選択が結果に都合よく引っ張られる危険がある。隠さず書く。

引き受け方を3つ決める。

1. **方法の正当化を、見えた答えと独立に述べる。** 後述のとおり、PC で錨づける
   方法は「ゲートを踏んだか」を直接見るものであり、run の長さという代理指標
   より近い。**第1回の診断が無くてもこの方法のほうが良い。** 実際、第1回の
   陰性対照は、診断の前に run 長方式の不成立を示していた。
2. **判定器を、腕を1走も回す前に固定する。** 第1回と同じ規律を守る。
3. **陰性対照を測定の中に残す。** ゲートを持たない B0・B6-A0 でゲート番地の
   I/O が0件であることを要求する。方法が「都合よく」動いていないことを、
   測定自身に示させる。

**そして、第1回の診断値を取り直しの結果として使わない。** 期待の形を本追補に
書かない（第1回が示した形をここで期待値として固定すると、当てはめになる）。

## 1. 到達判定の是正（不備1）

`tools/analyze_m6id.py` の到達判定から、**`sizes_valid(rom_dir)` を外す。**

理由は[第1回の試行](m6i-d-attempt1-instrument-failure.md) §2 のとおり。
エミュレータは実行中に ROM ディレクトリへ `generated.srm` を書き込むので、
「中身がちょうど7ファイル」は走らせた後には必ず偽になる。**走らせると変わる
ものを、走らせた後に検査していた。**

事前登録 §2 の到達指標は

> 腕の ROM 一式が、m6i-b の対応する腕のものとバイト一致する

であり、これは所定7ファイルに対する SHA-256 照合が満たす。`sizes_valid` は
器具が独自に足した条件であって、事前登録に無い。外しても到達指標は弱くならない。

**一般則として**: 到達判定は、**走らせる前に確定するもの**と、**走らせた結果
そのもの**だけで組む。走が書き換えうる対象への検査は、走らせる前に済ませる
（本測定では関門G4 が既にそうしている）。

## 2. 観測をゲート番地に錨づける（不備2）

### 変えること

ゲートの入場・解除を、**run の長さではなく PC で判定する。**

- **ゲート番地**: 腕ごとのゲートラベルのアドレス。
  `src/l3_service/make_subrom.py` の `build()` に `metadata` を渡して得られる
  ラベル表から引く。腕とラベル名の対応は次で固定する。

  | 腕 | ラベル名 |
  |---|---|
  | D-B1 | `M6IB_B1_RESET_GATE` |
  | D-B2 | `M6IB_B2_BEFORE_FDC_GATE` |
  | D-B3 | `M6IB_B3_AFTER_INIT_GATE` |
  | D-B4 | `M6IB_B4_BEFORE_ROUND0_GATE` |
  | D-B5 | `M6IB_B5_AFTER_ROUND0_GATE` |
  | D-B0, D-B6-A0 | **無し**（ゲートを持たない） |

- `gate_entered`: I/O ログに、**PC がゲート番地に等しい sub の I/O が1件以上**ある。
- `gate_released`: **最後の**ゲート番地 I/O より後に、sub の I/O で
  **PC がゲート番地と異なるもの**が1件以上ある。
- `gate_io_count`: ゲート番地での sub I/O の件数。
- `post_gate_io_count`: 最後のゲート番地 I/O より後の、PC が異なる sub I/O の件数。

**ROM は1バイトも変えない。** ラベル表はビルドの副産物であり、ROM の内容では
ない。番地は自作 sub ROM のものであって、公式ROMは関与しない。

### なぜこのほうが良いか（第1回の診断と独立に）

- run の長さは**代理指標**である。「長く同じポートを読んでいる」は、ゲートで
  詰まっていることの必要条件ですらない（ゲートが1回で抜ければ短い）し、
  十分条件でもない（暇な待ちループも長い）。**代理指標が対象を挟まない典型**。
- PC はゲートそのものを指す。**「ゲートを踏んだか」という問いに、ゲートの
  所在で答える。** 閾値も要らない（`gate_run_min_length` を使わなくなる）。
- 第1回で run 長方式が壊れたことは、**診断の前に陰性対照が示していた**。
  方法を替える理由は、答えが見えたことではなく陰性対照が落ちたことである。

### 凍結値の変更

- `gate_run_min_length`（32）は**使わなくなる**ので凍結表から外す。
- 腕とゲートラベル名の対応表（上の6行）を凍結表へ入れる。
- ラベル名が `make_subrom.py` のラベル表に存在しない腕があれば、
  エミュレータ起動前に `gate_failed` で止める（D-B0・D-B6-A0 は
  「ラベルを持たない」ことが正しい状態なので、**持っていたら** `gate_failed`）。

## 3. 関門の差し替え

- **G5（観測の検出力）を差し替える。** 合成入力で次の3つを別々に識別すること。
  (1) ゲート番地の I/O が0件 (2) ゲート番地の I/O があり、その後に別 PC の
  sub I/O がある (3) ゲート番地の I/O があり、その後に別 PC の sub I/O が無い。
  **run の長さに依存する合成入力は作り直す。**
- **G6（陰性対照）を強くする。** ゲートを持たない D-B0・D-B6-A0 で、
  **ゲート番地が定義されないこと**と、**長いスピンの有無にかかわらず
  `gate_entered` が偽になること**を要求する。第1回はここで落ちた。
  引き続き関門ではなく帰属条件として扱い、破れたら
  `m6i_d_observation_unusable` とする。
- **G8（新設・器具の自己汚染検査）**: 到達判定が参照する対象のうち、
  測定の走によって書き換えられうるものが無いことを確認する。具体的には、
  到達判定は「走らせる前に確定した期待SHA-256」と「走の出力である I/O ログ」
  だけを参照し、ROM ディレクトリの**列挙**には依存しない。
  第1回の不備1 を二度と通さないための関門である。

G1〜G4・G7 は変更しない。

## 4. 判定名

腕ごと・陰性対照・総合・副問の判定名は、[追補1](m6i-d-addendum1-unverified-arms.md)
のものをそのまま使う。**1つも変えない。** 変えたのは、`gate_entered` と
`gate_released` を何から算出するかだけである。

`arm_gate_not_entered` の意味は追補2 の下でより強くなる。**ゲート番地を一度も
踏んでいない**という意味になり、「観測が拾えなかった」possibility が縮む。
追補1 が決めた「未検証腕に数える」という扱いは変えない。
