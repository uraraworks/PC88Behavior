# m7z: `$FF`制御語彙を測定ログから仕様化できる根拠と高速バルク入口

測定日: 2026-08-13

## 伏せ字規則の確認

`tools/redact_iolog.py`のモジュール説明、`DEFAULT_TARGET_PORTS`、合成自己検査を
実際に確認した。既定の伏せ字対象はデータ経路の`$FB`/`$FC`/`$FD`だけであり、
`$FF`は明示的に「フェーズコード」として保持する制御ポートである。したがって、
公式ROMを直接読まず、測定フックで得た伏せ字後ログから`OUT $FF`の値を制御
プロトコルの事実として読み、`docs/spec/`へ移す経路は`CLAUDE.md`が定める
情報の流れそのものである。

この判断はデータ経路へ拡張しない。`$FB`/`$FC`/`$FD`の値は公式ディスクの
実データを含み得るため、引き続き伏せ、表示・仕様化・実装定数化しない。

## 測定

公式環境を1800フレーム再測定し、生ログをリポジトリ外で直ちに
`tools/redact_iolog.py --in-place`へ通した。伏せ字後ログのsub側だけを調べると、
交換#14累積12件目の通常RECV完遂（最後の受理解除）の直後に、`$FE`アクセスを
挟まず`OUT $FF`が`81,08,0A,0C,0E`の順で5件連続した。

その直後の定常周期は次の構造だった。

1. `IN $FE`でゼロ到達を待つ。
2. `OUT $FF,09`。
3. `IN $FE`でbit0セット到達を待つ。
4. `OUT $FC`、続けて`OUT $FD`（両値は伏せ字のまま）。
5. `OUT $FF,08`。
6. `IN $FE`でbit0クリア到達を待ち、次周期へ戻る。

入口直後の最初の周期も同じポート・フェーズ順であり、以後の反復と差がない。
データポートの値は解析にも本記録にも使用していない。
