作成: L1 仕様書を起草したセッション（以下「仕様セッション」）

## なぜ担当を分けるのか

**古典的なクリーンルームは「仕様を書く担当」と「実装する担当」を分ける。**
このプロジェクトはこれまで 1 セッションで両方をやってきたが、L1 の実装からは分ける。

理由は汚染ではない。`docs/notes/contamination-2026-08-07.md` に記録した件は
L3 のディスク関係とゴール B に限られ、**L1 は領域が違うので制約にならない**。

分ける理由は、**「仕様書だけで実装できる」という主張を検証するため**である。
仕様セッションは `docs/spec/l1-ipl.md` を書くために測定ログを直接読んでいる。
同じ担当が実装すると、仕様書に書き落とした細部を測定の記憶で補ってしまい、
仕様書の不備が表に出ない。分ければ、足りない箇所は**実装が詰まるという形で露見する**。

これは失うものではなく、得られる検査である。

## 実装セッションが見てよいもの

`CLAUDE.md` の情報の流れどおり、**`docs/spec/` から右側だけ**。

| | |
|---|---|
| 見る | `docs/spec/l1-ipl.md`（付録A で自己完結している）、`CLAUDE.md`、`docs/PLAN.md` |
| 見る | `tools/`（ハーネスと比較器の使い方） |
| **見ない** | `measurements/`（仕様書の左側。付録A があるので不要） |
| **見ない** | `private/`（規律で遮断済み） |

`docs/spec/l1-ipl.md` を読んで実装できなければ、**それは仕様書の不備である。**
測定ログを見に行かず、**何が足りなかったかを記録して仕様セッションに戻す**こと。
それがこの分割の目的なので、遠慮する場面ではない。

## やること

`docs/spec/l1-ipl.md` 第6節の適合条件を満たす N88.ROM を作る。

1. **ROM の作り方**: この環境に Z80 アセンブラが無い。
   `tools/harness/make_test_rom.py` / `make_trap_rom.py` と同じく
   **Python でバイト列を組み立てる**。外部依存ゼロで第三者が再ビルドできる。
   置き場は `src/l1_ipl/`。
2. **走らせ方**: `tools/harness/frontend/q88measure` に `--rom-dir <自作ROMの置き場>`
   と `--io-log <出力>` を渡す。**公式 ROM は要らない**。
3. **比べ方**: `tools/cmp_io.py`。
   既定は OUT 列の比較で、最初に食い違った 1 件を指す。
   ただし第6節の適合条件は 2 段階（初期化 350 件の完全一致 ／ 以降が 7 件周期）
   なので、**比較器にその 2 段階を扱う機能が無ければ足すこと**
   （現状の `cmp_io.py` は列全体を突き合わせる）。
   物差しを直したら、`tools/cmp_io_selftest.sh` に検査を足し、
   **わざと壊して落ちることを確かめてから**使う。
4. **進め方**: 一度に全部書かない。第6節「実装の順序」の P0 → P2 → P3 → P4 → 定常
   の順に足し、そのつど比較して**食い違いが後ろへ動いていくこと**を確認する。
   これが lockstep 差分実行（`docs/PLAN.md` 第6節⑤）の実体になる。

## 注意

- **コミットは分ける。** 実装と、比較器の改修と、記録。
- **行き止まりを消さない。** 失敗した試行を残す（`CLAUDE.md` コミット規律）。
- `tools/check_cleanroom.sh` が全項目 OK であることをコミット前に確認する。
- git は必ず `-C <このリポジトリ>` で打つ。シェルの cwd はすぐ親へずれる。
