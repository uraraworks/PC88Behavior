# m7bg: 6バイトレコードは読み出し要求だった（種別値で限定してはいけない）

作業日: 2026-08-19

## 情報境界

公式ROM一式・公式diskA（使い捨て複製）を**実行して**測定した。読んでいない。
本ノートに書くのは件数・位置・既知定数との一致関係だけである。

## 1. m7bfの実装が発火しなかった理由

m7bfで「6バイトレコードのうち**種別が0x02のもの**を読み出し要求として扱う」
経路を実装したが、一度も発火しなかった。診断ポート`$F9`に「run長6のときの
種別バイト」を出したところ、**届く13件はすべて種別0x01**だった。

種別0x02は「BASIC起動後のREADの直前レコード」を測って得た値である。だが
その測定は**mainがそこまで進んだ後の要求**しか見ていない。バルク直後に来る
要求は種別0x01で、こちらを取りこぼしていた。

## 2. 6バイトレコードは全部「読み出し要求」と読める

既知の9グループ表のうち**6バイトのもの（#5と#9）の応答は、どちらも
`EXCHANGE3_OBSERVED_RESPONSE` と同じ値**である。そして起動後のREADに対する
1バイト応答（m7bfで実測、11/11で同一値）も**同じ値**だった。

つまり「6バイトレコード → セクタを読んで ack を1バイト返す」という**ひとつの
規則**で、起動時の#5/#9も起動後のREADも説明できる。表の#5/#9が単発応答に
見えていたのは、**ackだけを見て読み出しを見落としていた**からである。

判別を種別値から**レコード長6**へ変えた。

## 3. 効果

| | m7bf（種別0x02で限定） | m7bg（長さ6で判別） |
|---|---:|---:|
| READ DATA | 8回 | **11回** |
| FDCコマンド総数 | 187（fallback連発を含む） | **59** |
| 画面（起動直後） | `Syntax error` が出る | **出ない（公式と同じ`Ok`）** |
| SAVE時のエラー | `Bad allocation table` | **`Disk I/O error`** |

fallback（SENSE DRIVE STATUS）の連発が消え、BASICの起動画面が公式と同じ
並びになった。SAVEは走るがディスクI/Oエラーで終わる（公式はREAD 19回、
自作は11回なので、まだ足りない読み出しがある）。

**適合条件1（5635件・SHA-256）は維持**。`verify_l3.sh` 全項目OK、
`conform_l3.sh` rc=0。応答列の一致プレフィックスは6415のまま
（バルク直後の応答はまだ違う）。

## 4. 次の一手

応答列6416件目の食い違いが残っている。いまは6バイトレコードで読み出しを
行うようになったので、**読んだセクタの座標か、返し方（ackのあとの256バイトの
出し方）**のどちらかが違うはず。公式19回に対し自作11回という差も、
そこから追える。

## 5. この節の教訓

**「測って得た値で限定する」ときは、その測定がどの場面を見ていたかを確かめる。**
種別0x02は正しく測れていたが、それは「BASICが起動したあと」の場面だけの値
だった。限定条件を狭く作ったせいで、同じ役割の要求（種別0x01）を取りこぼした。
**役割が同じものは、値ではなく構造（レコード長）で括るほうが安全なことがある。**
