# B102 事前登録：行入力で ESC・TAB・ROLL・HELP・CTRL+英字を押したときの公式 BASIC の扱い

記録日: 2026-11-18。B101 で INKEY$ の値を表に入れたあと、自作は行入力（スクリーンエディタ）で表の 0x20 未満を無視するようにした（36f0701）。この扱いは CI を通すための暫定で、公式の行入力がこれらのキーをどう扱うかは測っていない。特に TAB（09）は無視でよいか分からず、ROLL UP・ROLL DOWN（F8・F9）は 0x20 以上なので自作では文字として入ってしまう可能性がある。

## 方法

公式 ROM で BASIC を起動し、自作のプログラムを打鍵して RUN する。

```
10 LINE INPUT A$
20 P=&HD000:POKE P,LEN(A$)
30 FOR I=1 TO LEN(A$):POKE P+I,ASC(MID$(A$,I,1)):NEXT
40 POKE &HD100,CSRLIN:POKE &HD101,POS(0)
50 GOTO 10
```

各腕で、入力待ちに `A` `B` を打ち、調べるキー K を1回押して離し、`C` を打って RETURN を押す。前後で D000〜D1FF の RAM を読み、A$ の長さと各バイト、RETURN 後のカーソル位置を記録する（打った文字と自作プログラムが書いた値で、画面は読まない。CLAUDE.md 禁止事項7）。比較のため K を押さない対照腕（`ABC` だけ）を走らせる。画面がスクロールしたかは、測定終了時の画面を `tools/check_l3_screen_output.py` の署名で対照腕と比べ、一致／不一致だけを記録する。

腕ごとに起動からやり直す。同じ腕を2走して揺れを見る。

## キー（K）

ESC、TAB、SHIFT+TAB（ある場合）、ROLL UP、ROLL DOWN、HELP、CTRL+A・CTRL+B・CTRL+E・CTRL+H・CTRL+I・CTRL+M・CTRL+Q・CTRL+X・CTRL+Z。

## 公開するもの

各腕の A$ の長さ・バイト列（打った `A` `B` `C` と、K が入れた値があればその値）、カーソル位置、画面署名が対照腕と一致したか。

## 判定と実装への反映

- A$ が `ABC` のまま → 自作でもそのキーは行入力で無視する（現状の 0x20 未満の無視と合うか確認）。
- K の値が A$ に入る → 自作でもその値を文字として入れる。
- A$ の中身や長さが変わる（TAB の空白展開、CTRL+H の1字削除など）→ 規則として記し、自作で同じにする。
- 画面署名だけ違う（スクロール等）→ その動きを別の測定で特定する。行入力への影響が無ければ、今回は「文字は入らない」とだけ反映する。
- 2走で値が違う腕は判定しない。
