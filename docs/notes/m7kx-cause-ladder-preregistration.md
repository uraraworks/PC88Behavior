# m7kx: (c)の正体を梯子で切る — 事前登録

## 位置づけ

[m7kw](m7kw-third-branch-results.md)が**(c)を立てた**——**再試行ループは
W・L1・L2で1度も回っていないのに、3つの回帰は出る。**
**本稿は「では何が変えたのか」を切る。**

**`m7kw`は「(c)の正体は分からない。『再試行ではない』までである」と書いた。**
**本稿はその先へ1段だけ進む。当てにいかない。**

## 測る前に分かっていること

- **両版（絞り込み・一律）は`2039 → 2050`で、+11バイトが完全に一致する。**
  **回帰の内訳も両版で同一**（`m7kw`）。**共通の原因がある。**
- **「コードがフェッチ窓の外へ出た」という機構は、既に排除されている。**
  **生成器の関門がそれを検査しており**（印を足したときは実際に9バイト超過で
  止まった）、**両版はその関門を通っている。**
  **したがって、`m7ks`が疑った「配置とサイズ」は、少なくとも窓の外へ出る形
  ではない。**

## 梯子（1段ずつ足す。**同じ位置・同じ11バイト**を保つ）

**絞り込み版を対象にする**（`m7ks`が絞り込んだ経路であり、一律版と結果が
同一だったため）。挿入点は`_general_read_request`の
`call FDC_READ_SECTOR`の前後で、**内訳は「前に2バイト・後ろに9バイト」**である。

| 段 | 中身 | 何を足したか |
|---|---|---|
| **P1** | **11バイトすべてNOP**（前2・後9） | サイズと配置と、余分なサイクルだけ |
| **P2** | `LD C,0x09`（2バイト）＋後ろ9バイトNOP | **Cレジスタへの書き込み** |
| **P3** | 完全な再試行コード。**ただし後戻りの`JR NZ`だけを2バイトのNOPに置換** | **A・フラグ・`FDC_ABORT`の読み** |
| **F** | **完全版（無改変）** | **到達指標＝陽性対照** |

**P3は`m7kw`の結論の整合検査でもある。** **ループが1度も回らないなら、
後戻りの分岐を潰しても完全版と同じ結果になるはずである。**
**ならなければ、`m7kw`のどこかが誤っている。**

## 到達指標（これが偽なら主判定を出さない）

> **段Fで、`m7ks`の3つの回帰が再現すること。**
>
> - `混成: 書き込みストリームが期待値と一致しない`
> - `[LOAD-混成] m7cf-load-main-fc: 件数不一致`
> - `LOAD: 公式件数へ到達したが受信列の内容または長さ…`

**同じ実行群の中で採る**（`m7kw`の数字と突き合わせるのではなく、
**この測定の中に陽性対照を置く**）。

## 記録するもの（値を出さない。件数・真偽・分類名のみ）

各段について:

1. **生成コードサイズ**（**全段2050で一致すること**。これが「同じ配置」の担保）
2. **3つの回帰それぞれの真偽**と、**NGの見出し行**
3. **`conform_l3.sh`の総合判定**
4. 場面W・L1・L2・Pの**`READ DATA`件数**と**連続した対の数・最長連続**
   （`m7kw`と同じ指標。**P3とFが一致するかを見るため**）
5. rc・SKIPの件数

## 事前登録する判定（測定前に固定する）

- **UA1（サイズ・配置・サイクルの束）**: **P1で3つの回帰が出る。**
- **UA2（Cレジスタ）**: **P1で出ず、P2で出る。**
- **UA3（A・フラグ・`FDC_ABORT`の読み）**: **P1・P2で出ず、P3で出る。**
- **UA4（後戻りの分岐そのもの）**: **P1・P2・P3のどれでも出ず、Fで出る。**
  **これは`m7kw`と矛盾する**——**ループが回らないなら後戻りの分岐は
  実行されないはずだからである。** **UA4なら`m7kw`を疑い、測り直す。**
- **UA5（段ごとに割れる）**: 上のどれにも当てはまらない並び
  （例: P1で出てP2で出ない）。**段ごとに記録し、1つにまとめない。**
- **O（測定不能）**: 到達指標が偽、決定論性が偽、**全段のサイズが2050で
  一致しない**、ビルドが通らない、のいずれか。

**どの判定になるかは予測しない。**

## 総合の線を先に引く

- **UA1のとき**——**「11バイト増えるだけで壊れる」ことになる。**
  そのとき次に測るのは**バイト数を変えて閾値を探すこと**ではなく、
  **何が位置に依存しているのか**である（窓の外は既に排除されているので、
  別の機構がある）。**閾値探しは当てにいく形なのでやらない。**
- **UA2のとき**——**Cが生きている経路を特定する。**
  **そのとき再試行はCを使わない形（メモリ上のカウンタ等）へ書き直せる**
  ので、**`m7kr`の合格条件3が現実的になる。**
- **UA3のとき**——**A・フラグのどれかを特定する。** 同じく退避すれば済む
  可能性が高い。
- **UA4のとき**——**`m7kw`を疑う。本稿では確定しない。**
- **いずれの場合も、本稿では実装を採用しない。**

## 段階0

1. **全段のサイズが2050で一致すること**（P1〜P3・F）。
   **一致しなければ「同じ配置」の前提が崩れるので、主判定は`O`。**
2. **決定論性**: 各段・各場面で独立2回の全件数が一致すること。
3. **陽性対照**: **段Fで3つの回帰が出ること**（＝到達指標）。
4. **陰性対照**: **現行の既定ビルド（2039・無改変）で、3つの回帰が出ないこと。**
   **同じ実行群の中で採る。** **これが偽なら、測っているのは回帰ではない。**

**どれかが偽なら、測定へ進まず主判定を`O`として止める。**

## 事前登録する合格条件（測定前に固定）

1. **到達指標**と**段階0の4項目。**
2. **`src/`をリポジトリ本体で変更しないこと。** worktreeで行い、
   **測定後にworktreeを撤去する。** **この実装をコミットしないこと。**
3. **実行した段の数（5＝P1・P2・P3・F・既定）を出力に載せ、期待値と一致すること。**
4. **`tools/run_all_selftests.sh`がrc=0**（**本稿から合格条件に戻す**。
   `75ad42a`で門が使えるようになった。`m7kv`の除外理由は解消済み）。
5. **`tools/check_cleanroom.sh`が全項目OK。**

## 言えないこととして先に書いておくこと

- **P1は3つの要因を束にしている**——**サイズ・配置・余分なサイクル。**
  **P1で回帰が出ても、そのどれかまでは決まらない。**
  **NOPも実行されるので、サイクルは必ず増える。** **束ねていることを
  結論に明記する。**
- **本稿も自作の実装を測っている。公式の振る舞いは1件も測っていない。**
  **(a)は本稿でも決まらない。**
- **原因が1つとは限らない。** 複数段で出たら、**「最初に出た段」を原因と
  呼ばない**——**足した要因が累積している**からである。
- 診断ポート・FDCの生バイト・時刻・frame番号・画面本文は出さない。

## 委譲する場合の指示に必ず含めること

- **委譲先が「待機します」で終えたら、親は引き取る前に必ず停止させる**
  （`m7ku`の開示1。停止せずに引き取って`conform_l3.sh`が3本同時に走った）。
- **`conform_l3.sh`は環境変数（`PC88_REF_ROM_DIR`・`PC88_REF_DISK_DIR`）を
  必ず付ける。** 付けないと本体がSKIPされ、**rcはPASSと同じ0で戻る。**
- **`git stash`と`git checkout --`を使わない。測定を並行させない。**
- **判定（UA1〜UA5）を書かせない。件数と真偽だけ報告させる。**
- **再委譲しない。バックグラウンドのプロセスを残さない。**
