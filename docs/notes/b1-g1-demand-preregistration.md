# B1: G1 の需要測定 — 事前登録

記録日: 2026-10-24
位置づけ: [goal-b-policy-2026-10-24.md](goal-b-policy-2026-10-24.md) 第7節4。
**このノートは測定より先にコミットする。** 以降の集計・判定はここに書いた規則に従い、
結果を見てから規則を変えない（変えるときは後続ノートで理由を残す）。

## 1. 目的

G1（市販ゲーム1本・1枚目のみ）を起動させ、メインCPUで次の3つを**番地と回数だけ**測る。
公式 ROM 上と自作 ROM 上の両方で取り、並べる。

1. RAM→ROM の境界の横断（記録 A: 飛び先・call/jump/int・戻り）
2. ROM のデータ読み（記録 B: 番地と回数。値は記録しない）
3. ROM と共有される RAM 番地（記録 C: 番地・読み書き別の回数）

器具は `q88measure --boundary-log`（53986de、自己検査は `tools/harness/boundary_selftest.sh`）。

## 2. 条件

| 項目 | 値 |
|---|---|
| ゲーム | G1 の1枚目のみ（`tools/stage_game.sh` が返す中立パスをドライブ1へ） |
| 打鍵 | なし（`--type` 系・`--key-matrix` を一切付けない） |
| 走の長さ | `--frames 3600`。フレーム数で区切るので実時間の時間切れは無い |
| 走 | 公式 ROM 2走（official-1, official-2）、自作 ROM 1走（self-1） |
| 起動 | すべて同一の器具・同一のディスクの中立パス・同一フレーム数 |
| 実行 | `nice -n 10`。生の出力は作業場 `PC88/tmp/b1-g1-demand-work/` にだけ置く |

走ごとに変えるのは ROM だけ。公式2走は同一条件の反復（再現性を見るため）。
自作 ROM はこのノートをコミットした時点の HEAD のビルドを使い、結果ノートにそのコミットを書く。

## 3. 記録の白リスト

コミットするファイルには次の行**だけ**を残す。実装は `tools/b1_whitelist_boundary.py`。

- 境界の記録の行: `A <addr> 5個の数`, `B <addr> 数`, `C <addr> 4個の数`、各節の終端行
  `# (A|B|C 終わり)`（アドレスは大文字16進4桁、数は10進整数。全行 fullmatch）
- 走の条件の行: `frames    : N`, `instr     : ram=N rom=N none=N`（命令数の集計のみ）,
  `ret-stack : dropped=N`、およびフィルタが自分で付ける2行 `# 識別子: G1` / `# ROM: official|self`
- 上記に合わない行は**内容を表示せず捨て、件数だけ**を標準エラーに出す
  （`dropped: comment=N other=N kept=N`）。捨てる対象は、見出しの説明コメント、
  `core`/`rom-dir`/`disk`/`disk2` のパス行、レジスタ値の混入（故障注入の行を含む）、未知の行すべて
- q88measure の他の節（`--out` の画面の写し・レジスタ・メモリの値・ファイル名・パス）は
  作業場から出さない。コミットへ回すのは `--boundary-log` のファイルを濾したものだけ。
  `--out` は第5.2節の画面の署名比較に要る場合だけ作業場へ出し、署名ツールの真偽だけを読む。
  q88measure の標準出力・標準エラーは作業場のファイルへ落とし、自分では開かない
- 濾過後のファイルだけが読んでよいもの。生の出力は `cat`/`head`/`grep` しない

## 4. 記録しないもの（方針ノート第4節の再確認）

ゲームディスク・RAM上のゲームコードのバイト列、画面本文・スクリーンショット

## 5. 判定・集計（事前に決める）

集合は「記録 A の飛び先番地」「記録 B の番地」「記録 C の番地」それぞれ別に作る。

### 5.1 公式2走の再現性
- 3種の集合がそれぞれ official-1 = official-2 なら**再現**。回数も一致するかを別に報告する
- 集合が1つでも違えば**不再現**とし、差分の番地だけを報告する。不再現のときは
  以降の公式対自作の比較で「公式集合 = 2走の和集合」と「共通部分」の両方を使い、
  差分番地は「揺れる番地」と注記して、需要の確定には使わない
- 回数だけが違い集合が同じ場合は、集合の再現とみなし、回数は「揺れる」と注記する
  （回数の閾値で判定を変えない）

### 5.2 公式と自作の差
公式の集合を O（再現なら official-1、不再現なら共通部分と和集合の両方）、自作を S とする。
- **自作で横断が出ない**: S の A が空、または `instr` の rom が 0 → 早期停止（自作 ROM が起動しない等）。「止まった」として報告し、番地分析はしない
- **別の番地へ飛ぶ**: S の A − O（自作だけの飛び先）と O − S（公式だけの飛び先）を
  それぞれ列挙。S − O が空でなく、かつ O の飛び先に対する call 回数が一致しないものは
  「分岐が変わった」の候補とする（ゲームが ROM の種類を見て分岐している可能性）
- **止まる位置**: S が O の部分集合で、かつ O − S が空でない場合、ゲームは自作 ROM で
  途中までしか進めていないと読む。O − S のうち公式側で最初の走で現れる順は記録にないので、
  順序は主張しない（集合の差だけ）
- 画面の状態は、同一の署名ツールで公式と自作を比べた**一致／不一致の真偽だけ**を報告する（本文は書かない）

### 5.3 ROM のデータ読み（記録 B）
- 番地を**連続区間にまとめた一覧**（開始・終了・区間内の総回数）と、区間数・総番地数を出す
- 区間は隣接番地（差が1）でまとめる。値は存在しないので範囲と回数のみ
- O と S の差があれば S − O / O − S を区間で報告

### 5.4 共有 RAM 番地（記録 C）
- 番地の**数**と、連続区間にまとめた一覧、ROM 読み/書き・RAM 読み/書きの別に何番地か
- 公式と自作で番地数・集合がどう違うかを報告（自作は内部配置が自由なので、
  差があるのは予期される。差を「不具合」と決めつけず、需要としては**公式側の集合**を採る）

### 5.5 採用の基準（次段へ渡すもの）
- 需要として次段（プローブの事前登録）に渡すのは、公式の再現した A の飛び先のうち、
  call 型または jump 型で total ≥ 1 のもの。回数は優先順位の参考にするのみ
- 1走の1回きりの飛び先は採るが「低頻度」と注記する
