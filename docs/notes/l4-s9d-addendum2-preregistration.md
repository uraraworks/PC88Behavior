## 動機

1回目・追補1は上限 a を10進の正の数でしか測っていない。自作ROMで `clear ,&hd000` が
Illegal function call になった（&hd000 は符号付き16ビットで -12288）。マニュアルの例は
`CLEAR ,&HCFFF`。PEEK/POKE の番地は負の値に 65536 を足す規則（l4-basic 第18節）。
CLEAR の上限でも同じ変換か、公式で測る。

## 腕（各2走。打鍵は1回目と同じ形: CLEAR の前に ON ERROR、成功後に張り直し）

`a2-*`。a の表記を `clear ,<表記>` にそのまま打つ。受理なら `fre(0)`、拒否なら ERR 番号を採る。

| 腕 | 表記 | 意味（16bit/65536補正後） |
|---|---|---|
| a2-hd000 | &hd000 | 0xD000 |
| a2-neg12288 | -12288 | 0xD000 |
| a2-hcfff | &hcfff | 0xCFFF（マニュアルの例） |
| a2-neg1 | -1 | 0xFFFF（範囲外なら ERR 5） |
| a2-he5ff | &he5ff | 0xE5FF |
| a2-neg6657 | -6657 | 0xE5FF |
| a2-frac | 53248.5 | 非整数の丸め |
| a2-over | 65536 | 範囲外（ERR 6 か 5 か） |
| a2-neg32769 | -32769 | 範囲外 |

## 仮説

**C_NEG**: CLEAR の上限は PEEK/POKE の番地と同じ変換を受ける
（負は +65536、正の 32768〜65535 は 65536 を引いてから整数化。
つまり 16進 &hXXXX は符号付き16ビットとして扱われ、負の10進は +65536 される）。

予測される帰結（器具は期待値を持たない。結果ノートで照合する）:
- `&hd000` と `-12288` は同じ結果。受理なら `fre(0) = 53248 − 35098 = 18150`。
- `&he5ff` と `-6657` は同じ結果（追補1の `&he5ff` の値と一致するはず）。
- `&hcfff` は受理（マニュアルの例）。
- `-1`（0xFFFF）は範囲外で拒否の見込み（ERR 番号は観測）。
- `65536`・`-32769` は範囲外で拒否（ERR 6 か 5 かは予測しない）。
- `53248.5` の丸め方向は予測しない。

反例: 16進と対応する負の10進で結果が異なる、`&hd000` が拒否される、
または `fre(0)` が傾き1の式から外れる。
