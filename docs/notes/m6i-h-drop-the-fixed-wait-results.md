**本ノートの結果を `docs/spec/l3-subrom.md` へ書かない。**

### G4 と、その検出力について

G4 は次を検査した。4腕の `DISK.ROM` が互いに、かつ素のサブROM
（`d8b2e64b…`）とバイト一致すること。共通5ファイルが4腕で同一であること。
`N88.ROM` が互いに相異し、H-N が m6i-b B0 と・H-W が m6i-b B4 とバイト一致
すること。**H-A・H-B の main にフレーム計数の待ちループが無いこと。**
7ファイルが所定サイズであること。

**この最後の項目には、当初まったく検出力が無かった。**
「待ちループが無いこと」の判定を丸ごと削っても、自己検査は rc=0 のまま通って
いた。置いてあった陰性対照（H-A の main を B4 のものへ差し替える）は、
**同じ判定式の手前にある「成果物と再ビルドの一致」で落ちていただけ**で、
待ちループの判定を一度も踏んでいなかった。加えて自己検査に終了コードの
伝播漏れがあった。

直したうえで、述語を直接呼ぶ単体検査を置いた（待ちループを持つ H-W の main は
False、H-A・H-B は True）。さらに **G4 の全9項目について「その項目だけを常に
真へ倒したら自己検査が落ちるか」を試し、9項目すべてが変異を拒否すること**を
確認した。親セッション側でも独立に2項目を変異させ、どちらも rc=1 になることを
確かめている。

**陰性対照を置いたことと、その対照が狙いの判定を踏んだことは別である。**

## 5. 総合判定

**`m6i_h_no_wait_sufficient`**。`h_a_success` である。

**起動専用SEND を1件出した直後に、フレーム待ちを1回も挟まずに通常READ を
出して成立する。** H-A はフレーム6で発行して256位置一致に至った。
**実装にフレーム待ちを置く必要は無い。**

副問は **`m6i_h_retry_without_send_sufficient`**。`h_b_success` である。

**起動専用SEND を出さず、通常READ を1回失敗させてからもう一度出すだけでも
成立する。** 再試行はちょうど1回で足りた。

## 6. 得られたこと

- **m6i-g が残した「待ちをどう実装するか」という問いは、消えた。**
  待ちは要らない。m6i-g §8 が「60という値を実装へ直結しない」と書いた懸念は、
  待ち自体が不要だったことで解消した。
- **実装の選択肢が2つあり、どちらも成立する。**
  - (1) 起動専用SEND 1件を前置きとして出す（H-A）
  - (2) 前置きを出さず、初回の失敗を再試行で吸収する（H-B）
- **H-B のほうが、実装に「意味の説明がつかない空送信」を置かずに済む。**
  H-A の前置きは「1件送ると通る」という観測に基づく措置であり、**なぜ1件
  必要かを本測定は説明していない。** H-B は「初回は失敗しうるので、もう一度
  出す」という、読んで意味の分かる形である。

## 7. この測定で決まらないこと

- **公式 sub が何を要求するかは決まらない**（§2）。
- **なぜ待たなくてよいのかは決まらない。** `MAIN_SUB_SEND` の有限ポーリングが
  肩代わりしている、という説明は自然だが、**本測定はそれを測っていない。**
  H-A で発行フレーム6・`a=1` が観測されたことも、機序の証拠として扱わない。
- **待ちの余裕がどれだけあるかは決まらない。** 成立するかどうかだけを測った。
- **再試行が1回で足りることの一般性は決まらない。** 本測定は1回の再試行しか
  試しておらず、2回以上要る場面があるかを問うていない。
- H-B は結果条件が他腕と異なるので、他腕との数値比較に使わない。
- 別媒体、WRITE、複数セクタREAD、BASIC命令一般へ一般化しない。
- `docs/spec/l3-subrom.md` へ規則を起こさない。

## 8. 行き先

事前登録 §5 の「`m6i_h_no_wait_sufficient` かつ
`m6i_h_retry_without_send_sufficient`」の行き先に従う。

1. **`src/` の統合実装は、再試行1回を採る。** 前置きの空送信を置かない。
2. **再試行の上限は1回に固定し、超えたら失敗を返す。** 本測定は1回で足りる
   ことしか示していないので、無制限の再試行にしない。
3. **実装コミットの前に、この判断の根拠として本ノートを引く。**
4. 1.65節への規則の追加は行わない（§2）。
5. **統合後は、FILES/LOAD/SAVE 等の BASIC 命令からの接続を別稿で測る。**
   本測定は `MAIN_SUB_READ_KNOWN`（既知座標の単一セクタREAD）しか通していない。
