# m7jz: 位相と要求の中身 — 「外側の4はmain側」が確定するか — 事前登録

## 位置づけ

[m7jy](m7jy-request-run-pairing-results.md)は判定GA1（公式では要求`R`と
run `U`が1対1で交互する）を出したが、**2つ足りない。**

1. **位相**——列は`U`から始まるが、**窓（`frame >= 700`）の外に要求が
   あれば`R→U→R→U…`とも読める。**
2. **要求の中身**——**同じ対象を4回要求したのかどうかを見ていない。**

**本稿はこの2つを埋める。両方が揃えば「外側の4はmain側」が確定する。**

## 本稿は介入を含まない（到達指標を置かない理由）

`m7jm`以降、到達指標は**介入と同じ次元で書く**という規律で運用してきた。
**本稿は条件を何も振らない**（`m7jy`と同じ3水準を測り、窓の取り方と
集計の切り口だけを変える）。

**介入が無いので到達指標は置かない。** 代わりに**再現**（過去稿との一致）を
合格条件にする。**「到達指標が無い」ことを、無いと明示しておく**——
書き忘れではない。

## 段階0: 器具に検出力があることを先に示す

要求の内容を分類する器具について、測定の前に確認する。

- **偽陽性が無いこと**: 同一水準の独立2回で、**要求の記号列が一致**する。
- **検出力があること**: **O-E1とM-E1で要求の内容の基数が異なる**、
  **または**O-E1とO-E3で**記号列の長さが異なる**。

**どちらかが期待どおりにならなければ、測定へ進まず主判定を`O2`として
止める。器具を取り替えて当たるまで試さない。**

## 「要求の内容」の定義（測定前に固定する。前稿の教訓）

`m7jy`で「要求記号の基数」が`m7jw`と食い違った。原因は
**数え方を事前登録で固定していなかった**ことである。**本稿は固定する。**

> **要求の内容**: `tools/analyze_main_to_sub.py`が再構成する
> **1要求ぶんの送信バイト列そのもの**を単位とし、
> **バイト列が完全一致するものを「同じ内容」とみなす。**
> **バイト列は出さない。** 出すのは**相異なる個数（基数）**と、
> **出現順にA,B,C…を振った記号列**と、**記号ごとの件数**だけである。

**部分一致・先頭バイトだけの一致では同じ内容とみなさない。**
**`analyze_request_kinds.py`の記号（`K00`等）は本稿では使わない**
（あれは受信runの先頭バイトによる分類で、単位が違う）。

## 段階A: 位相を決める

**同じ生ログを、窓を外して（`frame >= 0`）集計し直す。**
測定をやり直す必要はない（段階Bと同じログを使う）。

> **位相の判定**: 全区間の混合列において、**`frame >= 700`以降で最初に
> 現れる`U`の直前の記号**が`R`か`U`か。

- **HA1（要求が先）**: 直前が`R`。
- **HA2（runが先）**: 直前が`U`。
- **HA3（直前が無い）**: その`U`が全区間の先頭である。

**起動区間（A:からの読み込み）も混合列に入る**ので、**全区間の総数は
記録するが、判定には「直前の記号」だけを使う。**

## 段階B: 要求の中身の異同を測る

窓（`frame >= 700`）の中の要求について、上の定義で:

- **要求の内容の基数**
- **同じ内容ごとのグループの多重度の並び**（例`4,4,4`）
- **記号列**（出現順にA,B,C…）

**`m7jk`がrunに対してやったのと同じやり方**である（値を出さず、異同だけ）。

- **HB1（3種類×4本）**: 基数が3で、多重度が`4,4,4`。
- **HB2（基数3だが多重度が違う）**: 基数3で多重度が`4,4,4`でない。
- **HB3（基数が3でない）**: 上以外。

## 総合判定の線を先に引く（後付けにしない）

- **HA1かつHB1のとき**——**「mainは同じ内容の要求を4回ずつ、3種類について
  出しており、各要求のあとにrunが1本ずつ走る」と言える。**
  **これをもって「外側の4はmain側の再要求である」と読んでよい。**
  ただし**「mainが自発的に決めた」ではない**——**subの応答に依存して
  そうなっている可能性は残る**（mainは同じ公式ROMなのに混成では要求の形が
  違う、という`m7jw`の事実がその可能性を示している）。
- **それ以外のどの組合せでも、「外側の4はmain側」は確定しない。**
  何が言えるかは結果を見てから書くのではなく、**「確定しない」とだけ書く。**
- **内側の9がsub側かどうかは、本稿では決まらない**（`m7jx`のまま）。

## 測定条件（`m7jy`と同一。何も変えない）

- A: は`disk#8`（`650cfac8`。`stage_disk_by_digest.sh`経由）に固定。
- B: は`m7jo`のD3に固定。**ディスクは振らない。**
- 打鍵時刻は動かさない。`--frames`は3000。
- 各水準を独立に2回。**媒体パス・出力パス・引数を固定して測る。**

| 水準 | ROM | 打鍵 | 役割 |
|---|---|---|---|
| **O-E1** | 公式一式 | `FILES 2\n` | 主対象（**判定はこれで決める**） |
| **M-E1** | 混成（素の自作サブROM） | `FILES 2\n` | 比較・器具の検出力 |
| **O-E3** | 公式一式 | `FILES 2\nFILES 2\n` | 陽性対照 |

## 記録するもの（すべて値を出さない）

1. **段階A**: 全区間の混合列の`R`総数・`U`総数、**`frame >= 700`以降で
   最初の`U`の直前の記号**、その`U`より前にある`R`の件数
2. **段階B**: 要求の内容の基数・多重度の並び・記号列・記号ごとの件数
3. 窓内の`R`総数・`U`総数・混合列が交互かの真偽（`m7jy`の再現確認）
4. FDC側: K・多重度・run長の多重集合・run内基数・`READ DATA`総数・
   エラー真の件数・SEEK件数（過去稿の再現確認）
5. 最後に記録されたframe・全イベント数
6. rc・再試行の有無・タイムアウト到達の真偽

## 言えないこととして先に書いておくこと

- **総合判定の線は上に引いたとおり。** HA1かつHB1以外では確定しない。
- **「mainが自発的に4回と決めている」とは言わない**（subの応答依存の
  可能性が残る）。
- **内側の9がsub側かどうかは決まらない。**
- **要求のバイト列は出さない。異同と件数だけである。**
- **位相が決まっても、時刻順の隣接が因果になるわけではない**
  （`m7hb`のH3の教訓）。**順序の形しか言わない。**
- 条件・打鍵・ディスクを固定した1つの使い方しか見ていない。

## 委譲する場合の指示に必ず含めること

- 値・バイト列・**時刻の値や差**を報告に書かない。**記号列・件数・基数・
  真偽だけ。**
- **「要求の内容」は上の定義（送信バイト列の完全一致）で数えること。**
  **`analyze_request_kinds.py`の記号は使わない。**
- **`--emit-spec-table`は使わない。**
- **ディスクの原本確認は`cmp`の真偽で行う。**
- **画面本文を出力・転記しない。**
- **決定論性は最初から固定パスで測る。**
- **判定（HA1〜HA3・HB1〜HB3）を書かせない。**
- **段階0に失敗したら測定へ進まず、そこで報告して止まること。**
- **合格条件6・7では、照合した指標名を明示的に列挙すること。**
- **再委譲しないこと。**

## 禁止（本稿の測定中も例外なく適用）

- 公式ROMのバイト列を読まない・出力しない・保存しない。逆アセンブルしない。
- **公式ディスクのイメージを直接読まない。**
- FDCデータポート値、シリンダ値・セクタ番号、PCN値、受信run・応答run・
  **要求の送信バイト列**の値、**イベントの時刻の値**を出力しない。
- **要求されたセクタ番号が自作ディスク上のどれに当たるかを照合しない。**
- **画面本文の生の行を報告・ノート・コミットメッセージ・ツール出力へ書かない。**
- 公式ROM・公式ディスクの実ファイル名を展開して表示しない。
- トレースバックを集計ファイルへ流さない。
- 第三者の逆アセンブルリスト・解析記事のコード断片を参照しない。
