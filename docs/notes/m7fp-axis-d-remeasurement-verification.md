# m7fp: 軸Dの誤測定の疑いは否定され、代わりに条件5の記録が再現しなかった

実施日: 2026-09-03

## 位置づけ

`m7fo`は、サブ側RAM（0x4000-0x7FFF、`REQ_HDR`を含む）が常に固定値0xFFで
初期化され、ROMファイルの内容に依存する経路が無いことを確認した。段4・段6
（`SENSE INTERRUPT STATUS`）は起動区間にあり、段27（軸Dが並べ替えた
`_exchange14_prepare_first_read`）より**前**に実行される。したがって`m7fm`
が記録した「段27の並べ替え（軸D）が、実行順序上より前の段4・段6の外形を
変化させた」という現象は、`m7fo`の結果と物理的に整合しない。

この不整合から、観測系そのものを疑った。**「軸Dとして測定に使われたROMが、
実際には自作軸D版ではなく公式ROM一式（条件O）だったのではないか」**という
疑いを立て、実測済みのデータで検証した。本稿はその検証結果と、検証の過程で
判明した`m7fm`の記録の再現性の記録である。**新しい介入・新しいビルドは
行っていない。既に実測済みのログとROMを、追加で確認しただけである。**

## 立てた疑いと、それが否定されたこと

3つの独立した検査すべてで、疑いは否定された。

1. **測定に実際に使われたROMの確認。** `run_l3_mixed_measurement`が
   q88measureへ渡した`--rom-dir`内のサブROMのSHA-256が、軸D適用後に独立に
   再ビルドしたROMのSHA-256と**完全一致**した（軸Dの2runとも同一値）。
   ベースライン測定に使われたROMのSHA-256も、独立に再ビルドしたベースライン
   ROMと完全一致した（軸Dとは別の値）。条件O（公式ROM一式）は混成ディレクトリ
   を経由せず`PC88_REF_ROM_DIR`を直接q88measureへ渡しており、公式側サブROMの
   SHA-256は自作軸D版のSHA-256と相違する。**いずれのROMもバイト内容は
   読んでいない。SHA-256の一致／不一致だけを比較した。**
2. **ログ全体の比較。** 軸Dのログと条件Oのログは**完全一致していない**。
   main側は畳み込み後74472/74479件中258件目まで一致し259件目で分岐（生
   イベント換算で約7300件目、フレーム27〜34）。sub側も767件目までで分岐した。
   条件Oを取り違えて測っていたのであれば全長一致するはずだが、そうなって
   いない。
3. **陽性対照。** ベースライン対条件Oも軸D対条件Oと**同じ分岐点**
   （258/259件目、フレーム27〜34）で分岐した。この分岐はサブROMの内容に
   依存せず、混成構成そのものに由来するタイミング差であり、この検査が
   実際に差を検出できていることを示す。分岐点が偶然一致しただけではなく、
   検査系自体が機能していることの確認になっている。

以上により、**「軸Dの測定ログが実は条件Oだった」という疑いは否定された。**
軸Dの測定は、意図したとおり自作軸D版ROMに対して行われている。

## `m7fm`の条件5の記録が再現しなかった（本稿の核心）

上記の検査に使ったログを使って、`m7fm`が記録した条件5の判定内容
（段4・段6のunit/head分類が軸Dで変化した、SEEK 11段すべて条件Oと一致した）
を確認し直したところ、**再現しなかった。**

- **ベースライン対軸D: unit/head差は0件。** 全SEEK/SENSE INTERRUPT STATUS
  段で一致している。**段4・段6は変化しない。**
- **軸D対条件O: unit/head差は2件残る。ベースライン対条件Oと全く同じ2件**
  （同じ段・同じ食い違い方）である。軸Dはこの2件を一切動かしていない。
- SEEK 11段のシリンダ一致状況は次のとおりだった。
  - ベースライン対軸D: 10/11一致（不一致は軸Dが標的とする1段のみ）。
  - **軸D対条件O: 9/11一致（2段が不一致のまま残る）。**
  - ベースライン対条件O: 8/11一致（不一致3段）。
  → `m7fm`が記録した「SEEK 11段すべて条件Oと一致」も再現しなかった。
- **軸Dの効果は、標的とした1段のSEEKシリンダのみに完全に局所化されており、
  起動区間には一切及んでいない。** これは`m7fo`が確認したRAM初期値0xFF
  固定・実行順序の物理（段27は段4・段6より後に実行される）と整合する。

## 再現した点

- **READ DATA 9段すべてIC=正常終了**（ベースラインは1段が異常終了、8段が
  正常終了）。条件Oも9段すべて正常終了で一致する。この点は`m7fm`の記録と
  再現した。

## 決定論性

軸D・ベースライン・条件Oのいずれも各2runで構造的分岐は無かった。DISK.ROMの
SHA-256とiolog行数も2run間で完全一致している。

## `--after-frame`と「入口区間」「起動区間」の取り違えを避けるための確認

`m7ex`は、`tools/compare_l3_entry_fdc.py`の`--after-frame`が指定するframe
以降を**「入口区間」**と呼び、`print_entry_classification`・
`print_first_entry_difference`（両者とも`--after-frame`で絞った
`off_entry`/`mix_entry`を受け取る）がその区間だけを対象にunit/head分類と
最初の差を報告することを確認済みである。一方、**「起動区間」**は`--after-frame`
の指定に関わらず含まれる、起動直後からのFDCコマンド列全体（1.46節・`m7ex`が
言う段3・段5〜段6付近を含む区間）を指す。この2つは別の区間であり、
`--after-frame`を指定しなければ`off_entry`/`mix_entry`は単に全コマンド列
（`off_cmds`/`mix_cmds`）と等しくなる（コード357行`off_entry, mix_entry =
off_cmds, mix_cmds`、`args.after_frame is not None`の分岐でのみ絞り込まれる）。

本稿が扱った「段4・段6のunit/head差」「SEEK 11段の一致状況」は、`m7fl`の
条件5が対象とする「段0〜段26（起動時FDC初期化を含む、段27より前の全段）」
についてのものであり、**`--after-frame`で絞り込んだ「入口区間」の話ではなく
「起動区間」の話である。** これは`m7ex`が段3・段5（0起点。1起点では4・6件目）
のunit/head差を「起動区間にあり、1.46節の入口区間の検査範囲の外」と明記して
いることとも整合する。**したがって本稿で扱った段4・段6の差・SEEK 11段の一致
状況は「起動区間」についてのものであり、「入口区間」の話ではない、と確認できた。**

## `--list-all-stages`の段番号の数え方（確認できた範囲）

`tools/compare_l3_entry_fdc.py`の`print_all_stage_details`
（194〜233行）を読んだ。この関数は、渡された`official`/`mixed`コマンド列
（`--after-frame`を指定しなければ起動からの全FDCコマンド列）を**先頭から
1件ずつ**（`for index in range(1, n + 1)`）走査し、`index`をそのまま
`段{index}`として出力する。**SEEK・SENSE INTERRUPT STATUS以外の種別
（SENSE DRIVE STATUS・READ DATA・WRITE DATA・RECALIBRATE・SPECIFY等）も
`index`を消費するが、出力行は作らない**（`opcode`がSEEK(0x0F)・
SENSE INTERRUPT STATUS(0x08)のいずれでもなければ、種別一致の場合は何も
印字せずループを継続する）。

したがって、**`段N`は「全FDCコマンド列における通し番号」であり、
「SEEK/SENSE INTERRUPT STATUSだけに絞った部分列内の番号」ではない**——
本稿の依頼が挙げた(i)/(ii)のうち**(i)**に該当することを、コードを読んで
確認できた。

ただし、コード上の`index`は**1から**始まる（`range(1, n + 1)`）。一方
`m7fm`本文は「段番号は0起点で数える」と明記しており、`m7ex`も同様に0起点で
記録している（「段は0起点であり、1起点では4件目と6件目にあたる」）。
`m7ex`が0起点の段3・段5（1起点の4件目・6件目）で観測した種別は**SEEK**と
**RECALIBRATE**だったが、`m7fm`は段4・段6を**SENSE INTERRUPT STATUS**と
記録している。この2つの種別が食い違っている以上、`m7fm`が「段4・段6」と
呼んだ位置が、`m7ex`が特定した起動区間の不一致位置（0起点の段3・段5、
1起点の4・6件目）と同一の位置を指しているのかどうかは、**本稿では確認
できなかった。** `m7fm`が`--list-all-stages`をどの引数（`--after-frame`の
有無を含む）で実行し、その生出力のどの行を「段4」「段6」と読んだのかを示す
生ログ・実行コマンドは本稿の手元に無く、再実行もしていない
（新しい測定は行わない、という本稿の制約による）。

**したがって、段番号の数え方（0起点と書きつつ実際のツール出力は1起点で
あること）の食い違いが、`m7fm`の「段4・段6=SENSE INTERRUPT STATUS」という
記録の誤りの原因ではないか、という疑いは持てる。しかし、これを`m7fm`の誤り
の原因だと断定はしない。** 確認できたのは、ツールの`段N`表記が全コマンド
通し番号かつ1起点であること、`m7fm`本文の0起点という記述との間に食い違いが
あること、`m7ex`が0起点の同じ位置番号で報告した種別が`m7fm`の種別と異なる
ことの3点までである。

## `m7fm`の何が訂正され、何が訂正されないか

**訂正される（本稿による）:**

- 「軸Dが段4・段6（起動区間のunit/head分類）を変化させた」という記録。
  再測定（本稿の検証で用いた既存ログの再確認）では**変化しなかった**。
- 「SEEK 11段すべてが条件Oと一致した」という記録。再確認では**9/11一致**
  であり、2段は条件Oと不一致のまま残る。
- 上記2点に基づく**条件5=noという判定**。条件5の判定基準（段0〜段26の
  外形がベースラインから不変）そのものに照らすと、本稿の再確認では
  unit/head差0件であり、**条件5は満たされる方向の結果になった。**

**訂正されない:**

- READ DATA 9段すべてが正常終了したという記録。本稿でも再現した。
- 条件4（容量関門、`build()`が`SystemExit`を出さず成功）・条件6（WRITE経路
  のI/O列完全一致）。本稿はこの2条件を再検証していないが、`m7fm`の記録を
  覆す材料も無い。
- 陽性対照（自作サブROMのSHA-256の変化、段27SEEKシリンダの変化、
  `stage_cylinder_consistency`のFalse→True）。
- 決定論性（軸D・ベースライン・条件Oいずれも2run内で構造的分岐なし）。

**`m7fm`のノート本文は書き換えない。** 事前登録・測定記録を遡って書き換えない
という本リポジトリの方針（`m7fg`と同じ扱い）に従い、`m7fm`の記録はそのまま
残し、本稿で訂正の事実を記録する。

## `m7fo`の(a)/(b)の問いが消えたこと

`m7fo`は、`m7fm`が記録した「段4・段6の変化」の原因として、(a)ROM像
（バイト列・配置）への依存か、(b)軸Dの並べ替えの未特定の前方影響かの
どちらであるかを切り分けようとしていた。**しかし本稿で、段4・段6はそもそも
軸Dによって変化していなかったことが分かった。** 変化していないものについて
「何が原因で変化したか」を問うこと自体が成り立たない。したがって、**(a)/(b)
の問いは、`m7fm`の観測が誤っていたことによって解消する。** どちらが正しい
かが決まったのではなく、問いの前提が無くなった。

`m7fo`が確認した「サブ側RAM初期値がROMファイル内容と無関係な固定値0xFFで
あること」という調査結果自体は、本稿の結果とは独立に有効なまま残る。この
結果は今後もサブROMの初期化を考えるうえで参照できる。

## `m7fm`の誤りの原因

**特定していない。** 上記のとおり、段番号の数え方（0起点と1起点の食い違い）
が疑われるが、`m7fm`が実際に何を見て「段4・段6=SENSE INTERRUPT STATUS」と
書いたのかを示す生ログ・実行コマンドが本稿の手元に無いため、断定できない。

確認できたこと:

- `--list-all-stages`の`段N`は全FDCコマンド通し番号であり、1起点である
  こと（コードを読んで確認）。
- `m7fm`本文は「段番号は0起点で数える」と明記していること。
- `m7ex`が0起点の段3・段5（1起点の4・6件目）で報告した種別（SEEK・
  RECALIBRATE）と、`m7fm`が段4・段6として報告した種別
  （SENSE INTERRUPT STATUS）が食い違うこと。

確認できなかったこと:

- `m7fm`測定時の実際のコマンド呼び出し・生ログ・生出力。
- 上記の食い違いが本当に`m7fm`の誤りの原因かどうか。

## 言えること／言えないこと

**言えること:**

- 「軸Dの測定ログが条件Oだったのではないか」という疑いは、3つの独立した
  検査で否定された。
- `m7fm`が記録した条件5の判定内容（段4・段6の変化、SEEK 11段全一致）は、
  本稿の再確認では再現しなかった。
- 軸Dの効果は標的とした1段のSEEKシリンダのみに局所化されており、起動区間
  （段0〜段26）には及んでいない。
- READ DATA 9段全正常終了は再現した。
- 本稿が扱った差異は「起動区間」についてのものであり、`--after-frame`で
  絞り込む「入口区間」の話ではない。
- `--list-all-stages`の段番号は全FDCコマンド列の通し番号（1起点）であり、
  SEEK/SENSE INTERRUPT STATUSだけの部分列番号ではない。

**言えないこと:**

- `m7fm`の誤りの原因（段番号の数え方の食い違いが疑われるが特定していない）。
- **軸Dの合否。本稿では判定しない。** 条件1〜3・条件2（run長一致）・条件3
  （適合条件1〜5）を本稿では測っておらず、条件5だけを再確認した状態では
  総合判定ができない。改めて全条件を測り直したうえで判定する。
- 段30（`WRONG CYLINDER`）の原因。
