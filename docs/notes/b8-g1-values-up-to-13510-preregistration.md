# B8: 位置 13510 までの通信の値が公式と同じかを、値を出さずに比べる — 事前登録

記録日: 2026-10-31
位置づけ: [b7-g1-main-sub-cross-results.md](b7-g1-main-sub-cross-results.md) の次段の1。
**このノートは測定より先にコミットする。** 結果を見てから規則を変えない（変えるときは後続ノートで）。

## 1. 問い

自作サブの腕は入出力の並びが位置 13510 まで公式と同じで、そこで途切れる。並びだけでなく値も同じか。
違うなら、最初に違うのはどのポートの何番目か。

ポート `$FC`・`$FD` には公式ディスク由来のデータが載るので、値そのものは出さない（禁止事項5）。
器具の中で一致だけを判定し、**一致したか、何件違うか、最初に違う番号**だけを出す。

## 2. 条件

| 項目 | 値 |
|---|---|
| 比較 | 主: OO 対 OS（main はどちらも公式で、サブだけ違う）。参考: OO 対 SS |
| 走 | 各腕 1 走。条件は [B7](b7-g1-main-sub-cross-preregistration.md) 第2節と同じ |
| 自作 | このノートをコミットした時点の HEAD の配布ビルド |
| 実行場所 | クラウドの実行環境 |
| 対照 | 入出力の要約が `b7-g1-OO-1-io.txt`・`b7-g1-OS-1-io.txt`・`b7-g1-SS-1-io.txt` と走の名前の行を除いて一致 |
| 空振りの対照 | OO 対 OS の `compared` が `IN $FC` で 3840、`OUT $FD` で 10（B7 の OS の件数）。違えば判定せず、そのまま報告する |

## 3. 比べ方（事前に固定）

実装は `tools/b8_io_values.py`。`# main` 節の、B6 第3節と同じ開始の行から後を使う。発行元 PC の領域も B6 と同じく `hi` と `lo` に分けて並びに含める。

- **そのまま比べるポート:** `IN $FC`、`OUT $FD`。ポートごとに k 番目どうしを比べる
- **畳んで比べるポート:** `IN $FE`、`OUT $FF`。待ちの回数は ROM の速さで変わるので、連続する同じ値を1つに畳んでから k 番目どうしを比べる
- 比べる範囲は両者に共通して存在する分だけ。余りの件数は別に数える

## 4. 判定（事前に決める）

OO 対 OS について、排他的に1つ選ぶ。

- **値も同じ:** 4 ポートとも違いが 0。自作サブは位置 13510 までの通信を正しくこなしている。途切れの原因は値の違いではない
- **`IN $FC` が先に違う:** 自作サブが main へ渡すデータが違う。番号から、何バイト目かが分かる
- **`IN $FE` か `OUT $FF` が先に違う:** 受け渡しの段取りが違う
- **`OUT $FD` が先に違う:** main が送る内容が変わった。main は同じ公式なので、それより前に受け取ったものの違いを疑う

「先に」は、OS の走の中で該当する行が現れた順で決める。違いのある最初の行のポートを1つ記録する。
なぜ違うかは、この測定からは言わない。
