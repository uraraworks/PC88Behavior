# B42: 0x0D で移るまでの時間を変えると、G1 の値の違いが変わるかを介入で確かめる — 事前登録

記録日: 2026-11-01
位置づけ: [B41](b41-g1-sub-cross-origin-results.md) の次段。**このノートは測定より先にコミットする。**

## 1. 問い

自作の `0x0D` で `JP (HL)` の前に待ちを足すと、`IN $FC` の違い（257 件、最初 76570）と、移る回数（公式 71、自作 30）は変わるか。

## 2. 介入

測定専用のビルド引数で、`0x0D` の経路のレジスタ設定の前に `LD B,n`・`DJNZ $` を足す。**配布ビルドの ROM は変えない。** 引数なしのビルドが ff113bf と同じバイト列であることを自己検査で確かめる。

n は 1、8、16、24、32、48、64、128、255 と、対照に待ちなし（ff113bf）。

## 3. 条件

腕 F の 4800 フレーム。待ちなしと n ごとに SS を 1 走。OO を 2 走。自作の待ちなしは 2 走。

関門: OO どうしと待ちなしどうしの記録が一致する。待ちなしと OO の差が B30 と同じ（257 件、最初 76570、連続 132）。

## 4. 記録の白リスト

`row <none|n> fc-diff=<N> first=<N|none> run=<N> left=<N> right=<N> cross=<N> screen=<same|differ>`

`left`・`right` は `IN $FC` の回数、`cross` は移る回数である。`screen` は 4800 フレームの画面の署名の一致で、本文は出さない。**値は出さない。**

## 5. 判定（事前に決める）

- どの n でも行が待ちなしと同じなら、この待ちは効かないと書く。タイミング全体を否定はしない
- 行が変わる n があれば、並べて書く。`fc-diff=0` か `cross=71` に届く n があれば、次にどの時間が合っているかを別のノートで測る
- 待ちを配布ビルドへ入れるかは、この結果だけでは決めない
