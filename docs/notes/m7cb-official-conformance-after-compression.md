# m7cb: 容量圧縮後コードの公式環境適合実走

実施日: 2026-08-23

## 情報境界

開発者本人が `PC88_REF_ROM_DIR`・`PC88_REF_DISK_DIR`・`PC88_REF_DISKB` を
設定した公式環境で、オーケストレータが `tools/conform_l3.sh` の本体を実走した。
本ノートの記録担当は公式ROM・公式ディスクを読まず、再測定もしていない。
受け取った実測結果は件数・総バイト数・SHA-256の一致／不一致と判定結果だけで、
ROMやディスク由来の値は含まない。生ログはリポジトリへ保存しない。

diskBは市販ソフトのディスクである。実ファイル名・製品名・パスは記録せず、
環境変数 `PC88_REF_DISKB` だけで参照する既存方針を維持した。

先行する `m7as-condition2-3-judging.md` には条件2を「判定した」とする追記と、
「実判定が残る」とする記述が併存している。今回受領した実走結果では条件2が
初判定であることが明示されているため、判定時期については本ノートの記録を
優先する。先行ノートは判定器の設計経緯として残し、履歴を消さない。

## 測定条件と位置づけ

実走対象はコミット `829b259` の容量圧縮後コード（サブROMコード長
1982/2048バイト）である。公式main一式＋公式sub、公式main一式＋自作subの
混成ROM、ならびに各判定器の対照構成を `tools/conform_l3.sh` で測定し、
スクリプト全体は rc=0 だった。混成ROMディレクトリ構築の自己検査も全項目OK。

この実走は適合条件の判定であると同時に、`829b259` の挙動不変容量圧縮が
公式環境でも観測挙動を変えていないことの確認にもなっている。

## 判定結果

| 対象 | 結果 | 根拠 |
|---|---|---|
| 本番 m6g-d0-boot | OK | 公式一式で件数5635・SHA-256とも期待値に一致 |
| 適合条件1 | **合格** | 混成のm6g-d0-bootも件数5635・SHA-256とも一致 |
| 適合条件4 | **合格** | ディスク無し・公式main＋自作subでsub I/O 0件。陽性対照の試験用mainドライバ構成は2549件 |
| 適合条件2 | **合格（今回が初判定）** | 混成のdiskB起動で `sub OUT $FC` 0件。同じ数え方の陽性対照diskA（混成）は5635件 |
| 条件3判定器の検出力 | OK | 陽性対照（直前main）を不合格、陰性対照（直前sub）を合格と判定 |
| 適合条件3 | **判定不能** | 自作subの割り込み受理点0件。ポーリングのみで判定対象が無い |
| 適合条件5 | **合格** | 混成の書き込みストリームが期待値（8件・2112バイト・SHA-256）と一致 |

条件3と同じ条件の公式subは割り込みを13593件受理し、そのうち直前1件が
main側だったものは0件だった。判定器が公式側の成立を捉える一方、自作subには
受理点自体が無いため、条件を緩めたり空集合を合格扱いしたりせず、判定不能を
維持する。したがって適合条件1・2・4・5は合格し、未判定で残るのは条件3だけである。

## この記録作業で走らせていない検証

記録担当のセッションには公式環境の環境変数が渡されていないため、
`tools/conform_l3.sh` の本体は再実行していない。上記は開発者本人の環境で
オーケストレータが行った実測の記録であり、このセッション独自の再測定結果ではない。
文書・説明文の更新後に実行したのは、構文検査と公式環境を要しない自己検証だけである。
