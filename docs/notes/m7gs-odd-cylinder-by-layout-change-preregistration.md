# m7gs: 起動ディスクの配置を自作BASICプログラムで変え、交換#6の奇数シリンダを狙う（事前登録）

実施日: 2026-09-04

## 位置づけ

`m7fz`は診断固定条件（`N88_FE.D88`単独起動・打鍵なし・`--frames 1800`）で
`break_exchange6_drive_bit_clear`（`REQ_HDR+2`のbit0を0へ強制）がベースラインと
完全一致することを確認した（H1判定。目的シリンダのbit0はこの条件では
偶数だった）。`m7ga`/`m7gb`はこの偶数条件を崩す「目的シリンダが奇数になる
条件」を、**別の起動ディスクを持ってくる**方向で探索したが、`m7gd`の
スクリーニング結果、使える起動ディスクが実質1択（`disk#8`、L3ディスク
サービスに入ると確認できたのはこの1本だけ）で、行き詰まっている
（`m7gb`、および`m7gf`の訂正節も参照）。

交換#6は起動区間で1回だけ発生し、それより後の打鍵・B:への挿入には
依存しない（`m7ga`の読解と、`m7gj`/`m7gp`以降の一連の測定が確立した
「打鍵後の分岐には依存しない」という事実と整合する）。つまり、目的
シリンダのbit0を動かせる余地があるとすれば、**「起動時にA:へ挿入されて
いるディスクの中身」だけ**である。

## 今回の梃子: 機械自身にディスクの中身を書かせる

`m7gk`が`SAVE"<ドライブ番号>:<ファイル名>"`の構文を言語リファレンスから
特定し、`m7gm`〜`m7gr`が実測でこの構文を検証・WRITE経路を公式と一致
させた。**この機能を使えば、公式ディスクのバイト列を一切読まずに、
ディスクの配置（ディレクトリ・FATの使用状況）だけを変えられる。**

- `disk#8`の使い捨て複製を起動ディスクとして使う。
- その複製で起動し、BASIC上で短い自作プログラムを**名前を変えて複数回
  `SAVE`**し、A:（`SAVE"1:<名前>"`、`m7gm`で1=A:と確認済み）の
  ディレクトリ／FATへ新規ファイルを追加していく。
- 保存を終えた複製を、次段の「起動ディスク」として使い、そこから
  改めてブートして交換#6を測る。

**公式ROMのバイト列は一切読まない。BASICに書かせるだけである。** 本稿の
どの手順も、公式ディスク・公式ROMの内容を読み出したり画面へ出したりしない。
交換#6の測定器（`compare_l3_entry_fdc.py`・`check_l3_screen_output.py`）は
種別名・段番号・一致/不一致の真偽・行数/文字数/SHA-256だけを出す
（`m7fz`と同一の器材・同一の情報境界）。

## 段階1: 配置を変えた起動ディスクを作る（測定しない。ここでは手順だけ決める）

1. `tools/stage_disk_by_digest.sh 650cfac8`で、水準ごとに**別々の**使い捨て
   複製を作る（前の水準の結果を引きずらせない。水準1本ごとに複製を
   1本ずつ、計3本）。元ファイルには書き込まない。
2. その複製をq88measureへ`--disk`として渡し、`--save-to-disk-image`を
   付けて1回起動する（このオプションを付けないと、書込みはコアの
   save directory側の`.srm`差分に置かれ、複製ファイル自体は変化しない
   ——`tools/harness/frontend/main.c`のコメント・`tools/ladder_dirfiles.sh`の
   `run_frontend`の使い方と同じ理解）。
3. 打�键（`m7gr`と同じ`--type-at 300 --type '\n'`で前置し、`--type-at 700`
   から本文を打つ）:
   `1 PRINT "T"\n` に続けて、水準の本数ぶん`SAVE"1:<名前>"\n`を連続で打つ。
   **NEWは打たない**（`SAVE`はそのつどプログラムメモリの現在状態を
   指定名で保存するだけであり、直前の内容を消す必要はない。保存の
   たびに新しいディレクトリエントリ・新しいFAT割当が生まれるので、
   目的（配置を変える）には十分）。
   ファイル名は自作の通し名（`QF01`〜`QF16`、4文字。公式ディスクの
   実ファイル名ではない、本稿が新規に作る名前）。
   - 水準1（1本）: `SAVE"1:QF01"`
   - 水準4（4本）: `SAVE"1:QF01"`〜`SAVE"1:QF04"`
   - 水準16（16本）: `SAVE"1:QF01"`〜`SAVE"1:QF16"`
4. `--frames`は水準ごとに打鍵量に応じて広めに取る（`m7gr`が1本の`SAVE`を
   `--frames 4200`で確実に完了させている実績を基準に、本数に比例して
   拡大する）。**事前登録する値**: 水準1=4200、水準4=8000、水準16=20000。
   途中で打ち切られた（打鍵が末尾まで届かない）形跡が出た場合は、
   その水準を「保存が失敗した」として記録し、フレーム数を増やして
   もう一度だけ試す。2回目も届かなければ、その水準はL3判定に進まず
   記録するだけにとどめる。
5. ROMは`build_mixed_rom`の**既定ビルド**（探針引数なし）を使う
   （配置変更そのものはWRITE経路の測定であり、`m7gr`が確認したとおり
   既定ビルドはWRITE DATAが公式と一致するため、配置変更の結果が
   ROM側の不具合で歪む心配が無い）。

## 段階2: 各水準で交換#6の目的シリンダのbit0を測る（`m7fz`と同一の探針・器材）

1. 段階1で作った水準ごとの複製を、そのままA:起動ディスクとして
   `--disk`に渡す（打鍵なし、診断固定条件。`m7fz`と同一の測定条件——
   `--frames 1800`、B:は挿入しない）。
2. ROM条件は`m7fz`と同一の3条件:
   - ベースライン（`build_mixed_rom`既定ビルド、探針引数なし）
   - 陽性対照（`--break-exchange6-cylinder`）
   - `clear`（`--break-exchange6-drive-bit-clear`）
   `set`は本稿では測らない（`m7fz`がH1を確定させる目的では使ったが、
   本稿の目的は「奇数条件を見つけること」であり、`clear`が相違するか
   どうかだけが必要な情報。予算をベースライン・陽性対照・`clear`の
   3条件に絞る）。
3. 判定器材・使い方は`m7fz`と同一:
   `compare_l3_entry_fdc.py --after-frame 0 --list-all-stages`（種別列・
   段20/21の一致/不一致）、`check_l3_screen_output.py --compare-report`
   （画面署名）。新しい解析器は作らない。

## 事前登録する合格条件（測定前に固定。後から動かさない）

判定に数値比較を使わない。

1. 判定規則を先に各水準のベースライン2run同士へ当てる（`compare_l3_entry_fdc.py`
   の最初の差「なし」、`check_l3_screen_output.py --compare-report`が
   `screen_compare=match`であること）。
2. 水準ごとの陽性対照（`--break-exchange6-cylinder`）がその水準で末端に
   差を出すこと。通らない水準の`clear`は解釈しない。
3. **配置が実際に変わったことの独立確認**: 保存前（`stage_disk_by_digest.sh`
   直後、まだ何も`SAVE`していない複製）と保存後（段階1を終えた複製）の
   イメージそれぞれを起動し、`FILES`を打鍵して、`check_l3_screen_output.py`
   の行数・文字数・SHA-256が**変わっていること**を確認する。変わって
   いなければ「配置を変えた」と言えないので、その水準の結果を解釈しない
   （`m7gf`の訂正節が扱った、確かめずに「新しい刺激」と呼んだ前例を
   繰り返さない）。
4. ROMの取り違え防止: q88measureへ渡した`--rom-dir`内のサブROMのSHAが、
   全runで毎回ビルド直後の期待SHAと一致すること。
5. 決定論性: `clear`が相違した水準は2run測って自己一致を確認する。
   1runにとどめた水準は明記する。
6. **元ディスクを壊さない**: 全測定後に`private/disk`内の複製元ファイル
   （`disk#8`）のSHA-256が測定前と不変であることを確認して記録する。
7. 成果物（本稿・結果稿）に実ファイル名（公式ディスクの実ファイル名、
   および`private/`配下のパス）が含まれないこと。自作の通し名
   （`QF01`等）とディスクの通し番号・ダイジェストのみで表す。

## 事前登録する予測（測定前に書く。どれになるかは予測しない）

- **L1**: いずれかの水準で`clear`がベースラインと相違 ⇒ **奇数条件を
  確保**。1.56節の穴が埋まる。次稿で公式ROMとの比較へ進む
  （**本稿では進まない**）。
- **L2**: 全水準で`clear`がベースラインと一致（かつ陽性対照は通っている）
  ⇒ 配置を変えても偶数のまま。「バグが無い」ではなく「この梃子でも
  届かなかった」と書く。
- **L3**: 配置が変わらない／保存が失敗する／陽性対照が通らない ⇒
  梃子が効いていない。解釈しない。

**L2だった場合は、「測定では届かない」ことを示した記録として書く。**
これまで試した梃子（`m7ga`/`m7gb`の別起動ディスク探索、`m7gf`のB:媒体
状態、打鍵の有無、そして本稿の配置変更）を一覧にし、何を試して届かな
かったのかが後から分かる形にする。これは失敗の記録ではなく、限界を
測定で示した記録である。

## 測定の実務（`CLAUDE.md`・過去稿と同一の規律）

- 混成ROMは`tools/lib_l3_measure.sh`の`build_mixed_rom`で作る。
- フォアグラウンドで走らせる。`run_in_background`は使わない。
- 測定中に`git stash`・ブランチ切替・ファイル編集を重ねない。
- 無言でSKIPする分岐を作らない。SKIP・リトライ失敗は件数を数えて記録する。
- 生ログ・混成ROM・ディスク複製はリポジトリ外（scratchpad配下）に置き、
  コミットしない。
- 出力は`grep -c`等で件数・一致/不一致・rcに絞る。値の列を画面に出さない。
- `src/`は変更しない。
- ディスクの実ファイル名は展開して表示しない（`stage_disk_by_digest.sh`
  経由の中立パスだけを使う）。

## 情報境界（測定前の宣言）

読まない・出力しないもの: 公式ROM・公式ディスクのバイト列、公式ROMの
逆アセンブル、`private/`配下の内容、FDCデータポートの値列、画面本文、
シリンダ値・PCN値そのもの。記録するもの: 公開FDCコマンド種別名、段番号、
unit/head分類の一致/不一致、件数、画面出力の行数・文字数・SHA-256、
ディスクの通し番号・ダイジェスト、rc。
