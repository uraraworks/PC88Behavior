# m7bw: 9種結線とWRITE経路は2048バイトに収まったがK00由来の空振り1件が残る

実施日: 2026-08-20

## 情報境界

公式main ROM一式＋自作sub ROMを公式diskAの複製で1800フレーム実行した。
公式ROM・ディスクの内容は読まず、`private/`への
`cat`/`xxd`/`od`/`strings`・逆アセンブルは行っていない。生iolog、混成ROM、
ディスク複製、診断ROMはリポジトリ外の`mktemp -d`配下だけに置いた。
`$FC/$FD`値およびFDCデータ値は出力・記録せず、件数とSHA-256だけを扱った。

## 実装と容量圧縮

`REQ_HDR/RUN_LEN`およびWRITE循環添字とは独立した、window(a)の飽和位置と
先頭種別を追加した。`OUT $FB/$FD`で位置を0へ戻し、m7buで一意だった9種だけを
既存のREAD準備・単発応答・SENSE DRIVE STATUS経路へ渡した。K00は完了長表を0に
して未結線のまま据え置き、WRITEストリーミングも従来の長いrun経路を維持した。

容量は次の挙動不変な置換で確保した。

- 観測要求表の重複長を1本化: 11バイト削減
- 同表の追跡フラグを長さbit7へ格納: 8バイト削減
- FDC結果7件の3列をDJNZ化・共通化: 46バイト削減
- 到達範囲内のJP/JR置換: 9バイト削減
- `CP 1`を、Zだけを見る箇所で`DEC A`へ置換: 1バイト削減
- 独立位置・先頭を連続RAMへ置き、対で更新: 3バイト削減

生成コードは**2038 / 2048バイト**。WRITE自己検証はデータ窓256/256、座標一致、
応答1件で合格した。

## 実走結果

| 必須項目 | 結果 |
|---|---|
| 適合条件1 | **5635件・SHA-256一致** |
| 空振り`0B` | **14→1**、必要な対応は**66/66** |
| 最初の非データ値差 | **7036件目**、`IN $FE`、pc `3853`、公式`0x21`／混成`0x20` |
| コード長 | **2038 / 2048バイト** |
| `tools/verify_l3.sh` | **適合**。既存故障注入はすべてNG検出 |
| WRITE経路 | **保持**（256/256・座標・応答1件） |

`conform_l3.sh`の適合条件1と条件4も合格した。条件2はdiskB未指定でSKIP、条件3は
割り込み受理0件で判定不能、条件5は従来どおりSAVE未到達だった。

## 不合格と撤回した介入

残る空振り1件はK00の最後の受信後、既存単発送信の直前に出る`0B`だった。
K00を長さ1として完了表へ入れると消せるが、K00は二つの終端列が残るため、今回の
「未確定なので結線しない」に反する。またWRITE自己検証の長いrunも先頭がK00で、
無条件結線はWRITEを255件目より前で壊す。

種別を使わず、再アーム前に`$FE`のbit0/bit1を待つ介入も試した。しかしmainは
次データ時にsubの`0B`を待ってからbit0を立てるため相互待ちとなり、自己検証の
受信応答が771件から0件へ後退したので撤回した。したがってK00の選択規則を
推測せずWRITEを保持する制約下では、必須の空振り0件を満たせず、**m7bwは不合格**
とする。仕様書・PLAN・`romram_selftest.sh`は変更していない。
