# B5: 起動用セクタ実装後の自作 ROM で G1 を走らせる — 事前登録

記録日: 2026-10-28
位置づけ: [goal-b-policy-2026-10-24.md](goal-b-policy-2026-10-24.md) 第7節4の後半
（「自作 ROM 上でも同じ記録を取り、どこで止まるかを並べる」）のやり直し。
[b1-g1-demand-results.md](b1-g1-demand-results.md) では自作 ROM が起動用セクタを読まず
RAM へ一度も出なかった。その後 1411825 で起動用セクタの受け渡し（l3-boot-sector）を配布ビルドに
取り込んだので、同じ測り方で自作側を取り直す。
**このノートは測定より先にコミットする。** 結果を見てから規則を変えない（変えるときは後続ノートで）。

## 1. 目的

1. 自作 ROM 上の G1 が、起動用セクタを経てゲームのコード（RAM 上の命令）まで進むかを確かめる
2. 進んだ場合、公式で再現した需要（B1 の記録 A の飛び先 8 番地）のうち、どれに自作上でも
   到達したか・どれに到達しなかったかを並べ、次に測るべき番地（プローブの事前登録の対象）を決める

## 2. 条件

器具・濾過・記録の白リストは [B1 事前登録](b1-g1-demand-preregistration.md) 第2〜4節をそのまま使う
（`q88measure --boundary-log`、`tools/b1_whitelist_boundary.py`、G1 の1枚目をドライブ1、打鍵なし、
`--frames 3600`、`nice -n 10`、生の出力は作業場 `PC88/tmp/b5-g1-self-boot-work/` にだけ置く）。

| 走 | ROM | 目的 |
|---|---|---|
| official-1 | 公式 | 器材の同一性の確認（B1 以降にコアを arm64 で作り直したため） |
| self-1, self-2 | 自作（このノートをコミットした時点の HEAD の配布ビルド） | 本測定と再現性 |

自作 ROM は `src/build_main_rom.py` を引数なし（配布ビルド）で作る。結果ノートにそのコミットを書く。

## 3. 判定（事前に決める）

### 3.1 器材の同一性
- official-1 の濾過後ファイルが `measurements/b1-g1-demand-official-1.txt` と**バイト単位で一致**すれば
  「器材同一」とし、公式の集合 O は B1 のものをそのまま使う
- 一致しなければ「器材差あり」とし、差分の行数と、A・B・C の集合差の件数だけを報告する。
  この場合 O は今回の official-1 を使い、B1 との比較は参考に留める

### 3.2 自作の再現性
- self-1 と self-2 の濾過後ファイルがバイト一致なら「再現」。違えば A・B・C の集合差の件数を報告し、
  以降は共通部分を S とする（和集合にだけある番地は「揺れる」と注記）

### 3.3 どこまで進んだか（段階を排他的に1つ選ぶ）
- **段階0 RAM に出ない**: `instr` の ram が 0（B1 と同じ）
- **段階1 RAM に出たが ROM へ横断しない**: ram > 0 かつ S の A が空
- **段階2 横断はあるが公式の需要に一部しか届かない**: S の A が空でなく、O の A − S の A が空でない
- **段階3 公式の需要すべてに届く**: O の A ⊆ S の A

あわせて `instr` の ram・rom・none、ret-stack の dropped、および公式と自作の画面署名の一致／不一致
（`tools/check_l3_screen_output.py` の真偽のみ）を報告する。

### 3.4 番地ごとの表
O の A の 8 番地それぞれについて、自作での total・call・jump・int・ret を並べ、
「到達」（自作で total ≥ 1）か「未到達」かを付ける。S の A − O の A（自作だけの飛び先）があれば
別に列挙する（ゲームが ROM の違いを見て分岐した候補。断定はしない）。

### 3.5 次段へ渡すもの
- 段階0・1 なら、番地の需要より前に壁がある。止まった場所の切り分けは別ノートで事前登録する
  （このノートでは原因を推測で書かない）
- 段階2・3 なら、O の A のうち**自作で到達した番地**を「働きの測定（プローブ）を先に要する番地」、
  **未到達の番地**を「そこへ至る前に何かが足りない番地」として分けて渡す。順序は記録に無いので主張しない

### 3.6 記録 B・C
B1 の 5.3・5.4 と同じ集計を自作について出し、O との差を区間の件数で報告する（差を不具合と決めつけない）。

## 4. 記録しないもの

B1 事前登録第4節・方針ノート第4節のとおり。ゲームの画面本文・ディスクやメモリのバイト列・
レジスタ値・ゲーム名やファイル名は記録せず、識別子 G1 だけで呼ぶ。
