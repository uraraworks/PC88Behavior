# l4-s9w 追補5 — DIM の刻みを細かくした腕と、長い点線の診断の腕（事前登録の追補）

状態: 2026-10-09。追補4の公式の走り（`official_add4.tsv`、6腕×2走、関門通過）と、追補3の観測を読んだあとに書く。

## 動機

1. 追補4: `dim a(4000)` は成功（誤りなし）で塗りも完全。`dim a(8000)`・`12000`・`16000` は **DIM 自体が ERR 7** で、配列は確保されず、塗りは完全だった。つまり配列で空きメモリを「ほぼ使い切る」手前の N（4000〜8000）はまだ試していない。ERR 7 が PAINT の側で出る余地があるのはその間だけ。
2. 追補3: `ws-4b`（`clear ,,4096`）の最終画面は、誤りなしで、画素数（84422）はモデルと一致したが**ハッシュが不一致**だった（小・中の格子と櫛を含む `ws-7a` はハッシュも一致）。差は画面幅の格子（639×99、点線の長さ 636 ドット）にしかない。点線のスタイル（`&haaaa`）の数え方か、塗りの違いか切り分ける。PAINT の規則の一部かもしれないので、診断の腕を足す。

## 足す腕（`tools/l4_paint_measure.py`）

- `ws-8e`〜`ws-8j`: `ws-8a`〜`8d` と同じ形で N = 5000・5500・6000・6500・7000・7500。**予測なし**。
- `ws-9a`: 枠 (0,100)-(639,121) の中に、偶数行の点線（`line(2,j)-(637,j),7,,&haaaa`、j=102〜120）を引き、(1,101) を領域色 5・境界色 7 で塗る。誤りなしで、モデル（点線の規則は l4-s9u の確定済みの規則で、塗りは4連結）どおりに塗られる（弱）。
- `ws-9b`: 塗らずに、様々な長さ・始点の点線だけを引く（幅 100・300・500・636、始点 x=100、始点 x=3 の奇数）。モデルは l4-s9u の線の規則（スタイルは第1点から数え、最上位ビットが最初の画素）どおり（弱）。

結果は同じ期待値ファイルに載せる。ws-4/4b のハッシュ不一致の原因が ws-9 で分かれば結果ノートに書く。分からなければ「原因を特定できなかった」と書く。
