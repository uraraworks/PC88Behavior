# INKEY$の文境界走査の頑健性（2026-10-04）

根拠は docs/spec/l4-basic.md 第19節。公式ROM・private/は読まず、実行せず、
自作ROMだけで検査した。期待値・既存照合器・既存selftestの合格条件は変更していない。

## 検査

`bash tools/l4_inkey_robust_selftest.sh < /dev/null` は一時領域で自作ROMをビルドする。
自分で打ったプログラムのVRAMから、整数の印行だけを既存採取器で取り出す。
画面本文やフロントエンドの生診断は出力しない。

* BASICの14種：待ちループへの `x=x+1` 追加0〜8個、FOR待ち1/8/32/128、2行構成。
  80桁を越える腕はIFを次行へ分ける。代入はIFより前に実行する。
* 各腕で押下4フレーム・2フレーム、RUNのRETURNから600〜607フレームの8位相。
  取得後も200回読み、ASC=97の取得が1回だけであることと終了印を要求する。
  打鍵直前の写しで結果がまだ出ていないことも確認する。
* BASIC解析を外した短周期ドライバも2/4フレーム×8位相。
  自作ROMの通常起動後、通常は呼ばないLEX自己検査領域に置いた自作ドライバへ移り、
  DIのまま生産コードのS9C_INIT/POLL/TRYを呼ぶ。走査本体・中継・バンクは差し替えない。
  打鍵前10フレームの書込みログで1周が0.1フレーム未満であることも要求する。
  読み出したコード97が1回だけであることを1024回の追加読出しで確認する。
  自作の数値結果だけをVRAMに表示して同じ採取器に渡す。

BASICの基本待ちループは実測約0.74フレーム/周、追加代入8個は約4.95フレーム/周。
FOR腕はNEXTごとにも文境界があるため、複数フレームの待ち中にも取得・保持を検査できる。
短周期ドライバでは、高期間より短い周回を別途実測して検査する。
修正後の短周期は16条件すべて0.025フレーム/周だった。

## 陰性対照

ソース変更前のHEAD `98c2017` を一時ビルドして検査した。
BASIC224条件中68条件が取りこぼしで不合格（4フレーム20/112、2フレーム48/112）。
例：追加代入0個・hold=4・offset=603、追加代入2個・hold=4・offset=602、
2行構成・hold=4・offset=606。短周期16条件は通過した。
採取失敗・待ち状態の違反はなく、複数の陽性条件も通っている。
検査を最終版にした後も、保存した同じHEADビルドで追加代入0個・hold=4の
offset=600は合格、offset=603は取りこぼしになることを再確認した。

陰性対照用の自作ビルドを保持している場合は以下で再実行できる。

```sh
bash tools/l4_inkey_robust_selftest.sh --rom-dir "$OWN_HEAD_ROM" \
  --asm-dir "$OWN_HEAD_ASM" --expect-failure < /dev/null
```

## 修正

候補(b)を選択。main側で毎文12行を前回の行列と比較し、変化があれば即座に
バンク3を呼ぶ。VRTCの高期間を飛び越しても、押下・解放の取り込みはVRTCに依存しない。
変化がない文ではバンクを呼ばない。割り込みの有効化や文数に依存する間引きは不要。

リピートは従来の「観測できたVRTC立ち上がり」を時計とする。
行列変化だけの呼出しではリピート時計を進めない。中継がAF/BC/DEを使用するため、
時計の有無はE8E8の1バイトで渡す。第19.4節の未確定な回数・間隔へは合わせない。
hold-aは両走とも7回（公式期待34、修正前8）。走査時間の変化で観測縁の数が変わった。

mainのS9C_POLLは18Bから42Bへ増加。一時アセンブルによる末尾は0x7FF8、空き8B。

## 照合

頑健性検査は最終スクリプトで240/240合格（hold=4は120/120、hold=2は120/120）。
2フレーム押下でも取りこぼし・重複はなかった。

INKEY$本体は23腕×2走の採取関門を通過。
凍結表にあるhold-a以外の21腕は既存checkに21/21一致。
追補1は6腕×2走の関門通過・既存checkに6/6一致（定数3腕は本体と重複）。
凍結表にない既存腕buffer-abcdeもK_BUF予測に両走一致した。
本体のcheckには一時領域で凍結表と採取表を同じ21腕へ絞ったコピーを渡した。
期待値の内容や照合器は変更していない。

strcmpは自作ROMで213腕×2走を最後まで測定した後、既存checkに213/213一致。

```sh
python3 tools/l4_strcmp_measure.py measure --rom-dir "$OWN_ROM" \
  --work-dir "$OWN_WORK/strcmp" --out "$OWN_WORK/strcmp.tsv" < /dev/null
python3 tools/l4_strcmp_measure.py check \
  --expected tests/conformance/expected_l4_strcmp.tsv \
  --measured "$OWN_WORK/strcmp.tsv" < /dev/null
```

指定の退行10本はすべてrc=0：asm/asm、ext_bank、l4_basic、l4_strfunc、
l4_peekpoke、l4_inkey、l4_strcmp、l4_rnd、l4_program、l4_mbf_z80の各selftest。
すべてbash経由・stdin=/dev/nullで実行し、作業先を受け取る検査は一時領域を指定した。

測定成果物と詳細ログの作業先：`/private/tmp/pc88-inkey-work/`。
`run_all_selftests.sh` にはstrcmp自己検査の直後、期待rc=0で登録した。
