# M3b: ALPHA-DOS 需要プロファイルと「近道」案の検討

測定日: 2026-08-16
対象: ALPHA-MINI DOS 1.5 / ALPHA-DOS 2.99系（MUCOM88em, voiceeditor）の
起動シーケンス（公式 N88-BASIC ROM 32KB・メイン CPU、DISK.ROM 2KB・サブ CPU）。
関連コミット: `e4e43c8` `243d920` `56c19d4` `f7f77f7`。
測定結果の実体: `measurements/alpha-mini-boot.txt` `measurements/alpha-mini-boot3600.txt`
`measurements/mucom88em-boot.txt` `measurements/mucom88em-boot5400.txt`
`measurements/mucom88em-boot-cr.txt` `measurements/voiceeditor-boot.txt`
`measurements/voiceeditor-boot3600.txt`（アドレスとアクセス種別のみ。ROM の内容は含まない）。

---

## 発端

別セッションで MUCOM88 を調べていて「ALPHA-DOS」
（https://onitama.tv/alphados/ ）を知った。MUCOM88 が動く環境を提供する
軽量 OS と説明されており、**N88-BASIC より手前の到達目標として使えないか**
（M7（L4）を飛ばして「ALPHA-DOS が起動する互換 ROM」を先に作れないか）
を検討した。

**結論はこの案の否定である。**

## 経緯

1. 配布ページを使い捨ての判定係に先に見せ、公式 ROM の内部構造・コード断片が
   無いことを確認した（`CLAUDE.md`「Web ページにはカバーもまえがきも無い」の手順）。
2. 配布物3種のうち、**最小・最新・ライセンスが最も緩い** ALPHA-MINI DOS 1.5 を
   最初の測定対象に選んだ（測定対象としては踏む番地が少ないほど切り分けが良いため）。
3. M3 と同じ手順で需要プロファイルを測定 → **終了時画面に N88-BASIC のバナーが出た**。
4. 配布ページのスクリーンショット（v1.2）と実測（v1.5）が
   `56810 Bytes free` まで一致し、測定が実物を再現していることの裏取りになった。
5. 配布元の説明文・付属テキストも「N88-DISK BASIC 2D 形式とファイルシステム互換」
   「起動時に固定名 `MENU.ALP` の BASIC ファイルを自動実行」と一致
   → **ALPHA-MINI は BASIC 常駐型で確定**。
6. ALPHA-DOS 2.99 系（MUCOM88em / voiceeditor）は**BASIC のバナーが出ない**。
   独立起動の可能性が浮上した。
7. しかしこの時点の需要プロファイルは**番地しか記録しておらず**、PC-88 は
   0000-7FFF に RAM を差し替えられるため、「ROM を実行した」のか「RAM を実行した」
   のか区別できなかった。数字は ROM 依存度ではなく**依存度の上限**にすぎなかった。
8. ハーネスを改修（コミット `56c19d4`）。コアの実バンクポインタから ROM 像 / RAM を
   判定し、`(fetch, ROM)` / `(fetch, RAM)` として分けて出力する。陽性対照として
   素の N88-BASIC がほぼ ROM 側に張り付くことを確認した。
9. 再測定の結果、**RAM モード仮説は否定された**（0000-7FFF での RAM 実行は
   3枚とも 0 件）。

## 数字

ROM/RAM 内訳（メイン CPU）:

| 条件 | ROM 実行 | RAM 実行 | 備考 |
|---|---:|---:|---|
| b0-prompt（素の N88-BASIC が Ok まで） | 3093 (98.7%) | 41 | 陽性対照 |
| alpha-mini-boot | 4498 (90.3%) | 485 | BASIC 常駐型 |
| mucom88em-boot | 4982 (87.8%) | 690 | **アプリ本体に未到達** |
| voiceeditor-boot | 6732 | 991 | アプリ UI まで到達 |

N88-BASIC を実際に動かした既存 203 条件の和集合（13458 バイト = ROM の 41.1%）
との比較:

| | ROM 実行 | 和集合の内側 | 外側 |
|---|---:|---:|---:|
| voiceeditor | 6732 | 6385 (94.8%) | 347 |
| mucom88em | 4982 | 4734 (95.0%) | 248 |
| alpha-mini | 4498 | 4310 (95.8%) | 188 |

飽和確認: 1800 → 3600 フレームで実行番地の増加は 0（測定は短くてよい、
という M3 の知見と一致）。

サブ CPU: 3枚とも ROM 524〜525 バイトで、diskA の 529 とほぼ同じ
（ディスク経路は共通）。

## 結論

- **ALPHA-DOS 先行案は、M7（L4）を飛ばす近道としては成立しない。**
  ALPHA-MINI も 2.99 系も本体 ROM に実質的に依存する。「BASIC のバナーが
  出ない」ことは「ROM に依存しない」ことを意味しなかった。
- ただし踏む範囲は**BASIC が踏む範囲の内側 約95%**。新しい territory は
  ほぼ無く、M6（L3）→ M7（L4）を順に進めれば自然に満たされる。逆走にはならない。
- ALPHA-DOS の位置づけを**「近道」から「受け入れテスト」へ変更**する。
  公開ライセンスのサードパーティ製フリーソフトなので、第三者が自分の環境で
  再現でき、M8（適合性テストスイート）の題材として diskA（公式ディスク、
  中身をコミットできない）より扱いやすい。
- マイルストーンは**M6 → M7 の順のまま**。検討していた M6.5 は取り下げ。

## 残す宿題（未解決）

1. MUCOM88em がアプリ本体に到達しない（5400 フレームでも RETURN 送出でも
   画面が変わらない）。起動に必要な操作が不明。voiceeditor で代替できているため
   急ぎではない。
2. ROM/RAM 判定器の**RAM 側の枝が実測で一度も踏まれていない**。コードを読んで
   正しさを確認しただけなので、故障注入で検出力を確認すべき。
3. ハーネスの Makefile がヘッダを依存に含めておらず、再ビルド漏れで
   **偽の測定結果が一度出た**（別途対処中）。

## 手順上の教訓

- **否定形だけで資料に問いを立てると、肯定形の記述を取りこぼす。**
  判定係に「本体 ROM を使わないという趣旨の記述があるか」と聞いたため
  「記述なし」と返ってきたが、実際には「N88 BASIC v1/v2 モード上で動作する」
  という肯定の記述が配布ページにあった。依存の有無を問うときは両方向で聞く。
- **番地だけの観測では ROM 依存度を測れない。** 測っているつもりで測れて
  いなかった。[[不自然に揃った数字は観測系の故障を疑う]] と同型の失敗。
