# m6i-c 追補1 — 副問の観測方法を ROM 無改変に直す（測定前）

記録日: 2026-09-23  
状態: 測定前。[事前登録](m6i-c-b5-b6a0-divergence-preregistration.md)を置いた
直後であり、**腕は1走も回していない。**

## 1. なぜ直すか

事前登録 §2「副問の観測」は、ゲート入場・解除を

> 別マーカーで数える

と書いた。**これは同じ事前登録の関門 G4 と両立しない。** G4 は

- C0 の一式が m6i-b B5 の一式とバイト一致
- C1 の一式が m6i-b B6-A0 の一式とバイト一致

を要求する。ROM へマーカーを足せばバイトが変わり、G4 が必ず落ちる。
どちらかを緩めれば両立するが、**緩めるべきは観測方法のほうである。**
G4 は本測定の主張そのもの（2要因が直交していること）を支える関門であり、
副問はそれに従属する。

もう一つ理由がある。ゲートは「main の通常SEND開始を待つスピンループ」であり、
**観測用のコードを同じ経路へ入れると、待ちの長さそのものが変わりうる。**
測ろうとしている対象を測定器が動かす形になる。

したがって、**ROM を1バイトも変えずに、既存の I/O ログだけから副問を観測する。**

## 2. 直した観測定義（測定前に凍結する）

測定ハーネスは `--io-log` で CPU 別・ポート別の I/O 事象を記録している。
ゲートは sub が `IN $FE`（ポートC）を読み続けるループなので、ログの構造から
そのまま見える。ROM の改変も探針も要らない。

- **sub run**: I/O ログの sub 行だけを時刻順に並べ、`IN $FE` が連続する区間を
  1本の run とする。間に sub の別ポートの I/O（IN でも OUT でも）が入ったら
  run はそこで切れる。**main 側の行は run を切らない**（ゲートは sub 側の
  ループであり、main はその間も並行に動くため）。
- **ゲート run**: ラウンド#0応答（sub の OUT として既存解析器が識別している行）
  より後に始まる sub run のうち、長さが `gate_run_min_length` 以上のもの。
- `gate_entered`: ゲート run が1本以上ある。
- `gate_released`: ゲート run の終端より後に、sub の `$FE` 以外の I/O が
  1件以上ある。
- `request_runs`: m6i-b 解析器の要求 run と同一定義。変更しない。

凍結値を1つ足す。

| 項目 | 凍結値 |
|---|---|
| `gate_run_min_length` | 32 |

この 32 は予備走で決めた値ではなく、本稿で先に置く値である。**値の妥当性は
次節の陰性対照で測定中に検査する。** 測定後に調整しない。

## 3. 関門 G8 の差し替え（測定前）

事前登録 §3 の G8「副問の検出力」を次に差し替える。合成入力での2種識別は
そのまま残し、**測定そのものの中に陰性対照を1つ足す。**

- **G8-1（従来どおり）**: ゲートを強制的に素通りさせた合成入力と、ゲートから
  永久に抜けない合成入力で、`gate_never_released` と
  `gate_released_but_request_lost` が別々に出ることを確認する。
- **G8-2（追加・陰性対照）**: **ゲートを持たない腕 C1・C2 で、ゲート run が
  0本であること。** C1・C2 の sub ROM にはゲートが無いのだから、ゲート run が
  観測されてはならない。

G8-2 は関門ではなく、副問の帰属条件として扱う。C1 または C2 でゲート run が
1本以上出た場合、`gate_run_min_length` の選び方が短すぎて通常のポーリングを
拾っていることになる。そのときは副問を

- `gate_observation_unusable`: C1 または C2 にゲート run が観測された。
  **副問の帰属をしない。**

とし、C0・C3 のゲート判定を付けない。**総合判定（要因S・要因M の切り分け）は
この影響を受けない。** 総合判定は通常READの成否だけで決まり、ゲート run の
観測には依存しないためである。

G8-2 を関門（`gate_failed`）にしないのは、副問が崩れても主問は立つからである。
主問が使える結果を、従属する問いの都合で捨てない。

## 4. 変わらないもの

- 腕 C0〜C3 の構成、ROM の組み合わせ、関門 G1〜G7・G9、通常READの結果条件、
  総合判定5種、判定後の行き先は、事前登録のまま変更しない。
- 副問の判定名 `gate_not_entered` / `gate_never_released` /
  `gate_released_but_request_lost` / `gate_released_and_request_ran` は
  そのまま使う。`gate_observation_unusable` を1つ足すだけである。
- 本文・値列を出さない規律（事前登録 §6）はそのまま適用する。ゲート run に
  ついても、長さ・本数・真偽だけを扱い、値列は扱わない。
