# L2 — グラフィック文字 65 コード（0x80-0xA0, 0xE0-0xFF）の割り当て

作成日: 2026-08-08

`docs/notes/l2-code-assignment.md` 3節が空欄のまま残していた 65 コードのうち、
資料から図形が判別できた分をルール生成で埋める作業のノート。
**公式ROM・公式フォントは一切見ていない。** 見たのは NEC 純正マニュアルの
文字コード表（対応関係の記述）だけであり、点の配置は写し取っていない
（`CLAUDE.md` 資料の使い方 (a)/(b) の区分）。

## 1. 参照した資料・ページ

- `../refs/PC-8801MA ユーザーズマニュアル.pdf` **p.234**（資料4「グラフィックキャラクタキーと
  キャラクタコード表」の2節「キャラクタコード表」、16x16 のコード表）。
  `pdftoppm -f 234 -l 234 -r 150/400 -png` でページ画像化して読んだ
  （`docs/notes/refs-pc8801ma-manual.md` の先例と同じ手順）。
  epub 側のページ番号は `[p233]`。
- 読んだのはこの1ページのみ。同ページ1節「グラフィックキャラクタキー」（キーボード配置図）は
  資料4のうちどの物理キーがGRPH併用でこの表のコードを出すかの参考情報であり、
  コード↔図形の対応そのものはすべて2節の表から読んだ。

表の見方: 列（上位4ビット、0-F）×行（下位4ビット、0-F）。コード = 列*16+行。
**採ったのは「そのコードがどんな図形か」という記述だけ**。ドット単位の形状は
このあとの実装セクションで**自分で規則から作った**（`CLAUDE.md`「採ってよい/
採ってはいけない」の線引きどおり）。

## 2. 読み取った内容（コード→図形の記述）

### 0x80-0x8F（列8） — 棒メータ文字

列8は下へ向かうにつれて黒塗りの面積が増えていく16パターンで構成されている。

- `0x80`-`0x87`（8段階）: **セルの下辺を基準に、高さが 1/8 ずつ増える棒**
  （0x80=1/8の高さ、0x87=セル全体が黒＝8/8）。全幅。
- `0x88`-`0x8E`（7段階）: **セルの左辺を基準に、幅が 1/8 ずつ増える棒**
  （0x88=幅1/8の細い縦棒、0x8E=ほぼ全幅）。全高。
- `0x8F`: 前2系列とは別の図形。**中央の小さな「+」記号**（十字マーク）。

棒グラフを1/8刻みで作図するための部品文字と読める（縦棒メータ8段＋横棒メータ7段＋
十字マーク1、という構成）。

### 0x90-0x9F（列9） — 罫線（線・T字・コーナー）文字

列9は列8とは別の、線分の組み合わせでできる16パターン。

| コード | 図形の記述 |
|---|---|
| `0x90` | 水平線＋中央から下へ伸びる線（下向きT字） |
| `0x91` | 水平線＋中央から上へ伸びる線（上向きT字） |
| `0x92` | 垂直線＋中央から左へ伸びる線（左向きT字） |
| `0x93` | 垂直線＋中央から右へ伸びる線（右向きT字） |
| `0x94` | 水平線の左半分だけ（セル左辺から中央まで） |
| `0x95` | 水平線の右半分だけ（中央からセル右辺まで） |
| `0x96` | 垂直線の上半分だけ（セル上辺から中央まで） |
| `0x97` | 垂直線の下半分だけ（中央からセル下辺まで） |
| `0x98` | 直角コーナー（下＋右、「┌」相当） |
| `0x99` | 直角コーナー（下＋左、「┐」相当） |
| `0x9A` | 直角コーナー（上＋右、「└」相当） |
| `0x9B` | 直角コーナー（上＋左、「┘」相当） |
| `0x9C`-`0x9F` | 丸みのついたコーナー4種（上記4コーナーの丸角版）。**どの回転がどのコードかは資料からは確信を持てなかったが、「直角コーナー4種の丸角版が4つある」という構成自体は読み取れた** |

`0x94`-`0x97`（半分だけの線分）は、上半分/下半分・左半分/右半分という
位置づけを対称性から読んだもの（列9後半の縦線2種が「上半分」「下半分」と
明確に読めたため、横線2種も同じ論理＝「左半分」「右半分」と判断した）。

罫線を1マスずつ組み合わせて枠線・表を描くための部品文字と読める。

### 0xA0 — 未決定のまま残す

列A・行0（コード0xA0、半角カナ域0xA1の直前の1コード）に小さな点状の図形がある。
`0xA1`（句点「。」）とは別の記号に見えるが、印刷が小さく**確信を持って図形の種類を
特定できなかった**。1コードのみであり、無理に埋めない。

### 0xE0-0xE3（列E前半） — 未決定のまま残す

太字/二重線の罫線らしき図形（列9と対になる「太い罫線」系統に見える）が4つあるが、
**それぞれがどの接続パターン（T字4種のうちどれか、あるいは十字か）を表すのか、
資料の印刷だけでは確信を持って判別できなかった。** 無理に割り当てず未決定のまま残す。

### 0xE4-0xE7（列E中盤） — 対角線三角形

正方形のセルを対角線で2分割し、どちらか片方の三角形を塗りつぶした図形が4つ
並んでいる。対角線の向き（左上-右下 / 右上-左下）と、塗る側（2通り）の
組み合わせで、ちょうど 2×2=4 パターンになる、という**構成**が読み取れる。

**コードとパターンの対応は、資料の印刷から確信を持てる精度では読み取れなかった**
（4つとも同系統の図形で、細部の向きの識別が印刷の小ささにより難しい）。
そのため実装では「対角線三角形が2方向×2種で4パターンある」という構成だけを採り、
**コードへの割り当ては生成器側で機械的に決めた**（0xE4=左上右下の対角線・右上側、
0xE5=左上右下の対角線・左下側、0xE6=右上左下の対角線・左上側、0xE7=右上左下の
対角線・右下側、という順で割り当てた。これは資料の写し取りではなく実装側の取り決め）。

### 0xE8-0xEF（列E後半） — トランプ柄・丸・斜線

| コード | 図形の記述 |
|---|---|
| `0xE8` | トランプの**スペード**（塗りつぶし） |
| `0xE9` | トランプの**ハート**（塗りつぶし） |
| `0xEA` | トランプの**ダイヤ**（塗りつぶし） |
| `0xEB` | トランプの**クラブ**（塗りつぶし） |
| `0xEC` | **塗りつぶした円** |
| `0xED` | **輪郭だけの円**（白抜き） |
| `0xEE` | 左下から右上への**斜線**（"/"） |
| `0xEF` | 左上から右下への**斜線**（"\\"） |

いずれも「何の図形か」という一般名称の記述であり、ドットの配置は写していない。
スペード等のトランプ柄は自分で新規に描いた8x8のアイコン
（`KANA_ART` を自作した先例と同じやり方。公式ROM・他社フォントは見ていない）。
円・斜線は幾何規則（距離判定・直線の式）で生成した。

### 0xF0 — 格子状ハッチ

セルいっぱいに×印（2本の対角線を両方引いた形）が入っている。
`0xEE`/`0xEF` の斜線2本を組み合わせるだけで表現できる図形なので、
生成器側でその2つを合成した。

### 0xF1-0xF7 — 未決定のまま残す（漢字1文字）

資料には「円」「年」「月」「日」「時」「分」「秒」という**漢字1文字**がそのまま
コードに割り当てられている（キーボード上部の「年月日時分秒／円」の専用キーに対応）。

**これは埋めない。** 理由:
- 必要なのは「8x8 で判読できる漢字グリフ」だが、このプロジェクトが採用している
  自由フォント（unscii-8 は英数記号のみ、美咲フォントは半角カナ用途で導入した
  ものであり漢字までは検証していない）の枠内で、8x8 の判読可能な漢字を
  ルール生成することはできない（罫線・棒メータ・トランプ柄のような
  「幾何規則」に落とし込めない字種のため）。
- 公式フォントの字形を見に行くことも、新たに別の漢字フォントを無検証で
  持ち込むこともしない。**空欄のまま残し、理由を記録する**方針
  （指示書「全部埋まらなくてよい」）に従う。

### 0xF8-0xFF — 表の時点で空欄（確認できる事実）

資料の表そのものに、このコード域の図形が印刷されていない
（コマ自体が空白）。**読み取れなかったのではなく、資料上「未定義」であることが
確認できた。** 実装でも空欄（0x00埋め）のままにする。

## 3. 内訳まとめ

| 区分 | コード数 | 状態 |
|---|---|---|
| 棒メータ（0x80-0x8E）＋十字（0x8F） | 16 | 生成した |
| 罫線T字・半線・直角コーナー（0x90-0x9B） | 12 | 生成した |
| 罫線の丸角コーナー（0x9C-0x9F） | 4 | 生成した（4種構成は確認、回転の割当は実装側の取り決め） |
| 対角三角形（0xE4-0xE7） | 4 | 生成した（2方向×2種の構成は確認、コード割当は実装側の取り決め） |
| トランプ柄・円・斜線（0xE8-0xEF） | 8 | 生成した |
| ×ハッチ（0xF0） | 1 | 生成した（斜線2本の合成） |
| **小計（埋めた）** | **45** | |
| 0xA0（点状記号、種別不明） | 1 | 未決定 |
| 0xE0-0xE3（太字罫線、接続パターン不明） | 4 | 未決定 |
| 0xF1-0xF7（漢字1文字、8x8生成手段なし） | 7 | 未決定 |
| 0xF8-0xFF（資料上そもそも空欄） | 8 | 未決定（確定した空欄） |
| **小計（未決定）** | **20** | |
| **合計** | **65** | |

**65個のうち45個を埋め、20個は未決定のまま残した。**
理由の内訳は上記の通り: 判読確信が持てなかったもの（0xA0, 0xE0-0xE3 = 5個）、
8x8では表現手段がないもの（0xF1-0xF7 = 7個）、資料上そもそも定義がないもの
（0xF8-0xFF = 8個）。
