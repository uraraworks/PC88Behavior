## 1単位の内側の構造（今回確定した）

**公式（O-E1・O-E3）では、12単位／24単位のすべてで同じ並びだった。**

> **`SEEK → SENSE INTERRUPT STATUS → SENSE DRIVE STATUS → READ DATA ×9`**

**全単位で同じかの真偽: 真。** 1単位あたり**12コマンド**であり、
`m7hb`が「SEEK1回＋READ 9件連続の12コマンド周期」と記述した構造の
**内訳がこれで埋まった。**

混成（M-E1）は全5単位で`… → READ DATA ×1`だった。

## 主指標: 位置ごとの結果ステータス

**run内の位置1〜9それぞれについて、12単位ぶんを集約した公開ビットの
復号名の集合。**

| 位置 | 復号名の集合 |
|---|---|
| **1〜9（全位置で共通）** | `IC=異常終了 / B / head1`、`NO DATA`、`ST2はエラービットなし` |

- **位置間で異なる位置は無い**（差のある位置の件数0）。
- 件数も位置ごとに一致した。

判定規則を当てると:

- **MA2（全位置で同一）: 成立。**
- MA1（位置9だけ違う）・MA3（別のパターン）: 不成立。
- O2・O: 不成立（合格条件11項目すべて通過）。

**主判定はMA2である。**

## 併せて記録した2つ

- **位置ごとの`READ DATA`の要求パラメータの基数**: 位置1〜9すべてで
  **3**（12単位をまたいで数えた場合）。**`m7jk`の「run内は基数1」と
  `m7kg`の「対象は3種類」の両方と整合する**——同じ位置を12単位ぶん集めると
  3種類になり、1単位の内側では1種類である。
- **9件目の直後に現れるイベント**: 全単位で**「方向転換（送信側へ）」のみ**。
  **`READ DATA`が10件目に続くことも、別のFDCコマンドが挟まることも無い。**

## 総合の線（`m7kh`で先に引いたものをそのまま当てる）

> **MA2のとき——「9件の結果はどれも同じで、打ち切りの合図は結果ステータスに
> 現れない」と言える。**

**これが成立した。** `m7hb`は**END OF CYLINDERという1ビット**で
H1b（結果ステータスが継続・打ち切りを駆動する）を棄却したが、
**本稿は公開ビットの復号名全体へ広げた。** 9件はどれも同じ結果を返しており、
**9件目だけが違うということは無い。**

**ただし「9は内部の固定カウンタである」とは断定しない**（事前登録どおり）。
**結果以外の入力——時間、ポーリング回数、他のポートの状態——を潰していない。**

## 記述（判定ではない）

**言えること:**

- **1単位の内側の構造が確定した**（`SEEK → SENSE INT → SENSE DRIVE →
  READ ×9`。全単位で同一）。
- **9件の結果はどれも同じで、9件目に特別な結果は返っていない。**
- **9件目の直後は必ず方向転換**であり、`READ DATA`が続くことは無い。
- **混成は1件で終わる**（`… → READ DATA ×1`）。

**言えないこと:**

- **「9は内部の固定カウンタ」とは断定しない**（上記）。
- **「結果に依存しない」と言えるのは、公開ビットの復号名という粒度まで**で
  ある。**生の値の違いは見ていない**（見ない方針である）。
- **9件目の直後の方向転換は種別だけを見た。** そこで何が送られたかは
  見ていない。
- **6バイトの単位がさらに分かれる可能性の留保は残る**（`m7kd`から引き継ぐ）。
- 条件・打鍵・ディスクを固定した1つの使い方しか見ていない。
