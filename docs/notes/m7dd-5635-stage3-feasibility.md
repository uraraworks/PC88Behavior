# m7dd: 起動時5635件の第3段媒体介入は起動可能な規則生成D88不足で停止

実施日: 2026-08-28

`docs/notes/m7da-5635-origin-preregistration.md` 第3段について、媒体差し替え機構と
起動到達性を下見し、既存の公開規則生成D88を1条件だけ実走した。結果はバルク0件で
介入不成立だったため、事前登録どおりH1/H5の判定へ数えず、追加条件も走らせず停止した。
`src/`、公式ROM、公式ディスクの内容には触れていない。

## 情報境界

- 既存ノート、公開された測定ツール、公開D88規則だけを調べた。`private/`配下の
  ファイル内容は開いていない。
- 実走に用いた私物は、環境変数で渡した公式ROM一式だけである。媒体は
  `tools/make_l3_testdisk.py` が数式から生成した自作D88で、公式ディスクを
  複製、参照、加工していない。
- 生iolog、stdout、stderr、解析出力、自作D88はリポジトリ外の一時領域だけに置いた。
  データポートの値は表示、転記、判定に使用していない。公開するのは件数、構造、
  rc、SHA-256だけである。
- 本稿は測定と実現可能性調査だけであり、`src/`および`docs/spec/`は変更しない。

## 既存の媒体差し替え機構

測定フロントエンド`q88measure`は`--disk PATH`でD88またはM3Uを受け取る。
`tools/measure.sh`では`PC88_REF_DISK_DIR`と`--disk-name NAME`を組み合わせ、原媒体を
一時領域へ不透明コピーしてから`--disk`へ渡す。ライトプロテクト条件は
`--disk-writable`でその一時コピーの公開D88ヘッダだけを変更する。
`PC88_REF_ROM_DIR`は公式ROM一式の場所を渡す環境変数であり、媒体形状の制御変数ではない。

`tools/analyze_exchange14_read_rules.py`の`--disk-compare`と`--config-compare`は、
別条件で取得済みの生ログを値非表示で比較する解析側の入口である。媒体を作成・変更する
機能ではない。

m7abの媒体14条件は、公式diskAの使い捨て複製をリポジトリ外で変化させた条件であり、
全条件が起動バルクへ到達してFDCデータ部と定常列に連動差を生じた。ただし、残っている
ノートとツールには14条件を再生成する恒久ツールや環境変数はなく、記録されているのは
媒体**内容**への連動判定である。READのセクタ数またはEOTを変えた形状介入の実績ではない。
m7adはそのm7ab結果を参照した観測応答の候補走であり、独立した媒体差し替え機構ではない。

## セクタ数・EOTを変える能力

`tools/make_l3_testdisk.py`は公開D88規則から、片面、1トラック8セクタ、N=1、
1セクタ256バイトのD88を生成する。全データは座標と位置の数式だけから作られるため、
公式媒体から独立している。一方、現行CLIにはトラック当たりセクタ数、シリンダ数、
セクタ長を条件別に指定する引数がなく、定数を固定している。

D88のセクタ記述部はC/H/R/N、当該トラックのセクタ数、データ長を持つため、公開規則だけで
トラックのセクタ形状を変えること自体は可能である。しかしEOTはD88ヘッダのフィールドでは
なくFDC READ DATAコマンドのパラメータなので、D88差し替えだけで命令上のEOTを直接指定する
ことはできない。媒体側のR集合を変えれば実際の読取り完了長やエラー位置は変え得るが、
交換#14へ到達して公式main/subがその形状を採用することを別途確認する必要がある。

従って第3段に足りないのは、単なる可変D88ライタではなく、公式ディスクを複製せずに
交換#14の起動経路まで到達する、公開仕様だけから作られた起動可能な測定用D88である。

## 起動到達性の既存実績

m7abの14条件では差し替え後もバルクが発生し、定常列に7〜8位置の連動差が出た。
ただしこれは公式diskAの使い捨て複製を土台にした内容介入であり、今回禁止された
「公式ディスクを複製しない」条件へ再利用できない。

完全規則生成媒体については逆の実績がある。m7kでは同じ生成器のD88で最初の6交換は
成立したが、有効な起動内容ではないため、その後は同系列を反復して起動に成功しなかった。
交換#14の高速バルクへ到達した実績はない。

## 下見実走

既存生成器を変更せず8セクタ/track条件を生成し、公式ROM一式と組み合わせて
1800フレーム実走した。測定rc=0で、生成媒体と生ログのSHA-256はそれぞれ
`c83e94186268cb2acd5330200c89283cf7f31f7c8f5fd867e429db09b1b5e15e`、
`cd1f106a7186593251e5d23af3f173ab57e008e7d99d97439fb5f60`だった。

値を参照しない`tools/analyze_bulk_trigger.py`はrc=0でmain `IN $FD`を0件、
sub `OUT $FC`を全ログ再集計でも0件とした。
`tools/analyze_exchange14_read_rules.py`は「交換#14または公式バルク区間を特定できない」
としてrc=2だった。

| m7da第3段の観測量 | 結果 |
|---|---|
| 5回のREAD長 | バルク未到達のため判定不能 |
| 選択された一意セクタ数 | 判定不能 |
| 両ポートの定常件数 | バルク入口0件のため定常区間不成立 |
| 末尾パディング件数 | 判定不能 |

これは「8セクタ形状なら0件へ追随する」というH1支持でも、「固定5632件を保てない」という
H5反証でもない。起動経路に到達していないため、事前登録上の**介入不成立**である。

## 停止理由と次に必要なもの

第3段を成立させるには、別担当が公開FDC/D88仕様と公開された起動インターフェースだけから、
交換#14の起動経路へ到達する測定用IPL／D88フィクスチャを独立に用意する必要がある。
そのフィクスチャには、少なくとも対照形状と、トラックのR集合またはREAD命令上のEOTを
変えた2条件を規則生成できる入口が要る。公式diskAの内容を読んで起動部分を真似る方法、
または公式diskAの不透明コピーを土台にする方法は採用しない。

現セッションは情報境界違反後の測定担当であり、実装には参加しない。この前提物が無いまま
追加の規則生成媒体を走らせてもバルク0件を重ねるだけなので、H1/H5の数字を作らずここで止める。

## 結論

媒体差し替えの搬送経路と値非表示比較器は既にあるが、既存の完全規則生成D88は起動バルクへ
到達しない。m7abのバルク到達実績は公式diskA複製を土台にしており第3段へ流用できない。
今回の1条件も介入不成立で、H1/H5はいずれも未判定のままである。
