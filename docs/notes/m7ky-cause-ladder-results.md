# m7ky: 不活性な詰め物11バイトだけで、3つの回帰がそっくり出る（判定UA1）

実施日: 2026-09-10
事前登録: [m7kx](m7kx-cause-ladder-preregistration.md)（**測定前に単独コミット済み**。
段・場面・指標・段階0・判定規則・線は本稿で動かしていない）

## 主判定

> **UA1。** **梯子の最初の段P1——`LD C` もループも無く、11バイトすべてNOP——で、
> `m7ks`の3つの回帰がそっくり出る。**
>
> **再試行のコードは、回帰に一切関与していない。**

## 段階0（すべて満たした）

| 項目 | 結果 |
|---|---|
| 1. 全段の生成コードサイズが2050で一致 | **真。P1・P2・P3・Fとも2050** |
| 2. 決定論性（各段で独立2回が一致） | **真。全5段** |
| 3. 陽性対照（段Fで3つの回帰＝到達指標） | **真** |
| 4. **陰性対照（既定ビルドで回帰が出ない）** | **真。BASEは「適合」** |

**決定論性について**: 素の`cmp`では**BASEだけ2回が不一致**だった。差は
**2行**で、**中身は「初回だけフロントエンドをビルドした」という注記**である
（判定にも件数にも関係しない）。**その2行を除くと全5段で一致した。**
**素の`cmp`のまま「決定論性が偽」と報告していれば、測定はここで止まっていた。**

## P3がFと一致したこと——`m7kw`の整合検査は通った

`m7kx`はP3を**`m7kw`の整合検査**として置いた——
**ループが1度も回らないなら、後戻りの分岐を潰しても完全版と同じになるはず。**

**W・L1・L2でP3とFは完全に一致した。** **`m7kw`の結論は整合している。**
（**場面Pだけは違う**——Pでは再試行が実際に回るので、後戻りを潰したP3は
21件、Fは117件になる。**これも予想どおりで、Pが「回る場面」であることの
確認になっている。**）

## 判定の意味（言えることと、言えないこと）

**言えること:**

- **回帰の原因は再試行の意味論でも、`LD C`でも、`FDC_ABORT`の読みでもない。**
  **11バイトの不活性な詰め物で足りる。**
- **`m7ks`の「行き止まり」は、完全に別の原因によるものだった。**
  **`m7kr`の合格条件3は、再試行の書き方の問題ではない。**
  **11バイト増やせないことのほうが問題である。**

**言えないこと（`m7kx`で先に書いたとおり）:**

- **P1は3つの要因を束にしている**——**サイズ・配置・余分なサイクル。**
  **NOPも実行されるのでサイクルは必ず増える。** **どれが効いているかは
  決まっていない。**
- **「コードがフェッチ窓の外へ出た」機構は既に排除されている**（生成器の関門を
  通っている）。**したがって、既知の機構ではない何かである。**
- **(a)は本稿でも決まらない。公式の振る舞いは1件も測っていない。**

## 次に測ること——束を3つに分ける

**2つの実装（絞り込み版＝`_general_read_request`・一律版＝`FDC_READ_SECTOR`）は
挿入点が違うのに結果が同一だった。** 現行の配置は
**`_general_read_request` = 0x029E、`FDC_READ_SECTOR` = 0x0377**（コード全長
0x07F7）なので、**両版に共通するのは「0x0377以降が11バイトずれること」**である。
**これはどの要因とも矛盾しないので、切り分けには使えない。**

**次の梯子（別稿で事前登録する）:**

| 段 | 置き方 | 動く要因 |
|---|---|---|
| **Q1** | **コード末尾に11バイト**（実行されない） | サイズだけ（移動なし・サイクル増なし） |
| **Q2** | **0x0377より前の、実行されない位置に11バイト** | サイズ＋移動（サイクル増なし） |
| **Q3** | （Q1・Q2とも陰性なら）**サイクル** | 消去法ではなく、別に介入して確かめる |

**Q1で出ればサイズ、Q1で出ずQ2で出れば移動、どちらも出なければサイクルが
残る**——**ただし残ったものを「消去法で確定」とはしない**
（`feedback_intervene_before_trusting_the_bottleneck`）。**残ったら、それを
直接振る介入を作る。**

**閾値探し（バイト数を変えて何バイトから壊れるかを探すこと）はやらない。**
**当てにいく形であり、機構の説明にならない。**

## 測定の条件

- **worktree（`PC88/tmp/m7kx-wt`）で`src/`を段ごとに差し替えた。**
  **リポジトリ本体の`src/`は変更していない。この実装はコミットしない。**

- 各段を独立2回、**5段で計10回を逐次実行**（12:47〜13:41）。
  **並行実行はしていない。**
- 環境変数は`PC88_REF_ROM_DIR`・`PC88_REF_DISK_DIR`を付けた。
  **`PC88_REF_DISKB`は未設定でSKIPが1件**（本測定の4場面はdiskBを使わない）。
