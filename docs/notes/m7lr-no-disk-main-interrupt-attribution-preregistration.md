# m7lr: B:媒体未挿入の要求長の分岐（公式5／混成6）を、main側の割り込み受理へ帰属させる — 事前登録

## 位置づけ

1.58節の外で残っている公式との食い違いは、**B:媒体未挿入（no_disk）**だけである（2026-09-11の洗い出し。
適合テストのBASEの`--`行のうち、A:/B:の要求runの差は公式にも同じ差があるので食い違いではなく、
B:規則生成媒体のFDC種別列の分岐はm7leの再試行で消え、`$FC`の中身の差は1.58節の9件後の応答の値と同じ事実）。

no_diskでは、交換列の最初の差が相対+0の**main→sub要求長（公式5・混成6）**で、手前は値まで一致する（1.50節）。
これまでに6つの容疑者を、有効な介入でも指標が動かないことで除外した（1.50〜1.52節: 相対-3の256バイト応答内容、
相対-1の1バイト応答内容、軸近傍で自作subが受理する割り込み2件、応答準備を遅い方向へ2clock、公式と同じ2clockへ短縮、
早期応答N=3〜6）。**残る未帰属候補として仕様が挙げているのは、窓内のmain側割り込み受理の差（公式683件／混成679件）
である**（1.50節・3章）。

**mainは公式・混成とも同じ公式main ROMである。** 受理件数の差は、mainが待った時間の違いから来ている可能性が高いが、
それが要求長を変えたかどうかは測っていない。本稿はそれを介入で確かめる。

## 器具（本稿で足した。測定前にコミットする）

- **コアの測定用介入 `q88h_main_interrupt_intervention`**（`tools/harness/core/`・パッチ`0013`）: 指定した交換run窓の間だけ、
  **main CPUの割り込み受理を保留する**。sub側（`0012`・m7co）と同じ形で、対象CPUだけが違う。無指定時は常に許可し、
  交換値・ROM本体は変えない。`suppress`は窓の間の受理をすべて保留（要求は取り下げない）、`delay-one`は受理の直前検査を
  1回だけ保留してから通す。
- **フロントエンド `--main-interrupt-intervention FIRST:LAST:MODE`**: 走り終わりに証跡（照合回数・保留回数・窓内の受理数）を
  出し、照合0回・保留0回なら失敗で終わる（sub側と同じ）。
- **自己検査 `tools/main_interrupt_intervention_selftest.sh`**: 無介入・窓の前・窓の後ろ・suppress・delay-one・sub側に
  触れないこと・不正な設定の拒否。**陽性対照3つ（窓の上限・下限・delay-oneの再装填をそれぞれ壊す）で落ちることを確かめた。**
  最初の版は窓の後ろの場合を持たず、上限を壊しても通った——陽性対照で気づき、場合を足した。
- **`tools/search_error_response_candidate.py main-interrupt-attribute`**（no_disk専用）: 下の腕を走らせ、判定を出す。

## 測定前の関門（すべて真でなければ測定しない）

- **P1** 自己検査と陽性対照3つ（済み）。
- **P2** `tools/setup_harness.sh`で、上流のきれいな取得からパッチ0001〜0013を当ててコアを作り直し、main割り込み介入の
  シンボル検査を含む全検査がOK（済み）。
- **P3** **新しいコアで、介入を何も指定しないときの振る舞いが変わらない**: 適合テストを1回走らせ、判定行の集合がm7lqの
  候補1回目（今の`src/`と同じ）と一致し、データを運ぶポートのイベント列が全iologで一致する（m7ldの比較器）。
- **P4** `calibrate --scenario no_disk --frames 900`で校正軸が取れ、対照の要求長が公式5・混成6（道具が確かめる）。

## 腕（公式側・混成側の両方で走らせる。axisはcalibrateが保存した+0の交換run番号）

| 腕 | main割り込みへの介入 | 役割 |
|---|---|---|
| control | なし | 対照 |
| control_repeat | なし | 決定論性（対照と成果物指紋・指標が一致すること） |
| suppress_near | 交換run [axis-1, axis] の間 suppress | 軸の直前だけを動かす |
| delay_one_near | 交換run [axis-1, axis] の間 delay-one | 同上で、保留を最小にする |
| suppress_wide | 交換run [axis-4, axis] の間 suppress | 683／679を数えた校正窓の全体 |
| clock_shift_257（混成だけ） | なし（ログのclockへ既知量を足す） | 指標がarmごとに再計算されている陽性対照（m7co） |

**有効な介入**とは、証跡（照合・保留とも1回以上）が立ち、**成果物指紋（値を含まないI/O指紋・受理件数・相対到達clock）が
同じ側の対照から変わった**腕をいう。

## 判定規則（測定前に固定する）

- どちらかの側で**対照と対照の繰り返しが一致しない** → `nondeterministic`（結論を出さない）。
- **公式側のどれかの腕で要求長が5以外、または混成側のどれかの腕で6以外になった** → `main_interrupt_affects_branch`:
  **main側の割り込み受理を保留すると、+0の要求長が動く。**
- どれも動かず、**介入の腕6つがすべて有効** → `main_interrupt_excluded`: **保留した窓と方式の範囲で、main側の受理差は
  分岐の原因ではない**（7つ目の容疑者の除外）。
- どれも動かず、有効でない腕が1つでもある → `inconclusive_ineffective_arms`（除外もしない）。

## 記述として載せるもの（合否に使わない）

- 各腕の窓内main受理件数（校正窓・軸近傍）、交換prefix・FDC prefix・画面署名の一致、相対到達clockの対照との差。
- 公式・混成の対照で、窓内main受理件数が1.50節の683／679を再現するか。

## 言えないこととして先に書いておくこと

- **エミュレータの上での振る舞いである。**
- 動いても「main側の受理を保留すると分岐が動く」までで、**公式mainが割り込みで要求長を決めているとは言わない**。
- 動かなくても、保留した窓（-1〜+0、-4〜+0）と方式（suppress・delay-one）の範囲での除外である。
  受理を**早める**方向の介入はこの器具では作れない。

## 禁止（本稿の測定中も例外なく適用）

公式ROM・公式ディスクのバイト列を読まない・出力しない・逆アセンブルしない。`private/`の中身を見ない。道具は交換値・FDC生値・
画面本文・PC・割り込みlevel・絶対clockを保存しない（件数・長さ・一致・指紋だけ）。私物のパスは環境変数でだけ渡す。
