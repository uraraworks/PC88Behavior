# m7dg: run切り出し誤差の合成陽性対照

実施日: 2026-08-28

`docs/notes/m7df-run-cutter-error-preregistration.md`で固定した予測を、規則生成した
合成iolog/intlogへ現行cutを適用して検算した。公式環境の新規実走および既存の
実ログ再解析は行っていない。

## 試験方法

`tools/run_cutter_positive_selftest.py`は一つの入口から次の二系統を独立に試験する。

1. **FEスピン系**: `tools/analyze_sub_fe.py`の`parse_iolog()`と
   `analyze_sub_fe()`を直接使い、同一pc・同一`IN $FE`の隣接列を現cutとする。
2. **SEND run系**: `tools/analyze_run_boundary.py`の`main_send_runs()`が返すrunへ、
   同じ解析器の`0F`位置窓と偶奇・末尾pc規則を適用する。

合成ログの真の呼出し開始clock／run開始clockは生成器が別に保持する。補正cutは
判定対象の例外、`0F`位置、偶奇、末尾pcを境界作成に使わず、明示開始clockまたは
合成intlogの共通clockだけを境界アンカーとする。SENDのintlog-aware cutは、現cutが
既に認識する非許容ポート境界を保った上で、iologから不可視の割り込み境界を加える。

## SEND run系の予測値との突き合わせ

正常形は1000本の3バイトrunで、次の全項目が予測どおりだった。

| 指標 | 事前予測 | selftest実測 | 判定 |
|---|---:|---:|---|
| 先頭`0F`あり | 1000/1000（100%） | 1000/1000（100%） | 一致 |
| 継続`0F`なし | 2000/2000（100%） | 2000/2000（100%） | 一致 |
| 偶奇・末尾pc反例 | 0件 | 0件 | 一致 |

偽分割の段階注入は次のとおりである。`s=100`では事前登録どおり偶奇反例も
100件となった。全腕で明示run開始clockによるcutは正常形へ戻った。

| 挿入数s | 先頭`0F`率の事前予測 | selftest実測 | 判定 |
|---:|---:|---:|---|
| 10 | 99.01% | 1000/1010 = 99.01% | 一致 |
| 53 | 94.97% | 1000/1053 = 94.97% | 一致 |
| 100 | 90.91% | 1000/1100 = 90.91% | 一致 |
| 190 | 84.03% | 1000/1190 = 84.03% | 一致 |

偽結合の段階注入も次のとおりである。`m=100`では検出run 900本、先頭
900/900、継続2000/2100、偶奇反例100件となり、事前登録した全分子・分母に
一致した。全腕で明示run開始clockによるcutは正常形へ戻った。

| 置換数m | 継続`0F`なし率の事前予測 | selftest実測 | 判定 |
|---:|---:|---:|---|
| 20 | 99.01% | 2000/2020 = 99.01% | 一致 |
| 100 | 95.24% | 2000/2100 = 95.24% | 一致 |
| 353 | 85.00% | 2000/2353 = 85.00% | 一致 |

割り込み受理だけを20境界へ置いた腕は、現cutで980 run、先頭980/980、
継続2000/2020、偶奇反例20件となった。intlog-aware cutでは1000 run、先頭
1000/1000、継続2000/2000、偶奇反例0件へ戻った。handlerの別ポートI/Oを
10 runへ挿入した腕は現cutで先頭1000/1010となり、明示境界cutで正常形へ戻った。

先頭／末尾打切り、境界の1位置ずれ、選択イベント1件欠落も独立に検出した。
0件入力と解析可能行0件の入力は有効な合格標本として扱わず、拒否確認に含めた。

## 検出力、空振り、ロケール

故障腕の内訳はFEスピン系9腕、SEND run系14腕の計23腕である。検出は
**23/23、空振り0件**だった。正常形ではFE例外0件、SEND先頭`0F`率100%、
継続`0F`なし率100%、偶奇反例0件であり、故障を入れていない標本の誤検出も0件だった。

`LC_ALL=C`と`LC_ALL=ja_JP.UTF-8`でselftestを個別実行し、出力のdiffは0件、
両方ともrc=0だった。

全selftest登録後の`tools/run_all_selftests.sh`はrc=0だった。新設selftestは
C/UTF-8ともrc=0で、一覧上も期待rc=0に一致した。`tools/check_cleanroom.sh`も
rc=0（全項目OK）だった。公式環境を要する既存3項目の明示SKIPは合格として
数えていない。

## 予測との不一致と切り分け

事前登録した予測値に対する不一致は**0項目**だった。実装途中の初回確認では、
合成割り込みclockを次のI/Oと同値に置いたこと、SENDのaware cutへ現行の明示I/O
境界を合成していなかったこと、というselftest側の配線不備を検出した。予測値や
故障量は変更せず、共通clockの厳密な前後関係と二種類の境界の和集合になるよう
補正cutだけを修正した後、上表の完全一致を得た。従って予測の算術、現cutの挙動、
最終的な合成生成器の間に未解決の食い違いはない。

## 事前登録条件に対する位置づけ

m7dfの合成selftest到達条件は満たした。少数の境界欠落だけで0.1089%／0.1814%を、
SENDの偽分割／偽結合だけで84〜99%域と偶奇反例を機械的に生成でき、独立境界cutで
基準へ戻ることを確認した。ただしこれは測定手法にその誤差生成能力があることの
陽性対照であり、既存実ログの例外が手法由来だというM判定ではない。M/R/Xの判定には、
m7dfで事前登録した新規2走と独立境界アンカーによる位置帰属がなお必要である。

## 情報境界

- 使用した入力は規則生成した一時領域の合成iolog/intlogだけである。`private/`、
  公式ROM、公式ディスク、既存の実測ログは読んでいない。
- データポートのpayloadは合成ログでも伏せ字とし、値列を標準出力、ノート、
  リポジトリ成果物へ出していない。記録したのは件数、率、pc規則、境界構造だけである。
- 新規公式実走、`src/`、`docs/spec/`の変更は行っていない。
