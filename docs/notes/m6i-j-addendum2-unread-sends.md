# m6i-j 追補2 — main の送信と sub の受信の対応を「直前の送信」で決める

記録日: 2026-09-29  
状態: **測定前**（有効な測定はまだ無い）

## 1. 3回目の起動（器具 `23e7715`、追補1 適用）

公式ROM起動1回（J-D1-S-N の1走目）で、再び `transfer_count` で `gate_failed`。入出力ログはフレーム1600から始まり、送受信はフレーム1871〜1891に収まっていた（ログの欠けではない）。
診断（公式ROM起動1回、件数だけ）: main の `OUT $FD` 2195件、sub の `IN $FC` 2152件。時刻順に並べると、**sub が1回も読まないうちに main が次の値を書いた送信が43件**、
**同じ送信を sub が2回以上読んだものは0件**。

## 2. 原因

事前登録 §3 は main の送信と sub の受信を「単調な全単射」で結ぶ前提だった。実際には、sub が読まない送信がある（main が同じ口へ続けて書く）。
各受信の側から見ると、どの受信も直前の送信を1回だけ読んでいる。前提が厳しすぎた。

## 3. 変更

- 対応づけ: **sub の各 `IN $FC` を、それより前で最も新しい main の `OUT $FD` に結ぶ**。値の一致（受信値＝その送信の値）を全数検査する（`transfer_mapping`）。
  同じ送信に2つ以上の受信が結ばれたら `gate_failed`（今回の観測では0件だが、条件として置く）。
- 読まれなかった送信（結ばれる受信が無い送信）は `unread_send` として、件数と、main の送信列の中の位置（何番目か）と、前後の読まれた送信との関係（制御の値・長さの分類）を記録する。
  値は制御の値として扱い、256バイトのデータ部の中に入っていれば「データ部の中」とだけ記録する。
- 6バイト制御レコード・データ部の同定と、事前登録 §3 の625候補の照合は、**sub が受信した列**（読まれた送信だけ）について行う（sub が受け取る内容が、書き込みを成立させる内容であるため）。
  読まれなかった送信の規則は、別の判定 `unread_send_rule_unique` / `inconclusive_unread_send` として、腕の間で位置と件数が一致するかだけを判定する。
- `transfer_count`（件数の完全一致）は外し、上の対応づけの関門に置き換える。そのほかの項目（腕・候補・判定・関門）は変えない。器具のハッシュを含む凍結値は作り直す。
