# GW-BASIC `PRINT` フリーフォーマットの固定小数点／指数表記判定

**出所:** Codex（gpt-5.6-sol）が GW-BASIC のソース（コミット`edf82c2`、
MATH1.ASM/MATH2.ASM/GIO86.ASM）のみから命令単位で導出した分析であり、
PC88Behavior（PC-88 公式 ROM の測定）は一切参照していない。l4-s4e の
候補規則（`--small-rule gw`）はこの分析の導出式をそのまま実装したもの
であり、測定より先の仮説である（実測との一致・不一致は今後の測定で
判定する）。取り込みにあたり、PC88Behavior 側での自己確認は
`docs/notes/l4-mbf-oracle.md`「l4-s4e: GW-BASIC本来の判定規則の組み込み」
に記録した。

---

## 0. 調査範囲と記号

対象は指定された GW-BASIC ソースだけである。Web、`PC88Behavior`、他の Microsoft BASIC のソースは参照していない。行番号はコミット `edf82c2` として指定された作業ツリーを `nl -ba` で数えた番号である。このツリーでは、質問文のルーチンは次のファイルに分かれている。

- `GIO86.ASM`: 通常の `PRINT` ドライバ
- `MATH2.ASM`: `$FOUT`, `$FOUT2`, `$FOTNV`, `$FOTCV`, `$FOTAN`, `$FOTED`, `$SIGD`
- `MATH1.ASM`: `$FOFMT`, `$PUEXP`, `$FOTZS`、10 の冪テーブル

以下の記号を使う。

- `N`: 出力する10進有効桁数。単精度は 7、倍精度は 16。
- `v`: 符号を除いた非ゼロ値。
- `E`: `v=d.ddd...×10^E`（`1<=d<10`）の通常の10進指数。
- `A`: `$FOTNV` が AL に返す「complementing exponent」。通常、`$FOTNV` 後の FAC を `B` とすると `v=B×10^A` であり、`B` は整数部に `N` 桁を持つので `A=E-N+1`。
- `R=INT(B+0.5)`: 出力時の正数に対する10進整数丸め結果。ただし、もともと整数なら `.5` は加えない。
- `t`: `R` の右端から続く 0 の個数。
- `s=N-t`: その末尾 0 を除いた有効桁数（通常ケース）。
- `k=-E-1`: `0<v<1` のとき、小数点と最初の非ゼロ数字の間にある 0 の個数。

「確認」は命令列・コメント・テーブルから直接確認できること、「導出」はそれらを代数的に置き換えた結果、「予測」はソースを実行せずに各入力へ適用した結果を表す。

## 1. `PRINT` から文字列完成まで

### 1.1 通常の `PRINT` から `$FOUT` へ（確認）

1. `GIO86.ASM:433-458` の `PRINT` は式を `FRMEVL` で評価する。
2. `GIO86.ASM:460-466` で文字列でないことを確認し、`CALL FOUT` する。
3. `GIO86.ASM:467-468` は `$FOUT` のゼロ終端バッファを `STRLIT` で BASIC 文字列にし、末尾に `PRINT` 用の空白を置く。質問の表ではこの周辺空白を除外する。

### 1.2 `$FOUT` の入口と型分岐（確認）

- `MATH2.ASM:789-804` の `S` は `$FBUFF+1` に正数用空白を仮置きし、負数なら `-` を置いて FAC を絶対値にし、次位置にゼロ用の `0` を仮置きする。
- `MATH2.ASM:806-812` の `$FOUT` はゼロならその `0` をゼロ終端して即 return する。
- 非ゼロなら `MATH2.ASM:813` の `$GETYP` へ進む。整数は `MATH2.ASM:814-820` の `$FOTCI` 経路、単精度・倍精度は `MATH2.ASM:821` から `$FOFMT` へ進む。
- `$GETYP` 自体は `MATH1.ASM:1517-1524`。`VALTYP=4` が単精度、`VALTYP=8` が倍精度であり（設定箇所は `MATH2.ASM:198-199`, `217-218`）、CF と parity flag を利用して両者を分ける。

### 1.3 `N` のロードと正規化（確認）

`$FOFMT` は次のように `N+1` を作る。

- `MATH1.ASM:1338`: 単精度を仮定して `AL=8`、コメントにも「print 7 digits」。
- `MATH1.ASM:1340-1341`: 単精度ならそのまま、倍精度なら `AL=17`。
- `MATH1.ASM:1342-1344`: `CH=CL=N+1` として保存。

`MATH1.ASM:1346-1348` が `$FOTNV` を呼ぶ。`$FOTNV` の契約は `MATH2.ASM:705-709` に「単精度 7 桁、倍精度 16 桁を FAC の整数部へ移し、補指数を AL に返す」と明記されている。

実装は次の通り。

- `MATH2.ASM:719-733`: `$FOTB` で二進指数から10の冪を選び、`MDPTEN` で FAC をその冪倍／除算し、逆向きの指数を DI に累積する。`MDPTEN` が正指数で乗算、負指数で除算することは `MATH1.ASM:1228-1249` で確認できる。
- `MATH2.ASM:735-744`: 単精度表現の `10^6` と比較し、必要ならもう一度 10 倍して補指数を 1 減らす。これで共通部分は 7 桁を整数部へ置く。
- `MATH2.ASM:745-755`: 単精度なら終了。倍精度ならさらに `10^9` を掛け、補指数から 9 を引くので、合計 16 桁になる。
- `MATH2.ASM:756-764`: 倍精度では、後の `.5` 加算が16桁整数をあふれさせるほど大きい場合に 10 で割って補指数を直す。境界 `HIDBL=9999999999999999` は `MATH2.ASM:772-776`。

`$FOTB` は `MATH1.ASM:526-560`、倍精度10の冪は `MATH1.ASM:572-611`（`$DP06` は `579`、`$DP09` は `582`）にある。

### 1.4 表記の決定と小数点位置（確認）

`MATH1.ASM:1349-1399` が本題の決定部である。詳しい式は次節に示す。決定後は以下のように文字列になる。

- 指数表記を表すときは CH を 3 にする（`MATH1.ASM:1396-1397`）。固定表記を表すときは AL を 2 にする（`1392-1395`）。
- `MATH1.ASM:1398-1402` の `DEC AL` 2 回で、指数表記なら AL が最終的な `E`、固定表記なら AL が 0 かつ ZF=1 になる。この ZF をスタックへ保存する。
- `MATH1.ASM:1403-1408` から `MATH2.ASM:510-535` の `$FOTAN/$FOTED` を使い、小数点と先行 0 を先に配置する。`$FOTAN` が ZF=1 で返った場合、`MATH1.ASM:1406-1408` が小数点直後に必要な `0` を一つ確定する。
- `MATH1.ASM:1409-1410` が `$FOTCV` を呼び、丸めた FAC を10進数字へ変換する。

### 1.5 丸め、桁テーブル、末尾 0 除去（確認）

`$FOTCV` は正数 FAC を整数に丸めてから数字を引き算で取り出す。

- 倍精度: `MATH2.ASM:556-583`。整数部と一致しなければ `$DADDH` で `.5` を加え、`$FTDNT` で整数化する。`MATH2.ASM:584-610` は `$FODTB` を使う 9 桁と、共通の後半 7 桁へ進む。したがって実命令は 9+7=16 桁である。`MATH2.ASM:543-546` の「10+3+3」というコメントは実命令・テーブルと一致しない古い説明である。
- 単精度: `MATH2.ASM:611-631`。整数でなければ `$FADDH` で `.5` を加え、`$QINT` で整数化する。
- 共通後半: `MATH2.ASM:634-671`。`$FOSTB` から 3 桁、続いて `$FCI4` から 4 桁、合計 7 桁を出す。`$FOSTB` は `MATH1.ASM:751-760`（`10^6,10^5,10^4`）、整数冪 `$FOITB` は `MATH1.ASM:761-770`。`$FCI4` の4桁ループは `MATH1.ASM:76-95`。

数字列ができた**後**、`MATH1.ASM:1411-1416` が右から文字 `0` を削り、直前が `.` ならそれも削る。指数表記なら `MATH1.ASM:1421-1444` の `$PUEXP` が、単精度は `E`、倍精度は `D`（`1423-1427`）、符号と必ず2桁の指数（`1431-1444`）を付加する。`MATH1.ASM:1445-1448` がゼロ終端し、文字列先頭と末尾ポインタを返す。

## 2. 固定／指数の正確な条件

### 2.1 ソースが直接使う量（確認）

`$FOTNV` 後の AL を `A` とする。`CH=CL=N+1` である。

1. `A>0`: `MATH1.ASM:1349-1351` から `FFM15`、さらに `FFM20` へ行き、無条件に指数表記。
2. `A<=0`: 型を復元し、倍精度は `A+16`（`MATH1.ASM:1363-1366`）、単精度は `A+7`（`1372-1375`）を調べる。
   - `A+N>=0` なら `FFM18`、固定表記。
   - `A+N<0` なら `$SIGD` を呼ぶ（`1376-1380`）。
3. `$SIGD` は元 FAC を保存し（`MATH2.ASM:1829-1833`）、必要なら `.5` を足して整数化し（`1839-1853`）、10 で割って戻す反復により右端の 0 ごとに CL を 1 増やす（`1854-1874`）。したがって返値は `CL=N+1+t`。
4. `MATH1.ASM:1381-1383` は `A+CL` を符号付きで調べ、`A+CL<=0` なら指数表記、`A+CL>0` なら固定表記。

### 2.2 通常の10進指数 `E` に直した式（導出）

通常ケースでは `A=E-N+1` なので、`|v|>=1`（`E>=0`）は単純になる。

```text
固定表記  <=> E <= N-1  <=> E < N
指数表記  <=> E >= N
```

`0<v<1` では、`E=-1` は `A+N=0` なので `$SIGD` を呼ばず固定表記。`E<=-2` では `$SIGD` の比較を代入すると、比較値を

```text
J = A + (N+1+t)
  = E + t + 2
  = E + N - s + 2
```

と書ける。

```text
固定表記  <=> J > 0
指数表記  <=> J <= 0
```

さらに `k=-E-1`, `s=N-t` を代入すると、同じ条件は最も直観的に次となる。

```text
固定表記  <=> k+s <= N
指数表記  <=> k+s > N
```

つまり、1 未満では「先頭の 0 と、末尾 0 を除いた有効数字を合わせて N 桁以内なら固定」である。境界 `J=0` は `JLE FFM20` なので**指数表記側**であり、不等号に曖昧さはない。

### 2.3 末尾 0 抑制の時期（確認）

実際の文字列から末尾 0 を消す処理は、表記判定と `$FOTCV` の**後**（`MATH1.ASM:1411-1416`）である。ただし小さい数の判定だけは、判定の**前**に `$SIGD` が「出力時と同様に丸めた整数」の末尾 0 を数える。したがって「削除処理そのものは後、削除できる桁数の先読みは判定前」が正確である。

## 3. `N` は何か所に現れるか／単精度6桁版

### 3.1 結論（確認）

`N` は1か所ではない。判定だけでも、(i) `N+1` の初期値と、(ii) `A+N` の深い小数判定という独立した2か所に現れる。さらに `$FOTNV` のスケールと `$FOTCV` の桁抽出テーブルにも埋め込まれている。

単に `MATH1.ASM:1338` の 8 を 7 にするだけでは、FAC はなお7桁へ正規化され、`$FOTCV` も7桁を出すため、「6桁版」にはならない。

### 3.2 構造を保つ6桁化（推測上の版の定義）

以下の予測表の (b) は、元の制御構造を N パラメータ化し、単精度だけ `N=6`、倍精度は `N=16` のまま、とした版である。必要な変更は次の通り。

1. `$FOFMT`:
   - `MATH1.ASM:1338` の単精度 `N+1`: `8D -> 7D`。
   - `MATH1.ASM:1373` の単精度しきい値: `ADD AL,7 -> ADD AL,6`。
   - 倍精度の `17D`（`1341`）と `ADD AL,16D`（`1364`）は不変。
2. `$FOTNV`:
   - 単精度の整数部を `[10^5,10^6)` にするため、`MATH2.ASM:735` の共通下限 `10^6` を単精度について `10^5` にする。
   - 現状はこの共通7桁化の後に倍精度だけ `10^9` を掛けて16桁にしている（`750-755`）。構造をそのまま共有するなら、共通部を6桁化すると同時に倍精度側を `10^10`、補指数減算を 10 にして、倍精度を 6+10=16 桁へ戻す。別案は型分岐を前へ出し、倍精度だけ従来の `10^6` と `10^9` を使うこと。どちらも意味は同じ。
3. `$FOTCV`:
   - 共通後半を 7 桁から 6 桁にするには、`MATH2.ASM:635` の最初のループ数を `3 -> 2`、`636` の開始を `$FOSTB -> $FOSTB+3`（`10^5` から）にし、後半4桁は不変にする。
   - そのままでは倍精度も 9+6=15 桁になるため、`MATH2.ASM:585` の倍精度前半を `9 -> 10` にする。`$FODTB` には `10^15` から必要な10項が既にある（`MATH1.ASM:681-750`）ので、10+6=16 桁を保てる。
4. 6桁丸めの桁上がり:
   - 元コードの単精度は格納精度と出力7桁が釣り合うため、`$FOTCV` の `.5` 加算で 7 桁が 8 桁になる一般的な高端ガードを持たない。一方、6桁化すると `999999.5` などが `1000000` に上がる。
   - したがって、倍精度の `HIDBL` 検査（`MATH2.ASM:756-764`）と同型に、6桁単精度では丸め前 `B>=999999.5` を 10 で割り `A` を 1 増やす正規化が必要である。以下の (b) はこのガードも含む。これがなければ先頭桁抽出が 10 となって ASCII `:` に達し、数値文字列ですらなくなる。

入力読取り側 `MATH2.ASM:53-61` にも `1000000` があるが、これは10進定数を単精度から倍精度へ昇格させる精度保護であり、出力 N の定数ではないので変更しない。

## 5. 追い切れなかった箇所と予測への影響

固定／指数の**判定そのもの**、`$SIGD` の丸め後末尾 0 計数、`$FOTCV` の桁数、小数点・指数付加、末尾 0 除去までは命令単位で追えた。ここに未解決の分岐はない。

一方、次は完全なビット列シミュレーションまでは行っていない。

1. 数値リテラル入力全体と単精度・倍精度除算の各内部丸め。
2. 仮想的な6桁版に新設する高端桁上がりガードの具体的な機械語定数と比較命令列。
