# l4-s5d — 条件分岐・比較・論理演算・配列・CONT — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

ゴールA（代表プログラムが動く）には`IF`〜`THEN`〜`ELSE`・比較演算・
配列が要るが、これまでの段階5の測定（`l4-s5a`〜`l4-s5c`）では未測定
のまま残っている。仕様書`docs/spec/l4-program.md`第2版（`9fee1e2`）の
未確定のうち、`CONT`・配列もあわせて本ノートで測る（`l4-s5c`は変数と
流れの制御の続きを別途測定中。中身は参照しない）。

## 問い

- Q1 `IF`の分岐（D1・D2・D6・D13・D15）
- Q2 比較演算の値（`真`・`偽`がどの数値で表されるか。D3〜D5）
- Q3 論理演算`AND`・`OR`・`NOT`の値（ビット単位か論理値かを含む。
  D7・D8）
- Q4 配列（宣言あり・宣言なし・範囲外。D9〜D11）
- Q5 `CONT`（`STOP`で止めたプログラムを`CONT`で再開できるか。D12）
- Q6 演算子`^`（べき乗）・`\`（整数除算）・`MOD`（剰余）の値（D14）

## 腕（15腕＋陽性対照1腕）

打鍵はこのまま使う（英字は小文字）。1腕＝`new`のあと行を打ち、最後に
`run`を打つ、という一連の打鍵を1つの`--type`文字列として与える
（`l4-s5a`〜`l4-s5c`と同じ作法）。D12のみ、`run`の後に`cont`を別の
`--type`区間として打つ（下記「D12の扱い」参照）。

| 腕 | 打鍵文字列（`\n`は改行） | 目的 |
|---|---|---|
| D1 | `new`/`10 if 1<2 then print 1`/`run` | Q1 真の分岐 |
| D2 | `new`/`10 if 2<1 then print 1 else print 2`/`run` | Q1 ELSE分岐 |
| D3 | `new`/`10 print 1<2`/`run` | Q2 真の値 |
| D4 | `new`/`10 print 2<1`/`run` | Q2 偽の値 |
| D5 | `new`/`10 print 1=1`/`run` | Q2 等号 |
| D6 | `new`/`10 a=3`/`20 if a>2 then 40`/`30 print 1`/`40 print 2`/`run` | Q1 THEN後の行番号 |
| D7 | `new`/`10 print 3 and 5`/`20 print 3 or 5`/`run` | Q3 AND/OR |
| D8 | `new`/`10 print not 0`/`run` | Q3 NOT |
| D9 | `new`/`10 dim a(3)`/`20 a(2)=7`/`30 print a(2)`/`run` | Q4 宣言あり配列 |
| D10 | `new`/`10 a(5)=1`/`20 print a(5)`/`run` | Q4 宣言なし配列 |
| D11 | `new`/`10 a(11)=1`/`20 print 1`/`run` | Q4 宣言なし配列の範囲外 |
| D12 | `new`/`10 print 1`/`20 stop`/`30 print 2`/`run`、続けて`cont` | Q5 CONT |
| D13 | `new`/`10 if 1 then print 5`/`run` | Q1 0以外を条件に |
| D14 | `new`/`10 print 2^3`/`20 print 7\2`/`30 print 7 mod 2`/`run` | Q6 演算子 |
| D15 | `new`/`10 if 1<2 and 3<4 then print 8`/`run` | Q1 複合条件 |

### 陽性対照（1腕、腕数には含めない）

直接モードの`print 7717`（`l4-s4a`以来使ってきた陽性対照と同一）。

- 打鍵文字列: `print 7717\n`（文字数11）
- フレーム計算式は下記「条件・関門」節の全腕共通の式をそのまま使う:
  `line_end = 700 + 8*11 = 788`、`dump = line_end + 300 = 1088`、
  `run = dump + 200 = 1288`（`l4-s5c`の作法を踏襲し、陽性対照のフレーム
  式も本文に明記する）。

腕の総数: **15腕**（D1〜D15）。各腕2走（決定論性の関門G3）。

## D12の扱い（RUN後にCONTを打つ）

D12は`run`で`STOP`により止まった後、**`run`の出力が完全に終わって
から**`cont`を打つ。フレームの決め方は次のとおり。

```
d12a = "new\n10 print 1\n20 stop\n30 print 2\nrun\n"
n1          = len(d12a)   （改行を含む文字数の合計）
line_end1   = 700 + 8 * n1
dump1       = line_end1 + 300   （runの出力完了の確認用の写し。関門G8
                                   をここでも適用する）
type_at2    = dump1              （dump1の時点でOk行〔STOPの応答〕が
                                   現れていることをG8で確認した後、
                                   同じフレームから続けて打鍵を再開する）
d12b = "cont\n"
n2          = len(d12b)
line_end2   = type_at2 + 8 * n2
dump2       = line_end2 + 300
run2        = dump2 + 200
```

`run`の出力（`STOP`の応答を含む）と`cont`の出力を**分けて記録する**
（下記「記録する内容」節）。写しは3枚（打鍵前、`run`後、`cont`後）を
取る。

## 条件・関門

`l4-s5c`（`09c933a`）の「条件・関門」節をそのまま踏襲する。

- 起動settle`--type-at 300 --type '\n'`、実打鍵開始`--type-at 700`
- 1文字あたり`hold+gap=8`フレーム/文字（`\n`も1文字として数える）
- フレーム計算式（全腕共通。陽性対照にも同じ式を適用する）:
  ```
  line_end(k) = 700 + 8 * (その腕で打った文字数の累計。\n も1文字。
                            複数行にわたる打鍵は全体を1つの--type文字列
                            として与え、文字数は改行を含めた合計)
  dump(k)     = line_end(k) + 300
  run(k)      = dump(k) + 200
  ```
- 写しは打鍵前（`--type-at`の10フレーム前=690）と`dump(k)`後の2枚を
  `--diff-before`/`--diff-after`に渡す（D12を除く。D12は「D12の扱い」
  節のとおり3枚）。
- 複数行を打つ腕は、行ごとの打鍵の間隔が上記の式で正しく積み上がって
  いることと、`RUN`の後の実行と表示が写しの時刻`dump(k)`までに終わって
  いること（関門G8）を確認する。

## 記録する内容

`l4-s5c`と同一の手順を踏襲する。

- **`Ok`行の位置（打った行からの相対行）と、`RUN`の後に出た行の数を、
  すべての腕で必ず記録する。**
- 出力行（`RUN`の後に現れる行）は、**行ごとに**`l4-s4a`の数値分類器
  （`tools/l4_s4a_float_classify.py`、`5735eb3`）を適用する。
  `numeric_output`と分類された行は、(相対行, 相対桁, 文字コード)の
  並びをそのまま記録する。それ以外の行（エラー・`Ok`自身の文字列等）
  は、件数と位置の範囲だけを記録する。コード・文言は一切出さない。
- **D11（配列の範囲外）**: `10 a(11)=1`によって誤りが起きる想定の腕
  であり、Q4の該当項目は**出力行数と`Ok`の位置だけを記述する**（依頼
  文のとおり。誤りの行そのものは、上記の分類規則により`non_numeric_
  output`として件数と範囲だけの記録になる）。
- **D12（`CONT`）**: `run`の後の出力（`STOP`までの応答）と、`cont`の
  後の出力（再開後の応答）を、それぞれ別の表として結果ノートに記録
  する。両方とも同じ分類規則（数値行はコード、それ以外は件数と範囲）
  を適用する。

## 本文を出さない取り扱い

`l4-s4a`〜`l4-s5c`と同一。「記録する内容」節の分類規則に従い、
`numeric_output`の行だけコードを記録し、それ以外は件数と範囲だけに
する。分類器（`tools/l4_s4a_float_classify.py`）は集合外のコードを
標準出力・標準エラーへ出さない設計であることが`5735eb3`の時点で確認
済み。

## 関門

`l4-s5c`のG1〜G5・G8と同一（G6は対になる予測表が無いため本測定にも
適用しない）。

- G1 器具の自己検査: 測定時HEADで`tools/harness/vram_dump_selftest.sh`・
  `tools/harness/vram_dump_dynamic_selftest.sh`・
  `tools/harness/key_matrix_selftest.sh`・
  `tools/harness/type_untypable_selftest.sh`・
  `tools/screen_content_leak_selftest.sh`の全項目がOK
- G2 取りこぼし0・打てない文字の警告0（全走のstderrで確認。`\`（`¥`
  キー）が打てない場合は該当する腕〔D14〕のみ`gate_failed`とする）
- G3 決定論性: 各腕2走とも、写しはファイルのsha256が一致、記録は
  sha256が一致（D12は`run`後・`cont`後それぞれで確認する）
- G4 陰性対照: 何も打たない走（起動settleのみ）で差分0件
- G5 陽性対照: 直接モードの`print 7717`腕で`7717`の並びを確認
- G8 出力完了の確認: 「後」の写しで、出力行の後に`Ok`行が現れている
  こと。D12は`run`後の写し・`cont`後の写しの両方で確認する。現れない
  腕は`gate_failed`とし、「写しが早すぎた」とだけ記述する

判定の前にG1〜G5・G8がすべて真であること。いずれかが偽の腕は、その
腕を`gate_failed`として判定に含めず、理由を記述する。

## 判定

判定名はこの事前登録に書いたものだけを使う。「記録する内容」節を
参照する。当てはまらない形はすべて`other`とし、記述で補う。

- Q1（D1・D2・D6・D13・D15）: `branch_ok`（`THEN`側・`ELSE`側それぞれ
  期待どおりの分岐先が実行される）／`other`
- Q2（D3〜D5）: 記述に加え判定を付ける。`true_is_minus1`（真が`-1`と
  して出力される）／`true_is_1`（真が`1`として出力される）／`other`。
  各腕の値をそのまま記述する。
- Q3（D7・D8）: 記述に加え判定を付ける。`bitwise`（`AND`・`OR`・`NOT`
  がビット単位の演算として振る舞う。D7の結果がビットANDと一致するか
  で判定する）／`other`。各腕の値をそのまま記述する。
- Q4（D9・D10）: `array_ok`（宣言・代入・参照が期待どおりに機能する）
  ／`other`。D11は判定名を付けず、出力行数と`Ok`の位置を記述する
  （「記録する内容」節のとおり）。
- Q5（D12）: `cont_resumes`（`cont`の後、`30 print 2`相当の出力が
  現れる）／`other`
- Q6（D14）: 記述のみ（判定名は付けない）。`^`・`\`・`MOD`それぞれの
  出力値をそのまま書く。
- `gate_failed`: 関門のいずれかが偽だった腕。判定に含めず、理由を
  記述する。

## 器具の確認（公式ROMは使わない）

測定開始前に、自作main ROM（測定時HEAD`9fee1e2`から`src/build_main_
rom.py`で組み立て）に対し、15腕（D12は「D12の扱い」節の2段階打鍵）＋
陽性対照の計16腕すべてを打鍵し、各行のエコーが打鍵どおりに届くかを
`tools/l4_vram_probe.py --marker`（各腕の打鍵文字列を`\n`で分割し、
各行をそれぞれmarkerとして指定）で確認した。**自作ROMはまだプログラム
モードを持たないため、実際の`RUN`・`IF`・配列・`CONT`の挙動は見ておら
ず、エコーだけを確認した。**

結果: **16腕すべてで、全行のエコーが打鍵どおりに出現した**（腕ごとの
全行でmarker一致、打鍵前の走行失敗〔型チェックによる事前拒否〕も
無し）。`<`・`>`（D1〜D6・D15）、`=`（D5）、`^`（D14）、`(`・`)`
（D9〜D11）を含め、届かなかった記号は無かった。

**`\`（D14の`7\2`）について特に記録する。** PC-88のキーボードでは
`\`は`¥`キー（スキャンコード`05/4`）に当たり、仕様書`docs/spec/
l3-main.md`の既存のキー測定（255行目・405行目）では`¥`キーがASCII
`0x5C`として届くと記録されている。本ノートのエコー確認では、`--marker`
にPython文字列としての`\`（`0x5C`）をそのまま渡し、`20 print 7\2`と
いう行全体が1件でmarker一致したことから、**`\`は打鍵注入でも`0x5C`
として届いていることを確認した**（一致判定はマーカーのバイト列と画面
の文字域バイト列の完全一致によるため、`0x5C`以外のコードで届いていれ
ば不一致になっていたはずである）。

作業に使ったROM・写し・スクリプトはリポジトリ外の使い捨てディレクトリ
（scratchpad配下）に置き、確認後に削除した。
