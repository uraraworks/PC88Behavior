# B15: 公式の上の G1 で、サブの RAM から ROM へ飛ぶ番地と、RAM へ書く範囲を測る — 事前登録

記録日: 2026-10-31
位置づけ: [B14](b14-g1-request-headers-results.md) の次段。[方針ノート](goal-b-policy-2026-10-24.md)第2節・第3節の「需要」をサブ側で測る。
**このノートは測定より先にコミットする。** 結果を見てから規則を変えない（変えるときは後続ノートで）。

## 1. 問い

1. G1 のサブ RAM 上のコードは、公式サブ ROM の番地へ飛ぶか。どの番地へ、何回か
2. G1 の要求で、サブの RAM のどの番地の範囲へ書き込まれるか

## 2. 器具

`q88measure` にサブ側の記録を足す（`--sub-boundary-log`）。main 側の [境界の記録](b1-g1-demand-preregistration.md) と同じ形で、番地と回数だけを持つ。

- **記録 A:** サブの PC が `0x2000` 以上から `0x2000` 未満へ移った命令について、飛び先・種別（call / jump / 割り込み）・回数・RAM へ戻った回数
- **記録 W:** サブの RAM（`0x4000` 以上）への書き込みの番地と回数。発行元が ROM か RAM かの別も持つ。**値は持たない**

器具は G1 を使わずに自己検査する: 陽性対照（自作の試験コードで横断が記録される）、陰性対照（ROM 内どうし・RAM 内どうしは記録されない）、値が出ないこと。

## 3. 条件

OO・SS 各 2 走（自作は 2a4f910）。条件は B13 と同じで、クラウドの実行環境で行う。B13 と同じ対照を通し、`--sub-boundary-log` が走を変えていないことを main の境界記録の一致で確かめる。

## 4. 判定（事前に決める）

- **再現:** 同じ腕の 2 走が一致するか
- **サブ ROM への飛び先:** OO の記録 A の飛び先を全部並べる。1 つも無ければ「G1 のコードは公式サブ ROM を呼ばない」と書く
- **書き込み範囲:** OO の記録 W を連続区間にまとめ、発行元の別とともに書く。SS の区間と並べる
- 飛び先の働きは、この測定では決めない。自作のプローブで別に測る

## 5. 記録の白リスト

`A <4桁16進> <total> <call> <jump> <int> <ret>`、`W <開始>-<終了> <rom|ram> <回数>`、走の条件の行だけ。全行を検査してから書く。

## 6. 記録しないもの

書き込みの値、サブの RAM の内容、発行元の番地、レジスタ、ディスクのバイト列、画面本文、ゲーム名やファイル名。
