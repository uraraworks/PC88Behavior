### G4（要因直交のバイト照合）

本測定の主張を支える関門である。10項目すべて OK だった。

- C0 の一式が凍結値 `4c2fe213…` と一致（= m6i-b B5 の一式）
- C1 の一式が凍結値 `904dd024…` と一致（= m6i-b B6-A0 の一式）
- C2 の `N88.ROM` は C0 と、`DISK.ROM` は C1 とバイト一致
- C3 の `N88.ROM` は C1 と、`DISK.ROM` は C0 とバイト一致
- 4腕を通じて `N88.ROM` は2種類、`DISK.ROM` も2種類しか存在しない
- 残り5ファイルは4腕で全て同一、7ファイルすべてが所定サイズ

**したがって、要因M（main の枝タグ）と要因S（sub のゲート）は成果物の
バイト単位で直交している。** m6i-b の B5 対 B6-A0 が抱えていた交絡は、
ここで解けている。

なお `check_m6ic_rom_gate.py` の10項目それぞれに陰性対照を1つずつ置き、
「`passed=false` になった」だけでなく **NG になった項目の集合まで照合**して
いる。検出力の示されていない検査項目を関門に数えないためである。

## 3. 腕ごとの結果

いずれも2走で同一。

| 腕 | main | sub | 結果種別 | 要求run | ゲートrun | 解除 |
|---|---|---|---|---:|---:|---|
| C0 | 枝タグなし | ゲートあり | timeout | 0 | 1本 | されず |
| C1 | 枝タグあり | ゲートなし | 256位置一致 | 1 | 0本 | — |
| C2 | 枝タグなし | ゲートなし | **256位置一致** | 1 | 0本 | — |
| C3 | 枝タグあり | ゲートあり | **timeout** | 0 | 1本 | されず |

- **C0 `c0_reproduced`**: m6i-b B5 の timeout を再現した。要求 run は0件。
- **C1 `c1_reproduced`**: m6i-b B6-A0 の256位置一致を再現した。
- **C2 `c2_success`**: 期待SHA一致、定常入力待ちへ復帰、要求 run 1件。
- **C3 `c3_failure`**: timeout、要求 run 0件。

**再現腕2つがどちらも再現した。** したがって要因の帰属へ進める。

## 4. 総合判定

**`m6i_c_sub_gate_only`**。

`c2_success` かつ `c3_failure` である。すなわち:

- main の枝タグを持たないままでも、sub のゲートを外せば成立する（C2）
- main の枝タグを持っていても、sub のゲートを付ければ失敗する（C3）

**成否を決めていたのは要因S（sub のラウンド#0直後のスピンゲート）だけであり、
要因M（main の枝タグ格納）は効いていない。**

## 5. 副問

> **後日の訂正（2026-09-23）**: 本節の `gate_never_released` という帰属は誤りである。
> 観測していた長い run はゲートではなく sub の通常の待ちループ `IDLE_DISPATCH` であり、
> ゲートは最初のポーリングで抜けていた。詳細と裏取りは
> [m6i-c 副問の訂正](m6i-c-subquestion-correction.md) と
> [m6i-d 第1回の試行](m6i-d-attempt1-instrument-failure.md) を見よ。
> **§4 の総合判定 `m6i_c_sub_gate_only` と §3 の腕ごとの結果は訂正しない。**
> 以下の本文は記録として当時のまま残す。

G8-2 の陰性対照が成立した。**ゲートを持たない C1・C2 では、ゲート run が
2走とも0本だった。** `gate_run_min_length` = 32 が通常のポーリングを拾って
いないことを、測定そのものの中で示せている。したがって
`gate_observation_unusable` にはならず、副問の帰属ができる。

C0・C3 の副問判定は**どちらも `gate_never_released`** だった。
ゲート run へは入り（`gate_entered` = 真）、測定終了まで一度も抜けていない
（`gate_released` = 偽）。ゲート run の長さは測定期限いっぱいまで伸びていた。

**つまり sub は、main の通常SEND開始を最後まで検出できないまま、ゲートの中で
回り続けていた。** m6i-b 結果 §6 が挙げた2つ目の切り分け対象
（「sub 側の停止ゲートがラウンド#0の後に置かれたとき、main の通常SEND開始を
取りこぼすことがあるか」）は、**取りこぼす**という形で決着した。

## 6. 得られたこと

- **m6i-b の B5 が示した timeout は、測定器具の副作用である。**
  自作 sub の状態が通常READを許さなかったのではなく、測定のために置いた
  停止ゲートが解除されなかった。
- **したがって m6i-b の B5 を、状態境界の証拠として使ってはならない。**
  m6i-b で境界判定7種がどれも成立しなかったのは、7種が共通要件に含む
  `abc_sufficient` が B5 で崩れたからであり、その崩れ方が器具由来だった。
- **枝タグ格納は無関係だった。** m6i-b 結果 §6 が最初に疑った要因は、
  ここで否定された。
- **要因が交絡していたことを、バイト一致で解いた。** 実行時の観測ではなく
  成果物の同一性で直交を示す形は、同種の切り分けで再び使える。

### m6i-b の他の腕も同じゲートを使っている

本測定の結果を受けて `src/l3_service/make_subrom.py` を確認したところ、
**停止ゲートの生成ヘルパ `_emit_m6ib_release_gate` は B1・B2・B3・B4・B5 の
5腕すべてで使われていた。** 違うのは置かれる場所だけである
（B1 はリセット直後、B2 は FDC 初期化の手前、B3 は初期化の後、B4 は
ラウンド#0の手前、B5 はラウンド#0の後）。

**しかしゲートは一律に致命的ではない。** m6i-b で B2 と B4 は256位置一致で
成立しており、それらのゲートは解除されている。解除されなかったのは、本測定で
確かめた B5 のゲート（ラウンド#0の後に置かれたもの）である。

ここから、**m6i-b で timeout だった B1 と B3 の解釈も疑わしくなる。**

- B1 は陰性対照であり、sub を停止させたまま60フレーム待ち、解除と同時に
  通常READを出す設計だった。**ゲートが解除されなければ sub は再開しない。**
  そのとき出る timeout は「60フレーム待っただけでは足りない」という
  状態の話ではなく、器具の話である。
- B3 も同様に、ゲートの解除を前提にした腕である。

**本測定は B1・B3 のゲートが解除されたかを測っていない。** 測っていない以上、
ここで「B1・B3 も器具由来だった」と結論しない。**疑いが生じたという事実だけを
記録し、m6i-d で測る。**

## 7. この測定で決まらないこと

事前登録と追補から引き継ぐ。

- 公式ROM内部の実装、公式の送受信値、実機での絶対時間は決まらない。
- **通常READを許してよい最早時点は決まらない。** `docs/spec/l3-subrom.md`
  1.65節が未確定として残した点は、依然として未確定である。本稿は
  m6i-b の B5 が使える証拠かどうかだけを決めた。
- **C2 の成立を `abc_sufficient` として読み替えない。** C2 は B5 と同じ
  `b→a→c` 前置きを持ち、ゲートを持たない腕なので、m6i-b の B5 が本来
  測ろうとしていたものに近い。しかし m6i-c は B0〜B4 との比較を持たないため、
  境界の位置をここで決めることはできない。**境界判定7種は別稿で取り直す。**
- 要因S のゲートは測定専用の介入であり、公式 sub がそのような待ちを持つとは
  主張しない。ゲートが解除されなかったことは器具の性質についての知見であり、
  公式の挙動についての知見ではない。**仕様書へ書かない。**
- m6i-b の B6-A2 が到達しなかったことは本稿の対象外である。
- 別媒体、WRITE、複数セクタREAD、BASIC命令一般へ一般化しない。

1. **m6i-b の結果ノートと総合判定 `m6i_b_inconclusive` は書き換えない。**
   測定の記録は記録のまま残す。読み方の訂正は
   [m6i-c 準備](m6i-c-arm-difference-correction.md) と本ノートが引き受ける。
2. **ゲートを使わない前置き腕で、m6i-b の境界判定7種を取り直す追補を
   別稿（m6i-d）で事前登録する。** §6 のとおり B1〜B5 は5腕とも同じゲートを
   使っているので、取り直しの対象は B5 だけではない。m6i-d では少なくとも
   次を先に決める。

   - **各腕のゲートが解除されたかを、腕ごとに観測量として出す。**
     本稿と同じく I/O ログの sub run から取れるので、ROM は変えなくてよい。
   - 解除されなかった腕の結果を、状態についての結果として読まない。
   - 可能なら停止方式そのものをゲートに頼らない形へ置き換え、置き換えた腕と
     置き換えていない腕をバイト一致で直交させて比べる（本稿の G4 と同じ形）。
3. 1.65節への規則の追加は、m6i-d が境界を確定させるまで行わない。
