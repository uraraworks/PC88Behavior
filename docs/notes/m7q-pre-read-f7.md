# m7q: sub側222件目とREAD DATA直前の制御出力

測定日: 2026-08-13

## 1. 情報境界

第34版自作sub ROMの混成ログと公式基準ログを、CPU・方向・ポートだけで比較した。
データポート値は伏せたまま使用していない。比較器の自己検査は全件合格した。

## 2. 222件目の構造差

sub側の畳み込み後構造列は221件まで一致した。公式subはSENSE DRIVE STATUSの
結果入力直後、READ DATAのステータス確認へ入る前に制御出力を1件発行する。
自作subはこの制御出力を省き、直接FDCステータス読みへ進んでいた。

公式4条件の同じ遷移で、SENSE DRIVE STATUSの結果入力、制御出力、READ DATAの
ステータス確認が隣接することを確認した。結果フェーズ後のTC三つ組みと異なり、
後続の確認入力を伴わない単発形である。値と方向は仕様書1.5節で確定済みの
`$F7`制御と同じであり、新しい値推測は行っていない。

## 3. 測定時点の到達点

- sub側構造的一致プレフィックス: 221件
- main側構造的一致プレフィックス: 258件
- main側単発送受信列の値一致プレフィックス: 4件
- 混成照合のmain `IN $FD`: 0件

生ログと一時解析物はリポジトリ外に置き、コミットしない。この境界で単発形を
選ぶ内部判定理由は未確定のまま残す。

## 4. 第35版実装後の再測定

仕様書1.28節・6節27項だけを根拠に、SENSE DRIVE STATUSの結果入力直後、
READ DATA前へ単発の制御出力を追加した。後続の確認入力は追加していない。

最初の混成実走はエミュレータコアが異常終了してログを取得できなかった。コードや
条件を変更せず独立に再実行すると完走し、同条件の構造比較でsub側一致プレフィックスは
221件から255件へ伸びた。main側構造的一致プレフィックスは258件、main側`IN $FC`
値一致プレフィックスは4件、混成`main IN $FD`は0件で、いずれも変化しなかった。

次のsub側256件目はREAD DATAの入力反復終端で、公式subがデータ入力を続けるのに対し、
自作subがTC出力へ進む差である。公式側のデータ入力件数と、256件の実データに続く
結果部の境界を値を使わず再集計する必要がある。

`tools/verify_l3.sh`では既存の交換#3/#4・FDC・負の検出力試験が通り、既知の
ディスク無し時I/Oだけが引き続き不適合だった。期待値と比較条件は変更していない。
