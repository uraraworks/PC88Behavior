# 資料判定 2026-08-07 — 「工場のご案内」PC-8801 漢字ページ

URL: `http://www.kiwi-us.com/~ohta/pc88/kanji/index.htm`（`input.htm` / `other.htm` を含む）

## 判定: **見てよい。ただし L2 には効かない**

禁止事項1・2に触れるもの（ROM のダンプ、逆アセンブルリスト、グリフのビットマップ、
実行可能なソースコード）は**いずれも含まれない**。

## 何の文書か

PC-88 上で動いた各種日本語 BASIC（N88-日本語BASIC / 8801漢字BASIC /
新8801漢字BASIC / N88-漢字BASIC）の、**文字列の内部エンコーディング方式の比較**。
KI/KO エスケープの有無、JIS コードの上位下位バイト順、Shift_JIS との対応など。
著者名と連絡先が明記された個人サイトで、素性は分かる側。

## 効く場所・効かない場所

- **L2（フォント/漢字ROM）には効かない。** 漢字 ROM の物理構造にも ANK の
  格納形式にも踏み込んでいない。文字コード表は gif 画像への参照で、
  本文に数値が書かれていない
- **L4（N88-日本語BASIC）では効く可能性がある。** 文字列を内部でどう持つかは
  BASIC の実装そのものなので、その段になったら読み直す価値がある

## 手順として記録しておくこと

1. **`https` では取得できない。** このホストは `*.m78.com` の証明書を返すので
   証明書名の不一致で失敗する。`http` のまま `curl` し、`iconv -f CP932` を通す。
   `web.archive.org` 経由も（少なくとも当方の環境からは）取得できなかった
2. **可否の判定には使い捨ての担当を立てた。** 中身を見る役が、見た結果として
   実装から外れられるようにするため。今回は「含まれない」判定だったので
   実害は無かったが、**判定の前に中身が本セッションへ入ってしまう経路を
   作らない**のが目的である（[[feedback_screen_sources_by_cover_not_toc]] と同じ考え方で、
   Web ページにはカバー・まえがきが無いぶん、読む主体を分ける形で代用する）
3. 判定係への指示には「バイト列・16進ダンプ・アセンブリを報告に引用するな。
   含まれていたという事実と、在り処の見出しだけ書け」を明記した。
   そうしないと判定の報告経由で汚染が伝播する
