# B48: main の `IN $FC` が、サブの出した列のどの位置を読んでいるかを値なしで測る — 事前登録

記録日: 2026-11-01
位置づけ: [B47](b47-g1-pio-handoff-results.md) の次段。**このノートは測定より先にコミットする。**

## 1. 問い

`IN $FC` の番号 i で読むのは、サブの `OUT $FD` の何番目か。公式と自作でその対応はどう違うか。違う範囲の読みを出したのは ROM 側か RAM 上のコードか。

## 2. 器具

コアは変えない。`--io-log` の生の記録から `k(i)`（読みの時点でサブが出した `OUT $FD` の数）を求めるツールを足す。行は次だけである。**値は出さない。**

- `at <i> ok=<k> sk=<k> ok-issuer=<RAM の PC|rom> sk-issuer=<RAM の PC|rom>`（i は 76300 と、76560〜76580 の全部、76826、76827）
- `offset-change <i> <k(i) の公式−自作>`（差が変わる位置。最大 64 行。超えたら `offset-change more`）
- `step arm=<OO|SS> range=<all|76315-76827> 0=<N> 1=<N> 2=<N> other=<N>`（`k(i+1)-k(i)` の分布）
- `issuer arm=<OO|SS> range=76570-76827 rom=<N> ram=<N>`

器具は G1 なしで自己検査する。陽性対照は合成の記録で k の数え方、差の変わる位置、発行元の別。陰性対照は値が出ないこと、ROM 側の番地が出ないこと。

## 3. 条件

腕 F の 4800 フレーム。OO・SS 各 2 走。自作 ROM は 62254d3 と同じソースの配布ビルド。クラウドの実行環境で行う。

関門: `IN $FC` の差が B44 と同じ。OO どうし・SS どうしの出力が同じ。取りこぼしが無い。

## 4. 記録の白リスト

第 2 節の行だけ。

## 5. 判定（事前に決める）

- 違う範囲で `k` の差があるか、発行元が ROM か RAM かをそのまま書く
- 差が 76570 で変わるなら、そこを書く
- 原因は断定しない
