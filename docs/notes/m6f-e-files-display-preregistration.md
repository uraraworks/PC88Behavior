# m6f-e — `FILES` の画面表示形式 — 事前登録

記録日: 2026-09-26  
状態: **測定前**

## 0. 位置づけと担当範囲

[m6f-d 結果](m6f-d-disk-rules-results.md)と
[L3 ディスク形式 第3版](../spec/l3-disk-format.md)により、ディレクトリを読む側は
(18,1,1)〜(18,1,12) の16バイトエントリを先頭から読み、先頭 `0xFF` で止まり、
先頭 `0x00` を削除済みとして飛ばすところまで決まった。本稿は、そのエントリを
公式ROMの `FILES` が**画面へどう配置するか**を決める。媒体の形式を再測定する稿ではない。

実装はまだ行わない。本稿で凍結するのは、問い、候補規則、媒体、腕、器具の要件、関門、
判定名、結果の行き先である。公式ROMの測定と `src/l4_basic/` の実装は本稿の後に分ける。

### 0.1 クリーンルーム境界

- `CLAUDE.md` の禁止事項1〜7を適用する。公式ROMのバイト列、逆アセンブル、公式ディスクの
  バイト列、測定終了時の画面本文は読まず、出力せず、保存しない。
- `tools/make_n88_blank_disk.py`、同 selftest、`vendor/`、QUASI88 の `image.c`、および
  m7eb 系ノートは開かない。本稿の作業中にも開いていない。
- ドライブ1の参照 diskA 複製は起動だけに使う。参照 diskA が挿入されたままのドライブ1へ
  `FILES`、`FILES 1`、または不正引数がドライブ1へフォールバックしうる命令を送らない。
- 生の像、入出力ログ、署名化前の画面はリポジトリ外にも残さない。測定結果として残してよい
  ものは、行番号、各行の文字数、各行の SHA-256、画面全体の行数・文字数・SHA-256、
  候補との一致／不一致、導出した規則名、エラー番号などの意味へ還元した値だけとする。
- 参照 diskA 複製の測定前後 SHA-256 は同一であることだけを記録し、値自体は本稿の結果には
  要らない。公式ディスクのディレクトリ名・件数・画面署名は導出へ使わない。

### 1.2 N88-BASIC リファレンスマニュアル

採用資料は `../refs/NEC PC-8801mkIIMR N88-BASIC N88-日本語BASIC REFERENCE MANUAL 1986年.pdf`。
NEC純正の言語リファレンスであり、表紙とまえがきは、N88-BASIC/N88-日本語BASICの機能・命令を
プログラミング経験者向けに説明する書物だと述べている。今回読む命令の機能・書式・実行例は
外部から打鍵と画面で測定できる言語仕様で、ROM内部構造・番地・逆アセンブルではないため可とした。

読み方は `pdftoppm -f N -l N -r 150 -png` でページ画像化する方法だけとした。位置確認用の
一時画像を別解像度でも作ったが、下表の全ページを最後に150dpiで再画像化して照合した。
`pdftotext`、PDF内テキスト検索、`grep`、`strings` は使っていない。画像は一時ディレクトリに置き、
リポジトリへ入れない。

読んだPDF物理ページは次のとおり。

| PDF | ページ | 用途 |
|---|---|---|
| `PC-8801mkII_BASIC_Refference_Manual_N88BASIC.pdf` | 1 | 候補資料の表紙だけ。採用規則には使わなかった |
| 採用資料 | 1〜8 | 表紙、注意、内表紙、まえがき、構成、用語。可否判定 |
| 採用資料 | 9〜16 | 目次。`FILES/LFILES` が本文ラベル2-79にあることを確認 |
| 採用資料 | 148〜152 | PDFページと本文ラベルの対応を探すために開いた近傍。規則には使わない |
| 採用資料 | 160〜162 | 前後を含む命令項目。**161（本文ラベル2-79）が `FILES/LFILES`** |

物理161頁から採った仮説の出所は次だけである。実行例の画面本文はここへ転記しない。

- 書式は `FILES [<ドライブ番号>]`、プリンタ向けの別命令は `LFILES [<ドライブ番号>]`。
- ドライブ番号省略時はドライブ1。
- 表示対象はファイル名、種類、大きさ。種類は名前と拡張子の間の区切り記号で表す。
- 区切り記号には空白・ピリオド・アスタリスクの3種が説明され、ASCII保存のプログラムまたは
  データ、バイナリ保存のプログラム、`BSAVE` の機械語プログラムを区別する。
- 大きさはクラスタ単位。
- 実行例は1行に複数件を横へ並べる。件数、セル幅、空白の扱い、折返し規則は文章では明記されない。

資料は候補の出所にとどめ、測定と食い違えば測定を採る。

### 1.3 既存測定から引き継ぐもの

- `m7ci-error-and-drive2-paths.md`: `FILES "B:"` はFDCへ到達せず、`FILES 1`/`FILES 2` は
  それぞれのドライブを選んだ。前者の画面本文・エラー番号は記録されていない。
- `m7lu`・`m7lw`: ドライブ2が未挿入の `FILES 2` では、公式subは SENSE DRIVE STATUSを
  繰り返し、媒体の挿入を待つ。挿入すると続行した。したがって、既存ノートに
  **未挿入時のエラー番号は無い**。エラーへ到達した記録ではなく、待機の記録である。

本稿では未挿入を「エラー番号が出るはず」と決めず、`waits_for_media` を第一候補に置く。

10. ドライブ未挿入は待機かエラーか。エラーなら番号はいくつか。

## 3. 事前に置く54候補

候補IDは `files_layout_rule_<L>_<N>_<T>_<S>` とし、次の直積 **3×2×3×3=54候補**を
凍結する。候補から予測画面を作るときだけ自作名の文字列をメモリ内で組み立て、予測本文も
ファイル・標準出力へ書かない。予測値ファイルに置くのは行番号・文字数・SHA-256だけとする。

### 3.1 配置 L（3候補）

| ID | 規則 |
|---|---|
| `G5` | 80桁を16桁セル×5件として使い、件の途中では折り返さない |
| `G4` | 80桁を20桁セル×4件として使い、件の途中では折り返さない |
| `PACK` | 各件の最小表現を1空白で連結し、次の件全体が80桁へ収まらなければ次行へ送る |

`G5` はマニュアル実行例の第一解釈、`G4` は大きさ欄を広く取る解釈、`PACK` は見かけ上の
空白が固定セルでなく各欄の詰め物だけである解釈である。1件/行は実行例と両立しないため
候補へ入れない。実測が3候補すべてと違えば `inconclusive_layout` とする。

### 3.2 名前 N（2候補）

| ID | 規則 |
|---|---|
| `SPLIT63` | 名前欄の先頭6バイトを名前、末尾3バイトを拡張子とし、その間に種別印を置く。各欄の空白詰めは欄幅を保つ |
| `RAW9` | 9バイト全部を1つの名前欄とし、末尾の空白詰めの後ろに種別印を置く |

第3版では9バイトが名前＋拡張子に分かれるか未確定である。物理161頁の説明は分割を示唆するが、
媒体測定で裏を取るまで `SPLIT63` に決めない。

### 3.3 種別印 T（3候補）

| ID | `0x80` | `0x00` |
|---|---|---|
| `80DOT_00BLANK` | ピリオド | 空白 |
| `80BLANK_00DOT` | 空白 | ピリオド |
| `BOTHBLANK` | 空白 | 空白 |

第3版の `0x80`=プログラム、`0x00`=データとマニュアルの説明を合わせると
`80DOT_00BLANK` が第一候補である。ただし、種別印がこの1バイトだけで決まること自体を
まだ測っていないため逆対応と無印も残す。アスタリスクの媒体上の値は本稿では決めない。

### 3.4 大きさ S（3候補）

| ID | 規則 |
|---|---|
| `UNITS` | FAT鎖に含まれる割り当て単位の個数を10進表示 |
| `SECTORS` | 最終値 `0xC0+u` の `u` と、それ以前の単位ごとの8セクタを合計して10進表示 |
| `NONE` | 数値欄を表示しない |

数値は最小桁数で、直前に1空白を置くものとして予測する。実測が桁揃えだけで外れた場合は
勝手に最近傍候補へ寄せず `inconclusive_size_alignment` とし、追補で桁幅候補を置く。

### 3.5 54候補に共通する規則

- 生きたエントリを媒体上の順に出し、削除済みを飛ばし、最初の未使用で止まる。
- 見出し・空き容量・件数などの追加行は無い。通常終了後の既知の入力待ち行と、予約された
  ファンクションキー行は表示規則そのものに数えない。
- 0件ではエントリ行は0行。
- 画面下端では [l3-main.md](../spec/l3-main.md) 第15節の既知のスクロール範囲に従い、
  エントリを省略・停止しない。

この共通部のどれかが外れたときは、その軸だけを事後に足して54候補を救済しない。
`inconclusive_order`、`inconclusive_extra_lines`、`inconclusive_empty`、
`inconclusive_overflow` の該当名で止め、新しい事前登録を置く。

## 4. 自作媒体

### 4.1 作り方

基礎像は `tools/make_m6fc_blank_disk.py` の `build_blank_disk` で作り、第3版だけを根拠に
次を上書きする専用器具を後で追加する。

- 割り当て表3セクタは同一。位置74・75を `0xA0`、空きを `0xFF`、各自作ファイルの鎖を
  第3版 §2.4どおりに置く。
- (18,1,13) は全 `0x00`。ディレクトリは (18,1,1) の先頭から16バイト単位で置く。
- 名前欄は自分で決めたASCII 1〜9文字＋ `0x20` 詰め。名前欄直後（0始まりオフセット9）は
  `0x80` または `0x00`、オフセット10は自作の先頭単位、11〜15は `0xFF`。
- 削除済み枠は先頭だけ `0x00` とし、残り15バイトも自分で決めた値にする。
- 残り最初の枠は全 `0xFF`。ファイル本体も自分で決めた一様値または通し番号だけで埋める。
- 公式ディスクからバイトを写さない。媒体生成器は、画面予測器を import せず、相互に独立させる。

### 4.2 名前・長さ・種別・大きさ

11件腕の先頭9件は、順に `A`、`BC`、`DEF`、`GHIJ`、`KLMNO`、`PQRSTU`、
`UVWXYZ1`、`ABCDEFGH`、`NINECHARS` とする。長さ1〜9を1回ずつ含み、種別は先頭から
`0x80`,`0x00` を交互に置く。すべて1単位、最終値 `0xC1` とする。

残る2件は `CHAIN10U` と `LAST8SEC`。前者は10単位をつなぎ最終値 `0xC1`、後者は1単位で
最終値 `0xC8` とする。これにより `UNITS` は10/1、`SECTORS` は73/8を予測し、1桁・2桁の
大きさと「単位数か使用セクタ数か」を同時に区別できる。

11件腕には、3件目の前、5件目と6件目の間、9件目の後へ削除済み枠を1つずつ置く。
削除済み枠の残りは自作目印 `DELONE`、`DELTWO`、`DELTHREE` に由来する値で埋めるが、
画面へ現れないことだけを判定する。

4・5・6件腕は、9文字の自作名 `B00000001` からの連番、種別交互、各1単位 `0xC1` とし、
削除枠を入れない。96件腕は `Q00000001`〜`Q00000096`、種別交互、各1単位 `0xC1` とする。
予約単位74・75は割り当てず、ほかの自作単位を重複なく使う。

## 5. 腕（15腕、各2走）

通常腕はドライブ1＝参照 diskA の使い捨て複製で起動し、ドライブ2＝自作媒体とする。
各走は別の媒体像・別のエミュレータ過程を使う。最初に `CLS` を実行して署名だけの基準時点を
取り、その後に `CLS:FILES 2` 等を実行する。通常腕は8000フレーム、L96は12000フレーム。

### 5.1 件数・配置（7腕）

| 腕 | 生きた件数 | 目的 |
|---|---:|---|
| L0 | 0 | 0件時の行、追加メッセージ、正常終了 |
| L1 | 1 | 1件の欄構成。名前 `A`、種別 `0x80` |
| L4 | 4 | 4件/行候補の境界 |
| L5 | 5 | 5件/行候補の境界 |
| L6 | 6 | 4件/行・5件/行・可変詰めの区別 |
| L11 | 11 | 複数行、長さ1〜9、2種別、削除済み混在、2種の大きさ |
| L96 | 96 | 19表示行を超える出力。スクロール、停止、打切り、末尾順序 |

L96で途中停止らしい画面になっても、その場でキーを追加して結果を選ばない。
`inconclusive_overflow` とし、ページ送りのキー候補を凍結する追補を先に置く。

### 5.2 ドライブ番号と構文（7腕）

この7腕では、起動完了後・打鍵前にドライブ1の参照 diskA 複製を取り外し、1件だけを持つ
自作媒体 D1（名前 `DRIVEONE`）へ交換する。ドライブ2には異なる1件の自作媒体 D2
（名前 `DRIVETWO`）を置く。交換完了を器具が確認するまで命令を送らない。この構成により、
不正引数が予想外にドライブ1へフォールバックしても公式ディスクの一覧を表示しない。

**既知の危険**: 起動時に読んだドライブ1のディレクトリを ROM がメモリに保持していて、交換後も
媒体を読み直さない場合、D-omit・D-1 は参照 diskA の一覧を表示する（署名しか残らないので
本文は漏れないが、D1 の予測とは一致しない）。この場合の判定は `drive1_served_from_cache` とし、
`drive_selection_other` と区別する。判別には、交換後の `FILES 1` の前後でドライブ1への
READ が起きたかを入出力の件数（値は見ない）で記録する。

| 腕 | 命令 | 事前候補 |
|---|---|---|
| D-omit | `CLS:FILES` | D1。物理161頁の既定値 |
| D-1 | `CLS:FILES 1` | D1 |
| D-2 | `CLS:FILES 2` | D2 |
| D-expr | `CLS:FILES 1+1` | 数値式を受けるならD2、リテラルだけなら構文エラー |
| E-0 | `FILES 0` を誤り捕捉用プログラムから実行 | 範囲エラーまたは別の意味 |
| E-3 | `FILES 3` を誤り捕捉用プログラムから実行 | 範囲エラー |
| E-str | `FILES "B:"` を誤り捕捉用プログラムから実行 | 構文または型のエラー。既存測定ではFDC到達なし |

E腕は `ON ERROR GOTO` を持つ自作プログラムで実行し、捕捉できたときは `CLS` 後に `ERR` の
数値だけを既知のPRINT規則で出す。予測器は0〜255の候補画面をメモリ内で作り、署名が一意に
一致した番号だけを `files_error_err_<N>` として記録する。本文は出さない。行の登録自体が
拒否されて捕捉できない場合は、`l4-basic.md` §7.1の凍結済みエラー分類の署名と照合し、
`files_error_parse_<class>` とする。どちらにも一意一致しなければ `inconclusive_error`。

### 5.3 未挿入（1腕）

N-waitはドライブ2を空で起動し、`CLS:FILES 2` を送る。frame 1200まで媒体アクセスが続き、
正常終了署名もエラー署名も無いことを確認してから、L1の自作媒体をドライブ2へ挿入し、
frame 4000まで走らせる。

- 挿入前は待機し、挿入後にL1と同じ一覧署名へ到達: `files_no_media_waits_for_media`。
- 挿入前に一意なERRへ到達: `files_no_media_error_<N>`。
- 挿入前に止まるが、挿入後もL1へ到達しない: `files_no_media_stuck`。
- 2走不一致または署名不明: `inconclusive_no_media`。

第一候補は既存 `m7lu`・`m7lw` と同じ `waits_for_media` であり、その場合にエラー番号は
「未測定」ではなく**該当なし（エラーへ遷移しない）**と記録する。

## 6. 署名器具の追加設計（本稿では実装しない）

### 6.1 現器具をそのまま使わない理由

`check_l3_screen_output.py` は本文を標準出力へ出さないが、入力reportに画面本文がすでに
書かれている。また、出力するSHA-256は画面全体の1個で、今回必要な行別の幅・折返し・
スクロールを直接凍結できない。この測定で署名化前reportを作ることは禁止する。

### 6.2 必要なモード

`q88measure` 側に `--screen-signature-only` 相当を追加し、指定フレームの80桁×表示行を
**プロセス内だけ**で読む。各物理行について、既存器具と同じ
`行番号<TAB>本文<LF>` のUTF-8列をSHA-256へ入れ、次だけを署名reportへ書く。

```
snapshot_id, physical_row, char_count, sha256
```

画面全体についても `line_count`、`char_count`、`sha256` を書くが、本文、先頭文字、末尾文字、
文字種ヒストグラムは書かない。空白をstripせず、大小変換・空白圧縮もしない。

`check_l3_screen_output.py` 系の新しい比較器は、次を行う。

1. シナリオ定義から54候補の予測画面をメモリ内で作る。
2. 予測も同じ行単位で直ちに署名化し、予測本文をファイルへ書かない。
3. 実測署名と候補署名を、物理行番号・文字数・SHA-256のすべてで比較する。
4. 出力は候補ID、一致数、不一致行数、最初の不一致行番号、文字数差の有無だけ。
5. `CLS` 基準署名と比べ、予約されたファンクションキー行が不変であること、追加行の有無、
   L96のスクロール範囲を本文なしで分類する。

署名report、期待値TSV、判定JSONの全フィールドは許可リスト方式にし、文字列型の自由記述欄を
持たせない。例外メッセージも画面文字を含めず、エラー型と座標だけにする。

### 6.3 陰性対照

自己検査は公式環境を使わず、合成画面と自作名だけで行う。

- 1文字を同じ長さの別文字へ変える、末尾空白を1個増減する、2行を入れ替える、行番号を1変える、
  4件/行と5件/行を入れ替える、`0x80`/`0x00` の印を入れ替える、削除済みを誤って1件出す、
  末尾単位の `u` を1変える、スクロールを1行ずらす故障をすべて不一致にする。
- 候補自身は一致し、54候補のうち故障前に意図した候補だけが残る合成シナリオを最低1つ持つ。
- 合成画面本文へ置いた漏えい目印が、stdout、stderr、署名report、期待値TSV、判定JSON、
  例外経路のどこにも現れないことを陰性対照つきで確かめる。
- 既存 `tools/screen_content_leak_selftest.sh` も通す。ただし禁止された生成器selftestを呼ぶ
  一括selftestは使わず、許可したselftestを明示的に列挙する。

## 7. 凍結値と関門

### 7.1 公式ROMを1回も起動する前の関門 G0〜G8

次のどれかが偽なら、**公式ROM起動回数0のまま停止**し、腕を1つも走らせない。

- **G0 禁止範囲**: 実装・レビューの入力一覧に禁止ファイル、`private/`、m7eb系が無い。
- **G1 生成器自己検査**: `make_m6fc_blank_disk_selftest.sh` と、今回追加する媒体生成器の
  自己検査が成功。公式バイトを入力に使わない。
- **G2 媒体検査**: 15腕で使う各像について、D88外形、ディレクトリ位置、先頭未使用、削除位置、
  名前長、型、FAT3複製、鎖、終端、単位重複なし、74・75予約を独立検査器が確認する。
- **G3 シナリオ凍結**: 名前、型、エントリ順、削除位置、鎖、命令、フレーム、交換・挿入時刻を持つ
  manifestのSHA-256が事前に凍結した値と一致する。
- **G4 54候補凍結**: 54候補×対象腕の行別期待署名TSVのSHA-256が凍結値と一致し、候補IDの
  欠落・重複が無い。
- **G5 検出力**: §6.3の全故障を検出し、正例を受理する。
- **G6 漏えい防止**: 合成目印が全出力に無く、許可リスト外フィールドが無い。
- **G7 ドライブ交換安全性**: D系・E系では参照 diskA を外した確認イベントが `FILES` 打鍵より前。
  交換失敗時は打鍵しない。通常腕では命令が常にドライブ2を選ぶ。
- **G8 実行計画**: 15腕×2走=30過程が一意な作業先を持ち、既存ファイルを上書きしない。

凍結値は器具実装後、公式ROM・参照diskAの環境変数を与える前に、自作規則だけから作る。
凍結後にmanifest、予測器、署名規約を変える必要が出たら、その時点で止め、測定前の追補を
コミットして新しい凍結値を置く。古い値を測定結果に合わせて更新しない。

### 7.2 各走と全体の関門

- **G9 決定論性**: 同じ腕の2走で、各行署名・全体署名・候補一致集合・エラー分類が一致する。
- **G10 完了**: 通常腕は遅い2時点（300フレーム差）の画面署名が同一で、既知の入力待ち状態へ
  戻ったことを本文なしの判定器で確認する。L96のページ停止候補とN-waitの挿入前には適用しない。
- **G11 参照媒体不変**: 各走の参照 diskA 複製が開始前後で不変。D/E腕では取り外した後も不変。
- **G12 出力監査**: 測定作業先を許可リスト検査し、画面本文を持つファイルが0件。
- **G13 候補の検出力**: 実測署名の1行SHA、文字数、行番号をそれぞれ壊したコピーが不一致になる。

G9〜G13のどれかが偽なら `gate_failed` とし、その腕以後を止める。通った腕の署名を使って
都合のよい候補を選ばない。コアabortや時間切れは腕・走番号を記録し、同一条件の自動再走は
最大2回まで。3回目も失敗した腕は `gate_failed`。

## 8. 導出と判定名

### 8.1 表示規則

L0・L1・L4・L5・L6・L11・L96の全腕について、2走とも全行署名が一致する候補集合 C を取る。

- `|C|=1`、追加行なし、順序・0件・画面超過も共通規則どおり:
  一意な候補IDそのもの、たとえば `files_layout_rule_G5_SPLIT63_80DOT_00BLANK_UNITS`。
- `|C|=0`: `inconclusive_no_candidate`。どの軸の腕で初めて全候補が消えたかだけ記録。
- `|C|>1`: `inconclusive_multiple_candidates`。残った候補IDだけ記録。
- 共通規則の違反: §3.5の個別 `inconclusive_*`。
- 関門失敗: `gate_failed`。

候補間で同一画面になる腕はそのまま許し、全腕の積集合でのみ一意性を判定する。

### 8.2 個別の補助判定

- 順序: `directory_order_skips_deleted` / `order_other`。
- 0件: `empty_has_no_entry_rows` / `empty_other`。
- 画面超過: `scrolls_to_tail` / `page_wait` / `truncates` / `overflow_other`。
- ドライブ: `default_is_1_explicit_1_2` / `drive1_served_from_cache` / `drive_selection_other`。
- 数値式: `drive_expression_accepted` / `drive_literal_only` / `drive_expression_other`。
- E腕: `files_error_err_<N>` / `files_error_parse_<class>` / `inconclusive_error`。
- 未挿入: §5.3の4分類。

### 8.3 候補に依存しない構造の導出（候補照合と独立）

54候補は完全一致を要求するので、桁揃えや区切り1文字の違いで全滅しうる。全滅しても
次の追補に使える情報が残るよう、**候補照合とは別に、行番号と行ごとの文字数だけから**次を導く。
規則はここで凍結し、結果を見てから足さない。

- **1行の件数 K**: L4・L5・L6 のエントリ行数（`CLS` 基準から増えた行の数）の組から決める。
  (1,1,2) なら K=5、(1,2,2) なら K=4、(1,1,1) なら K≥6。ほかの組は `rows_per_count_other`。
- **1件の幅**: L1 の増えた行の文字数を w1 とし、L4・L5 の1行目の文字数との差から
  「固定幅セル（件数に比例）」か「内容幅」かを分ける。記録するのは w1 と差の値だけ。
- **名前の長さへの依存**: L11 の各エントリ行の文字数が、名前の長さ（1〜9）によって変わるかを
  真偽で記録する（`width_depends_on_name_length` / `width_fixed_per_entry`）。
- 画面の文字数が空白を含む80桁固定で出る場合（全行が同じ文字数）は、本節の導出は
  `char_count_uninformative` とし、候補照合の結果だけを使う。

これらは判定名を置き換えない。`inconclusive_*` のときに追補の候補を絞る材料として結果ノートへ書く。

## 9. 結果の行き先

一意な表示規則が得られた場合:

1. `docs/spec/l4-basic.md` に新設する「`FILES`」節へ、構文、既定ドライブ、表示欄、1行の配置、
   0件、スクロール、エラー／待機を記す。画面本文や自作名の実測行は載せない。
2. `docs/spec/l3-disk-format.md` は媒体上の事実だけを受け持つ。`SPLIT63` が確定した場合の
   9バイト欄の解釈、種別バイトから論理的なファイル種類への対応、大きさを出すためのFAT鎖の
   数え方のうち、媒体解釈として必要な部分だけを §1 の新しい小節へ加える。列数、セル幅、
   折返し、プロンプト、エラーはL3ディスク形式へ書かない。
3. 結果ノート `docs/notes/m6f-e-files-display-results.md` に、関門、30走の成否、行別署名、
   候補の消え方、最終判定名を記す。本文は載せない。

`inconclusive_*` または `gate_failed` なら結果ノートだけを書き、仕様書を改版しない。

## 10. この測定で決めないこと

- `LFILES` のプリンタ上の配置。
- `0x80`・`0x00` 以外の種別バイトと、アスタリスクの媒体上の対応。
- 小文字、半角カナ、制御文字、9バイト欄へ空白を途中に含む名前。
- 壊れたFAT鎖、範囲外先頭単位、未使用より後ろの生きたエントリに対するエラー。
- ドライブ1からの起動規則。参照 diskA の一覧内容。
- `FILES` 実装そのもの。測定結果を仕様書へ起こすコミットより先に実装しない。
