# m6f-f — 保存の方法ごとの種別バイト（名前欄の直後）— 事前登録

記録日: 2026-09-27  
状態: **測定前**

## 0. 位置づけ

`FILES` の表示（l4-basic.md 第11節）は、名前欄直後のバイト（以下 種別バイト）が `0x80`・`0x00` の場合しか決まっていない
（11.3節 未確定）。マニュアル（m6f-e 事前登録 §1.2、物理161頁）は種別の印に空白・ピリオド・アスタリスクの3種を挙げ、
ASCII 保存・バイナリ保存・`BSAVE` を区別すると説明する。表示の候補を立てる前に、**公式ROM が保存の方法ごとに種別バイトへ
何を書くか**を測る。表示は次稿（m6f-g）で測る。

担当・禁止は m6f-d 事前登録 §0 と同じ（`make_n88_blank_disk.py`・`vendor/`・QUASI88 の image.c・m7eb 系ノートを開かない）。

### 0.1 出力の制限

- エントリは、名前欄（自分で与えた名前）と 9〜15 バイト目だけを出力してよい（m6f-d §0.1 と同じ）。
- **ファイル本体のセクタの中身は出力しない。** `BSAVE` はメモリの内容を本体へ書くので、本体には自分で書いた値以外が混ざりうる
  （[自作媒体でもROMの書いた値が混ざる](contamination-2026-09-25-fat-buffer-overrun-values.md) と同じ型の危険）。本体は読まない。
- 割り当て表は位置 0〜159 だけを扱う（m6f-d §0.1）。本稿では割り当て表を導出に使わない。
- 測定後の像は、導出の後に削除する（m6f-d と同じ運用）。

## 1. 問い

- **F-I**: `SAVE`・`SAVE ,A`・`SAVE ,P`・`BSAVE`・`OPEN … FOR OUTPUT` で作ったファイルの種別バイトの値。
- **F-II**: 種別バイト以外の 11〜15 バイト目が、保存の方法で変わるか（作成直後は `0xFF`、m6f-c・m6f-d の観察）。

## 2. 構成

m6f-d と同じ: ドライブ1＝参照 diskA の使い捨て複製で起動、ドライブ2＝`tools/make_m6fc_blank_disk.py` の空の媒体（m6f-c の B0 と同じ規則）。
各腕2走、別の像・別の過程。フレーム 8000。

## 3. 腕（6腕）

打鍵は小文字で届く（m6f-a 結果 (i)）。名前はすべて自分で決めた4文字。本体は自分で決めた内容だけにする。

| 腕 | 打鍵（`\n` は RETURN） | 事前の見込み |
|---|---|---|
| F-S（対照） | `new\n10 print 1\nsave "2:qzs"\n` | `0x80`（m6f-b E8 の再確認） |
| F-A | `new\n10 print 1\nsave "2:qza",a\n` | 未知 |
| F-P | `new\n10 print 1\nsave "2:qzp",p\n` | 未知 |
| F-B | `for i=0 to 15:poke A+i,65:next:bsave "2:qzb",A,16\n`（A は下記） | 未知 |
| F-D（対照） | `open "2:qzd" for output as #1:print #1,"x":close #1\n` | `0x00`（m6f-b E8 の再確認） |
| F-0（陰性対照） | 何も保存しない | 媒体のディレクトリに生きたエントリが無い |

**F-B の番地 A** は、マニュアルの言語仕様の範囲で「利用者が自由に使ってよい」とされる番地から選び、選んだ根拠（マニュアルの頁）を
器具のコメントと結果ノートに書く。ROM のワークエリア番地の資料は使わない。`POKE` で自分の値を書いた範囲だけを `BSAVE` する。
`BSAVE` がエラーになった場合は腕を `f_b_error_<ERR>` として記録し、別の番地を後から選ばない（追補を置く）。

## 4. 読み取り

測定後の像のドライブ2のディレクトリ (18,1,1)〜(18,1,12) から、名前で自分のエントリを探す（`tools/m6fd_entry.py` の `entry_fields`）。
記録するのは、見つかった位置と 9〜15 バイト目の7値だけ。

## 5. 関門

- **G1**: 自己検査（器具の run_all 登録分）を腕の前に1回。
- **G2**: 空の媒体が m6f-c B0 と同じ規則でできている（生成器の自己検査）。
- **G3**: 凍結値（媒体の SHA-256、打鍵列の SHA-256）の照合を公式ROM起動前に行う。偽なら起動回数0で止める。
- **G4**: 各腕2走で 9〜15 バイト目が一致。
- **G5**: F-S が `0x80`、F-D が `0x00`（既知の再確認）。偽なら全体を `control_failed`。
- **G6**: F-0 でエントリが見つからない。
- **G7**: 参照 diskA 複製は前後で不変。

## 6. 判定

- 腕ごとに `type_byte_<腕>=0xNN`（2走一致のとき）。一致しなければ `inconclusive_<腕>`。
- F-II: 11〜15 バイト目が全腕で `0xFF` なら `bytes11_15_unchanged`、そうでなければ変わった腕と位置と値を記録（`bytes11_15_vary`）。
- 保存が失敗した腕（エントリが無い）は `no_entry_<腕>`。

## 7. 行き先

- `docs/spec/l3-disk-format.md` 1.2節の表の「名前欄の直後の1バイト」に、測った値を足す（第4版）。
- 次稿 m6f-g で、この値を種別バイトに持つ自作媒体を作り、`FILES` の印を測る。あわせて大きさが3桁のときの表示も測る。

## 8. 決めないこと

- 種別バイトのビットの意味（値の対応だけを記録する）。
- 本体の保存形式（読まない）。
