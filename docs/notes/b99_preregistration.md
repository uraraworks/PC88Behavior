# B99 事前登録：途中リセット（ウォームリセット）で公式 ROM は画面とディスクをどう扱うか

記録日: 2026-11-17。WebQ88 で本人から、ゲーム中にリセットすると前の画面が残り、ディスクを抜いた後もアクセスランプが激しく点滅するという報告を受けた。ゲーム無しでも、自作 ROM で BASIC から `screen 0,0:line(0,0)-(639,199),7,bf` を描いてからリセットすると、グラフィック画面が消えずに残ることを Mac の自作 ROM だけで確かめた（テキスト側は起動表示と Ok まで進む。ランプは点かない）。L1 の測定（[l1-ipl.md](../spec/l1-ipl.md)）は電源投入（メモリがすべて初期値）だけで、途中リセットは測っていない。値・画面本文・媒体データは公開記録に含めない。

## 腕

リセットは QUASI88 の `quasi88_reset`（libretro の `retro_reset` と同じ経路）で行う。公式 ROM と自作 ROM（main 699b2b7 相当、compat-rom と同じ版）で同じ腕を走らせる。

| 腕 | リセット前 | リセット時の媒体 |
|---|---|---|
| R-G | BASIC で上の1行を打鍵してグラフィックを描く（自作の打鍵） | 無し |
| R-T | BASIC で `print` を数行打ってテキストを出す | 無し |
| R-G5-OUT | G5 を F3600 まで動かす | 2枚とも抜く |
| R-G5-IN | G5 を F3600 まで動かす | 入れたまま |
| R-COLD | 何もしない（電源投入直後にもう1回リセット） | 無し |

リセット後 1800 フレーム走らせる。

## 記録すること（値は出さない）

- リセット後に main が書いたポートの種類と件数の列（公式と自作で最初に違う件目）。特にポート 31・53・5C〜5F（表示面の選択・表示の切り替え）への書き込みがあるか、いつか。
- リセット後の 300・1800 フレームでグラフィック VRAM の3面がすべて0か（真偽）、テキスト画面の署名（`tools/check_l3_screen_output.py` の行数・文字数・SHA-256。公式・自作で一致するかだけ）。画面に表示されているのがグラフィックかテキストだけか（ポート 31・53 の最後の書き込みから決める表示の有無の真偽）。
- リセット後の FDC コマンドの種別ごとの件数（SEEK・RECALIBRATE・READ DATA・SENSE 系）と、最後のコマンドのフレーム。sub が同じコマンドを繰り返し続けているか（末尾 600 フレームで同じ種別が10回以上）。
- リセット後に main が BASIC の入力待ちへ着いたか（`tools/check_l3_entry_screen.py` で Ok の有無）。

## 判定

- 公式で R-G・R-G5-OUT 後にグラフィックが消える（VRAM が0になる、または表示が切られる）なら、自作の起動処理に同じ働きを入れる。どちらの方法かは測った書き込みの種類で決める。
- R-G5-OUT で公式は FDC を叩き続けず、自作だけが叩き続けるなら、自作の起動時の媒体判定・再試行の違いとして原因を調べる。公式も叩き続けるなら、エミュレータ側（媒体を抜いた状態の扱い）の問題として WebQ88 側で扱う。
- R-COLD で公式と自作が一致しなければ、器具（リセットの掛け方）を疑い判定しない。
