# B46: スペース後の G1 で、RAM 上のコードの読み書きが最初に違う所を値なしで測る — 結果

記録日: 2026-11-01
規則: [b46-g1-sub-event-stream-preregistration.md](b46-g1-sub-event-stream-preregistration.md) どおり。測定はクラウドの実行環境で OO・SS 各 2 走。関門 5 項目はすべて通った。値は記録していない。記録は `measurements/b46-g1-sub-event-stream.txt`。

## 結果

出来事の数は公式 741030、自作 505882。最初の違いは番号 499250 で、種類・`PC`・番地・値のすべてが違う。

| | 種類 | `PC` | 番地 | fc |
|---|---|---|---|---:|
| 公式 | 書き | `7833` | `7FFF` | 76831 |
| 自作 | 読み | `7882` | `7821` | 76829 |

**それより前の 499250 件は、読み・書き・`OUT` の値まで公式と同じである。** 直前は `4000` 台を読んで `OUT $FD` する列で、`41FF` を読んで送ったところで終わる。

## 読み方（推定）

- B30 の `IN $FC` の違いの範囲（76570〜76826）では、サブの RAM 上のコードが出す値は公式と同じである。**サブが違う値を出しているのではない。main の読む値だけが違う**
- したがって「サブの計算が違う」という B38〜B45 の見立ては外れ、`BC`・`HL`・`F`・`DE` は値の違いの原因ではない
- 残るのは、main とサブのポートの受け渡しである。B47 で、main の読んだ値がサブの直前の `OUT $FD` と同じかを腕ごとに比べる
- 道の分かれ（番号 499250）は、`7833` で書く公式と `7882` で読む自作で、main の読んだ値の違いのあとに起きる
