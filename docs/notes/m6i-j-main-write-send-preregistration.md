# m6i-j — 公式 main の書き込み送信 — 事前登録

記録日: 2026-09-29  
状態: **測定前・器具実装前**

## 0. 境界と根拠

本稿は、公式 ROM 一式で自作の空媒体へ `SAVE "<ドライブ>:<名前>",a` を行った際の、**main 視点の送信**を測る計画だけを凍結する。ここでは測定、公式 ROM の起動、実装、仕様書の改版を行わない。公式 ROM・公式ディスクの内容を読まず、逆アセンブルせず、画面本文を標準出力・標準エラー・ファイル・報告へ出さない。公式 diskA は起動用の使い捨て複製とし、書き込み先にはしない。

先に確認した資料は `CLAUDE.md`、凍結済みの `m6f-e-files-display-preregistration.md`、`l3-subrom.md` 1.35〜1.38・1.53節、`l3-disk-format.md` 第6版 1.5節・2章、`l4-basic.md` 第13節、`m6i-a`・`m6i-i`・`m6f-j` の各事前登録、`tools/measure_m6ii.sh`、`tools/harness/frontend/main.c` の usage とする。1.35節で sub 視点の6バイト制御レコードの末尾2位置は `[論理トラック=C*2+H, R]` と分かったが、先頭4位置は未確定である。1.36節の READ 先頭バイト表は **sub 視点の受信 run** の規則であり、1.53節により main 視点の SEND run へ転用できない。READ の後続交換は1.36・1.37節の既知事項として分類に使い、WRITE の送信規則をそこから推定しない。

## 1. 問い

1. 1セクタの WRITE DATA に至るまで、main はどの SEND run をどの順で出すか。各 run の長さ、先頭バイト、run 境界、6バイト制御レコードの位置0〜5、256バイトデータの開始位置・末尾、複数レコード時の境界を決める。main の SEND run と sub の受信 run の対応は、件数や添字の1対1対応を前提にしない。
2. WRITE DATA の結果後、main が何を受け取り、次の送信にどう進むか。1レコードにつき1バイトの既知の sub 応答が main 側ではどの RECV と対応するか、結果の前後の交換順、成功判定までを決める。FDC の7バイト結果と sub 応答を混同しない。
3. `SAVE ,A` 全体で、ディレクトリ、書き込み禁止の印、割り当て表、本体の読み取り・書き込み要求がどの順で現れるか。既存ファイルの上書き時に古い割り当て表をいつ読み直し、ディレクトリ・割り当て表3複製をいつ書き戻すか、1セクタと9セクタで順序がどう変わるかを決める。

## 2. 媒体・腕（8腕、各2走、計16走）

各走は別のエミュレータ過程・別の自作 D88 複製・一意の一時作業先を使う。起動時のドライブ1だけに参照 diskA の使い捨て複製を入れ、ドライブ2には `m6f-j` B0（空）または B1（同名1件）の自作媒体を入れる。ドライブ1腕では、起動後、打鍵前に `--swap-disk1`・`--swap-disk1-at` でドライブ1を同じ種類の自作媒体へ差し替え、差し替え成功イベントとパスを確認するまで打鍵しない。ドライブ2腕の参照 diskA は書き込み禁止のまま保持する。両腕とも自作媒体の複製だけを書き込み可能にし、媒体保存口 `--save-to-disk-image` を使う。

ドライブ以外の条件を揃えるため、1セクタ用と9セクタ用の ASCII 自作 BASIC プログラムは、`l3-disk-format.md` 2.6節の行形式で、それぞれ終端 `0x1A` を含む有効本体長が1〜256バイト、2049〜2304バイトとなるよう測定前に固定する。生成器と独立の検査器が保存前の長さ・行構造・予測セクタ数を検査する。保存名は自作小文字名を2つ用意し、長さごとに固定する。新規は B0、上書きは長さ別の同名既存 ASCII 1セクタファイルを持つ B1 の2変種を使う。B1 の旧本体と新本体は異なる自作内容にし、旧単位は新規割り当て先から外す。B0・B1 は `m6f-j` の構成と第6版1.5節・2章に従い、公式ディスクのデータを写さない。

| 腕 | 保存先 | 本体 | 既存同名 | 入力の形 |
|---|---|---|---|---|
| J-D1-S-N | ドライブ1 | 1セクタ | なし B0 | `SAVE "1:<短名>",a` |
| J-D1-S-O | ドライブ1 | 1セクタ | あり B1 | 同上 |
| J-D1-L-N | ドライブ1 | 9セクタ | なし B0 | `SAVE "1:<長名>",a` |
| J-D1-L-O | ドライブ1 | 9セクタ | あり B1 | 同上 |
| J-D2-S-N | ドライブ2 | 1セクタ | なし B0 | `SAVE "2:<短名>",a` |
| J-D2-S-O | ドライブ2 | 1セクタ | あり B1 | 同上 |
| J-D2-L-N | ドライブ2 | 9セクタ | なし B0 | `SAVE "2:<長名>",a` |
| J-D2-L-O | ドライブ2 | 9セクタ | あり B1 | 同上 |

打鍵は `NEW`、自作の行入力、`CLS`、上表の `SAVE` の順とする。打鍵列、フレーム、差し替えフレーム、媒体像とプログラムの SHA-256 は器具を実装した後、**公式 ROM を起動する前**に manifest へ固定する。末尾の画面は既存の `--screen-signature-only` で本文を保持せず署名化し、`l4-basic.md` 第13節の完了状態と照合する。完了判定に画面本文は使わない。

## 3. 観測単位と先に凍結する導出規則

`--io-log` の共通 clock を使い、`main OUT $FD` を `$FE`/`$FF` だけを許容する既存の main SEND run 規則で切る。別に `sub IN $FC` を `sub OUT $FB/$FD` で切る sub 受信 run 規則で切る。両者を同じ run 番号で結ばず、SAVE 打鍵後の転送イベントを共通 clock 上で単調対応づけ、値・順序・件数の一致を**全数**検査する。対応しないイベント、ログ容量超過、clock の欠落や逆転が1件でもあれば関門失敗とする。FDC の READ DATA/WRITE DATA コマンド、座標、結果境界を別系列から取り、各 WRITE の直前に対応する制御6位置と256位置のデータを同定する。制御12位置などがあれば6位置ずつに分け、WRITE と結ぶ。main 側の run 境界がその途中に来ても分割を保つ。

各 WRITE について `idx4=論理トラック`、`idx5=R`、データ256位置が自作媒体の予測書き込み内容と一致することを検査する。`idx0`〜`idx3` は**位置ごとに独立**に、以下の5候補と照合する。4位置の候補割当は **5^4=625通り**。`その他` は予測式を持つ第6候補ではなく、625通りから外れたときの判定である。候補の意味と照合手順は測定後に変更しない。

| 候補 | 全数照合の条件 |
|---|---|
| `constant` | 全8腕の全 WRITE レコードで同じ値 |
| `drive` | 保存先ドライブ番号が同じレコードでは同じ値、異なるドライブでは異なる値。ほかの軸を振っても保つ |
| `track` | 論理トラックが同じなら同じ値、異なれば異なる値。ほかの軸を振っても保つ |
| `r` | R が同じなら同じ値、異なれば異なる値。ほかの軸を振っても保つ |
| `count_order` | 同一要求群の予定セクタ数とその群内の1始まり順番の組が同じなら同じ値、異なれば異なる値。ドライブ・座標・上書きだけを変えても保つ |

ここで「同じなら同じ、異なれば異なる」は**観測した全レコード対**の等値関係で判定する。数値がドライブ番号・トラック・R・順番に等しいことまでは、この分類だけでは主張しない。分類後、候補ごとの観測値→入力値の対応表を作り、単純な等値・固定差・ビット符号化などの式は**全数に一意一致したものだけ**補助結果に記す。単一軸を変えて他の軸を固定した区別可能な対が無い候補、候補が複数残る位置、あるいは予測を外れる位置は、それぞれ `inconclusive_axis_confounded`、`inconclusive_multiple_candidates`、`inconclusive_control_other` とする。対応表に無い座標・長さへ一般化しない。

`count_order` の「要求群」は、連続 WRITE の間に挟まる制御・応答交換の閉じ目で決め、結果を見て群の境界を選び直さない。境界が既存の clock と交換相から一意に切れない場合は `inconclusive_group_boundary`。WRITE 順序は、各走の SAVE 打鍵後から完了までの READ/WRITE 要求を、`方向・ドライブ・(C,H,R)・main SEND/RECV run の長さと先頭制御値・FDC境界・結果相` の順序付き列へ還元して比較する。READ のデータ値は列へ入れない。既知のディレクトリ (18,1,1〜12)、印 (18,1,13)、割り当て表 (18,1,14〜16)、本体の単位座標へ分類し、分類不能の座標もそのまま件数・座標・位置として残す。読み直し回数、3複製の書き戻し順、上書き時の旧単位解放と新単位確保の順は、この全列の前後関係からのみ導く。同じ座標への反復を省略しない。

## 4. 出力境界

生の I/O ログと媒体像は一時領域にだけ置き、標準出力へ流さない。解析器の標準出力・結果ノートは許可リスト制にし、run 長・先頭**制御**値・6位置の制御値・座標・方向・件数・候補一致集合・応答分類・判定名だけを残す。256バイトの送信データ部は自分で書いた ASCII 本体とバイト照合してよいが、列そのものは残さず一致数と真偽だけを出す。ディレクトリ・割り当て表を書き戻すデータも位置と変更件数だけを残し、値列は出さない。

sub からの READ データは、ディレクトリ・割り当て表ともセクタ内位置0〜159以外の値を出力しない。割り当て表の位置0〜159も規則照合に必要な意味値だけを残し、160以降は解析で読まない。ディレクトリは第6版で定義済みのエントリ欄を意味へ還元し、実データ列を出さない。参照 diskA 由来の READ データ値は一切扱わない。最後の本体セクタは予測した有効長の終端 `0x1A` までだけを照合し、余りを読まない（`m6f-h` §0.1）。媒体像の後検査でも同じ上限を守る。画面署名は一時的な完了判定にだけ使い、結果には制御値、長さ、件数、候補一致、関門の成否だけを残す。

`CLAUDE.md` 禁止事項5に従い、もし I/O ログを証拠としてコミット対象にするなら、**データポート `$FB`/`$FC`/`$FD` の値列を `tools/redact_iolog.py` で伏せてから gzip** し、`tools/check_cleanroom.sh` で検査する。未伏せ字ログ・一時媒体像・画面本文はコミットしない。本稿ではログを作らず、コミットもしない。

## 5. 関門と自己検査

いずれかが偽なら `gate_failed` とし、公式 ROM 起動**0回**のまま停止する。

- **G0 禁止範囲**: 器具の入力・依存先に禁止された生成器とその selftest、`vendor/`、QUASI88 の `image.c`、m7eb 系ノート、`private/` が無い。
- **G1 凍結**: manifest の腕・打鍵・媒体・フレーム・ハッシュ、625候補の定義、run 切り出し規則、結果の許可フィールド、判定名の SHA-256 が事前凍結値と一致する。1バイト壊した凍結値ならフロントエンド起動回数0で NG。
- **G2 媒体・本体**: B0/B1 の D88 外形、ディレクトリ、割り当て表0〜159、予約単位、旧ファイル、1/9セクタの長さを生成器とは独立に検査する。壊した媒体・本体は NG。
- **G3 器具自己検査**: 合成 I/O ログと偽フロントエンドだけで正例を通し、SEND run を1件欠落、先頭値・制御位置・データ1位置・応答1件・clock・書き戻し順・候補表をそれぞれ壊す陰性対照が NG になる。合成 READ の位置160・最終セクタ余り・画面本文の漏えい目印も出力監査で NG。新しい selftest を作る段階で `tools/run_all_selftests.sh` の `SCRIPTS_EXPECTED` に `:0` で列挙し、既存の `PC88_SELFTEST_EXCLUDE` の登録名照合を保つ。
- **G4 実行計画**: ドライブ1の交換は SAVE 打鍵より前、各走の自作媒体複製と作業先は固有、参照 diskA は使い捨て複製で書き込み不能。交換失敗なら打鍵しない。

各走後の関門は、I/O ログの容量・欠落・共通 clock の単調性・main/sub 間の単調対応が全件成立、対象以外への WRITE が0、参照 diskA 複製の前後 SHA-256 が一致、SAVE が署名だけで完了判定可能、結果の出力監査が通ることである。同じ腕の**2走で** run 境界、制御値、要求・応答の全順序、件数、媒体差分の許可範囲、判定名が一致しなければ `gate_failed`。実測ログを1件欠落・1位置改変したコピーでも検査が NG になることを陰性対照として確認する。関門を通らない腕の部分結果を候補の選択に使わない。

## 6. 判定名と行き先

- `m6i_j_main_write_send_unique`: 16走が関門を通り、4位置すべての候補が一意、WRITE ごとのデータ・応答の対応と SAVE 全体の要求順序が2走一致。
- `inconclusive_axis_confounded` / `inconclusive_multiple_candidates` / `inconclusive_control_other` / `inconclusive_group_boundary`: §3 の条件による。必要な軸または群定義を追補で先に固定し、結果へ合わせて候補を変更しない。
- `inconclusive_transfer_mapping` / `inconclusive_write_response` / `inconclusive_save_order`: 対応・応答・全順序のいずれかが一意に導けない場合。
- `gate_failed`: §5 のいずれかが偽。仕様書を改版しない。

一意に決まった場合だけ、結果ノート `docs/notes/m6i-j-main-write-send-results.md` に16走の関門・長さ・件数・制御値・候補の消え方・順序・判定名を記録し、`docs/spec/l3-subrom.md` に **main 側の書き込み送信**の節を新設する。sub 側1.35〜1.38節とは視点と run 境界を明記して分ける。未確定なら結果ノートだけに理由を記し、仕様へ推測を入れない。

## 7. この測定で決めないこと

- 公式 ROM の内部番地・処理手順・データテーブル。main と sub の run 境界が常に一致するという一般則。
- `SAVE ,A` 以外の `SAVE`、順次ファイル、壊れた媒体、満杯、書き込み禁止、未挿入時の送信経路。
- 観測しないドライブ・座標・本体長・上書き形態への外挿。制御4位置の数値式が一意にならなかった場合の実装値。
- 割り当て表の位置160以降と、本体最終セクタの余りの値。参照 diskA の内容。
- 自作 main の書き込み実装と、公式 sub または公式 `FILES`・`LOAD` での適合測定。
