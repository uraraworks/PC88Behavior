# B52b: 要求 `0x16` が範囲の中のどこへ何を書くかを測る — 結果

記録日: 2026-11-01
規則: [b52b-sub-request-16-layout-preregistration.md](b52b-sub-request-16-layout-preregistration.md) どおり。公式の 2 走は一致した。記録は `measurements/b52b-official-1.tsv`・`-2.tsv`。

## 結果

| 行 | 番地 | L | 並び |
|---:|---|---:|---|
| 1 | `7810` | 8 | `p0 p1 b b b p0 p7 b` |
| 2 | `7810` | 2 | `p0 p1` |
| 3 | `7810` | 16 | `p0 p1 b b b p0 p7 p14 b b b b b b b b` |
| 4 | `7820` | 8 | `p0 p1 b b b b b b` |
| 5 | `7810` | 9 | `p0 p1 b b b p0 p7 b b` |

## 読み方

`7815`〜`7817` の `p0 p7 p14` は**記号の取り違え**である。元の模様 `(i*7+13)&255` の値が、送った模様 `0xA0+i` と偶然同じになる位置で、行 4 の番地では出ない。これらは元のまま（`b`）である。

したがって範囲の中で変わるのは先頭の 2 バイトだけである。公式の `0x16` は、残りのバイトを番地 A から連続では書かない。B52c で RAM 全体のどこが変わるかを測る。
