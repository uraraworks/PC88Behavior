# m7ha: 公式が連続READ DATAへ移行する判断規則 — 事前登録

## 位置づけ

`docs/spec/l3-subrom.md` 1.57節（第144版）は、条件O（公式一式）が位置48・52
（1起点）の2回のSEEK後、新しい受信runを要求せずに連続した`READ DATA`へ
移行するのに対し、自作`general_read_request`はレコードごとに新しい受信run
を受け取るたびにSEEKからやり直すため連続READへ移行しないことを確定した。

**未確定のまま3節へ引き継がれたのは「公式が連続READへ移行してよいとどう
判断しているか」である。** この判断規則が分からないまま「連続READにする」
とだけ真似ると、条件が違えば破綻する実装になる。本稿は測定と記録だけを
行い、`src/`は修正しない。

## 段階0（本稿）: 事前登録を測定前にコミットする

本稿は測定を1回も走らせる前にコミットする。測定後の書き換え・amendは
行わない。

## 測定条件（共通）

- ROM: `PC88_REF_ROM_DIR`（未設定時`private/rom`）の公式一式（条件O）のみ。
  本稿は経路特定（`m7gz`が既に条件M側の欠落構造を確定済み）ではなく
  公式の判断規則を探るのが目的のため、混成ROM（条件M）の追加測定は
  必須としない。
- A: `disk#8`（`650cfac8`）の使い捨て複製に固定（起動可能ディスク）。
- B: 主対象は`disk#10`（`0c6f7a53`、`READ DATA` 108件）。段階3の他候補は
  `m7gg`が確認済みの読める7候補から、`READ DATA`件数が異なる2本
  （`disk#2`＝`3c218749`＝7件、`disk#1`＝`0cd0727b`＝5件）を選ぶ。
- 打鍵は`m7gy`・`m7gz`と同一: `--type-at 300 --type '\n' --type-at 700
  --type 'FILES 2\n' --frames 3000`。
- ディスクはすべて`tools/stage_disk_by_digest.sh`でダイジェストから
  中立パスを得てから使う。実ファイル名を扱う経路を作らない。

## 段階1: 移行の直前に何が起きているかを、値を見ずに特定する

条件Oの`disk#10`・`FILES 2`ログについて、既存モジュール
（`tools/analyze_write_path.parse_commands`・`tools/compare_l3_entry_fdc.
command_names`・`tools/analyze_main_to_sub.parse_iolog`・
`tools/analyze_record_boundaries.window_a_runs`）を呼ぶ使い捨てスクリプト
（scratchpad配下、コミットしない）で、起動からの完全なFDCコマンド種別列
（1.57節・`m7gz`と同じ数え方、`--after-frame`無し相当）を求め、以下を
**値を見ずに**記述する:

- 位置48・52（1起点）のSEEKの前後で、`READ DATA`が連続する区間の**開始位置
  ・長さ**（SEEKに挟まれず連続する`READ DATA`の最大run）。
- 1.37節が扱う交換（`0x06`受信→`0xC0`送信→`0x12`受信）が、位置48〜56付近
  （2回目のSEEK直後から連続READ開始までの間）に**現れるかどうか**。
  現れなければ「現れなかった」と書く。
- `general_read_request`の呼び出し側から見て、連続READ区間の**各READ DATA
  が指定するC（シリンダ）が、直前に発行されたSEEKのCと一致するか**を、
  `tools/compare_l3_entry_fdc.stage_cylinder_consistency`（値を出さず真偽
  だけを返す既存関数）で確認する。
- SEEKコマンドが**位置48・52以降にも再出現するか**（起動からの完全列
  全体で）。再出現する位置があれば段番号だけを記録する。

## 段階2: 規則の候補を立て、区別できる観測で絞る

段階1の観測から、以下の候補を立てる。**候補ごとに、真なら観測されるはず
のこと・偽なら観測されないはずのことを先に書く。**

### 候補H1: 同一トラック仮説
「次レコードの目標シリンダ（C）が、直前に発行済みのSEEKが指定したCと
一致するときはSEEKを省略する」。

- 真なら: 連続READ区間の**全レコード**で`stage_cylinder_consistency
  (直前SEEK, 該当READ) == True`になるはず。
- 偽なら: 連続READ区間の一部で`False`になるレコードがあるはず（それでも
  SEEKなしでREADが続いている）。
- 区別できる観測: `disk#10`（108件）の連続READ区間全体を走査し、`False`
  が1件でもあれば候補を弱める。また、段階1で見つけた「SEEKの再出現位置」
  があれば、その直前のREADのCと再出現SEEKのCを比較し、
  `stage_cylinder_consistency`が`False`（＝トラックが変わったからこそ
  再SEEKした）と一致するかを見る——一致すれば強い支持になる。

### 候補H2: 固定回数上限仮説
「連続READへ移行した後は、SEEK/READの4コマンド単位に戻らず、固定の
上限回数（または無制限）まで連続READを続ける」——トラックの同一性とは
無関係。

- 真なら: `disk#10`の連続READ区間内でSEEK再出現位置があるとすれば、それは
  レコード数（カウント）に依存した固定間隔で現れるはずで、
  `stage_cylinder_consistency`の真偽とは無関係に現れる。
- 偽なら: SEEK再出現位置は常に`stage_cylinder_consistency==False`の直後
  にのみ現れる（H1が説明する）。
- 区別できる観測: H1と同じデータ（disk#10内のSEEK再出現位置とその前後の
  `stage_cylinder_consistency`）で両候補を同時に評価する。H1が支持されれば
  H2は積極的には支持されない（両立しない領域がある場合のみ判別可能）。

### 候補H3: 直前受信runの形依存仮説
「直前の受信runが1.36節の特定の分類（`0x02`類、run長5・直後READ）で
あるときだけ連続READへ移行する」。

- **この候補は移行の"定義"（新しい受信runが来ないことがそのまま連続READ
  という記述）に近く、判断規則の"根拠"の説明にはならない可能性が高い**
  ——その旨を明記した上で、段階1の観測（56に至るまで新しい受信runが無い
  こと自体）と矛盾しないかだけ確認する。

### 候補H4: 直前READ結果依存仮説
「直前の`READ DATA`の結果が正常終了（エラーなし）のときだけ連続READへ
移行する」。

- 真なら: 連続READ区間内の各READ結果（`tools/compare_l3_entry_fdc.
  is_error_status`、値を出さず真偽のみ）はすべて`False`（正常）のはず。
- **弱い必要条件**であり、単独では十分性を示せない（正常終了はほぼ常に
  真であるため）。参考情報として記録するにとどめる。

## 段階3: 他候補での再現

`disk#2`（7件）・`disk#1`（5件）でも同じ条件O・`FILES 2`を測り、以下を
確認する:

- 位置48・52相当の2回のSEEK後、連続READへ移行する構造が現れるか。
- 現れる場合、`stage_cylinder_consistency`が段階2と同じ形で成り立つか。
- 現れない場合、それは「連続読み出しが続く条件でないと観測窓に現れない」
  という1.57節の記述と整合すると書く（レコード数が少なく、2回目のSEEK
  後の残りレコード数が1〜数件しかないため、構造自体は判別しにくい可能性
  がある——その旨も明記する）。

## 事前登録する合格条件（測定前に固定。後から動かさない）

判定に数値比較を使わない。

1. **陽性対照**: 既存の`build_mixed_rom ... --break-drive-selector`
   （1.46節の既存故障注入）を条件M・`FILES 2`・B:=`disk#10`で測り、
   `tools/compare_l3_entry_fdc.py --after-frame 700`のunit/head差件数が
   0件より大きいことを確認する。あわせて
   `tools/analyze_error_exchange_shape_selftest.sh`のrc=0（全項目OK）を
   確認する。**この2件はいずれも`m7gz`が同一目的で通した既存の陽性対照
   であり、本稿が使う構造記述（`compare_l3_entry_fdc`の各関数・
   `parse_commands`・`window_a_runs`）と同じ基盤モジュール群の検出力を
   確認する。通らなければ以降を解釈しない。**
2. **判定規則を先にベースラインへ当てる**: 条件Oを`disk#10`・`FILES 2`で
   独立2回測り、段階1の構造記述（連続READ区間の開始位置・長さ、
   `stage_cylinder_consistency`の真偽列、SEEK再出現位置）が完全一致する
   ことを確認してから解釈する。
3. **対照条件**: `disk#10`の観測は、必ず他のB:候補（`disk#2`・`disk#1`）
   と同条件（条件O・`FILES 2`・同一打鍵）で比較する。
4. **決定論性**: 差が出た条件（`disk#10`の構造記述、および候補間で判定が
   割れた場合）は2run測って自己一致を確認する。1runにとどめた条件
   （`disk#2`・`disk#1`、差が出なければ）は明記する。
5. 元ディスクを壊さない——書き込みを伴う測定はしない（`FILES 2`のみ、
   `--save-to-disk-image`未指定）。全測定後にA:/B:双方のダイジェストが
   測定前と不変であることを確認する。
6. 成果物に実ファイル名が含まれないこと。

## 事前登録する予測（測定前に書く。どれになるかは予測しない）

- **R1**: 移行の判断規則が1つに絞れた ⇒ 次稿で修正を設計できる
- **R2**: 候補は絞れたが1つに決まらない ⇒ 何が足りないかを書く
- **R3**: 1.37節の交換が境界に現れ、そこが鍵だった ⇒ 1.37節の「測定範囲を
  越えた選択」の見直しに直結する
- **R4**: 絞れなかった ⇒ 次に何を測れば絞れるかを具体的に書く
- **R5**: 陽性対照が通らない ⇒ 解釈しない

## 測定の実務

- 混成ROMが要る場合（陽性対照のみ）は`tools/lib_l3_measure.sh`の
  `build_mixed_rom`で作る。条件O本体は公式ROMディレクトリをそのまま
  `--rom-dir`に渡す（混成不要）。
- フォアグラウンドで走らせる。`run_in_background`は使わない。
- 測定中に`git stash`・ブランチ切替・ファイル編集は重ねない。
- 無言でSKIPする分岐は作らない。SKIP・リトライ失敗は件数を数えて記録する。
- 生ログ・混成ROM・ディスク複製はリポジトリ外（scratchpad配下）に置き、
  コミットしない。
- 出力は件数・一致/不一致・rcに絞る。値の列を画面に出さない。
- `src/`は変更しない。修正しない。
- 使い捨てのデバッグでもディスクの実ファイル名を展開して表示しない。
