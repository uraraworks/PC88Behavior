# l4-s5e — INPUTと文字列関数・数値関数 — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

ゴールA（代表プログラムが動く）には、実行中のキー入力（`INPUT`）と
文字列・数値の関数が要る。`l4-s5a`〜`l4-s5d`で行の入力・`RUN`・流れの
制御・変数・`IF`・配列を測った。本ノートはその続きとして、`INPUT`と
主要な文字列関数・数値関数を測る。

## 問い

- Q1 `INPUT`（E1・E2）: プロンプトの後に入力した値が正しく変数へ入り、
  計算結果が出力されるか
- Q2 文字列関数（E3〜E10）: `MID$`・`LEN`・`LEFT$`・`RIGHT$`・`VAL`・
  `STR$`（先頭の空白の有無を含む）・`ASC`・文字列の`+`結合の値
- Q3 整数化（E11〜E14）: `INT`（床関数）・`FIX`（切り捨て）・`CINT`
  （半端の丸め方向。絶対値の大きい側か最近接偶数か）
- Q4 その他（E15・E16）: `ABS`・`SGN`・`SQR`・`SIN`・`COS`の値（答えが
  割り切れる入力だけを選んでいる。割り切れない値を使う関数の精度検証
  は別の測定に回す）

## 腕（16腕＋陽性対照1腕）

打鍵はこのまま使う（英字は小文字）。プログラムの腕（E1・E2）は`new`
のあと行を打ち`run`を打つ。それ以外は直接モードの1行（`new`・`run`は
不要）。

| 腕 | 打鍵文字列（`\n`は改行） | 目的 |
|---|---|---|
| E1 | `new`/`10 input a`/`20 print a*2`/`run`、続けて`21` | Q1 単一変数のINPUT |
| E2 | `new`/`10 input a,b`/`20 print a+b`/`run`、続けて`3,4` | Q1 複数変数のINPUT |
| E3 | `print mid$("12345",2,3)` | Q2 MID$ |
| E4 | `print len("12345")` | Q2 LEN |
| E5 | `print left$("12345",2)` | Q2 LEFT$ |
| E6 | `print right$("12345",2)` | Q2 RIGHT$ |
| E7 | `print val("12")+1` | Q2 VAL |
| E8 | `print str$(12)` | Q2 STR$（先頭空白） |
| E9 | `print asc("1")` | Q2 ASC |
| E10 | `a$="12"+"34":print a$` | Q2 文字列の+結合 |
| E11 | `print int(-1.5)` | Q3 INT |
| E12 | `print fix(-1.5)` | Q3 FIX |
| E13 | `print cint(2.5)` | Q3 CINT（正の半端） |
| E14 | `print cint(-2.5)` | Q3 CINT（負の半端） |
| E15 | `print abs(-3);sgn(-3);sgn(0)` | Q4 ABS・SGN |
| E16 | `print sqr(16);sin(0);cos(0)` | Q4 SQR・SIN・COS |

### 陽性対照（1腕、腕数には含めない）

直接モードの`print 7717`（`l4-s4a`以来使ってきた陽性対照と同一）。

- 打鍵文字列: `print 7717\n`（文字数11）
- フレーム計算式は下記「条件・関門」節の全腕共通の式をそのまま使う:
  `line_end = 700 + 8*11 = 788`、`dump = line_end + 300 = 1088`、
  `run = dump + 200 = 1288`（`l4-s5c`・`l4-s5d`の作法を踏襲し、陽性
  対照のフレーム式も本文に明記する）。

腕の総数: **16腕**（E1〜E16）。各腕2走（決定論性の関門G3）。

## E1・E2の扱い（RUN後にプロンプトを待って入力する）

E1・E2は、`run`でプログラムが`INPUT`文に到達し、プロンプト（`?`）が
表示された後に、入力値を打つ。フレームの決め方は`l4-s5d`のD12
（`run`の後に`cont`を打つ扱い）と同じ考え方を使う。

```
prog        = 冒頭の打鍵（new〜run。例: E1なら
              "new\n10 input a\n20 print a*2\nrun\n"）
n1          = len(prog)
line_end1   = 700 + 8 * n1
dump1       = line_end1 + 300   （プロンプトが出るまでの余裕。D12の
                                   run出力完了確認と同じ+300フレーム
                                   を流用する。INPUTのプロンプトは
                                   PRINT1回分程度の短い出力であり、
                                   D12のSTOP応答〔Ok相当の応答〕と
                                   同程度以下の分量で済むため、同じ
                                   余裕で足りると判断する）
type_at2    = dump1              （プロンプトが出ていることを、後述の
                                   「プロンプト出現の判定方法」で確認
                                   した後、続けて入力値を打つ）
val         = 入力値（E1なら"21\n"、E2なら"3,4\n"）
n2          = len(val)
line_end2   = type_at2 + 8 * n2
dump2       = line_end2 + 300
run2        = dump2 + 200
```

**プロンプト出現の判定方法**: `type_at2`の直前（`dump1`）に単独の写し
を取り、`tools/l4_vram_probe.py --nonblank-summary-rows`で、`run`を
打った行の次の相対行（プロンプトが出ると期待される行）の非空白セル
件数が0でないことを確認する。プロンプトの文字コードそのものは見ない
（後述「記録する内容」節のとおり、プロンプトの行は件数と範囲だけを
扱う対象であるため、出現の判定にも文字コードを使わない）。

## 条件・関門

`l4-s5d`（`697ffbf`）の「条件・関門」節をそのまま踏襲する。

- 起動settle`--type-at 300 --type '\n'`、実打鍵開始`--type-at 700`
- 1文字あたり`hold+gap=8`フレーム/文字（`\n`も1文字として数える）
- フレーム計算式（全腕共通。陽性対照にも同じ式を適用する）:
  ```
  line_end(k) = 700 + 8 * (その腕で打った文字数の累計。\n も1文字)
  dump(k)     = line_end(k) + 300
  run(k)      = dump(k) + 200
  ```
- 写しは打鍵前（`--type-at`の10フレーム前=690）と`dump(k)`後の2枚を
  `--diff-before`/`--diff-after`に渡す（E1・E2を除く。E1・E2は「E1・
  E2の扱い」節のとおり3枚: 打鍵前・プロンプト確認用・最終）。

## 記録する内容

`l4-s5c`（`09c933a`）で定めた手順をそのまま踏襲する。

- **`Ok`行の位置（打った行からの相対行）と、出力の行数を、すべての
  腕で必ず記録する。**
- 出力行は、**行ごとに**`l4-s4a`の数値分類器（`tools/l4_s4a_float_
  classify.py`、`5735eb3`）を適用する。`numeric_output`と分類された
  行は、(相対行, 相対桁, 文字コード)の並びをそのまま記録する。それ
  以外の行（プロンプト・エラー・`Ok`自身の文字列等）は、件数と位置の
  範囲だけを記録する。コード・文言は一切出さない。
- **E1・E2のプロンプトの行**: `INPUT`のプロンプト（`?`）が出る行は、
  上記のとおり件数と範囲だけを記録する（システムが生成する記号であり、
  自分で打った内容の直接のエコーではないため、`l4-s4a`のエラー行と
  同じ扱いにする）。
- **E1・E2の記録は、`run`を打った後プロンプトが出た時点（「E1・E2の
  扱い」節の`dump1`）の写しと、入力値を打った後（`dump2`）の写しを
  分けて記録する**（`l4-s5d`のD12が`run`後・`cont`後を分けて記録した
  のと同じ考え方）。

## 本文を出さない取り扱い

`l4-s4a`〜`l4-s5d`と同一。「記録する内容」節の分類規則に従い、
`numeric_output`の行だけコードを記録し、それ以外は件数と範囲だけに
する。分類器（`tools/l4_s4a_float_classify.py`）は集合外のコードを
標準出力・標準エラーへ出さない設計であることが`5735eb3`の時点で確認
済み。

## 関門

`l4-s5d`のG1〜G5・G8と同一（G6は対になる予測表が無いため本測定にも
適用しない）。

- G1 器具の自己検査: 測定時HEADで`tools/harness/vram_dump_selftest.sh`・
  `tools/harness/vram_dump_dynamic_selftest.sh`・
  `tools/harness/key_matrix_selftest.sh`・
  `tools/harness/type_untypable_selftest.sh`・
  `tools/screen_content_leak_selftest.sh`の全項目がOK
- G2 取りこぼし0・打てない文字の警告0（全走のstderrで確認）
- G3 決定論性: 各腕2走とも、写しはファイルのsha256が一致、記録は
  sha256が一致（E1・E2はプロンプト確認用の写しと最終写しの両方で
  確認する）
- G4 陰性対照: 何も打たない走（起動settleのみ）で差分0件
- G5 陽性対照: 直接モードの`print 7717`腕で`7717`の並びを確認
- G8 出力完了の確認: 「後」の写しで、出力行の後に`Ok`行が現れている
  こと。E1・E2は`dump1`でプロンプトの非空白セル件数が0でないこと（G8
  相当。`Ok`行の代わりにプロンプトの出現で確認する）、`dump2`で最終
  出力の後に`Ok`行が現れていることの両方を確認する。現れない腕は
  `gate_failed`とし、「写しが早すぎた」とだけ記述する

判定の前にG1〜G5・G8がすべて真であること。いずれかが偽の腕は、その
腕を`gate_failed`として判定に含めず、理由を記述する。

## 判定

判定名はこの事前登録に書いたものだけを使う。「記録する内容」節を
参照する。当てはまらない形はすべて`other`とし、記述で補う。

- Q1（E1・E2）: `input_ok`（プロンプトが出て、入力した値が変数へ入り、
  計算結果〔E1は入力値×2、E2は入力値の和〕が出力される）／`other`。
  プロンプトの行は件数と範囲のみを記述する。
- Q2（E3〜E10）: `fn_ok`（各関数が期待どおりの型・値を返す）／`other`。
  腕ごとに出力値をそのまま記述する。
- Q3（E11〜E14）: 記述に加え、丸め方向の判定を付ける。腕ごとの値を
  そのまま記述したうえで、E13・E14（`CINT`の半端）については
  `rounds_half_away`（半分は絶対値の大きい側）／`rounds_half_even`
  （最近接偶数）／`other`。
- Q4（E15・E16）: 記述のみ（判定名は付けない）。各腕の出力値をそのまま
  書く。
- `gate_failed`: 関門のいずれかが偽だった腕。判定に含めず、理由を
  記述する。

## 器具の確認（公式ROMは使わない）

測定開始前に、自作main ROM（測定時HEAD`ec2375f`から`src/build_main_
rom.py`で組み立て）に対し、16腕（E1・E2は「E1・E2の扱い」節の2段階
打鍵）＋陽性対照の計17腕すべてを打鍵し、各行のエコーが打鍵どおりに
届くかを`tools/l4_vram_probe.py --marker`（各腕の打鍵文字列を`\n`で
分割し、各行をそれぞれmarkerとして指定）で確認した。**自作ROMはまだ
プログラムモードを持たないため、実際の`INPUT`・関数の挙動は見ておらず、
エコーだけを確認した。**

結果: **17腕すべてで、全行のエコーが打鍵どおりに出現した**（腕ごとの
全行でmarker一致、打鍵前の走行失敗〔型チェックによる事前拒否〕も
無し。E1の入力値`21`・E2の入力値`3,4`も、続けて打った打鍵としてmarker
一致した）。`$`（E5・E6・E8・E10）、`"`（E3〜E9）、`(`・`)`（E3〜E9・
E11〜E16）、`,`（E2・E3・E14〜E16は含まないがE2・E3の引数区切り）、
`;`（E15・E16）、`:`（E10）を含め、届かなかった記号は無かった。

作業に使ったROM・写し・スクリプトはリポジトリ外の使い捨てディレクトリ
（scratchpad配下）に置き、確認後に削除した。
