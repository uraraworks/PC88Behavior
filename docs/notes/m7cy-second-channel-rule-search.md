# m7cy: 第2チャンネル生成規則探索の事前登録

実施日: 2026-08-27

本稿は、第2チャンネル（main `IN $FC` = sub `OUT $FD`）の構造測定と
生成規則探索について、到達条件・観測指標・候補・打ち切り条件を実測前に
固定する。既知の出発点は、公式6672件、自作6414件、値の一致プレフィックス
779件、第1チャンネル（main `IN $FD` = sub `OUT $FC`）5635件の完全一致である。

## 到達条件

第1段の到達条件は、公式一式と混成の各ログについて、最初の
`sub OUT $FC` より前を「バルク前」、最初から最後の `sub OUT $FC` と同じ
共通クロック範囲を「バルク中」、最後より後を「バルク後」と先に定義し、
`sub OUT $FC` と `sub OUT $FD` の件数を3区間へ分解できることとする。
境界上のイベントはバルク中へ含める。共通クロックが欠けるログ、境界が無いログ、
時系列が逆転するログは測定失敗とし、0件を成功扱いしない。

算術仮説「第2チャンネルはバルク前779件、バルク中は公式5893件・混成5635件、
公式だけ258件多い」は期待値にしない。上記の独立な境界定義で肯定または否定する。
バルク中の2ポートが一対一でなければ、`OUT $FC` を基準に、余分な
`OUT $FD` の出現位置だけを記録する。先頭・末尾への集中、隣接する
`OUT $FC` 間の位置、余分イベント間の距離、256件その他の周期、境界との一致を
調べる。位置は0-based/1-basedの別を出力に明記する。

第2段の到達条件は、公式値を表示せず比較器内部だけで照合し、各候補について
第2チャンネル全列の件数と値の一致プレフィックス長を得ることとする。
既知779件を1件でも超えた候補があれば伸長と判定し、第1チャンネル5635件の
完全一致を維持する候補だけを残す。完全一致に届かない候補を規則確定とは呼ばない。

## 観測指標

記録する指標は、両モード・両ポートのバルク前／中／後の件数、余分イベントの位置と
間隔、その度数、一致プレフィックス長、候補条件数、故障注入の検出数、必要に応じて
列全体のSHA-256だけとする。比較対象の値、候補が生成した値、最初の不一致値、
前後の値窓は一切出力しない。

解析器には合成入力だけを使うselftestを付ける。正常な3区間分解、境界欠落、
共通クロック欠落、余分イベントの既知周期を検査する。探索判定器には、合成列で
プレフィックスが779を超えて伸びる陽性対照、先頭から不一致となる陰性対照、
常に779を返す故障、常に一致とする故障を注入し、全故障を検出して空振り0件を必須とする。

## 候補規則

第1段で余分な位置が観測された場合は、その位置へ候補値を挿入して公式と同じ
イベント配置を作る。周期や境界が観測されなければ、等間隔挿入を推測で増やさず、
既存イベントと一対一に生成できる候補だけを値探索の対象とする。優先順位は次のとおり。

1. 位置由来: バルク内0-based index `i` の下位バイト `i & 0xFF`、
   `(i+k) & 0xFF`。`k` はまず -4..+4、構造測定でレコード周期が得られた場合は
   その境界起点とレコード番号も追加する。
2. オフセット違い: 第1チャンネルと完全一致している既知データ列を `D` とし、
   `D[2i+1+k]` 相当の既存生成元参照を `k=-4..+4` で振る。範囲外は候補不成立とし、
   周回させない。
3. 加工: 各未加工候補に対し8bit補数、ビット反転、定数XOR、`D+i`、
   1〜7bitの左右ローテートを適用する。定数XORは0..255を有限走査する。
4. 別領域起点: 自作側で公開仕様から生成済みの別セクタ、前後セクタ、別トラック、
   読込み済み別バッファを起点とする。同じ媒体座標の単なる再試行は重複候補に数えない。
5. 対の入れ替え: 偶数／奇数のチャンネル割当てを逆にする陰性対照。
   第1チャンネルの一致プレフィックスが5635未満へ落ちることを必須確認する。
6. 累積値: 8bit加算・XORの走行チェックサム（初期値0と255、更新前／更新後出力）、
   公開されたCRC-8の代表的な多項式について初期値0と255、反転有無を有限走査する。

m7bbで既に陰性だった同位置、前後1位置、直前値の複製、FDC読出し列との単純な
位置対応だけの4系統は、単独候補として再測定しない。上記の新しい加工・広い
オフセット・構造上の挿入と組み合わさる場合だけ別候補として数える。

## 打ち切り条件

上記候補を有限集合として列挙し、重複を除いた全候補を1周だけ掃く。全候補の
一致プレフィックス長が779から1件も伸びなければ、「ここが現在の測定手法の境界」
と記録し、その周で打ち切る。類似定数、別のCRC多項式、別媒体座標を際限なく追加しない。
打ち切り時も、掃いた総条件数と各条件のprefix長を数字で残す。

779を超える候補が出た場合だけ、その候補群を同じ有限な加工範囲で絞り込み、
完全一致または次の不一致位置まで進める。伸長が再現せず、合成陽性対照も失敗した場合は
解析器故障として結果を破棄し、修正後に全候補を先頭から再実行する。

## 情報境界

公式ROM・公式ディスクは実行して測定し、内容を読まない。`private/` 配下の内容を
直接開かない。`xxd`、`od`、`hexdump`、`strings`、逆アセンブラを公式媒体へ使わない。
生ログと媒体複製はリポジトリ外の一時領域だけに置く。記録してよいのは件数、位置、
一致プレフィックス長、SHA-256、公開μPD765のコマンド名だけである。
2本のチャンネルを流れる値は、自作候補を含めて1バイトも標準出力、測定ノート、
テスト結果、コミット対象、コミットメッセージへ出さない。

ここまでを実測前の事前登録とする。
