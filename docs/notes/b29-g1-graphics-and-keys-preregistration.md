# B29: G1 のグラフィック画面とキー入力後を、公式と自作で一致だけ比べる — 事前登録

記録日: 2026-11-01
位置づけ: [B28](b28-g1-after-rom-version-results.md) はテキスト画面だけを、打鍵なしの 3600 フレームで比べた。**このノートは測定より先にコミットする。**

## 1. 問い

自作 ROM の上の G1 は、グラフィックを含む画面でも公式と一致するか。もっと先のフレームと、キーを押したあとでも一致するか。

## 2. 条件

OO・SS 各 2 走。自作はブランチ `impl/l3-sub-load-run` の先頭のビルド。走ごとにディスクを複製し、`*.srm` を消す。クラウドの実行環境で行う。

| 腕 | フレーム | 打鍵 |
|---|---|---|
| A | 1800 | なし |
| B | 3600 | なし |
| C | 7200 | なし |
| D | 14400 | なし |
| E | 7200 | フレーム 3600 でリターン |
| F | 7200 | フレーム 3600 でスペース |
| G | 14400 | フレーム 3600 と 7200 でリターン |

打鍵は既存の `--type` / `--type-at`（`--key-hold`・`--key-gap` は既定）で与える。打鍵は G1 の操作を知らずに選んだ、よくある 2 つのキーである。

## 3. 比べ方

`--screenshot` の画像と、`--out` のテキスト画面を走ごとに作り、**一致するかどうかだけ**を見る。

- 画像: 同じ腕の中で、OO の 2 走、SS の 2 走、OO 対 SS を `cmp` する
- テキスト: `tools/check_l3_screen_output.py` の `screen_compare`

**画像はどこへも置かない。** ライブラリにも、会話にも出さない。開かない。ハッシュも記録しない。作業場の外へ出さず、判定のあとで消す。

## 4. 判定（事前に決める）

- 公式の 2 走が画像で一致しない腕は「公式が揺れる」として OO 対 SS の判定をしない
- 腕ごとに「画像が一致」「テキストが一致」の真偽を書く
- 打鍵の腕で OO の画面が打鍵なしの腕と変わらないときは「打鍵が効いていない」と書く（OO の腕 C と腕 E・F の画像の一致を比べる）
- 一致しない最初の腕を、次の切り分けの対象にする。原因は書かない
