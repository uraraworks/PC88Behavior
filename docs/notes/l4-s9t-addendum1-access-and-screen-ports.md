## 初回で出た疑問（開示）

- 初回の予測「点を1つ描くのに 0x5C・0x5D・0x5E のいずれかを書く」（群の項目 `acc_uses_5c_5e`）は外れた。カラーモードの `pset` では 0x5C〜0x5E の書き込みが**無く**、
  0x34（値が色に応じて変わる）と 0x35（0x80 と 0 の往復）が動いていた。一方、白黒モード（`screen 1`）では 0x5C/5D/5E（アクティブページに対応する 1 つ）と 0x5F、0x34 の別の値（0xEE・0xDD・0xBB 系）が出た。
  ただし初回は連長圧縮列の**先頭 60 件**（`cls 3` の塗りが占める）しか持たず、`pset` 1 回分の列そのものは取れていない。ポートごとの値の初出順と最後の値だけが手がかり。
- 画面スイッチ（`sw-*`）は 0x31 の bit3 を使う（0x19 → 0x11）が、`screen` 文の各引数が 0x31・0x53 のどれをどう動かすかは、初回の `scr-e*` が複数の文をまとめていたため切り分けられていない
  （0x53 に 0xF4・0xF8 が現れた。`screen 2` では 0x31 が 0x08 になり 0x53 が 0xF8）。

## 追加する腕（23本）と採るもの

器具の拡張は 1 点: 腕に `evx` を付けたときだけ、メイン CPU の OUT のうち 0x31・0x34・0x35・0x53・0x5C〜0x5F の**全列**（連長圧縮、最大 3000 件）を `evx` に記録する。
制御ポートの値で、データポートは採らない（s9o〜s9s と同じ判断）。他の腕の観測は変わらない（`evx` を持たない）。
