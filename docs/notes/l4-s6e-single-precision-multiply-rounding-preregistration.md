# l4-s6e — 候補M7(範囲縮約の単精度乗算だけ正しい丸め)の事前登録

記録日: 2026-09-19
状態: 事前登録(測定前)。(i)は記録済み62腕への事後照合(参考)、(ii)が
測定前に固定する本命の判定。

## 位置づけ・原因の切り分け(手順1、根拠)

親の事後検算(D22 `sin(99999)`等がπから求めた正しい範囲縮約と一致)を
受け、`tools/l4_mbf_oracle_v5_m5.py`・`v3`が使う単精度定数(1/(2π)・
π/2)のビットと、範囲縮約の単精度乗算の丸めのどちらが原因かを検算した
(公式ROM不使用、πの高精度値からの直接計算のみ)。

1. **定数のビットは正しい。** `IN2PI_SINGLE`(`force_to_single(v3.IN2PI)`)
   ・`v3.PI2`はいずれも、独立に計算した「πの高精度値から求めた
   1/(2π)・π/2を単精度へ正しく丸めた値」と仮数まで完全一致した。
2. **範囲縮約の最初の乗算(`x×IN2PI_SINGLE`)の丸めが原因だった。**
   `SIN(99999)`について、v2の`gw_binop`(GW-BASICの`$FMULS`の粗い丸め、
   48bit積の下位16bitをスティッキーに畳み込まず捨てる、既知の課題)
   による結果(仮数`0xf8ad56`)と、厳密積を1回だけ正しく丸めた結果
   (仮数`0xf8ad57`)が1違い、正しい丸めの方が真値に近かった
   (誤差0.000193対0.001170)。この1ULPの差が、後続の「大きな整数部を
   引く」処理で増幅され、観測された52108ULPの食い違いにつながったと
   考えられる。

## 候補M7

`tools/l4_mbf_oracle_v7_m7.py`(新規、v3・v5・v6は無改変)。M6(角度領域
でπ/2を単精度加算しSINをやり直す)と同じ構造のまま、**範囲縮約の
乗算(`x×IN2PI_SINGLE`)だけを正しい丸め(厳密積→1回round-half-even)に
差し替える。** それ以外(多項式評価の乗算・加減算・除算)は変更していない。
係数の当てはめは行っていない。根拠・検算コードの詳細はファイル冒頭の
docstring参照。

## (i) 記録済み62腕への事後照合(参考)

l4-s6b(19腕)+l4-s6c(21腕)+l4-s6d(22腕)の記録済み62腕全てに対し、M6・
M7の予測を単精度ビットで照合した(公式ROM未使用、既に記録済みの数値
文字列のみ使用)。

**62腕中M7は50腕(81%)がビット完全一致した(M6は44腕、71%)。**
特に、A05(`sin(6.283185)`、従来は指数が違う大きな不一致)・D09/A11
(`cos(200)`)・D10/A12(`tan(200)`)・D22(`sin(99999)`)がいずれもM7で
完全一致に変わった。

残る不一致12腕は、A16(`sin(6.28)`、M6でも不一致だったが、M7ではむしろ
ULP差が拡大した=近接2πのごく特殊な境界での挙動)を除き、いずれも
±1〜2ULPの小さい食い違いにとどまった:
A07(`sin(50)`,+1)・A09(`tan(50)`,+1)・A15(`tan(1.2)`,+6)・
C07(`sin(88)`,+1)・C09(`tan(88)`,+1)・C11(`cos(500)`,+1)・
D04(`tan(50)`,+1)・D06(`tan(77)`,+1)・D11(`cos(999)`,+2)・
D12(`tan(999)`,-2)・D18(`tan(54321)`,+1)。

TANの腕(A09・D04・D06・D18・D12)に±1〜2ULPが集中しており、SIN/COSの
除算(`$FDIVS`)自体の丸めに、まだ捉えきれていない小さな差がある
可能性がある(手順3、深追いせず(ii)で傾向だけ見る)。

## 判定

- 21腕それぞれについて、公式出力がM6・M7のどちらの予測と一致するかを
  記録し、単精度ビットのULP差も出す。
- 「割れる」15腕でM7一致率がM6一致率よりはっきり高ければM7を支持する。
- TANの腕(E03・E06・E09・E12・E15・E18・E21)のULP差の傾向(手順3、
  ±1〜2ULP級の残差が引き続き見られるか)を記述する。
- 外れが残れば、ULP差の分布・傾向を書いて止める(深追いしない)。
