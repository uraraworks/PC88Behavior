# m7co — no_disk要求長分岐で3容疑者を除外

日付: 2026-08-24

## 結論

この周で原因は見つかっていない。介入が成果物へ届いた状態でも指標が不変だったため、
次の3候補を相対位置+0の要求長5対6を生む原因から除外した。

1. 相対-3の256バイト応答の中身
2. 相対-1の1バイト応答の中身
3. 軸近傍で自作subが受理する2件の割り込み

3は抑止によって混成の受理を2件から公式と同じ0件へ変えたが、+0要求長6、交換prefix
36/54、画面3指標、各位置への到達clock差は不変だった。確定したのはこの3候補が原因
ではないことだけであり、原因そのものは未確定である。

## 校正と観測された時間構造

交換イベント列を先頭から値も含めて比較すると、最初の差は相対+0そのものの構造差
（公式5バイト、混成6バイト）だった。それより手前は構造も交換値も公式と混成で一致する。

一方、相対-4先頭を基準にした各run到達clockの混成−公式差は、-3が+4、-2が+25、
-1が+29、+0が-76だった。軸直前の1バイト応答では、main待機開始→sub準備が
公式2clock／混成5clock、sub準備→main読取が公式5clock／混成6clockだった。
また窓内のmain側割り込み受理は公式683件／混成679件である。

これらは時間構造の差を示す観測でしかない。その差が+0の分岐を生んだという帰属は
取れておらず、「原因はタイミングである」とは結論しない。残る帰属候補はmain側の
割り込み受理差4件と応答準備の遅さである。

## 行き止まりと検査系の訂正

`search_error_response_candidate.py`の一般化で`measure_once`の戻り値を
`AbstractResult`から`(AbstractResult, 介入証跡)`へ変えた際、既存のbit6帰属回帰検査だけが
タプルを展開せず`compare_result`へ渡す回帰を作った。新機能側のselftestは全通しし、壊れたのは
既存の検査だった。公式環境が要る検査は委譲先の確認では本体がSKIPされるため、この破壊が
見えなかった。「SKIPした検査が合格の顔をする」失敗の再来である。

戻り値は介入成立の証跡に必要なので旧型へ戻さず、bit6検査を新型へ合わせた。さらに公式環境や
実測を使わず、合成した`(AbstractResult, 介入証跡)`を同じ判定関数へ通す型契約selftestを独立に
登録した。未展開タプルを`compare_result`へ渡す今回と同型の故障注入も、この検査の失敗条件にした。

1回目の4arm帰属実験は、対照、-3介入、-1介入、両介入の全armが同一だった。当初は
両応答を原因から除外しかけたが、成果物が1ビットも変わらないことは介入がrunへ届いて
いない徴候だった。校正軸の-3/-1を全区間の同形窓へ拡張したため、先行介入が後続run列を
ずらしていた。この走から帰属結論は採らない。

介入対象を軸直結の各1 runだけへ限定し、対象直前のrun構造prefixをSHA-256で照合した。
さらに成立判定を「介入箇所を踏んだ回数」から「成果物が対照と変わったか」へ変更した。
成果物が変わったうえで指標だけが動かない場合は
`intervention_effective_no_metric_change`として、失敗でなく帰属結論にした。

3armの到達clock指標が同一だったため、対照結果の流用を疑い、陽性対照
`clock_shift_257`を追加した。陽性対照では-3/-2/-1/+0の全`arrival_delta`が正確に
+257ずれ、`metric_source`もarmごとに異なった。従って指標は各armのログから独立に
再計算され、流用ではなかった。疑って陽性対照で確かめたこの手順自体を検査記録とする。

timing報告は当初33KBあり判読しにくかったため、既定出力を差分要約へ縮め、全量は
`--verbose`時の別ファイルへ移した。各armの再計算元を追跡できるよう、指標には
`metric_source`を付与した。

## 次境界

次は未帰属のまま残る二候補、窓内main側割り込み受理の差4件と、軸直前応答の準備が
混成で遅いことを個別に介入して帰属する。既定実装の挙動はこの周では変更しない。

## 情報境界

記録したのは件数、位相、間隔、clock差、prefix位置、画面の行数・文字数・SHA-256だけ
である。交換値、`$FE`生値、PC、絶対clockは保存していない。生ログと詳細報告は外部の
一時領域で扱い、本文には私物の絶対パスや値の列を残さない。
