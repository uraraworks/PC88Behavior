# m7ih: ビット反転で連続READの「形」がどう変わるかを見る — 事前登録

## 位置づけ

[m7ig](m7ig-request-bit-flip-results.md)は判定M2（特異性なし）に終わったが、
**効くビットの集合が位置ごとに分かれ、入れ子になっている**ことを確定した。

```
位置1 {} ⊂ 位置3 {40,80} ⊂ 位置4 {10,20,40,80} ⊂ 位置0 = 位置2 {全部}
```

`m7ig`は次の一手として2つを挙げた。**本稿はその両方を1つの測定で行う。**

1. **位置3と位置4の感度差`{10,20}`**（位置4に固有で位置3に無い2ビット）を狙う。
2. **非保持armのrun長の並びがどう変わったか**を見る。`m7ig`は「run長9が12本か
   否か」でしか分類しておらず、**壊れ方の中身を捨てていた。**

**本稿は問いを「位置4は特別か」から「壊れ方はどんな形か」へ移す。**
`m7ig`が示したとおり、位置0・位置2が全ビットで壊れる以上、「位置4だけが壊れる」
形の証拠はこの経路では取りにくい。**形を見るほうが、値を読まずに意味へ迫る
道として筋が良い。**

本稿は測定と記録だけを行い、`src/`・`tools/`は修正しない。

## なぜ「形」が意味に迫るのか

連続READ構造は**「SEEK 1回 + READ DATA 9件」が12周期**である（`m7hb`）。
この「9」と「12」のどちらが動くかで、壊した位置・ビットが何に効いているかが
分かれる。

- **run長そのもの（9）が別の一定値に変わる**なら、その位置・ビットは
  **1回のSEEKで何件読むか**に効いている可能性がある。
- **run長は9のままで本数（12）だけ減る**なら、**何件読むかではなく
  どこまで続けるか／全体の量**に効いている可能性がある。

`m7ie`の`XOR 0xFF`では位置0・3・4がそろって「9のまま12本→11本」だった。
**1ビットに分解しても同じなのか、違う形が出るのかは測っていない。**

**どちらの可能性も、値を読まずに区別できる。**

## 段階0（本稿）: 事前登録を測定前にコミットする

本稿は測定を1回も走らせる前に単独でコミットする。測定後の書き換え・amendは
行わない。

## 測定条件（`m7if`／`m7ig`と同一に固定する）

- 条件Oのみ（公式ROM一式）。A:=`disk#8`（`650cfac8`）、B:=`disk#10`
  （`0c6f7a53`）。
- 打鍵は水準E（`--type-at 300 --type '\n' --type-at 700 --type 'FILES 2\n'
  --frames 3000`）。
- 対象は**交換run36**、位置0〜4。
- 水準は`m7ig`と同じ**5位置 × 8ビット = 40 arm**（`--request-intervention
  36:<POS>:xor:<MASK>`）。**armを後から追加しない。**
- `m7ig`の生ログは既にscratchpadから削除済みのため、**本稿で全40armを取り直す。**
  取り直した基準・armの分類が`m7ig`と一致することを合格条件に含める（後述）。

## 記録する指標（すべて値を出さない）

各armについて次を記録する。

- `changed`（介入が届いたか）
- FDCコマンド総数、READ DATA総数
- **READ DATAのrun長の並び（完全な列）**——`m7ig`はこれを「run長9が何本か」に
  畳んでいた。本稿は畳まずに記録する。
- run長の**多重集合**（どの長さが何本か）

## armの分類（測定前に固定。後から動かさない）

- **A型（保持）**: run長の並びが基準と完全に一致する
  （単発9本＋run長9が12本）。
- **B型（本数だけ変化）**: 現れるrun長が**1と9だけ**で、run長9の本数が12未満。
- **C型（run長そのものが変化）**: **9でも1でもないrun長**が1本以上現れる。
- **D型（不揃い・暴走）**: 上のどれでもない。FDC総数が基準（195）の10倍＝1950を
  超えるものは無条件にD型とする（`m7if`の閾値をそのまま使う）。

## 事前登録する判定（測定前に固定。後から動かさない）

- **N1（run長そのものが変わる位置・ビットが存在する）**: C型のarmが1つ以上ある。
- **N2（本数だけが変わる）**: C型が無く、B型が1つ以上ある。
- **N3（形が変わらない）**: B型もC型も無い（A型とD型だけ）。
- **O（測定不能）**: 基準が再現しない、`m7ig`の分類と食い違う、決定論性が
  確認できない。
- **O'（介入が届かなかったarmがある）**: `changed`が0のarmは判定に用いず記録する。
  全armが該当した場合は主判定をO'とする。

**どの判定になるかは予測しない。**

## 併せて記述すること（判定ではない）

1. **位置4に固有のビット`{10,20}`が属する型**と、**位置3の`{40,80}`が属する型**を
   並べる。同じ型なら「感度の幅が違うだけ」、違う型なら「効き方の質が違う」と
   いう手掛かりになる。**どちらであっても本稿は機序を主張しない。**
2. 位置・ビットごとの型の表（5×8）。
3. B型・C型について、**run長の多重集合がarm間で一致するか**。一致するなら
   同じ壊れ方をしていることになる。

## 事前登録する合格条件（測定前に固定）

1. `tools/recv_run_field_leak_selftest.sh`が全項目OK・rc=0。
2. `tools/analyze_error_exchange_shape_selftest.sh`がrc=0。
3. **基準の再現**: 摂動なしの条件Oが、FDC総数195・READ DATA 117・run長9が12本で
   あること。
4. **`m7ig`との一致**: 40armそれぞれについて、本稿の型を`m7ig`の分類
   （保持／壊れた／暴走）へ畳んだとき、`m7ig`の結果と**完全に一致すること**。
   （A型→保持、B型・C型→壊れた、D型→暴走または壊れた。FDC総数1950超が
   `m7ig`で暴走だった1armと一致すること。）食い違えば判定O。
   **これは「取り直した測定が前回と同じものを見ている」ことの確認である。**
5. **介入が届いていることをarmごとに確認**: 各armで`changed>=1`。
6. **決定論性**: 基準と、**C型に分類された全arm**（N1の根拠になるため）、
   および**位置4の8arm**について、生ログが独立2回でバイト一致すること。
   C型が無い場合は位置4の8armと基準のみ。
7. `tools/check_cleanroom.sh`が全項目OK。

## 実務上の取り決め（測定前に固定）

- **各armの生ログは、指標を取り出した直後にscratchpad内で削除する**
  （`m7ig`で40armのログが1.0GBに達したため）。削除するのはリポジトリ外の
  一時ファイルのみである。ただし**決定論性の確認に使うarm**（合格条件6の対象）は
  2回目を取り直して比較するので、その場で2回走らせて比較してから消す。
- 測定はフォアグラウンドで行い、測定中に`git stash`・ブランチ切替・`src/`の
  編集をしない。
- **反復回数を数えて出力に載せる**（`m7ig`でzshの語分割の誤りによりループが
  1回しか回らなかったため。件数以外に縮んだ手掛かりが無い）。

## 言えないこととして先に書いておくこと

- **N1が出ても「その位置のそのビットが読む件数を指定している」とは言えない。**
  言えるのは「そのビットを反転するとrun長が別の値になる」までである。
  **意味は本稿では決まらない。**
- **run長が変わったことから、元の値を推し量らない。** 例えば「run長がkになった
  から元の値はk相当だった」といった推論はしない（禁止事項5）。
- **D型（暴走・不揃い）は構造の話ではなく、要求が不正になって別経路へ落ちた
  可能性が高い。** N1の根拠にD型を使わない（C型のみを根拠とする）。
- 条件O・`disk#10`という1本のディスク・1条件である。一般性は主張しない。

## 禁止（本稿の測定中も例外なく適用）

- 公式ROMのバイト列を読まない・出力しない・保存しない。逆アセンブルしない。
- 受信run・応答runのバイト値、FDCデータポート値、シリンダ値、PCN値を出力しない。
  出してよいのは件数・run長・位置番号・**ビットマスクの指定値**・真偽値・rcのみ。
- **対象位置の値を掃引・推論で復元しない。** 全256値の`replace`掃引は行わない。
  **run長から元の値を逆算しない。**
- 画面本文の生の行を報告・ノート・コミットメッセージ・ツール出力へ書かない
  （禁止事項7）。
- 公式ディスクの実ファイル名を展開して表示しない。
- 第三者の逆アセンブルリスト・解析記事のコード断片を参照しない。
