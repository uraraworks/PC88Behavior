結果である。** 今回の指示に従い公式環境を各2run測り、AA・BA・FAB等の個別介入と

## H-D / H-Bの登録済み予測判定

**H-D（後続OPEN段階の使い回し）: 反証。** 登録規則は、E2/E3の少なくとも一方が
E1より小さく、どちらも大きくなければ支持、`E2=E1`かつ`E3=E1`なら反証だった。
実測は両指標で`E1=E2=E3=1292件・7単位`に完全一致した。従って、後続OPEN/CLOSE
包絡の使い回しが削減を生むというH-Dを、今回の3行ファイル・隣接媒体条件で反証する。
OPENとCLOSE、ディレクトリ検索と他の管理情報読出しは分離していない。

**H-B（後続読出しの内容保持）: 反証。** 登録規則は、D2/D3の少なくとも一方がD1より
小さく、どちらも大きくなければ支持、両方がD1と等しければ反証だった。実測は両指標で
`D1=D2=D3=258件・1単位`に完全一致した。従って、後続ファイルのデータ読出し費用が
内容保持により減るというH-Bを、今回の条件で反証する。メモリ領域の再利用自体が存在
しないとは言わず、I/O件数を減らす保持効果が観測されなかったという範囲に限る。

## 固定費モデルの算術検算

m7dsの登録式は`Z=P0`、`A=R1`、`B=SB`、`C=SC`を使う。

```text
pred(R2) = A + B - Z
pred(R3) = A + B + C - 2*Z
```

今回はP0〜R3限定の指示によりSB/SCを実測していないため、**登録式へ全入力を代入した
H-Fの正式判定は未了**である。SB/SCをR1と同額だと仮定して正式判定へ代用はしない。

一方、今回の値から、式が実測R2/R3へ一致するために必要なB/Cは一意に逆算できる。

| 必要値 | main `IN $FC` | READ単位 | 計算 |
|---|---:|---:|---|
| B | **8222** | **17** | R2 − A + Z |
| C | **8222** | **17** | R3 − R2 + Z |

従って、今後同じadjacent媒体でSB=8222件・17単位、SC=8222件・17単位が成立すれば、

```text
pred(R2) = 8222 + 8222 - 6672 = 9772件
             17 +   17 -    9 =   25単位
pred(R3) = 8222 + 8222 + 8222 - 2*6672 = 11322件
             17 +   17 +   17 - 2*9    =    33単位
```

となり実測へ完全一致する。`m7dp`の別媒体・別ブートQ9B単独既測値8222件・17単位は
Bの必要値と一致するが、m7dsが要求する今回のadjacent媒体SBの代用にはしない。SCは
既測値が無い。結論は**固定費モデルは算術上完全一致し得るが、H-FはSB/SC取得まで
未判定**である。

## 固定署名の再判定と故障注入

各条件run1の件数・SHA-256・READ単位・画面署名を固定後、run2を再判定し、7条件全て
一致した。P0/R3の固有マーカー、`S9C`、直後`Ok`を各々欠く画面陰性対照を全て不一致に
できた。件数破壊、SHA-256破壊、期待値0行、バルク0件も全て検出し、空振りは0件だった。

## 未了と解釈限界

- 今回指定された段階ラダーP0〜R3は全7条件・各2runを完了し、未了は無い。
- m7ds全体のうちSB/SC、AA、BA、FP0/FA/FB/FABは指示どおり未実施である。固定費モデルの
  正式判定、同一ファイル、逆順、配置介入は次回以降へ残る。
- EはOPEN/CLOSE包絡、Dは読出し追加とその後のCLOSEを含む別run差分である。H-D/H-Bの
  反証を、OPEN内部やバッファ機構一般が存在しないという主張へ拡張しない。
- QUASI88上の同じ3行ファイル・隣接媒体に対する結論で、実機一般性や別媒体へ一般化しない。
