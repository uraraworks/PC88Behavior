# 自作ROMのバナー・著作権表示に関する決定（2026-08-16）

## 背景

ALPHA-DOS の測定（コミット `e4e43c8`〜`f7f77f7`）で、`measurements/*.txt` の
終了時テキスト画面に公式ROM由来のバナー文字列が観測結果として載った。
これは**外部から観測した事実**なので測定ログに残すこと自体は問題ない。
しかし**自作ROMが同じ文字列を出力するかどうか**は全く別の判断が要る。

本ノートは M7（L4 = N88-BASIC 互換処理系）に入る前に、この2つを混同しないための
決定を記録する。

## 決定

**自作ROMは、公式の製品名バナー・著作権表示を出力しない。** 既定で禁止する。

## 判断基準 — 機能か、表現か

| | 例 | 扱い |
|---|---|---|
| 機能（ソフトが依存しうる） | `How many files(0-15)?` のような対話文、`Ok` プロンプト、空きバイト数の数値 | 必要なら再現してよい |
| 表現（誰の作品かを示す） | 公式の製品名バナー、著作権表示 | **再現しない** |

空きバイト数のような数値は実際のメモリ状態を反映した事実であり、同じ数字が
出ること自体は構わない（それは実装が正しく動いている証拠でしかない）。
一方、バナー文字列や著作権表示は「誰が書いたか」を名乗る表現であり、
機能的な必然性がない。

## 禁止する理由

- 書いていない主体の著作権表示を名乗ることになり、独立実装という主張と正面から矛盾する
- 法的な議論以前に、見た人が最初に受け取る印象がそれで決まる。
  `docs/PLAN.md` 第3節（主張ではなく構造で返す）の努力が、画面1行で崩れる
- 互換性のために必要である、という説明が立たない（バナー文字列にソフトが
  依存する例が実測で示されない限り）
- 前例: FreeDOS・C-BIOS・SeaBIOS・coreboot はいずれも自分の名前とバージョンを
  表示し、互換性は説明文の側で述べている。**「互換であることは名乗ってよく、
  相手を名乗ってはいけない」**

## 例外の扱い

ゴールB（公式ROMの完全な差し替え、番地互換）で「バナー文字列を見て分岐する
市販ソフトがある」と**測定で示された**場合に限り、個別の例外として判断する。
それまでの既定は「出さない」。測定なしに先回りで再現はしない。

## 代替経路 — 自作ROMが起動時に出すバナーの暫定案

禁止は選択肢を消すだけで代わりを指さない、というのがこのリポジトリの規律。
代わりに以下を既定案とする。プロジェクト名・バージョン番号は未確定でよい。

- **起動画面に出すのは、自分の名前とバージョンだけにする。** 例: `PC88Behavior vX.Y`。
  互換性の表明（「N88-BASIC 互換」等）を**起動画面には書かない**。
- **互換性は README・配布ページ・仕様書の側で説明として述べる。** 名詞的用法は
  説明の文脈でこそ安全で、画面上の名乗りに他社の製品名を並べると、意図に
  関わらず「その製品の一種」に見える。法的な当否以前に、印象の問題として避ける。
  前例: FreeDOS の起動画面は `FreeDOS` としか出さない。「MS-DOS compatible」は
  README や配布ページの側にある。
- **公式のレイアウト・書体・行配置に似せない。** 行数・改行位置・記号の使い方まで
  一致させると、表現の面で公式を模したことになる。文言だけでなく見た目の
  独立性も保つ。
- 著作権表示を出すなら、それは自作コードに対する自分たちの表示にする
  （公式の著作権者名・年号を書かない）。

具体的な文言・レイアウトは M7 着手時に別途決める。この暫定案は「方向性」を
示すためのものであり、確定仕様ではない。

## `docs/spec/` の運用

**`docs/spec/` に公式バナーを実例として載せない。**

理由: 委譲先（実装するエージェント）は仕様書に書かれた書式例をそのまま
再演する傾向がある。書式例として公式バナーの文字列を載せてしまうと、
「削除対象」という意図が伝わらず、実装側が親切心でそのまま実装に
書き戻すおそれがある。同じ構造の事故がバナー文字列でも起こりうる。

したがって:

- `docs/spec/` の仕様書には公式の製品名バナー・著作権表示の**文字列そのものを
  書かない**。「終了時に製品名バナーが表示される」のように一般名で記述するに留める。
- 文字列の実物が必要な場面（差分確認・回帰チェックなど）は、`measurements/`
  配下の測定ログを参照させる。測定ログは観測結果としての置き場であり、
  仕様書は実装が読む場所だから、両者の役割を分ける。

## 測定ログとの区別（再掲）

- **測定ログに公式バナーが載ること = 許容。** 外部から観測した事実の記録であり、
  由来が正しい（公式ROM→測定→ログ、という一方向の経路）。
- **自作ROMが公式バナーを出力すること = 禁止。** 自作コードが表現として
  公式を模することになり、由来の話ではなく創作の話になる。

同じ文字列でも「載っている場所」で扱いが正反対になる、という点を
実装者は必ず区別すること。
