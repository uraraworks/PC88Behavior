# m7gk: SAVE のドライブ指定構文を言語リファレンスで特定する

## 位置づけ

[m7gi](m7gi-remaining-callers-stage12-results.md) 段階2の結果として、`_recv_dispatch_write_sector`
（WRITE 経路）には B: の条件軸（B: に置いたディスクの内容を変える介入）を適用できていない。
理由は、保存先ドライブを明示して `SAVE` するときの打鍵構文が、これまでの測定では
特定できていなかったことである。本ノートは、その構文を N88-BASIC の言語リファレンスから
特定する（打鍵しての実測は次周の作業であり、本ノートの範囲外）。

## 特定できた構文

- `SAVE` 命令のファイル名指定には、**ファイル名の前にドライブ番号とコロンを置く**という
  記法がある（`<ドライブ番号>:<ファイル名>` の形）。ドライブを指定しなければ、装置側が
  暗黙に選んでいるドライブが使われる。
- **既定のドライブそのものを切り替える専用の命令は見当たらなかった。** 命令一覧
  （第2章の目次、ABS〜WINDOW までを通読）を確認したが、ドライブ選択を行う命令は
  ファイル名側にドライブ番号を書く方式のみで、"カレントドライブを変更する" ような
  独立コマンドの項目は無い。`FILES` 命令はドライブ番号の指定を省略するとドライブ1が
  選ばれる、という**個別コマンドごとの既定値**の説明はあったが、これは「既定ドライブを
  切り替える命令」とは別の話である。

まとめると、WRITE 経路に B: 軸を通すために使える構文は、`SAVE` のファイル名指定に
ドライブ番号とコロンを前置する形——つまり `SAVE"<ドライブ番号>:<ファイル名>"` の形——
になる。既定ドライブの切り替え命令は無いという理解でよい（ただし「無い」は本書1冊を
確認した限りでの結論であり、後述のとおり測定で最終確認する）。

## どの資料の何ページを見たか

`NEC PC-8801mkIIMR N88-BASIC N88-日本語BASIC REFERENCE MANUAL 1986年.pdf`
（`docs/notes/refs-nec-manuals-2026-09-04.md` の判定表で「可」の1本）。

`pdftoppm -f <N> -l <N> -r 150 -png` でページ画像化して読んだ。テキスト走査（`pdftotext`/
`grep`/`strings`）は使っていない。読んだページ（PDF 内の通しページ番号。カッコ内は
本文中のページラベル）:

- 9, 10, 11, 12（目次。第2章の命令一覧、ABS〜WINDOW を通読してドライブ切り替え系の
  独立コマンドが無いことを確認）
- 36（本文ラベル 1-10。目次との対応づけの基準点として見ただけ）
- 234（本文ラベル 2-152、NEW 命令）——本文ページ番号とPDFページ番号の対応づけ
  （オフセット算出）のために見た。NEW 命令自体は今回の主題と無関係
- 290（本文ラベル 2-208、**SAVE 命令**）——構文と実行例を確認
- 161（本文ラベル 2-79、**FILES/LFILES 命令**）——ドライブ番号省略時の既定値
  （ドライブ1）の説明を確認

いずれも命令リファレンスの本文・目次であり、資料/メモリマップ節・APPENDIX には
到達していない。

## 立入禁止範囲・(b)/(c) への抵触

`refs-nec-manuals-2026-09-04.md` の判定表で、この資料（mkIIMR REFERENCE MANUAL 1986）は
立入禁止範囲が「現時点で特定されていない」とされている本である。今回読んだページは
いずれも命令の機能・書式・解説・実行例という、(a) 言語仕様の範囲に収まる内容だった。
読んでいる最中に (b) ROM 内部の構造（番地・ワークエリア・ジャンプテーブル・メモリマップ）
や (c) 逆アセンブル・機械語コードに着地した箇所はない。

## (a) に該当すると判断した理由

`CLAUDE.md` の分類でいう (a)「ハードウェアの事実」に相当するのは測定で裏が取れる情報だが、
BASIC の**言語仕様・命令の構文**も同じ理由で (a) 側に置かれている
（CLAUDE.md「やってよいこと」に「N88-BASIC のマニュアル（言語仕様・命令の意味）を読む」
と明記）。今回確認したのは「`SAVE` のファイル名にドライブ番号を前置できる」という
構文規則であり、ROM 内部のエントリアドレスやワークエリア番地・データテーブルではない。
構文は入力した打鍵列そのもの（ユーザーがキーボードから打つ文字列）であり、装置の
外部から観測できる仕様である点で、番地・命令列とは性質が異なる。

## 測定で裏が取れることの確認方法（資料が唯一の出所にならないことの明記）

この構文理解が正しいかどうかは、**資料を読んだだけでは確定しない**。次周で
`--type` により実機（自作エミュレータ上のB案ROM混成環境）に
`SAVE"2:TQ"` のような打鍵列を投入し、`_recv_dispatch_write_sector` に到達する
FDC コマンド列の中に、ドライブ2を選択したことを示す差（今回もし2ドライブ構成の
テスト治具を組むなら、A:/B: の識別に使ってきたのと同じ「宛先ドライブに応じて
ポート値列やコマンド系列が変わるか」という観測）が出るかどうかを見ることで、
独立に裏が取れる。**資料はその構文候補を得るための近道であって、正しさの
唯一の出所ではない。** 測定と食い違えば測定を採る、という `CLAUDE.md` の
資料格付けの原則もそのまま適用する。

## 言えること・言えないこと

- 言えること: `SAVE` のファイル名指定にドライブ番号とコロンを前置する記法があることを、
  言語リファレンスの命令解説・実行例から確認した。
- 言えること: この資料の命令一覧（第2章目次）を通読した範囲では、既定ドライブを
  切り替える独立コマンドは見当たらなかった。
- 言えないこと: 上記の「構文で書き込み先ドライブを実際に切り替えられる」ことは、
  まだ実測で確認していない。次周の打鍵測定で裏を取る必要がある。
- 言えないこと: 他の4本の資料（`refs-nec-manuals-2026-09-04.md` の判定表にある
  条件付き可の3冊、および未判定の残り）は今回参照していないので、それらに
  矛盾する記述が無いかは未確認。
