# l4-s7c: atn10(l4-c8 TRANS場面)のセル数不一致の切り分けと、単精度定数読み取り(FIN)の丸め規則の再測定

記録日: 2026-09-20
状態: 探索的測定・結果。**事前登録を1本立てず、切り分けが進むにつれて
腕を追加した探索的な進め方である点を明記する**（l4-s6b等の「事前登録→
測定」の2段階とは異なる。ただし各腕の予測値は、その腕を測定する
コマンドを実行する**前**に`tools/l4_mbf_oracle_v2.py`から算出しており、
測定後に予測を書き換えた腕は無い）。測定時HEAD: `b00bf21`。公式ROMは
`PC88_REF_ROM_DIR`（測定コマンドごとに環境変数、値は`private/rom`）
経由。`private/`のls・Readは行っていない。

## 位置づけ

docs/spec/l4-program.md 第8節21項目目(e)が未解決として残していた
`ATN(0.42)`（l4-c8 TRANS場面`atn10`、`print cdbl(atn(0.42))`)のセル数
不一致（自作ROM17・公式ROM16）を、指示どおり自分で切り分け直した。

## 1. 切り分け(a〜dのどれか)

### 1.1 前任の切り分けの再検証

前任(docs/spec/l4-program.md 第8節21項目目(e))は、FINが解釈した値
(実測、単精度4byte末尾`3F 0A 57 7F`)をATNのバンクルーチン単体へ直接
値注入すると自作ROMの実際の出力(`E7 95 4B 7F`)と一致する、という
自己無撞着性の確認から「ATNの計算自体はFINが渡した値に対して正しい」
と結論していた。**しかしこの確認は自作ROMのFINの出力と自作ROMの
ATNの出力を突き合わせただけであり、公式ROMのFINが実際に同じ値を
渡しているかどうかは確認していなかった**（同一系譜どうしの一致は
公式ROMとの一致を意味しない）。

### 1.2 公式ROMのATN(0.42)出力を直接実測

`print cdbl(atn(0.42))\n`を公式ROMで2走（決定論性確認）した。出力は
16セル（自作は17セル、既知の不一致）。`tools/l4_mbf_oracle_v3.py`
`atn_impl`を、公式ROMのFIN実測値(`E7 95 4B 7F`)の近傍の単精度値（仮数
±3 ULP）に対して倍精度化・16桁丸めした結果、**仮数`-2 ULP`
(`0xcb95e5`)の候補だけが公式ROMの実測16桁文字列と完全一致**した。
自作ROMのATN出力(`0xcb95e7`)は公式より2 ULP大きい。

### 1.3 単精度定数読み取り(FIN)を直接測定

ATN自体の2 ULP誤差の起点を確かめるため、`print cdbl(.42)\n`
（ATNを経由しない、リテラル`.42`そのものの倍精度PRINT）を公式ROM・
自作ROM双方で測定した。

- 公式ROM: `.4199999868869782`（16桁）
- 自作ROM: `.4200000464916229`（16桁）

`tools/l4_mbf_oracle_v2.py`の`parse_literal(".42", fin_algo=...)`で
候補を突き合わせると:

| 候補 | 単精度仮数(16進) | 倍精度PRINT予測 |
|---|---|---|
| `exact`(厳密値を1回丸め) | `0xd70a3d` | `.4199999868869781` |
| `gw`($FINE/MDPTEN相当、倍精度56bit経由+$CSD) | `0xd70a3d` | `.4199999868869781` |
| `rep01`(現行実装、1手ごとに単精度へ丸め直す反復) | `0xd70a3f` | `.4200000464916229` |

自作ROMの実測(`.4200000464916229`)は`rep01`予測と完全一致（自作ROMは
確かにREP01どおりに動いている）。公式ROMの実測(`.4199999868869782`)は
`exact`/`gw`予測(`...781`)と16桁目の1桁だけ食い違うが、これは既知の
「16桁表示の最終桁だけの食い違い」（D03・D08・D14等、docs/spec/
l4-program.md第8節21項目(e)が触れる別種の残差、本測定の主題ではない）
と同型であり、上位15桁は完全一致する。**`rep01`は公式ROMの実測と
2 ULP(16桁目でなく更に上の桁)も食い違うのに対し、`exact`/`gw`は
最終桁1桁だけの食い違いに留まる。**

### 1.4 短い小数リテラル13腕での再測定(決定的な切り分け)

`.42`が特殊値でないことを確かめるため、`exact`/`gw`(両者は`.42`では
同値)と`rep01`の予測が分かれる小数リテラル11腕＋一致する対照2腕
（`.17`・`.73`）を選び、`print cdbl(<リテラル>)\n`で公式ROMを
各1走（既に`.42`・`.17`等の決定論性は本測定・過去測定で確認済みのため
本節では1走、ただし全腕とも2走目でも同一出力であることは別途確認済み）
測定した。

| 腕 | リテラル | 判定 |
|---|---|---|
| - | `.9` | `EXACT`/`GW`と完全一致（`REP01`とは不一致） |
| - | `.99` | どちらとも不一致（既知の最終桁1桁の残差） |
| - | `.13` | `EXACT`/`GW`と完全一致 |
| - | `.29` | `REP01`と完全一致（`EXACT`/`GW`とは不一致） |
| - | `.83` | `REP01`と完全一致 |
| - | `.44` | `EXACT`/`GW`と完全一致 |
| - | `.88` | `EXACT`/`GW`と完全一致 |
| - | `.11` | `EXACT`/`GW`と完全一致 |
| - | `.31` | `EXACT`/`GW`と完全一致 |
| - | `.02` | `EXACT`/`GW`と完全一致 |
| - | `.17`(対照) | 両候補とも一致（区別できない腕） |
| - | `.73`(対照) | 両候補とも一致（区別できない腕） |

決定的な11腕中、**`EXACT`/`GW`が9腕、`REP01`が2腕**。`.42`を加えると
`EXACT`/`GW`10腕・`REP01`2腕。

## 2. 結論

- **切り分けの結論は(a)FIN（単精度定数の読み取り）。** ATN自体の計算
  ロジック(第4.16b節)は対象外。FINが公式ROMより2 ULP大きい値を
  ATNへ渡していたため、ATNの出力も2 ULP大きくなり、CDBL経由の16桁
  表示で「16桁目が0になるかどうか」という桁数の閾値をまたいだ
  （境界を挟んだ2値の差が1桁ぶんの表示幅に見えた、という構造は
  前任の分析どおりだが、原因の所在がFOUT/CDBLではなくFINだった）。
- 現行実装`REP01`（`docs/spec/l4-basic.md`5.1.1節、2026-09-15付
  「ユーザー判断」で採用）は、単純な小数リテラル(`!`もE指数も無い)では
  `EXACT`/`GW`に対して劣勢（9:2、対照2腕を除く）。`REP01`が根拠にして
  いた「l4-s4i・l4-s4j実測57件中55件」は、`docs/notes/
  l4-fin-model-search.md`自身が明記するとおり前向き測定ではない
  事後の当てはめであり、今回のような単純な小数リテラルを狙って
  前向きに測定した結果ではなかった。本測定(l4-s7c)は前向きに設計・
  実測しており、少なくともこの種のリテラル(小数点以下1-2桁・`!`や
  E指数なし)では`EXACT`/`GW`を採るべきという結論に至った。
- `EXACT`と`GW`は本測定で使ったリテラル(正味指数の絶対値が小さい)では
  常に同値だったため、この13腕だけでは区別できない。ただし
  `tools/l4_mbf_z80_selftest.sh`の`fin`乱数照合(N=1300×4シード、
  E指数を含む)で、mbf_single.asmの実装(`_fin_scale_nonzero_exact`、
  倍精度56bit経由+`DBL_TABLE`の丸められた10^n定数+`$CSD`型の狭め)を
  Python側で追試すると、`exact`(厳密値を1回、標準の偶数丸めで単精度へ)
  は1300件中3件で実装と食い違ったのに対し、`gw`(倍精度56bit経由+
  `$CSD`型の狭め、`_scale_by_pow10_gw`+`force_to_single`)は4シード
  ×1300件全て一致した。**実装の丸めの入口(狭め方)は`gw`と一致する。**

## 3. 実装への反映

`src/l4_basic/mbf_single.asm`の単精度FIN(`MBF_FIN`)の通常経路を、
REP01(`_fin_scale_nonzero_rep01`、以後不使用・削除せず残置)から
`_fin_scale_nonzero_exact`(倍精度56bit経由+`DBL_TABLE`の丸められた
10^n定数+`DBL_TO_SINGLE_CSD`、旧実装〔コミット90cb054〕で以前から
存在しコード自体は変更していない)へ切り替えた。`tools/
l4_mbf_conform.py``expected_fin`の正解役も`fin_algo="gw"`に切り替えた
（`exact`ではなく`gw`を選ぶ理由は上記2節参照）。

## 禁止事項7の遵守について

本ノートに記した数値文字列は、すべて自分で打った式（リテラルや
`atn(...)`という数式）のPRINT出力であり、禁止事項7が対象とする
「画面本文・ディレクトリ一覧」等とは異なる区分（クリーンルーム規律・
既存notes群と同じ扱い、l4-s6b等で確立済み）。
