# m7y: 交換#14のFDC配置と高速バルク入口の未確定値

測定日: 2026-08-13

## 情報境界

公式ROM・公式ディスクおよび公式ディスク由来データの値は表示・記録していない。
公式環境と公式main＋第42版自作subを各1800フレーム新規実走し、生ログはリポジトリ外の
使い捨て領域だけで比較した。外へ出したのは要求位置、FDC公開コマンド種別、件数、
方向・ポート列、一致位置だけである。

## 交換#14の分節とFDC構造

交換#13の単発応答後に来る交換#14は12件要求である。公式subは先頭7件を受信した直後に
SEEK、SENSE INTERRUPT STATUS、SENSE DRIVE STATUS、READ DATAを各1回発行する。
続く4件、すなわち累積11件目の受信直後には同じ4コマンド組を4回発行し、最後の1件を
受信した後に高速バルクへ遷移する。READ DATAは合計5回で、FDC入力のデータ部長は
256バイト単位で1、14、16、16、2単位だった。結果部は各7件である。

READ DATAの8引数を要求12位置と値を表示せずに比較した。0始まり位置で記す。

- 1回目のunit/headとRは要求位置4だけに直接一致した。CとHは要求位置1/10の
  二候補で、要求値が同じため意味上の生成元は未確定である。
- 2〜5回目のunit/head、C、H、Rは要求内に同値位置が複数あり、直接同値比較だけでは
  一意に決まらない。5回のC/H/R列とFDC入力長は決定的に再現したが、要求位置からの
  生成式は未確定である。
- N、GPL、DTLは5回すべて固定で、それぞれ公開FDC形式の固定パラメータとして扱える。
  EOTも5回すべて固定だが要求12位置のどれとも直接一致せず、具体的な生成根拠は未確定。

したがって「要求長12だけで既存の1セクタREADへ一般化する」根拠はなく、実装しては
ならない。確定した駆動境界は累積7件、累積11件、累積12件の三箇所である。

## 高速バルク入口の停止条件

累積12件目のRECV完遂後、公式subは通常SEND/RECV語彙に属さない値を`$FF`へ5件連続で
出力し、その後に定常バルク周期へ入る。この5件は既存の1.14節・m6jでも値未確定と
されていた。今回の生ログでも値は読まず、方向・ポート構造だけを再確認した。

定常周期自体は、`$FE`待ち、既知の`$FF`送信フェーズ、再度の`$FE`待ち、`OUT $FC`、
`OUT $FD`、既知の`$FF`解除フェーズという構造で再現可能である。しかしmainをその周期へ
遷移させる連続5件の値は仕様書から生成できず、公式ROM内部由来の値が必要な状態である。
停止条件に従い、ブラックボックス値探索や推測値による入口実装は行わない。
