# l4-mbf-oracle — GW-BASIC 数値部の予測器（M7 / L4 段階4 事前登録用）

記録日: 2026-09-15

## 位置づけ

`docs/notes/l4-design.md`「2. GW-BASIC は数値部だけ移植する」の方針に従い、
Microsoft が MIT ライセンスで公開した GW-BASIC のソース（コミット
`edf82c2ebf6bfe099c2054e0ae125c3efe5769c4`、2020-05-21）の数値演算部分だけを
読み、その浮動小数点（Microsoft Binary Format、以下 MBF）の丸め・整形規則を
Python で再現した予測器を `tools/l4_mbf_oracle.py` として作った。

**目的は「公式 ROM を測る前に、GW-BASIC のアルゴリズムを Z80 へ移せば
N88 と一致するか」という仮説を事前登録することであり、この予測器自体は
実装の正解ではない。** 一致・不一致は今後、公式 ROM を測った結果
（別担当が並行して作る事前登録・測定）と突き合わせて判定する。本予測器
および `docs/notes/l4-s4a-gwbasic-predictions.tsv` は公式 ROM を一切
参照せずに作った。

## 読んだ範囲・読んでいない範囲

読んだ:
- `refs/GW-BASIC/LICENSE`（MIT ライセンス全文）
- `refs/GW-BASIC/MATH1.ASM`（数値部の中心。定数入力 `$FIN`/`$FIDIG`、
  型強制 `$FINEX`/`$FINFC`、正規化 `$NORMS`/`$NORMD`、整数変換
  `$INT`/`$QINT`、オーバーフロー/ゼロ除算 `$OVFLS`/`$DIV0S`/`DOINF`、
  自由形式整形 `$FOFMT` の該当行だけを `grep -na` と `Read` で選んで読んだ）
- `refs/GW-BASIC/MATH2.ASM`（`$FIDIG` 本体、`$FINEX`、`$FINFC`
  (`$FIND`/`$FINS`/`$CSD`)、`$ROUNS`（偶数丸め）、`$FOUT`/`$FOFMT` の入口、
  `$SIGD` の該当行）

読んでいない: 上記2ファイルの他の関数（三角関数・対数・べき乗・乱数等）、
`GWEVAL.ASM`・`GWMAIN.ASM` 等の他ファイル（`NUMINS`/`DOASIG` 周辺だけ
`grep` で確認したが、これは `INPUT`/`READ` 文用の経路であり本予測器の対象
（直接モード `PRINT` の定数・式）には使っていない）。GW-BASIC 以外の
Microsoft BASIC 派生（MBASIC・Altair BASIC・MSX-BASIC 等）や PC-88 の
解析記事は一切参照していない。Web 検索もしていない。

`measurements/`・`private/`・`docs/notes/l4-s4a-*` の事前登録（別担当が
並行で書いている）は触っていない。

## 確認できたこと（ソースの該当行から直接読み取った）

1. **偶数丸め。** `$ROUNS`（MATH2.ASM 1779-1796）は、ガードバイトへ
   0x80 を加算した結果ちょうど桁上がりが起きた場合、ZF（加算結果が
   ちょうどゼロ、すなわち「元の値がちょうど半分」を意味する）を見て
   丸め方向を分ける。ZF=1（ちょうど半分）のときは
   「偶数になるように丸める」（コメント原文 "IF ZF=1 WANT TO ROUND TO
   EVEN"）。本予測器は round-half-to-even として再現した。
2. **小文字 e/d の扱い。** `$FINCH` テーブル（MATH1.ASM 670-678）は
   `"." / 小文字"e" / "E" / "%" / "#" / "!" / "D" / 小文字"d"` の8文字を
   持ち、`$FIN` のディスパッチ（MATH1.ASM 2094-2118, FN95 ジャンプ表）で
   小文字"e"と"E"は同じ `FN200` へ、小文字"d"と"D"は同じ `FN92` へ飛ぶ。
   **大文字化はしておらず、字句テーブル自体が両ケースを直接認識する。**
3. **E は単精度強制・D は倍精度強制。** `$FINEX`（MATH2.ASM 100-137）が
   `$VALTP` が既に倍精度でなければ `$FINFC`（MATH2.ASM 186）を呼び、
   ZF に応じて `$FD`（強制倍精度、D 側）か `$FS`（強制単精度、E 側）へ
   分岐する。D の場合は `FN92` で `XOR AL,AL`（ZF=1 を作る）、E の場合は
   `FN200` の `$CHKEL` 通過後に ZF=0 のまま `FN94` へ落ちる、という経路の
   違いから確認した。**既に倍精度なら E は何もしない（倍精度のまま）。**
4. **整数→単精度の昇格しきい値。** `$FIDIG`（MATH2.ASM 21-52）は、
   整数として蓄積中の値が 3277（10進、`3277D` と明記）以上になったら
   次の桁を足す前に単精度へ変換する。変換後の乗算加算で 32768/32769 に
   達した場合（符号ビット）も単精度へ落ちる（`FFI10`）。
5. **単精度→倍精度の昇格しきい値。** `$FIDIG`（MATH2.ASM 53-61,
   `FFFI20`/`FI35`）は、単精度で蓄積中の値が「100万相当」以上になったら
   次の桁を足す前に倍精度へ変換する（比較定数は `$DBUFF+4/+6` に置かれた
   MBF 倍精度の即値で、命令単位の値そのものは読んだが、ここでは「約100万」
   という近似規則として実装した。厳密な比較対象値そのものをコメントに
   転記してはいない）。
6. **オーバーフロー・ゼロ除算は「継続する」エラー。** `$OVFLS`/`$DIV0S`/
   `DOINF`（MATH1.ASM 1252-1313）は、エラーメッセージを出したあとも
   `RET` で呼び出し元に戻り、`$FAC` にはその型で表現できる最大値
   （符号は演算結果もしくは被除数の符号）が入ったまま処理が続く。
   つまり **直接モード `PRINT` の式の中でオーバーフロー／ゼロ除算が
   起きても、その文の実行自体は止まらず、代入された最大値がそのまま
   続けて PRINT される**と読める。本予測器はこれに基づき、
   `kind=error` の予測に「エラー種別;続く数値行」の形を採用した。
   （エラートラップ (`ON ERROR GOTO`) が有効なときの分岐 (`TRAPER`) は
   直接モードでは働かない前提で無視した。実機測定で確かめる対象。）
7. **単精度/倍精度の有効桁数予算。** `$FOFMT`（MATH1.ASM 1338-1341,
   1364, 1384）は単精度 7 桁・倍精度 16 桁を使って固定小数点/指数表記の
   判定と丸めを行う。
8. **指数表記の記号と桁。** `$FOFMT`（MATH1.ASM 1424-1442）は単精度に
   "E"、倍精度に "D" を使い、符号は常に付け（"+"/"-"）、指数は常に2桁。
9. **1桁の "%" は定数解析に効果がない。** `FN400`（MATH1.ASM 2141-2144）
   は "%" を読み飛ばすだけで、型を強制する呼び出しをしていない（"#"の
   `$FIND`・"!"の`$FINS`とは異なる）。本予測器の32腕には"%"を使う腕が
   無いため実害はないが、ノートとして残す。
10. **`-32768` は単精度を経由しても整数に戻る。** `FINF`
   （MATH1.ASM 2152-2160）は、符号反転後に単精度でちょうど `-32768`
   になった場合、`$CONI2` で整数へ変換し直す。

## 近似・推測として区別する箇所（要検証）

以下は「ソースを読んで確信を持てた」のではなく、**限られた時間で追い切れず
一般的な整合規則として近似した箇所**である。実測との不一致が出たら、まず
ここを疑うこと。

1. **固定小数点⇔指数表記の切替しきい値そのもの。**
   `$FOFMT` の `FFM10`〜`FFM30`（MATH1.ASM 1338-1399）は分岐が細かく、
   命令単位までは追い切れていない。本予測器は
   「値を `d.ddd…×10^E` の形にしたときの `E` が
   `-有効桁数 < E <= 有効桁数` の範囲なら固定小数点、それ以外は指数表記」
   という対称なしきい値を採用した。既知の期待例（`.1`/`.01`/`.001` が
   固定小数点、`1E-10` が指数表記、`999999`/`9999999` が固定小数点、
   `1E10` が指数表記）とは矛盾しないが、境界そのもの（例えば単精度で
   `E=-7` や `E=8` のときにどちらになるか）は本予測器では未検証。
2. **`$FOTNV`/`$SIGD` による末尾ゼロの扱いの細部。** 有効桁数丸め後の
   末尾ゼロ抑制・小数点位置の決定は `$SIGD`（MATH2.ASM 1809-1880）が
   絡むが、命令単位のトレースはしていない。本予測器は「丸めた桁文字列の
   右側から0を落とす」という素直な規則で近似した。
3. **加算・減算・乗算・除算そのものの丸め。** `$FADDS`/`$FMULS`/`$FDIVS`
   のガードバイト蓄積・シフトの命令列は読んでいない。本予測器は
   「両オペランドの厳密値を有理数として正確に計算し、結果の型の精度へ
   1回だけ偶数丸めする」方式で近似した（$ROUNS の偶数丸めは直接確認済み
   だが、桁合わせのシフトで捨てるビットの「スティッキービット」の扱いが
   実際の実装と完全に同じかどうかは未検証）。
4. **定数の指数適用（`$FINE`/`MDP10`）の丸め回数。** 実際のソースは
   10進定数の指数適用を常に倍精度の10のべき表で行い、最後に必要なら
   単精度へ丸め直す（2回丸めになりうる）。本予測器は「厳密値を計算して
   最終型へ1回だけ丸める」方式に単純化した（二重丸めの違いが出る場合が
   ありうる。今回の32腕では該当しないと考えているが未検証）。
5. **オーバーフロー時の残留値 `DOINF` の実バイト列。** `$INFPD`/`$INFMD`
   という定数テーブルの実バイト列そのものは読んでいない（読むと ROM では
   なく GW-BASIC 自身のデータテーブルなので禁止事項には触れないが、
   時間の都合で読まなかった）。本予測器は「その型で表現できる最大値
   （仮数全ビット1、指数バイト255）」として独自に導出した
   （既知のMBF単精度バイト列4件で符号化そのものは検証済みなので、
   この導出自体は自己無矛盾だが、実際の `$INFPD`/`$INFMD` と一致する
   保証はない）。
6. **倍精度の桁列生成における10進指数の探索。** `_decimal_exponent`/
   `_significant_digits`（`tools/l4_mbf_oracle.py`）は `Fraction` の
   厳密比較で桁位置を決めており、アルゴリズムとしては exact だが、
   GW-BASIC 内部の `$FOTNV` のアルゴリズム（10のべきを使った逐次
   ブラケット）とは実装方法が異なる。結果が一致する保証は数学的な
   正しさに基づくものであり、命令単位の一致確認ではない。

## 推測で埋めた箇所の数

上記「近似・推測」6件。いずれも32腕の予測に影響しうるが、特に(1)(3)が
影響範囲が広い（固定小数点/指数表記の切替と、四則演算の最終ビットに
効く）。

## 動作確認

- `tools/l4_mbf_oracle_selftest.sh`: 既知のMBF単精度バイト列（1.0/0.5/
  -1.0/10.0）との一致と往復変換、偶数丸めの直接確認（2.5→2, 3.5→4）と
  故障注入（`L4_ORACLE_FAULT=round_up` で「常に切り上げ」に壊すと検査が
  不一致になることを確認）、整数溢れ時の単精度昇格（`30000+30000=60000`）
  と故障注入（昇格を無効化すると検査が不一致になることを確認）、代表値
  （指数表記・固定小数点・整数溢れ・エラー系）を検査する。
- `tools/gen_l4_s4a_predictions.py`: `docs/notes/l4-s4a-gwbasic-predictions.tsv`
  を再生成するスクリプト。再生成がバイト一致することを selftest の
  一項目として確認している。
