# m7w: main側構造259は揺れではなく制御フロー差

測定日: 2026-08-13

## 情報境界

公式ROM・公式ディスクおよび公式ディスク由来データの値は読まず、表示せず、記録して
いない。既存の伏せ字済み公式2走と、公式main＋現行自作subの新規1800フレーム走を
`tools/diag_l3_mixed.py`の既定比較へ入力した。比較に使ったのはCPU、方向、ポート、PC、
発生順、連続反復数だけである。`private/`は直下の名前だけを確認し、内容は開いていない。

## 259件目の構造

main側は畳み込み後258件まで一致する。直前5件は両側とも同じ列で、末尾はシステム制御
ポートへの出力と続くローカルポートへの出力である。259件目は同じ`$31`ポートだが、
公式側はシステム制御の出力、混成側はDIP読み出しの入力で、発行PCも異なる。直後も公式は
`$E4`、`$51`、`$50`側へ、混成は`$32`、`$71`、`$E6`側へ進むため、単一イベントの挿入・
削除やポーリング連長差ではない。

既存m7iの交換窓分類と突き合わせると、このイベント自体は通信ポートでもFDCでもなく、
交換#3の8件要求を組み立てている途中にmain内部の制御フロー差がローカルI/Oへ表面化した
ものである。値一致指標がその後も伸びるのは、同指標がmain `IN $FC`だけを抽出し、この
ローカル分岐を母集団に含めないためであり、259の差が無害であることを意味しない。

## 公式2走の対照

同一条件の`measurements/m6g-d0-boot-run{1,2}`を同じ比較器で直接比較した。mainは
畳み込み後74,479件、subは65,095件の全構造列が一致し、構造分岐は無かった。連続する
同一キーの反復数にも差が無く、259位置を含むイベント列の件数・順序・方向・ポート・PCは
揺れなかった。伸長前の既存記録にある「展開後ログの完全一致」とも整合する。

現行混成の新規走でもmain 258件、sub 752件という既知の構造プレフィックスを再現した。
比較器selftest a〜lは、同一入力を一致とし、意図的なポート差・PC差を分岐として検出し、
スピン回数だけの差を構造差から分離した。

## 結論

main側構造259は、タイミング由来のイベント数の揺れを数えた誤検出ではなく、現行自作subを
相手にした公式mainが公式環境とは別の命令経路へ進んだことを示す、本当の振る舞いの差で
ある。比較対象と畳み込み定義は目的どおりに働いており、判定基準の変更・緩和は行わない。
ただしこの構造指標とmain `IN $FC`値一致長は母集団が異なるため、前者が258で止まったまま
後者が522まで伸びること自体は矛盾しない。

分岐判断に使われたmain内部状態はI/Oログから特定できない。259突破だけを目的にsub応答値や
定数を推測する根拠は無いため、実装変更は行わない。次の作業は独立に観測可能なmain
`IN $FC`値列523位置目から続ける。
