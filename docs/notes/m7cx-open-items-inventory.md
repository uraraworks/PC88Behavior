# m7cx: 3節「未確定として残すこと」の棚卸し

実施日: 2026-08-27
対象: `docs/spec/l3-subrom.md` 第89版 3節（箇条書き42件）

これは測定ノートではなく**判断のノート**である。新しい実測は行っていない。
既に書かれている42件を、**「次に何ができるか」で分類し直した**。
42件すべてをどれかに割り当てており、「など」で省いた項目は無い。

## なぜ棚卸しが要るか

3節は「推測で埋めない」ための置き場として正しく機能してきた。ただし版を重ねるうちに、
性質の違うものが1つの平らな箇条書きへ同居するようになった。いま同じ列に並んでいるのは、

- 追跡しないと**決めた**もの
- 規律上、測定では**原理的に届かない**もの
- 測れるのに、時間の都合で**やっていないだけ**のもの
- 測ろうとして**足踏みしている**もの

の4種類である。**同じ「未確定」という語で呼ばれているが、次の一手がまったく違う。**
平らに並んでいる限り、残件42という見た目が実際の宿題より重く見え、
かつ「やればすぐ閉じるもの」が「原理的に無理なもの」に埋もれる。

## 分類（42件の内訳）

| 区分 | 件数 | 次の一手 |
|---|---|---|
| A 決着済み・3節から降ろせる | 7 | 無し（見出しを分けて移す） |
| B 規律上、測定では届かない | 13 | 無し（設計上の帰結として扱う） |
| C 測れるのに、やっていないだけ | 4 | **既存の測定器で回すだけ** |
| D 測ろうとして足踏み中 | 14 | 手法を変える／原因を切り分ける |
| E 別環境が要る | 3 | 別エミュレータ実装・実機資料 |
| F 人間の判断待ち | 1 | 線引きを決める |

### A. 決着済み・3節から降ろせる（7件）

未確定のままでよいが、**追加作業の対象ではない**。0節が「実装に不要」と判断したか、
測定で「届かないこと自体」を示し終えたか、既に解消済みのもの。

1. `$FA`/`$FB` の bit7 以外の意味論（0節: 追跡しない）
2. `OUT $FB` の各値が何のFDCコマンドに対応するか（0節: 追跡しない）
3. `$FB` で読んだデータの `$FC` への中継経路（0節: 追跡しない）
4. 単発1バイト応答の値と生成規則（11源×21加工＝231条件すべて値一致長0。
   **「測定では届かない」を測定で示した**）
5. ドライブ別のシーク・モータ状態を別々に保持する必要性
   （どの測定も要求していない。差が観測されるまで実装しない保留が正しい）
6. 起動時FDC初期化 batch2・5 が SPECIFY か SEEK か（第17版でSEEKと決着）
7. 書き込み要求のヘッダ構造（第53版で解消。取り消し線）

**降ろす**とは消すことではない。3節の中へ「決着」の小見出しを作って移し、
残りを「これからやること」だけにする。分からないことを分からないと書き続ける規律は変えない。

### B. 規律上、測定では届かない（13件）

**共通の原因はひとつ**——`CLAUDE.md` 禁止事項5でデータポートの value 列を伏せている。
値が読めない以上、「値に依存する判定」は外形からは決められない。

交換#3要求の分節を選ぶ内部判定根拠／ディスパッチャの判別条件／run境界の判別条件／
ラウンド#0がどのFDCコマンドか／バルク2バイトの意味／sub SENDで `OUT $FD` が2回現れる理由／
`$FF=0x91` と起動直後の `IN $FE` 2回の意味論／交換#3 byte3・byte4 の意味／
交換#3 byte7 bit0 の役割／`$FE`/`$FF` の2ビットが独立信号か連動信号か／
sub RECV前待ちの2起点／batch1 内の順序（run に区切りが無い）／
`$FC`/`$FD` の対称性（main が `$FC` へ一度も OUT しないので検証しようがない）。

**これらは伏せ字を外せば解ける。だが外さない。** それがこのプロジェクトの主張そのものなので、
B は「未解決」ではなく**設計上の帰結**である。実装は既に、この列を見ない適合条件（5.2節）の上に立っている。

### C. 測れるのに、やっていないだけ（4件）— **今回の収穫**

読み返して分かったのは、**足踏みしている難問の陰に、安い未着手が埋もれていた**ことだった。

1. **1.18節のFDC時間相関が d0-boot 以外でも成立するか。**
   共通クロック付きログが `measurements/m6g-d0-boot-run{1,2}` にしか無い。
   他条件で同じログを取るだけ。「時間の都合」で省略と明記されている
2. **1.22節（起動時FDC初期化シーケンス）の決定論性の直接確認。**
   run1/run2 の突き合わせを省略した。同種の手法は1.16節・1.21節で確認済みで、
   同じ突き合わせを回すだけ
3. **5635 という数値の由来。** D88 のセクタ構成を**公開仕様ベースで**確認する。
   公式ROM も公式ディスクの中身も要らない
4. **SEND/RECV 1回ごとの実時間遅延。** 起動時バルクへの遷移手順は1.14節で解消したが、
   1回あたりの遅延そのものは測っていない

**この4件は、難しいから残っているのではない。**「本筋ではなかったので後回しにした」まま、
42件の列に紛れて見えなくなっていた。

### D. 測ろうとして足踏み中（14件）

- **no_disk の要求長5対6の分岐**（最重量）。6容疑者を除外したが原因未特定。
  直近3周で指標が1ミリも動いていない
- **unreadable_disk に残るFDC発行列の差**（prefix=55・全長不一致）
- **unreadable_disk 応答の残る7ビット**（bit6 のみ確定）
- **同型の3件**: main視点RECV前後の例外0.11〜0.18%／`OUT $FF 0F` の run 先頭専有が
  100%でない理由／run 長の偶奇と pc の対応。
  **3件とも「本当の例外か、run 切り出し手法の誤差か」を切り分けられていない**
- 応答形式を決める一般規則／`$F8` TC三つ組みの発行条件／batch1・2直後のTCが簡略形な理由／
  終端マーカーに対応する sub 受信が無い理由／FDCアクセス件数と応答バイト数の比例関係／
  5635件のカウンタが main 側か sub 側か／diskB が使う別経路の中身／
  sub SEND の `0F`/`0E` 相当 `OUT $FF` が本当に存在しないのか（未測定の操作で現れうる）

### E. 別環境が要る（3件）

1. ST3 bit6/bit3 による no_disk 区別の実機一般性
2. サブ割り込みの真の源（FDCのハード割込線か、QUASI88内部のタイマ生成か）
3. `$FC`/`$FD` の経路そのものが QUASI88 実装由来でないと言えるか

**3件とも同じ道具で進む**——別のエミュレータ実装での再測定、または実機資料との照合。
どれも未着手で、「エミュで測った値はエミュの実装を測っている」の直撃領域である。

### F. 人間の判断待ち（1件）

**第2チャンネル（main `IN $FC` = sub `OUT $FD`）がバルク転送中に何を運んでいるか。**
公式6672件に対し自作は780件目で食い違う。**適合条件1はこのチャンネルを見ていない**ため、
条件を満たしていても混成はBASIC起動途中で止まる。
**これを適合条件へ含めるかどうかが宿題**であり、測定ではなく線引きの問題である。
含めれば「まだ完成ではない」、含めなければ「条件は満たしたが動かない」が正式な状態になる。

## この棚卸しから言えること

**42件のうち、実際に手が動かせるのは C(4) + D(14) + E(3) = 21件で、
残り半分（A 7件 + B 13件 + F 1件）は決着済みか、規律上そこで止まると決めた場所である。**

手が動く21件のうち、**いちばん安いのは C の4件**、いちばん高いのは no_disk（D）である。
直近3周の実績を見るかぎり、no_disk は「もう1周やれば出る」形をしていない。
**同じ場所を4周目で叩くより、先に C を閉じて足場を作るほうが期待値が高い。**

D の中に「解析手法の誤差か本当の例外か」という**同型の宿題が3件ある**のも収穫だった。
3件それぞれを個別に追うより、**run 切り出し手法そのものへ陽性対照を入れて
「この手法はどんな誤差を作るか」を先に測る**ほうが、1回で3件に効く。

## 次の3手（推奨順）

1. **C-1 と C-2 を閉じる。** 共通クロックログを d0-boot 以外でも取り、
   1.22節の run1/run2 突き合わせを回す。どちらも新しい設計が要らない
2. **D の同型3件へ、手法の陽性対照を入れる。** run 切り出し手法をわざと壊し、
   0.11〜0.18% の例外が手法由来なら再現するかを見る。再現すれば3件が同時に片付く
3. **F を人間が決める。** 第2チャンネルを適合条件へ含めるか。
   ここが決まらないと「完成」の定義が宙に浮いたままになる

no_disk（D の最重量）は、1〜2で観測手法の信頼度を上げてから戻る。

## 追補: m7cyでFの前提が解消した

同日、`docs/notes/m7cy-second-channel-rule-search.md`で現HEADを再実測したところ、
第2チャンネルは公式・混成とも6672件で、値の一致プレフィックスも6672件の完全一致だった。
m7bb時点の混成6414件は、その後のバルク後258件応答実装より前の過去状態である。

従ってFの1件は「適合条件へ含めるか」という線引き以前に、現在の実装で差そのものが
解消しており、Aへ移す。追補後の内訳はA 8、B 13、C 4、D 14、E 3、F 0で合計42件。
手を動かせるC+D+Eは21件のままである。上記「次の3手」のF判断は実施不要になった。

## 追補: m7czでCの3件を測定した

同日、`docs/notes/m7cz-common-clock-three-questions.md`で、QUASI88のd1-filesと
d5-seqfileを共通clock付きで各2回取得し、Cの1・2・4を測定した。

- C-1（1.18節FDC時間相関）は、追加2条件×2runでも成立して**解消**した。
- C-2（1.22節決定論性）は、既存d0 run1/run2の直接署名一致で**解消**した。
  追加d1/d5も同一条件2回が一致した。
- C-4（SEND/RECV遅延）は通常標本の分布を得たが、d5ストリーミング等では
  1バイトごとの`$FE`終点へ一意対応できず、**この手法の境界として閉じた**。
  有効部分だけを完全分布とは呼ばない。

3件は「追加作業対象から降ろせる解消または測定済み境界」なのでAへ移す。
追補後の内訳は**A 11、B 13、C 1、D 14、E 3、F 0で合計42件**。
Cに残る1件は「5635という数値の公開D88仕様上の由来」だけである。
手を動かせるC+D+Eは18件になり、上記「次の3手」のC-1/C-2は実施済みである。

この追補の定量値はQUASI88実装に固有であり、採るのは相関、同一ビルド内決定論性、
通常遅延がおおよそ一〜二桁clockという定性的結論だけである。実機一般性は主張しない。
