# m7cx: 3節「未確定として残すこと」の棚卸し

実施日: 2026-08-27
対象: `docs/spec/l3-subrom.md` 第89版 3節（箇条書き42件）

これは測定ノートではなく**判断のノート**である。新しい実測は行っていない。
既に書かれている42件を、**「次に何ができるか」で分類し直した**。
42件すべてをどれかに割り当てており、「など」で省いた項目は無い。

## なぜ棚卸しが要るか

3節は「推測で埋めない」ための置き場として正しく機能してきた。ただし版を重ねるうちに、
性質の違うものが1つの平らな箇条書きへ同居するようになった。いま同じ列に並んでいるのは、

- 追跡しないと**決めた**もの
- 規律上、測定では**原理的に届かない**もの
- 測れるのに、時間の都合で**やっていないだけ**のもの
- 測ろうとして**足踏みしている**もの

の4種類である。**同じ「未確定」という語で呼ばれているが、次の一手がまったく違う。**
平らに並んでいる限り、残件42という見た目が実際の宿題より重く見え、
かつ「やればすぐ閉じるもの」が「原理的に無理なもの」に埋もれる。

## 分類（42件の内訳）

| 区分 | 件数 | 次の一手 |
|---|---|---|
| A 決着済み・3節から降ろせる | 7 | 無し（見出しを分けて移す） |
| B 規律上、測定では届かない | 13 | 無し（設計上の帰結として扱う） |
| C 測れるのに、やっていないだけ | 4 | **既存の測定器で回すだけ** |
| D 測ろうとして足踏み中 | 14 | 手法を変える／原因を切り分ける |
| E 別環境が要る | 3 | 別エミュレータ実装・実機資料 |
| F 人間の判断待ち | 1 | 線引きを決める |

### A. 決着済み・3節から降ろせる（7件）

未確定のままでよいが、**追加作業の対象ではない**。0節が「実装に不要」と判断したか、
測定で「届かないこと自体」を示し終えたか、既に解消済みのもの。

1. `$FA`/`$FB` の bit7 以外の意味論（0節: 追跡しない）
2. `OUT $FB` の各値が何のFDCコマンドに対応するか（0節: 追跡しない）
3. `$FB` で読んだデータの `$FC` への中継経路（0節: 追跡しない）
4. 単発1バイト応答の値と生成規則（11源×21加工＝231条件すべて値一致長0。
   **「測定では届かない」を測定で示した**）
5. ドライブ別のシーク・モータ状態を別々に保持する必要性
   （どの測定も要求していない。差が観測されるまで実装しない保留が正しい）
6. 起動時FDC初期化 batch2・5 が SPECIFY か SEEK か（第17版でSEEKと決着）
7. 書き込み要求のヘッダ構造（第53版で解消。取り消し線）

**降ろす**とは消すことではない。3節の中へ「決着」の小見出しを作って移し、
残りを「これからやること」だけにする。分からないことを分からないと書き続ける規律は変えない。

### B. 規律上、測定では届かない（13件）

**共通の原因はひとつ**——`CLAUDE.md` 禁止事項5でデータポートの value 列を伏せている。
値が読めない以上、「値に依存する判定」は外形からは決められない。

交換#3要求の分節を選ぶ内部判定根拠／ディスパッチャの判別条件／run境界の判別条件／
ラウンド#0がどのFDCコマンドか／バルク2バイトの意味／sub SENDで `OUT $FD` が2回現れる理由／
`$FF=0x91` と起動直後の `IN $FE` 2回の意味論／交換#3 byte3・byte4 の意味／
交換#3 byte7 bit0 の役割／`$FE`/`$FF` の2ビットが独立信号か連動信号か／
sub RECV前待ちの2起点／batch1 内の順序（run に区切りが無い）／
`$FC`/`$FD` の対称性（main が `$FC` へ一度も OUT しないので検証しようがない）。

**これらは伏せ字を外せば解ける。だが外さない。** それがこのプロジェクトの主張そのものなので、
B は「未解決」ではなく**設計上の帰結**である。実装は既に、この列を見ない適合条件（5.2節）の上に立っている。

### C. 測れるのに、やっていないだけ（4件）— **今回の収穫**

読み返して分かったのは、**足踏みしている難問の陰に、安い未着手が埋もれていた**ことだった。

1. **1.18節のFDC時間相関が d0-boot 以外でも成立するか。**
   共通クロック付きログが `measurements/m6g-d0-boot-run{1,2}` にしか無い。
   他条件で同じログを取るだけ。「時間の都合」で省略と明記されている
2. **1.22節（起動時FDC初期化シーケンス）の決定論性の直接確認。**
   run1/run2 の突き合わせを省略した。同種の手法は1.16節・1.21節で確認済みで、
   同じ突き合わせを回すだけ
3. **5635 という数値の由来。** D88 のセクタ構成を**公開仕様ベースで**確認する。
   公式ROM も公式ディスクの中身も要らない
4. **SEND/RECV 1回ごとの実時間遅延。** 起動時バルクへの遷移手順は1.14節で解消したが、
   1回あたりの遅延そのものは測っていない

**この4件は、難しいから残っているのではない。**「本筋ではなかったので後回しにした」まま、
42件の列に紛れて見えなくなっていた。

### D. 測ろうとして足踏み中（14件）

- **no_disk の要求長5対6の分岐**（最重量）。6容疑者を除外したが原因未特定。
  直近3周で指標が1ミリも動いていない
- **unreadable_disk に残るFDC発行列の差**（prefix=55・全長不一致）
- **unreadable_disk 応答の残る7ビット**（bit6 のみ確定）
- **同型の3件**: main視点RECV前後の例外0.11〜0.18%／`OUT $FF 0F` の run 先頭専有が
  100%でない理由／run 長の偶奇と pc の対応。
  **3件とも「本当の例外か、run 切り出し手法の誤差か」を切り分けられていない**
- 応答形式を決める一般規則／`$F8` TC三つ組みの発行条件／batch1・2直後のTCが簡略形な理由／
  終端マーカーに対応する sub 受信が無い理由／FDCアクセス件数と応答バイト数の比例関係／
  5635件のカウンタが main 側か sub 側か／diskB が使う別経路の中身／
  sub SEND の `0F`/`0E` 相当 `OUT $FF` が本当に存在しないのか（未測定の操作で現れうる）

### E. 別環境が要る（3件）

1. ST3 bit6/bit3 による no_disk 区別の実機一般性
2. サブ割り込みの真の源（FDCのハード割込線か、QUASI88内部のタイマ生成か）
3. `$FC`/`$FD` の経路そのものが QUASI88 実装由来でないと言えるか

**3件とも同じ道具で進む**——別のエミュレータ実装での再測定、または実機資料との照合。
どれも未着手で、「エミュで測った値はエミュの実装を測っている」の直撃領域である。

### F. 人間の判断待ち（1件）

**第2チャンネル（main `IN $FC` = sub `OUT $FD`）がバルク転送中に何を運んでいるか。**
公式6672件に対し自作は780件目で食い違う。**適合条件1はこのチャンネルを見ていない**ため、
条件を満たしていても混成はBASIC起動途中で止まる。
**これを適合条件へ含めるかどうかが宿題**であり、測定ではなく線引きの問題である。
含めれば「まだ完成ではない」、含めなければ「条件は満たしたが動かない」が正式な状態になる。

## この棚卸しから言えること

**42件のうち、実際に手が動かせるのは C(4) + D(14) + E(3) = 21件で、
残り半分（A 7件 + B 13件 + F 1件）は決着済みか、規律上そこで止まると決めた場所である。**

手が動く21件のうち、**いちばん安いのは C の4件**、いちばん高いのは no_disk（D）である。
直近3周の実績を見るかぎり、no_disk は「もう1周やれば出る」形をしていない。
**同じ場所を4周目で叩くより、先に C を閉じて足場を作るほうが期待値が高い。**

D の中に「解析手法の誤差か本当の例外か」という**同型の宿題が3件ある**のも収穫だった。
3件それぞれを個別に追うより、**run 切り出し手法そのものへ陽性対照を入れて
「この手法はどんな誤差を作るか」を先に測る**ほうが、1回で3件に効く。

## 次の3手（推奨順）

1. **C-1 と C-2 を閉じる。** 共通クロックログを d0-boot 以外でも取り、
   1.22節の run1/run2 突き合わせを回す。どちらも新しい設計が要らない
2. **D の同型3件へ、手法の陽性対照を入れる。** run 切り出し手法をわざと壊し、
   0.11〜0.18% の例外が手法由来なら再現するかを見る。再現すれば3件が同時に片付く
3. **F を人間が決める。** 第2チャンネルを適合条件へ含めるか。
   ここが決まらないと「完成」の定義が宙に浮いたままになる

no_disk（D の最重量）は、1〜2で観測手法の信頼度を上げてから戻る。

## 追補: m7czでCの3件を測定した

同日、`docs/notes/m7cz-common-clock-three-questions.md`で、QUASI88のd1-filesと
d5-seqfileを共通clock付きで各2回取得し、Cの1・2・4を測定した。

- C-1（1.18節FDC時間相関）は、追加2条件×2runでも成立して**解消**した。
- C-2（1.22節決定論性）は、既存d0 run1/run2の直接署名一致で**解消**した。
  追加d1/d5も同一条件2回が一致した。
- C-4（SEND/RECV遅延）は通常標本の分布を得たが、d5ストリーミング等では
  1バイトごとの`$FE`終点へ一意対応できず、**この手法の境界として閉じた**。
  有効部分だけを完全分布とは呼ばない。

3件は「追加作業対象から降ろせる解消または測定済み境界」なのでAへ移す。
追補後の内訳は**A 11、B 13、C 1、D 14、E 3、F 0で合計42件**。
Cに残る1件は「5635という数値の公開D88仕様上の由来」だけである。
手を動かせるC+D+Eは18件になり、上記「次の3手」のC-1/C-2は実施済みである。

この追補の定量値はQUASI88実装に固有であり、採るのは相関、同一ビルド内決定論性、
通常遅延がおおよそ一〜二桁clockという定性的結論だけである。実機一般性は主張しない。

## 追補: m7da〜m7deでCの残り1件を測定した

同日、`docs/notes/m7da-5635-origin-preregistration.md`から
`docs/notes/m7de-5635-stage3-shape-intervention.md`までの事前登録・再集計・
再現対照・形状介入により、Cに残っていた「5635という数値の公開D88仕様上の由来」を
測定した。公開D88仕様との算術照合と公式diskA 2走の再現確認から、5635の直接説明は
交換#14の44セクタ窓を2チャンネルへ交互配置した片側長とプリアンブル3件で決着した。

未確定として残るのは、なぜ上流で44セクタを選ぶかである。媒体形状追随（H1）と
固定`0x1600`カウンタ（H5）は形状介入3条件でも観測等価だった。これはD区分相当の
「測ろうとして足踏み中」ではなく、5 READの制御流を保ったまま1件のREADだけを
1セクタ変えて正常完了させる、値非表示の識別介入がまだハーネスへ実装されていないという
別の壁である。元の42件に新たなD項目を加えず、Cの残り1件はAへ移す。

追補後の内訳は**A 12、B 13、C 0、D 14、E 3、F 0で合計42件**。
C区分の未着手項目はなくなり、手を動かせるD+Eは17件となる。44セクタ選択の
上流理由は、識別介入が実装されるまで別途未確定として維持する。

## 追補: m7df〜m7diでDの同型3件のうち1件がMで決着した

`docs/notes/m7df-run-cutter-error-preregistration.md`の事前登録、
`docs/notes/m7dg-run-cutter-positive-selftest.md`の合成陽性対照、
`docs/notes/m7dh-run-cutter-independent-anchor-attribution.md`の新規実測（d0-boot/
d1-files/d2-save/d5-seqfile相当4条件×各2走）、`docs/notes/m7di-attribution-tool-negative-control.md`
の帰属器自体の陰性対照で、Dの「同型3件」を判定した。

**この棚卸しが立てた「run切り出し手法へ陽性対照を入れれば1回で3件に効く」という
前提は外れた。** m7dfの出典整理で判明したとおり、3件は単一の切り出し手法を
共有していない。`0F`先頭専有とrun長偶奇は`analyze_run_boundary.py`の
`main_send_runs()`を共有するが、RECV前後の例外は別ファイル`analyze_sub_fe.py`の
`analyze_sub_fe()`が作るスピンであり、選択ポート・境界条件・集計単位のすべてが
異なる。実際に効いたのは**1件だけ**だった。

- **RECV前後の例外（0.11〜0.18%）は独立境界アンカーでM（手法由来）と確定した。**
  判定対象のbit0規則・スピン長・終端pcを一切使わないアンカーで4条件×2走を
  切り直すと、アンカーcutは全条件0件、現cut例外は100%が`false_split`へ
  一意に帰属した。「アンカー例外0件」がアンカー自体の壊れ方（常に0を返す
  空検査）でないことも、境界を保ったまま本物のbit0違反を仕込む陰性対照で
  別途確認した（分類器が6カテゴリを独立に出し分けられることも単体で確認済み）。
  **Dから外し、Aへ移す。**
- **残る2件（`0F`先頭専有・run長偶奇）はDに残るが、状態が変わった。**
  同じ独立境界アンカーで`0F`例外92件・偶奇例外81件を帰属したところ、
  `0F`は`boundary_match`48／`false_split`27／`interrupt_boundary`17、偶奇は
  `boundary_match`50／`false_split`31（`interrupt_boundary`0）だった。
  過半を占める`boundary_match`（アンカーが現cutと同じ境界を引いたのに例外が
  残る）は、m7dgの合成陽性対照（23腕）のどの境界誤認腕にも対応しない。
  もはや「まだ測っていない足踏み」ではなく、**境界誤認モデルでは説明し
  切れない残差として件数付きで確定した状態**である。m7df事前登録の
  M/R到達条件はどちらも満たさず、X（混在／識別不能）のまま残す。

追補後の内訳は**A 13、B 13、C 0、D 13、E 3、F 0で合計42件**。
手を動かせるD+Eは16件になった。「1件で3件に効く」前提が外れた記録として、
今後同型の宿題をまとめて処理する際は、切り出し手法が実際に共有されているか
（呼び出し元のコードを見て確認する）を先に確かめる必要がある。

## 追補: m7dj〜m7dkでDに残った2件が同一現象と判明、規則探索も打ち切った

`docs/notes/m7dj-boundary-match-residual-rule-search-preregistration.md`の
事前登録と`docs/notes/m7dk-boundary-match-residual-rule-search-results.md`の
実測で、前回追補でDに残した2件（`0F`先頭専有・run長偶奇の`boundary_match`残差）
を扱った。

**論点0（2指標が同じrun集合を指すか）を先に確定した。** `0F`側`boundary_match`
（48件）は、4条件すべてで例外なく偶奇側`boundary_match`（50件）の部分集合に
なっており（共通部分48・和集合50、Jaccard 0.96）、偶奇側だけが持つ2件を除けば
同一のrun群を指す。**この2件は別々の未確定事項ではなく、ほぼ同一現象の2つの
現れ方だった。**

**規則探索も行ったが、見つからなかった。** 発行pc・共通clock間隔・フェーズ・
条件・run長・pc列パターンの単一軸5種と2軸コンボ3系統を評価したが、誤り0件
（偽陽性0・偽陰性0）の候補は1件も無く、事前登録した打ち切り条件どおり探索を
終了した。分かった否定的事実として、「直前runとの間隔が短いほど起きる」という
候補は偽陰性全数（`0F`側48/48・偶奇側50/50）で積極的に反証され、
`boundary_match`の約9割はrun長6に集中するが分離し切れないため部分確定とは
呼ばない。陽性対照・故障注入（評価器が「常に誤り0件」を返す壊れ方をしていない
ことの確認を含む）はすべて成立した。

**内訳の数字は変えない。** 2件が同一現象の2つの現れ方だと分かったことは
`docs/spec/l3-subrom.md`側では1つの未確定事項へ統合したが、本棚卸しの
42件カウントは元の粒度（`0F`側・run長偶奇側をそれぞれ1件として数えた版）を
維持し、Dの13件・合計42件を動かさない。理由は、この2件を1件へ数え直すには
42件という基準そのものを引き直す必要があり、それは棚卸し全体の再集計という
別作業になるためである。統合したのはあくまで**仕様書の記述単位**であって、
棚卸しの数え方ではない。実質は「Dに残る13件のうち2件は、独立した2つの
未解決問題ではなく、1つの残差の2つの観測面である」という注記として扱う。

**足踏みの質が、前回よりさらに変わった。** 前々回（m7dh時点）は「境界誤認
モデルで説明できない残差」、今回（m7dj/m7dk）は「探索した軸集合の範囲では
説明する規則が見つからなかった残差」になった。まだ試していない軸（値そのもの
を使う説明、より広いclock間隔の走査、他の割り込み位置関係等）は残っており、
「これ以上は分からない」という最終結論ではない。

追補後の内訳は**A 13、B 13、C 0、D 13、E 3、F 0で合計42件**（変更なし）。

## 追補: m7dl〜m7dmで2周目の規則探索も見つからなかった

`docs/notes/m7dl-run-length-6-protocol-axis-preregistration.md`と
`docs/notes/m7dm-run-length-6-protocol-axis-results.md`で、前回追補の
run長6偏り（Dに残る2件の共通の手掛かり）を、m7dj/m7dkが使わなかった
プロトコル側の軸（要求種別・sub側FDCアクセス件数・往復の位置・直後FDC
コマンド種別）で追った。

**前提検証で新しい構造的事実が1つ確定した。** 本稿対象のmain視点SEND run
（`main_send_runs()`）と、1.36節のsub視点受信run（`window_a_runs()`）は
1:1対応しない（4条件で件数不一致、位置対応での長さ一致率13〜21%）。
これにより要求種別軸（Y1）は使えないと判明し、無理に対応付けずに外した。
この事実は`docs/spec/l3-subrom.md`1.53節へ新設・反映済みである
（1.20節・1.36節から相互参照、両節の対象を混同しないための注意書きも
追加した）。

**規則探索自体は、2周目も見つからなかった。** 残る3軸（sub側FDCアクセス
件数・往復の位置・直後FDCコマンド種別）と2軸コンボ3系統を評価したが、
誤り0件の候補は1件も無かった。最良でも誤り31〜36件で、m7dkのrun長軸単独
（誤り8〜10件、ただし「run長6かどうか」の言い換えとして不合格）より
判別力が低かった。「run長6かどうか」への言い換え判定（run長6だが
`boundary_match`でない例・run長6以外の`boundary_match`例の両方を母集団に
含める）も再確認したうえでの結果である。

**足踏みの質は変わらない。** m7dj/m7dk時点の「探索した軸集合の範囲では
説明する規則が見つからなかった残差」から進んでおらず、試した軸が
（発行pc・共通clock間隔・フェーズ・条件・run長・pc列パターン）から
（要求種別・sub側FDCアクセス件数・往復の位置・直後FDCコマンド種別）へ
1周分増えただけである。まだ試していない軸（値そのものを使う説明、
交換番号のより精密な対応付け等）は残っており、「これ以上は分からない」
という最終結論ではない。

追補後の内訳は**A 13、B 13、C 0、D 13、E 3、F 0で合計42件**（変更なし）。

## 追補: m7do〜m7drで複数ファイル読出しの非加法性を確定した

`docs/notes/m7do-multi-file-open-entry-preregistration.md`・
`docs/notes/m7dp-multi-file-open-entry-conformance.md`の同時オープン測定と、
`docs/notes/m7dq-same-session-sequential-open-preregistration.md`・
`docs/notes/m7dr-same-session-sequential-open-conformance.md`の同一セッション逐次対照により、
需要入口の読出しアクセスが加法的でないことを確定した。別ブート単独2回の合計
（main `IN $FC` 16444件・READ 34単位）に対し、同時オープンは9254件・21単位、
同一セッション逐次は9772件・25単位だった。同一セッションへ集約するだけで削減の
大部分が再現され、純粋な同時性効果はA–B差の518件・4単位が上限となる。ただし、
引き継ぎ状態、A/Bの読出し順・ハンドル・CLOSE位置、Cだけの2ブート固定費という
交絡があるため、特定機構へは帰属しない。

この結果は元の42件の移動・統合ではなく、**「削減がディレクトリ検索、OPEN、データ
読出し、CLOSE、シーク／FDC状態のどの段階で生じるか」という新しい未確定事項を1件
発見した**ものである。段階境界をclockで区切る集計、起動固定費を揃えた増分対照、逆順・
別配置・同時／非同時対照を追加すれば測定可能であり、まだ実施していないためCへ1件を
追加する。既存42件の歴史的な粒度は変更しない。

追補後の内訳は**A 13、B 13、C 1、D 13、E 3、F 0で合計43件**。
算術は13+13+1+13+3+0=43であり、手を動かせるC+D+Eは17件となる。

## 追補: m7ds〜m7duで「削減段階」を固定費と同時オープン残差へ分解した

`docs/notes/m7ds-read-reduction-stage-intervention-preregistration.md`の事前登録、
`docs/notes/m7dt-read-reduction-stage-ladder-results.md`の段階ラダー、
`docs/notes/m7du-fixed-cost-model-and-p0-identity.md`のSB/SC・起動列同一性測定により、
直前の追補でCへ追加した1件を分解した。

- OPEN/CLOSE包絡は`E1=E2=E3=1292件・7単位`、読出し追加は
  `D1=D2=D3=258件・1単位`で、後続段階が安くなるH-D/H-Bは反証された。
- SB/SCは各8222件・17単位で、R2/R3は事前登録した固定費式へ完全一致した。
  P0=6672件・9単位も起動列とSHA-256・区間構造・位置署名まで一致し、別ブート単独値の
  加算が起動固定費を二重計上していたと確定した。逐次条件の「削減段階」は解消した。
- ただし同時オープンAだけは逐次B／固定費予測より518件・4単位少なく、この残差は
  固定費で説明できない。A/Bは交互／連続読出し、ファイル番号、CLOSE時点も異なるため、
  純粋な同時性や特定機構への帰属は未確定のままである。

**件数は動かさない。** 直前に追加したCの1件は、削減段階とA–B差を含む1つの広い
未確定事項として数えていた。今回はその段階側を解消し、同じ項目を518件・4単位の
同時オープン残差へ狭めたので、解消部分だけをAへ1件移し、残差を新規C 1件として加える
二重計上はしない。H-D/H-B/H-Fも独立した棚卸し項目ではなく、この1件を判定するための
仮説だった。

追補後の内訳は**A 13、B 13、C 1、D 13、E 3、F 0で合計43件**（変更なし）。
算術は13+13+1+13+3+0=43であり、手を動かせるC+D+Eは17件のままである。Cの1件は
「削減がどの段階で起きるか」から「同時オープン条件だけに残る518件・4単位の説明」へ
置き換わった。
