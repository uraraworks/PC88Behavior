事前登録 §8 の `m6f_c_boot_blocked` の行き先（起動の経路を測る追補。起動用セクタの中身は
規則で作る）に従う。

## 2. 刺激

生成器に規則を1つ足す: **(0,0,1) の 256 バイトすべてを値 X にする**（既定では詰め物 F と同じ。
既定のときの生成物は `a9ea861` の生成器とバイト一致させる）。

腕 `BX-00`〜`BX-FF`: 媒体は `B(0xFF, 0xFF)` の (0,0,1) だけを X にしたもの。打鍵は GB と同じ
（`print chr$(90);chr$(81);"bt"\n` をフレーム 700）、フレーム 3000、各2走。

**X は全値を掃引し、特定の値を本命として置かない。**

## 3. 導出規則

- **B1 起動できる値**: 2走とも `ZQbt` が出た X の集合 Xboot。空でなければ `derived`
  （集合を記録）、空なら `not_found`。2走で食い違った X は外して列挙する。
- **B2 次の読み込み**（副）: 各 X について、刺激の前後を通じた READ DATA の (C,H,R) の
  初出順の列の先頭4個と、(0,0,1) を読んだ回数を記録する。

**X\*** = Xboot の最小値。

## 4. 行き先

- B1 が `derived`: 生成器の規則に「(0,0,1) は X\*」を加え、**本測定（GB・SW・段階2）を
  最初から回し直す。** 事前登録 §4〜§7 はそのまま使う（媒体の規則が1つ増えるだけ）。
  1回目の結果（`m6f_c_boot_blocked`）は消さずに結果ノートへ残す。
- B1 が `not_found`: (0,0,1) の一様値では起動を通せない。位置ごとの値を測る追補2を置く。

## 5. 決まらないこと

- ROM が (0,0,1) の何を見ているか（一様値の掃引では、どのバイトが効いているかは分からない）。
- Xboot の値で起動が通る理由（中身を命令として実行しているのか、値を検査しているのか）。

## 6. 結果（2026-09-24 追記）

器具 `3390b50`、G1 は除外2件で rc=0（腕の前に親が1回）。256 腕 × 2 走。
結果 JSON・導出は `PC88/tmp/m6-work/m6fc-boot-2026-09-24/`（リポジトリ外）。
導出の出力の SHA-256（入力 result の SHA）は `66a43540e797a854b0e7e3fda077c6c28ff4fcf2158eea8c103938775197442b`。

- **B1 `derived`: Xboot = {0xC0, 0xC9, 0xD0, 0xE0, 0xF0}。** 2走の食い違いは無し。
  **X\* = 0xC0**（事前登録どおり最小値）。
- **B2**: Xboot の5値では、READ DATA は (0,0,1) の1回だけで BASIC に届いた（(0,0,2) は読まない）。
  残る 251 値のうち 247 値は (0,0,1) を 3000 フレームで 102 回読み続け、2値は1回読んで止まり、
  1値は 11 回、1値は 101 回だった（いずれも目印なし）。

**解釈（決定ではない）:** Xboot の5値は、いずれも Z80 の「戻り」命令の符号（無条件1つと
条件付き4つ）に当たる。ROM が (0,0,1) を命令として実行し、戻ってくれば BASIC へ進む、と
読むのが自然である。ただし §5 のとおり、一様値の掃引ではこれを決めない。

§4 に従い、生成器の規則に「(0,0,1) は X\*=0xC0」を加えて本測定を最初から回し直す。
