## 2. 刺激

生成器に規則を1つ足す: **(0,0,1) の 256 バイトすべてを値 X にする**（既定では詰め物 F と同じ。
既定のときの生成物は `a9ea861` の生成器とバイト一致させる）。

腕 `BX-00`〜`BX-FF`: 媒体は `B(0xFF, 0xFF)` の (0,0,1) だけを X にしたもの。打鍵は GB と同じ
（`print chr$(90);chr$(81);"bt"\n` をフレーム 700）、フレーム 3000、各2走。

**X は全値を掃引し、特定の値を本命として置かない。**

## 3. 導出規則

- **B1 起動できる値**: 2走とも `ZQbt` が出た X の集合 Xboot。空でなければ `derived`
  （集合を記録）、空なら `not_found`。2走で食い違った X は外して列挙する。
- **B2 次の読み込み**（副）: 各 X について、刺激の前後を通じた READ DATA の (C,H,R) の
  初出順の列の先頭4個と、(0,0,1) を読んだ回数を記録する。

**X\*** = Xboot の最小値。

## 4. 行き先

- B1 が `derived`: 生成器の規則に「(0,0,1) は X\*」を加え、**本測定（GB・SW・段階2）を
  最初から回し直す。** 事前登録 §4〜§7 はそのまま使う（媒体の規則が1つ増えるだけ）。
  1回目の結果（`m6f_c_boot_blocked`）は消さずに結果ノートへ残す。
- B1 が `not_found`: (0,0,1) の一様値では起動を通せない。位置ごとの値を測る追補2を置く。

## 5. 決まらないこと

- ROM が (0,0,1) の何を見ているか（一様値の掃引では、どのバイトが効いているかは分からない）。
- Xboot の値で起動が通る理由（中身を命令として実行しているのか、値を検査しているのか）。
