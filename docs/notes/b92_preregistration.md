# B92 事前登録：G5 の 7071 直前への介入

追補7に基づく。実走の前に、対象・腕・比較方法を固定する。G5 の番地は利用者指定の B91 実走の読み取り番地に由来し、ゲームの値は採らない。

- 対象は E60E–E616、E63D–E640、E6B0–E6B4、E6B8–E6B9、E6C0–E6C2、E6C4–E6C5、EABD、EACC–EACD、EB10–EB11、EC41–EC42、EC46、EF86、EF88–EF89。陰性対照は E700。
- 腕は介入なし2回、および各番地に 00、01、02、04、08、10、20、40、80、FF を各1回。各腕は独立起動。陰性対照にも同じ値を使う。
- RAM から main ROM 7071 への横断を boundary-timeline と同じ分類で検出し、入口の命令実行前に1回だけ書く。入口以外、ROM 内移動、割り込みを介入対象にしない。介入回数と到達を確認する。先行する OUT 31 と E6C2 書き込み後の横断であることを別途確認する。
- 入口から RAM に戻るまでを区間とし、OUT のポートと出現順ごとの基準一致、画面書き込み件数と番地範囲の変化、帰還と帰還時 SP、経過フレームを比較する。異なる長さ・順序は欠落／追加として報告し、対応を推測しない。未帰還・記録欠落・溢れはそのまま明示する。
- OUT と入力の関係は同じ番地の全値の腕で検査する。全腕が入力値に一致すればそのまま、各出力ビットが入力ビットまたはその反転に全腕で対応すればビット対応、全腕同一なら定数とする。複数成立時は候補を併記し、一部欠測や腕による OUT の並びの変化は判定不能とする。いずれにも当てはまらなければ未分類とし、単発の偶然の一致を規則としない。
- 基準2回の一致性を先に示し、不一致の場合は介入の効果を断定しない。基準の OUT 値、作業域値、画面本文は出力しない。生記録はリポジトリ外に限定する。
- Mac での検査は自作 ROM・自作起動セクタの陽性と E700 相当の陰性に限る。公式 ROM・ゲームを使わず、run_all は実行しない。

器具を完成。Mac では自作データの検査のみ実施し、G5・公式 ROM の実走は未実施。

## 器具と実行

- パッチ `0029-b92-before-rom-entry.patch` と `tools/harness/core/b92_intervention.*`。
  `--intervene-before-rom-entry ENTRY:ADDR=VAL` は16進指定・1個限り。
  パッチ0016・0027のメモリ割当てによる境界分類を使い、入口の最初の fetch 内で、
  入口命令が実行される前に `main_mem_write` で一度だけ書く。
  先行する RAM 側の OUT 31 と、その後の E6C2 書込みは値なしの真偽で記録する。
  書込み先が main RAM / high RAM でない場合は介入せず、不適合を明示する。
- `--b92-log FILE` は必須。基準では介入指定を省く。
  `--b92-entry ENTRY` の既定は7071。介入と併用する場合は同じ ENTRY を先に指定する。
  生記録はリポジトリ外のみ（`tmp/` 例外なし、シンボリックリンクも実体で検査）。
- 区間は最初の対象横断から、初めて ROM 外へ出るまで。
  JP で入った場合も、入口時のスタック先頭の戻り番地と SP+2 に一致すれば帰還とする。
  異なる出口とフレーム上限までの未帰還は区別する。
  画面書込みは、区間終了時（未脱出なら採取終了時）の DMA 開始番地と
  CRTC の行長×行数の範囲に属する main RAM 物理番地で集計する。
  設定前に行われた書込みも含め、VRAMバンク・high RAM・範囲外のスタック書込みは除く。
  値は採らず、重複を含む件数と、書かれた番地の連続範囲を出す。
- `tools/b92_run.sh 外部の新規出力ディレクトリ` は `PC88_REF_ROM_DIR`、
  `PC88_GAME_DIR`、必要なら `PC88_CORE` / `PC88_FRONTEND` を使う。
  コアは0029まで適用済みのものを用意する。
  `stage_game.sh G5` の中立名媒体を腕ごとに複製し、先頭2枚をドライブ1・2へ挿す。
  対象36番地＋陰性E700の各10値、基準2回の計372腕を独立起動する。
  フレーム数は既定2010（`B92_FRAMES` で指定可）。
  全腕を走らせ、失敗腕は欠測として集計する。生記録は `raw/`、値なし集計は
  `summary.json`。画面本文は採らず frontend の画面署名モードを使う。
- 基準が不安定、入口未到達、先行イベント未確認、未帰還、介入不成立、
  腕欠落、OUT順序不一致の場合は入力との関係を判定不能にする。
  ビット対応では不変ビットの値を伏せ、入力に追随するビットだけを対応付ける。

## Mac の最小自己検査

`tools/b92_patch_selftest.sh` はローカルの固定上流コミットから一時ツリーを作り、
全パッチの適用・0029の逆適用検査・ビルド・介入状態機械の陽性陰性対照だけを行う。
元の vendor ツリーを書き換えず、ネットワークも使わない。

`tools/b92_selftest.sh` は上記を含み、自作 ROM＋自作起動セクタの基準2回、
陽性10腕、陰性10腕を検査する。自作 D88 を G5 として中立名へ stage し、
自作ローダがその同じ起動セクタ像を RAM へコピーして実行する（FDC 検査ではない）。
RAM の OUT 31・E6C2 書込み後の JP、ROM 内移動の非介入、二度目の入口で非介入、
帰還SP、OUT応答、画面書込み、集計での基準値不在、漏洩検出の陽性対照、
未到達・記録切断・基準不一致、frontend の書式と出力先制約を確認する。
`run_all` は実行しない。
