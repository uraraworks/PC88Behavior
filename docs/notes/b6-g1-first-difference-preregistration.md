# B6: G1 の公式と自作で、入出力の列が最初に分かれる所を探す — 事前登録

記録日: 2026-10-31
位置づけ: [b5-g1-self-boot-results.md](b5-g1-self-boot-results.md) 第3.5節の切り分け。
**このノートは測定より先にコミットする。** 結果を見てから規則を変えない（変えるときは後続ノートで）。

## 1. 問い

自作 ROM の上の G1 は RAM で走り続けるが、公式なら起きる ROM への横断が起きない。
ゲームの起動用セクタが動き始めてから、main CPU の入出力の**ポートと方向の列**は、公式と自作でどこまで同じか。

分かるのは「どこで列が分かれるか」だけである。分かれた理由、値による分岐、ゲームの内部の処理は、この測定からは言わない。

## 2. 条件

| 項目 | 値 |
|---|---|
| ゲーム | G1 の1枚目をドライブ1、打鍵なし、`--frames 3600` |
| 走 | 公式2走（official-1,2）、自作2走（self-1,2） |
| ROM | 公式はライブラリの9本。自作はこのノートをコミットした時点の HEAD の配布ビルド |
| 実行場所 | クラウドの実行環境（[追補2](goal-b-policy-addendum2-remote-measurement-2026-10-31.md)）。作業場はリポジトリの外 |
| 記録 | `--io-log`（main 節のみ使う）と `--boundary-log` を同じ走で取る |

### 観測の対照
同じ走の境界記録の濾過後が、公式は `measurements/b1-g1-demand-official-1.txt`、自作は
`measurements/b5-g1-self-boot-self-1.txt` とバイト一致することを確かめる。
一致しなければ `--io-log` が走を変えたとみなし、結果を根拠にしない。

## 3. 列の作り方（事前に固定）

実装は `tools/b6_io_sequence.py`。

1. `# main` 節の各行から、方向・ポート・領域だけを取る。領域は発行元 PC が `0x8000` 以上なら `hi`、未満なら `lo`。
   **値、PC そのもの、seq、frame は読み捨てる**
2. 列の開始は、発行元 PC が `C000-C0FF`（[l3-boot-sector](../spec/l3-boot-sector.md) の読み込み先）にある最初の行とする。
   その行が無ければ、PC が `0x8000` 以上の最初の行とする。どちらを使ったかを記録する
3. 連続する同じ（方向, ポート, 領域）を1要素に畳み、回数を付ける。比較は回数を見ない。
   待ちの回数は ROM の速さで変わるので、回数まで比べると本題でない差で止まる

取りこぼしの件数も記録する。取りこぼしがある走は、記録が残っている範囲だけを比べ、その旨を書く。

## 4. 判定（事前に決める）

- **再現**: 公式どうし、自作どうしで畳んだ列が一致するか。回数の違いは別に件数で報告する。
  再現しなければ、一致している範囲だけで比べ、それ以降は「揺れる」と書く
- 公式と自作を先頭から比べ、排他的に1つ選ぶ。
  - **差なし**: 両者の列が最後まで一致。入出力の列では分かれ目が見えない。別の観測が要る
  - **自作が先に途切れる**: 自作の列が公式の列の先頭部分。自作側はそこから先に入出力をしない
  - **公式が先に途切れる**: 公式の列が自作の列の先頭部分
  - **分岐**: ある位置 k で要素が異なる
- **分岐の扱い**: 自作側の要素が `hi` の待ちで、公式も同じ `hi` のポートを読んでいれば「同じ待ちから別の所へ進んだ」と書くだけにし、原因を断定しない

## 5. 記録の白リスト

コミットするのは `tools/b6_io_sequence.py` の要約だけ。全行が次のどれかに fullmatch することをツールが検査する。

- `# 識別子: G1` / `# 走: <name>` / `# 開始: boot-sector|first-hi`
- `events: N` / `dropped: N` / `runs: N`
- `port <IN|OUT> <4桁16進> <lo|hi> <回数>`（方向・ポート・領域ごとの集計）

比較の出力は次の行だけ。

- `result: same|self-ends-first|official-ends-first|diverged`
- `position: k`（畳んだ列での位置）
- `context <official|self> <-8〜+8> <IN|OUT> <4桁16進> <lo|hi> <回数>`（分かれ目の前後8要素まで）
