# m7hm: 連続READの周期「9」が受信runのフィールドに現れるかを、値を出さずに測る — 結果

実施日: 2026-09-07

## 位置づけ

[m7hl](m7hl-recv-run-count-field-preregistration.md)が事前登録した測定の
結果である。事前登録は測定開始前に単独コミット（`a4f09d6`）してあり、
本稿では事前登録の条件・群の定義・判定規則を後から動かしていない。
`src/`は本稿では変更していない（新設したのは`tools/`の測定器2本のみ）。

**結論を先に書く: 主判定はN（対応づけ不成立）である。** 事前登録が定めた
中止規則——「連続READ区間の入口12箇所のうち、直前完了runが一意に定まらない
箇所が1件でもあれば段階2は実施しない」——に該当した。12箇所**すべて**で
一意に定まらなかった（`entry_ambiguous_count=12`）。したがって段階2
（群Rと群Sのフィールド比較）は**実施していない**。C1・C2・C3のいずれも
主張しない。

**ただしNの中身は「候補が無い」ではなく「候補が多すぎる」だった。** これは
次の測定を設計できる形の失敗であり、詳細は後述する。

## 陽性対照（最初に書く）

事前登録 合格条件1の4項目を、本測定の解釈より先にすべて通した。

| 対照 | 結果 |

| 同じ比較を故障注入なしの混成ROMで行ったときのunit/head差件数 | **0件**（偽陽性を作らないことの確認） |
| `tools/analyze_error_exchange_shape_selftest.sh` | 全4項目OK・rc=0 |
| `tools/recv_run_field_leak_selftest.sh`（新設。陰性対照込み） | 全5項目OK・rc=0 |
| comparatorの故障注入（同一runは全位置eq=True、1バイト差し替えはその位置だけFalse） | 通った（上のselftest c項） |

**すべて通ったため、以降の解釈を行う。**

漏洩自己検査（`recv_run_field_leak_selftest.sh`）の内訳は、a. stage1/stage2
のどちらでも値を出さない、b. 合成データがC1と判定される（判定器が動く
ことの陽性対照）、c. comparatorの故障注入、d. **陰性対照——わざと値を出す
改変版では検査a.が正しく落ちる（検出力があることの確認）**、e. 改変版は
一時コピーのみで本体が無傷、の5項目である。d.が無ければ検査a.が
「何も検査していないのに緑」になりうるため、これを合格条件に含めた。

## 段階1 項目2・項目3: 対応づけは成立しなかった

| 項目 | 結果 |
|---|---:|
| 直前完了runが一意に定まらないSEEK段の件数（全23段中） | 21件 |
| 同（連続READ区間の入口12箇所のうち） | **12件（全部）** |
| `halt_stage2` | True |

**中止規則に該当したため、段階2は実施していない。** 実施しなかったことを
ここに明記する（無言でSKIPしていない）。事前登録が「実装で中止規則が効く
こと」を要求していたため、`stage2`サブコマンドを実際に起動して確認した
ところ、`verdict=N` / `reason=stage1_entry_ambiguous`を返して比較へ進まな
かった。中止規則は散文だけでなくコードでも効いている。

## Nの中身: 「候補が無い」のではなく「候補が2つある」

事前登録の`ambiguous`は「候補数が1でない」と定義してあり、候補0件と
候補2件以上を区別しない。どちらであったかは解釈上まったく意味が違うため、
候補数の分布を数えた（件数のみ。値は出していない）。

| 段の種類 | 候補数の分布（候補数: 段数） |
|---|---|
| 全23段 | 0件:4、1件:2、2件:12、4件:4、6件:1 |
| 連続READ区間の入口（12段） | **2件:11、4件:1**（0件は無い） |
| 単発区間の段（11段） | 0件:4、1件:2、2件:1、4件:3、6件:1 |

run1・run2で完全一致した。

**言えること: 連続READ区間の入口には、必ず受信runが先行している。**
12箇所のいずれも候補0件ではなかった。したがって「公式は1本の要求だけで
108件を読み切っており、以降まったく要求を受け取っていない」という描像は
**この測定では支持されない**。むしろ各9件周期の手前に、事前登録の窓の
取り方では2本（1箇所だけ4本）の受信runが入る。

**同時に、単発区間には候補0件の段が4件ある**——受信runが1本も先行しない
のにSEEKが発行されている段が実在する。これは`m7hb`が「間に新しいrunが
挟まっていないにもかかわらず複数回SEEKが発行されている」と記録した観察の
独立な再現であり、**単発側と連続側で、SEEK発行と受信runの関係そのものが
非対称**であることを示す。

## 言えること・言えないこと

**言えること:**

- 事前登録した「直前に完了した受信run」という窓の取り方では、連続READ
  区間の入口12箇所すべてで受信runが一意に定まらない。**この対応づけ方法
  では、要求の内容から連続READ移行を説明できるかどうかを判定できない。**
  これは`m7hb`が対応づけの破綻を定性的に記録したのに続く、**同じ方法の
  2度目の失敗を定量的に示したもの**である。
- 連続READ区間の入口には受信runが必ず先行し（候補0件は12箇所中0件）、
  単発区間には受信runが先行しない段が4件ある。**両者は非対称である。**
- 上記はすべて、生ログのバイト一致という最も強い形で決定論的である。

**言えないこと:**

- **「9」が固定カウンタ由来（H2）か要求レコード数由来（H1派生）かは、
  本稿でも区別できていない。** 段階2を実施していないため、C1・C2・C3の
  いずれも主張しない。`m7hb`が残した未確定は未確定のまま残る。
- 候補が2本あるという事実は、「そのうち片方が要求で片方が別物」とも
  「2本で1つの要求を成す」とも決めていない。本稿は候補数を数えただけで、
  候補の中身を見ていない（値を出さない設計のため、意図的に見ていない）。
- 単発区間の候補0件の段について、SEEKの引き金が何かは本稿では扱っていない。

## 事前登録の設計に、測定後に見つかった弱点（次稿へ回すもの。本稿では直さない）

**群Sの定義に場面の交絡がある。** 本測定で、READ DATAの単発run 9本は
すべてframe 35〜76（起動段階）に、連続run 12本はすべてframe 759〜761
（`FILES 2`打鍵後の入口）に現れることが分かった。事前登録の群S（単発区間）
と群R（連続READ区間の入口）は、**「連続か単発か」だけでなく「起動か入口か」
という場面の違いも同時に含む**。仮に段階2を実施してC1が出たとしても、
その位置が「レコード数」を表すのか「場面が違う」だけなのかを区別できない。

**これは事前登録の欠陥であり、本稿で群Sを定義し直すことはしない。**
（測定後に群の定義を動かせば、事前登録である意味が無くなる。）次稿の
事前登録で扱う。

## 次に何を測れば絞れるか

1. **場面を揃えた比較へ替える。** 群Sを起動段階の単発runから取るのを
   やめ、**同じ入口場面で、公式（連続READへ移行する）と混成（レコード
   ごとに再SEEKする）を比較する**。要求を出す側のmainは両条件とも公式
   ROMであるため、少なくとも分岐点（1.57節の段56）までは同じ場面・
   同じ相手が出した要求どうしを比べられる。ただし段56以降はmainが
   subの応答に反応して分岐するため、「同じ場面」と言えるのは分岐点まで
   である——この境界を事前登録で明示する必要がある。
2. **候補が2本になる窓の取り方を、事前登録で決め直す。** 本稿の
   `prev_boundary < 完了clock <= SEEK発行clock`という窓は、連続READ段で
   一貫して2本を拾った（11/12箇所）。「最後に完了した1本を採る」等の
   同点解消規則は自然だが、**これは候補数が2だと知った後に選ぶ規則である**。
   後知恵で規則を選ぶことになるため、次稿では同点解消規則と併せて
   **その規則が偽陽性を作らないことを示す反証条件**を事前に書く。
3. **単発区間の候補0件の段（4件）を、連続READとは別の現象として扱う。**
   受信runが先行しないSEEKは、要求駆動ではない別の引き金を示唆する。
   これは`m7hb`の「数千〜2万クロックの開き」と同じものを見ている可能性が
   高く、連続READ移行の規則を探る前に、こちらを先に片付けるほうが筋が
   良い可能性がある。

  の実装のみで、測定・解釈・判定は親セッションが行った。委譲先の報告を
  そのまま採らず、親セッションで(1)selftestを再実行してrc=0を確認し、
  (2)`print`・`stderr`・例外経路をすべて目視監査して、出力に到達するのが

- `stage1`サブコマンドの引数形式を取り違えて2回rc=2で失敗した（`--iolog`
  が必要なところを位置引数で渡した）。測定内容には影響しない。
- `find_l3_core`を`REPO`未設定のまま呼んで1回失敗した。コアパスを明示して
  やり直した。測定内容には影響しない。
- 上記以外の手順逸脱は無い。測定はすべてフォアグラウンドで実行し、測定中に
  `git stash`・ブランチ切替・`src/`の編集は行っていない。無言でSKIPした
  分岐は無い（段階2を実施しなかったことは中止規則に基づく明示的な判断で

- 測定器の実装中および測定中に、`m7hj`で起きたような画面本文の露出は
  発生していない。本測定は画面本文を扱う経路自体を使っていない。

読んでいない・出力していない。記録したのは公開μPD765コマンド種別名、件数、
