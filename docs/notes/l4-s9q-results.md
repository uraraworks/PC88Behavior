## 1. CLEAR の境界（`clear ,&hXXXX[,n]`、n は第3引数でスタック域、既定 512）

12条件すべてで、b5（誤り5でない最小の上限）と b7（受理の最小の上限）が幅1まで絞れ、単調（誤り5 → 誤り7 → 受理）・受理の傾き1・先頭と末尾のアンカー一致・2反復の完全一致が成り立った。

| 条件 | b5 | b7 | T=0xE000−fre(アンカー) | b7−T（受理の最小 fre） |
|---|---|---|---|---|
| base・n10・padrem（約800B）・padrem2（約2400B）・paddata・str1000・str20000・var | 0x8719（34585） | 0x892D（35117） | 35098 | 19 |
| stk128 | 0x8719 | 0x87AD（34733） | 34714 | 19 |
| stk256 | 0x8719 | 0x882D（34861） | 34842 | 19 |
| stk1024 | 0x8719 | 0x8B2D（35629） | 35610 | 19 |
| stk2048 | 0x8719 | 0x8F2D（36653） | 36634 | 19 |

確認腕 `cf-plain`・`cf-arr500`・`cf-arr3000`（配列がある状態の最初のプローブ）は、base の式から作った b5−1・b5・b7−1・b7 の4点の結果（誤り5・誤り7・誤り7・受理）を全て当てた。
`clear ,&h8400`＝誤り5・`&h8800`＝誤り7・`&h8C00`＝受理で fre 742 の既知値（kn）も再現した。

**規則（実効上限 X は 20.7 の変換後。0xE5FF 以下）**

- 誤り5: `X < 0x8719`（34585）。**本文・第3引数・第1引数・変数・配列に依らない固定の番地**。
- 誤り7: `0x8719 ≤ X < 34605 + n`（n は第3引数、既定 512。n=512 なら 0x892D）。誤り7の幅は `n + 20`。
- 受理: `34605 + n ≤ X ≤ 0xE5FF`。受理のとき `fre(0) = X − (34586 + n)`、最小の `fre(0)` は 19。`0xE600 以上`は誤り5（s9d 追補1と同じ）。
- **本文の長さ（rem・data で約800・2400バイト伸ばしても）は T も b7 も動かさない**。文字列変数、配列（2KB・12KB）、第1引数（1000・20000）も効かない。`fre(0)` に本文は入っていない。

失敗した CLEAR の後の `fre(0)`（誤りのプローブの印字値）は直前までの履歴で変わる（同じ 0x8000 で 11・13・115・22238 など）。CLEAR の結果ではないので使わない。

### CLEAR の文の種類（cv）

- 第1引数: `clear`・`clear 0`・`clear 1000`・`clear 20000` は誤りなし。`clear 65535`・`clear 70000` は**誤り6**、`clear -1` は誤り5。
- 第3引数 n（上限 0xE000）: 0 は誤り5、64・72 は誤り7、96・104・112・120・124・126・127・128・129・1024 は受理（`fre(0)` は n が1増えるごとに1減る）、
  32767・−1・32768 は誤り7。**80 と 88 は CLEAR のあとの印字が続かず結果が読めない**（受理かどうか不明）。最小の n は 72 と 96 の間で、80・88 は未解決。
- 上限を省略した `clear ,,128` は受理、`clear ,,64` は誤り7。

## 2. COLOR の第2〜4引数

第2〜4引数は書式 `COLOR [第1引数][,第2][,第3][,第4]`（マニュアル 2-29・2-30、s9p で読んだとおり第2〜4はグラフィック側）。誤り番号は `on error`・`err` で採った（参照 5・13 が全チャンクで取れた）。

| 位置 | 受理 | 誤り |
|---|---|---|
| 第2引数（背景） | 0〜7 | −1・8・9・255・256 は誤り5 |
| 第3引数（ボーダ） | **0 だけ** | 1〜7・−1・8・9・255・256 は全て誤り5 |
| 第4引数（前景） | 0〜7 | −1・8・9・255・256 は誤り5 |
| 文字列 `"a"`（第2・3・4） | — | 誤り13 |
| 小数 2.5（第2・第4） | 受理（四捨五入） | — |

- **`color 3,1,1,2` が誤り5になる原因は第3引数が 1 だから**（H1 が当たり）。4引数の格子 `color 3,b,bo,fg`（b・bo・fg ∈ {0,1,2}）は **bo=0 の9通りは全て誤りなし、bo=1・2 の18通りは全て誤り5**。b と fg の組み合わせに依らない。
- 部分形: `color 3,1`・`color 3,,,2`・`color ,1,,2` は誤りなし、`color 3,1,1`・`color 3,,1`・`color ,1,1`・`color ,,1,2` は誤り5（第3引数が 1）。省略した引数は誤りにならない。
- 5引数は誤り2、引数なし・末尾のカンマは誤り22（s9p 追補1）。

### ポートへの効果（制御ポートの書き込み値列。`cp-*`）

基準 `rem` との差は**ポート 0x54 の書き込み**で、`COLOR` が実行されて誤りにならなかった腕の全てで**2回**書かれる（基準・誤り5の腕では書かれない）。0x52 は動かない（陽性対照 `out &h52,&h40` は 0x52 に 0x40 を示した）。

- 値は第2引数 b（3ビット）で決まる。1回目 = `0x80 | (b の bit0 なら 0x07) | (b の bit1 なら 0x38)`（b=0〜3 で 128・135・184・191）、2回目 = `0xC0 | (b の bit2 なら 0x07)`（b=0〜3 は 192、b=4〜7 は 199）。
  つまり b の3ビットが 7 段階の 3 成分（0x07・0x38・0x07）に対応する。**ポートの意味は資料を開かず測定値だけで読んだ**（アナログのパレット書き込みの形に見えるが資料との照合は未）。
- 第2引数を省略した `color 2`・`color 7`・`color ,,0`・`color ,,,b`（b=0〜7）も同じ 2回書き込みで、値は b=0 と同じ（128・192）。**COLOR は実行のたびに背景（色0）を第2引数（省略時 0）へ書き直す**。第3・第4引数はポートに現れない（第4引数は値を変えても 0x54 の値が b=0 のまま）。
- 0x30・0x31・0x34・0x35・0x53・0x55〜0x5B の書き込みは全腕で無く（0x31 は 1回 0x19）、**0x32 は全腕で 0xA9/0xAA を多数回切り替える雑音**（COLOR の腕では 0xA8 も混ざる）。意味は決めない。

**17/23 的中、6外れ**（予測なしの項目は数えない: 第3引数の下限境界・`clear ,&hE000,n`（0・−1・32768）・`color 3,1,1,2` の原因（候補 H1 が的中）・部分形・`,,b`・`,,,b` のポート）。

## 4. 自作ROM（`35301b9` 時点、同じ器具、57腕×2走・関門失敗）の現状

- COLOR の誤り番号（co、参照込み 96文）は**公式と全て一致**（第3引数は 0 だけ受理を含む）。
- COLOR のポート: 自作は 0x54 などへ書かない（公式の 0x54 に書く19腕が差）。`out &h52,&h40` は自作では誤り2。基準・誤り5の8腕は差なし。
- CLEAR（cv の公式が読めた28文のうち）: 22一致、6差。`&h8400` は自作が誤り7（公式5）、`clear -1`・`clear ,&he000,0` は自作が受理／誤り7（公式5）、
  `clear 65535`・`70000` は自作が誤りなし（公式6）、`&he000,96` は自作が誤り7（公式は受理）。`&h8800` は自作が受理（公式誤り7、20.1 の既知の残差）。
  自作の最小受理の位置は本文長に依存する（`fre(0)` の T が本文で動く）。**自作では境界の探索が第2ラウンドで走行が崩れ、b5・b7 は採れなかった**（格子では b5 は 0x8280〜0x8500、b7 は 0x8780〜0x8A00 の間）。

## 5. 未測定・決めないこと

- 最小の第3引数 n（72 と 96 の間。80・88 は CLEAR のあとの印字が続かず不明）、`clear 65535` が誤り6になる境界（32768 以上か）。
- 第3引数を省略した上限のみの形・第4引数（前景）の効果（ポートに現れない）、ボーダ（第3引数）が 0 以外を拒む理由、カラーモード・`CONSOLE ,,,1` との関係。
- 0x54 の書き込みの意味の照合（資料未読）、0x32 の雑音の正体。
