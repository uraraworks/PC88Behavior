# l4-s5c — 変数と流れの制御の続き — 事前登録

記録日: 2026-09-15
状態: 事前登録、測定前

## 位置づけ

`l4-s5b`（測定`7a2fabf`）で`RUN`・`FOR`・`GOSUB`・変数の基本を測った。
仕様書`docs/spec/l4-program.md`第2版（別担当が並行で改訂中。**中身は
本ノートでは参照しない**）で未確定に残る点のうち、段階5の代表プログ
ラムに要るものを本ノートで測る。

## 問い

- Q1 ループを抜けた後の制御変数の値（C1・C11）
- Q2 `FOR`の入れ子、`NEXT`に変数名を付けた場合の対応（C2）
- Q3 変数名の何文字目までが区別されるか（C3、`abc`と`abd`）
- Q4 整数変数（`%`）への代入で、小数がどう丸められるか（C4・C5・C12）
- Q5 倍精度変数（`#`）への、単精度の演算結果の代入（C6・C7）
- Q6 文字列変数（`$`）の基本動作（C8）
- Q7 行番号を指定した`RUN`（C9、`run 20`）
- Q8 `GOSUB`の入れ子（C10）

## 腕（12腕＋陽性対照1腕）

打鍵はこのまま使う（英字は小文字）。1腕＝`new`のあと行を打ち、最後に
`run`を打つ、という一連の打鍵を1つの`--type`文字列として与える
（`l4-s5a`・`l4-s5b`と同じ作法）。C9のみ最後に`run 20`（行番号指定）
を打つ。

| 腕 | 打鍵文字列（`\n`は改行） | 目的 |
|---|---|---|
| C1 | `new`/`10 for i=1 to 3`/`20 next`/`30 print i`/`run` | Q1 ループ後の制御変数 |
| C2 | `new`/`10 for i=1 to 2`/`20 for j=1 to 2`/`30 print i*10+j;`/`40 next j`/`50 next i`/`run` | Q2 入れ子・NEXTに変数名 |
| C3 | `new`/`10 abc=1`/`20 abd=2`/`30 print abc`/`run` | Q3 変数名の有効文字数 |
| C4 | `new`/`10 a%=5/2`/`20 print a%`/`run` | Q4 整数代入の丸め（正） |
| C5 | `new`/`10 a%=-5/2`/`20 print a%`/`run` | Q4 整数代入の丸め（負） |
| C6 | `new`/`10 a#=1/3`/`20 print a#`/`run` | Q5 単精度演算→倍精度変数 |
| C7 | `new`/`10 a#=1#/3`/`20 print a#`/`run` | Q5 倍精度演算→倍精度変数 |
| C8 | `new`/`10 a$="12"`/`20 print a$`/`run` | Q6 文字列変数 |
| C9 | `new`/`10 print 1`/`20 print 2`/`run 20` | Q7 行番号指定RUN |
| C10 | `new`/`10 gosub 30`/`20 end`/`30 gosub 50`/`40 return`/`50 print 5`/`60 return`/`run` | Q8 GOSUB入れ子 |
| C11 | `new`/`10 i=10`/`20 for i=1 to 3`/`30 next`/`40 print i`/`run` | Q1 既存値を持つ制御変数 |
| C12 | `new`/`10 a=1`/`20 a%=a+0.5`/`30 print a%`/`run` | Q4 1.5を整数へ |

C8（文字列変数）は、中身を数字`"12"`にして、既存の数値の記録規則
（下記「記録する内容」節）でそのまま扱えるようにしている。

### 陽性対照（1腕、腕数には含めない）

直接モードの`print 7717`（`l4-s4a`以来使ってきた陽性対照と同一）。

- 打鍵文字列: `print 7717\n`（文字数11）
- フレーム計算式は下記「条件・関門」節の全腕共通の式をそのまま使う:
  `line_end = 700 + 8*11 = 788`、`dump = line_end + 300 = 1088`、
  `run = dump + 200 = 1288`（`l4-s5a`では本文にこの式を明記していな
  かった反省を踏まえ、本ノートでは陽性対照のフレーム式も明記する）。

腕の総数: **12腕**（C1〜C12）。各腕2走（決定論性の関門G3）。

## 条件・関門

`l4-s5b`（`3f41c15`）の「条件・関門」節をそのまま踏襲する。

- 起動settle`--type-at 300 --type '\n'`、実打鍵開始`--type-at 700`
- 1文字あたり`hold+gap=8`フレーム/文字（`\n`も1文字として数える）
- フレーム計算式（全腕共通。陽性対照にも同じ式を適用する）:
  ```
  line_end(k) = 700 + 8 * (その腕で打った文字数の累計。\n も1文字。
                            複数行にわたる打鍵は全体を1つの--type文字列
                            として与え、文字数は改行を含めた合計)
  dump(k)     = line_end(k) + 300
  run(k)      = dump(k) + 200
  ```
- 写しは打鍵前（`--type-at`の10フレーム前=690）と`dump(k)`後の2枚を
  `--diff-before`/`--diff-after`に渡す
- C9は、`10 print 1`・`20 print 2`の2行を打った後、`run 20`（行番号を
  指定した`RUN`）を打つ。`run 20`も同じ`--type`文字列の一部として
  連続で打ち、文字数の累計にそのまま含める。
- 複数行を打つ腕（特にC2・C10のように行数が多い腕）は、行ごとの打鍵の
  間隔が上記の式で正しく積み上がっていることと、`RUN`の後の実行と
  表示が写しの時刻`dump(k)`までに終わっていること（関門G8）を確認
  する。

## 記録する内容

`l4-s5b`と同一の手順を、正式な手順として明記する。

- **`Ok`行の位置（打った行からの相対行）と、`RUN`の後に出た行の数を、
  すべての腕で必ず記録する。**
- 出力行（`RUN`の後に現れる行）は、**行ごとに**`l4-s4a`の数値分類器
  （`tools/l4_s4a_float_classify.py`、`5735eb3`。文字コードが「数字
  0-9・`.`・`+`・`-`・`E`・`D`・空白」の集合に入る行だけコードを記録
  する）を適用する。`numeric_output`と分類された行は、(相対行, 相対
  桁, 文字コード)の並びをそのまま記録する。それ以外の行（エラー・
  `Ok`自身の文字列等）は、件数と位置の範囲だけを記録する。コード・
  文言は一切出さない（`l4-s5b`結果ノートで実際に使った、分類器を出力
  行ごとに適用する手順を、本ノートで正式な手順として定める）。
- C8（文字列変数、中身`"12"`）の出力行も、上記の数値分類器をそのまま
  適用する（出力される文字列`12`は数字だけの並びなので、
  `numeric_output`として扱える）。

## 本文を出さない取り扱い

`l4-s4a`〜`l4-s5b`と同一。「記録する内容」節の分類規則に従い、
`numeric_output`の行だけコードを記録し、それ以外は件数と範囲だけに
する。分類器（`tools/l4_s4a_float_classify.py`）は集合外のコードを
標準出力・標準エラーへ出さない設計であることが`5735eb3`の時点で確認
済み。

- Q3（C3、変数名`abc`/`abd`）: 変数名の文字列そのものは、自分で打った
  識別子であり、打鍵の直接の結果として出力にコードごと記録してよい
  （`l4-c1`以来の「自分で指定した記号のエコー/出力」と同じ扱い）。

## 関門

`l4-s5b`のG1〜G5・G8と同一（G6は対になる予測表が無いため本測定にも
適用しない）。

- G1 器具の自己検査: 測定時HEADで`tools/harness/vram_dump_selftest.sh`・
  `tools/harness/vram_dump_dynamic_selftest.sh`・
  `tools/harness/key_matrix_selftest.sh`・
  `tools/harness/type_untypable_selftest.sh`・
  `tools/screen_content_leak_selftest.sh`の全項目がOK
- G2 取りこぼし0・打てない文字の警告0（全走のstderrで確認）
- G3 決定論性: 各腕2走とも、写しはファイルのsha256が一致、記録は
  sha256が一致
- G4 陰性対照: 何も打たない走（起動settleのみ）で差分0件
- G5 陽性対照: 直接モードの`print 7717`腕で`7717`の並びを確認
- G8 出力完了の確認: 「後」の写しで、出力行の後に`Ok`行が現れている
  こと。特に行数の多い腕（C2・C10）で確認する。現れない腕は
  `gate_failed`とし、「写しが早すぎた」とだけ記述する

判定の前にG1〜G5・G8がすべて真であること。いずれかが偽の腕は、その
腕を`gate_failed`として判定に含めず、理由を記述する。

## 判定

判定名はこの事前登録に書いたものだけを使う。「記録する内容」節を
参照する。当てはまらない形はすべて`other`とし、記述で補う。

- Q1（C1・C11）: `after_loop_N`（Nは記録した出力の値そのもの。値を
  記述する）／`other`
- Q2（C2）: `nested_ok`（内側・外側それぞれのループが期待どおりの回数
  実行され、出力が`i*10+j`の並びとして現れる）／`other`
- Q3（C3）: `first2_significant`（`abc`と`abd`が同じ変数として扱われ、
  `print abc`が`abd`への代入の影響を受ける）／`more_significant`
  （3文字目以降も区別され、`abc`と`abd`は別変数のまま）／`other`
- Q4（C4・C5・C12）: `rounds_half_away`（半分は絶対値の大きい側へ丸め
  られる）／`truncates`（小数部を切り捨てる）／`rounds_half_even`
  （最近接偶数丸め）／`other`。腕ごとに値を記述する。
- Q5（C6・C7）: 記述のみ（判定名は付けない）。C6・C7それぞれの出力
  値をそのまま書く。
- Q6（C8）: `string_ok`（`"12"`が代入・出力とも正しく機能する）／
  `other`
- Q7（C9）: `starts_at_line`（`run 20`が20行目から実行を始め、10行目
  の`print 1`は実行されない）／`other`
- Q8（C10）: `nested_gosub_ok`（`GOSUB`の入れ子が両方とも`RETURN`で
  正しく戻り、`50 print 5`の出力が現れる）／`other`
- `gate_failed`: 関門のいずれかが偽だった腕。判定に含めず、理由を
  記述する。

## 器具の確認（公式ROMは使わない）

測定開始前に、自作main ROM（測定時HEAD`7a2fabf`から`src/build_main_
rom.py`で組み立て）に対し、12腕＋陽性対照の計13腕すべてを打鍵し、
各行のエコーが打鍵どおりに届くかを`tools/l4_vram_probe.py --marker`
（各腕の打鍵文字列を`\n`で分割し、各行をそれぞれmarkerとして指定）で
確認した。**自作ROMはまだプログラムモードを持たないため、実際の`RUN`
の挙動は見ておらず、エコーだけを確認した。**

結果: **13腕すべてで、全行のエコーが打鍵どおりに出現した**（腕ごとの
全行でmarker一致、打鍵前の走行失敗〔型チェックによる事前拒否〕も
無し）。`%`（C4・C5・C11・C12）、`#`（C6・C7）、`$`・`"`（C8）、`;`
（C2）を含め、届かなかった記号は無かった。

作業に使ったROM・写し・スクリプトはリポジトリ外の使い捨てディレクトリ
（scratchpad配下）に置き、確認後に削除した。
