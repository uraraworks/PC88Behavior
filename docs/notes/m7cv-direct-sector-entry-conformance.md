# m7cv: 直接セクタ入出力需要入口の事前登録

実施日: 2026-08-27

本稿の到達条件は実測前に固定した。公式ROM・公式ディスクの内容は読まず、
生ログ、画面報告、ROM／ディスク複製はリポジトリ外の一時領域だけに置く。
書込み対象には、参照diskAから作った使い捨て複製だけを用いる。

## 対象入口と自作データ

第1候補はN88-DISK BASICの直接セクタ入出力 `DSKI$` / `DSKO$` とする。
使い捨てdiskA複製のドライブ1、トラック39、セクタ16だけを対象とし、256文字の
自作文字列を `DSKO$` で書く。書込み後、受け変数を保存値とは異なる256文字へ
代入し、破壊が成立した場合だけ `D8C` を表示する。その後 `DSKI$` で同じ座標を
読み、長さ256かつ自作文字列と完全一致した場合だけ `D8R`、最後まで通過した場合
だけ `D8E` を表示する。不一致時は `D8N` を表示する。

座標はファイルシステムの内容に依存せず、原本を変更しない。公式一式／混成の
各runには同じ原本から作り直した別々の複製を与え、複製間で書込み結果を継承しない。

## 到達条件・対照

直接セクタ書込みの到達は、(1) 自作文字列の生成と `DSKO$` の打鍵が画面へ反映、
(2) FDCの `WRITE DATA` が1件以上発行、(3) 書込み後に変数を別値へ破壊したことを
示す `D8C`、再読出し全長一致を示す `D8R`、末端の `D8E` が順に出る、の全条件と
する。直接セクタ読込みの到達は、(1) `DSKI$` の打鍵が画面へ反映、(2) FDCの
`READ DATA` が1件以上発行、(3) 同じ3マーカーが順に出る、の全条件とする。
`Ok` の表示だけは、どちらの到達条件にも採らない。

陽性対照は、打鍵したプログラムと `D8C`、`D8R`、`D8E` が順に現れる合成画面、
かつREAD/WRITE発行を持つ形とする。陰性対照は、事前破壊に失敗して `D8C` を欠く
形、読戻しが一致せず `D8R` を欠く形、末端へ届かず `D8E` を欠く形とする。
従って構文受理、FDC書込み要求、または破壊前の変数が偶然一致しただけでは合格しない。

## 不採用条件と切替

この環境で `DSKI$` / `DSKO$` が `Syntax error` 等となり、公式一式でも上記入口へ
到達しない場合、その試行の署名は期待値へ採らず、不採用の事実だけを本稿へ残す。
その場合は媒体初期化（公開μPD765の `WRITE ID` / `FORMAT` 系を踏む操作）へ切り替える。
切替時は、その実測より前に、初期化後の使い捨て媒体へ自作データを書き、別値へ破壊後に
読み戻して一致時だけ固有マーカーを出す到達条件と対照を本稿へ追加固定する。

## 観測指標と固定手順

公式一式／混成を各2回実走し、FDCコマンド種別列、`READ DATA`・`WRITE DATA`件数、
main `IN $FC` と `IN $FD` の件数・SHA-256、画面の行数・文字数・SHA-256を測る。
同一モード2回の全イベント列と画面の決定論性、および公式／混成の全長一致を確認する。
最初の公式到達runで署名を出し、期待値を固定してから4runを判定し直す。

期待値は専用TSVへ置き、判定器は表示ラベルを一時パスへ使わず `mktemp` で故障コピーを
作る。生成失敗と期待値0行を必ず失敗とする。合成画面の陽性・陰性対照に加え、
SHA-256破壊、件数破壊、期待値0行の3故障を注入し、空振り0件を必須とする。

ここまでを実測前の事前登録とする。

## 情報境界

記録するのは件数、SHA-256、画面の行数・文字数・SHA-256、自分で打鍵した文字列、
および公開されたμPD765のコマンド名だけとする。画面本文、ディスクのデータ部、
公式の応答値は記録しない。

## 初回校正

参照した公開言語仕様は、Internet Archive
`NECPC8801mkIIMRN88BASICN88BASICREFERENCEMANUAL1986L`のページ画像
2-63、2-65、2-236だけである。2-65により、`DSKO$`は文字列引数を取らず、
`FIELD #0`または0番バッファへ用意した256バイトを書き込む文だと確認した。
2-63は`DSKI$`が同じ0番バッファへ256バイトを読み込むこと、2-236は
`VARPTR(#0)`がバッファ先頭の9バイト前を返すことを定めている。この公開書式に
従い、最終形は`VARPTR(#0)+9`から256バイトを自作値で埋める形へ校正した。

不採用試行は次のとおりである。最初の`DSKO$`へ文字列を渡す形と、括弧・代入形・
文字列先行形の複数書式は、WRITE DATA 0件かつ末端マーカー0件だった。応答本文は
記録せず、署名も採用しなかった。`STRING$(256,...)`と`LEN(...)=256`に依存する形も、
公開仕様上の通常文字列上限255文字に合わないため不採用とした。

正しい`DSKO$ 1,0,39,16`はWRITE DATAを1件発行したが、当初のハーネス引数では
書込み後の直接読出しが自作値と1件だけ不一致だった。書込みデータ部そのものは
自作256バイトと全長一致していた。使い捨て複製へ明示的に更新を反映する
`--save-to-disk-image`を同一runへ付けると、WRITEデータ部と後続READデータ部が
256件全長一致したため、この引数を固定した。これは原本への保存ではなく、runごとに
原本から作り直すリポジトリ外複製だけへの反映である。

途中で`VARPTR(#0)`をバッファ先頭そのものと誤認してPOKEした試行は、末端マーカーへ
届かなかった。公開仕様の「先頭-9」に従い`+9`へ訂正し、0番バッファ全256バイトを
自作値81で埋めて書込み、全256バイトを別値88へ破壊して`D8C`、同じ座標を再読出し
して全256バイトが81へ戻った場合だけ`D8R`、末端で`D8E`を出す形に確定した。
最終単発公式runは3マーカーが順に出て不一致マーカー0件、WRITE DATA 1件、
取りこぼし0件だった。この署名だけを期待値へ採用する。

## 実測結果

採用したのは媒体初期化への切替ではなく、直接セクタ`DSKI$` / `DSKO$`入口である。
公式一式／混成を各2回実走し、全4runで`D8C`、`D8R`、`D8E`が順に出て、
取りこぼしは各0件だった。各モード2回のmain/sub全イベント列と画面は決定論的に
一致した。公式／混成間もFDCコマンド種別列59件、main受信列、画面が全長一致した。

FDCはREAD DATAが各10件、WRITE DATAが各1件だった。main `IN $FD`は5635件・
SHA-256 `e26b22e7eec0d20725b25a34c00bc968820e1c7434c21cc45e0fb61939315ab7`、
main `IN $FC`は6931件・SHA-256
`02c8f75b60c7ff8f77e1f822ab9cb10fa4047c4f358301415e0463274d16f2fd`だった。
画面は19行・491文字・SHA-256
`84a1692bb71a6c1ee23aa724202b0d044b83f975d4199c57db288869d85d9d29`である。

判定器は表示ラベルを一時パスに使わず、`mktemp`でSHA-256故障・件数故障・
空期待値を作る。3故障をすべて不一致として検出し、空振り0件だった。合成画面も
完全形を到達、`D8C`・`D8R`・`D8E`を各1個欠く3形を未到達と判定した。

判定器実装中の行き止まりも残す。任意引数配列を空にした既存入口で`set -u`が
未定義配列と判定し、最初の全実走はFILES開始時に停止した。存在判定付き配列展開へ
直した。次の全実走は、成功表示中の`DSKI$`直後の日本語を変数名と解釈して、追加入口
公式run1の取りこぼし0件確認後に停止した。ドル記号をエスケープし、再び全入口を
最初から実走してrc=0を得た。停止前の署名は結果へ採用していない。

公式／混成差は無く、`src/l3_service/make_subrom.py`の実装追加は不要だった。

## 検証

`PC88_REF_ROM_DIR=$PWD/private/rom PC88_REF_DISK_DIR=$PWD/private/disk
tools/conform_l3.sh`はrc=0だった。直接セクタ入口の実測行は4件、同入口のSKIPは
0件である。全体には今回の対象外で環境変数未設定のdiskB起動SKIPが1件ある。
`tools/run_all_selftests.sh`はrc=0、OK 51件、NG 0件、SKIP 3件、Traceback 0件。
`tools/check_cleanroom.sh`はrc=0だった。

`src/l3_service/make_subrom.py`は差分0件で、既定ROMを別々の一時ディレクトリへ
2回生成してバイト一致を確認した。実装は変更していない。
