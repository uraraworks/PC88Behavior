# B9: 自作サブが渡したデータはディスクのどこのものかを、座標だけで比べる — 事前登録

記録日: 2026-10-31
位置づけ: [b8-g1-values-up-to-13510-results.md](b8-g1-values-up-to-13510-results.md) の次段。
**このノートは測定より先にコミットする。** 結果を見てから規則を変えない（変えるときは後続ノートで）。

## 1. 問い

1. `IN $FC` の 3840 バイトを 256 バイトずつに分けた各ブロックは、G1 のディスクのどのセクタと同じか。公式と自作でどう違うか
2. `IN $FE` の違いは、どのビットで起きているか

## 2. 条件

OO・OS・SS 各 1 走。条件は [B8](b8-g1-values-up-to-13510-preregistration.md) 第2節と同じ。クラウドの実行環境で行う。
B8 の入出力の要約と同じ対照を通す。

## 3. 求め方（事前に固定）

実装は `tools/b9_sector_coordinates.py`。B6 第3節と同じ開始の行から後を使う。

- `IN $FC` の先頭から 3840 バイトを 256 バイトずつ 15 ブロックに分ける
- 器具の中で D88 を読み、各ブロックをセクタの本体と比べる
  1. 大きさ 256 バイトのセクタと完全に同じものを探す。あれば座標 `(C,H,R)`。複数あれば番号の小さい順の最初と、一致の件数を出す
  2. 無ければ、ディスクの全セクタ本体を連結した列の中から完全に同じ並びを探す。あれば、始まりのセクタの座標とセクタ内の位置を出す
  3. どちらも無ければ `none`
- **全部が同じ値のブロック**（全 0x00 や全 0xE5 など）は座標に意味がないので `uniform` とし、値は書かない
- `IN $FE` は B8 と同じく畳んで k 番目どうしを比べ、ビット 0〜7 それぞれで違う件数を数える

## 4. 判定（事前に決める）

OO 対 OS・OO 対 SS のそれぞれについて、15 ブロックの座標を並べ、次の言葉で事実だけを書く。

- **同じ座標:** 同じセクタを渡している
- **別の座標:** ディスクの別の所を読んでいる。ずれの形（トラック、ヘッド、セクタ番号のどれが違うか）を書く
- **位置つきの一致:** 並びがセクタの境界からずれている
- **none:** ディスクの中身そのものではない
- `IN $FE` は違いのあるビットの番号と件数を書く

なぜそうなるかの推定は結果ノートに書いてよいが、推定と明記する。実装の修正は別の担当が仕様書から行う。

## 5. 記録の白リスト

コミットするのは `tools/b9_sector_coordinates.py` の出力だけ。全行が次のどれかに fullmatch することをツールが検査する。

- `# 識別子: G1` / `# 腕: <OO|OS|SS>`
- `block <番号> sector <C> <H> <R> matches=<N>`
- `block <番号> within <C> <H> <R> offset=<N> matches=<N>`
- `block <番号> uniform`
- `block <番号> none`
- `fe-bit <OS|SS> <0-7> differ=<N> compared=<N>`

## 6. 記録しないもの

ディスクのバイト列、ブロックの値、値のハッシュ、`OUT $FD` の値、発行元 PC の番地、フレーム番号、画面本文、ゲーム名やファイル名。
`uniform` の値も書かない。座標はディスクの構造の観測であり、中身ではない。
