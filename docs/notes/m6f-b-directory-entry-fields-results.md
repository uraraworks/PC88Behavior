## 5. E1 — 大文字・小文字

- 名前を**大文字の符号**（`CHR$(81)` 等）で与えると、ディスク上も**大文字**だった。
- **小文字の符号**で与えると、**小文字**だった。
- **キーボードから打った** `"QZ7A"` は、ディスク上で**小文字**だった。

したがって、**ROM はファイル名を与えられたとおりに格納する**（大文字・小文字をそろえない）。
そして**この測定環境（q88measure の `--type`）で打った英字は、小文字の符号として届く。**

ハーネス `tools/harness/frontend/main.c` の注記は「英字は小文字の RETROK コードを送れば
大文字として入る」だった。**これは誤りである。** 注記を直す（同じコミットで行う）。

これまでの測定は、公式ROMと自作ROMを**同じ打鍵**で比べてきたので、比較の結論は
この誤りの影響を受けない。ただし「打った文字が大文字で届いている」という前提で読んだ
解釈があれば、見直しの対象になる。

m6f-a が SAVE で観測した「小文字で入っていた」は、E1 の G3 と同じ現象（打鍵が小文字で
届いた）であり、SAVE と OPEN で扱いが違うのではない。

## 6. E7 — 割り当て表

3腕（G1・G2・G3）で本体の中身を変えたので、本体のセクタは3腕で同じ変化にならず、
候補から外れた。残った3セクタは、3腕で**位置も新しい値もまったく同じ**に変わり、
大きいファイル（G7）でより多くのバイトが変わった。

3セクタが同じに変わることは、**割り当て表を複数持つ形に見えるが、そうとは結論しない。**
中身の意味（どのバイトがどの割り当て単位か、空きの印は何か）は、古い値が伏せられるので
差分からは読めない。

## 7. 記録しないこと

**公式ディスク固有の事柄は書かない**（m6f-a 結果 §7 と同じ）。名前が現れたセクタ内の
位置（＝何番目のエントリが空いていたか、既存ファイルの数）、本体の割り当て位置、
割り当て番号とみられるバイトの値は、いずれもノートに書かない。E2・E5 の導出結果に
含まれるセクタ内オフセットも同じ理由で書かない（「エントリの先頭」と相対位置で書く）。

## 8. 行き先

事前登録 §7 の `m6f_b_entry_fields_derived` の行き先に従う。

1. **エントリの欄を `docs/spec/l3-disk-format.md`（新設）に規則として起こす。**
2. **ハーネスの注記を直す**（§5）。
3. 次稿で、**空の公式形式ディスクを自作の生成器で作り、公式ROM がそれに SAVE・FILES・
   LOAD を行えるかを測る。** 割り当て表の空きの印や、ディレクトリがどこまで続くかなど、
   差分から読めないものは、そこで**挙動から再構成する**。

## 9. この測定で決まらないこと

- ディレクトリが (18,1,3) 以外のどのセクタまで続くか。
- エントリの名前欄・属性以外の欄（割り当てに関わるとみられるバイトを含む）の意味。
- 割り当て表の中身の意味と空きの印。
- ファイル名の最大長を超えたとき、使えない文字の扱い。
- 実機で英字キーが大文字・小文字のどちらを出すか（本稿が確かめたのはこの測定環境で
  打鍵が小文字で届くことだけである）。
