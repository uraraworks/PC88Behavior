# m7iq: 入口場面より前の要求を全位置で掃引し、非対称を埋める — 結果

実施日: 2026-09-07

## 位置づけ

[m7ip](m7ip-early-exchange-allpos-preregistration.md)が事前登録した測定の結果で
ある。事前登録は測定開始前に単独コミット（`02aa15a`）してあり、本稿では水準・
分類・判定規則を後から動かしていない。`src/`・`tools/`は本稿では変更していない。

**結論を先に書く: 主判定はS2（「9」は動かないが影響はある）である。**
70armすべてを測ったが**C型（9以外のrun長）は1本も出なかった。**

**さらに強い形で言える——70armを通じて現れたrun長は`1`と`9`の2種類だけ**
だった。ほかの長さは一度も現れていない。

**これで`m7io`が挙げた非対称は埋まった。** `m7ii`（40）・`m7ik`（12）・
`m7im`（9）と本稿（70）で**のべ131arm**、C型は**0本**である。

## 記述（判定ではない）: run長は常に1か9

**70armを通じて現れたrun長は`1`と`9`だけである。** `2`も`8`も`10`も一度も
現れていない。run長9の本数の分布は次のとおり。

| run長9の本数 | arm数 | 備考 |
|---:|---:|---|
| 0 | 20 | すべて「入口未到達の可能性」の印付き |
| **12** | **45** | 基準と同じ本数 |
| **13** | **5** | **基準より1本多い** |

### 基準より増えた5本

| arm | FDC総数 | READ総数 | 多重集合 |
|---|---:|---:|---|
| run 6 pos 3 | 207 | 126 | `{1:9, 9:13}` |
| run 12 pos 1 | 207 | 126 | `{1:9, 9:13}` |
| run 22 pos 3 | 207 | 126 | `{1:9, 9:13}` |
| run 28 pos 1 | 203 | 125 | `{1:8, 9:13}` |
| run 30 pos 1 | 207 | 126 | `{1:9, 9:13}` |

**暴走した5本（FDC総数1950超）は、この5本の「すぐ次の位置」だった**——
run 6 pos 4、run 12 pos 2、run 22 pos 4、run 28 pos 2、run 30 pos 2。
**同じrunの中で、ある位置は周期を1本増やし、その隣の位置は機械を暴走させる。**
本稿はこの隣接の理由を測っていない（記述にとどめる）。

**言えること:**

- **C型は1本も無い。** 入口場面より前の要求を、**全位置**にわたって壊しても
  run長9は動かない。
- **run長は常に1か9**。70armのどれでも他の長さが現れない。
- 周期数（12）は動く——減る（B型）ことも、**増える**（13本、5arm）こともある。
  **動くのは「何本あるか」だけで、「1本の大きさ」ではない。**
- 全armで`changed>=1`。介入は全部届いている。

**言えないこと:**

- **本稿は`XOR 0xFF`しか当てていない**（事前登録に明記した限界）。`m7ig`は
  交換run36で1ビット反転が`XOR 0xFF`と違う結果を出すことを示している。
  **「全位置を触った」とは言えるが「全ビットを触った」とは言えない。**
  本稿が閉じたのは**位置の非対称**であって**ビットの非対称**ではない。
- **20armは入口へ到達していない可能性がある**ため、「9が動かなかった」の証拠と
  しては弱い。有効なのは50armである。
- **`sub→main`方向（応答）は本稿でも触っていない。** `m7io`が挙げた第2の
  未閉経路は残る。
- 周期が13本に増える理由も、その隣が暴走する理由も測っていない。
- run長や本数から元の値を逆算していない（禁止事項5）。
- 条件O・`disk#10`という1本のディスク・1条件である。一般性は主張しない。

**それでもrun長9は一度も動かず、現れたrun長は常に1か9だけだった。**

## この結果の使い道（事前登録が先に定めたとおり）

事前登録は「C型が出なければ**『要求のバイト列を触る経路では「9」に届かない』を
3節へ記録する**」と定めていた。**その条件が満たされた。**

**ただし事前登録が同時に定めたとおり、「『9』の出所はROM内部である」とは
主張しない。** 言えるのは**「この経路では届かない」**までである
（3節・第28版が231条件の全滅を「直接読めるハードウェア状態からは導けなかった」と
書いたのと同じ書き方）。

**残る未閉経路（本稿が閉じていないもの）:**

1. **ビットの非対称**——入口場面より前の18本には`XOR 0xFF`しか当てていない。
   全ビットへ広げると70×8＝560armになる。
2. **`sub→main`方向（応答）**——一度も「9」を狙って壊していない。
3. **ディスクの側**——`m7il`が土俵無しと記録したまま。

## 次に何を測れば絞れるか

1. **`sub→main`方向を狙う（未閉経路2）。** 既存の`--exchange-intervention`が
   そのまま使え、armも交換run 30本ぶんで済む。**位置の非対称を埋めた今、
   方向の非対称を埋めるのが筋である。**
2. 1でもC型が出なければ、**未閉経路1（ビット）を残したまま**でも
   「要求のバイト列では届かない」を3節へ記録してよいと考える——ただし
   **560armを測っていないことを明記した上で**である。
3. `m7ig`が示したとおり1ビット反転は`XOR 0xFF`と違う結果を出すので、
   **未閉経路1を全部潰すかどうかは費用対効果の判断になる。** 本稿は判断せず、
   事実（560arm未測）だけを残す。

- 本稿は委譲を行っていない。測定・解釈・判定はすべて親セッションで行った。
- 上記以外の手順逸脱・事故は無い。無言でSKIPした分岐は無い。
