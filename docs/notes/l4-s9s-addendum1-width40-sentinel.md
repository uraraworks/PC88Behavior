# l4-s9s 追補1 — 最後に40桁になる3腕の終了の印が見つからなかった（器具の欠陥）: 事前登録

状態: **再測定前**（2026-10-08）。事前登録 `l4-s9s-console-preregistration.md`（7de2feb）、器具 f346d74。

## 起きたこと

公式ROM 138腕×2走と自作ROM 138腕×2走の初回測定で、**どちらも同じ3腕**（`cm-w40`・`cm-c1-w40`・`cm-w40-c1`）だけが関門落ちになった（残り135腕は2走一致・終了の印が1か所）。
原因は器具: 最後の `width` が40桁の腕では、文字が**2バイトおき**に置かれる（l4-program 5.6.1）のに、解析の間隔指定（`gap`）を `ww` 腕（`console 5,10` のあとの `width 40`）にしか適用しておらず、
終了の印 `s9sz` を間隔1で探して見つからなかった。事前登録の関門（「全ての sc/cm 腕で終了の印が1か所だけ見つかる」）の通りに落ちたもので、関門の条件は変えない。
この3腕は ports（0x30）だけで判定する予測（`cm-c1-w40`・`cm-w40-c1` の最後の 0x30 が 0x20）を持つが、関門落ちのため判定されていない。

見たもの（開示）: 関門落ちを調べるときに、この3腕の記録の `rows`（行ごとの記号。行0と行19が `?`、他は `.`）と `sz=[]` を見た。それ以上の観測（カーソル・ポート・順序列）はこの3腕については読んでいない。
他の腕の結果は、この追補を書くまで解析していない。

## 変更

- 解析の間隔を「プログラムの最後に有効な桁数」で決める（`cols_end`: 最後の `width` が `width 40` なら40桁＝間隔2、それ以外は80桁＝間隔1）。`ww-width40-*` を含む5腕（`ww-width40-14`・`ww-width40-bot`・`cm-w40`・`cm-c1-w40`・`cm-w40-c1`）が間隔2になる。
- 自己検査に、間隔2の合成VRAMで `cm-w40` が valid になること、間隔1で読むと印が見つからないこと、80桁の腕は間隔2の印を印と読まないことを足した。
- 予測・関門・他の腕は変更しない。

## 再測定

`--only cm-w40,cm-c1-w40,cm-w40-c1` の3腕を公式・自作の両方で2走ずつ測り、`official_add1.tsv`・`own_add1.tsv` に記録する。初回の記録（`official_main.tsv`・`own_all.tsv`）は残し、135腕はそのまま結果に使う。
