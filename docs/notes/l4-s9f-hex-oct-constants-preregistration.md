以下は公開ソースの**散文要約**であり、コードやROM内部の番地を転載しない。

`&`直後の文字は空白を飛ばして大文字扱いで調べる。Hなら16進、Oなら8進、
それ以外はOを省略した8進である。16進では以後の空白を飛ばさず、0–9とA–F/a–fを読む。
数字のない場合は0で止まり、G等の英字も数の外へ残る。16進は**桁数を数え、5桁目でERR=6**
（先頭の0も桁数に含む）。単なる下位16ビットへの切り詰めではない。
8進は数字の間も空白を飛ばし、8・9でERR=2、積み上げが65535を越すとERR=6。
読み終わった16ビットは**符号付き整数**として式に渡り、32768–65535は-32768–-1になる。
数の中の符号は読まず、`-&h1`の負号は式の単項演算子である。

この読取りは10進FINの接尾辞処理へ戻らない。`%`・`!`・`#`は未消費の文字となり、
今回の代入式ではERR=2になると予測する（型指定としては吸収しない）。
行入力の字句化でも同じ読取りを呼び、LISTは保存された値を&H/&Oの表記で出す。
字句化中のエラーは行挿入前に起きる。正常な挿入はON ERRORの設定を解除するので、
RUNでは15番で設定し直す。直接入力と入力拒否には、既存のハンドラを入力直前に設定する。

整数の加算は符号付きで、結果が整数の範囲を越える場合は単精度へ昇格する。
`&hffff+1`は0。`a%=&hffff`は-1。`/`は整数の両辺を単精度にして除算する。
`abs(-32768)`は単精度へ昇格して32768となる。
これはPC-88の確定仕様ではなく候補 **H_GW** の予測である。

大小文字は、器具の打鍵が小文字のみであるため、同じ小文字式の直接入力と、
小文字で行入力してLISTの大文字の書き直しを経てRUNする経路を対にする。
LISTは値を再入力する操作ではない。生の大文字を直接打った場合を独立に測ったとは主張しない。
予測器の固定値では`&HfF`・`&O17`も検査する。PEEKや任意番地は使わない。

範囲外で切り詰める小候補なら、`&h10000`=0、`&h1ffff`=-1、`&o200000`=0となり、
H_GWのERR=6・入力拒否と区別できる。符号なし小候補なら`&h8000`=32768・`&hffff`=65535。
接尾辞を型指定として吸収する小候補ならsuffix群は16となる。
これらは外れた場合の比較用で、既定予測を変更しない。

## 入力時と実行時の切り分け

1標本は1腕、番号は1。NEW後、誤りの印を出す940番（RESUME 960）、
実行用950番（RESUME NEXT）、960番ENDを設ける。
入力用ハンドラは`940 print "s9ge";1;err:f=1:resume 960`。
直接モードはf=0・ON ERROR GOTO 940・CLS・代入・成功時PRINT・完了PRINT。
番号付き行はハンドラの定義に限る。測る直接モードの文を数字で始めない。

プログラムは10番でf=0、15番でON ERROR GOTO 950、20番に代入と成功時PRINTを
**同じ1行**で置き、40番で完了印、50番END。20番が拒否されても別の行で古いvをPRINTしない。
次の3枚を同じ走行で採る。

1. 入力直前にf=0・ON ERROR GOTO 940・CLS。20番を入力し、入力時ERR印だけを採取。
2. CLS・LIST。行の本文は保存せず、行頭の番号だけを内部で分類する。
   足場10・15・40・50・940・950・960が各1行あることと、対象20が0行または1行あることを検査。
   重複・予期しない番号・足場欠落・非ASCIIは関門失敗。範囲付きLISTには依存しない。
3. CLS・RUN。数値または実行時ERRの印と完了印だけを採る。

対象20が0行なら`entry_rejected`相当（listed_lines=0）として記録し、RUNの完了印だけを
許す。エラー本文からERRを推測しない。**入力時ON ERRORが効かない場合の印の有無は
PC-88で未確定**。主予測はGWのエラー処理に基づきERR印ありとするが、ERR印なしでも
行拒否を記録できる。小候補H_GW-Uは主予測の入力時ERR印だけを空列にしたもの。
この場合、値は無く、ERR番号は未採取であり、0やSKIPへ置き換えない。
直接モードでERR印を採れない場合は完了印だけとなり、形式関門が失敗する。
対照のON ERROR/ERRORが機能しない場合も全体をgate_failedとする。
代替の判定法が必要なら追補を事前登録し、先に対照を検証する。

全行は80文字未満、小文字、`@`なし。8フレーム/文字、行間240、公式の起動改行300・
入力開始700、自作入力開始100、RUN後15000、採取前200、採取から次行まで100を固定。
複数枚の写しは元名に`.f<6桁フレーム>`が付くので、指定フレームから実際の名を組み立てる。
写しは一時ディレクトリ内だけに置いてfinallyと一時ディレクトリの終了時に削除する。
標準出力・エラー・TSVに画面本文は出さない。印以外の行は件数だけ記録する。

## 採取形式・関門・照合

観測は`entry_errors`・`listed_lines`・`result`の3項目。
通常のresultは`[s9g,1,V]`または`[s9ge,1,N]`の後に`[s9gd,1,1]`。
行拒否ならresultは完了印だけ。直接モードのlisted_linesはnull。
正数には先頭空白、負数には`-`を要求し、小数・E/D指数も数値として正規化する。
印行は全体一致・引数2個限定。欠けた印や余分な印を成功として扱わない。
PRINT値は表示された数字との完全一致で比較し、許容誤差は設けない。

定数対照は10進の0・16・-32768・5.33333と`error 5`を両モードで各2走（10腕）。
全対照が既知値と一致したときだけ全体関門を通す。対照の欠落・SKIPを合格にしない。
各腕は2走の3項目が一致し、形式が妥当なら主候補H_GWをagree/differと判定する。
入力時ERRの有無に関する小候補H_GW-Uも列として出す。
`check`は対象腕の過不足、重複、2走の番号、形式、関門、打鍵失敗、期待値改変を拒否する。

器具: `tools/l4_hexconst_measure.py`の`predict --out FILE`、
`measure --rom-dir DIR --out FILE [--official] [--work-dir D]`、
`check --expected FILE --measured FILE`、`selftest [--work-dir D]`。
既定作業場は`../tmp/l4s9f-work`。公式ROMのDIRは実行者が環境変数PC88_REF_ROM_DIR経由で渡す。
公式測定は本作業に含めない。

selftestは`bash tools/l4_hexconst_selftest.sh < /dev/null`だけを実行する。
作業場の書込み制限がある環境では同じスクリプトに`--work-dir /tmp/l4s9f-work`を指定する。
GW読取りの手計算固定値、印採取の陽性・破損・欠け・数値/ERR改変の陰性、
LISTの行拒否・重複・足場欠落、2走再生・片走改変、対照改変・欠落、打鍵失敗、checkを検証。
さらに自作ROMを一時ビルドし、**10進の数値定数だけ**の8腕×2走を測り、既知値との一致を必須とする。
自作の&H・&O・ON ERRORをこの自己試験で使わない。
`run_all_selftests.sh`は`l4_inkey_robust_selftest.sh`の直後に1行登録する。

## 決めないこと

任意番地の値、ROMの内部表現、PRINT書式の新しい丸め規則、速度、別の入力装置での
大文字打鍵の独立性、複合式の網羅は対象外。測定結果を実装へ渡すには別途仕様への起草を要する。
