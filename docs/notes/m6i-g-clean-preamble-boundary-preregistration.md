# m6i-g — sub 無改変の腕で、前置きの最小構成を測る — 事前登録

記録日: 2026-09-23  
状態: 測定前

[m6i-e 結果](m6i-e-gate-harm-mechanism-results.md) は、m6i-b の腕を汚染した
経路が **ラウンド#0応答の直後の `IN A,($FE)` 1回**だったことを確定した。
本測定は、**sub 側に介入を一切持たない腕**で前置きの最小構成を測り直す。

## 0. 何を決める測定で、何を決めない測定か（先に書く）

**本測定は自作 main を自作 sub に対して測る。** したがって決まるのは
**自作どうしの統合条件**であって、**公式 sub が何を要求するかではない。**

この区別を先に書くのは、自作実装を自作の相手役で試験すると、両側に共通する
誤解が通ってしまうからである。**本稿の結果を `docs/spec/l3-subrom.md` 1.65節へ
書かない。** 1.65節は公式の観測に基づく節であり、本稿はそこへ規則を1つも
起こさない。公式 sub に対する適合は `tools/conform_l3.sh` の系統で別に確かめる。

本稿が決めるのは「**自作 main が自作 sub へ初回の通常READを出す前に、
どこまで前置きを行えばよいか**」である。M6統合（案A）の実装条件である。

## 1. 問い

自作 main ＋ 自作 sub（**無改変**）で、初回の通常READが成立するために必要な
前置きは、次のどれか。

- **なし**（状態を進めず、同じ時間だけ待つ）
- **(b)+(a)**: 起動専用SENDを1件出し、sub が自律的に行う FDC 初期化7 batch が
  完了するまで待つ
- **(b)+(a)+(c)**: さらにラウンド#0（2位置要求・1位置応答）まで行う

## 2. 腕（arm）

**4腕すべてで `DISK.ROM`（sub ROM）をバイト一致させる。** m6i-b の B0・B6-A0 が
使っている素のサブROM（介入フラグを1つも渡さずに生成したもの）をそのまま使う。
**`FONT.ROM` と `N88_0`〜`N88_3` も4腕で同一。** 違うのは `N88.ROM` だけである。

main は m6i-b が既に持っている前置きコードを流用する。媒体・セクタ・
期待SHA-256・打鍵・測定期限は m6i-c の凍結値と同じ。

| 腕 | main | 発行フレーム | 発行直前の状態（期待） |
|---|---|---:|---|
| G-N | m6i-b B0 の main（前置きなし・即発行） | 6 | `a=0,b=0,c=0` |
| G-L0 | m6i-b B1 の main（送信せず待つ） | 60 | `a=0,b=0,c=0` |
| G-L1 | m6i-b B4 の main（起動専用SEND 1件） | 60 | `a=1,b=1,c=0` |
| G-L2 | m6i-b B5 の main（SEND＋ラウンド#0） | 60 | `a=1,b=1,c=1` |

`a` は FDC 初期化7 batch の完了、`b` は起動専用SEND/RECV 1件の完了、
`c` はラウンド#0の完了を指す。m6i-b と同じ定義・同じ観測量を使う。

### G-L0 は m6i-b の B1 と同じ腕ではない

m6i-b の B1 は、sub をリセット直後のゲートで止めていた。**本稿の G-L0 は
ゲートを持たない。** sub はリセットから起動ハンドシェイクまで進み、main の
最初の送信を待ってそこで自然に止まる。したがって:

- **sub は I/O を行う**（ハンドシェイク待ちのポーリング）。m6i-b の B1 が
  報告した「停止中の sub の CPU 進行0件」は、本稿では成り立たない。
- 一方で、**発行直前の状態が `a=0,b=0,c=0` であること**は変わらない。
  陰性対照として意味があるのはそちらである。

**「sub が1命令も動いていない」ではなく「状態が1つも進んでいない」を対照とする。**

### G-L1 で `a` が自律的に完了することは、仮定ではなく到達指標である

素のサブROMは、起動ハンドシェイクを終えると main の関与なしに FDC 初期化を
行う。G-L1 はこれを利用して、sub 側の介入なしに `a=1,b=1,c=0` を作る。

**ただしフレーム60までに初期化が完了するかは測ってみないと分からない。**
完了していなければ到達指標を満たさず `unreached` とする。**期待の形を到達の
根拠にしない。**

### 到達指標（4腕共通）

- 発行直前の `(a,b,c)` が、上の表の登録値と一致する
- 発行フレームが登録値（G-N は 6、他は 60）と一致する
- 前置きの通信を要求 run へ数えていない
- 2走の判定が一致する

### 結果条件

通常READが「256位置一致かつ期待SHA一致かつ定常入力待ちへ復帰し、要求 run が
1件」であるとき `success`、そうでないとき `failure`。m6i-c から変更しない。

## 3. 関門（gate）

- **G1 自己検査**: `tools/run_all_selftests.sh` が rc=0。
- **G2 クリーンルーム検査**: `tools/check_cleanroom.sh` が rc=0 かつ NG 0件。
- **G3 凍結値**: 媒体SHA・セクタSHA・測定期限・反復数が m6i-c の凍結表と一致する。
- **G4 sub 無改変と main の直交をバイトで示す**。本測定の主張を支える関門である。
  - 4腕の `DISK.ROM` がすべてバイト一致し、**素のサブROM**
    （介入フラグ無しで生成したもの）と一致する
  - 4腕の `FONT.ROM`・`N88_0`〜`N88_3` がすべて同一
  - 4腕の `N88.ROM` は互いに相異し、それぞれ m6i-b の B0・B1・B4・B5 の
    `N88.ROM` とバイト一致する
  - 7ファイルすべてが所定サイズ
  陰性対照として、1腕の `DISK.ROM` を介入ありのものに差し替えた一式で
  false になることを示す。
- **G5 時刻と状態**: 4腕とも発行フレームが登録値で、発行直前の `(a,b,c)` が
  登録値と一致する。
- **G6 結果検出力**: 合成入力で、256位置一致、1位置欠落、SHA不一致、timeout、
  定常入力待ち未復帰を別々に識別する。
- **G7 状態観測の独立性**: `a`・`b`・`c` を別マーカー／別事象で観測し、
  同じ事象を2状態へ重複計上しない。
- **G8 器具の自己汚染検査**: 到達判定が、測定の走によって書き換えられうるもの
  を参照していない。
- **G9 未確定値の凍結**: 腕名・判定名・発行フレーム・期待状態・素のサブROMの
  SHA-256 を測定前に器具の設定ファイルへ固定し、本稿と違えばエミュレータ
  起動前に `gate_failed`。

## 4. 判定名

判定は関門、到達、結果の順で付ける。2走が一致しない腕は `unreached`。

- `gate_failed` / `unreached`
- `g_n_reproduced`: G-N が `failure`。/ `g_n_not_reproduced`: G-N が `success`。
- `g_l2_reproduced`: G-L2 が `success`。/ `g_l2_not_reproduced`: G-L2 が `failure`。
- `g_l0_success` / `g_l0_failure`
- `g_l1_success` / `g_l1_failure`

総合判定は、`g_n_reproduced` と `g_l2_reproduced` がともに成立することを
共通の前提とする。どちらかが崩れたら `m6i_g_inconclusive` とし、境界の帰属を
しない。

- `m6i_g_elapsed_time_only`: `g_l0_success`。**状態を1つも進めずに待つだけで
  成立する。** この場合は G-L1 の形にかかわらず境界の主張をしない。
- `m6i_g_ab_sufficient`: `g_l0_failure` かつ `g_l1_success`。
  **(b)+(a) の完了で足り、(c) は必要条件ではない。**
- `m6i_g_c_required`: `g_l0_failure` かつ `g_l1_failure`。
  **(b)+(a) では足りず、(c) まで要る。**
- `m6i_g_inconclusive`: 関門は通過したが、1腕以上が `unreached` であるか、
  再現腕が再現しなかった。

## 5. 判定後の行き先

- `m6i_g_ab_sufficient`: 自作 main の統合では、通常READの前に
  **起動専用SENDを1件出し、sub の初期化完了を待つ**前置きを採る。
  ラウンド#0を一般的な前提にしない。
- `m6i_g_c_required`: 前置きにラウンド#0まで含める。**なぜ必要かは本稿では
  決まらない**ので、必要性の機序は別稿へ送る。
- `m6i_g_elapsed_time_only`: 状態境界を実装せず、固定待ちの期限と再現性を
  別稿で事前登録する。本稿から待ち値を実装へ直結しない。
- `m6i_g_inconclusive`: 到達器具か期限だけを直す追補を先に置き、結果条件と
  判定名は緩めない。

**いずれの判定でも `docs/spec/l3-subrom.md` へ規則を起こさない**（§0）。
行き先はすべて `src/` 側の統合実装に関するものである。

### `b` 単独（`a` を伴わない）を本稿では測らない

素のサブROMは、起動ハンドシェイクの後に自律的に FDC 初期化を行う。
**sub を改変せずに「`b` だけで `a` を伴わない状態」を作ることはできない。**
m6i-b の B2 はそれを sub 側のゲートで作っていた。

本稿はその腕を持たない。したがって境界は「**(b)+(a) 以前のどこか**」までしか
絞れない。**より細かい境界を主張しない。** さらに絞る必要が生じたら、
ラウンド#0より前に置く介入の無害性を先に確かめる稿を立てる
（m6i-e はラウンド#0の**後**についてしか測っていない）。

## 6. 本文に出さないもの

- 測定終了時のテキスト画面本文、main↔sub のデータポート値列、セクタ本文は、
  標準出力、標準エラー、結果ノート、コミットメッセージへ出さない。件数、順序、
  真偽、SHA-256、判定名だけを扱う。
- ROM の相違はバイト列を転記せず、一致／不一致と相違バイト数だけを扱う。
- I/Oログを残す場合は `tools/redact_iolog.py` で値列を伏せ、
  `tools/check_cleanroom.sh` を通す。
- 本文またはデータ列の漏えいを検出した走は結果に使わず `gate_failed` とする。

### この測定で決まらないこと

- **公式 sub が何を要求するかは決まらない**（§0）。自作どうしの統合条件である。
- 公式ROM内部の実装、公式の送受信値、実機での絶対時間は決まらない。
- **`b` 単独で足りるかは決まらない**（§5末尾）。
- **`c` が必要だった場合、なぜ必要かは決まらない。**
- 別媒体、WRITE、複数セクタREAD、BASIC命令一般へ一般化しない。
- m6i-b の腕の結果を、本稿の結果で上書きしない。m6i-b は記録として残る。
