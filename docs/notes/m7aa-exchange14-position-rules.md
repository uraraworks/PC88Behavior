# m7aa: 交換#14のREAD位置対応と規則候補

測定日: 2026-08-13

公式環境を1800フレーム新規実走し、生ログはリポジトリ外だけに置いた。
`tools/analyze_exchange14_read_rules.py`はデータポート値をメモリ内で比較し、
標準出力には位置と一致ベクトル・一致件数だけを出す。値は表示・記録していない。

## 位置対応

交換#14の12件要求と5回のREAD DATAを0始まり位置で比較した。

- READのC（パラメータ位置1）は、各回直前のSENSE INTERRUPT STATUSの
  PCNと5/5一致した。したがって5回ともSEEK対象をCへ引き継ぐ。
- 第1 READのunit/headとRは要求位置4だけに一致した。CとHは要求位置1/10に
  一致したが、この2位置は同値のため意味上の生成元は未確定である。
- 第2 READのRは要求位置3だけに一致した。第3〜第5 READのRは要求位置1/10と
  一致したが、両位置の意味上の区別は未確定である。
- Cは第1・第4・第5 READで要求位置1/10、第2・第3 READで要求位置2/6/9/11に
  一致した。Hは第1・第3・第5 READで要求位置1/10、第2・第4 READで
  要求位置2/6/9/11に一致した。
- 直前READ結果では、R→次READのRが4/5で一致したが全件規則ではない。
  ST0〜ST2、直前C/H/Nのいずれにも5/5で座標を決める対応は無かった。

## 公開FDC規則候補

READ間ではH反転が4遷移すべてで成立した。Cは同一が2/4、+1が1/4、
R=1が3/4であり、「Rを単純加算」「EOT+1を次Rへ転記」は0/4だった。
よって単純セクタ連番ではなく、要求位置からSEEK/C/Rを転記しつつHを交互に
反転する規則が残る。データ部長は順に256、3584、4096、4096、512件だった。

最初の介入候補は、累積7件境界の第1 READだけを、確定した位置一致に従い
unit/head・Rを要求位置4、SEEK/C/Hを同値候補の早い要求位置1から転記する。
C/Hの位置1選択は意味の確定ではないため、観測した交換#14第1 READだけに限定し、
公式期待5635件との一致が伸びるかで規則候補を反証可能にする。

## 第1介入と出力配置の追加測定

第1 READ介入後の公式期待5635件との一致プレフィックスは0件のままだった。
4指標は値一致長779、main構造258、sub構造752、混成main `IN $FD` 1031件。
よって正しい第1 READ座標だけを既存の単一`SECTOR_BUF`へ置く規則では先頭を生成しない。

公式main `IN $FD`は先頭3件と定常5632件にPC位置で分かれる。先頭3件は要求12位置、
5回のREADパラメータ、結果各7位置のどれにも一致元が無かった。2件目だけは
`5632 / 256`で得る転送組数と一致したが、1件目・3件目の規則は未確定である。

5回のREADデータ総長は49セクタ、両ポートの定常出力総長は44セクタ相当である。
「各READの先頭1セクタを除外」すると長さは11264件で厳密に一致するため候補としたが、
次の配置規則はいずれも公式定常列との先頭一致0件で外れた。

- 5回READデータの単純連結
- 各READ先頭1セクタ除外後の偶数位置／奇数位置分離
- 同じ11264件の前半／後半分離

したがって未確定なのは座標値そのものだけではなく、FDCデータから二つの定常出力列を
作る配置・変換規則と、先頭3件のうち1件目・3件目の生成規則である。
