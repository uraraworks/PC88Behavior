# m7lt: 1回目——関門G0/G1が不成立（gate_failed）。I/Oログ指紋が見出しの作業パスを含んでいた

実施日: 2026-09-12（15:53〜16:10頃）
事前登録: [m7lt-...-preregistration](m7lt-no-disk-cpu-mode-screen-preregistration.md)
（**測定前に単独コミット済み**。腕・+0の定義・関門・判定規則は本稿で動かしていない）

## 結論（1回目）

> **`gate_failed`。結論は出さない。** 事前登録どおり「器具を直すところから」の分岐へ進む。

## 原因の診断（事前登録外、公式・引数なしを同条件で2回、行単位比較。値は出さず件数・行番号だけ）

- `io_log_full_sha256()`はI/Oログのファイル全体をハッシュしていたが、フロントエンド
  （`tools/harness/frontend/main.c`の見出し出力）は`rom-dir`行・`disk`行に**走ごとの
  作業ディレクトリ名（タグ入り）**を書く。そのため同一条件の2回でも指紋が必ず異なっていた。
- 診断: ログ1,426,187行のうち異なるのは2行だけ（0始まりで16・17行目＝上記パス行）。
  I/Oのデータ行は全一致——**走行自体は決定的**だった。
- **G2の「m0と指紋が異なる」判定も同じ欠陥の下では常に真になる**（どんな2走でも
  パス行が違えば指紋は割れるため）。したがって1回目のG2「到達=真」は、有効性を
  実際に確認したものではなく、**器具の欠陥がそう見せていただけ**である。

## 行き止まりの記録

事前登録に「同一条件2回で指紋が一致すること」を**測定前の段階0**として置いていなかった。
置いていれば、公式環境を使う前に（または1回目の走で）気づけた。器具の陽性対照2つ
（P1）は「異なるべきものが異なる」側（G2が無効を検出できるか）しか見ておらず、
「同じであるべきものが同じ」側（陰性対照）が無かった。

## 記述（合否に使わない。関門不成立の走なので観測として記すだけ）

- 公式: `none`/`m0`/`m0_repeat`は+0長5・+0開始759・+0前のrun36本・起動終わり77。
  `m1`/`m1_repeat`は5・759・36・**245**。`m2`/`m2_repeat`は5・759・36・**183**。
- 混成: `none`/`m0`/`m0_repeat`は6・759・36・82。`m1`/`m1_repeat`は6・759・36・**133**。
  `m2`/`m2_repeat`は6・759・36・**126**。
- +0前の(方向,長さ)列の指紋は14走すべて同一（`90e4178f4204`）。
  `core_option`は全走`requested=2`、`returned`はnone/0/1/2が条件どおり。
- G0（`none`と`m0`のio指紋一致）は両側で偽、G1（決定論性）は全組で偽、
  G2到達はm1/m2で真（ただし上記のとおり器具の欠陥の下での真で、意味を持たない）、
  G3は全組真。
- モード1・2では起動終わりが公式245/183・混成133/126と**混成のほうが早くなる**が、
  +0の長さは5/6のまま。**ただし関門不成立の走なので観測として記すだけで、判定には
  使わない。**
